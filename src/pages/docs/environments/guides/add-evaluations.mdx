An agent can do what a scenario asks and still behave badly while doing it, such as a pharmacy line stepping outside its authority. Evaluations catch that: they decide whether your agent did the right thing in each conversation. In an [environment](/docs/environments/concepts/understanding-environments), a **run** plays a set of scenarios against your agent, and each [scenario](/docs/environments/concepts/scenarios-and-trials) played once is a **call**, a phone call for a voice agent or a conversation for a chat agent. The evaluations on the environment score every call of every run, so you choose them once, and keeping the set fixed is what makes one run comparable with the next.

An evaluation you add grades calls from then on. Grading a run that already finished is a separate action, covered at the end of this guide.

<Prerequisites title="Before you start">
- An environment in **Ready** status; [Build an environment](/docs/environments/guides/build-an-environment) covers getting one.
- To grade a past run, a run that has completed. Only a completed run can be graded again.
</Prerequisites>

## How a call is graded

Three things grade a call in an environment, and only one of them is what this page changes:

<div class="sdk-ref-table max-sm:[&_td]:px-1.5! max-sm:[&_th]:px-1.5!">

| Layer | Where it comes from | What it checks | Same for every scenario? |
|---|---|---|---|
| Sub-goals | Written into each scenario from the [contract](/docs/environments/concepts/contracts) | The specific things that scenario tests, such as `checks_refill_status` | No, each scenario has its own |
| Evaluations | Chosen on the **Evaluations** tab, from the Future AGI [evaluation library](/docs/evaluation) | Qualities every call should have, such as staying within the agent's authority | Yes |
| Tool call evaluation | A switch on the **Evaluations** tab | Whether each tool call was the right tool, with the right arguments, at the right time | Yes, when it is on |

</div>

Sub-goals say whether the agent did what one scenario asked. Evaluations say whether it behaved well while doing it, the same way in every call, which is why they are the ones you choose and keep fixed.

## See what is already added

Open the **Evaluations** tab. It already holds a few evaluations: when the builder reads your agent into its contract, it picks the ones that fit, so a pharmacy line might start with `advice_authority_boundary` and [`customer_agent_prompt_conformance`](/docs/evaluation/builtin/customer-agent-prompt-conformance).

<img src="/images/docs/environments/guides/add-evaluations/evaluations-tab.png" alt="The Evaluations tab with the Enable tool call evaluation toggle off, and the Added evaluations card with its Add evaluations button and four evaluations, each listing the inputs it reads" style={{ borderRadius: '5px' }} />
*Evaluations picked from the contract arrive already added, each with the inputs it reads*

An evaluation scores a call from a few named inputs, and in an environment those inputs are wired for you. Each evaluation under **Added evaluations** lists them under **Reads**, with what fills each one: `{{conversation}}` from the **Call recording** or **Transcript**, `{{agent_prompt}}` from the **Agent instructions**.

To decide what to add, start from what a failure would cost you. Keep the suggested set, add one evaluation for each behavior that would be a release blocker if it broke, such as escalating to a human or never giving clinical advice, and resist adding many overlapping ones: a small, stable set gives a clearer trend from run to run.

## Add or remove evaluations

1. Click **Add evaluations**, in the header of the **Added evaluations** card.

   **Select Evaluation**, the evaluation library, opens.

2. Search by name, or narrow the library with a category such as **Conversation**, **Agents** or **Safety**.
3. Expand a row to see what fills each input.
4. Click **Add** on each evaluation you want.

   **Create New Eval** writes your own; [Create a custom eval](/docs/evaluation/guides/custom-evals) covers it.

<img src="/images/docs/environments/guides/add-evaluations/add-evaluations-drawer.png" alt="The Select Evaluation drawer filtered to the Conversation category, listing 19 library evaluations such as persona_consistency and conversational_naturalness, each with an Add button" style={{ borderRadius: '5px' }} />
*Each library evaluation is one click to add, and grades every call from then on*

An evaluation you add scores every call from then on. Calls that already finished are left as they were, so adding one doesn't silently change a run you have already read; [grade a finished run](#grade-a-run-that-already-finished) to bring a past run up to date. To remove an evaluation, click the delete icon on its row.

## Grade tool calls

If your agent calls tools, turn on **Enable tool call evaluation** at the top of the **Evaluations** tab. It grades the tool calls your agent makes during each call: whether it picked the right tool, with the right arguments, at the right time.

## Grade a run that already finished

Adding an evaluation to the environment doesn't reach back into past runs, so a finished run has its own way to catch up.

1. Open the run from **Runs**.
2. Click **Run evals** at the top.

   The **All Evaluations** drawer lists every evaluation on the run.

3. To grade with an evaluation that isn't on the run yet, click **Add Evaluations** to bring it in from the library first.
4. Tick the evaluations to grade with, or tick **Evals (N)** to tick them all.
5. Click **Run (N)**, or **Run All (N)** when every one is ticked, and confirm.

   Grading runs in the background, and when it finishes the new verdicts appear as columns beside the others.

6. Click a call's row and open its **Evals** tab to read each new verdict and the reason behind it.

You can also run or remove a single evaluation from its own row. If a row can't be ticked, its score came from the run itself, and only re-running the call refreshes it.
