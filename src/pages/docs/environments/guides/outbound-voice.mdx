## About

Ridgeline Outfitters calls customers when a tent repair is ready. Use a voice environment to test what the agent says when a mailbox answers; verify physical outbound dialing separately on a test line you control.

## Test a callback that reaches voicemail

Start with a [hosted voice environment](/docs/environments/guides/build-an-environment). For a Retell test agent, choose **Hosted platform**, **Retell AI**, and **Web** to test the conversation without placing a phone call. With an environment's **Phone** connection, the simulator dials the agent at the contact number you supply. An outbound *scenario* makes the agent play the caller; it does not reverse who physically dials.

<Steps>
<Step title="Ask the builder for a personal mailbox">

*Add an outbound tent repair callback. Sam's personal mailbox says “You've reached Sam. Leave a message.” Check that the agent waits for the tone, names Ridgeline Outfitters, explains why it called, and gives a next step without asking Sam a question.*

In the scenario the builder authors, voicemail requires both `call_direction: outbound` and `answered_by: voicemail`. Without `answered_by`, the recipient is a person. The greeting goes in `persona.initial_message`; specify `voicemail_style` so the builder knows which mailbox to test. The default style is `personal`.

{/* MEDIA: Voice environment builder with the Ridgeline mailbox request and the resulting scenario. */}

</Step>
<Step title="Run only that case">

In **Scenarios**, tick the mailbox case, choose **1×** under **Repeats**, then choose **Run simulation**. A mailbox greets once and does not answer further questions.

{/* MEDIA: Scenarios selection bar showing one mailbox case selected and one repeat. */}

</Step>
<Step title="Listen for the agent's first words after the greeting">

[Open the call](/docs/environments/guides/read-run-results). Use the recording to check the timing against the tone, and the transcript to check the message. For example, “This is Ridgeline Outfitters. Your tent repair is ready. Please call the store to arrange pickup” gives Sam a next step. “When would you like to come in?” needs an answer the mailbox cannot give.

</Step>
</Steps>

### Compare mailbox styles

| `voicemail_style` | What to listen for | Expected agent behavior |
| --- | --- | --- |
| `personal` | A personal greeting followed by a tone | Wait for the tone before leaving the pickup message. |
| `carrier` | A network greeting that names nobody, then a tone | Give a callback instruction without assuming Sam answered. |
| `operator` | A longer formal announcement before the tone | Wait through the entire announcement so the start of the message is audible. |
| `full` | An announcement that the mailbox cannot record. No tone. | End the call without leaving a message. |

If your suite has room for a second mailbox, ask for the same callback with `voicemail_style: full` and the greeting “This mailbox is full and cannot accept new messages.” Select the personal and full cases together. The successful outcome changes from *leaves a message* to *ends without leaving one*. Neither case should require a customer to agree to a pickup time.

## Preview the two mailbox instructions locally

Before running a paid call, you can compare the instructions the Agent Learning Kit gives a simulated personal mailbox and a full mailbox. Create a virtual environment with `python3 -m venv .voice-venv`, activate it with `source .voice-venv/bin/activate`, then install `python -m pip install agent-learning-kit==0.3.7`. Save this as `mailboxes.py` and run `python mailboxes.py`:

```python
from fi.alk.harness.simulator_voice import simulator_instructions

for style in ("personal", "full"):
    instructions = simulator_instructions(
        direction="outbound", answered_by="voicemail", voicemail_style=style
    )
    print(f"{style}: {instructions.strip()}\n")
```

This prints instructions, not a recording or a verdict. Listen to the actual call to check whether the repair agent waits for the greeting and responds appropriately. Voicemail must be enabled for the environment runner. For suites of four or more scenarios, the mailbox limit is 5% of the suite, rounded up: one in a suite of 20, two in a suite of 21.

## Verify physical outbound dialing separately

A completed Environment voicemail scenario is **not** proof that your provider dialed a phone number. If you also need that assurance, use your provider's outbound-call test with a disposable agent and an originating and destination number you control. Check the provider's call ID, connection status and disconnect reason. A call that never connected cannot tell you whether Ridgeline left a good message. Never dial a customer to verify this workflow.
