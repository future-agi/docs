## About

Ridgeline Outfitters calls customers when a tent repair is ready. Use a voice environment to test what the agent says when a mailbox answers; use a hosted Retell phone test when you also need to verify that the agent can dial out.

## Test a callback that reaches voicemail

Start with a [hosted voice environment](/docs/environments/guides/build-an-environment). For a Retell test agent, choose **Hosted platform**, **Retell AI**, and **Web** to test the conversation without placing a phone call. With an environment's **Phone** connection, the simulator dials the agent at the contact number you supply. An outbound *scenario* makes the agent play the caller; it does not reverse who physically dials.

<Steps>
<Step title="Ask the builder for a personal mailbox">

*Add an outbound tent repair callback. Sam's personal mailbox says “You've reached Sam. Leave a message.” Check that the agent waits for the tone, names Ridgeline Outfitters, explains why it called, and gives a next step without asking Sam a question.*

In the scenario the builder authors, voicemail requires both `call_direction: outbound` and `answered_by: voicemail`. Without `answered_by`, the recipient is a person. The greeting goes in `persona.initial_message`; specify `voicemail_style` so the builder knows which mailbox to test. The default style is `personal`.

{/* MEDIA: Voice environment builder with the Ridgeline mailbox request and the resulting scenario. */}

</Step>
<Step title="Run only that case">

In **Scenarios**, tick the mailbox case, choose **1×** under **Repeats**, then choose **Run simulation**. A mailbox greets once and does not answer further questions.

{/* MEDIA: Scenarios selection bar showing one mailbox case selected and one repeat. */}

</Step>
<Step title="Listen for the agent's first words after the greeting">

[Open the call](/docs/environments/guides/read-run-results). Use the recording to check the timing against the tone, and the transcript to check the message. For example, “This is Ridgeline Outfitters. Your tent repair is ready. Please call the store to arrange pickup” gives Sam a next step. “When would you like to come in?” needs an answer the mailbox cannot give.

{/* MEDIA: Mailbox call result with audio playback and the transcript of the callback message. */}

</Step>
</Steps>

### Compare mailbox styles

| `voicemail_style` | What to listen for | Expected agent behavior |
| --- | --- | --- |
| `personal` | A personal greeting followed by a tone | Wait for the tone before leaving the pickup message. |
| `carrier` | A network greeting that names nobody, then a tone | Give a callback instruction without assuming Sam answered. |
| `operator` | A longer formal announcement before the tone | Wait through the entire announcement so the start of the message is audible. |
| `full` | An announcement that the mailbox cannot record. No tone. | End the call without leaving a message. |

If your suite has room for a second mailbox, ask for the same callback with `voicemail_style: full` and the greeting “This mailbox is full and cannot accept new messages.” Select the personal and full cases together. The successful outcome changes from *leaves a message* to *ends without leaving one*. Neither case should require a customer to agree to a pickup time.

## Test whether Retell can dial out

Use a hosted Retell **run test** for this check, not the environment's phone connection. You need a Retell test agent, a Retell number that can place outbound calls, and a hosted runner configured for voice calls and number leasing.

| Number | Where it comes from | Ridgeline example |
| --- | --- | --- |
| From | Your Retell agent's originating number, in E.164 format | A test line in the form `+12025550141`, not Sam's number. |
| To | The runner reserves a destination and releases it after the run | Retell dials the simulated recipient at this number. Do not enter a customer number as the destination. |

<Steps>
<Step title="Configure the originating agent">

[Create a voice agent definition](/docs/api/agent-definitions/createagentdefinition) with `agent_type: voice`, `provider: retell`, `authentication_method: api_key`, and `inbound: false`. Use the test agent's Retell ID for `assistant_id`, its provider key for `api_key`, and the full **originating** number for `contact_number`.

</Step>
<Step title="Choose the calls to place">

[Create a run test](/docs/api/run-tests/createruntest) for that agent. Start with one scenario containing one row: Sam answers and can collect the tent today. To test reuse, attach a second one-row scenario where Sam asks to collect it tomorrow. This requires a compatible runner with `HOSTED_RUNNER_LEASED_ROOM_REUSE` enabled; otherwise select one row per run.

</Step>
<Step title="Start the test once">

The following request starts a real phone test for the first scenario. Set `FI_API_KEY` and `FI_SECRET_KEY` to your Future AGI credentials, `RUN_TEST_ID` to the saved test UUID, and `SCENARIO_ID` to the attached scenario UUID. To test both scenarios on the same leased number, include both UUIDs in the `scenario_ids` array in **one** request.

```bash
curl --fail-with-body --silent --show-error \
  --request POST "https://api.futureagi.com/simulate/run-tests/${RUN_TEST_ID:?Set RUN_TEST_ID}/execute/" \
  --header "X-Api-Key: ${FI_API_KEY:?Set FI_API_KEY}" \
  --header "X-Secret-Key: ${FI_SECRET_KEY:?Set FI_SECRET_KEY}" \
  --header 'Content-Type: application/json' \
  --data "{\"scenario_ids\":[\"${SCENARIO_ID:?Set SCENARIO_ID}\"]}"
```

A successful response includes `execution_id`. It identifies the run, not a call, and does not mean a recipient picked up. With reuse enabled, the runner waits for the first call to leave the room before dialing the same destination for the second case. Two separate requests do not guarantee the same destination.

</Step>
</Steps>

## Read the result and handle limits

- **Did the calls connect?** In the [call history](/docs/api/run-tests/getcallexecutions), match `test_execution_id` to the returned `execution_id`. For the two-row example, look for two call rows with different `id` values. The platform rows expose `status` and `ended_reason`. Retell's own call records use a separate `call_id` for each accepted call, with `call_status` and `disconnection_reason`.
- **Did the agent do the right thing?** A Retell `not_connected` record is a final connection outcome, not evidence of a poor message. If Retell rejected the request before issuing a call ID, check the dialing error rather than looking for a transcript. On a connected outbound call, Retell's `agent` speaker is Ridgeline and `user` is the simulated recipient. Speaking over the mailbox greeting is a behavior you can evaluate.
- **Why won't the builder add another mailbox?** Voicemail must be enabled for the environment runner. For suites of four or more scenarios, the mailbox limit is 5% of the suite, rounded up: one in a suite of 20, two in a suite of 21. Use different greetings and styles when comparing two mailboxes. The limit is on the authored suite, not the subset you select to run.
