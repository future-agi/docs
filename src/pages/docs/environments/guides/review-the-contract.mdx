---
title: "Review the contract"
description: "Check what the builder read from your agent, and correct it through chat orchestration before you trust a run"
---

Do this once, after the environment shows **Ready** and before your first run. The [contract](/docs/environments/concepts/contracts) is the builder's record of your agent's tools, rules and use cases, and every scenario and grade is written from it, so a wrong reading shows up later as runs that test the wrong thing. The usual mistakes are a tool that was missed, a rule that was paraphrased into something weaker, and a use case the agent doesn't actually handle.

## Check Overview

Open the environment from **My Environments**. **Overview** states what was connected: the **Channel**, voice or chat, the **Connector** it was reached through, and the **Test subject**, the agent being tested. Under **Capabilities**, **Read from source** lists what the builder found:

- **Tools**: every tool the agent can call, as it is named in your agent
- **Rules**: the hard constraints the agent must hold, quoted from its instructions

Check both lists against what you know the agent does. A tool missing here is a tool no scenario will exercise, and a rule missing here is a rule no run will check.

## Check the Contract tab

Open **Contract** for the full view, and check each section:

| Section | Check that |
|---|---|
| Capability graph | Every item under **Flows** is a use case the agent is built for, and **Guardrails** matches the rules on Overview |
| World state | The tables and row counts mirror the data your agent's tools act on |
| Tools | Every tool is there, including any Overview missed |
| Run end conditions | The limits fit how long a real conversation with your agent takes |

<img src="/images/docs/environments/guides/review-the-contract/environment-contract.png" alt="The Contract tab headed Environment contract, with a capability graph branching from the agent into 5 tools, 6 flows, 30 personas and 7 guardrails" style={{ borderRadius: '5px' }} />
*The capability graph shows everything read from the agent as one picture*

If everything matches, the environment is ready to [run](/docs/environments/guides/run-a-simulation).

## Correct what is wrong

Tell [chat orchestration](/docs/environments/concepts/chat-orchestration), on the left of the workspace, what is wrong and what is true, in plain language:

- "The agent also has a `cancel_order` tool that takes an order ID"
- "There is a rule that the agent never quotes a delivery date; add it"
- "The refund tool needs the order ID, not the email address"

Then confirm the correction landed: reopen **Overview** or **Contract** and look for the tool or rule you named. If it isn't there, restate the correction more specifically, naming the tool or quoting the rule.

A correction applies to what the builder writes from then on. To make sure the next run tests the corrected part, ask for scenarios that exercise it, such as "add two scenarios that test the new rule".

<Note>
A correction changes the environment's understanding of your agent, never the agent itself. If the agent's own behavior is what is wrong, change it where the agent lives, on its hosted platform or in its code, then run the environment again.
</Note>

## Check the build settings

**Settings** records how the environment was built, and everything there is fixed at build time except the name:

- **Environment info**: rename the environment here
- **Environment variables**: the values the agent was built with, with secrets never shown

To build from a different source or with different values, [build a new environment](/docs/environments/guides/build-an-environment).
