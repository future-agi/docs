A **run** plays an environment's [scenarios](/docs/environments/concepts/scenarios-and-trials) against your agent and grades each conversation. This guide starts a run for the whole suite or for a selection, follows it until it finishes, and shows how to read the run history it adds to.

<Note>
A run needs an environment in **Ready** status with at least one scenario; [Build an environment](/docs/environments/guides/build-an-environment) covers getting one. Evaluations are optional, but a run without them records conversations with nothing to say whether the agent was right, so [add evaluations](/docs/environments/guides/add-evaluations) first.
</Note>

## What a run plays

A run takes the scenarios you pick and plays each one as many times as you ask, and every play is its own **call**: a phone call for a voice agent, a conversation for a chat agent. For an agent read from code, each call starts from a clean copy of the world, so one call never sees what another changed. When a call ends it is graded against its scenario's sub-goals and the environment's evaluations.

## Choose how many trials

Each scenario can play more than once in a run. The count is called **Repeats** on the whole-suite control and **trials** everywhere else, and they are the same thing: how many times each scenario plays. A run's size is scenarios times trials, so 4 scenarios at 3 trials is 12 conversations.

A conversation with an AI agent is not deterministic, so one pass can succeed by luck. Use 1 trial to check that an environment works, and 3 or more when you want to trust the result: the same scenario passing three times out of three says much more than once out of once.

## Run every scenario

At the top right of the environment workspace, set **Repeats** to **1×**, 3×, 5×, 8× or a custom number. The menu shows the total number of conversations, such as `30 scenarios × 1 repeat = 30 runs`. Click **Run simulation**, check the scenario count and repeats in the dialog, and click **Run simulation** again to start. The run appears at the top of the **Runs** tab.

## Run selected scenarios

To run part of the suite, open the **Scenarios** tab and tick the scenarios you want. A bar appears with the number selected, a trials picker, an estimate of how long the run takes, and **Run simulation** labeled with the count, such as **Run simulation (4)**. Set trials from 1 to 20 and click it. The run appears on **Runs** like any other, with its scenarios and trials recorded.

## Follow the run

On **Runs**, the run's status moves through these:

| Status | What is happening |
|---|---|
| Queued | Waiting to start |
| Provisioning | Preparing a clean copy of the world for each scenario |
| Running | Conversations are in progress |
| Grading | Each conversation is being scored against its scenario's sub-goals, the checks written for it, and the environment's evaluations |
| Completed | Every conversation finished and was graded |
| Failed | The run could not finish |
| Cancelled | You stopped the run |

You can leave the page while a run is going. To end it early, open the run and click **Stop simulation**. If a run fails, open it to see which calls errored and why, then use **Run again**; [Environment FAQ & fixes](/docs/environments/troubleshooting) covers the common causes.

## Read the Runs tab

**Runs** opens with a **Simulations summary**: a chart of each evaluation's average across runs, so you can see whether a change to your agent moved its scores. Pick one evaluation or keep all of them in the menu above the chart.

Below it, the runs table lists every run:

| Column | What it shows |
|---|---|
| Scenarios, Trials | What the run played |
| Simulations | The total conversations, scenarios times trials |
| Pass | The share of conversations that passed |
| Duration, Tokens | How long the run took and the tokens it used |

## Runs are comparable

Each run records the agent version it ran against, shown in the run's name, such as **Run 4 · agent v1**. Scenarios belong to the environment, so the same suite runs against every version of your agent: change the agent, run again, and the two runs differ only by what you changed, which is what makes the **Simulations summary** trend meaningful.

Scenario edits you make between runs, whether by hand or through [chat orchestration](/docs/environments/concepts/chat-orchestration), are played by the next run. Runs that already finished keep the scenarios they played.
