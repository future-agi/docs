---
title: "Lock versions"
description: "Lock an environment version and a scenarios version together with train and test splits, so runs on them use the same scenarios"
---

A score only means something next month if it was measured on the same scenarios and graded the same way. **Lock** freezes the environment's current versions together, for example **environment v3, scenarios v2**: the scenarios, their train and test splits and the scorer can't change after that. Each lock gets an id, such as **lock 2026.11.1**.

## What a lock holds

A lock holds the environment's default **environment version** and **scenarios version**. Versions never change once they're saved, so a lock stays exactly as it was. When you edit the environment, the edit makes a new, unlocked version, and the lock keeps the old one.

Every lock splits its scenarios into two sets:

- **Train**: the scenarios a team or a coding agent learns from
- **Test**: the scenarios that check the result, which the learning never sees

Only scenarios that a run can score get a split. A scenario that needs a tool that reaches production can't pass in a controlled test, so it gets no split either. The split is picked for you, so nobody can tune the test set by hand:

- The test set is about 30% of a small suite and 20% of a large one, and never more than 30%. A suite of 20 scenarios gets 6 test scenarios. A suite of 500 gets 100.
- Each use case is split in proportion, and every use case gets a test scenario while the test set stays within 30% of the suite. On a small suite with many use cases, the smallest ones stay in train until they gain scenarios.
- A use case with two or more scenarios keeps at least one in train. Use cases with a single scenario are split together as one group.
- A scenario keeps the split it got the first time it was locked, in every later lock. A growing suite adds new scenarios to fill the test set. It never moves a test scenario into train.

## Lock the current versions

Open the environment and go to **Overview**. The card reads **Lock environment v3, scenarios v2** and shows:

- the versions it would lock, as `agent v4 · acme/support-bot@main · a1b2c3d · environment v3 · scenarios v2`
- **Reference passes**: **Passed** when the scenarios version was proved against this environment version, or **Not proved**
- the split it would get, for example `Train 14 · Test 6 scenarios once locked.`

Click **Lock versions** and confirm. The card now reads **Locked: environment v3, scenarios v2**, with a line such as `Lock 2026.11.1 · 26 Nov · Train 14 · Test 6 scenarios · scorer frozen`. The id is the month you locked in, then the lock's count in that month.

Workspace members who can edit the environment can lock it. Viewers can't.

### When you can't lock yet

The card says why, in one sentence, and the lock button stays off:

- **Add scenarios to lock: a test split needs at least 4.** A suite needs at least 11 scenarios that a run can score for the test set to reach 4. Click **Add scenarios** to open the Scenarios tab, then add and save them.
- **This environment is building or its last build failed. Lock it once a build finishes.** Wait for the build to finish, or fix it and build again.

If someone changed the default versions while you had the page open, the lock is refused and the card shows the current versions. Check them and lock again.

## Unlock

An owner or admin of the organization, or a workspace admin, can unlock. On the card, click **Unlock**, then **Unlock versions** to confirm.

Unlocking changes nothing about the versions themselves. The lock moves to **Earlier locks**, marked unlocked, and its scores stay, but they're no longer a locked comparison. Each scenario keeps its train and test split. Lock the same versions again, and you get a new lock with a new id and the same splits.

## Delete an environment with a lock

An environment with a lock can't be deleted. Deleting it shows **Lock 2026.11.1 covers this version. A workspace admin or owner must unlock it first.** An admin can click **Unlock versions** right there, then delete. A lock stays when you edit the environment, so look under **Earlier locks** too: each lock there has its own **Unlock**.
