Connect a code agent from GitHub or a folder, get its first version checked, then build an environment from it. [Agents & versions](/docs/environments/concepts/agents-and-versions) explains how agents and their versions fit together.

## Before you start

- Only voice and chat agents can be connected. When you connect, your code is read to find the agent and describe it; [Supported agents](/docs/environments/reference/supported-agents) lists the frameworks that reading recognizes
- An administrator has to turn connecting from code on for the workspace. If **Connect agents** opens the environment build page instead of the Connect page, it isn't on yet, so ask an administrator
- A private repository needs the GitHub App, and only an admin of the GitHub account or organization can connect its installation
- Have the values your agent reads at startup, such as API keys, ready to enter

## Open the Connect page

Go to **Agents**, open the **Connected agents** tab, and click **Create agents**, then **Connect agents**. The **New agent** page lists the ways to connect an agent. **GitHub** and **Upload a folder** are available today, and everything else on the page is coming soon.

Click **Connect** on one of the two to open its drawer. If you close the drawer partway, you're asked whether to discard the agent. Reloading the page brings you back to the same step.

## Connect from GitHub

The **GitHub** drawer offers two ways in:

- **Connect GitHub** lists your repositories, private ones included. It needs the GitHub App installed for the workspace
- **Paste a repo link** starts straight away from a public repository, such as `https://github.com/owner/repo`, with an optional **Branch or tag**. Click **Find agents**, then go on to [Pick and name the agent](#pick-and-name-the-agent)

A private repository can't be pasted as a link. Connect GitHub and choose it from your repositories instead.

### Private repository: install the GitHub App if needed

If the app isn't installed for the workspace yet, click **Install GitHub App**. It opens **Settings** > **Integrations**, where the GitHub card installs the app on your repositories, then brings you back to the drawer with a **Repository** field.

If it doesn't work:

- **An organization owner has to approve the install**: connect again once they approve it
- **Another GitHub account is already connected**: a workspace connects to one GitHub account at a time, so disconnect the old one on the integration card before you connect another

### Private repository: pick the repository and branch

Choose the repository from **Repository**. The branch starts at the repository's default branch; click **Change** to read another one. If a repository is missing from the list, click **Missing a repository or an account? Add it on GitHub**. It reopens the GitHub App install, where you can add the repository or account.

Click **Find agents**, then go on to [Pick and name the agent](#pick-and-name-the-agent).

## Upload a folder

Use **Upload a folder** when the code isn't on GitHub. Pick the folder that holds the agent's code, not a whole repository. Secrets files and dependencies are left out of the upload.

Click **Find agents**. To skip the list and connect the whole folder as one agent, click **Connect the uploaded folder anyway**. Otherwise go on to [Pick and name the agent](#pick-and-name-the-agent).

## Pick and name the agent

The code is read for agents, and each one found is listed with its name, framework, folder and entry file, rough counts of its tools and prompt files, and how confident the reading is. Pick the one you mean. A lower confidence means the reading is less sure it found the right agent, so check the entry file and folder before you pick it, and look it over again on the **Definition** tab later.

If the agent you expect isn't listed, or the list is empty:

- **GitHub**: click **Not in the list? Name its folder** and enter the **Folder of the agent**, relative to the repository root
- **Upload**: click **Connect the uploaded folder anyway**, which connects the whole folder as one agent. Upload the folder that holds the agent's code to get the right one

If connecting stops with "Choosing a folder isn't supported yet; connect the repository root", naming a folder isn't turned on yet. Go back and connect the repository root instead, leaving **Folder of the agent** empty.

Click **Next**, then fill in:

- **Name**: starts as the agent's name in the list, or the folder's name for an upload
- **Environment values**: a value for each name the code reads. They're stored as the agent's credentials and never shown again. Click **Add a value** for a name the reading missed. You can leave one blank to skip it, but if the agent needs a value you skip, its first version stops and asks for it (see [Check the first version](#check-the-first-version))

Click **Connect agent**.

## Check the first version

You land on the agent's **Overview** while its first version, v1, is stored, read and checked. A banner shows each step, and the **Definition** tab fills in with what the reading found.

Two banners can need you, in this order:

- **Missing credentials**: expected when you skipped a value, not an error. The banner reads "Couldn't read v1" but shows a field for each missing name. Fill them in and click **Save credentials**. That makes a new version with them and checks it
- **Confirming what was found**: once the version passes, a banner asks you to check the entry, prompt, tools and model on the **Definition** tab. Click **Looks right**. Every agent you connect here needs this once, and building an environment from it is refused with "Check what we found about this agent before building from it" until you do

If v1 fails for another reason, the banner also reads "Couldn't read v1" but has no fields to fill in, just the reason. [Environment FAQ & fixes](/docs/environments/troubleshooting#fixes-while-connecting-an-agent) lists each message and what to do about it.

The first version that passes its check becomes production, the version environments test by default. Later versions wait for you, as [Manage agent versions](/docs/environments/guides/manage-agent-versions) covers.

## Build an environment

Click **Build environment** on the **Next steps** card of the **Overview**, or on the agent's **Environments** tab. The environment is built from the version in production unless you pick another. [Build an environment](/docs/environments/guides/build-an-environment) covers the build itself.
