---
title: "Add test conditions"
description: "Make a scenario's tool time out, fail or need approval during a run"
---

Hide a test condition on a scenario's tool, so the tool misbehaves while the agent is tested. Use one to see how your agent copes when a tool times out, fails, is unavailable or needs an approval first. The call's [World state](/docs/environments/guides/read-run-results#world-state) then shows what the tool did.

<Note>
If the scenario editor has no **Hidden · test conditions** section, test conditions are not turned on for your deployment. See the [configuration reference](/docs/self-hosting/configuration/reference#agent-simulations-in-hosted-sandboxes).
</Note>

## Add a condition

1. Open the environment's **Scenarios** tab and click the pencil icon on the scenario's row to open **Edit scenario**, as in [Work with scenarios](/docs/environments/guides/work-with-scenarios#edit-a-scenario)
2. Scroll to **Hidden · test conditions**. A scenario without any reads **Tools behave normally**
3. Click **Add a test condition**.
4. Pick the **Tool**. If a tool is greyed out, it runs inside your agent, and hovering shows **This tool runs inside the agent, so it cannot be held**. Pick another tool
5. Pick **What happens**. It stays disabled until you pick a tool
6. Fill in the fields that mode asks for, then click **Add a test condition** under the fields. It stays disabled until a tool and a mode are picked and the fields are valid. **Cancel** beside it closes the form without adding

<img src="/images/docs/environments/guides/add-test-conditions/test-conditions-empty.png" alt="The Edit scenario panel scrolled to Hidden · test conditions, reading Tools behave normally, with the Add a test condition button" style={{ borderRadius: '5px' }} />
*A scenario with no test conditions reads Tools behave normally*

Each mode asks for its own fields:

| What happens | Fields it asks for | Ranges |
|---|---|---|
| **Times out before it runs** | **On which call**, **Delay in seconds** | Call 1 or higher, default 1. Delay 0 to 30, default 30 |
| **Runs, then the answer is lost** | **On which call**, **Delay in seconds** | Call 1 or higher, default 1. Delay 0 to 30, default 30 |
| **Unavailable** | **On which call** | Call 1 or higher, default 1 |
| **Answers with an error** | **On which call**, **Status**, **Message** | Call 1 or higher, default 1. Status 400 to 599, default 500. Message up to 500 characters |
| **Needs approval first** | **Approval it needs**, **Approved when (optional)** | None |

<img src="/images/docs/environments/guides/add-test-conditions/test-condition-approval.png" alt="A test condition on the apply_discount tool set to Needs approval first, with Approval it needs set to approvals.put by Alex Vance or Sam Rivera and an empty Approved when field" style={{ borderRadius: '5px' }} />
*With Needs approval first, pick the actor whose approval the tool waits for*

## Save the scenario

Click **Save scenario**. Conditions are checked when you save. To remove one, click the trash icon next to it.

## Fix a refused condition

A condition the test world cannot apply is refused when you save, with a message in this shape:

```text
Scenario X has a test condition the test world cannot apply: ...
```

The text after the colon says why. For **Needs approval first**, the tool must be one that writes, and the scenario needs an actor who can approve. Give an actor the approval action in [Add actors](/docs/environments/guides/add-actors), then save again.
