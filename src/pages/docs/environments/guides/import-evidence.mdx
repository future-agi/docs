The conversations that went wrong with real callers make the best tests. Import one as evidence and it becomes a [scenario](/docs/environments/concepts/scenarios-and-trials) in your environment that you can run again. Importing only starts a review: nothing runs, and nothing joins the suite until you add it. Once the cases are in, [Epoch](/docs/epoch) can fix the failures they show.

<Note>
A **regression test** is a scenario that records something a real customer did. Evidence from production becomes one. A conversation from a Simulator project always becomes a plain test, because no customer was in it. Transcripts and dataset rows become regression tests only if you mark them as production when you import them, and the mark can't change afterwards.
</Note>

<Prerequisites title="Before you start">
- An [environment](/docs/environments/concepts/understanding-environments) to add the cases to.
- The evidence: sessions or voice calls in an [Observe](/docs/observe) project, [dataset](/docs/dataset) rows, or transcripts. One import takes up to 20 sessions or calls, 20 rows, or 20 transcript files.
- For dataset rows and transcripts, know whether they come from production before you import them. That mark decides whether they become regression tests.
</Prerequisites>

## Import from Observe

1. Open the Observe project and go to its [sessions](/docs/observe/concepts/sessions), or to its voice calls for a voice agent.
2. Tick the ones you want, up to 20 at a time. Tick them one by one: **Select all** isn't available for this.
3. In the bar that appears above the list, open **Actions** and choose **Create environment test**.
4. Choose the **Environment** to add them to.
5. Click **Create environment test** again.

   The environment opens on its **Scenarios** tab, with the import ready to review.

<img src="/images/docs/environments/guides/import-evidence/observe-create-environment-test.png" alt="The Sessions tab of the refill-line-production Observe project with three sessions ticked, the 3 selected bar above the list, and its Actions menu open on Create environment test" style={{ borderRadius: '5px' }} />
*Tick the sessions where your agent went wrong, or where it got something right that it must keep doing*

## Import dataset rows

1. Open the dataset and tick the rows, up to 20 at a time.
2. Click **Create environment test**.
3. Set the **Conversation column**: the column that holds the conversation, as chat messages in JSON or as lines that start `User:` or `Agent:`. Audio-only rows aren't supported yet.
4. Under **Label columns (optional)**, pick up to 10 columns to read as context, such as the caller's intent.
5. Under **Expected outcome column (optional)**, pick the column that says what should have happened. The scenario's expected behavior is written from it, and the environment's rules win if the two disagree.
6. Tick **These rows come from production** for rows from real conversations, to make regression tests.
7. Choose the **Environment**.
8. Click **Create environment test**.

   The rows are read again from the dataset each time you review the import.

## Add a transcript

1. On the environment's **Scenarios** tab, click **Add scenarios**.
2. Choose **Upload transcript or file**.
3. Paste a transcript, or click **Upload files** to add up to 20 files.
4. Pick the **Format**: **JSON messages**, **User: / Agent: lines**, or **CSV with role and text**.
5. Name the transcript.
6. Tick **These transcripts come from production** if they do.
7. Click **Create environment test**.

Emails, phone numbers, and card and ID numbers become placeholders before the text is stored. An import keeps up to 60,000 characters, shared by its files.

**Add scenarios** also has **From production** and **From a dataset**, which take you to Observe and to your datasets, the other two starting points.

## Review the imported cases

The **Review imported evidence** drawer opens on the import, such as `3 sessions from Observe`. Each source is one **case**, and the drawer has four steps: **Evidence**, **Starting state**, **Drafted scenarios** and **Add to the suite**. The drawer also says how many values of personal data become placeholders before anything becomes scenario text.

1. Under **Evidence**, read the card for each case: what the record holds, what it's missing, and a link back to its source.

   A case the environment already holds shows **Already imported**, with a link to the existing case.

2. Under **What should this case's scenario be?**, choose what the case becomes, such as **Reproduce the failure as a regression test** or **Keep this success as a regression test**.

   The card then says what the scenario keeps from the evidence and what it adds. **Set every waiting case to** picks one choice for all of them.

3. Check **Starting state**.

   The records your agent's tools read first, such as an earlier refund, aren't in a conversation. The draft marks them synthetic, so the test isn't an exact replay.

4. Click the draft button at the bottom of the drawer, such as **Draft 3 scenarios**.

   **Drafted scenarios** shows how the drafting is going. Drafting takes up to 90 minutes, and you can close the drawer while it runs. Don't edit the environment until it ends: an edit made meanwhile blocks the drafted cases.

5. Click the save button at the bottom of the drawer, such as **Save 3 to the suite**.

   If the environment has unsaved changes, the button reads **Add 3 to unsaved changes** instead; press **Save** in the draft bar to make them live.

<img src="/images/docs/environments/guides/import-evidence/review-imported-evidence.png" alt="The Review imported evidence drawer for 3 sessions from Observe, with the line saying 4 values of personal data will be replaced with placeholders, Set every waiting case to, a card for each session with its What should this case's scenario be? choice, and Draft 3 scenarios at the bottom" style={{ borderRadius: '5px' }} />
*You decide what each case tests; the builder writes the scenario from that*

## Pick up an import later

Imports you haven't finished stay under **Draft imports** on the **Scenarios** tab, each with its source and where it got to, such as `drafted, not added` or `blocked: import again to retry`. Click **Resume** to open its review again, or **Discard** to drop it. Discarding never removes cases already added to the suite.

A case is blocked when it can't be drafted or added, for example because the environment changed after it was drafted. Import its source again; the new import replaces the blocked case.

## Run the imported cases

1. Once the cases are in the suite, [run the environment](/docs/environments/guides/run-a-simulation). To play only the imported cases, tick them on **Scenarios** and run that selection.
2. Open the finished run and read each call's sub-goals, verdicts and transcript.

## Run Epoch on the imported failures

When the run finishes and some of its failing scenarios came from imported evidence, **Run Epoch** shows in the run's header, next to **Debug failures**. Hover over it to see how many of the failing scenarios came from imported evidence.

<img src="/images/docs/environments/guides/import-evidence/run-epoch-imported.png" alt="The header of Run 4 of the Northwind Pharmacy refill line, with Run Epoch between Export and Debug failures above the run's Test runs tab, which shows Failed 14 and Passed 16" style={{ borderRadius: '5px' }} />
*Run Epoch here starts from the failures your imported cases showed*

The launch form starts with the imported failing scenarios as the cases to fix. If there are too few, it adds more failing scenarios from the run to reach the minimum, and says how many of each it picked. [Run Epoch](/docs/epoch/run-an-epoch#pick-the-cases-to-fix-and-protect) covers the rest of the form. When you ship the winner as a pull request, its description says where the cases came from.
