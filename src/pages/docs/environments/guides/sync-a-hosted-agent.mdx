---
title: "Sync a hosted agent"
description: "Pick up changes to a Vapi, Retell, LiveKit or phone agent as a new agent version"
---

To pick up a change you made on Vapi, Retell, LiveKit or a phone platform, open the agent and click **Sync** for a Vapi or Retell agent ([steps](#sync-a-vapi-or-retell-agent)) or **Add version** for a LiveKit agent or a phone agent, one connected by its phone number ([steps](#add-a-version-to-a-phone-or-livekit-agent)). These agents run outside Future AGI, so a change you make there isn't seen until you bring it in as a new version. [Agents & versions](/docs/environments/concepts/agents-and-versions) explains how versions work.

You need an environment already built on the agent. These agents are made when you [build an environment](/docs/environments/guides/build-an-environment) on them. Open one from **Agents** > **Connected agents**. The button is on the right of the agent's header.

A new version does not change what the environment runs. The environment moves to it only when you [rebuild the environment](#rebuild-the-environment-on-the-new-version).

## Sync a Vapi or Retell agent

Click **Sync**. The agent is read from its platform: for Vapi, the assistant and the reusable tools its model lists; for Retell, the agent's settings and, depending on the agent, its prompt, tools and model, or its flow.

The first Sync makes no new version. It records what it found on the current version, as the baseline for later ones. After that:

- A Sync that finds a change makes a new version, which is [checked](#check-the-new-version)
- A Sync that finds nothing new leaves the current version as it is

## Add a version to a phone or LiveKit agent

After you change a phone or LiveKit agent, add a version so scenarios and checks use its new prompt and settings. Neither can be read from where it runs, so you describe the change yourself.

1. Click **Add version**. The dialog starts from the agent's current version
2. Change the fields to match your live agent. Take the values from the phone platform or your LiveKit project
   - **System prompt**: the prompt your agent answers calls with. LiveKit doesn't expose it, so paste it in. It only seeds scenarios, so editing it does not change the live agent
   - **Phone number**, phone agents only: the number the platform calls, in international format such as `+14155550100`. Calls are always inbound
   - **LiveKit agent name**, LiveKit agents only: the name your LiveKit worker registers with. Each call dispatches it into the room
   - **Agent speaks first**: turn it on if your agent greets callers first, so the simulator waits for it
3. Click the save button, which names the next version, such as **Save as v2**. It stays disabled until something has changed and the fields are valid. If what you save matches a version that already exists, no new version is made

The new version is [checked](#check-the-new-version) like any other.

## Check the new version

A new version is checked first, to confirm it can be used. Its status shows in the version list and in a banner on the agent page. If the check fails, see [Manage agent versions](/docs/environments/guides/manage-agent-versions).

## Rebuild the environment on the new version

Once the check has finished, rebuild the environment to move it to the new version. A hosted agent belongs to the environment that built it, so there's no production step on the agent itself.

1. Click the environment's name next to **Managed by** in the agent's header
2. Find the rebuild card in the environment's build console. It reads like **Agent v2 is available**
3. Click **Rebuild** to update the environment for the new version and make it the environment's default, or **Skip** to leave the environment as it is

If you don't see the card, check that the version's check has finished and passed, and that you opened the environment named next to **Managed by**. If the change doesn't affect that environment, there is no card and nothing to rebuild.

After a rebuild, [run a simulation](/docs/environments/guides/run-a-simulation) to test the new version.

## What a synced version contains

A synced version keeps what describes how the agent behaves and hides anything that could be a secret, so you know what a version holds. It keeps:

- Tool names, descriptions and parameters
- Tool endpoint URLs, without query strings or credentials
- Model settings such as temperature
- The voice, language and speed

It hides:

- API keys, tokens and passwords
- Header and query-parameter values
- Sample values on tool parameters whose names look secret
