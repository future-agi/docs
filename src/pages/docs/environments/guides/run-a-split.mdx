---
title: "Run a split"
description: "Run the train or test split of a locked version, see which locked version each run used, and compare split runs fairly"
---

A [locked version](/docs/environments/guides/lock-a-version) splits its scenarios into **train** and **test**. This guide runs one of those splits, shows where each run records the locked version it ran under, and explains which runs compare.

<Note>
You can run a split only when the environment and scenario versions you pick are locked. [Lock a version](/docs/environments/guides/lock-a-version) covers locking them.
</Note>

## Pick a split

Open the environment and click **Run simulation**. The **Run simulation** dialog asks which agent, environment and scenario versions to use. When the environment version and the scenario version you pick are locked, a **Split** field appears under them:

- **All scenarios**: the run plays the scenarios you selected, as a run without a split does
- **Train split · 23 scenarios**: the run plays the train scenarios of the locked version
- **Test split · 10 scenarios**: the run plays the test scenarios of the locked version

Pick **Test split** and the dialog says what will run, such as `Runs the test split of locked version 2026.11.1: 10 scenarios.` Set the repeats as for any run, then click **Run**.

If you pick versions that aren't locked, the **Split** field goes away and the run plays the scenarios you selected.

### Which scenarios a split runs

A run of a split plays every scenario of that split in the scenario version, in suite order. You don't need to select them on the **Scenarios** tab.

If you select scenarios first, each one must be in the split. A scenario from the other split refuses the run with a message such as `refund-late-order is not in the test split of locked version 2026.11.1.` Clear the selection, or pick **All scenarios**.

A run never plays a scenario that it can't score. A scenario that needs a tool that reaches production is left out, by the same rule that a lock counts scenarios with.

## See the locked version a run used

Every run of a split records the locked version it ran under when it starts. The **Runs** table and the run's header show it next to the versions, such as `locked version 2026.11.1 · test`.

A run records its own locked version, not the one its versions match now. If you unlock 2026.11.1 and lock the same versions again as 2026.11.2, the earlier runs still say 2026.11.1 and new runs say 2026.11.2. A run of **All scenarios** records no locked version, even when its versions are locked.

## Run a split again

**Run again** on a run of a split opens the dialog with the same versions and the same split. If those versions are unlocked now, the dialog says `That run's locked version is unlocked now, so this run doesn't use its split.` and runs the scenarios without a split. Lock the versions again to run the split.

## Compare split runs

When you compare two runs and either of them ran a split, the verdicts count only if both runs ran the same split of the same environment and scenario versions. Otherwise the comparison shows `Not comparable: these runs ran different versions or splits.` and gives no verdict for any scenario. Each scenario's results are still listed side by side.

Two locks of the same versions keep the same splits, so a test run under 2026.11.1 compares with a test run under 2026.11.2.

## When a split can't run

| Message | What to do |
|---|---|
| `Lock these versions to run their train or test split.` | Lock the versions on **Overview**, or pick versions that are locked |
| `… is not in the test split of locked version 2026.11.1.` | Select only scenarios of that split, or run the whole split |
| `The test split has no scenarios to run.` | Pick the other split, or add scenarios and lock the new versions |
| `A coding agent runs the whole suite. Leave out the split.` | A coding agent's run can't take a split; start the run from the dialog instead |
