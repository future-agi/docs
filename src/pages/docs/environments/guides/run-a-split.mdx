---
title: "Run a split"
description: "Run the train or test split of a lock, see which lock each run used, and compare split runs fairly"
---

A [lock](/docs/environments/guides/lock-versions) freezes an environment version and a scenario version, and splits the scenarios into **train** and **test**. This guide runs one of those splits, shows where each run records the lock it ran under, and explains which runs compare.

<Note>
You can run a split only when the environment and scenario versions you pick are locked. [Lock versions](/docs/environments/guides/lock-versions) covers locking them.
</Note>

## Pick a split

Open the environment and click **Run simulation**. The **Run simulation** dialog asks which agent, environment and scenario versions to use. When the environment version and the scenario version you pick are locked, a **Split** field appears under them:

- **All scenarios**: the run plays the scenarios you selected, as a run without a split does
- **Train split · 23 scenarios**: the run plays the train scenarios of the lock
- **Test split · 10 scenarios**: the run plays the test scenarios of the lock

Pick **Test split** and the dialog says what will run, such as `Runs the test split of lock 2026.11.1: 10 scenarios.` Set the repeats as for any run, then click **Run**.

If you pick versions that aren't locked, the **Split** field goes away and the run plays the scenarios you selected.

### Which scenarios a split runs

A run of a split plays every scenario the lock put in that split, in their order in the scenario version. The lock records its scenarios when you lock, so a later change never moves one in or out. You don't need to select them on the **Scenarios** tab.

If you select scenarios first, each one must be in the split. A scenario from the other split refuses the run with a message such as `refund-late-order is not in the test split of lock 2026.11.1.` Clear the selection, or pick **All scenarios**.

A run never plays a scenario that it can't play now. A scenario of the split that needs a tool that reaches production for the run's agent is left out, by the same rule that a lock counts scenarios with.

## See the lock a run used

Every run of a split records the lock it ran under when it starts. The **Runs** table tags it, such as `Lock 2026.11.1 · Test`, and the run's header shows it next to the versions, such as `lock 2026.11.1 · test`.

A run records its own lock, not the one its versions match now. If you unlock the versions of lock 2026.11.1 and lock them again as lock 2026.11.2, the earlier runs still say 2026.11.1 and new runs say 2026.11.2. A run of **All scenarios** records no lock, even when its versions are locked.

## Run a split again

**Run again** on a run of a split opens the dialog with the same versions and the same split. If those versions are unlocked now, the dialog says `That run's versions are unlocked now, so this run doesn't use its split.` and runs the scenarios without a split. Lock the versions again to run the split.

## Compare split runs

When you compare two runs and either of them ran a split, the verdicts count only if both runs ran the same split of the same environment and scenario versions. Otherwise the comparison shows `Not comparable: these runs ran different versions or splits.` and gives no verdict for any scenario. Each scenario's results are still listed side by side.

Two locks of the same versions keep the same splits, so a test run under lock 2026.11.1 compares with a test run under lock 2026.11.2.

## When a split can't run

| Message | What to do |
|---|---|
| `Lock environment v3, scenarios v2 to run their train and test splits.` | Lock the versions on **Overview**, or pick versions that are locked |
| `… is not in the test split of lock 2026.11.1.` | Select only scenarios of that split, or run the whole split |
| `The test split has no scenarios to run.` | Pick the other split, or add scenarios and lock the new versions |
| `A coding agent runs every scenario. Leave out the split.` | A coding agent's run can't take a split; start the run from the dialog instead |
