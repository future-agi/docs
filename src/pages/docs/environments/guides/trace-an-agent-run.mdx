## About

A transcript tells you what your agent said; a trace tells you which operations its code ran. Suppose the Ridgeline Outfitters support agent gives the same return window for a full-price tent and a clearance tent. Open each call's trace to see which return policy the agent actually looked up.

## Instrument the code that runs during a call

Start with a code agent that sends spans through traceAI or OpenTelemetry over HTTP. The Environment checks Python imports for signs of instrumentation. That check does not run your code, verify delivery, or add tracing to an uninstrumented agent. A JavaScript tracing dependency is not detected by this Python check, and a gRPC-only OpenTelemetry exporter does not qualify.

For example, the following Python module traces Ridgeline's policy lookup. Install `opentelemetry-sdk` and `opentelemetry-exporter-otlp-proto-http` in the agent's dependencies and call `lookup_return_window` from the returns handler. If the agent already configures tracing, reuse its tracer instead of creating a second provider. Leave the exporter endpoint unset in the code so the sandbox can supply it.

```python
from opentelemetry.exporter.otlp.proto.http.trace_exporter import OTLPSpanExporter
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import BatchSpanProcessor

provider = TracerProvider()
provider.add_span_processor(BatchSpanProcessor(OTLPSpanExporter()))
tracer = provider.get_tracer("ridgeline-returns")


def lookup_return_window(policy: str) -> int:
    with tracer.start_as_current_span("lookup_return_window") as span:
        days = {"full-price": 30, "clearance": 14}[policy]
        span.set_attribute("ridgeline.policy", policy)
        span.set_attribute("ridgeline.window_days", days)
        return days


if __name__ == "__main__":
    print(lookup_return_window("clearance"))
    provider.shutdown()
```

[Run a simulation](/docs/environments/guides/run-a-simulation) against the instrumented chat agent. In one scenario, ask how long you have to return a full-price tent. In the other, ask the same question about a clearance tent. Select the two scenarios and set **Repeats** to **1×** for one call per case. Open the run from the Environment's **Runs** tab. Under **Test runs**, select the full-price call, read its **Transcript**, and copy the **Conversation ID** from the header. This is the `call_execution_id`, not the trace ID.

</Step>
<Step title="Match the lookup to the answer">

Select **Traces** in the same call. Open a trace row and select `lookup_return_window` in the read-only trace detail. In **Preview**, compare `ridgeline.policy` and `ridgeline.window_days` with the transcript. Use **Copy Trace ID** and keep it with this call's conversation ID. Close the trace and repeat for the clearance call. Both spans can have the same name. The `fi.simulator.call_execution_id` span attribute identifies the call during which each span started.

</Step>

If the clearance call's span says `full-price` and `30`, investigate how the agent selected the policy. If it says `clearance` and `14` but the transcript promises 30 days, the lookup returned the expected value. Investigate how the agent used that result instead.

## Retrieve the same span with the SDK or MCP

The spans your code agent exports during a simulation go to its hidden project. You won't find that project in the ordinary Observe project list. To open a trace or span by ID, supply exactly one execution ID alongside it: `call_execution_id` for a call or `test_execution_id` for a run you can read. This selects the agent's project, not just the spans from that call. Match the `fi.simulator.call_execution_id` attribute to confirm which call produced the lookup.

### Find a trace ID without the drawer

Use the run execution ID (the last path segment in the Environment's run detail URL) and the call's conversation ID. With `FI_API_KEY` and `FI_SECRET_KEY` set for that workspace, run this in Bash:

```bash
read -r -p 'Run execution ID: ' run_id
read -r -p 'Conversation ID: ' call_id
curl --silent --show-error --fail-with-body --get \
  "${FI_BASE_URL:-https://api.futureagi.com}/simulate/v3/test-executions/${run_id}/traces/" \
  --header "X-Api-Key: ${FI_API_KEY}" \
  --header "X-Secret-Key: ${FI_SECRET_KEY}" \
  --data-urlencode "call_execution_id=${call_id}"
```

The `traces` array contains up to 200 traces for that call. Choose the `trace_id` of the trace you want. An empty array is a successful read with no matching traces. If the call ID belongs to a different run, the request returns HTTP 400 instead.

### SDK

Set `FI_API_KEY` and `FI_SECRET_KEY` for the workspace that owns the run. Use the **Conversation ID** and the dashboard's **Copy Trace ID** from the same call. The example walks the trace tree, checks the call mark, then opens the lookup by its span ID.

- **Python:** Install `python -m pip install futureagi==0.8.0`. Run the script and paste the two IDs when prompted.
- **TypeScript:** With Node.js 22.18 or later, install `npm install @future-agi/sdk@0.3.0`. Save the example as `lookup.mts` and run `node lookup.mts CONVERSATION_ID TRACE_ID`, replacing the arguments with the two copied IDs.

<CodeGroup titles={["Python", "TypeScript"]}>
```python
from fi import Client

client = Client()
call_id = input("Conversation ID: ").strip()
trace_id = input("Trace ID: ").strip()
trace = client.traces.get(trace_id, call_execution_id=call_id)
nodes = list(trace.model_dump().get("observation_spans") or [])

while nodes:
    node = nodes.pop()
    nodes.extend(node.get("children") or [])
    span = node["observation_span"]
    attrs = span.get("span_attributes") or {}
    if (
        span["name"] == "lookup_return_window"
        and attrs.get("fi.simulator.call_execution_id") == call_id
    ):
        result = client.spans.get(span["id"], call_execution_id=call_id)
        policy = result.observation_span["span_attributes"]
        print(policy["ridgeline.policy"], int(policy["ridgeline.window_days"]))
        break
else:
    print("No marked policy lookup in this trace for this call.")
```

```typescript
import { Client } from "@future-agi/sdk";

type Span = { id: string; name: string; span_attributes?: Record<string, unknown> };
type Node = { observation_span: Span; children?: Node[] };

const [callId, traceId] = process.argv.slice(2);
if (!callId || !traceId) throw new Error("Usage: node lookup.mts CONVERSATION_ID TRACE_ID");
const client = new Client();
const scope = { call_execution_id: callId };
const trace = await client.traces.get(traceId, scope);
const nodes = [...((trace.observation_spans ?? []) as Node[])];
let message = "No marked policy lookup in this trace for this call.";
while (nodes.length) {
  const { observation_span: span, children } = nodes.pop()!;
  nodes.push(...(children ?? []));
  if (span.name === "lookup_return_window" &&
      span.span_attributes?.["fi.simulator.call_execution_id"] === callId) {
    const result = await client.spans.get(span.id, scope);
    const attrs = (result.observation_span as Span).span_attributes!;
    message = `${attrs["ridgeline.policy"]} ${attrs["ridgeline.window_days"]}`;
    break;
  }
}
console.log(message);
```
</CodeGroup>

If Ridgeline selected the expected policies, the first call prints `full-price 30` and the second prints `clearance 14`.

### MCP

[Connect your MCP client](/docs/falcon-ai/guides/use-the-mcp-server) to the same workspace. Give it the conversation ID and trace ID you copied and ask: “Use `get_trace` with the trace ID as `id` and the conversation ID as `call_execution_id`. Find `lookup_return_window` whose `fi.simulator.call_execution_id` matches that conversation ID. Call `get_span` with its span ID as `id` and the same `call_execution_id`. Which policy and return window did it record?” Repeat with the IDs from the second call.

## If a trace is missing

| What you see | What to check |
|---|---|
| **Observability was not turned on** | Read the reason on the Environment. A missing instrumenter does not block the build. Add an HTTP exporter to the agent code, have the Environment read the updated code, and enable observability before running again. |
| **No trace for this call** | The call can succeed without exporting a span. Check that the selected call exercised the instrumented code and that the exporter uses the sandbox's destination, not a hard-coded collector. The call shows the code agent's traces, not production voice calls or the platform's own traces from building the Environment. |
| **Root span not stored yet** | A marked span exists, but the list has no root span for this trace. You can still open the row by trace ID. The root name, start time, status and latency appear only if the root is stored. |
| **Couldn't load this call's traces.** | Retry the read. This is a retrieval error, not evidence that the agent sent no spans. |
| SDK or MCP cannot find the trace | Without an execution ID, a lookup reads ordinary visible projects. Use a credential that can read the run, and check that you copied a trace ID for `get_trace` or a span ID for `get_span`, not the conversation ID. |
