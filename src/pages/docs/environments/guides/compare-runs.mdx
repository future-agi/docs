---
title: "Compare runs"
description: "Put 2 to 8 finished runs side by side, scenario by scenario, to see what a change to your agent or environment moved"
---

After you change your agent or your environment, run it again and compare the new run with the one before. The compare page lines up 2 to 8 finished runs scenario by scenario, with every run's call for the same trial side by side, so you can see which scenarios ended differently.

## Pick the runs

Open the environment and go to **Runs**. Tick the runs you want to compare. The header counts them, such as `3 of 8 selected`, and **Compare** opens the page once at least 2 are ticked.

- Only finished runs can be compared. A run that is still going can't be ticked.
- You can pick up to 8 runs. At 8, clear one to pick another.
- The first run you tick is the **baseline**. Every other run is read against it.

The page's address holds the runs, such as `/dashboard/simulate/environments/<environment>/compare?runs=<run>,<run>,<run>`, so you can bookmark it or send it to a teammate.

## Read the header

Each run is a pill: `Run N`, the agent version and environment version it ran, and its pass rate. The baseline carries a **baseline** tag. A run from before versioning reads **before versioning**.

Use **Add run** to bring in another finished run, or **Remove from this comparison** on a pill to drop one. The subtitle gives the totals, for example `3 runs · 12 tasks · 4 ended differently`, where a task is one scenario trial, as on a run's results page. A run that can't be compared, for example one from another environment, is named in an error with a **Remove** action.

**Score distribution** charts one evaluation's scores across the runs. **Evaluation** chooses which one.

## Go scenario by scenario

The table has one row per scenario trial, such as `check-refill-status · Trial 2`, with one line per run underneath. A line shows the run's call: its outcome, how many sub-goals it met, such as `3/4 sub-goals`, and the same columns as a run's results page. **Columns** chooses which show.

- Rows that ended differently across runs come first. A scenario's verdict, such as improved or regressed, is worked out across all its trials and shown on each of its trial rows.
- A run that never played a scenario reads **Not run**.
- The search box, filters and **Group by** work as on a run's **Test runs** tab, and a scenario stays in the table if any call from any run matches.
- Click a row, or tab to its scenario name and press Enter, to open **Calls across runs**. It shows every run's call for that trial side by side, with **Open call** to go to the full call.

### Show diff

**Show diff** puts an arrow on each number that moved against the baseline's call for the same trial, green when it got better and red when it got worse. Lower is better for duration, latency, tokens, turns, interruptions and cost, and higher is better for everything else. Values that look the same on screen draw no arrow.

### Edited and Can't verify

Scenarios are paired by their key, so an edited scenario stays on the same rows. If a run played a version of the scenario that differs from the baseline's, for example a different persona, instruction, tests, sub-goals, branch, background noise or turn limit, the row shows a yellow **Edited** tag under the use case, with the runs that played the edited version, such as `Run 3 played the edited version`. The comparison still stands, but read it with that in mind.

A run from before versioning was not pinned to a scenario version, so its scenario can't be checked against a pinned baseline, or the other way round. Those rows show **Can't verify** with the runs it applies to.

## Scores that are still arriving

A finished run can still be grading its calls. While any compared run is still scoring, the page refreshes every few seconds and stops when all of them settle.

## Things to know

- With only one or two trials per scenario, one flipped call is not enough to say a scenario improved or regressed, so those rows usually read as inconclusive. Raise **Repeats** on the next run for a firmer answer.
- Compare works within one environment. Runs from another environment can't be added.
