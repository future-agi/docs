---
title: "Prove and archive scenarios"
description: "See which scenarios are proved to catch a wrong answer, prove the rest, and take a scenario out of runs without losing it"
---

A [scenario](/docs/environments/concepts/scenarios-and-trials) is only worth running if its checks can tell a right answer from a wrong one. Future AGI proves each scenario before it counts. It plays the expected handling, which the checks must pass, and a deliberately wrong answer, which they must fail. A run takes only scenarios that are proved or kept as written, and tells you about the rest before it starts.

<Note>
You need an environment in **Ready** status. [Work with scenarios](/docs/environments/guides/work-with-scenarios) covers the **Scenarios** tab itself.
</Note>

## Read each scenario's state

Open the environment and select **Scenarios**. The line above the table counts the scenarios in each state on the versions you are viewing, such as `4 proved · 1 kept as written · 0 not proved`. When some are archived, the count of archived scenarios follows; click it to show them.

| State | What it means | Runs? |
|---|---|---|
| **Active** | Proved on the saved versions: its checks pass the expected handling and fail a wrong answer | Yes |
| **Kept as written** | Part of the expected handling could not be played here, for example a tool with nothing to call; it runs, labelled not proved | Yes |
| **Not proved** | Not proved on these versions yet, or its proof found a problem | No |
| **Archived** | Taken out of runs by someone on your team | No |

To see one state only, pick it in **State** in the toolbar.

## See why a scenario is not proved

Click a scenario to open its drawer. **Status** says where it stands:
- **State**: its state, in the words above;
- **Proof**: **Proved on these versions** or **Not proved on these versions**, with the reason when there is one;
- **Wrong-way examples**: each wrong answer that was played, marked **Caught** when the checks failed it as they should, or **Not caught** when they let it pass;
- **Sources**: the rules and files the scenario relies on, each **Confirmed** or **Changed since** a version

A scenario whose checks let a wrong answer pass is not proved, because a run could pass your agent for the wrong reason. To change what it checks, ask the builder in the chat beside the environment. It rewrites the scenario and proves it again.

## Prove scenarios

Click **Validate cases not yet proved** to prove every scenario that is not proved on these versions. To prove only one scenario, click **Validate scenario against the environment** in its drawer.

Proving plays each scenario in a sandbox and can take a while. While it works, the toolbar reads `Validating 3 scenarios`, and each of those rows reads **Validating**. When it finishes, the states update. A scenario that still fails says why under **Proof**.

<Note>
Proving uses the same kind of sandbox as a run, so it is billed. Prove the scenarios you changed rather than the whole suite.
</Note>

## Check a scenario after its source changed

When a rule or file a scenario cites changes in a new environment version, the drawer shows **Source changed** with the version. Click **Compare** to see the rule before and after, side by side. Then click **Validate 2 scenarios** (the count is how many cite it) to prove them on the new version.

## Archive a scenario

Archive a scenario to take it out of runs without deleting it, for example when it tests a flow your agent no longer offers.
1. Open the scenario's drawer and click **Archive**.
2. Add a note if you like, so your team knows why
3. Confirm, and the scenario stops running and counting

To bring it back, show the archived scenarios with **State**, open the scenario and click **Restore**. A restored scenario runs again. If its versions changed while it was archived, it comes back held, and its **Status** says why.

## Run with some scenarios held back

When you click **Run simulation**, the run dialog says how many of the scenarios you picked will run, such as `6 of 8 will run`. Under **Held back** it lists each reason with how many scenarios it holds back, for example **Not validated on these versions** or **Archived**. Click **Show which** to see which scenarios a reason covers.

Click **Run** to run the scenarios that are not held back. If every scenario you picked is held back, the dialog says so and nothing runs: prove them, or pick others.
