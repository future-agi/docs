For a GitHub repository or a code upload, connecting runs a **reading**: Future AGI reads the agent's code to describe it. You then build an environment from the agent, and that is when the build runs it.

## Ways to connect an agent

The builder makes an environment by reading your agent, so the first choice is how it reaches the agent. [Build an environment](/docs/environments/guides/build-an-environment) walks through each source.

| Source | Agent types | What you need |
|---|---|---|
| Source repository | Voice, chat | A GitHub repository, see [Repository and upload requirements](#repository-and-upload-requirements) |
| Code upload | Voice, chat | A folder from your machine, see [Repository and upload requirements](#repository-and-upload-requirements) |
| Hosted platform | Voice, chat | The agent's ID on its platform and credentials, see [Hosted platforms](#hosted-platforms) |

A repository needs `owner/repo`, a branch or tag, an optional entry path, and for a private repository a GitHub App installation ID. An upload needs the folder and the entry file that defines the agent.

## Hosted platforms

**Web** and **Phone** in the last column are how the builder reaches a voice agent. A **Web** call places no phone call; a **Phone** call dials the agent's number. **Others** is the catch-all for a voice agent on a platform that isn't listed.

| Platform | Agent type | Identifier | Credential | Reached by |
|---|---|---|---|---|
| Vapi | Voice | Assistant ID | Vapi API key | **Web** or **Phone** call |
| Retell AI | Voice | Agent ID | Retell API key | **Web** or **Phone** call |
| LiveKit | Voice | Agent name | LiveKit URL, LiveKit API key and LiveKit API secret | Web call only |
| Others | Voice | Phone number | None | Phone call only |
| Retell AI | Chat | Chat agent ID | Retell API key | Not a call |

LiveKit and **Others** don't expose the agent's instructions, so you paste its system prompt into the form and the builder reads them from that.

Optional: add a GitHub repository, which lets the builder read the agent's tools and prompts from its code as well as from the platform.

## Repository and upload requirements

The builder runs your agent as you ship it and never writes code your agent is missing. A repository or an upload needs:

| Requirement | Applies to |
|---|---|
| A Docker Compose file or a Dockerfile that starts the agent | Voice and chat |
| A conversation endpoint over HTTP, in the agent's own format or the OpenAI-compatible one, or over a JSON WebSocket | Chat |
| Values the agent reads at startup, entered as environment values when you build | Voice and chat, when the agent reads any |
| Public hosts the agent calls by name, entered as additional egress domains when you build | Voice and chat, when the agent calls any |

An upload leaves `.env` files behind, so enter those values as environment values instead. You don't need to ship a database the agent depends on: when the agent's code declares Postgres, MySQL, ClickHouse, MongoDB, Redis, Qdrant, RabbitMQ, NATS or MinIO without shipping it, the builder provides it.

When a requirement isn't met, the build reads **Failed** with the reason on the step that failed; [Environment FAQ & fixes](/docs/environments/troubleshooting) covers the common ones.

## Build and run limits

**Repeats** is how many times each scenario plays, and the runs table records it as **Trials**; [Run a simulation](/docs/environments/guides/run-a-simulation) explains the controls. [Contracts](/docs/environments/concepts/contracts) covers run end conditions.

| Setting | Range | Default |
|---|---|---|
| Scenarios to generate, at build | 1 to 1000 | 10 |
| Parallel worlds, scenarios running at once | 1 to 4 | 1 |
| Repeats, when running selected scenarios | 1 to 20 | 1 |
| Repeats, when running the whole suite | 1, 3, 5, 8 or a custom number | 1 |
| Credential file, for agents that need a Google service account | Google service-account JSON, up to 5 MiB | None |
| Length of a single conversation | Not a fixed range: set per environment, under **Run end conditions** on the **Contract** tab, and the build sets them | Set at build |

## Details of the reading

When you [connect an agent](/docs/environments/guides/connect-your-agent) from GitHub or a folder upload on the **Agents** page, Future AGI reads its code to describe the agent: its framework, entry, prompt, tools, model and the credentials it needs. The reading happens before any environment is built. This part has five subsections:

- [Recognized frameworks](#recognized-frameworks)
- [How a repository or upload is read](#how-a-repository-or-upload-is-read)
- [Agents that are refused](#agents-that-are-refused)
- [Secrets in your code](#secrets-in-your-code)
- [Reading limits](#reading-limits)

### Recognized frameworks

Any framework can be connected; these are the ones the reading names. Naming the framework helps the reading describe the agent. Each named framework has one of three levels, and none is Tested yet:

- Recognized: the framework is named from the code
- Read: a real reading described a reference agent on it correctly
- Tested: an agent on the framework ran from its reading

The level describes how well the reading is proven for that framework. It doesn't limit which frameworks you can connect.

| Level | Frameworks |
|---|---|
| Read | CrewAI |
| Recognized | Claude Agent SDK, Deep Agents, Google ADK, LangChain, LangGraph, OpenAI Agents SDK, Pipecat, Pydantic AI |

Named in your code but with no level yet: LlamaIndex, AutoGen, Semantic Kernel, Haystack, Agno, BeeAI, DSPy, smolagents and Strands.

### How a repository or upload is read

[Repository and upload requirements](#repository-and-upload-requirements) above covers what a build needs to run your agent. This covers how the code is read when you connect it.

| Topic | What happens |
|---|---|
| Default folder, GitHub | The repository root |
| Naming a folder, GitHub | Allowed only on a GitHub source; where naming one isn't available yet, connecting a folder is refused, see [Agents that are refused](#agents-that-are-refused) |
| Folders above the named one | The agent's code is the named folder plus the folders above it |
| Folder, upload | Always read from the top of its folder |
| Entry file | Tells the agents apart when one folder holds several |
| Multiple agents | Each is listed when you connect, and the one you pick is read. At most 50 are listed; name the folder of one that's missing |
| Test and example folders | Read last, so they never crowd out your agent's own code |
| Symlinks | Not followed |
| Unparseable Python files | Skipped, and named in the agent's description. A file that needs a newer Python than 3.12 is named with the version it needs |

### Agents that are refused

In these messages, `v1` is the version being read; a later version shows its own number, such as `v3`.

| Refused when | What you see | What to do |
|---|---|---|
| Browser, computer-use or crawler agent | `Couldn't read v1: This kind of agent isn't supported yet (browser, computer-use and crawler agents)` | Connect a voice or chat agent instead; a refused agent can't be retried |
| Folder that doesn't exist | `Couldn't read v1: The folder named isn't in the repository` | Check the folder path and the branch |
| Folder named where naming one isn't available yet | `Choosing a folder isn't supported yet; connect the repository root` | Connect the repository root, as the folder rules above say |
| Agent type changed between versions (voice to chat, or the reverse) | `This version changed from chat to voice or back; connect it as a new agent` | Connect it as a new agent. An agent stays voice or chat across all its versions, as its first reading decided |

### Secrets in your code

| Rule | What it means |
|---|---|
| Hidden from the reading | `.env` files, keys, certificates and credential files are never read |
| Replaced in what is read | Secret values that still appear are replaced with `[redacted]` |
| Recorded by name | The reading records the names of the credentials the agent needs, never their values. You enter the values as environment values when you connect |

### Reading limits

| Limit | Value |
|---|---|
| Agents listed per repository | 50. Past that the list is marked truncated |
| Files in an upload | 1000 |
| Size of an upload | 200 MiB |
| A reading, or the search for agents in a repository, that runs too long | Marked failed: "We couldn't read this source. Try again." |
