## About

The harness builds the test environment. The simulated caller plays the customer in a voice trial. Your agent is the target of that trial. For example, to test how Ridgeline Outfitters handles a return, you can change which model asks for a refund or which voice says the words without changing the support agent that answers.

## Choose the authoring backend

For a local run, install Agent Learning Kit in an active Python virtual environment:

```bash
python -m pip install agent-learning-kit==0.3.7
```

| Setting | What it selects |
|---|---|
| `ALK_HARNESS` | The software that reads the agent and builds the environment. Unset or `claude` uses the Claude Code loop. `vertex-gemini` uses Google's Agent Development Kit (ADK). Neither selects your target agent's framework. |
| `ALK_HARNESS_MODEL` | The model the authoring backend calls. Locally, leaving it unset uses the backend's default. The `claude` loop can call a Gemini model through Agent Command Center without using Google ADK. |
| `ALK_VERTEX_LOCATION` | The location for a **direct** Vertex connection from `vertex-gemini`; defaults to `global`. It does not set the location for a gateway request. |

Google ADK requires the user's explicit approval **for this run**, including when you select it by an alias such as `gemini`. Only after that approval may the operator set `ALK_GOOGLE_ADK_EXPLICITLY_APPROVED_BY_USER=1` for the authoring process. Do not put it in a shared deployment default or an uploaded agent's environment. A gateway key is not approval.

To see the refusal without creating an environment or calling a model, run:

```bash
env -u ALK_GOOGLE_ADK_EXPLICITLY_APPROVED_BY_USER -u ALK_HARNESS_MODEL \
  ALK_HARNESS=vertex-gemini alk harness --help
```

The command exits with `ValueError: the Google ADK harness backend requires explicit user approval; set ALK_GOOGLE_ADK_EXPLICITLY_APPROVED_BY_USER=1 only after the user approves this run`.

## Put credentials on the right side of the call

| Where you run | What to configure |
|---|---|
| Local harness, through Agent Command Center | Load your own `AGENTCC_API_KEY` into the harness environment. `AGENTCC_BASE_URL` is the gateway **root**, by default `https://gateway.futureagi.com`, not a URL ending in `/v1`. The gateway supplies the upstream credentials for the model and speech routes it serves. |
| Local harness, direct to providers | Without a gateway key, supply the credentials for the providers you select. For direct Vertex ADK authoring, use Google Application Default Credentials and a project (set `GOOGLE_CLOUD_PROJECT` if it cannot be discovered). For direct Deepgram or Cartesia speech, use `DEEPGRAM_API_KEY` or `CARTESIA_API_KEY`, respectively. |
| Hosted environment | The platform operator configures a sandbox-reachable `ALK_HOSTED_AGENTCC_BASE_URL` (or `AGENTCC_BASE_URL`) and a platform-owned `AGENTCC_HARNESS_API_KEY` (or `AGENTCC_INTERNAL_API_KEY`). The worker receives the gateway settings separately from the target's credentials. If you use the hosted product, you do not supply these values. |

For Ridgeline, a key its agent needs to look up an order belongs with the **target**. The gateway key that pays for the simulated customer does not. Adding simulator settings or an ADK approval flag to target credentials does not configure the hosted caller or authorize authoring.

## Configure the simulated voice call

Load the [gateway key](/docs/quickstart/command-center-gateway) in your local shell before using this configuration. Here the author writes the return scenario using Gemini through the Claude Code loop. During the call, Deepgram transcribes the support agent, the caller's model decides what the customer says next, and Cartesia speaks the reply.

```bash
export AGENTCC_BASE_URL=https://gateway.futureagi.com
export ALK_HARNESS=claude
export ALK_HARNESS_MODEL=vertex_ai/gemini-3.7-flash

export SIMULATOR_LLM_PROVIDER=vertex
export SIMULATOR_LLM_MODEL=vertex_ai/gemini-3.8-flash
export SIMULATOR_LLM_FALLBACK_MODELS=gemini-3.7-flash,gemini-3.5-flash-lite

export SIMULATOR_STT_PROVIDER=deepgram
export SIMULATOR_STT_MODEL=nova-3
export SIMULATOR_TTS_PROVIDER=cartesia
export SIMULATOR_TTS_MODEL=sonic-3.6
```

`vertex_ai/` identifies a model served by Vertex. A bare Gemini name on the gateway normally means the Gemini API. For a caller configured with `SIMULATOR_LLM_PROVIDER=vertex`, or for the `vertex-gemini` author, the kit adds `vertex_ai/` to a bare model name and preserves an already qualified name.

The caller tries its primary model first. If an attempt fails or times out **before the caller has spoken**, it tries the comma-separated fallback models in order with the same provider adapter. In this example the first fallback is `gemini-3.7-flash`. This list does not retry a speech provider, switch the authoring backend, or replay a partly spoken reply.

Deepgram and Cartesia can each serve speech-to-text (STT) or text-to-speech (TTS). Through the gateway they use its `/deepgram` and `/cartesia` routes and its key; the worker does not need either speech vendor's key. The agent answering the call keeps its own speech configuration.

## Check the settings before a run

With those settings in the same shell, inspect the selected components without placing a call or printing credentials:

```python
import os

from fi.alk.harness.backends import resolve
from fi.alk.harness.config import chosen_model
from fi.alk.harness.simulator_voice import simulator_definition

caller = simulator_definition(os.environ.get)
print("Author:", resolve().name, chosen_model())
print("Caller:", caller.llm.provider, caller.llm.model)
print("Listen:", caller.stt.provider, caller.stt.model)
print("Speak:", caller.tts.provider, caller.tts.model)
```

Expect `Author: claude vertex_ai/gemini-3.7-flash`, `Caller: vertex vertex_ai/gemini-3.8-flash`, `Listen: deepgram nova-3` and `Speak: cartesia sonic-3.6`. These are configured routes, not evidence that a provider answered. To build the contract with this local author, run `alk harness understand --name ridgeline-support --path . --once` from the support agent's repository. That command calls the model.

## Limits and errors

| Symptom | What to check |
|---|---|
| The harness reports that the backend cannot drive the model | Check `ALK_HARNESS_MODEL` against the selected backend and route. In the example, the Claude Code loop needs the gateway to reach Gemini. Changing `SIMULATOR_LLM_MODEL` does not fix the author. |
| Hosted `503` with `agentcc_not_configured` | The operator must configure both the gateway URL and a platform-owned harness or internal key. Adding a key to the target does not fix it. |
| Hosted `503` with `simulator_speech_provider_unsupported` | Set both simulator speech providers to supported values: `deepgram` or `cartesia`. |
