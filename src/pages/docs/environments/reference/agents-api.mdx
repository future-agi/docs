This page is the REST reference for connected agents and their versions. For the model behind it, see [Agents and versions](/docs/environments/concepts/agents-and-versions).

For a walkthrough of connecting an agent, see [Connect your agent](/docs/environments/guides/connect-your-agent).

## Authenticate

Base URL: `https://api.futureagi.com`. Every path on this page starts with `/simulate/`.

| Header | Type | Required | Description |
|---|---|---|---|
| `X-Api-Key` | API Key | yes | Your Future AGI API key used to authenticate requests. Find and manage your API keys in the [Dashboard](https://app.futureagi.com) under Settings |
| `X-Secret-Key` | Secret Key | yes | Your Future AGI secret key, used alongside the API key. It is generated when you create an API key in the [Dashboard](https://app.futureagi.com) |

A wrong key and secret pair is refused with `Invalid API key or secret key`. API keys of type `ingest` are refused on every call. API keys of type `coding_agent` are limited to a fixed list of routes. A workspace Viewer cannot make write calls and sees `Viewers can't {action}. Ask a workspace admin for the Member role.` These refusals, and the `{action}` text each call puts in the Viewer message, are listed under [Authentication errors](#authentication-errors).

An agent that belongs to another organization answers `404` as if it did not exist.

Send both headers on every call:

```bash
curl https://api.futureagi.com/simulate/agents/connect/availability/ \
  -H "X-Api-Key: $API_KEY" \
  -H "X-Secret-Key: $SECRET_KEY"
```

## Connect

### Availability

`GET /simulate/agents/connect/availability/` takes no parameters and returns `200`. It answers only [authentication errors](#authentication-errors).

| Field | Type | Description |
|---|---|---|
| `reading_enabled` | boolean | Whether this installation reads agents. When `false`, scan and connect answer `422 reading_unavailable` |

### Scan

`POST /simulate/agents/scan/` starts a search for agents in a source. Errors: [Connect, scan and GitHub](#connect-scan-and-github).

| Field | Type | Required | Description |
|---|---|---|---|
| `kind` | string | yes | `github` or `archive` |
| `repository` | string | for `github` | `owner/name`, using letters, digits, `_`, `.` and `-` |
| `ref` | string | no | A branch or tag. Names containing `..` are refused |
| `visibility` | string | no | `public` (default) or `private`. `private` requires `installation_id` |
| `installation_id` | string | for `private` | GitHub App installation, up to 255 characters |
| `repository_id` | integer | no | 1 or more |
| `archive_artifact_id` | UUID | for `archive` | The uploaded folder. Not allowed with `github` |

An `archive` source may not carry `repository`, `ref`, `visibility`, `installation_id` or `repository_id`.

A public GitHub repository:

```json
{ "kind": "github", "repository": "acme/support-bot", "ref": "main" }
```

A private GitHub repository, which needs `installation_id`:

```json
{ "kind": "github", "repository": "acme/support-bot", "visibility": "private", "installation_id": "12345678" }
```

An uploaded folder:

```json
{ "kind": "archive", "archive_artifact_id": "9d1c0b3e-5a7f-4c21-8e64-0f2a6b7d3c10" }
```

Success is `202 Accepted` with `id` (UUID) and `status` (starts as `pending`). Poll the [scan result](#scan-result) with that `id`.

### Scan result

`GET /simulate/agents/scan/{scan_id}/` returns `200`. The scan must belong to your organization and workspace. Poll until `status` is no longer `pending` or `running`, then read `agents`, `error` or `failure`.

| Field | Type | Description |
|---|---|---|
| `id` | UUID | The scan |
| `status` | string | `pending`, `running`, `found`, `none`, `error` or `failed` |
| `kind` | string | `github` or `archive` |
| `repository`, `ref` | string | The source that was read |
| `commit_sha` | string or null | The commit that was read |
| `agents` | array | The agents found, see below |
| `truncated` | boolean | `true` when more agents exist than are listed |
| `error` | object or null | `{code, message}`, what the scan found wrong with the source |
| `failure` | object or null | `{code, message, retryable}`, why the scan itself stopped |

Each entry in `agents`:

| Field | Type | Description |
|---|---|---|
| `name` | string | Agent name |
| `subfolder` | string | Folder inside the source, empty for the root |
| `entry` | string | Entry file |
| `framework` | object | `{name, version, label}`, `version` and `label` may be null |
| `confidence` | string | `high`, `medium` or `low` |
| `evidence` | string[] | Where the agent was recognized |
| `env_names` | string[] | Environment variable names the code reads |
| `estimates` | object | `{tools, prompt_files}`, both integers |

A finished scan:

```json
{
  "id": "0e6f...", "status": "found", "kind": "github",
  "repository": "acme/support-bot", "ref": "main",
  "commit_sha": "0123456789abcdef0123456789abcdef01234567",
  "agents": [
    {
      "name": "support-bot", "subfolder": "", "entry": "agent.py",
      "framework": {"name": "langchain", "version": "0.3.1", "label": "LangChain"},
      "confidence": "high", "evidence": ["agent.py:12 create_react_agent"],
      "env_names": ["OPENAI_API_KEY"],
      "estimates": {"tools": 4, "prompt_files": 1}
    }
  ],
  "truncated": false, "error": null, "failure": null
}
```

### Connect an agent

`POST /simulate/agents/connect/` takes the same source fields as [Scan](#scan) (`kind`, `repository`, `ref`, `visibility`, `installation_id`, `repository_id`, `archive_artifact_id`) plus the fields below. Errors: [Connect, scan and GitHub](#connect-scan-and-github).

A complete request for a public GitHub repository:

```json
{
  "kind": "github",
  "repository": "acme/support-bot",
  "ref": "main",
  "name": "support-bot",
  "commit_sha": "0123456789abcdef0123456789abcdef01234567",
  "entry": "agent.py",
  "env_values": { "OPENAI_API_KEY": "sk-..." }
}
```

| Field | Type | Required | Description |
|---|---|---|---|
| `name` | string | yes | Up to 255 characters. Blank is refused with `name the agent`, surrounding spaces are trimmed |
| `commit_sha` | string | no | 40 hex characters. `github` only. When omitted, the branch head is read now |
| `subfolder` | string | no | Relative folder, up to 512 characters. No leading or trailing slash, no `.` or `..` segment. Blank means the root. `github` only |
| `entry` | string | no | The agent's entry file path, same pattern, up to 512 characters |
| `env_values` | object | no | Environment variable name to string value, each value up to 65,536 characters. Empty values are dropped. Same rules as `secret_values` under [Change](#change) |

| Status | Meaning |
|---|---|
| `201 Created` | A new agent was connected |
| `200 OK` | The same repository, folder and entry (or the same upload) is already connected in the workspace |

Both return `agent_id` (UUID), `version_id` (UUID) and `exists` (boolean, `true` when already connected). The first version starts its check, with origin `connect`.

```json
{ "agent_id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890", "version_id": "5b0c2f58-3f8e-4d0e-9a52-7d7b5f1e9c11", "exists": false }
```

Confirm what was found with [found-check](#found-check).

## Versions

### Agent

`GET /simulate/agent-definitions/{agent_id}/` returns the agent. Besides its usual fields (see [Get agent definition](/docs/api/agent-definitions/getagentdefinition)), it carries the fields below. Errors: [Versions: lookup](#versions-lookup).

| Field | Type | Description |
|---|---|---|
| `versions` | array | Version list rows, see below |
| `active_version` | object or null | The production version, as a list row |
| `version_count` | integer | Number of versions |
| `agent_kind` | string or null | The kind of agent |
| `source` | string or null | The connector or source kind, for example `github` |
| `environment_count` | integer | Count of environments |
| `observability_enabled` | boolean | Whether observability is on for the agent |
| `observe_project` | object or null | `{id, name}` of the observability project, or null |
| `connected` | boolean | Whether the agent was connected on the Agents page |
| `managed_by` | object or null | `{id, name}` of the environment that made and owns the agent. When set, that environment manages its versions and production |
| `found_check` | object | `{required, done_at}`, `done_at` is null until confirmed. See [Found-check](#found-check) |
| `source_checked_at` | datetime or null | When GitHub last answered for the agent's branch |
| `source_check_interval_seconds` | integer or null | How often watched branches are read. Set only when `source` is `github`. Currently 600 |

### List versions

`GET /simulate/agent-definitions/{agent_id}/versions/` returns a page (`count`, `next`, `previous`, `results`, `total_pages`, `current_page`), newest version first. Pagination uses `page` and `limit`, with a default page size of 10. Each result is a list row. See also [List agent versions](/docs/api/agent-versions/listagentversions). Errors: [Versions: lookup](#versions-lookup).

### Read a version

`GET /simulate/agent-definitions/{agent_id}/versions/{version_id}/` returns one version in the detail shape. See also [Get agent version](/docs/api/agent-versions/getagentversion). Errors: [Versions: lookup](#versions-lookup).

The list row and the detail shape share most fields. The detail adds `release_notes`, `agent_definition`, `organization`, `configuration_snapshot`, `agent_kind`, `api_key` and `updated_at`. The list row adds `in_production`. The table covers both, with the List and Detail columns showing which carries each field.

| Field | Type | List | Detail | Description |
|---|---|---|---|---|
| `id` | UUID | yes | yes | The version |
| `version_number` | integer | yes | yes | Sequential number |
| `version_name`, `version_name_display` | string | yes | yes | Name and display label such as `v4` |
| `status`, `status_display` | string | yes | yes | `draft`, `active`, `archived` or `deprecated`, and its label |
| `score`, `test_count`, `pass_rate` | number or integer | yes | yes | Score, test count and pass rate |
| `description`, `commit_message` | string | yes | yes | Text on the version |
| `release_notes` | string or null | no | yes | Release notes |
| `agent_definition`, `organization` | string | no | yes | Parent agent and owning organization |
| `configuration_snapshot` | object | no | yes | The version's configuration snapshot |
| `agent_kind` | string | no | yes | The kind of agent |
| `api_key` | string or null | no | yes | Masked. Null for a Viewer |
| `is_active` | boolean | yes | yes | `true` when the status is `active` |
| `in_production` | boolean | yes | no | Same value as `is_active` |
| `is_latest` | boolean | yes | yes | `true` for the highest `version_number` |
| `origin` | string or null | yes | yes | How the version was made |
| `preflight_status` | string or null | yes | yes | The check state |
| `check_step` | string or null | yes | yes | Where a pending check is |
| `check_failure` | object or null | yes | yes | Why a check failed |
| `check_started_at` | datetime or null | yes | yes | When the latest check was asked for (creation, retry or restart) |
| `environments_count` | integer | yes | yes | Environments whose default agent version is this one |
| `source` | object or null | yes | yes | `{kind}` plus, when present, `repository`, `ref`, `commit_sha`, `subfolder`, `archive_artifact_id` |
| `created_at` | datetime | yes | yes | Creation time |
| `updated_at` | datetime | no | yes | Last change |

`origin` is one of `creation`, `push`, `upload`, `prompt`, `agent_payload`, `credentials`, `provider_sync`, `backfill`, `connect`, `sync` or `fix`. `preflight_status` is one of `pending`, `passed`, `failed`, `legacy` or `discarded`. `origin`, `preflight_status` and `source` are null for a version made through the older create call.

`check_step` is non-null only while `preflight_status` is `pending`: `snapshot` (storing the code), `reading` (reading the agent) or `check` (checking credentials).

`check_failure` is set only when the check `failed`, or the version was `discarded` because a newer one superseded it. Its cases, first match wins:

| `code` | `message` | `retryable` | Meaning |
|---|---|---|---|
| `superseded` | `Superseded by a newer version` | false | The version was discarded by a newer one |
| the reading's code, such as `agent_reading_unavailable` or `archive_source_not_found` | the reading's message | varies | Reading the agent failed |
| a check error code | empty | true | The check itself errored |
| `credentials_missing` | `Missing credentials: A, B` | false | Also carries `missing`, a sorted string array of the names |
| `{id}_failed` | the failed item's label | true | A credential check item failed |

### Change

`POST /simulate/agent-definitions/{agent_id}/versions/change/` makes a new version from the production version, or the latest when none is in production. Errors: [Versions: change](#versions-change). A `sync` can also fail with the GitHub errors under [Connect, scan and GitHub](#connect-scan-and-github): `github_installation_not_connected` (sync message), `github_not_connected`, `github_installation_revoked`, `github_rate_limited` (`429` with `Retry-After`) and `503 source_unreachable`.

`kind` is required and is one of `sync`, `upload`, `credentials` or `manual`. It decides which other fields the body takes:

| Kind | Takes | Does | Notes |
|---|---|---|---|
| `sync` | no other field | Reads the agent's GitHub branch head, or the provider again for a Vapi or Retell agent. Makes a version only when something changed | |
| `upload` | `archive_artifact_id` (UUID, required) | Makes a version from an uploaded folder. The same folder returns the existing version | |
| `credentials` | `secret_values` (object, required) | Makes a version with the given values on top of the parent's credentials | Name to string value, each value up to 65,536 characters. Must not be empty. See the rules below |
| `manual` | `prompt` and/or `settings`, at least one | Makes a version with an edited prompt or settings. The same content returns the parent | `prompt` is up to 65,536 characters and may be blank. `settings` takes `phone_number` (string, E.164, up to 512), `agent_name` (string, up to 512) and `target_speaks_first` (boolean), all optional, but the object must not be empty. Phone agents take `phone_number` and `target_speaks_first`, Vapi and Retell agents take `target_speaks_first`, LiveKit agents take `agent_name` and `target_speaks_first` |

One body per kind:

```json
{ "kind": "sync" }
```

```json
{ "kind": "upload", "archive_artifact_id": "9d1c0b3e-5a7f-4c21-8e64-0f2a6b7d3c10" }
```

```json
{ "kind": "credentials", "secret_values": { "OPENAI_API_KEY": "sk-..." } }
```

```json
{ "kind": "manual", "prompt": "You are a support agent.", "settings": { "target_speaks_first": false } }
```

`secret_values` rules:

- At most 100 values. Otherwise: `at most 100 values may be stored at once`
- Names are alphanumeric or underscore and do not start with a digit. These names are reserved: `DOCKER_HOST`, `FI_API_KEY`, `FI_BASE_URL`, `FI_SECRET_KEY`, `HARNESS_PLATFORM_API_KEY`, `HARNESS_PLATFORM_SECRET_KEY`, `HARNESS_PLATFORM_URL`, `HOME`, `PATH`, `PYTHONPATH`. Otherwise: `invalid or runner-reserved environment names: A, B`
- Total size is at most 1 MiB. Otherwise: `environment values may not exceed 1 MiB`
- Names starting `SIMULATOR_` are reserved. Otherwise: `SIMULATOR_ names are reserved for platform-managed credentials: X`
- All values are strings. Otherwise: `values must be strings: X`

Field errors answer `400`:

- A field missing for its kind gives `required for kind {kind}` on that field
- A field that does not belong to the kind gives `not part of a {kind} change`
- An empty `secret_values` or `settings` gives `nothing to change`
- A `phone_number` that is not valid gives `phone_number must be in E.164 format, e.g. +14155551234`. Some countries need an exact length, which gives `phone_number must have exactly {n} digits after the +{cc} country code`

| Status | Meaning |
|---|---|
| `202 Accepted` | A new version was created and its check runs next. `created` is `true`, `up_to_date` is `false` |
| `200 OK` | The same content already has a version. `created` is `false`, `up_to_date` is `true` |

Both return `version` (the detail shape above), `created` and `up_to_date`.

### Production

`POST /simulate/agent-definitions/{agent_id}/versions/{version_id}/production/` takes no body. Errors: [Versions: production, retry, discard](#versions-production-retry-discard).

It makes a checked version the production version. The earlier production version becomes `archived`. Environments set to follow production move to it when the change is compatible. Pinned environments are only offered it.

Returns `200` with `version` (now `active`) and `moved_environment_ids` (string array, empty when none moved).

### Retry

`POST /simulate/agent-definitions/{agent_id}/versions/{version_id}/retry/` takes no body. Errors: [Versions: production, retry, discard](#versions-production-retry-discard).

It queues the check again for a version whose check `failed`, or one stuck as `pending`. Returns `202` with `{"message": "Check queued"}`.

### Discard

`POST /simulate/agent-definitions/{agent_id}/versions/{version_id}/discard/` takes no body. Errors: [Versions: production, retry, discard](#versions-production-retry-discard).

It sets the version aside with check status `discarded`. The version keeps its number and is not deleted. Discarding an already discarded version succeeds. Returns `200` with `{"message": "Version discarded"}`.

### Compatibility

`GET /simulate/agent-definitions/{agent_id}/versions/{version_id}/compatibility/?environment_id=` compares the version with the one the environment was built from. Errors: [Versions: lookup](#versions-lookup).

| Query | Type | Required | Description |
|---|---|---|---|
| `environment_id` | UUID | yes | A live environment in your organization |

| Field | Type | Description |
|---|---|---|
| `environment_id`, `version_id` | string | Echo of the request |
| `status` | string | See below |
| `base` | string or null | The version the environment was built from |
| `reason` | string | Only when `status` is `unmeasured`: `environment_not_built`, `base_not_read` or `version_not_read` |
| `same_version` | boolean | Only when the version is the build base, with status `clean` |
| `tools_added`, `tools_removed` | string[] | Present when both versions were read |
| `tools_changed` | array | `{name, before, after}`, where `before` and `after` are `{arguments, required, kind}` |
| `services_added`, `rules_added` | string[] | Present when both versions were read |
| `prompt_changed`, `model_changed` | boolean | Present when both versions were read |

| `status` | Meaning |
|---|---|
| `clean` | Only the prompt, model, voice or instructions moved |
| `new_tool` | A tool or outside service appeared |
| `tool_removed_or_changed` | A tool went away or takes different arguments |
| `new_rule` | A hard constraint appeared |
| `unmeasured` | The comparison could not be made, see `reason` |

When several apply, the worst class wins.

### Found-check

`POST /simulate/agent-definitions/{agent_id}/found-check/` takes no body.

Call it after [connecting](#connect-an-agent) an agent and before building an environment from it. Connecting starts a reading of the agent, and this call records that you confirmed what that first reading found. Until it is confirmed, [build-preflight](#build-preflight) reports a blocked `found_check` and a build answers `409 found_check_required` ([Building](#building)). Repeating the call keeps the first time. Returns `200` with `found_checked_at` (ISO 8601 datetime). Errors: [Versions: lookup](#versions-lookup).

### Build-preflight

`GET /simulate/agent-definitions/{agent_id}/build-preflight/?version_id=` reports what building an environment from this agent would find. Call it after [found-check](#found-check) and before building. A blocked check answers `200` with `ok` `false`, not an error. Errors: [Versions: lookup](#versions-lookup).

| Query | Type | Required | Description |
|---|---|---|---|
| `version_id` | UUID | no | Defaults to the production version, else the latest |

| Field | Type | Description |
|---|---|---|
| `ok` | boolean | `true` when every check is `ok` |
| `version_id` | string or null | The version checked |
| `checks` | array | `{name, status, message}`, with `status` `ok` or `blocked` |

| Check `name` | Message |
|---|---|
| `version` | `This agent has no version to build from yet`, or `v{N} is ready`, or `v{N} is {preflight_status}` |
| `code`, GitHub version | `the commit's code is stored`, or `the commit is pinned; its code is fetched on the first build` |
| `code`, upload version | `the upload is stored`, or `the upload expired; upload again` |
| `credentials` (always `ok`) | `{n} credential names come from the version`, for example `2 credential names come from the version`. For one name: `1 credential name come from the version` |
| `found_check` (`blocked`) | `check what we found about this agent first` |

`found_check` appears when the agent was connected and what was found is not yet confirmed.

## Environment policy

`POST /simulate/api/harness-environments/{id}/agent-policy/` chooses whether an environment follows production or stays pinned. Errors: [Environment policy (flat body)](#environment-policy-flat-body).

| Field | Type | Required | Description |
|---|---|---|---|
| `policy` | string | yes | `follow` or `pinned` |
| `version_id` | UUID | no | Only with `pinned` |

`follow` moves the environment to the agent's production version now, if it is not already on it. `pinned` with `version_id` pins the environment to that version. `pinned` without it pins the current default.

Returns `200`:

| Field | Type | Description |
|---|---|---|
| `policy` | string | `follow` or `pinned` |
| `agent_version` | object or null | The environment's default agent version, with `id`, `label` (such as `v3`), `status` (`draft`, `active` or `discarded`), `is_default`, `created_at`, `created_by`, `origin`, `summary`, `hash`, `parent_id`, `derived_from_agent_version_id`, `scenario_count`, `source`, `prompt`, `preflight_status`, `preflight_report`, `preflighted_at`, `check_started_at`, `credential_names`, `required_variable_names`, `activation_outcome`, `requested_here`, `pickable` and `discardable` |

Domain errors on this route use a flat body, unlike the rest of this page:

```json
{ "error": "version_not_pickable", "message": "that version can't be this environment's default yet", "retryable": false }
```

Validation errors, the Viewer refusal and authentication errors still use the common envelope.

## Code

The code endpoints are reads. They show the code stored for a version: a GitHub commit or an uploaded folder.

Shared errors. Errors specific to one call are under [Code: file and compare](#code-file-and-compare):

| Status | Code | Message |
|---|---|---|
| 404 | `no_code` | `This version has no code to show` |
| 503 | `archive_unavailable` | `Code is temporarily unavailable` |
| 422 | `code_too_large` | `This version's code is too large to show here` |

### Tree

`GET .../versions/{version_id}/code/tree/` takes no query.

| Field | Type | Description |
|---|---|---|
| `subfolder` | string | The agent's folder in the source, empty for the root |
| `files` | array | `{path, size, kind}`, sorted by path. `size` is in bytes |
| `truncated` | boolean | `true` when the list was cut at 5,000 entries |

`kind` is `text`, `binary` or `too_large`. A file over 1 MiB is `too_large`. A file is `binary` when its first 64 KiB hold a NUL byte or are not valid UTF-8.

### File

`GET .../versions/{version_id}/code/file/?path=`

| Query | Type | Required | Description |
|---|---|---|---|
| `path` | string | yes | Up to 4,096 characters. Not starting with `/`, no backslash, no empty, `.` or `..` segment |

| Field | Type | Description |
|---|---|---|
| `path`, `size` | string, integer | The file and its size in bytes |
| `kind` | string | `text`, `binary` or `too_large` |
| `language` | string | Guessed from the extension, `plaintext` by default |
| `content` | string | Only when `kind` is `text` |

### Changes

`GET .../versions/{version_id}/code/changes/?against=` lists changed files.

| Query | Type | Required | Description |
|---|---|---|---|
| `against` | UUID | no | One of the agent's versions. Defaults to the previous version |

| Field | Type | Description |
|---|---|---|
| `against` | string or null | The version compared with |
| `files` | array | `{path, status}`, with `status` `added`, `removed` or `modified`. A rename shows as one `removed` and one `added` |
| `unavailable` | string | `no_previous_version` (with `against` null and no files), or `no_code` when the compared version has no code |

### Compare

`GET .../versions/{version_id}/code/compare/?against=` returns a summary of what changed. The flow is: call Compare for the summary, then call [Compare patches](#compare-patches) for the files that come back `collapsed: true`. `against` is as above. The older version is always on the left: when `against` is newer than `{version_id}`, the two are swapped, so `version` in the response is always the newer one.

| Field | Type | Description |
|---|---|---|
| `version` | string | The newer version |
| `against` | string or null | The older version |
| `unavailable` | string | `no_previous_version` or `no_code`. The rest of the summary is then empty or zero |
| `same_code` | boolean | Both versions use the same stored code |
| `env_changed` | boolean | The two versions' credential sets differ. Values are never shown |
| `files` | array | Changed files, see below |
| `total_files` | integer | The full count of changed files |
| `additions`, `deletions` | integer | Sums over files whose patch was computed |
| `truncated` | boolean | `true` when more files changed than are listed |

Each file:

| Field | Type | Description |
|---|---|---|
| `path` | string | The file |
| `previous_path` | string or null | Set for renames |
| `status` | string | `added`, `removed`, `modified` or `renamed` |
| `kind` | string | `text`, `binary` or `too_large` |
| `additions`, `deletions` | integer or null | Null until a patch is computed |
| `collapsed` | boolean | `true` when the patch is not loaded yet |

How files are classified and listed:

| Case | Rule |
|---|---|
| Files listed | 300, sorted by path. `total_files` still gives the full count |
| Renames | An added and a removed file with identical content pair as `renamed` |
| `binary` | Either side is binary |
| `too_large` | Either side is over 1 MiB, or a text file is over 512,000 bytes |
| `too_large` by lines | A text file with more than 5,000 lines on either side. No additions or deletions are counted for it |
| Time budget | 5 s per request. Files not diffed in time come back `collapsed: true` with null counts, and load through the patches call |
| Auto-collapse | A file collapses when additions plus deletions exceed 400, or its patch exceeds 20,480 bytes |

### Compare patches

`GET .../versions/{version_id}/code/compare/patches/?against=&path=` loads the line changes of chosen files, typically those [Compare](#compare) returned as `collapsed: true`. `against` and the swap rule work as they do for Compare.

| Query | Type | Required | Description |
|---|---|---|---|
| `path` | string, repeated | yes | `?path=a.py&path=b.py`. At most 25 paths, each up to 4,096 characters. Duplicates are collapsed |
| `against` | UUID | no | Defaults to the previous version |

| Field | Type | Description |
|---|---|---|
| `version` | string | The newer version |
| `against` | string or null | The older version |
| `files` | array | One entry per path, in the order asked |

Each file has `path`, `kind` (`text`, `binary`, `too_large` or null), `unchanged` (boolean) and `hunks`. A hunk is `{old_start, old_lines, new_start, new_lines, lines}`, where each line starts with a space (context), `-` (removed) or `+` (added), with 3 context lines. A path that did not change returns `kind: null`, `unchanged: true` and no hunks. A `binary` or `too_large` file returns no hunks. The Compare limits on lines and time apply here too, so such a file comes back as `too_large` with no hunks.

## Deleting

| Call | Success | Notes |
|---|---|---|
| `DELETE /simulate/agent-definitions/{agent_id}/delete/` | `200` `{"message": "Agent definition deleted successfully"}` | Answers `409 agent_in_use` while an environment still tests the agent, and deletes nothing |
| `DELETE /simulate/agent-definitions/` | `200` | Body `{"agent_ids": [...]}`, at least one UUID |
| `DELETE /simulate/agent-definitions/{agent_id}/versions/{version_id}/delete/` | `410` | Removed. Nothing is deleted |

Bulk delete returns:

| Field | Type | Description |
|---|---|---|
| `message` | string | `Agents deleted successfully` |
| `agents_updated` | integer | Agents deleted |
| `versions_updated` | integer | Versions deleted with them |
| `skipped_agent_ids` | UUID[] | Agents an environment still tests, in the order asked. They keep their versions while the rest of the request is deleted |

Unknown or already deleted ids are left out of the response, and are not listed in `skipped_agent_ids`.

The version delete route answers `410 Gone` with code `version_delete_removed` and the response header `Deprecation: true`. Discard a version that has not passed its check instead. Errors: [Delete errors](#delete-errors).

## Errors

Every error is JSON with these fields, except the [environment policy](#environment-policy) domain errors.

| Field | Type | Description |
|---|---|---|
| `status` | boolean | Always `false` |
| `type` | string | `validation_error` (400), `authentication_error` (401), `payment_required` (402), `permission_error` (403), `not_found` (404), `conflict` (409), `client_error` (410, 413, 422), `rate_limit` (429), `server_error` (500), `service_unavailable` (503), `timeout` (504), else `api_error` |
| `code` | string | Machine code. Defaults when none is given: 400 `invalid`, 401 `not_authenticated`, 403 `permission_denied`, 404 `not_found`, 409 `conflict`, 410 `gone`, 422 `invalid`, 429 `rate_limited`, 500 `server_error`, 503 `service_unavailable` |
| `message` | string | The human text. `detail`, `error` and `result` carry the same string |
| `attr` | string | Optional. The first field named in `details` |
| `details` | object | Optional. Field name to a list of strings |
| `retryable` | boolean | On domain errors from the connect and version calls |

A `429` carries a `Retry-After` header when `details.retry_after` exists. Validation errors answer `400`; with one bad field, `message` is `<field>: <text>`, and unknown fields give `Unknown field.` under that field.
