<TLDR>
**What you'll build:** An [environment](/docs/environments/concepts/understanding-environments) around a voice agent you already run on Vapi, a small suite of scenarios written for it, and a graded run you can read call by call. Nothing here needs code.
</TLDR>

## The problem

A caller checking a prescription refill corrects their date of birth mid-sentence. The agent asks for identification, but does it act on the correction? A completed call tells you the connection worked, not whether the agent checked the refill.

## What you'll build

A reusable environment that knows your Vapi assistant's tools and rules, calls it with scenarios written for it, and puts each verdict beside the conversation that produced it.

You'll:

1. Connect a Vapi assistant without writing code. The builder reads the assistant's configuration on Vapi.
2. Check the tools and rules the builder read into its [contract](/docs/environments/concepts/contracts).
3. Run a small suite of [scenarios](/docs/environments/concepts/scenarios-and-trials).
4. Compare a call's verdict with the words and tool calls in its transcript.

<Prerequisites title="Before you start">
- A Future AGI account.
- A voice agent on Vapi, with its **Assistant ID**.
- A Vapi API key that can call that assistant.
- Every scenario in a run is a real call to your agent, billed by Vapi like any other. Start with a small suite, as below, and grow it once the environment looks right.
- An agent connected through a hosted platform keeps calling its own tools on its own service, so choose an assistant whose tools are safe to call in a test.
</Prerequisites>

## Connect the assistant

1. Open **Simulate > Environment**.
2. On **Build environment**, choose **Hosted platform** under **Or connect your own agent**.

   <img src="/images/docs/environments/guides/build-an-environment/build-environment-tab.png" alt="The Build environment tab with Source repository, Code upload and Hosted platform cards under Or connect your own agent, and Prebuilt and Web Environments marked Coming soon" style={{ borderRadius: '5px' }} />

3. Set **Agent type** to **Voice**.
4. Set **Platform** to **Vapi**.
5. Enter the **Assistant ID**.
6. Enter the **Vapi API key**. It is stored encrypted and used only to call the agent.
7. Leave the caller on **Web**, so the simulated caller reaches the agent over a web call and no phone call is placed.
8. Turn on **Agent speaks first** if your assistant greets the caller before they say anything.

   <img src="/images/docs/environments/guides/build-an-environment/hosted-platform-form.png" alt="The Hosted platform form with Voice and Vapi selected, empty Assistant ID and Vapi API key fields, the Web and Phone choice set to Web, and the Agent speaks first toggle" style={{ borderRadius: '5px' }} />

## Build a small suite

1. Set **Scenarios to generate** to `5`.

   A first environment is for checking that the builder read your agent correctly. Five scenarios are enough to see that, and you can add more later just by asking.

2. Leave **Parallel worlds** at `1`.
3. Click **Run preflight**.

   It should report **Ready to build**. If it reports **Credentials need attention**, the Assistant ID or the key is wrong. Check that the ID is the assistant's, not a phone number's, and that the key belongs to the Vapi account that owns the assistant. Then run preflight again.

4. Click **Build environment**.

   The workspace opens straight away and fills in as the builder works: understanding the agent, building the environment, then generating and validating scenarios. You can leave and come back. Wait for the status beside the environment's name to read **Ready**.

## Check the contract before placing calls

1. Open **Overview**.
2. Under **Read from source**, check that **Tools** lists every tool your assistant can call.
3. Check that **Rules** lists the hard constraints from its instructions, quoted.
4. If something is missing, tell the conversation on the left, for example “the agent also has a `cancel_order` tool”.

   The builder only records what it can read. [Chat orchestration](/docs/environments/concepts/chat-orchestration) is how you correct it.

5. Check **Overview** again before you run the suite.

The contract holds your assistant's tools, rules and real use cases. Every scenario was written from one of those use cases and kept only after passing its checks. Each carries **sub-goals** naming what it tests, such as whether the agent identified the caller before discussing their account. The builder also picked evaluations from the library that fit your agent, and those grade every call alongside the sub-goals.

## Run the scenarios

1. Leave **Repeats** at **1×**.
2. Click **Run simulation** at the top right.

   The run starts straight away.

3. Open the **Runs** tab.

   The run moves through **Provisioning**, **Running** and **Grading** to **Completed**.

## Read the call that failed

1. Open the completed run.
2. Click the **Failed** chip above the table.
3. Click a row to open the call.
4. On the right of the call, open **Evals**.
5. Expand the failed evaluation.

   Each evaluation's verdict comes with the reason it failed.

6. Find that moment in the **Transcript** on the left.

   Every tool call the agent made appears there with its arguments.

## Run the suite after a change

Because the scenarios belong to the environment, the next run plays the same suite. Change your assistant on Vapi, run again, and the two runs differ only by what you changed. Once the environment looks right, grow the suite by asking the builder for more scenarios.

## Build from your agent's code instead

Nothing in this quickstart needs code, because the builder reads the assistant's configuration on Vapi. To build from your agent's source instead, [Build an environment](/docs/environments/guides/build-an-environment) covers repositories and uploads.

## Troubleshooting

- **Preflight keeps failing:** check that the API key belongs to the Vapi account that owns the assistant, and that the Assistant ID is the assistant's, not a phone number's.
- **A tool or rule is missing from Overview:** the builder only records what it can read. Tell the conversation on the left what is missing, then check **Overview** again.
- **Calls show as Error:** the call itself could not run, so there is no verdict and it never counts against the agent. Open one to see why, then tick those calls and use **Re-run**.
- **The build reads Failed:** the reason is on the step that failed. [Environment FAQ & fixes](/docs/environments/troubleshooting) covers the common ones.
