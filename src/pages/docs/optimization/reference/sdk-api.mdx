## About

Agent Learning Kit provides `fi.opt` and the public `fi.alk.optimize` module. This page covers the six **prompt** searches also offered in the dataset dashboard. A Python run takes a list of rows, generates answers for candidate prompts, scores them, and returns an `OptimizationResult`. For a complete model-backed run, see [Optimize from the SDK](/docs/optimization/guides/optimize-from-the-sdk).

```bash
python -m pip install agent-learning-kit==0.3.7
```

## Evaluator

Import `Evaluator` from `fi.alk.optimize` (or `fi.opt.base.evaluator`). Call `evaluate(inputs)` with a list of mapped dictionaries; it returns a list of `EvaluationResult` records. Choose one scoring mode:

| Mode | Constructor arguments | Credentials and behavior |
|---|---|---|
| Local heuristic | `metric=` with a `BaseMetric` instance, such as `Equals()` | Runs the metric in Python. No provider or Future AGI keys are needed for a text comparison. |
| Local LLM judge | `metric=` with a `BaseLLMJudgeMetric` instance | If the metric has no provider, the evaluator uses the optional `provider=` or creates a `LiteLLMProvider`. The judge needs credentials for its model. |
| Future AGI platform | `eval_template=` and `eval_model_name=` | Pass `fi_api_key` and `fi_secret_key` or set `FI_API_KEY` and `FI_SECRET_KEY`. Both are required. The template's required inputs determine what to map. |

These credentials are independent of the ones your generator uses. The optimization evaluator clamps numeric metric scores to the range 0 to 1. When a row fails to score, inspect the returned `reason` rather than assuming a zero always means the answer was wrong.

## BasicDataMapper

`BasicDataMapper(key_map=...)` maps **evaluator input name → source**. A source of `"generated_output"` means the model's answer, not a column you have to create. Other sources name keys in the dataset row. Missing source keys are omitted, so you can inspect `mapper.map(output, row)` before starting a search.

This example tests the scoring rule for a support router without making any model calls:

<CodeGroup titles={["Python"]}>

```python
from fi.alk.optimize import BasicDataMapper, Evaluator
from fi.evals.metrics.heuristics.string_metrics import Equals

row = {"ticket": "Can I exchange a rain jacket?", "queue": "RETURNS"}
mapper = BasicDataMapper(key_map={"response": "generated_output", "expected_response": "queue"})
metric = Evaluator(metric=Equals(config={"case_sensitive": True}))
for output in ["RETURNS", "RETURNS: send the jacket back."]:
    mapped = mapper.map(output, row)
    score = metric.evaluate([mapped])[0]
    print(output, score.score, score.reason, sep=" | ")
```

</CodeGroup>

```text
RETURNS | 1.0 | Response matches expected text.
RETURNS: send the jacket back. | 0.0 | Response does not match.
```

## LiteLLMGenerator

`LiteLLMGenerator(model, prompt_template)` takes a LiteLLM model identifier and a Python format string. For example, `model="openrouter/openai/gpt-4o-mini"` routes through OpenRouter. `generate(prompt_vars, **litellm_kwargs)` substitutes the supplied row fields, sends the filled prompt as a user message, and returns the answer text. Supply the key for the model's provider.

Use `get_prompt_template()` to retrieve the unfilled template and `set_prompt_template(template)` to replace it. A placeholder such as `{ticket}` must exist in the row; the substitutions happen **before** the provider call. A missing placeholder value raises `KeyError`, whereas an exception in the model call can yield an empty string.

## optimize()

All six searches take `evaluator`, `data_mapper`, `dataset` (a list of dictionaries), and optionally `early_stopping` (default `None`) on `optimize()`. The remaining arguments depend on the algorithm. These are **Python** settings, not defaults for the dashboard form.

| Class from `fi.alk.optimize` | Configure on the optimizer | Pass to `optimize()` in addition to the shared inputs |
|---|---|---|
| `RandomSearchOptimizer` | Supply `generator`; `teacher_model` defaults to `"gpt-5"`, `num_variations` to `5`. | No `initial_prompts` needed. It reads the starting template from the generator and scores the proposed variations, not a separate baseline. |
| `BayesianSearchOptimizer` | Set the task model with `inference_model_name`. The search defaults to `min_examples=2`, `max_examples=8`, `n_trials=10`. Set `eval_subset_size` on the constructor, not the call. | Supply `initial_prompts`; it uses the first prompt as the instruction to accompany the few-shot examples. |
| `MetaPromptOptimizer` | Supply `teacher_generator`. Set `task_model` if candidates should run on a different model; otherwise they run on the teacher's model. | Supply `initial_prompts` (first prompt used). Optional: `task_description`, `num_rounds=5`, `eval_subset_size=40`. |
| `ProTeGi` | Supply `teacher_generator`; `num_gradients=4`, `errors_per_gradient=4`, `prompts_per_gradient=1`, `beam_size=4`. Optional `task_model`. | Supply `initial_prompts` for the starting beam. Optional keyword arguments: `num_rounds=3`, `eval_subset_size=32`. |
| `PromptWizardOptimizer` | Supply `teacher_generator`; `mutate_rounds=3`, `refine_iterations=2`, `beam_size=1`. Optional `task_model`. | Supply `initial_prompts` (first prompt used). Optional: `task_description`, `eval_subset_size=25`. |
| `GEPAOptimizer` | Supply `reflection_model`; `generator_model` defaults to `"gpt-4o-mini"`. | Supply `initial_prompts` (first prompt used). Optional: `max_metric_calls=150`. |

For Meta-Prompt, ProTeGi, and PromptWizard the teacher generator takes `prompt_template="{prompt}"`. That placeholder receives the optimizer's rewrite instructions; the starting **task** prompt uses your row placeholders instead. Meta-Prompt and GEPA do not accept arbitrary extra keyword arguments to `optimize()`.

## EarlyStoppingConfig

Import `EarlyStoppingConfig` from `fi.opt.utils.early_stopping` and pass an instance as `early_stopping=`. All fields default to `None`. The checker stops when **any** enabled condition is met. It updates the count and checks the budget first, then the score threshold, then patience.

| Field | Accepted value | Meaning |
|---|---|---|
| `max_evaluations` | Positive integer | Stop when the optimizer's reported row-evaluation count reaches or exceeds the budget. Checks happen after scoring, so a batch can exceed it. This isn't a limit on all model calls or on spend. For example, PromptWizard counts the mutation pool at its stopping check, not the later scoring of refined candidates. |
| `min_score_threshold` | Number from 0 to 1, inclusive | Stop when the score passed to the checker reaches or exceeds this value. |
| `patience` | Positive integer | Stop after this many consecutive checks without sufficient improvement. |
| `min_delta` | Nonnegative number | Reset patience only if the score is **greater than** the previous best plus this amount. With `None`, any positive improvement counts. Setting only `min_delta` doesn't enable stopping. |

In the [routing example](/docs/optimization/guides/optimize-from-the-sdk#read-the-result), `EarlyStoppingConfig(max_evaluations=6)` permits two Meta-Prompt rounds of three rows each. The reason string can report a different best score than `final_score`: the checker tests the budget before updating its own best score for that batch.

## Return values

### OptimizationResult

| Field | Meaning |
|---|---|
| `best_generator` | Generator holding the selected prompt; call `get_prompt_template()` to recover its text. |
| `final_score` | Score the optimizer reports for the selected prompt. |
| `history` | List of `IterationHistory` records. An algorithm that scores several candidates in a round can add several records. |
| `early_stopped`, `stop_reason` | Whether an `EarlyStoppingConfig` condition triggered, and the explanation if it did. Reaching the algorithm’s own limit (such as Meta-Prompt’s `num_rounds`) does not by itself set `early_stopped`. |
| `total_iterations`, `total_evaluations` | Counts the optimizer reports for scored iterations and row evaluations. They are not counts of provider requests. |
| `best_candidate`, `metadata` | Optional candidate object and result details. Defaults are `None` and an empty dictionary. |

In 0.3.7, Meta-Prompt, ProTeGi, and PromptWizard score candidates with `task_model` when supplied, but construct `best_generator` with the teacher's model. If those models differ, use `LiteLLMGenerator(model=task_model, prompt_template=result.best_generator.get_prompt_template())` for subsequent predictions on the tested model.

With Random Search in 0.3.7, a variation is added to `history` **before** the stopping check and selected as best **after** it. If stopping triggers, compare the last history score and prompt before accepting `best_generator`. If it stops on the very first variation, the generator can still hold the starting prompt and `final_score` can be `-1.0`.

### IterationHistory

`prompt` is the candidate text; `average_score` is its aggregate score; `individual_results` holds its row-level `EvaluationResult` records. The record can also carry `candidate_id`, `candidate_config`, `layers`, and `metadata`.

### EvaluationResult

`score` is numeric, `reason` is an explanation (empty string by default), and `metadata` is a dictionary (empty by default). For an exact-label metric, read the reason alongside the score to distinguish an output mismatch from an input validation failure.
