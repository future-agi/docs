## About

PromptWizard tries different styles of instruction before it decides what needs fixing. It scores the current prompt alongside the variations, checks the leading candidates for errors, then asks a teacher to critique and rewrite those that failed.

## Try one mutation and refinement cycle

Ridgeline Outfitters wants agents to ask for an order number before starting a return. The task prompt uses `{message}` for the customer ticket. The teacher uses `{prompt}` instead, because its input is a critique or rewrite request, not a ticket.

With Python 3.12, install Agent Learning Kit in a virtual environment:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install agent-learning-kit==0.3.7
```

Set `OPENAI_API_KEY` in the shell where you run the script. Save the example as `promptwizard.py` and run `python promptwizard.py`. The local `Contains` metric gives a reply `1` if it includes “order number” (case-insensitive) and `0` otherwise. You do not need Future AGI keys for this example.

<CodeGroup titles={["Python"]}>

```python
from fi.evals.metrics.heuristics.string_metrics import Contains
from fi.opt.base.evaluator import Evaluator
from fi.opt.datamappers import BasicDataMapper
from fi.opt.generators import LiteLLMGenerator
from fi.opt.optimizers import PromptWizardOptimizer

model = "gpt-4o-mini"
tickets = [
    {"message": "The rain shell is too big. Can I send it back?"},
    {"message": "I would like to return my unused headlamp."},
]
prompt = (
    "You work at Ridgeline Outfitters. Ask for the detail you need before "
    "starting a return. Customer message: {message}"
)
evaluator = Evaluator(metric=Contains(config={"keyword": "order number"}))
mapper = BasicDataMapper(key_map={"response": "generated_output"})

teacher = LiteLLMGenerator(model=model, prompt_template="{prompt}")
optimizer = PromptWizardOptimizer(
    teacher_generator=teacher, mutate_rounds=1, refine_iterations=1, beam_size=1,
)
result = optimizer.optimize(
    evaluator=evaluator,
    data_mapper=mapper,
    dataset=tickets,
    initial_prompts=[prompt],
    task_description="Ask for the order number and keep the {message} placeholder.",
)
print(f"Score: {result.final_score:.2f}")
print(result.best_generator.get_prompt_template())
```

</CodeGroup>

The script prints the highest mean keyword score, followed by the selected prompt. The returned `OptimizationResult.history` contains a record for each scored candidate, not just one per refinement iteration. A single cycle can therefore produce several entries.

## Parameters

| Where | Argument | SDK default | Purpose |
|---|---|---|---|
| Constructor | `teacher_generator` | Required | `LiteLLMGenerator` used for critique and refinement. |
| Constructor | `mutate_rounds` | `3` | Mutation calls per refinement cycle. Each asks for variations based on different thinking styles. |
| Constructor | `refine_iterations` | `2` | Number of complete mutate, score and refine cycles. |
| Constructor | `beam_size` | `1` | Number of top-scoring candidates to check for errors and consider for refinement. |
| Constructor | `task_model` | `None` | Model for mutations and for running candidate instructions. Falls back to the teacher's model. |
| `optimize()` | `evaluator`, `data_mapper`, `dataset` | Required | Metric wrapper, evaluator input mapping, and ticket rows. |
| `optimize()` | `initial_prompts` | Required | Nonempty list of templates. Only the first seeds the search. |
| `optimize()` | `task_description` | `"No task description given."` | Goal for the mutation step. |
| `optimize()` | `eval_subset_size` | `25` | Up to this many randomly sampled rows for comparing candidates in a cycle. |
| `optimize()` | `early_stopping` | `None` | Optional `EarlyStoppingConfig`, checked after scoring the mutation pool. |

## Limits and troubleshooting

- `beam_size=1` narrows refinement to one leader; it does not limit how many candidates get scored. Raising `mutate_rounds` or `refine_iterations` can add calls even when no prompt needs fixing.
- For each leader, the optimizer checks up to 10 sampled rows for scores below `0.5`. A leader with no failures skips critique. If no leader produces a rewrite, the highest-scoring candidate starts the next cycle. Otherwise the optimizer compares the rewrites with the instruction that started this cycle. Use at least one refinement iteration so there is a scored result to select.
- If you set `task_model` separately, the returned `best_generator` uses the teacher's model. Use its template with your task model when deploying the selected wording.
