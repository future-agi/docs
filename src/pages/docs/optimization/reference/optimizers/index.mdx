## About

A prompt optimizer tries different ways to ask a model to do a task, then compares its answers using a metric you choose. Suppose Ridgeline Outfitters wants its support agent to ask for an order number before starting a return. You could try different wording, add examples of good replies, or use the missed requests to decide what to change.

## Choose an optimizer

Install Agent Learning Kit with `python -m pip install agent-learning-kit==0.3.7`. Import the classes below from `fi.opt.optimizers`. Each link includes a complete Python example for the returns task.

| Optimizer | Python class | What changes between candidates? |
|---|---|---|
| [Random Search](/docs/optimization/reference/optimizers/random-search) | `RandomSearchOptimizer` | A teacher proposes a batch of alternative instructions before it sees any scores. Start here to compare wording. |
| [Bayesian Search](/docs/optimization/reference/optimizers/bayesian-search) | `BayesianSearchOptimizer` | Optuna selects examples to include with a fixed instruction. Use it when you have labeled replies you can show the model. |
| [Meta-Prompt](/docs/optimization/reference/optimizers/meta-prompt) | `MetaPromptOptimizer` | A teacher reads the scores and reasons, then rewrites one instruction for the next round. |
| [ProTeGi](/docs/optimization/reference/optimizers/protegi) | `ProTeGi` | A teacher critiques failing cases and proposes edits for each critique. Several competing prompts can survive a round. |
| [PromptWizard](/docs/optimization/reference/optimizers/promptwizard) | `PromptWizardOptimizer` | The optimizer proposes different instruction styles, scores them, then critiques and refines the leaders that still have failures. |
| [GEPA](/docs/optimization/reference/optimizers/gepa) | `GEPAOptimizer` | A reflection model uses examples of outputs and evaluator feedback to propose changes, with a budget measured in metric calls. |

## What you pass and what you get back

All six `optimize()` methods take an `evaluator` to score replies, a `data_mapper` to supply that evaluator's inputs, and a `dataset` (a list of row dictionaries). Random Search reads its starting prompt from the generator you pass to the constructor. The other five take `initial_prompts` on `optimize()`. Pass optimizer-specific arguments where the linked reference places them: `num_variations` belongs on the Random Search constructor, for example, but `num_rounds` belongs on the Meta-Prompt method.

Each returns a `fi.opt.types.OptimizationResult`. Read `result.best_generator.get_prompt_template()` for the selected template and `result.history` for the prompts scored along the way. `result.final_score` reports the selected score, with one caveat: [Random Search with early stopping](/docs/optimization/reference/optimizers/random-search) can stop before updating it. Each history entry includes `average_score` and `individual_results` with per-row scores and reasons.

Before adopting a prompt, check that it still includes the input placeholder, such as `{message}`, and evaluate it on tickets you did not use in the search. A reply that says “I don't need your order number” passes a keyword check but fails the returns policy.

## Dashboard settings are not SDK defaults

The [dashboard run form](/docs/optimization/guides/run-an-optimization) prefills the values below when you select an algorithm. The SDK defaults on the individual reference pages apply only to Python calls. If you create a platform run by API, include the listed configuration keys rather than passing SDK constructor options.

| Optimizer | Dashboard label, configuration key and prefilled value |
|---|---|
| Random Search | Number Variations: `num_variations=3` |
| Bayesian Search | Min examples: `min_examples=2`; Max examples: `max_examples=4`; No.of trials: `n_trials=5` |
| Meta-Prompt | Optimization Objective: `task_description=""`; Number of Rounds: `num_rounds=4` |
| ProTeGi | Number of gradients: `num_gradients=4`; Errors per gradient: `errors_per_gradient=4`; Prompts per gradient: `prompts_per_gradient=1`; Beam size: `beam_size=4`; Number of Rounds: `num_rounds=3` |
| PromptWizard | Mutated Rounds: `mutate_rounds=3`; Refined Iterations: `refine_iterations=2`; Beam size: `beam_size=2` |
| GEPA | Max Metric Calls: `max_metric_calls=40` |

The form shows **Optimization Objective** for all six and starts it empty. When you supply `optimizer_config`, the API checks its keys against the selected algorithm. Include `task_description` for Meta-Prompt; the other five accept it but do not require it. Missing algorithm-specific keys and unexpected keys both fail validation.
