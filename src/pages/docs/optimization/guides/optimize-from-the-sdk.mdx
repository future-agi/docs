## About

Ridgeline Outfitters needs its support router to return `RETURNS` or `SHIPPING`, not a reply to the customer. Use Agent Learning Kit's Meta-Prompt optimizer to score the existing prompt, ask a teacher model to rewrite it, and compare the two on the same tickets. You can run this in Python without creating a dashboard dataset.

## Install and authenticate

Use Python 3.10 or later. In a new virtual environment, install the pinned package:

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install agent-learning-kit==0.3.7
```

Set `OPENROUTER_API_KEY` in the environment where you'll run Python. Both the teacher and the ticket classifier use OpenRouter, so the provider receives the examples and charges for model calls. The score is an exact text comparison performed locally: you don't need Future AGI API keys for this example.

## Build the dataset

Make one row per ticket. Keep the expected `queue` as a separate field: the starting prompt uses only `{ticket}`. The teacher sees the labeled rows when it writes a new prompt. Because the SDK formats each rewrite against the whole row, the script rejects a winner that drops `{ticket}` or asks for `{queue}`. For example, a customer asking to exchange a jacket should go to `RETURNS` even though the ticket never uses the word “return.”

## Run the optimization

Save this as `route_tickets.py` and run `python route_tickets.py` in the activated environment.

<CodeGroup titles={["Python"]}>

```python
from string import Formatter

from fi.alk.optimize import BasicDataMapper, Evaluator, LiteLLMGenerator, MetaPromptOptimizer
from fi.evals.metrics.heuristics.string_metrics import Equals
from fi.opt.utils.early_stopping import EarlyStoppingConfig

model = "openrouter/openai/gpt-4o-mini"
rows = [
    {"ticket": "The tent arrived without its poles. Can I send it back?", "queue": "RETURNS"},
    {"ticket": "My hiking boots haven't arrived. Where is my package?", "queue": "SHIPPING"},
    {"ticket": "The rain jacket is too small. Can I exchange it?", "queue": "RETURNS"},
]
start = "Write a helpful reply to this outdoor-gear support ticket: {ticket}"
metric = Evaluator(metric=Equals(config={"case_sensitive": True}))
mapper = BasicDataMapper(key_map={"response": "generated_output", "expected_response": "queue"})
optimizer = MetaPromptOptimizer(
    teacher_generator=LiteLLMGenerator(model=model, prompt_template="{prompt}"),
    task_model=model,
)
result = optimizer.optimize(
    evaluator=metric,
    data_mapper=mapper,
    dataset=rows,
    initial_prompts=[start],
    task_description=(
        "Route each ticket using exactly one uppercase label, RETURNS or SHIPPING. "
        "Return no other text. Keep the literal {ticket} placeholder in the improved prompt."
    ),
    num_rounds=5,
    eval_subset_size=len(rows),
    early_stopping=EarlyStoppingConfig(max_evaluations=6),
)
if not result.history:
    raise RuntimeError("No round was scored. Check the row keys and optimizer logs.")
winner = result.best_generator.get_prompt_template()
fields = {(name, spec, conversion) for _, name, spec, conversion in Formatter().parse(winner)
          if name is not None}
if fields != {("ticket", "", None)}:
    raise ValueError("Do not use this winner: it must use only the literal {ticket} placeholder.")
for i, trial in enumerate(result.history, start=1):
    print(f"Round {i}: {trial.average_score:.2f}")
print(f"Evaluations: {result.total_evaluations}")
print(f"Stopped: {result.stop_reason}")
print(f"Best score: {result.final_score:.2f}")
print("Winning prompt:", winner)
```

</CodeGroup>

`{prompt}` and `{ticket}` serve different purposes. The teacher receives the optimizer's entire rewrite request through `{prompt}`. The task model receives one ticket at a time through `{ticket}`. After generation, `BasicDataMapper` passes the model's answer to `Equals` as `response` and the row's expected queue as `expected_response`. A correct label followed by an explanation scores zero.

## Read the result

One run produced:

```text
Round 1: 0.00
Round 2: 1.00
Evaluations: 6
Stopped: Evaluation budget exhausted: 6 >= 6 (best score: 0.0000)
Best score: 1.00
Winning prompt: Determine whether the following outdoor-gear support ticket is about a return or a shipping issue. Use the labels RETURNS or SHIPPING to categorize it based on its content. {ticket}
```

The original prompt missed all three labels. The rewrite matched all three. The budget stopped the search after two rounds of three tickets, even though `num_rounds` allowed five. The score in the budget message is the best the stopping checker recorded **before** the last round; `result.final_score` includes that round. Your rewrite and scores can differ. If a rewrite only ties the starting prompt, Meta-Prompt keeps the earlier prompt.

Before replacing your application's prompt, try the winner on tickets you kept out of the run. Three correct labels tell you the output format works for these tickets, not how accurately it will route the rest of your inbox.

## If scores stay at zero

If history is empty, inspect the optimizer logs for a skipped round; there is no scored winner. Otherwise, find the entry whose `prompt` you want to diagnose and inspect its `individual_results` for each row’s `score` and `reason`. The first entry is the starting prompt, not necessarily the rewrite. Verify that every row has `ticket` and `queue`, that the rewrite keeps `{ticket}`, and that the model returns just the label. Empty outputs can also mean the provider call failed; confirm the model and provider key before increasing the budget.
