## About

A winning trial is the highest-scoring **variation**, not necessarily a better prompt than the one you started with. Use the graph to compare with the baseline, the prompt diff to see the edit, and the trial items to decide whether you'd keep it. This page covers dashboard runs; for an Agent Learning Kit script, see [Read the result](/docs/optimization/guides/optimize-from-the-sdk#read-the-result).

## Open the completed run

In your dataset's **Optimization** tab, select a run marked **Completed**. Under **Optimization Results**, the **Evaluation Score** axis runs from 0 to 100. The horizontal axis starts at **Baseline**, the original prompt, followed by the numbered variations. Use **Evaluations** to choose the eval lines to display.

For Ridgeline's ticket router, follow the eval that compares the predicted queue with the expected label. A rise from 60 to 80 on that line means a gain of 20 percentage points, not a 20 percent increase relative to 60.

## The trial list

Below the graph, the list shows the variations in trial order and flags the highest-scoring one in the **Trial** column. The baseline appears on the graph, not as a row in this list. Each eval column shows its own score and, when a baseline score exists, its change in percentage points. With several evals, compare the columns: a higher mean can hide a drop on the eval you care about. Select **View Column** to show or hide columns.

## Open a trial

1. Select a trial row. On **Prompt**, read the candidate instruction. Turn on **Show Diff** to compare its changes side by side with the original. For the router, look for a change from “reply to the customer” to “return one queue label.”

{/* MEDIA: Prompt tab with Show Diff enabled and the baseline beside the candidate. */}

![Show Diff comparing the original prompt with the optimized prompt](/images/docs/optimization/trial-detail-show-diff.png)

2. Select **Trial Items**. For each scored row, compare **Input**, **Output**, and the per-eval scores. For example, did the prompt correctly return `RETURNS` on an exchange request, or did it return `RETURNS` for every ticket, including missing shipments?

{/* MEDIA: Trial Items with a ticket input, generated queue label, and evaluation score on the same row. */}

Check which tickets each trial actually scored before comparing averages. In a GEPA run, different candidates can be scored on different rows. Before adopting a rewrite, compare it with the original on the same tickets outside the run. The dashboard uses at most the first 50 rows in dataset order, not a fresh random sample of the entire dataset.

## If there are no results

| Status | What to do |
|---|---|
| **Queue** or **Running** | Check **Optimization Steps** for progress. The completed graph and trial table don't appear while the run is in progress. |
| **Failed** | Read the reason under **Failed to optimize**. Use [Optimization troubleshooting](/docs/optimization/troubleshooting) to decide what to change before another run. |
| **Cancelled** | The run shows **Optimization Stopped** instead of a trial list. [Start a new run from the stopped one](/docs/optimization/guides/run-an-optimization#restart-a-stopped-run). |
