To improve the summaries in a [dataset](/docs/dataset), start from its existing [prompt column](/docs/dataset/guides/run-a-prompt-on-every-row) and score alternative prompts against the same eval. The run returns a candidate for review without overwriting the original prompt.

<Prerequisites title="Before you start">
- A column created by **Run Prompt**: **Choose Column** only lists those. The example uses `summary_prompt`.
- At least one [eval attached to that column](/docs/evaluation/guides/running-evaluations). The example's [`summary_quality` eval](/docs/evaluation/builtin/summary-quality) scores the generated summaries.
</Prerequisites>

## Open the run drawer

1. Open the dataset containing `summary_prompt`.
2. Select **Optimization**.

   An empty tab shows **Run Optimization**; if you already have runs, look for **Optimize Prompts** in the grid header. Optimization is a tab on the dataset, so a run is always tied to the dataset you opened it from.

![The empty Optimization tab on a dataset, with Run Optimization below the empty-state message.](/images/docs/optimization/guides/run-an-optimization.png)

3. Select **Run Optimization** or **Optimize Prompts**.

   Both open the same drawer. If you see **Run Prompt** instead of the configuration fields, create the prompt output column first, then reopen the drawer.

## Fill the run drawer

1. In **Name**, keep the generated column-optimizer-timestamp name or enter a name you'll recognize. Your edit is kept instead of the generated value.
2. Set **Choose Column** to `summary_prompt`.
3. Keep **Choose Optimizer** set to [GEPA](/docs/optimization/reference/optimizers/gepa), the default.
4. Select an available **Language Model**.

![The Run Optimization drawer with GEPA selected and its Optimization Objective and Max Metric Calls fields above Evaluations.](/images/docs/optimization/run-optimization-drawer-gepa-parameters.png)

5. Enter `Produce concise, accurate summaries that capture the key points of the source text` in **Optimization Objective**.

   The objective is a goal statement that describes what the optimized prompt should achieve.

6. Keep **Max Metric Calls** at the suggested default of `40` for this example.

   This is the total number of metric evaluations the run can spend. All six [optimizers](/docs/optimization/reference/optimizers) share **Optimization Objective**; the other parameter fields change with the optimizer you select.

7. Open **Evaluations**.

   You should see `summary_quality` if it's attached to `summary_prompt`. Every attached eval scores the candidates. If the drawer shows “No evaluations added”, use **Add Evaluations** before starting.

Closing the unfinished drawer asks “Are you sure you want to close? Your work will be lost”. Confirming discards your entries.

## Start the run

1. Select **Start Optimization**.

   You should see “Optimization created successfully” and land on the new run's page instead of the run list. The run keeps going if you leave the tab.

A run samples at most 50 rows from the dataset regardless of how many rows the dataset holds, so results reflect that sample rather than the full dataset. [Read optimization results](/docs/optimization/guides/read-optimization-results) covers how to track the run and read what it produces.

If submission is blocked with “Add evaluations before starting your optimization run”, check the selected column's **Evaluations** list. If the server returns no specific error, the toast says “Failed to create optimization”; retry with **Start Optimization**.

## Stop a run

1. On a **Queue** or **Running** row, select **Stop**.
2. In the **Stop optimization run** dialog, select **Stop Optimization**.

   The status becomes **Cancelled**. There is no **Stop** control on a completed, failed, or cancelled run.

## Restart a stopped run

1. Open the **Cancelled** row.

   The **Optimization Stopped** panel says “The run was stopped before completion. Click below to start it again.”

2. Select **Re-Run Optimization**.
3. Review the **Re-run Optimization** drawer.

   The column, optimizer, model, configuration, and evals carry over; the name has a `- Rerun - <date>` suffix.

4. Select **Start Optimization**.

   This launches a new run from the beginning. It does not resume the stopped run.

## Create a hosted run from code

The [platform SDK reference](/docs/sdk/reference/optimizations#optimizationscreate) documents `client.optimizations.create` in Python and TypeScript and the MCP tool `create_optimization_run`. These operate on a hosted dataset column by ID. The local `agent-opt` workflow takes a dataset you supply in Python instead.
