## About

A self-hosted Future AGI install runs as Community until you activate an Enterprise license. This page covers what each edition includes, what "no commercial usage caps" means on your own hardware, what you still pay for, how to get and activate a license on Docker Compose or Helm, what happens when a license expires, and what to check when a gate still appears after you activate.

<TLDR>
Community includes one organization, one workspace and up to 3 members, with no commercial usage caps on the products it includes. Enterprise adds Falcon AI, Turing Models, Protect, Error Feed, and more members, organizations and workspaces. To get a license, email sales@futureagi.com. To activate it, set `EE_LICENSE_KEY` for every backend and worker service, restart them, then check **Settings → Plan & License**. If a license expires or you remove it, everything you have stays; creating more than Community allows, and new work in the four Enterprise products, needs a usable license again.
</TLDR>

## Compare the editions

| Capability | Community | Enterprise |
|---|---|---|
| Falcon AI, Turing Models, Protect, Error Feed | Not available | Available |
| Organization members | Up to 3 | More than 3 |
| Organizations | 1 | More than 1 |
| Workspaces | 1 | More than 1 |
| Other products included in Community | Available, no commercial usage caps | Available, no commercial usage caps |

Every self-hosted install without a usable license is Community. A usable Enterprise license lifts all three limits. Organizations and workspaces are counted across the whole install. The member limit counts active members plus invites that are still pending. An invite that has expired doesn't count. Deactivated members don't count, and reactivating one counts as adding a member.

When you try to add a fourth member, a second organization or a second workspace on Community, the app shows an Enterprise feature dialog with **Contact sales** and **Activate license**. Nothing is created and nothing you already have changes. The API returns HTTP 402 with the code `ENTERPRISE_FEATURE_REQUIRED` and an `enterprise_gate` object. It isn't a rate limit, so retrying won't help.

{/* Confirm against the implementation before publishing: the counting rules above, the dialog and button labels, and the 402 body (code ENTERPRISE_FEATURE_REQUIRED, enterprise_gate). */}

On Community, a second person joins by invitation. Signing up on the sign-up page creates a new organization, so a second sign-up is refused. Running `create_user` a second time is refused for the same reason, with a message telling you to invite the user from Settings instead. See [Users & sign-in](/docs/self-hosting/user-management#create-accounts) for how to invite people.

## What "no commercial usage caps" means

Future AGI Cloud meters usage: dataset rows, eval and prompt runs, knowledge bases, MCP calls, ingested events and gateway requests all have plan allowances there. On a self-hosted install, the products included in Community have none of those allowances, on either edition. The edition limits above are the only limits Future AGI sets on them.

Your install is still bounded by what you run it on and by the controls you configure:

- **Your hardware.** CPU, memory, disk and database size decide how much you can ingest and store. See [Requirements](/docs/self-hosting/requirements).
- **Your gateway budgets and rate limits.** Budgets and limits you set on the LLM gateway still apply. See [Rate limiting](/docs/command-center/features/rate-limiting).
- **Guardrails.** Guardrails you configure still block what they're set to block. See [Guardrails](/docs/command-center/features/guardrails).
- **Safety bounds.** Authentication, API-key revocation, and the MCP server's response size and depth limits stay on. A request refused for one of these reasons says why. It never asks you to upgrade.

## What you pay for

No commercial usage cap doesn't mean nothing costs money:

- **Your infrastructure.** You run the hosts, storage and databases, and pay for them.
- **Your model providers.** Calls made with your own provider keys, such as LLM-as-judge evals, prompt runs and gateway traffic, are billed to you by that provider, under your agreement with them. Future AGI sets no usage caps on them.
- **Services hosted by Future AGI.** Optional services hosted by Future AGI, such as Turing Models, use the entitlements or credits in your contract. They need a connection from your install to Future AGI, and stop working without one. See [Telemetry and outbound connections](/docs/self-hosting/configuration/telemetry).

An Enterprise license is a contract with Future AGI; [sales@futureagi.com](mailto:sales@futureagi.com) can tell you what yours covers.

## Get an Enterprise license

Email [sales@futureagi.com](mailto:sales@futureagi.com) for a license, a renewal, or help activating one. The license arrives as a key you set in your environment. Your install checks the key itself with a signature check, so deciding the edition never needs a connection to Future AGI. The license heartbeat and the services Future AGI hosts make their own connections; see [Telemetry and outbound connections](/docs/self-hosting/configuration/telemetry).

## Activate a license

Activation sets the key for every service that runs the backend code, then restarts them. Each service reads the key once when it starts. A service you don't restart keeps running as Community.

<Warning>
**Treat the license key as a secret.** Keep it out of version control, shell history and support posts, and never pass it on a command line. Plan & License never shows the full key.
</Warning>

{/* Confirm against the implementation before publishing: what Plan & License shows in place of the key (proposed: a masked license ID and a short fingerprint). */}

<Tabs>
<Tab title="Docker Compose">
<Steps>
<Step title="Add the key to .env">
In the repository root, add the key to `.env`:

```bash
EE_LICENSE_KEY=YOUR_LICENSE_KEY
```

If Future AGI sent a public key with the license, add it too; images with Future AGI's public key built in ignore it. Write the PEM key on one line in single quotes, with `\n` where each line break was. The app turns each `\n` back into a line break:

```bash
EE_LICENSE_PUBLIC_KEY='-----BEGIN PUBLIC KEY-----\nYOUR_PUBLIC_KEY_LINES\n-----END PUBLIC KEY-----'
```

With the production overlay, put `EE_LICENSE_KEY` in `deploy/.env.production` and `EE_LICENSE_PUBLIC_KEY` in the root `.env`: the compose files pass `EE_LICENSE_KEY` on from the overlay's env file, and the public key reaches the containers only from the root `.env`. See [Which file a key goes in](/docs/self-hosting/production/checklist#which-file-a-key-goes-in).
</Step>
<Step title="Restart the services">
```bash
docker compose up -d
```

This recreates every container whose environment changed, and their start-up adds the Enterprise apps' database tables before the API starts. On Standalone that is `app`, whose API process also runs the Temporal worker. On Distributed it is `backend`, every `worker` service, `serving` and the start-up jobs.

With the production overlay, its start-up jobs only check the schema, and the first activation adds tables. Run the PostgreSQL schema job from [`deploy/README.md`](https://github.com/future-agi/future-agi/blob/main/deploy/README.md#performing-that-initialization-first-install) once, then start the stack with the overlay's command:

```bash
docker compose --env-file deploy/.env.production \
  -f docker-compose.distributed.yml -f deploy/docker-compose.production.yml up -d
```

Without the schema job, the schema check fails and the backend and workers don't start.
</Step>
<Step title="Check the start-up log">
```bash
docker compose logs | grep license_startup
```

Each backend and worker service logs `license_startup_active` when the license is usable. `license_startup_invalid` or `license_startup_unusable` means the key, the public key or the license's dates need checking: see [Troubleshooting](#troubleshooting). With the production overlay, pass the same `--env-file` and `-f` flags to `docker compose logs`.
</Step>
</Steps>
</Tab>
<Tab title="Helm">
<Steps>
<Step title="Store the key in a Secret">
Write the key to a file, `license.env`, in the same form as a `.env` line:

```bash
EE_LICENSE_KEY=YOUR_LICENSE_KEY
```

Create the Secret from that file, so the key stays off the command line, then delete the file:

```bash
kubectl -n futureagi create secret generic futureagi-license --from-env-file=license.env
rm license.env
```
</Step>
<Step title="Set the values and upgrade the release">
Add the edition and the Secret to `my-values.yaml`, so every later upgrade keeps them. Add `publicKey` only if Future AGI sent a public key with the license:

```yaml
edition: ee
license:
  existingSecret: futureagi-license
  publicKey: |
    -----BEGIN PUBLIC KEY-----
    YOUR_PUBLIC_KEY_LINES
    -----END PUBLIC KEY-----
```

Then upgrade with every values file you installed with, as in [Upgrade and roll back](/docs/self-hosting/helm#upgrade-and-roll-back):

```bash
helm upgrade futureagi oci://ghcr.io/future-agi/charts/futureagi --version "$VERSION" \
  -n futureagi -f medium.yaml -f my-values.yaml --timeout 20m
```

`edition: ee` refuses to render without a license. The bootstrap job runs first and adds the Enterprise apps' database tables, then the backend and worker Deployments roll with the key.
</Step>
<Step title="Restart after a renewal">
When you later replace the key inside the same Secret, for a renewal, the chart's values don't change, so the pods keep the old key until they restart. Restart this release's backend and workers:

```bash
kubectl -n futureagi get deployments -l app.kubernetes.io/instance=futureagi -o name \
  | grep -E '/futureagi-(backend|worker)' | xargs kubectl -n futureagi rollout restart
```

The workers are `futureagi-worker`, `futureagi-worker-exact-aggregation` and one `futureagi-worker-<queue>` per entry in `worker.queues`. With a release name other than `futureagi`, list them with `kubectl -n futureagi get deployments -l app.kubernetes.io/instance=<release>`. Or set `reloader.enabled: true`, and Stakater Reloader restarts the Deployments when a Secret they read changes.
</Step>
<Step title="Check the start-up log">
```bash
kubectl -n futureagi logs deploy/futureagi-backend -c backend | grep license_startup
kubectl -n futureagi logs deploy/futureagi-worker -c worker | grep license_startup
```

A usable license logs `license_startup_active`.
</Step>
</Steps>
</Tab>
</Tabs>

While a restart is rolling out, a request can reach a service that hasn't restarted yet and get the Community answer. Wait until every service has restarted, then retry. Nothing is lost.

## Verify the license

Open **Settings → Plan & License** as an organization Owner or Admin (`/dashboard/settings/ee-licenses`). A usable license shows **Enterprise · Self-hosted**, the license state, who it was issued to and when it expires. Without a usable license the page shows **Community · Self-hosted** with your current organizations, workspaces and members against the Community limits.

## Renewal and expiry

Expiry needs no restart: each service checks the license's dates as it works. A license with a grace period keeps working until the grace period ends, and Plan & License shows the grace end date. After that, the install runs as Community:

- Everything you have stays, with the permissions it already has: organizations, workspaces, members, traces, datasets, evals and every other record. Nothing is deleted or deactivated.
- Creating an organization, a workspace or a member past the Community limits needs a usable license again, and shows the Enterprise dialog.
- Falcon AI, Turing Models, Protect and Error Feed also need a usable license. An activity that's already running when the license ends may finish; the next one that needs the license is refused, so a job made of several steps can stop partway.

To renew, email [sales@futureagi.com](mailto:sales@futureagi.com) before the expiry date, then activate the new key the same way: replace `EE_LICENSE_KEY` and restart every backend and worker service. On Helm, see [Restart after a renewal](#activate-a-license).

The license is checked on your install with a signature check. A network outage, a firewall or an air-gapped install doesn't change your edition. The license heartbeat only reports to Future AGI; turning it off doesn't affect the license. In this release the check doesn't tie a license to one install, and a license can't be revoked before it expires.

## Downgrade and data safety

Removing the key and restarting every backend and worker service turns the install back into Community. No data is deleted or deactivated, and everything keeps its existing permissions. Data in Falcon AI, Turing Models, Protect and Error Feed stays in your databases, but those products need a usable license to use again.

An install that is over a Community limit, from an earlier license or from before this release, keeps everything it has. Creating more organizations, workspaces or members past a limit needs a usable license, and Plan & License says which limit you're over.

## Upgrade note for custom manifests

From this release, fi-collector and the LLM gateway read `COMMERCIAL_QUOTAS_ENABLED`. Unset means the Cloud usage caps code is on. The shipped Compose files and the Helm chart set it to `false`, so a standard install needs nothing.

If you run your own Compose files or pass your own environment to fi-collector and the gateway, set it to `false` on both:

```bash
COMMERCIAL_QUOTAS_ENABLED=false
```

Without it, an install that holds usage counters or pause keys left in Redis from an earlier release can still have trace ingestion paused or gateway requests refused with an upgrade message. See the [Configuration reference](/docs/self-hosting/configuration/reference).

## Troubleshooting

**The Enterprise dialog still appears after you activated.** A service is still running without the key. Check the start-up log of each backend and worker service for `license_startup_active`, and restart any that don't show it. On Distributed and Helm the workers are separate services, and they're the ones most often missed.

**Plan & License still shows Community after every service restarted.** Your browser has the old answer cached. Reload the page.

**The start-up log shows `license_startup_invalid`.** The key was copied incompletely, or the image needs the public key Future AGI sent with it. Check both, then restart. If the license isn't valid yet, check the host clock: the check tolerates `EE_LICENSE_CLOCK_SKEW_SECONDS` of drift (300 by default; `license.clockSkewSeconds` on Helm).

**Trace ingestion pauses or the gateway returns "Upgrade to Pay-as-you-go".** fi-collector or the gateway is running without `COMMERCIAL_QUOTAS_ENABLED=false`. Set it as in the [upgrade note](#upgrade-note-for-custom-manifests) and restart them.

**A second person can't sign up.** Community has one organization, and sign-up creates a new one. Invite them from Settings instead.
