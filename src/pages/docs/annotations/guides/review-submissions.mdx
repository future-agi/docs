In a [queue](/docs/annotations/concepts/queues-and-items) that requires reviewer approval, collecting enough answers doesn't finish an item. A fully annotated item lands in pending review and waits for a reviewer. This guide covers the reviewer's side: compare the submissions, send an answer back with feedback if it needs fixing, and approve the item once the issue is resolved.

<Prerequisites title="Before you start">
- Your organization needs the [review workflow entitlement](/docs/annotations/reference/queue-settings-and-limits#limits-caps-and-gated-features), and the queue must have **Require reviewer approval** enabled.
- You can't review an item you annotated yourself. **Approve** and **Request changes** don't appear on an item you submitted answers for, even if you also hold the reviewer role on the queue.
- Start with an item pending review. For example, in [Support quality review](/docs/annotations/guides/create-queue), the required annotators each submit their `Response quality` answer with **Submit for Review**.
</Prerequisites>

## Open the comparison

1. Open the queue containing the submitted item.
2. Choose the entry point for your role:

   - **Reviewer only:** select **Review Items** in the queue header to open the first item pending review.
   - **Reviewer and annotator:** in the annotation workspace, switch **Workspace action** from **Annotate my answers** to **Review submissions**. Only people with both roles see this toggle.

3. Compare the annotators' answers to each [label](/docs/annotations/concepts/labels) side by side.

   The comparison panel lays out every annotator's answer for the item, so you can weigh `Response quality` from both submissions before deciding. Each answer has its own feedback field. **Approve** and **Request changes** apply to the item as a whole.

If the header button reads **View Submissions** instead of **Review Items**, the queue's **Require reviewer approval** setting is off. That depends on the setting, not on the entitlement. The workspace is then read-only: you can read what was submitted, but there's nothing to approve or send back.

## Request a change

1. If the problem is one specific answer, click **Feedback** on that annotator's row.

   If it applies to the whole item, use the **Whole-item feedback** box instead.

2. Write what needs to change.
3. Click **Done** to close an answer's feedback field. **Clear** discards what you typed.
4. Click **Request changes**.

   The item goes back to the annotator. **Request changes** stays disabled until you've left a note in **Whole-item feedback** or on at least one answer. **Approve** takes no note and is disabled the moment you type any feedback, so clear the feedback if you decide to approve instead.

## Recheck the revised answer

The annotator sees your feedback in the header's **Comments** button and as a **Reviewer feedback** alert in the [annotation workspace](/docs/annotations/guides/annotate-items), then revises and resubmits the answer. The item lands back in pending review the same way it did the first time.

1. Reopen the item from the **Items** tab once it is pending review again.
2. Compare the revised answer with what you asked for.
3. Click **Approve** if the issue is resolved.

   The item moves to completed. **Approve** is unavailable while an earlier request for changes on the item is still open, so the request has to be addressed first.

## Follow the comment threads

Every review action (comment, approve or request changes) drops into a thread scoped to the item or to one specific answer. A thread moves through open, addressed, resolved and reopened as reviewers and annotators go back and forth. You can @mention teammates in a comment, up to 50 per comment.

## Approve in bulk

When there's nothing to argue with, you don't have to open every item.

1. On the queue's **Items** tab, select the items you want to clear.
2. Click **Approve Selected**.

   The button appears only once at least one selected item is pending review, and it counts only the pending-review items in your selection.

## Read submissions from code

Over REST, [Get Queue Item Annotations](/docs/api/annotations/items/get-item-annotations) returns the annotation scores submitted for a queue item, including label values and the annotator ID. In Python or TypeScript, the [queue SDK reference](/docs/sdk/reference/annotation-queues#annotation_queuesitemslist_annotations) documents the method that lists an item's annotations. Both only read submissions. This guide covers approving and requesting changes in the review workspace. To get completed items into a [dataset](/docs/dataset), export them.
