---
title: "Annotate items"
description: "Work an item end to end in the annotation workspace: read the source, answer the labels, submit"
---

Once a queue is active and has items in it, this is where an annotator actually spends their time: one item, one set of labels, over and over. This walks through a full pass using an item from `Support quality review`, the queue built in [Create a queue](/docs/annotations/guides/create-queue).

## Open the workspace

From the queue's Items tab, or its **Start Annotating** button (see [Explore a queue](/docs/annotations/guides/explore-queue) for where those live), click into an item to open the workspace. It splits into two panes across a resizable divider: the source on the left, the labels on the right.

## Read the source

The left pane renders whatever the item points at, a [trace, dataset row, or one of the other source types](/docs/annotations/concepts/understanding-annotation) a queue can hold. This is what you're judging; everything you do next happens in the right pane.

## Answer the labels

The right pane lists every [label](/docs/annotations/concepts/labels) the queue collects answers for, under a **Labels** heading. If the queue creator wrote instructions, they're in a collapsible section above the labels, worth a look before your first item. Answer each label with whichever control matches its type; number keys `1`-`9` select an option or set a rating on the focused label without touching the mouse.

The submit button stays off until every label attached to the queue has an answer. Try to submit early and it tells you exactly what's missing: **Please annotate all labels: `{names}`**.

<Note>
Numeric and text answers are checked again on the server, not just by the control you see. A numeric value has to land within the label's configured min, max, and step; a text value has to fall within its length bounds. See [Label types & values](/docs/annotations/reference/label-types-and-values) for the exact numbers per label.
</Note>

## Add a note

Below the labels, an optional **Notes** field ("Add notes for this item...") lets you leave a comment about the item that isn't tied to any single label's value, useful context for why the scores landed where they did.

## Submit

Once every label's answered, the submit button enables, and its text tells you what it's about to do:

- **Submit & Next**: a fresh answer, and the queue doesn't require reviewer approval
- **Submit for Review**: the queue requires reviewer approval, so this answer lands in review instead of finishing outright ([Review submissions](/docs/annotations/guides/review-submissions) covers what happens next)
- **Update & Next**: you're revising an answer you already submitted

Submitting moves the item off pending into in progress; it only actually completes once every required label has been answered by the number of annotators the queue's submissions-per-item setting calls for.

## Skip or move between items

**Skip**, in the header or the `S` key, moves you to the next item without submitting anything for this one. It won't work on an item that's already completed or sitting in review; the button explains why on a completed item: **Completed items cannot be skipped**.

To move around without skipping, use **Previous** / **Next** in the footer, or the position indicator (`n / total`) to see where you are. **Back to Queue** returns you to the queue detail view, **Show completed** toggles whether finished items reappear in your list, and **Comments** opens the item's comment thread.

## Keyboard shortcuts

| Shortcut | Action |
|----------|--------|
| `Tab` / `Shift+Tab` | Move to the next / previous label |
| `1`-`9` | Select an option or set a rating on the focused label |
| `Cmd/Ctrl+Enter` | Submit and move to the next item |
| `S` | Skip the current item |
| `←` / `→` | Move to the previous / next item |
| `?` | Toggle the shortcuts overlay |

## What stops you from opening an item

- **Item Reserved**: someone else already has this item open. Pick a different one.
- **Queue Not Active**: the queue isn't active, so nothing in it can be annotated yet.
- **Assigned to `{name}`**: without auto-assign on, an item assigned to someone else stays closed to you.
- **All Done!**: every item you have access to is answered, and this screen replaces the workspace.
