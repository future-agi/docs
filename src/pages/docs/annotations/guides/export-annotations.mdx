Once an annotation [queue](/docs/annotations/concepts/queues-and-items) has completed items worth keeping, export them. Download the queue as a file to inspect its [sources](/docs/annotations/concepts/understanding-annotation) and scores, or write selected items into a [dataset](/docs/dataset) for [evaluation](/docs/evaluation). The route you pick decides which statuses and fields you keep.

<Prerequisites title="Before you start">
- A queue with items to export, such as `Support quality review` from [Create a queue](/docs/annotations/guides/create-queue).
- For the API, the queue ID and [workspace API credentials](/docs/admin-settings/api-keys).
</Prerequisites>

## Choose an export

| If you need | Use | What you get |
| --- | --- | --- |
| Every status, with source content | **Export > Download** | A JSON file with one entry per item and nested annotations. No UI format or status picker. |
| A status filter, or rows instead of nested JSON | The queue export endpoint | JSON or CSV. CSV has one row per label value, not one row per queue item. |
| Selected annotations as dataset columns, or more than 1,000 items | **Export > Export to Dataset** | A new dataset or rows added to an existing one, with a status filter and column mapping. No item cap. |

## Download JSON

1. Open `Support quality review`.
2. Select **Export > Download** in the queue header.

   Every item in the queue, any status, downloads immediately as a JSON file: one entry per item, carrying its annotations, review status, and the source's own content resolved onto it.

Each entry holds these fields:

| JSON field | What it holds |
| --- | --- |
| `item_id` | Queue item ID |
| `source_type` | `trace`, `observation_span`, `trace_session`, `prototype_run`, `call_execution`, or `dataset_row` |
| `source_id` | ID of the annotated source |
| `status` | `pending`, `in_progress`, `completed`, or `skipped` |
| `order` | Position in the queue |
| `review` | Review status and reviewer, once reviewed |
| `item_notes` | Latest note on the item |
| `annotations` | Submitted label values, annotators and score sources |
| `annotation_metrics` | Annotations keyed by label name |
| `evals` | Eval scores already attached to the item's source, if any |
| `source` | Content of the source itself |

## Request a filtered file

The endpoint behind **Download** also accepts a CSV format and a status filter. There's no picker in the UI for either yet, so call the [queue export endpoint](/docs/api/annotations/queues/export) directly.

1. Call the export endpoint for your queue ID.
2. Set `export_format` to `csv` for rows, or leave it at `json` for nested items.

   CSV flattens item, review, and annotation fields to one row per label value. It drops `source`, `evals`, `source_id`, `item_notes`, and `annotation_metrics`.

3. Set `status` if you only want items in one state, such as `completed`.

## If the queue has more than 1,000 items

Download tops out at 1,000 items, the [synchronous export limit](/docs/annotations/reference/queue-settings-and-limits). Push past that and it returns an error instead of a file, since there's no status filter on the button to narrow the set first. For a queue that big, use **Export to Dataset** instead, which carries no such cap, or filter by status through the API. [Self-hosted deployments](/docs/self-hosting) can raise the ceiling with the `ANNOTATION_EXPORT_SYNC_MAX` Django setting.

## Export to a dataset

1. In the queue header, click **Export > Export to Dataset**.

   The export drawer opens.

2. Choose **Create new dataset** or **Add to existing dataset**.
3. Name the new dataset or search for the existing destination.
4. Set **Items to export**. The default is **Completed only**; other choices are **All items**, **Pending only**, and **In Progress only**.
5. Review the mapping from source fields, labels and review details to dataset columns.

   For example, check which column will receive `Response quality`. You can rename, add, or drop columns before the export.

6. Click **Export**.
7. Open the destination dataset and check for the mapped label column and the rows your filter selected.

Unlike Download, Export to Dataset has no item cap, so a queue past 1,000 items still exports in full.

From code, the [dataset export endpoint](/docs/api/annotations/queues/export-to-dataset) does the same job and returns the dataset's ID and name and a `rows_created` count.

## What you do with it

- **Fine-tuning:** the annotated examples become training data for a model update.
- **Eval datasets:** completed items become a golden set you run other evals against.
