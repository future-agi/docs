Fill an annotation [queue](/docs/annotations/concepts/queues-and-items) with the items your reviewers need. Hand-pick rows when you know which ones to review; use a filter when you want every match, not just the rows on screen.

<Prerequisites title="Before you start">
- An existing queue, such as `Support quality review` from [Create a queue](/docs/annotations/guides/create-queue).
- Manager access on that queue. Without it, the add and assignment controls are hidden.
</Prerequisites>

## Open the picker

1. Open `Support quality review`.
2. Select **Items**.
3. Select **Add Items**.

   On an empty queue the button sits under **No items in this queue**. Otherwise it's in the toolbar above the table.

4. Choose a source: **From Datasets** for [dataset rows](/docs/dataset/concepts/understanding-datasets), **From Traces** for [traces](/docs/observe/concepts/traces), **From Spans** for [spans](/docs/observe/concepts/spans), **From Sessions** for [sessions](/docs/observe/concepts/sessions), or **From Simulation** for [simulation runs](/docs/environments).

## Hand-pick items

1. Check the specific rows you want.
2. Select **Add to queue**.
3. Find the selected sources on **Items**.

   Check who the new items are assigned to. With auto-assign off they arrive unassigned, and someone has to assign them by hand. With auto-assign on, every queue member can annotate any item without being assigned to it first.

You can also start from a traces table: select the rows, then open **Actions > Add to annotation queue**. The popover lets you search for an existing queue or create one.

## Add every filter match

1. In the picker, set the filters above the source table.
2. Tick the header checkbox.

   A banner offers to extend the selection beyond the rows on screen.

3. Select **Select all N matching your filter**.
4. Select **Add to queue**.

   For traces, spans, sessions and simulation, the queue resolves everything the filter matches on the server at that moment, not just what's loaded on screen.

5. Compare the confirmation with the rows on **Items**.

   Duplicates are skipped, not errored. A source that is already in the queue, or that shows up twice in what you're adding, is dropped, and the confirmation names the count, for example “12 items added · 3 already in queue”.

The picker splits large hand-picked selections into requests. Filter selections above 10,000 are rejected in full: narrow the filter before trying again. An enumerated list sent directly to the [Add Items endpoint](/docs/api/annotations/items/add-items) is limited to 1,000 items per call; a larger list returns HTTP 413. The [Python and TypeScript SDK reference](/docs/sdk/reference/annotation-queues#annotation_queuesitemsadd) describes the corresponding add operation.

## Find and assign a row

1. On **Items**, narrow the table by item status or source.

   Review status is available only when review is enabled. **My Items** shows only items assigned to you. The preview is a snapshot from the time of addition; opening an item to annotate shows the current source.

2. Select the rows to assign.
3. Select **Assign Selected**.
4. In **Assign Selected Items**, choose the queue members who should work the rows.

   This replaces the full set of assignees. Selecting nobody clears assignment; someone who is not a member of the queue cannot be assigned.

## Remove items

**Removal has no undo.** It takes the selected items and their submitted annotations out of the queue. Adding the source again creates a new item with zero submissions. To keep submissions and just clear the assignees, use **Assign Selected** instead.

1. Select only the rows you intend to remove.
2. Select **Remove Selected**.
