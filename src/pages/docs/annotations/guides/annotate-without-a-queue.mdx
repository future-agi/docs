Not every [score](/docs/annotations/concepts/scores) needs a [queue](/docs/annotations/concepts/queues-and-items) behind it. If you notice a problem while reading a [trace](/docs/observe/concepts/traces), score it right there, on the trace itself, instead of setting a queue up for a one-off judgment.

<Prerequisites title="Before you start">
- A [source](/docs/annotations/concepts/understanding-annotation) open in Future AGI: a trace, [span](/docs/observe/concepts/spans), [dataset row](/docs/dataset), or [prompt run](/docs/prompt).
- A [label](/docs/annotations/concepts/labels) for what you want to score. The labels on offer are the ones set up for the workspace.
</Prerequisites>

## Score the source

<Mermaid chart={`flowchart LR

    accDescr: From a source's Annotations tab, choose a workspace label and a value. Save the score and read it back on the source.
    A["Source: Annotations"] --> B["Label and value"]
    B --> C["Save score"]
    C --> D["Read it on the source"]

1. Open the source's detail view.
2. Select **Annotations**.

   You should see any scores already recorded on this source.

3. Click **Annotate** to enter edit mode.
4. Pick a label that applies, for example `Response quality`.
5. Fill in its value.

   You can pick more than one label and fill in a value for each before saving.

6. Optionally type a note in the box under the label.

   Not every label carries a note field, only the ones set up for it. Where one is available, it is already visible under the label, with no click needed. To add the field to a label, check **Allow notes** when you [create the label](/docs/annotations/guides/create-label).

7. Click **Save**.

   The **Annotations** tab should now list the value you saved. Saving writes the same kind of score record as one submitted through a queue. It shows up wherever the source appears and in [exports](/docs/annotations/guides/export-annotations), right next to any queue-based scores on the same source.

## Correct a score

To correct a judgment, score the same label again on the same source. When the same annotator scores the same source and label inline twice, the second write lands on the same score and updates it, and the old value is kept in the score's history.

## Score from code

The [scores SDK reference](/docs/sdk/reference/scores#scorescreate) shows `scores.create` in Python and TypeScript. To read back what was stored, [list the scores for the source](/docs/api/annotations/scores/get-scores-for-source).

## When to use a queue instead

A score saved on the spot is right for a one-off: you noticed something while looking at a source and want it on record. It stops being enough once more than one person needs to score the same batch of sources, or you need to see how far through that batch you've gotten. That's what a queue is for: it organizes who scores what, and whether a reviewer has to approve before it counts as done.
