## A reusable question with a fixed answer type

A **label** is a reusable question plus the answer type it accepts. Attach it to a [queue](/docs/annotations/concepts/queues-and-items) and every annotator working that queue answers the same question, the same way, and each answer lands as a [score](/docs/annotations/concepts/scores). The full object model connecting labels, queues, and scores lives in [Understanding Annotation](/docs/annotations/concepts/understanding-annotation); this page is about the label on its own.

Three things follow from that definition.

**The type is the contract.** A label's type fixes the control the annotator sees, whether that's radio buttons, a number slider, a text box, stars, or a thumbs toggle, and it fixes the shape of the value that gets written into the resulting score. Because every score under a label depends on that shape staying put, the type is locked once the label is created: you can still edit its name, description, or settings afterward, but you can't turn a numeric label into a categorical one.

**Labels are organization-scoped.** A label belongs to the org, optionally narrowed to a workspace, not to any single queue. A queue attaches an existing label rather than copying it, so editing a label's name, description, or settings changes it everywhere it's attached, because every queue is pointing at the same row.

**A queue needs at least one label to exist.** You can't create or save a queue with zero labels attached. The label is what turns a pile of items into something answerable.

## Five types, five kinds of judgement

- **Categorical** offers a predefined set of options to choose from. Reach for it when the answer is one of a fixed list: a defect category, a sentiment, an escalation reason
- **Numeric** collects a score within a range. Reach for it when the judgement is a matter of degree: relevance from 1 to 10, a quality score out of 100
- **Text** collects free-text feedback. Reach for it when you need a correction, a rewrite, or an explanation in the annotator's own words
- **Star Rating** is a star-based rating. Reach for it for a quick, low-friction quality gut-check
- **Thumbs Up/Down** is binary feedback. Reach for it for a single pass/fail call, the fastest type to answer

The settings each type requires and the exact validation applied to a submitted value live on [Label types & values](/docs/annotations/reference/label-types-and-values).

## Picking a type

Match the type to the shape of the judgement, not the topic:

- The answer is one of a fixed set of outcomes → Categorical
- The answer is a position on a scale → Numeric
- The answer is open-ended, in the annotator's own words → Text
- The answer is a fast quality gut-check → Star Rating
- The answer is a single yes/no call → Thumbs Up/Down

If an item needs more than one kind of judgement, attach more than one label to the queue rather than stretching a single label to cover two jobs.

## Why it matters

Because a label is one row that every attached queue points at, standardizing on a small set of labels (one for quality, one for tone) is what keeps scores comparable across teams and projects: everyone answering "Response quality" is answering the exact same categorical question, with the exact same options. And because the type is locked, whatever you build a dashboard or export against today keeps the same shape tomorrow.
