## Package and deployment prerequisites

The SDK source contains `fi.context` transport and CLI interfaces. That is different from a verified package release. This page documents the inspected interface, not a successful clean-install or native-host qualification. An operator must obtain the deployment-compatible released package and its provenance before use. No `pip install` version is asserted here.

The context **Use** surface may remain unavailable when its qualification prerequisites are missing. Neither direct API access nor a preview profile overrides that boundary. [Compatibility](/docs/skills/compatibility) lists the supported-subset conditions.

## Configure one authentication mode

The CLI reads these environment variables:

| Variable | Meaning |
| --- | --- |
| `FI_CONTEXT_ORIGIN` | Explicit API origin, without a resource path |
| `FI_CONTEXT_ORGANIZATION_ID` | Organization UUID |
| `FI_CONTEXT_WORKSPACE_ID` | Workspace UUID |
| `FI_CONTEXT_CREDENTIAL` | Isolated credential value, supplied through a secret mechanism |

The wire header is `Authorization: Context <credential-id>.<secret>`. A consume credential reads only its grants; a report credential records observations for declared bindings. Neither is a broad authoring key. Secrets belong in neither a plan nor a checked-in lock. [Safe installation](/docs/skills/safe-installation#use-one-authentication-mode) covers issuance, expiry, revocation, and mixed-auth rejection.

## Python transport

The inspected SDK exports `ContextClient` and `AsyncContextClient` from `fi.context`. Both wrap a caller-owned platform client. Their `resolve(name, label=..., version=...)` operation selects one immutable identity and reconstructs all manifest pages. A snapshot exposes `identity`, `read_file(path)`, and `read_all()`; asynchronous reads must be awaited.

`read_all()` verifies the complete file set rather than assuming a single resolve response contains every file. `check_access(identity, lease)` reauthorizes the exact bytes; it does not renew the lease or report model delivery. The transport does not itself install a project, configure a native agent, or start an application.

Python sync/async and TypeScript transport parity is a separate qualification requirement. A TypeScript transport does not establish a native JavaScript application adapter. Exact consumption schemas are in [the sealed API reference](/docs/skills/sealed-api).

## Inspect the CLI before applying changes

The inspected entrypoint is `python -m fi.context`. These commands describe source interfaces, not cloud-verified installation examples:

```bash
python -m fi.context --help
python -m fi.context inventory --repositories selected-repositories.json
python -m fi.context inspect --plan reviewed-plan.json
python -m fi.context verify --project /path/to/project
python -m fi.context doctor --project /path/to/project
```

The inventory input is a JSON array of explicit `repository_id` and `project` selections. Inventory reads selected repositories without hooks or writes. `inspect --diff` explicitly includes bounded source/local text; operators should treat that output as potentially sensitive.

## Plan, then apply

| Command | Interface and review boundary |
| --- | --- |
| `plan` | Requires `--name`, `--client` (`codex` or `claude-code`), `--project`, and `--out`. `--label` and `--version` are mutually exclusive. |
| `inspect` | Requires `--plan`; the operator reviews additions, replacements, removals, collisions, and source/destination identities. |
| `apply` | Requires `--plan`; `--quiescent` is the explicit local-reader coordination option. Application rechecks approved preimages. |
| `update` | Accepts `--lock` or `--project`, writes a new plan through `--out`, and supports read-only `--check`. |
| `restore` | Uses a retained lock and creates a reviewed plan; it is not a production-pointer mutation. |
| `remove` | Plans removal of unchanged owned files, preserving modified and unowned content. |
| `recover` | Requires `--project` and supports `--quiescent`; recovery reconciles an interrupted local journal. |

`--adopt-local` and `--allow-preview` are explicit plan options. They must not be added as routine workarounds for a collision or unqualified host. A preview profile is not delivery evidence. The guide intentionally does not supply a copy-and-run mutating installation recipe until the package and host prerequisites are established.

## Verify the right result

Byte verification, client discovery, and model-boundary delivery are separate results. The installer must preserve local policy, reject changed preimages, journal multi-file changes, and commit the ownership lock last. A pointer move does not update checked-in locks or old threads.

[Safe installation](/docs/skills/safe-installation) describes those invariants. [Updates and recovery](/docs/skills/rollout-recovery) explains exact restoration, clean-thread upgrades, and unknown consumers.
