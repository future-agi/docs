## About

Skills and agent contexts use the same installation flow: **Choose your tool**, **Create a read-only key**, **Preview the changes**, then **Install**. A skill uses `python -m fi.skills`; a context uses `python -m fi.context`. Planning and applying are separate decisions. Neither a fetch nor an installation proves that a model followed the instructions.

**Preview: not yet tested with Claude Code** (or **Codex**) is a qualification warning, not a successful installation result. Both Install tabs retain it until the released package and selected host profile are qualified. These examples describe the inspected interfaces; they do not establish a released SDK version or a passing host test. Obtain a deployment-compatible SDK/CLI before trying the preview. See [Safe installation](/docs/skills/safe-installation) and [Compatibility](/docs/skills/compatibility).

## Choose a client and location

Open the skill's **Install** tab and select **Coding agent**. Under **Version to install**, choose a label or **Pinned version**. The managed CLI flow offers **Claude Code** and **Codex** and a **Project directory**. It does not offer personal installation or change host settings.

A label is resolved when the plan runs, not when the tab opens. The plan records that immutable version and digest; installed files do not automatically follow later releases. A pinned version stays fixed. [Selection rules](/docs/skills/versions-and-labels#one-selection-rule) apply: choose a label or a version, never both. With neither, the default is `production`; a missing label is an error, not a fallback to latest.

For an agent context, the Install tab defaults to the production version. **Install viewed vN instead** explicitly selects another viewed version without changing production. If production is unassigned, the tab installs the viewed version only. The generated context plan uses that exact version, not a floating label.

## Create a read-only key

A workspace administrator creates a scoped **consume** credential in the Install tab, or supplies one through the team's secret mechanism. A skill label selection needs a `skill` grant for that resource UUID and label so a later update can resolve its next release. A pinned selection needs an exact-version grant. A context installation needs an `agent_context` grant for the selected version. A key for a different resource or selector is not interchangeable.

The secret is shown once. Set it as `FI_CONTEXT_CREDENTIAL` in the terminal or secret manager; never commit it, paste it into the copied command, or capture it in a screenshot. A consume key cannot author, publish, move a label, or run paid tests. See [authentication and rotation](/docs/skills/safe-installation#use-one-authentication-mode).

Both CLIs and the application examples use these variables:

| Variable | Value |
| --- | --- |
| `FI_CONTEXT_ORIGIN` | The deployment's public HTTPS API origin, without a resource path |
| `FI_CONTEXT_ORGANIZATION_ID` | Organization UUID |
| `FI_CONTEXT_WORKSPACE_ID` | Workspace UUID |
| `FI_CONTEXT_CREDENTIAL` | The read-only credential, supplied through a secret mechanism |

Expand **Before you install** to inspect workspace identity, version, digest, and preview limitations. **Copy** on the plan block includes the organization and workspace variables even when the disclosure is closed. It never includes the secret.

## Install one skill

### Preview the changes

After supplying the environment above, run from the intended project root. This preview example selects `support-policy` at `production` for Claude Code; use `--client codex` for Codex. Replace `--label production` with `--version 3` to pin v3. Do not pass both.

```bash
python -m fi.skills plan --name support-policy --label production \
  --client claude-code --project . --allow-preview --out skill-plan.json
python -m fi.skills inspect --plan skill-plan.json --diff
```

`--allow-preview` is an explicit opt-in to an unqualified host profile, not a workaround for collisions or permission failures. Check the resolved version and digest, every file addition, replacement and removal, and any preserved local instructions. The skill CLI manages the skill directory, not standing `AGENTS.md`. [Context plans](/docs/skills/sdk-cli#plan-then-apply) also manage the context's standing instructions and accepted linked skills.

### Install the inspected plan

Only after checking the full diff, stop the coding tool and apply that same plan:

```bash
python -m fi.skills apply --plan skill-plan.json --quiescent
python -m fi.skills verify --project .
```

The page does not execute these commands. The installer rechecks authorization and destination preimages; a changed file requires a new inspected plan, not an overwrite. Keep the ownership lock with the installed files. Verification checks bytes and identity, not client discovery or model delivery. Start a new session as required by the chosen client.

## Update an installed skill

A label move does not update local files. Check whether the installed selector resolves to a different immutable identity:

```bash
python -m fi.skills update --project . --name support-policy --check --allow-preview
```

The check exits with status `8` when an update is available and `0` when the identity is unchanged. Other failures must not be treated as an available update. To inspect an update, create a new plan separately:

```bash
python -m fi.skills update --project . --name support-policy --allow-preview --plan skill-plan.json
python -m fi.skills inspect --plan skill-plan.json --diff
```

Apply it with the separate command above only after inspecting the changes and stopping the tool. A pinned install must not advance to the label's newer version. Preserve unrelated skills and local edits. A legacy ZIP lock is not proof that a directory is already managed; do not adopt or overwrite it implicitly. See [local update and recovery rules](/docs/skills/safe-installation#update-restore-remove-verify-and-doctor).

## Without Python

The skill Install tab's **Without Python** disclosure offers a `curl` + `jq` file-download fallback using the same read-only key. It resolves through `/model-hub/skills/consumption/resolve/`, follows manifest and file continuations, and carries the returned `X-Context-Resolution` lease on immutable reads. It does not use the broad-key ZIP route or offer collection downloads by tag. The context Install tab has no equivalent fallback.

<Warning>
The fallback writes files without a plan, digest verification, ownership lock, or journal. It may replace local edits, leave deleted files behind, or stop with only part of a bundle downloaded. Use a new empty destination with no symlinks and inspect and verify the complete result before letting an agent read it. Do not use it to update a managed destination. This fallback and legacy ZIP recipes are not safe managed updaters; use the CLI to inspect a plan before installation or updates.
</Warning>

The fallback lists these destination conventions, including **Project** and **Personal** locations. A path is not evidence that a host/version is qualified:

| Client | Project directory | Personal directory |
| --- | --- | --- |
| Claude Code | `.claude/skills` | `~/.claude/skills` |
| Codex | `.agents/skills` | `~/.agents/skills` |
| Cursor | `.cursor/skills` | `~/.cursor/skills` |
| Gemini CLI | `.gemini/skills` | `~/.gemini/skills` |
| VS Code Copilot | `.github/skills` | `~/.copilot/skills` |

Cursor, Gemini CLI, and VS Code are fallback choices, not managed CLI profiles. Use a client with Agent Skills support and follow its discovery and reload rules. Host-specific frontmatter may be ignored by another client; see [portability notes](/docs/skills/checks-reference#portability-notes).

<Warning>
Skills are instructions, not trusted executables. Agents may execute bundled scripts after installation. Inspect them before installation and promotion. `allowed-tools` does not sandbox a skill. If an older header or library menu still copies a broad-key ZIP command, use the Install tab's read-only-key flow instead.
</Warning>

## Fetch files in an application

Select **Application** on the skill's Install tab. The Python and TypeScript snippets use `SkillsClient` with isolated Context authentication and the same four environment variables. Run credentialed code server-side, never in a public browser. Use a deployment-compatible SDK that exports these interfaces; source availability is not a package-release claim.

<CodeGroup titles={["Python", "TypeScript", "cURL"]}>

```python
import os

from fi.platform import Client, ContextAuth
from fi.skills import SkillsClient

client = Client(
    auth=ContextAuth(os.environ["FI_CONTEXT_CREDENTIAL"]),
    base_url=os.environ["FI_CONTEXT_ORIGIN"],
    workspace_id=os.environ["FI_CONTEXT_WORKSPACE_ID"],
    default_headers={"X-Organization-Id": os.environ["FI_CONTEXT_ORGANIZATION_ID"]},
)
skill = SkillsClient(client).resolve("support-policy", label="production")
print(skill.identity.version_id, skill.identity.digest)
skill_instructions = skill.read_file("SKILL.md")
# Pass inspected instructions to the application's context-loading code.
```

```typescript
import { Client, SkillsClient } from "@future-agi/sdk";

const credential = process.env.FI_CONTEXT_CREDENTIAL;
const origin = process.env.FI_CONTEXT_ORIGIN;
const workspaceId = process.env.FI_CONTEXT_WORKSPACE_ID;
const organizationId = process.env.FI_CONTEXT_ORGANIZATION_ID;
if (!credential || !origin || !workspaceId || !organizationId) {
  throw new Error("Set all four FI_CONTEXT_* environment variables");
}
const client = new Client({
  auth: { type: "context", credential },
  baseUrl: origin,
  workspaceId,
  defaultHeaders: { "X-Organization-Id": organizationId },
});
const skill = await new SkillsClient(client).resolve("support-policy", { label: "production" });
console.log(skill.identity.versionId, skill.identity.digest);
const skillInstructions = await skill.readFile("SKILL.md");
// Pass inspected instructions to the application's context-loading code.
```

```bash
curl -fsS -G \
  -H "Authorization: Context $FI_CONTEXT_CREDENTIAL" \
  -H "X-Organization-Id: $FI_CONTEXT_ORGANIZATION_ID" \
  -H "X-Workspace-Id: $FI_CONTEXT_WORKSPACE_ID" \
  --data-urlencode 'name=support-policy' \
  --data-urlencode 'label=production' \
  "$FI_CONTEXT_ORIGIN/model-hub/skills/consumption/resolve/"
```

</CodeGroup>

Python uses `version=3` and TypeScript uses `{ version: 3 }` for a pinned read, replacing the label argument. The SDK verifies file bytes before handing them to application code. The cURL example only resolves identity and a manifest page; it does not read or verify the complete file set. Continue all pages and file chunks against that resolved version with its lease, rather than resolving the label again between files. See [snapshot verification](/docs/skills/safe-installation#resolve-once-and-verify-the-whole-snapshot).

Using `SkillsClient` makes loads recordable when runtime tracing support is enabled and an active trace exists. These examples do not configure tracing or prove a load was recorded. **Loaded** means verified bytes reached application code during a traced request; it never means the model followed them. Fetching does not inject instructions into a model.

## Cache and fetch usage

Partition caches by API origin, organization, workspace, credential identity, resource, and selector. Recheck access before reuse; a cached copy or a matching digest does not override revocation, expiry, or quarantine. See [lease and cache rules](/docs/skills/safe-installation#resolve-once-and-verify-the-whole-snapshot).

**Activity** reports retrieval (fetches). A fetch count is not proof that a client installed, discovered, loaded, followed, or successfully acted on the instructions. An installation receipt and runtime load evidence answer different questions; a label move does not establish downstream adoption.
