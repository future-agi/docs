## About

Download a skill into the coding agent's skill directory, or resolve its files from the team's application. Select a label for future updates, or pin a numeric version for repeatable reads. [Selection rules](/docs/skills/versions-and-labels#one-selection-rule) are identical across REST, downloads, and MCP.

## Legacy download boundary

The ZIP commands on this page are legacy leaf-skill download/overlay recipes, not safe managed updaters or certified agent-context installers. They may overwrite local edits or leave deleted files behind. They must not be used to update an existing managed destination. The listed client paths are destination conventions, not evidence that every host/version is qualified. Standing `AGENTS.md` belongs to the context profile, not a skill-only directory. [Safe installation](/docs/skills/safe-installation) and [SDK/CLI interfaces](/docs/skills/sdk-cli) cover the new plan/apply boundary.

## Choose a client and location

Open **Use skill** on a skill's detail page. Choose a label or **Pinned version**, then select a client and project or personal location. Project installs are scoped to the repository; personal installs can be discovered across the projects, depending on the client's configuration.

| Client | Project directory | Personal directory |
| --- | --- | --- |
| Claude Code | `.claude/skills` | `~/.claude/skills` |
| Codex | `.agents/skills` | `~/.agents/skills` |
| Cursor | `.cursor/skills` | `~/.cursor/skills` |
| Gemini CLI | `.gemini/skills` | `~/.gemini/skills` |
| VS Code Copilot | `.github/skills` | `~/.copilot/skills` |

Use a client version with Agent Skills support. Discovery and reload behavior belong to the client; downloading files does not enable unsupported client features. Host-specific frontmatter can be ignored by other clients. Review the [portability notes](/docs/skills/checks-reference#portability-notes).

## Install one skill

Run from the project root. Set `DIR` to the chosen directory from the table. For a personal install, use `$HOME`, for example `DIR="$HOME/.agents/skills"`; a quoted `~` will not expand in a shell.

```bash
export HOST_API="https://api.futureagi.com"
: "${FI_API_KEY:?Set FI_API_KEY from your secret manager}"
: "${FI_SECRET_KEY:?Set FI_SECRET_KEY from your secret manager}"
: "${FI_WORKSPACE_ID:?Set FI_WORKSPACE_ID to your workspace UUID}"
DIR=".claude/skills"
mkdir -p "$DIR" && \
curl -fsSL \
  -H "X-Api-Key: $FI_API_KEY" \
  -H "X-Secret-Key: $FI_SECRET_KEY" \
  -H "X-Workspace-Id: $FI_WORKSPACE_ID" \
  "$HOST_API/model-hub/skills/download/?names=support-policy&label=production" \
  -o /tmp/futureagi-skills.zip && \
unzip -oq /tmp/futureagi-skills.zip -d "$DIR" && \
rm /tmp/futureagi-skills.zip
```

For Codex, Cursor, Gemini CLI, or VS Code Copilot, change `DIR` to `.agents/skills`, `.cursor/skills`, `.gemini/skills`, or `.github/skills` respectively. The request and ZIP layout are the same for every client. To pin version 3 instead, replace `label=production` with `version=3`; do not send both.

The archive puts files under `support-policy/`, not directly in the target directory. It also includes `.futureagi-skills.lock.json` at its root. The lock file contains `schema: 1`, `origin`, `skills`, and `skipped`. Each skill entry contains `name`, `version`, `version_id`, `digest`, and `label`. A direct version download has a null label. Keep this lock file alongside installed skills to record what the operator downloaded. It is not an automatic updater or dependency resolver.

## Install every skill with a tag

Use `tag` instead of `names` to download the team's labeled collection, up to 50 skills. This example installs all skills tagged `support` that have `production` assigned.

```bash
export HOST_API="https://api.futureagi.com"
: "${FI_API_KEY:?Set FI_API_KEY}"
: "${FI_SECRET_KEY:?Set FI_SECRET_KEY}"
: "${FI_WORKSPACE_ID:?Set FI_WORKSPACE_ID}"
DIR=".claude/skills"
mkdir -p "$DIR" && \
curl -fsSL \
  -H "X-Api-Key: $FI_API_KEY" \
  -H "X-Secret-Key: $FI_SECRET_KEY" \
  -H "X-Workspace-Id: $FI_WORKSPACE_ID" \
  "$HOST_API/model-hub/skills/download/?tag=support&label=production" \
  -o /tmp/futureagi-skills.zip && \
unzip -oq /tmp/futureagi-skills.zip -d "$DIR" && \
rm /tmp/futureagi-skills.zip
```

Inspect the lock file's `skipped` list. Skills missing the selected label are not silently replaced with their latest version. Zero resolvable skills returns HTTP 404 `nothing_to_download`. A numeric `version` is supported only with exactly one explicit name, not for a tag collection.

## Update an installed skill

Install commands overwrite matching files but do not delete old files that are absent from the new ZIP. To avoid stale instructions, download into an empty staging directory, inspect its manifest and contents, and replace only the specific skill directory after backing up local edits. Do not delete the whole client skills directory: it may contain skills from other sources.

Each download writes a lock file for that archive; separate one-skill installs can overwrite the previous lock file. Use a single collection download when the operator needs one lock file describing the collection. Do not run the sample commands concurrently: they share `/tmp/futureagi-skills.zip`.

<Warning>
Skills are instructions, not trusted executables. Agents may run files under `scripts/`. Review them before installation and promotion. `allowed-tools` may pre-approve tools in some agents; it does not sandbox the skill. API keys used for installation retain their full access, with no read-only Skills scope.
</Warning>

## Fetch files in an application

These are direct HTTP examples, not `futureagi-sdk` methods. The Python example needs `requests`; the TypeScript example uses the built-in `fetch` in Node.js 18 or later and can run as a module in a TypeScript project. Run credentialed requests on the server, never in public browser code.

Set `FI_API_KEY`, `FI_SECRET_KEY`, and `FI_WORKSPACE_ID` in the environment. `HOST_API` defaults to the production API origin. Each example fetches the `production` manifest with full text and returns the resolved `version_id` and `digest`. Python and TypeScript verify each file's UTF-8 SHA-256 before handing text to application code. The operator’s application still decides which instructions to load and when; fetching alone does not inject them into a model.

<CodeGroup titles={["Python", "TypeScript", "cURL"]}>

```python
import hashlib
import os

import requests

host = os.environ.get("HOST_API", "https://api.futureagi.com").rstrip("/")
response = requests.get(
    f"{host}/model-hub/skills/resolve/",
    headers={
        "X-Api-Key": os.environ["FI_API_KEY"],
        "X-Secret-Key": os.environ["FI_SECRET_KEY"],
        "X-Workspace-Id": os.environ["FI_WORKSPACE_ID"],
    },
    params={"name": "support-policy", "label": "production", "include_content": "true"},
    timeout=30,
)
response.raise_for_status()
envelope = response.json()
if not envelope["status"]:
    raise RuntimeError("Skill resolution failed")
manifest = envelope["result"]
files = {}
for file in manifest["files"]:
    content = file["content"]
    if hashlib.sha256(content.encode("utf-8")).hexdigest() != file["sha256"]:
        raise ValueError(f"Digest mismatch for {file['path']}")
    files[file["path"]] = content
print(manifest["version_id"], manifest["digest"])
skill_instructions = files["SKILL.md"]
# Pass reviewed instructions to your application's context-loading code.
```

```typescript
import { createHash } from "node:crypto";

const host = (process.env.HOST_API ?? "https://api.futureagi.com").replace(/\/$/, "");
const apiKey = process.env.FI_API_KEY;
const secretKey = process.env.FI_SECRET_KEY;
const workspaceId = process.env.FI_WORKSPACE_ID;
if (!apiKey || !secretKey || !workspaceId) {
  throw new Error("Set FI_API_KEY, FI_SECRET_KEY, and FI_WORKSPACE_ID");
}
const url = new URL(`${host}/model-hub/skills/resolve/`);
url.search = new URLSearchParams({
  name: "support-policy",
  label: "production",
  include_content: "true",
}).toString();
const response = await fetch(url, {
  headers: {
    "X-Api-Key": apiKey,
    "X-Secret-Key": secretKey,
    "X-Workspace-Id": workspaceId,
  },
  signal: AbortSignal.timeout(30000),
});
if (!response.ok) throw new Error(`Resolve failed: HTTP ${response.status}`);
const envelope = await response.json();
if (!envelope.status) throw new Error("Skill resolution failed");
const manifest = envelope.result;
const files = new Map();
for (const file of manifest.files) {
  const sha256 = createHash("sha256").update(file.content, "utf8").digest("hex");
  if (sha256 !== file.sha256) throw new Error(`Digest mismatch for ${file.path}`);
  files.set(file.path, file.content);
}
console.log(manifest.version_id, manifest.digest);
const skillInstructions = files.get("SKILL.md");
// Pass reviewed instructions to your application's context-loading code.
```

```bash
export HOST_API="https://api.futureagi.com"
: "${FI_API_KEY:?Set FI_API_KEY}"
: "${FI_SECRET_KEY:?Set FI_SECRET_KEY}"
: "${FI_WORKSPACE_ID:?Set FI_WORKSPACE_ID}"
curl -fsS -G \
  -H "X-Api-Key: $FI_API_KEY" \
  -H "X-Secret-Key: $FI_SECRET_KEY" \
  -H "X-Workspace-Id: $FI_WORKSPACE_ID" \
  --data-urlencode 'name=support-policy' \
  --data-urlencode 'label=production' \
  --data-urlencode 'include_content=true' \
  "$HOST_API/model-hub/skills/resolve/"
```

</CodeGroup>

For smaller responses, omit `include_content` and retrieve individual files using the manifest's `skill_id` and resolved `version`. Follow every `next_offset` until `eof`; see [file reads](/docs/skills/api-reference#read-a-file-chunk). Pin those reads to the resolved version instead of resolving the label again between files.

## Cache and fetch usage

Resolve returns an `ETag` containing the quoted bundle digest. Send it back in `If-None-Match` for conditional reads; a 304 response has no JSON body. Keep the previously verified manifest and files for that request. Scope caches by API origin, organization/workspace, credential identity, skill name, selector, and whether content was included. Never share a tenant's cached instructions with another tenant.

**Usage** supports 7, 30, or 90 days. It groups fetches by version, channel (`api`, `download`, `mcp`), and consumer, such as an API key name or user email. A request count is not evidence that instructions were loaded, followed, or successful. No trace linkage is ingested by Skills in this release.
