## About

Create a skill named `support-policy`, publish its first version, and install it in a Claude Code project. The policy in this example is synthetic. Replace it with the team's reviewed policy before using it for customer requests.

This is the standalone leaf-skill quickstart. Protected labels require the [reviewed release workflow](/docs/skills/reviewed-releases); publication must not bypass protection. [Agent contexts](/docs/skills/agent-contexts) have a separate authoring flow.

## Before starting

The operator needs a Future AGI workspace with write access, a workspace administrator who can create a read-only key, and Python with the Future AGI SDK on the machine where the skill will be installed. Choose the same workspace in the dashboard and in the commands.

Store the key in an environment variable or the secret manager. Do not paste it into `SKILL.md`, a repository, a copied command, or an agent conversation. The read-only key cannot author, publish, or move labels; [Safe installation](/docs/skills/safe-installation) covers issuance, expiry, and revocation.

## Create and publish

<Steps>
  <Step title="Open the library">
    Open **Skills** in the dashboard. Select **New skill**, or **Create your first skill** in an empty library. Choose a template inside the creation dialog.

    ![Library with three synthetic skills and their production, latest, and fetch columns](/images/docs/skills/skills-library.png)
  </Step>
  <Step title="Create a draft">
    Enter `support-policy` as the name and `Use when answering refund or return questions using the team's reviewed support policy.` as the description. Select the **Support policy** template and create the skill.

    A **Skill draft created** dialog states that nothing is published. Select **Open editor**. The editor opens with `SKILL.md` and supporting policy files. The name is permanent after creation. If it is already taken in this workspace, use a new lowercase, hyphenated name.

    ![New skill dialog with the support-policy name, description, and the Support policy template, before Create skill is selected](/images/docs/skills/skills-create.png)
  </Step>
  <Step title="Review the files and checks">
    Read `SKILL.md` and `references/policy.md`. Replace the example policy with the team's reviewed instructions. Open relative links in Markdown preview to inspect the referenced files.

    Wait for **Saved** before leaving. Autosave stores the draft on the server; it does not publish it. Fix every error in the checks panel. Review warnings rather than accepting them automatically.

    ![Draft editor for support-policy with SKILL.md, two reference files, passing checks, and Saved status](/images/docs/skills/skills-editor-checks.png)
  </Step>
  <Step title="Publish and label">
    Select **Publish**. Review the changed-file list and add a note such as `Initial reviewed support policy`. Under **Release labels (optional)**, select `production`. Each label says what ticking it does, for example **Not set yet; ticking sets it to v1**; where `production` is a **Protected label (only admins can move it)**, only a workspace admin can publish and move it, while writers can still publish the version without the label. If there are warnings the operator has reviewed and accepted, acknowledge them. Review the consequence summary, then select **Publish and move production**.

    The operator now has immutable version 1 and a `production` label pointing to it. Publishing without that label is allowed, but a default fetch would then return `label_not_found` rather than silently choosing the latest version.

    ![Publish dialog with the version note, production selected under Release labels (optional), and no check issues](/images/docs/skills/skills-publish.png)
  </Step>
</Steps>

## Install in Claude Code

Open the skill's **Install** tab. Under **Choose what agents receive**, keep **Production (currently v1)** in **Version to install**. Under **Use in your agent**, keep **Coding agent**, choose **Claude Code** in **1. Choose your tool**, and keep `.` as the **Project directory**. The **Preview: not yet tested with Claude Code** badge stays on this flow; it is a qualification warning, not a successful installation result.

![Install tab with production selected, the Claude Code tool, the project directory, and the read-only key step](/images/docs/skills/skills-use-claude-code.png)

In **2. Create a read-only key**, a workspace administrator creates a key limited to this skill's production label. The secret is shown once and is never placed in a command. Store it as `FI_CONTEXT_CREDENTIAL`, and set `FI_CONTEXT_ORIGIN`, `FI_CONTEXT_ORGANIZATION_ID`, and `FI_CONTEXT_WORKSPACE_ID` as the tab shows. Then, from the project root, preview the plan the tab copies:

```bash
: "${FI_CONTEXT_CREDENTIAL:?Set FI_CONTEXT_CREDENTIAL from your secret manager}"
python -m fi.skills plan --name support-policy --label production \
  --client claude-code --project . --allow-preview --out skill-plan.json
python -m fi.skills inspect --plan skill-plan.json --diff
```

Check the resolved version and digest and every file the plan adds or replaces. Only then stop Claude Code and apply that same plan:

```bash
python -m fi.skills apply --plan skill-plan.json --quiescent
python -m fi.skills verify --project .
```

The commands need a deployment-compatible Future AGI Python SDK that provides `python -m fi.skills`; these pages do not establish a released version. The installed skill lands in `.claude/skills/support-policy/`. The installer keeps a `.futureagi-skills.lock.json` lock that records each skill's resolved version, `version_id`, `digest`, and requested label, plus a separate ownership receipt for the files it manages. [Use skills in your agents](/docs/skills/use-in-agents) covers Codex, pinned versions, updates, and the no-Python fallback.

<Warning>
Review the planned files before letting an agent use them, particularly scripts. A changed local file requires a new inspected plan, not an overwrite. A later production move does not update installed files; see [updating installed skills](/docs/skills/use-in-agents#update-an-installed-skill).
</Warning>

## Confirm the result

Open the installed `SKILL.md` and compare the lock's version with the dashboard. Start or reload the coding-agent session according to the client's skill-discovery behavior. Ask a synthetic refund question that should trigger the skill, then inspect the agent's actual response and tool activity. Verification checks bytes and identity; it does not prove the client loaded or followed them.

A fetch can appear in **Activity** even if the agent never uses the skill. Do not treat that count as task success.
