## About

Create a skill named `support-policy`, publish its first version, and install it in a Claude Code project. The policy in this example is synthetic. Replace it with the team's reviewed policy before using it for customer requests.

This is the standalone leaf-skill quickstart. Protected labels require the [reviewed release workflow](/docs/skills/reviewed-releases); publication must not bypass protection. The ZIP install recipe is not a managed updater and must not overwrite an existing managed destination. [Agent contexts](/docs/skills/agent-contexts) have a separate authoring flow.

## Before you start

The operator needs a Future AGI workspace with write access, an API key and secret from **Settings > API Keys**, and `curl` and `unzip` on the machine where the operator will install the skill. Choose the same workspace in the dashboard and in the API requests.

Store credentials in environment variables or the secret manager. Do not paste them into `SKILL.md`, a repository, or an agent conversation. The broad key in this legacy download example retains its existing access. Isolated Context consume credentials are a separate mode documented in [Safe installation](/docs/skills/safe-installation).

## Create and publish

<Steps>
  <Step title="Open the library">
    Open **Skills** in the dashboard. Select **New skill**. The operator can also start from the template gallery in an empty library.

    ![Library with three synthetic skills](/images/docs/skills/skills-library.png)
  </Step>
  <Step title="Create a draft">
    Enter `support-policy` as the name and `Use when answering refund or return questions using the team's reviewed support policy.` as the description. Select the **Support policy** template and create the skill.

    The editor opens with `SKILL.md` and supporting policy files. The name is permanent after creation. If it is already taken in this workspace, use a new lowercase, hyphenated name.

    ![New skill dialog with support-policy template and synthetic description](/images/docs/skills/skills-create.png)
  </Step>
  <Step title="Review the files and checks">
    Read `SKILL.md` and `references/policy.md`. Replace the example policy with the team's reviewed instructions. Open relative links in Markdown preview to inspect the referenced files.

    Wait for **Saved** before leaving. Autosave stores the draft on the server; it does not publish it. Fix every error in the checks panel. Review warnings rather than accepting them automatically.

    ![Draft editor with SKILL.md, supporting files, checks, and Saved status](/images/docs/skills/skills-editor-checks.png)
  </Step>
  <Step title="Publish and label">
    Select **Publish**. Review the changed-file list and add a note such as `Initial reviewed support policy`. Under **After publishing, move label**, select `production`. If there are warnings the operator has reviewed and accepted, acknowledge them, then publish.

    The operator now has immutable version 1 and a `production` label pointing to it. Publishing without that label is allowed, but a default fetch would then return `label_not_found` rather than silently choosing the latest version.

    ![Publish dialog with file changes and production selected](/images/docs/skills/skills-publish.png)
  </Step>
</Steps>

## Install in Claude Code

Open **Use skill**, select the `production` label, choose **Claude Code**, and select the project location. Run the command from the project root. Set `HOST_API` to `https://api.futureagi.com`, or the deployment’s API origin. Load `FI_API_KEY`, `FI_SECRET_KEY`, and `FI_WORKSPACE_ID` from the environment; `FI_WORKSPACE_ID` is the workspace UUID.

```bash
export HOST_API="https://api.futureagi.com"
: "${FI_API_KEY:?Set FI_API_KEY from your secret manager}"
: "${FI_SECRET_KEY:?Set FI_SECRET_KEY from your secret manager}"
: "${FI_WORKSPACE_ID:?Set FI_WORKSPACE_ID to your workspace UUID}"
mkdir -p .claude/skills && \
curl -fsSL \
  -H "X-Api-Key: $FI_API_KEY" \
  -H "X-Secret-Key: $FI_SECRET_KEY" \
  -H "X-Workspace-Id: $FI_WORKSPACE_ID" \
  "$HOST_API/model-hub/skills/download/?names=support-policy&label=production" \
  -o /tmp/futureagi-skills.zip && \
unzip -oq /tmp/futureagi-skills.zip -d .claude/skills && \
rm /tmp/futureagi-skills.zip
```

Expected files include `.claude/skills/support-policy/SKILL.md`, `.claude/skills/support-policy/references/policy.md`, and `.claude/skills/.futureagi-skills.lock.json`. The lock file records the resolved version, `version_id`, and `digest`. Inspect it before starting an agent session.

![Use tab with production selected and Claude Code project install command](/images/docs/skills/skills-use-claude-code.png)

<Warning>
Installation overwrites matching local files. Review the downloaded files before letting an agent use them, particularly scripts. Installing again does not remove files that disappeared from a newer bundle; see [updating installed skills](/docs/skills/use-in-agents#update-an-installed-skill).
</Warning>

## Confirm the result

Open the installed `SKILL.md` and compare the lock file's version with the dashboard. Start or reload the coding-agent session according to the client's skill-discovery behavior. Ask a synthetic refund question that should trigger the skill, then inspect the agent's actual response and tool activity. The install command only downloads files; it does not prove the client loaded or followed them.

A download can appear in **Usage** even if the agent never uses the skill. Do not treat that count as task success.
