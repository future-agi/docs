## Scope

**Pilot preview.** The pilot qualifies one existing repository and application, including cold adoption, second update, removal, and interruption recovery. Multi-repository campaigns are **deferred until the pilot checkpoint passes**. This page does not advertise an enabled campaign button or rollout command. Confirm [Compatibility](/docs/skills/compatibility) first.

## Read consumer observations accurately

A binding is an explicitly declared repository/runtime target, not an agent inferred from fetch traffic. Inspect each stage with its identity, timestamp, provenance, and observation age:

| Stage | Meaning |
| --- | --- |
| Desired | Target selected by the binding's current policy. |
| Resolved | An authorized immutable snapshot was selected. |
| Installed | Verified materialized bytes were recorded. |
| Discovered | A qualified host observed the configured instructions/catalog. |
| Delivered | Instructions/file ranges reached the actual model boundary under a supported adapter. |
| Outcome | The declared application case/tool/answer result, when separately observed. |

A fetch is retrieval only. A PR being merged is not installation. Installation is not delivery. Delivery is not successful behavior. Missing observations remain **Unknown**, not failed or recovered by inference.

States can coexist: pinned as intended, update available, local modifications, mixed sessions, old thread retained, stale observation, offline/unknown, or quarantined. Compare immutable identities and resolution events, not whether the version number is larger. A valid rollback can point to a lower-numbered release.

## Roll back a pointer versus restore files

**Roll back production** moves one label to an eligible retained version through reviewed compare-and-swap checks. It creates no new content version. Pointer and aggregate release revisions protect against ABA moves such as v4 → v5 → v4.

**Restore as a new version** copies the complete historical snapshot and accepted dependency lock into a new immutable version. It does not move production. An explicit restore creates a new version even when bytes match the latest; retrying the same operation key returns its existing receipt instead of creating another version.

**Local locked restore** materializes an approved exact lock/release through a new preimage-bound local plan. A pointer rollback alone does not change checked-in locks, offline files, or instructions already present in a conversation. See [Safe installation](/docs/skills/safe-installation).

## Recover an interrupted application

1. Start from the retained incident trace/event and declare the affected application/repository cohort.
2. Inspect a complete eligible recovery release, dependency closure, and runtime configuration. Check for quarantined alternatives before offering rollback.
3. Review and authorize the protected pointer move. Restore local files only through the reviewed lock plan.
4. If the registry becomes unavailable between a tool result and the next model call, the managed boundary pauses. It must not silently use latest, switch versions, or fall back to stale authorization.
5. Persist the tool-result/business-operation receipt before advancing the checkpoint. Resume only the original eligible immutable identity and checkpoint after authorization succeeds.
6. If a new context is needed, start a **clean new thread**. Prior messages, pinned skill bodies, catalog metadata, offloaded results, and writable state are not transferred by default. Review any task reconstruction explicitly and count its cost.
7. Reconcile already executed business actions before continuing. A fresh thread must not automatically repeat a refund or transfer. An application without applicable side-effect idempotency is ineligible for this pilot.
8. Recheck the original case and actual supported delivery. Keep unobserved, stale, pinned, and mixed consumers visible rather than declaring the entire cohort recovered.

A missing/expired session mapping is **thread context unknown**, not permission to resolve the current label. An expired/revoked credential or quarantined snapshot blocks continuation even if cached files exist. Measure the live-authorization latency and the work of reconstructing a clean thread; live-only operation has an availability tradeoff.

## Retirement, quarantine, and archived recovery

**Archive/retire** hides a source from new direct selection and dependency acceptance. Retained published parent snapshots preserve their embedded bytes. Retirement is not revocation.

**Quarantine** blocks future managed distribution of the target and affected retained parents: direct resolution, pin/cache/304 reuse, materialization, restore, worker delivery, and session authorization. Authorized forensic inspection is a separate human path, not a consume-token installer workaround. Clearing quarantine requires current authority, revision checks, and a recorded reason.

Neither action erases offline copies or retracts a model request already sent.

For both legacy skills and contexts, authorized archived listing/inspection and **unarchive** must recover the original UUID, retained versions, labels, policy, and history. Review retained-label consequences and current protected authority. If another live resource reused the name, resolve that collision explicitly; do not redirect old UUID-bound consumers to the replacement. Restoring the original identity is not merely creating another resource with the same name.

## Multi-repository campaigns: not yet enabled

The later campaign qualification must include cold repositories with real local instructions, a fixed selected inventory, complete exception/pin accounting, preimage-bound plans, independent repository review/merge, and a second update/reverse plan. No automatic membership expansion, force push, or automatic merge is promised.

Measure cold adoption, recurring rollout, and recovery as separate jobs. Credit native batching without counting its automatic internal stages as operator actions, but retain independent review, authorization, and outcome evidence. A favorable combined action total cannot compensate for failed or unmeasured recovery.

An unknown Git write must be reconciled by deterministic repository/branch/marker before retry. Pausing prevents new claims; an in-flight request may still complete. A synthetic 40-repository exercise checks orchestration, not real GitHub permissions or comparative superiority. A bounded authorized real-GitHub conformance run is required before campaign support is advertised.

Keep using the existing repository workflow until that capability is qualified. The individual-repository recovery path does not imply fleet-wide rollout or instant revocation.
