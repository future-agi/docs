## About

Skills is the context hub for your agents: a workspace library of instructions and supporting text files that agents load when needed. A skill contains a root `SKILL.md` and can include reference material, examples, and scripts. You can write a skill, import an existing one, or start from a template, then publish a version for your team to use.

Open **Skills** in the dashboard's **BUILD** group, after **Prompts**. Use search, tags, and label filters to find a skill. Open its detail page to read files, compare versions, inspect fetch usage, or copy an install command.

## Drafts, versions, and labels

| Object | What it means |
| --- | --- |
| Skill | A stable name in one workspace, with tags and a description. You cannot rename it after creation. |
| Draft | Your editable, server-saved files. Saving does not affect published versions or production. |
| Version | An immutable snapshot of all files, with a version number, version ID, and content digest. |
| Label | A pointer such as `production` or `staging` to one version of that skill. Moving it changes future fetches by that label. |

The usual flow is **create → edit → check → publish → promote → consume**. [Versions and labels](/docs/skills/versions-and-labels) explains what changes at each step and how to roll back without rewriting history.

## What checks and usage tell you

Checks inspect file structure, frontmatter, relative links, suspected secrets, instruction length, and portability. Errors block publishing. Warnings require your acknowledgment. Checks do not run your scripts or test the skill against a model, and passing them is not a security review.

The **Usage** tab counts requests that fetched a skill, grouped by version, channel, and consumer. A fetch does not prove an agent used the skill. It is not a count of successful tasks, unique agents, or evaluation results.

## How skills relate to other features

- [Prompts](/docs/prompt) hold prompt templates. Skills hold an instruction folder an agent loads on demand. Skills have their own version and label rules; prompt default-version behavior does not apply.
- [MCP tools](/docs/skills/mcp-tools) let a connected agent discover a skill and read only the files it needs. The `trace-debugging` and `eval-writer` templates contain instructions for working with Future AGI tools; they do not create automatic trace linkage or evaluation gates.
- [Agent installation](/docs/skills/use-in-agents) downloads files into a supported client's skill directory. REST examples let your application fetch an immutable version and decide how to use its contents.

## Current boundaries

This release supports text files only. It does not include model test runs, evaluation gates, trace linkage ingestion, GitHub import, protected labels or approvals, webhooks, read-only API key scopes, skill dependencies, binary assets, library folders, cross-workspace copy, or skill renaming. Paths such as `references/policy.md` inside a skill are supported; library folders are not.

There is no Skills adapter for Falcon, no Skills methods in `futureagi-sdk`, and no Skills tools in the standalone `futureagi-mcp-server` package. Use the REST API or the platform MCP server documented here.
