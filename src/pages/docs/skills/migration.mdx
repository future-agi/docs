## Before migration

Retained migration is distinct from the older upload-and-publish operation. It retains a reviewed source plan and accepts supported content as **unpublished drafts**. It does not issue runtime credentials, move production labels, modify the source, or establish native delivery.

Supported intake includes a private folder or ZIP and the explicit `langfuse-skills-v1` exchange schema. An arbitrary Langfuse export or remote URL is not that schema. The operator first inventories the local source and preserves its immutable origin, project, resource, revision, and digest identities. Names are not migration identities.

## Preview the supported subset

1. In **Skills → Import → Retained migration**, the operator chooses the source format and files.
2. For a local source, the operator supplies the immutable source-identity mapping produced by inventory. This mapping is needed to match a later import to the same source.
3. **Preview retained migration** returns a retained plan, digest, expiry, and compatibility inventory.
4. The operator reviews every accepted, blocked, and excluded member. Nested managed instructions, binary files, and executable host controls must not disappear silently.
5. If proceeding with a supported subset, the operator explicitly acknowledges the excluded members. This is a subset trial, not a complete migration.

![Retained migration preview showing immutable source identities, explicit blocked-member exclusion, and the whole-context capacity warning](/images/docs/skills/retained-migration.png)

The screenshot uses synthetic fixtures. A supported leaf inventory alone does not certify the compiled context's capacity. The root, descriptor, mounted paths, and all child files count toward the [complete-tree limits](/docs/skills/compatibility#content-limits).

## Accept and reconcile

The operator reviews the retained plan and accepts the selected items with one operation identity. Acceptance produces per-item receipts and drafts, not a production move. After a timeout or lost response, the operator reopens the original plan and reconciles its receipts before retrying. A retry must not be treated as a new import merely because the response was lost.

The API separates `intake/preview/`, `intake/langfuse/preview/`, plan read, review, accept, receipts, and reconcile. Exact fields are in [the sealed API reference](/docs/skills/sealed-api).

## Publish a context deliberately

After reviewing imported leaf drafts, the author publishes the required leaves, creates or edits the `AGENTS.md` context, and explicitly accepts each published link. The author reviews the complete context before publication. Linked files and `.futureagi/context.json` are generated/read-only in that context.

![Published synthetic context showing fourteen accepted pinned skill locks and production not assigned](/images/docs/skills/context-linked-skills.png)

This screen establishes published lock identity, not installation or model delivery. Labels, credentials, and local installation remain separate authorized steps.

## Second update and exit

The operator keeps source identities and the original receipt when preparing a later update. Local divergence and unrelated drafts require explicit preservation or replacement decisions; a source-name match is insufficient. Before exit, the operator exports the selected immutable version through its migration-export endpoint and reviews the local removal plan. Removing unchanged managed output must preserve local or modified files.

[The reversible pilot](/docs/skills/reversible-pilot) covers trial, second update, and exit. [Safe installation](/docs/skills/safe-installation) covers destination ownership and interrupted local changes.
