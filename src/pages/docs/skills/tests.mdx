## Check availability first

Skill test endpoints and context test endpoints are separate. The sealed API includes both, but the retained context UI evidence shows **Tests** disabled. A disabled control is not a passing result or an invitation to bypass a capability gate. The [API reference](/docs/skills/sealed-api) records registered operations; [Compatibility](/docs/skills/compatibility) records prerequisites.

## Choose the claim being tested

| Evidence | Appropriate claim | Not established |
| --- | --- | --- |
| Static checks | Saved files satisfy structural checks | Model behavior, script safety, or application success |
| Text comparison | The frozen examples, supplied text, and answer checks were compared | Native discovery or real application tool execution |
| Native application comparison | The qualified entrypoint ran against pinned application configuration | Unobserved hosts, cases, or deployments |
| Installation or delivery receipt | Specific bytes were installed or reached an observed boundary | Instruction compliance or a successful business action |

The standing `AGENTS.md` root has no activation score. A child-only test does not establish whole-context behavior. Forced selection and natural selection remain separate observations.

## Prepare an enabled skill comparison

1. The author saves all file edits and reviews the acknowledged draft revision or immutable version.
2. In the skill's test configuration, the author records the cases and expected behavior. The suite is read or updated through `GET` or `PUT /model-hub/skills/{skill_id}/tests/`.
3. The author requests a run preview and reviews the selected model/provider, outbound content, redaction findings, planned work, and budget. A preview does not start paid execution.
4. The author resolves the preview's findings and explicitly starts the reviewed configuration. The server checks current permissions, limits, and preconditions.
5. The author inspects the run, results, and individual attempts. File reads, selection, tools, answer outcomes, missing work, and provider failures must not be collapsed into one success badge.
6. Evidence remains private until the author explicitly shares it with the declared audience.

The API exposes separate preview, start, read, results, attempts, files, cancel, and share operations for each resource kind. Request fields and response definitions are in [the sealed API contract](/docs/skills/sealed-api). Context and skill identifiers must not be substituted across these routes.

## Capture a regression case

Where enabled, **Create regression case from trace** starts a reviewed capture. The operator supplies the physical source identity, reviews authorized source content and redaction, and accepts an explicit expectation. A link to an incident is not a reproduced failure. The context capture API separates source inspection, preview, and acceptance.

Historical repair starts from **Edit viewed vN**, not whichever version happens to be latest. The author preserves unrelated personal work, reviews the candidate against the current publication head, and retains the original content origin. [Agent contexts](/docs/skills/agent-contexts#repair-the-historical-version-you-intended) explains that workflow.

## Interpret incomplete and disputed results

Both comparison arms failing is not candidate success. Startup, parsing, tool, and provider errors remain errors. A cancelled run may still include an in-flight paid call. Missing attempts remain incomplete, and expired payloads are not inspectable evidence merely because a receipt survives.

Reviewers can record **Agree**, **Disagree**, or **Cannot assess** against evidence. An annotation is attributed and append-only; it does not replace the machine result. A new annotation can make an earlier release approval stale.

## Share only the intended evidence

Sharing includes the retained inputs, answers, and receipts visible to the selected audience. Publication does not implicitly share private runs, and sharing does not extend retention. External CI references remain operator-recorded unless an explicitly qualified import exists.

[Reviewed releases](/docs/skills/reviewed-releases) binds evidence identity, visibility, expiry, and annotation revision to the exact release decision. Neither a passing comparison nor an approved request changes production by itself.
