## About

Start with the HTTP status and error `code`, then check the workspace, selected version or label, and saved draft revision. JSON errors have `status: false`. Do not work around a missing label by silently fetching `latest`; that can load unreviewed instructions.

## Error codes and recovery

| HTTP status | Code | What to do |
| --- | --- | --- |
| 403 | `workspace_required` | Authenticate and provide a workspace you can access through `X-Workspace-Id`. Both organization and workspace must resolve. |
| 404 | `skill_not_found` | Check the name or UUID and workspace. Archived skills cannot be resolved. Objects outside your organization or workspace are also returned as not found. |
| 404 | `version_not_found` | Check the version number. A skill with no published versions is not resolvable. |
| 404 | `label_not_found` | Assign the requested label to a reviewed version, or explicitly request an existing version. Omitting selectors means `production`, not `latest`. |
| 404 | `draft_not_found` | There is no draft for the authenticated person. Open the editor to begin one; a successful draft publish removes it. |
| 404 | `nothing_to_download` | None of the selected skills resolve. Check names, tag, label, and publication state. |
| 400 | `invalid_selector` | Send `label` or `version`, not both. Numeric download versions require exactly one explicit name. |
| 400 | `invalid_name` | Use 1–64 lowercase letters or digits separated by single hyphens. |
| 400 | `invalid_label` | Use `^[a-z0-9][a-z0-9-]{0,39}$`, stay within 20 labels, and do not assign the reserved `latest` label. |
| 400 | `invalid_tags` | Use at most 20 tags, each matching `^[a-z0-9][a-z0-9._-]{0,39}$`. |
| 409 | `name_taken` | Choose another name or publish a new version of the existing skill instead of creating a second skill with the same name. |
| 409 | `stale_base` | Compare against `latest_version` from the error detail. Decide whether to update your draft or publish with `force: true`. |
| 409 | `label_conflict` | Read `current_version` from the error detail and review the intervening change. Retry only with a newly confirmed `expected_version`. |
| 409 | `draft_conflict` | Read the server's `revision` and `updated_at`, preserve your unsaved edits, and reconcile before saving with the new revision. |
| 422 | `checks_failed` | Inspect the ChecksResult in the error detail and fix every error. `force` does not bypass checks. |
| 422 | `warnings_unacknowledged` | Review each warning. Fix it or explicitly send `acknowledge_warnings: true` after accepting it. |
| 413 | `payload_too_large` | Reduce the upload or file set to the [documented limits](/docs/skills/checks-reference#limits). |
| 400 | `import_invalid` | Inspect rejected entries and correct archive, encoding, or path problems before previewing again. |

A missing template ID can return HTTP 404 `template_not_found`. Read the current template list rather than guessing an ID.

Authentication failures and permission denials can happen before a Skills error is returned. API-key authentication needs **both** `X-Api-Key` and `X-Secret-Key`; Bearer authentication needs a valid JWT, not an API key. Every non-GET operation needs workspace write access, including checks and import preview. Ask a workspace administrator to verify access rather than switching tenants until a request succeeds.

## Another tab saved my draft

A draft belongs to you and the skill, not to a browser tab. Two tabs can therefore edit the same server record. When **Conflict** appears, preserve your local text before choosing **Reload theirs**. Use **Overwrite with mine** only after reviewing what will be replaced; it must save against the latest server revision.

If a save fails because of connectivity, use **Retry** and wait for **Saved** before leaving. An unsaved-navigation warning does not guarantee that your last changes reached the server. Discarding a draft removes your saved work; it does not delete published versions.

## Someone published while I was editing

A draft's `base_version` can become stale even when its autosave revision is current. Compare your draft with the latest published version. For the legacy leaf draft only, **Publish anyway** accepts the stale base and publishes your complete files; it does not automatically merge the other person's changes.

## Publishing did not add a version

If the content digest equals the latest version's digest, publishing returns `unchanged: true` and the existing latest version. Changing only the version note is not a content change. Read the returned version number and current labels instead of assuming the number increased.

## A download contains fewer skills than expected

Inspect `.futureagi-skills.lock.json`, especially `skipped`. Collection downloads skip skills lacking the requested label. They do not choose another version for you. If nothing resolves, the API returns `nothing_to_download` rather than an empty ZIP.

For imports, inspect every per-bundle result. A failure does not roll back successful bundles. Re-upload the same reviewed files with the preview's exact `selected` keys. The multipart upload field is `files`, repeated for each part, with the relative path as each part's filename.

## A label changed but the agent still uses old files

Moving a label changes future resolution, not previously downloaded files or application caches. Reinstall or refetch, and compare the resolved `version_id` and `digest` with your lock file. `unzip -oq` overwrites matching paths but leaves obsolete local files in place. Use the [staged update procedure](/docs/skills/use-in-agents#update-an-installed-skill), preserving unrelated skills and local edits.

After changing files, follow your coding client's reload behavior. Check that you chose its correct [project or personal directory](/docs/skills/use-in-agents#choose-a-client-and-location). A fetch count does not demonstrate that the client discovered or used a skill.

## MCP instructions end midway through a file

`read_skill_file` is chunked. Append `text` and follow `next_offset` until `eof` is true. Offsets count characters, not bytes. Verify the SHA-256 of the complete UTF-8 text. If the response reports truncation, the digest differs, or the next offset does not advance, stop and retry rather than using partial instructions. See the [MCP read flow](/docs/skills/mcp-tools#read-a-complete-skill).

## Checks passed but the skill behaved incorrectly

Checks validate files and flag common problems; they do not run model tests, prove compliance with instructions, or verify business policy. Review the actual agent behavior separately. Where enabled, [tests and evidence](/docs/skills/tests) provide separately reviewed comparisons and case capture; a registered endpoint or disabled test tab does not establish availability. Use version comparison to inspect the content change and roll back a label if needed.

## Context head conflicts and unavailable controls

Agent contexts have no force-publication shortcut. After latest moves, the author preserves the candidate, reviews it against the new head, and explicitly acknowledges that head before publication. Content origin remains the historical version originally selected.

Disabled Tests, Use, repository rollout, or archived-identity controls remain unavailable until their qualification requirements pass. A direct API request is not a supported workaround. A release conflict requires re-review of the exact packet; dropping evidence or refreshing preconditions without inspection must not make an old approval current.
