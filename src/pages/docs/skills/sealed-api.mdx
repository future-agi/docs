The current head has **152 paths, 182 operations, and 534 schemas**. Compared with the previous documented head at `8254acd488c074ec30f660c68619e4039f52bb90` (147 paths, 177 operations, 508 schemas), it adds the runtime reads `GET /usage/`, `GET /comparison/`, `GET /loads/`, and `GET /filter-values/` under `/model-hub/skills/`, and the trace projection `POST /tracer/trace/skill-projection/`. The original runtime integration added twenty-six referenced schemas. Its other additions included `SkillsHubUsage` (`first_fetched_on`), `SkillsHubConsumer` (`sdk_version`, `tracing_mode`, `can_record`), `SkillsHubChannels` (`sdk`), and `SkillsContextRenewalPreview` (`policy_changes`). The [runtime reads guide](/docs/skills/api-reference#runtime-reads) describes inputs, pagination, and typed errors.

The latest contract also exposes the immutable `event_id` on label history and `linked_version_differences` on the trace-detail projection. Context detail and latest-load responses keep required fields present when a value is null: `latest` or `own_draft` can be null on a context, and `load` or `fetch` can be null when nothing was observed. A null load does not mean a failed load. The seven additional MCP reads reuse existing REST operations.

## Authentication and tenant scope

Human authoring uses an authorized JWT Bearer identity or the existing `X-Api-Key` / `X-Secret-Key` pair, with `X-Workspace-Id` selecting an accessible workspace. The original [API examples](/docs/skills/api-reference#authentication-and-example-setup) show that setup.

Isolated consumption uses `Authorization: Context <credential-id>.<secret>` on its dedicated surfaces. Report grants are binding-scoped and are not read grants. Context credentials cannot be mixed with broad credentials or substituted into authoring endpoints. Immutable consumption continuations also carry the returned `X-Context-Resolution`; this lease header is not standalone authority.

Operation tables describe operation-specific parameters; they do not waive authentication, workspace access, resource-kind checks, label protection, quarantine, or runtime capability checks. The original leaf routes are not aliases for context UUIDs.

## Mutations, retries, and examples

An operation declaring a required UUID `Idempotency-Key` requires a caller-owned key retained across retries of that same intent. After an unknown outcome, the caller reconciles the original operation receipt before creating a new intent. Draft revisions, source revisions, preview IDs, reviewed head identities, and release/security revisions are preconditions, not values to refresh silently.

JSON success envelopes generally contain `status` and `result`; the per-status schema below is authoritative. Binary downloads and empty responses must not be parsed as JSON. A `202` job acknowledgment is not completed work. Conflicts require inspection and deliberate re-review; they are not force-retry instructions.

No invented success payload is presented as a live response. Captures use synthetic content and the E2E stack's provider/GitHub transport fakes; they establish HTTP behavior for that build, not real-provider, GitHub-permission, native-delivery, or comparative qualification. Complete schema objects are available under **Request and response schemas**, including required fields, nested definitions, enums, and bounds. Where Swagger has an underspecified object, that limitation remains visible rather than being filled with guessed fields.
