## About

Checks inspect your skill's files without running them or calling a model. Use the editor's checks panel to open the file and line for a finding, or call the [stateless checks endpoint](/docs/skills/api-reference#check-files). Errors block publishing; warnings require `acknowledge_warnings: true`; informational notes never block.

A passing check is not proof that a skill is safe, correct, or effective. Review instructions and scripts before promoting them.

## Skill format

Every skill needs a root file named exactly `SKILL.md`. Its YAML frontmatter must be a mapping with a `name` and `description`. The name must match the skill's permanent name when publishing an existing skill.

```markdown
---
name: support-policy
description: Use when answering refund or return questions using the team's reviewed policy.
---

# Support policy

Read [the policy](references/policy.md) before answering.
If the policy does not cover the case, ask for review rather than inventing a rule.
```

Include `references/policy.md` in that bundle. Relative Markdown links open supporting files in the preview. Backtick path references starting with `scripts/`, `references/`, or `assets/` are also checked. URLs, anchors, and `mailto` links are ignored by the broken-link check.

The portable frontmatter keys are `name`, `description`, `license`, `compatibility`, `metadata`, and `allowed-tools`. `metadata` must map strings to strings. `compatibility` is at most 500 characters. Other keys are either known host extensions or unknown-key warnings.

## Limits

Sizes below count UTF-8 bytes, not characters. A KiB is 1,024 bytes; a MiB is 1,048,576 bytes.

| Item | Limit or rule |
| --- | --- |
| Skill name | 1–64 characters; `^[a-z0-9]+(-[a-z0-9]+)*$` |
| Description | 1–1,024 characters |
| Tags | At most 20; each matches `^[a-z0-9][a-z0-9._-]{0,39}$` |
| Labels | At most 20; each matches `^[a-z0-9][a-z0-9-]{0,39}$`; `latest` is reserved |
| Files per draft or version | At most 200 |
| Path | At most 255 characters and 8 segments |
| One file | At most 512 KiB |
| Complete draft or version | At most 2 MiB |
| YAML frontmatter block | At most 16 KiB |
| Version note | At most 2,000 characters |
| Label history note | At most 500 characters |
| Download collection | At most 50 skills |
| List page size | Default 25, maximum 100 |
| REST file chunk | Default 32,768 bytes, maximum 49,152 bytes |
| MCP file chunk | 24,000-byte budget |

Paths must be relative POSIX paths: no leading `/`, backslashes, empty segments, `.` or `..` segments, control characters, or segments ending with a space or period. Names differing only in case are duplicates. Files must be valid UTF-8 text without NUL or control characters other than tab, newline, and carriage return. See [import limits](/docs/skills/import-skills#limits-and-rejected-entries) for ZIP and upload limits.

## Errors

Any error prevents publication with HTTP 422 `checks_failed`. Fix the files and run checks again. Draft saves enforce size limits but may retain incomplete content while you edit.

| Code | Cause and fix |
| --- | --- |
| `root_missing` | Add a root `SKILL.md`, with that exact capitalization. |
| `frontmatter_missing` | Add a YAML frontmatter block at the beginning of `SKILL.md`. |
| `frontmatter_invalid` | Fix YAML syntax, make the block a mapping, and keep it within 16 KiB. |
| `name_missing` | Supply the frontmatter `name`. |
| `name_invalid` | Use the lowercase, hyphenated name rule above. |
| `name_mismatch` | Make the frontmatter name match the existing skill's name. You cannot rename a skill by publishing. |
| `description_missing` | Supply a nonempty description. |
| `description_too_long` | Shorten the description to 1,024 characters or fewer. |
| `compatibility_too_long` | Shorten `compatibility` to 500 characters or fewer. |
| `metadata_invalid` | Make `metadata` a string-to-string mapping, not a list or nested object. |
| `path_invalid` | Use a path satisfying every path rule above. |
| `path_duplicate` | Remove or rename case-insensitive duplicate paths. |
| `file_too_large` | Reduce the file to 512 KiB or less. |
| `too_many_files` | Keep at most 200 files. |
| `bundle_too_large` | Reduce the complete file set to 2 MiB or less. |
| `file_not_text` | Remove binary content, NUL, and disallowed controls; encode the file as UTF-8. |

## Warnings

Warnings return HTTP 422 `warnings_unacknowledged` unless you explicitly acknowledge them when publishing. Acknowledgment records your decision to proceed; it does not fix the finding.

| Code | Meaning and recommended action |
| --- | --- |
| `secret_suspected` | A string resembles a credential. Remove it and rotate it if it was real; use environment-variable names instead. |
| `link_broken` | A relative Markdown link or supported backtick path reference is absent from the bundle. Include the target or correct the path. |
| `skill_md_long` | `SKILL.md` exceeds 500 lines. Move supporting detail into referenced files. |
| `skill_md_tokens` | `SKILL.md` exceeds an estimate of 5,000 tokens. Keep core instructions short and load details on demand. |
| `description_short` | The description is under 40 characters. Explain what the skill does and when to use it. |
| `frontmatter_unknown_key` | A key is outside the portable and known host-extension sets. Check for typos or host-specific behavior. |
| `file_empty` | A file has no content. Remove it or explain its purpose with content. |

Secret checks look for AWS access-key IDs, private-key blocks, GitHub tokens, OpenAI and Anthropic keys, Slack tokens, Google API keys, Stripe live keys, JWT-shaped tokens, and high-entropy values assigned to names such as `api_key`, `secret`, `password`, or `token`. The generic rule checks values of at least 16 characters with Shannon entropy of at least 3.5. Findings redact suspected values. Detection can produce false positives and can miss real secrets; it is not a secret-management system.

## Portability notes

| Code | Meaning |
| --- | --- |
| `host_extension` | Known Claude Code frontmatter keys are present; other hosts may ignore them. |
| `allowed_tools_note` | `allowed-tools` pre-approves tools in some agents; it does not sandbox the skill. |
| `executable_content` | Files under `scripts/`, or with `.sh`, `.py`, `.js`, `.ts`, `.rb`, or `.ps1` extensions, may be run by agents. Review them before promoting. |
| `description_trigger_hint` | The description does not clearly say when to use the skill. Add wording such as “Use when answering refund questions.” |

Known host-extension keys are `disable-model-invocation`, `user-invocable`, `context`, `agent`, `hooks`, `paths`, `shell`, `when_to_use`, `model`, and `argument-hint`. Keeping these keys is allowed; it does not make them portable.

The trigger hint looks for phrases matching `use (this|it)? ?(when|for|to)`, `when (the )?user`, or `whenever`. This is a writing hint, not a model-based test of discovery.

## Check result and token estimates

A `ChecksResult` has `items`, `summary`, `tokens`, and `frontmatter`. Each item contains `code`, `severity`, and `message`, with optional `path`, `line`, and `detail`. The summary counts `errors`, `warnings`, and `infos`. `frontmatter` is the parsed mapping or `null`.

The `tokens` object contains `metadata`, `skill_md`, and `total`. Estimates use character count divided by four, rounded up; metadata covers the name and description. The UI labels estimates **≈ tokens**. They are not a tokenizer-specific bill or a guarantee that the complete skill fits a model's context window.
