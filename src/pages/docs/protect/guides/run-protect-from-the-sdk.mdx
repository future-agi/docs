Call `protect()` from your own code, with no dashboard involved, to screen a customer’s message before it reaches your model or the model’s reply before it reaches the customer. It takes a string either way. This guide covers initializing the client, building a rules list, running the check and reading the result, so you can tell a failed check from one that never finished. For how these checks fit into the guardrail model, see [Understanding Protect](/docs/protect/concepts/understanding-protect).

<Prerequisites title="Before you start">
- Python, and a matching pair of [workspace credentials](/docs/admin-settings/api-keys): `FI_API_KEY` and `FI_SECRET_KEY`.
- One text string, image or audio input per call. The media examples below use paths that you must replace with your own files.
</Prerequisites>

## Initialize Protect

Install the SDK first:

```bash
pip install ai-evaluation
```

Then initialize the client:

```python
from fi.evals import Protect

protector = Protect()
```

Protect reads `FI_API_KEY` and `FI_SECRET_KEY` from your environment.

## Build the rules list

[`protect_rules`](/docs/sdk/protect#rule-structure) is a list of dictionaries, each naming one check with a `metric` key:

```python
rules = [
    {"metric": "toxicity"},
    {"metric": "bias_detection"},
    {"metric": "prompt_injection"},
    {"metric": "data_privacy_compliance"},
]
```

The SDK accepts these `metric` values: `toxicity`, `bias`, `bias_detection`, `sexist`, `prompt_injection`, `data_privacy_compliance`, and `pii`. A `metric` name outside this list raises an error before anything is screened, so confirm the name before you ship it. See [Protect SDK rejects an input](/docs/protect/troubleshooting/protect-sdk-rejects-an-input) if the call raises instead of returning a result.

## Run the check

Call `protector.protect()` with:

- `inputs`: your input, as the first positional argument
- `protect_rules`: the rules list
- `action`: the message returned when a rule fails
- `reason`: set `True` to include an explanation with the result
- `timeout`: how long the check can run, in milliseconds

```python
text_to_check = "the text you want to screen"

result = protector.protect(
    text_to_check,
    protect_rules=rules,
    action="I'm sorry, I can't help you with that.",
    reason=True,
    timeout=25000,
)
```

## Read the result

`protect()` returns a dictionary shaped like this:

```python
{
    "status": "failed",
    "completed_rules": ["toxicity"],
    "uncompleted_rules": ["bias_detection", "prompt_injection", "data_privacy_compliance"],
    "failed_rule": ["toxicity"],
    "messages": "I'm sorry, I can't help you with that.",
    "reasons": ["Message contains content flagged as toxic."],
    "time_taken": 0.42,
}
```

- `status`: `"passed"` or `"failed"`
- `messages`: on a failure, carries the `action` string instead of the original input
- `completed_rules` / `uncompleted_rules`: which checks ran to completion, and which didn't; on a failure, the remaining checks can come back in `uncompleted_rules`
- `failed_rule`: the check(s) that tripped a failure, as a list, for example `["toxicity"]`
- `reasons`: holds an explanation for a failure when `reason=True` is set
- `time_taken`: how long the check took, in seconds

If a rule doesn't finish before `timeout` elapses, it lands in `uncompleted_rules` instead. Read `status` alongside `completed_rules` and `uncompleted_rules`: a rule that timed out is not a rule that passed.

Use `status` to decide what to send onward: on a failure, forward `messages` instead of the original input; on a pass, forward the input unchanged.

```python
if result["status"] == "failed":
    response = result["messages"]
else:
    response = text_to_check
```

## Screen an image or audio input instead of text

`inputs` isn't limited to text. Pass an image or audio path or URL in place of the text string, and call `protect()` the same way. The `rules` list carries over unchanged. Supply an actual local file or a reachable URL, not the literal example path. For accepted URL and file formats, see the Protect SDK reference linked under **Next**.

```python
result = protector.protect(
    "/path/to/local/audio.wav",
    protect_rules=rules,
    action="Audio content cannot be processed",
    reason=True,
    timeout=25000,
)
```

```python
result = protector.protect(
    "/path/to/local/image.png",
    protect_rules=rules,
    action="Image content cannot be processed",
    reason=True,
    timeout=25000,
)
```

Text, image, and audio are the only accepted input types for this call. Image sets, PDFs, and [knowledge bases](/docs/knowledge-base/concepts/understanding-knowledge-base) are not accepted.

## Check the result before forwarding

1. Run the text check on a safe reply, such as “Thank you for reaching out.”
2. Read `status` and `completed_rules`.
3. Run it again on a synthetic reply that reads back a full card number. Do not use real customer information.
4. Read `messages` and `reasons`.

   On a failure, `messages` carries your `action` string, not the original text.

5. Read `uncompleted_rules`.

   It lists the rules that did not finish before `timeout`. On a failure, the remaining checks can also come back here, so its presence alone does not mean a timeout.
