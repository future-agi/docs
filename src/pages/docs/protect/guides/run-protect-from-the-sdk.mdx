title: "Run Protect from the SDK"
description: "Screen a single input for toxicity, bias, prompt injection, or PII, straight from your own code."

This guide screens a single input by calling `protect()` directly from your own code: no dashboard involved. You can call it on incoming input before it reaches your model, or on the model's output before it reaches whoever receives it; `protect()` takes a string either way. The guide walks through initializing the client, building a rules list, running the check, and reading the result back, for both text and non-text input. For every parameter and return field, see the [Protect SDK reference](/docs/sdk/protect).

## Initialize Protect

Your deployment needs access to the Protect models. In a new directory, create a Python 3.12 virtual environment and install the kit and Pillow (for the image example):

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install agent-learning-kit==0.3.7 pillow
```

Set `FI_API_KEY` and `FI_SECRET_KEY` from [API Keys](/docs/admin-settings/api-keys). Start `python` in the activated environment and run the Python blocks in order in the same session.

```python
from fi.evals import Protect

protector = Protect()
```

## Build the rules list

`protect_rules` is a list of dicts, each naming one check to run with a `metric` key:

```python
rules = [
    {"metric": "toxicity"},
    {"metric": "bias_detection"},
    {"metric": "prompt_injection"},
    {"metric": "data_privacy_compliance"},
]
```

For how these checks fit into the guardrail model, see [Understanding Protect](/docs/protect/concepts/understanding-protect).

The SDK accepts these `metric` values: `toxicity`, `bias_detection`, `prompt_injection`, and `data_privacy_compliance` (plus the deprecated aliases `content_moderation` and `security`). A `metric` name outside this list raises an error, so confirm the name before you ship it.

## Run the check

Call `protector.protect()` with:

- `inputs`: your input, as the first positional argument
- `protect_rules`: the rules list
- `action`: the message returned when a rule fails
- `reason`: set `True` to include an explanation with the result
- `timeout`: how long the check can run, in milliseconds

```python
text_to_check = "Can Ridgeline replace the buckle on my hiking pack?"

result = protector.protect(
    text_to_check,
    protect_rules=rules,
    action="I'm sorry, I can't help you with that.",
    reason=True,
    timeout=25000,
)
```

## Read the result

For example, a blocked text can return a dictionary like this. Rule order, explanations and timing can vary:

```text
{
    "status": "failed",
    "completed_rules": ["toxicity"],
    "uncompleted_rules": ["bias_detection", "prompt_injection", "data_privacy_compliance"],
    "failed_rule": ["toxicity"],
    "messages": "I'm sorry, I can't help you with that.",
    "reasons": ["Message contains content flagged as toxic."],
    "time_taken": 0.42,
}
```

- `status`: `"passed"` or `"failed"`
- `messages`: on a triggered rule, carries its action instead of the input. A request or input error can return an SDK error message instead
- `completed_rules` / `uncompleted_rules`: which checks ran to completion, and which didn't; on a failure, the remaining checks can come back in `uncompleted_rules`
- `failed_rule`: the check(s) that tripped a failure, as a list, for example `["toxicity"]`
- `reasons`: holds an explanation for a failure when `reason=True` is set
- `time_taken`: how long the check took, in seconds

If a rule doesn't finish before `timeout` elapses, it lands in `uncompleted_rules` instead.

Only forward the input after all requested checks pass. An incomplete check can leave `status` set to `"passed"`. Keep a separate fallback for that case.

```python
def fully_checked(result, rules):
    return (
        result["status"] == "passed"
        and not result["uncompleted_rules"]
        and set(result["completed_rules"]) == {rule["metric"] for rule in rules}
    )

if fully_checked(result, rules):
    response = text_to_check
elif result["status"] == "failed":
    response = result["messages"]
else:
    response = "We couldn't finish screening this message."
print(response)
```

## Screen an image or audio input instead of text

Pass an existing local file or a direct media URL instead of the text. A nonexistent local path can be treated as plain text. These examples create a short audio tone and a blue gear-color swatch in a temporary directory, then check each for toxicity. Replace the generated files with your own media when you're ready.

```python
import math
import struct
import tempfile
import wave
from pathlib import Path

media_rules = [{"metric": "toxicity"}]
with tempfile.TemporaryDirectory() as directory:
    audio = Path(directory) / "notification.wav"
    with wave.open(str(audio), "wb") as clip:
        clip.setparams((1, 2, 8000, 0, "NONE", "not compressed"))
        clip.writeframes(b"".join(
            struct.pack("<h", round(2000 * math.sin(2 * math.pi * 440 * i / 8000)))
            for i in range(4000)
        ))
    audio_result = protector.protect(str(audio), protect_rules=media_rules)
    print("Audio cleared:", fully_checked(audio_result, media_rules))
```

```python
from PIL import Image

with tempfile.TemporaryDirectory() as directory:
    image = Path(directory) / "swatch.png"
    Image.new("RGB", (64, 64), (44, 84, 114)).save(image)
    image_result = protector.protect(str(image), protect_rules=media_rules)
    print("Image cleared:", fully_checked(image_result, media_rules))
```

Text, image, and audio are the only accepted input types for this call. Image sets, PDFs, and knowledge bases are not accepted.
