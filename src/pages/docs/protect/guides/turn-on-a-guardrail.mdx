Every check in Protect's [guardrail catalog](/docs/protect/reference/guardrail-checks) starts out switched off. This guide turns one on end to end, using **PII Detection** configured for a support agent as the running example: enable it, set it to block requests that contain personally identifiable information (PII), and push it live. The same steps apply to any other check in the catalog.

Saving a check's settings only changes its card. Pushing the change to the gateway is a separate step.

<Prerequisites title="Before you start">
- [Agent Command Center](/docs/command-center/quickstart), where Protect's guardrails live under Gateway, set up with at least one [provider](/docs/command-center/features/providers) connected.
</Prerequisites>

## Stage the rule

1. Open **Gateway > Guardrails > Rules**.

   The Rules tab lists the full guardrail catalog as check cards, split between **AI-Powered Checks** and **Rule-Based Checks**. Find **PII Detection** under **Rule-Based Checks**. It sits below every AI-powered check, so expect to scroll a fair way down. Each card carries a **Switch** and a pencil icon button.

2. Turn on the **Switch** on the **PII Detection** card.

   This stages the change. The unsaved-changes banner means the gateway has not received it yet.

3. Click the pencil icon on the card.

   **Configure: PII Detection** opens with **Enabled** on, matching the switch. The dialog always has **Cancel** and **Save** buttons.

4. Set **Action** to **Block**.
5. Leave **Confidence Threshold** at **0.80**.

   The slider runs from 0.0 to 1.0, with the current value shown in the label. [Understanding Protect](/docs/protect/concepts/understanding-protect) explains what the action and threshold do to a request.

6. Click **Save** in the dialog.

   The dialog closes. The card's badge should flip from **Inherited** to **Custom**, a **Reset** button appears beside the pencil, and a summary line reads **Action: block** and **Threshold: 0.80**.

**Provider-backed checks:** If a check calls out to an external provider, its dialog also has a **Provider Settings** section. That is where the check's own provider connection lives, not the model provider connected during Agent Command Center setup. A credential you've already saved shows up masked; click into the field and it clears, ready for you to enter a new one. **PII Detection** has no such section, so skip it.

## Activate the change

1. Back on the Rules tab, find the banner that reads "You have unsaved changes. Save to push guardrail config to the gateway."

   Nothing you set in the check's dialog reaches the gateway until you save here. **Reset** in the banner discards the unsaved changes, not the check's saved configuration. **Reset** on a customized card is a separate control: it clears the customization, switching the check back off and its action and threshold back to the defaults (**Block**, **0.8**).

2. Click **Save & Activate** in the banner.

   The button reads **Saving...** while the save is in flight, then a toast confirms with "Config saved and activated".

3. Open **Overview**.

   Look for an enabled `pii-detector` row with **Before LLM** in the **Stage** column. Before any guardrail is enabled, this tab reads "No guardrails configured" instead.

## Inspect the saved stage

1. Click the **Edit** icon button on the `pii-detector` row.

   **Edit Guardrail: pii-detector** opens. **Stage** already shows **Pre**, matching the **Before LLM** you just saw in Overview. This dialog is where you'd change it if you needed a different stage. **Action** and **Threshold** carry over from the pencil dialog: **Block** and **0.8**. The threshold's helper text reads "Numeric threshold for the guardrail (optional)".

2. Click **Save**.

   The button reads **Saving...** during the save, then a toast confirms: `Guardrail "pii-detector" updated`.

**PII Detection** is now enabled, blocking at a 0.8 confidence threshold, running at the **pre** stage.

<Note>
Two organization checks, Data Leakage Prevention and Hallucination Detection, run post-stage regardless of the **Stage** control. [Built-in guardrail types](/docs/command-center/features/guardrails#built-in-guardrail-types) lists the stage of each check.
</Note>
