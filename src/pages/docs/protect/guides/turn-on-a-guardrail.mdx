---
title: "Turn on a guardrail"
description: "Add a check in Protect's guardrail catalog and set how it behaves."
---

This guide adds **PII Detection** for a support agent: choose the check, set its action, and save it to the gateway.

You need an organization **Owner** or **Admin** role and Agent Command Center set up with a connected gateway and at least one provider. If it isn't set up yet, start with the [Agent Command Center Quickstart](/docs/command-center/quickstart).

## Find the check in Rules

Go to **Gateway** > **Guardrails** > **Rules**. If no checks are configured, the page shows **No guardrails**. Click **Add check**, then choose **PII Detection** under **Built into the gateway**. You can also use **Search checks** to find it.

If PII Detection is already configured, open its saved row in Rules instead of adding it again.

## Set how it behaves

In the **PII Detection** drawer:

1. Leave the switch **On**.
2. Set **Action** to **Block**.

The drawer describes where the check runs: PII Detection reads the request before the model is called. It has no provider connection to configure. With its default settings, it has no **Match threshold** slider; see [Guardrail fires on the wrong requests](/docs/protect/troubleshooting/guardrail-fires-on-the-wrong-requests) for tuning limits.

For what the actions do, see [Understanding Protect](/docs/protect/concepts/understanding-protect). Other checks can have their own **Settings** fields; complete any required fields before saving.

## Push the change to the gateway

Click **Add check** in the drawer, or **Save** when editing an existing rule. This sends the change immediately; there is no separate **Save & Activate** step. On success, the drawer closes and the toast reads **PII Detection saved**.

Read any warnings returned by the save. **Saved, but the gateway did not apply it** means the configuration was stored, but the gateway did not confirm the change. The drawer stays open with the warning; don't treat the saved row alone as proof that the gateway is running it. See [Guardrail changes not taking effect](/docs/protect/troubleshooting/guardrail-changes-not-taking-effect).

## Confirm the saved rule

Back in **Rules**, find the PII Detection row and confirm it is on. Open the row to review its action and request stage. The same drawer is used for later edits; there is no separate Overview editor.

<Note>
If the page says **Guardrails are off on this gateway**, rules can still be saved, but no check runs. The gateway operator must turn on the guardrail pipeline in the gateway configuration before those rules are enforced.
</Note>
