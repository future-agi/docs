title: "Update Experiment"
description: "Edit an experiment's base column, prompt or agent configurations, and evaluation metrics."
---

`PUT /model-hub/experiments/v2/{experiment_id}/`

Replace the example experiment UUID and API credentials with your own values.

### cURL

```bash
curl --request PUT 'https://api.futureagi.com/model-hub/experiments/v2/4b626c23-2a8f-41fd-9660-43b43c42dc02/' \
  --header 'X-Api-Key: YOUR_API_KEY' \
  --header 'X-Secret-Key: YOUR_SECRET_KEY' \
  --header 'Content-Type: application/json' \
  --data '{"column_id":null}'
```

### Python

```python
import requests

response = requests.put(
    "https://api.futureagi.com/model-hub/experiments/v2/4b626c23-2a8f-41fd-9660-43b43c42dc02/",
    headers={
        "X-Api-Key": "YOUR_API_KEY",
        "X-Secret-Key": "YOUR_SECRET_KEY",
    },
    json={"column_id": None},
)
response.raise_for_status()
print(response.json())
```

The example removes the base evaluation column selection. Read the current experiment first and change only the fields you intend to update.

<ApiSection title="Authentication">
  <ParamField name="X-Api-Key" type="API Key" required>Your Future AGI API key.</ParamField>
  <ParamField name="X-Secret-Key" type="Secret Key" required>Your Future AGI secret key.</ParamField>
</ApiSection>

<ApiSection title="Request body">
  <ParamField body="column_id" type="UUID | null" optional>The new base column from the experiment's result dataset, or `null` to remove the base selection. Unlike creation, this ID belongs to the experiment's copied data, not the original source dataset.</ParamField>
  <ParamField body="prompt_config" type="object[]" optional>The desired prompt/agent configuration list. Each entry follows the [create entry format](/docs/api/experiments/create-experiment). Include the existing configuration's `id` to retain or modify it.</ParamField>
  <ParamField body="user_eval_metrics" type="object[]" optional>The desired evaluation metric list. Include each existing metric's `id` to retain or modify it, together with its template, name, and configuration.</ParamField>
</ApiSection>

`name` and `experiment_type` are set at creation and are not editable through this request.

## List replacement and reruns

Omitting a field leaves that field unchanged. Supplying `prompt_config` or `user_eval_metrics` provides the desired list, not just the entries to append. Keep entries you still need: omitted entries in a supplied list are removed from that configuration.

Changes to prompt/agent configurations or evaluations can trigger selective reruns. Setting a different non-null base column reruns its base evaluations. Sending unchanged configuration does not itself request a rerun; use [Rerun Experiments](/docs/api/experiments/rerun-experiments) for that action.

<ApiSection title="Response" status={200} statusText="OK">
  <ResponseField name="status" type="boolean">`true` on success.</ResponseField>
  <ResponseField name="result" type="object">Updated experiment details, using the [detail response](/docs/api/experiments/read-experiments#experiment-details).</ResponseField>
</ApiSection>

Example response (selected detail fields):

```json
{
  "status": true,
  "result": {
    "id": "4b626c23-2a8f-41fd-9660-43b43c42dc02",
    "name": "Support answer evaluation",
    "dataset_id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
    "column_id": null,
    "experiment_type": "llm"
  }
}
```

Read status and result rows after an update that starts execution. An update acknowledgment is not proof that the rerun has completed.

Return to the [Experiments API](/docs/api/experiments).
