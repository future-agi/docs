## LLM prompt entries

Each LLM prompt entry requires:

| Field | Type | Description |
|-------|------|-------------|
| `prompt_id` | UUID | Saved prompt ID |
| `prompt_version` | UUID | Version ID belonging to that prompt, not a version label |
| `model` | string or object | Model name or ModelSpec object |

Optional entry fields include `name`, `model_params`, `configuration`, and `output_format` (default `string`). `model_params` contains sampling settings such as `temperature` and `max_tokens`; `configuration` contains call settings such as `tools` and `tool_choice`.

Use a saved, non-draft prompt version. To compare the same prompt with two models, repeat `prompt_id` and `prompt_version` in two entries and give each entry its own `model`.

## Agent entries

An agent entry requires `agent_id` and `agent_version`, both UUIDs. The version must belong to that agent and cannot be a draft. Agents are accepted only with `experiment_type: "llm"`.

```json
{
  "agent_id": "51555f43-20df-4b35-b75b-e00353ef1d65",
  "agent_version": "8c189431-1bc9-4d8b-a209-8a4727e310a7"
}
```

Do not include `model`, prompt identifiers, or `messages` in an agent entry. One entry cannot be both a prompt configuration and an agent configuration.

## Other experiment types

For `tts`, `stt`, or `image`, prompt entries require `model` and a nonempty `messages` array instead of `prompt_id` and `prompt_version`. Each message has `role` and `content`; content is a string or an array of content parts. STT entries additionally require `voice_input_column_id`.

## Evaluation entries

Each `user_eval_metrics` entry requires:

| Field | Type | Description |
|-------|------|-------------|
| `template_id` | UUID | Evaluation template accessible to the request |
| `name` | string | Name for this evaluation metric, up to 2,000 characters |
| `config` | JSON | Template-specific input mapping and evaluation settings |

Optional fields include `model`, `error_localizer`, and `kb_id`. Evaluation templates scored externally by the caller are not executable through this create endpoint.

<ApiSection title="Response" status={200} statusText="OK">
  <ResponseField name="status" type="boolean">`true` on success.</ResponseField>
  <ResponseField name="result" type="string">`Experiment created successfully. experiment_id=` followed by the experiment UUID. It is not an object with an `id` field.</ResponseField>
</ApiSection>

Save the experiment UUID and use [Read Experiments](/docs/api/experiments/read-experiments) to check progress. A successful response does not mean every row has finished.

<ApiSection title="Errors">
  <ParamField name="400" type="Bad Request">Missing or empty configurations, invalid IDs, an unsupported entry combination, or an invalid evaluation configuration.</ParamField>
  <ParamField name="403" type="Forbidden">The request cannot execute the selected target.</ParamField>
  <ParamField name="404" type="Not Found">The dataset, column, or another requested resource is unavailable in the request scope.</ParamField>
  <ParamField name="503" type="Service Unavailable">Execution admission is unconfirmed. If the response says the configuration was saved, retry the same submission rather than creating another experiment.</ParamField>
</ApiSection>

See [Dataset Splits](/docs/api/datasets/splits) for creating and assigning the subsets used by `split_ids`, or return to the [Experiments API](/docs/api/experiments).
