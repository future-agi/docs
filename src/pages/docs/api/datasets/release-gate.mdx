title: "Case-Level Release Gate"
description: "Evaluate a complete baseline and candidate comparison with a small fail-closed policy over recorded case evidence."
---

## About

Add `release_gate` to [Compare Experiment Runs](/docs/api/datasets/compare-experiment-runs) when CI needs a case-level verdict. The API reuses the same pinned dataset version, exact example/trial plan, selected evaluator binding, and recorded score evidence. It does not execute tasks, approve a baseline, attest a remote evaluator, or deploy a release.

  Draft API reference. Use a deployment containing the release-gate comparison change. The endpoint remains read-only and returns a verdict derived from caller-supplied evidence.

## Request

Keep the existing comparison fields and add:

```json
{
  "release_gate": {
    "max_regressions": 0,
    "critical_cases": [
      {
        "example_id": "22222222-2222-4222-8222-222222222222",
        "trial_number": 1
      }
    ]
  }
}
```

| Field | Type | Default | Meaning |
| --- | --- | --- | --- |
| `max_regressions` | nonnegative integer | `0` | Maximum number of comparable cases with a candidate regression. |
| `critical_cases` | unique example/trial identities | `[]` | Cases that cannot regress even when the overall allowance permits regressions. Every identity must be in the pinned plan. |

The existing optional `passing_score` and `higher_is_better` fields apply to critical cases. With `higher_is_better: true`, the candidate must be at least the threshold. With `false`, it must be at most the threshold. Omitting `passing_score` does not invent an absolute score requirement.

The gate always requires the complete pinned plan on both sides. Missing, duplicate, invalid, failed, unknown, unsupported, or not-assessed evidence cannot pass. An empty plan fails closed. Unrelated evaluator bindings remain outside a gate for the selected metric.

## Response

Valid evidence returns HTTP `200` and includes `result.release_gate`:

```json
{
  "verdict": "fail",
  "expected_count": 2,
  "comparable_count": 2,
  "regression_count": 1,
  "policy": {
    "max_regressions": 0,
    "critical_cases": []
  },
  "passing_score": 1,
  "higher_is_better": true,
  "blockers": [
    {
      "example_id": "22222222-2222-4222-8222-222222222222",
      "trial_number": 1,
      "reason": "regression_limit_exceeded"
    }
  ]
}
```

Blockers are sorted by example ID, trial number, then reason, so the saved JSON is deterministic. A failed verdict is a valid result and should make a CI caller exit nonzero. Invalid policy or incompatible runs return `400`; hidden runs return `404`. The endpoint performs no writes.

## Limits

Comparison retains its existing 10,000 planned/recorded item bound. Critical-case identities are capped by the same practical plan size. The gate does not add partial coverage, statistical significance, a policy language, a saved baseline, or a release-decision table.
