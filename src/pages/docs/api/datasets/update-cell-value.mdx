## Replacement values

Omitting `new_value` in a REST request is **not a no-op**: it defaults to an empty value. Include the replacement explicitly unless you intend to clear the cell.

For `json` and `array` columns, send **serialized JSON strings**, not native objects or arrays. Object text starts with `{`; array text starts with `[`. For numeric zero and boolean false, use the strings `"0"` and `"false"` respectively.

| Column type | Request body field |
|-------------|--------------------|
| `json` | `"new_value": "{\"label\":\"positive\"}"` |
| `array` | `"new_value": "[\"first\",\"second\"]"` |
| `integer` or `float` | `"new_value": "0"` |
| `boolean` | `"new_value": "false"` |
| Clear a cell | `"new_value": null` |

For file-type columns, upload via `multipart/form-data`.

<Tip>
The platform SDK's `datasets.cells.update` requires an explicit replacement and rejects omission. Pass `None` in Python, `null` in TypeScript, or an explicit empty string to clear a cell.
</Tip>
