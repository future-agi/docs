title: "Error taxonomy"
description: "The fixed set of groups, categories, and fix layers a finding can carry."
---

Every finding Error Feed detects gets classified into a **group**, a **category** within that group, and a **fix layer** naming the part of your system where the fix belongs. Five groups, twenty categories across them, four fix layers.

## Groups and categories

| Group | Category |
|---|---|
| **Tool Failures** | Tool-related |
| | Tool Selection Errors |
| | Tool Output Misinterpretation |
| | Formatting Errors |
| | Language-only |
| **Context & Retrieval** | Context Handling Failures |
| | Poor Information Retrieval |
| | Incorrect Memory Usage |
| | Unsupported Claim |
| **Planning & Goals** | Task Orchestration |
| | Goal Deviation |
| | Resource Abuse |
| **Output Quality** | Instruction Non-compliance |
| | Incorrect Problem Identification |
| | Incomplete Response |
| **Infrastructure** | Environment Setup Errors |
| | Resource Not Found |
| | Authentication Errors |
| | Timeout Issues |
| | Service Errors |

## Groups and fix layers

Each group points at one fix layer: the part of your system where a finding in that group actually gets fixed.

| Group | Fix layer |
|---|---|
| Tool Failures | Tools |
| Context & Retrieval | Prompt |
| Planning & Goals | Orchestration |
| Output Quality | Prompt |
| Infrastructure | Guardrails |

Five groups collapse onto four fix layers. Context & Retrieval and Output Quality both resolve to the same one, Prompt, so when you're deciding where to act on a finding, you're really choosing among four destinations, not five.

<Note>
Fix layer is also one of the live filters in Error Feed's UI: All Fix Layers, Prompt, Tools, Orchestration, Guardrails.
</Note>

## The set is closed

These 20 categories are the whole list, not a starting point. Every finding lands in exactly one of them, there's no open-ended "other" category. That's what makes filtering by category or fix layer exhaustive: a filter covers everything that can show up, not a subset of it.
