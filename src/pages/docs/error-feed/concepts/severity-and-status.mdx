## Two axes, one issue

Every [issue](/docs/error-feed/concepts/understanding-error-feed) in the feed carries two independent labels. **Status** is the triage axis: where the issue sits in your team's workflow. **Severity** is the impact axis: how bad the problem is. Neither one moves the other, and neither moves on its own. Every change is a person picking a new value, and either axis can jump straight from any value to any other, in any order.

A new issue starts life with status `escalating`.

The status values sit side by side, not in a line: nothing about the shape says `resolved` comes after `acknowledged`. Severity looks the same from the outside, but underneath, what you see isn't what's stored: the issue holds a `priority` field, and severity is a fixed, one-to-one relabeling of it. `urgent` and `critical` are the same value seen from two sides, one used in the data, the other in the product.

## Status: the triage axis

Status has exactly four values.

| Status | What it means |
|---|---|
| Escalating | The default for a new issue. Nothing has been decided about it yet |
| For review | Flagged for a closer look before someone decides what to do |
| Acknowledged | Confirmed as real |
| Resolved | The underlying problem has been fixed |

## Severity: the impact axis

Severity has four values too, and each maps to a `priority` stored on the issue.

| Severity | Stored as | What it means |
|---|---|---|
| Critical | `urgent` | The most severe impact |
| High | `high` | Significant impact |
| Medium | `medium` | Moderate impact, the default for a new issue |
| Low | `low` | Minor impact |

## They don't predict each other

A critical issue can be acknowledged just as easily as it can be escalating: severity says how bad the problem is, status says where your team is with it. One doesn't imply the other, so read them separately rather than treating one as a stand-in for the other.

## Why it matters

Keeping the two axes apart is what makes the feed filterable in a useful way. "Critical and still escalating" is a different, more urgent shape than "critical and already acknowledged," and you'd lose that distinction if severity and status were collapsed into one field. See [Triage issues](/docs/error-feed/guides/triage-issues) for how to change either value on an issue.
