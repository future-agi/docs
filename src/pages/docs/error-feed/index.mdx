Every failing trace in your app is evidence of something broken, but scrolling through them one at a time doesn't tell you what's actually wrong. Error Feed pulls the failing ones out of an [Observe project](/docs/observe) and groups the ones that fail the same way (same error type, same part of the workflow) into a single issue, then gives you a queue you work down instead of a pile you scroll through.

## What is Error Feed?

Error Feed lives in the sidebar under **Observe**. It's where hallucinations, eval failures, and pipeline issues, the kinds of failure plain trace search doesn't surface on its own, turn into something you can act on.

An **issue** is a row you triage like a ticket, not a trace you read line by line. Every issue carries a severity, a status, an assignee, and an optional link to a Linear ticket, and it points at the fix layer, the part of your system the fix actually belongs in.

## What you need

Error Feed needs three things in place before it shows anything:

- **An Observe project producing failing traces**: without one there's nothing to group
- **An Enterprise or Cloud license**: without one, the page shows an upgrade prompt instead of a feed, and the API declines every request the same way
- **Sampling raised above the default of 0**: every Observe project ships with its scanner sampling rate at 0, so nothing gets scanned and no issues appear until you raise it yourself. See [Turn on Error Feed](/docs/error-feed/guides/turn-on-error-feed)
