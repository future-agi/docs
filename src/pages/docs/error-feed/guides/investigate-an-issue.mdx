title: "Investigate an issue"
description: "How to read an issue's header, sidebar, and Overview, Traces, and Trends tabs to find out what's going wrong."
---

Every issue in the feed opens onto the same detail page: a header, a metadata sidebar, and four tabs. This page walks the three tabs that help you diagnose the problem, top to bottom, in the order you'd naturally read them.

## The header, sidebar, and tabs

The header stays fixed at the top no matter which tab you're on. Left to right: a breadcrumb reading **Error Feed** that takes you back to the list, a chip naming the error type, the issue title, a status badge and a severity badge (see [Severity & Status](/docs/error-feed/concepts/severity-and-status) for what those values mean), and a chip showing the trace count. Two icon buttons sit on the right: **Copy cluster ID** and **Share**.

A fixed sidebar on the right of the page carries the issue's metadata, status, severity, assignee, and any linked Linear ticket. This page doesn't touch any of it. Changing status, severity, or assignee is [Triage issues](/docs/error-feed/guides/triage-issues); linking a Linear ticket is [Create a Linear issue](/docs/error-feed/guides/create-linear-issue).

Below the header sits a bar with exactly four tabs: **Overview**, **Traces**, **Trends**, and **Fix**. This page covers the first three, the ones that help you understand what's happening. The Fix tab runs an automated root cause analysis and has its own guide, [Run a root cause analysis](/docs/error-feed/guides/run-root-cause-analysis).

## Overview tab: the pattern and the evidence

Overview comes first in the tab bar, and it's where most investigations start. Four things worth reading in order:

- Pattern-summary cards, covering what's common across the whole cluster, not just one trace
- A chart plotting events and users for the cluster over time
- A trace evidence reel that walks through the traces backing the pattern
- A split compare that puts a failing trace beside the nearest trace that didn't fail

The evidence reel has three view modes: **Breadcrumb**, **Agent Graph**, and **Agent Path**. Switch between them depending on whether you want a linear read of what happened, a graph of the agent's steps, or the path it took through them. Within the reel, two tabs separate the evidence: **Failing** and **Working**.

The split compare is the reel's payoff. Toggle **Split with working** to line a failing trace up against the nearest trace that succeeded (toggle **Single view** to go back to one trace at a time). Error Feed pins the closest passing trace it found to the cluster ahead of time, so the comparison is already matched, not a random working trace picked on the spot. That's what makes it useful for spotting exactly where the two runs diverge.

## Traces tab: every trace in the cluster

Traces lists every trace grouped into this cluster, one row each. The tab itself carries a badge with the same count.

Five cards at the top give you the shape of the cluster before you scroll a single row: **Total traces**, **Avg score**, **Avg turns**, **P50 latency**, **P95 latency**. The grid below has seven columns: **Trace ID**, **Input**, **Start Time**, **Duration**, **Tokens**, **Cost**, **Score**. Click any row to open it in the trace drawer for the full detail.

<Note>
Voice and simulator projects open a different trace drawer, matched to what that kind of project actually captures.
</Note>

## Trends tab: errors against traffic

Trends is a single chart: errors and traffic plotted on two axes over time. Read the two lines as a pair, not separately. If the error line climbs while traffic barely moves, something got worse in the system itself. If both climb together, you're most likely looking at more volume, not a rising failure rate, which is often enough on its own to tell you whether an issue is urgent or just a side effect of growth.
