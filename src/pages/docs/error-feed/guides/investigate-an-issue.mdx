---
title: "Investigate an issue"
description: "How to work through an issue's Overview, Traces, and Trends tabs, in the order that actually finds the problem."
---

Open an issue from the [Feed](/docs/error-feed/features/the-feed) list and you land on its detail page: a header, a metadata sidebar, and four tabs. An issue is a [cluster](/docs/error-feed/concepts/how-it-works): every trace that failed the same way, grouped together, so investigating one means finding what's common across the group, not just reading a single trace.

This page walks the order that actually finds the problem: start on Overview to see whether the cluster is one failure or several, open the evidence reel, split-compare a failing trace against a working one to find where they diverge, and drop into Traces only if the pattern doesn't hold up. Trends tells you how urgent it is.

## Header, sidebar, and tabs

The header stays fixed across every tab: the error type chip tells you the category, and the trace count chip tells you how big the cluster is before you read anything else. The metadata sidebar on the right carries status, severity, and assignee. Below sit four tabs, **Overview**, **Traces**, **Trends**, and **Fix**; this page walks the first three.

## Overview tab: is this one failure or several?

Overview comes first in the tab bar, and it's where every investigation starts: work out whether the cluster is one clean failure or several tangled together before you dig into individual traces.

### Read the pattern

The pattern-summary cards cover what's common across the whole cluster, not just one trace. Read them first: if they describe one coherent pattern, you're likely looking at a single failure mode; if they don't cohere, the cluster may need a closer, trace-by-trace look. The chart beside them plots events and users for the cluster over time, so you can see at a glance whether it's a steady trickle or a recent spike.

### Open the evidence reel

The trace evidence reel walks through the traces backing the pattern. It has three view modes: **Breadcrumb**, **Agent Graph**, and **Agent Path**. Breadcrumb gives a linear read of what happened. Agent Graph shows every step the agent could take; Agent Path shows the sequence this particular run actually took. Within the reel, two tabs separate the evidence: **Failing** and **Working**.

### Split-compare to find the divergence

The split compare is the reel's payoff. Toggle **Split with working** to line a failing trace up against the nearest trace that succeeded (toggle **Single view** to go back to one trace at a time). Error Feed pins the closest passing trace it found to the cluster ahead of time, so the comparison is already matched, not a random working trace picked on the spot. That's what makes it useful for spotting exactly where the two runs diverge.

If the cluster has no passing trace to pin, split compare has nothing to line up against. Fall back to the Traces tab to look for a working run directly, or widen the time range so one is more likely to be included.

## Traces tab: find the specific run

If Overview's pattern doesn't hold up under a closer look, or you need to inspect one specific run rather than the aggregate, drop into the Traces tab: it lists every trace grouped into this cluster, one row each. The tab itself carries a badge with the same count.

Five cards at the top give you the shape of the cluster before you scroll a single row: **Total traces**, **Avg score**, **Avg turns**, **P50 latency**, **P95 latency**. The grid below has seven columns: **Trace ID**, **Input**, **Start Time**, **Duration**, **Tokens**, **Cost**, **Score**. Click any row to open it in the trace drawer for the full detail.

<Note>
A voice trace opens with its transcript and recording front and center instead of a span tree; a simulation trace opens with the scenario and evaluation results for that run. See [Voice observability](/docs/observe/concepts/voice-observability) and [View Results](/docs/simulation/features/view-results).
</Note>

## Trends tab: is this urgent?

Trends is a single chart: errors and traffic plotted on two axes over time. Read the two lines as a pair, not separately. If the error line climbs while traffic barely moves, something got worse in the system itself. If both climb together, you're most likely looking at more volume, not a rising failure rate, which is often enough on its own to tell you whether an issue is urgent or just a side effect of growth.
