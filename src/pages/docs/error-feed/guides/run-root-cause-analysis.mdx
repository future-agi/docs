---
title: "Run a root cause analysis"
description: "Read the cause the Error Feed stored for an issue, and ask for the in-depth analysis on the Root cause tab"
---

The **Root cause** tab is where an issue's cause lives. It opens with what the Error Feed stored when it grouped the issue's traces, at no cost. When you need more, the in-depth analysis samples representative calls from the [cluster](/docs/error-feed/concepts/understanding-error-feed), compares them with passing ones, and writes a fuller explanation and a suggested change in a thread you can ask follow-ups in.

## Read the stored analysis

Start from an issue's detail page, with the failure pattern already confirmed via [Investigate an issue](/docs/error-feed/guides/investigate-an-issue). Click the **Root cause** tab. It opens with three lines, and makes no new call to produce them:

- **Likely cause**: what the Error Feed found is going wrong
- **Suggested change**: the narrow change that should stop it
- **Wrong if**: what you'd see if the cause is wrong, so you can check it before you act on it

<img src="/images/docs/error-feed/guides/root-cause-stored-analysis.png" alt="The Root cause tab of the refill-status issue showing Likely cause, Suggested change and Wrong if, with the line about the in-depth analysis and the Explain in depth button below them" style={{ borderRadius: '5px' }} />
*The stored analysis is there as soon as the issue is*

An issue grouped from eval results shows its eval explanation instead, and says the Error Feed stored no likely cause or suggested change for it. Some scan issues carry no stored analysis either, and the tab says so.

## Run the in-depth analysis

Below the stored analysis, click **Explain in depth**. You can also start it from the **Cluster analysis** card on the **Overview** tab, whose button reads **Debug this cluster**. Both start the same run, and the run costs credits, taken when it starts and refunded if it fails.

The run starts right away, and the tab keeps checking until it lands or fails, with a one-hour cut-off. The result arrives in the thread: a written explanation of what's going wrong, based on the calls it sampled, and its change, marked **In-depth suggestion**.

<img src="/images/docs/error-feed/guides/root-cause-in-depth.png" alt="The Root cause tab with the stored Likely cause, Suggested change and Wrong if above a Synthesis card, whose change is marked In-depth suggestion" style={{ borderRadius: '5px' }} />
*The stored analysis stays on top; the in-depth result adds to it*

To probe the reasoning further, type into the composer at the bottom (placeholder: **Ask a follow-up…**); **Investigating…** shows while a reply streams in.

Once the cluster has picked up new traces, click **Re-run** in the tab's header to analyze it against its current state. The **Cluster analysis** card on **Overview** carries the same option once a run exists.

To act on the suggested change, [Run Epoch from the issue](/docs/error-feed/guides/run-epoch-from-an-issue): it drafts scenarios from the issue's traces and searches for a change that fixes them. To take the analysis elsewhere, **Export** › **Analysis** in the issue's header downloads it as Markdown; [Investigate an issue](/docs/error-feed/guides/investigate-an-issue#header-and-sidebar) covers it.

## If it fails

A run can fail with one of two messages: **Couldn't start the analysis. Please try again.** or **Couldn't connect to the server. Please try again.** For what each one means and what to do about it, see [Analysis doesn't finish](/docs/error-feed/troubleshooting/analysis-does-not-finish).
