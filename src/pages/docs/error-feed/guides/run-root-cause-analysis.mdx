Once you've confirmed a failure pattern, ask [Falcon](/docs/falcon-ai) to compare representative calls from the [cluster](/docs/error-feed/concepts/understanding-error-feed) with a passing baseline. The **Fix** tab returns a written root cause and proposed fix in a thread where you can ask follow-up questions.

<Prerequisites title="Before you start">
- An [investigated issue](/docs/error-feed/guides/investigate-an-issue) with traces in the selected time range.
- One [credit](/docs/billing) for a run, including a rerun. It is taken when the run starts and refunded if the run fails.
</Prerequisites>

## Run the analysis

1. Open **Fix** on the issue's detail page.

   Before the first run, you should see **No analysis yet** and **Analyze this cluster**; **Re-run** sits in the headline card from the outset, so it isn't a sign that something already ran.

<img src="/images/docs/error-feed/guides/fix-tab-empty-state-annotated.png" alt="Fix tab empty state showing No analysis yet with the Analyze this cluster button, and the Re-run button on the headline card above it" style={{ borderRadius: '5px' }} />

2. Select **Analyze this cluster**.

   This spends one credit. **Overview > Cluster Analysis > Debug this cluster** starts the same run for the same cost, so use one entry point, not both.

The run starts immediately. Sub-agents sample representative calls and the tab checks for a result until the run finishes, fails or reaches its one-hour limit. The result arrives as a single written message in the thread.

## Read the result

1. Read **Synthesis** for the explanation of what went wrong and why.
2. Read **Fix** for the proposed change.
3. Check the confidence badge in the card's corner against the evidence it describes.

<div class="sdk-ref-table max-sm:[&_td]:px-1.5! max-sm:[&_th]:px-1.5!">

| Badge | Evidence for the root cause, not the proposed fix |
| --- | --- |
| **High confidence** | Several traces show the same pattern and show what causes it. |
| **Medium confidence** | The pattern is clear but part of the cause is inferred. |
| **Low confidence** | The failure is visible but the traces don't establish its cause. |

</div>

4. Ask about any missing evidence in **Ask Falcon a follow-up...** beneath the thread.

   You should see **Falcon is investigating...** while the reply streams in.

The **Cluster Analysis** card on **Overview** shows the same root cause and fix. **View reasoning** opens the thread; **Create Linear issue** starts the [ticket handoff](/docs/error-feed/guides/create-linear-issue). Collapsing the card leaves the confidence level and fix layer visible.

## Decide whether to rerun

Ask a follow-up when you need more explanation of the existing analysis. If the cluster has new traces, a fresh run can analyze its current state instead.

1. Check that the selected Feed time range includes the new calls.
2. Select **Re-run** only if a fresh comparison is worth another credit.

   The header tooltip reads **Re-run with current cluster state (1 credit)**; after a run, the Overview card also offers **Re-run analysis (1 credit)**.

## Read a stored result from code

Use the [cluster detail lookup](/docs/sdk/reference/error-clusters#error_clustersget) to read the stored analysis through the API, Python or TypeScript. Its response includes the `rca` field. The read-only MCP tool `get_error_cluster` also returns the stored analysis. These reads do not start a new run.

## If the analysis fails

A failed run shows an error message in the thread, for example **Couldn't start the analysis. Please try again.** or **Couldn't connect to the server. Please try again.** Any such message appears in a **Synthesis** card with a **Low confidence** badge and no **Fix** line. That's an error, not a result.

Those two messages mean the request failed before a run started, so run it again. A different message says the connection dropped after the run started. That message also appears when the workspace has no credit left, so check the credit balance and the Feed time range before you retry.
