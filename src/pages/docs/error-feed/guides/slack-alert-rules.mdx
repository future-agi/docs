## About

Use an Error Feed alert when you want to hear about a particular issue, such as the fifth time the Ridgeline Outfitters support agent times out looking up an order. If you want an alert about a project metric, such as latency, use an [Observe monitor](/docs/observe/guides/setup-alerts) instead.

## Create and test a rule

You need write access to a Future AGI workspace with Error Feed. For the example, use a project that [sends issues to Error Feed](/docs/error-feed/guides/turn-on-error-feed) and a Slack channel where you can check the notification.

<Steps>
  <Step title="Choose the project">
    Open **Error Feed > Alert rules > Create alert**. Enter `Ridgeline repeated timeouts` in **Rule name**. Under **Project**, select your support agent's project, for example `ridgeline-support`. Leave **All projects in this workspace** selected only if you want issues from any project in the Future AGI workspace to qualify.

    {/* MEDIA: Create Error Feed alert drawer with the Ridgeline rule name and project selected. */}
  </Step>
  <Step title="Set the event and filters">
    Under **When**, set **Issue event** to **Occurrence count crosses a threshold** and **Occurrence threshold** to `5`. This counts occurrences of one issue, not timeouts across several issues.

    Under **If**, enter `Timeout Issues` in **Issue categories** and press Enter. Category names must match exactly. For a different scanner issue, use its [category name](/docs/error-feed/reference/error-taxonomy). Leave the other fields empty to accept any value. You can also filter by **Sources**, **Severity filter**, **Status**, or **Issue groups**. Selecting High and Critical in the severity filter would match either level, but the issue would still have to match the category.

    {/* MEDIA: When and If sections showing an occurrence threshold of 5 and the Timeout Issues category tag. */}
  </Step>
  <Step title="Choose the Slack channel and frequency">
    Under **Then**, select the **Slack workspace**, then search **Channel** for your destination, for example `#ridgeline-support-alerts`. If no workspace is connected, use **Connect Slack** and complete authorization. The form keeps your draft while you connect.

    Leave **Notify at most** at **Once per issue every 1 hour**. You can also choose 5 minutes, 15 minutes, 24 hours, or **On every matching event**. The cooldown applies to this rule and this issue: it does not silence a different issue in the same channel.

    {/* MEDIA: Slack workspace, private destination channel, one-hour cooldown, and Preview in the Then section. */}
  </Step>
  <Step title="Save first, then send a test">
    Read **Preview** to check the event, project, and channel. It is a summary in the form; it does not contact Slack. Click **Create alert**. In the **Alert rules** table, find the saved row and click **Test**.

    Look in the selected channel for `[Test] Error Feed alert: Ridgeline repeated timeouts`. This confirms delivery to the channel without waiting for a timeout. It does not evaluate the filters or change **Last sent**.

    {/* MEDIA: Saved Ridgeline rule with its Test button and the labeled test message in the selected Slack channel. */}
  </Step>
</Steps>

## What makes a rule fire?

| Issue event | What has to happen |
|---|---|
| A new issue is created | Error Feed creates a matching issue after you save the rule. Another occurrence of an existing issue is not a new issue. |
| Severity reaches a level | The issue first receives a severity at or above the selected level, or moves from below it to that level or higher. A default placeholder severity does not count. |
| Issue status changes to escalating | An existing issue changes from a different status to Escalating. An issue created already Escalating does not qualify. To catch those creations, use **A new issue is created** with **Status** set to **Escalating**. |
| Occurrence count crosses a threshold | One issue's count moves from below the threshold to the threshold or higher. Choose a whole number from 1 to 1,000,000. |

For the Ridgeline rule, watch the same `Timeout Issues` issue in `ridgeline-support` after saving:

| What happens | What you should see in Slack |
|---|---|
| The count goes from 3 to 4. | No message. The count is still below 5. |
| The count goes from 4 to 5. | An issue notification, not a `[Test]` message. It includes the issue title, state, severity, project, and rule name. |
| The count goes from 5 to 6, even the next day. | No repeat. Staying above 5 is not a crossing. Even if this issue's count later drops to 4 and returns to 5, the rule does not send the same alert again. |
| A different `Timeout Issues` issue in the project crosses 5 within the hour. | A new notification. The first issue's cooldown does not apply to this one. |

## Check the saved settings with cURL

To check the rule without sending another Slack message, use [API keys](/docs/admin-settings/api-keys) for the same workspace. With `FI_API_KEY` and `FI_SECRET_KEY` exported and `jq` installed, run:

```bash
curl --fail --silent --show-error \
  -H "X-Api-Key: ${FI_API_KEY:?Set FI_API_KEY}" \
  -H "X-Secret-Key: ${FI_SECRET_KEY:?Set FI_SECRET_KEY}" \
  'https://api.futureagi.com/tracer/alerts/?kind=error_feed' |
  jq '.result.alerts[] | select(.name == "Ridgeline repeated timeouts") |
    {id, enabled, trigger_type, occurrence_threshold, filters, slack_channel_name, cooldown_seconds}'
```

Look for `occurrences_crossed`, an `occurrence_threshold` of `5`, and `cooldown_seconds` of `3600`. If the request succeeds but prints nothing, no rule in that workspace has the exact name in the `jq` filter.

To send the same test message as the **Test** button, export the saved rule's `id` as `RULE_ID` and run:

```bash
curl --fail --silent --show-error \
  -H "X-Api-Key: ${FI_API_KEY:?Set FI_API_KEY}" \
  -H "X-Secret-Key: ${FI_SECRET_KEY:?Set FI_SECRET_KEY}" \
  -H 'Content-Type: application/json' \
  --data '{}' \
  "https://api.futureagi.com/tracer/alerts/error_feed/${RULE_ID:?Set RULE_ID}/test/"
```

On success, `result.sent` is `true`.

## If a notification is missing

- **Channel missing from the picker:** Check that you selected the right Slack workspace and the channel is not archived. For a private channel, invite the Slack app and reload the picker. For a public channel, the app can join when you save the rule. If the picker says **Could not load channels.**, click **Retry**.
- **Test fails:** Check the Slack connection in [Settings > Integrations](/docs/admin-settings/integrations) and confirm the app still has access to the saved channel. Then click **Test** on the saved row again.
- **Test arrives but the issue notification does not:** Check the **Status** switch on the rule, its project, and all filters. They must match the issue at the time of the event. Saving a rule does not replay an earlier crossing. For repeatable events such as a change to Escalating, a second matching transition for the same issue during its cooldown is suppressed, not delayed.
