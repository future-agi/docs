## About

Use **Error Feed** to decide which issues to investigate, who should own them, and how urgent they are. Suppose the Ridgeline Outfitters support agent promises a refund without checking eligibility. You want to find the failed refund-policy eval, then review what the scanner found.

## Filter the list by source

1. Open **Error Feed**. The time range starts at **Last 7 days**. Use **Search errors** to match the issue title, group, or category. For example, search for `Ridgeline refund policy` if that is the name of your eval task.
2. Open **Filter**, choose **Source**, leave the operator at **is** (equals), and select **Eval**. The list updates as you select the value. Under the issue title in the **Error** cell, **Eval** identifies the source; the separate error-type badge identifies the failed eval, such as **Ridgeline refund policy**.
3. Remove the search text. Switch the source to **Scanner** to see scanner findings instead, or remove the Source filter to see both sources. Use **Add filter** to narrow the list by **Project**, **Status**, **Severity**, or **Fix layer** as well.

## Check impact before changing triage

Sort by **Severity**, **Events**, or **Last seen** to choose a row. Use **Trend (14d)** to see when occurrences were concentrated, and **Users** to see how many end users were affected.

1. Open the scanner issue about the refund promise. Read the severity badge in the header, not just the value in the edit menu. **Pending** or **Unassessed** means the default isn't an established impact grade. You can inspect the grouped evidence on **Traces** without waiting for a grade.
2. Hover over the severity badge. For an assessed grade, the tooltip gives the reason. If the tooltip says “reassessment pending”, the badge still shows the prior grade.
3. In the **Triage** sidebar, use **Severity** only if you want to set impact yourself. For example, if the issue is **High** but the refund commitment warrants **Critical** for your team, choose **Critical**. Check the header: the badge should now read **Critical** and the tooltip “Set by a user.” When another matching finding joins this issue, your grade stays in place.
4. Use **Acknowledge** to mark the issue as recognized. Use **Assignee** in the sidebar to choose the teammate handling refunds. Check that the header now shows **Acknowledged** alongside **Critical**.

{/* MEDIA: A grouped refund issue with an assessed severity tooltip, followed by the Triage sidebar changing High to Critical and the header showing the manual reason. */}

### Other status actions

- For one issue, **Resolve** marks it Resolved. **Ignore issue** sets its status to Escalating. To pick a status directly, use **Status** in the **Triage** sidebar.
- For several issues, select their row checkboxes and open **Bulk actions**. Choose **Mark as Resolved**, **Mark as Acknowledged**, **Mark as For Review**, or **Mark as Escalating**. This changes status, not severity.

## Example: inspect the same fields with cURL

With `FI_API_KEY` and `FI_SECRET_KEY` set, use cURL and `jq` to list the same eval issues and see the fields behind their badges. Replace the search text with your eval task's name.

```bash
set -o pipefail
curl --silent --show-error --fail --get 'https://api.futureagi.com/tracer/feed/issues/' \
  --header "X-Api-Key: ${FI_API_KEY:?Set FI_API_KEY}" \
  --header "X-Secret-Key: ${FI_SECRET_KEY:?Set FI_SECRET_KEY}" \
  --data-urlencode 'search=Ridgeline refund policy' \
  --data-urlencode 'source=eval' \
  --data-urlencode 'time_range_days=7' |
  jq '.result.data | map({cluster_id, source, error, status, severity, severity_source, severity_assessment_status, severity_reason})'
```

An empty array means no rows matched. To inspect the scanner issue instead, change `source=eval` to `source=scanner` and search for its title. `source` tells you who detected the problem; `severity_source` tells you where the grade came from.

## If a result looks wrong

- **A Medium filter includes Pending.** The filter uses the stored priority. Hover over the badge before counting the issue as an assessed Medium.
- **A source filter hides the issue you just saw.** The source filter matches the detection pipeline, not the error type. Remove the filter and check the two badges under the title.
- **An edit is missing after refresh.** Reopen the issue from the feed and verify the saved status or severity in the header. A shared issue view is read-only; make changes in your workspace.
