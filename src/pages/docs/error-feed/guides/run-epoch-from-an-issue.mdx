---
title: "Run Epoch from an issue"
description: "Start an epoch from an Error Feed issue, from its traces to a change you can ship"
---

An issue groups the traces where your agent failed the same way. **Run Epoch** on the issue turns a few of those traces into scenarios in an environment, and starts an [epoch](/docs/environments/concepts/epoch) that searches for a fix. You follow the epoch, and ship its winner, from the issue.

<Note>
The epoch runs in an [environment](/docs/environments/concepts/understanding-environments) of the issue's agent, connected as a source repository or a code upload. [Build an environment](/docs/environments/guides/build-an-environment) for the agent first if it has none.

Every Cloud plan includes Epoch. A self-hosted install needs an Enterprise license key that lists Epoch, or **Run Epoch** doesn't appear; see [Enterprise Edition](/docs/self-hosting/configuration/reference#enterprise-edition). A shared link to an issue never shows it.
</Note>

## Start from the issue

Open the issue from the [Feed](/docs/error-feed/guides/triage-issues) and click **Run Epoch** in its header. A drawer opens beside the issue.

<img src="/images/docs/error-feed/guides/issue-run-epoch.png" alt="The issue Agent says a refill is ready while the pharmacy is still filling it, Escalating and High with 23 traces, and Run Epoch at the right of its header" style={{ borderRadius: '5px' }} />
*Run Epoch sits in the issue's header, next to the triage actions*

## Choose where it runs

The first time you run an epoch for a project, the drawer asks **Where it runs**. Pick the environment that tests the issue's agent and click **Continue**. Only environments of code agents are listed. The project's next epochs use the same environment; to change it, click **Change** beside it in the plan.

<img src="/images/docs/error-feed/guides/run-epoch-environment-picker.png" alt="The Run Epoch drawer asking Where it runs, with Northwind Pharmacy refill line, a GitHub chat agent, selected above Northwind Pharmacy voice line, and Continue at the bottom" style={{ borderRadius: '5px' }} />
*Pick the environment once; the project remembers it*

If no environment can run an epoch yet, the drawer says so and offers **Build an environment**, which opens in a new tab. Come back to the issue when it's built, and the list is read again.

## Read the plan

The plan says what will happen before anything does:

- **Runs in**: the environment, and how many of its scenarios came from issues, such as `Holds 4 of at most 36 scenarios from issues`
- **Traces**: the traces picked from the issue, chosen to vary, each with why it was picked: **Cited in the root cause**, **Typical of the issue** or **Recent**. Click **Swap** to trade one for another trace of the issue
- **Drafting**: `One builder turn, billed as authoring credits`
- **Budget**: you set the epoch's budget and limits after the review, before anything runs

Click **Draft scenarios**. Each trace becomes a drafted scenario.

<img src="/images/docs/error-feed/guides/run-epoch-plan.png" alt="The Run Epoch plan for the refill-status issue: Runs in Northwind Pharmacy refill line, three traces from the issue with Cited in the root cause or Typical of the issue and a Swap button each, the Drafting and Budget rows, and Draft scenarios at the bottom" style={{ borderRadius: '5px' }} />
*Nothing runs until you've reviewed the drafts and started the epoch*

If the environment has unsaved scenario changes, the plan can't draft on top of them: click **Review unsaved changes**, then save or discard them.

## Review the drafted scenarios

Drafting goes on if you close the drawer. The issue shows **Drafting scenarios** under its header, then **Drafts ready**; click **Review drafts** in the header to open them again.

Each drafted scenario shows the trace it came from, with **Open in Observe**, what the trace holds and what it's missing, and the conversation. Untick any scenario that doesn't show the issue. Below the scenarios, set what the epoch may change and what it's held to. **May change** starts with every part of the agent the epoch can edit ticked; untick the ones it should leave alone. **Reply time**, **Agent's cost** and **Budget** work as in [Run Epoch](/docs/environments/guides/run-epoch#set-what-it-may-change). **Models** is locked to the models your current agent calls, read from its run before the epoch starts.

Click **Run Epoch**, or **Discard** to drop the drafts.

<img src="/images/docs/error-feed/guides/run-epoch-review-drafts.png" alt="The Review the drafted scenarios drawer with three ticked scenarios drafted from refill-status traces, each with its trace, what it has and misses, and the conversation, then the May change, Models, Reply time and Agent's cost rows, and Run Epoch at the bottom" style={{ borderRadius: '5px' }} />
*Keep only the scenarios that show the issue; the epoch is fixed against them*

Run Epoch adds the kept scenarios to the environment, then runs them on your current agent. The issue shows **Measuring** while that run plays, and you can **Stop** it. When the run ends, the epoch starts on its own.

An environment holds a limited number of scenarios from issues. When it's full, the review says how many it holds and links **Open scenarios**, where you remove some.

## Follow the epoch from the issue

Once the epoch starts, a strip under the issue's header shows its state, one sentence about it, and what you can do next. The header's button changes with it:

| The epoch | The header's button |
|---|---|
| Running | **View Epoch 5**, to follow its steps |
| **Ready for review** | **Open pull request** for an agent on GitHub, or **Make default** for an uploaded agent; **View pull request** once it's open |
| **Failed**, and it can be retried | **Retry** |
| Any other ending | **Run Epoch again** |

<img src="/images/docs/error-feed/guides/issue-epoch-strip.png" alt="The refill-status issue with the strip Ready for review, Epoch 5 found a change that passed every check, View Epoch 5 at the right of the strip, and Open pull request in the header" style={{ borderRadius: '5px' }} />
*The issue says how its epoch ended without opening the epoch*

The Feed shows it too: an icon after the issue's name marks its epoch, and hovering over it gives the state, such as `Epoch 5 · Ready for review`.

<img src="/images/docs/error-feed/guides/feed-epoch-icon.png" alt="The Error Feed list with the refill-status issue first, a check icon after its name, and the tooltip Epoch 5 · Ready for review above it" style={{ borderRadius: '5px' }} />
*Each ending has its own icon, so you can scan the Feed for epochs to review*

The epoch's own page starts its breadcrumb at the issue's ID, which takes you back to the issue. [Review an epoch](/docs/environments/guides/review-an-epoch) covers reading the result and shipping it.

## When the epoch doesn't start

| What the issue says | What to do |
|---|---|
| None of the issue's scenarios failed on the current version | The agent may already be fixed. If it isn't, run Epoch again and pick other traces |
| Too few of the issue's scenarios failed on the current version | Run Epoch again and pick other traces |
| The environment changed after the drafts were reviewed | Run Epoch again to draft them on the current environment |
| Another epoch is running in this environment | Run Epoch again when it ends |
| The run on the current version did not finish | Run Epoch again |
| A problem on our side, not your agent | Run Epoch again |
