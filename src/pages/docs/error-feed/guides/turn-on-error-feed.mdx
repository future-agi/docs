If a project is receiving [traces](/docs/observe/concepts/traces) but its sampling rate is 0%, [Error Feed](/docs/error-feed) won't scan them. Save a nonzero rate to scan new requests, then check whether a scan found an issue.

<Prerequisites title="Before you start">
- A project receiving traces in [Observe](/docs/observe). If it's empty, [send your first request](/docs/observe/quickstart) before you change the rate.
- Error Feed access: every Cloud plan includes it; a self-hosted installation needs an [Enterprise license](/docs/self-hosting/configuration/reference#enterprise-edition) that includes Error Feed. Otherwise the page shows an upgrade prompt and the API returns 402.
- A request that completes its [root span](/docs/observe/concepts/spans). For a trial, use a low-volume test project with a known failure.
</Prerequisites>

## Choose the rate before you spend credits

There's no universally right number. It's a coverage-versus-cost call: analyze more traces and you catch more, but you pay more for it.

On Cloud, each scanned trace consumes [credits](/docs/billing). The amount isn't fixed; it varies from trace to trace with the work the scan does. The rate starts at 0% and applies only to traces that arrive after you save it, not to anything that already went by.

<div class="sdk-ref-table max-sm:[&_td]:px-1.5! max-sm:[&_th]:px-1.5!">

| Situation | Rate | Why |
| --- | --- | --- |
| Building or testing a project | 100% | Nothing slips past you. |
| Low-volume production | 100% | The absolute cost stays low. |
| High-volume production | 10–20% | Enough to catch recurring issues. |
| Cost-constrained, high volume | 5–10% | Still catches patterns that repeat. |

</div>

## Enable scanning

1. Open the target Observe project.
2. Click **Settings** (the gear in the project header).

   You should see **Configure Project** with the project name and current sampling rate.

3. Move **Sampling rate** to the percentage you chose.

   The box beside the slider shows the value from 0% to 100%. 100% is a safe default while you're trying it out.

<img src="/images/docs/error-feed/guides/turn-on-error-feed.png" alt="The Configure Project dialog for the ava-production project, with the Sampling rate slider at 100% and Cancel, Delete, and Update buttons below" style={{ borderRadius: '5px' }} />

4. Click **Update** to save the rate.

   The same dialog has a **Delete** button for the project; use **Update** for this change.

## Check a new request

1. Send a request through your agent that reproduces the known failure.
2. Confirm that the new trace finished in the project.

   Scanning is triggered per trace, not on a timer. On the inline path, Error Feed waits about ten seconds after the root span completes before a scan starts and samples the trace. Traces sent through the [collector](/docs/error-feed/troubleshooting/no-issues-in-the-feed#the-traces-came-in-through-the-collector) skip that trigger and wait for a periodic sweep that works through them in small batches, so expect the first issues in occasional bursts.

3. Open **Error Feed** in the sidebar.
4. Look for an issue from the test project.

   A row appearing in the list confirms scanning is live. A blank feed alone doesn't tell you whether the trace was sampled, the scanner found nothing, or a filter hid the issue.
