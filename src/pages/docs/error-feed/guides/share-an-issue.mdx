## About

Use **Share** when someone needs to inspect the evidence behind one Error Feed issue without editing it or browsing the project. Use **Copy cluster ID** when a ticket only needs a reference: the ID identifies the issue but does not grant access.

## Share with a reviewer

Suppose the Ridgeline Outfitters support agent promises a refund after the return window closes. You want the returns lead to see what the agent said and how a successful run handled the same question.

<Steps>
  <Step title="Check the evidence before sharing">
    Open **Error Feed** and select the refund issue. Review the affected traces, the working comparison if there is one, and any saved analysis on **Fix**. The link opens the current issue, not a snapshot of the tab or trace you have open. Trace inputs, span details, assignee emails, and an existing Linear issue link can all be visible to a recipient.

    {/* MEDIA: Synthetic refund issue with affected traces and the Share and Copy cluster ID controls in the header. */}
  </Step>
  <Step title="Choose who can open the link">
    Click **Share** in the issue header. Under **Who can access**, check the selected option. A new link starts as **Restricted**; an existing link keeps its setting. For the returns lead, select **Restricted**. The link creator and people you add by email can open it while signed in.

    {/* MEDIA: Refund issue header and Share dialog with Restricted selected. Mask the share token. */}
  </Step>
  <Step title="Add the reviewer's sign-in email and send the link">
    Under **Invite people**, enter the email the returns lead uses to sign in, then click **Invite**. Click **Copy** next to the URL and send it to the lead. Ask them to open it while signed in with that address and confirm they see **View only**. The dialog can show the email under **People with access** before the server confirms the invitation.

    {/* MEDIA: Share dialog with a synthetic reviewer marked Can view, the Remove access control, and the Copy button. Mask the share token. */}
  </Step>
</Steps>

Use **Anyone with the link** only if the evidence is suitable for a signed-out reader. This setting applies to the same URL, including copies you already sent. Anyone who receives a forwarded copy can read the evidence without being on the invite list. To check a public demo, use an issue with synthetic traces and open the link in a signed-out browser window.

## Read the shared evidence

The returns lead opens the link and sees **View only**. Here's how to follow the refund decision without changing the original issue:

| Tab | What to do in the shared view |
| --- | --- |
| **Overview** | Pick the late-return conversation under **Traces affected**. The sidebar shows metadata and evaluations for that trace. If the trace evidence offers **Split with working**, use it to read the failing and passing runs side by side. Evaluation issues show input and output instead. |
| **Traces** | Click an affected trace row to open its read-only drawer. Inspect the spans to see, for example, whether the agent looked up the return policy before it answered. |
| **Trends** | Compare errors with traffic to see whether the rise in refund mistakes coincides with more conversations. |
| **Fix** | Read the last saved analysis. If none exists, the tab says **No analysis saved for this issue.** You cannot start or rerun an analysis from this link. |

{/* MEDIA: Shared synthetic refund issue marked View only, switching from an affected trace to its drawer and then to the saved Fix. */}

The shared page does not let the lead resolve the issue, change its severity or assignee, or create a Linear ticket. The drawer reads `GET /tracer/shared/{token}/traces/{trace_id}/` under the issue link's access rules. It allows traces that belong to the issue plus the designated passing comparison, if one exists. Even with a valid public link, a request for a trace outside that set returns `404`.

## Narrow or remove access

Reopen **Share** on the original issue. To turn off signed-out access, select **Restricted** and wait for its checkmark. If the dialog offers **Recheck**, use it before relying on the change. Reload the previously copied URL in a signed-out window: it should now show **Sign in required**. Invited accounts still have access.

To remove a reviewer, use **Remove access** next to their email under **People with access**. Removing an email does not block a public link. Keep the link restricted and verify that the removed reviewer sees **Access denied** when they reload it while signed in. A row can disappear from the dialog without removing the saved permission. Removing an email also does not remove access for the link creator.

{/* MEDIA: Restricted link showing Sign in required in a signed-out window and Access denied for a removed reviewer. Mask the URL in both windows. */}

If the address is missing from the dialog or still has access, use the authenticated shared-link API for that issue.

1. List the issue's links with `GET /tracer/shared-links/?resource_type=error_feed_issue&resource_id={cluster_id}`. Choose the entry whose `token` matches the last part of the URL you sent.
2. Use that entry's `id` in `GET /tracer/shared-links/{id}/`. In `access_list`, find the reviewer's email and note the `id` of that access entry.
3. Call `DELETE /tracer/shared-links/{id}/access/{access_id}/` with the link ID and access entry ID. Read the link detail again to confirm the email is gone.

## Check a link without signing in

For the Ridgeline demo, open a row on the shared issue's **Traces** tab and select **Copy Trace ID** in the drawer. This Bash example checks whether a signed-out recipient can read that trace without printing the token or trace contents. It uses the API for `app.futureagi.com`; for another deployment, set `API_BASE` to its API origin first.

```bash
read -r -s -p 'Paste the issue share link: ' issue_link; printf '\n'
read -r -p 'Trace ID from the shared issue: ' trace_id
issue_link=${issue_link%/}
curl -q --silent --show-error --output /dev/null --write-out 'HTTP %{http_code}\n' \
  "${API_BASE:-https://api.futureagi.com}/tracer/shared/${issue_link##*/}/traces/${trace_id}/"
unset issue_link
```

For an available trace on an active public link, expect `HTTP 200`. After switching the same link to **Restricted**, expect `HTTP 401` from the same signed-out check. If the link does not exist, expect `HTTP 404`.

| Message when opening the link | What to do |
| --- | --- |
| **Sign in required** (`401`) | Choose **Sign in to continue** and use the invited email. |
| **Access denied** (`403`) | Check which account you used. Ask the person who shared the issue to add that email if you need access. |
| **Link not found** (`404`) | Ask for the link from the original issue. The URL may be wrong or the issue may no longer be available. |
| **Link expired** (`410`) | The link expired or was revoked. Ask the person who shared it for a current link. |
