---
title: "No issues in the feed"
description: "The five causes to check, in order, when the Error Feed table stays empty."
---

The Error Feed table is empty and you expected rows. Start with the feed's own empty state below: it tells you whether you're filtered or genuinely empty. If you're genuinely empty, work through the causes that follow in order.

## Check the feed's empty state first

The feed's own empty state tells you which situation you're in. With filters applied, it shows **"No errors match your filters"** and **"Try adjusting your search or filter criteria."** With no filters applied, it shows **"No errors — everything looks good!"** and **"Errors captured by Future AGI will appear here."**

Fix: if you see the filtered message, clear your filters and check again. If you see the unfiltered message, work through the causes below.

## The project's sampling rate is still 0

This is by far the most common cause. A project ships with its sampling rate at 0, so nothing gets scanned until you raise it yourself. If you haven't touched the sampling control since creating the project, this is almost certainly why the feed is empty.

Fix: raise the rate. See [Turn on Error Feed](/docs/error-feed/guides/turn-on-error-feed).

## Your workspace doesn't have an Error Feed license

If your workspace doesn't have the Error Feed capability, the page shows an upgrade message instead of a table, and the API answers with a 402. The message reads **"This feature requires an upgrade."** with a reason and a **Contact us to upgrade** link.

If you instead see **"Couldn't verify feature access."** with a **Retry** button, that's a separate, transient failure to check access, not a licensing block. Retry before assuming it's the license.

Fix: contact Future AGI to add the Error Feed capability to your workspace.

## The traces are too new

Scanning doesn't start the instant a trace lands. It waits for the trace's root span to complete, then pauses about ten seconds before sampling and scanning it. A trace you just sent won't have anything to show yet, purely because of that delay.

Fix: wait a bit longer, then refresh the feed.

## The traces came in through the collector

Traces reach Future AGI one of two ways: through the SDK's inline path, or through Future AGI's collector. Check how tracing was set up for this project; if you're not sure, ask whoever configured it. If it's the collector, traces skip that ten-second trigger entirely. Instead they wait on a periodic sweep: it dispatches traces in small batches of 15, with about a minute of grace before a trace is eligible, and can take up to 15 minutes to complete its first pass on a project that hasn't been scanned before.

Fix: give the sweep time, especially right after you enable scanning or connect the collector for the first time.

<Note>
Scanning a trace produces a **finding**; Error Feed still has to cluster findings into an **issue** before a row shows up in the table. So even a trace that's already been scanned can take a little longer than the waits above to appear as one.

Fix: give it a little longer, then refresh the feed.
</Note>

## Still empty after all of this?

Contact Future AGI for help.
