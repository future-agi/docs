---
title: "Analysis doesn't finish"
description: "Why a Fix tab analysis stalls or ends without a result, and how to recover it"
---

A cluster's [root cause analysis](/docs/error-feed/guides/run-root-cause-analysis) on the **Fix** tab can stall instead of landing a result. Here's how to tell which of four things happened, and what to do about it.

## Couldn't start, or the connection dropped

Two different messages point to two different failures.

- `Couldn't start the analysis. Please try again.` The request that kicks off the run never went through. Nothing started
- `Couldn't connect to the server. Please try again.` The run started, but the connection that streams its progress back dropped partway through. Reloading won't recover it: nothing from that interrupted attempt carries over into a new run, so there's nothing to wait for

Either way, it's safe to re-run.

## The run hit its one-hour limit

A run is capped at one hour. If it's still going when it hits that limit, it ends as failed instead of landing a result, even if it was close to finishing. The signal is timing: the run keeps going for most of an hour before it drops into that failed state, it doesn't fail right away.

## The workspace was out of credit

Future AGI checks and deducts a credit before the run starts, not after. If the workspace doesn't have one to spare, the run can't start at all: it fails immediately, not after running for a while like the one-hour case above.

## What to do

Before you re-run, check the cluster still has traces inside the time window you've got selected. If the window has moved past everything in the cluster, there's nothing there for the re-run to analyze.

Press **Re-run** in the cluster's header. Its tooltip reads `Re-run with current cluster state (1 credit)`, since each run, including a re-run, draws a fresh credit. That deduction is refunded automatically whenever a run fails, whichever of the reasons above caused it, so a run that didn't finish shouldn't have cost you anything.

What happens if you re-run depends on which cause you hit:

- Couldn't start, or the connection dropped: safe to re-run right away, nothing from the interrupted attempt carries over
- Hit the one-hour limit: the cap doesn't move between runs, so re-running the same cluster and window is likely to hit it again
- Out of credit: the re-run above still needs a fresh credit, so it fails the same way until the workspace has credit to spare

If a re-run still doesn't land a result, go back through the symptoms above to confirm which cause you're actually dealing with; it's easy to mistake one for another.
