## What an agent definition holds

An **agent definition** is the record of the agent under test. It names the agent, sets its type as voice or chat, and holds the connection details Simulation needs to reach it. Scenarios and runs point at a definition, and at one of its versions, to know exactly which agent they are testing. A "Support agent" voice definition, connected to your Vapi assistant, is a typical one.

## Voice agents and chat agents

The type decides how Simulation talks to your agent.

### Voice

A voice agent is provider-connected. You give it a provider, currently **Vapi** or **Retell**, an assistant ID, and an API key, and Simulation places or receives the call through that provider. You can pull the assistant's name and system prompt straight from the provider so the definition matches what runs in production.

### Chat

A chat agent is answered by your own code. Simulation sends each user turn to your agent through the SDK callback or a websocket, and your service returns the reply. This is how you test a chat agent that is not tied to a voice provider.

## Versions

A **version** is a numbered snapshot of a definition's configuration, created when you explicitly save one, not on every edit: editing the definition directly updates its current version in place. A version carries a status, one of **Draft**, **Active**, **Archived**, or **Deprecated**, and only one version is Active at a time: new runs use the Active version by default. Because every run is tied to the version it used, you can change the definition, create a new version, and see whether the score moved against a frozen config. Versions are never deleted, so if a new one regresses, you roll back by activating an older one again.
