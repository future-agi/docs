## What a scenario is

A **scenario** is one test case for your agent: the situation the conversation starts from, the flow it should take, and the data each run needs. A refund request, a booking change, a billing dispute, each is a scenario, and each holds the rows that turn it into many concrete conversations.

## Four ways to build one

You build a scenario from whichever source fits how you already describe your tests.

### Workflow graph

A visual flow of nodes and edges: conversation steps, end-call, and transfer nodes wired together. Build it by hand for full control, or auto-generate it from a description. Best when a test has multiple paths and branches.

### Dataset

One scenario row per table row, from a file you upload or synthetic data you generate. Best when you already have structured customer profiles and variables.

### Script

A call script of customer and agent lines you paste or upload. The platform parses it into a graph and rows. Best for compliance or a specific dialogue you need to test.

### Call or chat SOP

A standard operating procedure written as numbered steps. The platform turns the procedure into a graph and rows. Best for consistency and training checks.

| Source | Reach for it when |
|---|---|
| Workflow graph | The test branches across several paths |
| Dataset | You have structured rows or want many synthetic ones |
| Script | You have a real transcript or a fixed dialogue |
| Call or chat SOP | You have a written procedure to enforce |

## The simulator prompt

Each scenario carries a **simulator prompt** that tells the simulator how to play the customer. It reads values from the scenario table with `{{column_name}}` placeholders, so every row personalises the same prompt: `{{customer_name}}` and `{{objection_type}}` fill in per row. A variable only resolves if a column of that name exists, so the editor flags any that do not.

## Global nodes

A **global node** is a conversation step the agent can jump into at any point, not only when the flow reaches it. It fires when the user's message matches what the node's prompt describes, which makes it the right home for things that can interrupt any moment: an off-topic question, a sudden pricing query, or a "talk to a human" request. One global node handles the case from anywhere, so you do not draw an edge to it from every node. Only conversation nodes can be global.

## Scenarios are reusable

Because a scenario is defined once and pinned to a run, the same set of scenarios can play against every agent version. Kept together, they become a regression suite: run them after each change and any conversation that used to pass and now fails stands out.
