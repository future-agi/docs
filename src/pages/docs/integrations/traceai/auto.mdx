## About

Preload `@traceai/auto` to record supported AI calls without changing your Node.js model code. By default, Future AGI receives the model call while your existing tracing setup continues to send application spans to its own destination.

## Trace your application

You need Node.js 20.6 or later on the server, a Future AGI [API key and secret key](https://app.futureagi.com/dashboard/keys), and credentials for your model provider. If you cannot open the keys page, ask a workspace administrator to provision the keys. Use your existing app, or try the [Ridgeline Outfitters support example](#try-a-minimal-openai-app).

<Steps>
<Step title="Install the package">

Run in your application's directory:

```bash
npm install @traceai/auto@0.4.1
```

Installation alone does not start tracing. The package includes OpenAI SDK instrumentation and an observer for supported AI requests made with global `fetch`.

</Step>
<Step title="Configure your project">

Set the keys in your secret manager or replace the placeholders in your shell. The example sends support-agent calls to `ridgeline-support`. Set `FI_TRACES_URL` to your collector origin if you self-host. Each launch below passes that URL as the Node agent’s `FI_BASE_URL`, without changing the platform URL for other commands.

```bash
export FI_API_KEY="YOUR_API_KEY"
export FI_SECRET_KEY="YOUR_SECRET_KEY"
export FI_PROJECT_NAME="ridgeline-support"
export FI_TRACES_URL="https://api.futureagi.com"
```

<Warning>
Prompts, responses and supported tool content are captured by default. Before sending sensitive content, set `FI_HIDE_INPUTS=true`, `FI_HIDE_OUTPUTS=true` and `FI_HIDE_ERROR_DETAILS=true`. See [privacy controls](#privacy-controls).
</Warning>

</Step>
<Step title="Start with the preload">

Replace `app.mjs` with your entry file. The preload must run before the target SDK loads.

```bash
FI_BASE_URL="$FI_TRACES_URL" node --import @traceai/auto/register app.mjs
```

For an npm start script, add the preload to `NODE_OPTIONS`, preserving any flags you already use:

```bash
FI_BASE_URL="$FI_TRACES_URL" NODE_OPTIONS="${NODE_OPTIONS:+$NODE_OPTIONS }--import @traceai/auto/register" npm start
```

For CommonJS, `--import` also works, or you can use:

```bash
FI_BASE_URL="$FI_TRACES_URL" node --require @traceai/auto/register app.cjs
```

Choose one method per process. Preload each worker you want to trace. Do not also register a second instrumentation for the same client.

</Step>
<Step title="Find the model call">

Make a model request and consume the response. In Future AGI, open **Tracing** under **Observe** and select `ridgeline-support`. On the **Trace** tab, choose **Display > Group traces by > Span**, then open `OpenAI Chat Completions` for the example app. You can see the model, duration, inputs and outputs unless hidden, and token usage when the provider returns it.

![The OpenAI Chat Completions span shows the backpack question and rain-cover reply from gpt-4.1-mini, with a duration of 774 ms and 39 tokens: 20 prompt and 19 completion.](/images/docs/integrations/traceai/auto/backpack-rain-cover-model-span.png)

A short-lived Node process flushes completed spans on natural exit. A hard exit can lose spans. For Lambda, flush at each invocation boundary; see [short-lived processes](https://github.com/future-agi/traceAI/blob/npm-traceai-auto-v0.4.1/typescript/packages/traceai_auto/docs/FRAMEWORKS.md#aws-lambda-and-short-lived-processes).

</Step>
</Steps>

## Try a minimal OpenAI app

In a new example directory with the preload installed, add the OpenAI client and a start script for `app.mjs`. If you are tracing an existing app, keep its own start script:

```bash
npm install openai@6
npm pkg set scripts.start="node app.mjs"
```

Set `OPENAI_API_KEY` in your environment. The example defaults to `gpt-4o-mini`; set `OPENAI_MODEL` to use a different chat model. For an OpenAI-compatible gateway, also set `OPENAI_BASE_URL` to its API base. Save this as `app.mjs` and run the preload command above. The app itself needs no tracing imports.

```javascript
import OpenAI from "openai";

const response = await new OpenAI().chat.completions.create({
  model: process.env.OPENAI_MODEL || "gpt-4o-mini",
  messages: [{ role: "user", content: "Name one item that keeps a backpack dry on a rainy hike." }],
});
console.log(response.choices[0].message.content);
```

For the CommonJS preload command, save this equivalent entry point as `app.cjs`:

```javascript
const OpenAI = require("openai");

async function main() {
  const response = await new OpenAI().chat.completions.create({
    model: process.env.OPENAI_MODEL || "gpt-4o-mini",
    messages: [{ role: "user", content: "Name one item that keeps a backpack dry on a rainy hike." }],
  });
  console.log(response.choices[0].message.content);
}
main().catch(error => { console.error(error.name); process.exitCode = 1; });
```

## Compare the two exporters

Suppose your support service already traces each reply as `support.answer`. With the default settings, the agent creates its own provider for AI spans. It does not register a global provider, context manager or propagator. The model span still inherits the active app span's trace ID and parent ID, even though Future AGI does not receive the parent span itself.

To see both destinations, install the OpenTelemetry packages for a small test application:

```bash
npm install @opentelemetry/api@1.9.0 @opentelemetry/sdk-trace-base@2.2.0 @opentelemetry/sdk-trace-node@2.2.0
```

Save this as `support-request.mjs` beside `app.mjs`. It registers the app's provider first, then loads the agent, so importing `app.mjs` makes one model call inside the active `support.answer` span. The in-memory exporter prints only names and IDs.

```javascript
import { trace } from "@opentelemetry/api";
import { InMemorySpanExporter, SimpleSpanProcessor } from "@opentelemetry/sdk-trace-base";
import { NodeTracerProvider } from "@opentelemetry/sdk-trace-node";

const appExporter = new InMemorySpanExporter();
const provider = new NodeTracerProvider({ spanProcessors: [new SimpleSpanProcessor(appExporter)] });
provider.register();
await import("@traceai/auto/register");

try {
  await trace.getTracer("ridgeline-support").startActiveSpan("support.answer", async span => {
    try {
      await import("./app.mjs");
    } finally {
      span.end();
    }
  });
  await provider.forceFlush();
  for (const span of appExporter.getFinishedSpans()) {
    console.log("app exporter:", span.name, span.spanContext().traceId, span.spanContext().spanId);
  }
} finally {
  await provider.shutdown();
}
```

Run the file twice, in separate processes. It already loads the agent, so do not add a preload to these commands.

```bash
FI_BASE_URL="$FI_TRACES_URL" FI_FORWARD_APP_SPANS=false node support-request.mjs
```

```bash
FI_BASE_URL="$FI_TRACES_URL" FI_FORWARD_APP_SPANS=true node support-request.mjs
```

In the project's span list, match each run by trace ID. Ignore hyphens when comparing IDs: OpenTelemetry prints the same hex characters without them. Use span rows for this comparison so you can find the model call even when its parent was not exported.

| Run (app provider starts first) | App exporter prints | Future AGI receives |
| --- | --- | --- |
| Forwarding off (default) | `support.answer` | One `OpenAI Chat Completions` span. Its parent ID points to the app span. |
| Forwarding on | `support.answer` and `OpenAI Chat Completions` | One `support.answer` parent with one model-call child, not two root spans. |

![Three span rows in ridgeline-support, newest first. The top two rows, OpenAI Chat Completions and support.answer, share the forwarded run’s trace ID. The earlier run has only the model span.](/images/docs/integrations/traceai/auto/span-forwarding-comparison.png)

Forwarding includes your provider's application spans, not just the parent of an AI call. Enable it only if you want both destinations to receive that telemetry. If the **app's SDK starts after the agent** with forwarding on, the agent attaches its export route on the next tick or when the next AI span starts. App spans that end after attachment reach Future AGI. AI spans stay on the agent's provider, so your app exporter does **not** receive them in that order. To use an application-owned exporter instead of Future AGI, see [custom OpenTelemetry destinations](https://github.com/future-agi/traceAI/blob/npm-traceai-auto-v0.4.1/typescript/packages/traceai_auto/docs/CONFIGURATION.md#bring-your-own-opentelemetry-destination).

## Select incoming HTTP spans

If you want the incoming request around a model call, install `@opentelemetry/instrumentation-http@0.202.0` and explicitly include `http` in `FI_INSTRUMENTATIONS`, for example `FI_INSTRUMENTATIONS=openai,wire,http`. This is an allowlist: include the AI integrations you still want. Installing the HTTP package alone does nothing.

On the default Future AGI route, the agent exports an incoming HTTP `SERVER` span only if it sees an AI span in the same trace. A support request that calls the model qualifies; a `/health` request that never calls it does not. The HTTP integration does not create outgoing non-AI client spans. Set `FI_DISABLED_INSTRUMENTATIONS=http` to turn the hook off even when allowlisted.

If your app already has a provider when the agent starts and forwarding is off, the agent leaves incoming HTTP to your app. It warns once and reports `http` as `disabled` rather than instrumenting the request twice. If you turn on forwarding, your app's own HTTP spans are application telemetry and can be forwarded too.

## Supported libraries

The preload includes OpenAI library hooks. The wire observer recognizes specific AI endpoints and request shapes used with global `fetch`; it yields to covered model calls rather than recording the same request again. Dedicated integrations for other libraries must be installed separately. From your app directory, see which ones are missing:

```bash
npx --no-install traceai-auto bootstrap
```

`bootstrap` reports suggested packages without installing them. Restart after installing an instrumentor. For Genkit, distinguish a model request from the flow that made it. Genkit creates native spans on the global provider. With Genkit and its instrumentor installed and enabled, `genkit` reports `manual` on the default AI-only route even if automatic setup succeeds: a captured model request does not mean the Genkit flow was exported. To include native spans, opt into forwarding with Genkit's provider registered first, or use the [Genkit span processor](/docs/integrations/traceai/genkit) instead of the preload. An installed instrumentor without an `enable` entry needs the explicit processor setup. Do not instrument the same client twice.

See the [library coverage table](https://github.com/future-agi/traceAI/blob/npm-traceai-auto-v0.4.1/typescript/packages/traceai_auto/README.md#library-coverage) for package names and setup modes.

## Privacy controls

To hide content from the first request, set the flags before starting Node:

```bash
FI_HIDE_INPUTS=true FI_HIDE_OUTPUTS=true FI_HIDE_ERROR_DETAILS=true \
FI_BASE_URL="$FI_TRACES_URL" node --import @traceai/auto/register app.mjs
```

| Data | Control on the Future AGI route |
| --- | --- |
| Inputs and outputs | `FI_HIDE_INPUTS` and `FI_HIDE_OUTPUTS` hide supported content, including recognized prompt and response fields on forwarded app spans. They do not make arbitrary custom attributes safe. |
| Errors | Set `FI_HIDE_ERROR_DETAILS=true` to hide details explicitly. When unset, hiding input/output values, messages, text or invocation parameters can also hide errors. Explicit `false` overrides that derived setting, not credential or media scrubbing. |
| Credentials and PII | Known secrets are scrubbed, but unknown or transformed secrets may remain. PII pattern redaction is off by default; `FI_PII_REDACTION=true` enables it. |
| Media and embeddings | Raw audio and recognized base64 media are omitted. Raising `FI_BASE64_IMAGE_MAX_LENGTH` does not enable base64 image export. Catalog wire embeddings retain dimensions, not vectors; `FI_HIDE_EMBEDDING_VECTORS=true` also hides vectors on other supported routes. |

Privacy switches accept `true`, `1`, `yes`, `on` or `false`, `0`, `no`, `off`, ignoring case and surrounding spaces. Blank means unset; any other nonblank value turns hiding on and produces one warning per switch without echoing the value. Do not assume these aliases work for other settings: use literal `true` or `false` for `FI_FORWARD_APP_SPANS`.

Other exporters retain their own privacy policies. Configure them separately if you enable forwarding. See the [privacy reference](https://github.com/future-agi/traceAI/blob/npm-traceai-auto-v0.4.1/typescript/packages/traceai_auto/docs/CONFIGURATION.md#privacy-options).

## Configuration and deployment

Set configuration before startup. Later `init()` calls do not change the setup; restart the process to apply changes.

| Setting | When to use it |
| --- | --- |
| `FI_API_KEY`, `FI_SECRET_KEY` | Both keys must come from the same configuration source for the Future AGI destination. |
| `FI_PROJECT_NAME`, `FI_BASE_URL` | Choose the Observe project and, for a self-hosted install, the collector base URL or full traces endpoint. The default URL is `https://api.futureagi.com`. |
| `FI_INSTRUMENTATIONS`, `FI_DISABLED_INSTRUMENTATIONS` | Set a comma-separated allowlist or denylist. The denylist wins. Without an allowlist the agent considers eligible integrations other than incoming HTTP. |
| `FI_WIRE_CAPTURE` | Set to `false` to turn off global-fetch capture and transport credential observation. Defaults to `true`. |
| `FI_SAMPLE_RATE` | Override sampling on the agent's provider. When unset, it honors standard OpenTelemetry sampler settings. An app-owned provider keeps its own sampler. |
| `FI_AUTO_DEBUG`, `OTEL_SDK_DISABLED` | Set the first to `true` for a masked startup report, or the second to `true` to disable initialization. |

For [Next.js](https://github.com/future-agi/traceAI/blob/npm-traceai-auto-v0.4.1/typescript/packages/traceai_auto/docs/FRAMEWORKS.md#nextjs), initialize in the Node runtime and never expose FI keys as `NEXT_PUBLIC_*`. For [server bundlers](https://github.com/future-agi/traceAI/blob/npm-traceai-auto-v0.4.1/typescript/packages/traceai_auto/docs/FRAMEWORKS.md#node-server-bundlers), keep the target SDKs external for library hooks and deploy the full agent payload. The Node preload does not run in [browsers or edge runtimes](https://github.com/future-agi/traceAI/blob/npm-traceai-auto-v0.4.1/typescript/packages/traceai_auto/docs/FRAMEWORKS.md#edge-and-browsers).

## Troubleshooting

Run diagnostics from the app directory with the same environment as your service:

```bash
FI_BASE_URL="$FI_TRACES_URL" npx --no-install traceai-auto doctor
```

Read the JSON, not just the exit code. `active: true` means instrumentation initialized. `collector: "accepted"` means the test export succeeded; `"failed"` means it did not. `"not_tested (...)"` means no result, for example with `doctor --no-check`, which skips the test export. A zero exit code alone does not prove export health.

For the OpenAI example, the same report can show `wire` as `instrumented`, `openai` as `pending`, and `http` as `disabled`: the fetch observer is ready, the doctor process has not imported the OpenAI client, and you have not selected incoming HTTP.

| Symptom | What to check |
| --- | --- |
| `active: false` or `collector: "failed"` | Check both FI keys, `OTEL_SDK_DISABLED`, the collector URL and outbound connectivity. Startup itself does not probe the collector. |
| A library shows `pending` | A hook is waiting for a compatible import. Doctor runs in a separate process. Check your app's load order and inspect `report()` from `@traceai/auto` **in the running app** to see its actual integration statuses. |
| `missing_instrumentor` or `manual` | Use `bootstrap` to find the missing package. For `manual`, use the library's explicit wrapper or processor instead. |
| No wire span | Consume or cancel the response. Direct `undici.fetch`, `node-fetch`, WebSocket and gRPC are not the process's global `fetch`. |
| Duplicate model spans | Check for a second instrumentor or export route to the same destination. A custom transport that nests the network request inside two or more consecutive app spans within the model span can also defeat wire deduplication. |
