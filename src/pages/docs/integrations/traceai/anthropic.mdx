Trace Anthropic Messages API calls in Future AGI, including request timing, model details, token usage and, when you enable it, message content.

## 1. Install

<CodeGroup titles={["Python", "JS/TS"]}>

```bash Python
pip install "anthropic>=1.14.0" fi-instrumentation-otel
```

```bash JS/TS
npm install @traceai/anthropic@0.1.3 '@anthropic-ai/sdk@^0.27.3' @traceai/fi-core '@opentelemetry/instrumentation@^0.202.0'
```

</CodeGroup>

The Python example uses the Anthropic SDK's native OpenTelemetry tracing, available in SDK 1.14.0 and later, so it doesn't need `traceAI-anthropic`. To keep an existing `AnthropicInstrumentor` setup, see [Keep AnthropicInstrumentor in Python](#keep-anthropicinstrumentor-in-python).

The TypeScript instrumentor declares [`@anthropic-ai/sdk` `^0.27.3`](https://github.com/future-agi/traceAI/blob/main/typescript/packages/traceai_anthropic/package.json) as its peer dependency. Keep that SDK range rather than installing the latest major version.

## 2. Set environment variables

Export credentials before running either example. Set `ANTHROPIC_MODEL` to a Messages API model available to your account.

```bash
export FI_API_KEY="YOUR_FI_API_KEY"
export FI_SECRET_KEY="YOUR_FI_SECRET_KEY"
export ANTHROPIC_API_KEY="YOUR_ANTHROPIC_API_KEY"
export ANTHROPIC_MODEL="YOUR_MODEL_ID"
```

In Python, the SDK's spans include model, timing and token usage but no prompts or responses until you set `content_mode` to `"content"` in step 4.

In TypeScript, messages, responses, images and tool payloads can be captured by default. To hide input and output content, set these [TraceConfig controls](/docs/sdk/tracing/trace-config) before initialization:

```bash
export FI_HIDE_INPUTS=true FI_HIDE_OUTPUTS=true
export FI_HIDE_INPUT_MESSAGES=true FI_HIDE_OUTPUT_MESSAGES=true
```

Model metadata and custom attributes can still be exported. Error text may contain request data, credentials or local paths; input/output hiding alone is not a guarantee that every error or custom field is redacted. Review the controls supported by your installed core version before tracing sensitive workloads.

## 3. Initialize tracing

Use the same project name for the provider and the project you open in Observe.

<CodeGroup titles={["Python", "JS/TS"]}>

```python Python
from fi_instrumentation import register
from fi_instrumentation.fi_types import ProjectType

trace_provider = register(
    project_type=ProjectType.OBSERVE,
    project_name="anthropic_project",
)
```

```typescript JS/TS
import { register, ProjectType } from "@traceai/fi-core";

const tracerProvider = register({
  projectType: ProjectType.OBSERVE,
  projectName: "anthropic_project",
});
```

</CodeGroup>

## 4. Trace the client

In Python, pass the provider to the Anthropic client. In TypeScript, instrument before making API calls; the example patches the imported SDK explicitly so it does not depend on module-loading order.

<CodeGroup titles={["Python", "JS/TS"]}>

```python Python
import anthropic

client = anthropic.Anthropic(
    open_telemetry={
        "tracer_provider": trace_provider,
        "traces": {"content_mode": "metadata_only"},
    }
)
```

```typescript JS/TS
import Anthropic from "@anthropic-ai/sdk";
import { AnthropicInstrumentation } from "@traceai/anthropic";
import { registerInstrumentations } from "@opentelemetry/instrumentation";

const instrumentation = new AnthropicInstrumentation();
registerInstrumentations({
  instrumentations: [instrumentation],
  tracerProvider,
});
instrumentation.manuallyInstrument(Anthropic);
```

</CodeGroup>

To export prompts and responses from Python, change `"metadata_only"` to `"content"`. Pass the same `open_telemetry` option to `anthropic.AsyncAnthropic` for async code.

`TraceConfig` and `FI_HIDE_*` settings don't apply to the SDK's spans, and neither does the session, user, metadata or tags context you set with [context helpers](/docs/sdk/tracing/context-helpers) such as `using_session` or `using_attributes`. If you group traces by session or user, use [AnthropicInstrumentor](#keep-anthropicinstrumentor-in-python) instead.

## 5. Make a request

Run these snippets in the same file as the setup above. Shutdown flushes pending spans before this short script exits.

<CodeGroup titles={["Python", "JS/TS"]}>

```python Python
import os

try:
    message = client.messages.create(
        model=os.environ["ANTHROPIC_MODEL"],
        max_tokens=128,
        messages=[{"role": "user", "content": "Explain what an API is in one sentence."}],
    )
    print(message.content)
finally:
    trace_provider.shutdown()
```

```typescript JS/TS
const client = new Anthropic({ apiKey: process.env.ANTHROPIC_API_KEY });
const model = process.env.ANTHROPIC_MODEL;
if (!model) throw new Error("Set ANTHROPIC_MODEL");

try {
  const message = await client.messages.create({
    model,
    max_tokens: 128,
    messages: [{ role: "user", content: "Explain what an API is in one sentence." }],
  });
  console.log(message.content);
} finally {
  await tracerProvider.shutdown();
}
```

</CodeGroup>

## View the trace

In Future AGI, open **Observe**, select `anthropic_project`, and open the trace to inspect the model call. Message content depends on the capture controls you configured.

Python spans are named `anthropic.messages.create`. Their input token count already includes cache reads and cache writes, so don't add those counts again.

## Keep AnthropicInstrumentor in Python

Applications that already use `traceAI-anthropic` can keep it, for example to keep its `TraceConfig` and `FI_HIDE_*` controls, the session, user, metadata and tags from context helpers, or its Protect spans. Trace each call with one owner: on Anthropic SDK 1.14.0 and later, create the client with `open_telemetry=False` so that only the instrumentor records its calls.

```python
import anthropic
from traceai_anthropic import AnthropicInstrumentor

AnthropicInstrumentor().instrument(tracer_provider=trace_provider)
client = anthropic.Anthropic(open_telemetry=False)
```

Install it with `pip install traceAI-anthropic anthropic`. SDK versions before 1.14.0 don't accept `open_telemetry`; create the client without it.

## Troubleshooting

- **Two model spans for each request:** both the SDK and `AnthropicInstrumentor` trace the client. Remove the instrumentor, or create the client with `open_telemetry=False`.
- **No Python spans:** check that the client receives `trace_provider` in `open_telemetry`, and that the script calls `trace_provider.shutdown()` before it exits.
- **Missing streaming spans:** read the stream to the end, or close it, before shutting down the provider.
