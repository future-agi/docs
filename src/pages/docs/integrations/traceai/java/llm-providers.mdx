<TLDR>
- Google GenAI, Azure OpenAI, Ollama and Watsonx use `Traced*` wrappers
- The legacy Vertex AI generative SDK requires migration
- Azure OpenAI traces chat completions, embeddings, and legacy completions
- Ollama wraps `ollama4j`, Watsonx uses reflection like Anthropic
</TLDR>

## Prerequisites

Complete the [Java SDK setup](/docs/integrations/traceai/java) first. All providers below need `traceai-java-core` and `TraceAI.init()` called before use.

### Control captured content

The examples use default content capture, which can send prompts, responses, messages, raw request/response data and exception details to Future AGI. To hide standard input, output and message fields, replace `TraceAI.initFromEnvironment()` with:

```java
import ai.traceai.TraceAI;
import ai.traceai.TraceConfig;

TraceAI.init(TraceConfig.builder()
    .hideInputs(true)
    .hideOutputs(true)
    .hideInputMessages(true)
    .hideOutputMessages(true)
    .build());
```

These are separate [Java configuration controls](https://github.com/future-agi/traceAI/blob/dev/java/traceai-java-core/src/main/java/ai/traceai/TraceConfig.java). They do not suppress exception messages or stack traces recorded by `setError`, and are not a filter for every provider-specific attribute. Use non-sensitive sample data if your data policy does not permit those fields.

## Google GenAI

Wraps the `com.google.genai.Client` for Google's Gemini API.

<CodeGroup titles={["Maven", "Gradle"]}>

```xml Maven
<dependency>
    <groupId>com.github.future-agi.traceAI</groupId>
    <artifactId>traceai-java-google-genai</artifactId>
    <version>main-SNAPSHOT</version>
</dependency>
```

```groovy Gradle
implementation 'com.github.future-agi.traceAI:traceai-java-google-genai:main-SNAPSHOT'
```

</CodeGroup>

```java
import ai.traceai.TraceAI;
import ai.traceai.googlegenai.TracedGenerativeModel;
import com.google.genai.Client;

TraceAI.initFromEnvironment();

Client client = Client.builder()
    .apiKey(System.getenv("GOOGLE_API_KEY"))
    .build();

// Note: model name is a constructor parameter
TracedGenerativeModel model = new TracedGenerativeModel(client, "gemini-2.0-flash");

// Simple generation
var response = model.generateContent("What is the capital of France?");
System.out.println(response.text());

// Multi-turn chat
var chat = model.startChat();
var reply = chat.sendMessage("Hello!");
System.out.println(reply.text());

// Token counting
var tokenCount = model.countTokens("How many tokens is this?");
```

**Spans created:**
- `generateContent()` - "Google GenAI Generate Content" (LLM)
- `chat.sendMessage()` - "Google GenAI Chat Message" (LLM)
- `countTokens()` - "Google GenAI Count Tokens" (LLM)

Open your project in Future AGI to inspect the spans.

## Vertex AI

Google removed `com.google.cloud.vertexai.generativeai` from Vertex AI SDK releases after June 24, 2026. For new applications, follow [Google's migration guide to the Google Gen AI SDK](https://cloud.google.com/vertex-ai/generative-ai/docs/deprecations/genai-vertexai-sdk). The legacy `traceai-java-vertexai` wrapper targets that removed package; do not apply it to a `com.google.genai.Client`.

The [Google GenAI example above](#google-genai) uses a Gemini API key. It is not a Vertex AI project/location authentication example.

## Azure OpenAI

Trace synchronous chat completions, embeddings, and legacy text completions from existing applications using `com.azure.ai.openai.OpenAIClient`.

Microsoft [no longer updates this Azure SDK client in its current form](https://github.com/Azure/azure-sdk-for-java/blob/5bf21284d74c27d37110169721e0ef2b6de4bc83/sdk/openai/azure-ai-openai/README.md). For new OpenAI features, follow Microsoft's guidance to the official OpenAI Java SDK. That SDK uses different client types; this wrapper is not a drop-in adapter for it.

### Install the legacy client and wrapper

Use Java 17 or later and add both dependencies from Maven Central. The wrapper declares the Azure SDK as a provided dependency, so your application must include it explicitly.

<CodeGroup titles={["Maven", "Gradle"]}>

```xml Maven
<dependency>
    <groupId>com.futureagi</groupId>
    <artifactId>traceai-java-azure-openai</artifactId>
    <version>1.0.0</version>
</dependency>
<dependency>
    <groupId>com.azure</groupId>
    <artifactId>azure-ai-openai</artifactId>
    <version>1.0.0-beta.16</version>
</dependency>
```

```groovy Gradle
implementation 'com.futureagi:traceai-java-azure-openai:1.0.0'
implementation 'com.azure:azure-ai-openai:1.0.0-beta.16'
```

</CodeGroup>

### Trace a chat completion

Set `AZURE_OPENAI_ENDPOINT` to your Azure resource endpoint, `AZURE_OPENAI_API_KEY` to its API key, and `AZURE_OPENAI_DEPLOYMENT` to your chat deployment name. A deployment name can differ from the underlying model name. Configure your Future AGI credentials using the [Java SDK setup](/docs/integrations/traceai/java).

```java
import ai.traceai.TraceAI;
import ai.traceai.azure.openai.TracedAzureOpenAIClient;
import com.azure.ai.openai.OpenAIClient;
import com.azure.ai.openai.OpenAIClientBuilder;
import com.azure.core.credential.AzureKeyCredential;
import com.azure.ai.openai.models.ChatCompletionsOptions;
import com.azure.ai.openai.models.ChatRequestUserMessage;
import java.util.List;

TraceAI.initFromEnvironment();
try {
    OpenAIClient client = new OpenAIClientBuilder()
        .endpoint(System.getenv("AZURE_OPENAI_ENDPOINT"))
        .credential(new AzureKeyCredential(System.getenv("AZURE_OPENAI_API_KEY")))
        .buildClient();
    TracedAzureOpenAIClient traced = new TracedAzureOpenAIClient(client);

    var options = new ChatCompletionsOptions(List.of(
        new ChatRequestUserMessage("What is the capital of France?")
    ));
    var response = traced.getChatCompletions(
        System.getenv("AZURE_OPENAI_DEPLOYMENT"), options);
    System.out.println(response.getChoices().get(0).getMessage().getContent());
} finally {
    TraceAI.shutdown();
}
```

For a long-running application, initialize TraceAI once and call `TraceAI.shutdown()` when the application exits, not after each request.

Open your project in Future AGI to inspect the **Azure OpenAI Chat Completion** span, its deployment name, response model, messages, and token usage. Content capture follows the controls described above.

### Supported operations

| Wrapper method | Span | Kind |
| --- | --- | --- |
| `getChatCompletions()` | Azure OpenAI Chat Completion | LLM |
| `getEmbeddings()` | Azure OpenAI Embedding | EMBEDDING |
| `getCompletions()` | Azure OpenAI Completion | LLM, legacy text API |

These three methods are blocking calls. Use a deployment appropriate to the operation; an embeddings request needs an embeddings deployment.

Streaming, `OpenAIAsyncClient`, Responses, audio, images, and files are not traced by this wrapper. `unwrap()` returns the original client without this wrapper's instrumentation. Calling a streaming method through `unwrap()` does not create a semantic LLM span, even if separate Azure HTTP tracing is enabled. Keep calls on the wrapper's supported methods when you need these traces; do not switch to `traceai-java-openai` expecting equivalent Azure or streaming behavior.

## Ollama

Wraps `io.github.ollama4j.OllamaAPI` for local Ollama models.

<CodeGroup titles={["Maven", "Gradle"]}>

```xml Maven
<dependency>
    <groupId>com.github.future-agi.traceAI</groupId>
    <artifactId>traceai-java-ollama</artifactId>
    <version>main-SNAPSHOT</version>
</dependency>
```

```groovy Gradle
implementation 'com.github.future-agi.traceAI:traceai-java-ollama:main-SNAPSHOT'
```

</CodeGroup>

```java
import ai.traceai.TraceAI;
import ai.traceai.ollama.TracedOllamaAPI;
import io.github.ollama4j.OllamaAPI;
import io.github.ollama4j.models.chat.OllamaChatMessage;
import io.github.ollama4j.models.chat.OllamaChatMessageRole;
import java.util.List;

TraceAI.initFromEnvironment();

OllamaAPI api = new OllamaAPI("http://localhost:11434");
TracedOllamaAPI traced = new TracedOllamaAPI(api);

// Generate
var result = traced.generate("llama3", "What is the capital of France?");
System.out.println(result.getResponse());

// Chat
var chatResult = traced.chat("llama3", List.of(
    new OllamaChatMessage(OllamaChatMessageRole.USER, "Hello!")
));

// Embeddings
var embedding = traced.embed("llama3", "Hello world");

// List models
var models = traced.listModels();
```

**Spans created:**
- `generate()` - "Ollama Generate" (LLM)
- `chat()` - "Ollama Chat" (LLM)
- `embed()` - "Ollama Embed" (EMBEDDING)
- `listModels()` - "Ollama List Models" (LLM)

Ollama spans include `ollama.response_time_ms` from the Ollama server's own timing.

## IBM Watsonx

Wraps the Watsonx Java SDK using reflection (like Anthropic). Compatibility depends on the methods exposed by the SDK version you use.

<CodeGroup titles={["Maven", "Gradle"]}>

```xml Maven
<dependency>
    <groupId>com.github.future-agi.traceAI</groupId>
    <artifactId>traceai-java-watsonx</artifactId>
    <version>main-SNAPSHOT</version>
</dependency>
```

```groovy Gradle
implementation 'com.github.future-agi.traceAI:traceai-java-watsonx:main-SNAPSHOT'
```

</CodeGroup>

`TracedWatsonxAI` is a wrapper reference, not a standalone Watsonx application. Pass an initialized SDK client to its constructor, then pass that SDK's request objects to `generateText`, `chat` or `embedText`. See the [wrapper source](https://github.com/future-agi/traceAI/blob/dev/java/traceai-java-watsonx/src/main/java/ai/traceai/watsonx/TracedWatsonxAI.java) for the reflected method signatures; request construction depends on your Watsonx SDK.

**Spans created:**
- `generateText()` - "Watsonx Text Generation" (LLM)
- `chat()` - "Watsonx Chat" (LLM)
- `embedText()` - "Watsonx Embed" (EMBEDDING)

Watsonx spans include `watsonx.project_id`, `watsonx.space_id`, and `watsonx.stop_reason`.

Like Anthropic, the reflection approach means the client and request objects are typed as `Object`. Cast the return values to your SDK's response types.

## Common span attributes

Depending on the provider and operation, spans can include these attributes:

| Attribute | Description |
|-----------|-------------|
| `llm.provider` | Wrapper-specific provider label: `google`, `azure`, `ollama` or `ibm` (Watsonx) |
| `llm.request.model` | Model name from the request |
| `llm.response.model` | Model name from the response (if different) |
| `llm.token_count.prompt` | Input token count |
| `llm.token_count.completion` | Output token count |
| `llm.token_count.total` | Total token count |
| `input.value` / `output.value` | Plain text input/output |
| `fi.raw_input` / `fi.raw_output` | Full request/response as JSON |
