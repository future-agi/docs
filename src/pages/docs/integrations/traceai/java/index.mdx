## About

Use the traceAI Java SDK to trace a client call or a custom operation. This example creates a span for a Ridgeline Outfitters order lookup. You can check the masking policy in your console without sending an order to a provider or a collector.

## Installation

Use Java 17 or later. Create a directory with this `pom.xml` to use Java core 1.4.1 from Maven Central:

```xml
<project xmlns="http://maven.apache.org/POM/4.0.0">
  <modelVersion>4.0.0</modelVersion>
  <groupId>example.ridgeline</groupId>
  <artifactId>order-tracing</artifactId>
  <version>1.0</version>
  <properties>
    <maven.compiler.release>17</maven.compiler.release>
  </properties>
  <dependencies>
    <dependency>
      <groupId>com.futureagi</groupId>
      <artifactId>traceai-java-core</artifactId>
      <version>1.4.1</version>
    </dependency>
  </dependencies>
</project>
```

In an existing Gradle project, add `implementation 'com.futureagi:traceai-java-core:1.4.1'` to `dependencies` and enable `mavenCentral()` in `repositories`. For automatic instrumentation of supported client operations, also install the matching [integration](#available-integrations) and its provider SDK.

## Initialization

Save this class as `src/main/java/OrderLookup.java`. It initializes a tracer, records a synthetic lookup with `FITracer` setters, then flushes the span before exit.

```java
import ai.traceai.ContextAttributes;
import ai.traceai.FISpanKind;
import ai.traceai.FITracer;
import ai.traceai.TraceAI;
import ai.traceai.TraceConfig;
import io.opentelemetry.api.trace.Span;

public class OrderLookup {
    public static void main(String[] args) throws Exception {
        TraceAI.init(TraceConfig.builder()
            .projectName("ridgeline-support")
            .enableConsoleExporter(true)
            .hideInputs(true)
            .hideOutputs(true)
            .hideErrorDetails(true)
            .build());
        try (var session = ContextAttributes.usingSession("demo-session")) {
            FITracer tracer = TraceAI.getTracer();
            Span span = tracer.startSpan("order.lookup", FISpanKind.TOOL);
            try {
                tracer.setAttribute(span, "gen_ai.tool.call.arguments.quantity", 2L);
                tracer.setRawInput(span, "Lookup RGL-DEMO-82");
                tracer.setOutputValue(span, "Order found");
            } finally {
                span.end();
            }
        } finally {
            TraceAI.shutdown();
        }
    }
}
```

Run from the directory containing `pom.xml`. Use a clean shell without trace sampling overrides. The subshell unsets the remote exporter configuration for this run only.

```bash
(
  unset FI_BASE_URL FI_API_KEY FI_SECRET_KEY
  mvn compile org.codehaus.mojo:exec-maven-plugin:3.5.0:java -Dexec.mainClass=OrderLookup
)
```

Look for `order.lookup`, `__REDACTED__` in place of the quantity, and no `output.value` or raw order reference. For hosted tracing, configure `FI_BASE_URL`, `FI_API_KEY`, `FI_SECRET_KEY`, and `FI_PROJECT_NAME` in the application environment. Use `TraceAI.initFromEnvironment()` for environment-only configuration. With the builder, an explicit hide setting wins over its environment variable. Call `TraceAI.getTracer()` only after initialization; otherwise it throws `IllegalStateException`.

<Warning>
Content is captured by default. Use `hideInputs(true)` and `hideOutputs(true)` for known content fields, and `hideErrorDetails(true)` for exception text. Direct OpenTelemetry writes and context attributes copied at span creation do not pass through the content setters. Keep customer content out of tags, metadata, and the attribute map passed to `startSpan`. See the [masking matrix](/docs/sdk/tracing/trace-config#match-the-policy-to-your-sdk).
</Warning>

## TraceConfig reference

| Builder method | Type | Default | What it does |
|----------------|------|---------|-------------|
| `baseUrl(String)` | String | `$FI_BASE_URL` | FutureAGI OTLP endpoint |
| `apiKey(String)` | String | `$FI_API_KEY` | API key for authentication |
| `secretKey(String)` | String | `$FI_SECRET_KEY` | Secret key for authentication |
| `projectName(String)` | String | `$FI_PROJECT_NAME` | Project name in FutureAGI dashboard |
| `serviceName(String)` | String | Project name, or `traceai-java-app` if absent | OpenTelemetry `service.name` resource attribute |
| `hideInputs(boolean)` | boolean | `false` | Hide input values, input messages, and known input fields including tool arguments |
| `hideOutputs(boolean)` | boolean | `false` | Hide output values, output messages, and known output fields including tool results |
| `hideInputMessages(boolean)` | boolean | `false` | Hide structured input messages, aggregate input values, template variables, and embedding input text |
| `hideOutputMessages(boolean)` | boolean | `false` | Hide structured output messages and aggregate output values |
| `hideErrorDetails(boolean)` | boolean | `false` | Hide error messages, stack traces, and status descriptions written by `FITracer`; keep error status and type |
| `enableConsoleExporter(boolean)` | boolean | `false` | Print spans to console for debugging |
| `batchSize(int)` | int | `512` | Spans per export batch |
| `exportIntervalMs(long)` | long | `5000` | How often to flush spans (ms) |

With any of the four input, output, or message switches on, `setRawInput` and `setRawOutput` skip both bodies. Known content keys match even if their values are numbers, booleans, or arrays. One exception: a whole-number count on the exact `gen_ai.reranker.input_documents` or `gen_ai.reranker.output_documents` key (or its `reranker.*` alias) is retained. Text and document descendants are still masked under the corresponding switch. Model names and token counts stay available. Use `tracer.setAttribute(span, key, value)` for known content fields rather than writing directly to `span`.

## FITracer methods

`FITracer` is what the Java client wrappers use internally. Use the same helpers for your custom spans so that known content fields follow the configured policy.

| Method | What it does |
|--------|-------------|
| `startSpan(name, kind)` | Creates and starts a new span |
| `startSpan(name, kind, parentContext)` | Creates a child span under a specific parent |
| `setInputValue(span, value)` | Sets `input.value` attribute (respects `hideInputs`) |
| `setOutputValue(span, value)` | Sets `output.value` attribute (respects `hideOutputs`) |
| `setRawInput(span, object)` | Serializes the raw request only when all four content switches are off |
| `setRawOutput(span, object)` | Serializes the raw response only when all four content switches are off |
| `setInputMessages(span, messages)` | Sets structured input messages (role + content) |
| `setOutputMessages(span, messages)` | Sets structured output messages (role + content) |
| `setTokenCounts(span, prompt, completion, total)` | Sets token count attributes |
| `setError(span, throwable)` | Records exception and sets ERROR status |
| `trace(name, kind, supplier)` | Executes operation in a span, returns result |
| `trace(name, kind, runnable)` | Executes void operation in a span |
| `message(role, content)` | Helper to build message maps |

## FISpanKind

Every span has a kind that identifies the type of AI operation:

| Kind | Used for |
|------|----------|
| `LLM` | Chat completions, text generation |
| `EMBEDDING` | Text-to-vector conversions |
| `RETRIEVER` | Vector search, document retrieval |
| `VECTOR_DB` | Vector store writes (upsert, delete) |
| `RERANKER` | Reranking retrieved documents |
| `CHAIN` | Sequential pipeline steps |
| `AGENT` | Autonomous agent operations |
| `TOOL` | LLM tool/function calls |
| `GUARDRAIL` | Safety and validation checks |
| `WORKFLOW` | Custom pipeline steps |
| `EVALUATOR` | Quality scoring |
| `CONVERSATION` | Voice and conversational AI |
| `UNKNOWN` | Unspecified |

## Context attributes

`ContextAttributes.usingSession`, `usingUser`, `usingMetadata`, and `usingTags` attach context to `FITracer` spans on the current thread. Use try-with-resources as in [Initialization](#initialization) to restore the previous context on close. Establish context on the thread that creates the spans: it does not automatically propagate to executor tasks or reactive callbacks.

## Shutdown

With `TraceAI.init(config)`, traceAI owns the provider. It registers a JVM shutdown hook; you can also call `TraceAI.shutdown()` in a short-lived process. It waits up to 10 seconds each for flush and shutdown. If you passed your own OpenTelemetry instance to `TraceAI.init(config, openTelemetry)`, `shutdown()` only detaches the tracer: you still own flushing and closing that provider. Either way you can initialize again and get a new tracer after shutdown.
