## About

Trace calls to Amazon Bedrock Agents made with the AWS SDK for JavaScript v3. This page covers `InvokeAgentCommand` and `InvokeInlineAgentCommand` from `BedrockAgentRuntimeClient`. It does not cover the Bedrock model runtime API or [Bedrock AgentCore Runtime](/docs/integrations/traceai/bedrock-agentcore).

Each invocation creates an AGENT span for the agent call and its streamed completion. Set `enableTrace: true` on the command to receive Bedrock trace events and record child spans for the steps Bedrock reports. Without it, the parent span is still recorded, but the substeps are not.

## Install and configure

<Steps>
  <Step title="Install the packages">

    Use Node.js 20.6 or later. From your application's directory, install the auto-instrumentation preload, Bedrock integration, and Agent Runtime client:

    ```bash
    npm install @traceai/auto@0.4.0 @traceai/bedrock@0.2.1 @aws-sdk/client-bedrock-agent-runtime@^3.693.0
    ```

  </Step>
  <Step title="Set credentials and project settings">

    Set the Future AGI keys and project name in the application environment. Configure AWS credentials using the AWS SDK's normal credential chain, and set the AWS region. The agent ID and alias ID must refer to an agent you can invoke.

    ```bash
    export FI_API_KEY="YOUR_API_KEY"
    export FI_SECRET_KEY="YOUR_SECRET_KEY"
    export FI_PROJECT_NAME="ridgeline-support"
    export AWS_REGION="us-east-1"
    export BEDROCK_AGENT_ID="YOUR_AGENT_ID"
    export BEDROCK_AGENT_ALIAS_ID="YOUR_AGENT_ALIAS_ID"
    ```

    Use your own keys, region, agent ID and alias ID. If you host Future AGI yourself, also set `FI_BASE_URL` to the base URL of your trace collector. Before tracing customer requests, review the [privacy settings](#privacy-limits-and-errors).

  </Step>
  <Step title="Run the example with tracing">

    Save the [example below](#capture-streamed-agent-calls) as `bedrock-agents.mjs`. Run it with the preload so instrumentation starts before the AWS SDK loads:

    ```bash
    node --import @traceai/auto/register bedrock-agents.mjs
    ```

  </Step>
</Steps>

## Capture streamed agent calls

This example sends the same request in two independent Bedrock sessions. The first call leaves `enableTrace` off. The second enables Bedrock trace events. To see tool or retrieval spans, use a test agent with an inventory action group or a return-policy knowledge base. Bedrock determines which steps run for a request.

```javascript title="bedrock-agents.mjs"
import { randomUUID } from "node:crypto";
import {
  BedrockAgentRuntimeClient,
  InvokeAgentCommand,
} from "@aws-sdk/client-bedrock-agent-runtime";

const client = new BedrockAgentRuntimeClient({
  region: process.env.AWS_REGION,
});

for (const enableTrace of [false, true]) {
  const mode = enableTrace ? "traced" : "basic";
  const sessionId = `ridgeline-${mode}-${randomUUID()}`;
  const { completion } = await client.send(
    new InvokeAgentCommand({
      agentId: process.env.BEDROCK_AGENT_ID,
      agentAliasId: process.env.BEDROCK_AGENT_ALIAS_ID,
      sessionId,
      inputText:
        "Can I exchange the Alpine 45L pack for a blue 55L pack? Check the configured inventory and return policy.",
      enableTrace,
    }),
  );

  const decoder = new TextDecoder();
  let answer = "";
  for await (const event of completion) {
    if (event.chunk?.bytes) {
      answer += decoder.decode(event.chunk.bytes, { stream: true });
    }
  }
  answer += decoder.decode();
  console.log(`${sessionId}: ${answer}`);
}
```

The example reads every event in `completion` and prints the assembled answer. It does not add tracing calls to the application. The preload instruments the AWS client and exports the spans under the `ridgeline-support` project.

## Compare the spans

Open the `ridgeline-support` project in Future AGI and compare the calls by their session IDs. Both have an AGENT parent span. The trace-enabled call also has children for trace events the agent emitted; their presence depends on the steps Bedrock reports for that request.

| Bedrock trace event | Span | What the span records |
| --- | --- | --- |
| Model invocation | LLM, named `chat <foundationModel>` or `chat` | Model, prompt and response, and token usage when Bedrock provides it. |
| Action group invocation | TOOL, named `execute_tool <name>` | Tool name, invocation input and output. |
| Code interpreter invocation | TOOL, named `execute_tool code_interpreter` | Code interpreter input and output. |
| Knowledge base lookup | RETRIEVER, named `retrieve <knowledgeBaseId>` or `retrieve` | Lookup input and retrieved documents. |
| Agent collaborator invocation | AGENT, named `invoke_agent <agentCollaboratorName>` or `invoke_agent` | Collaborator input and output. |
| Agent failure | CHAIN with error status, named `agent_failure` | The failure reason and type Bedrock returned. |

The parent span is named `invoke_agent <agentId>/<agentAliasId>`. Calls to `InvokeInlineAgentCommand` use the name `invoke_agent inline` and also record the foundation model as `gen_ai.request.model`. The parent records the operation name `invoke_agent` and the Bedrock session ID. Regular agent calls also include the agent and alias IDs.

The instrumentation observes the stream as your code consumes it. It returns the original events to your application and does not read ahead. The parent span ends when the stream is fully consumed, fails, or is closed before it is fully consumed. Consume or close the stream so tracing can finish the span.

## Privacy, limits, and errors

Input and output content is captured by default. To hide it, set these variables before starting the Node process:

```bash
export FI_HIDE_INPUTS=true
export FI_HIDE_OUTPUTS=true
export FI_HIDE_ERROR_DETAILS=true
```

These settings hide prompts, responses, action group arguments (`input.value`), retrieved document text, and error details in spans. They do not change what your application receives or prints.

- Not every Bedrock trace event creates a span. For example, the integration skips `guardrailTrace` and `customOrchestrationTrace`.
- If `send()` or stream consumption fails, the integration records the error and rethrows it to your application.
- If you stop reading early, break from the `for await...of` loop or close the iterator with `return()`. Closing the stream ends any open child spans. If you neither read nor close it, the completion cannot be observed and the parent span remains open.
