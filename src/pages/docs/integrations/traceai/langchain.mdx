## About

When a support agent quotes a return policy, you can use its trace to see which document it retrieved and check that the same passage reached the model's next call. This guide traces a local LangChain.js v1 graph that pauses for approval, then streams an answer. The Python example traces the same question with a prompt and model call instead of a graph.

## 1. Set credentials

Export your [Future AGI API keys](/docs/admin-settings/api-keys) in the shell where you'll run the example. Set `OPENAI_API_KEY` to an OpenAI key and `OPENAI_MODEL` to a chat model available to that key. For an OpenAI-compatible provider, also set `OPENAI_BASE_URL` to its API base URL and use its key and model ID instead. The JavaScript graph requires streaming and forced tool calling.

```bash
export FI_API_KEY="YOUR_API_KEY"
export FI_SECRET_KEY="YOUR_SECRET_KEY"
export OPENAI_API_KEY="YOUR_MODEL_PROVIDER_KEY"
export OPENAI_MODEL="YOUR_MODEL_ID"
```

Use sample data while inspecting the messages below. By default, a trace can include prompts, tool arguments, returned documents and model replies. See [privacy and stream limits](#privacy-and-stream-limits) before using customer data.

## 3. Trace the return-policy question

For JavaScript, save the graph as `returns.mjs`. Its `approve` node pauses before the first model call. The example supplies approval itself; in your application, resume only after the reviewer responds.

For Python, save the chain as `returns.py`. Call `instrument()` once at startup. It applies to the whole process, so calling it again with a different provider does not switch projects. Run workflows that need separate providers in separate processes.

<CodeGroup titles={["JavaScript", "Python"]}>

```javascript
import { register, ProjectType } from "@traceai/fi-core";
import { LangChainInstrumentation } from "@traceai/langchain";
import { registerInstrumentations } from "@opentelemetry/instrumentation";
import * as callbacks from "@langchain/core/callbacks/manager";
import * as chatModels from "@langchain/core/language_models/chat_models";
import * as runnables from "@langchain/core/runnables";
import { awaitAllCallbacks } from "@langchain/core/callbacks/promises";
import { BaseRetriever } from "@langchain/core/retrievers";
import { HumanMessage } from "@langchain/core/messages";
import { tool } from "@langchain/core/tools";
import { ChatOpenAI } from "@langchain/openai";
import { StateGraph, MessagesAnnotation, MemorySaver, Command, interrupt, START, END } from "@langchain/langgraph";
import { z } from "zod";

const provider = register({ projectName: "ridgeline-langchain-returns", projectType: ProjectType.OBSERVE });
const tracing = new LangChainInstrumentation();
registerInstrumentations({ tracerProvider: provider, instrumentations: [tracing] });
tracing.manuallyInstrument(callbacks, chatModels, runnables);

class PolicyRetriever extends BaseRetriever {
  lc_namespace = ["ridgeline", "retrievers"];
  async _getRelevantDocuments() {
    return [{ pageContent: "Unused packs can be returned within 30 days of delivery.",
              metadata: { source: "returns-handbook", section: "packs" } }];
  }
}
const policies = new PolicyRetriever();
const lookup = tool(async ({ question }) => (await policies.invoke(question))[0].pageContent, {
  name: "lookup_policy", description: "Look up the store's return policy for packs.",
  schema: z.object({ question: z.string() }),
});
const model = new ChatOpenAI({ model: process.env.OPENAI_MODEL });

const graph = new StateGraph(MessagesAnnotation)
  .addNode("approve", () => {
    const approved = interrupt("Look up the pack return policy?");
    return new Command({ goto: approved ? "answer" : END });
  }, { ends: ["answer", END] })
  .addNode("answer", async ({ messages }) => {
    const request = await model.bindTools([lookup], { tool_choice: "lookup_policy" }).invoke(messages);
    const results = [];
    for (const call of request.tool_calls) {
      results.push(await lookup.invoke({ ...call, type: "tool_call" }));
    }
    const stream = await model.stream([...messages, request, ...results]);
    let reply = "";
    for await (const chunk of stream) {
      process.stdout.write(chunk.text);
      reply += chunk.text;
    }
    console.log();
    return { messages: [request, ...results, { role: "assistant", content: reply }] };
  })
  .addEdge(START, "approve").addEdge("answer", END)
  .compile({ checkpointer: new MemorySaver() });

const thread = { configurable: { thread_id: "ridgeline-pack-return" } };
try {
  const paused = await graph.invoke({ messages: [new HumanMessage("Can I return my unused pack after 20 days?")] }, thread);
  console.log(paused.__interrupt__[0].value);
  await graph.invoke(new Command({ resume: true }), thread);
} finally {
  await awaitAllCallbacks();
  await provider.shutdown();
}
```

```python
import os
from fi_instrumentation import register
from fi_instrumentation.fi_types import ProjectType
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI
from traceai_langchain import LangChainInstrumentor

provider = register(project_name="ridgeline-langchain-returns-python", project_type=ProjectType.OBSERVE, verbose=False)
LangChainInstrumentor().instrument(tracer_provider=provider)
try:
    prompt = ChatPromptTemplate.from_template("Use this policy: {policy}\nCustomer: {question}")
    chain = prompt | ChatOpenAI(model=os.environ["OPENAI_MODEL"])
    print(chain.invoke({
        "policy": "Unused packs can be returned within 30 days of delivery.",
        "question": "Can I return my unused pack after 20 days?",
    }).content)
finally:
    provider.shutdown()
```

</CodeGroup>

**Python**: Run `python returns.py`. It prints an answer about the 30-day return window. In the **Observe** section, open **Tracing** and select `ridgeline-langchain-returns-python` to inspect the prompt and model spans.

**JavaScript**: Run `node returns.mjs`. You should see the approval question, then an answer explaining that 20 days falls within the 30-day return window. The checkpointer and the same `thread_id` let the second invocation continue the first. `MemorySaver` keeps the checkpoint only in this process.

Notice that `lookup.invoke()` receives the whole tool call, not just `call.args`. LangChain uses its ID to construct the tool result message. Passing that message to the final model call gives you a link you can follow in the trace.

## 4. Inspect the JavaScript traces

In the **Observe** section, open **Tracing**, select `ridgeline-langchain-returns` and open the trace for each invocation. Start with the earlier run to see why the graph stopped; open the resumed run to see which policy the model received.

{/* MEDIA: Tracing project with the two graph invocations listed in time order. */}

| Select this span | What to look for |
|---|---|
| `approve` in the first run | `langgraph.interrupt=true` and an `interrupt` event on the **Events** tab. The pause ends with `OK`, not `ERROR`. The event does not record the interrupt payload. |
| First chat model in `answer` | In `gen_ai.output.messages`, find the assistant's `tool_calls` entry. Note its `id`, `function.name` (`lookup_policy`) and JSON-encoded `function.arguments`. |
| `lookup_policy` and its retriever | The tool returns the policy text. On the retriever span, `retrieval.documents.0.document.content` contains the passage and `retrieval.documents.0.document.metadata` identifies `returns-handbook`. |
| Second chat model in `answer` | In `gen_ai.input.messages`, find the message with `role: "tool"`. Its `tool_call_id` matches the first model's `tool_calls` ID. This is the ID to compare, not the tool span's OpenTelemetry span ID. |
| Streamed model reply | `gen_ai.response.time_to_first_token` measures seconds from model run start to the first observed token or chunk. It is absent if none was observed. |

{/* MEDIA: Two traces for ridgeline-langchain-returns, with the paused approve span in Events and the resumed model spans expanded to show the matching tool call and result IDs. */}

A subgraph that hands control to its parent with `Command.PARENT` also finishes without an error, but it has no interrupt marker. A node that throws an ordinary exception still produces an `ERROR` span.

## Privacy and stream limits

- **Sensitive content**: Set `FI_HIDE_INPUTS=true` and `FI_HIDE_OUTPUTS=true` before initialization to hide inputs and outputs, including retrieved document content and metadata. Hiding the output alone does not hide a tool result repeated in the *next model's input*. Use `FI_HIDE_ERROR_DETAILS=true` for error details, and keep secrets out of custom attributes. See [TraceConfig](/docs/sdk/tracing/trace-config).
- **Closing streams**: In ESM, pass all three modules to `manuallyInstrument()`. The callback manager covers ordinary runs; the other modules also catch early closure of model and composed runnable streams. Consume streams to completion or explicitly close them. A cancelled stream ends with `ERROR` and `langchain.stream.cancelled=true`, not a successful partial answer. An abandoned iterator without a close or abort signal has no observable end.
- **Missing final spans**: LangChain.js can dispatch callbacks in the background. Await `awaitAllCallbacks()` before flushing or shutting down. In a server, keep the provider running between requests and shut it down when the service stops.
