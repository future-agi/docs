## About

`traceAI-discoveryengine` wraps the official [`google-cloud-discoveryengine`](https://pypi.org/project/google-cloud-discoveryengine/) Python client (Google Discovery Engine, sold as Vertex AI Search) so every `search`, `search_lite` and `answer_query` call becomes a `RETRIEVER` span in Future AGI.

The client does not trace itself. At `google-cloud-discoveryengine` 0.20.5 an uninstrumented call emits no span, even with `GOOGLE_SDK_EXPERIMENTAL_PYTHON_TRACING_ENABLED=true`, and a gRPC instrumentation you add yourself only creates transport spans without the query, result count or retriever kind. The package fills that gap with one span per call.

The package is Alpha. It is released from [future-agi/traceAI](https://github.com/future-agi/traceAI) (`python/frameworks/discoveryengine`).

## 1. Installation

```bash
pip install traceAI-discoveryengine
```

Tested with `google-cloud-discoveryengine` 0.20.5 (still the latest release on PyPI on 2026-10-18), against the live API on Python 3.12 and in the test suite on Python 3.10, 3.11, 3.12 and 3.13. The package accepts `google-cloud-discoveryengine>=0.20.5,<1`; outside that range `instrument()` logs an error and wraps nothing.

## 2. Set environment variables

```python
import os

os.environ["FI_API_KEY"] = "your-futureagi-api-key"
os.environ["FI_SECRET_KEY"] = "your-futureagi-secret-key"
```

Google credentials stay where the Google client already reads them: Application Default Credentials (`gcloud auth application-default login` or `GOOGLE_APPLICATION_CREDENTIALS`), credentials you pass to the client, or `client_options={"api_key": ...}` for `search_lite` (public website search only). The package never reads ADC and never records a credential.

The Future AGI project (`project_name` below) is not your GCP project. The GCP project only appears inside resource names such as the serving config.

## 3. Register and instrument

```python
from fi_instrumentation import register
from fi_instrumentation.fi_types import ProjectType
from google.cloud import discoveryengine_v1 as discoveryengine
from traceai_discoveryengine import DiscoveryEngineInstrumentor

trace_provider = register(
    project_type=ProjectType.OBSERVE,
    project_name="support-search",
)
DiscoveryEngineInstrumentor().instrument(tracer_provider=trace_provider)

serving_config = (
    "projects/my-gcp-project/locations/global/collections/default_collection/"
    "engines/my-engine/servingConfigs/default_search"
)
search = discoveryengine.SearchServiceClient()  # Application Default Credentials
pager = search.search(request={"serving_config": serving_config, "query": "rotate an API key"})

answers = discoveryengine.ConversationalSearchServiceClient()
answers.answer_query(
    request={"serving_config": serving_config, "query": {"text": "How do I rotate an API key?"}}
)
```

Import the clients from `google.cloud.discoveryengine_v1`. **`from google.cloud import discoveryengine` produces no spans**: at 0.20.5 that unversioned module re-exports the v1beta clients, which are not traced.

An engine in a multi-region location needs its regional endpoint, for example `client_options={"api_endpoint": "eu-discoveryengine.googleapis.com"}`. The gRPC (default), gRPC asyncio and REST (`transport="rest"`) transports are traced the same way.

What the server accepts depends on your app, not on this package. `search_lite` serves public website search with an API key; against any other data store Discovery Engine answers `FAILED_PRECONDITION` ("API key is only supported for public website search."). `answer_query` needs an app with the Large Language Model add-on (Enterprise edition); a Standard edition app answers `FAILED_PRECONDITION` ("This feature is only available when Large Language Model add-on is enabled."). Both show up as `ERROR` spans with `discoveryengine.error.status` = `FAILED_PRECONDITION`.

Call `register()` first so the instrumentor has a tracer provider. Under an active span (an agent or a RAG pipeline step) the Discovery Engine span is its child, so a retrieval followed by an LLM call shows as one trace.

## What is captured

| Call | Span name | Span kind |
|---|---|---|
| `SearchServiceClient.search`, `SearchServiceAsyncClient.search` | `discoveryengine.search` | `RETRIEVER` |
| `SearchServiceClient.search_lite`, `SearchServiceAsyncClient.search_lite` | `discoveryengine.search_lite` | `RETRIEVER` |
| `ConversationalSearchServiceClient.answer_query`, `ConversationalSearchServiceAsyncClient.answer_query` | `discoveryengine.answer_query` | `RETRIEVER` |

| Attribute | Value |
|---|---|
| `gen_ai.retrieval.query`, `input.value` | The query (`SearchRequest.query` or `AnswerQueryRequest.query.text`), credentials removed, cut to 1 KB. Shown as **Query** in the span view. |
| `discoveryengine.serving_config` | The serving config resource name from the request. |
| `discoveryengine.result_count` | Results on the returned (first) page for search; number of `references` for answers. |
| `discoveryengine.answer.length`, `discoveryengine.answer.state` | Length of the answer text in characters, and the answer state (`SUCCEEDED`, `FAILED` ...). |
| `discoveryengine.session` | The Discovery Engine session resource name, from the request and then the response. |
| `discoveryengine.error.status`, `discoveryengine.error.code` | On failure: the status name (`PERMISSION_DENIED`) and code (`403`). |

Iterating a search pager past the first page adds no span: later pages are fetched by the pager, and `result_count` counts the first page only.

An error raised by the client (`PermissionDenied`, `InvalidArgument`, `ServiceUnavailable`, `Forbidden` on REST, or `RetryError`) ends the span with status `ERROR` and a message such as `PermissionDenied: 403 ...`; your code still receives the exception unchanged. An answer returned with state `FAILED` is marked `ERROR` (`answer state FAILED`) without an exception.

Not captured: search results (titles, snippets, documents, summaries), answer text, citations and reference content, request metadata, model name, token counts and cost. The answer response carries no model field, and Discovery Engine is billed in GCP rather than per token. Google credentials, stack traces and local file paths are never exported.

Not traced: conversation and session CRUD (`create_conversation`, `converse_conversation` ...), `stream_answer_query`, document ingestion and data store or engine administration, and the v1beta and v1alpha clients.

## Privacy

traceAI instrumentors follow the standard `TraceConfig`: the query is recorded by default. To turn it off, set `FI_HIDE_INPUTS=true` or pass a config:

```python
from fi_instrumentation import TraceConfig

DiscoveryEngineInstrumentor().instrument(
    tracer_provider=trace_provider, config=TraceConfig(hide_inputs=True)
)
```

With hidden inputs, `input.value` is `__REDACTED__`, `gen_ai.retrieval.query` is dropped, and the query is removed from server error text too (verbatim and in the escaped copies the Google client libraries write). Counts, the state and resource names stay. `FI_PII_REDACTION=true` replaces emails, phone numbers and similar patterns in every recorded text; it also matches the last ten digits of a numeric GCP project number in a resource name. `using_session`, `using_user`, `using_metadata` and `using_tags` apply.

### Live vendor verification (2026-10-18)

The package was run as this page describes against the real `discoveryengine.googleapis.com` (v1, `global`), exporting to a local Future AGI deployment. The app was the smallest Standard edition setup: one unstructured data store with three short inline documents and one generic search engine without the LLM add-on, deleted after the run. The only change from the code above: ADC was not set up on the test machine, so each client got `credentials=google.oauth2.credentials.Credentials(token=..., quota_project_id=...)`.

| Call | Transport | Result from Google | Span in Future AGI |
|---|---|---|---|
| `search` | gRPC, REST, gRPC asyncio | 2 results | `OK`, `discoveryengine.result_count` = 2, query, serving config |
| `search` on a serving config that does not exist | gRPC, REST | `NotFound` 404 | `ERROR`, `NOT_FOUND` / 404 |
| `search_lite` with OAuth credentials | gRPC | `FailedPrecondition` 400 | `ERROR`, `FAILED_PRECONDITION` / 400 |
| `answer_query` on the Standard edition app | gRPC and REST | `FailedPrecondition` 400 (`BadRequest` on REST) | `ERROR`, `FAILED_PRECONDITION` / 400 |

The RAG trace (agent span, three Discovery Engine spans, then an LLM call that used the returned snippets) as stored, trace `276682b6-0d8f-43de-bf3a-ab48b507cf22`:

```text
- [agent] orbit-support-agent
  - [retriever] discoveryengine.search
  - [retriever] discoveryengine.search_lite  status=ERROR: FailedPrecondition: 400 API key is only supported for public website search.
  - [retriever] discoveryengine.answer_query status=ERROR: FailedPrecondition: 400 This feature is only available when Large Language Model add-on is enabled.
  - [llm] ChatCompletion model=gpt-5.6-terra tokens=453/31
```

Privacy was checked in every stored column. With the defaults the query was on each Discovery Engine span; with `FI_HIDE_INPUTS=true` it was in no column (`input.value` = `__REDACTED__`, no `gen_ai.retrieval.query`). In both modes the Discovery Engine spans held no result content, and nothing stored contained a credential, an access token, a local path, a user name, a host name or a stack trace.

Not verified against Google yet, only against local stand-ins of the documented API: a successful `search_lite` (needs a public website data store and an API key), a successful `answer_query` with its answer state, length and session (needs the LLM add-on), pagination, a regional endpoint, the async REST transport, and removing a hidden query from a server error that quotes it (the real errors seen did not quote the query).

## Troubleshooting

- **No spans appear.** Import the clients from `google.cloud.discoveryengine_v1` (not `google.cloud.discoveryengine`), call `instrument()` before the first call, and check `FI_API_KEY` and `FI_SECRET_KEY`.
- **`instrument()` logs a version error.** The installed `google-cloud-discoveryengine` is outside `>=0.20.5,<1`; upgrade it.
- **Only gRPC transport spans, no query.** Those come from a gRPC instrumentation, not from this package. Install and instrument `traceAI-discoveryengine`; the gRPC spans then nest under its spans.
- **`FailedPrecondition` on `answer_query`: "This feature is only available when Large Language Model add-on is enabled."** The app is Standard edition. Enable the LLM add-on (Enterprise edition) or use `search`.
- **`FailedPrecondition` on `search_lite`: "API key is only supported for public website search."** `search_lite` only serves public website data stores with an API key. Use `search` with OAuth or service account credentials for other data stores.
- **`NotFound`: "We were unable to find an engine to service the request."** The engine ID in the serving config is wrong, or the engine was created moments ago. Check the resource name and the location.
- **`search` returns no results right after you add documents.** Indexing takes a few minutes (about six in our test for three small documents), and `search` returns an empty page until then.
- **`PermissionDenied` or `Forbidden` on every call.** That is the GCP side: check the credentials, the serving config name and the regional endpoint. The span records the status and code, not the credential.
- **Duplicate spans.** Do not combine this package with another instrumentor that wraps the same client methods.

## Limitations

- Python only; the Java and Node clients are not traced.
- Only v1 clients. `stream_answer_query` and `converse_conversation` are not traced.
- Query removal from error text matches the verbatim query and the escaped copies the client libraries write; a reworded or truncated server copy is not matched, and other request fields a server error may quote (a `filter`, `user_pseudo_id`) are not removed.
- The async REST transport is not exercised by the tests.

## Difference from related integrations

- [Google GenAI](/docs/integrations/traceai/google_genai) and [Vertex AI](/docs/integrations/traceai/vertexai) trace Gemini model calls (`LLM` spans with model and tokens). `traceAI-discoveryengine` traces the search and grounded-answer calls of Vertex AI Search (`RETRIEVER` spans); it does not instrument `google.genai`, and the two can be used together in one RAG trace.
- A gRPC OpenTelemetry instrumentation records the transport call only. This package adds the retrieval span with the query, serving config, result count and error status.
