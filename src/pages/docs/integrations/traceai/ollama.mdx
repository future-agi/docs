## About

You can run inference locally with Ollama while sending traces to Future AGI. A localhost address does not identify the model server, so label your Ollama client explicitly if you want to find its spans by provider.

## Prepare the model and collector

Start your Ollama server and pull the model on the machine where it runs. Use Python 3.10 to 3.13 for this example.

```bash
ollama pull llama3.2:1b
python -m pip install 'traceAI-openai==0.1.16' 'fi-instrumentation-otel==1.5.1' 'openai==3.57.0'
export FI_API_KEY="YOUR_FUTURE_AGI_API_KEY"
export FI_SECRET_KEY="YOUR_FUTURE_AGI_SECRET_KEY"
```

The model client below connects to `http://localhost:11434/v1`. Keep the Future AGI key pair separate: it authenticates trace export, not local inference. If you self-host Future AGI, also set `FI_BASE_URL` to your trace collector origin.

## Trace a return-policy question

Save this as `returns.py` and run `python returns.py`:

```python
from fi_instrumentation import register
from fi_instrumentation.fi_types import ProjectType
from openai import OpenAI
from traceai_openai import OpenAIInstrumentor, set_client_provider

provider = register(project_type=ProjectType.OBSERVE, project_name="ridgeline-returns")
OpenAIInstrumentor().instrument(tracer_provider=provider)
try:
    with OpenAI(base_url="http://localhost:11434/v1", api_key="unused-local-key") as client:
        set_client_provider(client, provider="ollama")
        result = client.chat.completions.create(
            model="llama3.2:1b",
            messages=[{"role": "user", "content": "Ridgeline Outfitters accepts unused packs within 30 days. Can I return an unused pack on day 12?"}],
        )
        print(result.choices[0].message.content)
finally:
    provider.force_flush()
    provider.shutdown()
```

Open **Observe**, choose `ridgeline-returns`, and inspect the `ChatCompletion` span. Check `gen_ai.provider.name=ollama` and the model ID. The local Ollama server ignores the placeholder SDK key. Use a placeholder distinct from the provider label: a value that matches a credential can be redacted in telemetry. The provider override stays on this client; it is not a credential and is not sent to Ollama.

## Limits and troubleshooting

- **Connection refused or model unavailable:** Check the local server address and pulled model first. Sending spans to another collector will not repair local inference.
- **An answer, but no trace:** Check the Future AGI key pair, collector destination and shutdown. By default, trace content can leave the machine even when inference does not. Review [attribute masking](/docs/sdk/tracing/mask-span-attributes) before sending customer data.
- **Provider says `openai`:** Unlabeled loopback clients keep the fallback. Set the override before the call, including on new clients returned by `copy()` or `with_options()`. Use `set_client_provider(client, provider=None)` to restore host detection. The hosted `https://ollama.com/v1` is identified automatically.
- **Using the native Ollama Python SDK:** Use `traceai-ollama` for that client. The example above instruments `openai.OpenAI`, not native `ollama` calls.
