## About

This page is for **EverOS from EverMind AI** (repository `EverMind-AI/EverOS`, PyPI package `everos`). It is not EverMemOS Cloud or its `evermemos-mcp` connector, and it is not the legacy Claude Code plugin.

EverOS has exported its own OpenTelemetry spans since 1.2.0. They are off by default. There is no `traceAI-everos` package and nothing to instrument: you switch EverOS's export on and point it at Future AGI.

| | |
|---|---|
| Tested versions | `everos` 1.4.2 (latest on PyPI, 2026-10-16) and 1.4.1, Python 3.12 and 3.13, OpenTelemetry 1.45.0 |
| Not tested | 1.2.0 to 1.3.x (the floor for native tracing is 1.2.0), the `/api/v1` alias, library use without the server |
| Status | Alpha. Spans arrive and are stored, but every EverOS span has the kind `unknown` today (see [Limitations](#limitations)) |

## 1. Installation

```bash
pip install 'everos[otel]==1.4.2'
everos init   # creates ~/.everos/everos.toml; add your [llm] and [embedding] keys there as usual
```

EverOS needs Python 3.12 or newer. Without the `otel` extra nothing is exported.

## 2. Configure the export

Set EverOS's own `[observability]` settings as environment variables (or in `~/.everos/everos.toml`; environment variables win):

```bash
export FI_API_KEY="YOUR_FI_API_KEY"
export FI_SECRET_KEY="YOUR_FI_SECRET_KEY"

export EVEROS_OBSERVABILITY__ENABLED=true
export EVEROS_OBSERVABILITY__ENDPOINT="https://api.futureagi.com/tracer/v1/traces"
export EVEROS_OBSERVABILITY__HEADERS="$(python -c 'import json, os; print(json.dumps({"X-Api-Key": os.environ["FI_API_KEY"], "X-Secret-Key": os.environ["FI_SECRET_KEY"]}))')"
export OTEL_RESOURCE_ATTRIBUTES="project_name=my-everos-app,project_type=observe"
```

Three details matter:

- **The endpoint needs its full path.** EverOS uses the value as given. An endpoint with no path posts to `/` and Future AGI answers 404, so nothing is stored.
- **The project comes from `OTEL_RESOURCE_ATTRIBUTES`.** EverOS has no setting for resource attributes, and Future AGI rejects a batch without `project_name` (HTTP 400).
- **Leave the `langfuse_*` settings unset.** Setting all three makes EverOS add a Langfuse `Authorization` header and push scores to Langfuse.

The same keys in `everos.toml`:

```toml
[observability]
enabled = true
endpoint = "https://api.futureagi.com/tracer/v1/traces"
capture_content = false

[observability.headers]
X-Api-Key = "YOUR_FI_API_KEY"
X-Secret-Key = "YOUR_FI_SECRET_KEY"
```

## 3. Run EverOS as usual

```bash
everos server start
```

Then use it normally, for example:

```bash
curl -X POST http://127.0.0.1:8000/api/v2/memory/add -H 'Content-Type: application/json' \
  -d '{"session_id":"s1","messages":[{"sender_id":"user-ada","role":"user","timestamp":1790000000000,"content":"I work on Lighthouse."}]}'
curl -X POST http://127.0.0.1:8000/api/v2/memory/flush -H 'Content-Type: application/json' -d '{"session_id":"s1"}'
curl -X POST http://127.0.0.1:8000/api/v2/memory/search -H 'Content-Type: application/json' \
  -d '{"user_id":"user-ada","query":"What does Ada work on?","method":"hybrid"}'
```

Spans leave in batches and when the server shuts down cleanly, so stop it with Ctrl+C before looking for the last request. If you use EverOS as a library without the server, call `init_tracing(load_settings().observability)` (from `everos.core.observability.tracing` and `everos.config`) before the first memory call and `shutdown_tracing()` at exit. That path is not tested.

## What is captured

One trace per API call; children are the pipeline stages. From a real run of 1.4.2 against a local Future AGI:

| Trace | Spans |
|---|---|
| `add` | `everos.memory.add` > `everos.memcell.boundary` |
| `flush` | `everos.memory.flush` > `everos.memcell.boundary`, `everos.extract`, `everos.persist.markdown`, `everos.ome.extract_agent_case`, `everos.ome.extract_atomic_facts`, `everos.ome.trigger_profile_clustering` > (`everos.embedding`, `everos.ome.extract_user_profile`) |
| `search` | `everos.memory.search` > `everos.search.recall` > `everos.embedding`; `everos.search.rank` |

- **Model and tokens** are filled on the spans where EverOS records an LLM or embedding call (`everos.memcell.boundary`, `everos.extract`, `everos.embedding`, and the agent span `everos.ome.extract_atomic_facts`). Embedding spans carry input tokens only when the embedding API reports usage. EverOS sets no provider name, so the provider column stays empty.
- **Errors** appear as ERROR spans. A search whose embedding call was rejected stored `everos.embedding`, `everos.search.recall` and `everos.memory.search` with status ERROR.
- **Background spans** (`everos.ome.*`) depend on timing and on the conversation; not every run shows all of them.
- **Cost** is not exported by EverOS. Future AGI may price the tokens itself when it knows the model.

## Privacy

Content capture is **off by default** (`capture_content = false`, or `EVEROS_OBSERVABILITY__CAPTURE_CONTENT`). In a run where nothing failed, with it off, a unique marker in the message text and the search query was found in no stored column.

- **Opt in:** set `EVEROS_OBSERVABILITY__CAPTURE_CONTENT=true`. EverOS then adds the query and returned memory ids (`everos.memory.search`), and the extracted episode text (`everos.extract`). In the real run the marker appeared in exactly those two spans' attributes. Values are cut at 4096 characters. EverOS's redaction hook does nothing unless your code calls `set_redactor`.
- **Exported in both settings:** session, user, owner, app, project, memcell, request and run ids; model names; the search's top score.
- **Error text is not covered by the switch.** When an exception leaves an EverOS span, OpenTelemetry records the message as the ERROR status description and an `exception` event with the stack trace, whatever `capture_content` says. Embedding and model providers often quote the rejected input in their error body, so an error can export your query or messages. If that is not acceptable, keep tracing off.
- Your Future AGI keys travel only as request headers; the model API key is never exported.

## Troubleshooting

- **Nothing arrives.** Check that `everos[otel]` is installed (not just `everos`), `EVEROS_OBSERVABILITY__ENABLED=true`, and the server was stopped cleanly so the last batch flushed.
- **404 from the collector.** The endpoint has no `/tracer/v1/traces` path.
- **400 from the collector.** `OTEL_RESOURCE_ATTRIBUTES` does not include `project_name=...`.
- **401 from the collector.** Wrong `X-Api-Key` or `X-Secret-Key`; check the JSON in `EVEROS_OBSERVABILITY__HEADERS`.
- **Header values with `,` or `=`.** The JSON form needs no encoding. If you use OpenTelemetry's `OTEL_EXPORTER_OTLP_HEADERS` instead, percent-encode them.
- **First `add` fails offline.** EverOS's tokenizer downloads `o200k_base` from `openaipublic.blob.core.windows.net` unless it is cached.
- **You followed an EverMemOS Cloud dashboard.** That product is not this page.

## Limitations

- Every EverOS span is stored with kind `unknown`: Future AGI reads `fi.span.kind` and similar keys, which EverOS does not set. EverOS types its spans in `langfuse.observation.type`, which is not mapped for spans ingested this way. Kind mapping is a follow-up in the shared span-kind work, not something this recipe delivers.
- Input and Output columns are empty, even with capture on: EverOS writes content to `langfuse.observation.input` and `.output`, which appear only as raw span attributes.
- Sessions and Users views do not group EverOS data: EverOS writes `langfuse.session.id` and `langfuse.user.id`, not `session.id` and `user.id`.
- The `/api/v1` alias, `sample_rate`, `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` and EverOS without the server were not exercised against Future AGI.

## How this differs from related integrations

- **traceAI instrumentors** (for example OpenAI or LangChain) wrap a client library and set Future AGI span kinds and content attributes. EverOS needs no wrapper: it emits its own spans, so its privacy switch, span names and attributes are EverOS's, not `FI_HIDE_*`.
- **EverMemOS Cloud** is a hosted product with its own tooling and is not covered here.
- **MCP** (`traceAI-mcp`) traces the Model Context Protocol; if you connect an MCP client to EverOS, that is a separate trace source.
