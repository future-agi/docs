title: "Firecrawl Integration with Future AGI Tracing"

`traceAI-firecrawl` instruments the Firecrawl **v2** Python client. Each `scrape`, `search`, `map`, `crawl`, `start_crawl`, `get_crawl_status` and `cancel_crawl` call becomes one span, sync or async.

<Note>
**Status: beta, not yet on PyPI.** The package is in [traceAI PR #206](https://github.com/future-agi/traceAI/pull/206) (`python/frameworks/firecrawl`). Until it is released, install it from that source tree. Tested against a local stand-in of the Firecrawl v2 HTTP API; no live call to `api.firecrawl.dev` has been made.
</Note>

## v1, v2 and OpenLIT

`firecrawl-py` 4.x ships two clients. This package wraps the v2 client (`from firecrawl import Firecrawl`, `AsyncFirecrawl`). It does not wrap the feature-frozen v1 `FirecrawlApp`. OpenLIT's `FireCrawlInstrumentor` wraps `FirecrawlApp.scrape_url` (v1). If you build both clients and enable both instrumentors you get two spans for different calls; pick the one that matches your client.

## 1. Install

```bash
pip install firecrawl-py fi-instrumentation-otel
pip install ./python/frameworks/firecrawl   # from a traceAI checkout, until published
```

Supported: `firecrawl-py >=4.46.2,<5`, Python 3.10 to 3.13.

## 2. Configure

```bash
export FI_API_KEY="your-futureagi-api-key"
export FI_SECRET_KEY="your-futureagi-secret-key"
```

## 3. Instrument

Call `instrument()` **before** constructing the client.

```python
from firecrawl import Firecrawl
from fi_instrumentation import register
from fi_instrumentation.fi_types import ProjectType
from traceai_firecrawl import FirecrawlInstrumentor

tracer_provider = register(project_name="firecrawl", project_type=ProjectType.OBSERVE)
FirecrawlInstrumentor().instrument(tracer_provider=tracer_provider)

client = Firecrawl(api_key="your-firecrawl-api-key")
client.scrape("https://example.com")
```

Put the calls inside your own agent or chain span and they show up as its children.

## What is captured

| Method | Span | Kind | Attributes |
|---|---|---|---|
| `scrape`, `map` | `firecrawl.scrape`, `firecrawl.map` | TOOL | `server.address` (host of the target URL only) |
| `search` | `firecrawl.search` | RETRIEVER | `gen_ai.retrieval.query`, `input.value`, `firecrawl.result_count` |
| `crawl` (blocking) | `firecrawl.crawl` | TOOL | one span for the whole crawl, plus `firecrawl.job_id`, `firecrawl.limit`, `firecrawl.page_count`, `firecrawl.status` |
| `start_crawl`, `get_crawl_status`, `cancel_crawl` | `firecrawl.<method>` | TOOL | `firecrawl.job_id` (shared across the job) |

A blocking `crawl()` that fetches many pages is one span, not one per page. A crawl job that returns status `failed` or `cancelled` ends the span ERROR. SDK exceptions end the span ERROR with a safe event that carries only the exception type; the original exception is re-raised unchanged.

## Privacy

- Captured by default: the **search query** (API key redacted, capped at 1024 characters) and the target host.
- Never captured: page content (markdown, HTML, screenshots), URL paths and query strings, JSON-format prompts or schemas, the Firecrawl API key, raw exception text and tracebacks.
- Turn the query off with the standard traceAI switches: `FI_HIDE_INPUTS=true`, or `TraceConfig(hide_inputs=True)` passed as `instrument(config=...)`. Shared PII redaction (`FI_PII_REDACTION=true`) applies to the query when enabled.

## Troubleshooting

- **No spans:** the client was constructed before `instrument()`. Construct it afterwards. Outside the supported version range `instrument()` logs an error and wraps nothing.
- **Duplicate spans:** both this package and OpenLIT's Firecrawl instrumentor are enabled for the same client; enable one.
- **`firecrawl.credits_used` is `0` on crawls:** the SDK fills `0` when the API omits it, so `0` can mean "not reported".

## Limitations

- Facades constructed before `instrument()` are not traced; facades built while instrumented keep tracing until you build a new one after `uninstrument()`.
- `Firecrawl.watcher()` polls from its own thread, so each poll is a separate root span.
- Format metadata (`firecrawl.formats`) is not recorded when `scrape_options["formats"]` is a raw nested dict; use the typed `ScrapeOptions` / `ScrapeFormats`.
- No `agent`, `interact`, `parse` or browser-session spans.
