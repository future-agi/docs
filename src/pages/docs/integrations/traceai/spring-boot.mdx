## About

Before you add traceAI wrappers to a Spring AI application, check the compatibility limitation below.

<Warning>
The M4-based traceAI wrapper was compiled against Spring AI `1.0.0-M4`. This is a compilation target, not a tested support range. The M4-based wrapper is not a supported integration path for Spring AI `1.1.x`: a `NoSuchMethodError` involving `Message.getContent()` has been reported.

Do not use the historical M4 installation examples as a Spring AI 1.1 setup. This page does not yet provide a verified replacement artifact coordinate.
</Warning>

## Use native Spring observability meanwhile

For a Spring AI 1.1 application, follow the official [Spring AI 1.1 observability guide](https://docs.spring.io/spring-ai/reference/1.1/observability/index.html). For a Spring Boot 3.5 application, use the matching [Spring Boot tracing guide](https://docs.spring.io/spring-boot/3.5/reference/actuator/tracing.html) for OpenTelemetry and OTLP configuration.

Keep your working native observability configuration rather than adding the M4-based traceAI wrapper. Native observations are an interim tracing path, not a guarantee of identical traceAI attributes, token counts or cost fields across providers. Do not enable sensitive prompt or completion logging just to work around this compatibility issue.

## Check compatibility before installing

The previous M4 dependency blocks, provider table and wrapper examples have been removed from this page until a replacement installation can be verified. This is not a recommendation to downgrade Spring AI.

A source version pin does not establish runtime compatibility. Use only an artifact coordinate and exact Java, Spring AI and Spring Boot combination that have been verified together. No compatibility claim for Spring AI 1.0 GA, Spring AI 2.0 or later releases follows from the historical M4 compilation target.
