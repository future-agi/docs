## About

AG2 Classic is the `autogen` distribution at 0.14.x, imported as `autogen`, with the `ConversableAgent` API. It ships its own OpenTelemetry module, `autogen.opentelemetry`. `traceAI-ag2-classic` switches that module on against your Future AGI tracer provider and maps its span attributes to Future AGI conventions (span kinds, tokens, cost, session). Alpha.

### Which AutoGen are you on?

The AutoGen family has several packages that look alike. Check what you installed.

| You installed | You import | Use |
|---|---|---|
| `autogen` 0.14.x | `autogen` | This page (`traceAI-ag2-classic`) |
| `ag2` 1.x | `ag2` | The AG2 1.x integration (`traceAI-ag2`) |
| `autogen-agentchat` | `autogen_agentchat` (Microsoft AutoGen) | [AutoGen](/docs/integrations/traceai/autogen) (`traceAI-autogen`) |
| `pyautogen` | older alias | Not supported |

`setup()` raises `AG2ClassicCompatibilityError`, naming the right package, when it finds one of the other layouts.

Supported range is `autogen>=0.14.0,<0.15`. The upstream repository (`ag2ai/ag2classic`) has had no commit since 2026-07-08, so there is no nightly-latest check; if Classic is formally retired the package becomes maintenance-only.

## 1. Installation

```bash
pip install traceAI-ag2-classic "autogen[openai]"
```

Plain `autogen` installs no model client. The `openai` extra adds the OpenAI client; use `"autogen[anthropic]"` or `"autogen[gemini]"` for other providers. `autogen[tracing]` also works; this package never creates the gRPC exporter that extra installs.

## 2. Set environment variables

```bash
export FI_API_KEY="YOUR_API_KEY"
export FI_SECRET_KEY="YOUR_SECRET_KEY"
export OPENAI_API_KEY="YOUR_OPENAI_API_KEY"
```

## 3. Register the tracer provider and enable tracing

Call `setup()` after `register()` and pass every agent you want traced. Upstream instruments agents one at a time.

```python
import os

from autogen import ConversableAgent
from fi_instrumentation import register
from fi_instrumentation.fi_types import ProjectType
from traceai_ag2_classic import setup

trace_provider = register(
    project_type=ProjectType.OBSERVE,
    project_name="ag2-classic-demo",
)

llm_config = {"config_list": [{"model": "gpt-4o-mini", "api_key": os.environ["OPENAI_API_KEY"]}]}

def get_weather(city: str) -> str:
    """Return the weather for a city."""
    return f"sunny in {city}"

assistant = ConversableAgent(
    "assistant",
    llm_config=llm_config,
    human_input_mode="NEVER",
    is_termination_msg=lambda m: "TERMINATE" in (m.get("content") or ""),
    system_message="Use the weather tool, answer briefly, then say TERMINATE.",
)
user = ConversableAgent("user", llm_config=False, human_input_mode="NEVER", max_consecutive_auto_reply=3)
assistant.register_for_llm(description="Get the weather")(get_weather)
user.register_for_execution()(get_weather)

tracing = setup(tracer_provider=trace_provider, agents=[assistant, user])

user.initiate_chat(assistant, message="What is the weather in Paris?", max_turns=3)

trace_provider.force_flush()  # short scripts: flush before exit
```

Other entry points on the returned handle:

- `tracing.instrument_agent(agent)` for agents created later. Passing a `GroupChatManager` also instruments its members and speaker selection.
- `setup(..., patterns=[...])` or `tracing.instrument_pattern(pattern)` for group patterns.
- `tracing.instrument_a2a_server(server)` only when you ask for it and upstream exports it (the `autogen[a2a]` extra).
- `tracing.uninstrument()` restores `OpenAIWrapper.create`. Agents already instrumented stay instrumented; upstream has no per-agent undo.

`setup()` never creates a provider, never sets the global provider and never adds an exporter. One provider, the one `register()` returned. Do not also use the `[tracing]` extra's gRPC exporter as a global provider, or spans are duplicated.

## What is captured

A two-agent chat with one tool call produces one trace:

```text
conversation user                CHAIN   (session.id = chat id)
  invoke_agent assistant         AGENT
    chat gpt-4o-mini             LLM     model, provider, input/output/total tokens
  invoke_agent user              AGENT
    execute_tool get_weather     TOOL    tool name, type, call id
  invoke_agent assistant         AGENT
    chat gpt-4o-mini             LLM
```

| Field | What you get |
|---|---|
| Span kind | `gen_ai.span.kind` from upstream `ag2.span.type`: `llm` is LLM, `agent` is AGENT, `tool` and `code_execution` are TOOL, `conversation`, `multi_conversation`, `speaker_selection` and `human_input` are CHAIN. |
| Model, provider | `gen_ai.request.model`, `gen_ai.provider.name` on LLM, agent and conversation spans; `gen_ai.response.model` on LLM spans. |
| Tokens | `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens` and `gen_ai.usage.total_tokens` on LLM spans only. The chat-wide sum upstream puts on the conversation span moves to `ag2.usage.*`, so Future AGI counts each call once. |
| Cost | `gen_ai.cost.total` on LLM spans from AG2's own price table, only when above 0. When AG2 cannot price a model it reports 0; that is not copied, so Future AGI prices the call from its tokens. With `cache_seed` set, a cached reply carries the original call's cost and tokens (upstream behaviour). |
| Session | `session.id` from the chat id on the outermost conversation span. Inside `using_session(...)` / `using_attributes(...)` every AG2 span carries your session instead. |
| User | `user.id`, `metadata` and tags from `using_user(...)` / `using_attributes(...)`. |
| Tools | `gen_ai.tool.name`, `gen_ai.tool.type`, `gen_ai.tool.call.id`; arguments and result unless hidden. |
| Errors | A model call that raises keeps ERROR status and `error.type` (for example `BadRequestError`). A tool that raises is caught inside AG2, which only sets `error.type=ExecutionError`; the package turns that into ERROR status. A non-zero code exit becomes ERROR too. |

Not emitted upstream: retrieval spans, and a conversation span for a `GroupChatManager` run. Remote-agent, A2A, code execution and human-input spans are covered by mapping tests only, not by a live run.

## Privacy

Message bodies, tool arguments and tool results are exported by default, like every traceAI instrumentor. Hide them with the standard variables; there is no package-specific switch.

```bash
export FI_HIDE_INPUTS=true     # messages in, tool arguments, human prompt
export FI_HIDE_OUTPUTS=true    # messages out, tool results, code output, chat summaries
```

`FI_HIDE_INPUT_MESSAGES`, `FI_HIDE_OUTPUT_MESSAGES`, `FI_HIDE_INPUT_TEXT` and `FI_HIDE_OUTPUT_TEXT` are honoured too, and so is `setup(..., config=TraceConfig(hide_inputs=True))` (`from fi_instrumentation import TraceConfig`). `setup(..., capture_content=False)` hides both sides and `capture_content=True` keeps both; either overrides the config.

Upstream has a content flag only for LLM spans. Its agent, conversation, tool, human-input and code spans always record bodies, so this package removes those keys itself when a side is hidden. A conversation's output messages carry the whole chat history, so the prompt also appears there unless outputs are hidden.

Verified on a real run (autogen 0.14.1, local Future AGI): with both variables set, a unique marker placed in the prompt, the tool result and a tool exception message was found in none of the stored columns, attributes or events; with defaults it was found on every span. Local paths, user names, host names, e-mail addresses and stack traces were not exported in either mode. Exception messages raised by the model provider or your own tool do appear in the span status text, as with any OpenTelemetry instrumentation.

## Troubleshooting

- No traces: `register()` needs a project name (`project_name=` or `FI_PROJECT_NAME`); the collector drops a batch with no `project_name`.
- `setup()` raises and names a package: you have Microsoft AutoGen, `ag2` 1.x or `pyautogen` instead of `autogen` 0.14.x. Use the matching integration.
- `ImportError: ... 'openai' is not installed` when creating an agent: install `"autogen[openai]"`.
- No LLM spans after a second `setup()` on another provider: upstream patches `OpenAIWrapper.create` once and keeps the first provider. Call `uninstrument()` on the first handle first.
- Content missing: check `FI_HIDE_INPUTS`, `FI_HIDE_OUTPUTS` and any `TraceConfig` you pass.
- Calling `trace_provider.add_span_processor(...)` after `register()` drops the default exporter (an `fi_instrumentation` behaviour). `setup()` puts its own processor back first when you do.
- Use the default `SynchronousMultiSpanProcessor` that `register()` creates. A provider with `ConcurrentMultiSpanProcessor` can export a span before content is removed; `setup()` logs a warning.
- Exporter errors are logged and never fail the agent.

## Limitations

- Alpha; the upstream Classic line receives little maintenance.
- LLM spans bind to the first provider that is set up in a process.
- Nested chats (for example the internal chat behind group-chat speaker selection) keep their own chat id but get no `session.id`, and `initiate_chats` gives one session per chat unless you wrap the call in `using_session(...)`.
- The nested-chat check tracks up to 10000 live spans per provider.

## Difference from related integrations

- [AutoGen](/docs/integrations/traceai/autogen) (`traceAI-autogen`) targets Microsoft AutoGen (`autogen-agentchat`, 0.4+) and wraps its runtime. This package does not wrap anything; it enables the instrumentation `autogen` 0.14.x already ships.
- `traceAI-ag2` targets AG2 1.x (`ag2` import) with a different telemetry middleware and API. The two do not share code or releases.
- OpenInference's AG2 instrumentor patches `ConversableAgent`; this package uses the upstream OpenTelemetry module instead and does not depend on it.
