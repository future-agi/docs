## About

The OpenAI instrumentor traces calls from your application, whether you send them to OpenAI, a gateway or a local model. For example, you can check which provider your client called for a Ridgeline Outfitters return-policy question without mistaking the gateway for the model it routed to.

## Set up the client

Use Python 3.10 to 3.13 or Node.js 22 or later. Install the packages for the language you use. The provider labels in the table below are for the Python release shown here; the Node adapter has its own host map.

<CodeGroup titles={["Python", "Node.js"]}>

```bash Python
python -m pip install 'traceAI-openai==0.1.16' 'fi-instrumentation-otel==1.5.1' 'openai==3.57.0'
```

```bash Node.js
npm install @traceai/openai@0.1.18 @traceai/fi-core@1.4.1 openai@7.47.0
```

</CodeGroup>

`OPENAI_BASE_URL` is the **inference** base URL; the SDK appends `/chat/completions` or `/responses`. If you self-host Future AGI, set `FI_BASE_URL` to the platform API origin. If the collector has a separate origin, set `FI_TRACES_URL` to that origin. Leave both Future AGI URL variables unset for the default cloud destination. Get your [Future AGI key pair](/docs/get-started/send-your-first-trace) separately from your inference key. Never send your Future AGI keys to a model provider.

```bash
export FI_API_KEY="YOUR_FUTURE_AGI_API_KEY"
export FI_SECRET_KEY="YOUR_FUTURE_AGI_SECRET_KEY"
export OPENAI_BASE_URL="https://api.openai.com/v1"
export OPENAI_API_KEY="YOUR_OPENAI_API_KEY"
export OPENAI_MODEL="gpt-4o-mini"
```

Use a model your account can call. For another provider, replace **all three** `OPENAI_` values using the [endpoint table](#choose-a-provider). `OPENAI_MODEL` is read by the example, not selected by the instrumentor. For example, to use OpenRouter, set the base to `https://openrouter.ai/api/v1`, use an OpenRouter key, and set the model to `openai/gpt-4o-mini` if your account can call it. The prompts and answers can be exported to Future AGI. Review [attribute masking](/docs/sdk/tracing/mask-span-attributes) before using customer data; masking the trace does not hide a request from the inference provider.

## Send a request

Save one of these scripts. Each run asks the same return-policy question. You should see a one-sentence answer and one model span for the call. Register once when your application starts; the `finally` block is for a short-lived script. In a server, shut down the provider when the server stops.

<CodeGroup titles={["Python: returns.py", "Node.js: returns.mjs"]}>

```python Python
import argparse
import os

from fi_instrumentation import register
from fi_instrumentation.fi_types import ProjectType
from openai import OpenAI
from traceai_openai import OpenAIInstrumentor

parser = argparse.ArgumentParser()
parser.add_argument("--stream", action="store_true")
parser.add_argument("--usage", action="store_true", help="Request usage with a chat stream")
parser.add_argument("--responses", action="store_true", help="Use the Responses API")
args = parser.parse_args()
if args.usage and (not args.stream or args.responses):
    parser.error("--usage requires a chat stream: use --stream without --responses")
model = os.environ["OPENAI_MODEL"]
question = "Ridgeline Outfitters accepts unused packs within 30 days. Can I return an unused pack on day 12? Answer in one sentence."
provider = register(project_type=ProjectType.OBSERVE, project_name="ridgeline-returns")
OpenAIInstrumentor().instrument(tracer_provider=provider)
try:
    with OpenAI() as client:
        if args.responses:
            result = client.responses.create(model=model, input=question, stream=args.stream)
            if args.stream:
                completed = False
                for event in result:
                    if event.type == "response.output_text.delta":
                        print(event.delta, end="", flush=True)
                    elif event.type == "response.completed":
                        completed = True
                    elif event.type in {"response.failed", "response.incomplete", "error"}:
                        raise RuntimeError(f"Responses stream ended with {event.type}")
                if not completed:
                    raise RuntimeError("Responses stream ended before completion")
                print()
            else:
                if result.status != "completed":
                    raise RuntimeError(f"Response status: {result.status}")
                print(result.output_text)
        else:
            options = {}
            if args.stream and args.usage:
                options["stream_options"] = {"include_usage": True}
            result = client.chat.completions.create(
                model=model, messages=[{"role": "user", "content": question}],
                stream=args.stream, **options,
            )
            if args.stream:
                for chunk in result:
                    if chunk.choices and chunk.choices[0].delta.content:
                        print(chunk.choices[0].delta.content, end="", flush=True)
                print()
            else:
                print(result.choices[0].message.content)
finally:
    provider.force_flush()
    provider.shutdown()
```

```javascript Node.js
import OpenAI from "openai";
import { register, ProjectType } from "@traceai/fi-core";
import { OpenAIInstrumentation } from "@traceai/openai";

const model = process.env.OPENAI_MODEL;
if (!model) throw new Error("Set OPENAI_MODEL to a model available to your account.");
const stream = process.argv.includes("--stream");
const responses = process.argv.includes("--responses");
const usage = process.argv.includes("--usage");
if (usage && (!stream || responses)) throw new Error("--usage requires a chat stream: use --stream without --responses");
const question = "Ridgeline Outfitters accepts unused packs within 30 days. Can I return an unused pack on day 12? Answer in one sentence.";
const provider = register({ projectName: "ridgeline-returns", projectType: ProjectType.OBSERVE });
const instrumentation = new OpenAIInstrumentation({});
instrumentation.setTracerProvider(provider);
instrumentation.manuallyInstrument(OpenAI);
try {
  const client = new OpenAI();
  if (responses) {
    const result = await client.responses.create({ model, input: question, stream });
    if (stream) {
      let completed = false;
      for await (const event of result) {
        if (event.type === "response.output_text.delta") process.stdout.write(event.delta);
        else if (event.type === "response.completed") completed = true;
        else if (["response.failed", "response.incomplete", "error"].includes(event.type)) {
          throw new Error(`Responses stream ended with ${event.type}`);
        }
      }
      if (!completed) throw new Error("Responses stream ended before completion");
      console.log();
    } else {
      if (result.status !== "completed") throw new Error(`Response status: ${result.status}`);
      console.log(result.output_text);
    }
  } else {
    const result = await client.chat.completions.create({
      model, messages: [{ role: "user", content: question }], stream,
      ...(usage ? { stream_options: { include_usage: true } } : {}),
    });
    if (stream) {
      for await (const chunk of result) process.stdout.write(chunk.choices[0]?.delta.content ?? "");
      console.log();
    } else console.log(result.choices[0].message.content);
  }
} finally {
  instrumentation.disable();
  await provider.shutdown();
}
```

</CodeGroup>

Run `python returns.py` or `node returns.mjs`. Add `--stream` to print text as it arrives. On a Chat Completions endpoint that supports streamed usage, add `--stream --usage`. Consume the whole stream, including a final usage chunk with no choices. Do not request `stream_options` from a model that does not support it.

## Read the span

Under **Observe**, open **Tracing** and select `ridgeline-returns`. Open the trace for your call and select the model span (`ChatCompletion` for Python chat). Check **Provider** and **Model** above the **Preview** tab. The **Markdown** preview below shows a similar return-policy question sent through OpenRouter.

![ChatCompletion span with provider openrouter and model openai/gpt-4o-mini. The answer confirms an unused pack can be returned on day 12. Usage is 33 prompt tokens and 13 completion tokens.](/images/docs/integrations/traceai/openai/openrouter-return-policy-span.png)

Select **JSON** in the same tab to inspect the span attributes. Compare a regular call with a streamed call:

| Python span field | What to look for |
| --- | --- |
| `gen_ai.provider.name` | The service identified from the client's configured hostname, not the author of the model or proof the request reached the service. |
| `gen_ai.request.model` | For a successful non-streamed chat, the returned model, which may be a dated ID rather than your alias. For a streamed or failed chat, the requested model. |
| `gen_ai.request.parameters` | The model ID and parameters you sent, unless invocation parameters are hidden. Compare this ID with the one above when a deployment name differs from the returned model. |
| `input.value`, `output.value` | The return-policy question and the answer, unless hidden. Python chat spans can also record the conversation roles, tool calls and content parts. A tool call on a model span is not a span for the tool's execution. |
| `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens`, `gen_ai.usage.total_tokens` | Counts supplied by the endpoint. The token chips can show `0` even when the endpoint omits usage. If the usage attributes are absent in **JSON**, the counts are unknown. Cached-input and reasoning-token counts can also appear when supplied. |

## Choose a provider

For each row, put the base URL in `OPENAI_BASE_URL`, the indicated credential in `OPENAI_API_KEY` and your model or deployment name in `OPENAI_MODEL`. The instrumentor recognizes documented hosts, including specific workspace-domain patterns. It does not infer a vendor from a model prefix or a similar hostname. Unless you explicitly label the client, a custom proxy or loopback host keeps `openai`.

| Inference service | SDK base URL | Credential and model selection | Python provider label |
| --- | --- | --- | --- |
| OpenAI | `https://api.openai.com/v1` | OpenAI API key; a chat model your project can use | `openai` |

With the Node adapter shown here, Vercel and Perplexity are recognized as `vercel` and `perplexity`. CometAPI, Novita, Z.ai and Ollama are not in that release’s Node host map and keep `openai`. A fallback label alone does not mean the request went to OpenAI.

### When the API differs

- **Perplexity:** Run `python returns.py --responses`, then `python returns.py --responses --stream` (or use `node returns.mjs` with the same flags). This is the OpenAI SDK calling the Agent API, not native Perplexity Search or Embeddings instrumentation. The SDK adds `/responses` once. A Python `Response` span uses the returned model on success, including from `response.completed` for a stream, and keeps the requested model if the request fails before a response model is available. Search results may appear in the raw response; the adapter does not turn them into citation or retriever spans.
- **Foundry:** Use the resource's v1 inference base, not a project URL, deployment-specific REST path or `api-version` query. For Entra ID instead of a resource key, use the [Microsoft v1 token provider](https://learn.microsoft.com/en-us/azure/foundry/openai/api-version-lifecycle) with the same base URL. [Foundry Agent Service tracing](/docs/integrations/frameworks/azure-ai-foundry) is a different integration.
- **Databricks:** Use your actual workspace host under `*.cloud.databricks.com`, `*.azuredatabricks.net` or `*.gcp.databricks.com`. Do not append the endpoint name or `/invocations` to the SDK base. This traces a model request, not an MLflow export.
- **Baseten and Lepton:** The Baseten row selects the shared Model APIs catalog, not a custom deployment. Lepton has no shared base URL: provision a compatible LLM endpoint before instrumenting your client.
- **Doubleword:** The example uses synchronous Chat Completions, not [Responses async inference](https://docs.doubleword.ai/inference-api/async-inference). To select flex capacity on a supported chat model, pass `service_tier="flex"` to `client.chat.completions.create`. `extra_body={"service_tier": "flex"}` also sends the field, but only the native keyword appears in the Python span's `gen_ai.request.parameters` when those parameters are visible.

## Troubleshooting

- **An alias or proxy shows `openai`:** Check the hostname the application actually calls, not a model ID or an upstream URL. A Python `vercel` or `orcarouter` span identifies the receiving gateway, not its internal retries, fallback attempts, routing decisions or billed cost. Use the gateway's own telemetry for those.
- **Inference fails:** Check the provider key, base path and model access. For Qwen, use the key for the selected region and workspace. The Hong Kong shared host falls back to `openai`; a `*.maas.aliyuncs.com` workspace host is labeled `dashscope`. For Bonsai or Ollama, first check that your server is running and serving the requested model. Changing `FI_BASE_URL` will not fix an inference connection error. A failed SDK request can still produce an error span.
- **An answer prints but no span arrives:** Inference worked. Check the Future AGI key pair, collector origin, project name and exporter errors. Make sure the script instruments the client before the call, consumes any stream and shuts down telemetry. Local inference does **not** imply local telemetry storage.
- **Sensitive data in traces:** On the pinned releases, input or output hiding also hides standard span error details by default. Set `FI_HIDE_ERROR_DETAILS=true` to hide them independently. Review custom attributes and application logs separately; avoid putting secrets in prompts or model identifiers.
