## About

Use `traceAI-promptflow` to see which step in a Microsoft Prompt flow run called the model. Tracing only the OpenAI client shows the model request, but not the flow or the policy lookup that informed the reply.

## Install and set credentials

Use Python 3.10 through 3.13. The integration supports `promptflow-tracing>=1.12.0,<2`. In an empty directory, install the integration, the flow executor, and the OpenAI client. The exporter pin keeps OpenTelemetry compatible with this version of Prompt flow:

```bash
python3 -m venv .venv
source .venv/bin/activate
export FI_TRACES_URL=https://api.futureagi.com
python -m pip install traceAI-promptflow==0.1.0 promptflow-core==1.18.5 'openai>=1,<2' \
    opentelemetry-exporter-otlp-proto-http==1.38.0
```

Set these variables in the environment where you will run Python. Keep credentials out of the flow files.

| Environment variable | What to set |
| --- | --- |
| `FI_API_KEY`, `FI_SECRET_KEY` | Your [Future AGI key pair](https://app.futureagi.com/dashboard/keys), for exporting spans. |
| `OPENAI_API_KEY` | Your model provider's API key, for one Chat Completions request. If you use an OpenAI-compatible provider, also set `OPENAI_BASE_URL` to its API base URL. |
| `OPENAI_MODEL` | Optional. Defaults to `gpt-4o-mini`; set it to choose a different chat model. |

## Define the returns flow

Ridgeline Outfitters' support agent looks up the return policy for a tent, then drafts a reply using that policy. Save the following as `flow.flex.yaml`. The entry points to the `answer` function in `support.py`.

```yaml
entry: support:answer
```

Save `support.py` in the same directory. Use Prompt flow's `@trace` on the two helpers so you can distinguish time spent looking up the policy from time spent drafting the reply.

```python
import os

from openai import OpenAI
from promptflow.tracing import trace


@trace
def find_policy(item: str) -> str:
    policies = {"tent": "Unused tents can be returned within 30 days."}
    return policies[item]


@trace
def draft_reply(question: str, policy: str) -> str:
    with OpenAI() as client:
        response = client.chat.completions.create(
            model=os.getenv("OPENAI_MODEL", "gpt-4o-mini"),
            messages=[
                {"role": "system", "content": f"Answer in one sentence using this policy: {policy}"},
                {"role": "user", "content": question},
            ],
        )
    return response.choices[0].message.content


def answer(item: str, question: str) -> str:
    return draft_reply(question, find_policy(item))
```

## Run the flow and close a preview early

Save `run_flow.py` next to the other two files. Register the provider and instrument Prompt flow **before** creating the executor. This example hides both inputs and outputs: you can inspect the call hierarchy and token usage without exporting the customer's question or the model's reply.

```python
from fi_instrumentation import TraceConfig, register
from fi_instrumentation.fi_types import ProjectType
from promptflow.executor import FlowExecutor
from promptflow.tracing import trace
from traceai_promptflow import PromptflowInstrumentor

provider = register(
    project_name="ridgeline-returns", project_type=ProjectType.OBSERVE, verbose=False
)
PromptflowInstrumentor().instrument(
    tracer_provider=provider,
    config=TraceConfig(hide_inputs=True, hide_outputs=True),
)


@trace
def preview_reply(reply: str):
    yield "Ridgeline Outfitters support"
    yield reply


try:
    flow = FlowExecutor.create("flow.flex.yaml", {})
    result = flow.exec_line({
        "item": "tent",
        "question": "Can I return an unused tent after two weeks?",
    })
    if result.run_info.error:
        raise RuntimeError("The returns flow failed. Inspect the answer trace in Observe.")
    print(result.output)

    preview = preview_reply(result.output)
    try:
        print(next(preview))
    finally:
        preview.close()
finally:
    provider.force_flush()
```

Run the script from that directory:

```bash
python run_flow.py
```

You should see a reply based on the 30-day policy, then `Ridgeline Outfitters support`. The preview consumer closes the generator after the heading, before it reads the reply.

## Inspect the two traces

Open **Observe → Tracing**, select `ridgeline-returns`, and open the `answer` trace. Select each span and look for `gen_ai.span.kind` under **Attributes**:

| Span | Kind | What to inspect |
| --- | --- | --- |
| `answer` | `CHAIN` | The whole flex flow run. A DAG run also has a `CHAIN` root, with its nodes beneath it. |
| `find_policy` and `draft_reply` | `TOOL` | These are siblings under `answer`. Only `draft_reply` has a model call. |
| `openai_chat` | `LLM` | The OpenAI call under `draft_reply`. Look for the request model, response model, and input and output token counts when the provider returns usage. |

![The answer trace branches into find_policy and draft_reply. Under draft_reply, the selected openai_chat span shows openai/gpt-4o-mini with 40 input tokens and 21 output tokens.](/images/docs/integrations/traceai/promptflow/returns-flow-model-span.png)

Open the separate `preview_reply` trace. It is a `CHAIN` because you called the decorated function outside the flow. A generator span stays open while you consume it. Closing it early sets `promptflow.stream.incomplete` to `true`; consuming it to exhaustion finishes the span without that flag. For an async generator, use `await stream.aclose()` if you stop early.

![The preview_reply span shows promptflow.stream.incomplete set to true in Attributes. No question or reply text appears in the span preview.](/images/docs/integrations/traceai/promptflow/incomplete-preview-span.png)

## Limits and troubleshooting

- **No flow spans:** If you explicitly set `PF_DISABLE_TRACING=true`, `instrument()` respects it. Unset the variable before starting the process to let the instrumentor enable tracing.
- **Two spans for one model call:** Do not also enable `OpenAIInstrumentor` for calls Prompt flow already traces. Instrumenting only the provider has the opposite problem: you lose the flow and tool spans.
- **No question or reply on the spans:** The two hide settings in the example omit `input.value` and `output.value`. By default the integration captures these values. It drops Prompt flow's native `inputs`, `output`, `prompt.template`, `prompt.variables`, and `promptflow.*` events rather than exporting a second copy. On failure, it records `ERROR` and `error.type`, not the exception message or traceback.
- **Batch workers or feedback:** Instrumentation applies to the current process. Call `instrument()` in each batch worker that should export spans. Do not rely on the parent's hide settings for uninstrumented workers or for Prompt flow's serving `/feedback` endpoint, which is outside this integration.
