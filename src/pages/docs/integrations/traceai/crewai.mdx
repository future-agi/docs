title: "CrewAI tracing"
description: "Send CrewAI's native crew, task, agent, Flow and model-call spans to Future AGI over OpenTelemetry."

Trace crews, standalone agents, Flows and model calls in **Observe** using CrewAI's native OpenTelemetry session.

## Install

Use Python 3.10–3.13 and CrewAI 1.15.33 or newer.

```bash
pip install 'crewai>=1.15.33,<2' opentelemetry-exporter-otlp-proto-http
```

This route uses CrewAI's event lifecycle directly. You do not need `traceAI-crewai` or a copied tracing helper.

## Configure credentials and destinations

Set your Future AGI credentials and an OpenAI model available to your account before importing CrewAI.

```bash
export FI_API_KEY="your-futureagi-api-key"
export FI_SECRET_KEY="your-futureagi-secret-key"
export OPENAI_API_KEY="your-openai-api-key"
export OPENAI_MODEL="openai/gpt-4o-mini"

# Turn off CrewAI's separate analytics and hosted trace destination.
export CREWAI_DISABLE_TELEMETRY=true
export CREWAI_TRACING_ENABLED=false
```

The explicit session below still sends spans to Future AGI. Do not enable another CrewAI or model-client instrumentor for the same execution: native sessions already create model-call spans, and combining routes can duplicate them.

**Content capture:** native sessions export application inputs, outputs, Flow state and error details. Keep credentials and sensitive data out of these fields, including tool results and exception messages. `FI_HIDE_INPUTS` and `FI_HIDE_OUTPUTS` do not apply to CrewAI's native provider. If you require content filtering, send through an OpenTelemetry Collector with your organization's redaction policy before forwarding to Future AGI; do not assume the traceAI privacy settings cover this route.

## Run a traced crew

Save this as `crewai_example.py`. The OpenTelemetry exporter sends OTLP/HTTP protobuf to Future AGI; the resource selects your Observe project.

```python
import os
from uuid import uuid4

from crewai import Agent, Crew, LLM, Task
from crewai.telemetry.tracing import telemetry_session
from opentelemetry.exporter.otlp.proto.http.trace_exporter import OTLPSpanExporter
from opentelemetry.sdk.resources import Resource

exporter = OTLPSpanExporter(
    endpoint="https://api.futureagi.com/tracer/v1/traces",
    headers={
        "X-Api-Key": os.environ["FI_API_KEY"],
        "X-Secret-Key": os.environ["FI_SECRET_KEY"],
    },
)
resource = Resource({
    "service.name": "crewai-app",
    "project_name": "crewai_project",
    "project_type": "observe",
})

writer = Agent(
    role="Writer",
    goal="Explain technical ideas clearly",
    backstory="You write concise explanations for developers.",
    llm=LLM(model=os.environ["OPENAI_MODEL"]),
    allow_delegation=False,
)
task = Task(
    description="Explain why distributed tracing helps debug an agent workflow.",
    expected_output="A two-sentence explanation.",
    agent=writer,
)
crew = Crew(agents=[writer], tasks=[task])

with telemetry_session(
    str(uuid4()),
    "crewai_project",
    exporters=[exporter],
    resource=resource,
):
    result = crew.kickoff()
    print(result.raw)
```

```bash
python crewai_example.py
```

Exiting `telemetry_session` drains the event handlers, finishes pending spans, flushes the exporter and removes that session's listeners. Create a new session and exporter for each independent execution; do not reuse a shut-down exporter.

## Trace a standalone agent or Flow

For a standalone agent, replace the `crew.kickoff()` call inside the session with `writer.kickoff("Explain distributed tracing in two sentences.")`. Keep the call inside the session so its agent and model spans share the same execution.

For a Flow, define the Flow in the same script, then replace the session's two execution lines with `print(ExplanationFlow().kickoff())`. The Flow and each executed method get their own spans.

```python
from crewai.flow.flow import Flow, listen, start

class ExplanationFlow(Flow):
    @start()
    def topic(self):
        return "Distributed tracing connects the steps in an agent workflow."

    @listen(topic)
    def summarize(self, explanation):
        return {"summary": explanation}
```

In async code, keep the session open while awaiting `flow.kickoff_async()` or `writer.kickoff_async(...)`. Do not start background work that outlives the session.

## View the trace

Open **Observe** in Future AGI and select **crewai_project**. Expand the trace to inspect the execution hierarchy, durations and errors. Model spans include the model name and token usage when the provider reports it. Native content is carried in `gen_ai.input.messages`, `gen_ai.output.messages` and `crewai.*` span attributes.

## Existing traceAI installations

You can keep the maintained wrapper route for existing crew/task/tool workloads. Use Python 3.10–3.12 and upgrade the package rather than retaining an older pinned release:

```bash
pip install --upgrade 'traceAI-crewai>=0.1.10'
```

This route wraps crew kickoff, task execution and tool usage. It does not add Flow, standalone-agent or model lifecycle spans; use the native session above for those paths. Do not run both tracing routes together.

Configure the wrapper route using [the package README](https://github.com/future-agi/traceAI/tree/dev/python/frameworks/crewai). Its `FI_HIDE_INPUTS=true` and `FI_HIDE_OUTPUTS=true` controls apply to wrapper-captured content; see [mask span attributes](/docs/sdk/tracing/mask-span-attributes). They do not control CrewAI's independent exporters.

CrewAI 0.41.1 has no native telemetry opt-out: upgrade CrewAI if you need to disable its separate analytics exporter. On maintained releases, set `CREWAI_DISABLE_TELEMETRY=true` before importing it.

## Troubleshooting

- **No spans arrive:** keep execution inside `telemetry_session`, let the context exit, and check that both Future AGI headers are set. Use the full `/tracer/v1/traces` HTTP endpoint, not a gRPC endpoint.
- **Duplicate model spans:** remove other CrewAI and model-client instrumentors from this execution and disable CrewAI-hosted tracing with `CREWAI_TRACING_ENABLED=false`.
- **Native session import fails:** upgrade CrewAI to the version range in the install command and restart the Python process.
