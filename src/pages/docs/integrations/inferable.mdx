---
title: "Inferable Tracing Is Not Supported Yet"
description: "Future AGI does not support tracing Inferable yet. What we checked in the Inferable source, why a Langfuse base URL is not a supported path, and what would change that."
---

Inferable ([inferablehq/inferable](https://github.com/inferablehq/inferable)) is a durable-execution runtime for AI workflows. **Future AGI does not support tracing it yet.** There is no setup guide on this page on purpose.

Evidence date: 2026-10-16. Nothing on this page was run against a live Inferable cluster. The checks below are source and documentation reads only.

## What we checked

| Check | Result |
| --- | --- |
| Trace export in the Inferable control plane | The only export we found is the Langfuse integration (`control-plane/src/modules/integrations/langfuse.ts`). It builds a client from the `langfuse` npm package (`^3.31.0`) and calls its `trace()` and `generation()` methods. It does not use an OpenTelemetry SDK or an OTLP exporter for runs. |
| Settings on the Inferable side | Secret key, public key, base URL and a "send message payloads" switch. The base URL is user-settable ([pinned integration source](https://github.com/inferablehq/inferable/blob/c67acb81/control-plane/src/modules/integrations/langfuse.ts)). |
| Export hook in the Node or Go SDK | None found. |
| Source checked | `main` at `c67acb81` (committed 2025-07-05), MIT licence. The repository has had no later commit on `main`. |

## Why this is not supported

Future AGI ingests OpenTelemetry traces over OTLP. The Langfuse client that Inferable uses is not an OTLP exporter, so the request it sends is a Langfuse client request, not OTLP. We did not record that request, and a recipe that says "paste your Future AGI keys into the Langfuse fields" would be a guess. This page does not make that claim.

We did not add a second ingest protocol, a new collector route or an adapter for it. The repository has had no commit on `main` since July 2025 and we have no customer request for it, so we do not think the effort is justified yet.

## What you should not do

- Do not paste Future AGI keys into the Inferable Langfuse fields and expect traces.
- Do not turn on "send message payloads" for an experiment. It sends prompts and tool arguments.

## What would change this

We will add a supported page if one of these becomes true:

- Inferable (or a maintained fork) exports OTLP traces, or exports a body Future AGI already accepts.
- A recorded request from a self-hosted Inferable run shows a body Future AGI already accepts. The record would be attached to the page as evidence.

If a recording shows only Langfuse's own batch body, this page stays "not supported".

## Related

If your application calls model providers directly, use the model instrumentors under [traceAI](/docs/integrations/traceai). This page is about Inferable's own runs and tool calls, which those instrumentors do not see.

## Troubleshooting

- **No traces appear in Future AGI from Inferable.** Expected. This integration is not supported yet.
- **A guide tells you to set a Langfuse base URL to Future AGI.** That route is not supported. Do not follow it for production data.
