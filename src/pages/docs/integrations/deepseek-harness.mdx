---
title: "DeepSeek Harness Tracing Is Not Supported Yet"
description: "Future AGI does not support tracing DeepSeek Harness (dsh) yet. What we checked, what a third-party plugin exported in a dated check, and why that is not enough."
---

DeepSeek Harness (`dsh`, [deepseek-ai/deepseek-harness](https://github.com/deepseek-ai/deepseek-harness)) is DeepSeek's coding-agent harness. **Future AGI does not support tracing it yet.** There is no setup guide on this page on purpose.

This is not the DeepSeek chat API, and it is not the DeepSeek model instrumentor. If you call DeepSeek models from your own code, use the model instrumentors under [traceAI](/docs/integrations/traceai).

The runtime results below were checked on 2026-10-16 and are historical. A source-only recheck on 2026-10-29 covered npm latest `@deepseek-ai/dsh` **0.2.1-rc.2**, tag `dsh-v0.2.1-rc.2` at `687f282e8625c6b8d11ff58211a90524be2e4317`. The same trace-term search in `packages/` and `apps/` found no native trace SDK/exporter; all three logs-export positive controls matched. This is a source result, not a runtime qualification of 0.2.1-rc.2. The current `@loongsuite/dsh-plugin` **0.1.3** package still contains the `dsh.session.cwd` and `host.name` exports.

## What we checked

| Check | Result |
| --- | --- |
| Trace export in `dsh` source (`packages/` and `apps/`) | None. No trace SDK, no trace exporter, no `/v1/traces`, no `traceparent`, no `gen_ai` attributes. Searched at `86a40220` (tag `dsh-v0.2.1-alpha.4`, head of `master` on 2026-10-16), `639ed015` (tag `dsh-v0.2.0-rc.2`, npm `latest` on 2026-10-16) and `5badb150` (the commit the first review read). |
| What `dsh` does export | OpenTelemetry **logs** to a DeepSeek-run collector. It is not a trace path and you cannot point it at Future AGI. |
| Tested versions | `@deepseek-ai/dsh` `0.2.1-alpha.4` and `0.2.0-rc.2`, with the third-party plugin below at 0.1.3, on Node 26. |
| License | `dsh` is MIT. |

## Historical third-party plugin results

A community plugin, `@loongsuite/dsh-plugin` (Apache-2.0, not made or supported by DeepSeek or Future AGI), adds OpenTelemetry traces to `dsh`. We ran it against a local Future AGI to see what a customer would get. Future AGI accepted the spans with the expected tree:

```
enter_ai_application_system
  invoke_agent deepseek-harness      model and token counts
    react step
      chat <model>                   llm span with prompt and completion tokens
      execute_tool bash              tool span
    react step
      chat <model>
```

We are not shipping or documenting this as a setup, because of what else came with it:

| Finding | Why it blocks support |
| --- | --- |
| With message content capture **off**, every span still carried `dsh.session.cwd` (the working directory path) and the resource carried `host.name` and `service.instance.id` (the machine host name). Run from a home directory, the path contains the user name. | These metadata fields expose local identity information even when message capture is off. |
| With content capture off, a failed model call put the provider's raw error body into the span status message. | This can expose request content through an error field. |
| A shell command that exits non-zero (we ran exit code 3) shows as an `OK` tool span. | Failures would be hidden in the trace. |
| A wrong API key produced no message from `dsh`; the run looked successful and nothing was stored. | Customers would not learn the setup is broken. |
| The plugin is a third-party, early-stage package (created August 2026) on a fast-moving preview host. | We cannot promise it keeps working. |

Message content (prompts, replies, tool arguments and results) was off by default and absent from every stored column in our check. It appeared only after the plugin's content setting was turned on.

## What would change this

We will add a supported page when `dsh` itself, or a plugin we can review, exports traces without local paths, host names and raw error text by default, and marks failed tools as errors. Using the third-party plugin as a documented option later is possible; it needs a decision from Future AGI first.

## What this page does not claim

- No setup steps, package, peer dependency or vendored code.
- No claim that Future AGI supports `dsh` tracing, or that the plugin is safe to use with sensitive projects.
- No test of DeepSeek-hosted models. The local runs used an OpenAI-compatible endpoint standing in for the model provider.

## Scope

This notice does not provide a tracing setup or support subagent/session behavior. The historical spike used a local Future AGI collector and an OpenAI-compatible model endpoint; it is not evidence for DeepSeek-hosted models or later runtime releases.
