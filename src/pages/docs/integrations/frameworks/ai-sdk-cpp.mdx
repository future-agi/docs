## About

[AI SDK C++](https://github.com/ClickHouse/ai-sdk-cpp) is ClickHouse's C++20 library for calling OpenAI and Anthropic models, with tools and multi-step runs. You cannot trace it into Future AGI today, so this page has no setup steps. It records what was checked, so you do not have to repeat it.

<Warning>
Not supported. No AI SDK C++ trace has been sent to Future AGI, and nothing on this page makes one appear. Every finding below comes from reading the source at one pinned commit and from running the real library against a local stand-in for a Langfuse server.
</Warning>

The only tracing code in the SDK is `ai::langfuse`, a client for Langfuse's own ingestion API. It does not speak OpenTelemetry, and it cannot send the headers or the project name that Future AGI requires. If ClickHouse adds an OTLP export, this page will be replaced by a setup guide.

## Why the Langfuse client cannot be pointed at Future AGI

The module was built from the pinned commit and run once with a tool call (`ai::langfuse::generate_text`, then `Trace::end()`), with the Langfuse host set to a loopback capture stub. This is what Future AGI needs, next to what arrived:

| | Future AGI needs | `ai::langfuse` sends |
| --- | --- | --- |
| Format | OTLP traces | One JSON body, `{"batch": [...]}`, of Langfuse events: `trace-create`, `span-create`, `span-update`, `generation-create` |
| URL | The Future AGI trace endpoint | `<host>/api/public/ingestion`. The path is a constant in the source. The host may carry a path prefix, but the suffix is always appended |
| Auth | `X-Api-Key` and `X-Secret-Key` headers | `Authorization: Basic`, built from a Langfuse public and secret key pair, plus `User-Agent` and two `X-Langfuse-Sdk-*` headers. There is no setting for other headers |
| Project | A `project_name` resource attribute | None. The batch is not OTLP, so it has no resource attributes |

Future AGI receives traces over OTLP ([Observability model](/docs/observe/concepts/observability-model)), which this client does not speak. Pointing its `host` at Future AGI sends Langfuse-shaped JSON to a path that is not a Future AGI trace endpoint.

Wrapping the client, or translating its batch into OTLP, would mean shipping a C++ component to Future AGI customers. The [traceAI repository](https://github.com/future-agi/traceAI) has Python, TypeScript, Java and C# packages and no C++ one (top-level folders on its `dev` branch, read 2026-10-16), and Future AGI has not built one for this SDK.

## What `ai::langfuse` does at runtime

Observed on the pinned build. Any future OTLP export for this SDK has to match these rules, because they decide whether the last trace of a process is lost.

| Case | Observed |
| --- | --- |
| One run with a tool call | Events are held in memory and sent in one request at `end()`: a trace, a tool span under the generation, and the generation with model and token usage |
| `end()` called twice | One request in total. Both calls return true |
| Process exits without `end()` | Nothing is sent. The trace is lost |
| `generate_text` fails (unknown model) | One request. The generation has level `ERROR`, and the provider's raw error text is in `statusMessage` |
| Langfuse host unreachable, default `kStrict` | The first `end()` returns false and logs an error. The batch is dropped, not retried. A second `end()` returns true and sends nothing |
| Langfuse host unreachable, `kBestEffort` | `end()` returns true and logs an error |
| All of the above | No exception left the SDK |

## Privacy

Nothing from AI SDK C++ reaches Future AGI, so there is no capture setting to choose.

For reference, `ai::langfuse` has no switch to leave content out. In the run above the batch carried the system and user prompt, the tool arguments and result, and the model output. In the failed run it carried the provider's raw error text. Any bridge to another backend would have to add its own redaction first.

## Scope boundary

This is a source-backed unsupported-status notice, not an installation guide. It does not prescribe a Langfuse-import bridge or a C++ OpenTelemetry component for AI SDK C++.

## Troubleshooting

**I set the Langfuse `host` to Future AGI and no traces appear.** This is expected. `ai::langfuse` sends Langfuse ingestion batches to `<host>/api/public/ingestion` and never calls a Future AGI OTLP trace endpoint.

**My last trace is missing.** `Trace::end()` is the only call that sends anything. A process that exits without it loses the trace. With the default `kStrict` policy, a failed flush is reported once and the batch is not retried.

**Does a newer commit change this?** The findings are about the commit above. The source folder has a script that repeats the search on any commit.
