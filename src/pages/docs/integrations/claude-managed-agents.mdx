## About

Claude Managed Agents is Anthropic's hosted agent service: Anthropic runs the agent loop and a sandbox for each session, and your code creates sessions and exchanges events with them through the Sessions API (beta header `managed-agents-2026-04-01`). The Claude Platform can push OpenTelemetry traces of those sessions to an endpoint you choose, called a telemetry destination. This page points a destination at a small OpenTelemetry Collector that you run, which hands the spans to Future AGI.

You need the collector because of two differences between what Anthropic sends and what Future AGI accepts:

| Anthropic | Future AGI | What the collector does |
| --- | --- | --- |
| The first request of every delivery is gzip-compressed. | The destination and receiver must agree on compression. | Accepts gzip and forwards plain OTLP. |
| A destination sets request headers only. Spans carry `service.name` = `claude-platform` and no project. | Every batch needs a `project_name` resource attribute. | Stamps `project_name` and the two Future AGI key headers. |

<Warning>
**Beta: do not send production data until you verify delivery and privacy with a test session in your workspace.** Anthropic's export is in beta; span names and attributes can change.
</Warning>

This page is not about related products that run the agent loop in your own process: the Claude Messages API in your own code ([Anthropic](/docs/integrations/traceai/anthropic)), the Claude Agent SDK (`traceai-claude-agent-sdk` in the [instrumentor list](/docs/sdk/tracing/instrumentors)), and Claude Code (the Claude Code coding-agent page).

## Before you start

- A Future AGI account with an API key and secret key, and a Future AGI endpoint your collector can reach.
- An Anthropic Console organization where you have the **admin** role, which is needed to add destinations. Developers can only view them.
- A host with a public DNS name and HTTPS on port 443 for the collector. Anthropic accepts only an HTTPS URL on port 443 with a hostname, not an IP address, and disables a destination whose hostname resolves to a non-public address or that answers with a redirect. Put a same-host TLS reverse proxy in front of the loopback-bound collector. If your TLS load balancer runs on a separate host, restrict TCP 4318 with a firewall so only the load balancer can reach it.
- Docker and, for the optional Admin API command, `jq`, or another way to run the OpenTelemetry Collector contrib distribution. The example uses `otel/opentelemetry-collector-contrib` 0.162.0.

## 1. Run the collector

Save this as `otelcol.yaml`. It takes five values from the environment.

```yaml
# OpenTelemetry Collector (contrib) between a Claude Console telemetry destination and Future AGI.
#
# Anthropic's destination takes an endpoint URL and request headers. It has no field for resource attributes,
# and Future AGI requires `project_name`. Anthropic gzips the first request of every delivery.
# This collector:
#   1. accepts OTLP/HTTP (protobuf, gzip or plain) from Anthropic, only with your bearer token,
#   2. sets the Observe project,
#   3. maps Anthropic's gen_ai.* / anthropic.* attributes to what Observe reads,
#   4. keeps prompts, replies, tool arguments, tool results and error text OUT unless you opt in,
#   5. forwards plain (uncompressed) OTLP to Future AGI with the two Future AGI key headers.
#
# Collector distribution: otel/opentelemetry-collector-contrib 0.162.0.
# Span reference: https://platform.claude.com/docs/en/api/opentelemetry/spans.
#
# Environment:
#   ANTHROPIC_DEST_TOKEN   secret you invent; the destination sends `Authorization: Bearer <token>`
#   FI_API_KEY, FI_SECRET_KEY   Future AGI keys (they never go to Anthropic)
#   FI_PROJECT_NAME        Observe project every Anthropic span goes to
#   FI_TRACES_URL          full traces URL, e.g. http://<self-hosted>:4318/v1/traces
#                          or https://api.futureagi.com/tracer/v1/traces
#   FI_CAPTURE_CONTENT     optional, default false. `true` lets prompts, replies, tool arguments, tool results
#                          and error text through. The destination's own content mode must also be Full content.

extensions:
  bearertokenauth/anthropic:
    scheme: Bearer
    token: ${env:ANTHROPIC_DEST_TOKEN}

receivers:
  otlp:
    protocols:
      http:
        endpoint: 0.0.0.0:4318
        auth:
          authenticator: bearertokenauth/anthropic
        # Anthropic needs HTTPS on port 443 with a public hostname. Put TLS in front of this (a load balancer or
        # reverse proxy), or set `tls:` here with cert_file and key_file.

processors:
  resource/future_agi:
    attributes:
      - key: project_name
        value: ${env:FI_PROJECT_NAME}
        action: upsert
      - key: project_type
        value: observe
        action: insert

  transform/anthropic:
    error_mode: ignore
    trace_statements:
      - context: resource
        statements:
          - keep_keys(attributes, ["service.name", "project_name", "project_type"]) where "${env:FI_CAPTURE_CONTENT:-false}" != "true"
      - context: span
        statements:
          # Span kinds in Observe, from gen_ai.operation.name.
          - set(attributes["fi.span.kind"], "AGENT") where attributes["gen_ai.operation.name"] == "invoke_agent"
          - set(attributes["fi.span.kind"], "LLM") where attributes["gen_ai.operation.name"] == "chat"
          - set(attributes["fi.span.kind"], "TOOL") where attributes["gen_ai.operation.name"] == "execute_tool"
          - set(attributes["fi.span.kind"], "EVALUATOR") where name == "anthropic.session.outcome_evaluation"
          - set(attributes["fi.span.kind"], "CHAIN") where attributes["fi.span.kind"] == nil
          # Sessions view: group by the Managed Agents session id.
          - set(attributes["session.id"], attributes["anthropic.session.id"]) where attributes["anthropic.session.id"] != nil
          # Name the agent turn after the agent.
          - set(name, Concat(["anthropic.session.turn", attributes["gen_ai.agent.name"]], " ")) where name == "anthropic.session.turn" and attributes["gen_ai.agent.name"] != nil
          # Content ON: fill the Input and Output panes.
          - set(attributes["input.value"], attributes["gen_ai.input.messages"]) where attributes["gen_ai.input.messages"] != nil and "${env:FI_CAPTURE_CONTENT:-false}" == "true"
          - set(attributes["output.value"], attributes["gen_ai.output.messages"]) where attributes["gen_ai.output.messages"] != nil and "${env:FI_CAPTURE_CONTENT:-false}" == "true"
          - set(attributes["input.value"], attributes["gen_ai.tool.call.arguments"]) where attributes["gen_ai.tool.call.arguments"] != nil and "${env:FI_CAPTURE_CONTENT:-false}" == "true"
          - set(attributes["output.value"], attributes["anthropic.tool_result.content"]) where attributes["anthropic.tool_result.content"] != nil and "${env:FI_CAPTURE_CONTENT:-false}" == "true"
          # Content OFF: allow only known metadata. A denylist misses content carried in new keys,
          # indexed message keys, or nested OTLP values from other exporters.
          - keep_keys(attributes, ["fi.span.kind", "session.id", "gen_ai.provider.name", "gen_ai.operation.name", "gen_ai.conversation.id", "gen_ai.agent.id", "gen_ai.agent.name", "gen_ai.request.model", "gen_ai.response.model", "gen_ai.usage.input_tokens", "gen_ai.usage.output_tokens", "gen_ai.usage.cache_read.input_tokens", "gen_ai.usage.cache_write.input_tokens", "anthropic.organization.id", "anthropic.workspace.id", "anthropic.request.id", "anthropic.session.id", "anthropic.session.outcome.id", "anthropic.session.outcome_evaluation.result", "anthropic.session.outcome_evaluation.iteration", "anthropic.content.truncated", "error.type", "http.request.method", "http.route", "http.response.status_code", "server.address", "server.port"]) where "${env:FI_CAPTURE_CONTENT:-false}" != "true"
          # Error text can echo the request. Keep the fact of the error, not the words.
          - set(status.message, "error") where status.message != "" and "${env:FI_CAPTURE_CONTENT:-false}" != "true"
      - context: spanevent
        statements:
          - delete_matching_keys(attributes, ".*") where "${env:FI_CAPTURE_CONTENT:-false}" != "true"

  # Anthropic caps content per span, not per batch. The downstream receiver limits a request to
  # 16 MiB; one span per export prevents hundreds of full-content spans from overflowing it.
  # This count limit is not a general byte-size guarantee for arbitrary/non-native OTLP senders.
  batch:
    send_batch_size: 1
    send_batch_max_size: 1
    timeout: 2s

exporters:
  otlp_http/future_agi:
    traces_endpoint: ${env:FI_TRACES_URL}
    encoding: proto
    compression: none          # avoid relying on an unqualified downstream gzip behavior
    headers:
      X-Api-Key: ${env:FI_API_KEY}
      X-Secret-Key: ${env:FI_SECRET_KEY}

service:
  extensions: [bearertokenauth/anthropic]
  telemetry:
    metrics:
      level: none
    logs:
      level: warn
  pipelines:
    traces:
      receivers: [otlp]
      processors: [resource/future_agi, transform/anthropic, batch]
      exporters: [otlp_http/future_agi]
```

Generate a destination token without printing it, then enter your Future AGI keys without putting them in shell history. Keep the token in your secret manager; you will need it again when configuring the destination. Run these commands in the shell that starts Docker:

```bash
export ANTHROPIC_DEST_TOKEN="$(openssl rand -hex 32)"
read -r -s -p "Future AGI API key: " FI_API_KEY; echo
export FI_API_KEY
read -r -s -p "Future AGI secret key: " FI_SECRET_KEY; echo
export FI_SECRET_KEY

docker run -d --name cma-otelcol --memory 512m -p 127.0.0.1:4318:4318 \
  -v "$PWD/otelcol.yaml:/etc/otelcol/config.yaml:ro" \
  -e ANTHROPIC_DEST_TOKEN -e FI_API_KEY -e FI_SECRET_KEY \
  -e FI_CAPTURE_CONTENT="${FI_CAPTURE_CONTENT:-false}" \
  -e FI_PROJECT_NAME=claude-managed-agents \
  -e FI_TRACES_URL=https://api.futureagi.com/tracer/v1/traces \
  otel/opentelemetry-collector-contrib:0.162.0 --config /etc/otelcol/config.yaml
```

`ANTHROPIC_DEST_TOKEN` is the secret shared with Anthropic; the receiver only accepts `Authorization: Bearer <that token>`. Do not expose TCP 4318 outside the host or place the keys in your shell history. For a self-hosted Future AGI use `FI_TRACES_URL=http://<your collector>:<HTTP port>/v1/traces`; the hosted URL above is the Future AGI OTLP traces endpoint. `service.telemetry.metrics.level: none` turns off the collector's own metrics endpoint, and `compression: none` keeps the export plain. The collector sends a single span per downstream request to avoid aggregating multiple full-content spans beyond the receiver request limit. This does not bound arbitrary OTLP payloads by byte size; test request sizes before enabling full content.

Changing `FI_CAPTURE_CONTENT` requires recreating the container: export the new value, run `docker rm -f cma-otelcol`, then rerun the command above. `docker restart` retains its original environment. Keep the default `false` unless your privacy policy permits content export.

## 2. Add the destination in Anthropic

Adding a destination sends the selected workspaces' activity to your collector and Future AGI, under their access and retention policies. An authorized organization admin must choose and approve the destination and workspace scope before enabling it.

### In the Claude Console

1. Open your organization's [OpenTelemetry settings page](https://platform.claude.com/settings/telemetry-destinations) and click **Add destination**.
2. Set **Provider** to **Custom**.
3. **OTLP endpoint URL**: the base URL of the collector, for example `https://otel.example.com`. Do not add `/v1/traces`, because Anthropic adds it.
4. **Request headers**: `authorization` with the value `Bearer <your ANTHROPIC_DEST_TOKEN>`. Anthropic does not show header values again after you save.
5. **Content mode**: **Metadata only** (the default and the one to start with), or **Full content**. See [Content modes](#content-modes).
6. **Workspaces**: the workspaces whose spans the destination receives.
7. Click **Add destination**, then **Test** in the destination's **More actions** menu.

### With the Admin API

The same destination, created with the beta header `telemetry-destinations-2026-08-11` and an admin key:

Use the workspace ID (`wrkspc_...`) for the workspace you approved, not an organization-wide setting. Enter the Admin API key without putting it in shell history. The destination token must be the same value you supplied to Docker.

```bash
read -r -s -p "Anthropic Admin API key: " ANTHROPIC_ADMIN_API_KEY; echo
read -r -p "Selected Anthropic workspace ID: " ANTHROPIC_WORKSPACE_ID
jq -n --arg workspace "$ANTHROPIC_WORKSPACE_ID" \
  '{endpoint_url:"https://otel.example.com", headers:{authorization:("Bearer " + env.ANTHROPIC_DEST_TOKEN)},
    traces:{content_mode:"metadata_only"},
    workspaces:{type:"include", workspace_ids:[$workspace]}}' |
curl --fail-with-body -sS "https://api.anthropic.com/v1/organizations/telemetry_destinations" \
  -H "x-api-key: $ANTHROPIC_ADMIN_API_KEY" \
  -H "anthropic-version: 2023-06-01" \
  -H "anthropic-beta: telemetry-destinations-2026-08-11" \
  -H "content-type: application/json" \
  --data-binary @-
```

Anthropic documents the same call for its CLI and SDKs (`client.beta.organization.telemetry_destinations.create(...)`). The settings come from Anthropic's [API tracing guide](https://platform.claude.com/docs/en/manage-claude/opentelemetry/api); check it for the current field names while the feature is in beta.

## What shows up in Observe

Run a session, then open the project in Observe. Spans can take up to a minute to arrive. A session with a tool call and two model requests should appear as:

```text
anthropic.sessions.events.send     chain
  anthropic.session.turn <agent>   agent
    anthropic.model_request        llm     1,834 input / 41 output tokens
    anthropic.tool_use bash        tool
    anthropic.model_request        llm     1,907 input / 18 output tokens
```

| Anthropic | Observe |
| --- | --- |
| `gen_ai.operation.name` = `invoke_agent` (the agent turn) | Agent span, named `anthropic.session.turn <agent name>` |
| `chat` (`anthropic.model_request`) | LLM span, with `gen_ai.request.model` and `gen_ai.usage.input_tokens` and `output_tokens` |
| `execute_tool` (`anthropic.tool_use <tool>`) | Tool span |
| Outcome-evaluation iterations (`anthropic.session.outcome_evaluation`) | Evaluator span; tokens on the evaluation are separate from model-request totals |
| Session request spans (`anthropic.sessions.*`) and other operations | Chain span |
| `anthropic.session.id` | Copied to `session.id`, so each Managed Agents session is one Observe session |
| `error.type`, error status | Span status `ERROR` |
| `gen_ai.input.messages`, `gen_ai.output.messages` (turn), `gen_ai.tool.call.arguments`, `anthropic.tool_result.content` (tool) | Input and Output panes, only when you turn content on |

Cost depends on Observe pricing support for the model name and is not guaranteed by token attributes alone. Cache token counts (`gen_ai.usage.cache_read.input_tokens`) stay as raw attributes.

## Content modes

Anthropic's **Metadata only** mode, the default, exports identifiers, timing, status, token counts, and agent and tool names. **Full content** adds prompts, replies, tool arguments and tool results. Pick the mode in the destination. The collector adds a second gate: with `FI_CAPTURE_CONTENT` unset or `false` (the default), it keeps only an explicit set of metadata attributes, removes event attributes, and replaces error text with `error`, even if the destination was left on Full content. Do not send arbitrary non-Anthropic resources or span names through this recipe. To see content in Observe, set the destination to **Full content** and start the collector with `-e FI_CAPTURE_CONTENT=true`.

Identifiers are exported in both modes: organization, workspace, session, agent and request IDs. Prompts and tool payloads can hold personal data, so start with Metadata only. Anthropic caps content at 0.75 MB per span by default and marks a shortened span with `anthropic.content.truncated`. If your organization has a HIPAA, FERPA or K-12 data-handling restriction with Anthropic, destinations export metadata only whatever their content mode.

## Link to your own traces

If your application calls the Sessions API inside its own OpenTelemetry span, send the W3C `traceparent` header with each request. Anthropic reads it and nests its spans under yours, so a session appears inside your own trace. The Claude SDKs do this for you when tracing is set up; with plain HTTP, copy the active span's context into the headers with your propagator, as in Anthropic's [example](https://platform.claude.com/docs/en/manage-claude/opentelemetry/api#4-connect-api-spans-to-your-own-traces). If the sampled flag in the header is off, Anthropic does not emit the request's spans. Your own spans reach Future AGI through your own exporter, as for any [traceAI](/docs/sdk/tracing/instrumentors) application, with the same project name.

## Limits

- **Beta.** Anthropic's OpenTelemetry export is in beta, and span names and attributes can change.
- **At-least-once delivery.** A destination can receive the same span more than once, and a span can be lost before delivery. Check for duplicates in your project when testing delivery.
- **No zero data retention.** Managed Agents is not eligible for zero data retention, and OpenTelemetry export does not change that.
- **Admin only.** Only an organization admin can add or change a destination. Anthropic allows 10 destinations per organization and 20 request headers per destination.
- **Delivery rules.** Each delivery must finish its TLS handshake and send response headers within 5 seconds, and times out after 10 seconds in total. A destination is disabled after a redirect, a non-public hostname, or 24 hours of failed deliveries.

## Verify the destination

Use the destination's **Test** action, then run a real Managed Agents session in a selected workspace. Confirm the project, session grouping, model-request usage and tool calls in Observe. With content capture off, verify that your own test prompt does not appear in stored attributes or events. If you opt into full content, check the downstream receiver's request-size behavior with your own traffic before production use.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| The destination's **Test** or delivery shows Failing with HTTP 401 | The `authorization` header value does not match `ANTHROPIC_DEST_TOKEN`, or it lacks the `Bearer ` prefix. |
| Failing with HTTP 400 from the collector | The request was not OTLP protobuf, or Future AGI rejected the batch. Look at the collector's log for the Future AGI status. A 401 from Future AGI means the key or secret is wrong. |
| Destination is **Disabled** | The hostname resolves to a non-public address, the endpoint answered with a redirect, or every delivery failed for 24 hours. Fix it, then enable it again. |
| No spans for a workspace | The destination must cover that workspace. Spans can take up to a minute to arrive. |
| Spans arrive but Input and Output are empty | Content is off by design. Use **Full content** in the destination and `FI_CAPTURE_CONTENT=true` on the collector. |
| Tokens and model appear, cost is $0.00 | Observe has no price for the model name. Cost is not computed from Anthropic's token counts. |
