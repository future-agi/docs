## About

Augment's Auggie CLI runs [hooks](https://docs.augmentcode.com/cli/hooks) at fixed points of a session and passes each one a JSON event on stdin. This page registers the Future AGI [hook-to-OTLP emitter](/docs/integrations/coding-agents/hook-to-otlp) on those hooks, so every Auggie conversation shows up in Future AGI as one trace:

```
Auggie session            one Auggie conversation (conversation_id), last stop cause
├── launch-process        tool call: status, MCP flag
├── view
├── str-replace-editor    file-change count and change types
└── Agent stop            stop cause (end_turn, interrupted, max_iterations, empty_completion, error)
```

Auggie hooks carry no turn id, tool call id, or timing, so tools and stops sit directly under the session in arrival order.

This is not the same as:

- **Augment in VS Code or JetBrains.** Augment's settings table says the IDE extensions read `~/.augment/settings.json`, but Augment does not document that they fire the same hook events. Only the CLI is supported here.
- **Augment's Context Engine** as a retrieval product, or Auggie's debug log file. Neither is read.

## 1. Install the hook

Clone the examples and run the installer. It copies the emitter, the Augment adapter, and a small `futureagi-hook.sh` wrapper into `~/.augment/fi-hook-to-otlp/`, and writes `~/.augment/settings.json` if you do not have one. If the file exists, the installer leaves it alone and prints the `hooks` entries to merge.

```bash
git clone --depth 1 https://github.com/future-agi/docs.git fi-docs
fi-docs/examples/coding-agents/augment-code/install.sh
```

The hook entries it writes (with your home directory in place of `/Users/you`):

```json
{
  "hooks": {
    "SessionStart": [{ "hooks": [{ "type": "command", "command": "/Users/you/.augment/fi-hook-to-otlp/futureagi-hook.sh", "timeout": 5000 }] }],
    "PostToolUse":  [{ "matcher": ".*", "hooks": [{ "type": "command", "command": "/Users/you/.augment/fi-hook-to-otlp/futureagi-hook.sh", "timeout": 5000 }] }],
    "Stop":         [{ "hooks": [{ "type": "command", "command": "/Users/you/.augment/fi-hook-to-otlp/futureagi-hook.sh", "timeout": 5000 }] }],
    "SessionEnd":   [{ "hooks": [{ "type": "command", "command": "/Users/you/.augment/fi-hook-to-otlp/futureagi-hook.sh", "timeout": 5000 }] }]
  }
}
```

- Augment documents a hook command as the path to a script with a `.sh` extension (or Windows `.ps1`, `.cmd`, `.bat`). So the hook command is a script, `futureagi-hook.sh`, and the guard that other coding-agent pages put in the hook command lives inside it: the script runs `(python3 -B emit.py augment 2>/dev/null || true)` with its output discarded, and always exits 0. A missing `emit.py`, a missing `python3`, or an emitter crash therefore never reaches Auggie as an error or as output.
- The wrapper prints nothing, so Auggie has nothing to act on. Auggie adds plain-text `SessionStart` output to the agent's context, and reads `{"decision": "block"}` on `Stop` as "keep working". With no output, `Stop` is observed and never blocked.
- If your home directory contains a space or a shell character, the installer single-quotes the path, which Auggie accepts. A home directory that contains a single quote cannot be registered: the installer stops before copying anything.
- `timeout` is in milliseconds. The emitter sends in a background process and returns in well under a second.
- No `metadata` block is set. Leave `includeUserContext` and `includeConversationData` off: the adapter ignores the `context`, `conversation`, and `user_prompt` fields anyway, so turning them on only adds your email and conversation text to the hook input on your machine.
- `PreToolUse` is deliberately not registered: it is the hook that can block a tool, and tracing never takes part in approving or blocking. As a result, tool spans have no measured duration.

`~/.augment/settings.json` is also read by the Augment VS Code and JetBrains extensions. To trace one repository only, and keep the hooks out of that shared file, install into the repository's workspace settings instead, which only the CLI reads:

```bash
fi-docs/examples/coding-agents/augment-code/install.sh --project /path/to/your/repo
```

This writes `<repo>/.augment/settings.local.json` and leaves `~/.augment/settings.json` alone. If you installed the user-level hooks earlier, remove their entries from `~/.augment/settings.json`, otherwise every repository is still traced. (Auggie 0.36.0 runs an identical hook command only once when several settings files register it, so keeping both does not send tool calls twice.)

The workspace file contains your home directory path, so do not commit it. Unless git already ignores the file, the installer adds it to the repository's `.git/info/exclude`, a local ignore list that is never committed, so `git add -A` skips it. The installer does not change `.gitignore` or any other tracked file. Outside a git repository it only prints a reminder.

## 2. Add your Future AGI keys

```bash
mkdir -p ~/.config/fi-hook-to-otlp
cat > ~/.config/fi-hook-to-otlp/env <<'EOF'
FI_API_KEY=your-futureagi-api-key
FI_SECRET_KEY=your-futureagi-secret-key
FI_PROJECT_NAME=auggie-sessions
EOF
chmod 600 ~/.config/fi-hook-to-otlp/env
```

Variables set in the environment Auggie runs in take precedence over the file. For a self-hosted Future AGI, also set `FI_BASE_URL` (traces go to `$FI_BASE_URL/tracer/v1/traces`). All settings are listed on the [hook-to-OTLP page](/docs/integrations/coding-agents/hook-to-otlp#configuration).

## 3. Run a session

In a repository, run Auggie with a prompt that uses a tool:

```bash
auggie --print "List the files in this folder and read README.md"
```

Open **Observe** in Future AGI and select the project (`auggie-sessions` above). The conversation appears as one trace named **Auggie session**. Later prompts in the same interactive session add more tool spans and another **Agent stop** to the same trace.

## What is captured

| Auggie hook | Future AGI span | Fields |
| --- | --- | --- |
| `SessionStart` | **Auggie session** (root) | `session.id` = `conversation_id`. The root span is sent with the first tool or stop span; a session with no activity sends nothing. |
| `PostToolUse` | tool span named after the tool (`launch-process`, `view`, `str-replace-editor`, `save-file`, `codebase-retrieval`, MCP tool names) | `gen_ai.tool.name`, MCP flag (`is_mcp_tool`), file-change count and change types; status `ERROR` when `tool_error` is set, with the message `tool error` (with content capture on, the error text) |
| `Stop` | **Agent stop** | `agent_stop_cause`; status `ERROR` when the cause is `error`. The last cause is also kept on the session span. Auggie 0.36.0 can also report `empty_completion` (not in Augment's docs); it is recorded as-is with status OK. |
| `SessionEnd` | **Auggie session** end | |

## What is not available

- **Turns.** Auggie hooks have no turn id or prompt event in the documented set, so there is no turn span. Each **Agent stop** marks the end of one agent response. (Auggie 0.36.0 also accepts an undocumented `PromptSubmit` hook, which carries the prompt text; it is not used.)
- **Tool duration and tool call ids.** `PostToolUse` carries neither, and `PreToolUse` (which would mark the start) is not registered because it can block tools. Tool spans have no measured duration, and repeated calls of the same tool are told apart only by arrival order.
- **Model name, token counts, and cost.** Not in the hook input. The model display name exists only inside the `includeUserContext` block, which this integration does not use.
- **Prompt and response text.** Not forwarded, even with content capture on.
- **Augment IDE extensions, webhooks, and log files.** See [About](#about).

## Privacy

By default only structure and metadata leave your machine: the conversation id, tool names, MCP flag, file-change counts and types, stop causes, and statuses. A failed tool is marked with the fixed message `tool error`, never with the error text.

- **Not exported by default**: tool input (`tool_input`), tool output (`tool_output`), and tool error text (`tool_error`).
- **Never exported, even with content capture on**: `workspace_roots`; the `context` object (`userEmail`, model display name); the `conversation` object (prompt, response, code); `user_prompt`, which Auggie 0.36.0 adds to tool events when `includeConversationData` is on; `_exchange`, an internal object Auggie 0.36.0 passes on `Stop`; `mcp_metadata`; and file paths and contents from `file_changes`.
- **MCP server names.** Augment names MCP tools `<tool>_<server>`, so the server name is exported as part of the tool name.

To include tool input, output, and error text, add `FI_HOOK_CAPTURE_CONTENT=1` to the env file. Paths inside that content (for example the `path` a `view` call reads, or a path in an error) are then exported too, with the user name in home-directory paths replaced by `<user>`. Each field is capped at 4096 characters and common key formats are replaced with `[REDACTED]`. See [Privacy](/docs/integrations/coding-agents/hook-to-otlp#privacy) for details.

## Verification status

The configuration above passes the hook-configuration validator shipped inside Auggie 0.36.0, and the payload fields the adapter reads match the ones that build constructs. The hook commands were run the way Auggie 0.36.0 runs them, using the command-handling code from its bundle. The adapter was tested end to end with payloads shaped as Augment documents them, sent through `futureagi-hook.sh` into Future AGI. A signed-in Auggie session has not been traced yet: Auggie requires an Augment account before it starts a session or fires any hook. Still to check in a real session: the exact `Stop` payload, and what a resumed conversation (`auggie --continue`) sends.

## Troubleshooting

**No trace appears.**
1. Run `auggie --log-level debug --log-file - --print "..."` and look for `Loaded hooks configuration` and `Hook execution completed` lines. `Invalid hooks configuration` names the field Auggie rejected. `--log-level` and `--log-file` are not listed in `auggie --help` in 0.36.0; without `--log-file -`, Auggie writes the log to `augment-log.txt` in your temp directory (`$TMPDIR` on macOS) instead of the terminal.
2. Check that `futureagi-hook.sh` is executable (`chmod +x`) and that `python3` resolves for Auggie.
3. Set `FI_HOOK_LOG_FILE=/tmp/fi-hook.log` in `~/.config/fi-hook-to-otlp/env` and run again. No lines: Auggie did not run the wrapper. `error=` lines: the collector is unreachable. `http=401`/`403`: wrong keys.

**A resumed conversation looks wrong.** Resuming with `auggie --continue` or `--resume` has not been verified. If Auggie reuses the conversation id, the new tool spans join the original trace, and the session span restarts at the resume time while the earlier tool spans keep their times.

## Uninstall

1. Remove the four hook entries from `~/.augment/settings.json` (or the workspace settings file). To pause tracing without editing settings, set `FI_HOOK_DISABLED=1` in `~/.config/fi-hook-to-otlp/env`.
2. Then delete `~/.augment/fi-hook-to-otlp/`. If you delete the folder first, Auggie reports a failed hook on each event but keeps working: none of these hooks can block it.
