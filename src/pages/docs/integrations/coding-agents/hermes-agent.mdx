title: "Hermes Agent CLI tracing"
description: "Set up Future AGI tracing for Hermes in one command, then inspect prompts, model requests, tool calls and conversation sessions."
---

Trace each [Hermes Agent](https://hermes-agent.nousresearch.com/) CLI prompt and its model requests and tools in Future AGI. Turns from one conversation share a session.

You need Hermes with native plugin support and a model provider configured, Git, and Node.js 22.16+ on macOS or Linux for setup. Tracing runs in the maintained Python plugin; Node is not needed while Hermes runs. This guide covers the CLI. Desktop and messaging-platform gateway integrations are not yet available.

## 1. Get your keys

Create an API key and secret key on the [Future AGI Keys page](https://app.futureagi.com/dashboard/keys). Keep them for the terminal prompts in the next step; do not paste them into your Hermes conversation.

## 2. Set up tracing

```bash
npx @traceai/agents setup hermes --project coding-agents
```

Enter your keys in the masked prompts. Setup validates them, saves a private credential profile and installs the plugin through Hermes. Review Hermes' Python dependency prompt. The installer uses your active Hermes profile, or your explicit `HERMES_HOME`; it does not change your model or grant plugin capabilities silently.

**Content capture is on.** Prompts, model responses and tool results may include file contents or secrets the agent reads. For metadata only, add `--no-capture-content` to the setup command.

## 3. Run Hermes and inspect the trace

Start a new session in a project with a `README.md`:

```bash
hermes chat --oneshot -q "Read README.md and summarize this project."
```

Open **Observe** in Future AGI, select **coding-agents**, and open the **hermes.turn** trace. Expand a model request to see its input, output and available token usage, or a tool to see its arguments, result and duration. Open **Sessions** to follow multiple turns in one conversation.

The final turn is exported after completion; you do not need to send another prompt. For an interactive conversation, run `hermes chat` normally.

## Check status or stop tracing

```bash
npx @traceai/agents status hermes --check
npx @traceai/agents doctor hermes
npx @traceai/agents disable hermes
npx @traceai/agents enable hermes
```

Status shows plugin registration, whether the plugin has received a turn, and recent export results. `--check` validates the connection; `doctor` includes the same check. Add `--json` for machine-readable output. Delivery counters describe the latest process, not lifetime totals across concurrent Hermes processes. Open Observe to confirm that your trace is visible.

Disable prevents collection and fences queued exports. Current Hermes CLI clients can reuse a persistent native gateway: a new CLI window does not restart that process. After re-enabling or changing destination/privacy settings, restart the gateway when idle with `hermes gateway restart`. Setup does not restart it automatically.

Environment overrides, including `FI_AGENT_ENABLED=false`, must be set in the gateway launch environment. Setting a variable only on a new CLI client cannot change an already-running gateway. Use `disable hermes` for immediate shutdown of tracing without credentials or network access.

To remove a plugin installed by shared setup:

```bash
npx @traceai/agents uninstall hermes
```

Setup does not overwrite existing plugins, and uninstall leaves installations it does not own untouched.

## Configuration

Credentials are saved with owner-only permissions in `${XDG_CONFIG_HOME:-$HOME/.config}/futureagi/agents/credentials.json`. The active Hermes home contains a non-secret `futureagi.json` profile reference. No collector, daemon or copied hook scripts are required.

| Setting | Purpose |
| --- | --- |
| `FI_API_KEY`, `FI_SECRET_KEY` | Override saved credentials as a complete pair. A single environment key never mixes with a saved key. |
| `FI_PROJECT_NAME` | Destination project name; the quick start saves `coding-agents`. |
| `FI_BASE_URL` | API origin, default `https://api.futureagi.com`; `/tracer/v1/traces` is appended. |
| `FI_OTLP_ENDPOINT` | Exact traces URL; takes precedence over the base URL. |
| `FI_USER_ID` | Explicit user identity; shared setup otherwise creates an opaque local ID. |
| `FI_AGENT_CAPTURE_CONTENT=false` | Metadata-only tracing; new shared setups capture content by default. |
| `FI_AGENT_ENABLED=false` | Disable tracing in the environment that launches Hermes. |
| `FI_HIDE_INPUTS`, `FI_HIDE_OUTPUTS`, `FI_HIDE_ERROR_DETAILS` | Retain stricter input, output or error privacy controls. |
| `FI_HERMES_MAX_CHARS` | Per-field content cap, default 20,000 characters, bounded to 256–20,000. |
| `FI_AGENT_CONFIG_DIR` | Override the shared credential/configuration directory. |
| `HERMES_HOME` | Select a Hermes home explicitly; otherwise setup discovers your active profile. |

### User and project scope

Shared setup saves a user configuration by default. Commands also inspect the current directory's project configuration. To ignore that repository layer for a setup or diagnostic command, add `--user-only` (without `--project-dir`):

```bash
npx @traceai/agents setup hermes --project coding-agents --user-only
npx @traceai/agents status hermes --check --user-only
```

`--user-only` applies to that CLI command; it does not permanently disable project discovery when Hermes runs. `--scope user` chooses where setup writes settings, whereas `--user-only` skips reading repository overrides.

For a CLI project override:

```bash
npx @traceai/agents setup hermes --project my-project --scope project --project-dir /absolute/project/path
```

Non-secret settings go in `.futureagi/agents.json`, keyed by `hermes`. Credentials stay in the private store, bound to that project's canonical path. Launch Hermes from that directory. A project cannot raise your saved privacy ceiling or send saved keys to an unapproved destination.

### Python-only alternative

If Node is not installed, configure `FI_API_KEY`, `FI_SECRET_KEY` and optionally `FI_PROJECT_NAME` through your secret manager, then use the native installer:

```bash
hermes plugins install future-agi/traceAI/python/frameworks/hermes-agent/hermes-plugin/futureagi --enable
```

This route uses the Python plugin independently of npm. Env-only installations retain their earlier metadata-only default; set `FI_AGENT_CAPTURE_CONTENT=true` to capture content. `FI_HERMES_CAPTURE_CONTENT` remains a compatibility alias. Use `hermes plugins list --json` for native registration status.

## What is captured

| Trace item | Details |
| --- | --- |
| **hermes.turn** (`AGENT`) | User message, final answer, session/turn/task IDs and completion state. Failed or interrupted turns are not reported as successful. |
| **chat &lt;model&gt;** (`LLM`) | Actual provider attempt, model/provider host, request ID, available token/cache/reasoning usage, finish reason and time to first streamed chunk. Retries remain separate attempts. |
| **Tool name** (`TOOL`) | Actual call ID, arguments, result, duration and outcome from the completed-tool callback. |
| **Compaction and approval events** | Events on an existing turn when the Hermes version exposes these observers. No extra prompt or generation is created. |

Turn summaries do not duplicate model token usage. In-process subagent turns nest under their parent turn when Hermes provides parent IDs, and carry their own session IDs. Arbitrary subprocess ancestry is not inferred. A tool with no completion callback has no tool span.

Cost, auxiliary model calls such as titling/compression, and streaming deltas are not synthesized. The plugin never registers a fail-closed tool-policy callback or returns directives that change agent behavior.

## Privacy

The plugin observes hook payloads rather than reading transcripts, memory, skills, `.env` files or keychains. Captured fields are bounded and configured Future AGI credentials are redacted best-effort. This is not a general secret or PII scrubber. System prompts are represented by size only. Model IDs, provider hostnames, tool names and source IDs are metadata and can themselves be sensitive.

A private OpenTelemetry provider leaves Hermes' global provider and signal handlers alone. Exports use a bounded in-memory queue, explicit authentication/project headers and no HTTP redirects. Undeliverable data is dropped after bounded attempts; there is no disk content journal or exactly-once delivery guarantee.

## Troubleshooting

**Not registered.** Check `hermes plugins list --json` in the same Hermes profile. Run `hermes plugins enable futureagi` to complete dependency consent. If an older plugin is installed, update it through Hermes before repeating shared setup.

**Not activated or settings have not changed.** Start a new CLI session after installation and send a prompt. If Hermes reuses a persistent gateway, restart it when idle with `hermes gateway restart`, then try again. A new CLI window does not update that gateway's launch environment.

**No trace appears.** Run `npx @traceai/agents doctor hermes`, verify the project and endpoint, and check that neither the saved configuration nor `FI_AGENT_ENABLED` disables tracing. Environment credential overrides must contain both keys. Run diagnostics from the same project directory and Hermes profile as your session.

**Hermes takes a few seconds to exit.** An unreachable endpoint can delay final delivery briefly. The plugin then drops the undeliverable spans rather than waiting indefinitely.

**A turn is unfinished or interrupted.** Hermes stopped or reset before normal completion. Open spans are closed with the appropriate incomplete/interrupted state.
