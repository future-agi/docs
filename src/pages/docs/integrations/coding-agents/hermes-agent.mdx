## About

[Hermes Agent](https://hermes-agent.nousresearch.com/) runs plugins that observe its agent loop through [documented hooks](https://hermes-agent.nousresearch.com/docs/user-guide/features/hooks). The Future AGI plugin, `traceAI-hermes-agent`, listens to those hooks and exports every Hermes turn to Future AGI as one trace:

```
hermes.turn            AGENT   one user message to final answer: session, platform, outcome
├── chat gpt-6-luna    LLM     one provider request: model, provider, tokens, finish reason
├── search_files       TOOL    one tool call: name, call id, duration, status
├── read_file          TOOL
└── chat gpt-6-luna    LLM
```

Every span carries the Hermes session id as `session.id`, so the turns of one `hermes chat` session (or one gateway conversation) group into one Future AGI session. A subagent's turn is nested under the turn that started it.

The plugin is opt-in: Hermes loads it only after `hermes plugins enable futureagi`. It reads nothing from disk; everything it exports comes from the hook payloads.

This is not the same as:

- **Hermes' Langfuse plugin.** It sends turns to Langfuse's API, which Future AGI does not ingest. Pointing it at Future AGI does not work.
- **Hermes gateway monitoring** (`monitoring.export.otlp`). That is OTLP for gateway health and message delivery, not agent turns.
- **Model-provider tracing** for whatever model Hermes calls. The spans here come from Hermes' own loop.

## 1. Install the plugin

How you install depends on who manages the Python environment Hermes runs in.

**Installed with Hermes' installer or Hermes Desktop** (Hermes manages its environment): install the directory plugin. When you enable it, Hermes asks to install its Python dependency, `traceAI-hermes-agent`, and installs it into Hermes' own environment.

```bash
hermes plugins install future-agi/traceAI/python/frameworks/hermes-agent/hermes-plugin/futureagi
hermes plugins enable futureagi
```

**A source checkout, container image or other environment you manage**: install the package into the Python that runs Hermes. It registers the plugin through Hermes' `hermes_agent.plugins` entry point.

```bash
/path/to/hermes/python -m pip install traceAI-hermes-agent
hermes plugins enable futureagi
```

`hermes plugins list` shows `futureagi` as enabled. Plugins are per Hermes home: with profiles or a custom `HERMES_HOME`, enable it in each home you want traced.

## 2. Add your Future AGI keys

Put them in the Hermes home's `.env` (`~/.hermes/.env` by default), which Hermes loads at start, or in the environment Hermes runs in:

```bash
FI_API_KEY=your-futureagi-api-key
FI_SECRET_KEY=your-futureagi-secret-key
FI_PROJECT_NAME=hermes-agent
```

| Variable | Default | Meaning |
| --- | --- | --- |
| `FI_API_KEY`, `FI_SECRET_KEY` | none | Required. Without them the plugin logs one warning and does nothing. |
| `FI_PROJECT_NAME` | `hermes-agent` | Future AGI project. |
| `FI_BASE_URL` | `https://api.futureagi.com` | For a self-hosted Future AGI. Spans go to `$FI_BASE_URL/tracer/v1/traces`. |
| `FI_HERMES_CAPTURE_CONTENT` | off | `true` also exports prompt and tool text. See [Privacy](#privacy). |
| `FI_HERMES_MAX_CHARS` | `8000` | Per-field cap on captured text. |

Restart Hermes, and its gateway if you run one, so the plugin and the keys are loaded.

## 3. Run a session

```bash
hermes chat -q "List the files in this folder and read README.md"
```

Open **Observe** in Future AGI and select the project (`hermes-agent` above). The turn appears as a trace named **hermes.turn**. Spans are batched and flushed when Hermes exits, so a one-shot `hermes chat -q` shows up as soon as it returns; a long-running gateway sends them within a few seconds.

`run_e2e.sh` in the examples folder does all of this in a temporary directory: a fresh Hermes checkout and virtualenv, its own `HERMES_HOME`, the plugin, and one turn. It never reads or changes your `~/.hermes` or a running gateway.

```bash
git clone --depth 1 https://github.com/future-agi/docs.git fi-docs
FI_API_KEY=... FI_SECRET_KEY=... \
MODEL_BASE_URL=https://your-openai-compatible-endpoint/v1 MODEL_API_KEY=... MODEL_ID=... \
  fi-docs/examples/coding-agents/hermes-agent/run_e2e.sh
```

## What is captured

| Hermes hook | Span | Fields |
| --- | --- | --- |
| `pre_llm_call` | **hermes.turn** (`AGENT`) start | `session.id`, turn id, task id, platform (`cli`, `telegram`, ...), model, first-turn flag, parent session |
| `pre_api_request` | **chat &lt;model&gt;** (`LLM`) start | `gen_ai.request.model`, `gen_ai.provider.name`, provider host, API mode, attempt and retry counts, message and tool counts, approximate input tokens |
| `post_api_request` | **chat &lt;model&gt;** end | `gen_ai.response.model`, finish reason, `gen_ai.usage.input_tokens` (including cached), `output_tokens`, `total_tokens`, cache read and write tokens, reasoning tokens, time to first streamed chunk |
| `api_request_error` | **chat &lt;model&gt;**, status `ERROR` | Hermes' error category (`overloaded`, `rate_limit`, `timeout`, ...), HTTP status, retryable flag. A retried request shows the failed attempt and the retry as two spans |
| `pre_tool_call`, `post_tool_call` | span named after the tool (`TOOL`) | `gen_ai.tool.name`, `gen_ai.tool.call.id`, status, duration; `ERROR` when Hermes reports `error`, `blocked`, `timeout` or `cancelled` |
| `on_session_end` | **hermes.turn** end | completed, failed, interrupted, exit reason; `ERROR` when the turn failed |
| `subagent_start` | | the child session's turn becomes a child of the parent turn |
| `on_session_finalize`, process exit | | spans still open are closed (`hermes.unfinished`) and flushed |

## What is not available

- **Cost.** Hermes passes token counts to the hooks, not its cost estimate. Future AGI computes cost from the model name only when it has pricing for that model.
- **One trace per session.** Each turn is its own trace; the session groups them.
- **Gateway delivery, cron and kanban events.** They are not agent turns and are not traced.
- **Auxiliary model calls** (titling, compression, vision, approvals). Hermes reports them on separate hooks that this plugin does not use.
- **Streaming deltas.** The model span covers the whole request; time to first chunk is recorded, individual chunks are not.
- **Gateway sessions were not run in our test.** The hooks are the same in the gateway, so turns from messaging platforms are traced the same way, with the platform name on the turn.

## Privacy

By default the plugin reads no text from the hook payloads. It exports ids, the platform, model and provider names, the provider host (not the full URL), token counts, message and tool counts, durations and outcomes.

- **Not exported by default:** the user message, the assistant's answer, conversation history, the request sent to the model, tool arguments, tool results, and provider or tool error text (error statuses carry Hermes' category, such as `rate_limit` or `tool_error`).
- **Never read:** Hermes' session transcripts, `config.yaml`, memory, skills or other files under `~/.hermes`.

To include content, add `FI_HERMES_CAPTURE_CONTENT=true` to `.env` and restart Hermes. The turn gets the user message as input and the final answer as output, each model call gets Hermes' sanitized request payload as input and the assistant text or requested tool calls as output, each tool call gets its arguments and result, and error statuses carry the error text. Each value is cut at `FI_HERMES_MAX_CHARS` characters.

## Troubleshooting

**No trace appears.**
1. `hermes plugins list` must show `futureagi` as enabled in the Hermes home you are using (`HERMES_HOME`, profile).
2. `HERMES_PLUGINS_DEBUG=1 hermes plugins list` shows whether the plugin was discovered and why it was skipped.
3. Check `~/.hermes/logs/agent.log` for `traceAI-hermes-agent`: the plugin logs one warning when `FI_API_KEY` / `FI_SECRET_KEY` are missing, and setup failures.
4. A gateway loads plugins at start: restart it after enabling the plugin or changing `.env`.

**`ModuleNotFoundError: traceai_hermes_agent`.** The directory plugin was installed with `--no-deps`, or the dependency step was declined. Re-run `hermes plugins enable futureagi` and accept the dependency, or install `traceAI-hermes-agent` into Hermes' Python.

**The turn is marked `hermes.interrupted` or `hermes.unfinished`.** You stopped the turn (Ctrl+C reports `interrupted`), or Hermes exited or tore the session down before reporting the end of the turn (`unfinished`). Either way the open spans are closed and sent.
