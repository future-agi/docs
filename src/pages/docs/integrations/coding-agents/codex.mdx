title: "Trace OpenAI Codex CLI with Future AGI"
description: "Connect Codex CLI to Future AGI with one setup command, then inspect user turns, model attempts, token usage, and tool calls."
---

Trace each Codex prompt in Future AGI, with model attempts and tool calls below it. Prompts in the same conversation appear together in **Sessions**.

This integration is for local Codex CLI **0.167.0** on Linux, with Node.js **22.16 or later in the 22.x series**, or **24.x**. Codex must already be installed and connected to your model provider. For an application using the Codex SDK, use the separate [Codex SDK integration](/docs/integrations/coding-agents/codex-sdk).

## 1. Get your Future AGI keys

Open [API keys](https://app.futureagi.com/dashboard/keys) in Future AGI. You need an API key and its secret key. Keep them out of Codex conversations and source control.

## 2. Connect Codex

Run this command in your terminal:

```bash
npx @traceai/agents setup codex --project coding-agents
```

Setup asks for your keys without echoing them, checks the destination, saves a private configuration, and installs the native Codex plugin. It does not change your model provider or project permissions.

Open Codex and use **`/hooks`** to review the **Future AGI** hook definitions. Setup reports `TRUST_REQUIRED` until you approve the exact definitions in Codex. Restart an existing Codex session after installation or review.

Content capture is on by default. Prompts, model responses, and tool input/output may include file text or secrets Codex reads. To collect structure and usage without this content, add `--no-capture-content` to setup.

## 3. Run Codex and open the trace

Use Codex normally, or run a prompt from your repository:

```bash
codex exec "Read README.md and summarize the setup steps."
```

In Future AGI, open **Observe**, select **coding-agents**, and open the **codex** trace. Expand a **codex.model_attempt** to inspect the model and reported usage, or a tool span to inspect its input, output, and outcome. Open **Sessions** to follow subsequent prompts in the conversation.

The last prompt exports when Codex finishes it; you do not need to send another prompt.

## Configuration

Setup saves credentials separately from the Codex configuration, in a private file under `~/.config/futureagi/agents`. The Codex settings file is `$CODEX_HOME/futureagi.json`, or `~/.codex/futureagi.json` when `CODEX_HOME` is unset. Both use owner-only file permissions.

| Setting | Purpose |
| --- | --- |
| `FI_API_KEY` and `FI_SECRET_KEY` | Override saved credentials. Set both together. |
| `FI_PROJECT_NAME` | Choose the Future AGI project. |
| `FI_USER_ID` | Set an explicit user identifier. Otherwise, setup generates an opaque local ID. |
| `FI_AGENT_CAPTURE_CONTENT=false` | Turn off prompts, responses, and tool content. |
| `FI_AGENT_ENABLED=false` | Stop collection and export for the process. |
| `FI_OTLP_ENDPOINT` | Use an exact OTLP/HTTP traces URL. |
| `FI_BASE_URL` | Set a self-hosted API origin; the traces path is appended automatically. |

Environment variables override saved settings. Existing `FI_HIDE_*` privacy settings remain effective, including `FI_HIDE_ERROR_DETAILS`.

For a per-repository override, create `.codex/futureagi.json` in that repository without credentials:

```json
{
  "schemaVersion": 1,
  "captureContent": false
}
```

A repository can reduce content capture, but cannot increase your saved privacy setting or silently redirect your saved credentials to another destination.

## Status and troubleshooting

```bash
npx @traceai/agents status codex --check
```

Status distinguishes registration, hook review, observed activation, credential acceptance, and recent exports. A successful HTTP export is not a product-readback check.

- **`TRUST_REQUIRED`:** open Codex's `/hooks` view and review Future AGI's exact hook definitions. Changed definitions require another review.
- **No trace after installation:** restart Codex, submit a prompt, and let it finish. Check that the plugin and its hooks are enabled in Codex.
- **Unsupported version:** use Codex 0.167.0. Setup stops rather than installing against an unrecognized hook schema.
- **Missing content:** check `FI_AGENT_CAPTURE_CONTENT`, `FI_HIDE_*`, and your repository override. Model inputs contain the user prompt, not a complete provider request body; model output is reconstructed from Codex's rollout when available.
- **Authentication or destination error:** run setup again to validate the key pair and destination. Do not put keys in command arguments.

Disable tracing without network access:

```bash
npx @traceai/agents disable codex
```

To remove the native plugin:

```bash
npx @traceai/agents uninstall codex
```

## Privacy and limits

The plugin reads only the rollout paths supplied by Codex hooks under Codex's session directory. It does not search unrelated transcripts or read model-provider authentication caches.

Cross-hook state is sanitized, encrypted, and stored in owner-only local files. Content fields are capped at 20,000 characters, and each turn's journal is bounded. State expires after 24 hours when a subsequent session starts. Known Future AGI credentials receive best-effort redaction; do not rely on redaction to remove every secret from arbitrary file contents.

Model token counts belong to their request attempts and are not repeated as additive turn totals. Costs are omitted when Codex does not report them. Missing lifecycle data is marked incomplete, not inferred successful from silence.

Exports have a bounded deadline and fail open. Tracing cannot approve tool calls or change Codex's result. If a terminal hook is killed or an export fails, trace data can be lost; this is not an exactly-once delivery service.

Local hooks do not run in hosted Codex tasks. This page does not configure hosted tasks or other Codex surfaces.
