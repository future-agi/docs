## About

Kiro IDE runs [agent hooks](https://kiro.dev/docs/hooks/) when its agent starts a session, receives a prompt, uses a tool, or stops, and passes each hook a JSON payload on stdin. This page registers the Future AGI [hook-to-OTLP emitter](/docs/integrations/coding-agents/hook-to-otlp) on those hooks, so every Kiro IDE chat session shows up in Future AGI as one trace:

```
Kiro IDE session               one Kiro chat session (session_id)
└── Kiro IDE turn              one prompt, from Prompt Submit to Agent Stop
    ├── read_file              tool call: name, status, timing from Pre/Post Tool Use
    ├── execute_bash           ERROR when the tool reports failure
    ├── Spec task              Pre/Post Task Execution, task success
    └── File saved             agent file create / save / delete
```

This is not the same as:

- **Kiro CLI.** The CLI has its own setup and adapter: see [Kiro CLI](https://docs.futureagi.com/docs/integrations/coding-agents/kiro-cli).
- **Kiro enterprise OpenTelemetry.** That admin feature pushes daily usage metrics (credits, message and conversation counts) once a day. It has no per-session trace and is not used here.
- **This recipe is observe-only.** It does not register on Kiro's gating hooks (`PreToolUse` or `PreTaskExec`); tool/spec-task spans are emitted after completion.
- **Model-call tracing.** Kiro calls models on AWS; hooks do not expose the model, tokens, or cost.

## 1. Install the hook

Clone the examples and run the installer against your project. It copies the emitter and the Kiro IDE adapter into `.kiro/fi-hook-to-otlp/` and writes `.kiro/hooks/fi-hook-to-otlp.json`. An existing file with that name is left alone.

```bash
git clone --depth 1 https://github.com/future-agi/docs.git fi-docs
fi-docs/examples/coding-agents/kiro-ide/install.sh /path/to/your/project
```

To trace every project on this machine, install global hooks into `~/.kiro/` instead:

```bash
fi-docs/examples/coding-agents/kiro-ide/install.sh --user
```

The hook file registers one command hook per observed trigger. It intentionally excludes gating triggers (`PreToolUse`, `PreTaskExec`). Each entry looks like this (the file lists `SessionStart`, `UserPromptSubmit`, `PostToolUse`, `PostTaskExec`, `PostFileCreate`, `PostFileSave`, `PostFileDelete`, `Stop`, and `SessionEnd`):

```json
{
  "version": "v1",
  "hooks": [
    {
      "name": "Future AGI tracing: tool end",
      "trigger": "PostToolUse",
      "action": { "type": "command", "command": "python3 .kiro/fi-hook-to-otlp/emit.py kiro_ide || true" },
      "timeout": 10
    }
  ]
}
```

Command hooks run in the project root, so the path starts with `.kiro/`. Hooks activate when a session starts. You can see and toggle them in the **Agent Hooks** section of the Kiro panel.

<Note>
The emitter only observes. The commands are guarded with `|| true`, so a missing emitter cannot block a prompt or tool. The adapter prints nothing, and this recipe does not register `PreToolUse` or `PreTaskExec`; completed hooks are used instead, without vendor duration.
</Note>

## 2. Add your Future AGI keys

Kiro started from the Dock does not see variables exported in your shell. Put the keys in the emitter's env file:

```bash
mkdir -p ~/.config/fi-hook-to-otlp
cat > ~/.config/fi-hook-to-otlp/env <<'EOF'
FI_API_KEY=your-futureagi-api-key
FI_SECRET_KEY=your-futureagi-secret-key
FI_PROJECT_NAME=kiro-ide-sessions
EOF
chmod 600 ~/.config/fi-hook-to-otlp/env
```

For a self-hosted Future AGI, also set `FI_BASE_URL` (traces go to `$FI_BASE_URL/tracer/v1/traces`). All settings are on the [hook-to-OTLP page](/docs/integrations/coding-agents/hook-to-otlp#configuration).

## 3. Run an agent session

Open the project in Kiro, start a new chat session, and send one prompt that uses a tool, for example *"List the files in this folder and read README.md"*.

Open **Observe** in Future AGI and select the project (`kiro-ide-sessions` above). The chat session appears as one trace named **Kiro IDE session**. Each prompt in the same chat adds a **Kiro IDE turn** to that trace.

## What is captured

| Kiro trigger | Future AGI span | Fields |
| --- | --- | --- |
| `SessionStart` | **Kiro IDE session** (root) | `session.id` = Kiro `session_id` |
| `UserPromptSubmit` | **Kiro IDE turn** start | prompt length |
| `PostToolUse` | completed tool span, named after the tool (`read_file`, `execute_bash`, `@<server>/<tool>`, ...) | `gen_ai.tool.name`; no vendor duration |
| `PostToolUse` with failed response | tool span | status `ERROR` when `tool_response.success` is `false` |
| `PostTaskExec` | **Spec task** | task success, `ERROR` when the task failed; no pre-task gating hook |
| `PostFileCreate` / `PostFileSave` / `PostFileDelete` | **File created** / **File saved** / **File deleted** | event only, no path. Kiro may emit both File created and File saved for one agent-created file. |
| `Stop` | **Kiro IDE turn** end | user decision on a confirm prompt, when set |
| `SessionEnd` | session metadata update | Kiro fires this when it unloads/reloads a persisted session; it is not a terminal chat end |

Kiro sends no turn id and no tool call id. The emitter pairs a `Stop` with the open turn. It observes `PostToolUse` directly, so blocked or denied tools do not create orphan FIFO entries.

## What is not available

- **Model, token counts, and cost.** Kiro hook payloads do not include them.
- **Model request spans.** There is no hook per model call.
- **Tool call ids.** Tool spans have a name but no vendor call id.
- **Manual file edits.** File triggers fire only for changes the agent makes; your own saves are not traced.
- **Kiro Web and cloud sessions.** Kiro Web stores hook configuration but does not run these triggers.
- **Daily usage metrics** from Kiro enterprise OpenTelemetry are not joined to sessions, and the IAM Identity Center user id or email from that feed is never added.

<Warning>
Kiro CLI V3 also loads `.kiro/hooks/*.json`. If you run Kiro CLI in a project that has this hook file, those CLI sessions are exported as **Kiro IDE** sessions. Use the [Kiro CLI](https://docs.futureagi.com/docs/integrations/coding-agents/kiro-cli) setup for CLI sessions instead.
</Warning>

## Privacy

By default only structure and metadata leave your machine: session id, tool names, prompt length, statuses, and timing.

- **Not exported by default:** prompt text, tool input, tool output, spec and task names, file paths.
- **Never exported:** `cwd`. The emitter reads only the stdin payload. Legacy Kiro 0.x hooks exposed `USER_PROMPT`; this v1 emitter never reads it, and it never opens files named in a payload.

To include content, add `FI_HOOK_CAPTURE_CONTENT=1` to the env file. The prompt becomes the turn's `input.value`, tool input and output go on the tool span, a failed tool's response becomes its status message, and file events carry the path. Each field is capped at 4096 characters and common key formats are replaced with `[REDACTED]`. See [Privacy](/docs/integrations/coding-agents/hook-to-otlp#privacy).

## Troubleshooting

**No trace appears.**
1. Check that the hooks are listed and enabled in the **Agent Hooks** section of the Kiro panel, and that the workspace is trusted.
2. Set `FI_HOOK_LOG_FILE=/tmp/fi-hook.log` in `~/.config/fi-hook-to-otlp/env` and send another prompt. No lines: Kiro did not run the command, or `FI_API_KEY` / `FI_SECRET_KEY` are not set (the emitter is a silent no-op without both). `error=` lines: the collector is unreachable. `http=401`/`403`: wrong keys.
3. `python3` must resolve for Kiro. Use an absolute interpreter path such as `/opt/homebrew/bin/python3` in the hook file if it does not.

**Tools appear directly under the session.** A tool hook arrived without an open turn, for example when hooks were installed in the middle of a chat. It is attached to the session rather than guessed.

**The turn is marked incomplete.** The session ended before Kiro sent `Stop` for that turn. The turn is closed at session end with `coding_agent.incomplete=true`.
