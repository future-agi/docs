## About

The [OpenAI Codex SDK](https://learn.chatgpt.com/docs/codex-sdk) (`@openai/codex-sdk`) runs the Codex agent from your own TypeScript code: it starts the `codex` binary in a subprocess and streams the agent's events back to you. The `@traceai/codex-sdk` package turns that event stream into spans, so every `thread.run()` or `thread.runStreamed()` shows up in Future AGI as one trace:

```
codex.turn                     one run() / runStreamed(): session.id = thread id, model, tokens
├── codex.reasoning            reasoning summary
├── codex.agent_message        LLM: a message from the agent
├── codex.command_execution    TOOL: shell command, exit code, status
├── codex.file_change          TOOL: patch, number and kinds of changes
├── codex.mcp_tool_call        TOOL: MCP server and tool, status
├── codex.web_search           TOOL
├── codex.todo_list            the agent's plan, items done
└── codex.error                non-fatal error item (warning, deprecation, model reroute)
```

All turns of one Codex thread share a `session.id`, so Future AGI groups them into one session.

This is not the same as:

- **Codex application session tracing**: the `codex` CLI, TUI, and IDE extension exporting their own telemetry through the `[otel]` section of `~/.codex/config.toml`. That is a separate integration.
- **OpenAI API tracing** (`@traceai/openai`). The SDK makes its model requests inside the `codex` subprocess, so an OpenAI client instrumentor in your app does not see them.

## 1. Install

```bash
npm install @traceai/codex-sdk @traceai/fi-core @openai/codex-sdk
```

<Note>
`@traceai/codex-sdk` ships with [traceAI PR #251](https://github.com/future-agi/traceAI/pull/251). Until it is released to npm, install it from source:

```bash
git clone --depth 1 --branch feat/th-8262-codex-sdk https://github.com/future-agi/traceAI.git
cd traceAI/typescript
pnpm install --filter "@traceai/codex-sdk..."
cd packages/traceai_codex_sdk && pnpm run build && pnpm pack --pack-destination /tmp
cd /path/to/your/app
npm install /tmp/traceai-codex-sdk-0.1.0.tgz @traceai/fi-core @openai/codex-sdk
```
</Note>

## 2. Set environment variables

```bash
export FI_API_KEY="your-futureagi-api-key"
export FI_SECRET_KEY="your-futureagi-secret-key"
```

Codex itself authenticates as it normally does (`codex login`, or the `apiKey` option on `Codex`). For a self-hosted Future AGI, also set `FI_BASE_URL`; traces go to `$FI_BASE_URL/tracer/v1/traces`.

## 3. Register a tracer provider and instrument the SDK

```typescript
import * as CodexSDK from "@openai/codex-sdk";
import { register, ProjectType } from "@traceai/fi-core";
import { CodexSDKInstrumentation, shutdown } from "@traceai/codex-sdk";

const tracerProvider = register({
  projectType: ProjectType.OBSERVE,
  projectName: "codex-sdk-app",
});

new CodexSDKInstrumentation({ tracerProvider }).manuallyInstrument(CodexSDK);
```

Pass the module namespace (`import * as CodexSDK`), not the `Codex` class. The SDK is ESM-only, so the package patches its `Thread` class once for the whole process.

To trace only some clients, wrap instances instead of the class:

```typescript
const instrumentation = new CodexSDKInstrumentation({ tracerProvider });
const codex = instrumentation.wrapCodex(new CodexSDK.Codex()); // every thread it starts or resumes
```

## 4. Run the agent

```typescript
const codex = new CodexSDK.Codex();
const thread = codex.startThread({ workingDirectory: "/path/to/repo", model: "gpt-5.6-terra" });

const turn = await thread.run("List the files in this folder and read README.md");
console.log(turn.finalResponse);

// Streaming works the same way and is traced the same way.
const { events } = await thread.runStreamed("Now summarize app.py");
for await (const event of events) {
  // the SDK's own event objects, unchanged
}

await shutdown(tracerProvider); // flush before a short script exits
```

Open **Observe** in Future AGI and select the project (`codex-sdk-app` above). Each turn is one trace named **codex.turn**; open it to see the commands and messages it ran. Both turns above share the thread's `session.id`, so the **Sessions** view shows them together.

## What is captured

| SDK event | Future AGI span | Fields |
| --- | --- | --- |
| your `run()` / `runStreamed()` call | **codex.turn** (root, `AGENT`), opened when the first event is read | prompt length, thread options, `codex.thread.resumed` |
| `thread.started` | sets `session.id` and `gen_ai.conversation.id` = thread id on **codex.turn** | |
| `turn.completed` | **codex.turn** end | token usage (see below), status `OK` |
| `turn.failed` | **codex.turn** end, status `ERROR` | `codex.error.message` (see [Privacy](#privacy)) |
| `error` | counted in `codex.stream_error.count`, one `codex.stream_error` span event each | Codex also sends `error` for errors it retries ("Reconnecting... 1/5"). A turn that still reaches `turn.completed` ends `OK`; one that does not ends `ERROR` |
| `command_execution` item | **codex.command_execution** (`TOOL`) | exit code, output length, status; `failed` marks the span `ERROR` |
| `file_change` item | **codex.file_change** (`TOOL`) | number of changes, kinds (`add`, `delete`, `update`), status |
| `mcp_tool_call` item | **codex.mcp_tool_call** (`TOOL`) | `tool.name` = MCP tool, `codex.mcp.server`, status |
| `web_search` item | **codex.web_search** (`TOOL`) | |
| `agent_message` item | **codex.agent_message** (`LLM`) | model, text length |
| `reasoning` item | **codex.reasoning** | text length |
| `todo_list` item | **codex.todo_list** | item count, completed count (updated until the turn ends) |
| `error` item | **codex.error**, status unset, `codex.warning=true` | message length. Codex 0.162.1 sends config warnings, deprecation notices, and model reroutes this way, so they do not mark the turn `ERROR` |

The turn span also records the thread options you passed: `gen_ai.request.model`, `codex.sandbox_mode`, `codex.approval_policy`, `codex.model_reasoning_effort`, `codex.web_search_mode`. If you `break` out of the `for await` loop (or call `events.return()`) before `turn.completed`, or abort with `TurnOptions.signal`, the turn and any open items end as `ERROR` with `codex.cancelled=true`. A `runStreamed()` iterator that is neither read to the end nor closed never ends its turn, so nothing is exported for it. If the `codex` binary exits with an error, the turn ends `ERROR` with `codex.error.type` and a summary in `codex.error.message` (see [Privacy](#privacy)), and the SDK's error is thrown to your code unchanged.

### Token usage

Tokens are recorded on the **codex.turn** span only: `gen_ai.usage.input_tokens`, `output_tokens`, `total_tokens`, `cache_read_tokens`, `cache_write_tokens`, and `output_tokens.reasoning`.

The SDK's `turn.completed` usage is the thread's running total, not the turn's own spend: on 0.162.1 a thread's second turn reported 39,318 input tokens after the first reported 19,378. So each turn span holds the difference from the last total seen in your process for that thread, and Future AGI's per-trace and per-session sums stay correct. The running totals are on `codex.cumulative.*`.

When a thread is resumed with `resumeThread(id)` in a process that has not seen it before (after a restart, or on another worker), the first turn has no earlier total to subtract. It records no `gen_ai.usage.*` and sets `codex.usage.baseline_unknown=true`; its later turns record their difference. Keep a thread's turns in one process for exact per-turn tokens.

A turn that fails or is cancelled reports no usage, so its tokens are counted on the thread's next completed turn. A new thread starts at zero even when its first turn fails, so the next turn still records its difference. If the running total ever goes down, the reported value is recorded as is and `codex.usage.non_monotonic=true` is set.

This running-total handling was measured on 0.162.1. Older SDK and `codex` versions were checked for the `Thread` shape only, not for how they report usage across turns.

## What is not available

- **Per-request model spans.** The SDK reports agent messages, not individual model requests, so there is no span per Responses API call and no per-request token counts.
- **Model chosen in `config.toml`.** The model is recorded only when you pass `model` in `startThread()` or `resumeThread()`; the SDK does not report which model the binary used.
- **Reported cost.** Codex does not report cost and the package sends none. The cost Future AGI shows on a turn is its own estimate from the model and token counts, so it appears only when you pass `model` and Future AGI knows that model's price.
- **Exact durations.** Span times are when each event reached your process. `agent_message` and `reasoning` arrive only when complete, so their spans start at the previous event. The binary reports a command's start and end close together, so command spans are short.
- **Approval decisions.** The SDK event stream does not carry them.
- **Subagents.** Codex 0.162.1 also emits `collab_tool_call` items (a subagent spawn) that are not in the SDK's types. They appear as a generic `codex.collab_tool_call` span, with no link to the subagent's own work.
- **The actual provider.** `gen_ai.provider.name` is always `openai`. The SDK does not report which `model_provider` the binary used, so an Azure, `--oss`, or other custom provider setup is still labelled `openai`.

## Privacy

By default only structure and metadata are exported: thread id, item ids and types, statuses, exit codes, counts, lengths, tool and MCP server names, model, token counts, and fixed error summaries:

- A thrown error (for example the `codex` binary exiting non-zero) exports its class name in `codex.error.type` and only a fixed summary in `codex.error.message`, the span status, and the exception event: `Codex Exec exited with code N` (or `signal S`), `Failed to parse item`, or the class name. The exception event has no stack trace.
- `turn.failed` exports the label `turn failed`, and a turn that had an `error` event and never reached `turn.completed` exports `stream error`.

**Not exported by default:** the prompt, shell commands, command output, file paths in patches, MCP arguments and results, web search queries, reasoning text, agent messages, to-do text, and all error text: the SDK's full error message (on a non-zero exit it includes the `codex` binary's stderr, which can quote config lines, absolute paths, and your user name), the provider's error body from `turn.failed` and `error` events, the exception stack trace (local file paths), the text of `codex.error` items, and an MCP tool's error text.

To include content, opt in when you create the instrumentation:

```typescript
new CodexSDKInstrumentation({
  tracerProvider,
  traceConfig: { hideInputs: false, hideOutputs: false },
}).manuallyInstrument(CodexSDK);
```

or set `FI_HIDE_INPUTS=false` and `FI_HIDE_OUTPUTS=false`. With inputs visible, the turn's `input.value` is the prompt and tool spans carry the command, the file changes including their paths, MCP arguments, or search query; any path in those is exported too. With outputs visible, the turn's `output.value` is the final agent message, items carry their output, and every error text listed above is exported, including the SDK's full error message with the binary's stderr and the exception stack trace. Only `false` (any case) turns capture on; `0`, `no`, or `off` keep content hidden.

## Troubleshooting

**`register()` throws `FI_PROJECT_NAME is not set`.** Pass `projectName` to `register()` or set `FI_PROJECT_NAME`.

**No trace appears.**
1. Pass the module namespace to `manuallyInstrument()`: `import * as CodexSDK from "@openai/codex-sdk"`. It returns `false` when it finds no `Thread` class. Its warning is logged only when an OpenTelemetry diag logger is set, for example `diag.setLogger(new DiagConsoleLogger(), DiagLogLevel.WARN)` from `@opentelemetry/api`.
2. Call `await shutdown(tracerProvider)` before a short script exits, so the last spans are sent.
3. Read every `runStreamed()` iterator to the end, or close it with `break` or `events.return()`. An iterator that is dropped part way never ends its turn, so that turn is never exported.

**A turn has no token counts.** Look for `codex.usage.baseline_unknown=true` on the turn: the thread was resumed in a process that had not seen it. `codex.cumulative.*` still has the thread's totals. A failed or cancelled turn has no token counts either; its tokens are counted on the thread's next completed turn.

**The turn is marked cancelled.** Your code left the `for await` loop with `break` (or called `events.return()`) before `turn.completed`, or aborted the turn. Read the stream to the end (or let `run()` finish) to record the turn as completed.

**An OK turn has `codex.stream_error.count`.** Codex hit a stream error, retried, and the turn completed. Nothing failed.

**The error message only says `Codex Exec exited with code 1`.** The full message, with the binary's stderr, is content. Set `hideOutputs: false` (or `FI_HIDE_OUTPUTS=false`) while you debug, or read the error your code receives.

**No model on the turn.** Pass `model` in the thread options.
