## About

Gemini CLI has [built-in OpenTelemetry](https://geminicli.com/docs/cli/telemetry/). With traces turned on it emits a span for every model call and every tool call, and in interactive mode a span for every turn. This page sends those spans through a small OpenTelemetry Collector running next to Gemini CLI, which forwards them to Future AGI:

```
Gemini CLI  ──OTLP/HTTP──▶  otelcol-contrib (localhost:4318)  ──▶  Future AGI
                            keeps traces, drops logs and metrics,
                            strips prompt-shaped attributes and error text,
                            labels span kinds, adds your keys
```

One Gemini CLI session shows up in Future AGI as one **session**. How it splits into traces depends on how you run Gemini CLI.

**Interactive `gemini`:** one trace per prompt you type, rooted at a `user_prompt` span:

```
user_prompt                   one turn: the prompt you typed
├── llm_call                  one model request: model, input/output tokens, status
├── schedule_tool_calls       the tool calls the model asked for
│   ├── list_directory        tool call: name, call id, duration, status
│   └── read_file
└── system_prompt             follow-up turn: Gemini CLI sends the tool results back
    └── llm_call              the next model request
```

Two cases in Gemini CLI 0.64.0 differ from that. A prompt you type while a turn is still running is queued and sent when that turn ends; in our test it then nested under the running turn, in the same trace, instead of starting its own. A slash command you type (`/quit`, `/stats`, ...) also starts a `user_prompt` trace, with no spans under it.

**Non-interactive `gemini -p "..."`:** there is no turn span, so each model call and each tool batch is its own trace:

```
llm_call                      one model request
schedule_tool_calls           one batch of tool calls
├── list_directory
└── read_file
llm_call                      the next model request
```

Gemini CLI has no span for the whole session. Every span carries the Gemini CLI session id, which the collector copies to `session.id`, so the **Sessions** tab groups a session's traces in both modes.

This is not the same as:

- **The [Google GenAI](/docs/integrations/traceai/google_genai) and [Vertex AI](/docs/integrations/traceai/vertexai) SDK instrumentors** (`traceAI-google-genai`, `traceAI-vertexai`), which trace your own code that calls the Gemini API. They do not see Gemini CLI's tool scheduler or session.
- **Google Antigravity** or Gemini in other IDEs. Those are separate integrations.
- **Gemini CLI's `target: "gcp"` export**, which sends telemetry to Google Cloud, not to Future AGI.

## 1. Run the collector

Download the example collector config and start `otelcol-contrib` with your Future AGI keys:

```bash
curl -fsSLO https://raw.githubusercontent.com/future-agi/docs/main/examples/coding-agents/gemini-cli/otel-collector.yaml
export FI_API_KEY=your-futureagi-api-key
export FI_SECRET_KEY=your-futureagi-secret-key
export FI_PROJECT_NAME=gemini-cli
otelcol-contrib --config otel-collector.yaml
```

It listens on `127.0.0.1:4318` (set `GEMINI_OTLP_LISTEN` to change it) and sends traces to `$FI_BASE_URL/tracer/v1/traces` (default `https://api.futureagi.com`; set `FI_BASE_URL` for a self-hosted Future AGI). Keep it running while you use Gemini CLI, or run it as a service. The collector's own metrics endpoint is turned off in the config (`service.telemetry.metrics.level: none`), so it does not take port 8888 from Jupyter or another collector.

The collector does four things Gemini CLI cannot do on its own:

| Step | Why |
| --- | --- |
| Adds `X-Api-Key`, `X-Secret-Key` and `project_name` | Gemini CLI 0.64.0 has no setting for OTLP headers. (Gemini CLI's main-branch docs list an `otlpHeaders` setting that is not in 0.64.0; the other three steps still need the collector.) |
| Drops logs and metrics | Gemini CLI always exports all three signals; Future AGI ingests traces. |
| Deletes `gen_ai.system_instructions`, `gen_ai.tool.definitions`, message attributes, error messages and stack traces, and the command line, executable paths, OS user name and machine name that Node's resource detectors add | Privacy default, see [Privacy](#privacy). |
| Sets `gen_ai.span.kind` from Gemini CLI's operation names, names tool spans after the tool, copies the session id to `session.id` | Gemini CLI uses its own operation names (`user_prompt`, `llm_call`, `tool_call`, ...), which Future AGI does not map by itself. |

It also sends uncompressed: the Future AGI collector answers gzip-encoded OTLP requests with HTTP 400.

## 2. Turn on Gemini CLI telemetry

Add the `telemetry` block to `~/.gemini/settings.json` (all projects) or `.gemini/settings.json` in one project:

```json
{
  "telemetry": {
    "enabled": true,
    "target": "local",
    "otlpEndpoint": "http://127.0.0.1:4318",
    "otlpProtocol": "http",
    "traces": true,
    "logPrompts": false
  }
}
```

- `traces: true` is required for token counts. With it off, Gemini CLI still emits the spans with the model, the tool names, the system prompt and the tool schemas, but without token counts. It is not a privacy setting on its own: keep `transform/strip-content` in the collector either way.
- `logPrompts: false` is not Gemini CLI's default. The vendor default is `true`, which puts prompts, responses, tool arguments and tool results on the spans. Keep it `false` unless you opt in to content.
- Do not set `outfile` (it replaces the OTLP export) or `target: "gcp"`.

Gemini CLI also documents environment variables for these settings (`GEMINI_TELEMETRY_ENABLED`, `GEMINI_TELEMETRY_TRACES_ENABLED`, `GEMINI_TELEMETRY_TARGET`, `GEMINI_TELEMETRY_OTLP_ENDPOINT`, `GEMINI_TELEMETRY_OTLP_PROTOCOL`, `GEMINI_TELEMETRY_LOG_PROMPTS`). Prefer the settings file: in our 0.64.0 test, `GEMINI_TELEMETRY_ENABLED=false` did not stop the export when the settings file had `"enabled": true`. Setting `"enabled": false` in the file did: no spans reached the collector.

Optionally also export `OTEL_NODE_RESOURCE_DETECTORS=env` in the shell that runs `gemini`. Node's default resource detectors record the full command line (for `gemini -p "..."` it contains the prompt), the Node executable path (often under your home directory), your OS user name and the machine name. The collector deletes all of these either way (`process.command_args`, `process.command`, `process.executable.*`, `process.owner`, `host.name`, `host.id`); this setting keeps them from leaving the Gemini CLI process at all.

## 3. Run a session

Start `gemini` in a project and send one prompt that uses a tool, for example *"List the files in this folder and read README.md"*. Exit Gemini CLI, or wait a few seconds: spans are batched.

Open **Observe** in Future AGI and select the project (`gemini-cli` above). For an interactive session the **Trace** tab lists one `user_prompt` trace per prompt; for `gemini -p` it lists separate `llm_call` and `schedule_tool_calls` traces. The **Sessions** tab groups them by Gemini CLI session.

`run_e2e.sh` in the [examples folder](https://github.com/future-agi/docs/tree/main/examples/coding-agents/gemini-cli) does all three steps against a throwaway `HOME`, so it does not touch your own `~/.gemini`. It runs `gemini -p`, so its traces have no `user_prompt` span. It also checks what the collector forwarded: at least one span, and not the prompt's marker string, your user name, home directory or machine name (with `CAPTURE_CONTENT=1`, the marker must be there). It fails if another process already listens on its port, 24318 (`GEMINI_OTLP_PORT`):

```bash
git clone --depth 1 --filter=blob:none --sparse https://github.com/future-agi/docs.git fi-docs
git -C fi-docs sparse-checkout set examples/coding-agents/gemini-cli
FI_API_KEY=... FI_SECRET_KEY=... GEMINI_API_KEY=... \
  fi-docs/examples/coding-agents/gemini-cli/run_e2e.sh
```

`tests/test_collector.py` in the same folder runs the shipped config in a real `otelcol-contrib` and checks what it forwards; it is skipped when no `otelcol-contrib` binary is found (set `OTELCOL_BIN`).

## What is captured

| Gemini CLI span | Future AGI span kind | Fields |
| --- | --- | --- |
| `user_prompt` (interactive mode only) | `CHAIN` | one turn, the root of its model and tool spans: `gen_ai.agent.name=gemini-cli`, duration, status. No prompt text, even with the content opt-in: Gemini CLI 0.64.0 does not record it on this span (with the opt-in, the prompt is on the first `llm_call`) |
| `system_prompt` (interactive mode only) | `CHAIN` | the follow-up turn Gemini CLI starts itself to send tool results back to the model, a child of `user_prompt`; same fields. It starts when `user_prompt` ends, so a turn's full duration is `user_prompt` plus its `system_prompt` children. Despite the name it does not hold the system prompt (that is `gen_ai.system_instructions` on `llm_call`, deleted by default) |
| `llm_call` | `LLM` | `gen_ai.request.model`, `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens`, `gen_ai.prompt.name` (Gemini CLI's prompt id), status `ERROR` when the API call fails, with the error class and HTTP status as the status message (for example `ApiError HTTP 503`; a retried 503 shows up as its own `ERROR` span) |
| `schedule_tool_calls` | `CHAIN` | parent of the tool calls the model requested in one response |
| `tool_call`, renamed to the tool (`read_file`, `list_directory`, `run_shell_command`, ...) | `TOOL` | `gen_ai.tool.name`, `gen_ai.tool.call_id`, `gen_ai.tool.description`, duration. Status `ERROR` (status message: the error class, for example `ENOENT`) only when the tool throws; see [What is not available](#what-is-not-available) |
| `agent_call` | `AGENT` | a subagent run; its model and tool spans nest under it. Gemini CLI 0.64.0 overwrites the subagent's name with `gen_ai.agent.name=gemini-cli`, so the subagent's own name is not available. Read from Gemini CLI 0.64.0's source; not exercised in our test |
| every span | | `gen_ai.conversation.id` and `session.id` = Gemini CLI session id; resource `service.name=gemini-cli` |

## What is not available

- **One trace per session.** Gemini CLI has no session span: interactive mode gives one trace per turn, `gemini -p` one trace per model call or tool batch. Use the **Sessions** tab for the whole session.
- **Tool failures the tool reports itself.** A tool that returns an error instead of throwing (file not found, path outside the workspace, a shell execution error) ends its span with status `OK` in Gemini CLI 0.64.0. Only an exception thrown while the tool runs is marked `ERROR`. The failure is visible only in the tool result, which is exported only with the [content opt-in](#privacy).
- **Error messages and stack traces** by default. The collector keeps the `ERROR` status and the error class (plus the HTTP status of a Gemini API error) and removes the text; see [Privacy](#privacy).
- **Cost.** Gemini CLI reports tokens, not cost. Future AGI computes cost from the model name only when it has pricing for that model.
- **Cached, thinking and tool-use token counts.** Only input and output tokens are on the spans.
- **Gemini CLI logs and metrics** (`gemini_cli.user_prompt`, `gemini_cli.api_request`, token and latency metrics). The collector drops them; Future AGI ingests traces only.
- **Telemetry in sandbox mode** was not tested.

## Privacy

With the settings above, only structure and metadata leave your machine: model, token counts, tool names, call ids, tool descriptions (static text from Gemini CLI or your MCP servers), durations, statuses, error classes (`ApiError HTTP 429`, `ENOENT`), and the session id.

- **Not exported by default:** prompts and responses, tool arguments and results (Gemini CLI leaves them out with `logPrompts: false`); the system prompt, which includes your `GEMINI.md` memory and local paths, the tool schemas, and error messages, which carry API error bodies and, for a tool that throws, file paths and command output (the collector deletes them or replaces them with the error class); the command line, executable paths, OS user name and machine name.
- **Never forwarded:** Gemini CLI's logs and metrics, and error stack traces (they list your Gemini CLI install path, including your home directory; the collector deletes them even with the content opt-in).

To include content:

1. Set `"logPrompts": true` in the `telemetry` block.
2. In `otel-collector.yaml`, remove `transform/strip-content` from the traces pipeline:

   ```yaml
   processors: [transform/gemini-cli, batch]
   ```

Model spans then carry the request and response messages, and tool spans the call request and result, as `gen_ai.input.messages` / `gen_ai.output.messages`; the collector also copies them to the span's input and output in Future AGI. Gemini CLI truncates each value to 10,000 characters. The `user_prompt` and `system_prompt` turn spans stay without input and output: Gemini CLI 0.64.0 does not record content on them. The system prompt (with your `GEMINI.md` memory and local paths such as the working directory), the tool schemas and the full error messages (`exception.message` and the status message, which can contain file paths) are exported too in this mode. The command line, executable paths, user and machine name, and stack traces stay removed.

## Troubleshooting

**No traces appear.**
1. Check that the collector is running and listening on the `otlpEndpoint` port. With `otlpProtocol: "http"` Gemini CLI posts to `<otlpEndpoint>/v1/traces`; the default protocol is `grpc`, which this collector config does not accept.
2. If the collector exits with `address already in use`, another process owns port 4318 (often another OpenTelemetry Collector or agent). Start this one on a free port, for example `GEMINI_OTLP_LISTEN=127.0.0.1:24318`, and set the same port in `otlpEndpoint` (`http://127.0.0.1:24318`).
3. Check the collector's output for `Exporting failed`. `401`/`403` means wrong keys. `400` means a request the Future AGI collector could not decode: keep `compression: none` on the exporter.
4. `telemetry.enabled` must be `true` in the settings file. `useCollector` together with `useCliAuth` disables telemetry.

**Model spans have no token counts.** `telemetry.traces` is `false` in the settings file.

**A failed tool call shows status `OK`.** Expected in Gemini CLI 0.64.0 when the tool reports the failure in its result instead of throwing; see [What is not available](#what-is-not-available).

**Error spans show only `ApiError HTTP 503` or `error`.** The collector removes error text by default. Remove `transform/strip-content` (the content opt-in) to keep full error messages.

**Tool spans show as `unknown` and are named `tool_call`, or `user_prompt` spans have no span kind.** The spans did not go through the `transform/gemini-cli` processor; send Gemini CLI's export to the collector, not straight to Future AGI.

**No `user_prompt` traces, only separate `llm_call` and `schedule_tool_calls` traces.** Expected for `gemini -p` (non-interactive): Gemini CLI emits the turn span only in interactive mode.

**Prompts show up although you did not opt in.** `logPrompts` defaults to `true` in Gemini CLI. Set it to `false`, and keep `transform/strip-content` in the pipeline.
