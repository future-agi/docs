## About

Devin Desktop (the IDE formerly called Windsurf) runs [Cascade hooks](https://docs.devin.ai/desktop/cascade/hooks) at fixed points of the Cascade agent's work and passes each one a JSON event on stdin. This page registers the Future AGI [hook-to-OTLP emitter](/docs/integrations/coding-agents/hook-to-otlp) on those hooks, so every Cascade conversation shows up in Future AGI as one trace:

```
Cascade session            one Cascade conversation (trajectory_id), model label
└── Cascade turn           one prompt and response (execution_id)
    ├── read_code          file read
    ├── run_command        terminal command
    ├── write_code         file edit: number of edits
    └── list_commits       MCP tool call: server and tool name
```

This covers the Cascade agent only. It is not the same as:

- **Devin Local**, the other agent inside Devin Desktop (shared with Devin CLI). It has its own [lifecycle hooks](https://docs.devin.ai/cli/extensibility/hooks/lifecycle-hooks) with a different configuration format, and is not covered here.
- **Hosted Devin** sessions in the Devin web app, Slack, or the API. They do not run on your machine and do not fire Cascade hooks.
- **Devin Desktop's transcript files** (`post_cascade_response_with_transcript`, `~/.windsurf/transcripts/`) and the support-log bundle. Neither is read.

## 1. Install the hook

Clone the examples and run the installer. It copies the emitter and the Devin Desktop adapter into `~/.codeium/windsurf/fi-hook-to-otlp/` and writes the user-level Cascade hook file `~/.codeium/windsurf/hooks.json`. If that file already exists, the installer leaves it alone and prints the entries to merge.

```bash
git clone --depth 1 https://github.com/future-agi/docs.git fi-docs
fi-docs/examples/coding-agents/devin-desktop/install.sh
```

The hook file it writes:

```json
{
  "hooks": {
    "pre_user_prompt":       [{ "command": "python3 \"$HOME/.codeium/windsurf/fi-hook-to-otlp/emit.py\" devin_desktop", "show_output": false }],
    "post_read_code":        [{ "command": "python3 \"$HOME/.codeium/windsurf/fi-hook-to-otlp/emit.py\" devin_desktop", "show_output": false }],
    "post_write_code":       [{ "command": "python3 \"$HOME/.codeium/windsurf/fi-hook-to-otlp/emit.py\" devin_desktop", "show_output": false }],
    "post_run_command":      [{ "command": "python3 \"$HOME/.codeium/windsurf/fi-hook-to-otlp/emit.py\" devin_desktop", "show_output": false }],
    "post_mcp_tool_use":     [{ "command": "python3 \"$HOME/.codeium/windsurf/fi-hook-to-otlp/emit.py\" devin_desktop", "show_output": false }],
    "post_cascade_response": [{ "command": "python3 \"$HOME/.codeium/windsurf/fi-hook-to-otlp/emit.py\" devin_desktop", "show_output": false }]
  }
}
```

Cascade runs `command` with `bash -c`, so `$HOME` expands. Hooks from the system, user, and workspace files are merged, so this file does not replace hooks your team already deploys. Hooks do not run in a workspace opened in Restricted Mode.

- `pre_user_prompt` opens the turn and `post_cascade_response` closes it. They are the only hooks Cascade fires at the start and end of a turn. Their text (the prompt and the response markdown) is dropped by the emitter unless you turn on content capture.
- The other pre-hooks (`pre_read_code`, `pre_write_code`, `pre_run_command`, `pre_mcp_tool_use`) are not registered: they can block an action, and the matching post-hook carries the same information. `pre_user_prompt` can also block; the emitter always exits 0, so it never does.
- `post_cascade_response_with_transcript` is never registered.

## 2. Add your Future AGI keys

Devin Desktop started from the Dock does not see variables exported in your shell. Put the keys in the emitter's env file:

```bash
mkdir -p ~/.config/fi-hook-to-otlp
cat > ~/.config/fi-hook-to-otlp/env <<'EOF'
FI_API_KEY=your-futureagi-api-key
FI_SECRET_KEY=your-futureagi-secret-key
FI_PROJECT_NAME=cascade-sessions
EOF
chmod 600 ~/.config/fi-hook-to-otlp/env
```

For a self-hosted Future AGI, also set `FI_BASE_URL` (traces go to `$FI_BASE_URL/tracer/v1/traces`). All settings are listed on the [hook-to-OTLP page](/docs/integrations/coding-agents/hook-to-otlp#configuration).

## 3. Run a Cascade conversation

Restart Devin Desktop, open a trusted folder, and send Cascade one prompt that reads a file or runs a command, for example *"List the files in this folder and read README.md"*.

Open **Observe** in Future AGI and select the project (`cascade-sessions` above). The conversation appears as one trace named **Cascade session**. Open it to see the turn and its tool spans. Later prompts in the same conversation are added to the same trace as new turns.

## What is captured

| Cascade hook | Future AGI span | Fields |
| --- | --- | --- |
| `pre_user_prompt` | **Cascade turn** start (the **Cascade session** root is created with the first span) | `session.id` = `trajectory_id`, `execution_id`, model label |
| `post_read_code` | **read_code** | `execution_id`, model label |
| `post_write_code` | **write_code** | number of edits |
| `post_run_command` | **run_command** | |
| `post_mcp_tool_use` | tool span named after `mcp_tool_name` | MCP server and tool name |
| `post_cascade_response` | **Cascade turn** end | |

The model is Cascade's `model_name`, the label shown in the model selector (for example `Claude Sonnet 4`). It is recorded as `llm.model_name` and `devin_desktop.model_label`, but it is a display name that Devin Desktop may change, not a stable model id. When Cascade reports `Unknown`, no model is recorded.

## What is not available

- **Token counts, cost, and model request spans.** Cascade hooks do not report them.
- **Tool duration and tool call ids.** Post-hooks carry neither, so tool spans mark when the action finished. Command exit codes are not in the hook input either.
- **Session start and end.** Cascade has no session hook. The session span starts at the first prompt and is re-sent, with a later end time, whenever a turn or tool span is sent.
- **Turn status.** There is no hook for a cancelled or failed turn. The turn span is sent when `post_cascade_response` arrives; if Cascade never sends it for a turn, that turn's span is missing and its tool spans have no parent in the trace view.
- **Devin Local and hosted Devin.** See [About](#about).

## Privacy

By default only structure and metadata leave your machine: trajectory and execution ids, hook names, tool names, MCP server names, edit counts, and the model label.

- **Not exported by default:** prompt text, response markdown, file paths, edit text, command lines and their working directory, MCP arguments and results.
- **Never exported:** transcript paths and transcript files (the emitter never opens them), worktree paths.

To include content, add `FI_HOOK_CAPTURE_CONTENT=1` to the env file. The prompt becomes the turn's `input.value`, the response markdown its `output.value`, and the file path, edits, command line, or MCP arguments and result go on the tool span. Each field is capped at 4096 characters and common key formats are replaced with `[REDACTED]`. See [Privacy](/docs/integrations/coding-agents/hook-to-otlp#privacy) for details.

## Troubleshooting

**No trace appears.**
1. Set `"show_output": true` on one hook in `hooks.json`; hook output and errors then show in the Cascade panel.
2. Set `FI_HOOK_LOG_FILE=/tmp/fi-hook.log` in `~/.config/fi-hook-to-otlp/env` and send another prompt. No lines: Cascade did not run the command (check `python3` and the path, and that the workspace is not in Restricted Mode). `error=` lines: the collector is unreachable. `http=401`/`403`: wrong keys.
3. If your organization deploys hooks from the Devin Desktop dashboard or a system-level `hooks.json`, they run before yours; a failing system hook does not stop this one.

**Tool spans have no parent turn.** Cascade did not send `post_cascade_response` for that turn, or `post_cascade_response` is missing from `hooks.json`. The turn span is only sent when that hook runs.
