## About

Devin Desktop (the IDE formerly called Windsurf) runs [Cascade hooks](https://docs.devin.ai/desktop/cascade/hooks) at fixed points of the Cascade agent's work and passes each one a JSON event on stdin. This page registers the Future AGI [hook-to-OTLP emitter](/docs/integrations/coding-agents/hook-to-otlp) on those hooks, so every Cascade conversation shows up in Future AGI as one trace:

```
Cascade session            one Cascade conversation (trajectory_id), model label
└── Cascade turn           one prompt and response (execution_id)
    ├── read_code          file read
    ├── run_command        terminal command
    ├── write_code         file edit: number of edits
    └── list_commits       MCP tool call: server and tool name
```

This covers the Cascade agent only. It is not the same as:

- **Devin Local**, the other agent inside Devin Desktop (shared with Devin CLI). It has its own [lifecycle hooks](https://docs.devin.ai/cli/extensibility/hooks/lifecycle-hooks) with a different configuration format, and is not covered here.
- **Hosted Devin** sessions in the Devin web app, Slack, or the API. They do not run on your machine and do not fire Cascade hooks.
- **Devin Desktop's transcript files** (`post_cascade_response_with_transcript`, `~/.windsurf/transcripts/`) and the support-log bundle. Neither is read.

## 1. Install the hook

Clone the examples and run the installer. It copies the emitter and the Devin Desktop adapter into `~/.codeium/windsurf/fi-hook-to-otlp/` and writes the user-level Cascade hook file `~/.codeium/windsurf/hooks.json`. If that file already exists, the installer leaves it alone and prints the entries to merge.

```bash
git clone --depth 1 https://github.com/future-agi/docs.git fi-docs
fi-docs/examples/coding-agents/devin-desktop/install.sh
```

The hook file it writes:

```json
{
  "hooks": {
    "pre_user_prompt":       [{ "command": "(python3 -B \"$HOME/.codeium/windsurf/fi-hook-to-otlp/emit.py\" devin_desktop pre_user_prompt 2>/dev/null || true)", "show_output": false }],
    "post_read_code":        [{ "command": "(python3 -B \"$HOME/.codeium/windsurf/fi-hook-to-otlp/emit.py\" devin_desktop post_read_code 2>/dev/null || true)", "show_output": false }],
    "post_write_code":       [{ "command": "(python3 -B \"$HOME/.codeium/windsurf/fi-hook-to-otlp/emit.py\" devin_desktop post_write_code 2>/dev/null || true)", "show_output": false }],
    "post_run_command":      [{ "command": "(python3 -B \"$HOME/.codeium/windsurf/fi-hook-to-otlp/emit.py\" devin_desktop post_run_command 2>/dev/null || true)", "show_output": false }],
    "post_mcp_tool_use":     [{ "command": "(python3 -B \"$HOME/.codeium/windsurf/fi-hook-to-otlp/emit.py\" devin_desktop post_mcp_tool_use 2>/dev/null || true)", "show_output": false }],
    "post_cascade_response": [{ "command": "(python3 -B \"$HOME/.codeium/windsurf/fi-hook-to-otlp/emit.py\" devin_desktop post_cascade_response 2>/dev/null || true)", "show_output": false }]
  }
}
```

Cascade runs `command` with `bash -c`, so `$HOME` expands. Hooks from the system, user, and workspace files are merged, so this file does not replace hooks your team already deploys. Hooks do not run in a workspace opened in Restricted Mode.

- Every command is wrapped as `( ... 2>/dev/null || true)`, so it exits 0 and prints nothing even if the emitter folder or `python3` is missing. This matters because Cascade treats exit code 2 from a pre-hook as "block", and `python3` exits 2 when its script file is missing. Keep the parentheses and the guard if you edit the commands.
- `pre_user_prompt` opens the turn and `post_cascade_response` closes it. Their text (the prompt and the response markdown) is dropped by the emitter unless you turn on content capture. `post_cascade_response_with_transcript` also fires at the end of a turn, but it writes the full transcript to disk and is never registered.
- The other pre-hooks (`pre_read_code`, `pre_write_code`, `pre_run_command`, `pre_mcp_tool_use`) are not registered: they can block an action, and the matching post-hook carries the same information. `pre_user_prompt` can also block, but it is the only hook that marks the start of a turn. The guarded command always exits 0 and prints nothing, and exit code 0 means "action proceeds normally" in Cascade, so it never blocks or changes a prompt.

## 2. Add your Future AGI keys

Devin Desktop started from the Dock may not see variables exported in your shell, so put the keys in the emitter's env file:

```bash
mkdir -p ~/.config/fi-hook-to-otlp
cat > ~/.config/fi-hook-to-otlp/env <<'EOF'
FI_API_KEY=your-futureagi-api-key
FI_SECRET_KEY=your-futureagi-secret-key
FI_PROJECT_NAME=cascade-sessions
EOF
chmod 600 ~/.config/fi-hook-to-otlp/env
```

`FI_*` variables that do reach Devin Desktop's environment take precedence over the file. For a self-hosted Future AGI, also set `FI_BASE_URL` (traces go to `$FI_BASE_URL/tracer/v1/traces`). All settings are listed on the [hook-to-OTLP page](/docs/integrations/coding-agents/hook-to-otlp#configuration).

## 3. Run a Cascade conversation

Restart Devin Desktop, open a trusted folder, and send Cascade one prompt that reads a file or runs a command, for example *"List the files in this folder and read README.md"*.

Open **Observe** in Future AGI and select the project (`cascade-sessions` above). The conversation appears as one trace named **Cascade session**. Open it to see the turn and its tool spans. Later prompts in the same conversation are added to the same trace as new turns.

## What is captured

| Cascade hook | Future AGI span | Fields |
| --- | --- | --- |
| `pre_user_prompt` | **Cascade turn** start (the **Cascade session** root is sent with the first span) | `session.id` = `trajectory_id` |
| `post_read_code` | **read_code**, status OK | |
| `post_write_code` | **write_code**, status OK | number of edits |
| `post_run_command` | **run_command**, status unset | |
| `post_mcp_tool_use` | tool span named after `mcp_tool_name`, status OK | MCP server and tool name |
| `post_cascade_response` | **Cascade turn** end | |

Every span also carries the hook name (`coding_agent.hook.event`), the turn's `execution_id` (`coding_agent.turn.id`), and the model label. Cascade fires the read, write, and MCP post-hooks after a successful action, so those spans are OK. `post_run_command` carries no exit code, so a command span's status is left unset rather than shown as successful.

The model is Cascade's `model_name`, the label shown in the model selector (for example `Claude Sonnet 4`). It is recorded as `llm.model_name` and `devin_desktop.model_label`, but it is a display name that Devin Desktop may change, not a stable model id. When Cascade reports `Unknown`, no model is recorded.

## What is not available

- **Token counts, cost, and model request spans.** Cascade hooks do not report them.
- **Tool duration, tool call ids, and command exit codes.** Post-hooks carry none of them, so tool spans mark when the action finished and a failed command is not marked as an error.
- **Session start and end.** Cascade has no session hook. The session span starts at the first prompt and is re-sent, with a later end time, whenever a turn or tool span is sent. The emitter's per-conversation state file is therefore not deleted at the end of a conversation; it is swept after 24 hours (`FI_HOOK_STATE_TTL_HOURS`).
- **Turn status.** There is no hook for a cancelled or failed turn. If Cascade never sends `post_cascade_response` for a turn, the emitter closes that turn when your next prompt starts and marks it `coding_agent.incomplete=true`; if the response hook arrives later after all, the turn is re-sent complete.
- **Devin Local and hosted Devin.** See [About](#about).

## Privacy

By default only structure and metadata leave your machine: trajectory and execution ids, hook names, tool names, MCP server names, edit counts, and the model label.

- **Not exported by default**: prompt text, response markdown, file paths, edit text, command lines, MCP arguments and results.
- **Never exported**: transcript paths and transcript files (the emitter never opens them), worktree paths, and the command's working directory.

To include content, add `FI_HOOK_CAPTURE_CONTENT=1` to the env file. The prompt becomes the turn's `input.value`, the response markdown its `output.value`, and the tool input goes on the tool span: the file path (and edits) for reads and writes, the command line for commands, the MCP arguments and result for MCP tools. With content on, file paths therefore do leave your machine inside the tool input, with the user name in home-directory paths replaced by `<user>` (`/Users/<user>/project/README.md`). While content is on, the per-conversation state file on disk also holds the open turn's prompt and the content of turns closed as incomplete until it is swept; a turn that ends normally leaves no content in it. Each field is capped at 4096 characters and common key formats are replaced with `[REDACTED]`. See [Privacy](/docs/integrations/coding-agents/hook-to-otlp#privacy) for details.

## Troubleshooting

**No trace appears.**
1. Set `FI_HOOK_LOG_FILE=/tmp/fi-hook.log` in `~/.config/fi-hook-to-otlp/env` and send another prompt. No lines: Cascade did not run the command (check that `python3` resolves and the emitter path exists, and that the workspace is not in Restricted Mode). `error=` lines: the collector is unreachable. `http=401`/`403`: wrong keys.
2. Run one hook by hand. The guard hides errors, so drop it while testing:
   ```bash
   echo '{"agent_action_name":"post_read_code","trajectory_id":"t1","execution_id":"e1","tool_info":{}}' \
     | python3 -B ~/.codeium/windsurf/fi-hook-to-otlp/emit.py devin_desktop post_read_code
   ```
   It should exit 0 without output. A `can't open file` error means the emitter is not installed at that path.
3. If your organization also deploys hooks from the Devin Desktop dashboard or a system-level `hooks.json`, they run before yours (dashboard, system, user, then workspace).

**A turn is marked incomplete.** Cascade did not send `post_cascade_response` for that turn before the next prompt (for example, the turn was cancelled). If the last turn of a conversation has no turn span at all, check that `post_cascade_response` is in `hooks.json`: Cascade has no session-end hook to close it.

## Uninstall

Remove the Future AGI entries from `~/.codeium/windsurf/hooks.json` first, then delete `~/.codeium/windsurf/fi-hook-to-otlp/`. To pause tracing without editing the hook file, set `FI_HOOK_DISABLED=1` in the env file.
