---

See each Cursor prompt as a trace in Future AGI, with model generations, token usage, tool calls and session context. The maintained `@traceai/cursor-plugin` installs through `@traceai/agents`; you do not need to write hooks or run a collector.

## Quick start

You need **Node.js 22.16+**, **Cursor IDE 3.x on macOS**, and a Future AGI account. For terminal use, also install and sign in to Cursor CLI (`cursor-agent`). The IDE and interactive CLI use the same user hooks and the same `cursor` tracing profile; keep the IDE installed even if you work primarily in the CLI.

### 1. Get your Future AGI keys

Open [API keys](https://app.futureagi.com/dashboard/keys) and create an API key and secret key. Keep them ready for the hidden prompts in the next step; do not paste them into a shell command or commit them to your repository.

### 2. Set up tracing

From your project directory, run:

```bash
npx @traceai/agents setup cursor --project cursor-sessions
```

Enter each key when prompted. Setup checks the connection, saves the credentials privately, and registers the package's hooks in `~/.cursor/hooks.json` while preserving unrelated hooks. The saved configuration also works when you launch Cursor from the Dock.

<Note>
Content capture is **on by default**, including prompts, responses and tool input/output. To keep content out of traces from the first prompt, add `--no-capture-content` to the setup command. See [Privacy](#privacy).
</Note>

### 3. Run Cursor and open the trace

**IDE:** restart Cursor, open your project, and send an Agent prompt such as:

```text
List the files in this folder and read README.md. Summarize what the project does.
```

**Interactive CLI:** start Cursor from the same project and send the same prompt:

```bash
cursor-agent
```

If your Cursor installation exposes the command as `agent`, use that instead. No second tracing setup or wrapper is needed.

After the turn completes, open **Observe** in Future AGI, select **cursor-sessions**, and open its trace. Inspect the model generations and the file-read tool call. Send a follow-up prompt to create another trace with the same session ID. CLI transcripts can arrive after the turn ends, so allow about 30 seconds for the full trace to appear.

## What you see

| Data | How it appears in Future AGI |
| --- | --- |
| Prompts and sessions | One trace per prompt, linked to the conversation through `session.id`. |
| Model generations | LLM spans reconstructed from Cursor's transcript, with bounded input context and responses, including tool-call-only outputs. These are not direct provider-request measurements. |
| Tokens | Cursor's input/output and cache usage, when supplied. Turn totals are counted once on the final generation, or on the root if generations cannot be reconstructed. They are not individual model-call token counts. |
| Tools | Named spans for actions such as Read, Write and Shell, with input/output, timing and failure status when Cursor supplies them. |
| Subagents | Child agent spans when Cursor supplies both the subagent ID and its parent Task call ID. Missing relationships are not guessed; separate subagent transcript internals are not reconstructed. |
| Outcomes | Completed, interrupted or failed turns and tool errors, based on Cursor events. |

**Auto mode reports the model as `default`.** This is the value Cursor provides, not the name of the underlying routed model. Select a specific model in Cursor if you need its reported model name.

Cursor does not provide per-request billing cost through this integration. Missing usage or cost is not evidence that a turn was free. Tab completions are not traced.

### CLI print mode

Use the interactive CLI for complete prompt and generation traces. In `cursor-agent -p` print mode, Cursor's hook stream can contain only tool events and session end. That produces a partial trace without prompt text, reconstructed generations or token totals; those missing values are not inferred.

### Cursor Cloud

Cursor Cloud tracing is **not yet available**. This setup is for local IDE and CLI sessions. For agents launched from your own Node.js application, use the separate [Cursor SDK integration](/docs/integrations/coding-agents/cursor-sdk).

## Configuration

Environment variables override saved settings only when they are present in the process running Cursor. A Dock-launched IDE does not inherit variables exported in a terminal; use setup for persistent settings.

| Setting | Purpose |
| --- | --- |
| `--project cursor-sessions` / `FI_PROJECT_NAME` | Future AGI project receiving traces. |
| `FI_API_KEY` and `FI_SECRET_KEY` | Credential pair for noninteractive setup or a process-level override. Supply both together; keys are never command-line arguments. |
| `--no-capture-content` / `FI_AGENT_CAPTURE_CONTENT=false` | Disable prompt, response and tool-content capture. New installations capture content by default. |
| `--base-url` / `FI_BASE_URL` | Future AGI origin for a self-hosted deployment. Setup validates the destination before using the credentials. |
| `FI_USER_ID` | Optional user identifier attached to traces; prefer an opaque ID over an email address. |
| `--scope project` | Save a repository-specific tracing configuration instead of the default user configuration. |
| `--project-dir /path/to/project` | Select the project directory explicitly; otherwise the CLI uses the current directory. |
| `--user-only` | Ignore the current repository's configuration when managing the user profile. Do not combine it with `--project-dir`. |

### Configuration files and scope

| Location on macOS | Contents |
| --- | --- |
| `~/.cursor/futureagi.json` | User tracing configuration. |
| `<project>/.cursor/futureagi.json` | Project configuration created by `--scope project`. |
| `~/.cursor/hooks.json` | Shared hook registration used by the IDE and CLI. Project scope does not install a second set of project hooks. |
| `~/.config/futureagi/agents/credentials.json` | Private credential profiles, written with owner-only permissions (`0600`). Never copy this into a repository. |

To use a project-specific destination:

```bash
npx @traceai/agents setup cursor --scope project --project my-app
```

Review the destination and project shown by setup before approving use of saved credentials. A repository configuration cannot silently redirect a saved credential profile to a new destination. Project scope changes the selected project's settings; it does not disable an existing user-wide tracing configuration in other projects.

## Manage tracing

Run these commands from the project whose configuration you want to inspect. They apply to the shared IDE and CLI integration:

```bash
# Inspect configuration, hook registration and recent export state
npx @traceai/agents status cursor

# Also check the connection and credentials
npx @traceai/agents doctor cursor

# Pause exports without removing the hooks
npx @traceai/agents disable cursor

# Resume tracing
npx @traceai/agents enable cursor

# Refresh the installed runtime and hooks
npx @traceai/agents update cursor

# Disable tracing and remove the integration's owned hooks
npx @traceai/agents uninstall cursor
```

Use `status cursor --json` for machine-readable output or `status cursor --check` for a connection check. Add `--user-only` to inspect or manage the user profile without the current repository's settings. Uninstall preserves unrelated Cursor hooks; it is not a command to delete traces already stored in Future AGI.

## Privacy

With content capture enabled, traces can include source code, file paths, command output and other data the agent reads. The plugin redacts common secret patterns and bounds content size, but redaction cannot guarantee removal of every secret or personal detail.

To turn content capture off persistently, rerun setup:

```bash
npx @traceai/agents setup cursor --project cursor-sessions --no-capture-content
```

If you configured tracing with `--scope project`, include `--scope project` again when changing content capture; changing the user default does not override an existing project setting.

For a terminal session, `FI_AGENT_CAPTURE_CONTENT=false` provides the same content-off override. With content off, structural metadata such as session identifiers, model and tool names, timing, outcomes and reported usage can still be exported. This does not remove content from earlier traces or change Cursor's own data retention.

The plugin reads the local transcript associated with the turn to reconstruct model generations. It uses temporary encrypted local state to assemble hook events and exports after the turn finishes. A short-lived finisher may wait for a late CLI transcript and then exit; no persistent background service is required.

## Troubleshooting

**No trace appears.** Run `status cursor`, then `doctor cursor`. Confirm the selected project, an enabled profile, hook registration and a successful connection check. Restart Cursor and finish a new prompt. In the IDE, check Cursor's **Hooks** output channel if no activation is observed.

**CLI setup does not activate.** Use `setup cursor` and `status cursor`, not the separate `cursor-cli` profile. The supported interactive CLI path uses the shared IDE hooks. Confirm that Cursor IDE is installed and `cursor-agent` is signed in.

**Tools appear but generations or tokens are missing.** Allow about 30 seconds for the CLI transcript to settle. Use interactive mode rather than `-p`. If the transcript cannot be safely correlated to the turn, the integration retains available tool and usage data instead of inventing generations.

**Authentication fails.** Check that both keys belong to the intended Future AGI account and destination. To replace saved keys, run `npx @traceai/agents setup cursor --project cursor-sessions --replace-credentials` and enter them at the hidden prompts. Stale `FI_API_KEY` and `FI_SECRET_KEY` environment variables override saved keys.

**Duplicate registration is reported.** Remove the old Future AGI tracing entries if you previously installed a copied-hook recipe or another Future AGI hook integration. Keep unrelated hooks. Then rerun setup; the package will not overwrite a conflicting registration.

**Tracing stops after a Node.js change.** Run `doctor cursor`. If it reports a missing interpreter or runtime, restore Node.js 22.16+ and run `update cursor` to refresh the installed hooks.
