title: "OpenClaw agent tracing with Future AGI"
description: "Set up local OpenClaw tracing with one command, then inspect each prompt's model calls, tools, token usage and errors in Future AGI."
---

Trace each local OpenClaw prompt in Future AGI, with model calls, token usage and tool results beneath it. The maintained `@traceai/openclaw` integration uses OpenClaw's official [`diagnostics-otel` plugin](https://docs.openclaw.ai/gateway/opentelemetry); no collector or copied instrumentation scripts are required.

Use **OpenClaw 2026.10.5 or later in the 2026.x line**, **Node 24.16 or newer in the 24.x line**, and macOS or Linux. Configure your agent and model provider in OpenClaw first. Gateway, channels, TUI, Control UI and `agent exec` tracing are **not yet available** through this integration.

## 1. Get your Future AGI keys

Create an API key and secret key at [Future AGI → Keys](https://app.futureagi.com/dashboard/keys). Setup asks for both with hidden terminal input. Do not paste them into an agent conversation.

## 2. Set up tracing

```bash
npx @traceai/agents setup openclaw --project coding-agents
```

Setup validates your credentials, saves private settings and installs the diagnostics and integration plugins through OpenClaw's own installer. Review OpenClaw's source and capability prompts in your terminal. Setup does not accept those prompts or grant conversation-access hooks for you, and preserves existing plugin allowlists and model settings.

**Content capture is on by default.** Messages and tool results can include source files or secrets that the agent reads. To keep structure and usage without content, add `--no-capture-content`:

```bash
npx @traceai/agents setup openclaw --project coding-agents --no-capture-content
```

## 3. Run a local turn

```bash
npx @traceai/agents run openclaw -- agent --local --agent main \
  --session-id readme-review --message "Read README.md and summarize the project."
```

Replace `main` with your configured agent ID if needed. Reuse `--session-id` for later prompts in the same conversation; without it, the launcher creates a new session ID for each invocation.

Open your **coding-agents** project in [Future AGI](https://app.futureagi.com) and select an `openclaw.prompt` trace. Expand its model and tool spans to inspect the requests, results, usage and errors.

**Use the launcher for traced runs.** An ordinary `openclaw` launch is not redirected to Future AGI. Setup does not restart a running Gateway.

## What you see

| Trace detail | What it shows |
| --- | --- |
| One `openclaw.prompt` trace per launcher invocation | The prompt's overall duration and outcome, with retries beneath the same root. |
| Model calls | Model/provider, input/output when exposed, input/output/cache tokens, reported time to first byte and error status. |
| Tool calls | Tool names, input/output when exposed, duration and error status. |
| Sessions | An opaque session identifier groups prompts that use the same `--session-id`; each prompt remains a separate trace. |
| Native lifecycle spans | Run and context-assembly timings. Subagent and compaction visibility is limited to the spans OpenClaw's official plugin emits. |

Content is included only when OpenClaw exposes it and your privacy settings allow it. Native timings and internal parent relationships are preserved beneath the prompt root; the integration does not instrument model calls twice.

Request tokens are counted once. The repeated `openclaw.model.usage` rollup is removed, and usage is not assigned to failed attempts. If an external harness exposes only turn-level usage, the prompt root owns that usage once instead of inventing model calls. OpenClaw exports cost estimates as metrics, which this integration does not send. System prompts and external-harness internals are not available as content.

## Configuration

Setup saves user-level settings by default. Credentials are separate from preferences and are never written into your repository.

| File | Purpose |
| --- | --- |
| `~/.config/futureagi/agents/credentials.json` | Saved credentials, protected with file mode `0600`. `XDG_CONFIG_HOME` replaces `~/.config`; `FI_AGENT_CONFIG_DIR` overrides the shared directory. |
| `~/.openclaw/futureagi.json` | User preferences beside OpenClaw's host configuration. Discovery respects `OPENCLAW_CONFIG_PATH`, then `OPENCLAW_STATE_DIR`, then `OPENCLAW_HOME/.openclaw`, before the default path. |
| `.futureagi/agents.json` | Repository preferences when you choose project scope; contains no credentials. |

| Setting | Effect |
| --- | --- |
| `FI_API_KEY` and `FI_SECRET_KEY` | A complete environment pair overrides saved credentials; use for headless setup. |
| `FI_PROJECT_NAME` | Future AGI destination project. |
| `FI_AGENT_CAPTURE_CONTENT=false` | Exclude messages, tool content and error messages. Also available at setup as `--no-capture-content`. |
| `FI_HIDE_INPUTS=true` / `FI_HIDE_OUTPUTS=true` | Apply stricter input/output privacy. |
| `FI_HIDE_ERROR_DETAILS=true` | Keep error status without its details. |
| `FI_AGENT_ENABLED=false` | Stop export while the agent continues to run. |
| `FI_USER_ID` | Use an explicit user identifier instead of the saved opaque ID. Avoid personal data. |
| `FI_BASE_URL` | Self-hosted API origin. |
| `FI_OTLP_ENDPOINT` | Exact trace URL; overrides `FI_BASE_URL`. |
| `FI_AGENT_CONFIG_DIR` | Override the shared protected configuration directory. |

The Cloud destination is `https://api.futureagi.com/tracer/v1/traces`. The integration sends `X-Api-Key`, `X-Secret-Key` and `X-Project-Name`, with resource attributes `project_name` and `project_type=observe`. Metrics and logs stay off.

### Project scope

Commands read the current directory's project configuration by default. For a separate project destination, run these commands from your repository:

```bash
npx @traceai/agents setup openclaw --scope project --project my-project
npx @traceai/agents run openclaw -- agent --local --agent main --message "Summarize README.md"
```

Use `--project-dir /path/to/repo` on setup, run and status commands when working from elsewhere. Use `--user-only` without `--project-dir` to ignore repository settings and use only your user configuration. A repository cannot silently increase content capture or redirect saved credentials to an unapproved destination; rerun setup to approve the intended destination.

## Status and controls

```bash
npx @traceai/agents status openclaw --check
npx @traceai/agents doctor openclaw
npx @traceai/agents disable openclaw
npx @traceai/agents enable openclaw
npx @traceai/agents update openclaw
npx @traceai/agents uninstall openclaw
```

Status reports configuration, plugin registration, credential acceptance and recent exports. After setup, activation remains unobserved until you run a traced prompt. Use `doctor` to check configuration and connectivity.

Disable works without credentials or network and stops already-running exporters and queued work. It cannot recall data already accepted by a server. After upgrading the CLI, run `update`; if the integration plugin changed, follow OpenClaw's interactive replacement prompts and rerun update. Headless update prints the commands to complete that review.

Uninstall restores only unchanged settings owned by the integration. Shared native plugins remain installed, but do not export through Future AGI without the launcher. Settings you modified after installation are not overwritten.

## Troubleshooting

**Setup returns `TRUST_REQUIRED`.** Complete OpenClaw's interactive source and capability review for the integration plugin, then rerun setup. Enabling diagnostics does not authorize conversation-access hooks.

**Registered, but no exports.** Run through `npx @traceai/agents run openclaw -- agent --local ...`, not an ordinary OpenClaw launch or an existing Gateway. Check your agent/provider configuration in OpenClaw, then run `doctor openclaw`.

**Unsupported host version.** Check `openclaw --version` and `node --version`. Use OpenClaw 2026.10.5 or later in the 2026.x line with Node 24.16 or newer in the 24.x line.

**Existing exporter or preload.** Keep your existing tracing route or explicitly remove it before setup. Do not run two tracing routes together; setup will not disable an existing exporter for you.

**Project config is ignored.** `PROJECT_CONFIG_IGNORED` means the repository settings are malformed or their location is unsafe. Tracing continues with protected user settings. Fix the file or use an owner-controlled directory for project overrides.

**Destination is not approved or registration changed.** Rerun setup for the intended project and endpoint. Inspect host-config changes before updating; the integration will not overwrite settings you changed after installation.

**Content is missing.** Check `FI_AGENT_CAPTURE_CONTENT`, input/output privacy settings and OpenClaw's own access policy. The official plugin does not expose system prompts or external-harness internals.

## Privacy and delivery

Content capture includes what the agent reads or produces. The integration removes host/process metadata, arbitrary attributes, event payloads and tool definitions, bounds captured fields to 20,000 characters and applies best-effort redaction, including known Future AGI credentials. Redaction cannot reliably detect every application secret. Turn content capture off for sensitive work.

Environment-supplied Future AGI keys are removed before the model/tool runtime starts. Programs running as your OS user can still access the credential store. This package does not read `.env` files, shell profiles or keychains; OpenClaw's own environment and access policies still apply.

The launcher handles delivery without a background daemon, local receiver or model proxy. Temporary capture records are encrypted with a per-run, memory-only key in an immediately unlinked private file, capped at 4 MiB per invocation. No plaintext capture file or reusable key is saved. The launcher drains delivery for up to five seconds after the agent exits. Network failures drop telemetry rather than failing model/tool calls; force-killing the launcher can lose queued spans. Delivery is not exactly-once.
