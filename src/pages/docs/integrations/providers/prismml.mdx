Trace calls to your local [PrismML Bonsai server](https://docs.prismml.com/run/server) using the maintained [traceAI OpenAI integration](/docs/integrations/traceai/openai). This guide covers your Python client's Chat Completions requests, not the server's built-in web chat or other products named Prism.

## Install

Use Python 3.10–3.13:

```bash
python -m pip install 'openai==3.42.1' 'traceAI-openai==0.1.12' 'fi-instrumentation-otel==1.2.2'
```

## Start the local server

Follow the [PrismML setup](https://docs.prismml.com/run/server) to download a model. In the Bonsai demo directory, start the llama.cpp server with a stable model alias:

```bash
./scripts/start_llama_server.sh --alias bonsai
```

The API base URL is `http://localhost:8080/v1`. The SDK appends `/chat/completions`; do not include that suffix in the base URL.

<Warning>
The local server does not authenticate requests. Keep it on loopback, or restrict access with a trusted network and firewall. The `not-needed` key below is only a placeholder required by the OpenAI SDK, not a Future AGI credential.
</Warning>

On Apple Silicon, PrismML also provides `./scripts/start_mlx_server.sh` at `http://localhost:8081/v1`. Follow the [MLX sampling and thinking settings](https://docs.prismml.com/run/server), which must be supplied in each request rather than inherited from the llama.cpp launcher.

## Configure tracing

Set your Future AGI credentials separately from the model server address:

```bash
export FI_API_KEY="YOUR_FUTURE_AGI_API_KEY"
export FI_SECRET_KEY="YOUR_FUTURE_AGI_SECRET_KEY"
export FI_PROJECT_NAME="prismml-bonsai"
export PRISMML_BASE_URL="http://localhost:8080/v1"
export PRISMML_MODEL="bonsai"
```

Trace export goes to `https://api.futureagi.com/tracer/v1/traces` by default. If you self-host Future AGI, set `FI_BASE_URL` to its origin, without `/tracer/v1/traces`. Do not point it at the Bonsai server.

## Run a completion

Save this as `prismml_chat.py`. Instrument the OpenAI SDK once, before creating the client; do not layer another OpenAI instrumentor over the same requests.

```python
import os

from fi_instrumentation import register
from fi_instrumentation.fi_types import ProjectType
from openai import OpenAI
from traceai_openai import OpenAIInstrumentor

provider = register(
    project_name=os.environ.get("FI_PROJECT_NAME") or "prismml-bonsai",
    project_type=ProjectType.OBSERVE,
    set_global_tracer_provider=False,
    verbose=False,
)
OpenAIInstrumentor().instrument(tracer_provider=provider)
try:
    with OpenAI(
        base_url=os.environ.get("PRISMML_BASE_URL") or "http://localhost:8080/v1",
        api_key=os.environ.get("PRISMML_API_KEY") or "not-needed",
    ) as client:
        response = client.chat.completions.create(
            model=os.environ.get("PRISMML_MODEL") or "bonsai",
            messages=[{"role": "user", "content": "What is the capital of France?"}],
        )
        print(response.choices[0].message.content or "")
finally:
    provider.force_flush()
```

```bash
python prismml_chat.py
```

`PRISMML_API_KEY` is optional and defaults to `not-needed`. The script prints the answer and flushes the trace before exiting.

## View the result

Open **Observe** in Future AGI and select `prismml-bonsai`, or the project set in `FI_PROJECT_NAME`. Each completion produces one `ChatCompletion` LLM span with the prompt, answer, latency and token counts supplied by the server. The provider label is `openai` because this local endpoint uses the shared OpenAI instrumentor.

Non-streamed calls record the server's returned model name in `gen_ai.request.model`. For streamed and failed calls, that field contains the requested name. Local models may have no matching price entry, so cost can be unavailable even when token counts are present.

For a ready-to-run streaming client, use the [PrismML recipe](https://github.com/future-agi/traceAI/tree/dev/python/examples/prismml). Streamed token counts require both `stream_options={"include_usage": True}` and a final usage chunk from the server; missing counts are not replaced with zero.

## Privacy

Local model execution does not mean local-only telemetry: prompts and answers are exported to Future AGI by default. Set these before starting the script to hide content and invocation parameters:

```bash
export FI_HIDE_INPUTS=true
export FI_HIDE_OUTPUTS=true
export FI_HIDE_LLM_INVOCATION_PARAMETERS=true
```

Hide both inputs and outputs when the answer might echo sensitive input. These flags do not change what the local server receives or logs.

The model name remains visible metadata. Without an alias, llama-server can return the model file's absolute path, including your user name or directory layout. Use `--alias bonsai` to keep that path out of traces.

## Troubleshooting

- **Connection refused:** start the server and check the port: 8080 for llama.cpp, 8081 for MLX.
- **404 from the server:** use the API base URL ending in `/v1`, not the web chat root or the full completion URL.
- **No traces:** check your Future AGI keys, project name and export origin. See [No traces appearing](/docs/observe/troubleshooting/no-traces-appearing).
- **A local path appears as the model:** restart llama-server with `--alias bonsai`.
