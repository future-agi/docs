## About

CometAPI serves an OpenAI-compatible chat endpoint. You keep using `openai.OpenAI`, set `base_url` to `https://api.cometapi.com/v1`, and the existing [traceAI-openai](/docs/integrations/traceai/openai) instrumentor traces the call. There is no CometAPI package to install and nothing to configure on the CometAPI side.

This page is not:

- **A CometAPI export.** It traces calls your own code makes. It does not read CometAPI usage logs, the dashboard or billing, and it does not import history.
- **A new traceAI package.** There is no `traceai-cometapi`. The existing instrumentor handles the call, and [What is not captured](#what-is-not-captured) lists the gaps found.
- **A recipe for every CometAPI model.** It covers `chat.completions.create` on `/v1/chat/completions` only. Models that CometAPI says need the Responses API, and image, video and audio routes, are not covered. See [What this page covers](#what-this-page-covers).

The provider name on the span reads `openai`, not CometAPI. That is a display limit of the instrumentor, not something this page can change.

## Install

Install the OpenAI instrumentor and the OpenAI SDK.

```bash
pip install traceAI-openai openai
```

## Trace a chat completion

Set the three keys. The CometAPI key goes to the OpenAI client. The Future AGI keys go to `register()`. Neither key belongs on a span.

```bash
export COMETAPI_KEY="YOUR_COMETAPI_KEY"
export FI_API_KEY="YOUR_API_KEY"
export FI_SECRET_KEY="YOUR_SECRET_KEY"
```

Then register the tracer, install the instrumentor, and build the client. Replace the model with a current model ID from CometAPI's [Models page](https://apidoc.cometapi.com/overview/models).

```python
import os

from fi_instrumentation import register
from fi_instrumentation.fi_types import ProjectType
from openai import OpenAI
from traceai_openai import OpenAIInstrumentor

trace_provider = register(
    project_type=ProjectType.OBSERVE,
    project_name="my-chatbot",
)
OpenAIInstrumentor().instrument(tracer_provider=trace_provider)

client = OpenAI(
    api_key=os.environ["COMETAPI_KEY"],
    base_url="https://api.cometapi.com/v1",
)

response = client.chat.completions.create(
    model="your-model-id",
    messages=[{"role": "user", "content": "What is the capital of France?"}],
)
print(response.choices[0].message.content)
```

<div style={{ overflowX: 'auto' }}>

| Piece | Value |
| --- | --- |
| Client | `openai.OpenAI` from the `openai` package |
| Base URL | `https://api.cometapi.com/v1` |
| Chat path | `https://api.cometapi.com/v1/chat/completions` |
| Auth | `Authorization: Bearer <COMETAPI_KEY>`, which the OpenAI client sends for `api_key`. CometAPI's own examples read the key from `COMETAPI_KEY` |
| Model | A current model ID from CometAPI's Models page. This page does not pin one, because CometAPI's catalog changes |
| Project | `project_name` in `register()`. The instrumentor does not set it |
| Self-hosted Future AGI | Also export `FI_BASE_URL` with your collector URL |

</div>

Build the client after `register()` and `instrument()`, as above. CometAPI still receives your prompt: tracing sends a copy to Future AGI and does not change what the API sees.

### The base URL

Use the string from CometAPI's quickstart, `https://api.cometapi.com/v1`. It is the only host this page documents. There is no regional host here and this page does not retry against another one.

- **Trailing slash.** `https://api.cometapi.com/v1/` and `https://api.cometapi.com/v1` reach the same `/v1/chat/completions` path through the OpenAI client, and the span is the same (checked against the stand-in only, not against live CometAPI).
- **Missing `/v1`.** CometAPI's base-URL guide lists `404` for a base URL without `/v1`. Its error-handling page says a wrong base URL or path may show up as a `301` redirect or HTML instead of a clean JSON `404`. Live check on 2026-10-17: `POST https://api.cometapi.com/chat/completions` (no `/v1`) returned `404` with a JSON body, `Invalid URL (POST /chat/completions)`, no redirect and no HTML. Either way it is a client configuration error: the call fails and is traced as a failed call, as the [error row](#what-you-get) below shows. It is not a tracing fault.

## What you get

Each call below produced the spans shown, including on the live CometAPI run of 2026-10-17. "Stand-in" means the CometAPI-shaped local server; "real model" means the local OpenAI-compatible proxy running a real model. Neither is CometAPI.

<div style={{ overflowX: 'auto' }}>

| Call | What lands in Observe | Notes |
| --- | --- | --- |
| `chat.completions.create` | One `LLM` span with the model, input and output messages, and input, output and total tokens | The model on a non-streaming span is the `model` field of the response body, not the id you sent. When the stand-in answered with a different model id, the span showed the response's id. Live: asking CometAPI for `gpt-4o-mini` returned `model: gpt-4o-mini-2024-07-18`, and that is the value on the span |
| `stream=True` | One `LLM` span with a first-token event | Token counts are present only when you pass `stream_options={"include_usage": True}`, which CometAPI's chat page documents. Without it the span has no token counts |
| Tool calls | Two `LLM` spans, one per round trip. The first carries the tool definitions | Running the tool is your code. It becomes a span only if you create one |
| A failed call | An `LLM` span with status `ERROR`, the exception type and the HTTP status in the message, and an `exception` event | Observed live with a wrong key (CometAPI answered `401`, `type: cometapi_error`, `invalid token (request id: ...)`), and against the stand-in with a base URL without `/v1` |

</div>

Spans group under any parent span or session you create. The example app wraps its calls in one `AGENT` span and a session id so the whole run is one trace.

## What is not captured

- **The model on streaming and failed calls, on 0.1.10.** traceAI-openai 0.1.10 leaves `gen_ai.request.model` off streaming spans and failed-call spans. [traceAI PR 249](https://github.com/future-agi/traceAI/pull/249) (open, not released) records it. The tests in the example pass on both.
- **Provider name.** `gen_ai.provider.name` is `openai`, and the local platform stored `openai` in its provider column. PR 249 adds a host-to-provider table that does not contain `api.cometapi.com`, so the value stays `openai` there too. Look for the project and model, not the provider name.
- **The host.** The exported span carries no CometAPI hostname, including on a failed connection. You cannot filter by host from the span.
- **CometAPI request ids.** CometAPI error messages include `(request id: ...)`. That text is part of the span's error status. No other CometAPI header or id is recorded.
- **Cost.** The span carries no price. The local platform stored a cost of 0 for the stand-in model id and showed `$0.00`. Whether it prices real CometAPI model ids was not checked (the live run did not inspect cost), and this page copies nothing from CometAPI's pricing.
- **Reasoning tokens.** Not checked live; the live run used a non-reasoning model.
- **Other APIs.** The Responses API, image, video and audio routes are outside this guide’s coverage. See [What this page covers](#what-this-page-covers).
- **TypeScript.** Only the Python client was tested.

## Privacy

traceAI-openai follows the standard traceAI `TraceConfig` defaults: prompts, completions, tool arguments and results, and request parameters are captured unless you turn them off. Set these before the process starts, or pass the same settings to `TraceConfig`.

```bash
export FI_HIDE_INPUTS=true
export FI_HIDE_OUTPUTS=true
export FI_HIDE_LLM_INVOCATION_PARAMETERS=true
```

With those three set, the model, token counts, status and timing still arrive and the content does not. Input and output fields hold `__REDACTED__`, the request parameters attribute is absent, and a unique marker placed in the system prompt, the user prompt, the model's answer, the tool-call arguments and the tool result appeared in no stored column of the local platform. With the variables unset, the same marker appeared in the prompts, answers, tool arguments and results. Content is therefore on by default. To turn it back on after hiding it, unset the variables or set them to `false`.

What the hide settings do not remove on traceAI-openai 0.1.10:

- **Tool definitions.** The name, description and JSON schema of tools you pass are still on the span.
- **Session id.** The id you set, if any, stays.
- **Error text.** The status message, such as `AuthenticationError: Error code: 401 - ...`, includes the CometAPI error body and its request id. The exported `exception` event also carries the exception message and a stack trace with local file paths. The local platform did not keep the stack trace in its stored rows in the runs documented here, but it is on the wire.

If your errors can contain sensitive text, do not rely on the hide settings for them.

CometAPI receives your prompts and responses whatever you set here. The hide settings only change the copy that goes to Future AGI.

## Run it yourself

The example in [`examples/providers/cometapi`](https://github.com/future-agi/docs/tree/main/examples/providers/cometapi) contains the recipe as a runnable app, a CometAPI-shaped stand-in, and tests. Its `run_e2e.sh` installs the pinned versions in a virtual environment, runs the tests, and exports to your collector.

```bash
cd examples/providers/cometapi
export FI_API_KEY="YOUR_API_KEY" FI_SECRET_KEY="YOUR_SECRET_KEY"
export FI_BASE_URL="http://localhost:4318"   # your collector, if self-hosted
./run_e2e.sh                                   # stand-in, no CometAPI account needed

COMETAPI_KEY="YOUR_COMETAPI_KEY" COMETAPI_MODEL="your-model-id" ./run_e2e.sh   # real CometAPI, may cost money
```

With `COMETAPI_KEY` set, the script calls `https://api.cometapi.com/v1`. It never creates an account.

## Troubleshooting

<div style={{ overflowX: 'auto' }}>

| Symptom | Cause and fix |
| --- | --- |
| The span says `openai`, not CometAPI | Known display limit. Look for the project and model, not the provider name |
| HTTP 401 from CometAPI | CometAPI's own auth error. Its guide says to send `Authorization: Bearer $COMETAPI_KEY`. The instrumentor does not retry against another host. Live body on 2026-10-17: `{'error': {'code': '', 'message': 'invalid token (request id: ...)', 'type': 'cometapi_error'}}` |
| HTTP 404, a redirect, or HTML instead of JSON | The base URL is probably missing `/v1`. Use `https://api.cometapi.com/v1` exactly. This is a client configuration error, not a tracing fault |
| The call fails for a coding or reasoning model | CometAPI says some of those models require the Responses API, which this page does not cover. Check the model's page on CometAPI |
| Image, audio or video calls are not traced as expected | Not covered. This page is chat completions only |
| No spans appear | Install the instrumentor with `tracer_provider=trace_provider` and use the `openai` package. Check `FI_API_KEY`, `FI_SECRET_KEY` and, if self-hosted, `FI_BASE_URL`. See [No traces appearing](/docs/observe/troubleshooting/no-traces-appearing) |
| A streaming span has no token counts | Pass `stream_options={"include_usage": True}` |
| `ai-evaluation is not installed, please install it to trace protect` printed at startup | Warning logged by `traceai-openai` on import. It concerns tracing Protect guardrails and did not affect chat tracing in these runs |
| `pip install` fails on Python 3.14 | traceAI-openai 0.1.10 requires Python below 3.14. Use 3.10 to 3.13 |

</div>
