## About

Novita AI serves an OpenAI-compatible chat API. You keep using `openai.OpenAI`, set `base_url` to Novita's versioned OpenAI-compatible URL, and the existing [traceAI-openai](/docs/integrations/traceai/openai) instrumentor traces the call. There is no Novita package to install and nothing to configure on the Novita side.

This page is not:

- **A Novita export.** It traces calls your own code makes. It does not read Novita usage logs or billing, and it does not import history.
- **A new traceAI package.** There is no `traceai-novita`, and nothing here rewrites a wrong URL. The instrumentor traces whatever the client sends. [What is not captured](#what-is-not-captured) lists the gaps found.
- **Novita's other products.** Image, video and audio generation, GPU instances, serverless GPUs, agent sandboxes, batch jobs, embeddings, rerank and Novita's own `novita-client` and `novita-sdk` packages were not tested. Novita's Anthropic-compatible URL (`https://api.novita.ai/anthropic`, used in Novita's Claude Code guide) is a different route and is not covered.

The provider name on the span reads `openai`, not Novita. That is a display limit of the instrumentor, not something this page can change.

## Which base URL

Use `https://api.novita.ai/openai/v1`. Novita's own pages show more than one string, so here is what each one is. Everything below was read on 2026-10-15.

<div style={{ overflowX: 'auto' }}>

| Base URL | Where it appears | Use it? |
| --- | --- | --- |
| `https://api.novita.ai/openai/v1` | The [Quickstart](https://docs.novita.ai/guides/quickstart) (`curl .../openai/v1/chat/completions`), the curl examples in the [LLM API guide](https://docs.novita.ai/guides/llm-api), the first request in the [API reference overview](https://docs.novita.ai/api-reference/api-reference-overview) (`.../openai/v1/models`), the [Hermes guide](https://docs.novita.ai/guides/hermes), and Novita's [Kimi K3 post](https://blogs.novita.ai/kimi-k3-api-quick-start) of 2026-07-22 | Yes. This is the recipe. The OpenAI client appends `/chat/completions`, so it requests `https://api.novita.ai/openai/v1/chat/completions`, the URL in Novita's Quickstart |
| `https://api.novita.ai/openai` | The API overview and `llms.txt` ("OpenAI-Compatible Endpoints"), the Python examples in the LLM API guide, and Novita's guides for the OpenAI Agents SDK, LangChain, Langfuse, Cursor and function calling | Not the recipe. Novita presents it as the root of its OpenAI-compatible routes and also uses it as an SDK base URL. The client then requests `https://api.novita.ai/openai/chat/completions`, a path no Novita curl example uses. Novita's Kimi K3 post lists it among common mistakes "when the client expects the versioned `.../openai/v1` path". Whether the live service routes that path was not checked. The trace is the same either way |
| `https://api.novita.ai/v3/openai` | [Langfuse's Novita page](https://langfuse.com/integrations/model-providers/novitaai). It appears in none of the Novita pages above | No |

</div>

Novita's pages disagree with each other, and this page does not settle it for you. It picks the form whose request URL matches Novita's Quickstart. If your own code or another Novita guide already uses `https://api.novita.ai/openai` and works, keep it. Tracing does not depend on the choice: traceAI-openai reads the host of `base_url` and never its path, and with the stand-in serving both paths the two forms produced identical spans. If you switch and calls start failing with 404, use the table to see which form you are on. The span for a failed call is an `ERROR` span with the HTTP status, so the failure is visible in Future AGI too.

## Install

Install the OpenAI instrumentor and the OpenAI SDK.

```bash
pip install traceAI-openai openai
```

## Trace a chat completion

Set the three keys. The Novita key goes to the OpenAI client. The Future AGI keys go to `register()`. Neither key belongs on a span.

```bash
export NOVITA_API_KEY="YOUR_NOVITA_API_KEY"
export FI_API_KEY="YOUR_API_KEY"
export FI_SECRET_KEY="YOUR_SECRET_KEY"
```

Then register the tracer, install the instrumentor, and build the client. Replace the model with an id copied from Novita's Model Hub.

```python
import os

from fi_instrumentation import register
from fi_instrumentation.fi_types import ProjectType
from openai import OpenAI
from traceai_openai import OpenAIInstrumentor

trace_provider = register(
    project_type=ProjectType.OBSERVE,
    project_name="my-chatbot",
)
OpenAIInstrumentor().instrument(tracer_provider=trace_provider)

client = OpenAI(
    api_key=os.environ["NOVITA_API_KEY"],
    base_url="https://api.novita.ai/openai/v1",
)

response = client.chat.completions.create(
    model="your-model-id",
    messages=[{"role": "user", "content": "What is the capital of France?"}],
    max_tokens=128,
)
print(response.choices[0].message.content)
```

<div style={{ overflowX: 'auto' }}>

| Piece | Value |
| --- | --- |
| Client | `openai.OpenAI` from the `openai` package |
| Base URL | `https://api.novita.ai/openai/v1`. See [Which base URL](#which-base-url) |
| Auth | `Authorization: Bearer <NOVITA_API_KEY>`, which the OpenAI client sends for `api_key`. Do not add a second auth scheme |
| Model | An id from Novita's Model Hub. Novita's own examples use ids such as `deepseek/deepseek-v4.1-flash` (Quickstart); check the Model Hub for what your key can call. This page does not freeze one |
| `max_tokens` | Novita's chat reference lists it as a required field and its Quickstart sends it, so the recipe does too |
| Project | `project_name` in `register()`. The instrumentor does not set it |
| Self-hosted Future AGI | Also export `FI_BASE_URL` with your collector URL |

</div>

Build the client after `register()` and `instrument()`, as above. Novita still receives your prompt: tracing sends a copy to Future AGI and does not change what the API sees.

## What you get

Each call below produced the spans shown. "Stand-in" means the Novita-shaped local server; "real model" means the local OpenAI-compatible proxy running a real model. Neither is Novita.

<div style={{ overflowX: 'auto' }}>

| Call | What lands in Observe | Notes |
| --- | --- | --- |
| `chat.completions.create` | One `LLM` span with the model, input and output messages, and input, output and total tokens | The model on a non-streaming span is the `model` field of the response body, not the id you sent. When the stand-in answered with a different model id, the span showed the response's id |
| `stream=True` | One `LLM` span with a first-token event | Token counts are present only when you pass `stream_options={"include_usage": True}`, which Novita's chat reference documents. What Novita sends without it was not checked; the stand-in sends no usage, and the span then has no token counts |
| Tool calls | Two `LLM` spans, one per round trip. The first carries the tool definitions | Running the tool is your code. It becomes a span only if you create one. Novita's function-calling guide says not to repeat `tools` on the request that carries the tool result, and the example app does not |
| A failed call | An `LLM` span with status `ERROR`, the exception type and the HTTP status in the message, and an `exception` event | Observed with a wrong key against the stand-in and the proxy. A path the server does not route fails the same way |

</div>

Spans group under any parent span or session you create. The example app wraps its calls in one `AGENT` span and a session id so the whole run is one trace.

## What is not captured

- **The host, the path and the region.** The exported span carries no Novita hostname and no URL. You cannot filter by base URL from the span. Put what you need in your `project_name` or in your own span attribute.
- **Novita request ids.** The `trace_id` that Novita's error envelope can carry is part of the error text on a failed call. It is not an attribute you can filter on.
- **Reasoning output.** Novita's reference documents `separate_reasoning` with `reasoning_content` and `enable_thinking` for some models. Neither was tested, and the stand-in does not return reasoning text. Whether reasoning tokens are inside `usage.completion_tokens` was not checked against a live response.
- **The model on streaming and failed calls, on 0.1.10.** traceAI-openai 0.1.10 leaves `gen_ai.request.model` off streaming spans and failed-call spans. [traceAI PR 249](https://github.com/future-agi/traceAI/pull/249) (open, not released) records it. The tests in the example pass on both.
- **Provider name.** `gen_ai.provider.name` is `openai` for the Novita host. PR 249 adds a host-to-provider table that does not contain `api.novita.ai`, so the value stays `openai` there too.
- **Cost.** The span carries no price. The local platform stored a cost of 0 for the stand-in model id and the proxy's model id and shows `$0.00`. Whether it prices real Novita model ids was not checked.
- **Other Novita APIs.** Legacy completions, embeddings, rerank, batch, structured outputs, vision and audio inputs were not tested.
- **TypeScript.** Only the Python client was tested.

## Privacy

traceAI-openai follows the standard traceAI `TraceConfig` defaults: prompts, completions, tool arguments and results, and request parameters are captured unless you turn them off. Novita sees your prompts too, so decide what you want in Future AGI separately. Set these before the process starts, or pass the same settings to `TraceConfig`.

```bash
export FI_HIDE_INPUTS=true
export FI_HIDE_OUTPUTS=true
export FI_HIDE_LLM_INVOCATION_PARAMETERS=true
```

With those three set, the model, token counts, status and timing still arrive and the content does not. Input and output fields hold `__REDACTED__`, the request parameters attribute is absent, and a unique marker placed in the system prompt, the user prompt, the model's answer, the tool-call arguments and the tool result appeared in no stored column of a local Future AGI stack (every ClickHouse table and a full Postgres dump). With the variables unset, the same marker appeared in the stored input, output and attribute columns. Content is therefore on by default. To turn it back on after hiding it, unset the variables or set them to `false`.

What the hide settings do not remove on traceAI-openai 0.1.10:

- **Tool definitions.** The name, description and JSON schema of tools you pass are still on the span.
- **Session id.** The id you set, if any, stays.
- **Error text.** The status message, such as `AuthenticationError: Error code: 401 - ...`, includes the error body the server returned. The exported `exception` event also carries the exception message and a stack trace with local file paths. The local platform did not keep the stack trace in its span store in the runs documented here, but it is on the wire.

If your errors can contain sensitive text, do not rely on the hide settings for them. In the same runs, no local path, user name, host name or the stand-in's API key was in any stored span row, with content hidden.

## Run it yourself

The example in [`examples/providers/novita-ai`](https://github.com/future-agi/docs/tree/main/examples/providers/novita-ai) contains the recipe as a runnable app, a Novita-shaped stand-in, and tests. Its `run_e2e.sh` installs the pinned versions in a virtual environment, runs the tests, and exports to your collector.

```bash
cd examples/providers/novita-ai
export FI_API_KEY="YOUR_API_KEY" FI_SECRET_KEY="YOUR_SECRET_KEY"
export FI_BASE_URL="http://localhost:4318"   # your collector, if self-hosted
./run_e2e.sh                                   # stand-in, no Novita account needed

NOVITA_API_KEY="YOUR_NOVITA_API_KEY" NOVITA_MODEL="your-model-id" ./run_e2e.sh   # real Novita, costs money
```

With `NOVITA_API_KEY` set, the script calls Novita at `https://api.novita.ai/openai/v1`. It never creates an account. To try the other form from [Which base URL](#which-base-url) against your own key, add `NOVITA_BASE_URL="https://api.novita.ai/openai"`. A real run is also the way to check which of the two paths Novita routes.

## Troubleshooting

<div style={{ overflowX: 'auto' }}>

| Symptom | Cause and fix |
| --- | --- |
| The span says `openai`, not Novita | Known display limit. Look for the project and model, not the provider name |
| HTTP 401 or 403 from Novita | Novita's [error codes page](https://docs.novita.ai/guides/error) says 401 means the key is missing, malformed or deleted, and that the gateway can return 403 `INVALID_API_KEY` for a missing or invalid key. A 403 can also mean the key's model access excludes the model. The span is an `ERROR` span, and the instrumentor does not retry against another host. Which status a live chat call returns for a wrong key was not checked |
| HTTP 404 | Check the base URL against [Which base URL](#which-base-url) and the model id against the Model Hub. Novita lists `MODEL_NOT_FOUND` as a 404. There is no path-normalizing proxy and the instrumentor does not fix a path |
| HTTP 400 (`INVALID_REQUEST_BODY` in Novita's error list) | Novita's chat reference lists `max_tokens` as a required field, so pass it, as the recipe does. Whether a request without it is rejected was not checked |
| No spans appear | Install the instrumentor with `tracer_provider=trace_provider` and use the `openai` package. Check `FI_API_KEY`, `FI_SECRET_KEY` and, if self-hosted, `FI_BASE_URL`. See [No traces appearing](/docs/observe/troubleshooting/no-traces-appearing) |
| A streaming span has no token counts | Pass `stream_options={"include_usage": True}` |
| `ai-evaluation is not installed, please install it to trace protect` printed at startup | Warning logged by `traceai-openai` on import. It concerns tracing Protect guardrails and did not affect chat tracing in these runs |
| `pip install` fails on Python 3.14 | traceAI-openai 0.1.10 requires Python below 3.14. Use 3.10 to 3.13 |

</div>
