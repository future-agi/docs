## About

The Open WebUI Pipe adds **Traced model** to your model picker. When you select it, Open WebUI sends the request to the model you configured and records one `openwebui.model` LLM span in Future AGI. If a support chat calls the model once to choose a tool and again to answer, you see two model calls, not one span timed across the whole turn.

## Set up the Pipe

You need admin access to a self-hosted Open WebUI instance (0.11.4 through 0.12.x, Python 3.11 or 3.12), a working OpenAI-compatible **Chat Completions** connection, and a [Future AGI key pair](/docs/quickstart/setup-observability). First check that the person who will use the chat can send a message to the target model directly. The Pipe delegates as the signed-in person; enabling it does not grant access to the target.

<Steps>
  <Step title="Retire the old Filter if you used it">
    In **Admin Panel → Functions**, disable and remove the copied Future AGI Filter before enabling the Pipe. Installing a package does not change Functions saved in Open WebUI's database. The old Filter labeled a whole-turn summary `openwebui.llm` under `openwebui.chat`; its latency and cumulative tool-loop usage are not per-request measurements. Leave only one producer counting these calls, including at the model gateway.
  </Step>
  <Step title="Generate the Function import file">
    Run these commands in the same Python environment that runs Open WebUI. For a container, install the package in your image, run the export there, and copy the JSON file to the computer where you open the admin panel.

    ```bash
    python -m pip install traceAI-openwebui==0.1.0
    traceai-openwebui export-function --output traceai-openwebui.json
    ```

    The JSON contains a small loader for the installed package. Use a new filename if the file already exists; the export command does not overwrite it.

    The Pipe checks the installed `open-webui` Python distribution on each call. If you build from the official `v0.12.5-slim` image, the server source is present but its distribution metadata is not. Add the matching host wheel to that image without replacing its dependencies:

    ```bash
    python -m pip install --no-deps open-webui==0.12.5
    ```
  </Step>
  <Step title="Import the Function and set its valves">
    Set `ENABLE_VALVE_ENCRYPTION=true` in Open WebUI before storing credentials. In **Admin Panel → Functions**, choose **Import JSON** and select `traceai-openwebui.json`. Open the valves (settings) for **Traced model** and set the values below.

    | Valve | What to enter |
    | --- | --- |
    | `target_model` | The exact model ID shown for your Chat Completions connection, not the display name of a workspace preset. |
    | `api_key`, `secret_key` | Both keys from your Future AGI workspace. These are not your model provider credentials. |
    | `project` | Your Observe project name. Use `ridgeline-support` for the example below. The default is `open-webui`. |
    | `endpoint` | Leave `https://api.futureagi.com` for Future AGI Cloud. For self-hosting, use your collector's HTTPS origin. The Pipe appends `/tracer/v1/traces`. HTTP is accepted only on loopback, such as `http://localhost:4318` when the collector shares the Open WebUI host's network namespace. |

    {/* MEDIA: Open WebUI Functions showing the imported Traced model Pipe and its valves, with credential fields hidden. */}
  </Step>
  <Step title="Enable the Function and select Traced model">
    Enable **Traced model**. In a new chat, select **Traced model** instead of the target model. Calls sent directly to the target do not pass through the Pipe. Configure tools and knowledge on the wrapper model, not a target-model preset. If your provider reports streamed token counts, enable **Usage** in the wrapper model's capabilities.

    {/* MEDIA: New Open WebUI chat with Traced model selected in the model picker. */}
  </Step>
</Steps>

## Verify a model call

In the new chat, send: “Ridgeline Outfitters accepts unused tents within 30 days. Can I return an unused tent after 12 days? Answer in one sentence.” Wait for the reply, then open **Observe**, choose `ridgeline-support`, and inspect the `openwebui.model` span for that request. Allow a few seconds for export.

| Look for | How to read it |
| --- | --- |
| `gen_ai.request.model` | The target model ID, not the wrapper name **Traced model**. |
| Duration | Time from dispatch until the Pipe finishes consuming the response. For streaming, that includes waiting for chunks, not just time to the first token. |
| Token usage | Input and output counts reported by the provider for this call. Repeated usage snapshots replace earlier ones. A missing count is unknown, not zero. |
| `openwebui.outcome` | `completed`, `error`, `cancelled`, or `incomplete`. The last three have error status. The span uses a fixed message rather than exporting raw provider error text. |

{/* MEDIA: Observe detail for a Ridgeline openwebui.model span showing the target model, duration, token counts, and completed outcome without message content. */}

If you later add a return-policy tool and the model is called again with its result, each call through **Traced model** gets its own span. The tool's execution, retrieval, and time spent waiting for approval are not model calls. The Pipe does not create spans for them or a parent span for the turn.

## Privacy and troubleshooting

The Pipe excludes message content and user identifiers by default. To inspect the question and reply for a saved chat, set `capture_content=true` in the valves. `max_chars` limits each captured input and output separately (default `32000`, allowed `1` to `131072`). Temporary and local chats still exclude content. These settings apply to the Pipe, not to Open WebUI's separate native telemetry exporter.

| Symptom | What to check |
| --- | --- |
| Target rejected before any span appears | Choose a native model ID on a Chat Completions connection. Responses API connections (even when streaming), native Ollama connections, workspace presets, Arena models, and other Pipes cannot be targets. |
| The chat works but no span appears | Confirm **Traced model** is enabled and selected, both Future AGI keys are set, and you opened the project named in `project`. Export failures do not stop the chat. Use a collector reachable directly from Open WebUI; the exporter does not follow redirects. |
| A completed reply has no token counts | Check that **Usage** is enabled on the wrapper for streaming and that the provider actually sends usage. The Pipe does not estimate tokens. |
| A streamed reply has an `incomplete` outcome | The consumer may have closed the stream early, or the provider may not have sent a completion marker. Without an explicit positive `n` in the request, the Pipe requires `[DONE]`. If `openwebui.observation_lost=true`, a streaming event was too large to inspect; this is not proof the model failed. |

When you upgrade `traceAI-openwebui`, regenerate the Function JSON, replace the saved loader with the new import, and restart Open WebUI to load the updated package.
