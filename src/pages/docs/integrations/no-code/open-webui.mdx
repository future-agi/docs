## About

The Open WebUI Pipe adds **Traced model** to your model picker. When you select it, Open WebUI sends the request to the model you configured and records one `openwebui.model` LLM span in Future AGI. If a support chat calls the model once to choose a tool and again to answer, you see two model calls, not one span timed across the whole turn.

## Set up the Pipe

Before you start, check that you have:

- Admin access to self-hosted Open WebUI 0.11.4 through 0.12.x on Python 3.11 or 3.12. Functions must be enabled. On 0.12.5, setting either `ENABLE_PLUGINS` or `ENABLE_FUNCTIONS` to `false` disables them.
- An OpenAI-compatible Chat Completions connection configured on the Open WebUI server, not a browser-only Direct Connection. Sign in as someone who will use the Pipe and check that you can chat with the target model. The Pipe delegates as the signed-in person; it does not grant access to the target.
- A [Future AGI key pair](/docs/quickstart/setup-observability) for the workspace where you want to see the spans.

<Steps>
  <Step title="Generate the Function import file">
    Run these commands in the same Python environment that runs Open WebUI. For a container, install the package in your image, run the export there, and copy the JSON file to the computer where you open the admin panel.

    ```bash
    python -m pip install traceAI-openwebui==0.1.0
    traceai-openwebui export-function --output traceai-openwebui.json
    ```

    The JSON contains a small loader for the installed package. Use a new filename if the file already exists; the export command does not overwrite it.

    The Pipe checks the installed `open-webui` Python distribution on each call. If you build from the official `v0.12.5-slim` image, the server source is present but its distribution metadata is not. Add the matching host wheel to that image without replacing its dependencies:

    ```bash
    python -m pip install --no-deps open-webui==0.12.5
    ```
  </Step>
  <Step title="Import the Function and set its valves">
    Set `ENABLE_VALVE_ENCRYPTION=true` in Open WebUI before storing credentials. In **Admin Panel → Functions**, open the menu beside **Create**, choose **Import JSON**, select the file you generated, and confirm the import. Open **Valves** for **Traced model** and set:

    | Valve | What to enter |
    | --- | --- |
    | `target_model` | The exact ID of the native model on your OpenAI-compatible Chat Completions connection. A workspace preset is not a valid target, even by ID. |
    | `api_key`, `secret_key` | Both keys from your Future AGI workspace. These are not your model provider credentials. |
    | `project` | Your Observe project name. Use `ridgeline-support` for the example below. The default is `open-webui`. |
    | `endpoint` | Leave `https://api.futureagi.com` for Future AGI Cloud. For self-hosting, use your collector's HTTPS origin. The Pipe appends `/tracer/v1/traces`. HTTP is accepted only on loopback. For `http://localhost:4318`, the receiver must share Open WebUI's network namespace and accept `/tracer/v1/traces`. If it serves only the standard `/v1/traces` path, configure the receiver or a reverse proxy to map the Pipe's path to it. |

    <img src="/images/docs/integrations/open-webui/open-traced-model-valves.gif" alt="The gear beside Traced model opens Valves. The example uses target openai/gpt-4o-mini, local collector http://localhost:4318, and project ridgeline-support. No credential values are shown." style={{ borderRadius: '5px' }} />
  </Step>
  <Step title="Enable the Function and select Traced model">
    If you used the old Future AGI Filter, disable and remove it in **Functions** before you enable the Pipe. The package cannot update copies saved in Open WebUI. The Filter's `openwebui.llm` child under `openwebui.chat` measured a whole turn, not an individual request. If your gateway also traces model calls, count usage from only one source.

    Enable **Traced model**. If you share it with others, give them read access to the wrapper in Open WebUI's model settings as well as access to the target. In a new chat, select **Traced model** instead of the target model. Direct calls to the target bypass the Pipe.

    Configure tools and knowledge on the wrapper, not on a target-model preset. For streamed token counts, enable **Usage** in the wrapper's capabilities if your provider supports it.

    ![In a new chat with the tent-return question drafted, the model picker shows a check beside Traced model rather than openai/gpt-4o-mini.](/images/docs/integrations/open-webui/new-chat-traced-model-picker.png)
  </Step>
</Steps>

## Verify a model call

In the new chat, send: “Ridgeline Outfitters accepts unused tents within 30 days. Can I return an unused tent after 12 days? Answer in one sentence.” After the reply, allow a few seconds for export. Open **Observe**, choose `ridgeline-support`, and inspect the `openwebui.model` span for the request. In the span details, check **Duration** and look under **Attributes** for the target model and outcome. For a successful request, `openwebui.outcome` is `completed`; the question and answer are absent by default.

| Look for | How to read it |
| --- | --- |
| `gen_ai.request.model` | The target model ID, not the wrapper name **Traced model**. |
| Duration | Time from dispatch until the Pipe finishes consuming the response. For streaming, that includes waiting for chunks, not just time to the first token. |
| Prompt and completion tokens | Input and output counts reported by the provider for this call. Repeated usage snapshots replace earlier ones. A missing count is unknown, not zero. |
| `openwebui.outcome` | `completed`, `error`, `cancelled`, or `incomplete`. The last three have error status. The span uses a fixed message rather than exporting raw provider error text. |

![The openwebui.model span completed in 943 ms with openai/gpt-4o-mini. Observe shows 4,408 prompt tokens, 25 completion tokens, and no message text.](/images/docs/integrations/open-webui/observe-openwebui-model-span.png)

If you later add a return-policy tool and the model is called again with its result, each call through **Traced model** gets its own span. The tool's execution, retrieval, and time spent waiting for approval are not model calls. The Pipe does not create spans for them or a parent span for the turn.

## Privacy and troubleshooting

The Pipe excludes message content and user identifiers by default. Leave `capture_content` off unless you intend to export content for **all users of this Pipe**, not just your test chat. With `capture_content=true`, the Pipe copies the role and content of each message sent to the model, plus response text. That can include earlier turns, system instructions, tool results, and personal data. `max_chars` truncates the input and output separately (default `32000`, allowed `1` to `131072`); it does not redact sensitive text.

Chat IDs starting with `temporary:` or `local:` suppress content even when capture is on. A missing chat ID does not: API requests without one can still export content. These settings apply to the Pipe, not to Open WebUI's separate native telemetry exporter.

| Symptom | What to check |
| --- | --- |
| Target rejected before any span appears | Choose a native model ID on a Chat Completions connection. Responses API connections (even when streaming), native Ollama connections, workspace presets, Arena models, and other Pipes cannot be targets. |
| The chat works but no span appears | Confirm **Traced model** is enabled and selected, both Future AGI keys are set, and you opened the project named in `project`. Export failures do not stop the chat. Use a collector reachable directly from Open WebUI; the exporter does not follow redirects. |
| The last few spans are missing after a worker restart | Each worker batches spans in memory. An abrupt stop can discard queued spans; they are not replayed after restart. |
| A completed reply has no token counts | Check that **Usage** is enabled on the wrapper for streaming and that the provider actually sends usage. The Pipe does not estimate tokens. |
| A streamed reply has an `incomplete` outcome | The consumer may have closed the stream early, or the provider may not have sent a completion marker. Without an explicit positive `n` in the request, the Pipe requires `[DONE]`. If `openwebui.observation_lost=true`, a streaming event was too large to inspect; this is not proof the model failed. |

## Upgrade the Pipe

After installing the new package version in the Open WebUI environment, update the saved Function in place. **Import JSON** creates a Function; it does not update the existing `traceai_openwebui` ID. Export the loader to a fresh filename and print its code:

```bash
traceai-openwebui export-function --output traceai-openwebui-new.json
python -c 'import json; print(json.load(open("traceai-openwebui-new.json"))[0]["content"])'
```

In **Admin Panel → Functions**, edit the existing **Traced model**, replace its code with that output, and save. This keeps the Function's ID and valves. Restart Open WebUI so every worker loads the updated package, then repeat the model-call check above.
