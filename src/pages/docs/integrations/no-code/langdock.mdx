---

Langdock gives you two kinds of [traces](/docs/observe/concepts/traces), and only one of them can go straight to Future AGI:

- **Your code calling Langdock's API.** Langdock's Completion API follows the OpenAI API, so the OpenAI client works against it. Instrument that client with `traceAI-openai` and every call appears in a Future AGI **Observe** project. This page sets that up.
- **Agents running inside Langdock.** Langdock documents [Langfuse](https://docs.langdock.com/en/using-langdock/agents/configuration) as its agent tracing backend, configured with Langfuse keys and a Langfuse URL. That export is not one the Future AGI collector accepts. Do not enter Future AGI keys or a Future AGI URL in Langdock's tracing settings.

## Before you start

- A Langdock API key with access to the Completion API. See Langdock's [API introduction](https://docs.langdock.com/en/developer/overview/api-introduction).
- A [Future AGI API key and secret key](/docs/admin-settings/api-keys).
- Python with the OpenAI SDK.

## Install

```bash
pip install traceAI-openai openai
```

## Set environment variables

```bash
export LANGDOCK_API_KEY="your-langdock-api-key"
export LANGDOCK_MODEL="a-model-id-from-your-workspace"
export FI_API_KEY="your-futureagi-api-key"
export FI_SECRET_KEY="your-futureagi-secret-key"
```

List the model IDs your workspace can use with `GET https://api.langdock.com/openai/eu/v1/models`. For self-hosted Future AGI, also set `FI_BASE_URL` to your collector origin.

## Trace a Langdock chat completion

Register the trace provider and instrument the OpenAI SDK before you create the client. Then point the client at Langdock:

```python
import os
from fi_instrumentation import register
from fi_instrumentation.fi_types import ProjectType
from traceai_openai import OpenAIInstrumentor
from openai import OpenAI

trace_provider = register(
    project_type=ProjectType.OBSERVE,
    project_name="langdock_project",
)
OpenAIInstrumentor().instrument(tracer_provider=trace_provider)

client = OpenAI(
    base_url="https://api.langdock.com/openai/eu/v1",
    api_key=os.environ["LANGDOCK_API_KEY"],
)

try:
    response = client.chat.completions.create(
        model=os.environ["LANGDOCK_MODEL"],
        messages=[{"role": "user", "content": "What is the capital of South Africa?"}],
    )
    print(response.choices[0].message.content)
finally:
    trace_provider.force_flush()
    trace_provider.shutdown()
```

The base URL uses Langdock's `eu` region, as in Langdock's [OpenAI-compatible endpoint guide](https://docs.langdock.com/en/developer/completion-api/openai). On a dedicated Langdock deployment, replace `https://api.langdock.com` with `<your-deployment-url>/api/public`.

The example flushes and shuts down the provider before the script exits. In a long-running application, shut it down only when the application stops.

## Verify

Run the script. Open **Observe** in Future AGI, select `langdock_project`, and open the model span. It shows the request messages, the response, the model and the token usage Langdock returned.

## What gets traced

`traceAI-openai` records each chat completion call made through the instrumented client: the input messages, the response, the model, request parameters and token counts. The span's provider is `openai`: traceAI labels OpenAI-compatible hosts it does not know by that name. See [Trace OpenAI calls](/docs/integrations/traceai/openai) for the JavaScript setup.

The span describes your application's call to Langdock. It does not show what Langdock does inside its platform, and calls made from Langdock's own chat UI or from Langdock agents are not traced.

Langdock's Completion API does not accept `n`, `service_tier`, `parallel_tool_calls` or `stream_options`. Leave them out of your requests.

The Agents API (`/agent/v1/chat/completions`) uses Vercel AI SDK message objects, not the OpenAI format, so the OpenAI instrumentation does not apply to it.

## Privacy

Tracing captures request and response content by default. Review [trace masking settings](/docs/sdk/tracing/mask-span-attributes) before you send sensitive data. Langdock still receives everything you send to its API.

## Langdock agent traces

If you need traces of Langdock agents themselves, they go to Langfuse. Langdock lets you set the **Tracing cloud URL** to a self-hosted Langfuse instance. Future AGI can then pull those traces from Langfuse with the [Langfuse importer](/docs/integrations/import/langfuse); check its source compatibility section first, because the importer needs Langfuse's trace-read APIs.
