<Warning>
**Status: not supported.** Langdock has no documented way to send agent traces to Future AGI. This page records what Langdock's and Langfuse's documentation say, and what would change that.
</Warning>

## What Langdock offers today

Langdock is a closed, hosted AI platform for building no-code agents. Its only documented tracing path is Langfuse (checked 2026-10-29):

- A **workspace admin** enables agent logging in the workspace settings (**Allow agent logs**).
- An **agent editor** then enables Langfuse tracing on each agent, sets the **Tracing cloud URL** (default `https://cloud.langfuse.com`), and adds Langfuse API keys.
- Langdock says a self-hosted Langfuse instance can be used by pointing the Tracing cloud URL at it.

Sources: [Langdock agent configuration](https://docs.langdock.com/en/using-langdock/agents/configuration) and [Langfuse: Langdock integration](https://langfuse.com/integrations/no-code/langdock).

## Why Future AGI cannot receive these traces

- **No generic export.** Langdock documents no OTLP or other vendor-neutral export setting. The setting is specific to Langfuse and takes Langfuse public and secret keys.
- **Wire protocol not documented.** Langdock's docs do not say whether it calls the Langfuse ingestion REST API or the Langfuse OpenTelemetry endpoint (`/api/public/otel`).
- **Only Langfuse hosts are documented.** Langdock's docs say the Tracing cloud URL defaults to Langfuse Cloud and that organizations running a self-hosted Langfuse instance can point it at their internal deployment. They document no other kind of host.
- **Future AGI does not serve a Langfuse-compatible endpoint.** The Future AGI collector accepts OTLP/HTTP traces at `/v1/traces` and `/tracer/v1/traces` with `X-Api-Key` and `X-Secret-Key` headers. It has no Langfuse ingestion or `/api/public/otel` route, and it needs a `project_name` resource attribute that Langdock has no way to set.

Because of this, pointing the Tracing cloud URL at Future AGI will not work. Do not try it with your production keys.

## Supported scope

There is no supported Langdock-to-Future-AGI setup in this guide. Neither changing the Langfuse host nor importing Langdock-origin traces is prescribed as a working integration. This notice supplies no installation commands or workaround recipe.

## What would unlock direct support

1. Langdock documenting a generic OTLP export, or accepting an arbitrary tracing endpoint with a documented protocol.
2. A Langfuse-ingestion-compatible endpoint in Future AGI. This is separate platform work and has not been scheduled.
3. Access to a Langdock workspace to verify the protocol and build a tested recipe.

## Evidence boundary

These findings come from the linked Langdock and Langfuse documentation and the Future AGI collector's documented routes.

## Troubleshooting

- **You do not see "Allow agent logs" in Langdock.** Your workspace admin must enable agent logging first. This is a Langdock setting and is unrelated to Future AGI.
- **You pointed the Tracing cloud URL at Future AGI and see no traces.** Expected. Reset it to your Langfuse host.
