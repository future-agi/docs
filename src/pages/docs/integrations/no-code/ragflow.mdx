---
title: "RAGFlow"
description: "Configure Future AGI trace export in a self-hosted, Future AGI-enabled RAGFlow deployment."
---

Send RAGFlow chat turns, retrieved documents and model calls to Future AGI Observe from RAGFlow's settings. You do not need to add instrumentation code to your chats.

## Prerequisites

- A Linux x86-64 self-hosted deployment of the [Future AGI RAGFlow fork](https://github.com/future-agi/ragflow/tree/60492deba70ea7431e13c23de271ab10c3aa0aea), using the Go backend, MySQL, Infinity, MinIO, Kvrocks and NATS.
- A chat model and an embedding model configured in RAGFlow, with your own provider credentials.
- Your Future AGI API key and secret key, available in **Settings → API keys**, and an Observe project name.

Stock RAGFlow **v1.0.0** images do not include this exporter. Installing a traceAI package in a stock image does not add the **Future AGI** settings card.

### Build the Future AGI-enabled image

If your deployment does not already use the fork, build this pinned image with Docker Buildx:

```bash
git init ragflow-futureagi
git -C ragflow-futureagi remote add origin https://github.com/future-agi/ragflow.git
git -C ragflow-futureagi fetch --depth 200 origin 60492deba70ea7431e13c23de271ab10c3aa0aea tag v1.0.0-rc1
git -C ragflow-futureagi checkout --detach 60492deba70ea7431e13c23de271ab10c3aa0aea
docker buildx build --load --network host --target production --tag ragflow-futureagi:60492deb --file ragflow-futureagi/Dockerfile ragflow-futureagi
```

Use `ragflow-futureagi:60492deb` as the application image in your self-hosted RAGFlow deployment. Keep its database, document engine, storage, cache and queue services configured using the fork's [deployment configuration](https://github.com/future-agi/ragflow/tree/60492deba70ea7431e13c23de271ab10c3aa0aea/docker). This image runs the Go services and applies database migrations before starting them.

Use a separate deployment and database for this pinned build; do not replace a newer RAGFlow installation or downgrade its database. Keep the release tag and Git history when building so the image's version can be compared with the database version. Do not disable the database version guard to make a mismatched deployment start.

## Configure trace export

1. In RAGFlow, open **User settings → API**.
2. On the **Future AGI** card, select **Configuration**.
3. Fill in the following fields:

   | Field | Value |
   | --- | --- |
   | **API key** | Your Future AGI API key |
   | **Secret key** | The matching Future AGI secret key |
   | **Observe project** | The project name to use for these traces |
   | **Endpoint** | `https://api.futureagi.com` for Future AGI Cloud, or your self-hosted collector origin |
   | **Redact content** | Enable to omit question, answer, prompt and retrieved text |

4. Select **Save**. RAGFlow checks the collector connection and credentials before saving.

Enter the collector origin in **Endpoint**, not a Langfuse URL. RAGFlow sends OTLP/HTTP to `/tracer/v1/traces` and manages the authentication headers itself. The Future AGI and Langfuse configurations are independent.

Configuration is per tenant. Saved keys are masked when you reopen the dialog; enter both keys again when changing any setting.

### Choose what to capture

Content capture is **on by default**: questions, answers, model prompts and retrieved text can be sent to Future AGI. Enable **Redact content** before sending sensitive data. Redaction keeps identifiers, retrieval scores, model names, token counts, status and timing while removing the text content.

RAGFlow stores these credentials in **plaintext database columns**. Restrict database access and protect its backups; masked fields in the settings dialog do not encrypt stored credentials.

## Send a chat and inspect its trace

Open a RAGFlow chat connected to a dataset with an ingested document, and ask a question answered by that document. Then open **Observe** in Future AGI and select the project name you saved.

Expand the chat trace:

- **`ragflow.chat`** — the chat turn and its result.
- **`ragflow.retrieval`** — retrieved text, document identifiers and similarity scores when the turn performs retrieval.
- **`ragflow.llm`** — the model call, messages, answer and token counts.

Token counts are RAGFlow's tokenizer estimates, not provider billing totals. This setup traces the Go chat pipeline; it does not add tracing to agent canvases.

## Troubleshooting

### The Future AGI card is missing

Check the deployed application image. Stock RAGFlow does not contain the card or exporter; use the Future AGI-enabled build above. An SDK installation alone cannot enable it.

### Saving the configuration fails

Check the API key/secret key pair and the collector origin. The RAGFlow server must be able to reach the collector over the network. Re-enter both keys rather than copying the masked values from a previous save.

### Chats work but traces are missing

Check the Observe project name and the collector connection, then send a new chat. Export is asynchronous: an unreachable collector or a full queue can drop traces without interrupting chat. A hard shutdown can also lose queued traces; this exporter is not a durable audit log.
