## Availability

The Future AGI exporter is a **fork-only prototype**, tracked in [future-agi/ragflow PR #1](https://github.com/future-agi/ragflow/pull/1). It is not part of stock RAGFlow images or an upstream release. This is a status page, not a supported installation guide; it does not prescribe a Docker image build, database migration or production onboarding.

As checked on **2026-10-29**, GitHub's latest RAGFlow release is [v1.0.0-rc2](https://github.com/infiniflow/ragflow/releases/tag/v1.0.0-rc2), published 2026-10-16. The exporter branch `feat/th-8233-futureagi-export` is at `be76831f046c892bd3c85faef91dc334e1aabf2a`; the fork PR remains open. No traceAI package installation adds this exporter to a stock RAGFlow deployment.

## Verified development scope

The recorded 2026-10-17 runs exercised RAGFlow's Go services **in process**, using SQLite, an OpenAI-compatible model, Tavily web search and a self-hosted Future AGI collector. They cover the chat-session completion service and the OpenAI-compatible completion endpoint, success and model-key errors, redacted content, rejected Future AGI keys and collector connection failures. They are not full-stack deployment receipts.

| Component | Evidence scope |
| --- | --- |

| Exporter changes applied to `v1.0.0-rc2` | Separate in-process service run |
| Exporter and settings service/handler | Unit tests, `go vet` and formatting checks |

Trace ids and run details are retained in the [fork PR](https://github.com/future-agi/ragflow/pull/1). No mocked UI result is presented as a real browser-to-database onboarding pass.

## What the prototype exports

For the exercised chat paths, a turn produces `ragflow.chat` (chain), an optional `ragflow.retrieval` child for web search, and `ragflow.llm` for the answer call. The model span carries the model and RAGFlow's token counts. These counts use RAGFlow's tokenizer (`ragflow.usage.source=ragflow_cl100k_count`), not provider billing totals.

The exporter sends uncompressed OTLP/HTTP JSON to `/tracer/v1/traces`, with `project_name`, `project_type=observe` and `service.name=ragflow`. Configuration is per tenant in `tenant_futureagi`; it is separate from RAGFlow's Langfuse integration and its `OTEL_HOST` settings. The tested route is self-hosted Future AGI, not the hosted service.

## Privacy and failure behavior

**Content is on by default in the prototype.** Questions, answers, prompts and retrieved text can leave RAGFlow. The per-tenant `redact=true` setting removes those values and substitutes fixed error text while retaining ids, model, token counts, status and timing. The recorded redacted runs scanned stored trace columns for prompt markers and email addresses; no matches were found. That receipt applies to the in-process paths above, not every RAGFlow feature.

Future AGI keys are stored in plaintext database columns; the settings GET response masks them. Protect the database and backups accordingly. Each tenant has a bounded 1,024-trace queue and a 5-second request timeout; a full queue or unavailable collector drops traces rather than blocking chat. Shutdown allows up to 2 seconds to flush, so a hard kill or slow collector can lose traces.

## Required before an installation guide

A supported onboarding guide needs an exact fork-image build and Docker Compose run using the real database and document engine, migration verification, and a browser session that saves settings and sends a traced chat through the running server. Those deployment receipts are outstanding, so the draft remains held.

The current scope excludes MySQL deployment, Elasticsearch/Infinity knowledge-base retrieval, embedded chatbots, agentic reasoning, agent canvases and hosted Future AGI. SQLite service tests and mocked settings responses do not establish those paths. Stock-image support additionally requires an upstream distribution that contains the exporter.
