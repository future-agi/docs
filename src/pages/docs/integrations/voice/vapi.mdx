title: "Vapi"
description: "Connect a Vapi assistant to Observe and inspect its calls, transcripts, recordings, and costs without adding an SDK."
---

Connect your Vapi assistant to Future AGI to inspect calls in **Observe**. Future AGI fetches call logs from Vapi and turns each call into a trace with a conversation span. No SDK installation, webhook handler, or OpenTelemetry exporter is required in your application.

## Before you begin

- A Future AGI account with permission to connect agents, build environments, and update agents in your workspace.
- A Vapi assistant and its **Assistant ID**, available in the [Vapi dashboard](https://dashboard.vapi.ai).
- A [Vapi private API key](https://docs.vapi.ai/security-and-privacy/api-keys) that can access that assistant and its calls.

<Warning>
Use the Vapi private API key, not a browser public key and not your Future AGI `FI_API_KEY` or `FI_SECRET_KEY`. Enter it only in the provider credential field in Future AGI; do not put it in frontend code or a shared screenshot.
</Warning>

## Connect the assistant

If the assistant is already listed under **Agents** > **Connected agents**, open it and go straight to the observability step below.

<Steps>
  <Step title="Start a hosted connection">
    Open **Agents** > **Create Agents** > **Connect agents**. This opens the environment builder. Choose **Hosted platform**, then **Voice** as the agent type and **Vapi** as the platform.
  </Step>
  <Step title="Enter the assistant credentials">
    Enter the assistant's ID in **Assistant ID** and your private key in **Vapi API key**. Both values must belong to the same Vapi organization.

    Complete the contact settings for your assistant. Choose web or phone calling as appropriate; phone calling requires a contact number. Set the scenario count for the environment.
  </Step>
  <Step title="Check the connection and build">
    Select **Run preflight** and resolve any failed checks. Once the checks pass, select **Build environment** and wait for the environment to finish building.

    Return to **Agents** > **Connected agents** and open the assistant you connected.
  </Step>
  <Step title="Turn on observability">
    Open the connected agent's **Definition** tab and turn on **Observability**. The change is saved automatically; there is no separate Save button. Wait for saving to finish and resolve any error shown below the switch.

    Future AGI creates an Observe project for the agent. Its name is based on the agent's name; if that name is already in use, the project name includes an identifier to distinguish it.
  </Step>
</Steps>

## Inspect a call

Make a short call to the connected assistant, such as asking about your support hours. End the call and confirm that the completed call appears in Vapi's call logs.

Open **Observe**, select the agent's project, and open the call. Call logs are fetched asynchronously, so refresh the project after ingestion rather than expecting a live audio stream.

The call's conversation span contains the transcript and the call details supplied by Vapi, such as duration and cost. Recordings are available when recording is enabled for the assistant and Vapi supplies the recording. Transcript messages are not separate STT, LLM, or TTS child spans; managed ingestion does not instrument Vapi's internal pipeline.

Use [evaluations on traces](/docs/observe/features/evals) to score the conversation, or [alerts](/docs/observe/features/alerts) to monitor it.

## Rotate your Vapi key

The connected agent's Definition tab displays its configuration but does not have a credential editor. Update the key through the environment that uses the agent:

1. Open the connected agent's **Environments** tab and select the environment created during setup.
2. On the environment's **Overview** tab, select **Manage versions** in the agent section.
3. Under **Credentials**, select **Change values**. Enter the new private key as the value of `VAPI_API_KEY`, leaving other values unchanged, then select **Save values**.
4. Wait for the new agent version's check to pass and confirm it becomes the environment's default. If the check fails, correct the key and try again. Make a short call and confirm it reaches Observe before revoking the old key in Vapi.

If **Manage versions** is unavailable, ask your workspace administrator for help updating the connection rather than creating a duplicate connection to rotate the key.

## Troubleshooting

- **The observability switch is disabled:** you need permission to update the agent. The switch is also temporarily disabled while a change is saving.
- **Turning on observability shows an error:** follow the error below the switch. Confirm the connection has a private API key and the correct Assistant ID; the switch returns to its previous state if the change is refused.
- **No calls appear:** confirm that observability is enabled, the saved Assistant ID matches the assistant used for the call, and the private key can read its call logs in Vapi. Check the selected workspace, project, and time range in Observe.
- **A recording is missing:** check whether recording was enabled for that call in Vapi. Vapi's recordings use authenticated access; do not replace the provider credential with a public key or paste a temporary recording URL into your configuration. See [Vapi's recording access guide](https://docs.vapi.ai/assistants/retrieve-call-artifacts).

To stop fetching new calls, open the connected agent's **Definition** tab and turn off **Observability**. The change is saved automatically.
