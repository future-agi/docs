## About

This guide covers **Python client tracing only**: `traceai-openai` instruments your application's OpenAI client while requests pass through [TrueFoundry AI Gateway](https://www.truefoundry.com/docs/ai-gateway/quick-start). The client creates the spans; TrueFoundry's native OTEL exporter is a separate feature, outside this recipe.

## Client tracing

Your code calls the gateway with the OpenAI client. `traceai-openai` wraps that client, so the call is traced in your process. Future AGI keys authenticate trace export; the TrueFoundry token authenticates gateway requests. They are not intentionally recorded as span attributes, but captured payloads or provider error text can contain credentials. Review the [capture controls](#privacy) before using this recipe with sensitive data.

<Steps>

<Step title="Install">

```bash
pip install "traceai-openai==0.1.10" "openai==3.31.0" "fi-instrumentation-otel==1.1.0"
```

`traceai-openai` supports Python 3.10 to 3.13.
</Step>

<Step title="Get the gateway values">

Open the TrueFoundry Playground, pick a model, and click **Code** to see all three.

| Value | TrueFoundry SaaS | Self-hosted |
| --- | --- | --- |
| Base URL | `https://gateway.truefoundry.ai` | Shown in the Playground Code Snippets |
| API key | A Personal Access Token (development) or a Virtual Account Token (applications) | Same |
| Model id | `provider_account/model_name`, for example `openai-main/gpt-4o-mini` | Same |

The base URL has no `/v1` suffix: the OpenAI client appends `/chat/completions`. Use the base URL shown in your Playground code snippet.
</Step>

<Step title="Trace the client">

```python
import os

from fi_instrumentation import register
from fi_instrumentation.fi_types import ProjectType
from openai import OpenAI
from traceai_openai import OpenAIInstrumentor

trace_provider = register(
    project_type=ProjectType.OBSERVE,
    project_name="my-chatbot",
)
OpenAIInstrumentor().instrument(tracer_provider=trace_provider)

client = OpenAI(
    base_url="https://gateway.truefoundry.ai",
    api_key=os.environ["TFY_API_KEY"],
)

response = client.chat.completions.create(
    model="openai-main/gpt-4o-mini",
    messages=[{"role": "user", "content": "What is the capital of France?"}],
)
print(response.choices[0].message.content)
trace_provider.force_flush()
trace_provider.shutdown()
```

Set `FI_API_KEY` and `FI_SECRET_KEY` in the environment. For a self-hosted Future AGI also set `FI_BASE_URL`: the SDK sends traces to `$FI_BASE_URL/tracer/v1/traces`.
</Step>

</Steps>

Open **Observe**, select `my-chatbot`, and open the trace. A complete example with an agent and a tool call is in [client_example.py](https://github.com/future-agi/docs/blob/main/examples/gateways/truefoundry/client_example.py).

### What the span shows

| Field | Value |
| --- | --- |
| Type and name | `llm`, `ChatCompletion` |
| Model | The model the response reports, for example `gpt-4o-mini-2024-07-18` for the id `<provider-account>/gpt-4o-mini` (a TrueFoundry model id is the provider account name you chose, a slash, then the model). The id you sent is kept in the request parameters. A failed call has no model field, and neither does a streamed call in `traceai-openai` 0.1.10 (it has token counts). |
| Tokens | Input, output and total, from the response `usage`. |
| Provider | `openai`. `traceai-openai` 0.1.10 recognises `api.openai.com`, `openai.azure.com` and `googleapis.com` by host and labels every other host `openai`, so this is not a TrueFoundry label. |
| Prompt, response, tool calls | Captured by default. See [Privacy](#privacy). |
| Error | A rejected call ends the span with status `ERROR` and the client's error text. Error text can include sensitive information, such as the signed-in user's email address. |
| Hierarchy | If you wrap the call in your own agent and tool spans, the LLM spans sit under them: agent, LLM, tool, LLM. The gateway does not receive your trace context in this setup, so its own spans are separate traces. |

TrueFoundry's `tfy.*` fields (cost, routing, caller identity, guardrails) are gateway-side and are not on client spans. This page does not supply a gateway-native export setup.

## Privacy

`traceai-openai` captures prompts, responses and tool arguments and results by default. Turn capture off with the [TraceConfig](/docs/sdk/tracing/trace-config) switches, in code or in the environment:

```bash
export FI_HIDE_INPUTS=true FI_HIDE_OUTPUTS=true
export FI_HIDE_INPUT_MESSAGES=true FI_HIDE_OUTPUT_MESSAGES=true
export FI_HIDE_LLM_INVOCATION_PARAMETERS=true
```

Model, token counts and tool names are still sent when these switches are enabled.

<Warning>
In `traceai-openai` 0.1.10, these switches do not hide failed-call error text. The exported exception event can also include a stack trace with local paths and user names. Do not use this pinned recipe for workloads whose errors may contain sensitive data; these content switches are not a complete error-redaction control.
</Warning>

## Scope and limitations

- Python client spans only. There is no TypeScript, native gateway-export, metrics, or gateway-admin setup here.
- `traceai-openai` 0.1.10 labels this host's provider as `openai` and sets no model on a failed or streamed call. Tokens are retained when reported.
- Gateway routing, cost, caller identity and guardrail attributes are not client-span attributes.
- A response model can be the provider's dated model name rather than the gateway model id you sent.
- If you separately enable gateway tracing, it creates separate traces. This recipe does not join or deduplicate them.

## Troubleshooting

| What you see | What to check |
| --- | --- |
| No client spans | Run `register()` and instrumentation before the call, set `FI_API_KEY` and `FI_SECRET_KEY`, and flush before process exit. For self-hosted Future AGI, set `FI_BASE_URL`. |
| Gateway rejects the model | Copy an authorized provider-account/model id from your TrueFoundry Playground. A token alone does not grant access to every model. |
| Model differs from the request id | The span shows the model in the provider response; request parameters retain your requested id. |
| Sensitive error text | The 0.1.10 content switches do not remove exception text. Do not use this pinned recipe for workloads whose errors contain sensitive data. |
