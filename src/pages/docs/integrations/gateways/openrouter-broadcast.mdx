## About

Send requests passing through [OpenRouter Broadcast](https://openrouter.ai/docs/guides/features/broadcast) to Future AGI Observe without adding instrumentation to your application.

Broadcast runs in OpenRouter, including for clients you cannot instrument. For application-side agent and tool spans, use the [OpenAI instrumentor](/docs/integrations/traceai/openai) with the OpenRouter base URL instead. Enabling both records the client call and the gateway call separately.

## Before you start

- Get a Future AGI API key and secret key from [API keys](/docs/admin-settings/api-keys) in the workspace that should receive the traces.
- Choose an Observe project name, such as `my-openrouter`.
- Have access to [OpenRouter's Observability settings](https://openrouter.ai/settings/observability). An organization admin configures organization-wide destinations.
- Have an OpenRouter API key with credits available. Set it as `OPENROUTER_API_KEY` in your terminal for the example below; do not commit it.

<Warning>
The direct destination stores your Future AGI credentials in OpenRouter. Use it only if your organization's credential-sharing policy allows this. OpenRouter encrypts destination credentials at rest. If you require credentials or custom redaction to stay in your infrastructure, keep an independently managed collector rather than replacing it with this direct destination.
</Warning>

## Set up Broadcast

<Steps>

<Step title="Configure the destination">

Open [Settings > Observability](https://openrouter.ai/settings/observability) in OpenRouter and enable **Broadcast**. Edit the **OpenTelemetry Collector** destination. Despite its name, this destination can send directly to Future AGI; you do not need to run a collector.

| Field | Value |
| --- | --- |
| Endpoint | `https://api.futureagi.com/tracer/v1/traces` |
| Headers | The JSON object below, with your Future AGI keys and project name |

```json
{
  "X-Api-Key": "YOUR_API_KEY",
  "X-Secret-Key": "YOUR_SECRET_KEY",
  "X-Project-Name": "my-openrouter"
}
```

Use the full endpoint, including `/tracer/v1/traces`. OpenRouter sends OTLP/HTTP with JSON encoding; do not select a gRPC endpoint or add an OpenRouter bearer token to these headers.

`X-Project-Name` routes spans that have no `project_name` resource attribute. The key pair selects the workspace; the header selects the project within it. An explicit `project_name` resource attribute takes precedence. Send one nonempty name of at most 255 characters, without commas, control characters or invisible characters. Do not send repeated project-name headers.

For self-hosted Future AGI, use your collector's public HTTPS OTLP/HTTP endpoint ending in `/v1/traces`. The deployment must support the `X-Project-Name` header; older collectors require an upgrade.

</Step>

<Step title="Choose which requests and content to send">

Set the destination's **API key filter** to the application's OpenRouter key and use a sampling rate of **1.0** while checking the setup. Leaving the included-key list empty sends traffic from all keys; excluded keys take precedence. In a shared account, coordinate these settings with its owner before changing them.

Enable **Privacy Mode** if you do not want prompts, responses or provider error text sent to Future AGI. Leave it off only when you intend to capture content. Privacy Mode still sends custom metadata and model parameters, including caller-supplied `stop` sequences. Use opaque user and session identifiers and keep secrets out of metadata. See [Privacy](#privacy).

</Step>

<Step title="Test and save">

Click **Test Connection**. OpenRouter saves the destination only if its test passes. Then send an application request and check the resulting trace: a connection test alone does not demonstrate that your key filter, sampling and project selection are correct.

</Step>

<Step title="Send a request">

Run this with your OpenRouter key in `OPENROUTER_API_KEY`. The request uses a short response limit and synthetic identifiers.

```bash
curl --fail-with-body https://openrouter.ai/api/v1/chat/completions \
  -H "Authorization: Bearer $OPENROUTER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-4o-mini",
    "max_tokens": 16,
    "messages": [{"role": "user", "content": "What is the capital of France?"}],
    "user": "demo-user",
    "session_id": "capital-demo",
    "trace": {"trace_name": "Capital lookup", "environment": "demo"}
  }'
```

Open **Observe** in the workspace that owns the Future AGI keys, select `my-openrouter`, and open the new trace. Broadcast sends traces asynchronously after the request completes.

</Step>

</Steps>

## Inspect the trace

OpenRouter's [span attributes reference](https://openrouter.ai/docs/guides/features/broadcast/otel-collector#span-attributes) describes the exported fields.

| Data | Where to look |
| --- | --- |
| Model and usage | The generation span's `gen_ai.request.model` and `gen_ai.usage.*` attributes |
| Prompt and response | `span.input` / `span.output` and `gen_ai.prompt` / `gen_ai.completion` on the generation span, when Privacy Mode is off |
| Session and user | `session.id` and `user.id` span attributes; a user attribute alone does not guarantee an entry in the Users tab |
| Custom metadata | Attributes under `trace.metadata.*`, such as `trace.metadata.environment` |
| Hierarchy | Generation spans and optional grouping spans; use `trace_name`, `span_name` and `generation_name` to name them |

Broadcast records what OpenRouter handles, not tools executed by your application. Use `parent_span_id` only when the referenced parent span is also exported to the same project. Input/output pane rendering, user indexing and cost summaries depend on your Future AGI collector's attribute mappings; inspect the generation attributes rather than treating an empty pane or zero cost as proof that OpenRouter sent no data.

## Privacy

[OpenRouter's Privacy Mode](https://openrouter.ai/docs/guides/features/broadcast#privacy-mode) excludes prompt and completion content and provider error text. Raw provider usage is replaced with `null` because the provider can add arbitrary fields to that object. Model, token usage, timing, cost, user/session identifiers, custom metadata and model parameters remain eligible for export.

There is no additional redaction layer in this direct route. Privacy Mode is not a general-purpose scrubber: custom metadata and model parameters, including `stop` sequences, can contain sensitive text. OpenRouter may also attach API key names and account identifiers. Review what your application puts into these fields before enabling Broadcast for production traffic.

<Warning>
If you already use a collector with content filtering, changing the endpoint bypasses those filters. The collector's `FI_CAPTURE_CONTENT` setting has no effect on this direct route. Set Privacy Mode deliberately and review the retained fields before switching.
</Warning>

## Troubleshooting

| Symptom | Action |
| --- | --- |
| Test Connection fails | Check the full endpoint and both Future AGI key headers. An OpenRouter API key is not a Future AGI credential. |
| HTTP 400 `no project_name` | Add `X-Project-Name` to Headers. On a self-hosted deployment, confirm that the collector supports it. |
| HTTP 400 with a project-name error | Send one nonempty project name within the rules above, not a list of names. |
| HTTP 401 | Check that both Future AGI keys belong to the intended workspace and have not been revoked. |
| Connection test passes, but no application trace appears | Check the destination's API key filter, exclusions and sampling. Select the matching workspace and project in Observe and widen the time range. |
| Prompt or response is missing | Check Privacy Mode, then inspect the generation span's attributes rather than only its Input and Output panes. |
| HTTP 413 | The export exceeds the receiver's request-size limit. Enable Privacy Mode to reduce content, or exclude keys producing oversized transcripts. See [ingestion request limits](/docs/observe/reference/export-formats#ingestion-request-limits). |
