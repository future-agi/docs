## About

[OpenRouter Broadcast](https://openrouter.ai/docs/guides/features/broadcast) copies a trace of each request that passes through OpenRouter to the observability tools you pick, so you can see those calls without adding code to your app. An organization admin turns it on under **Settings**, **Observability**. This page sends those traces to Observe through an OpenTelemetry Collector that you run.

Broadcast is not client tracing. The [OpenAI instrumentor](/docs/integrations/traceai/openai) with the base URL `https://openrouter.ai/api/v1` traces calls your own code makes. Broadcast traces what OpenRouter received, from any client, including tools you cannot instrument.

| | Client tracing | Broadcast |
| --- | --- | --- |
| Where it runs | Your application, with `traceai-openai` | OpenRouter, switched on by an organization admin |
| What you see | The call as your code made it, under your own agent and tool spans | One trace per OpenRouter request: a root span and a generation span |
| Prompts and responses | Captured by default, switched off with the `FI_HIDE_*` variables | Off by default on this page, switched on with `FI_CAPTURE_CONTENT` |
| What you run | Nothing beyond your app | A collector that OpenRouter's cloud can reach |

## Why a collector sits in the middle

OpenRouter's OpenTelemetry Collector destination has two fields, Endpoint and Headers. Pointing it straight at Future AGI runs into three things, each seen in the test:

1. Future AGI needs a `project_name` on every batch and the destination cannot set one. A batch without it is rejected with HTTP 400 `no project_name`.
2. Test Connection can pass anyway. OpenRouter's Webhook page says Test Connection posts an empty OTLP payload with an `X-Test-Connection: true` header and accepts a 2xx or a 400. The OpenTelemetry Collector page only says to click Test Connection, so this page assumes the same probe. Future AGI answers HTTP 200 to an empty payload when the keys are right, so Test Connection goes green and every real trace is then rejected without OpenRouter showing you.
3. OpenRouter's cloud has to reach the endpoint, so the endpoint needs a secret. OpenRouter's own examples send `Authorization: Bearer`. Future AGI answers 401 to a Bearer header, and putting your Future AGI keys in OpenRouter's settings hands them to a third party.

The collector below fixes all three: it accepts OpenRouter's Bearer token, sets the Observe project, and adds the Future AGI keys on your side. It also keeps prompts and error text out unless you opt in.

## Set up

<Steps>

<Step title="Write the collector config">

Save this as `otelcol.yaml`. Everything it reads from the environment is listed in the next step.

```yaml
extensions:
  # The endpoint has to be reachable from OpenRouter's cloud, so it must not be open: anyone who finds it
  # could write into your project. The Headers field of the destination carries the token.
  bearertokenauth/broadcast:
    scheme: Bearer
    token: ${env:BROADCAST_TOKEN}

receivers:
  otlp:
    protocols:
      http:
        endpoint: 0.0.0.0:4318
        auth:
          authenticator: bearertokenauth/broadcast
        # Put TLS in front of this (a load balancer or reverse proxy), or set `tls:` here with
        # cert_file and key_file.

processors:
  resource/future_agi:
    attributes:
      - key: project_name
        value: ${env:FI_PROJECT_NAME}
        action: upsert
      - key: project_type
        value: observe
        action: insert

  transform/openrouter:
    error_mode: ignore
    trace_statements:
      - context: span
        statements:
          # Future AGI reads gen_ai.usage.input_tokens and output_tokens. OpenRouter's Webhook page shows
          # prompt_tokens and completion_tokens instead; copy them across when only those arrive.
          - set(attributes["gen_ai.usage.input_tokens"], attributes["gen_ai.usage.prompt_tokens"]) where attributes["gen_ai.usage.input_tokens"] == nil and attributes["gen_ai.usage.prompt_tokens"] != nil
          - set(attributes["gen_ai.usage.output_tokens"], attributes["gen_ai.usage.completion_tokens"]) where attributes["gen_ai.usage.output_tokens"] == nil and attributes["gen_ai.usage.completion_tokens"] != nil
          # OpenRouter's cost for the request (US dollars). Observe reads gen_ai.cost.total; OpenRouter writes
          # gen_ai.usage.total_cost. Seen in a real Broadcast payload with the Cost metadata switched on.
          - set(attributes["gen_ai.cost.total"], attributes["gen_ai.usage.total_cost"]) where attributes["gen_ai.usage.total_cost"] != nil
          - set(attributes["gen_ai.cost.input"], attributes["gen_ai.usage.input_cost"]) where attributes["gen_ai.usage.input_cost"] != nil
          - set(attributes["gen_ai.cost.output"], attributes["gen_ai.usage.output_cost"]) where attributes["gen_ai.usage.output_cost"] != nil
          # Span types in Observe: the generation is an LLM span, everything else a chain.
          - set(attributes["fi.span.kind"], "LLM") where attributes["gen_ai.request.model"] != nil
          - set(attributes["fi.span.kind"], "CHAIN") where attributes["gen_ai.request.model"] == nil
          # Content ON: fill the Input and Output panes from OpenRouter's span.input / span.output.
          - set(attributes["input.value"], attributes["span.input"]) where attributes["span.input"] != nil and "${env:FI_CAPTURE_CONTENT:-false}" == "true"
          - set(attributes["output.value"], attributes["span.output"]) where attributes["span.output"] != nil and "${env:FI_CAPTURE_CONTENT:-false}" == "true"
          - delete_key(attributes, "span.input") where "${env:FI_CAPTURE_CONTENT:-false}" == "true"
          - delete_key(attributes, "span.output") where "${env:FI_CAPTURE_CONTENT:-false}" == "true"
          # Content OFF (the default): prompts and completions in every spelling OpenRouter or the
          # OpenTelemetry GenAI conventions use, including `<key>.truncated` markers and indexed keys.
          - delete_matching_keys(attributes, "^(span|trace)\\.(input|output|status_message)(\\..*)?$") where "${env:FI_CAPTURE_CONTENT:-false}" != "true"
          - delete_matching_keys(attributes, "^gen_ai\\.(prompt|completion|input\\.messages|output\\.messages)(\\..*)?$") where "${env:FI_CAPTURE_CONTENT:-false}" != "true"
          # Raw provider usage can hold any field the provider adds. OpenRouter nulls it in Privacy Mode.
          - delete_matching_keys(attributes, "^(span|trace)\\.metadata\\.openrouter_generation\\.upstream_raw_response_usage$") where "${env:FI_CAPTURE_CONTENT:-false}" != "true"
          # Error text can echo the request. Keep the fact of the error, not the words.
          - set(status.message, "error") where status.message != "" and "${env:FI_CAPTURE_CONTENT:-false}" != "true"
      - context: spanevent
        statements:
          - delete_key(attributes, "exception.message") where "${env:FI_CAPTURE_CONTENT:-false}" != "true"
          - delete_key(attributes, "exception.stacktrace") where "${env:FI_CAPTURE_CONTENT:-false}" != "true"

  # OpenRouter shortens any attribute over 10,000,000 characters. Future AGI reads at most 16 MiB per
  # request, so batching keeps requests small. A single generation can still exceed it.
  batch:
    send_batch_size: 256
    send_batch_max_size: 512
    timeout: 2s

exporters:
  otlp_http/future_agi:
    traces_endpoint: ${env:FI_TRACES_URL}
    encoding: proto
    compression: none          # the Future AGI HTTP receiver rejects gzip bodies
    headers:
      X-Api-Key: ${env:FI_API_KEY}
      X-Secret-Key: ${env:FI_SECRET_KEY}

service:
  extensions: [bearertokenauth/broadcast]
  telemetry:
    metrics:
      level: none              # no self-metrics endpoint; Broadcast sends traces only
    logs:
      level: warn
  pipelines:
    traces:
      receivers: [otlp]
      processors: [resource/future_agi, transform/openrouter, batch]
      exporters: [otlp_http/future_agi]
```

`FI_CAPTURE_CONTENT` is read as the exact string `true`. Any other value, or none, keeps content out.
</Step>

<Step title="Run the collector">

```bash
export BROADCAST_TOKEN=$(openssl rand -hex 24)   # the secret OpenRouter will send
export FI_API_KEY=YOUR_API_KEY FI_SECRET_KEY=YOUR_SECRET_KEY

docker run -d --name openrouter-broadcast-otelcol --memory 512m \
  -p 4318:4318 \
  -v "$PWD/otelcol.yaml:/etc/otelcol/config.yaml:ro" \
  -e BROADCAST_TOKEN -e FI_API_KEY -e FI_SECRET_KEY \
  -e FI_PROJECT_NAME=my-openrouter \
  -e FI_TRACES_URL=https://api.futureagi.com/tracer/v1/traces \
  otel/opentelemetry-collector-contrib:0.162.0 --config /etc/otelcol/config.yaml
```

| Variable | Value |
| --- | --- |
| `BROADCAST_TOKEN` | A secret you invent. It protects the collector, not Future AGI. |
| `FI_API_KEY`, `FI_SECRET_KEY` | Your Future AGI keys. They stay on this machine. |
| `FI_PROJECT_NAME` | The Observe project every Broadcast trace goes to. On the self-hosted stack tested, a new name created the project. Create it first if you want to set it up yourself. |
| `FI_TRACES_URL` | The full traces URL. Hosted Future AGI: `https://api.futureagi.com/tracer/v1/traces`, the URL the SDK uses, not tried with this collector. Self-hosted: `http://<your Future AGI host>:4318/v1/traces`. |
| `FI_CAPTURE_CONTENT` | Leave unset. See [Privacy](#privacy). |
</Step>

<Step title="Make it reachable over HTTPS">

OpenRouter's page says the collector must be on a publicly accessible endpoint. The collector listens on plain HTTP on port 4318. Put TLS in front of it with a load balancer or a reverse proxy, or add `tls:` with `cert_file` and `key_file` under the receiver's `http:` block. TLS was not part of the test, and nothing here was exposed publicly. Every request must carry the bearer token; without it the collector answers 401.
</Step>

<Step title="Add the destination in OpenRouter">

An organization admin opens [Settings, Observability](https://openrouter.ai/settings/observability), switches **Enable Broadcast** on, and edits **OpenTelemetry Collector**.

| Field | Value |
| --- | --- |
| Endpoint | `https://broadcast.example.com/v1/traces`, your collector's public URL with the `/v1/traces` path |
| Headers | `{"Authorization": "Bearer YOUR_BROADCAST_TOKEN"}`, with the value of `BROADCAST_TOKEN`. Do not put your Future AGI keys here. |
| Privacy Mode | Tick it unless you want prompts and responses in Observe. See [Privacy](#privacy). |

Click **Test Connection**. OpenRouter saves the destination only if the test passes. Test Connection checks OpenRouter to collector only. It passes even if your Future AGI keys are wrong, because an empty payload never reaches Future AGI. Send a real request and check Observe.
</Step>

<Step title="Send a request through OpenRouter">

Any client works. `user`, `session_id` and `trace` are optional and are what link traces to users and sessions in Observe:

```json
{
  "model": "openai/gpt-4o-mini",
  "messages": [{ "role": "user", "content": "What is the capital of France?" }],
  "user": "user_12345",
  "session_id": "session_abc",
  "trace": { "environment": "staging" }
}
```

Open **Observe**, select your project, and open the trace.
</Step>

</Steps>

## What shows up in Observe

From the live run on 2026-10-19 (three requests, one provider), replayed into a self-hosted Future AGI.

| Signal | What Observe shows |
| --- | --- |
| Hierarchy | There is no separate root span. The generation span, named `LLM Generation` whatever `trace_name` says, is the root, and `trace_name` arrives as the attribute `trace.name`. Under it sits one `provider attempt N: <provider>` span per attempt, and a streamed request also has a `generation` span. With `trace_id` and `parent_span_id` set, OpenRouter's documentation says the root carries your parent span id; that was not tried live. Observe's trace list shows a trace by its root span, so a trace whose root points at a parent that is not in the project is not listed. |
| Span types | The generation span is `llm`. The attempt and `generation` spans are `chain`. The collector sets this, because OpenRouter does not. |
| Model and provider | The model slug OpenRouter sends, for example `openai/gpt-4o-mini`, and the provider that served it from `gen_ai.provider.name`, for example `azure`. `gen_ai.system` holds the model's vendor (`openai`), not the host. A failed request that never reached a provider shows provider `unknown`. |
| Tokens | Input, output and total from `gen_ai.usage.*`. OpenRouter's Webhook page spells them `prompt_tokens` and `completion_tokens`, the other pages `input_tokens` and `output_tokens`. The collector accepts both. A request with no usage shows no tokens, not zero. |
| Cost | OpenRouter writes the cost in US dollars to `gen_ai.usage.total_cost`, with `input_cost` and `output_cost` beside it, when **Cost** is switched on under **Additional generation metadata**. The collector copies the total to `gen_ai.cost.total`, which Observe reads. Without that copy the live run showed 0. |
| User and session | `user.id` becomes the end user and `session.id` the session. Two requests with the same `session_id` land in one session. |
| Custom metadata | `trace.metadata.*` is stored as span attributes. It is not mapped to the metadata field. |
| Prompt and response | Absent by default. With the opt-in they fill the Input and Output panes of the generation span, as the JSON string OpenRouter sends. The string is `{"messages": [...]}` for the prompt, and `{"completion": ..., "toolCalls": [...], "rawRequest": {...}}` for the response. `rawRequest` echoes the request parameters, `user` and `trace` included. |
| Tool calls | Inside the response, visible only with the opt-in. OpenRouter reports whether the model called a tool. The tool runs in your app, so there is no tool span. |
| Errors | A request that fails after OpenRouter accepts it (the live run used a 402 for too few credits) arrives as a generation span with OTLP status code 2 and the error text as the status message, an `exception` event with `exception.message`, and the attributes `span.status_message`, `span.level` `ERROR` and `error.type`. Observe shows it as `ERROR` with the message replaced by `error` unless you opt in. A request OpenRouter rejects before routing, such as an unknown model id (400), sends no trace at all. |
| Cost options | With **Cost** and **Request context** switched on under **Additional generation metadata**, the `openrouter_generation.*` fields arrive as attributes on the generation span, once under `span.metadata.` and once under `trace.metadata.`. They repeat the same quantities, so do not add them. |
| Timing | Span start and end, and `openrouter.inter_token_latency_ms` as an attribute. |

## Privacy

Two switches decide whether prompts and responses reach Observe.

| Switch | Where | Default |
| --- | --- | --- |
| Privacy Mode | The destination in OpenRouter | Off, in OpenRouter |
| `FI_CAPTURE_CONTENT` | The collector's environment | `false` |

With the collector default, these never leave your network, whatever OpenRouter sends:

| Removed | Why |
| --- | --- |
| `span.input`, `span.output`, `gen_ai.prompt`, `gen_ai.completion`, and the `trace.input` and `trace.output` older copies, with their `<key>.truncated` markers and indexed spellings | Prompts and responses |
| `gen_ai.input.messages`, `gen_ai.output.messages` | The OpenTelemetry GenAI names for the same thing. OpenRouter does not document them. |
| `openrouter_generation.upstream_raw_response_usage` on the root and generation span | The provider's usage object can hold any field. OpenRouter nulls it in Privacy Mode. |
| The span status message, replaced by `error` | Error text can echo the request |
| `exception.message` and `exception.stacktrace` on span events | Stack traces carry paths and text |

Kept: model, provider, token counts, timing, finish reason, `user.id`, `session.id`, `trace.metadata.*` and the Cost options. These are values you choose, so do not put an e-mail address or free text in `user` or in `trace`.

To send content on purpose, set `FI_CAPTURE_CONTENT=true`, restart the collector, and leave Privacy Mode off in OpenRouter. The collector then copies `span.input` and `span.output` into the Input and Output panes and leaves the rest alone.

In the test with content off, two real model calls (a tool call and its answer), a failed request with an e-mail address in its text and a synthetic exception event with a stack trace, and a Privacy Mode request each carried a unique marker. None of the markers, the e-mail address, the user name, the host name, the home or working directory, `Traceback` or the stack trace path appeared in what the collector exported or in any stored row of the project (all 42 tables with a project column, 8 in ClickHouse and 34 in Postgres, of which 4 held rows, and the collector's own export capture was scanned as well, including resource attributes and span events). The custom metadata marker did appear, as described above. With content on, the same markers were stored and the Input pane filled.

## Pointing Broadcast straight at Future AGI

Not recommended, and it cannot work for a real trace today. What the stand-in sender saw from a self-hosted Future AGI:

| Request | Result |
| --- | --- |
| Test Connection with `X-Api-Key` and `X-Secret-Key` | HTTP 200 |
| Test Connection with wrong keys | HTTP 401, `authentication failed` |
| Test Connection with `Authorization: Bearer ...`, or with no headers | HTTP 401, `missing credentials` |
| A generation with no `project_name` | HTTP 400, `no project_name`, nothing stored |
| The same generation with `project_name` set by the sender | HTTP 200, stored. OpenRouter cannot do this. |
| The same body gzipped | HTTP 400 |
| About 18 MB (two 9,000,000-character copies of the prompt) | HTTP 413, `payload too large`. Future AGI reads up to 16 MiB per request. |
| A key from a second workspace, with a project name that exists in the first | HTTP 200, and a separate project of that name is created in the second workspace. The first workspace's project is untouched. |
| The same trace id and span ids sent twice | One trace and two spans |

## Live vendor verification (2026-10-19)

Run on 2026-10-19 and 2026-10-20 with a real OpenRouter account. The collector on this page ran on Google Cloud Run (public HTTPS, bearer token) and forwarded to the hosted Future AGI at `https://api.futureagi.com/tracer/v1/traces`. For this test only, a second pipeline printed the payload exactly as OpenRouter sent it to the Cloud Run log, with a debug exporter. The same payloads were then replayed through the recipe into a self-hosted Future AGI, once with `FI_CAPTURE_CONTENT` unset and once with it `true`.

| Step | Result |
| --- | --- |
| Destination | OpenTelemetry Collector, region Global, sampling 100%, header `Authorization: Bearer <token>`, Cost and Request context metadata on, Privacy Mode off. Saving worked; the Test Connection result could not be read in the dashboard. |
| Test Connection | OpenRouter posts OTLP/JSON with one span named `openrouter-connection-test` (a fixed all-zero trace id, status OK). The collector accepted it with 200. A wrong or missing token gets 401. The `X-Test-Connection` header the Webhook page describes was not among the headers recorded. |
| Success and streaming | Two requests through `openai/gpt-4o-mini` with `user`, `session_id` and `trace`. Both arrived as OTLP/JSON, about 13 to 14 KB, from user agent `OpenRouter/0.0`, and were stored in hosted Future AGI with model, provider `azure`, tokens, session and end user. |
| Failure | A request with too few credits (402) arrived as an `ERROR` trace and was stored as `ERROR`. A bad model id and a context-length error (both 400) produced no trace. |
| Replay, content off | `fi_verify` passed. The prompt, the completion, `rawRequest` and the error text, which names a key page URL, were not found in any stored ClickHouse or Postgres row of the project. |
| Replay, content on | `fi_verify` passed. The prompt and the error text were stored, and the Input and Output panes were filled. |

What the real run changed on this page:

1. **Cost** now reaches Observe. OpenRouter's cost key is `gen_ai.usage.total_cost`; the recipe copies it to `gen_ai.cost.total`. The first run, without the copy, stored cost 0.
2. **Error text leaked through a second attribute.** The status message also arrives as the attribute `span.status_message`, which the first recipe did not remove. With the first recipe, a credit error that names a key page URL was stored in hosted Future AGI. The recipe now removes `span.status_message` unless `FI_CAPTURE_CONTENT` is `true`. If you ran the first recipe, check your project for it.
3. The hierarchy, span names, provider and error rows above were rewritten from what arrived.

Kept on purpose, and worth knowing: OpenRouter sends the name of the API key (`trace.metadata.openrouter.api_key_name`) and its owner ids (`entity_id`, `creator_user_id`) on every generation. They are not removed.

Still untried: provider fallback, tool calls, Privacy Mode on in OpenRouter, `trace_id` and `parent_span_id` linking, and cancelled requests.

## Limitations

- Only one provider (Azure behind `openai/gpt-4o-mini`) and one kind of failure (a 402) were seen live. Fallback between providers, tool calls, cancelled generations, `trace_id`, `parent_span_id` and Privacy Mode were not run live.
- OpenRouter shortens an attribute at 10,000,000 characters and sends the prompt twice. Future AGI reads 16 MiB per request, so a very long conversation can be dropped. In the test, an 18 MB generation with content on was dropped and the collector log said so. With content off the batch is small.
- The same span ids sent twice are deduplicated. If OpenRouter re-exports a trace with new span ids, you would see it twice.
- One collector sends to one project. Run one collector per project, each with its own endpoint and token.
- The collector was reached over HTTPS through Cloud Run's front end, and the hosted Future AGI URL received the traces. Your own TLS setup is yours to check.
- Sampling and API key filters are OpenRouter's. A trace missing because of them is correct.

## Troubleshooting

| What you see | What it means |
| --- | --- |
| Test Connection fails | The token in Headers does not match `BROADCAST_TOKEN`, or the collector is not reachable from the internet. The collector answers 401 to a missing or wrong token. |
| Test Connection passes and nothing appears in Observe | Check the collector log for `Exporting failed. Dropping data`. A 401 there means the Future AGI keys or `FI_TRACES_URL` are wrong. Test Connection never reaches Future AGI. |
| HTTP 400 `no project_name` | You pointed OpenRouter straight at Future AGI. Use the collector. |
| Tokens are 0 | The request had no usage, or OpenRouter used key names this page does not know. Compare one trace's attributes with the tables above. |
| Cost is 0 | See [What shows up in Observe](#what-shows-up-in-observe). |
| No prompts or responses | That is the default. See [Privacy](#privacy), and check Privacy Mode in OpenRouter. |
| Some requests are missing | Sampling or API key filters on the OpenRouter destination. |
| A long conversation is missing | The export was over 16 MiB. The collector log shows HTTP 413. |
