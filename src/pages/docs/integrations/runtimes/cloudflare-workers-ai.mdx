---
title: "Cloudflare Workers AI"
description: "Trace Workers AI REST calls from Node.js with the maintained traceAI preload. Inspect model requests, responses, latency and token usage in Future AGI."
---

Trace your Node.js application's Workers AI chat completions in Future AGI with one startup preload and no tracing code in your application.

## Before you start

- **Node.js 20.6 or later**, running on the server.
- A Cloudflare account ID and API token with **Account → Workers AI → Read** permission for that account. See [Workers AI REST setup](https://developers.cloudflare.com/workers-ai/get-started/rest-api/).
- A Future AGI **API key and secret key** from [API keys](https://app.futureagi.com/dashboard/keys).

This guide uses Cloudflare's [OpenAI-compatible REST endpoint](https://developers.cloudflare.com/workers-ai/configuration/open-ai-compatibility/) from Node.js. You do not need to deploy a Worker or configure AI Gateway. The Node preload does not run inside a deployed Worker or instrument `env.AI.run` bindings.

## Connect your application

<Steps>
<Step title="Install the package">

Run in your Node.js application's directory:

```bash
npm install @traceai/auto@0.1.2
```

The maintained package observes supported model calls through Node's global `fetch`. You do not need a custom exporter, Wrangler or an instrumentation helper.

</Step>
<Step title="Set credentials and project">

Provide these variables through your deployment's secret manager or shell environment. Replace the placeholders and keep credentials out of version control:

```bash
export CLOUDFLARE_ACCOUNT_ID="your-account-id"
export CLOUDFLARE_API_TOKEN="your-workers-ai-token"
export FI_API_KEY="your-futureagi-api-key"
export FI_SECRET_KEY="your-futureagi-secret-key"
export FI_PROJECT_NAME="workers-ai"
```

<Warning>
Prompts and responses are **captured by default**. For sensitive workloads, set `FI_HIDE_INPUTS=true`, `FI_HIDE_OUTPUTS=true` and `FI_HIDE_ERROR_DETAILS=true` before starting the application. These controls apply to traceAI's export, not your application's own logs.
</Warning>

</Step>
<Step title="Make a chat completion">

Save this ordinary application code as **app.mjs**. It uses Cloudflare's Llama 3.2 1B model and limits the response to 16 tokens:

```javascript
const { CLOUDFLARE_ACCOUNT_ID, CLOUDFLARE_API_TOKEN } = process.env;
if (!CLOUDFLARE_ACCOUNT_ID || !CLOUDFLARE_API_TOKEN) {
  throw new Error("Set CLOUDFLARE_ACCOUNT_ID and CLOUDFLARE_API_TOKEN.");
}

const response = await fetch(
  `https://api.cloudflare.com/client/v4/accounts/${CLOUDFLARE_ACCOUNT_ID}/ai/v1/chat/completions`,
  {
    method: "POST",
    headers: {
      Authorization: `Bearer ${CLOUDFLARE_API_TOKEN}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({
      model: "@cf/meta/llama-3.2-1b-instruct",
      messages: [{ role: "user", content: "Say hello in one word." }],
      max_tokens: 16,
      stream: false,
    }),
    signal: AbortSignal.timeout(30_000),
  },
);
const result = await response.json();
if (!response.ok) {
  console.error(`Workers AI request failed (HTTP ${response.status}).`);
  process.exitCode = 1;
} else {
  console.log(result.choices[0].message.content);
}
```

Start with the preload:

```bash
node --import @traceai/auto/register app.mjs
```

Read the response body as in the example so the observer can finish the span. Let the process exit naturally; completed spans are flushed on exit. Do not replace this with an immediate `process.exit()`. For long-running servers or invocation-based runtimes, see the [lifecycle guidance](/docs/integrations/traceai/auto#frameworks-and-deployment).

</Step>
<Step title="Open the trace">

Open [Future AGI](https://app.futureagi.com), select **Observe → workers-ai**, then open the model-call span. Inspect the model, provider, request and response, duration, and token usage supplied by Cloudflare.

The example creates a client-side model-call span. It does not add a Worker request span or reproduce Cloudflare's internal execution tree. Missing usage is not estimated.

</Step>
</Steps>

## Troubleshooting

| Symptom | Action |
| --- | --- |
| Workers AI returns 401 or 403 | Check that the token has Workers AI Read permission on the configured account. An AI Gateway management token alone is not sufficient. |
| Model output appears but no trace does | Set both Future AGI keys in the same process environment, use the preload, and consume the response body. Check that `OTEL_SDK_DISABLED` is not enabled. |
| A REST call is not captured | Use the `/ai/v1/chat/completions` endpoint and Node's global `fetch`, as above. The `/ai/run/<model>` endpoint and direct `undici.fetch` are not this recipe's capture path. |
| Inputs or outputs are hidden | Check your `FI_HIDE_INPUTS` and `FI_HIDE_OUTPUTS` settings. Keep hiding enabled if the content is sensitive. |
| Traces disappear when the process stops | Allow a natural exit or flush at your invocation boundary. Hard termination and collector failures can lose spans; delivery is best effort. |

For diagnostics, other runtimes and configuration options, see [zero-code Node.js tracing](/docs/integrations/traceai/auto). [Cloudflare Workers native OpenTelemetry export](https://developers.cloudflare.com/workers/observability/opentelemetry-export/) and [AI Gateway OpenTelemetry export](https://developers.cloudflare.com/ai-gateway/observability/otel-integration/) are separate mechanisms configured in Cloudflare, not required by this client-side recipe.
