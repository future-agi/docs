title: "Workers AI REST tracing in local workerd"
description: "Run a local workerd handler against the real Workers AI REST API and export request spans to Future AGI. This guide does not deploy a Worker or use an AI binding."
---

## Scope

This recipe runs **local `workerd` with a REST-backed adapter**, not a deployed Worker and not Cloudflare's native `ai` binding. `src/live-entry.ts` calls the [Workers AI REST API](https://developers.cloudflare.com/workers-ai/get-started/rest-api/), then passes the result to the shared handler and tracer. A successful HTTP request creates a `worker.fetch` root and a `workers_ai.run` child.

The 2026-10-19 qualification used real Workers AI responses, usage, and a rejected model, with local `workerd` and a self-hosted Future AGI collector. That evidence applies to this REST path only. Native AI bindings, deployed request lifecycles, streaming, tools, scheduled/queue handlers, Durable Objects, `ctx.waitUntil` flushing, and hosted collector delivery are outside this guide. There are no deployment steps here.

## 1. Install the example

Use the [example folder](https://github.com/future-agi/docs/tree/main/examples/runtimes/cloudflare-workers-ai), which contains `src/live-entry.ts`, `src/index.ts`, `src/tracing.ts`, `wrangler.live.jsonc`, and the lockfile:

```bash
git clone --depth 1 https://github.com/future-agi/docs.git fi-docs
cd fi-docs/examples/runtimes/cloudflare-workers-ai
npm ci
npm test
npm run typecheck
```

Published dependency pins: `@opentelemetry/api` 1.9.1, `@opentelemetry/sdk-trace-base` and `@opentelemetry/resources` 2.12.0, `@opentelemetry/otlp-transformer` 0.223.0, and `wrangler` 4.151.1. The recipe uses `compatibility_date: 2026-10-01` and was qualified with Node 26 tooling.

The default `wrangler.jsonc` is a development reference for a native-binding variant. **Use `wrangler.live.jsonc` for this guide**, not that default configuration.

## 2. Set local credentials

Create an ignored `.dev.vars` file in the example folder, using your own values:

```dotenv
CLOUDFLARE_ACCOUNT_ID=your-account-id
CLOUDFLARE_API_TOKEN=your-workers-ai-token
FI_API_KEY=your-futureagi-api-key
FI_SECRET_KEY=your-futureagi-secret-key
FI_BASE_URL=http://127.0.0.1:14338
FI_PROJECT_NAME=workers-ai-rest-local
FI_CAPTURE_CONTENT=false
```

Use a Cloudflare token authorized to call Workers AI and a reachable self-hosted Future AGI collector. `FI_BASE_URL` is your collector's origin; the exporter appends `/tracer/v1/traces`. Inside local `workerd`, use `127.0.0.1` rather than `localhost` if the latter fails to connect.

Keep the file out of version control. Both Future AGI keys are required; if either is missing, tracing is disabled while model calls can still run. The project comes from local configuration, never from a caller-controlled request header.

## 3. Run locally

```bash
npx wrangler dev --local --config wrangler.live.jsonc --port 8787
```

In a second terminal:

```bash
curl -sS http://127.0.0.1:8787/chat \
  -H 'Content-Type: application/json' \
  -d '{"prompt":"Reply with one short greeting."}'
```

This makes one real Workers AI call using `@cf/meta/llama-3.1-8b-instruct`, capped at 40 output tokens. It creates no Cloudflare deployment. The `/bad-model` route exercises a real rejected model and returns HTTP 502.

Open the configured Observe project. The trace contains the request and model-call spans. Model and provider are set by the wrapper; token counts are copied only when the REST result supplies usage. No token values are invented.

## Delivery and flush budget

The handler ends both spans and **awaits export before returning the response**, on success and error. The batch processor's timer is not the delivery mechanism.

The local recipe uses a **20-second maximum flush wait**. A collector slower than the old two-second bound caused trace loss in the historical run. Regression tests now cover a three-second collector response (export finishes before the handler returns) and a hung collector (bounded wait, application response preserved). This is a tested local timeout policy, not a production delivery guarantee or latency target.

A failed or timed-out export can still lose the trace. The handler prints only `Future AGI trace export failed or timed out`, without payloads or credentials; it keeps the application's HTTP response unchanged. There is no retry queue or durable delivery. A process killed before flush completes can lose spans.

## Privacy

With `FI_CAPTURE_CONTENT=false`, the exporter includes span names, method, URL path, model, provider, available token usage, status, and error class. It omits the query string, prompt, response and raw exception text. Avoid sensitive data in the path itself.

`FI_CAPTURE_CONTENT=true` opts into prompt/result JSON (truncated to 4,000 characters each) and raw error messages. Those values can themselves contain personal data or paths. The switch does not sanitize application content. It is a setting of this example, not a traceAI `FI_HIDE_*` variable.

## Separate Cloudflare features

[Cloudflare's native OpenTelemetry destinations](https://developers.cloudflare.com/workers/observability/exporting-opentelemetry-data/) are a separate export mechanism. This guide supplies no destination configuration or compatibility claim for them. Likewise, the existence of an `env.AI.run` interface in the shared handler is not evidence that a native binding or deployed Worker passed this recipe's checks.

`src/e2e-entry.ts` and `run_e2e.sh` use a named model stand-in for local regression checks. They are distinct from the real REST-backed entry point above.
