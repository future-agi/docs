`fi` is the Future AGI command-line tool. It works against Future AGI Cloud or a self-hosted install, signs in with your personal API key pair, and prints every result as a table, JSON or JSON Lines, so the same command serves a person at a terminal, a CI job and a coding agent.

Today the CLI covers [Environments](/docs/environments) end to end: you push a new version of your agent, run an environment's suite against it, wait for the grades and fail a build when the pass rate drops. Many platform reads and writes that have no hand-written command are reachable through `fi api`, a set of commands generated from the platform's API.

<Warning>
The CLI is in early development and its repository is private: there is no published release, Homebrew formula or npm package yet. You install it from source with Go and GitHub access to the `future-agi` organization, as [Install and auth](/docs/cli/install-and-auth) shows. Commands and flags can still change.
</Warning>

## Type `futureagi`, not `fi`

`fi` is a reserved word in bash and zsh (it closes an `if` block), so a line that starts with `fi` is a syntax error in both shells. An alias named `fi` would break every `if ... fi` block in your shell, so the install steps put the same binary on your `PATH` under a second name, `futureagi`. The CLI pages' code blocks, which you can copy, use `futureagi`. Tables and text use the CLI's own name, `fi` (as in `fi sim run`), which matches the help text. Type `futureagi` wherever you see `fi`.

## Command groups

| Group | What it does |
|---|---|
| `fi auth` | Save, check and remove your personal API key pair |
| `fi profiles` | Keep several sign-ins side by side, such as Cloud and a self-hosted install |
| `fi doctor` | Check your configuration, the connection and your credentials in one go |
| `fi agents` | List agents and their versions, push a local folder as an environment's next agent version, and check it |
| `fi sim env` | Build environments (answer the cloud builder's questions), review and save unsaved edits (drafts), and manage versions, agent credentials, rebuild offers (`nudges`) and evaluations |
| `fi sim suites` | List an environment's suite versions (its saved sets of scenarios), choose the one a run uses by default, and review, save or discard unsaved suite edits |
| `fi sim scenarios` | List, read, edit and generate an environment's scenarios |
| `fi sim personas` | Keep personas as local YAML files and push or pull them |
| `fi sim run` | Preview or start a run of an environment's suite, and wait for its pass rate |
| `fi sim runs` | Follow a run, read its results and trials, re-run its interrupted calls, cancel it, or ask for Insights (an analysis of its failures) |
| `fi evals test` | Try an evaluation template once on sample inputs, as [Runs](/docs/cli/runs#try-an-evaluation-with-fi-evals-test) shows |
| `fi api` | Direct calls to a chosen set of platform API endpoints, including ones no other command covers yet |
| `fi version`, `fi completion` | Print the version, and generate shell completion |

## How the commands behave

- **Output**: tables by default, `--json` for one JSON document, `-o jsonl` for one object per line. Errors go to stderr, as JSON in the JSON modes
- **Exit codes**: 0 to 8 (7 is reserved), the same codes across commands, so a script can branch on them. [Install and auth](/docs/cli/install-and-auth#exit-codes) lists them; `fi api` maps a few HTTP errors differently, as [API](/docs/cli/api#exit-codes-in-fi-api) shows
- **Nothing runs on your machine**: pushing an agent uploads a folder, and checks, builds and runs happen in the cloud
- **Writes are sent once**: a write is never retried on its own, and the writes that take an idempotency key print it, so you can resend them with the same key. For any other write, read the resource before you repeat it
- **Waiting never cancels**: `--wait` polls until the work ends, the builder asks a question, or `--wait-timeout` (default 60 minutes) runs out. Ctrl-C or closing the terminal only stops the waiting, never the work
