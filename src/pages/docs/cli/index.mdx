## What fagi is

`fagi` is the Future AGI command-line tool. Use it to set up tracing, run evals, sync datasets and prompts, call the gateway and drive simulation environments, against Future AGI Cloud or a self-hosted install. People, CI jobs and coding agents all run the same commands.

To get started, follow the [Quickstart](/docs/cli/quickstart): install, sign in, send a trace and read it back.

## Command name and aliases

The primary command is `fagi`, and every example in these pages uses it. The package also installs two aliases, `futureagi` and `fi`, which run the same commands. `fi` is a reserved word in bash, zsh and sh (it closes an `if` block), so a line that starts with `fi` is a syntax error. To use that alias, type `\fi` or `command fi`.

## Command families

<Note>
Families marked Next release ship in the next release of the CLI. Once they ship, upgrade with `npm install -g @future-agi/cli@latest` (see [Upgrade](/docs/cli/install-and-auth#upgrade)). `fagi skills` is in preview, so its commands and manifest format may change.
</Note>

| Family | Reach for it when you want to | Status | Page |
|---|---|---|---|
| `fagi init`, `fagi run`, `fagi trace` | Set up a project for tracing, install tracing agents, start a program with tracing, and read, watch, diff, check or export stored traces | Available | [Tracing](/docs/cli/tracing) |
| `fagi datasets` | Validate, push, pull and list datasets as local CSV or JSONL files | Available | [Datasets](/docs/cli/datasets) |
| `fagi eval` | Grade one example with `eval test`, or a JSONL cases file with `eval suite`, and gate CI on the match rate (`eval run` is not available yet) | Available | [Evals](/docs/cli/evals) |
| `fagi prompts`, `fagi gateway` | Pull and diff prompt versions, send one prompt through the gateway and check its guardrails, or follow gateway requests | Available | [Prompts and gateway](/docs/cli/prompts-and-gateway) |
| `fagi sim env` | Build and version an environment, and manage its actors, files, agent versions and their credentials, rebuild offers and evals | Next release | [Simulate quickstart](/docs/cli/simulate-quickstart), [Environments](/docs/cli/environments), [Actors and evaluations](/docs/cli/actors-and-evaluations) |
| `fagi sim scenarios`, `fagi sim suites`, `fagi sim personas` | Review, edit and generate scenarios and their starting records, save suite versions, and keep personas as local files | Next release | [Scenarios, suites and personas](/docs/cli/scenarios-suites-and-personas) |
| `fagi sim run`, `fagi sim verify`, `fagi sim runs` | Start a run and gate on its pass rate, verify an agent version on held-back cases, and follow, read and compare runs | Next release | [Runs](/docs/cli/runs) |
| `fagi epoch` | Start an Epoch on a finished run with its model lock and limits, and check its state | Next release | [Epoch](/docs/cli/epoch) |
| `fagi skills` | Choose which coding hosts a repository installs skills for, record skills in a manifest, and sync or verify them | Preview, next release | [Skills](/docs/cli/skills) |
| `fagi api` | Call one platform endpoint directly when no dedicated command covers it | Available | [Call any endpoint](/docs/cli/api) |
| `fagi schema` | List or search every command, flag and exit code as JSON, offline and without credentials (`fagi schema --search <words>`, `fagi schema --command <path>`) | Available | [Configuration and output](/docs/cli/configuration-and-output#find-commands) |
| `fagi auth`, `fagi profiles` | Save, check and remove your key pair, and keep several sign-ins side by side | Available | [Install and auth](/docs/cli/install-and-auth) |
| `fagi doctor`, `fagi update`, `fagi version`, `fagi completion` | Check configuration, credentials and tracing (`doctor`), update fagi to the latest release (`fagi update --check` only reports), print the version, and generate shell completion | Available | [Install and auth](/docs/cli/install-and-auth) |

## How the commands behave

- **Output**: a table by default, or JSON for scripts; see [Output formats](/docs/cli/configuration-and-output#output-formats)
- **Exit codes**: each code means the same thing in every command, such as 0 for success and 5 for a failed gate; see [Exit codes](/docs/cli/configuration-and-output#exit-codes)
