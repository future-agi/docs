## About

Use `fagi api` to read or change platform resources from a terminal. This reference covers all 93 generated API commands in CLI **0.2.2**. The examples show how to inventory the prompts for a Ridgeline Outfitters support agent and preview a new returns-policy prompt without changing the workspace.

## Find a command offline

With `fagi` installed (`npm install -g @future-agi/cli@0.2.2` on Node.js `^22.15.0` or `>=23.11.0`), search by task, then inspect the exact command before you run it. Neither step needs keys or contacts the platform.

```bash
fagi schema --search 'prompt list' --limit 3
fagi schema --command 'api prompts list'
fagi api prompts list --help
```

In 0.2.2, that search returns `fagi api prompts list` and `fagi api prompts versions list`. `schema` always prints JSON. Search matches words without regard to case across paths, tool names, descriptions, groups and notes. Every query word must match. Some related words match the same term, such as `traces` and `trace`. Results rank by matches in the command path, then in the description, then alphabetically by path. `--limit` defaults to 5 and accepts 1 to 50. An empty `matches` array is a successful search. `--command` matches the **end** of a command path, so include `api` to distinguish an API operation from a higher-level workflow. Use either `--search` or `--command`, not both.

For an API operation, inspect `access`, `method`, `http_path`, `flags`, `data_only_body_fields` and `rows`. The short search result only lists required *flags*: a command may also require keys inside a JSON body. For a workflow such as `trace check`, inspect its `side_effects` and `exit_codes`. To enable Tab completion for command names, flags and known enum values, run `fagi completion bash --help` for setup instructions, replacing `bash` with `zsh`, `fish` or `powershell` for your shell.

## Read one page of prompts

Sign in with `fagi auth login`, or set `FI_API_KEY` and `FI_SECRET_KEY` from the same platform key pair in your environment. For a self-hosted platform, set `FI_BASE_URL`. With an unpinned key, use `--workspace` to select an accessible workspace by UUID. A key bound to an active workspace takes precedence over this flag. For commands that also accept a `--workspace-id` query filter, the shared workspace header takes precedence for workspace selection; set only one selector. Check the authenticated context, then read the first two prompts:

```bash
fagi api context whoami --json --no-input
fagi api prompts list --page 1 --limit 2 --fields id,name --json --no-input
```

Look for `results` in the second response. With `--fields`, each row contains only `id` and `name`; the surrounding response still contains pagination metadata. For one JSON object per line instead, run:

```bash
fagi api prompts list --page 1 --limit 2 --fields id,name -o jsonl --no-input
```

- **Pagination:** Each call requests one page. If `next` is not null on the first prompt page, repeat the command with `--page 2`. Do not assume other commands use the same flags or start at 1. Some start at 0, take an offset, or return a cursor. In JSON and JSONL modes, the CLI emits a `pagination` record on **stderr** when it recognizes a continuation. Silence does not prove you reached the last page. `next_flags` can give the next position; `cursor_field` names the field to read from full JSON and `cursor_flag` names the flag to pass. If both are present, use the cursor and the next position. The CLI never follows a continuation URL.
- **Projection:** `--fields` selects literal, case-sensitive top-level keys locally. Use letters, digits, underscores or hyphens in field names. It does not filter or sort rows, change the request size, fetch another page, or redact confidential data. Missing keys become `null`. An empty collection prints no JSONL records. Duplicate names, empty names and nested paths such as `prompt.name` are usage errors.
- **Format:** Table is the default. Use `--json` for the complete response, `-o jsonl` for the selected rows without the envelope, or `-o table` for a human-readable view. With `--fields`, JSON preserves everything outside the selected array, including sibling fields. Check the exit code rather than treating nonempty stderr as a failure.

For example, a row for an existing template named `ridgeline-warranty` would look like this in projected JSONL (the ID in your workspace will differ):

```json
{"id":"ab807869-8185-4f55-84dd-cba380dd372d","name":"ridgeline-warranty"}
```

If the support workspace has no prompts yet, you can try paging through system evaluation templates instead. Unlike prompt listing, this read uses a POST body, `--page-size` and a first page of **0**. These calls return the first two pages, one template per page, without running an evaluation:

```bash
fagi api evaluations templates list --owner-filter system --page 0 --page-size 1 --fields id,name -o jsonl --no-input
fagi api evaluations templates list --owner-filter system --page 1 --page-size 1 --fields id,name -o jsonl --no-input
```

For this endpoint, `--json` includes `result.page`, `result.page_size`, `result.total` and `result.items`. There is no pagination hint on stderr for this shape. To finish the inventory, keep the page size fixed and increment `--page` while `(page + 1) * page_size < total`.

## Preview a write and verify a refusal

Every generated API command supports `--dry-run`. It validates inputs and prints the HTTP method, encoded path and redacted body without looking up credentials or sending a request. It cannot tell you whether the server will accept the request. Pipe a single JSON object through stdin to preview the new Ridgeline prompt:

```bash
printf '%s\n' '{"name":"ridgeline-returns","description":"Answer questions about returning outdoor gear."}' |
  fagi api prompts create --data-file - --dry-run --json --no-input
```

The preview shows `POST` and `/model-hub/prompt-templates/`. No prompt exists as a result. A command with a JSON body accepts **either** `--data-file PATH` (`-` for stdin) **or** `--data` with one inline JSON object, up to 16 MiB. Explicit body flags override matching JSON keys. Use stdin or a protected file for sensitive values so they do not appear in shell history or process arguments.

| Access in the catalog | What happens without `--dry-run` |
| --- | --- |
| `read` | Runs without confirmation. Some reads use POST, for example `api evaluations templates list`. |
| `write` | Runs without confirmation and can change data or schedule work. `api prompts get` is a **write**: opening a template can create its first draft. |
| `destructive` | Requires `--yes` or typing exactly `yes` at the terminal prompt. If you omit `--yes` and either set `--no-input` or pipe stdin, the CLI refuses before credentials or network access. |

`--no-input` prevents questions; it is **not** a dry run. In CI, set it explicitly or use `FI_NO_INPUT=true`. This Bash check uses `jq` to verify the refusal for a synthetic template ID. It deliberately omits `--yes`:

```bash
(
  rc=0
  diagnostic=$(fagi api prompts delete --id 8bca26c6-d6af-4ba2-8918-12328efaf3cb --no-input --json 2>&1) || rc=$?
  printf 'CLI exit code: %s\n' "$rc"
  test "$rc" -eq 2 &&
    jq -e '.details.code == "confirmation_required"' <<<"$diagnostic"
)
```

The CLI returns **2** and writes a JSON error with `details.code` set to `confirmation_required` on stderr. The check prints `true` and succeeds only for that refusal. The command does not check whether the ID exists. Do not add `--yes` to fix a refusal unless you intend the deletion.

## API command catalog

Expand an operation to see its inputs, access, pagination and output. Each command starts with `fagi api`. To set a **JSON key** with no corresponding flag, put it in the request body. Only inputs marked `required` are unconditionally required by the CLI; see each command for additional server rules. For body fields with both a flag and a JSON key, use either spelling in its corresponding input. Array flags accept comma-separated values or repeated flags. Omitted optional inputs retain the server's defaults. If an operation lists no pagination flags, it has no CLI continuation control. The listed row path controls table and JSONL output; `--json` preserves the full response. When a command supports `--fields`, it requires an array of objects at that path.

This catalog is not the entire REST API or MCP tool list. Of 111 platform tools, this CLI excludes 16 legacy agent and simulation operations and four SQL operations. It adds `prompts delete` and `gateway playground test`, bringing the total to 93. The playground test makes a real model request unless you use `--dry-run`. Workflow commands outside `fagi api`, such as `fagi trace check`, are not part of that count.

## Limits and errors

A script can receive structured errors on stderr in either JSON mode. Preserve stdout separately. If the server returns a body but its rows are missing or unexpected, repeat a **read** with `--json` and without `--fields` to inspect the response. Do not repeat a write just to change its output format. For page-size flags with a CLI ceiling, `--allow-large-pages` relaxes only that ceiling, never the server's limit. Responses are limited to 8 MiB; request a smaller page if a result is too large. The default API timeout is 30 seconds; the server may still finish a write after the CLI times out. There are no automatic retries.

| Exit | Meaning | What to do |
| --- | --- | --- |
| `0` | Success, including a valid dry run, an empty list or an empty search | Read the result. A successful read is not a quality judgment. |
| `1` | Unexpected error, response-shape error or conflict (HTTP 409) | Inspect the error. For a conflict, check current resource state. |
| `2` | Invalid input, missing confirmation, or HTTP 400/422 | Fix the flag, JSON body or identifier. |
| `3` | Authentication, permission, plan or deployment restriction (HTTP 401/402/403) | Check the key pair for 401; check access or plan for 403/402. |
| `4` | Resource or endpoint not found (HTTP 404) | Check the ID, workspace and endpoint availability. |
| `5` | A workflow quality gate failed | Inspect the gate report, for example the failed assertion from `fagi trace check`. This is **not** a transport failure. |
| `6` | Connection or server error, including HTTP 408/425/429/5xx | Follow the diagnostic. Retry only when indicated; check whether a write took effect first. |
