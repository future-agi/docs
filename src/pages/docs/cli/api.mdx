---
title: "Call any endpoint"
description: "Call Future AGI platform endpoints that have no dedicated command with fagi api: find the command, read, write, page through results and shape the output"
---

`fagi api` calls the Future AGI platform API directly, one command per endpoint. Use it for anything without a dedicated `fagi` command, such as listing workspaces, submitting annotations, reading alert rules or changing one dataset cell. Each command takes its parameters as flags and prints a table, JSON (`--json`) or JSON Lines (`-o jsonl`). Sign-in, `--workspace` and the [exit codes](/docs/cli/configuration-and-output#exit-codes) work as for every other command.

When a dedicated command fits, use it instead: it looks up names, waits for work to finish and checks the result. `fagi datasets push` and `pull` move whole files, `fagi prompts pull` and `diff` compare versions, `fagi gateway try` checks guardrails, and `fagi epoch run` fills an Epoch launch from its defaults. Simulation has no `fagi api` equivalent; use `fagi sim`.

<Prerequisites>
- Signed in to the CLI (see [Sign in](/docs/cli/install-and-auth#sign-in))
- A workspace to act in (see [Choose a workspace](/docs/cli/install-and-auth#choose-a-workspace))
</Prerequisites>

## Command groups

Commands are grouped by product area, then resource. Run `fagi api --help` for the current list.

| Group | What it covers |
|---|---|
| `fagi api annotations` | Annotation queues and their items: read an item, submit values, complete it |
| `fagi api context` | Who you are signed in as, and the workspaces you can use |
| `fagi api dashboards` | Dashboards, their widgets, metric discovery, filter values and ad hoc metric queries |
| `fagi api datasets` | Datasets, columns, rows, cells, dataset evaluations, prompt columns, knowledge bases and prompt stats |
| `fagi api epoch` | Launch options for an Epoch on a finished run, starting one, and reading it. Ships in the next release (see [Epoch](/docs/cli/epoch#set-every-launch-field-yourself)) |
| `fagi api error-feed` | Grouped error issues, their overview and the traces in each |
| `fagi api evaluations` | Evaluation templates, evaluation groups, and testing a template on inputs |
| `fagi api experiments` | Experiments: create, list and read them |
| `fagi api gateway` | AI gateways, their config, analytics, request logs, sessions, guardrail rule counts and one test prompt |
| `fagi api observability` | Tracing projects, traces, spans, sessions, filter properties, online eval tasks, eval configs, alert rules and fired alerts |
| `fagi api optimization` | Dataset optimization runs |
| `fagi api prompts` | Prompt templates, their versions, running a version and reading its result |
| `fagi api usage` | Usage and cost overview for your organization. Future AGI Cloud only (see [Self-hosted](/docs/cli/install-and-auth#self-hosted)) |

## Find a command

Walk down the tree with `--help`. Each level lists the commands under it, and a command's help gives its description, its flags with their limits and allowed values, its table columns, and whether it reads, writes or destroys data.

```bash
fagi api --help
fagi api observability --help
fagi api observability traces search --help
```

To search by words instead, use `fagi schema --search`; see [Find commands](/docs/cli/configuration-and-output#find-commands).

Flags with a fixed set of values complete with Tab once [shell completion](/docs/cli/install-and-auth#turn-on-shell-completion) is on. Completion is local and makes no request:

```bash
fagi api evaluations templates create --eval-type <TAB>
```

## Read

Most reads act in one workspace; see [Choose a workspace](/docs/cli/install-and-auth#choose-a-workspace). `WORKSPACE_ID` is the `ID` column of `fagi api context workspaces list`. Every command sends only the flags you pass, so the server's defaults apply to the rest.

```bash
fagi api context whoami
fagi api context workspaces list --json
fagi api observability projects list --workspace WORKSPACE_ID
fagi api observability traces search --project-id PROJECT_ID --page-size 50 --json
```

`fagi api observability projects list` prints a table like this:

```text
ID                                    NAME            TRACE_TYPE  TRACE_COUNT
3fa85f64-5717-4562-b3fc-2c963f66afa6  support-agent   observe     1204
```

With `--json` it prints the full response object, with the rows under `result.projects`. `PROJECT_ID` is the `ID` column of that list.

Flags are checked before anything is sent; a bad or missing value exits 2 with no request made.

## Page through a list

Each command sends one request and returns one page. The CLI never follows the next page on its own: pass the page or cursor flag the command takes, such as `--page`, `--page-number` or `--cursor`. Check the command's `--help` for which paging flag it takes.

```bash
fagi api observability properties list --cursor-mode --page-size 50 --json
fagi api observability properties list --cursor-mode --page-size 50 --cursor NEXT_CURSOR --json
```

Here `NEXT_CURSOR` is the `result.next_cursor` field of the previous page's JSON. The field differs between commands: read its path from `cursor_field` in the `{"pagination":...}` record on stderr (see [What goes to stderr](/docs/cli/configuration-and-output#what-goes-to-stderr)).

Some list commands have a CLI safety maximum for `--page-size`, below the server maximum. `--help` shows it, and `--allow-large-pages` bypasses it.

## Write

Writes are sent once and never retried. After a timeout or a network error, read the resource to see whether the change landed before you run the command again.

Four commands are destructive and ask for confirmation: `fagi api datasets delete`, `fagi api dashboards delete`, `fagi api observability eval-tasks update` (it can rerun a task or reset its results) and `fagi api prompts delete`. On a terminal you type `yes`. With `--no-input`, or with no terminal, a missing confirmation exits 2 and sends nothing unless you pass `--yes`. A declined prompt also exits 2 and sends nothing.

Preview a write with `--dry-run`, then send it:

```bash
fagi api prompts delete --id PROMPT_ID --dry-run
fagi api prompts delete --id PROMPT_ID --yes --no-input
```

`PROMPT_ID` is the `ID` column of `fagi api prompts list`. Every `fagi api` command accepts `--dry-run`: it checks your flags and prints the request it would send (method, path, body, headers with secrets redacted, base URL and workspace) without reading credentials or contacting the server.

```text
method        DELETE
path          /model-hub/prompt-templates/PROMPT_ID/
body          null
base_url      resolved at execution (dry-run reads no profile files)
workspace_id  resolved at execution; pass --workspace to pin it
```

Some writes start billed work, such as running a prompt, running dataset evaluations, sending a gateway test prompt or launching an Epoch. Run `--dry-run` first and check `--help`, which notes when a command may incur charges.

### Request bodies

A command that sends a JSON body takes a flag for each simple field, plus one of:

| Flag | What it does |
|---|---|
| `--data JSON` | The body as an inline JSON object |
| `--data-file PATH` | The body from a JSON file, or `-` for stdin; at most 16 MiB |

Flags you pass override the same keys in the data. Nested and secret fields have no flag of their own; help lists them under "Other body fields (set with --data/--data-file)". Put secrets in a protected file or stdin rather than inline `--data`, which stays in shell history.

```bash
fagi api datasets delete --dataset-ids DATASET_ID --dry-run
echo '{"dataset_ids":["DATASET_ID"]}' | fagi api datasets delete --data-file - --yes --no-input --json
```

`DATASET_ID` is the `ID` column of `fagi api datasets list`. An array flag such as `--dataset-ids` takes comma-separated values or can be repeated.

## Shape the output

A table and `-o jsonl` print only the rows, with the columns listed in `--help`; `--json` prints the whole response (see [Output formats](/docs/cli/configuration-and-output#output-formats)). If the response lacks the row collection, table and JSONL output exit 1; rerun with `--json`. An empty list succeeds and prints a `No ... found.` line.

Most list and search reads take `--fields`, which keeps only the row keys you name, in that order. It shapes the output locally and does not change the request. Keys are comma-separated top-level row keys, and a missing key becomes null. With `--json` the rest of the response is kept. An invalid list exits 2 with `details.code` `invalid_fields`. `fagi schema` does not list `--fields`, so check the command's `--help`.

```bash
fagi api datasets list --fields id,name --json
fagi api observability traces search --project-id PROJECT_ID --fields trace_id,status,cost -o jsonl
```
