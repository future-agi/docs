`fi agents` works with the agents you simulate: list them and their versions, push a local folder of your agent's code as a new agent version of an [environment](/docs/cli/environments), and read that version's connection check: the server's test that it can reach your agent with its credentials. Nothing runs on your machine: push uploads files, and the check runs on the server.

## In this page

List and show agents, push a new version and what push uploads, the rule about which environments take a pushed version, and how `fi agents test` reports a check.

## List and show agents

```bash
futureagi agents list --search support
futureagi agents show AGENT_ID
futureagi agents versions list AGENT_ID
```

`AGENT_ID` is the `ID` column of `fi agents list`, and `VERSION_ID` is the `ID` column of `fi agents versions list AGENT_ID`. `ENV_ID`, used below, is the `ID` column of `fi sim env list`.

| Command | What it does |
|---|---|
| `fi agents list` | Agents in the workspace, newest first. `--agent-type voice` or `text`, `--search` (name, description, contact number or assistant ID), `--page`, `--limit` (1-100) |
| `fi agents show AGENT_ID` | The agent and its version history. `--version VERSION_ID` shows one version, and `--json` adds its configuration snapshot; `--definition` shows the agent document stored with a version, and exits 4 when the version has none |
| `fi agents versions list AGENT_ID` | The agent's versions, newest first. `STATUS` here is the agent record's status (`draft`, `active`, `archived` or `deprecated`), not whether a run can take the version |

To pick a version for `--agent-version`, use `fi sim env versions list ENV_ID`: it lists the environment's own agent versions with their checks and defaults, and `PICKABLE` shows which ones a run can take. A version that `fi agents push` made can show `draft` in `fi agents versions list` and still be pickable.

## Push a new version

```bash
futureagi agents push --repo ./my-agent --env ENV_ID --dry-run
futureagi agents push --repo ./my-agent --env ENV_ID --wait
```

Push uploads the folder and makes it the environment's next agent version. The server checks the new version in the background. When the check passes, the version becomes the environment's default, unless the server postpones that, for example while a build or run is in progress or the build did not complete. With `--wait`, the `connection_check.activation_outcome` row of the push output shows the result: `applied` means it is now the default, and another value, such as `environment_busy`, means it did not move. Without `--wait` that row is `-`, so check `IS_DEFAULT` in `fi sim env versions list ENV_ID` once the check ends.

| Flag | What it does |
|---|---|
| `--repo PATH` | The agent's local folder, such as `.` (required) |
| `--env ENV_ID` | The environment that gets the new version (required unless `--dry-run`) |
| `--name NAME` | Name of the upload (default: the folder name) |
| `--dry-run` | Upload nothing: print the file count, size and digest, list the files under `source.files`, and with `--env` check the environment exists |
| `--wait`, `--interval N` | Wait until the version's check ends, polling every N seconds (default 2), for at most `--wait-timeout` (default 60m, a [global flag](/docs/cli/install-and-auth)) |

With `--wait`, push exits 0 when the check passed, even if the move to default was postponed, 5 when it failed, 8 when the version was discarded, and 6 when `--wait-timeout` ended the wait; Ctrl-C stops the waiting only. Bad flags, a missing `--repo` folder, one over the upload limit, or a git checkout whose files git cannot list exit 2, and an unknown `--env` exits 4.

### What push uploads

- In a git checkout: the files git tracks plus untracked files that are not ignored. If git is missing or cannot list the files, push exits 2 and names the fix, such as `git config --global --add safe.directory PATH`
- Otherwise: every file except `.git`, `node_modules`, `.venv`, `venv` and `__pycache__`. `.gitignore` is not applied, so check the file list with `--dry-run`
- Never, in either case: symlinks, and files that may hold secrets, matched without regard to case: `.env` and `.env.*` files (`.env.example`, `.env.sample` and `.env.template` are kept); anything in a `.fi`, `.ssh`, `.aws`, `.gnupg`, `.azure`, `.kube` or `.config/gcloud` folder; `.docker/config.json`, `.git-credentials`, `.netrc`, `.npmrc` and `.pypirc`; SSH private keys such as `id_rsa` (`.pub` files are kept); and `.pem`, `.key`, `.p12`, `.pfx`, `.jks`, `.keystore`, `.ppk` and `.p8` files. In a git checkout, also nested git checkouts and submodules. They are listed under `source.skipped`, even when git tracks them
- In a plain folder, a nested git checkout loses only its `.git` folder: its other files are uploaded and not listed
- At most 999 files and 200 MiB. A large upload may take `--timeout` plus 1 second per 128 KiB; on a slow link, pass a larger `--timeout`

Other files that hold secrets, such as `config/prod.env` or a service-account `.json` file, are uploaded, so keep secrets out of the folder. Store each one with [`fi sim env agent secrets set`](/docs/cli/environments#set-a-credential), which saves it on the server and creates a new agent version that uses it.

Part of the `--dry-run` output; the full table also prints the environment, agent, version and check rows, and more `source.*` rows:

```text
source.kind          archive
source.name          my-agent
source.file_count    38
source.total_bytes   412870
source.upload_digest sha256:5f2c…e81a
source.skipped       [.env]
dry_run              true
```

### Which environments take a push

A pushed folder is an **archive** source, and only an environment whose agent came from an uploaded folder accepts one: its `SOURCE_KIND` in `fi sim env list` is `archive`. The server refuses the rest with HTTP 422, which exits 1 and prints the `source_id` of the upload it made:

- An agent from GitHub, a voice or chat platform, a phone number or LiveKit
- An agent managed on the **Agents** page of the web app
- An upload identical to the current default
- An upload that expired before the version was made
- A server that cannot run changed versions yet

A folder that holds only an archive file (`.zip`, `.tar`, `.tar.gz`, `.tgz`, `.rar` or `.7z`) exits 2 before anything is sent: expand it and push the folder.

Push sends no idempotency key. If reading the check fails after the version was made, push exits 6 (or 3) and prints its `version_id`. After exit 6 or 3, look for that `version_id`, or run `fi sim env versions list ENV_ID`, before you push again.

## Check a version

```bash
futureagi agents test AGENT_ID --env ENV_ID
futureagi agents test VERSION_ID --env ENV_ID --wait-timeout 5m --json
```

`fi agents test` reads the check of an agent version and prints it. With `AGENT_ID` it checks the environment's default agent version, or the one `--agent-version` names; with `VERSION_ID` it checks that version. A `VERSION_ID` always needs `--env` and exits 4 without it. Without `--env`, an `AGENT_ID` uses the only environment that uses the agent; if no environment or more than one uses it, the command exits 2.

After a push, check the pushed version with the `version_id` from the push output: `futureagi agents test VERSION_ID --env ENV_ID`. For an environment built from an uploaded folder, the `AGENT_ID` form can exit 4. To check the agent a run used, pass the `versions.agent.id` and `environment_id` rows of `fi sim runs status RUN_ID`.

`fi agents test` doesn't start a fresh check. For a version whose check failed, it checks the source and credentials again. For a version that passed, it shows the saved result. A re-check that passes makes the version the default, unless the server postpones that, as with push.

| Flag | What it does |
|---|---|
| `--env ENV_ID` | The environment the agent or version belongs to |
| `--agent-version VERSION_ID` | With `AGENT_ID`, the version to check instead of the default |
| `--interval N` | Seconds between polls while a check is pending (default 2) |
| `--wait-timeout DURATION` | The longest time to wait for a pending check (default 2 minutes for this command) |

| Exit | When |
|---|---|
| 0 | The check passed |
| 1 | The server refused the re-check (HTTP 409 or 422) |
| 2 | The version was discarded, the environment has no saved default, `--agent-version` is combined with a `VERSION_ID`, or without `--env` no environment or several use the agent |
| 4 | The agent or version is not found, a `VERSION_ID` is given without `--env`, or `--agent-version` is not a version in the environment |
| 5 | The check failed; the failing check and missing names are printed |
| 6 | `--wait-timeout` ended the wait, a network or server error, or the version has no check record |
| 8 | The version was discarded while the check was pending, or the check ended in another state |

Each row is one check, with its `SCOPE` and its state. Rows with scope `server`, such as `source`, `credentials_present`, `credentials_valid` or `provider_target`, are the checks the platform runs, and show `passed`, `failed` or `skipped`. Rows with scope `plan` (`start`, `two_turn_session`, `tool_binding`, `evidence` and `stop`) are deeper checks the platform doesn't run yet; they always show `unknown`, never `passed`. A pass means the agent can be reached with its credentials, not that an environment's scenarios will succeed.
