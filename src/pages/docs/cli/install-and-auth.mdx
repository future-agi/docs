The CLI is one Go binary. You build it from the private `future-agi/futureagi-cli` repository, sign it in with a personal API key pair, and point it at Future AGI Cloud or your own install. This page is the reference for everything that applies to every command: credentials, profiles, configuration, global flags and exit codes.

## Install

There is no published release, Homebrew formula or npm package yet. Both ways below need Go 1.24 or later and GitHub access to the `future-agi` organization. Each puts the binary on your `PATH` twice, as `fi` and as `futureagi`: `fi` is a reserved word in bash and zsh, so type `futureagi` in a shell. The tables on this page name commands `fi`; both names run the same command.

<Tabs>
<Tab title="go install">

```bash
git config --global url."git@github.com:".insteadOf "https://github.com/"
GOPRIVATE='github.com/future-agi/*' GOBIN="$(go env GOPATH)/bin" go install github.com/future-agi/futureagi-cli/cmd/fi@fi-cli-commands
ln -sf "$(go env GOPATH)/bin/fi" "$(go env GOPATH)/bin/futureagi"
PATH="$(go env GOPATH)/bin:$PATH"
futureagi version
```

The `git config` line makes Go fetch GitHub modules over SSH, since the module is private; `GOPRIVATE` stops Go from asking the public module proxy for it. Until the simulation commands reach the main branch, install from the `fi-cli-commands` branch, as `@fi-cli-commands` does. A binary built this way reports version `dev`.

</Tab>
<Tab title="Build from source">

```bash
git clone git@github.com:future-agi/futureagi-cli.git
cd futureagi-cli
git checkout fi-cli-commands
make build
PATH="$PWD/bin:$PATH"
futureagi version
```

`make build` writes `bin/fi` and `bin/futureagi`, stamped with the git version and commit.

</Tab>
</Tabs>

In CI, where there is no SSH key, rewrite the URL with a token that can read the repository instead: `git config --global url."https://x-access-token:${GH_TOKEN}@github.com/".insteadOf "https://github.com/"`. [Runs](/docs/cli/runs#gate-a-ci-build-on-the-pass-rate) has a full GitHub Actions example.

To upgrade, run the same `go install` line again, or `git pull && make build` in the clone.

For tab completion, `futureagi completion bash`, `zsh`, `fish` or `powershell` prints a completion script; `futureagi completion zsh --help` says where to put it. The script completes the command name `fi` only, so register it for `futureagi` too after loading it: in zsh add `compdef _fi futureagi`, and in bash add `complete -o default -F __start_fi futureagi`.

## Sign in

The CLI signs in with a **personal** API key pair: an API key and a secret key you create on [API Keys](https://app.futureagi.com/dashboard/keys). It never creates keys itself.

```bash
futureagi auth login
```

On a terminal it asks for both keys with echo off, then saves the pair in your OS keychain under the active profile (see [Profiles](#profiles) for how it is chosen; `default` when none is set). A later login without `--profile` saves to the active profile and overwrites its keys. Login only stores the pair; it does not contact the server. Check it with `futureagi auth status` or `futureagi doctor`.

| Command | What it does |
|---|---|
| `fi auth login` | Save a key pair in the OS keychain for this profile and base URL |
| `fi auth status` | Validate the profile against the server; prints the profile, the first six characters of the key and `signed_in` |
| `fi auth logout` | Remove this profile's stored credentials. It does not revoke the key on the server |

`fi auth login` takes `--api-key` and `--secret-key`, or reads `FI_API_KEY` and `FI_SECRET_KEY`. Values on the command line can end up in your shell history and process list, so prefer the prompt. Without a terminal, or with `--no-input`, a missing key exits 2 instead of prompting.

<Note>
In CI you do not need to log in at all: when the `FI_API_KEY` and `FI_SECRET_KEY` [environment variables](#environment-variables) are both set, every command uses that pair directly and stores nothing. With them set, `futureagi auth login --no-input` saves the pair to the keychain instead; where no OS keychain is available, that exits 3 or can hang with no output. If it hangs, press Ctrl-C and use the variables directly, or `--insecure-file-store`.
</Note>

A locked or missing keychain is an error, never a silent fallback. `--insecure-file-store` saves the pair as a plaintext file readable only by you (mode 0600) at `~/.config/fi/credentials/NAME.json`; every later command then needs the same flag to read it.

### Self-hosted installs

Create the key pair on your install's own dashboard, at `DASHBOARD_URL/dashboard/keys`, where `DASHBOARD_URL` is your install's dashboard address; Cloud keys do not work against a self-hosted API. Pass your install's API URL when you log in. The profile remembers it, so later commands need no flag.

```bash
futureagi auth login --profile self-hosted --base-url https://futureagi.example.com
futureagi doctor --profile self-hosted
```

`FI_BASE_URL` does the same as `--base-url`. Saved keys are bound to the URL they were saved with: pointing a profile at another URL refuses to send them (exit 3) until you log in for that URL. Without a base URL the CLI talks to Cloud, `https://api.futureagi.com`.

## Profiles

A profile is one named sign-in: a base URL and a key pair. Use one per install or per account.

```bash
futureagi auth login --profile staging --base-url https://staging.futureagi.example.com
futureagi profiles list
futureagi profiles use staging
futureagi profiles remove staging
```

| Command | What it does |
|---|---|
| `fi profiles list` | List saved profiles with their base URL and credential store, without reading any secret |
| `fi profiles use NAME` | Make NAME the profile commands use by default |
| `fi profiles remove NAME` | Remove the profile and its stored credentials; safe to repeat. Removing the active profile clears the selection, so commands fall back to `default` (Cloud) until you run `fi profiles use` or log in again |

The active profile is, in order: `--profile`, then `FI_PROFILE`, then the one `fi profiles use` set, then `default`. Whenever no profile is active (your first login, or after you remove the active one), the profile you log in to becomes active, so that login with `--profile staging` makes `staging` the active profile until you switch with `futureagi profiles use`.

## Choose a workspace

Most commands act in one workspace, sent to the server as `X-Workspace-Id`. List the workspaces your key can use; the `ID` column is the value to pass:

```bash
futureagi api context workspaces list
```

To use one for every command, save it as `workspace_id` under your profile's table in the user config file, `~/.config/fi/config.toml`, as [Configuration files](#configuration-files) shows. For a single command, pass `--workspace WORKSPACE_ID`. `FI_WORKSPACE_ID` also sets it (see [Environment variables](#environment-variables)); the flag wins over the variable, and the variable over the file.

Without a workspace, environment, run and agent lists may come back empty, with a warning. Persona commands use the key's own workspace or, for a key bound to none, the one you last selected in the web app. Save a workspace so every command acts in the one you expect. A value that is not a workspace UUID exits 2. A well-formed UUID your key cannot use is not an error: lists come back empty with no warning, reads by ID exit 4, and persona commands may return another workspace's personas. Check the ID against `futureagi api context workspaces list`.

## Configuration files

Settings can also live in TOML files, one table per profile. The CLI reads a project file, `.fi/config.toml`, found by searching up from the current directory, and a user file, `~/.config/fi/config.toml` (or `$XDG_CONFIG_HOME/fi/config.toml`).

```toml
[profiles.default]
base_url = "https://api.futureagi.com"
workspace_id = "4c1d2e3f-5a6b-4c7d-8e9f-0a1b2c3d4e5f"
```

For a profile saved with `fi auth login`, leave `base_url` out of the file or set it to the login URL; a different value makes the saved keys refuse to send (exit 3). Keep keys out of these files: use the keychain or the environment variables. Each setting is taken from the first place that has it:

1. Command-line flags
2. Environment variables
3. The project file
4. The user file
5. The profile saved by `fi auth login`

Saved profiles (`profiles.json`) and plaintext credentials (`credentials/NAME.json`, one per profile) live in the same directory as the user file, `~/.config/fi/`.

## Check your setup

`fi doctor` checks the configuration, then that the server is reachable, then that your credentials work, and stops at the first problem with what to fix.

```bash
futureagi doctor
```

```text
profile       default
base_url      https://api.futureagi.com
base_url_src  default
api_key       a1b2…9f3c
reachable     true
signed_in     true
user          you@example.com
```

`base_url_src` says where the URL came from: `flag`, `env`, a config file path, or `default` (Cloud, or the URL saved with the profile). An unreachable server exits 6. Missing credentials exit 3; a key pair the server rejects currently shows `reachable false` and exits 6.

## Global flags

Every command takes these.

| Flag | What it does |
|---|---|
| `--profile NAME` | Profile to use (or `FI_PROFILE`; default: the active profile, see [Profiles](#profiles)) |
| `--base-url URL` | Platform API URL, for self-hosted installs (or `FI_BASE_URL`) |
| `--workspace ID` | Workspace sent as `X-Workspace-Id` (or `FI_WORKSPACE_ID`, or `workspace_id` in a config file) |
| `-o`, `--output FORMAT` | `table` (default), `json` or `jsonl` |
| `--json` | Short for `--output json` |
| `--no-input` | Never prompt; fail instead. For CI and coding agents |
| `-y`, `--yes` | Confirm a destructive or charged action without a prompt |
| `--timeout DURATION` | Limit for each API request attempt, such as `30s` or `2m` (default 30s) |
| `--wait-timeout DURATION` | Longest time a `--wait` or `--follow` waits, such as `45m` (default 60m; `0` means no limit). When it runs out the command exits 6 and the work keeps running. `fi agents test` waits 2 minutes unless you pass it |
| `--insecure-file-store` | Allow plaintext credential storage instead of the keychain |

Commands that delete, overwrite or spend credits, such as building an environment, starting a run, canceling one or deleting a persona, ask for confirmation on a terminal. Without a terminal, or with `--no-input`, they need `--yes` and exit 2 without sending anything when it is missing.

In `--json` and `-o jsonl` modes, errors are printed to stderr as JSON with `error` and `exit_code`, plus fields such as `idempotency_key` when a write carried one. Secret values in any output are shown as `***`.

## Environment variables

| Variable | What it sets |
|---|---|
| `FI_API_KEY`, `FI_SECRET_KEY` | A key pair to use directly. Set both or neither; they win over any stored pair |
| `FI_BASE_URL` | Platform API URL |
| `FI_PROFILE` | Profile to use |
| `FI_WORKSPACE_ID` | Workspace to act in |
| `XDG_CONFIG_HOME` | Moves the user config directory to `$XDG_CONFIG_HOME/fi` |

## Exit codes

Every command uses the same codes, so scripts and agents can branch on them.

| Code | Meaning |
|---|---|
| 0 | Success |
| 1 | Unexpected error, or the server refused the request with a reason, such as a conflict or the resource's current state; some commands document an HTTP 409 or 422 refusal of this kind as exit 1 |
| 2 | Bad flags or arguments, a confirmation that needs `--yes`, a question that needs an answer, the server rejected the input (HTTP 422, unless the command documents it as exit 1), or an idempotency key was reused for a different request |
| 3 | Not signed in, credentials rejected, or not allowed |
| 4 | The resource does not exist, or is not in this workspace; `fi sim env save` and `fi sim suites save` also exit 4 when there is nothing to save |
| 5 | A gate failed: a run's pass rate is under `--fail-under`, or an agent check failed (`fi agents test`, and `--wait` on `fi agents push`, `fi sim env agent secrets set` and `fi sim env agent retry`) |
| 6 | Network or server error, a request timeout, `--wait-timeout` ended the wait, or an environment build failed for an infrastructure reason |
| 7 | Reserved |
| 8 | Work you waited for ended without a usable result: it failed, was canceled, is partial or has nothing measured, or the environment builder needs your answer. Also when the result doesn't exist: an environment section that isn't built, or an agent version with no check record |

Reads are safe to repeat after exit 6. After exit 8, read the work before you rerun anything: running `fi sim run` again starts a new charged run. Writes are not resent on their own: repeat one only with the same idempotency key, or after reading the resource to see whether the first try landed.

## Troubleshooting by exit code

| Exit | What to check |
|---|---|
| 1 | The server refused with a reason: read the message. A `version_conflict` means someone changed the environment's default version after you read it, so list the versions and pass the new one (see [Environments](/docs/cli/environments)). A refused `futureagi agents push` prints the `source_id` of the upload it made (see [Agents](/docs/cli/agents)) |
| 2 | Read the message: it names the flag or argument. Add `--yes` to confirm without a terminal. Without a terminal, `futureagi sim env create` needs `--yes` too |
| 3 | Run `futureagi doctor`. Log in again with `futureagi auth login`, check that `--base-url`, `FI_BASE_URL` or a config file `base_url` matches the URL you logged in with, pass `--insecure-file-store` on every command if you logged in with it, and check that both `FI_API_KEY` and `FI_SECRET_KEY` are set if you use them. If the message says the plan or edition does not include the feature (HTTP 402), the key is fine; for a 403 with `--workspace` set, check that your key can use that workspace. A workspace your key cannot use often returns empty lists or exit 4 instead (see [Choose a workspace](#choose-a-workspace)) |
| 4 | Check the ID and the workspace: the resource may be in another workspace, so pass `--workspace` or save `workspace_id` (see [Choose a workspace](#choose-a-workspace)). If every command exits 4, check that `--base-url` is the API URL, not the dashboard URL |
| 5 | The command worked and the gate failed: read the results or the failing check it printed |
| 6 | Run `futureagi doctor` to test the connection. If the message says HTTP 401, the server is reachable and rejected the key pair: log in again with a key pair from this install. When `--wait-timeout` ended the wait, rerun the status command it printed (with a larger `--wait-timeout` if needed); the work itself kept going |
| 8 | Read the message and the work's status before rerunning. A build that needs input names the question: answer it with `futureagi sim env chat ENV_ID` (see [Environments](/docs/cli/environments)). A failed, canceled or partial run: read `futureagi sim runs results RUN_ID` |
