Install `fagi` in a CI job, sign in with a key pair from your secrets, and fail the build with any of the CLI's gates.

<Prerequisites>
- A key pair stored as CI secrets, here `FI_API_KEY` and `FI_SECRET_KEY` (see [Sign in with environment variables](/docs/cli/install-and-auth#sign-in-with-environment-variables))
- For the `fagi sim` and `fagi skills` gates, a CLI from the next release; `fagi skills` is in preview (see [Command families](/docs/cli#command-families))
</Prerequisites>

## Authenticate in CI

```yaml
steps:
  - uses: actions/setup-node@v4
    with:
      node-version: 22
  - run: npm install -g @future-agi/cli
  - run: fagi auth status --json
    env:
      FI_API_KEY: ${{ secrets.FI_API_KEY }}
      FI_SECRET_KEY: ${{ secrets.FI_SECRET_KEY }}
      FI_NO_INPUT: "1"
```

With the key pair in the environment there is no login step; [Sign in with environment variables](/docs/cli/install-and-auth#sign-in-with-environment-variables) explains it, including `FI_BASE_URL` for a self-hosted install. `FI_NO_INPUT=1` makes a command fail instead of waiting for a prompt; [Coding agents](/docs/cli/coding-agents#machine-mode) covers it and `FI_OUTPUT`.

## Choose a gate

Each of these commands exits 5 when its gate fails, which fails the CI step. The report or diff is the output. Other exit codes follow the [shared exit codes](/docs/cli/configuration-and-output#exit-codes).

| Command | Gate flag | Fails when | Page |
|---|---|---|---|
| `fagi trace check` | A check flag such as `--max-error-spans`; `--junit-file` writes a report | A stored trace breaks a check | [Tracing](/docs/cli/tracing#gate-a-build-on-a-trace) |
| `fagi eval suite` | `--min-match-rate`; `--junit-file` writes a report | The match rate is below the threshold | [Evals](/docs/cli/evals#gate-ci-with-a-suite-of-cases) |
| `fagi prompts diff` | `--exit-code` | The platform's prompt differs from the committed file | [Prompts and gateway](/docs/cli/prompts-and-gateway#check-for-drift-in-ci) |
| `fagi gateway try` | `--expect` | The guardrail outcome differs | [Prompts and gateway](/docs/cli/prompts-and-gateway#assert-a-guardrail-outcome-in-ci) |
| `fagi skills verify` | None; it always gates | Installed skill files differ from the lock, or the lock or manifest is missing or invalid | [Skills](/docs/cli/skills#verify-the-installed-files) |
| `fagi skills update` | `--check` | A label names a newer version | [Skills](/docs/cli/skills#move-label-following-skills) |
| `fagi sim run` | `--wait --fail-under X` | The pass rate is below X | [Runs](/docs/cli/runs#wait-and-gate-on-the-pass-rate) |
| `fagi sim runs status`, `fagi sim runs results` | `--fail-under X` (`status` also needs `--wait`) | The pass rate is below X | [Runs](/docs/cli/runs#wait-and-gate-on-the-pass-rate) |
| `fagi sim runs compare` | `--fail-on-regression` | Any scenario regressed | [Runs](/docs/cli/runs#compare-two-runs) |
| `fagi sim verify` | `--wait --fail-under X` | The lower bound of the held-back pass rate is below X | [Runs](/docs/cli/runs#verify-an-agent-version) |

The `fagi sim` gates that wait can also exit 8 or 6; [Wait and gate on the pass rate](/docs/cli/runs#wait-and-gate-on-the-pass-rate) lists when.

## Example workflow

This GitHub Actions workflow runs every gate in one job. Keep the steps you need. It needs a key pair as secrets, and the project, judge model, workspace, environment and suite version IDs as variables. The skills steps can use the job's key pair; to use a read-only skills key instead, set `FI_CONTEXT_CREDENTIAL` as a secret and `FI_CONTEXT_WORKSPACE_ID` as a variable, as the commented lines show.

```yaml
name: Future AGI checks
on: [pull_request]

jobs:
  checks:
    runs-on: ubuntu-latest
    env:
      FI_API_KEY: ${{ secrets.FI_API_KEY }}
      FI_SECRET_KEY: ${{ secrets.FI_SECRET_KEY }}
      FI_NO_INPUT: "1"
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
      - run: npm install -g @future-agi/cli
      - run: mkdir -p reports

      # Replace with your end-to-end test; it must write the trace ID it produced
      - name: Run the end-to-end test
        run: echo "TRACE_ID=$(./scripts/e2e-test.sh)" >> "$GITHUB_ENV"
      - name: Check the agent's trace
        env:
          PROJECT_ID: ${{ vars.FI_PROJECT_ID }}
        run: |
          fagi trace watch --project-id "$PROJECT_ID" --trace-id "$TRACE_ID" \
            --until-first --timeout 90s
          fagi trace check "$TRACE_ID" --project-id "$PROJECT_ID" \
            --max-error-spans 0 --junit-file reports/trace.xml

      - name: Grade the golden cases
        run: |
          fagi eval suite --template eval.json --cases golden.jsonl \
            --model "${{ vars.FI_JUDGE_MODEL }}" --output-type pass-fail \
            --id-column id --expect-column expected \
            --max-cases 50 --min-match-rate 0.9 --junit-file reports/evals.xml

      - name: Check for prompt drift
        run: fagi prompts diff support-agent --against prompts/support-agent.json --exit-code

      # The skills steps use the job's key pair. For a read-only skills key, uncomment:
      #   env:
      #     FI_CONTEXT_CREDENTIAL: ${{ secrets.FI_CONTEXT_CREDENTIAL }}
      #     FI_CONTEXT_ORIGIN: https://api.futureagi.com   # self-hosted: your platform URL
      #     FI_CONTEXT_WORKSPACE_ID: ${{ vars.FI_CONTEXT_WORKSPACE_ID }}
      - name: Install and verify the locked skills
        run: |
          fagi skills sync --frozen --yes --quiescent
          fagi skills verify
      - name: Check for newer skill versions
        continue-on-error: true            # notify only
        run: fagi skills update --check

      - name: Start the simulation run
        run: |
          RUN_ID=$(fagi sim run \
            --workspace "${{ vars.FI_WORKSPACE_ID }}" \
            --env "${{ vars.FI_ENV_ID }}" \
            --suite "${{ vars.FI_SUITE_VERSION_ID }}" \
            --idempotency-key "ci-${{ github.run_id }}-${{ github.run_attempt }}" \
            --yes --json | jq -r '.job_id')
          echo "RUN_ID=$RUN_ID" >> "$GITHUB_ENV"
      - name: Gate on the pass rate
        run: |
          fagi sim runs status "$RUN_ID" --workspace "${{ vars.FI_WORKSPACE_ID }}" \
            --wait --wait-timeout 45m --fail-under 0.8
      - name: Cancel the run if the job is canceled
        if: cancelled() && env.RUN_ID != ''
        run: fagi sim runs cancel "$RUN_ID" --workspace "${{ vars.FI_WORKSPACE_ID }}" --yes
```

- **Trace:** your test step must write `TRACE_ID` to `$GITHUB_ENV`; an empty ID makes `trace watch` exit 2. The watch reads only a sampled window, so on a busy project it can exit 6 even though the trace exists; see [Watch for new traces](/docs/cli/tracing#watch-for-new-traces)
- **Evals:** each case is a charged judge call. A cases file longer than `--max-cases` (default 20) exits 2 before any call, so set it to at least your number of cases (see [Evals](/docs/cli/evals#gate-ci-with-a-suite-of-cases))
- **Skills:** `sync --frozen` installs exactly the locked versions on a fresh clone; see [Verify the installed files](/docs/cli/skills#verify-the-installed-files) for what `verify` checks
- **Simulation:** `run_attempt` in the [idempotency key](/docs/cli/configuration-and-output#fagi-sim-flags) makes a re-run of the job start a new run. Set `--wait-timeout` longer than your run takes

## Stop a run when the job is canceled

When the step times out or the job is canceled, the run keeps going in the cloud and is charged. The last step in the example cancels it: the start step saved the Run ID in `RUN_ID`, and `if: cancelled()` runs `fagi sim runs cancel` only when the job was canceled.
