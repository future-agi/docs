`fi sim env` is the CLI side of [Environments](/docs/environments): you build an environment from a local folder of your agent's code, answer the builder until it finishes, then review and save the drafts that later edits make. An environment has three pieces, each with its own saved versions: the **agent**, the **environment** (contract and world) and the **suite** (its scenarios). A run pins one version of each.

## In this page

Find and inspect environments, build one, review and save drafts, pick default versions, manage the agent piece and its credentials, answer rebuild offers and attach evaluations. The last sections cover suites, scenarios and personas, which have their own command groups.

Every command except the persona commands takes the environment ID from `fi sim env list`, as an argument or through `--env`. IDs below are placeholders, such as `ENV_ID`.

## Find an environment

```bash
futureagi sim env list
futureagi sim env show ENV_ID
```

| Command | What it does |
|---|---|
| `fi sim env list` | List environments, newest first, with agent type, source kind, status, scenario and run counts. `--agent AGENT_ID` keeps the ones that run that agent (the `ID` column of `fi agents list`); `--page` and `--limit` (1-100) page through |
| `fi sim env show ENV_ID` | Show the overview, contract, scenarios, evaluations and settings. `--json` also includes the world. `--section tools` or `--section actors` prints only the contract's tools or the world's actors (the simulated people in this environment), one per row |
| `fi sim env rename ENV_ID --name NAME` | Rename it (1-255 characters). The name is the only editable field, and a rename makes no new version |

A section the build has not produced yet prints `building`, or `not built` when the build failed or was canceled. With `--section`, the command exits 8 when that section isn't built.

## Build an environment

`fi sim env create` uploads a local folder and starts the cloud builder on it. Nothing runs on your machine. The new environment's ID is the builder job's ID.

```bash
futureagi sim env create --repo ./my-agent --name support-bot --dry-run
futureagi sim env create --repo ./my-agent --name support-bot --yes --wait
```

The build runs in the cloud and is charged, so the create asks for confirmation on a terminal. In a script pass `--yes`; without a terminal or with `--no-input` it exits 2 and uploads nothing.

`--dry-run` uploads the folder, because the server's check scans it for the credentials it needs, and asks the server whether the build could start, including which credentials are missing, without creating anything. It lists the uploaded files under `source.files` and never asks for confirmation. The command exits 0 once it has read the server's answer, even when that answer says the build can't start yet.

| Flag | What it does |
|---|---|
| `--repo PATH` | The agent's folder. In a git checkout, the tracked and unignored files are uploaded; otherwise everything except `.git`, `node_modules`, `.venv`, `venv` and `__pycache__`. Symlinks and files that may hold secrets are never uploaded (see [What push uploads](/docs/cli/agents#what-push-uploads)). Up to 999 files and 200 MiB |
| `--name NAME` | Environment name, 1-255 characters (default: the folder name) |
| `--connector` | How the platform reaches the agent: `auto` (default), `livekit`, `vapi`, `retell`, `retell_chat` or `phone` |
| `--artifacts` | Evidence runs keep: `metadata-only`, `traces` (default), `traces-and-recordings` or `full` |
| `--count N` | Scenarios to write, 1-1000 (default 10) |
| `--config KEY=VALUE` | A non-secret agent setting; repeatable |
| `--secret NAME=KEY` | A credential already stored in the platform vault, sent as a reference: `NAME` is the variable your agent reads and `KEY` is the credential's key in the vault; repeatable. Credential values are never taken on the command line |
| `--source-id ID` | Reuse an earlier upload instead of `--repo`, to replay a create |
| `--idempotency-key KEY` | Key for the create (default: a new one, printed to stderr) |
| `--wait`, `--interval N` | Wait for a question or the end of the build, polling every N seconds, for at most `--wait-timeout` (default 60m) |

The create sends an idempotency key: the same key with the same request returns the same environment. A rerun with `--repo` uploads again under a new source ID, which changes the request, so after exit 6 rerun with the printed `--source-id`, `--name` and `--idempotency-key`, or check `fi sim env list` first.

### Follow the build and answer the builder

```bash
futureagi sim env status ENV_ID --wait --messages
futureagi sim env chat ENV_ID
futureagi sim env approve ENV_ID
```

| Command | What it does |
|---|---|
| `fi sim env status ENV_ID` | The build's state and stage, scenario counts, failure and the builder's open question with its options. `--messages` adds the builder chat (the newest 200 messages); `--after SEQ` keeps only later ones |
| `fi sim env chat ENV_ID` | On a terminal, an interactive chat: it shows the open question, reads your answer (a number picks an option) and prints the builder's replies. `-m TEXT` sends one message and exits once it is accepted |
| `fi sim env approve ENV_ID` | Approve the design the builder proposed, so it goes on building. `-m` sets the text; `--reply-to` names another confirmation |
| `fi sim env edit ENV_ID --instruction TEXT` | Send a correction while the builder is still writing the environment, before the build finishes. `--target-stage` (`understand`, `environment` or `scenarios`) redoes from that stage, `--scenario-delta N` asks for N more scenarios |
| `fi sim env cancel ENV_ID` | Stop the whole build. Saved versions are kept. Asks for confirmation; `--wait` waits until it has stopped |

With `--wait`, `fi sim env status` and `fi sim env create` exit 0 when the build completed, 8 when the builder needs your answer (the error names the question and `blocking_input` holds it in `--json`), was canceled or failed otherwise, and 6 when it failed for an infrastructure reason. An open question wins: a failed build that still has one reports that question, so read `state` before you treat it as a build in progress. A failed build keeps its draft, and the error prints a `fi sim env chat ENV_ID -m TEXT` command to ask the builder to repair it.

Every `--wait` on this page is bounded by `--wait-timeout` (default 60m). When it runs out, the command exits 6 and the work keeps running on the server; reconnect with the command it prints, such as `fi sim env status ENV_ID --wait`.

`fi sim env chat -m` picks the message kind from the builder's state: it answers the open question if there is one. `--kind interrupt` stops the builder's current turn and `--kind cancel_operation` its current operation; neither stops the build. An approval is never chosen for you. Without a terminal or with `--no-input`, chat without `-m` exits 2 with the open question.

Approvals, chat messages and corrections each carry a `client_request_id`, printed to stderr; `--idempotency-key` sets it, and a resend with the same key is stored once.

## Review and save changes

A chat edit on a built environment writes a **draft** rather than changing the saved version. Review it, then save or discard it.

```bash
futureagi sim env diff ENV_ID
futureagi sim env save ENV_ID
```

| Command | What it does |
|---|---|
| `fi sim env diff ENV_ID` | The unsaved environment draft and what it changed: its revision, parent, the current default, and each added, removed or changed item. `--version VERSION_ID` shows what a saved version changed instead; `--against VERSION_ID` compares with that version |
| `fi sim env save ENV_ID` | Save the environment draft, and the suite draft when there is one, together in one atomic save; `--piece environment` saves only the environment draft. The new versions become the defaults. Saving never starts a run |
| `fi sim env discard ENV_ID` | Discard the environment draft. Saved versions, runs and the suite draft are untouched. Asks for confirmation |

Each draft is saved only if it is still at the revision read just before the save, so a newer edit by someone else is never overwritten. `--expected-revision N` (with `--piece environment`) checks the revision you reviewed instead. The save prints its idempotency key to stderr; after exit 6, rerun with the same `--idempotency-key` to get the first save's answer instead of saving twice.

## Versions

```bash
futureagi sim env versions list ENV_ID
futureagi sim env versions set-default ENV_ID --version VERSION_ID
```

`fi sim env versions list` lists every version of all three pieces; `VERSION_ID` in these commands is a row's `ID` column. Within each piece, drafts and discarded versions come first, then saved versions by number, newest first. Each row has its label (`v1`, `v2`), status, whether it is the default and its origin (such as `authoring`, `chat` or `nudge`, and for agent versions `upload` or `credentials`). The pickable column is filled for agent versions only: a run can pick an agent version whose check passed, and any saved environment or suite version.

`fi sim env versions set-default` makes a saved environment version the one runs use by default. `--expected-default-id` refuses the move (exit 1) if the default changed meanwhile. The agent and suite defaults move with `fi sim env agent set-default` and `fi sim suites set-default`.

## The environment's agent

An agent's versions belong to an environment, so the agent piece is managed under `fi sim env agent`. New versions come from [`fi agents push`](/docs/cli/agents) or from a credential change. Each new version gets a check: the platform's automatic test that the version starts and answers.

| Command | What it does |
|---|---|
| `fi sim env agent set-default ENV_ID VERSION_ID` | Make a version the default that runs use. Only a version whose check passed qualifies |
| `fi sim env agent retry ENV_ID VERSION_ID` | Re-check a version whose check failed or is stuck. `--wait`: exit 0 passed, 5 failed, 8 discarded, 6 when `--wait-timeout` ends the wait. A passing re-check makes it the default unless the server holds the move back (see [Agents](/docs/cli/agents)) |
| `fi sim env agent discard ENV_ID VERSION_ID` | Set a version aside so it cannot be run or made the default. It cannot be undone from the CLI. Asks for confirmation |
| `fi sim env agent diff ENV_ID VERSION_ID` | What a version changed against its parent, or `--against` another version |
| `fi sim env agent secrets set ENV_ID NAME` | Store one credential as a new agent version |

### Set a credential

The value is never taken from the command line and never printed. Run the command and type the value at the prompt:

```bash
futureagi sim env agent secrets set ENV_ID OPENAI_API_KEY --from-stdin --wait
```

On a terminal, `--from-stdin` reads the value with echo off; in a script, pipe the value in instead. `--from-file PATH` stores a credential file, which accepts only `GOOGLE_APPLICATION_CREDENTIALS` with a service-account JSON file of at most 5 MiB; the server stores it as `GOOGLE_APPLICATION_CREDENTIALS_JSON`, and `stored_as` in the output names what it used. Each change makes a new agent version, which is checked and becomes the default once the check passes, unless the server holds the move back (see [Agents](/docs/cli/agents)). With `--wait`, exit 0 means it passed, 5 that it failed and 8 that the version was discarded.

## Rebuild offers

When something an environment was built on changes, such as a new agent version, changed credentials, or a new environment version that the suite should be regenerated for, the environment raises a rebuild offer (a nudge). Versions that a rebuild offer creates show the origin `nudge`.

```bash
futureagi sim env nudges list ENV_ID --state pending
futureagi sim env nudges answer ENV_ID NUDGE_ID rebuild --yes --wait
```

| Command | What it does |
|---|---|
| `fi sim env nudges list ENV_ID` | The newest 100 offers, with target, state, the agent version that raised it, the changed files and the changed variable names (never values). Its `ID` column is the `NUDGE_ID` the other commands take. `--state` filters: `pending`, `answered_no`, `queued`, `running`, `applied`, `no_change`, `replaced`, `failed` |
| `fi sim env nudges answer ENV_ID NUDGE_ID rebuild` | Queue a rebuild with the change. It starts builder work, so it asks for confirmation. `--wait`: exit 0 on `applied` or `no_change`, 8 on `failed` |
| `fi sim env nudges answer ENV_ID NUDGE_ID skip` | Record that nothing should be rebuilt |
| `fi sim env nudges stop ENV_ID NUDGE_ID` | Stop a queued or running rebuild. The offer ends `failed` and can be answered again later. Asks for confirmation |

## Evaluations

The evaluations attached to an environment grade the calls of its later runs, alongside each scenario's own checks. [Add evaluations](/docs/environments/guides/add-evaluations) explains what they measure.

```bash
futureagi sim env evaluations available ENV_ID
futureagi sim env evaluations add ENV_ID conversation_resolution
futureagi sim env evaluations list ENV_ID
```

| Command | What it does |
|---|---|
| `fi sim env evaluations available ENV_ID` | Evaluations the environment can still add, with credits per graded call (the `CREDITS_PER_RUN` column) |
| `fi sim env evaluations list ENV_ID` | Attached evaluations, with the IDs `update`, `remove` and `run` take |
| `fi sim env evaluations add ENV_ID NAME` | Attach one by its exact name; at most eight per environment. `--run RUN_ID` also grades that finished run's ungraded calls |
| `fi sim env evaluations update ENV_ID EVAL_CONFIG_ID --input-json JSON` | Change `name`, `config`, `mapping`, `model`, `filters`, `error_localizer` or `kb_id` |
| `fi sim env evaluations remove ENV_ID EVAL_CONFIG_ID` | Stop grading later runs with it. Past verdicts stay. Asks for confirmation |
| `fi sim env evaluations tool-call ENV_ID --enable` | Turn the tool-call judge on (or `--disable` it) for later calls |
| `fi sim env evaluations run ENV_ID --run RUN_ID --evaluation EVAL` | Grade a completed run's calls again without rerunning them. `--evaluation` takes an attached evaluation's ID or name and is repeatable; each evaluation's earlier scores are replaced |

`RUN_ID` is the Run ID that `fi sim run` prints (`job_id`); see [Runs](/docs/cli/runs).

Grading spends judge credits, so `add --run` and `run` ask for confirmation, as `remove` does. `--input-json` takes inline JSON, `@FILE` or `-` for stdin.

## Suites

A suite is a saved version of an environment's scenarios. `fi sim run --suite` takes a suite version ID from this list.

```bash
futureagi sim suites list --env ENV_ID
futureagi sim suites show --env ENV_ID SUITE_VERSION_ID
```

| Command | What it does |
|---|---|
| `fi sim suites list --env ENV_ID` | Suite versions, with scenario count and the default marked. Drafts and discarded versions come first, then saved versions by number, newest first |
| `fi sim suites show --env ENV_ID SUITE_VERSION_ID` | The scenarios in one saved suite version |
| `fi sim suites diff --env ENV_ID` | The unsaved suite draft and what it changed, or `--version` a saved version |
| `fi sim suites save --env ENV_ID` | Save the suite draft as the next suite version, which becomes the default |
| `fi sim suites discard --env ENV_ID` | Discard the suite draft. Asks for confirmation |
| `fi sim suites set-default --env ENV_ID SUITE_VERSION_ID` | Make a saved suite version the default |

A suite draft that came from a chat edit which also changed the environment cannot be saved alone (exit 1, `draft_not_runnable`): save both with `fi sim env save ENV_ID`.

## Scenarios

```bash
futureagi sim scenarios list --env ENV_ID --search refund
futureagi sim scenarios show --env ENV_ID book-ride
```

| Command | What it does |
|---|---|
| `fi sim scenarios list --env ENV_ID` | One page of scenarios, ordered by number unless `--ordering` (`name` or `use_case`) says otherwise; `--page` and `--limit` (1-100) page through. `--search`, `--filter FIELD=VALUE` (repeatable, such as `persona.accent=Indian`), and `--group-by` (`goal`, `sub_goal`, `accent`, `age`, `attack` or `task`). When a draft is open, it lists the draft |
| `fi sim scenarios show --env ENV_ID SCENARIO_KEY` | One scenario's use case, situation, expected behavior, persona, coverage and sub-goals |
| `fi sim scenarios amend --env ENV_ID --input-json JSON` | Drop or edit scenarios, or change a scenario's persona. Changes go into the suite draft. Also `fi sim scenarios edit` |
| `fi sim scenarios generate --env ENV_ID --count N` | Ask the builder for 1-50 more scenarios, steered by `--guidance`. They land in the suite draft. Spends builder credits, so it asks for confirmation |

An amend is a list of changes, each with an `op` and the scenario it names (a name, key, number, range such as `2-4`, or comma-separated list such as `1,3`):

```bash
futureagi sim scenarios amend --env ENV_ID --input-json '{"changes":[{"op":"set_field","scenario":"1","field":"tests","value":"Confirms the pickup time before booking."}]}'
```

The ops are `drop`, `set_field` and `set_persona`. `set_field` can change `tests`, `keywords`, `max_turns` (chat only) or `background_noise` (voice only). An amend that drops scenarios asks for confirmation. `--no-rework` refuses every change the builder would have to recheck before the suite can run, which spends builder credits, so only `tests` can change. Each change gets a receipt: applied, queued or refused, with the reason.

## Personas

Personas are workspace-wide and have no versions. To track changes, pull them as YAML files, keep the files in your repo, edit them and push them back.

```bash
futureagi sim personas list --type workspace
futureagi sim personas pull --output-dir personas
futureagi sim personas push personas/*.yaml --dry-run
```

| Command | What it does |
|---|---|
| `fi sim personas list` | System and workspace personas. `--type system` or `workspace`, `--simulation-type voice` or `text`, `--search` |
| `fi sim personas show PERSONA_ID` | One persona, by the `ID` column of `fi sim personas list` |
| `fi sim personas pull [PERSONA_ID...]` | Write workspace personas (or the IDs named) as YAML files to `--output-dir` (default `personas`). A local file that differs is a conflict: it asks on a terminal, `--force` overwrites |
| `fi sim personas push FILE...` | Create or replace personas from JSON or YAML files, matched by name. `--if-exists error` (default), `skip` or `replace`. `--dry-run` writes nothing |
| `fi sim personas duplicate PERSONA_ID --name NAME` | Copy a system or workspace persona into the workspace |
| `fi sim personas delete PERSONA_ID` | Delete a workspace persona. It cannot be restored. Asks for confirmation |

A persona file holds `schema_version: futureagi.persona.v1`, `name` and `description`, plus any of the persona fields the platform has, such as `personality`, `communication_style`, `accent`, `language` or `simulation_type`. A field the file leaves out takes the platform's default.
