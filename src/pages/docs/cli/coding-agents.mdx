Run `fagi` from a coding agent or script with JSON output, no prompts, and exit codes it can branch on.

<Prerequisites>
- The agent signed in with `FI_API_KEY` and `FI_SECRET_KEY` (see [Sign in with environment variables](/docs/cli/install-and-auth#sign-in-with-environment-variables))
</Prerequisites>

## Machine mode

Put every command in machine mode at once:

```bash
export FI_OUTPUT=json FI_NO_INPUT=1
```

Stdout then carries one JSON document per command, and a command that would prompt fails instead. Stderr carries the JSON error, and can also carry target, pagination and warning records, so read it line by line (see [What goes to stderr](/docs/cli/configuration-and-output#what-goes-to-stderr)). Check the exit code rather than parsing text:

```bash
status=0
fagi trace check TRACE_ID --project-id PROJECT_ID --max-error-spans 0 > report.json || status=$?
[ "$status" -eq 5 ] && echo "gate failed"
```

## Find commands

`fagi schema` describes every command as JSON, offline and without credentials. Search by words, then read one command's entry, and check its `access` and `open_world` before you run it, to avoid charged or destructive commands while exploring ([Find commands](/docs/cli/configuration-and-output#find-commands) explains the fields):

```bash
fagi schema --search 'push dataset'
fagi schema --command 'datasets push'
```

## Preview and confirm

Preview with `--dry-run` where a command offers it, and pass `--yes` only deliberately, once you have read the preview. [Global flags](/docs/cli/configuration-and-output#global-flags) lists which commands ask for confirmation. `fagi epoch run` never asks, so always preview it (see [Start an Epoch](/docs/cli/epoch#start-an-epoch)).

## Handle errors

Branch on the exit code first, then on `details.code` in the JSON error. [Exit codes](/docs/cli/configuration-and-output#exit-codes) defines each code; this is what an agent does next:

| Exit | What to do |
|---|---|
| 0 | Done |
| 1 | Read the error; for HTTP 409, read the resource again before you change it |
| 2 | Fix the input or flags; `details.code` and `details.hint` say what was wrong |
| 3 | Check the key pair, its access and the plan |
| 4 | Check the ID or name |
| 5 | A gate failed: read the report on stdout |
| 6 | Network or server error, or a `fagi sim` wait ran out. Retry only when `details.retryable` is `true` |
| 8 | `fagi sim` work ended without a usable result: read it before you rerun anything |

The CLI never retries for you. Before you repeat a write that exited 6 or carries `write_state: "unknown"`, check whether it landed, or rerun with the same `--idempotency-key` where the command takes one.

## Run an environment and fix failures

Follow the [Simulate quickstart](/docs/cli/simulate-quickstart). In machine mode, save the `--json` output of `fagi sim env create --wait` or `fagi sim env status --wait` to a file; after exit 8, test it with `jq -e '.question'` to tell a question from the builder (answer it, see [Follow the build](/docs/cli/environments#follow-the-build-and-answer-the-builder)) from a failed or canceled build (read the error).
