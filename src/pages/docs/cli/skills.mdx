Pin the coding-agent skills a repository uses, install them into each host's skills folder, and check them in CI. `fagi skills` ships in the next release of the CLI (see [Command families](/docs/cli#command-families)) and is in preview: its commands and file formats may change, and installed files do not prove that a host loads a skill.

<Prerequisites>
- For `sync` and `update`, signed in (see [Sign in](/docs/cli/install-and-auth#sign-in)) or a read-only key from the skill's **Install** tab (see [Credentials](#credentials)); `init`, `add` and `verify` need no sign-in
- Skills published in your workspace
- A git repository to install skills into
- A supported coding host: Claude Code, Codex, Cursor, Gemini CLI or GitHub Copilot
</Prerequisites>

Two files hold the setup: `.futureagi/skills.toml` lists what you ask for, and `.futureagi-skills.lock.json` records what was installed, with file hashes. Nothing is committed for you: the result is a diff you review in a pull request.

## Choose the hosts

```bash
fagi skills init --host claude --no-input
fagi skills init --host claude --host codex
fagi skills init --host claude,cursor --origin https://futureagi.example.com
fagi skills init
```

`init` creates `.futureagi/skills.toml`. Run interactively without `--host`, it asks which hosts your team uses. Without a terminal, or with `--no-input`, pass `--host`; otherwise `init` exits 2.

| Host | Folder it reads |
|---|---|
| `claude` (Claude Code) | `.claude/skills/<name>/` |
| `codex` (Codex) | `.agents/skills/<name>/` |
| `cursor` (Cursor) | `.cursor/skills/<name>/` |
| `gemini` (Gemini CLI) | `.gemini/skills/<name>/` |
| `copilot` (GitHub Copilot) | `.github/skills/<name>/` |

| Flag | What it does |
|---|---|
| `--host HOST` | A coding host: `claude`, `codex`, `cursor`, `gemini` or `copilot`; repeat it or separate values with commas |
| `--origin URL` | Your platform URL, for [self-hosted installs](/docs/cli/install-and-auth#self-hosted) |
| `--workspace-id UUID` | Workspace UUID to record in the manifest (to choose the workspace a command uses, use the global `--workspace` flag or `FI_WORKSPACE_ID`) |
| `--force` | Replace the hosts, origin and workspace of an existing manifest; its skills are kept |
| `--dir DIR` | Project folder (default `.`) |

An existing manifest is kept unless you pass `--force`. The manifest never holds credentials.

## Add skills

```bash
fagi skills add pr-review
fagi skills add pr-review --label production
fagi skills add release-notes --version 7
```

`add NAME` records a skill in the manifest and installs nothing; run `sync` to install it. A skill name uses lowercase letters, digits and single hyphens, up to 64 characters.

| Flag | What it does |
|---|---|
| `--label LABEL` | Follow a label; `sync` installs the version it names now and only `update` moves it later |
| `--version N` | Pin an exact version that never moves; N is a positive integer |
| `--dir DIR` | Project folder (default `.`) |

Use one of `--label` or `--version`. With neither, the skill follows the `production` label. Adding a skill that is already listed replaces its label or version. The `latest` label is refused because it is not a reviewed release.

## Install with sync

```bash
fagi skills sync --dry-run
fagi skills sync
```

`sync` installs every skill in the manifest into each chosen host's folder and writes `.futureagi-skills.lock.json`. The lock records, per skill, the version, its digest, the label or version you asked for, and every file's path, SHA-256 and size. After applying, `sync` prints the exact `git add` command for your hosts; run it and open a pull request.

It prints one plan for all skills and hosts, then asks you to confirm that host sessions and other writers in the project are stopped. Without a terminal or with `--no-input`, pass `--yes --quiescent` (both are required) or use `--dry-run`; otherwise the command exits 2.

```bash
fagi skills sync --dry-run --json
fagi skills sync --frozen --yes --quiescent
```

| Flag | What it does |
|---|---|
| `--dry-run` | Print the plan and change nothing; exits 2 if local files block the plan |
| `--frozen` | Install exactly the locked versions and fail if the manifest and lock disagree; use it on fresh clones and in CI. Needs a committed lock; cannot be combined with `--force` |
| `--yes` | Apply without asking; requires `--quiescent` |
| `--quiescent` | Confirm that no host session or other writer is using these folders |
| `--force` | Overwrite or delete managed files you edited locally |
| `--dir DIR` | Project folder (default `.`) |

Skills already in the lock stay on their locked version; only `update` moves a label. If you edited an installed file, or a skill folder has files `sync` did not install, `sync` lists them and stops (exit 2); `--force` overwrites your edits, and extra files must be moved out by hand. Skills with invalid or non-text files, non-portable file paths, an empty `SKILL.md` or one without frontmatter, or (for Claude Code) ``!`command` `` shell substitutions are refused (exit 1) before anything is written.

If `.futureagi-skills.lock.json` was created by the ZIP install command copied from the platform, `sync` will not take it over: move that lock and the skill folders it installed aside, then run `sync`.

### Credentials

`init`, `add` and `verify` need no credentials. `sync` and `update` read published versions with one of these:

- **Read-only key (preferred):** set `FI_CONTEXT_CREDENTIAL`, `FI_CONTEXT_ORIGIN` (or pass `--base-url`) and `FI_CONTEXT_WORKSPACE_ID` (or pass `--workspace`), copied from the skill's **Install** tab in the platform; a missing origin or workspace exits 2. `FI_CONTEXT_ORGANIZATION_ID` from the same tab is optional. The key is only sent to that origin, and grants only the skills and labels it was issued for
- **API key pair:** your profile from `fagi auth login`, or `FI_API_KEY` and `FI_SECRET_KEY`

`sync` and `update` stop with exit 2 if the platform URL or workspace you are using differs from the one recorded in the manifest or lock. Keys are never accepted as arguments and never written to the manifest or lock. See [Install and auth](/docs/cli/install-and-auth) for profiles.

## Move label-following skills

```bash
fagi skills update --check
fagi skills update pr-review
fagi skills update --yes --quiescent
```

`update` moves each label-following skill to the version its label names now. Version pins never move. Naming skills limits the update to them. It prints the version moves, then the file changes, and asks for the same confirmation as `sync`; without a terminal, pass `--yes --quiescent` or use `--check` or `--dry-run`. While an interrupted sync is unfinished, `update NAME` exits 2; run `sync` first.

`update` takes `--dry-run`, `--yes`, `--quiescent`, `--force` and `--dir` with the same meaning as on `sync`, plus `--check`, which prints the label moves, writes nothing, and exits 5 when any label moved. With no lock yet, `update` exits 2; run `sync` first. When the manifest and lock disagree, for example after you add a skill or change hosts, `update` also stops and asks you to run `sync` first.

## Verify the installed files

```bash
fagi skills verify
fagi skills verify --json
```

`verify` checks that every locked file is installed in each host folder with exactly its locked bytes, that skill folders hold no extra files, and that the manifest asks for exactly what is locked. It reads only the project, needs no credentials and makes no network calls.

```text
OK: 2 skill(s), 6 installed file(s) match .futureagi-skills.lock.json.
```

```json
{"ok": true, "skills": 2, "files": 6, "drift": []}
```

On drift, each finding lists `drift`, `skill`, `path` and `detail`. `verify` exits 0 when everything matches and 5 on any drift, including a missing, invalid or foreign lock or manifest; a symlinked skill folder exits 2 and a file it cannot read exits 1.

## Exit codes

| Code | Meaning in `fagi skills` |
|---|---|
| 1 | A checksum or digest mismatch, refused skill content, or a local read or write failure |
| 2 | Except for `verify`: invalid manifest or lock; missing `--yes --quiescent`; local files block the plan; manifest and lock disagree with `--frozen` or `update`; or the platform URL or workspace differs from the one recorded |
| 3 | Missing or rejected credentials, or the key does not grant this skill or label |
| 4 | Skill, label or version not found; also check the workspace and whether the key grants the skill |
| 5 | `verify` found drift (including a missing or invalid lock), or `update --check` found a newer version |

The other codes follow the [shared exit codes](/docs/cli/configuration-and-output#exit-codes).

Every `skills` command takes the [global flags](/docs/cli/configuration-and-output#global-flags), including `--json` and `--no-input`. `fagi skills` installs only into the project folders listed above; it does not manage personal folders such as `~/.claude/skills` or `AGENTS.md` files.
