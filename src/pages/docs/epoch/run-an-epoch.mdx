Use [Epoch](/docs/epoch) when a finished run shows a failure you want to fix without breaking scenarios that already pass. You choose the cases, permitted changes and limits; Epoch searches for a candidate to review, not a change to deploy automatically.

<Prerequisites title="Before you start">
- An [environment](/docs/environments/guides/build-an-environment) with an agent connected as a **Source repository** or **Code upload**. Epoch can't edit a hosted platform agent whose prompt and tools run elsewhere.
- A finished run with failing calls and a [failure diagnosis](/docs/environments/guides/debug-failures) that found at least one problem. If you haven't diagnosed the run yet, start there below.
- Access to Epoch. Every Cloud plan includes it. A self-hosted install needs an [Enterprise license key](/docs/self-hosting/configuration/reference#enterprise-edition) that lists Epoch.
</Prerequisites>

## Open the launch form

1. Open the environment's **Runs** tab.
2. Select a finished run with failing calls.
3. Select **Debug failures** in the run's header.

   When the diagnosis finishes and finds a problem, you should see **Run Epoch** at the bottom of the drawer.

4. Select **Run Epoch**.

   The launch form opens with one sentence that sums up what you're asking for: how many failing cases to fix, how many protected cases it must not break, what it may change, and its budget and time limit. It changes as you edit the form, so read it again before you start.

<img src="/images/docs/environments/guides/run-epoch/debug-failures-run-epoch.png" alt="The Debug failures drawer on Run 4 of the Northwind Pharmacy refill line reading 14 failing of 30 measured, with goal cards for the refill status, patient identification and pharmacist hand-off goals, and Run Epoch at the bottom of the drawer" style={{ borderRadius: '5px' }} />
*Run Epoch starts from the run whose diagnosis you just read*

## Pick the cases to fix and protect

**Scenarios** shows how the epoch will use the run's scenarios, such as `14 failing: 10 to fix, 4 held back to prove it · 16 protected`. Opened from **Debug failures**, the form starts with every failing scenario as a case to fix and every passing scenario as a case to protect. Opened from **Run Epoch** in the run's header, it starts with the failing scenarios that came from [imported evidence](/docs/environments/guides/import-evidence#run-epoch-on-the-imported-failures).

1. Select **Choose cases**.
2. In **Cases to fix**, untick the failing scenarios the epoch should leave alone.
3. In **Cases to protect**, check the passing scenarios. The epoch must not break any case you protect.

   The line under **Scenarios** should now show your counts. A case can't be both fixed and protected. **Back to suggested** resets a list to the form's suggestion: every failing case to fix, or every passing case to protect.

<img src="/images/docs/environments/guides/run-epoch/choose-cases.png" alt="The Run Epoch on Refill line agent form with Choose cases open, showing 14 failing: 10 to fix, 4 held back to prove it and 16 protected, a Cases to fix list of failing scenarios such as authenticate-caller-dob-correction, and a Cases to protect list of passing scenarios such as authenticate-caller-spells-surname" style={{ borderRadius: '5px' }} />
*Opened from Debug failures, every failing case is ticked to fix and every passing case to protect until you change them*

From 12 failing cases up, the epoch holds back one in three of them. Under the **Scenarios** line, the form names them, as `Held back to prove it: <scenario names>`. The epoch never sees them while it searches, and runs them at the end to prove the fix. The rules differ for smaller sets and locked runs.

### When the run has fewer than 12 failing scenarios

An epoch needs 12 failing cases. Pick fewer, and the form says so under **Scenarios**: the epoch first writes three variations of each case, then fixes the ones your current agent also fails. You need at least three failing cases for that.

With fewer than six, the form adds that the epoch can end with **Limited validation** at best, because too few cases can be held back to prove the fix. For a GitHub agent, its pull request then opens as a draft.

The form also says when the held-back cases are chosen. With fewer than 12 failing cases, they're chosen after the variations are written. When you change the cases to fix with **Choose cases**, they're chosen from your cases when the epoch starts.

The variations are written into your environment's scenarios, so the environment can't have unsaved scenario or setup changes. If it has, **Run Epoch** stays disabled and **Review unsaved changes** takes you to the **Scenarios** tab, where you save or discard them.

### When the run's versions are locked

A run of [locked versions](/docs/environments/guides/lock-versions) already has a test split, so the epoch holds back that split instead of picking cases itself:

- The failing cases in the test split are held back, however few. The epoch learns only from the failing cases in the train split. Under **Scenarios**, the form says `Held back: lock 2026.11.1's test split. It learns only from the train split.`
- The `Held back to prove it:` line names only the failing cases in the test split
- **Choose cases** marks each case in the test split as `Test split`
- A case in the test split can't be protected, because the epoch would learn from it. The suggested cases to protect are the passing cases in the train split
- If every failing case you pick is in the test split, **Run Epoch** stays disabled, and the form says to pick failing cases from the train split
- When the epoch writes variations first, the variations of a held-back case are held back with it

The epoch reads the lock once, when it starts. If an admin unlocks the versions while the epoch runs, the same cases stay held back. A run whose versions aren't locked holds back cases as described above.

## Set what it may change

The next rows decide what a candidate may change, and what it's held to.

1. Under **May change**, tick the parts of your agent the epoch may edit: **Instructions**, **Tools**, **Settings** or **Code**.

   Only **Instructions** is ticked at first. A part it can't change for this agent is greyed out, with the reason when you hover over it.

2. Under **Locked files**, type each file or glob it must never edit, such as `prompts/*.md`, and press Enter after each one.
3. Under **Models**, add any other models a candidate may call.

   The list starts with every model your agent called in this run, and every one of those must stay on the list. Add others to let the epoch switch to them.

4. Under **Reply time**, choose how much slower than now a candidate may reply, from **No increase** up to **Up to 100% slower than now**.
5. Under **Agent's cost**, choose how much more than now a candidate may spend on each conversation, from **No increase** up to **Up to 100% more than now**.
6. To cap the spend for each conversation too, type a number after **and at most $**.

<img src="/images/docs/environments/guides/run-epoch/launch-limits.png" alt="The lower half of the Run Epoch form with Instructions ticked under May change, an empty Locked files field, gpt-4o-mini under Models, Reply time set to Up to 25% slower than now, Agent's cost set to Up to 25% more than now, Budget set to 1,500 credits and 3 h, and Stops at reading 1,500 credits or 3 h, whichever comes first" style={{ borderRadius: '5px' }} />
*A candidate that breaks any of these limits is rejected, however well it scores*

The model and cost limits can only be checked on model calls Epoch can measure. Epoch measures calls your agent makes through the OpenAI or Anthropic Python SDK on its own; for anything else, add [traceAI](/docs/observe/concepts/traceai) tracing to your agent. When it can't measure them, the **Models** row says so in place of the list, and those checks show `Unknown` on the epoch's page instead of passing or failing.

## Check how a winner would ship

Before you launch, the form and the Run Epoch drawer on an issue say how the winner ships:

- For a GitHub agent: **A pull request on the agent's repository**
- For an uploaded agent: **A new version of the agent, made the default when you choose**

If a pull request can't open, because the agent version isn't connected through the Future AGI GitHub App, the form says so and tells you the winner comes as a patch to download. Click **Connect GitHub** to fix it. To get pull requests, connect GitHub, update the agent from its repository, and run Epoch on the new version. [Ship the winner](/docs/epoch/review-an-epoch#ship-the-winner) covers shipping.

## Set the budget and start

1. Under **Budget**, set the [credits](/docs/billing) the epoch may spend.
2. Set how long it may run.

   **Stops at** reads both limits back in one line. The epoch stops at whichever it reaches first.

3. Read the launch summary again.
4. Select **Run Epoch**.

   The epoch's page should open, and the environment's **Epochs** tab should now list it.

## Follow the epoch

The header shows the environment's name and the epoch, such as **Epoch 4**, with **Running** and the step it's on. While the epoch waits to start, the first step reads **Queued**. The steps below it fill in as the epoch works:

<div class="sdk-ref-table">

| Step | What happens |
|---|---|
| **Writing variations** | Only when you picked fewer than 12 failing cases: the epoch writes variations of them and keeps the ones your agent fails |
| **Reproducing** | It runs your current agent on the cases, to confirm they fail and to see how much the results vary between repeats |
| **Diagnosing** | It works out what causes the failures. The causes show on the page as they're found |
| **Proposing** | It tries candidates on the cases to fix. The line counts them, such as `3 of up to 4 candidates · best so far 70% on 10 target scenarios` |
| **Checking** | It runs the best candidate on the held-back cases and the must-pass cases |

</div>

When the steps are done, the best candidate comes back to you as **Ready for review**. Nothing changes until you ship it. An epoch can also end without a winner.

**Held to**, under the steps, lists the limits you set and what the epoch has spent so far. Below it, the chart and the **Candidates** table add a row for each candidate as it's tried.

<img src="/images/docs/environments/guides/run-epoch/epoch-running.png" alt="Epoch 4 running at the Searching step, with Reproduce done from Run 4, Search at 3 of up to 4 candidates with a best so far of 70% on 10 target scenarios, Verify and Ready for review still to come, the Held to row with 780 of 1,500 credits spent, and a Candidates table with Candidates 1 and 2 rejected and Candidate 3 running" style={{ borderRadius: '5px' }} />
*You can leave this page; the epoch keeps running and stays on the Epochs tab*

An epoch can run for hours. You don't have to wait on the page: it keeps running, and you come back to it from the **Epochs** tab. To end it early, click **Stop**, then **Stop** again in the dialog that asks you to confirm. Stopping ends the search without picking a candidate, keeps your current agent, and spends nothing more.

## When Run Epoch isn't available

<div class="sdk-ref-table">

| What you see | Why | What to do |
|---|---|---|
| No **Run Epoch** at the bottom of **Debug failures**, and the diagnosis is still going | Run Epoch waits for the diagnosis | Wait for the diagnosis to finish |
| No **Run Epoch** at the bottom of **Debug failures**, and the **Imagine** tab is open | Run Epoch launches from the diagnosis | Switch to the **Diagnosis** tab |
| The diagnosis reads `Your agent held every goal on …` | Nothing in the run failed, so there's nothing for an epoch to fix | Run the environment again after a change, or import evidence of the failures you've seen |
| The diagnosis reads `Couldn't read this run` | The diagnosis failed | Click **Try again** |
| `This run is still going. Run an epoch once it finishes` | Some calls in the run haven't finished | Wait for the run to finish |
| `The environment's scenarios or setup changed since this run. …` | The epoch writes variations from the cases as they ran, and they've changed since | Run the environment again, then start the epoch from the new run |
| `Allow every model this run called: …` | A model your agent called is missing from **Models** | Add it back to the list |

</div>

Run Epoch also starts from an issue in the [Error Feed](/docs/error-feed), from a run's page and from the **Debug failures** launch form. Each says why it can't start and links to the fix.

### The environment can't run an Epoch yet

<div class="sdk-ref-table">

| What you see | Why | What to do |
|---|---|---|
| `This environment is still being built. Run Epoch once its build finishes` | The environment's build is running | Wait for the build, or click **Open the environment** to follow it |
| `This environment's build didn't finish. Open the environment to build it again, then Run Epoch` | The build stopped before it finished | Click **Open the environment**, build it again, then run Epoch |
| `This environment is updating. Run Epoch once the update finishes` | A rebuild or an added set of scenarios is running | Wait for the update to finish |
| `This environment's last update didn't finish. Open the environment to run it again, then Run Epoch` | The update stopped before it finished | Click **Open the environment**, run the update again, then run Epoch |
| **Build an environment** in the drawer | No environment can run an Epoch yet, and an Epoch runs on an uploaded or GitHub agent | Click **Build an environment** |
| The drawer asks you to pick an environment | Environments exist, but none is picked for the issue's project | Pick one. The list includes environments still being built, and once you pick one, the drawer says what to do next |
| **Review unsaved changes** | The environment has unsaved scenario or setup changes | Click it, then save or discard the changes |
| `This environment holds N scenarios from Error Feed issues, and it may hold M. Remove older ones from its scenarios, then Run Epoch`, with **Open scenarios** | The environment holds more scenarios from issues than it may | Remove older ones on the **Scenarios** tab, then run Epoch |
| **Open its epochs** | Another epoch is running in this environment. An environment runs one epoch at a time | Click it, then wait for that epoch to finish or stop it |
| **See usage** | Your organization has no credits left for Epoch | Click it, add credits, then start the epoch again |
| `Ask your Future AGI admin to turn on agent versions` | Agent versions are turned off for your organization | Ask your Future AGI admin to turn them on |
| `It was made before versions were kept: ask your Future AGI admin to save its versions` | The environment was made before versions were kept | Ask your Future AGI admin to save its versions |
| A message to pick an environment whose agent is uploaded or from GitHub | Epoch can't change this agent, because its prompt and tools run outside Future AGI | Pick an environment whose agent is uploaded or from GitHub |

</div>
