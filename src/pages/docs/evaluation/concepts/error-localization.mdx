## About

When an evaluation fails, error localization narrows down the cause by analyzing which input field led to the failure. Instead of knowing only that an eval failed, you learn which input, whether the prompt, context, or query, was responsible. This helps you debug faster and see whether the problem is in your data, your retrieval, or your instructions.

---

## How it works

Error localization runs when an evaluation produces a failed result. The process is:

1. **Evaluation fails**: the eval score falls below the configured threshold, triggering error localization.
2. **Analysis**: an error-localizing agent receives the input data, the eval criteria, the eval result, and the judge's explanation, then works out which input drove the failure.
3. **Result**: you get back an `error_analysis` block describing the problem and a `selected_input_key` naming the input field identified as the issue.
4. **Review**: in the dataset or trace view, the selected field is flagged so you can review it directly.

The analysis depends on the eval criteria and the judge's explanation, so vague rule prompts produce less precise results.

---

## When error localization runs

Error localization is selective. It only runs under specific conditions:

| Condition | What happens |
|---|---|
| Evaluation passes | Skipped; there is no error to locate |
| Evaluation fails | Runs to identify the problem |
| Code-type eval | Skipped; not applicable to code logic |
| Composite eval | Not supported yet |
| Non-scorable result | Skipped if the result cannot be converted to a numeric score |

---

## Where results appear

Error localization results appear wherever evaluations run:

- **Datasets**: the `selected_input_key` is shown alongside the eval result, so you can see which field was identified as problematic
- **Observe traces**: when you run an eval on a span, the result appears in the eval log attached to that span
- **SDK**: the `error_analysis` and `selected_input_key` fields are returned in the result object

---

## How to enable it

Error localization is opt-in on the eval template:

1. Open an eval template, built-in or custom.
2. Set `error_localizer_enabled` to true on the template.
3. Run an evaluation that uses the template.
4. If a result fails, error localization runs and its output is captured.

Each eval run inherits the template setting and can override it.
