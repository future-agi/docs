## What a connector is

A connector is an external tool you attach to an eval so the evaluator can use it while it judges. On its own, a judge reasons only over the text you hand it. With a connector, an [Agent Evaluator](/docs/evaluation/concepts/eval-types) can act mid-judgment: when the verdict needs a fact the response does not carry, it calls the connector, reads what comes back, and only then decides.

    R["Response to judge"] --> AE["Agent Evaluator"]

That loop is the difference: a plain judge scores what it can read, while a connected Agent Evaluator can go and check.

## What you can connect

- **Built-in tools**, like the **URL checker** that confirms a cited link actually resolves
- **Custom MCP connectors**: any tool you expose over the Model Context Protocol, so the evaluator calls your own service the same way it calls a built-in one

## When a connector helps

Connectors are used by **Agent Evaluators**, the eval type that can run multiple turns and use tools. Reach for one when the judgment needs a fact the response does not carry, like confirming a URL is real or checking a value against your own data. A single-pass LLM-as-Judge or a deterministic Code Eval does not use connectors.
