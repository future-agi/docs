A connector is an external tool you attach to an eval so the evaluator can use it while it judges. On its own, a judge reasons only over the text you hand it. With a connector, an [Agent Evaluator](/docs/evaluation/concepts/eval-types) can act mid-evaluation: verify a link, look a value up, or call a system of yours before it settles on a verdict.

Connectors live on the eval. You add one from the menu under the model, and **Manage connectors** shows what is attached.

<img src="/images/docs/evaluation/connectors/connectors-menu.png" alt="The eval's menu under the model showing Connectors, with a built-in URL checker and Manage connectors for adding a custom MCP connector" style={{ borderRadius: '5px' }} />
*Under the model on an eval, the menu holds Connectors: attach a built-in tool like the URL checker, or add your own from Manage connectors*

## What you can connect

- **Built-in tools**, like the **URL checker** that confirms a cited link actually resolves
- **Custom MCP connectors**: any tool you expose over the Model Context Protocol can be attached, so the evaluator calls your own service the same way it calls a built-in one

## When a connector helps

Connectors are used by **Agent Evaluators**, the eval type that can run multiple turns and use tools. Reach for one when the judgment needs a fact the response does not carry, like confirming a URL is real or checking a value against your own data. A single-pass LLM-as-Judge or a deterministic Code Eval does not use connectors.
