A **composite eval** rolls several child templates into a single score, so one check can stand for several at once. An **eval group** is a named set of templates you apply together, so a whole quality bar travels as one unit. Both let you treat "good" as more than one measurement without wiring the same pieces together by hand every time.

## Composite evals

Every template is either `single` or `composite`. A composite template holds an ordered list of **child** templates. When it runs, the parent scores each child on the same input, then combines the child scores into one parent score with an [aggregation function](#aggregation-functions).

Children share one output type, either pass/fail, score, or choices, so their scores are comparable before they are combined. A composite made of graded children produces a graded score; one made of pass/fail children produces a pass/fail-style score.

Reach for a composite when "good" is several checks at once, for example faithful *and* on-tone *and* complete. Instead of reading three separate results, you get one score that already reflects all three, and one threshold to gate on.

## Aggregation functions

The parent combines child scores with one of five functions. Every child score is normalized to a 0 to 1 range first, so they can be compared on the same scale.

| Function | What it returns |
|---|---|
| Weighted average | Each child score times its weight, divided by the total weight. This is the default |
| Average | The plain mean of the child scores |
| Minimum | The lowest child score, a strict gate where every child has to do well |
| Maximum | The highest child score |
| Pass rate | The fraction of children that individually meet their own pass threshold |

Pick the function to the shape of the check. Use minimum when any one failure should sink the whole score, pass rate when you care how many checks passed rather than by how much, and weighted average when some children matter more than others.

## Weights and pinned versions

Two settings on each child keep a composite stable as it grows.

- **Weight** sets how much a child counts in a weighted average, from 0.0 to 10.0, defaulting to 1.0. A child you care about more gets a higher weight, and a child at 0.0 drops out of the weighted score
- **Pinned version** locks a child to a specific [template version](/docs/evaluation/concepts/eval-templates), so the composite keeps scoring the same way even after that child template is edited later

Weights only change the weighted average function; the other four ignore them. Pinning matters most for a composite you rely on in CI, where a silent change to a child would quietly move the gate.

## Eval groups

An **eval group** is a named collection of templates you apply together in a single run. Where a composite folds its children into one combined score, a group runs its templates side by side and reports each result on its own.

Use a group when a whole suite belongs together, for example a safety bar, a tone bar, and a retrieval bar. You attach the group by its name instead of hand-picking the same templates every time, so the bar stays consistent across datasets, simulations, and traces.
