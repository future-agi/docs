Precision@K measures how much of what your retriever returns in the top K is actually relevant. Run it to quantify how much noise reaches the generator.

## What it does

Precision@K is a statistical metric. It compares the retrieved chunks against the ground-truth relevant chunks and scores the fraction of the top K results that are relevant.

### Input

| Required Input | Type | Description |
| --- | --- | --- |
| `hypothesis` | `string` | JSON-serialized list of retrieved chunks in ranked order |
| `reference` | `string` | JSON-serialized list of ground-truth relevant chunks |

### Output

| Field | Type | Description |
| --- | --- | --- |
| Result | `score` | A score between 0 and 1, where 1 means every chunk in the top K is relevant |
| Reason | `string` | Short summary string of the score, e.g. `Precision@3: 0.333` |

Use `k` to limit the number of ranked results to check. If you omit it, the evaluator checks the full retrieved list.

### Run it from code

In Python, use `Evaluator.evaluate()` so you can pass `eval_config` separately from the inputs. The TypeScript example calls the same hosted template over HTTP.

<Note>
Set `FI_API_KEY` and `FI_SECRET_KEY` for your [Future AGI account](/docs/evaluation/reference/sdk-api). For Python, run `python3.12 -m venv .venv`, `source .venv/bin/activate`, and `python -m pip install agent-learning-kit==0.3.7`. Save the example as `score.py` and run `python score.py`. For TypeScript, save the HTTP example as `score.mts` and run `node score.mts` with Node.js 22.18 or newer.
</Note>

<CodeGroup>

```python Python
import json
from fi.evals import Evaluator

retrieved = [
    "Unused boots can be returned.",
    "Tents come with stakes.",
    "Keep your purchase receipt.",
    "Returns are accepted within 30 days.",
    "Packs are measured in liters.",
]
relevant = [
    "Unused boots can be returned.",
    "Keep your purchase receipt.",
    "Returns are accepted within 30 days.",
]

batch = Evaluator().evaluate(
    "precision_at_k",
    inputs={"hypothesis": json.dumps(retrieved), "reference": json.dumps(relevant)},
    eval_config={"k": 3},
)
row = batch.eval_results[0]
if row is None or row.output is None:
    raise RuntimeError("No precision score returned")
print(f"{float(row.output):.3f}")  # 0.667
print(row.reason)
print(row.eval_id)
```

```typescript TypeScript (HTTP)
const response = await fetch(new URL("/sdk/api/v1/new-eval/", FI_BASE_URL), {
  method: "POST",
  headers: { "Content-Type": "application/json", "X-Api-Key": FI_API_KEY, "X-Secret-Key": FI_SECRET_KEY },
  body: JSON.stringify({
    eval_name: "precision_at_k",
    inputs: { hypothesis: JSON.stringify(retrieved), reference: JSON.stringify(relevant) },
    config: { params: { k: 3 } },
  }),
});
if (!response.ok) throw new Error(`Evaluation request failed: HTTP ${response.status}`);
const row = (await response.json()).result?.[0]?.evaluations?.[0];
if (row?.output == null || !row.eval_id) throw new Error("No precision score returned");
console.log(Number(row.output).toFixed(3)); // 0.667
console.log(row.reason);
console.log(row.eval_id);
```

Only the first three chunks count. Two of them match the reference list exactly, so the score is 2/3 (0.667 rounded). The fourth chunk is relevant but falls outside the cutoff.

### Batch evaluation

To score several queries in one request, pass parallel lists of JSON strings. Each pair at the same index describes one query. Save this example as `batch.py` and run `python batch.py`.

```python Python
import json
from fi.evals import Evaluator

# Each tuple holds retrieved chunk IDs in rank order and the relevant IDs for one query.
queries = [
    (["boot-fit", "tent-care", "pack-size"], ["boot-fit", "laces"]),
    (["returns", "refunds"], ["refunds", "returns"]),
    (["tent-care", "pack-size", "boot-fit", "shipping"], ["shipping"]),
]
results = Evaluator().evaluate(
    "precision_at_k",
    inputs={
        "hypothesis": [json.dumps(ranked) for ranked, relevant in queries],
        "reference": [json.dumps(relevant) for ranked, relevant in queries],
    },
    eval_config={"k": 3},
)
ids = []
for i, row in enumerate(results.eval_results, start=1):
    if row is None or row.output is None:
        raise RuntimeError(f"No precision score for query {i}")
    print(f"Query {i}: {float(row.output):.3f}")
    ids.append(row.eval_id)
print("Evaluation IDs:", ", ".join(ids))
```

The three scores are 0.333 (one match in three), 1.000 (both retrieved chunks match), and 0.000 (the match ranks fourth).

### How it works

Precision@K answers the question: of the top K chunks the retriever returned, how many are actually relevant?

Divide the number of matching entries among the first K retrieved chunks by the number of entries actually considered. If the retriever returns two chunks and K is three, divide by two, not three. An empty retrieval scores 0. Matching uses exact string equality, not semantic similarity.

## When to use

Run Precision@K wherever noisy retrieved context is the concern, not just missing coverage.

- RAG and retrieval pipelines, to check how much of the retrieved context is actually useful to the generator
- Cost and token-budget tuning, since irrelevant chunks add tokens without adding value
- Comparing retriever configurations to see which one returns cleaner results

## What to do when Precision@K fails

If precision is low, the retriever is returning too much irrelevant content:

- Reduce the number of chunks retrieved (lower K) to keep only the most confident matches
- Improve the embedding model to better distinguish relevant from irrelevant content
- Apply a similarity threshold to filter out low-confidence results before passing to the LLM
- Review your chunking strategy: chunks that are too large may contain a mix of relevant and irrelevant content
- Consider re-ranking retrieved results with a cross-encoder before passing them to the generator
