## About

Recall@K tells you what fraction of a query's relevant chunks your retriever found in its first K results. If Ridgeline Outfitters has three articles that answer a tent question and your retriever finds two, recall is 2/3, even if it also returns unrelated articles.

## How it works

`Recall@K = |top K retrieved ∩ ground truth| / |ground truth|`

The numerator counts distinct ground-truth chunks that appear in the first K results. The denominator counts all distinct ground-truth chunks, including those your retriever missed. The evaluator compares strings exactly: a repeated chunk takes up another rank but doesn't earn another match. If the ground truth is empty, the evaluator returns 0.0 rather than dividing by zero.

Set `eval_config={"k": N}` (`evalConfig` in TypeScript) to score the first N results, where N is a positive integer. If you omit `k` or set it higher than the number of results, the evaluator uses the whole list. Reordering the same chunks within the cutoff doesn't change recall.

### Input

| Required input | Type | Description |
| --- | --- | --- |
| `hypothesis` | `string` | JSON-serialized list of retrieved chunks in ranked order |
| `reference` | `string` | JSON-serialized list of ground-truth relevant chunks |

### Output

| Field | Meaning |
| --- | --- |
| `output` | A score from 0 to 1. A score of 1 means every ground-truth chunk appears in the top K. |
| `reason` | A summary with the cutoff and match count, for example `Recall@3: 0.500 (1/2 relevant items in top 3)`. |

## Run it from code

Use `Evaluator.evaluate()` to pass a cutoff to the hosted template. Each returned row includes an `output` score and a `reason`.

<Note>
Set `FI_API_KEY` and `FI_SECRET_KEY` for your Future AGI account. In a Python 3.12 virtual environment named `.venv`, run `source .venv/bin/activate` and `python -m pip install agent-learning-kit==0.3.7`. Save the Python example as `score.py` and run `python score.py`. Use Python to reproduce the scores below; the TypeScript example has not been verified.
</Note>

<CodeGroup titles={["Python", "TypeScript"]}>

```python Python
import json
from fi.evals import Evaluator

ranked = ["tent-warranty", "tent-care", "pack-fit", "tent-repairs", "returns"]
relevant = ["tent-warranty", "tent-care", "tent-repairs"]
batch = Evaluator().evaluate(
    "recall_at_k",
    inputs={"hypothesis": json.dumps(ranked), "reference": json.dumps(relevant)},
    eval_config={"k": 5},
)
row = batch.eval_results[0]
print(float(row.output))  # 1.0
print(row.reason)
print(row.eval_id)
```

</CodeGroup>

Ridgeline Outfitters has five retrieved articles and three relevant ones. Changing only `k` shows why the cutoff matters:

| K | Ground-truth articles found | Recall@K |
| --- | --- | --- |
| 3 | `tent-warranty`, `tent-care` | 2/3 ≈ 0.667 |
| 5 | `tent-warranty`, `tent-care`, `tent-repairs` | 3/3 = 1.0 |

### Batch evaluation

For multiple queries, pass one JSON-encoded list per query in each input column. Save this example as `batch_recall.py` and run `python batch_recall.py`.

```python Python
import json
from fi.evals import Evaluator

rankings = [
    ["returns", "repairs", "shipping"],
    ["pole-fit", "tent-specs"],
    ["sizes", "boot-care", "warranty", "boot-fit"],
]
relevant = [["returns", "exchanges"], ["pole-fit", "tent-specs"], ["boot-fit"]]
batch = Evaluator().evaluate(
    "recall_at_k",
    inputs={
        "hypothesis": [json.dumps(items) for items in rankings],
        "reference": [json.dumps(items) for items in relevant],
    },
    eval_config={"k": 3},
)

for i, row in enumerate(batch.eval_results, start=1):
    print(f"Query {i}: {float(row.output)}")
print(" ".join(row.eval_id for row in batch.eval_results))
```

The three scores are 0.5, 1.0 and 0.0. The last query's relevant item is ranked fourth, outside the cutoff.

## When to use

Run Recall@K wherever missing relevant context is the bigger risk than returning some noise.

- RAG and retrieval pipelines, to check whether the retriever is surfacing all the relevant chunks for a query
- Tuning retriever parameters like top-K or chunk size, where you need a coverage metric to track against
- Comparing embedding models or retrieval strategies on the same ground-truth set

## What to do when Recall@K fails

First check that your reference list is nonempty and uses the same chunk IDs or text as your ranked results. If you split a reference chunk into smaller pieces, none of those pieces matches the original string.

If the reference is correct, look for the missing chunks below the cutoff. In the single-query example, `tent-repairs` is fourth: raising K from 3 to 5 includes it. If you can only pass three chunks to your model, keep K at 3 and try to rank `tent-repairs` higher instead. If it never appears in the retrieved list, increasing the evaluator's K alone won't help.
