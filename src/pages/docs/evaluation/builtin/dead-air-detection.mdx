title: "Dead Air Detection"
description: "Detects excessive silence in conversation audio using RMS energy analysis against configurable thresholds."
---

Dead Air Detection checks whether a voice conversation has too much silence, either overall or in any single stretch. Run it on voice agent recordings where long pauses signal a stalled pipeline or an agent that's lost the thread.

## What it does

Dead Air Detection is a code-based check. It analyzes RMS energy across the audio to identify silent frames, then computes the total dead-air percentage and the longest single continuous silence gap. It passes only if both stay within their configured budgets: the total dead-air percentage against `dead_air_threshold` (default 20%) and the longest gap against `gap_threshold_ms` (default 3000ms). Frames below the `silence_threshold` energy level (default 0.01) count as silent.

### Input

| Required Input | Type | Description |
| --- | --- | --- |
| `input_audio` | `string` | An audio URL accessible to the service, or a base64 audio data URI. Encode local files before submitting them. |

### Output

| Field | Type | Description |
| --- | --- | --- |
| Result | `Passed` / `Failed` | Pass means both the total dead-air percentage and the longest single silence gap are within their configured thresholds; Fail means either budget was exceeded |
| Reason | `string` | A plain-language explanation reporting the measured dead-air percentage and max gap against their thresholds |

### Run it from code

Set `FI_API_KEY` and `FI_SECRET_KEY` to [your Future AGI credentials](/docs/evaluation/reference/sdk-api). Both examples print the verdict, the reason and the evaluation ID.

- **Python:** Create a virtual environment with `python3.12 -m venv .venv && source .venv/bin/activate`, then run `python -m pip install agent-learning-kit==0.3.7`. Save the example as `dead_air_detection.py` and run `python dead_air_detection.py`.
- **TypeScript:** This example calls the REST API directly from Node.js 22.18 or later. Save it as `dead_air_detection.mts` and run `node dead_air_detection.mts`.

For a reproducible signal, create a mono WAV with one second of tone, 300 milliseconds of silence and one more second of tone. Save this as `sample_audio.py` and run `python sample_audio.py` before either example. The silent interval is shorter than the default three-second gap limit, and occupies less than the 20% total silence budget, so the clip should pass. For your own recording, use its WAV file instead of `sample.wav`.

```python
import math
import struct
import wave

rate = 8000
tone = b"".join(
    struct.pack("<h", round(12000 * math.sin(2 * math.pi * 440 * i / rate)))
    for i in range(rate)
)
with wave.open("sample.wav", "wb") as recording:
    recording.setparams((1, 2, rate, 0, "NONE", "not compressed"))
    recording.writeframes(tone + bytes(2 * (rate * 3 // 10)) + tone)
```

```python Python
import base64
from pathlib import Path

from fi.evals import Evaluator

encoded = base64.b64encode(Path("sample.wav").read_bytes()).decode("ascii")
audio_uri = f"data:audio/wav;base64,{encoded}"

batch = Evaluator().evaluate(
    eval_templates="dead_air_detection",
    inputs={
        "input_audio": audio_uri,
    },
)
result = batch.eval_results[0]
if result.output is None:
    raise RuntimeError(result.reason or "No evaluation result returned")
print(result.output)
print(result.reason)
print(result.eval_id)
```

```typescript TypeScript
import { readFile } from "node:fs/promises";

const audioURI = "data:audio/wav;base64," + (await readFile("sample.wav")).toString("base64");
const { FI_API_KEY, FI_SECRET_KEY, FI_BASE_URL = "https://api.futureagi.com" } = process.env;
if (!FI_API_KEY || !FI_SECRET_KEY) throw new Error("Set both Future AGI credentials");

const response = await fetch(new URL("/sdk/api/v1/new-eval/", FI_BASE_URL), {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "X-Api-Key": FI_API_KEY,
    "X-Secret-Key": FI_SECRET_KEY,
  },
  body: JSON.stringify({
    eval_name: "dead_air_detection",
    inputs: {
      input_audio: audioURI,
    },
  }),
});
if (!response.ok) throw new Error(`Evaluation request failed: HTTP ${response.status}`);
const body = await response.json();
const result = body.result?.[0]?.evaluations?.[0];
if (result?.output == null) throw new Error("No evaluation result returned");
console.log(result.output);
console.log(result.reason);
console.log(result.eval_id);
```

## When to use

Run Dead Air Detection wherever a voice agent's audio needs to stay conversational rather than lapsing into long silences.

- Voice agent call recordings, to catch pauses caused by slow tool calls or model latency
- IVR and phone support flows, where extended silence makes callers hang up or repeat themselves
- Regression checks after changing TTS providers or pipeline latency, to confirm silence didn't get worse

## What to do when Dead Air Detection fails

Check the reason string for which budget was exceeded, total dead-air percentage or the longest single gap, since they point to different problems. A high total percentage usually means the conversation has many small pauses, often from consistent model or tool latency; a single long gap usually means one specific stall, like a slow API call or a dropped turn.

Look at where in the pipeline the delay is introduced: TTS generation time, tool execution, or model response latency are the usual culprits. If the failures are borderline and the audio is acceptable to a human listener, reconsider whether `dead_air_threshold` or `gap_threshold_ms` are set tighter than the product actually needs.
