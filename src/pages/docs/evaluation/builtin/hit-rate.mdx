Hit Rate answers the simplest retrieval question: did the retriever find at least one relevant chunk at all? Run it as a baseline sanity check before looking at finer-grained metrics.

## What it does

Hit Rate is a statistical metric. It compares the retrieved chunks against the ground-truth relevant chunks and returns whether any match was found.

### Input

| Required Input | Type | Description |
| --- | --- | --- |
| `hypothesis` | `string` | JSON-serialized list of retrieved chunks in ranked order |
| `reference` | `string` | JSON-serialized list of ground-truth relevant chunks |

### Output

| Field | Type | Description |
| --- | --- | --- |
| Result | `score` | 1.0 if at least one relevant chunk was retrieved, 0.0 otherwise |
| Reason | `string` | Short summary string of the score, e.g. `Hit rate: 1.0 (at least one relevant item was retrieved)` |

<Note>
Hit Rate doesn't take a `k` parameter. It checks the entire retrieved list for any match.
</Note>

### Run it from code

Python runs the evaluation and prints its score, reason, and execution ID. TypeScript submits the same evaluation asynchronously and prints its execution ID. To retrieve the result later, call `await evaluator.getEvalResult(run.id)` and check `result.eval_status` for `completed`.

<Note>
[Set `FI_API_KEY` and `FI_SECRET_KEY`](/docs/evaluation/reference/sdk-api). For Python, create and activate a virtual environment with `python3.12 -m venv .venv && source .venv/bin/activate`. Run `python -m pip install agent-learning-kit==0.3.7`, save the example as `score.py`, and run `python score.py`.

For TypeScript, use Node.js 22.18 or later, run `npm install @future-agi/agent-learning-kit@0.4.0`, save the example as `score.mts`, and run `node score.mts`.
</Note>

<CodeGroup>

```python Python
import json
from fi.evals import evaluate

result = evaluate(
    "hit_rate",
    hypothesis=json.dumps(["boot-sizing", "boot-returns", "pack-care"]),
    reference=json.dumps(["boot-returns", "return-labels"]),
    engine="turing",
)

if result.score is None:
    raise RuntimeError(result.error or result.reason or "No score returned")
print(result.score)
print(result.reason)
print(result.metadata["eval_id"])
```


The chunk ID `boot-returns` occurs in both lists, so the score is 1.0. Matching uses exact string equality; use stable chunk IDs when possible.

### Batch evaluation

For multiple queries, use `Evaluator().evaluate()` and read each item in `batch.eval_results`. Each pair of JSON strings represents one query. Save this example as `batch.py` and run `python batch.py` in the same environment.

```python Python
import json
from fi.evals import Evaluator

retrieved = [["boot-sizing", "boot-returns"], ["tent-care"], ["pack-care"]]
relevant = [["boot-returns"], ["tent-care", "tent-storage"], ["pack-sizing"]]
batch = Evaluator().evaluate(
    "hit_rate",
    inputs={
        "hypothesis": [json.dumps(chunks) for chunks in retrieved],
        "reference": [json.dumps(chunks) for chunks in relevant],
    },
)

for index, result in enumerate(batch.eval_results, start=1):
    if result.output is None:
        raise RuntimeError(result.reason or "No score returned")
    print(f"Query {index}: {result.output}")
print("Execution IDs:", *(result.eval_id for result in batch.eval_results))
```

The three scores are 1.0, 1.0, and 0.0.

### How it works

A query scores 1 when the retrieved and relevant lists share an item and 0 otherwise. The position of the matching item does not change the score. To measure hit rate at a cutoff, pass only the first `k` retrieved IDs in `hypothesis`. Average the per-query scores for an aggregate hit rate: in this batch, two of three queries have a hit.

## When to use

Run Hit Rate wherever you need a quick, coarse signal on whether retrieval is working at all.

- RAG and retrieval pipelines, as a first sanity check before digging into Recall@K, Precision@K, or NDCG@K
- Monitoring retrieval health over time, to spot changes in how often labeled relevant chunks appear
- Comparing indexing or chunking changes at a glance before running finer-grained metrics

## What to do when Hit Rate fails

If hit rate is low, the retriever is completely failing to find relevant content for some queries:

- Check if the failing queries use different vocabulary or phrasing than what appears in the indexed documents
- Verify that the relevant documents are actually indexed and not filtered out during preprocessing
- For domain-specific queries, consider fine-tuning the embedding model or adding synonyms to the index
- Ensure document chunking doesn't split relevant information into fragments too small to match
- Try hybrid retrieval (dense + sparse) to catch queries where one method fails
