Customer Agent Query Handling checks whether an agent correctly understands what the customer is asking and responds with a relevant, helpful answer. Run it to measure how well an agent handles the questions it's actually built for.

## What it does

Customer Agent Query Handling is an LLM-as-Judge eval. It reads the full conversation and scores how effectively the agent interprets and answers the customer's queries.

### Input

| Required Input | Type | Description |
| --- | --- | --- |
| `conversation` | `string` | The full conversation history between the customer and agent |

### Output

| Field | Type | Description |
| --- | --- | --- |
| Result | `never / occasionally / frequently / always` | How consistently the agent addresses each substantive request and follow-up; `always` is best |
| Reason | `string` | A plain-language explanation of the query handling assessment |

### Run it from code

Set `FI_API_KEY` and `FI_SECRET_KEY` to [your Future AGI credentials](/docs/evaluation/reference/sdk-api). Both examples print the label, the reason and the evaluation ID. The [evaluator model](/docs/evaluation/concepts/evaluator-models) is `turing_flash`.

- **Python:** Create a virtual environment with `python3.12 -m venv .venv && source .venv/bin/activate`, then run `python -m pip install agent-learning-kit==0.3.7`. Save the example as `query_handling.py` and run `python query_handling.py`.
- **TypeScript:** This example calls the REST API directly from Node.js 22.18 or later. Save it as `query_handling.mts` and run `node query_handling.mts`.

<CodeGroup>

```python Python
from fi.evals import Evaluator

batch = Evaluator().evaluate(
    eval_templates="customer_agent_query_handling",
    inputs={
        "conversation": "Customer: Can I return a backpack bought last week, and do I have to pay for shipping?\nAgent: Yes. Ridgeline accepts unused packs within 30 days. Mail returns cost $5; returning it to a store is free.",
    },
    model_name="turing_flash",
)
result = batch.eval_results[0]
if result.output is None:
    raise RuntimeError(result.reason or "No evaluation result returned")
print(result.output["choice"])
print(result.reason)
print(result.eval_id)
```

```typescript TypeScript
const { FI_API_KEY, FI_SECRET_KEY, FI_BASE_URL = "https://api.futureagi.com" } = process.env;
if (!FI_API_KEY || !FI_SECRET_KEY) throw new Error("Set both Future AGI credentials");

const response = await fetch(new URL("/sdk/api/v1/new-eval/", FI_BASE_URL), {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "X-Api-Key": FI_API_KEY,
    "X-Secret-Key": FI_SECRET_KEY,
  },
  body: JSON.stringify({
    eval_name: "customer_agent_query_handling",
    model: "turing_flash",
    inputs: {
      conversation: "Customer: Can I return a backpack bought last week, and do I have to pay for shipping?\nAgent: Yes. Ridgeline accepts unused packs within 30 days. Mail returns cost $5; returning it to a store is free.",
    },
  }),
});
if (!response.ok) throw new Error(`Evaluation request failed: HTTP ${response.status}`);
const body = await response.json();
const result = body.result?.[0]?.evaluations?.[0];
if (result?.output == null) throw new Error("No evaluation result returned");
console.log(result.output.choice);
console.log(result.reason);
console.log(result.eval_id);
```

## When to use

Run Customer Agent Query Handling to measure the core competence of a support agent: understanding and answering.

- Support bots fielding common product, billing, or policy questions
- Regression checks after a knowledge base or prompt update, to confirm answer quality didn't drop
- Comparing agent versions on how well they interpret customer intent

## What to do when Customer Agent Query Handling fails

Review cases where the agent misunderstood the user's intent, and improve intent detection and query classification around those patterns. Expand the agent's knowledge base with more relevant responses where gaps show up.

Add clarification prompts for ambiguous or complex queries instead of letting the agent guess.
