title: "Customer Agent: Clarification Seeking"
description: "Evaluates if the agent appropriately seeks clarification when needed rather than guessing on ambiguous queries."

Customer Agent Clarification Seeking checks whether an agent asks for more detail on ambiguous requests instead of guessing and answering incorrectly. Run it to confirm the agent knows when it doesn't have enough information.

## What it does

Customer Agent Clarification Seeking is an LLM-as-Judge eval. It reads the full conversation and rates how consistently the agent asks a useful follow-up when a request is ambiguous. If the request is already clear, the agent does not need to ask.

### Input

| Required Input | Type | Description |
| --- | --- | --- |
| `conversation` | `string` | The full conversation history between the customer and agent |

### Output

| Field | Type | Description |
| --- | --- | --- |
| `output.choice` | `never / occasionally / frequently / always` | Indicates how well the agent seeks clarification when needed |
| Reason | `string` | A plain-language explanation of the clarification seeking assessment |

### Run it from code

The result includes a rating label and its mapped score. Read the `choice` field to see the rating rather than treating the whole result as a number. Both examples use the hosted [`turing_flash` judge](/docs/evaluation/concepts/evaluator-models).

<Note>
Set [your Future AGI credentials](/docs/evaluation/reference/sdk-api) (`FI_API_KEY` and `FI_SECRET_KEY`). For Python, create and activate a virtual environment with `python3.12 -m venv .venv && source .venv/bin/activate`, then install the Agent Learning Kit with `python -m pip install agent-learning-kit==0.3.7`. Save the Python example as `customer_agent_clarification_seeking.py` and run `python customer_agent_clarification_seeking.py`.

The TypeScript example calls the same evaluation endpoint with Node.js 22.18 or later; no npm package is required. Save it as `customer_agent_clarification_seeking.mts` and run `node customer_agent_clarification_seeking.mts`.
</Note>

<CodeGroup>

```python Python
from fi.evals import Evaluator

batch = Evaluator().evaluate(
    eval_templates="customer_agent_clarification_seeking",
    inputs={
        "conversation": (
            "Customer: I ordered boots and a pack. Can I exchange one for a different size?\n"
            "Agent: Which item would you like to exchange, the boots or the pack?"
        ),
    },
    model_name="turing_flash",
)
result = batch.eval_results[0]
if result.output is None:
    raise RuntimeError(result.reason or "No rating returned")
print(f"Rating: {result.output['choice']}")
print(result.reason)
print(result.eval_id)
```

```typescript TypeScript
const inputs = {
  conversation: [
    "Customer: I ordered boots and a pack. Can I exchange one for a different size?",
    "Agent: Which item would you like to exchange, the boots or the pack?",
  ].join("\n"),
};
const base = process.env.FI_BASE_URL || "https://api.futureagi.com";
const response = await fetch(`${base}/sdk/api/v1/new-eval/`, {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "X-Api-Key": process.env.FI_API_KEY!,
    "X-Secret-Key": process.env.FI_SECRET_KEY!,
  },
  body: JSON.stringify({ eval_name: "customer_agent_clarification_seeking", inputs, model: "turing_flash" }),
});
if (!response.ok) throw new Error(`Evaluation request failed: ${response.status}`);
const { result } = await response.json();
const row = result[0].evaluations[0];
if (row.output == null) throw new Error("No result returned");
console.log(`Rating: ${row.output.choice}`);
console.log(row.reason);
console.log(row.eval_id);
```

## When to use

Run Customer Agent Clarification Seeking wherever a customer's request can be ambiguous enough to trip up the agent.

- Short or vague requests, like "I want to change it," where intent isn't specified
- Agents you suspect are guessing at intent instead of confirming it
- Balancing over-clarification against under-clarification on straightforward queries

## What to do when Customer Agent Clarification Seeking fails

Review cases where the agent guessed incorrectly instead of asking, and add intent confidence thresholds so the agent asks for clarification below a certain confidence level. Avoid over-clarifying for straightforward queries, which frustrates users just as much as guessing wrong.

Ensure clarification questions are specific and helpful rather than generic, so the follow-up actually narrows down what the user needs.
