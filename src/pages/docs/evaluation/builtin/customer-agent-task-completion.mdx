title: "Customer Agent: Task Completion"
description: "Checks whether the conversation shows that the agent fulfilled the customer's request or an explicitly accepted alternative."
---

Customer Agent Task Completion checks whether an agent actually finished what the customer asked for, not just responded to it. Run it to catch requests left pending, half-executed, or wrongly declined.

## What it does

Customer Agent Task Completion is an LLM-as-Judge eval. It compares the request and its stated conditions with what the conversation shows happened. A promise is not completion. A refusal can answer a policy question, but it does not fulfill an outstanding request to take action.

### Input

| Required Input | Type | Description |
| --- | --- | --- |
| `agent_prompt` | `string` | The agent's system prompt defining its task and behavior |
| `conversation` | `string` | The conversation to be evaluated |

### Output

| Field | Type | Description |
| --- | --- | --- |
| Result | `Passed` / `Failed` | Pass means the conversation shows the original objective or an explicitly accepted alternative was fulfilled. Fail means the objective or a material condition was not met, regardless of fault. |
| Reason | `string` | A plain-language explanation of the task completion assessment |

### Run it from code

Set `FI_API_KEY` and `FI_SECRET_KEY` to [your Future AGI credentials](/docs/evaluation/reference/sdk-api). Both examples print the verdict, the reason and the evaluation ID. The [evaluator model](/docs/evaluation/concepts/evaluator-models) is `turing_flash`.

- **Python:** Create a virtual environment with `python3.12 -m venv .venv && source .venv/bin/activate`, then run `python -m pip install agent-learning-kit==0.3.7`. Save the example as `task_completion.py` and run `python task_completion.py`.
- **TypeScript:** This example calls the REST API directly from Node.js 22.18 or later. Save it as `task_completion.mts` and run `node task_completion.mts`.

<CodeGroup>

```python Python
from fi.evals import Evaluator

batch = Evaluator().evaluate(
    eval_templates="customer_agent_task_completion",
    inputs={
        "agent_prompt": "You handle Ridgeline Outfitters returns. Start returns for unworn boots bought within 30 days when the customer asks.",
        "conversation": "Customer: Please start a return for the unworn boots I bought last week, order RG-48213.\nAgent: I've opened return R-208 for those boots and sent the shipping label to your order email.\nCustomer: I have the label. Thanks!",
    },
    model_name="turing_flash",
)
result = batch.eval_results[0]
if result.output is None:
    raise RuntimeError(result.reason or "No evaluation result returned")
print(result.output)
print(result.reason)
print(result.eval_id)
```

```typescript TypeScript
const { FI_API_KEY, FI_SECRET_KEY, FI_BASE_URL = "https://api.futureagi.com" } = process.env;
if (!FI_API_KEY || !FI_SECRET_KEY) throw new Error("Set both Future AGI credentials");

const response = await fetch(new URL("/sdk/api/v1/new-eval/", FI_BASE_URL), {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "X-Api-Key": FI_API_KEY,
    "X-Secret-Key": FI_SECRET_KEY,
  },
  body: JSON.stringify({
    eval_name: "customer_agent_task_completion",
    model: "turing_flash",
    inputs: {
      agent_prompt: "You handle Ridgeline Outfitters returns. Start returns for unworn boots bought within 30 days when the customer asks.",
      conversation: "Customer: Please start a return for the unworn boots I bought last week, order RG-48213.\nAgent: I've opened return R-208 for those boots and sent the shipping label to your order email.\nCustomer: I have the label. Thanks!",
    },
  }),
});
if (!response.ok) throw new Error(`Evaluation request failed: HTTP ${response.status}`);
const body = await response.json();
const result = body.result?.[0]?.evaluations?.[0];
if (result?.output == null) throw new Error("No evaluation result returned");
console.log(result.output);
console.log(result.reason);
console.log(result.eval_id);
```

## When to use

Run Customer Agent Task Completion wherever a conversation is supposed to end with the customer's request actually resolved, not just acknowledged.

- Support conversations involving returns, refunds, or account changes, to distinguish a confirmed outcome from a promise
- Requests that hit a policy boundary, to check the agent applied the policy correctly and still gave the customer a definitive answer
- Multi-step or back-end workflows, to check that the outcome described to the customer matches the stage of work they requested

## What to do when Customer Agent Task Completion fails

Check the reason for where the breakdown happened: the agent may have promised an action without executing it, left the request pending without a clear next step, abandoned the conversation mid-process, or declined a request it should have been able to fulfill. For promised-but-not-executed cases, review whether the agent actually has the tool or workflow access it claims to use.

Distinguish an unmet request from an agent mistake. If policy prevented a return, the request can be incomplete even when the refusal was correct. Check order or tool records separately if you need proof of execution outside the conversation.
