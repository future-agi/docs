title: "PII Detection"
description: "Detects personally identifiable information in text and flags it for redaction or compliance review."
---

PII Detection scans text for personally identifiable information such as names, addresses, or ID numbers. Run it wherever output could leak sensitive personal data.

## What it does

PII Detection is an LLM-as-Judge eval. It reads the text you pass as `input` and flags whether it contains personally identifiable information. It does not redact the text.

### Input

| Required Input | Type | Description |
| --- | --- | --- |
| `input` | `string` | The text content to be analysed for PII |

### Output

| Field | Type | Description |
| --- | --- | --- |
| Result | `Pass / Fail` | Fail means PII was detected in the content |
| Reason | `string` | A plain-language explanation of why the content was classified as containing or not containing PII |

### Run it from code

The Python example uses Agent Learning Kit; the TypeScript example calls the same hosted template over HTTP. Both use `turing_flash` as the [evaluator model](/docs/evaluation/concepts/evaluator-models). Each prints the result, the reason, and the evaluation ID.

<Note>
Set `FI_API_KEY` and `FI_SECRET_KEY` for your [Future AGI account](/docs/evaluation/reference/sdk-api). For Python, run `python3.12 -m venv .venv`, `source .venv/bin/activate`, and `python -m pip install agent-learning-kit==0.3.7`. Save the example as `score.py` and run `python score.py`. For TypeScript, save the HTTP example as `score.mts` and run `node score.mts` with Node.js 22.18 or newer.
</Note>

<CodeGroup>

```python Python
from fi.evals import evaluate

result = evaluate(
    "pii",
    model="turing_flash",
    input="Please send my return label to river.hiker@example.com.",
)
if result.score is None:
    raise RuntimeError(result.error or result.reason or "No score returned")

print(result.score)
print(result.reason)
print(result.metadata["eval_id"])
```

```typescript TypeScript (HTTP)
const { FI_BASE_URL = "https://api.futureagi.com", FI_API_KEY, FI_SECRET_KEY } = process.env;
if (!FI_API_KEY || !FI_SECRET_KEY) throw new Error("Set your Future AGI credentials");

const response = await fetch(new URL("/sdk/api/v1/new-eval/", FI_BASE_URL), {
  method: "POST",
  headers: { "Content-Type": "application/json", "X-Api-Key": FI_API_KEY, "X-Secret-Key": FI_SECRET_KEY },
  body: JSON.stringify({
    eval_name: "pii",
    model: "turing_flash",
    inputs: {
      input: "Please send my return label to river.hiker@example.com.",
    },
  }),
});
if (!response.ok) throw new Error(`Evaluation request failed: HTTP ${response.status}`);
const row = (await response.json()).result?.[0]?.evaluations?.[0];
if (row?.output == null || !row.eval_id) throw new Error("No evaluation result returned");
console.log(row.output);
console.log(row.reason);
console.log(row.eval_id);
```

</CodeGroup>

## When to use

Run PII Detection wherever generated text could carry personal data that shouldn't leave the system.

- Text, audio, image, and chat outputs before they reach a user or a log
- Support and chat transcripts, to catch names, addresses, or ID numbers slipping into responses
- Safety checks ahead of storing or forwarding model output to third parties

## What to do when PII is detected

When PII is detected, the first step is redaction: remove or mask the identified PII, for example by replacing sensitive information with placeholders or anonymising the data.

The explanation can repeat the identifier that triggered the verdict. The example uses a fictional email address; for real messages, avoid logging the raw text or explanation.
