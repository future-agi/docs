The Contains family checks text against a keyword, substring, or exact-match rule: whether it contains a term, contains any or all of a list, contains none of a list, starts or ends with a substring, or equals an expected string exactly. Run these wherever a response needs to satisfy a simple textual pattern.

## What it does

Each Contains eval is a deterministic, rule-based check. It reads the target text and a configured pattern, then returns a score and a reason. The examples below run locally: they do not use credentials or save an evaluation in Future AGI.

For Python, create and activate a virtual environment with `python3.12 -m venv .venv && source .venv/bin/activate`, then run `python -m pip install agent-learning-kit==0.3.7`. For TypeScript, use Node.js 22.18 or later and install the kit with `npm install @future-agi/agent-learning-kit@0.4.0`.

### 1. Contains

Checks whether the input text contains a specific keyword. Useful for ensuring that essential terms are present.

### Python inputs

| Input or setting | Type | Description |
| --- | --- | --- |
| `output` | `string` | The content column to search within |
| `config.keyword` | `string` | The text to search for in the output |
| `config.case_sensitive` | `bool` | Optional, whether the search matches case (defaults to `False`) |

### Output

| Field | Type | Description |
| --- | --- | --- |
| Result | `1.0 / 0.0` | Pass means `keyword` is present in the output; Fail means it's not |

This example passes. Save the Python example as `contains.py` and run `python contains.py`, or save the TypeScript example as `contains.mts` and run `node contains.mts`.

<CodeGroup>

```python Python
from fi.evals import evaluate

result = evaluate(
    "contains",
    output="Your Ridgeline return label is ready.",
    config={"keyword": "return label", "case_sensitive": True},
)
print(result.score)
print(result.reason)
```

```typescript TypeScript
import { contains } from "@future-agi/agent-learning-kit/local";

const result = contains("Your Ridgeline return label is ready.", {
  keyword: "return label",
  caseSensitive: true,
});
console.log(result.score);
console.log(result.reason);
```

</CodeGroup>

### 7. Equals

Compares whether the input text is exactly equal to an expected text. Useful for scenarios where precise matching is required.

### Python inputs

| Input or setting | Type | Description |
| --- | --- | --- |
| `output` | `string` | The content column to check |
| `expected_response` | `string` | The column containing the exact string to match against |
| `config.case_sensitive` | `bool` | Optional, whether the comparison matches case (defaults to `False`) |

### Output

| Field | Type | Description |
| --- | --- | --- |
| Result | `1.0 / 0.0` | Pass means the output equals `expected_response`; Fail means it differs |

This example fails: the extra word changes the whole response. Save the Python example as `equals.py` and run `python equals.py`, or save the TypeScript example as `equals.mts` and run `node equals.mts`.

<CodeGroup>

```python Python
from fi.evals import evaluate

result = evaluate(
    "equals",
    output="Ready for pickup tomorrow",
    expected_response="Ready for pickup",
    config={"case_sensitive": False},
)
print(result.score)
print(result.reason)
```

```typescript TypeScript
import { equals } from "@future-agi/agent-learning-kit/local";

const result = equals("Ready for pickup tomorrow", {
  expected: "Ready for pickup",
  caseSensitive: false,
  trim: false,
});
console.log(result.score);
console.log(result.reason);
```

</CodeGroup>

## When to use

Run the Contains family wherever a response needs to satisfy a simple, literal text rule rather than a judged quality check.

- Text outputs that must include required terms, such as a disclaimer or a specific product name
- Format checks, confirming a response starts or ends with an expected prefix or suffix
- Denylist enforcement, confirming a response contains none of a set of forbidden terms
- Exact-match validation, where the output must equal a known string precisely

## What to do when a Contains eval fails

- **Contains**: revise the text to include the missing keyword, or provide clearer instructions about required terms
- **Contains Any**: ensure at least one of the required keywords is included in the text
- **Contains All**: review the text to identify which keywords are missing and add them
- **Contains None**: identify which unwanted terms are present and remove them
- **Starts With**: revise the text to begin with the required substring
- **Ends With**: revise the text to conclude with the required substring
- **Equals**: review the text for discrepancies and adjust it to match the expected text precisely
