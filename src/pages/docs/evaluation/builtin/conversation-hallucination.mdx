---
title: "Conversation Hallucination"
description: "Checks whether an agent fabricated facts, user attributions, or self-contradictions across a conversation."
---

Conversation Hallucination checks an agent's claims against the dialogue and any grounding you supply. Run it to catch fabricated user attributions, self-contradictions, and invented facts in multi-turn agent conversations.

## What it does

Conversation Hallucination is an LLM-as-Judge eval. It reads the full conversation and, if provided, the context, then looks for false attributions, contradictions that the agent hasn't corrected, and claims that misrepresent the supplied context. Missing evidence alone does not establish that a claim is false.

### Input

| Input | Type | Description |
| --- | --- | --- |
| `conversation` | `string` | The full conversation (user and agent turns) to be evaluated for hallucinations in the agent's responses |
| `context` | `string` | Optional external grounding (e.g., retrieved documents, knowledge base) to check the agent’s factual claims |

### Output

| Field | Type | Description |
| --- | --- | --- |
| Result | `Pass / Fail` | Fail means the judge found a fabricated attribution, false dialogue history, material contradiction, or misrepresentation of context. Pass does not certify facts the inputs cannot verify |
| Reason | `string` | A plain-language explanation of the hallucination assessment |

### Run it from code

Compare the claim about delivery with what the customer actually said. The policy gives a second source of evidence for the judge. Both examples use the hosted [`turing_flash` judge](/docs/evaluation/concepts/evaluator-models).

<Note>
Set [your Future AGI credentials](/docs/evaluation/reference/sdk-api) (`FI_API_KEY` and `FI_SECRET_KEY`). For Python, create and activate a virtual environment with `python3.12 -m venv .venv && source .venv/bin/activate`, then install the Agent Learning Kit with `python -m pip install agent-learning-kit==0.3.7`. Save the Python example as `conversation_hallucination.py` and run `python conversation_hallucination.py`.

For TypeScript, use Node.js 22.18 or later. Run `npm install @future-agi/agent-learning-kit@0.4.0`, save the example as `conversation_hallucination.mts`, and run `node conversation_hallucination.mts`.
</Note>

<CodeGroup>

```python Python
from fi.evals import evaluate

result = evaluate(
    "conversation_hallucination",
    conversation=(
        "Customer: My boots arrived yesterday. Can I return them?\n"
        "Agent: As you said, you bought them two months ago, so the return window is closed."
    ),
    context="Ridgeline accepts returns within 30 days of delivery.",
    model="turing_flash",
)

if result.score is None:
    raise RuntimeError(result.error or result.reason or "No score returned")
print(f"Score: {result.score}")
print(result.reason)
print(result.metadata["eval_id"])
```

```typescript TypeScript
import { Evaluator } from "@future-agi/agent-learning-kit";

const run = await new Evaluator().submit(
  "conversation_hallucination",
  {
    conversation: [
      "Customer: My boots arrived yesterday. Can I return them?",
      "Agent: As you said, you bought them two months ago, so the return window is closed.",
    ].join("\n"),
    context: "Ridgeline accepts returns within 30 days of delivery.",
  },
  { modelName: "turing_flash" }
);

const { result } = await run.wait();
if (result?.output == null) throw new Error("No result returned");
console.log(result.output);
console.log(run.id);
```

## When to use

Run Conversation Hallucination wherever an agent carries state across multiple turns and could misremember or invent something along the way.

- Multi-turn support or sales conversations, to catch the agent claiming the user said something they didn't
- Long-running agent sessions, to catch self-contradictions or false self-quotations across turns
- Conversations grounded in retrieved documents or a knowledge base, to check external facts the agent states are actually supported

## What to do when Conversation Hallucination fails

Check the reason for which failure mode triggered: a false user attribution, a self-contradiction, or an unsupported external fact. For user-attribution and self-contradiction failures, review how conversation history is passed to the agent. Missing or reordered turns can change what the judge sees.

For claims that misrepresent your policy, tighten grounding: make sure retrieved context actually covers the claims the agent is allowed to make, and prompt the agent to hedge or say it doesn't know rather than fill gaps with invented specifics.
