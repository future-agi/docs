## About

NDCG@K (Normalized Discounted Cumulative Gain at K) measures how close your first K search results are to the best possible order. For a Ridgeline Outfitters support query about returns and warranties, retrieving the returns policy in second place earns less credit than putting it first.

## Inputs and output

| Required Input | Type | Description |
| --- | --- | --- |
| `hypothesis` | `string` | JSON-serialized list of retrieved chunks in ranked order |
| `reference` | `string` | JSON-serialized list of ground-truth relevant chunks |

### Output

| Field | Type | Description |
| --- | --- | --- |
| `output` | `score` | A score between 0 and 1, where 1 means the best possible ranking within the cutoff |
| `reason` | `string` | Summary of the calculation, such as `NDCG@2: 0.387 (DCG=0.631, IDCG=1.631)` |

`k` is an optional positive integer. In Python, pass it in `eval_config` on `Evaluator.evaluate()`. If you omit it, the template scores the full retrieved list.

## Run it from code

Use `Evaluator.evaluate()` for the hosted template so the SDK forwards `eval_config` to the evaluator. Each returned row contains the score in `output`, along with its reason and evaluation ID.

<Note>
Set `FI_API_KEY` and `FI_SECRET_KEY` for your Future AGI account. In a fresh Python 3.12 virtual environment named `.venv`, run `source .venv/bin/activate`, then `python -m pip install agent-learning-kit==0.3.7`. Save the Python example as `score.py` and run `python score.py`. Use Python with the current release: the TypeScript package is not runnable in version 0.4.0.

<CodeGroup titles={["Python", "TypeScript"]}>

```python Python
import json
from fi.evals import Evaluator

batch = Evaluator().evaluate(
    eval_templates="ndcg_at_k",
    inputs={
        "hypothesis": json.dumps(["sizing", "returns", "warranty"]),
        "reference": json.dumps(["returns", "warranty"]),
    },
    eval_config={"k": 2},
)
row = batch.eval_results[0]
if row is None or row.output is None:
    raise RuntimeError("No NDCG score returned")
print(f"NDCG@2: {float(row.output):.3f}")
print(row.reason)
print(row.eval_id)
```

Only the first two results count. `returns` is relevant at rank 2; `warranty` is relevant but outside the cutoff. The actual gain is `DCG@2 = 0 + 1/log₂(3) ≈ 0.631`. The ideal ranking puts both relevant chunks first, so `IDCG@2 = 1 + 1/log₂(3) ≈ 1.631`. The first line of output is `NDCG@2: 0.387`.

### Batch evaluation

To score multiple queries in one call, pass one JSON string per query in each input column. Here the first relevant result is at rank 1, 2, or 3. With `k=2`, the third query scores zero. Save this standalone example as `batch.py` and run `python batch.py`.

```python Python
import json
from fi.evals import Evaluator

batch = Evaluator().evaluate(
    eval_templates="ndcg_at_k",
    inputs={
        "hypothesis": [
            json.dumps(["returns", "sizing"]),
            json.dumps(["care", "warranty"]),
            json.dumps(["sizing", "warranty", "shipping"]),
        ],
        "reference": [json.dumps([doc]) for doc in ["returns", "warranty", "shipping"]],
    },
    eval_config={"k": 2},
)
rows = batch.eval_results
if len(rows) != 3 or any(row is None or row.output is None for row in rows):
    raise RuntimeError("Expected one score for each of the three queries")
for i, row in enumerate(rows, start=1):
    print(f"Query {i}: {float(row.output):.3f}")
print(json.dumps([row.eval_id for row in rows]))
```

The three queries print scores of `1.000`, `0.631`, and `0.000`, respectively. Each query has just one relevant chunk, so its ideal gain is 1.

## How it works

The evaluator scores the first `n` results, where `n` is the smaller of K and the number of chunks you retrieved. Let `|R|` be the number of distinct chunks in your reference list. At rank `i` (starting at 1), `rel(i)` is 1 if the chunk exactly matches a reference string and hasn't appeared at an earlier rank, or 0 otherwise. A repeated chunk still occupies a position but adds no gain.

1. **Discounted cumulative gain:** `DCG@K = Σ rel(i) / log₂(i + 1)` for `i = 1 … n`. The discount gives a first-place hit a gain of 1 and a second-place hit a gain of about 0.631.
2. **Ideal gain:** `IDCG@K = Σ 1 / log₂(i + 1)` for `i = 1 … min(|R|, n)`. This puts as many distinct relevant chunks as will fit at the top. Relevance is binary, so the order among those chunks doesn't matter.
3. **Normalized score:** `NDCG@K = DCG@K / IDCG@K`. If the retrieved list or reference list is empty, the evaluator returns 0 instead.

A short list can earn a perfect ranking score without finding every relevant chunk. If you ask for five results and get only one, and it matches one of three distinct reference chunks, the actual and ideal gain are both 1. NDCG@5 is 1.000, but [Recall@K](/docs/evaluation/builtin/recall-at-k) at the same cutoff is only 0.333.

## When to use

Run NDCG@K wherever the position of relevant chunks in the ranking matters, not just whether they were retrieved.

- RAG and retrieval pipelines, to check whether relevant chunks surface near the top
- Evaluating or tuning a re-ranking step, since NDCG@K directly rewards better ordering
- Comparing retrieval strategies where two approaches find the same chunks but rank them differently

## Next steps

If NDCG@K is low, check which relevant chunks made it into the top K. If you found them but ranked them too low, try re-ranking the same results and compare scores. If chunks are missing entirely, use [Recall@K](/docs/evaluation/builtin/recall-at-k) to measure coverage as you change the retriever.
