---
title: "NDCG@K"
description: "Rates RAG retrieval ranking quality using Normalized Discounted Cumulative Gain, rewarding relevant results that appear earlier."
---

NDCG@K scores not just whether relevant chunks were retrieved, but whether they land near the top of the ranked list. Run it when ranking order matters as much as coverage.

## What it does

NDCG@K is a statistical metric. It compares the retrieved chunks against the ground-truth relevant chunks and scores ranking quality, giving more credit for relevant chunks that appear earlier.

### Input

| Required Input | Type | Description |
| --- | --- | --- |
| `hypothesis` | `string` | JSON-serialized list of retrieved chunks in ranked order |
| `reference` | `string` | JSON-serialized list of ground-truth relevant chunks |

### Output

| Field | Type | Description |
| --- | --- | --- |
| Result | `score` | A score between 0 and 1, where 1 means the best possible ranking within the cutoff |
| Reason | `string` | Short summary string of the score, e.g. `NDCG@3: 0.469` |

`k` is an optional positive integer. In Python, pass it in `eval_config` on `Evaluator.evaluate()`. If you omit it, the template scores the full retrieved list.

### Run it from code

Use `Evaluator.evaluate()` for the hosted template so the SDK forwards `eval_config` to the evaluator. Each returned row contains the score in `output`, along with its reason and evaluation ID.

<Note>
Set `FI_API_KEY` and `FI_SECRET_KEY` for your Future AGI account. In a fresh Python 3.12 virtual environment named `.venv`, run `source .venv/bin/activate`, then `python -m pip install agent-learning-kit==0.3.7`. Save the Python example as `score.py` and run `python score.py`. Use Python with the current release: the TypeScript package is not runnable in version 0.4.0.
</Note>

<CodeGroup>

```python Python
import json
from fi.evals import Evaluator

batch = Evaluator().evaluate(
    eval_templates="ndcg_at_k",
    inputs={
        "hypothesis": json.dumps(["sizing", "returns", "warranty"]),
        "reference": json.dumps(["returns", "warranty"]),
    },
    eval_config={"k": 2},
)
row = batch.eval_results[0]
if row is None or row.output is None:
    raise RuntimeError("No NDCG score returned")
print(f"NDCG@2: {float(row.output):.3f}")
print(row.reason)
print(row.eval_id)
```

### Batch evaluation

To score multiple queries in one call, pass one JSON string per query in each input column. Here the first relevant result is at rank 1, 2, or 3. With `k=2`, the third query scores zero. Save this standalone example as `batch.py` and run `python batch.py`.

```python Python
import json
from fi.evals import Evaluator

batch = Evaluator().evaluate(
    eval_templates="ndcg_at_k",
    inputs={
        "hypothesis": [
            json.dumps(["returns", "sizing"]),
            json.dumps(["care", "warranty"]),
            json.dumps(["sizing", "warranty", "shipping"]),
        ],
        "reference": [json.dumps([doc]) for doc in ["returns", "warranty", "shipping"]],
    },
    eval_config={"k": 2},
)
rows = batch.eval_results
if len(rows) != 3 or any(row is None or row.output is None for row in rows):
    raise RuntimeError("Expected one score for each of the three queries")
for i, row in enumerate(rows, start=1):
    print(f"Query {i}: {float(row.output):.3f}")
print(json.dumps([row.eval_id for row in rows]))
```

### How it works

NDCG@K applies a logarithmic discount to lower-ranked positions, so a relevant chunk at position 1 contributes much more to the score than the same chunk at position 5.

**Formula:** Divide the discounted gain (`DCG@K`) by its ideal value (`IDCG@K`). Each rank i from 1 through K contributes `relevance(i) / log₂(i + 1)` to DCG.

Where:
- `relevance(i)` is 1 if the item at position i is in the ground truth, 0 otherwise
- `IDCG@K` (Ideal DCG) is the best possible DCG if all relevant items were ranked first
- Duplicate items in the retrieved list are only credited once

A score of 1.0 means the retriever achieved the ideal gain within the evaluated positions. A lower score can mean relevant chunks are missing, ranked too low, or outside the cutoff.

Matching uses exact string equality. Relevance is binary, so swapping two distinct relevant chunks at the top does not lower the score.

## When to use

Run NDCG@K wherever the position of relevant chunks in the ranking matters, not just whether they were retrieved.

- RAG and retrieval pipelines, to check whether the most relevant chunks surface near the top
- Evaluating or tuning a re-ranking step, since NDCG@K directly rewards better ordering
- Comparing retrieval strategies where two approaches find the same chunks but rank them differently

## What to do when NDCG@K fails

If NDCG@K is low, relevant chunks are being retrieved but ranked poorly:

- Apply a re-ranking model (cross-encoder) to reorder results by relevance after initial retrieval
- Fine-tune the embedding model on domain-specific data to improve ranking accuracy
- Check if your similarity metric (cosine, dot product) is appropriate for your embedding model
- Consider using a hybrid retrieval approach where sparse (BM25) and dense scores are combined for better ranking
- Review query preprocessing: adding context to short queries can improve ranking quality
