title: "Data Privacy Compliance"
description: "Screens model output for exposed personal or health information and unsupported inferences about individuals."

Data Privacy Compliance flags generated content that may disclose or infer sensitive information about a person. Run it wherever output could expose sensitive data or create compliance risk.

## What it does

Data Privacy Compliance is an LLM-as-Judge eval. It looks for exposed identifiers, health information linked to a person, and unsupported inferences about private details. A pass is not a determination of GDPR or HIPAA compliance.

### Input

| Required Input | Type | Description |
| --- | --- | --- |
| `output` | `string` | The content to be evaluated for privacy compliance |

### Output

| Field | Type | Description |
| --- | --- | --- |
| Result | `Passed` / `Failed` | Fail means the judge flagged a possible disclosure or misuse of sensitive information for review |
| Reason | `string` | A plain-language explanation of the data privacy compliance assessment |

### Run it from code

Set `FI_API_KEY` and `FI_SECRET_KEY` to [your Future AGI credentials](/docs/evaluation/reference/sdk-api). Both examples print the verdict, the reason and the evaluation ID. The [evaluator model](/docs/evaluation/concepts/evaluator-models) is `turing_flash`.

- **Python:** Create a virtual environment with `python3.12 -m venv .venv && source .venv/bin/activate`, then run `python -m pip install agent-learning-kit==0.3.7`. Save the example as `data_privacy.py` and run `python data_privacy.py`.
- **TypeScript:** This example calls the REST API directly from Node.js 22.18 or later. Save it as `data_privacy.mts` and run `node data_privacy.mts`.

<CodeGroup>

```python Python
from fi.evals import Evaluator

batch = Evaluator().evaluate(
    eval_templates="data_privacy_compliance",
    inputs={
        "output": "Ridgeline has approved your return. For the refund status, sign in and open your order history.",
    },
    model_name="turing_flash",
)
result = batch.eval_results[0]
if result.output is None:
    raise RuntimeError(result.reason or "No evaluation result returned")
print(result.output)
print(result.reason)
print(result.eval_id)
```

```typescript TypeScript
const { FI_API_KEY, FI_SECRET_KEY, FI_BASE_URL = "https://api.futureagi.com" } = process.env;
if (!FI_API_KEY || !FI_SECRET_KEY) throw new Error("Set both Future AGI credentials");

const response = await fetch(new URL("/sdk/api/v1/new-eval/", FI_BASE_URL), {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "X-Api-Key": FI_API_KEY,
    "X-Secret-Key": FI_SECRET_KEY,
  },
  body: JSON.stringify({
    eval_name: "data_privacy_compliance",
    model: "turing_flash",
    inputs: {
      output: "Ridgeline has approved your return. For the refund status, sign in and open your order history.",
    },
  }),
});
if (!response.ok) throw new Error(`Evaluation request failed: HTTP ${response.status}`);
const body = await response.json();
const result = body.result?.[0]?.evaluations?.[0];
if (result?.output == null) throw new Error("No evaluation result returned");
console.log(result.output);
console.log(result.reason);
console.log(result.eval_id);
```

## When to use

Run Data Privacy Compliance wherever output could expose regulated data or violate a privacy regime.

- Text, audio, image, and chat outputs from systems handling personal or health data
- Privacy reviews, to prioritize outputs that may need redaction or a closer look
- Safety checks before storing or forwarding model output in regulated industries

## What to do when Data Privacy Compliance fails

Identify specific privacy violations in the output and take immediate action to remove or redact any exposed sensitive data. Strengthening data handling and processing protocols can help prevent similar issues, while enhancing anonymisation and pseudo-anonymisation techniques ensures better data protection.

Regular privacy audits and assessments should be conducted to identify potential risks and maintain compliance.

Finally, integrating privacy-by-design principles into system development and operations ensures that data protection measures are embedded at every stage, minimising the risk of future compliance failures.
