title: "OCR Evaluation"
description: "Evaluates the accuracy of optical character recognition output by checking extracted JSON content against the source PDF."
---

OCR Evaluation checks whether text extracted from a PDF into JSON faithfully represents the source document. Run it wherever document extraction feeds a downstream pipeline.

## What it does

OCR Evaluation is an LLM-as-Judge eval. It reads the source PDF and the extracted JSON content, then scores how accurately the extraction represents the document.

### Input

| Required Input | Type | Description |
| --- | --- | --- |
| `input_pdf` | `string` | The PDF bytes encoded as a `data:application/pdf;base64,...` string. Send the file contents, not a path or an HTTPS URL. |
| `json_content` | `string` | The OCR fields to check, serialized as a JSON string |

### Output

| Field | Type | Description |
| --- | --- | --- |
| Result | `score` | Higher values indicate more accurate OCR extraction |
| Reason | `string` | A plain-language explanation of the OCR quality assessment |

### Run it from code

Download the [sample PDF](https://www.w3.org/WAI/ER/tests/xhtml/testfiles/resources/pdf/dummy.pdf) into your working directory. It contains one line: “Dummy PDF file”.

```bash
curl --fail --location --output sample.pdf https://www.w3.org/WAI/ER/tests/xhtml/testfiles/resources/pdf/dummy.pdf
```

Choose Python (Agent Learning Kit) or TypeScript (HTTP). Both examples read `sample.pdf` from that directory and send its contents to `turing_large`, a hosted [Turing model](/docs/evaluation/concepts/evaluator-models). Each prints the score, reason and evaluation ID.

<Note>
Set `FI_API_KEY` and `FI_SECRET_KEY` for your [Future AGI account](/docs/evaluation/reference/sdk-api). For Python, run `python3.12 -m venv .venv`, `source .venv/bin/activate`, and `python -m pip install agent-learning-kit==0.3.7`. Save the example as `score.py` and run `python score.py`. For TypeScript, save the HTTP example as `score.mts` and run `node score.mts` with Node.js 22.18 or newer.
</Note>

<CodeGroup>

```python Python
import base64
from pathlib import Path

from fi.evals import evaluate

pdf = base64.b64encode(Path("sample.pdf").read_bytes()).decode("ascii")
result = evaluate(
    "ocr_evaluation",
    model="turing_large",
    input_pdf=f"data:application/pdf;base64,{pdf}",
    json_content='{"heading": "Dummy PDF file"}',
)
if result.score is None:
    raise RuntimeError(result.error or result.reason or "No score returned")

print(result.score)
print(result.reason)
print(result.metadata["eval_id"])
```

```typescript TypeScript (HTTP)
import { readFile } from "node:fs/promises";

const pdf = await readFile("sample.pdf", { encoding: "base64" });
const { FI_BASE_URL = "https://api.futureagi.com", FI_API_KEY, FI_SECRET_KEY } = process.env;
if (!FI_API_KEY || !FI_SECRET_KEY) throw new Error("Set your Future AGI credentials");

const response = await fetch(new URL("/sdk/api/v1/new-eval/", FI_BASE_URL), {
  method: "POST",
  headers: { "Content-Type": "application/json", "X-Api-Key": FI_API_KEY, "X-Secret-Key": FI_SECRET_KEY },
  body: JSON.stringify({
    eval_name: "ocr_evaluation",
    model: "turing_large",
    inputs: {
      input_pdf: `data:application/pdf;base64,${pdf}`,
      json_content: JSON.stringify({ heading: "Dummy PDF file" }),
    },
  }),
});
if (!response.ok) throw new Error(`Evaluation request failed: HTTP ${response.status}`);
const row = (await response.json()).result?.[0]?.evaluations?.[0];
if (row?.output == null || !row.eval_id) throw new Error("No evaluation result returned");
console.log(row.output);
console.log(row.reason);
console.log(row.eval_id);
```

</CodeGroup>

For your own document, replace `sample.pdf` with your local file and set `json_content` to the fields your OCR tool extracted. You send the PDF to the hosted evaluator, but you do not need to publish it at a public URL. The judge checks whether each supplied JSON value is supported by the PDF; it does not penalize omitted fields.

## When to use

Run OCR Evaluation wherever a document goes through OCR and the extracted structure needs to be verified against the source.

- Document extraction pipelines, to confirm scanned PDFs are converted to accurate structured data
- Text and PDF/document workflows that feed downstream systems on extracted fields
- Quality checks after OCR tooling changes or model upgrades

## What to do when OCR Evaluation fails

If the OCR evaluation score is lower than expected, check for poor scan quality or low-resolution images in the PDF, and verify that the OCR tool supports the fonts and languages present in the document.

Review the JSON structure to ensure it maps correctly to the document fields, and look for misinterpreted characters (e.g. `0` vs `O`, `1` vs `l`). Ensure tables and multi-column layouts are being parsed correctly, and consider pre-processing the PDF to improve contrast and clarity before OCR.
