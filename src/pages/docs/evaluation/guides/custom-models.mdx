Bring your own LLM as the [evaluator model](/docs/evaluation/concepts/evaluator-models), instead of a Future AGI model, when the judge needs domain knowledge, inference must stay in a particular cloud or region, or you want to track costs against a model you already pay for. Once added, it appears in the model dropdown wherever you configure an eval.

<Prerequisites title="Before you start">
- An organization Owner or Admin for [AI Providers settings](/docs/admin-settings/ai-providers); workspace admins and members can view and use configured providers.
- Credentials for the model provider or HTTP endpoint. These authorize calls to the model, unlike [workspace API keys](/docs/admin-settings/api-keys), which authorize calls to Future AGI.
</Prerequisites>

## Choose the connection

Use a provider connection for OpenAI, AWS Bedrock, AWS SageMaker, Vertex AI or Azure. Use a custom endpoint for any model behind an HTTP API, including self-hosted, fine-tuned or proxy deployments.

1. Open **Settings**.
2. Select **AI Providers** in the settings sidebar.
3. Open the **Custom model** tab.

<img src="/images/docs/evaluation/guides/custom-models/custom-model-list.png" alt="AI Providers page on the Custom model tab, listing existing custom models with masked credentials and edit, delete, and copy icons, with a callout pointing at the Create custom model button top right" style={{ borderRadius: '5px' }} />

4. Select **Create custom model**.

   The **Add Model** drawer offers **From model Provider** and **Configure Custom Model**; complete only the matching path below.

## Configure a provider model

1. Select **From model Provider**.
2. Choose the provider in **Model Provider**.

<img src="/images/docs/evaluation/guides/custom-models/provider-dropdown.png" alt="Model Provider dropdown open, listing Open AI, AWS Bedrock, AWS Sagemaker, Vertex AI, and Azure, with a callout pointing at Open AI" style={{ borderRadius: '5px' }} />

3. Enter **Model Name**.

   For Bedrock, use the invocation ID from the AWS console, not a family name such as `Claude`.

4. Enter **Input Token Cost Per Million Tokens**.
5. Enter **Output Token Cost Per Million Tokens**.

   Both values are for cost tracking; zero is valid, but a negative value is not.

6. Choose **Form** for individual fields or **JSON** for raw configuration.
7. Enter the credentials for your provider.

| Provider in the dropdown | What to supply |
| --- | --- |
| **Open AI** | API key and, optionally, a base URL. |
| **AWS Bedrock** | Region and access keys. |
| **AWS Sagemaker** | Region and access keys. |
| **Vertex AI** | Service account. |
| **Azure** | Endpoint and key. |

</div>

<img src="/images/docs/evaluation/guides/custom-models/openai-form.png" alt="Add Model drawer with Open AI selected as the Model Provider, showing Model Name, Input and Output Token Cost Per Million Tokens, a Form/JSON toggle, API Key, and an optional Base URL field, with a callout pointing at the API Key field" style={{ borderRadius: '5px' }} />

Bedrock accepts a chat foundation-model ID such as `anthropic.claude-3-haiku-20240307-v1:0` or a system inference-profile ID such as `us.anthropic.claude-3-5-sonnet-20241022-v2:0`. This form doesn't support new application-profile ARNs, provisioned throughput, session tokens or role credentials. It connects to a model; it does not train or import one in AWS.

## Configure a custom endpoint instead

1. Select **Configure Custom Model**.
2. Enter the **Model Name** your endpoint serves.
3. Enter the input token cost per million tokens.
4. Enter the output token cost per million tokens.

   You can use zero for a model you host yourself.

5. Enter the full chat-completions URL in **API Base URL**, such as `https://your-host/v1/chat/completions`.
6. Enter any auth header, tenant ID or routing parameter as a key/value pair under **Custom Configuration**.
7. Select **Add more configuration** if the endpoint needs another pair.

<img src="/images/docs/evaluation/guides/custom-models/configure-custom-form.png" alt="Add Model drawer with Configure Custom Model selected, showing required Model Name, Input and Output Token Cost Per Million Tokens, and API Base URL fields, plus an Add Custom Configuration section with Custom Key and Custom Value inputs and an Add more configuration button, with a callout pointing at the API Base URL field" style={{ borderRadius: '5px' }} />

## Save and check the model

<Note>
When you add a custom endpoint, Future AGI sends a test request to the **API Base URL**. For Bedrock, saving sends a small validation request to AWS and can incur provider charges.
</Note>

1. Select **Add Custom model**.

   On success, you should see the entry on the **Custom model** tab, where you can edit, delete or copy it.

2. Open an eval's model dropdown.
3. Select the registered model as its evaluator.

## If the endpoint returns 404

The validation error can read: `https://your-host/v1 answered 404 Not Found. API Base URL must be the full chat-completions URL, such as https://your-host/v1/chat/completions, and the server must serve model 'my-model'.`

1. Check that **API Base URL** includes the chat-completions path rather than ending at `/v1`.
2. Check that **Model Name** matches a model served there.
3. Retry **Add Custom model** after correcting the mismatch.
