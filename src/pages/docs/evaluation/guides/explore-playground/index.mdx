The Evaluations page is your eval library: every built-in eval and every one your team creates lives here, so the first job is narrowing the list. To check whether a response sticks to its source, for example, find [groundedness](/docs/evaluation/builtin/groundedness). Combine a tag with an output-type filter to narrow the library to checks that return the verdict you need.

## Find an eval

1. Open **Build > Evals**.

   You should see one row per eval, including built-in templates and custom evals created by your workspace.

<img src="/images/docs/evaluation/explore-playground/evaluations-list.png" alt="The Evaluations page listing evals with their type, output type, and tags, plus search, tag filters, a Columns control, and a Create evals button" style={{ borderRadius: '5px' }} />

2. Select the **RAG** tag under the search field.

   Additional tag chips narrow the list further; `groundedness` carries both RAG and Retrieval Systems.

<img src="/images/docs/evaluation/explore-playground/tags-evals.gif" alt="Clicking tag chips on the Evaluations page to filter the list down to the evals that carry each tag" style={{ borderRadius: '5px' }} />

3. Open **Filter**.
4. Set a condition for **Output Type** of **Pass/fail**.

   In the library shown above, `groundedness` matches both conditions; `eval_ranking` also has the RAG tag but returns a percentage instead.

<img src="/images/docs/evaluation/explore-playground/filter-evals.gif" alt="Opening the Filter dropdown on the Evaluations page and building a condition on a field like name, eval type, output type, or tags" style={{ borderRadius: '5px' }} />

5. Select the `groundedness` row to open the eval, where you can inspect its rule or test it.

If you already know the name, type it into **Search**. Search, tag chips and filter conditions work together. If an expected row is missing, check all three. Conditions can use name, type, eval type, output type, tags or creator; for example, combine pass/fail with **Created By** set to your workspace for custom checks only.

## Read the columns

<div class="sdk-ref-table max-sm:[&_td]:px-1.5! max-sm:[&_th]:px-1.5!">

| Column | What to look for |
| --- | --- |
| **Evaluation Name** | The template name, such as `groundedness` or [prompt_injection](/docs/evaluation/builtin/prompt-injection). |
| **Type** | A single eval runs on its own; a [composite eval](/docs/evaluation/concepts/composite-evals) combines child evals. |
| **Eval Type** | How the eval decides: [Agent, LLM-as-Judge or Code](/docs/evaluation/concepts/eval-types). |
| **Output Type** | The [result format](/docs/evaluation/reference/output-types): pass/fail, percentage or category. |
| **Tags** | The categories the eval belongs to, such as Red Teaming, RAG or Safety. |
| **30 day chart** and **30 day error rate** | Recent run volume and failure rate. |
| **Created By** | **System** for a built-in eval or your workspace for a custom one. |
| **Last updated** | When the eval last changed. |
| **Versions** | The number of versions; this column is hidden by default. |

</div>

## Choose a tag

Every eval carries one or more tags that say what it checks and where it fits. The main tag chips fall into four kinds:

<div class="sdk-ref-table max-sm:[&_td]:px-1.5! max-sm:[&_th]:px-1.5!">

| Kind | What it tells you | Tags |
| --- | --- | --- |
| Concern | The risk the eval guards against. | Safety, Red Teaming, Data Leakage, Hallucination, Harmful Objects |
| Technique or check | How it measures. | RAG, Retrieval Systems, NLP Metrics, Output Validation, Output Format, Code |
| Modality | The kind of content. | Image, Audio, Text, PDF, Conversation |
| Domain | The use case. | Medical, Finance, Agents, Chatbot behaviors |

</div>

An eval usually carries more than one tag. For example, `prompt_injection` carries Red Teaming; individual evals also carry finer tags such as Quality, Bias or Data Privacy.

## Arrange the columns

1. Open **Columns**.
2. Toggle a field such as **Versions** to show or hide it.
3. Reorder the visible fields to put the ones you compare side by side.

<img src="/images/docs/evaluation/explore-playground/columns-evals.gif" alt="Opening the Columns control on the Evaluations page and toggling which columns show in the table" style={{ borderRadius: '5px' }} />

## Create your own

Select **Create evals** at the top right when the existing templates don't cover your rule. The [custom eval guide](/docs/evaluation/guides/custom-evals) walks through naming the eval, writing the rule and choosing its output type. The saved eval joins the same searchable, filterable library and can carry tags.
