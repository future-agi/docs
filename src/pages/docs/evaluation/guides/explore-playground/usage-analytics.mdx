## About

An evaluator's **Usage** tab shows how often it ran and what it scored. If an [Observe](/docs/observe) evaluation flags a wrong answer, you can go from the verdict to the exact span or voice call the evaluator checked, then return to the same log.

## Find the run in Evaluation Logs

<Steps>
  <Step title="Open the evaluator's Usage tab">
    Suppose your Ridgeline Outfitters support agent told a customer it had refunded a duplicate $61.20 charge. In **Evals**, open the evaluator that checks refund claims against tool results, then select **Usage**.

    <img src="/images/docs/evaluation/usage-analytics/open-evaluator-usage.gif" alt="Opening ridgeline-refund-accuracy from the Evaluations list and selecting Usage to see its 14 runs." style={{ borderRadius: '5px' }} />
  </Step>
  <Step title="Choose the time range">
    Choose **Today** if the exchange happened today, or **Custom** for a particular date range. The default is **30D**. **Runs** counts successful evaluator executions, not passing answers. The **Volume** bars show runs over time. When verdicts are available, a pass/fail evaluator also shows **Pass rate**; a percentage evaluator shows **Average score**.

    ![Usage with 7D selected: 14 runs, daily Volume bars, a Pass rate line, and passed and failed refund logs.](/images/docs/evaluation/usage-analytics/refund-usage-volume.png)
  </Step>
  <Step title="Open the matching row">
    Under **Evaluation Logs**, search for the order number if it appears in the input. Search matches the log ID, input, result, or reason on the current page. Check **Result**, **Reason**, and **Ran at** to identify the exchange, then click the row. In **Formatted**, read the **Explanation** if the evaluator gave a reason. Switch to **JSON** to inspect the log details. The source action appears in either view when the run has a source you can open.

    ![Formatted log for RO-54766 with View trace and an explanation that issue_refund declined the $61.20 refund the agent claimed to have made.](/images/docs/evaluation/usage-analytics/refund-log-explanation.png)
  </Step>
</Steps>

## Inspect the source and return

For the Ridgeline order, the next step depends on what the evaluator scored:

- **View trace** opens the trace with the evaluated [span](/docs/observe/concepts/spans) selected. If the evaluator scored the `issue_refund` tool call, you land on that call, not the root of the conversation. A `refund_declined` result explains why the agent's claim that it refunded $61.20 was wrong.
- **View call** opens the corresponding voice call. If the customer phoned about the duplicate charge, read the transcript to check whether the agent promised a refund or confirmed one.

Select **Back to evaluation** in either viewer to return to the same open log and compare what you found with the verdict. You do not need to search the table again.

## Check a log's source with the API

`GET /model-hub/get-eval-logs` reads one log. Set `LOG_ID` to the full evaluation log UUID, not the trace or span ID. The log panel shows only the first 12 characters. To get the full ID for an Observe log, open your browser's Network panel, then reopen the log. Copy the `log_id` query parameter from the `get-eval-logs` request.

With your [API key pair](/docs/admin-settings/api-keys) exported as `FI_API_KEY` and `FI_SECRET_KEY`, request the optional `result.source_navigation` object. This example uses cURL and `jq` to print just that object:

```bash
set -o pipefail
curl --fail --silent --show-error --get 'https://api.futureagi.com/model-hub/get-eval-logs' \
  --header "X-Api-Key: ${FI_API_KEY:?Set FI_API_KEY}" \
  --header "X-Secret-Key: ${FI_SECRET_KEY:?Set FI_SECRET_KEY}" \
  --data-urlencode "log_id=${LOG_ID:?Set LOG_ID to the full evaluation log UUID}" \
  --data-urlencode 'include_source_navigation=true' |
  jq -e '.result.source_navigation'
```

When `status` is `ready`, `kind` is `trace` or `voice_call`. The object includes the source `project_id`, `trace_id`, and evaluated `span_id`. Omit `include_source_navigation` or set it to `false` to get the original log without the extra object.

For an older Observe log that did not record its source project, the same request returns this object. The verdict is still readable:

```json
{
  "status": "source_not_recorded",
  "kind": null,
  "project_id": null,
  "trace_id": null,
  "span_id": null,
  "retryable": false
}
```

## When there is no source button

| What you see in the log | What to do |
| --- | --- |
| No source action in a Playground, Dataset, or composite evaluation log | Read the log itself. The trace and call buttons are only available for non-composite Observe logs. |
| A message that the log predates recorded evaluation sources (`source_not_recorded`) | Use the saved input and verdict. Retrying cannot recover a project the log never recorded. |
| **Source details could not be loaded. Try again.** (`temporarily_unavailable`) | Select **Retry** to check the source again. This does not rerun the evaluation. |
| **The source is unavailable or you do not have access.** (`unavailable`) | Check that you still have access to the source project. A deleted source can give the same message. |
| A message about a session target, a missing or invalid reference, or more than one possible source | Read the evaluation details instead. The log cannot open a unique trace or call. |
