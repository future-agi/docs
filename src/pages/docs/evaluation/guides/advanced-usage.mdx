title: "Give an Agent Evaluator tools and context"

When the text you're scoring leaves out a fact the judge needs, give an [Agent Evaluator](/docs/evaluation/concepts/eval-types) access to the rest of the request, an external tool, the web or your [knowledge bases](/docs/knowledge-base). You can also choose how it writes up its verdict. Save the choices in a custom eval version, or configure a built-in eval for one task.

<Prerequisites title="Before you start">
- A single Agent Evaluator. The connectors menu is not available on a [composite eval](/docs/evaluation/concepts/composite-evals), an LLM-as-Judge eval or a Code eval.
- To save a version, use a custom eval you own. Built-in templates are read-only.
</Prerequisites>

## Open the connectors menu

1. Open the eval, such as the `hateful_speech` example in [Create a custom eval](/docs/evaluation/guides/custom-evals).
2. Select **+** in the model bar below the instructions.

<img src="/images/docs/evaluation/guides/advanced-usage/open-menu.png" alt="The hateful_speech Agent eval detail page with the + button in the model bar, next to the Agent type and the Turing Large model" style={{ borderRadius: '5px' }} />

You should see five choices: **Use Internet**, **Connectors**, **Knowledge Base**, **Data Injection** and **Summary**. Enabled capabilities appear as chips in the model bar.

<Mermaid chart={`flowchart LR
  accTitle: How outside evidence reaches a verdict
  accDescr: The evaluator reads the response, requests an outside fact from a search or connector tool if needed, and uses the returned evidence to give a verdict and reason.
  R["Response to judge"] --> A["Agent Evaluator"]
  A -->|Look up a fact| T["Web search or connector"]
  T -->|Return evidence| A
  A --> V["Verdict and reason"]
`} />

## Look up a fact on the web or in a tool

1. For public facts, switch on **Use Internet**.

   You should see an **Internet** chip in the model bar.

<img src="/images/docs/evaluation/guides/advanced-usage/menu-items.png" alt="The connectors menu open showing Use Internet, Connectors, Knowledge Base, Data Injection, and Summary, with the Use Internet toggle on" style={{ borderRadius: '5px' }} />

2. For facts in your own systems, open **Connectors** instead.
3. Select the registered [MCP connector](/docs/falcon-ai/concepts/mcp-connectors) the eval should use.

   A connector is a tool you expose over the Model Context Protocol (MCP). The evaluator calls it mid-judgment, the same way it uses web search, to check a claim against your database, confirm an ID exists or verify a rule in an internal service.

<img src="/images/docs/evaluation/guides/advanced-usage/connectors.png" alt="The Connectors submenu showing a Tavily connector and a Manage connectors option" style={{ borderRadius: '5px' }} />

A registered connector is available across evals in the workspace and to Falcon AI. If the one you need isn't listed, **Manage connectors** takes you to the settings where you can [register a connector](/docs/falcon-ai/guides/connect-mcp-server).

## Attach reference documents

1. Open **Knowledge Base** in the menu.
2. Select one or more knowledge bases from the searchable list.

   If the list is empty, **Create in Knowledge Base** opens the [knowledge base setup](/docs/knowledge-base/guides/create-knowledge-base).

<img src="/images/docs/evaluation/guides/advanced-usage/knowledge-base.png" alt="The Knowledge Base submenu with a search field, a No knowledge bases yet message, and a Create in Knowledge Base button" style={{ borderRadius: '5px' }} />

Policies, operating procedures and style guides attached here are references for the judge. They do not serve documents to your application at runtime.

## Include the rest of a request

By default the evaluator sees only the `{{variables}}` you mapped. **Data Injection** widens that. If an eval's variables live on different spans, use **Trace context** so it scores across the whole trace instead of a single span.

1. Open **Data Injection**.
2. Switch on the context that contains the evidence.

<div class="sdk-ref-table max-sm:[&_td]:px-1.5! max-sm:[&_th]:px-1.5!">

| Option | What the evaluator receives |
| --- | --- |
| **Template variables** | Only the mapped `{{variables}}` (default). |
| **Dataset row context** | All columns in the current [dataset](/docs/dataset) row. |
| **Call context** | Call transcript, recording and scenario. |
| **Full span context** | One complete [span](/docs/observe/concepts/spans), including its metadata. |
| **Trace context** | The full [trace](/docs/observe/concepts/traces) tree with every span in the request. |
| **Session context** | The full conversation history for a [session](/docs/observe/concepts/sessions). |

</div>

<img src="/images/docs/evaluation/guides/advanced-usage/data-injection.png" alt="The Data Injection submenu with Template variables on and toggles for Dataset row, Call, Full span, Trace, and Session context" style={{ borderRadius: '5px' }} />

3. Check the task's variable mapping at the level you selected.

   In a task, the context level you pick is the level the eval runs on: trace, span or session. The `toxicity` task below has **Trace context** on and shows trace-level fields in **Variable Mapping**, including the trace name `support_turn`.

<img src="/images/docs/evaluation/guides/advanced-usage/data-injection-trace-context.png" alt="The built-in toxicity eval in a task on traces, with Data Injection set to Trace context and the trace's variable mapping shown on the right" style={{ borderRadius: '5px' }} />

If a mapped field is missing, check where it lives before changing the rule. The [eval troubleshooting guide](/docs/evaluation/troubleshooting#common-errors-and-fixes) covers the “not in row” error.

## Choose how to explain the verdict

1. Open **Summary**.
2. Select a preset.

<div class="sdk-ref-table max-sm:[&_td]:px-1.5! max-sm:[&_th]:px-1.5!">

| Preset | What it returns |
| --- | --- |
| **None** | Raw evaluation output, without a summary. |
| **Short** | A brief summary of key points. |
| **Long** | Full context and detailed explanations. |
| **Concise** | A compact summary of essential findings. |

</div>

<img src="/images/docs/evaluation/guides/advanced-usage/summary-presets.png" alt="The Summary submenu with None, Short, Long, and Concise presets, Concise selected, and a Create custom template option" style={{ borderRadius: '5px' }} />

For reusable criteria of your own:

1. Select **Create custom template**.
2. Enter a template name.
3. Write the summary criteria.
4. Confirm with the check icon to keep the template for reuse.

<img src="/images/docs/evaluation/guides/advanced-usage/summary-custom.png" alt="The new custom summary template form with a Template name field and a Summary criteria field" style={{ borderRadius: '5px' }} />

## Save what you turned on

1. Check the chips in the model bar of your custom eval.
2. Select **Save Version**.

<img src="/images/docs/evaluation/guides/advanced-usage/capability-chips.png" alt="The model bar with an Internet chip enabled, and the Save Version button highlighted at the bottom right" style={{ borderRadius: '5px' }} />

3. Open **Versions** to check the new default.

   The latest version becomes the **default**. The `hateful_speech` example shows **Version V2 saved** and lists **V2** as **Default** above **V1**.

<img src="/images/docs/evaluation/guides/advanced-usage/version-saved.png" alt="The hateful_speech eval now at V2, with the Versions tab showing V2 as Default above V1, and a Version V2 saved toast" style={{ borderRadius: '5px' }} />

4. When attaching the eval as a task, choose the [version](/docs/evaluation/concepts/eval-templates) you want to run.

<img src="/images/docs/evaluation/guides/advanced-usage/version-picker.png" alt="The hateful_speech V2 eval attached as a task, with a version dropdown offering Default version, V2, and V1" style={{ borderRadius: '5px' }} />

A built-in eval is read-only, so you can't save a version. Set the capabilities when you configure a run, such as attaching it as a task on your traces. They apply to that run only and are never saved back into the template. The `toxicity` example enables **Trace context** for its task only.
