An [Agent Evaluator](/docs/evaluation/concepts/eval-types) reasons over the text you hand it, but a **+** menu in its model bar lets it do more: reach the web, call your tools, read your knowledge bases, pull in extra trace data, and shape how it writes up its verdict. This guide covers every item in that menu and how to turn each one on.

<Note>
The **+** menu appears only on a **single** Agent Evaluator. It isn't available on a composite eval, or on an LLM-as-Judge or a Code Eval, which score what they're given.
</Note>

## Open the + menu

Create or open an Agent Evaluator eval. In the model bar under the instructions, next to the eval type and model, click the **+** button. Every option below lives in this menu. Once enabled, each shows up as a chip in the model bar, so you can see at a glance what the evaluator has.

## Use Internet

A toggle that lets the evaluator search the web while it judges, for verdicts that depend on public facts the response doesn't carry.

Open the **+** menu and switch **Use Internet** on. An **Internet** chip appears in the model bar; click it off, or toggle it again, to turn it back off.

## Connectors

Connectors are your own tools, exposed over the Model Context Protocol (MCP), that the evaluator can call mid-judgment, the same way it uses web search. Reach for one when the verdict depends on something only your systems know: checking a claim against your database, confirming an ID exists, verifying a rule in an internal service.

Connectors work on a single Agent Evaluator, not on a composite eval. Register the MCP server once for your organization first, shared across evals and with Falcon AI: if yours isn't registered yet, follow [MCP Connectors](/docs/falcon-ai/features/mcp-connectors) to add it. How you then attach it depends on the template.

### On a built-in template

A built-in template is read-only, so you attach connectors at run time. Open the eval, choose **Connectors** in the **+** menu, and select the ones it should call. They apply to that run's configuration and aren't saved back into the built-in template, so set them each time you run it.

### On a custom template

A custom single eval you own can carry connectors in the template itself. Choose **Connectors** in the **+** menu, select the ones it should call, then **save a new version**. That version stores the connectors, so every run and every dataset it evaluates uses them without picking again.

## Knowledge Base

Attach one or more knowledge bases and the evaluator can look up reference context while it judges, like your policies, SOPs, or style guides. Open the **+** menu, choose **Knowledge Base**, and select from the searchable list.

<Note>
A knowledge base here is reference context for the evaluator, not your agent's retrieval store. It gives the judge something to check against; it doesn't serve documents to your application at runtime.
</Note>

## Data Injection

By default an eval sees only the `{{variables}}` you mapped. **Data Injection** widens that, so the evaluator also reads surrounding context from wherever the eval runs. Open the **+** menu, choose **Data Injection**, and pick the context to include:

| Option | What the evaluator also receives |
|---|---|
| **Template variables** | Only the mapped `{{variables}}` (the default) |
| **Dataset row context** | Every column from the current dataset row |
| **Call context** | The call transcript, recording, and scenario |
| **Full span context** | The complete span, including its metadata |
| **Trace context** | The full trace tree, every span in the request |
| **Session context** | The full conversation history |

**Trace context** is what to reach for when an eval's variables live on different spans of one trace: it lets the evaluator aggregate across the whole trace instead of a single span. See [the errors table](/docs/evaluation/troubleshooting#common-errors-and-fixes) for the "not in row" case it solves.

## Summary

**Summary** controls how the evaluator writes up its result, from a raw verdict to a full explanation. Open the **+** menu, choose **Summary**, and pick a preset:

- **None**: return the raw evaluation output with no summary
- **Short**: a brief summary with the key points only
- **Long**: a detailed summary with full context and explanations
- **Concise**: a compact summary focused on the essential insights
- **Custom**: write your own summary criteria, saved as a reusable template
