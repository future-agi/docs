---
title: "Add ground truth"
description: "Attach reference answers to an eval so its judge calibrates against real examples"
---

[Ground truth](/docs/evaluation/concepts/ground-truth) is a dataset of reference rows an eval template can retrieve from at run time, injecting the most similar ones into the judge prompt as calibration examples. This guide attaches a small reference dataset to the `completeness` eval and turns retrieval on.

<Note>
The Ground Truth tab only shows on evals whose output type is `Pass/fail`, `Scoring`, or `Choices`. Code-based reference evals like Fuzzy Match or Answer Similarity compare against a dataset column directly instead; they don't use this tab.
</Note>

## Open the eval's Ground Truth tab

On the eval's detail page, click **Ground Truth**.

<img src="/images/docs/evaluation/guides/ground-truth/empty-state.png" alt="Empty Ground Truth tab reading Add ground truth dataset, upload annotated data to calibrate evaluations with human-scored reference examples, click anywhere to upload" style={{ borderRadius: '5px' }} />
*A fresh eval has no ground truth attached yet*

## Upload a reference dataset

Click anywhere in the empty state to open the **Add Ground Truth** drawer. Choose a file, CSV, Excel, or JSON, up to 50 MB, or pick **Choose from existing dataset** to import rows from a platform dataset you already have.

<img src="/images/docs/evaluation/guides/ground-truth/upload.png" alt="Add Ground Truth drawer with a Choose a file or drag and drop dropzone and a Choose from existing dataset option below it" style={{ borderRadius: '5px' }} />
*Upload a file directly, or import rows from an existing dataset*

## Map variables to columns

After the file loads, name the ground truth set and map each eval template variable to a column in your file. The drawer lists every detected column.

<img src="/images/docs/evaluation/guides/ground-truth/map-variables.png" alt="Configure Dataset step showing gt-sample.csv loaded, a ground truth name field, and a Map Variables section mapping input and output to detected columns" style={{ borderRadius: '5px' }} />
*Map each template variable to the column that holds it, then click Upload*

## Set the reference output and turn on retrieval

Once uploaded, the tab shows three sections: **Inputs** (the same variable mapping), **Reference output** (which column holds the expected answer, plus an optional explanation column), and **Retrieval** (how many similar examples, 1 to 10, get attached per run). Pick the **Output column**, the value the judge should converge toward.

<img src="/images/docs/evaluation/guides/ground-truth/configure.png" alt="Ground truth tab after upload showing the Inputs mapping, a required Output column selector under Reference output, an Examples shown slider under Retrieval, and a 3-row data preview" style={{ borderRadius: '5px' }} />
*Pick the column with the correct answer, and how many similar rows to retrieve per run*

## Turn it on and save

Toggle **Use ground truth** on, then click **Save**. The platform embeds the dataset in the background; once embedding finishes, every eval run retrieves the most similar rows and injects them into the judge prompt.

<img src="/images/docs/evaluation/guides/ground-truth/save.png" alt="Ground truth tab with Use ground truth toggled on, an Embedding generation started toast, and a Saved confirmation" style={{ borderRadius: '5px' }} />
*Saving with Use ground truth on kicks off embedding for retrieval*
