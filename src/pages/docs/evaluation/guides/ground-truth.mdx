title: "Add ground truth to an eval"
description: "Map human-scored rows to an eval, select the expected output, and enable retrieval so the judge can use similar examples when it runs."

---

If reviewers have already scored examples of the decision an eval makes, attach their answers as [ground truth](/docs/evaluation/concepts/ground-truth). The evaluator can retrieve similar rows as reference examples instead of relying on the instructions alone.

<Prerequisites title="Before you start">
- An existing [eval template](/docs/evaluation/concepts/eval-templates) and examples with input columns for its variables.
- An expected answer in each row that matches the eval's [output type](/docs/evaluation/reference/output-types). Use a CSV, Excel (`.xls` or `.xlsx`) or JSON file up to 50 MB, or reuse a dataset you already uploaded.
</Prerequisites>

## Find the eval

1. Open **Build > Evals**.

   The [Evaluations list](/docs/evaluation/guides/explore-playground) supports tag chips, **Filter** and **Columns**.

<img src="/images/docs/evaluation/guides/ground-truth/evals-list-open.png" alt="The Evaluations list under the Evals tab, showing system evals like toxicity, dead_air_detection, and conversation_hallucination with their Type, Eval Type, and Output Type columns" style={{ borderRadius: '5px' }} />

2. Enter `customer` in **Search**.
3. Select **customer_agent_human_escalation**.

   The [human escalation eval](/docs/evaluation/builtin/customer-agent-human-escalation) checks whether an agent hands off at the right time; the detail page shown here identifies a single Agent eval with fixed **Pass/fail** output.

<img src="/images/docs/evaluation/guides/ground-truth/search-select-eval.png" alt="The Evaluations list filtered to customer, showing customer_agent_* evals, with a callout to select the eval you want to provide ground truth for" style={{ borderRadius: '5px' }} />

4. Open **Ground Truth** beside **Eval Details**, **Usage** and **Feedback**.

<img src="/images/docs/evaluation/guides/ground-truth/switch-to-ground-truth-tab.png" alt="The customer_agent_human_escalation eval detail page with Instructions and an Output Type of Pass/fail, and a callout pointing to the Ground Truth tab" style={{ borderRadius: '5px' }} />

## Select the reference rows

1. Click anywhere in the **Add ground truth dataset** area on the empty tab.

   A fresh eval has no ground truth attached. The note reads “Upload annotated data to calibrate evaluations with human-scored reference examples.”

<img src="/images/docs/evaluation/guides/ground-truth/upload-empty-state.png" alt="The empty Ground Truth tab reading Add ground truth dataset, with the subtext about uploading annotated data and Click anywhere to upload" style={{ borderRadius: '5px' }} />

2. In the **Add Ground Truth** drawer, which opens on step 1, **Choose Source**, drop the file into **Choose a file or drag & drop**.

   Alternatively, select the file with **Browse files**, or use **Choose from existing dataset** to reuse data you've already uploaded.

<img src="/images/docs/evaluation/guides/ground-truth/add-ground-truth-drawer.png" alt="The Add Ground Truth drawer on the Choose Source step, with a Browse files dropzone accepting CSV, Excel, or JSON up to 50 MB, and a Choose from existing dataset option below" style={{ borderRadius: '5px' }} />

3. On step 2, **Map Variables**, name the ground truth set.
4. Map each template variable to a detected column.

   Columns are detected automatically. The example maps the `conversation` variable to `recording_url`.

<img src="/images/docs/evaluation/guides/ground-truth/map-variables-upload.png" alt="The Configure Dataset step mapping the conversation variable to the recording_url column, with the detected columns listed and an Upload button at the bottom" style={{ borderRadius: '5px' }} />

5. Select **Upload**.

   The dataset loads with a **Pending** status chip and a **Data Preview** on the right.

## Set the expected answer and save

1. Choose the required **Output column**.

   This column holds the expected answer, and its values must match the eval's output type. The example uses `interested_in_booking`.

2. Optionally select an **Explanation** column that explains each answer.

   The example uses `performance_feedback`.

3. Under **Retrieval**, set **Examples shown** to the number of similar rows to attach to each run.
4. Switch on **Use ground truth** so retrieved examples are injected into the evaluator prompt.
5. Select **Save** to start generating embeddings.

   You should see an **Embedding...** chip with a progress bar on the dataset row while embeddings generate in the background.

6. Wait for embedding to finish.

   Once it completes, every eval run retrieves the most similar rows and injects them into the evaluator prompt as calibration examples.

The top-right icons re-upload or delete the current table.

## If the reference isn't used

- **No expected answer is set.** Select an **Output column** with a value in every row, then save.
- **The rows are available but retrieval is off.** Switch on **Use ground truth**, then select **Save**.
- **Embedding is still in progress.** Retrieval starts on the next eval run once embedding completes. Changing the variable mapping marks the embeddings stale and re-embeds them automatically.
