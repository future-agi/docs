---
title: "Evaluate in CI/CD"
description: "Submit a versioned evaluation from CI, compare it with previous runs, and fail the job when a quality check misses its threshold."
---

Future AGI does not start your CI pipeline. Your CI runner submits the evaluation, waits for the results, and uses the score to decide whether the job passes. For example, Ridgeline Outfitters can check that its support agent still looks up an order before it offers a return.

## Prerequisites

- Create an **Observe** project named `support-agent`, or set `PROJECT_NAME` to an existing Observe project you can access.
- Store `FI_API_KEY` and `FI_SECRET_KEY` as CI secrets. Only expose them to trusted code. Do not run unreviewed pull request code with these credentials.
- Use Python 3.12 in a fresh virtual environment. If it is named `.venv`, run `source .venv/bin/activate`, then install the SDK:

```bash
python -m pip install agent-learning-kit==0.3.7
```

## Set up the pipeline

Save the following script as `evaluate_pipeline.py`. The `trajectory_match` template compares the actions from one agent turn with the expected actions. Replace the sample `actual` sequence with the tool names produced by your agent on a known support ticket; the fixed example alone will not detect changes in your application.

```python
import os
import time
from pathlib import Path
from uuid import uuid4

from fi.evals import Evaluator

project = os.environ.get("PROJECT_NAME", "support-agent")
version = os.environ.get("VERSION") or f"local-{uuid4().hex[:12]}"
baselines = [v.strip() for v in os.getenv("COMPARISON_VERSIONS", "").split(",") if v.strip()]
evaluator = Evaluator()
actual = '["lookup_order", "offer_return"]'
expected = '["lookup_order", "offer_return"]'
submitted = evaluator.evaluate_pipeline(
    project_name=project,
    version=version,
    eval_data=[{
        "eval_template": "trajectory_match",
        "inputs": {"output": [actual], "expected": [expected]},
    }],
)
if not submitted.get("status"):
    raise RuntimeError("Evaluation run was not accepted")
run_id = submitted["result"]["evaluation_run_id"]

deadline = time.monotonic() + 180
while time.monotonic() < deadline:
    response = evaluator.get_pipeline_results(project_name=project, versions=[version, *baselines])
    if not response.get("status"):
        raise RuntimeError("Could not retrieve evaluation runs")
    report = response["result"]
    if report["status"] == "completed":
        break
    if report["status"] != "processing":
        raise RuntimeError(f"Unexpected evaluation status: {report['status']}")
    time.sleep(2)
else:
    raise TimeoutError("No completed evaluation report within three minutes")

runs = report["evaluation_runs"]
current = next(run for run in runs if run["id"] == run_id)
lines = ["| Version | Trajectory match (%) |", "|---|---:|"]
for run in runs:
    score = run["results_summary"].get("trajectory_match")
    lines.append(f"| {run['version']} | {score if score is not None else 'not scored'} |")
summary = "\n".join(lines)
print(summary)
if os.getenv("GITHUB_STEP_SUMMARY"):
    with Path(os.environ["GITHUB_STEP_SUMMARY"]).open("a") as out:
        print(summary, file=out)
score = current["results_summary"].get("trajectory_match")
if score != 100:
    raise SystemExit(f"Expected a complete trajectory match (100%), got {score}")
print(f"Passed: {project} {version} {run_id}")
```

Run `python evaluate_pipeline.py` in the same environment. A matching sequence gives a pipeline summary of **100** (percent). A missing score is not a pass.

## Run on each change

Save this workflow as `.github/workflows/evaluation.yml`. Create a GitHub environment named `eval-ci`, require a reviewer, and store the two Future AGI secrets there. Approve only revisions you trust: the Python script can access those secrets. Fork pull requests are excluded.

```yaml
name: Support agent quality
on:
  pull_request:
    branches: [main]
permissions:
  contents: read
jobs:
  evaluate:
    if: github.event.pull_request.head.repo.full_name == github.repository
    runs-on: ubuntu-latest
    environment: eval-ci
    steps:
      - uses: actions/checkout@v4
        with:
          persist-credentials: false
      - uses: actions/setup-python@v5
        with:
          python-version: '3.12'
      - run: python -m pip install agent-learning-kit==0.3.7
      - run: python evaluate_pipeline.py
        env:
          FI_API_KEY: ${{ secrets.FI_API_KEY }}
          FI_SECRET_KEY: ${{ secrets.FI_SECRET_KEY }}
          VERSION: run-${{ github.run_id }}-${{ github.run_attempt }}
          COMPARISON_VERSIONS: ${{ vars.COMPARISON_VERSIONS }}
```

You can require the job as a status check. The script writes the table to the job log and, in Actions, the job summary. To preview that Markdown locally, run `GITHUB_STEP_SUMMARY=summary.md python evaluate_pipeline.py` and open `summary.md`. It does not need a personal access token or permission to post PR comments.

## Compare versions

Set `COMPARISON_VERSIONS` to a comma-separated list of versions that already exist in the same project. The report includes each version's score; only the **current** run is gated. The service requires a unique version for every submission, including reruns of the same commit. If a result is missing, check the template name, the required input keys, and that every input column is a list of the same length.

To compare two versions of the sample agent, record a baseline and run the check again. Run these commands in the same activated environment:

```bash
export VERSION="baseline-$(python -c 'from uuid import uuid4; print(uuid4().hex[:12])')"
unset COMPARISON_VERSIONS
python evaluate_pipeline.py
export COMPARISON_VERSIONS="$VERSION"
unset VERSION
GITHUB_STEP_SUMMARY=summary.md python evaluate_pipeline.py
```

The second table has two rows, one per version. With the unchanged example, both scores should be 100.
