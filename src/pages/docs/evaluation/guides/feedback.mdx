---
title: "Collect feedback"
description: "Correct a wrong eval result so the judge learns from it"
---

[Feedback](/docs/evaluation/concepts/feedback) is a correction you record on an eval result when you disagree with its verdict. This guide submits feedback on a `completeness` eval run from its evaluation logs, then queues the eval for re-tuning from that correction.

## Find the eval run

On the eval's **Usage** tab, **Evaluation Logs** lists every run: score, result, input, reason, source, and when it ran. Click a row to open it.

<img src="/images/docs/evaluation/guides/feedback/eval-log.png" alt="Evaluation Logs table with columns Score, Result, Input, Reason, Source, and Ran at, one row showing an Error result" style={{ borderRadius: '5px' }} />
*Every run of the eval lands here, whatever the result*

## Open the run

The drawer shows the run's score, result, and input variables, then an **Explanation**, and a **Feedback for Auto Learning** section with an **Add Feedback** button.

<img src="/images/docs/evaluation/guides/feedback/log-drawer.png" alt="Evaluation log drawer showing Score, Result, Status, Source, Ran at, Input Variables, an Explanation, and a Feedback for Auto Learning section with an Add Feedback button" style={{ borderRadius: '5px' }} />
*Feedback for Auto Learning sits at the bottom of every run's detail drawer*

## Add feedback

Click **Add Feedback**.

<img src="/images/docs/evaluation/guides/feedback/add-feedback-btn.png" alt="Evaluation log drawer with the Add Feedback button highlighted under Feedback for Auto Learning" style={{ borderRadius: '5px' }} />
*Add Feedback opens the correction form*

## Fill in the correction

The **Feedbacks for Auto Learning** drawer opens with the run's existing explanation for context. Fill in:

- **Write a right value**: the score or result the eval should have returned
- **What would you like to improve**: what was wrong with the original explanation, as specific as you can be
- **Select one of the options**: **Re-tune** creates a new version of the eval that future runs use, or **Re-calculate and re-tune** does that and also re-runs every past evaluation with the new version

<img src="/images/docs/evaluation/guides/feedback/feedback-form.png" alt="Feedbacks for Auto Learning drawer with the original Explanation, a Write a right value field set to 1, a What would you like to improve textarea filled in, and Re-tune selected" style={{ borderRadius: '5px' }} />
*Give the correct value, explain why, and choose whether to re-tune only or re-tune and re-calculate*

## Submit

Click **Submit feedback**.

<img src="/images/docs/evaluation/guides/feedback/submitted.png" alt="Log drawer with the submitted feedback recorded under Feedback for Auto Learning, showing the reviewer, the correction text, a Re-tune tag, and a Metric queued for retuning toast" style={{ borderRadius: '5px' }} />
*The correction is recorded and the eval is queued for retuning*

The eval template is embedded and stored so future runs can retrieve it as a few-shot example, the same mechanism the [correction loop](/docs/cookbook/evaluation/eval-correction-loop) walks end to end.

## Other places to give feedback

This same correction flow is also reachable from a scored cell in a dataset (hover an eval column and click **Add feedback**) and from a scored span in Observe (open the trace, hover the eval score, click **Add Feedback**). All three write to the same feedback history for the eval.
