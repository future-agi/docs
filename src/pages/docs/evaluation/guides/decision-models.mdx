<Prerequisites title="Before you start">
- A workspace where you can [create an eval](/docs/evaluation/guides/custom-evals)
- A [provider key](/docs/admin-settings/ai-providers) for at least one connection: OpenRouter (every decision model), TypeSafe (Jev), OpenAI (GPT-6 Luna Decisions) or Perplexity (Decider)
- For Python or cURL, a workspace [API key and secret key](/docs/admin-settings/api-keys). These are separate from the provider key.
</Prerequisites>

## Choose the question and output

A **decision model** answers a typed question about your data instead of writing free text. You give it a Pass/fail question, a set of choices or an ordered rubric, and it returns the answer with its probabilities. The evaluator model picker lists 35 decision models next to the Future AGI models: TypeSafe Jev, OpenAI GPT-6 Luna Decisions, Perplexity Decider, Microsoft Decision 1, Solar Decide, Clef, Reflex and more. Each one runs on your own provider key.

<Mermaid chart={`
flowchart LR
    accTitle: How a decision becomes an eval result
    accDescr: The eval's typed question and mapped support reply go to the selected model on its configured connection. The model's probabilities produce a pass or fail, choice or score according to the output settings.
    Q["Typed question and mapped input"] --> M["Model and connection"] --> P["Probabilities"] --> R["Verdict, choice or score"]
`} />

This guide follows one support team. Their assistant answers customers of an outdoor-gear store, and they want three checks on every reply:

<div class="sdk-ref-table max-sm:[&_td]:px-1.5! max-sm:[&_th]:px-1.5!">

| Eval | Question | Output type | Decision model |
|---|---|---|---|
| `resolves_request` | Does the reply resolve the request or give a specific next step? | Pass/fail | GPT-6 Luna Decisions via OpenRouter |
| `ticket_topic` | Which topic is the ticket about? | Choices | Decider 1.2 via Perplexity |
| `reply_tone` | How warm and helpful is the reply? | Scoring | Jev 1.14 via TypeSafe |

</div>

Decision models return typed decisions, not reasoning. Use an LLM judge such as a [Turing model](/docs/evaluation/concepts/evaluator-models) when you need a written explanation for each score.

The model picker never borrows a key or switches to another model. If a key is missing or rejected, the eval stops with an error until you fix the key.

## Create a decision-model eval

<Steps>
  <Step title="Start an LLM-as-a-Judge eval">
    1. Open **Evals**.
    2. Select **Create evaluation**.
    3. Choose the **LLM-As-A-Judge** tab.
    4. Enter `resolves_request` as the name.
    5. Write the question in the prompt, using variables for the customer message and reply:

    ```text
    Customer message: {{customer_message}}

    Assistant reply: {{assistant_reply}}

    Does the assistant reply resolve the customer's request or give a specific next step?
    ```

    Write the question only. The output type you pick below tells the model how to answer.
  </Step>

  <Step title="Open the model picker">
    1. Open **Select model** under the prompt.
    2. Find **Decision models** below the Future AGI models, or filter by name, author or connection in **Search models...**.

    Each row shows the model, its author, the output types it supports and the key state for the selected connection. A **Moving alias** badge marks a `latest` model whose version changes upstream.

    ![The Decision models section of the model picker: 35 models, with Jev 1.14, Jev 1.13 and Jev latest each showing TypeSafe, its output types, its key state and a Connection selector](/images/docs/evaluation/guides/decision-models/picker-decision-models.png)
  </Step>

  <Step title="Choose the model and its connection">
    <img src="/images/docs/evaluation/guides/decision-models/picker.gif" alt="Typing Luna in Search models, choosing the OpenRouter connection for GPT-6 Luna Decisions, and the model appearing under the prompt as GPT-6 Luna Decisions · OpenRouter" style={{ borderRadius: '5px' }} />

    Use the row's **Connection** selector to choose how the model is reached. For example, GPT-6 Luna Decisions can run on **OpenAI** directly or through **OpenRouter**. Every model is available through OpenRouter; Jev, GPT-6 Luna Decisions and Decider also have a direct connection.

    If the connection has no key, selecting it opens **Configure API keys**. You can also add keys in advance in **Settings > AI Providers**.

    1. Search for the provider.
    2. Paste the provider key.
    3. Select **Add**.

       Saving the key selects the model.

    ![Configure API keys opened from the model picker and filtered to OpenRouter, with an API Key field and Add button](/images/docs/evaluation/guides/decision-models/key-drawer-openrouter.png)

    The selected model appears under the prompt as **Model · Connection**, for example **GPT-6 Luna Decisions · OpenRouter**.
  </Step>

  <Step title="Configure the output type">
    Pick **Pass/fail**, **Scoring** or **Choices** under **Output Type**. Each decision model lists the types it supports; a model that does not support the selected type is locked in the picker with the reason.

    <div class="sdk-ref-table max-sm:[&_td]:px-1.5! max-sm:[&_th]:px-1.5!">

    | Output type | What you configure | What the model returns |
    |---|---|---|
    | **Pass/fail** | A **Pass threshold** (50% by default) and optional **Describe a pass (true)** and **Describe a fail (false)** | The probability that the pass description is true, compared with the threshold to give **Passed** or **Failed** |
    | **Choices** | Choice names, each **shown as** Pass, Neutral or Fail | One choice, with the probability of every choice and a confidence |
    | **Scoring** | 2 to 10 **Ordered levels**, lowest first, and a **Pass threshold** | The expected level and a normalized score: the level divided by `level count − 1` |

    </div>

    For `resolves_request`, set the descriptions:

    - **Describe a pass (true)**: `The reply resolves the request or gives a concrete next step, such as a tracking number, a refund or return instructions.`
    - **Describe a fail (false)**: `The reply deflects, stays vague or gives the customer nothing to act on.`

    ![resolves_request with GPT-6 Luna Decisions · OpenRouter, Pass/fail output, a 50% pass threshold and the pass and fail descriptions](/images/docs/evaluation/guides/decision-models/passfail-configured.png)
  </Step>

  <Step title="Test it on real examples">
    1. Open the **Custom** tab in **Test Evaluation**.
    2. Paste a JSON object with one key per variable:

    ```json
    {
      "customer_message": "Where is my order #48213? It was supposed to arrive Tuesday.",
      "assistant_reply": "Sorry for the wait. Order #48213 left our Denver warehouse on Monday with UPS, tracking number 1Z84A9E70312345678. UPS now expects to deliver it Thursday by 8 pm."
    }
    ```

    3. Select **Test Evaluation**.

    The result shows the verdict and the decision details: the probability, the model you requested, the model the provider returned, the connection and the token usage.

    Test a reply that should fail before you save.

    4. Replace the customer message with `"My package says delivered but it's not here."`.
    5. Replace the reply with `"We'll look into it."`.
    6. Select **Test Evaluation** again.

    This reply returns **Failed**. In the recording, the tracking reply passes with probability 1.00 and the vague reply fails with probability 0.00.

    <img src="/images/docs/evaluation/guides/decision-models/test-passfail.gif" alt="Test Evaluation run twice: the tracking-number reply returns Pass with probability 1.00, then the reply that only says it will look into it returns Fail with probability 0.00" style={{ borderRadius: '5px' }} />

    ![Test Evaluation result for the tracking-number reply: Pass, probability 1.00 against a 0.50 threshold, requested and returned model, OpenRouter connection and token usage](/images/docs/evaluation/guides/decision-models/passfail-result-pass.png)
  </Step>

  <Step title="Save the eval">
    Select **Save Evaluation**. The eval keeps its model and connection, and every place that runs it uses that model unless you choose another one for a run.
  </Step>
</Steps>

## Choices: route tickets by topic

`ticket_topic` asks only about the customer message:

```text
Customer message: {{customer_message}}

Which topic is this support ticket about?
```

1. Select **Choices** as the output type.
2. Enter the four topics: `Billing`, `Shipping`, `Returns and exchanges` and `Product question`.
3. Set each topic to **Neutral**.

   A topic identifies what the ticket is about, not whether the reply was good.

4. Choose **Decider 1.2**.
5. Select the **Perplexity** connection.

<img src="/images/docs/evaluation/guides/decision-models/choices.gif" alt="Adding four choices shown as Neutral, picking Decider 1.2 on its Perplexity connection, and testing the duplicate-charge ticket, which returns Billing" style={{ borderRadius: '5px' }} />

For `"I was charged twice for the Ridgeline 2 tent."`, Decider 1.2 chooses **Billing** with a probability of 1.00. The result lists the probability of every choice.

![Choices result: Chosen label Billing with the distribution across the four topics, confidence, requested and returned model, and usage](/images/docs/evaluation/guides/decision-models/choices-result.png)

## Scoring: rate the tone

`reply_tone` uses an ordered rubric:

```text
Customer message: {{customer_message}}

Assistant reply: {{assistant_reply}}

How warm and helpful is the tone of the assistant reply?
```

1. Choose **Jev 1.14**.
2. Select the **TypeSafe** connection.

   You should see **Jev 1.14 (pinned)** under the prompt.

3. Select **Scoring**.
4. Use **Add level** to enter `Dismissive`, `Neutral` and `Warm and helpful`, in that order.

<img src="/images/docs/evaluation/guides/decision-models/scoring.gif" alt="Picking Jev 1.14, choosing Scoring, adding the levels Dismissive, Neutral and Warm and helpful, and testing a dismissive reply" style={{ borderRadius: '5px' }} />

Jev places `"That's not something I can help with."` at the **Dismissive** level, and the duplicate-charge refund at **Warm and helpful**.

![Scoring result for the dismissive reply: expected level, normalized score and the probability of each level](/images/docs/evaluation/guides/decision-models/score-result.png)

## Run a saved eval from code

The dashboard examples above use the eval editor and dataset grid. To run a saved eval by name from Python, use Agent Learning Kit `0.3.7`; the cURL example uses the [REST API](/docs/api). Both use the saved model and connection by default. A decision model ID overrides the model for one call.

<div class="sdk-ref-table max-sm:[&_td]:px-1.5! max-sm:[&_th]:px-1.5!">

| Shell variable | Value | Where to find it |
|---|---|---|
| `FI_API_KEY` | Workspace API key | **Build > Keys** |
| `FI_SECRET_KEY` | Matching secret key | Shown when you create the pair |

</div>

For the Python example, install the package version in the listing. Save the listing as `check_decision.py` and run `python check_decision.py` after setting the two variables.

<CodeGroup titles={["Python", "cURL"]}>

```python Python
# python -m pip install agent-learning-kit==0.3.7
# export FI_API_KEY=... FI_SECRET_KEY=...
from fi.alk.evals import Evaluator

evaluator = Evaluator()

result = evaluator.evaluate(
    eval_templates="resolves_request",
    inputs={
        "customer_message": "My package says delivered but it's not here.",
        "assistant_reply": "We'll look into it.",
    },
)
print(result.eval_results[0].output)  # Failed
print(result.eval_results[0].reason)  # GPT-6 Luna Decisions probability 0.00 vs threshold 0.50 → Fail

# Same eval inputs, another decision model for this call only
topic = evaluator.evaluate(
    eval_templates="ticket_topic",
    inputs={"customer_message": "My package says delivered but it's not here."},
    model_name="decision/openrouter/upstage/solar-decide",
)
print(topic.eval_results[0].output)  # {'score': 0.5, 'choice': 'Shipping'}
```

```bash cURL
curl -X POST "https://api.futureagi.com/sdk/api/v1/new-eval/" \
  -H "X-Api-Key: $FI_API_KEY" \
  -H "X-Secret-Key: $FI_SECRET_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "eval_name": "ticket_topic",
    "inputs": {"customer_message": "My package says delivered but it'"'"'s not here."},
    "model": "decision/openrouter/upstage/solar-decide"
  }'
```

</CodeGroup>

In cURL, leave out `"model"` to use the model saved with the eval. The response lists each result with its `output` and `reason`:

```json
{
  "status": true,
  "result": [
    {
      "evaluations": [
        {
          "name": "ticket_topic",
          "reason": "Solar Decide chose \"Shipping\" (probability 1.00)",
          "runtime": 562,
          "output": {"score": 0.5, "choice": "Shipping"},
          "output_type": "choices",
          "eval_id": "a6519263-1b35-4dc1-8c19-b08e41154901"
        }
      ]
    }
  ]
}
```

This guide covers the dashboard, Python and cURL. It does not cover TypeScript, `fagi` or the [MCP server](/docs/falcon-ai/guides/use-the-mcp-server).

### Inputs and limits

Decision models read text and JSON only. The mapped input can be up to 120,000 UTF-8 bytes, except for these models:

| Model | Limit or behavior |
|---|---|
| Clef, Clef Flash | 2,000 UTF-8 bytes of input. A larger input is refused rather than truncated. |
| Joey 1, Elephant 1, Mammoth 1 | 48,000 UTF-8 bytes of input |
| Kev 4B | 24,000 UTF-8 bytes of input |
| Span-01, Span-01 Lite, Span-01 Lite (free) | Pass/fail only |
| Tev1 4B Experimental | 2 to 24 choices |
| Decisions Fast (free) | Researches the live web, so your inputs may be used in web queries |
| Mercury Decide | Listed but not selectable: OpenRouter has no active endpoint for it |

Decision models do not use few-shot examples, tools, knowledge bases or internet checks. If the eval already has few-shot datasets selected, the editor keeps them, and the decision model does not use them. See [Jev evaluators](/docs/evaluation/concepts/evaluator-models#jev-typesafe-system-one) for the controls the editor disables.

A **Moving alias** (`Jev latest`, `Decider latest`, `d1 latest`) follows the provider's newest version of that model, never a different model. Pick a versioned model when you need results that stay comparable over time.

### Costs

Each call is billed by the provider to the key you saved. For the free models, the picker notes: "Provider inference is free; FutureAGI evaluation charges still apply." Jev's Cloud fee is described in the Jev evaluators section linked above.

## Troubleshooting

### A test or run fails

| Message | What to do |
|---|---|
| `OpenAI rejected the request with the saved API key. Check the key and its model permissions in Settings → AI Providers.` | The provider refused the key for this model. Update the key in **Settings → AI Providers**, or choose another connection, such as OpenRouter, in the model picker. |
| `Decision evaluators are not available in this build.` | The deployment was built without Future AGI's `ee` code, which runs decision models. Use a standard Future AGI build. |

### A model is locked in the picker

A locked row shows the reason in place of its key state:

| Reason | What to do |
|---|---|
| `Span-01 does not support Choices. Choose another model or output type.` | The model cannot answer the selected output type. Change the output type or the model. |
| `Tev1 4B Experimental requires 2 to 24 choices.` | Add or remove choices to fit the model's range. |
| `No active OpenRouter endpoint. Choose another decision model.` | The model has no working endpoint. Choose another decision model. |
