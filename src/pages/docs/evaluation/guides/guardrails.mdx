---
title: "Set up guardrails"
description: "Turn on a safety check at the gateway and watch it block a live request"
---

A [guardrail](/docs/evaluation/concepts/guardrails) checks a request inline at the Protect gateway and acts on it, instead of scoring it after the fact. This guide turns on prompt-injection detection with a blocking action, so any request the check flags never reaches the provider.

## Open the guardrails dashboard

In the sidebar, go to **Gateway → Guardrails**. The **Overview** tab shows your guardrail count and, once you have any configured, a table of each one's type, action, and stage. Click **Rules** to configure checks.

<img src="/images/docs/evaluation/guides/guardrails/rules-tab.png" alt="Guardrails Rules tab listing AI-Powered Checks including Future AGI Eval, Llama Guard, Azure Content Safety, Presidio PII, Lakera Guard, and AWS Bedrock Guardrails, each with a toggle and an edit pencil" style={{ borderRadius: '5px' }} />
*Rules groups checks under AI-Powered Checks and, further down, Rule-Based Checks*

## Pick a check

Scroll past **AI-Powered Checks** (external ML models such as Llama Guard, Azure Content Safety, or Lakera Guard) to **Rule-Based Checks**: PII Detection, Content Moderation, Prompt Injection, Keyword Blocklist, Secret Detection, Topic Restriction, Language Detection, and System Prompt Protection. This example uses **Prompt Injection**.

<img src="/images/docs/evaluation/guides/guardrails/rule-based-checks.png" alt="Rule-Based Checks list showing PII Detection, Content Moderation, Prompt Injection, Keyword Blocklist, Secret Detection, Topic Restriction, Language Detection, and System Prompt Protection, each with a toggle and an edit pencil" style={{ borderRadius: '5px' }} />
*Prompt Injection is one of eight rule-based checks*

## Configure the check

Click the pencil icon on the check's row. In the dialog, toggle **Enabled**, pick an **Action**, `Block`, `Warn`, or `Log`, and set the **Confidence Threshold**, from 0.0 to 1.0, that decides how sure the check must be before it fires.

<img src="/images/docs/evaluation/guides/guardrails/configure-check.png" alt="Configure Prompt Injection dialog with an Enabled toggle, an Action dropdown set to Block, and a Confidence Threshold slider set to 0.80" style={{ borderRadius: '5px' }} />
*Enable the check, choose what it does when it fires, and how sure it needs to be*

- **Block** rejects the request before it reaches the provider
- **Warn** lets the request through and flags it
- **Log** records the violation with no change to the request or response

Click **Save** on the dialog.

## Save and activate

Back on Rules, a banner reads **You have unsaved changes. Save to push guardrail config to the gateway.** Click **Save & Activate** to push the change live.

<img src="/images/docs/evaluation/guides/guardrails/save-activate.png" alt="Guardrails Rules tab with an unsaved-changes banner and the Save and Activate button highlighted at the top right" style={{ borderRadius: '5px' }} />
*Nothing reaches the gateway until you click Save & Activate*

## Confirm it's live

Go back to **Overview**. The new guardrail lists with its type, whether it's enabled, its action, and its stage, `Before LLM` for a check that runs before the provider call.

<img src="/images/docs/evaluation/guides/guardrails/live.png" alt="Guardrails Overview tab showing one active guardrail named injection-detector, type Prompt Injection, action block, stage Before LLM, with a Config saved and activated toast" style={{ borderRadius: '5px' }} />
*The guardrail is active: type, action, and stage all show in the Overview table*

<Note>
This dashboard configures one shared set of checks for your whole organization. For a policy scoped to a single project or virtual key, with its own `mode` (`enforce` or `monitor`), use the `/agentcc/guardrail-policies/` API described in [Guardrails](/docs/evaluation/concepts/guardrails#guardrail-structure).
</Note>
