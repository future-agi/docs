A [guardrail](/docs/evaluation/concepts/guardrails) helps you decide whether to send a request to your model or show its reply to a user. You can enforce a policy in the gateway or check text directly in your application. This guide uses a local rule to keep warehouse-only references out of a Ridgeline Outfitters support conversation.

## Through the gateway

If your traffic already flows through Agent Command Center, you can turn on checks there and guard every request without touching application code: pick a check (prompt injection, PII, content moderation, and more), choose whether it blocks, warns, or logs, and push the config live. The [Command Center Gateway quickstart](/docs/quickstart/command-center-gateway) covers how requests flow through the gateway, and [Guardrails in the Gateway](/docs/command-center/features/guardrails) covers the checks, policies, and third-party integrations.

## Set up a guardrail in Python

The `RegexScanner` in Agent Learning Kit checks text in your process. It does not call a model, require API keys, or send a record to the dashboard. In a fresh Python 3.12 virtual environment named `.venv`, run `source .venv/bin/activate`, then install the kit:

```bash
python -m pip install agent-learning-kit==0.3.7
```

Run the Python blocks in order in the same session.

### Choose your rule

Suppose warehouse-only references start with `WH-` followed by six digits. Check that exact format rather than blocking every order number. The scanner returns `passed=False` when the pattern matches. `matched_patterns` gives you the rule names without exposing the matching text.

```python
from fi.evals.guardrails.scanners import RegexPattern, RegexScanner

warehouse_ref = RegexScanner(custom_patterns=[
    RegexPattern(name="warehouse_ref", pattern=r"\bWH-\d{6}\b")
])
check = warehouse_ref.scan("Check the bin for WH-123456.")
print(check.passed)            # False
print(check.matched_patterns)  # ['warehouse_ref']
```

### Act on the verdict

A scanner returns a decision; it doesn't prevent a model call or rewrite a reply. Make that branch explicit. Only pass text forward when the check succeeds, and don't log the original text when you block it.

```python
def support_turn(message, generate_reply):
    if not warehouse_ref.scan(message).passed:
        return "Please use your order number instead of a warehouse reference."
    reply = generate_reply(message)
    if not warehouse_ref.scan(reply).passed:
        return "I'll ask a support specialist to check that for you."
    return reply
```

### Guard input and output both

Here the reply function stands in for your model call. The first message is blocked before that function runs. The second passes the input check, but the proposed reply is withheld. The last turn passes both checks.

```python
def pickup_reply(message):
    return "Your tent is ready for pickup."

print(support_turn("Look up WH-123456.", pickup_reply))
print(support_turn("Where is my tent?", lambda message: "It is in bin WH-123456."))
print(support_turn("Where is my tent?", pickup_reply))
```

A pass means only that the message did not match this reference format. A pattern cannot decide whether a reply is abusive or biased, or whether someone is authorized to see an order.

### When to use hosted Protect

If you need model-based screening, [Protect](/docs/sdk/protect) accepts rules for `toxicity`, `prompt_injection`, `data_privacy_compliance`, and `bias_detection`. It requires Future AGI credentials and access to the hosted `protect` model. Its binary Flash mode requires the separate `protect_flash` model. Check that your deployment offers the model before using either path. Don't treat a service failure or an unfinished rule as a clean verdict.
