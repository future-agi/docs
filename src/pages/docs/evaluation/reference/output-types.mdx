## About

Every eval produces a result for each row or call it scores. This page is the lookup reference for those results: the output types a template can return, the range each one uses, how each evaluation method arrives at a score, and the exact fields you read back.

For the conceptual overview of results, see [Output types](/docs/evaluation/concepts/output-types). This page is the detailed reference you come back to when you need an exact value or field name.

---

## Output types

The output type is fixed by the eval template. It decides the shape of every result that template produces.

| Output type | Value | Range | Example evals |
|---|---|---|---|
| **Pass/Fail** | `1.0` for pass, `0.0` for fail | `{0.0, 1.0}` | Toxicity, PII, Is JSON, Prompt Injection |
| **Score** | A number | `0`–`100` | Groundedness, Context Relevance, Completeness |
| **Deterministic choice** | A category label from a fixed set | one label per result | Tone, Language handling, Intent |

Pass/Fail is a binary verdict. Score is a graded percentage for quality that is not simply right or wrong. A deterministic choice returns one label from a predefined set, which is useful for classification rather than grading.

---

## How each method scores

Every built-in eval uses one of four scoring methods. The method decides how the output value above is produced.

| Method | How it scores | Output it produces |
|---|---|---|
| **LLM as Judge** | An evaluator model reads the inputs against the template criteria and returns a verdict with a reason | Pass/Fail or Score |
| **Deterministic / Rule-based** | A rule checks the output directly, with no model call | Pass/Fail |
| **Statistical Metric** | A formula compares the output to a reference value (BLEU, ROUGE, embedding similarity, Recall@K) | Score |
| **LLM as Ranker** | An evaluator model ranks each candidate against the criteria | A ranking score per item |

The [Built-in evals reference](/docs/evaluation/builtin) lists the method for every template, so you can tell before you run whether a result comes from a model, a rule, or a formula.

---

## The result object

Each individual result has three parts, whichever output type it uses.

| Field | Description |
|---|---|
| **Output** | The result value: `1.0` / `0.0` for pass/fail, a `0`–`100` score, or a category label |
| **Reason** | A plain-language explanation from the evaluator describing why it assigned that result |
| **Eval ID** | A unique identifier for the run, used to retrieve async results |

The reason field is the fastest way to diagnose a failure. Instead of re-reading each response by hand, you read the reason to see exactly what drove the pass or fail.

---

## Turning a score into pass or fail

Pass/Fail templates already return a verdict. Score templates return a number, so anywhere you need a yes/no decision you set a threshold and the platform compares the score against it:

- [Guardrails](/docs/evaluation/concepts/guardrails) gate a request on whether the score clears the threshold you set.
- [CI/CD runs](/docs/evaluation/guides/cicd) fail the check when a score drops below the bar you define for that template.

The score itself does not change; the threshold is what decides pass or fail for a graded eval.

## Aggregates

When you run an eval across a dataset, Future AGI rolls the per-row results up into summary metrics.

| Aggregate | What it reports | Applies to |
|---|---|---|
| **Pass rate** | Percentage of rows that passed | Pass/Fail templates |
| **Average score** | Mean score across all rows | Score templates |
| **Distribution** | Breakdown of results across categories | Deterministic choice templates |
| **Trend** | How results move across runs over time | All templates |

These appear in the evaluation summary view and are tracked per template per dataset run, which gives you a versioned history of how quality changes.

## Reading results from the SDK

The SDK returns the same fields as the platform. After an `evaluator.evaluate()` run, read them off each result:

```python
print(result.eval_results[0].output)   # 1.0, a 0-100 score, or a label
print(result.eval_results[0].reason)   # why the evaluator scored it that way
```

For long or large-batch runs the SDK returns an `eval_id` immediately. Retrieve the result once the run finishes:

```python
final = evaluator.get_eval_result(eval_id)
```

See [SDK & API](/docs/evaluation/reference/sdk-api) for the full function signature and engine routing.
