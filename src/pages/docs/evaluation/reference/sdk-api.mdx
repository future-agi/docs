## Evals from code

Use `fi.evals.evaluate()` to score an output with a local metric, a hosted Turing template, or a custom LLM judge.

This page is the reference for reaching evals programmatically. For the full SDK docs, see the [SDK evals section](/docs/sdk/evals).

## Install and authenticate

For new Python evals, install `agent-learning-kit` in a [fresh virtual environment](/docs/sdk#quickstart). Activate it with `source .venv/bin/activate` if you named it `.venv`. The kit provides `fi.evals`; if you also use the `futureagi` platform SDK, install it in a separate environment because the packages share the `fi` namespace.

```bash
python -m pip install agent-learning-kit==0.3.7
```

Local string metrics need no API key. Only set Future AGI credentials if you are calling a hosted Turing template:

```bash
export FI_API_KEY="your-api-key"
export FI_SECRET_KEY="your-secret-key"
```

Find both under **Settings → API Keys** in the platform.

For the OpenAI judge example, also set `OPENAI_API_KEY`. This engine uses LiteLLM and bills your model provider instead of using your Future AGI credentials.

## One function, three engines

`evaluate()` picks the engine from what you pass. You never call a different function to switch engines.

| You pass | Engine | Key needed |
|---|---|---|
| A local metric name without a model | Local heuristic | No |
| A hosted template and `model="turing_flash"` | Cloud (Turing) | `FI_API_KEY` + `FI_SECRET_KEY` |
| `prompt=` + `engine="llm"` + `model=` | LLM-as-Judge | Model provider key |

Force an engine with `engine="local"`, `engine="turing"`, or `engine="llm"`.

There's also a combined mode: a supported local metric plus `model=` and `augment=True` runs the local heuristic first, then hands its score and reasoning to the LLM for refinement.

Each of these examples grades the same pickup notification, but asks a different question.

**Local keyword check.** No model call is made:

```python
from fi.evals import evaluate

local = evaluate("contains", output="Your tent is ready for pickup.", keyword="pickup")
print(local.score)   # 1.0
print(local.passed)  # True
print(local.reason)  # Keyword 'pickup' found
```

**Custom judge.** This call sends the reply and your criteria to OpenAI:

```python
from fi.evals import evaluate

judge = evaluate(
    prompt="Score 1 if the reply clearly says the item is ready for pickup, otherwise 0.",
    output="Your tent is ready for pickup.",
    engine="llm",
    model="gpt-4o-mini",
)
if judge.score is None:
    raise RuntimeError(judge.error or judge.reason or "No judge score returned")
print(judge.score)
```

**Hosted template.** Save this as `score.py` and run `python score.py`. The last line is the ID of the evaluation stored in Future AGI:

```python
from fi.evals import evaluate

hosted = evaluate("toxicity", output="Your tent is ready for pickup.", model="turing_flash")
if hosted.score is None:
    raise RuntimeError(hosted.error or hosted.reason or "No hosted score returned")
print(hosted.score)
print(hosted.metadata["eval_id"])
```

## What a result contains

A single eval returns an `EvalResult`. A list of metrics returns one result per metric.

| Field | Description |
|---|---|
| `eval_name` | The metric that produced this result |
| `score` | The numeric result: `1.0` / `0.0` for pass/fail metrics, or a numeric value for a scored metric; `None` when there is no numeric result |
| `passed` | The boolean verdict, or `None` if no verdict can be derived |
| `reason` | Why the evaluator scored it that way |
| `latency_ms` | How long the eval took |
| `status` | `completed` or `failed`; also check that the requested score is present |
| `error` | Engine error when available; some hosted failures report details in `reason` |
| `metadata` | Extra engine-specific detail about the run |

When a metric returns only a score, `passed` derives from `score >= 0.5`.

```python
from fi.evals import evaluate

# Batch: several metrics in one call
results = evaluate(["contains", "is_json"], output='{"greeting": "Hello"}', keyword="Hello")
for r in results:
    print(r.eval_name, r.passed)
```

<Warning>
  The same engine and model settings apply to every metric in a batch. Use separate calls if one metric must run locally and another must run on the platform.
</Warning>

## Function signature

Inspect the callable in your installed kit to see its keyword-only options and return type:

```python
from inspect import signature
from fi.evals import evaluate

print(signature(evaluate))
```

Inputs the metric needs (`output`, `context`, `expected_response`, and so on) are passed as keyword arguments. The [Built-in evals reference](/docs/evaluation/builtin) lists the required inputs for each template.

`generate_prompt=True` turns a short plain-English `prompt` into full grading criteria before the run; it needs a `model=`.
