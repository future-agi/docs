Your application can fetch a prompt by name and compile it into messages. The Python and TypeScript SDKs return different objects, and only the Python SDK caches fetched templates. Those differences matter when you pick up prompt changes or handle a failed fetch.

Before you start, follow [Install and authenticate](/docs/prompt/reference/sdk-api#install-and-authenticate). The examples below assume an existing prompt named `support-agent` with `company_name` and `customer_question` variables. Replace the name and variables with your own.

## Fetch and compile

<CodeGroup titles={["Python", "TypeScript"]}>

```python Python
from fi.prompt import Prompt

prompt = Prompt.get_template_by_name("support-agent")
messages = prompt.compile(
    company_name="Acme",
    customer_question="Where is my order?",
)

print(messages)
```

```typescript TypeScript
import { Prompt } from "@future-agi/sdk";

const template = await Prompt.getTemplateByName("support-agent");
const prompt = new Prompt(template);
const messages = prompt.compile({
  company_name: "Acme",
  customer_question: "Where is my order?",
});

console.log(messages);
```

</CodeGroup>

Python's `Prompt.get_template_by_name()` returns a `Prompt`, so you can call `compile()` on it directly. TypeScript's `Prompt.getTemplateByName()` returns a `PromptTemplate`; wrap it in `new Prompt(template)` before calling `compile()`.

## Python: account for the cache

The Python SDK keeps an in-memory cache in each process. It is not shared between processes or hosts.

| State | What happens |
|---|---|
| Successful fetch | The SDK stores the fetched template in the process's cache. |
| Fresh cache entry | The call returns a `Prompt` using the cached template instead of fetching it again. The default freshness window is **300 seconds (5 minutes)** from when the entry is stored. |
| Expired or missing entry | The next call attempts a live fetch and waits for it. This fetch path does not refresh in the background. |

A prompt change is not necessarily visible to a process that still has a fresh cached entry. Each process fetches independently, so different application instances can pick up a change at different times.

### A failed refresh can return stale data

If a live refresh fails, the SDK can return a previously cached template instead of raising an error. That template reflects an earlier successful fetch, not necessarily the current prompt.

<Note>
Stale fallback is conditional, not a guarantee for every fetch failure. Handle fetch exceptions even after a successful fetch. A new process with no cached template has no stale copy to use.
</Note>

The five-minute TTL is a freshness window, not a maximum age for the template your application can receive: a stale fallback can be older than five minutes. Do not assume that every application instance picks up a prompt change within five minutes.

## TypeScript: plan for network requests

`Prompt.getTemplateByName()` makes network requests rather than using the Python cache. It has no built-in stale-template fallback. Calling it for each application request adds a network dependency to each request.

If you need a cache in your TypeScript application, manage its lifetime and failure behavior explicitly. Do not assume Python's five-minute freshness window or stale fallback applies.
