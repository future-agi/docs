---
title: "Commit & compare versions"
description: "Turn a working draft into a version you can point to, then compare a few side by side"
---

A prompt starts out as a [draft](/docs/prompt/concepts/versions-and-labels) you're still editing. Running it once and committing turns that draft into a version, one that sticks around after you move on to the next edit. This guide covers both ways to commit, setting an already-committed version as default on its own, and comparing versions once you have more than one.

<Steps>
  <Step title="Run the prompt">
    Commit stays disabled until the draft has produced an output. Hover the greyed-out button and the tooltip explains why: **"Please run the prompt before saving and committing."**
  </Step>
  <Step title="Open Commit">
    Once you've run it, open the **Commit** button in the editor header, or choose **Save and commit** from the more-actions menu next to it. Both lead to the same place.
  </Step>
  <Step title="Write a commit message">
    Either route opens the **Commit changes to prompt** dialog. Describe what changed in the **Commit message** field.
  </Step>
  <Step title="Choose how to save it">
    Pick **Commit** to save the version as is, or **Commit and set as a default version** to save it and also make it the template's default in the same step.
  </Step>
</Steps>

## Set an existing version as default

You don't have to decide this at commit time. From the more-actions menu on any version you've already committed, choose **Set as default** to make it the template's default without touching anything else about it.

## Compare versions

Select the versions you want to look at together and open them side by side.

<Warning>
Three is the hard cap. Try to compare a fourth and the platform rejects it outright, so pick your set deliberately rather than adding versions as you go.
</Warning>

## Promoting a version

Comparing tells you which version should be live. Making it live isn't a commit or compare action, it's a [labelling](/docs/prompt/concepts/versions-and-labels) one: you point the Production label at the version you picked instead of changing the version itself. For now, do that from the [SDK & API](/docs/prompt/reference/sdk-api) reference.
