A [prompt](/docs/prompt) starts out as a draft you're still editing. Running it once and committing turns that draft into a version, one that sticks around after you move on to the next edit. Before promoting it, compare what the new version returned with the output from the previous one. The comparison shows its messages, model settings and last saved output alongside the alternatives.

<Prerequisites title="Before you start">
- Open an editable template, such as `support-agent` from [Create a prompt](/docs/prompt/guides/create-a-prompt).
- For a comparison, you need another version of that template in its history.
</Prerequisites>

## Commit the draft

1. Click **Run Prompt**.

   [Running a prompt](/docs/prompt/guides/run-a-prompt) produces the output, clears the **Draft** badge beside the version number and enables **Commit** when just one version is open.

2. Click **Commit** in the header.
3. In **Commit message**, describe the change, for example “Added escalation trigger for refund requests”.

   Both save options in **Commit changes to prompt** stay disabled while the message is empty.

4. Choose **Commit** to save the version, or **Commit and set as a default version** to save it as the template's default.

   The dialog closes. Look for a confirmation such as `Commit for <prompt> <version> successful` (or `...and set as default`).

5. Open **Commit History** to check that the new version is listed.

## Compare versions

1. Click **More** in the editor header.
2. Choose **History**.

   **History** includes drafts; **Commit History** includes only committed versions.

3. Click **Select to compare**.

   Checkboxes appear next to each version.

4. Check the other version you want to compare.

   The current version is already checked and locked. It counts toward the three-version limit, so you can add at most two others.

5. Click **Compare**, which appears once you've checked at least one version.

   You should see one panel per selected version, each with its own messages, last saved output and model configuration. The model configuration is often the detail that differs most between versions.

## Promote the version you picked

Assign the **Production** [label](/docs/prompt/concepts/versions-and-labels) to the chosen version. This changes which version the label points to, not the content of the version. Setting a default during commit and moving the Production label are separate decisions.

## If a control is disabled

- **Commit:** The tooltip says “Please run the prompt before saving and committing”. If you've already run it, check that only one version is open; the same tooltip appears during a comparison.
- **Version checkbox:** “Compare limit is upto 3 version only, Deselect other options to select this one” means three are selected. Deselect a version other than the locked current one, then select its replacement.
