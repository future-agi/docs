---
title: "Evaluate prompt outputs"
description: "Attach an eval template to a prompt's output, then read the score beside it"
---

Attach an eval template to a [prompt template](/docs/prompt/concepts/understanding-prompts) and its score shows up right next to the output it scored, inside the same editor you ran the prompt in.

## Run the prompt first

The **Evaluation** tab stays disabled until the template has at least one output to score. Open it too early and the tab shows why, in its own tooltip: "You need to submit at least one prompt and get an output before accessing the evaluation." Run `support-agent` once and the tab unlocks.

## Attach an eval

Open **Evaluation** and click **Add Evaluations**. Pick a template from the list, for example `customer_agent_human_escalation`, then map its required inputs to `support-agent`'s own variables (`company_name`, `customer_question`) or to the output itself. [Evaluations](/docs/evaluation) covers what a template checks and how it arrives at that score; this page only covers wiring one to a prompt.

Save the mapping and the eval is attached and scores the output you already have.

## Read the results next to each output

Each attached eval's score lands in its own column, next to the output it scored, so you can scan outputs and scores together instead of cross-referencing two views.

The table starts narrow: outputs and scores only. Two toggles widen it. **Show Prompts** adds the prompt text itself as a column, and **Show Variables** adds each variable's value as its own column, useful when a low score traces back to what the model was actually given rather than the model itself.

## Run the same evals across several versions

You don't have to reattach an eval to every version by hand. Once a template has more than one [committed version](/docs/prompt/concepts/versions-and-labels), pick the eval configs you want and the versions to run them against, and Future AGI runs all of them in one pass.

<Note>
Two rules gate that call. At least one eval config has to be selected, or the run never starts. And every eval config you pass has to actually belong to this template: an id copied from a different prompt's evaluation setup is rejected, not silently skipped.
</Note>

## Remove an eval config

Delete an eval config from the Evaluation tab, and it's gone: it drops off the list, its column disappears from the results table, and it won't run again.
