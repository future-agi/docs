Two versions of a [support prompt](/docs/prompt/concepts/understanding-prompts) can answer the same refund question in different tones. Attach an [Is Polite eval](/docs/evaluation/builtin/is-polite) to score the replies side by side; its verdict is about courtesy, not whether either answer states the right policy.

<Prerequisites title="Before you start">
- [Run the prompt](/docs/prompt/guides/run-a-prompt) at least once. The **Evaluation** tab needs an output to score.
- For the comparison, have two [committed versions](/docs/prompt/concepts/versions-and-labels) of the same template.
</Prerequisites>

## Match the eval to the evidence

`is_polite` needs one string, `output`. The support prompt provides it as `model_output`. By contrast, [customer agent human escalation](/docs/evaluation/builtin/customer-agent-human-escalation) needs a conversation: a single reply isn't that conversation. Check the [eval template](/docs/evaluation/concepts/eval-templates) requirements before attaching it, and pick one whose required inputs match what the prompt produces. See [Evaluations](/docs/evaluation) for what an eval checks and how it arrives at a score; this page only covers attaching one to a prompt.

## Attach the eval to the existing output

1. Open **Evaluation** in `support-agent`.
2. Select **Add Evaluations**.
3. Choose `is_polite`.
4. Map its required `output` input to `model_output`.

   For a different eval, the available sources also include `model_input` and template variables such as `customer_question` and `company_name`.

5. Give the eval a name.
6. Select **Save Eval**.

   You should see a new score column beside the output it checks. If saving stops with **Required input mappings must be filled**, complete every required mapping first.

## Read the score in context

Keep **Show Variables** on (the default) to see which question produced the reply. For example, find `Acme` and `Do you offer refunds after 30 days?` in the same row. Read the reply and its score together. Is Polite returns Pass when the response is polite and respectful, and Fail when it's not. If a low score surprises you, check the variable values first: the cause can be what the model was given, not the model itself.

Turn **Show Variables** off for a narrower table. **Show Prompts**, off by default, adds a header band with the messages above the output columns.

## Compare versions on the same input

1. Select **+** in the comparison column header.
2. In **Add version to compare**, select the second version.

   The current version is already selected and locked; you can add one or two more versions.

3. Select **Compare**.

   You should see the selected versions' output and score columns beside one another.

4. Reopen **Add Evaluations**.
5. Select the attached politeness eval.
6. Select **Run Selected**.

   The eval runs against every version in the table, in one pass. To rerun every attached eval instead, leave them unchecked and select **Run All**.

7. Compare the versions' verdicts for the same input row.

   If the scores differ, read both replies before attributing the difference to the prompt. The template needs at least one attached eval before there's anything to run, and an eval that belongs to a different template is rejected.

The [evaluator SDK guide](/docs/sdk/evals/evaluate) covers scoring supplied inputs directly. A standalone score is not an eval attached to a prompt or a rerun of the editor's comparison table.

## Remove an eval

Removal permanently deletes the eval's results from this template.

1. Open **Add Evaluations**.
2. Select the trash icon on the eval's row.
3. Confirm **Delete this evaluation and its results?**

   The eval should disappear from the list, along with its column and scores in the results table.

## If Evaluation is disabled

The tooltip says “You need to submit at least one prompt and get an output before accessing the evaluation.” Finish a Playground run without making another edit, then reopen the tab. See [Prompt troubleshooting](/docs/prompt/troubleshooting) for other blocked states.
