---
title: "Track prompt performance"
description: "See per-version latency, token, and cost medians for a prompt running in production"
---

Every generation your application sends through `support-agent` is a data point. Once your calls carry a reference to the template, the **Metrics** tab in the Prompt Workbench rolls latency, tokens, and cost up per version, so you can see how the prompt is actually performing instead of reading traces one at a time.

<Steps>
  <Step title="Reference the template in your calls">
    Metrics only pick up generations that carry a reference to the prompt template they came from. Wire that up as covered in [Log prompt templates](/docs/sdk/tracing/log-prompt-templates); this guide picks up once that's in place.
  </Step>
  <Step title="Open the prompt and switch to Metrics">
    In the Prompt Workbench, open `support-agent` and click the **Metrics** tab.

    <Note>
    Metrics stays disabled, with a tooltip explaining why, until the prompt has produced at least one output. If you haven't run it yet, do that first from the Playground: see [Run a prompt](/docs/prompt/guides/run-a-prompt).
    </Note>
  </Step>
  <Step title="Read the per-version medians">
    The **Metrics** sub-tab lists one row per version, for whatever period you're viewing:

    | Metric | What it tells you |
    |---|---|
    | **Median Latency** | Typical time for the model to produce a response |
    | **Median Input Tokens** | Typical size of the prompt sent to the model |
    | **Median Output Tokens** | Typical length of the model's reply |
    | **Median Costs** | Typical cost per generation for this prompt |
    | **Traces Count** | How many times this version was called in the period |
    | **First and Last Generation** | When this version was first and last used in that period |
  </Step>
</Steps>

## Drill into the traces behind a number

Next to Metrics sits a second sub-tab, **Linked Traces**. Switch to it to see the individual traces that rolled up into those numbers, useful when a median looks off and you want to check what actually produced it.

## Decide if a change helped

This is the actual use of the page: pick a metric, then compare it across two versions, or across two time ranges on the same version. If `support-agent` v3's median latency comes in lower than v2's on comparable traffic, the change helped. If median cost jumps right after you lengthen the system message, that's the number that tells you why.
