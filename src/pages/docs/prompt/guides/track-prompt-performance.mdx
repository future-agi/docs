You edited a prompt and need to know whether the new [version](/docs/prompt/concepts/versions-and-labels) is faster, shorter or more costly on real traffic. The **Metrics** tab in the prompt editor rolls latency, tokens and cost up per version, so you can compare two versions head to head instead of reading [traces](/docs/observe/concepts/traces) one at a time.

<Prerequisites title="Before you start">
- [Log the prompt template reference](/docs/sdk/tracing/log-prompt-templates) on each generation you want attributed to a version.
- [Run the prompt](/docs/prompt/guides/run-a-prompt) and get at least one output to unlock **Metrics**.
</Prerequisites>

## Compare two versions

1. Open `support-agent` in the prompt editor.
2. Select **Metrics**.

   You should see two sub-tabs: **Metrics** for the per-version table and **Linked Traces** for the individual calls.

3. Find the rows for the two versions you want to compare, such as v2 and v3.

   The table has one row per version, aggregated across every trace recorded for it.

4. Pick one metric and compare it across the two rows.

   If v3's **Median Latency** is lower than v2's, the change helped. If **Median Cost** jumps right after you lengthen the system message, the table shows why: check **Median Input Tokens** for the larger prompt.

<div class="sdk-ref-table max-sm:[&_td]:px-1.5! max-sm:[&_th]:px-1.5!">

| Column | What it tells you |
|---|---|
| **Median Latency** | Typical time for a model response |
| **Median Input Tokens** | Typical prompt size, in tokens |
| **Median Output Tokens** | Typical reply length, in tokens |
| **Median Cost** | Typical cost per generation |
| **No. of traces** | Number of traced calls attributed to this version |
| **First Used** | When the version was first called |
| **Last Used** | When it was most recently called |
| **Label Name** | Which label, if any, points to the version, including the version labelled for production |

</div>

## Inspect the calls behind a median

1. Switch to **Linked Traces**.

   You should see the individual traces that rolled up into the per-version numbers.

2. Inspect a trace from the version you are investigating.

   Use this when a median looks off and you want to check what produced it.

## Troubleshooting

- **Metrics is disabled.** The tooltip says: "You need to submit at least one prompt and get an output before accessing the metrics." Submit the prompt and wait for its output.
- **A version is missing, or its count looks low.** Check the template reference at the model call. After correcting it, send a new request using the affected version. Reopen **Metrics** and confirm its row appears or its trace count increases.
