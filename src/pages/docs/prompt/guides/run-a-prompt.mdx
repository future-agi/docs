---
title: "Run a prompt"
description: "Write messages, set variables and parameters, and run a prompt in the Playground"
---

The **Playground** tab is where an open template turns into a model response. This guide picks up with a template already open, either a fresh one from [Create a prompt](/docs/prompt/guides/create-a-prompt) or the support-agent template from [Understanding Prompts](/docs/prompt/concepts/understanding-prompts), with `{{company_name}}` and `{{customer_question}}` as its variables.

## Write the messages

Write the system message and the user message in the editor. For support-agent, the system message sets the agent's role and the user message carries the question it has to answer:

- **System**: "You are a support agent for `{{company_name}}`."
- **User**: "Answer the following customer question clearly and professionally: `{{customer_question}}`"

Click **Add Message** to add more, for example an assistant message showing the model a sample answer.

<Note>
The editor always keeps at least one message. Try to remove the only one left and it blocks you with **"You must have at least one prompt."**
</Note>

## Pick a model and set the parameters

Choose the model that runs the prompt, then set the parameters that shape its output, things like temperature, max tokens, and top-p. Concurrency is one of them: it controls how many generations run in parallel, defaults to 5, and won't go past 10. See [Model configuration](/docs/prompt/reference/model-configuration) for the full list of parameters and their valid ranges.

## Declare variables and supply values

A variable is a `{{name}}` placeholder inside a message, substituted with a real value when the prompt runs. `{{company_name}}` and `{{customer_question}}` are variables in the support-agent template above. Open **Variables** in the editor header to see every variable the template declares and type in a value for each one before you run it.

## Run the prompt and read the output

Click **Run Prompt**. The response fills in the output panel as the model generates it, rather than appearing all at once, so you can start reading before it finishes.

## Stop a run in progress

If a run is taking too long or heading somewhere you don't want, click **Stop Generating** to cancel it.
