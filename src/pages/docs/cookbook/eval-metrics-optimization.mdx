## About

A repair reply can name the right contact but exceed a preview field's 29-character limit. Score one Ridgeline Outfitters reply three ways: check its format locally, ask a model whether it follows the repair policy, or use a hosted template to assess whether it answers the question.

| Time | Difficulty | Package |
|---|---|---|
| 20 min | Intermediate | `agent-learning-kit==0.3.7` |

## Set up Python

Use a fresh Python 3.12 environment. In Bash, enter an OpenRouter API key when prompted. The custom rubric uses that key. The format rules need no credentials.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install agent-learning-kit==0.3.7
read -rsp 'OpenRouter API key: ' OPENROUTER_API_KEY; printf '\n'
export OPENROUTER_API_KEY
```

## Score one reply with rules and a rubric

Use a fixed reply so differences come from the evaluator, not from regenerating the answer. `BasicDataMapper` passes the generated text as `response`; the custom judge also gets the question and policy. Pass the resulting evaluator and mapper to an optimizer when you want to use that objective during search.

Save as `metrics.py` and run `python metrics.py`. Only the custom rubric calls OpenRouter.

<CodeGroup titles={["Python"]}>

```python
from fi.evals.llm import LiteLLMProvider
from fi.evals.metrics import AggregatedMetric, Contains, CustomLLMJudge, LengthLessThan
from fi.opt.base import Evaluator
from fi.opt.datamappers import BasicDataMapper

row = {"question": "Where do I start a repair?", "policy": "Email repairs for a repair form."}
reply = "Email repairs for a repair form."
mapper = BasicDataMapper({
    "response": "generated_output", "policy": "policy", "question": "question"
})
inputs = [mapper.map(reply, row)]

rules = AggregatedMetric(config={
    "aggregator": "weighted_average",
    "metrics": [
        Contains(config={"keyword": "repairs"}),
        LengthLessThan(config={"max_length": 30}),
    ],
    "weights": [0.5, 0.5],
})
rubric = CustomLLMJudge(
    LiteLLMProvider(),
    config={
        "name": "repair_next_step",
        "model": "openrouter/openai/gpt-4o-mini",
        "grading_criteria": (
            "Score 1 if the response tells the customer how to start a repair as described "
            "in the policy without inventing steps; otherwise score 0."
        ),
    },
)
for name, metric in [("Format", rules), ("Policy", rubric)]:
    result = Evaluator(metric=metric).evaluate(inputs)[0]
    print(f"{name}: {result.score:.2f}")
    print("Reason:", result.reason)
```

</CodeGroup>

## Read the result

The reply contains “repairs” but is not shorter than 30 characters, so it earns only half the format score. The policy judge asks a different question: did the reply describe the next step without inventing one? Score lines from one run:

```text
Format: 0.50
Policy: 1.00
```

## Use a hosted template instead

If you want to check whether the reply addresses the entire question, use the hosted `completeness` template. It takes `input` and `output`, not the `response` field used by the local metrics. This route requires access to the Turing model and your [Future AGI API and secret keys](/docs/admin-settings/api-keys). Set `FI_API_KEY` and `FI_SECRET_KEY` in the shell that runs the script. Use `fi.evals.Evaluator` to inspect the raw result: a failed request has no score, while a completed evaluation can legitimately score zero.

Save as `hosted_metric.py` and run `python hosted_metric.py`:

<CodeGroup titles={["Python"]}>

```python
from fi.evals import Evaluator

batch = Evaluator().evaluate(
    eval_templates="completeness",
    model_name="turing_flash",
    inputs={
        "input": "Where do I start a repair?",
        "output": "Email repairs for a repair form.",
    },
)
result = next(iter(batch.eval_results), None)
if result is None or result.output is None:
    raise RuntimeError(result.reason if result else "No evaluation result")
print("Completeness:", result.output)
print("Reason:", result.reason)
```

</CodeGroup>

## Limits and troubleshooting

- `LengthLessThan` checks characters, not words, and the limit is exclusive. If exactly 30 characters must pass, use `max_length=31`.
- Put the judge model in `CustomLLMJudge`'s `config` dictionary. Its `model` entry selects the provider model; passing `model` a second time as a completion keyword conflicts with the model the judge passes internally.
- Read `.reason` as well as `.score`. The evaluator can return zero for a failed provider request as well as for a reply that actually fails the rubric.
