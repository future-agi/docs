## Tutorial

<Steps>
<Step title="Define the agent you want to monitor">

The example is a small e-commerce support assistant. It handles two kinds of questions: product searches like *"What trail lanterns do you have in stock?"* routed to `search_products`, and order lookups like *"Where is my order ORD-12345?"* routed to `get_order_status`. Anything outside those two tools falls back to "I don't have that information" instead of inventing one, a rule written into the system prompt:

```python
SYSTEM_PROMPT = """You are the Ridgeline Outfitters support assistant. For product or order questions, use the matching tool. Answer only from its results.
If you don't have the information, say so. Never guess or fabricate details."""
```

Two function tools, mocked here so the cookbook is self-contained. In a real deployment these call your product catalog and shipping API:

```python
import json
from openai import OpenAI

TOOLS = [
    {
        "type": "function",
        "function": {
            "name": "search_products",
            "description": "Search the catalog using one product keyword, such as lantern or mug",
            "parameters": {
                "type": "object",
                "properties": {"query": {"type": "string"}},
                "required": ["query"],
            },
        },
    },
    {
        "type": "function",
        "function": {
            "name": "get_order_status",
            "description": "Look up order status by order ID",
            "parameters": {
                "type": "object",
                "properties": {
                    "order_id": {"type": "string", "description": "The order ID"},
                },
                "required": ["order_id"],
            },
        },
    },
]


def search_products(query: str) -> dict:
    catalog = [{"name": "Trail Lantern", "price": 79.99, "in_stock": True},
               {"name": "Camp Mug", "price": 15.00, "in_stock": True}]
    words = query.lower().split()
    matches = [p for p in catalog if any(
        word.rstrip("s") in p["name"].lower().split() for word in words
    )]
    if not matches:
        # The reply and its context evals both need the lookup outcome.
        return {"results": [], "message": "No catalog items matched this search."}
    return {"results": matches}


def get_order_status(order_id: str) -> dict:
    if order_id == "ORD-12345":
        return {"order_id": order_id, "status": "shipped", "carrier": "ParcelCo"}
    return {"order_id": order_id, "error": "No matching order"}


TOOL_MAP = {
    "search_products": search_products,
    "get_order_status": get_order_status,
}


def generate_reply(messages: list) -> tuple[str, str]:
    """Process a user message. Returns (answer, context_from_tools)."""
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "system", "content": SYSTEM_PROMPT}] + messages,
        tools=TOOLS,
    )

    msg = response.choices[0].message
    context = ""

    if msg.tool_calls:
        tool_messages = [msg]
        tool_results = []
        for tool_call in msg.tool_calls:
            fn_name = tool_call.function.name
            fn_args = json.loads(tool_call.function.arguments)
            result = TOOL_MAP.get(fn_name, lambda **_: {"error": "Unknown tool"})(**fn_args)
            result_str = json.dumps(result)
            tool_results.append(result_str)
            tool_messages.append({
                "role": "tool",
                "tool_call_id": tool_call.id,
                "content": result_str,
            })

        context = "\n".join(tool_results)
        followup = client.chat.completions.create(
            model="gpt-4o-mini",
            messages=[{"role": "system", "content": SYSTEM_PROMPT}] + messages + tool_messages,
        )
        msg = followup.choices[0].message

    if not msg.content:
        raise RuntimeError("The model did not return a text answer")
    return msg.content, context
```

**You should see:** a function that returns an `(answer, context)` tuple with no tracing, no evals, nothing else attached yet. Each step below layers one piece of the monitoring stack on top of this exact function.

</Step>
<Step title="Trace every call">

`register()` creates or reuses a project and wires up an OpenTelemetry trace provider. `OpenAIInstrumentor().instrument()` auto-traces every OpenAI call. `@tracer.agent(...)` creates a parent span for each request. At first only model calls have child spans; you will add tool spans later.

```python
from fi_instrumentation import register, FITracer, using_user, using_session
from fi_instrumentation.fi_types import ProjectType
from traceai_openai import OpenAIInstrumentor

trace_provider = register(
    project_type=ProjectType.OBSERVE,
    project_name="ridgeline-quality-monitor",
    set_global_tracer_provider=True,
    verbose=False,
)
OpenAIInstrumentor().instrument(tracer_provider=trace_provider)
client = OpenAI()

tracer = FITracer(trace_provider.get_tracer("ridgeline-quality-monitor"))
```

Wrap the original function instead of copying its body. Enter the user and session contexts **before** starting the span so the parent and children inherit them. In a real service, derive these identifiers from the authenticated request and authorize each order lookup.

```python
traced_reply = tracer.agent(name="support_assistant")(generate_reply)

def handle_message(user_id: str, session_id: str, messages: list) -> tuple[str, str]:
    with using_user(user_id), using_session(session_id):
        return traced_reply(messages)
```

Run a few queries and flush:

```python
test_queries = [
    "Show me trail lanterns under $100",
    "Where is my order ORD-12345?",
    "What's your return policy?",
]

for i, query in enumerate(test_queries):
    answer, _ = handle_message(
        user_id=f"user-{100 + i}",
        session_id=f"session-{i}",
        messages=[{"role": "user", "content": query}],
    )
    print(f"Q: {query}")
    print(f"A: {answer[:120]}...\n")

trace_provider.force_flush()
```

**You should see:** the first two queries trigger tool calls and return grounded answers. The third has no matching tool. Check whether the agent acknowledges the gap instead of inventing a policy.

Open **Tracing** in the dashboard and select `ridgeline-quality-monitor`. Each query has a trace with nested spans for the agent call and the OpenAI requests. Click a trace to expand the span tree and inspect inputs, outputs, latency, and tool arguments:

<Step title="Score every response with inline evals">

Traces show what happened, not whether it was good. Attach `fi.evals` to score each response as it flows through:

```python
from fi.evals import Evaluator
from opentelemetry import trace

evaluator = Evaluator()


def attach(metric, inputs):
    result = evaluator.evaluate(
        eval_templates=metric, inputs=inputs, model_name="turing_small",
    ).eval_results[0]
    if not result.eval_id or result.output is None:
        raise RuntimeError(f"No {metric} score: {result.reason}")
    span = trace.get_current_span()
    span.set_attribute(f"quality.{metric}.value", result.output)
    span.set_attribute(f"quality.{metric}.eval_id", str(result.eval_id))
    span.set_attribute(f"quality.{metric}.reason", result.reason or "")
    print(f"{metric}_check: {result.output}")
    return result.output


@tracer.agent(name="scored_assistant")
def score_reply(messages: list) -> str:
    answer, context = generate_reply(messages)
    question = messages[-1]["content"]
    attach("completeness", {"input": question, "output": answer})
    if context:
        attach("context_adherence", {"output": answer, "context": context})
        attach("context_relevance", {"input": question, "context": context})
    return answer


def handle_message_scored(user_id: str, session_id: str, messages: list) -> str:
    with using_user(user_id), using_session(session_id):
        return score_reply(messages)
```

Run it against varied queries and flush:

```python
eval_queries = [
    "What trail lanterns do you have in stock?",
    "Has order ORD-12345 shipped?",
    "Is the Camp Mug in stock?",
    "Can I get a refund on a product I bought two months ago?",
    "What's the cheapest item in your catalog?",
]

for i, query in enumerate(eval_queries):
    answer = handle_message_scored(
        user_id=f"user-{200 + i}",
        session_id=f"eval-session-{i}",
        messages=[{"role": "user", "content": query}],
    )
    print(f"Q: {query}")
    print(f"A: {answer[:150]}...\n")

trace_provider.force_flush()
```

**You should see** (illustrative, your scores will vary): every scored reply prints a completeness score; only replies with tool results also print context adherence and context relevance. Open the `scored_assistant` span and inspect the `quality.*` attributes. Each metric has its own value, reason and hosted eval ID, so checking one metric does not overwrite another. These are span attributes, not dashboard Eval Task columns.

<Tip>
These are synchronous hosted checks: their latency is part of the response time. If user-facing latency is critical, consider running an Eval Task on ingested spans instead.
</Tip>

See [Inline Evals in Tracing](/docs/cookbook/quickstart/inline-evals-tracing) for the full inline eval workflow and dashboard filtering.

</Step>
<Step title="Alert on quality drops">

Scores are only useful if someone acts on them. Go to **Tracing** → select `ridgeline-quality-monitor` → the **Charts** tab shows baseline latency, tokens, traffic, cost, and eval score charts. To configure notifications, open **Alerts** in the main sidebar, choose **Create alert**, then select your project. Consider these example thresholds after measuring your baseline:

**Slow responses**
- Type: **LLM response time**
- Warning: above **3000** ms, Critical: above **5000** ms
- Interval: **5 minute interval**, notify by email or Slack

**High error rate**
- Type: **LLM API failure rates**
- Warning: above **5%**, Critical: above **15%**
- Interval: **15 minute interval**, notify by email or Slack

**Token budget**
- Type: **Monthly tokens spent**
- Warning: above **5,000,000** tokens, Critical: above **8,000,000** tokens
- Interval: **Daily**, notify by email

<Step title="Cluster failures with Error Feed">

If Error Feed is enabled for the project, open a finding and compare its evidence to the trace. For instance, a model might report that an order shipped, yet the trace shows only model calls. That does not prove the agent fabricated the answer: the lookup may have run without instrumentation.

Replace the dispatch entries with traced versions of the actual functions, then repeat the lookup:

```python
TOOL_MAP["search_products"] = tracer.tool(name="search_products")(search_products)
TOOL_MAP["get_order_status"] = tracer.tool(name="get_order_status")(get_order_status)
for query in ("Where is my order ORD-12345?", "Is the Camp Mug in stock?"):
    answer, context = handle_message("user-replay", "tool-replay", [{"role": "user", "content": query}])
    print("Tool evidence:", context)
    print("Reply:", answer)
trace_provider.force_flush()
```

In the `tool-replay` session, look for a model request, a tool span with the actual lookup result, and a model reply in the same trace. Compare the final answer with that result. A tool span shows that the function ran, not that the data was correct. The example does not guarantee an Error Feed finding or its resolution.

See [Error Feed](/docs/error-feed) for per-trace quality scoring, error category drilldowns, and the fix-and-verify workflow.

</Step>
<Step title="Gate the request and response on safety verdicts">

Use the hosted evals as a gate, not just a scorecard. Screen the incoming message before generating a reply, then screen the draft before returning it. These checks reuse the same evaluator as Step 3, so you can inspect their verdicts on the corresponding span. They do not call the separate Protect service.

```python
INPUT_FALLBACK = "Please ask about an order or product without including sensitive details."
OUTPUT_FALLBACK = "I can't share that response. Please contact support through your account."


def allowed(text, stage):
    if stage == "input":
        checks = [("data_privacy_compliance", "output"), ("prompt_injection", "input"),
                  ("toxicity", "output")]
    elif stage == "output":
        checks = [("data_privacy_compliance", "output"), ("toxicity", "output"),
                  ("bias_detection", "output")]
    else:
        raise ValueError("Expected input or output stage")

    with trace_provider.get_tracer(__name__).start_as_current_span(f"{stage}_guard"):
        for metric, field in checks:
            if attach(metric, {field: text}) != "Passed":
                return False
    return True


@tracer.agent(name="guarded_assistant")
def guarded_reply(messages: list) -> str:
    if not allowed(messages[-1]["content"], "input"):
        return INPUT_FALLBACK
    answer = score_reply(messages)
    return answer if allowed(answer, "output") else OUTPUT_FALLBACK
```

Try a product lookup, then a request containing a fictional card number. Separately screen a synthetic draft that echoes a full card number. This exercises the output gate without depending on the model to generate sensitive text.

```python
for i, query in enumerate(("Is the Camp Mug in stock?",
                           "My full credit card number is 4111 1111 1111 1111. Can you find my order?")):
    with using_user(f"user-guard-{i}"), using_session(f"guard-{i}"):
        reply = guarded_reply([{"role": "user", "content": query}])
        print("Response:", reply)

draft = "The customer's full credit card number is 4111 1111 1111 1111."
print("Draft:", draft if allowed(draft, "output") else OUTPUT_FALLBACK)
trace_provider.force_flush()
```

Check for a normal product answer and the two distinct fallback messages. A blocked input should have no downstream OpenAI call. Look at the `quality.*` attributes on `input_guard` and `output_guard` to see which rules ran and where screening stopped. If an eval returns no verdict, `attach` raises rather than releasing an unchecked message. Handle that error at your application boundary without returning the draft.

If your deployment uses the dedicated Protect service, see [Protect Guardrails](/docs/cookbook/quickstart/protect-guardrails) for its rule and fallback API.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| No traces appear in the **Tracing** tab | `trace_provider.force_flush()` never called, or the process exited before the batch exporter flushed | Call `force_flush()` after every batch of test calls, and keep the process alive until it returns |
| `AuthenticationError` from `register()` or `Evaluator()` | `FI_API_KEY` or `FI_SECRET_KEY` missing or unexported in the current shell | Re-run the `export` block, then re-run the script in the same shell |
| OpenAI child spans are missing | `OpenAIInstrumentor().instrument()` called after the `OpenAI()` client was already imported and used elsewhere | Instrument before the first `client.chat.completions.create()` call, ideally right after `register()` |
| `evaluator.evaluate()` raises an unknown-model error | `model_name` isn't a valid Turing model name | Use `turing_small`, `turing_flash`, or `turing_large` |
| No scores on the span | The check ran outside a recording span or the hosted eval returned no verdict | Keep `attach()` inside `score_reply` or the guard span; inspect the eval error before retrying. |
