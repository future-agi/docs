## About

A Ridgeline Outfitters customer tells the support agent that a tent is torn, then asks what to do next. Does the agent remember the damage and send the customer to repairs, or give the returns address? You'll run the conversation, read the reply that failed, change one instruction, and check that ordinary returns still work.

## Set up the two processes

Use Python 3.12 and an empty directory. Set `OPENROUTER_API_KEY` in your shell for the agent's model calls. You don't need a hosted simulation: the synthetic customer, transcript, and evaluation all run in the Agent Learning Kit process. The addresses in this example are fictional; the agent never sends email.

```bash
python3 -m venv .venv-platform
.venv-platform/bin/python -m pip install futureagi==0.8.0
python3 -m venv .venv-alk
.venv-alk/bin/python -m pip install agent-learning-kit==0.3.7
```

| Process | What it does | What it shares |
| --- | --- | --- |
| Platform SDK (`.venv-platform`) | Defines or retrieves the agent's prompt using `fi.prompt` | A JSON file containing the system message |
| Agent Learning Kit (`.venv-alk`) | Runs the agent against the synthetic customers with `fi.simulate`, then scores replies with `fi.evals` | A transcript and verdict for each customer |

The two distributions both install `fi/` files. Don't install them in the same environment or pass Python client objects between them.

## 1. Snapshot the current instruction and the proposed fix

Save this as `export_policies.py`. The current policy routes **every** case to returns. The proposed change makes an exception for damage and leaves the unused-gear route alone. Exporting each system message once keeps the prompt fixed for every turn of its test run.

```python
import json
from pathlib import Path
from fi.prompt.types import PromptTemplate, SystemMessage

common = (
    "You are the support agent for Ridgeline Outfitters. "
    "Give one next step, including the exact contact address, on every reply. "
    "Use only the address for the customer's situation. "
)
policies = {
    "baseline": "For any gear issue, refer the customer to returns@ridgeline.example.",
    "candidate": (
        "For torn or damaged gear use repairs@ridgeline.example. "
        "For returns of unused gear use returns@ridgeline.example."
    ),
}
for name, instruction in policies.items():
    template = PromptTemplate(name=f"ridgeline-{name}",
                              messages=[SystemMessage(content=common + instruction)])
    message = template.messages[0].model_dump(include={"role", "content"})
    Path(f"{name}.json").write_text(json.dumps(message, indent=2))
```

```bash
.venv-platform/bin/python export_policies.py
```

For an agent already managed in Future AGI, export its actual instruction instead of defining the baseline by hand. Set `FI_API_KEY`, `FI_SECRET_KEY`, `PROMPT_NAME`, and `PROMPT_VERSION` to your [workspace credentials](/docs/admin-settings), template name, and a committed version such as `v1`. This optional command is for a template with a single, static system message; the simulated customer supplies the user messages.

```bash
.venv-platform/bin/python - <<'PY'
import json
import os
from pathlib import Path
from fi.prompt import Prompt

prompt = Prompt.get_template_by_name(name=os.environ["PROMPT_NAME"],
                                     version=os.environ["PROMPT_VERSION"])
system, = [msg for msg in prompt.compile() if msg["role"] == "system"]
Path("baseline.json").write_text(json.dumps(system, indent=2))
PY
```

## 2. Run two customers through the agent

Save this as `test_handoff.py`. Each `Persona` supplies the customer's situation and desired outcome, **not** the correct address. On the second turn the synthetic customer asks for the next step. The agent receives the full `messages` history so it can tell which issue the customer meant.

```python
import asyncio
import json
import sys
from pathlib import Path
from fi.evals import evaluate
from fi.simulate import AgentInput, Persona, Scenario, TestRunner
from litellm import acompletion

customers = [
    ("Ari", "The seam on my tent tore.", "repairs"),
    ("Jo", "I'd like to return an unused pack.", "returns"),
]
scenario = Scenario(
    name="gear-handoff",
    dataset=[Persona(persona={"name": name}, situation=situation,
                     outcome="Find the right contact for my gear.")
             for name, situation, _ in customers],
)

async def main():
    policy = Path(sys.argv[1])
    system = json.loads(policy.read_text())

    async def reply(turn: AgentInput) -> str:
        response = await acompletion(model="openrouter/openai/gpt-4o-mini",
                                     messages=[system, *turn.messages], temperature=0)
        return response.choices[0].message.content

    report = await TestRunner().run_test(scenario=scenario, agent_callback=reply,
                                         min_turns=2, max_turns=2)
    expected = {name: f"{team}@ridgeline.example" for name, _, team in customers}
    if len(report.results) != len(customers):
        raise RuntimeError("Missing conversation; inspect the run before scoring")
    transcripts = []
    for case in report.results:
        name = case.persona.persona["name"]
        replies = [m["content"] for m in case.messages if m["role"] == "assistant"]
        if len(replies) != 2:
            raise RuntimeError(f"Incomplete conversation for {name}; check the model call")
        correct = evaluate("contains", engine="local", output=replies[-1],
                           config={"keyword": expected[name]})
        other_addresses = sorted(set(expected.values()) - {expected[name]})
        no_other = evaluate("contains_none", engine="local", output=replies[-1],
                            config={"keywords": other_addresses})
        if correct.error or no_other.error:
            raise RuntimeError(correct.error or no_other.error)
        verdict = "PASS" if correct.passed and no_other.passed else "FAIL"
        print(f"{name}: {verdict} (expected {expected[name]})")
        transcripts.append(f"{name}: {verdict}\n{case.transcript}")
    Path(f"{policy.stem}-transcripts.txt").write_text("\n\n".join(transcripts))

if __name__ == "__main__":
    asyncio.run(main())
```

Run the baseline first. This makes four model calls, two per customer. The contact checks run locally on the **last assistant reply**, not on the customer's words or the whole transcript.

```bash
.venv-alk/bin/python test_handoff.py baseline.json
cat baseline-transcripts.txt
```

## 3. Diagnose the failure and replay the same cases

In one baseline run, the script printed:

```text
Ari: FAIL (expected repairs@ridgeline.example)
Jo: PASS (expected returns@ridgeline.example)
```

Ari's final reply said, “The exact next step is to email our returns department at returns@ridgeline.example.” Compare that with the first user message about the torn seam. The agent followed its instruction, but the instruction doesn't distinguish damage from returns. Fix the policy, not the expected address.

```bash
.venv-alk/bin/python test_handoff.py candidate.json
cat candidate-transcripts.txt
```

With the candidate policy, the same two cases produced:

```text
Ari: PASS (expected repairs@ridgeline.example)
Jo: PASS (expected returns@ridgeline.example)
```

Check **both** customers before promoting the change. Ari should now receive the repairs address; Jo still needs the returns address. Passing means that the final reply contains the expected address and not the other one. It does not tell you whether the repair was accepted, whether the response was polite, or whether the agent actually created a ticket.

## Limits and troubleshooting

- **Import failure:** run `export_policies.py` with `.venv-platform/bin/python` and `test_handoff.py` with `.venv-alk/bin/python`. If you installed both packages together, recreate them in separate environments.
- **Missing transcript or incomplete conversation:** check the model credential and provider availability. A callback that doesn't return both replies is a run failure, not evidence that the prompt chose the wrong address.
- **More coverage:** add a customer and expected queue to `customers` for each handoff you rely on. Keep the same cases across versions and use synthetic customer details.
