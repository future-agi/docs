<TLDR>
Build a PDF-grounded RAG chatbot with LlamaIndex, instrument it with traceAI to inspect the embedding, retrieval, and generation spans, then optionally configure Future AGI Eval Tasks on the spans you want to score.
</TLDR>

The full application (Gradio UI, ingestion, chat loop) lives in the [llamaindex integration repo](https://github.com/future-agi/cookbooks/tree/main/integrations/llamaindex). This cookbook walks through the instrumentation and evaluation layer you add on top of it.

| Time | Difficulty | Package |
|------|-----------|---------|
| 30 min | Intermediate | `traceAI-llamaindex` |

- Future AGI account → [app.futureagi.com](https://app.futureagi.com)

## Tutorial

<Steps>
<Step title="Instrument the app with traceAI">

Save this as `tracing.py`. Register one Observe provider before creating the index or making a query.

```python
from uuid import UUID

from fi_instrumentation import register
from fi_instrumentation.fi_types import ProjectType
from traceai_llamaindex import LlamaIndexInstrumentor

trace_provider = register(
    project_type=ProjectType.OBSERVE,
    project_name="llamaindex_project",
    set_global_tracer_provider=True,
    verbose=False,
)
LlamaIndexInstrumentor().instrument(tracer_provider=trace_provider)
tracer = trace_provider.get_tracer(__name__)
```

</Step>
<Step title="Ingest a PDF into a persistent vector index">

Save this as `ingest.py` and run `python ingest.py`. It creates a small, text-based PDF with one policy per page, parses it and persists the embeddings in `vectorstore`. To try your own PDF, point `SimpleDirectoryReader` at it instead.

```python
from pathlib import Path

from tracing import UUID, trace_provider, tracer
from llama_index.core import Settings, SimpleDirectoryReader, VectorStoreIndex
from llama_index.embeddings.openai import OpenAIEmbedding
from reportlab.pdfgen.canvas import Canvas

Settings.embed_model = OpenAIEmbedding(model="text-embedding-3-small")
STORAGE_PATH = Path("vectorstore")

if __name__ == "__main__":
    pdf = Path("ridgeline-policies.pdf")
    canvas = Canvas(str(pdf))
    for policy in (
        "Ridgeline Outfitters refunds defective products within 45 days of delivery.",
        "Standard shipping takes 3 to 5 business days.",
        "Bring your pack and proof of purchase for a buckle repair.",
    ):
        canvas.drawString(50, 760, policy)
        canvas.showPage()
    canvas.save()

    with tracer.start_as_current_span("index-policy-pdf") as span:
        docs = SimpleDirectoryReader(input_files=[str(pdf)]).load_data()
        index = VectorStoreIndex.from_documents(docs)
        index.storage_context.persist(persist_dir=str(STORAGE_PATH))
        trace_id = UUID(int=span.get_span_context().trace_id)
    trace_provider.force_flush()
    print(trace_id)
```

Embeddings can be batched. Don't expect one API call per page. The last line is the trace ID for ingestion.

</Step>
<Step title="Query the index and generate a grounded answer">

Save this as `ask.py` and run `python ask.py`. Loading the index from disk avoids re-embedding the document. Each invocation starts a new chat so the previous answer cannot change retrieval.

```python
import sys

from ingest import STORAGE_PATH, Settings
from tracing import UUID, trace_provider, tracer
from llama_index.core import StorageContext, load_index_from_storage
from llama_index.llms.openai import OpenAI

k = int(sys.argv[1]) if len(sys.argv) > 1 else 1
Settings.llm = OpenAI(model="gpt-4o-mini", temperature=0)
storage = StorageContext.from_defaults(persist_dir=str(STORAGE_PATH))
index = load_index_from_storage(storage)
engine = index.as_chat_engine(chat_mode="context", similarity_top_k=k)

with tracer.start_as_current_span(f"query-policy-top-{k}") as span:
    response = engine.chat("What is Ridgeline's refund window for a defective product?")
    print(response.response)
    for node in response.source_nodes:
        print(node.metadata.get("file_name"), node.metadata.get("page_label"), node.score)
    trace_id = UUID(int=span.get_span_context().trace_id)
trace_provider.force_flush()
print(trace_id)
```

Look for an answer of **45 days** and a source line for `ridgeline-policies.pdf`, page 1. The score is retrieval similarity, not the probability that the answer is correct. In **Observe**, select `llamaindex_project` and open the printed query trace ID.

</Step>
<Step title="Inspect the trace in Observe">

Open that trace and read it span by span.

You should see the retriever span listing the chunks it selected, with `file_name`, `page_label`, and a similarity score for each.

</Step>
<Step title="Attach evals to spans">

In the dashboard, define evals as tasks and attach them to a span type rather than calling `evaluate()` from code. Choose a span filter and map the evaluation inputs to attributes that actually contain the question, answer and retrieved text. Only eligible spans sampled by the task are scored.

<img src="/images/docs/cookbook-llamaindex-pdf-rag/3.png" alt="Future AGI dashboard panel for attaching an eval task to a span type in the llamaindex_project" style={{ borderRadius: '5px' }} />

*Attaching Task Completion, Detect Hallucination, Context Relevance, and Context Adherence to the LLM span type*

You should see the new eval task listed against the span type you selected, and it starts scoring the next trace that hits that span.

<Tip>
Read more about the built-in evals in [Evaluation](/docs/evaluation), and about writing your own in [Creating custom evals](/docs/evaluation/guides/custom-evals).
</Tip>

</Step>
<Step title="Read the eval results">

Reopen a trace after the eval task has run. The bottom panel now shows a score per span.

Compare context relevance (did you retrieve useful evidence?) with context adherence (did the answer stick to that evidence?). Low scores on these two checks suggest different changes.

<img src="/images/docs/cookbook-llamaindex-pdf-rag/5.png" alt="Future AGI charts dashboard showing eval score trends alongside latency and cost for the llamaindex_project" style={{ borderRadius: '5px' }} />

*Score trends over time, next to latency and cost, for spotting drift before it reaches customers*

If context relevance is low, inspect the chunks before changing the generation prompt.

</Step>
<Step title="Fix the retriever and rerun">

Raise `similarity_top_k` from 1 to 3 and ask the same question in a fresh chat:

```bash
python ask.py 3
```

Compare the cited pages and both traces. The larger candidate set includes the shipping and repair pages, which don't answer the question. A larger `top_k` can help if retrieval missed the right page, but it can also introduce irrelevant material. It does not guarantee a better score.

</Step>
<Step title="Set an alert on a quality metric">

Once you have a baseline, set a threshold so a drop pages you instead of a customer.

<img src="/images/docs/cookbook-llamaindex-pdf-rag/6.png" alt="Future AGI alert rule creation form with a metric selector, monitoring interval, and threshold fields" style={{ borderRadius: '5px' }} />

Set the monitoring interval and notification channel for the alert. Inspect the matching spans when the aggregate crosses the threshold.

</Step>
</Steps>

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `NameError: name 'LlamaIndexInstrumentor' is not defined` | Instantiated `LlamaIndexInstrumentor()` without importing it | Add `from traceai_llamaindex import LlamaIndexInstrumentor` before calling `register()` |
| No spans appear in the Observe dashboard | `register()` wasn't called, or `instrument()` ran before `register()` returned | Call `register(project_type=ProjectType.OBSERVE, ...)` first, then pass its return value into `LlamaIndexInstrumentor().instrument(tracer_provider=...)` |
| `401 Unauthorized` when spans try to ship | `FI_API_KEY` or `FI_SECRET_KEY` not set, or set after the script imports `fi_instrumentation` | Export both keys before running the script, not inside it |
| Queries return an empty or generic answer | The PDF is scanned or image-only, so `SimpleDirectoryReader` extracted no text | Run OCR on the file before ingestion, or check `docs` isn't empty before building the index |
| New PDFs don't show up in answers | You are reading a previously persisted index | Rebuild in a fresh storage directory and point the query script at it |
| Context Relevance scores stay low across runs | Chunk size doesn't match the PDFs' structure, or the query embedding drifts from the chunk embeddings | Tune the chunk size and `top_k` on the retriever, then rerun the same questions and compare the score |
| Ingesting a large PDF is slow | Parsing and embedding both take time | Use the ingestion trace to see where the time is spent before changing chunk or batch size |
