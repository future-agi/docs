<TLDR>
Does a wrong answer come from retrieving the wrong policy, or from ignoring the right one? Run the same Ridgeline Outfitters questions with one and two retrieved passages. Score each answer against the passages the model actually saw, then inspect the corresponding trace.
</TLDR>

<Prerequisites>
- Future AGI account with `FI_API_KEY` and `FI_SECRET_KEY` (see [Get your API keys](/docs/admin-settings))
- An OpenAI API key for chat and embeddings
- Python 3.12
</Prerequisites>

## Tutorial

<Steps>
<Step title="Define two comparable configurations">

Save this as `config.yaml`. Each policy is already a single passage, so chunk boundaries stay fixed. Change only the number of passages retrieved. The expected source is for scoring; it is not shown to the model.

```yaml
model: gpt-4o-mini
embedding_model: text-embedding-3-small
retrieval_depths: [1, 2]
policies:
  returns: "Unused hiking boots can be returned within 30 days of delivery."
  repairs: "Zipper repairs on Ridgeline daypacks take 14 business days."
  shipping: "Standard delivery takes 5 business days."
questions:
  - text: "How long do I have to return unused hiking boots?"
    source: returns
  - text: "How long will my daypack zipper repair take?"
    source: repairs
```

</Step>
<Step title="Build and instrument the pipeline">

Save this as `rag_benchmark.py`. LangChain embeds the three policies, retrieves the nearest passages, and sends only those passages and the question to the chat model. The kit's `Groundedness` metric takes `query`, `response`, and a list of `contexts`. It runs locally; the number on the root span is a custom attribute, not a hosted Eval Task result.

```python
import json
from pathlib import Path
from statistics import mean
from uuid import UUID

import yaml
from fi.evals.metrics.rag.generation.groundedness import Groundedness
from fi_instrumentation import register
from fi_instrumentation.fi_types import ProjectType
from langchain_core.documents import Document
from langchain_core.vectorstores import InMemoryVectorStore
from langchain_openai import ChatOpenAI, OpenAIEmbeddings
from traceai_langchain import LangChainInstrumentor

config = yaml.safe_load(Path("config.yaml").read_text())
provider = register(project_type=ProjectType.OBSERVE, project_name="ridgeline-rag", verbose=False)
LangChainInstrumentor().instrument(tracer_provider=provider)
tracer = provider.get_tracer(__name__)
embeddings = OpenAIEmbeddings(model=config["embedding_model"], check_embedding_ctx_length=False)
store = InMemoryVectorStore(embedding=embeddings)
store.add_documents([Document(page_content=text, metadata={"source": name})
                     for name, text in config["policies"].items()])
model = ChatOpenAI(model=config["model"], temperature=0)
metric = Groundedness()
rows = []
for k in config["retrieval_depths"]:
    retriever = store.as_retriever(search_kwargs={"k": k})
    for case in config["questions"]:
        question = case["text"]
        with tracer.start_as_current_span(f"policy answer k={k}") as span:
            docs = retriever.invoke(question)
            contexts = [doc.page_content for doc in docs]
            sources = [doc.metadata["source"] for doc in docs]
            answer = model.invoke([
                ("system", "Use only the policies below. Answer in one sentence. "
                           "If the policies do not say, say so.\n" + "\n".join(contexts)),
                ("human", question),
            ]).content
            score = metric.evaluate([{"query": question, "response": answer,
                                      "contexts": contexts}]).eval_results[0]
            if not answer or score.reason.startswith("Input validation failed"):
                raise ValueError("Missing answer or invalid grounding inputs")
            hit = case["source"] in sources
            span.set_attribute("rag.sources", sources)
            span.set_attribute("rag.source_hit", hit)
            span.set_attribute("rag.groundedness", float(score.output))
            rows.append(dict(k=k, question=question, sources=sources, contexts=contexts, answer=answer,
                             source_hit=hit, groundedness=float(score.output), reason=score.reason,
                             trace_id=str(UUID(int=span.get_span_context().trace_id))))
provider.force_flush()
Path("rag-results.json").write_text(json.dumps(rows, indent=2))
for k in config["retrieval_depths"]:
    group = [r for r in rows if r["k"] == k]
    print(f"k={k} source hit={mean(r['source_hit'] for r in group):.2f} "
          f"groundedness={mean(r['groundedness'] for r in group):.2f}")
```

Run `python rag_benchmark.py`. You get one summary line per retrieval depth and four question-level results in `rag-results.json`. Without an optional NLI model, the local groundedness metric falls back to word overlap. A high score can still miss a wrong number or an unsupported conclusion; it is not a hallucination rate.

</Step>
<Step title="Compare the evidence, not just the averages">

In **Observe**, open `ridgeline-rag`. Match a `trace_id` from the results file to its trace. Inspect the retriever and model spans, and check `rag.sources` and `rag.groundedness` on the parent span.

- **Source missed:** adjust retrieval or chunk boundaries first. The model could not cite a policy it never received.
- **Source present, answer unsupported:** compare the answer against the exact retrieved passages. Try a more explicit abstention instruction and rerun with retrieval unchanged.
- **Both configurations look good:** add harder questions, including questions none of the policies answer. More passages can increase cost and introduce distractors. Two toy questions are not enough to select a production configuration.

</Step>
</Steps>

## Troubleshooting

| Symptom | What to check |
|---|---|
| The first model call fails before any answer appears | The OpenAI key needs access to the embedding model as well as the chat model. |
| A result looks right but the grounding score is low | Inspect `reason` and `contexts` in `rag-results.json`. Lexical overlap can penalize a correct paraphrase. |
| No traces appear | Confirm your keys belong to the workspace you opened. On a self-hosted installation check the collector URL. |
