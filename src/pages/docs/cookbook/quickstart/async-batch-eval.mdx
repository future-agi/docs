## Tutorial

Run the Python blocks in order in the same interpreter. You will evaluate three Ridgeline Outfitters support answers. These are client-side batches: the examples submit individual evaluations, not a dataset job.

<Steps>
<Step title="Run a synchronous eval as a baseline">

`Evaluator.evaluate()` waits for the server to return the verdict. Start with an answer supported by its policy. Save the ID so you can look the verdict up later.

```python
from fi.evals import Evaluator

evaluator = Evaluator()
cases = [
    {"context": "Standard shipping takes 3 to 5 days.", "output": "Standard shipping takes 3 to 5 days."},
    {"context": "Final-sale items cannot be refunded.", "output": "Final-sale items qualify for a full refund."},
    {"context": "Prepaid return labels are available on the Orders page.", "output": "Find your prepaid return label on the Orders page."},
]

def score(case, *, background=False):
    batch = evaluator.evaluate(
        eval_templates="groundedness", inputs=case, model_name="turing_small", is_async=background
    )
    return batch.eval_results[0]

baseline = score(cases[0])
print(f"Baseline: {baseline.output}")
print(baseline.reason)
```

Example first line (the judge's explanation varies):

```text
Baseline: Passed
```

</Step>
<Step title="Submit an async evaluation">

With `is_async=True`, the request still waits for an acknowledgement, but not for the judge to finish. Keep `eval_id`, not the empty output on the submission response.

```python
single_id = score(cases[0], background=True).eval_id
print(f"Submitted async eval: {single_id}")
```

Example output:

```text
Submitted async eval: 1969f203-caf4-44ba-9e18-f7951f64ab27
```

</Step>
<Step title="Poll for the stored result">

`get_eval_result()` fetches the current server record. A failing grade can have status `failed` and still contain a valid verdict. Distinguish that from a job that failed without a verdict.

```python
import time

def read_if_ready(eval_id):
    job = evaluator.get_eval_result(eval_id)["result"]
    if job["eval_status"] not in {"completed", "failed"}:
        return None
    detail = job["result"]
    if not isinstance(detail, dict) or detail.get("value") not in {"Passed", "Failed"}:
        raise RuntimeError(f"Evaluation {eval_id} stopped without a groundedness verdict")
    return detail

for _ in range(60):
    detail = read_if_ready(single_id)
    if detail is not None:
        print(f"{detail['name']}: {detail['value']}")
        break
    time.sleep(2)
else:
    raise TimeoutError(f"Still waiting for {single_id}")
```

Example output:

```text
groundedness: Passed
```

</Step>
<Step title="Score independent answers in parallel">

With synchronous calls you can put the wait in worker threads. Associate each future with its input index: faster answers need not finish in input order. The example uses three real evaluations; when you expand the input list, keep the worker count within your rate limit.

```python
from concurrent.futures import ThreadPoolExecutor, as_completed

sync_ids = {}
with ThreadPoolExecutor(max_workers=3) as pool:
    pending = {pool.submit(score, case): i for i, case in enumerate(cases)}
    for future in as_completed(pending):
        i = pending[future]
        verdict = future.result()
        sync_ids[i] = verdict.eval_id
        print(f"Case {i + 1}: {verdict.output}")
```

Example output (the order and judge verdicts can vary):

```text
Case 3: Passed
Case 1: Passed
Case 2: Failed
```

</Step>
<Step title="Combine async submission with batch polling">

Submit the same three cases in the background. Save the IDs before you start polling so you can resume later with `get_eval_result()`. Each pass checks only the jobs without a verdict.

```python
import json
from pathlib import Path

with ThreadPoolExecutor(max_workers=3) as pool:
    pending = {pool.submit(score, case, background=True): i for i, case in enumerate(cases)}
    async_ids = {pending[f]: f.result().eval_id for f in as_completed(pending)}

Path("eval-ids.json").write_text(json.dumps({
    "baseline": baseline.eval_id, "single": single_id, "sync": sync_ids, "async": async_ids,
}, indent=2))

remaining = dict(async_ids)
for _ in range(60):
    for i, eval_id in list(remaining.items()):
        detail = read_if_ready(eval_id)
        if detail is not None:
            print(f"Case {i + 1}: {detail['value']}")
            del remaining[i]
    if not remaining:
        break
    time.sleep(2)
else:
    raise TimeoutError(f"Resume polling these evaluation IDs: {list(remaining.values())}")
print(f"Finished {len(async_ids)} async evaluations")
```

Example final line:

```text
Finished 3 async evaluations
```

</Step>
</Steps>

## Troubleshooting

| Symptom | What to check |
|---|---|
| No verdict on submission | Read the `eval_id` and poll it with the same account that submitted it. |
| Polling times out | A timeout stops the client, not the job. Resume with the saved IDs rather than submitting the batch again. |
| `401` or `403` | Check both exported keys against your workspace. |
| Frequent `429` errors | Reduce `max_workers` and submit larger lists in chunks. |

For batch evaluation over a CSV, see [Dataset SDK: Batch Evaluation](/docs/cookbook/quickstart/batch-eval).
