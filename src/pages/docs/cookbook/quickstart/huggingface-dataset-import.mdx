## About

Ridgeline Outfitters wants cancellation replies that fit in a chat window. You'll import three synthetic support exchanges from Hugging Face and flag any reply outside a 1 to 100 word limit. The result is a CSV with the customer instruction, the original reply, and the length check for each row.

## Set up one Python environment

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install futureagi==0.7.0
```

Set `FI_API_KEY` and `FI_SECRET_KEY` from your [API keys](/docs/admin-settings/api-keys) in the same shell. `fi.platform.Client` submits the import to Future AGI, so you don't need the Hugging Face `datasets` package on your machine.

## Choose the rows to import

Use the public [Bitext customer support dataset](https://huggingface.co/datasets/bitext/Bitext-customer-support-llm-chatbot-training-dataset). `instruction` is the customer message and `response` is the agent's reply. They are different inputs: a customer's two-word question tells you nothing about whether the reply is too long.

| Parameter | Value for this import | What it selects |
| --- | --- | --- |
| `huggingface_dataset_name` | `bitext/Bitext-customer-support-llm-chatbot-training-dataset` | The source repository, not your new dataset's name |
| `huggingface_dataset_config` | `default` | The configuration within that repository |
| `huggingface_dataset_split` | `train` | The split to read |
| `num_rows` | `3` | A bounded sample. Omitting the count requests the split's row count. |
| `name` | A new name starting with `ridgeline-cancellations-` | The dataset you'll find in Future AGI |

Save the following as `import_replies.py` and run `python import_replies.py`. The returned ID identifies the new dataset. Import processing continues in the background; the next script waits for the customer message and reply in all three rows.

<CodeGroup titles={["Python"]}>

```python
from uuid import uuid4

from fi.platform import Client
from fi.utils.types import ModelTypes

with Client() as client:
    created = client.datasets.create_from_huggingface(
        name=f"ridgeline-cancellations-{uuid4().hex[:8]}",
        model_type=ModelTypes.GENERATIVE_LLM.value,
        huggingface_dataset_name="bitext/Bitext-customer-support-llm-chatbot-training-dataset",
        huggingface_dataset_config="default",
        huggingface_dataset_split="train",
        num_rows=3,
    )
    print(created.dataset_id)
```

## Score the replies and save a CSV

The `word_count_in_range` template needs one input, `text`. Map that key to the **ID** of the imported `response` column. The word limits are literal integers in `config["params"]`, not column mappings. Both bounds are inclusive.

Save this as `score_replies.py`, then run `python score_replies.py DATASET_ID` with the ID from the import. The script sets up the evaluation without running it, looks up its attached ID, then starts it once.

<CodeGroup titles={["Python"]}>

```python
import argparse
import csv
import time

from fi.platform import Client

parser = argparse.ArgumentParser()
parser.add_argument("dataset_id")
parser.add_argument("--resume", action="store_true", help="Wait and export without starting a run")
args = parser.parse_args()
dataset_id = args.dataset_id
check = "reply-length"

with Client() as client:
    deadline = time.monotonic() + 300
    while time.monotonic() < deadline:
        table = client.datasets.get(dataset_id, page_size=3)
        cols = {c.name: c.id for c in table.column_config}
        rows = [row.model_dump() for row in table.table or []]
        if {"instruction", "response"} <= cols.keys() and len(rows) == 3 and all(
            row.get(cols[field], {}).get("cell_value")
            for row in rows for field in ("instruction", "response")
        ):
            break
        time.sleep(2)
    else:
        raise TimeoutError(f"Expected three complete support exchanges in {dataset_id}")

    def attached_check():
        items = client.datasets.evals.list(dataset_id, eval_type="user").evals
        return next(item for item in items if item["name"] == check)

    if not args.resume:
        page = 0
        while True:
            batch = client.evals.templates.list(
                owner_filter="system", search="word_count_in_range", page=page, page_size=20,
            )
            match = next((t for t in batch.items if t.name == "word_count_in_range"), None)
            if match:
                template = client.evals.templates.get(match.id)
                break
            if not batch.items or (page + 1) * batch.page_size >= batch.total:
                raise LookupError("No system template named word_count_in_range")
            page += 1

        if set(template.required_keys) != {"text"}:
            raise ValueError(f"Unexpected inputs: {template.required_keys}")
        client.datasets.evals.add(
            dataset_id, name=check, template_id=template.id, run=False,
            config={"mapping": {"text": cols["response"]},
                    "params": {"min_words": 1, "max_words": 100}},
        )

        client.datasets.evals.run(dataset_id, user_eval_ids=[attached_check()["id"]])
    deadline = time.monotonic() + 300
    while time.monotonic() < deadline:
        state = attached_check()["status"]
        if state == "Completed":
            break
        if state not in {"NotStarted", "Queued", "Running"}:
            raise RuntimeError(f"{check}: {state}")
        time.sleep(2)
    else:
        raise TimeoutError(f"{check} still shows {state} on {dataset_id}")

    table = client.datasets.get(dataset_id, page_size=3)
    cols = {c.name: c.id for c in table.column_config}
    fields = ["instruction", "response", check]
    path = f"ridgeline-replies-{dataset_id}.csv"
    records = []
    for row in table.table or []:
        cells = row.model_dump()
        record = {}
        for field in fields:
            cell = cells.get(cols[field], {})
            value = cell.get("cell_value")
            if cell.get("status") == "error" or value is None or value == "":
                raise RuntimeError(f"Missing or failed {field} in row {row.row_id}")
            record[field] = value
        records.append(record)
    if len(records) != 3:
        raise RuntimeError(f"Expected 3 scored rows, got {len(records)}")
    with open(path, "w", newline="", encoding="utf-8") as f:
        writer = csv.DictWriter(f, fieldnames=fields)
        writer.writeheader()
        writer.writerows(records)
    print(path)
```

## Interpret the results

The first three replies in the `train` split have 37, 48, and 205 whitespace-separated words. Under the 100-word policy, the first two fit and the third needs editing. The length check doesn't tell you whether the cancellation advice itself is correct.

## Limits and troubleshooting

- For another dataset, check its configuration, split, and column names first. Mapping `text` to `instruction` would score the customer's message; looking up `cols["output"]` would fail because this dataset has no `output` column.
- If the import hasn't populated the reply cells after five minutes, inspect the existing dataset before starting a new import. The examples use a new name on each import.
- On a self-hosted install, the import needs the optional `ml` dependency group. Without it, the cells stay empty and the worker log shows `` `datasets` is part of the optional `ml` dependency group ``. Rebuild the image with `--build-arg EXTRAS=ml`, or use the EE image, which bundles all extras. See [image build arguments](/docs/self-hosting/images).
- If you stopped waiting after the run started, use `python score_replies.py DATASET_ID --resume` to wait for and export the existing result rather than attaching `reply-length` again.
- To change the sample size, update `num_rows`, the readiness check, and the export. The export reads one page of three rows. For multiple pages, use `metadata.next_page_index` while `metadata.has_more` is true.
- To score the same rows again, call `run` with the existing attached evaluation ID. The template ID identifies a reusable definition, not your dataset's `reply-length` check.
