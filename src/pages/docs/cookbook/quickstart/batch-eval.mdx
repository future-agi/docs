## About

Ridgeline Outfitters' support agent sends a JSON handoff and a contact email to a returns queue. Either field can be malformed even when the other is valid. You'll upload three handoffs, run an independent check on each field, and save the results next to the original inputs.

## Install the SDK

Use one Python environment for the whole recipe. `futureagi` provides both `fi.datasets` for the upload and `fi.platform.Client` for the evaluations. The checks run on your dataset, not in your Python process.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install futureagi==0.7.0
```

Set `FI_API_KEY` and `FI_SECRET_KEY` in this shell using your [Future AGI API keys](/docs/admin-settings/api-keys). Keep them out of your scripts and CSV.

## Upload the handoffs

Save this as `upload_cases.py` and run `python upload_cases.py`. It writes a CSV and uploads it as a new dataset. Keep the printed dataset name: the next script reconnects to that exact upload.

```python
import csv
from uuid import uuid4

from fi.datasets import Dataset, DatasetConfig
from fi.utils.types import ModelTypes

name = f"ridgeline-handoffs-{uuid4().hex[:8]}"
path = f"{name}.csv"
with open(path, "w", newline="", encoding="utf-8") as f:
    writer = csv.writer(f)
    writer.writerow(["case", "handoff", "contact"])
    writer.writerows([
        ("return-label", "Return label ready", "returns@example.com"),
        ("order-status", '{"status":"shipped"}', "shipping at example.com"),
        ("repair", '{"status":"received"}', "repairs@example.com"),
    ])

dataset = Dataset(dataset_config=DatasetConfig(
    name=name, model_type=ModelTypes.GENERATIVE_LLM,
))
dataset.create(source=path)
print(name)
```

## Map and run both checks

Both templates call their required input `text`. For `is_json`, supply the ID of the `handoff` column; for `is_email`, supply the ID of `contact`. A column name is useful for finding that ID, but it is not the mapping value.

| ID | Where you get it | Where you use it |
| --- | --- | --- |
| Template ID | An exact name in `client.evals.templates.list(...)` | `template_id` when attaching a check |
| Column ID | `column_config` on the uploaded dataset | Value in `config["mapping"]` |
| Attached evaluation ID | `client.datasets.evals.list(dataset_id, eval_type="user")` | `user_eval_ids` when starting the run |

Save this as `score_cases.py`. Run `python score_cases.py DATASET_NAME`, replacing `DATASET_NAME` with the name from the upload. `run=False` lets you configure both checks before starting them together. The wait loops stop after five minutes each; they don't submit a second run.

```python
import csv
import sys
import time

from fi.datasets import Dataset
from fi.platform import Client

name = sys.argv[1]
dataset_id = str(Dataset.get_dataset_config(name).dataset_config.id)
checks = [
    ("is_json", "handoff", "handoff-json"),
    ("is_email", "contact", "contact-email"),
]


def find_template(client, name):
    page = 0
    while True:
        batch = client.evals.templates.list(
            owner_filter="system", search=name, page=page, page_size=20,
        )
        for item in batch.items:
            if item.name == name:
                return client.evals.templates.get(item.id)
        if not batch.items or (page + 1) * batch.page_size >= batch.total:
            raise LookupError(f"No system template named {name}")
        page += 1


with Client() as client:
    deadline = time.monotonic() + 300
    while time.monotonic() < deadline:
        table = client.datasets.get(dataset_id, page_size=3)
        state = (table.dataset_config or {}).get("file_processing_status")
        if state == "completed":
            break
        if state == "failed":
            raise RuntimeError(f"CSV upload failed: {name}")
        time.sleep(2)
    else:
        raise TimeoutError(f"CSV still processing: {name}")

    columns = {c.name: c.id for c in table.column_config}
    for template_name, column, check_name in checks:
        template = find_template(client, template_name)
        if set(template.required_keys) != {"text"}:
            raise ValueError(f"{template_name} requires {template.required_keys}")
        client.datasets.evals.add(
            dataset_id, name=check_name, template_id=template.id,
            config={"mapping": {"text": columns[column]}}, run=False,
        )

    def attached():
        items = client.datasets.evals.list(dataset_id, eval_type="user").evals
        return {item["name"]: item for item in items}

    metrics = attached()
    names = [check_name for _, _, check_name in checks]
    client.datasets.evals.run(dataset_id, user_eval_ids=[metrics[n]["id"] for n in names])

    deadline = time.monotonic() + 300
    while time.monotonic() < deadline:
        metrics = attached()
        states = {n: metrics[n]["status"] for n in names}
        if all(s == "Completed" for s in states.values()):
            break
        if any(s not in {"NotStarted", "Queued", "Running", "Completed"} for s in states.values()):
            raise RuntimeError(states)
        time.sleep(2)
    else:
        raise TimeoutError(f"Check {name} before starting another run: {states}")

    table = client.datasets.get(dataset_id, page_size=3)
    columns = {c.name: c.id for c in table.column_config}
    fields = ["case", "handoff", "contact", *names]
    path = f"{name}-scored.csv"
    with open(path, "w", newline="", encoding="utf-8") as f:
        writer = csv.DictWriter(f, fieldnames=fields)
        writer.writeheader()
        for row in table.table:
            cells = row.model_dump()
            writer.writerow({k: cells[columns[k]]["cell_value"] for k in fields})
    print(path)
```

## Read the scored CSV

Compare each check independently. A completed run means processing finished, not that every handoff passed.

| Case | JSON check | Email check | Why |
| --- | --- | --- | --- |
| `return-label` | Fail | Pass | `Return label ready` is plain text, not a JSON string or object. |
| `order-status` | Pass | Fail | `shipping at example.com` isn't an email address. |
| `repair` | Pass | Pass | The handoff parses and the address has a valid format. Neither check verifies that the repair actually arrived. |

## Limits and troubleshooting

- In `futureagi==0.7.0`, importing `fi.datasets` can log a warning about an optional evaluation dependency. That warning is for `Dataset.add_evaluation()`. The `client.datasets.evals` calls above do not need a second package.
- A missing required input gives `Missing required mapping keys: text`. If a check runs but scores the wrong thing, inspect the column ID mapped to `text` instead.
- `Eval not found` when starting a run means you should check the IDs against the evaluations attached to **this dataset**, not the template catalog. To rerun the checks, call `run` with the attached IDs; don't attach the same names again.
- The export reads one page because the input has exactly three rows. For a larger dataset, read subsequent table pages using `metadata.next_page_index` while `metadata.has_more` is true.
