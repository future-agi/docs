## Tutorial

<Note>
These checks run synchronously from your application. You record their results as span attributes, not as native **Evals** rows. For platform-managed evaluation columns and score filters, [configure an Eval Task](/docs/observe/guides/setup-evals).
</Note>

<Steps>
<Step title="Set up tracing and the Evaluator">

Initialize the tracer, OpenAI instrumentation, and hosted evaluator once. `attach_eval` writes the result to the parent span; the instrumentor creates a separate child span for the model call.

```python
import os
import openai
from fi_instrumentation import register
from fi_instrumentation.fi_types import ProjectType
from fi.evals import Evaluator
from traceai_openai import OpenAIInstrumentor

trace_provider = register(
    project_type=ProjectType.OBSERVE,
    project_name="ridgeline-inline-evals",
    set_global_tracer_provider=True,
    verbose=False,
)
OpenAIInstrumentor().instrument(tracer_provider=trace_provider)

evaluator = Evaluator(
    fi_api_key=os.environ["FI_API_KEY"],
    fi_secret_key=os.environ["FI_SECRET_KEY"],
)


def attach_eval(span, *, eval_templates, inputs, model_name, custom_eval_name):
    batch = evaluator.evaluate(
        eval_templates=eval_templates, inputs=inputs, model_name=model_name,
    )
    check = batch.eval_results[0]
    if not check.eval_id or check.output is None:
        raise RuntimeError(f"No verdict for {custom_eval_name}: {check.reason}")
    prefix = f"quality.{custom_eval_name}"
    span.set_attribute(f"{prefix}.value", check.output)
    span.set_attribute(f"{prefix}.id", str(check.eval_id))
    print(f"{custom_eval_name}: {check.output}")


client = openai.OpenAI()
tracer = trace_provider.get_tracer(__name__)
```

This sets up tracing and defines `attach_eval`, which copies a hosted verdict and its ID to the span you pass in. The name after `quality.` identifies the check. Call `OpenAIInstrumentor().instrument()` before creating the OpenAI client or making any calls, otherwise those calls trace without input/output attributes.

</Step>
<Step title="Attach a verdict to the answer span">

Call `attach_eval` while your answer span is open. It records two attributes, `quality.groundedness_check.value` and `quality.groundedness_check.id`, before the span is exported.

The first attempt retrieves a shipping policy for a refund question. A model that guesses a refund window has no evidence for it. A model that explains the context is insufficient can still pass groundedness: this check measures support, not whether retrieval found the right document.

```python
question = "What's the refund window for a final sale item?"

# Wrong chunk came back from retrieval: shipping info, not refund policy
context = "Standard shipping takes 3-5 business days within the continental US. Expedited orders arrive in 1-2 business days for an additional fee."

with tracer.start_as_current_span("answer-question") as span:
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": f"Answer using only this context:\n{context}"},
            {"role": "user",   "content": question},
        ],
    )
    answer = response.choices[0].message.content

    span.set_attribute("raw.input",  question)
    span.set_attribute("raw.output", answer)

    # Run a groundedness check and attach it to this span
    attach_eval(
        span, eval_templates="groundedness",
        inputs={
            "input":   question,
            "output":  answer,
            "context": context,
        },
        model_name="turing_large",
        custom_eval_name="groundedness_check",  # name used in the span attributes
    )

print(f"Answer: {answer}")

# Flush spans before the script exits. BatchSpanProcessor buffers for up to 5 seconds
trace_provider.force_flush()
```

In Observe, open the `answer-question` span and inspect its attributes. Compare `quality.groundedness_check.value` with `raw.output`. A missing value is not a failed verdict.

Fix the retrieval, not the eval: swap in the chunk that actually answers the question and re-run.

The second `answer-question` span uses the same question and metric. Its context now supports a specific answer: final sale items are not eligible for refunds. Compare the two answers and their verdicts.


</Step>
<Step title="Run multiple evals on the same span">

Pass the same open span to both checks. Their distinct names keep the toxicity verdict and instruction-adherence score from overwriting each other.

```python
user_input = "The customer says their refund hasn't arrived after 10 days. Draft a short, polite reply explaining our 5-7 business day refund window and the next step."

with tracer.start_as_current_span("explain-concept") as span:
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": user_input}],
    )
    answer = response.choices[0].message.content

    span.set_attribute("raw.input",  user_input)
    span.set_attribute("raw.output", answer)

    # Check 1: Is the response toxicity-free?
    attach_eval(
        span, eval_templates="toxicity",
        inputs={"output": answer},
        model_name="turing_small",
        custom_eval_name="toxicity_check",
    )

    # Check 2: Did the response follow the prompt instructions?
    attach_eval(
        span, eval_templates="prompt_instruction_adherence",
        inputs={"output": answer, "prompt": user_input},
        model_name="turing_small",
        custom_eval_name="instruction_check",
    )

print(f"Answer: {answer}")

# Flush spans before the script exits. BatchSpanProcessor buffers for up to 5 seconds
trace_provider.force_flush()
```

In the `explain-concept` span attributes, look for `quality.toxicity_check.value` (a verdict) and `quality.instruction_check.value` (a score). Each has its own `.id`.

<Tip>
Each synchronous check adds to the time before your function returns. Choose the evaluator model and the number of checks with that latency in mind.
</Tip>

</Step>
<Step title="Inline evals on a full RAG pipeline">

A realistic example: trace the full pipeline (retrieval and generation) and attach a groundedness eval to the generation span.

```python
from fi_instrumentation import using_user, using_session

def retrieve_docs(query: str) -> list[str]:
    # Simulate vector DB retrieval
    return [
        "Orders can be refunded within 30 days of delivery if the item is unused and in original packaging.",
        "Approved refunds are issued to the original payment method within 5-7 business days.",
    ]


def answer_question(question: str, user_id: str, session_id: str) -> str:
    with using_user(user_id), using_session(session_id):
        with tracer.start_as_current_span("rag-pipeline") as pipeline_span:
            pipeline_span.set_attribute("pipeline.question", question)

            # Retrieval span
            with tracer.start_as_current_span("retrieval") as ret_span:
                docs = retrieve_docs(question)
                ret_span.set_attribute("retrieval.doc_count", len(docs))

            # Generation span - eval attached here
            context = "\n".join(docs)
            with tracer.start_as_current_span("generation") as gen_span:
                response = client.chat.completions.create(
                    model="gpt-4o-mini",
                    messages=[
                        {"role": "system", "content": f"Answer from:\n{context}"},
                        {"role": "user",   "content": question},
                    ],
                )
                answer = response.choices[0].message.content
                gen_span.set_attribute("raw.output", answer)

                # Inline groundedness eval - did the answer stay grounded in the docs?
                attach_eval(
                    gen_span, eval_templates="groundedness",
                    inputs={
                        "input":   question,
                        "output":  answer,
                        "context": context,
                    },
                    model_name="turing_large",
                    custom_eval_name="groundedness_check",
                )

            return answer


result = answer_question(
    question="What's your refund window and how do I get my money back?",
    user_id="user-abc123",
    session_id="session-xyz789",
)
print(result)

trace_provider.force_flush()
```

Open the `rag-pipeline` trace. `retrieval` and `generation` are siblings. The verdict belongs to `generation`, not to `retrieval` or the root span.

</Step>
<Step title="Find the results in Observe">

1. Open **Tracing** under **Observe**, then open the `ridgeline-inline-evals` project.
2. Select an `answer-question` trace and open its `answer-question` span, not the automatically instrumented OpenAI child.
3. Inspect the span attributes for `quality.groundedness_check.value` and `.id`. Compare the answer with the source text you passed to the evaluator.
4. For the pipeline example, expand `rag-pipeline` and select `generation`. To check two metrics at once, open `explain-concept` instead.

The `.id` identifies the underlying hosted evaluation. In your Python session, `evaluator.get_eval_result(eval_id)` fetches its reason when you pass that ID. These attributes do not create a native **Evaluation Metrics** column.

</Step>

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| No spans appear in the project | The exporter has not flushed or is sending to the wrong endpoint | Call `trace_provider.force_flush()` before exit. For self-hosting, check the collector URL separately from the platform API URL. |
| A check is rate-limited (HTTP 429) | The evaluator is temporarily at capacity | Wait for the usage window to reset before running the affected example again. |
| A check returns no verdict | Credentials are missing or the model could not score the input | Verify the keys in this shell and the input names for that template before retrying. |
| The model call is present but the quality fields are absent | You opened the OpenAI child span, or the check ran after its parent closed | Open the parent span passed to `attach_eval` and call the helper inside its `with` block. |
| The Evals tab is empty | These examples store ordinary span attributes | Look for the `quality.` prefix in the span attributes. Use a platform Eval Task if you need evaluation columns. |
| The groundedness verdict passed despite a bad retrieval | Declining to answer can be faithful to an irrelevant context | Inspect the retrieved passage and score answer usefulness separately. |

Session-Based Observability covers tagging spans with `user_id` and `session_id` so multi-turn conversations group into a single filterable unit: [Session-Based Observability](/docs/cookbook/quickstart/session-observability).
