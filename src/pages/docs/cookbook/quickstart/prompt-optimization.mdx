## About

Ridgeline Outfitters' router sometimes explains its choice when the downstream system needs a single word. With `MetaPromptOptimizer`, you give a teacher model the task, a starting prompt, and scored examples. Then you run the best *scored* prompt on a new ticket.

| Time | Difficulty | Package |
|---|---|---|
| 15 min | Intermediate | `agent-learning-kit==0.3.7` |

## Give the teacher a testable goal

The goal is not just “answer correctly”: an exact match requires the entire response to be `RETURNS` or `REPAIRS`. Set `task_description` to that contract and tell the teacher to preserve `{ticket}`. The teacher generator itself uses `{prompt}`, where the optimizer inserts its rewrite request.

Run two rounds on the same two rows. Round one scores the original prompt before requesting a rewrite; round two can score that rewrite. Save as `meta.py` and run `python meta.py`.

<CodeGroup titles={["Python"]}>

```python
from fi.evals.metrics import Equals
from fi.opt.base import Evaluator
from fi.opt.datamappers import BasicDataMapper
from fi.opt.generators import LiteLLMGenerator
from fi.opt.optimizers import MetaPromptOptimizer

MODEL = "openai/gpt-4o-mini"
seed = "Which queue, RETURNS or REPAIRS, handles this ticket? {ticket}"
train = [
    {"ticket": "My new boots don't fit. Can I send them back?", "queue": "RETURNS"},
    {"ticket": "Can you fix a broken buckle on my pack?", "queue": "REPAIRS"},
]
mapper = BasicDataMapper({
    "response": "generated_output",
    "expected_response": "queue",
})
evaluator = Evaluator(metric=Equals(config={"case_sensitive": True}))

teacher = LiteLLMGenerator(MODEL, "{prompt}")
optimizer = MetaPromptOptimizer(teacher_generator=teacher, task_model=MODEL)
result = optimizer.optimize(
    evaluator=evaluator, data_mapper=mapper, dataset=train, initial_prompts=[seed],
    task_description=("Route each ticket to RETURNS for refunds or REPAIRS for fixes. "
                      "Output only the uppercase queue name. Keep {ticket} as the only placeholder."),
    num_rounds=2, eval_subset_size=len(train),
)
for n, entry in enumerate(result.history, start=1):
    print(f"Round {n}: {entry.average_score:.0%}")
print("Selected prompt:", result.best_generator.get_prompt_template())
print("New ticket:", result.best_generator.generate({"ticket": "Can you repair a jacket seam?"}))
```

</CodeGroup>

## Read the result

Each round prints the mean exact-match score over the two labeled examples. The final line is a reply from the selected generator on a different ticket. Selected lines from one run:

```text
Round 1: 0%
Round 2: 100%
Selected prompt: Based on the content of the ticket, determine the appropriate queue. If the ticket is about returning an item for a refund, respond with 'RETURNS'. If the ticket is about fixing or repairing an item, respond with 'REPAIRS'. Here’s the ticket: {ticket}
New ticket: REPAIRS
```

Scores and wording vary by run. In this example, the selected instruction names both cases and the exact text to return. It kept the `{ticket}` field, so the application can still insert a new request at runtime.

## Limits and troubleshooting

- With `num_rounds=1`, the optimizer scores the seed and asks for a rewrite but does not score that rewrite. Use at least two rounds to compare the first proposal with the seed.
- The teacher may propose an instruction that drops `{ticket}`. Inspect the selected template, not only the score, before using it in your router.
- A higher training score does not establish a higher score on new tickets. Keep a labeled evaluation set outside the search.
