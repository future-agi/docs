## About

Ridgeline Outfitters is changing its support router. A sentence like “Send this to the returns team” helps a person, but the ticket system expects the exact code `RETURNS`. You'll keep the current prompt under the `production` label, test a second version on the same tickets, then switch the label or roll it back.

## Set up two Python environments

Start in an empty directory with Python 3.12. Set `FI_API_KEY` and `FI_SECRET_KEY` from your [Future AGI account](/docs/admin-settings) and set `OPENROUTER_API_KEY` for the model calls. Use a workspace where you can create a practice prompt. Pick a `PROMPT_NAME` that does not already exist there.

```bash
python3 -m venv .venv-platform
.venv-platform/bin/python -m pip install futureagi==0.8.0
python3 -m venv .venv-alk
.venv-alk/bin/python -m pip install agent-learning-kit==0.3.7
export PROMPT_NAME="ridgeline-ticket-router"
```

Both distributions install files under `fi/`. Keep them apart: `.venv-platform` owns `fi.prompt`, while `.venv-alk` owns `fi.evals`. The commands below name the interpreter explicitly. The only thing the evaluation needs from the platform process is a file of test cases.

## 1. Commit a baseline and a candidate

Save this as `create_versions.py`. The first commit labels v1. The second commit saves v2 for comparison without moving that label.

```python
import os
from fi.prompt import Prompt
from fi.prompt.types import ModelConfig, PromptTemplate, SystemMessage, UserMessage

name = os.environ["PROMPT_NAME"]
routing = (
    "Route tickets for Ridgeline Outfitters. Unused gear goes to returns. "
    "Damaged gear goes to repairs. "
)

def template(instruction):
    return PromptTemplate(
        name=name,
        messages=[
            SystemMessage(content=routing + instruction),
            UserMessage(content="Ticket: {{ticket}}"),
        ],
        model_configuration=ModelConfig(model_name="gpt-4o-mini", temperature=0),
    )

if __name__ == "__main__":
    prompt = Prompt(template=template("Recommend the right team in a sentence."))
    prompt.create()
    prompt.commit_current_version(message="Route tickets for a support rep", label="production")
    prompt.create_new_version(template=template("Return only the queue code: RETURNS or REPAIRS."))
    prompt.commit_current_version(message="Return a code the ticket system can dispatch")
    live = Prompt.get_template_by_name(name=name, label="production")
    print("production:", live.template.version, "candidate:", prompt.template.version)
```

```bash
.venv-platform/bin/python create_versions.py
```

For a new template, check that `production` resolves to `v1` and the candidate is `v2`. You can also open the prompt's **History** drawer and select **Commit History** to see the two versions and which one has the label.

## 2. Export the same tickets for both versions

Save this as `export_cases.py`. Fetch each version **by number**, so a later label change cannot silently change the comparison. `compile()` substitutes the ticket into the template and returns chat messages; it does not call a model.

```python
import json
import os
from pathlib import Path
from fi.prompt import Prompt

cases = [
    ("The unused pack is too small. Can I return it?", "RETURNS"),
    ("The seam on my tent tore. Can you fix it?", "REPAIRS"),
]
rows = []
for version in ("v1", "v2"):
    prompt = Prompt.get_template_by_name(name=os.environ["PROMPT_NAME"], version=version)
    for ticket, expected in cases:
        rows.append({"version": version, "expected": expected,
                     "messages": prompt.compile(ticket=ticket)})
Path("router-cases.json").write_text(json.dumps(rows, indent=2))
print(f"Exported {len(rows)} cases")
```

```bash
.venv-platform/bin/python export_cases.py
```

`router-cases.json` contains four requests: two tickets for each version. It includes the prompt text and the tickets, so use synthetic tickets when sharing it.

## 3. Score the replies before promotion

Save this as `score_cases.py`. It makes four model calls through OpenRouter. The `equals` metric runs locally in Agent Learning Kit. It checks whether the reply is usable **as the routing code**, including its case, rather than whether the model mentioned the right team somewhere in a sentence.

```python
import json
from pathlib import Path
from fi.evals import evaluate
from litellm import completion

for row in json.loads(Path("router-cases.json").read_text()):
    reply = completion(model="openrouter/openai/gpt-4o-mini",
                       messages=row["messages"], temperature=0)
    text = reply.choices[0].message.content.strip()
    result = evaluate("equals", engine="local", output=text,
                      expected_response=row["expected"], config={"case_sensitive": True})
    if result.error:
        raise RuntimeError(result.error)
    print(row["version"], row["expected"], "PASS" if result.passed else "FAIL", repr(text))
```

```bash
.venv-alk/bin/python score_cases.py
```

Example output from the two prompts:

```text
v1 RETURNS FAIL 'Route this ticket to returns, as the unused pack can be returned. Recommend the returns team for processing the return.'
v1 REPAIRS FAIL 'Route this ticket to repairs for the damaged gear.'
v2 RETURNS PASS 'RETURNS'
v2 REPAIRS PASS 'REPAIRS'
```

Both v1 replies picked the right team but failed the ticket system's format check. If v2 produces a sentence, punctuation, or the wrong code, leave `production` on v1. Review the printed replies and revise the candidate. Passing these two cases tests the output contract, not every routing decision.

## 4. Promote, serve, or roll back

Save this as `serve.py`. With a version argument, it moves the label on **this template**. Without an argument it only looks up the labeled version, just as your application would. Pass the compiled `messages` to your chat model when serving a real ticket.

```python
import os
import sys
from fi.prompt import Prompt

name = os.environ["PROMPT_NAME"]
if len(sys.argv) == 2:
    Prompt.assign_label_to_template_version(template_name=name, version=sys.argv[1],
                                            label="production")
live = Prompt.get_template_by_name(name=name, label="production")
messages = live.compile(ticket="The seam on my tent tore. Can you fix it?")
print("Serving", live.template.version)
print(messages[-1]["content"])
```

After reviewing the scores, promote v2 and verify what the application fetches:

```bash
.venv-platform/bin/python serve.py v2
.venv-platform/bin/python serve.py
```

To roll back, move the same label to v1; there's no need to recreate either version:

```bash
.venv-platform/bin/python serve.py v1
```

## Troubleshooting

- **A prompt or eval import fails:** check which interpreter ran the script. If you installed both distributions together, start with two fresh environments rather than reinstalling them on top of one another.
- **The application still uses v1:** `get_template_by_name()` caches lookups in the Python process. Check the label in a fresh process with `serve.py` before changing it again. An application pinned to `version="v1"` does not follow a label.
- **The test inputs contain literal braces:** match the keyword passed to `compile(ticket=...)` to the `{{ticket}}` variable. An unresolved variable stays in the compiled message.
