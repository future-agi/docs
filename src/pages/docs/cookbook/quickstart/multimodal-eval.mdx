<TLDR>
Compare each output with its source: a caption with its image, speech with the intended text, or extracted fields with their PDF.
</TLDR>

## The problem

A caption can describe a red handbag in fluent detail when the image shows white sneakers. The same problem applies to speech and document extraction: reading the output alone cannot tell you what was actually in the source.

## What you'll build

A caption check that holds the image fixed while you change the description, with separate checks for image origin, audio and PDF extraction.

<Mermaid chart={`
flowchart LR
    accTitle: Compare a caption with its source
    accDescr: Use the same sneaker image for two captions. The caption evaluator compares each pair and returns a verdict with a reason.
    A["Sneaker image"] --> B["Two candidate captions"] --> C["Caption evaluator"] --> D["Verdict and reason"]
`} />

You'll:

1. Map a source file and its candidate output to the evaluator.
2. Compare the sneaker caption with the handbag caption using the same image.
3. Choose separate templates for audio quality, text-to-speech accuracy and optical character recognition (OCR).

<Prerequisites title="Before you start">
- A Future AGI account with [workspace keys](/docs/admin-settings/api-keys).
- For the Python steps, Python 3.11. For the dashboard, a dataset containing the source and output columns.
- For OCR, a publicly reachable PDF that is safe to share and the fields extracted from that document.
</Prerequisites>

## Check a dataset row in the dashboard

You can run these evals directly from the Future AGI platform without writing any code. To follow the caption example, use the sneaker image and the two captions from step 2 below, one dataset row per caption, so the image stays the same while the caption changes.

1. Go to **Datasets** and create or open a dataset.
2. Add columns for your multimodal inputs, for example an `image` column with image URLs, or an `audio` column with audio URLs.
3. Click **Add Evaluation**.
4. Select a multimodal eval, for example `caption_hallucination` or `audio_quality`.
5. Map the eval's required keys to your dataset columns, for example `image` to your image column and `caption` to your caption column.
6. Choose a Turing [evaluator model](/docs/evaluation/concepts/evaluator-models).
7. Click **Run**.

You should see scores alongside each row in the dataset. Read each result against the source image, not just the text of the caption.

This is the same approach shown in the [Dataset SDK cookbook](/docs/cookbook/quickstart/batch-eval), but with multimodal columns instead of text-only.

## Prepare the Python environment

The Python steps use the `Evaluator` class from `fi.evals`. Install the package the notebook uses:

```bash
pip install ai-evaluation
```

For the Agent Learning Kit evaluator interface (`fi.alk.evals`), see [Run a saved eval from code](/docs/evaluation/guides/decision-models#run-a-saved-eval-from-code).

Set the matching keys in the environment that runs the examples:

```bash
export FI_API_KEY="your-api-key"
export FI_SECRET_KEY="your-secret-key"
```

## 1. Set up the Evaluator

```python
import os
from fi.evals import Evaluator

evaluator = Evaluator(
    fi_api_key=os.environ["FI_API_KEY"],
    fi_secret_key=os.environ["FI_SECRET_KEY"],
)
```

You should see no output. `evaluator` has been constructed; this alone does not test access to a template.

## 2. Detect caption hallucination

Use [caption hallucination](/docs/evaluation/builtin/caption-hallucination) to check whether a caption describes what is visible. Pass the image as a URL (or base64) and the caption as text.

```python
result = evaluator.evaluate(
    eval_templates="caption_hallucination",
    inputs={
        "image": "https://raw.githubusercontent.com/future-agi/cookbooks/main/ecom_agent/observe/generated_products/nike_air_max_sneakers.png",
        "caption": "A pair of white sneakers with a wavy sole design.",
    },
    model_name="turing_small",
)

eval_result = result.eval_results[0]
print(f"Passed: {eval_result.output}")
print(f"Reason: {eval_result.reason}")
```

Read the verdict and reason for the sneaker caption. For the contrast, change only the caption:

```python
result = evaluator.evaluate(
    eval_templates="caption_hallucination",
    inputs={
        "image": "https://raw.githubusercontent.com/future-agi/cookbooks/main/ecom_agent/observe/generated_products/nike_air_max_sneakers.png",
        "caption": "A red leather handbag with gold buckles on a wooden table.",
    },
    model_name="turing_small",
)

eval_result = result.eval_results[0]
print(f"Passed: {eval_result.output}")
print(f"Reason: {eval_result.reason}")
```

Compare the two reasons. A useful failure on the second caption identifies what the image does not show, such as the handbag; a pass on the first should refer to the sneakers.

## 3. Detect AI-generated images

Use the [synthetic image evaluator](/docs/evaluation/builtin/synthetic-image-evaluator) to score whether an image was generated or photographed.

```python
result = evaluator.evaluate(
    eval_templates="synthetic_image_evaluator",
    inputs={
        "image": "https://raw.githubusercontent.com/future-agi/cookbooks/main/ecom_agent/observe/generated_products/nike_air_max_sneakers.png",
    },
    model_name="turing_small",
)

eval_result = result.eval_results[0]
print(f"Score:  {eval_result.output}")
print(f"Reason: {eval_result.reason}")
```

You should see a numeric score plus a reason describing the visual cues the model used.

## 4. Evaluate audio quality

Use [audio quality](/docs/evaluation/builtin/audio-quality) for a Mean Opinion Score (MOS) assessment. Pass the audio file as a URL or base64.

<Warning>
`audio_quality` requires `model_name="turing_large"`: audio evals need a model that can read audio, and a smaller model returns an unsupported-model error. The OCR example below also uses `turing_large`.
</Warning>

```python
result = evaluator.evaluate(
    eval_templates="audio_quality",
    inputs={
        "input_audio": "https://storage.googleapis.com/cloud-samples-data/speech/brooklyn_bridge.flac",
    },
    model_name="turing_large",
)

eval_result = result.eval_results[0]
print(f"Score:  {eval_result.output}")
print(f"Reason: {eval_result.reason}")
```

You should see a MOS-style score and a reason noting artifacts like noise or clipping, if any.

## 5. Evaluate text-to-speech accuracy

Use [text-to-speech accuracy](/docs/evaluation/builtin/tts-accuracy) to compare spoken words, emphasis and tone with the intended text. The audio URL below is a speech sample, not a recording of the supplied welcome message.

```python
result = evaluator.evaluate(
    eval_templates="TTS_accuracy",
    inputs={
        "text": "Welcome to Future AGI. Our platform helps you evaluate and optimize AI applications.",
        "generated_audio": "https://storage.googleapis.com/cloud-samples-data/speech/brooklyn_bridge.flac",
    },
    model_name="turing_large",
)

eval_result = result.eval_results[0]
print(f"Score:  {eval_result.output}")
print(f"Reason: {eval_result.reason}")
```

You should see a score and a reason comparing the spoken audio against the source text.

## 6. Evaluate OCR output against a PDF

Use [OCR evaluation](/docs/evaluation/builtin/ocr-evaluation) to compare extracted fields with the source PDF. The URL below is a placeholder. Substitute `input_pdf` with a publicly reachable URL to your own PDF, and `json_content` with the fields you expect the OCR pass to have extracted from it.

```python
result = evaluator.evaluate(
    eval_templates="ocr_evaluation",
    inputs={
        "input_pdf": "https://your-public-url.example.com/your-document.pdf",
        "json_content": '{"invoice_number": "INV-2024-001", "total": "$1,250.00", "date": "2024-03-15"}',
    },
    model_name="turing_large",
)

eval_result = result.eval_results[0]
print(f"Score:  {eval_result.output}")
print(f"Reason: {eval_result.reason}")
```

You should see a score and a reason listing which fields matched or diverged from the PDF, based on the document and fields you supplied.

## Troubleshooting

<div class="sdk-ref-table">

| Symptom | Cause | Fix |
|---|---|---|
| `Evaluator()` raises a missing-credentials error | `FI_API_KEY` or `FI_SECRET_KEY` isn't exported before the script runs | Export both keys, or pass `fi_api_key`/`fi_secret_key` directly to `Evaluator()` |
| `audio_quality` or `ocr_evaluation` returns an unsupported-model error | Called with a smaller model such as `turing_small`. A model that handled an image eval need not support audio or PDFs | Use `model_name="turing_large"`, as the audio and OCR examples do |
| `caption_hallucination` or `synthetic_image_evaluator` comes back empty or errors | The image URL isn't publicly reachable, for example a private bucket or an expired signed URL | Use a publicly accessible URL, or pass the image as base64 |
| `ocr_evaluation` scores low even on a correct extraction | `json_content` isn't valid JSON, for example a trailing comma or an unescaped quote | Validate the string with `json.loads()` before passing it in |
| `TTS_accuracy` or `audio_quality` times out on a long clip | The input audio runs several minutes and the evaluation model processes it in full | Trim the clip to the relevant segment before scoring |
| `result.eval_results[0]` is `None` | That row failed to evaluate, usually a bad input URL or an unsupported file type | Check the entry for `None` before reading `.output` or `.reason`, and re-check the input for that row |

</div>
