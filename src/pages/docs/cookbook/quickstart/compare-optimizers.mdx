## About

Three optimizers can all rewrite a support prompt but learn from different evidence. Try ProTeGi, GEPA, and PromptWizard on Ridgeline Outfitters' ticket router. Hold the model and grading rule fixed so a difference in scores means a difference in routing, not a change of metric.

| Time | Difficulty | Package |
|---|---|---|
| 15 min | Intermediate | `agent-learning-kit==0.3.7` |

## Set up Python

Use a fresh Python 3.12 environment. Set `OPENAI_API_KEY` to your OpenAI key. Both the teacher and the ticket router use that key; the exact-match metric runs locally without Future AGI credentials.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install agent-learning-kit==0.3.7
export OPENAI_API_KEY="your-openai-key"
```

## Compare three ways to use feedback

| Strategy | How it changes the prompt |
|---|---|
| ProTeGi | Finds low-scoring examples, asks for a critique, and uses that critique to propose edits. The beam contains the prompts retained for the next round. |
| GEPA | Uses the input, generated reply, score, and reason from an evaluation to reflect on what to change. |
| PromptWizard | Generates variants, scores them, then critiques and refines a top prompt if it finds errors. |

Use the same seed, `Equals` evaluator, and two training tickets in all three calls. The held-out rows are used only to compare the returned generators. Save as `compare_feedback.py` and run `python compare_feedback.py`.

<CodeGroup titles={["Python"]}>

```python
from fi.evals.metrics import Equals
from fi.opt.base import Evaluator
from fi.opt.datamappers import BasicDataMapper
from fi.opt.generators import LiteLLMGenerator
from fi.opt.optimizers import GEPAOptimizer, PromptWizardOptimizer, ProTeGi

MODEL = "openai/gpt-4o-mini"
seed = "Ticket: {ticket}\nQueue (RETURNS or REPAIRS):"
train = [
    {"ticket": "My new boots don't fit. Can I send them back?", "queue": "RETURNS"},
    {"ticket": "Can you fix a broken buckle on my pack?", "queue": "REPAIRS"},
]
mapper = BasicDataMapper({
    "response": "generated_output",
    "expected_response": "queue",
})
evaluator = Evaluator(metric=Equals(config={"case_sensitive": True}))
holdout = [
    {"ticket": "I ordered the wrong tent. Can I get a refund?", "queue": "RETURNS"},
    {"ticket": "Can you replace my sleeping bag zipper?", "queue": "REPAIRS"},
]


def accuracy(generator, rows):
    inputs = []
    for row in rows:
        reply = generator.generate({"ticket": row["ticket"]})
        if not reply:
            raise RuntimeError("No reply from the generator")
        inputs.append(mapper.map(reply, row))
    scores = evaluator.evaluate(inputs)
    return sum(item.score for item in scores) / len(rows)


teacher = LiteLLMGenerator(MODEL, "{prompt}")
shared = dict(
    evaluator=evaluator, data_mapper=mapper, dataset=train, initial_prompts=[seed]
)
protegi = ProTeGi(
    teacher, num_gradients=1, errors_per_gradient=1, prompts_per_gradient=1, beam_size=1
)
gepa = GEPAOptimizer(reflection_model=MODEL, generator_model=MODEL)
wizard = PromptWizardOptimizer(teacher, mutate_rounds=1, refine_iterations=1)
results = {
    "ProTeGi": protegi.optimize(**shared, num_rounds=1, eval_subset_size=len(train)),
    "GEPA": gepa.optimize(**shared, max_metric_calls=8),
    "PromptWizard": wizard.optimize(
        **shared, eval_subset_size=len(train),
        task_description="Return only RETURNS or REPAIRS. Keep {ticket} as the only placeholder.",
    ),
}
print(f"Baseline holdout: {accuracy(LiteLLMGenerator(MODEL, seed), holdout):.0%}")
for name, result in results.items():
    held_out = accuracy(result.best_generator, holdout)
    print(f"{name}: search={result.final_score:.0%}, holdout={held_out:.0%}")
```

</CodeGroup>

## Read the result

`search` is the best score reported by that search. `holdout` is a fresh exact-match score on the same two unseen tickets for every strategy. Here is an example of how to read the score lines. Your scores can differ:

```text
Baseline holdout: 100%
ProTeGi: search=50%, holdout=50%
GEPA: search=50%, holdout=100%
PromptWizard: search=100%, holdout=100%
```

In this example, PromptWizard had the highest search score, but on the unseen tickets it tied both GEPA and the original prompt. Choosing it on the search score alone would mistake a training result for an improvement.

## Limits and troubleshooting

- On a two-ticket holdout, one changed answer moves accuracy by 50 percentage points. A tie does not tell you the algorithms are equivalent.
- A ProTeGi round, a PromptWizard mutation round, and a GEPA metric call measure different work. Even one mutation round can generate several variants, each of which needs model replies to score.
- If a search appears to work but produces empty replies, check the model provider before changing the prompt. `LiteLLMGenerator.generate()` can return an empty string after a provider error.
