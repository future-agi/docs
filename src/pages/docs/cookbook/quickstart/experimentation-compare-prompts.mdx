<TLDR>
Run two prompt templates across two models on one dataset, score the outputs with groundedness, and let Choose Winner rank the variants in the Summary table.
</TLDR>

| Time | Difficulty | Package |
|------|-----------|---------|
| 15 min | Intermediate | Platform UI |

<Prerequisites>
- Future AGI account: [app.futureagi.com](https://app.futureagi.com)
- Permission to create datasets, prompts, and experiments in the same workspace
- An LLM API key configured in the platform
</Prerequisites>

## Tutorial

<Steps>
<Step title="Create a test dataset">

Go to [app.futureagi.com](https://app.futureagi.com). Select **Dataset** > **Add Dataset** > **Upload a file (JSONl/ JSON/ CSV)**.

Save as `experiment-data.csv` and upload:

```csv
question,context,expected_answer
"What is the return window for a purchase?","Items can be returned within 30 days of delivery for a full refund, provided the item is unused and in its original packaging.","30 days"
"Do you ship internationally?","We currently ship to over 40 countries. International orders take 7-14 business days and customs fees are the customer's responsibility.","Yes, to over 40 countries"
"Can I cancel an order after placing it?","Orders can be cancelled free of charge within 1 hour of placement. After that, the order enters fulfillment and cannot be cancelled.","Yes, within 1 hour of placement"
"How do I reset my account password?","Go to Settings > Security and click 'Reset Password'. A reset link is emailed to the account's registered address and expires after 24 hours.","Use Settings > Security > Reset Password"
"How are loyalty points earned and redeemed?","Customers earn 1 point per dollar spent. Points can be redeemed at checkout starting at 500 points for a $5 discount.","1 point per dollar, redeemable from 500 points"
```

You should see a 5-row dataset with `question`, `context`, and `expected_answer` columns in the dataset viewer.

</Step>
<Step title="Create the baseline prompt">

In **Workbench**, create a chat prompt named `baseline-prompt`. Use these two messages, then commit the version. The experiment selects committed versions, not drafts.

**System message:**
```
You answer customer questions for Ridgeline Outfitters. Answer questions using only the provided context.
```

**User message:**
```
Context: {{context}}
Question: {{question}}
```

The user message has two variables. Keep their names identical to the `context` and `question` CSV headers so the experiment can fill them from each row.

</Step>
<Step title="Create the second prompt">

In **Workbench**, create another chat prompt named `concise-prompt`. Commit this version with the following messages:

**System message:**
```
You are a precise question-answering assistant. Use only the information provided in the context. Do not add any external knowledge.
```

**User message:**
```
Step 1: Read the context carefully.
Step 2: Identify the specific fact that answers the question.
Step 3: Write a concise answer using only that fact.

Context: {{context}}
Question: {{question}}

Answer:
```

</Step>
<Step title="Configure the comparison">

Open the uploaded dataset and start an experiment. In **Basic information**, enter `prompt-ab-test` as the **Experiment Name** and select an LLM experiment. Continue to **Configure prompts/agents**.

1. Under **Add Prompt/Agents**, select the two chat prompts. For each, choose its committed version.
2. Choose the same two models for each prompt, for example `gpt-4` and `gpt-4o` from your configured provider. Use **Add models** to add the second model.
3. Check that both prompt variables match dataset columns. With five rows, two prompts and two models, you'll compare 20 generated answers.

</Step>
<Step title="Configure groundedness and run">

In **Configure Evaluations**, select `expected_answer` under **Compare against baseline (optional)**. Click **Add Evaluations**, select `groundedness`, choose `turing_small` as the evaluation model, and map the inputs:

| Metric input | Source |
|---|---|
| `output` | **Output**, the generated answer for the current variant |
| `context` | The `context` dataset column |
| `input` | The `question` dataset column |

Add the evaluation before starting the experiment. The baseline is a reference for comparing answers; it is not the generated output. Run the experiment and open its **Data** view to inspect the answers and groundedness results for each row.

</Step>
<Step title="Compare results in the Summary tab">

Switch to the **Summary** tab to see:

- **Summary table**: aggregate scores per prompt variant and model, including average response time, total tokens, and completion tokens
- **Comparison chart**: with one or two metrics, you see columns. With three or more metrics, you see a spider chart.
- **Evaluation charts**: one aggregate score per prompt/model combination for each metric

You should see `concise-prompt` and `baseline-prompt` as separate rows in the summary table, each with its own groundedness score.

Check the individual answers as well as the averages: on five rows, one unsupported answer can change the ranking.

</Step>
<Step title="Pick the winner">

1. Click **Choose Winner** (crown icon) in the Summary tab
2. The **Winner Settings** drawer opens. Set importance weights (0-10 scale) for:
   - Evaluation metrics (e.g. groundedness)
   - Average Response Time
   - Completion Tokens
   - Total Tokens
3. Click **Save & Run**

Look for the crown next to rank **1** in the Summary table. It identifies the winner even when it is not the first row.

</Step>
</Steps>

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `{{context}}` or `{{question}}` shows up literally in the output instead of being substituted | The `{{column_name}}` doesn't exactly match a dataset column header | Match the placeholder to the CSV header spelling and case, e.g. `{{context}}` for a `context` column |
| Cannot continue after selecting prompts | A selected version is still a draft, has no model, or its variables don't match columns | Commit the version, select a model, and check that both variables are mapped |
| Cannot run without an evaluation | No metric has been added in **Configure Evaluations** | Add `groundedness` and map its inputs before running |
| Groundedness is being computed on the reference answer | The `output` mapping points to `expected_answer` | Map `output` to **Output** so the check scores each generated answer |
| The Summary tab shows columns instead of a spider chart | You ran fewer than three evaluation metrics | Compare groundedness in the column chart. Add other metrics only if they measure something you need. |
| Choose Winner picks a variant with the lower groundedness score | Response Time and Token weights are set higher than the evaluation metric weight | Lower the Response Time and Token weights in Winner Settings if accuracy matters more than latency or cost |
