<TLDR>
Run two prompt templates across two models on one dataset, score the outputs with groundedness, and let Choose Winner rank the variants in the Summary table.
</TLDR>

| Time | Difficulty | Package |
|------|-----------|---------|
| 15 min | Intermediate | Platform UI |

<Prerequisites>
- Future AGI account: [app.futureagi.com](https://app.futureagi.com)
- A dataset with at least `question`, `context`, and `expected_answer` columns (follow Step 1 to create one)
- An LLM API key configured in the platform
</Prerequisites>

## Tutorial

<Steps>
<Step title="Create a test dataset">

Go to [app.futureagi.com](https://app.futureagi.com). Select **Dataset** > **Add Dataset** > **Upload a file (JSONl/ JSON/ CSV)**.

Save as `experiment-data.csv` and upload:

```csv
question,context,expected_answer
"What is the return window for a purchase?","Items can be returned within 30 days of delivery for a full refund, provided the item is unused and in its original packaging.","30 days"
"Do you ship internationally?","We currently ship to over 40 countries. International orders take 7-14 business days and customs fees are the customer's responsibility.","Yes, to over 40 countries"
"Can I cancel an order after placing it?","Orders can be cancelled free of charge within 1 hour of placement. After that, the order enters fulfillment and cannot be cancelled.","Yes, within 1 hour of placement"
"How do I reset my account password?","Go to Settings > Security and click 'Reset Password'. A reset link is emailed to the account's registered address and expires after 24 hours.","Use Settings > Security > Reset Password"
"How are loyalty points earned and redeemed?","Customers earn 1 point per dollar spent. Points can be redeemed at checkout starting at 500 points for a $5 discount.","1 point per dollar, redeemable from 500 points"
```

You should see a 5-row dataset with `question`, `context`, and `expected_answer` columns in the dataset viewer.

</Step>
<Step title="Prepare saved prompts and open New experiment">

Create and save a version of each prompt below before selecting it in the experiment. See [Prompt Versioning](/docs/cookbook/quickstart/prompt-versioning) for creating and committing prompt versions. Drafts cannot be selected as the saved version for a run.

**`baseline-prompt` — system message:**
```
You are a helpful assistant. Answer questions using only the provided context.
```

**`baseline-prompt` — user message:**
```
Context: {{context}}
Question: {{question}}
```

**`cot-prompt` — system message:**
```
You are a precise question-answering assistant. Use only the information provided in the context. Do not add any external knowledge.
```

**`cot-prompt` — user message:**
```
Step 1: Read the context carefully.
Step 2: Identify the specific fact that answers the question.
Step 3: Write a concise answer using only that fact.

Context: {{context}}
Question: {{question}}

Answer:
```

Open your dataset and click **New experiment**. The wizard has four steps: **Configuration → Data → Evaluations → Review & run**. New experiments use LLMs; there is no model-type choice for Text-to-Speech, Speech-to-Text, or Image Generation in this flow.

</Step>
<Step title="Configuration: choose prompts and models">

1. Name the experiment `prompt-ab-test`.
2. Add `baseline-prompt` and select its saved version.
3. Select the models to compare, for example `gpt-4o-mini` and `gpt-4o`.
4. Add `cot-prompt`, select its saved version, and choose the same models.

Each prompt-model pair is a separate configuration. Two prompts with two models each give you four configurations. Click **Continue** to move to **Data**.

</Step>
<Step title="Data: map the inputs">

Check the five dataset rows, then map the required variables for both prompts:

| Prompt variable | Dataset column |
|---|---|
| `context` | `context` |
| `question` | `question` |

Check the sample values for each mapping. Unmapped required variables block **Continue** and the final run action.

Select `expected_answer` in **Expected answers column** if an evaluation needs a reference answer. This is separate from the `context` column used by groundedness. Continue to **Evaluations**.

</Step>
<Step title="Evaluations: attach groundedness">

Add `groundedness` to score the configurations. Check its input mapping: `output` reads **Run output**, and `context` reads the dataset's `context` column. If the evaluation requests `input`, map it to `question`.

At least one evaluation must be attached before you can run the experiment. Continue to **Review & run** after checking the selected evaluation.

</Step>
<Step title="Review & run">

Review the four configurations, data mappings, and evaluation, then click **Run experiment**.

The platform runs both saved prompt versions across the selected models on the dataset rows and scores the generated outputs with the attached evaluation. In the experiment's **Data** tab, compare outputs and evaluation scores across the prompt/model combinations.

<Note>
To attach more evaluations, click **Add evaluations** in the experiment's **Data** toolbar. You do not need to wait for the whole experiment to finish before opening this control. Evaluations score the generated outputs, not the original dataset's input columns.
</Note>

</Step>
<Step title="Compare results in the Summary tab">

Switch to the **Summary** tab to see:

- **Summary table**: aggregate scores per prompt variant and model, including average response time, total tokens, and completion tokens
- **Spider chart**: visual comparison of all evaluation metrics across variants
- **Evaluation charts**: per-metric score distribution across prompt/model combinations

You should see `cot-prompt` and `baseline-prompt` as separate rows in the summary table, each with its own groundedness score.

The actual groundedness scores from the run behind these videos were not recorded, so no baseline-vs-`cot-prompt` delta is reported here. Re-run this experiment and note the two averages before publishing an outcome.

</Step>
<Step title="Pick the winner">

1. Click **Choose Winner** (crown icon) in the Summary tab
2. The **Winner Settings** drawer opens. Set importance weights (0-10 scale) for:
   - Evaluation metrics (e.g. groundedness)
   - Average Response Time
   - Completion Tokens
   - Total Tokens
3. Click **Save & Run**

The winning variant is ranked at the top of the summary table.

</Step>
</Steps>

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Prompt inputs do not match the intended dataset values | A required variable maps to the wrong column | In **Data**, check the `context` and `question` mappings and their sample values for both prompts |
| **Continue** or **Run experiment** stays disabled | A saved prompt version, model, required input mapping, or evaluation is missing | Resolve the issues shown in **Configuration**, **Data**, and **Evaluations**; attach at least one evaluation before running |
| Cannot find **Evaluate** on the Data tab | The toolbar control is named **Add evaluations** | Open the experiment's **Data** tab and click **Add evaluations**; this control is not limited to completed runs |
| Groundedness scores are missing | Outputs are not ready or evaluation inputs are mapped incorrectly | Check the run's outputs and evaluation mapping; in the wizard, `output` reads **Run output** and `context` reads the dataset's `context` column |
| Spider chart in the Summary tab shows only one axis | Only one evaluation metric has been run | Add and run at least one more eval metric so there are multiple axes to plot |
| Choose Winner picks a variant with the lower groundedness score | Response Time and Token weights are set higher than the evaluation metric weight | Lower the Response Time and Token weights in Winner Settings if accuracy matters more than latency or cost |

---
