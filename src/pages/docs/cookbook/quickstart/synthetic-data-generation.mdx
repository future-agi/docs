<TLDR>
Define a column schema with types, constraints, and categorical distributions, then generate a structured synthetic dataset from the Future AGI dashboard. Review the output, iterate on the schema, and run quality evals on the generated rows.
</TLDR>

| Time | Difficulty | Package |
|------|-----------|---------|
| 10 min | Beginner | Dashboard only |

<Prerequisites>
- A [Future AGI workspace](https://app.futureagi.com) with synthetic data generation enabled
- If you self-host, configure the generation worker for Vertex AI: set `GOOGLE_GENAI_USE_VERTEXAI=true`, set `GOOGLE_APPLICATION_CREDENTIALS` to the path of a credentials file the worker can read, and set `GOOGLE_CLOUD_PROJECT` and `GOOGLE_CLOUD_LOCATION` to a project and location with access to the model. These settings belong on the worker, not in the browser or the client script.
- Neither the wizard nor the API accepts a model or provider override. If you only have an OpenAI or OpenRouter key and no Vertex AI worker, you can generate the rows separately and [upload them as a CSV](/docs/dataset/guides/create-a-dataset#upload-a-file) instead.
</Prerequisites>

## Tutorial

<Steps>
<Step title="Start the synthetic data wizard">

1. Open [Future AGI](https://app.futureagi.com) or your self-hosted dashboard, then choose **Dataset** and **Add Dataset**
2. Select **Create Synthetic Data**

You should see the Create Synthetic Data wizard open, prompting for a dataset name and description.

</Step>
<Step title="Add details">

| Field | Value |
|---|---|
| **Name** | `support-qa-synthetic` |
| **Description** | `Ridgeline Outfitters customer support questions and answers about returns, shipping, billing, and account access.` |
| **Objective** | `Fine-tuning a support chatbot` |
| **Pattern** | `Use natural customer questions and concise, actionable answers. Use fictional orders and no personal information.` |
| **Enter No. of rows** | `20` |

**Select knowledge base** (optional): select a Knowledge Base to ground the generated rows in your own documents instead of the schema alone. Leave it empty to generate without domain grounding. Give the generated rows a skim before you rely on them; column properties aren't hard validation on the result.

To set up a KB first, see the [Knowledge Base cookbook](/docs/cookbook/quickstart/knowledge-base). You can also start directly from the KB detail view: click **Create Synthetic data** in the action bar, and the wizard opens with your KB pre-selected.

Click **Next**.

You should see the wizard advance to the column configuration step.

</Step>
<Step title="Add column properties">

Use the first blank column for `category`. Click **Add columns** twice to add `question` and `answer`.

**Column 1: `category`**
- **Column Type**: Text
- **Properties**: set **Value** to `Categorical`. Add `shipping`, `billing`, `returns`, and `account` and assign 25% to each.

**Column 2: `question`**
- **Column Type**: Text
- **Properties**: `Min Length` = `20`, `Max Length` = `200`

**Column 3: `answer`**
- **Column Type**: Text
- **Properties**: `Min Length` = `50`, `Max Length` = `500`

<Note>
Category percentages must sum to 100%. Use **Add more properties** to add constraints per column. See [Limits & Data Types](/docs/dataset/reference/limits-and-data-types) for supported column types and [Synthetic Data](/docs/dataset/concepts/synthetic-data) for the property editor.
</Note>

Click **Next**.

You should see the wizard advance to the column description step, with an input for each column you added.
</Step>
<Step title="Add descriptions">

Give each column a description. Describe the relationship you want between fields; check the result in the generated rows.

**Column 1: category**
```text
One of the four support categories: shipping, billing, returns, or account.
```

**Column 2: question**
```text
A customer asks Ridgeline Outfitters a realistic question about the category in this row. Use the customer's own words.
```

**Column 3: answer**
```text
Answer the customer's question in this row. Give a concrete next step without inventing order details or promising a refund.
```

You should see all three description fields filled in, with the **Create Dataset** button now active.

</Step>
<Step title="Generate">

Click **Create Dataset**. The dashboard opens `support-qa-synthetic` while the worker generates the data. The platform creates 20 empty rows before the worker fills them, so a row count of 20 does not mean generation succeeded. Before you continue, check that the rows contain categories, questions, and answers.
</Step>
<Step title="Review and iterate">

- Sort or filter rows to inspect quality
- To re-generate or modify: click **Configure Synthetic Data** in the dataset toolbar. The **Synthetic Data Details** drawer opens

<Warning>
Regenerating wipes the dataset's current rows and columns and rebuilds them from the config. To keep the original unchanged, choose **Edit Configuration**, then **Create as new dataset**.
</Warning>

- If the drawer shows **Re-Generate same Configuration** after a failure, use it to retry with the same settings. It rebuilds every row.
- Select **Edit Configuration** to modify the schema, then **Save** and choose:
  - **Replace the current dataset**: overwrite with new rows.
  - **Create as new dataset**: enter a new name and leave the original unchanged.
  - **Add it to existing dataset**: update the existing dataset to the requested **total**. To add five rows to a 20-row dataset, turn off **Keep no. of rows same** in **Add details** and set the count to `25`. Lowering the total removes rows; omitting a column removes it from the dataset.

</Step>
<Step title="Run evals on the generated data">

1. Click **Evaluate** in the dataset toolbar
2. **Add Evaluations** then select `completeness`
3. Map keys: `output` to `answer`, `input` to `question`
4. Click **Add & Run**

Inspect the `completeness` score column alongside the generated answers. For example, an answer can acknowledge the problem without telling the customer what to do:

| question | answer | What to review |
|---|---|---|
| "My order #4471 arrived damaged, what do I do?" | "We're sorry to hear that. Please reach out to our team for help." | The answer doesn't say how to reach support or what happens next. |

Inspect low-scoring answers. If an answer says only “contact support,” revise the description to ask for an actionable next step, then generate a new dataset and compare answers. A higher score does not establish that a response follows your store’s policy.

## Optional: create the dataset by API

Use this instead of clicking **Create Dataset** to submit the same schema to the generation worker. Save the three descriptions from Step 4 as `category.txt`, `question.txt`, and `answer.txt` in one directory. Set `FI_API_KEY` and `FI_SECRET_KEY` in your shell. If you self-host, set `FI_BASE_URL` to your own API origin before running the script; otherwise the request goes to `https://api.futureagi.com`. In the same directory, save the following as `create_support_dataset.py` and run `python3 create_support_dataset.py`.

```python
import json
import os
from pathlib import Path
from urllib.request import Request, urlopen
from uuid import uuid4

properties = {
    "category": {"value": "categorical", "shipping": "25", "billing": "25", "returns": "25", "account": "25"},
    "question": {"min_length": "20", "max_length": "200"},
    "answer": {"min_length": "50", "max_length": "500"},
}
name = f"support-qa-synthetic-{uuid4().hex[:10]}"
payload = {
    "dataset": {
        "name": name,
        "description": "Ridgeline Outfitters customer support questions and answers about returns, shipping, billing, and account access.",
        "objective": "Fine-tuning a support chatbot",
        "patterns": "Use natural customer questions and concise, actionable answers. Use fictional orders and no personal information.",
    },
    "num_rows": 20,
    "columns": [
        {"name": col, "data_type": "text", "property": props,
         "description": Path(f"{col}.txt").read_text(encoding="utf-8").strip()}
        for col, props in properties.items()
    ],
}
base = os.getenv("FI_BASE_URL", "https://api.futureagi.com").rstrip("/")
request = Request(
    f"{base}/model-hub/develops/create-synthetic-dataset/",
    data=json.dumps(payload).encode(),
    headers={"Content-Type": "application/json", "X-Api-Key": os.environ["FI_API_KEY"],
             "X-Secret-Key": os.environ["FI_SECRET_KEY"]},
)
with urlopen(request, timeout=60) as response:
    dataset_id = json.load(response)["result"]["data"]["id"]
print(f"Generation requested for {name}. Dataset ID:")
print(dataset_id)
```

The ID identifies the dataset, not a completed generation. Open the new dataset under **Dataset** and check that the cells contain generated values before evaluating them.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| **Next** stays disabled on the column properties step | A column is missing a name or type, or a property is missing its type or a nonzero value | Complete each field or remove the unused column or property |
| Generated rows read as generic Q&A, not tied to a category | Column descriptions do not explain how the fields relate | State that each question must fit its row’s category and that its answer must address that question |
| **Select knowledge base** dropdown is empty | The wizard has no knowledge bases to list for your workspace | Leave it empty for this example, or create a KB you can access |
| The dataset exists but all 20 rows remain empty | The worker has not filled the cells. On a self-hosted instance it may lack Vertex AI access | Reopen the same dataset instead of submitting another request. Ask your administrator to check the generation worker and its Vertex AI configuration before retrying |
| **Re-Generate same Configuration** produces near-duplicate rows | The schema, Pattern, and column descriptions are unchanged from the original run | Edit the Pattern or a column description under **Edit Configuration** before regenerating |
| Evaluate step shows no score column after **Add & Run** | `output` or `input` mapped to the wrong dataset column | Confirm `output` maps to `answer` and `input` maps to `question` before running |
