<Prerequisites title="Before you start">
- A workspace with traced conversations. If you don’t have sample traffic, [trace the example agent](#trace-your-own-agent) first.
- An **Agents** eval. You’ll create one in the first step.
- For the code examples, a workspace API key and secret key. The optional tracing example also needs an OpenAI API key.
</Prerequisites>

## Write the rule

1. Open **Build > Evals > Create evals**.
2. Choose **Single** as the eval type.
3. Select **Agents**.
4. In **Instructions**, open **Write with AI**.
5. Submit this request:

   > Fail if the assistant tells the guest the room is reserved, booked or confirmed when the reservation tool did not return status confirmed.

6. Check the draft against the two cases: a **booking claim** needs a `confirmed` tool result, but a reply that only reports **pending payment** should pass.
7. Select **Accept** to use the draft.

![Instructions editor showing the drafted booking rule, its three inputs and the Accept button above the draft.](/images/docs/cookbook/conversation-eval/01-writer-draft.png)

## Add Session context

A span covers one operation; a trace groups the spans for one request. The tool result and the reply can be in different traces, so give the judge access to the whole session.

1. In the **Instructions** footer, click **+** beside **Turing Large**.
2. Open **Data Injection**.
3. Switch on **Session context** (“Full conversation history”).

   ![The + menu with Data Injection selected. On the right, the Session context switch is on, with Full conversation history under it.](/images/docs/cookbook/conversation-eval/02-session-context-menu.png)

4. Close the menu. The footer should now show **+1 context**.
5. Under “Given the following,” replace the three input lines with `Session: {{session_id}}`.

   Keep the judging criteria: the variable identifies the session, and **Session context** lets the judge look up its messages and tool results.

6. Choose **Pass/fail** for the output type, leaving the model set to **Turing Large**.
7. Enter a unique **Eval Name**, such as `booking-claim-check-v2`.
8. Click **Save Evaluation**. The first saved version is **V1**.

## Test on two sessions

The video tests the rule on two guests. Maya’s reservation tool returned `confirmed`, and her assistant gave her the matching confirmation number. Daniel’s tool returned `pending_payment`, but his assistant opened with “I've reserved a double room for you, Daniel”. The rule should pass Maya and fail Daniel.

1. Open **Test Evaluation > Tracing**.
2. Choose the project containing your conversations (`harbor-view-booking` in the video).
3. Select **Sessions**.

   **Variable Mapping** already maps `session_id` to `session_id`; you don’t need to paste a transcript.

4. Use the row arrows to select Maya’s session.

   To check whose session you’ve selected, enter `user_id` in **Search columns or values**.

5. Click **Test Evaluation** for Maya.
6. Select Daniel’s session with the row arrows.
7. Click **Test Evaluation** again without changing the rule.

Compare **Result** and **Explanation**. These are the two results from the video:

## Run from code

Both SDKs call the same endpoint as **Test Evaluation**. Set these variables in your shell. Run the script once per guest, changing only `BOOKING_SESSION_ID`.

<div class="sdk-ref-table max-sm:[&_td]:px-1.5! max-sm:[&_th]:px-1.5!">

| Variable | What to set | Where to find it |
| --- | --- | --- |
| `FI_API_KEY` | Workspace API key | **Build > Keys** |
| `FI_SECRET_KEY` | Matching secret key | **Build > Keys**, when you create the key pair |
| `BOOKING_EVAL_ID` | Eval UUID | Saved eval’s URL |
| `BOOKING_SESSION_ID` | Session UUID, not its name | `session_id` in the tracing preview |
| `FI_BASE_URL` | API origin (self-hosted only) | Your deployment’s API address |

</div>

In a Python 3.12 virtual environment, install the platform SDK:

```bash
python -m pip install futureagi==0.8.1
```

Save as `check.py` and run `python check.py`:

```python
import os
from fi import Client

session_id = os.environ["BOOKING_SESSION_ID"]
with Client(timeout=120) as client:
    grade = client.request("POST", "/model-hub/eval-playground/", body={
        "template_id": os.environ["BOOKING_EVAL_ID"],
        "model": "turing_large",
        "session_id": session_id,
        "config": {"mapping": {"session_id": session_id}},
    })
print(grade["output"], grade["reason"])
```

**This run:** Maya passed and Daniel failed. Maya’s explanation did not cite her confirmation number.

Save as `check.mts` and run `node check.mts`:

```typescript
import { Client } from "@future-agi/sdk/platform";

const client = new Client({ timeout: 120_000 });
const { BOOKING_EVAL_ID: templateId, BOOKING_SESSION_ID: sessionId } = process.env;
if (!templateId || !sessionId) throw new Error("Set BOOKING_EVAL_ID and BOOKING_SESSION_ID");

const grade = await client.request("POST", "/model-hub/eval-playground/", {
  body: { template_id: templateId, model: "turing_large", session_id: sessionId,
          config: { mapping: { session_id: sessionId } } },
}) as { output: string; reason: string };
if (!grade.output || !grade.reason) throw new Error("No verdict or explanation returned");
console.log(grade.output, grade.reason);
```

## Trace your own agent

The example uses a recorded tool result but generates a **new reply** for each guest. No rooms are booked. Use the **same session ID** for every model call in one conversation.

1. Download <a href="/examples/conversation-eval/maya.json" download="maya.json">maya.json</a> and <a href="/examples/conversation-eval/daniel.json" download="daniel.json">daniel.json</a> to your working directory.
2. Set `OPENAI_API_KEY` for the model, keeping your workspace API key and secret key set.
3. **Self-hosted only:** point `FI_BASE_URL` at the trace collector (for example, `http://localhost:4318`) for this script, not at the API origin used by the eval.
4. In a Python 3.12 virtual environment, install the tracing packages:

```bash
python -m pip install fi-instrumentation-otel==1.5.1 traceai-openai==0.1.16 openai
```

Save the following as `trace_booking.py` alongside the two JSON files:

```python
import json
from pathlib import Path
from uuid import uuid4
from fi_instrumentation import register, using_session, using_user
from fi_instrumentation.fi_types import ProjectType
from openai import OpenAI
from traceai_openai import OpenAIInstrumentor

provider = register(project_type=ProjectType.OBSERVE, project_name="booking-docs-demo", verbose=False)
OpenAIInstrumentor().instrument(tracer_provider=provider)
client = OpenAI()
tool = {"type": "function", "function": {
    "name": "create_reservation", "description": "Reserve a room for a guest.",
    "parameters": {"type": "object", "properties": {
        "guest_name": {"type": "string"}, "check_in": {"type": "string", "description": "YYYY-MM-DD"},
        "nights": {"type": "integer"}, "room_type": {"type": "string"}},
        "required": ["guest_name", "check_in", "nights", "room_type"]}}}

for guest in ("maya", "daniel"):
    recorded = json.loads(Path(f"{guest}.json").read_text())
    messages = recorded[:2]  # system prompt and guest request, not the recorded reply
    tool_result = next(m["content"] for m in recorded if m["role"] == "tool")
    session = f"booking-{guest}-{uuid4().hex[:8]}"
    with using_user(guest), using_session(session):
        for _ in range(4):
            reply = client.chat.completions.create(
                model="gpt-4o-mini", messages=messages, tools=[tool]
            ).choices[0].message
            messages.append(reply.model_dump(exclude_none=True))
            if not reply.tool_calls:
                print(session, reply.content)
                break
            for call in reply.tool_calls:
                messages.append({"role": "tool", "tool_call_id": call.id, "content": tool_result})
        else:
            raise RuntimeError("No final reply after four calls")
provider.force_flush()
```

Run `python trace_booking.py`. The script prints each new session name and the reply its guest received.

In **Observe > Tracing > booking-docs-demo > Sessions**, open each printed session and compare the tool result with the new reply. Daniel’s new reply might describe the hold correctly.

## Run on new conversations

**Test Evaluation** grades only the selected row. Once the explanations cite the right evidence for both guests:

1. Follow [Set up evals in Observe](/docs/observe/guides/setup-evals) to create a task.
2. Choose **Sessions** as the unit to evaluate.
3. Preview a session before enabling the task.
4. Select **New incoming data**. To check every new session, use 100% sampling with no filters.

## Troubleshooting

- **Save or Test is disabled.** Keep `{{session_id}}` in the instructions; selecting **Session context** does not replace the template variable.
- **The reason ignores the tool.** In Observe, check that the tool call, its result and the guest-facing reply share a session. Check that **Session context** is on in the saved eval.
- **A verdict looks wrong.** Compare the cited tool status with the reply: mentioning a hold later does not undo an opening promise that the room is reserved.
- **Two runs give different verdicts.** Judges can disagree between runs; run the test again and read the reason.
