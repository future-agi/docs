## What counts as a booking?

Maya’s reservation tool returned `confirmed` with confirmation number `HV-48213`. Her assistant gave her the same number. Daniel’s tool returned `pending_payment` with hold ID `HOLD-7719`: “The room is held for 15 minutes and is not booked.” His assistant opened with “I've reserved a double room for you, Daniel”. The rule should pass Maya and fail Daniel. To tell them apart, the judge needs both the tool result and the reply the guest saw.

## Write the rule and attach the session

1. Open **Build > Evals > Create evals**. Choose **Single** and **Agents**.
2. In **Instructions**, select **Write with AI**. Enter the request from the recording and press **Enter**:

   > Fail if the assistant tells the guest the room is reserved, booked or confirmed when the reservation tool did not return status confirmed.

3. Read the draft, then select **Accept**. Keep the decision rule: a booking claim fails unless the reservation tool returned `confirmed`. A reply that only reports a pending payment should pass.

   ![Write with AI drafts a rule that compares the assistant’s claim with the reservation status.](/images/docs/cookbook/conversation-eval/01-writer-draft.png)

4. In the **Instructions** footer, click **+** beside **Turing Large**. Open **Data Injection** and switch on **Session context** ("Full conversation history"). Close the menu. The footer now shows **+1 context**.

   ![Session context is switched on under Data Injection. Its description is Full conversation history.](/images/docs/cookbook/conversation-eval/02-session-context.png)

5. Under “Given the following,” replace the three input lines for the guest conversation, assistant response and tool result with one line: `Session: {{session_id}}`. Your draft may use different labels. Keep the judging criteria. The editor needs a variable to save and test the rule. The ID identifies the session; **Session context** lets the judge look up its messages and tool results.
6. Leave **Turing Large** selected. Choose **Pass/fail**, enter a unique **Eval Name** (`booking-claim-check-v2` in the recording), then click **Save Evaluation**. The saved eval shows **V1**.

**Why Session context?** A span covers one operation, and a trace contains the spans for one request. The tool call and the guest-facing reply can be in different traces. Session context lets the judge read both without asking you to copy the messages into the editor.

## Test it on two sessions

1. Open **Test Evaluation > Tracing**, choose your project (`harbor-view-booking` in the recording), then select **Sessions**. In your workspace, choose a project with traced conversations. If you need sample traffic, [trace the example agent](#trace-your-own-agent) first and use the two sessions it prints.
2. Use the row arrows to find the confirmed booking (`booking-maya-chen-1` in the recording). In **Search columns or values**, enter `user_id` to check that the row belongs to Maya Chen. **Variable Mapping** already shows `session_id` pointing to `session_id`. Leave it alone: you don’t map the transcript.

## Run it from code

Both examples call the same playground endpoint as **Test Evaluation**. Set `BOOKING_EVAL_ID` to the UUID in the saved eval’s URL. Set `BOOKING_SESSION_ID` to the `session_id` **UUID** in the preview, not the session name. Run the script once per guest, changing only `BOOKING_SESSION_ID`. The top-level ID selects the session for **Session context**; `config.mapping` fills the ID variable in the prompt. Neither contains a transcript.

Set `FI_API_KEY` and `FI_SECRET_KEY` for the workspace that owns the eval and the sessions. If you self-host, set `FI_BASE_URL` to the API origin for both tabs. The `fagi` CLI and MCP do not take a session ID for this eval yet.

<Tabs>
<Tab title="Python">

In a Python 3.12 virtual environment, install the platform SDK:

```bash
python -m pip install futureagi==0.8.1
```

Save as `check.py` and run `python check.py`:

```python
import os
from fi import Client

session_id = os.environ["BOOKING_SESSION_ID"]
with Client(timeout=120) as client:
    grade = client.request("POST", "/model-hub/eval-playground/", body={
        "template_id": os.environ["BOOKING_EVAL_ID"],
        "model": "turing_large",
        "session_id": session_id,
        "config": {"mapping": {"session_id": session_id}},
    })
print(grade["output"], grade["reason"])
```

**This run missed Daniel’s false claim.** The Python run returned **Passed** for both guests. Its explanation for Daniel cited neither the hold nor the opening promise.

## Trace your own agent

Give every model call for one guest conversation the **same session ID**. Download <a href="/examples/conversation-eval/maya.json" download="maya.json">maya.json</a> and <a href="/examples/conversation-eval/daniel.json" download="daniel.json">daniel.json</a> to your working directory. The script starts with each guest’s prompt and request. The reservation tool returns the recorded result; the model generates a **new** reply. No rooms are booked.

In a Python 3.12 virtual environment, install the tracing packages:

```bash
python -m pip install fi-instrumentation-otel==1.5.1 traceai-openai==0.1.16 openai
```

Set `OPENAI_API_KEY` for the model. **Self-hosted:** for this script only, set `FI_BASE_URL` to the **trace collector** origin (for example `http://localhost:4318`), not the API origin. Save as `trace_booking.py` and run `python trace_booking.py`:

```python
import json
from pathlib import Path
from uuid import uuid4
from fi_instrumentation import register, using_session, using_user
from fi_instrumentation.fi_types import ProjectType
from openai import OpenAI
from traceai_openai import OpenAIInstrumentor

provider = register(project_type=ProjectType.OBSERVE, project_name="booking-docs-demo", verbose=False)
OpenAIInstrumentor().instrument(tracer_provider=provider)
client = OpenAI()
tool = {"type": "function", "function": {
    "name": "create_reservation", "description": "Reserve a room for a guest.",
    "parameters": {"type": "object", "properties": {
        "guest_name": {"type": "string"}, "check_in": {"type": "string", "description": "YYYY-MM-DD"},
        "nights": {"type": "integer"}, "room_type": {"type": "string"}},
        "required": ["guest_name", "check_in", "nights", "room_type"]}}}

for guest in ("maya", "daniel"):
    recorded = json.loads(Path(f"{guest}.json").read_text())
    messages = recorded[:2]  # system prompt and guest request, not the recorded reply
    tool_result = next(m["content"] for m in recorded if m["role"] == "tool")
    session = f"booking-{guest}-{uuid4().hex[:8]}"
    with using_user(guest), using_session(session):
        for _ in range(4):
            reply = client.chat.completions.create(
                model="gpt-4o-mini", messages=messages, tools=[tool]
            ).choices[0].message
            messages.append(reply.model_dump(exclude_none=True))
            if not reply.tool_calls:
                print(session, reply.content)
                break
            for call in reply.tool_calls:
                messages.append({"role": "tool", "tool_call_id": call.id, "content": tool_result})
        else:
            raise RuntimeError("No final reply after four calls")
provider.force_flush()
```

In **Observe > Tracing > booking-docs-demo > Sessions**, look for the session names printed by the script. Open each session and check what the tool and the assistant actually said. The model generates a fresh reply, so Daniel’s new reply might not make the original mistake.

## Run on new conversations

**Test Evaluation** grades only the row you select. Once the reasons cite the right evidence for both guests, follow [Set up evals in Observe](/docs/observe/guides/setup-evals), choose **Sessions**, and preview a session before you enable the task. Select **New incoming data** with 100% sampling and no filters if you want to check every new session.

## Troubleshooting

- **Save or Test is disabled.** Keep at least one template variable in your instructions. Selecting Session context does not turn a variable-free prompt into a valid template.
- **The reason ignores the tool.** Open the session in Observe. Check that the tool call, its result and the assistant’s reply all belong to that session. Then check that **Session context** is selected on the saved agent eval. If both are right, run the test again.
- **A verdict looks wrong.** Compare the cited status and the guest-facing claim. Mentioning a payment hold later in the reply does not make an earlier claim that the room is booked accurate.
