<TLDR>
Use a policy from your [knowledge base](/docs/knowledge-base) as evidence in a [dataset](/docs/dataset) evaluation, then compare the evaluator's reason with the document.
</TLDR>

## The problem

A support answer can sound reasonable without matching your return policy. Uploading `return-policy.txt` gives the workspace a source, but a file listed in the dashboard doesn't tell you whether an evaluator used it.

## What you'll build

A knowledge base called `product-docs` that a dataset [evaluation](/docs/evaluation) can consult when it scores answers about your policy.

<Mermaid chart={`flowchart LR
  accTitle: From return policy to evaluation evidence
  accDescr: Upload a policy and wait for indexing. Select that knowledge base for a dataset evaluation, then compare the resulting reason with the policy.
  F["Policy file"] --> K["Indexed knowledge base"] --> E["Dataset eval"] --> R["Score and reason"]`} />

You'll:

1. Add a policy document to `product-docs`.
2. Check that the file finished processing.
3. Attach the knowledge base to an eval and read its reason against the policy.
4. Add, rename or remove material with the Python SDK.

<Prerequisites title="Before you start">
- A [Future AGI account](https://app.futureagi.com) and a dataset containing an answer to check. Viewer and Workspace Viewer roles can't create, update or delete a knowledge base.
- A document with extractable text. The **Upload** tab accepts PDF, TXT, DOCX and RTF files up to 5 MB each.
- For the SDK examples: Python 3.11+, [workspace credentials](/docs/admin-settings/api-keys) in `FI_API_KEY` and `FI_SECRET_KEY`, and the local files named in each example.
</Prerequisites>

## Upload the policy

1. Open **Knowledge base** in the sidebar.
2. Select **Create Knowledge Base**.
3. Enter `product-docs` as the name.
4. Choose **Upload**.
5. Add the policy file.
6. Click **Create**.

   You should see `product-docs` in the list with its files processing.

## Check the file is ready

1. Open `product-docs` in the list.
2. Check the policy's processing status.

   The file list shows sizes and statuses. Use the knowledge base when processing is complete; **Add docs** lets you add another source later.

## Use the policy in an evaluation

1. Open **Dataset**.
2. Select the dataset with the answer you want to check.
3. Click **Evaluate**.
4. Choose **Add Evaluations**.
5. Select a built-in eval such as [completeness](/docs/evaluation/builtin/completeness).
6. In **Knowledge base**, select `product-docs`.

   The **Knowledge base** dropdown appears for Future AGI built-in evaluation metrics. It gives the evaluator domain-specific context, so it scores outputs against your documents rather than general knowledge.

7. Map the remaining inputs to your dataset columns.
8. Click **Add & Run**.

*The evaluation configuration connects the selected knowledge base to the dataset eval.*

The eval column fills in with scores and reasons grounded in your knowledge base documents. Read the reason for an answer about returns alongside `return-policy.txt` to check that it matches the policy.

### Other uses for the same documents

- **Create Synthetic data** opens the [synthetic data wizard](/docs/cookbook/quickstart/synthetic-data-generation) with this knowledge base selected once processing completes.
- [Agent-type evals](/docs/evaluation/concepts/eval-types) can use the knowledge base as a reference. A [simulation agent definition](/docs/environments/reference/supported-agents) can also attach a knowledge base. Neither makes it a live retrieval index for your production agent.

## Manage the files with Python

This is an alternative to creating `product-docs` in the dashboard. A knowledge base name has to be unique in your organization, so run the creation examples where the name `product-docs` is free. Each maintenance example below names the knowledge base it expects; they are not one sequence to run from top to bottom.

1. Install the SDK.

```bash
pip install futureagi
```

2. Set your workspace keys in the shell running Python.

```bash
export FI_API_KEY="your-api-key"
export FI_SECRET_KEY="your-secret-key"
```

### Create the knowledge base

Run this example with the three listed files available under `./docs/`:

```python
import os
from fi.kb import KnowledgeBase

kb_client = KnowledgeBase(
    fi_api_key=os.environ["FI_API_KEY"],
    fi_secret_key=os.environ["FI_SECRET_KEY"],
)

kb_client.create_kb(
    name="product-docs",
    file_paths=[
        "./docs/return-policy.txt",
        "./docs/shipping-info.txt",
        "./docs/product-catalog.pdf",
    ],
)

print(f"KB created: {kb_client.kb.name}")
```

You should see:

```
KB created: product-docs
```

### Recover from an unsupported file type

A Markdown file fails the call rather than being skipped:

```python
kb_client.create_kb(
    name="product-docs",
    file_paths=["./docs/changelog.md"],
)
```

You should see:

```
UnsupportedFileType: File type '.md' is not supported. Supported types: pdf, docx, txt, rtf
```

Convert the file to a supported format before retrying:

```python
kb_client.create_kb(
    name="product-docs",
    file_paths=["./docs/changelog.txt"],
)

print(f"KB created: {kb_client.kb.name}")
```

You should see:

```
KB created: product-docs
```

### Add documents or rename the knowledge base

When your content changes, add files without recreating the knowledge base:

```python
kb_client.update_kb(
    kb_name="product-docs",
    file_paths=["./docs/warranty-policy.txt"],
)

print("New document added to product-docs.")
```

You should see:

```
New document added to product-docs.
```

To rename the knowledge base in the same call as an upload, use this alternative:

```python
kb_client.update_kb(
    kb_name="product-docs",
    new_name="product-docs-v2",
    file_paths=["./docs/new-policy.txt"],
)
```

You should see the knowledge base listed as `product-docs-v2`.

### Remove a file or the whole knowledge base

To remove just `return-policy.txt` from `product-docs`:

```python
kb_client.delete_files_from_kb(
    file_names=["return-policy.txt"],
    kb_name="product-docs",
)

print("File removed from KB.")
```

You should see:

```
File removed from KB.
```

Use this separate example only when you intend to delete the **entire** `product-docs` knowledge base:

```python
kb_client.delete_kb(kb_names="product-docs")

print("KB deleted.")
```

You should see:

```
KB deleted.
```

## Troubleshooting

<div class="sdk-ref-table max-sm:[&_td]:px-1.5! max-sm:[&_th]:px-1.5!">

| Symptom | Cause | Fix |
|---|---|---|
| `create_kb()` raises an unsupported file type error | File extension isn't `pdf`, `docx`, `txt`, or `rtf` | Convert the document to a supported format before uploading |
| Knowledge base dropdown is empty | No Knowledge Base has finished processing in this organization | Create one and wait for processing to complete |
| `update_kb()` or `delete_files_from_kb()` resolves the wrong KB | No Knowledge Base name contains that string, or the lookup matched a different one | `kb_name` is a case-insensitive substring search that returns the first match; pass the full name as shown in the dashboard |
| **Create Synthetic data** button stays disabled | Uploaded documents are still processing | Wait until every file shows a processed status in the KB detail view, then retry |
| SDK calls fail with an authentication error | `FI_API_KEY` or `FI_SECRET_KEY` isn't exported in the shell running the script | Re-export both env vars in the same terminal session before running |
| `delete_files_from_kb()` raises an invalid-files error | A name in `file_names` doesn't exactly match a file in the KB (match is exact, including extension and case) | Copy the file name from the KB detail view |
| A file shows an error status after upload | The file is over the 5 MB per-file limit, or the KB has hit the 1 GB total storage limit | Split or compress the document, or delete unused files first |

</div>
