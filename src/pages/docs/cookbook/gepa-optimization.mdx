## About

Ridgeline Outfitters needs a queue name, not an explanation of where a ticket belongs. Give GEPA a starting prompt and an exact-match check. Its reflection model can use failed examples and their scores to propose a different instruction.

| Time | Difficulty | Package |
|---|---|---|
| 20 min | Intermediate | `agent-learning-kit==0.3.7` |

## Set up Python

Use a fresh Python 3.12 environment. In Bash, enter an OpenRouter API key when prompted. The model calls use that key; the exact-match metric runs locally without Future AGI credentials.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install agent-learning-kit==0.3.7
read -rsp 'OpenRouter API key: ' OPENROUTER_API_KEY; printf '\n'
export OPENROUTER_API_KEY
```

## Run a budgeted reflection search

1. Label two tickets and map the generated reply and the reference queue to `Equals`. Each row scores 1 for the exact uppercase label or 0 otherwise.
2. Set `generator_model` to the model that will route tickets and `reflection_model` to the model that will revise the prompt. They perform different jobs even when you use the same model for both.
3. Pass the seed in `initial_prompts` and the evaluation budget to **`optimize()`**, not the constructor. The adapter records an entry in `history` each time it scores a batch.

Save as `gepa.py` and run `python gepa.py`. GEPA is included in the pinned Agent Learning Kit installation.

<CodeGroup titles={["Python"]}>

```python
from fi.evals.metrics import Equals
from fi.opt.base import Evaluator
from fi.opt.datamappers import BasicDataMapper
from fi.opt.optimizers import GEPAOptimizer

MODEL = "openrouter/openai/gpt-4o-mini"
seed = "Which queue, RETURNS or REPAIRS, handles this ticket? {ticket}"
train = [
    {"ticket": "My new boots don't fit. Can I send them back?", "queue": "RETURNS"},
    {"ticket": "Can you fix a broken buckle on my pack?", "queue": "REPAIRS"},
]
mapper = BasicDataMapper({
    "response": "generated_output",
    "expected_response": "queue",
})
evaluator = Evaluator(metric=Equals(config={"case_sensitive": True}))

optimizer = GEPAOptimizer(reflection_model=MODEL, generator_model=MODEL)
result = optimizer.optimize(
    evaluator=evaluator, data_mapper=mapper, dataset=train,
    initial_prompts=[seed], max_metric_calls=14,
)
print(f"Seed score: {result.history[0].average_score:.0%}")
print(f"Selected score: {result.final_score:.0%}")
print("Selected prompt:", result.best_generator.get_prompt_template())
```

</CodeGroup>

## Read the result

The first history entry describes the seed evaluation. Compare its average to `final_score`, the selected candidate's score. GEPA can keep the seed when no revision scores higher. One run printed:

```text
Seed score: 0%
Selected score: 0%
Selected prompt: Which queue, RETURNS or REPAIRS, handles this ticket? {ticket}
```

## Limits and troubleshooting

- Scoring the seed uses part of `max_metric_calls`. A budget barely larger than your dataset can leave little room to try revisions. It is a metric-call budget, not a cap on model tokens.
- A history entry is a batch evaluation, not necessarily a distinct prompt. Do not use the highest minibatch average as the final validation score.
- The adapter supplies `dataset` as both the training and validation set. Keep a separate set of tickets for the release decision.
