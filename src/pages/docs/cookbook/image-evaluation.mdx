<TLDR>
Score how well a generated image matches its text prompt with `ImageInstructionAdherence`, then inspect visual signs of synthetic imagery with `SyntheticImageEvaluator`. Both run through the same `Evaluator.evaluate()` call.
</TLDR>

## Tutorial

Run the Python blocks in order in one session.

<Steps>
<Step title="Initialize the Evaluator client">

```python
import csv
from fi.evals import Evaluator

evaluator = Evaluator()
eval_log = []

def judge(template, inputs):
    row = evaluator.evaluate(eval_templates=template, inputs=inputs,
                             model_name="turing_flash").eval_results[0]
    if row.output is None:
        raise RuntimeError(row.reason or "No image score returned")
    score = float(row.output)
    if not 0 <= score <= 1:
        raise ValueError(f"Expected a score in [0, 1], got {score}")
    eval_log.append((row.eval_id, template.eval_name, score))
    return score, row.reason

print("Evaluator client initialized")
```

You should see `Evaluator client initialized` printed with no errors. This message confirms initialization, not successful authentication.

</Step>
<Step title="Check alignment between the image and its prompt">

`ImageInstructionAdherence` scores how well a generated image follows the prompt that produced it. Use a programmatically drawn trail marker so you know exactly what the image depicts. The same check works with an image from your generator: send its encoded PNG, not a local filename.

```python
import base64
from io import BytesIO
from PIL import Image, ImageDraw
from fi.evals.templates import ImageInstructionAdherence

image = Image.new("RGB", (192, 192), "white")
ImageDraw.Draw(image).polygon([(96, 24), (24, 158), (168, 158)], fill="blue")
buffer = BytesIO()
image.save(buffer, format="PNG")
image_data = "data:image/png;base64," + base64.b64encode(buffer.getvalue()).decode("ascii")

datapoint = {"prompt": "A solid blue triangle centered on a white background",
             "category": "marker-match"}
alignment_template = ImageInstructionAdherence()
score, reason = judge(alignment_template, {"instruction": datapoint["prompt"], "images": image_data})
print(score)
print(reason)
```

Example output (illustrative, depends on the actual image):
```
1.0
The image perfectly matches the instruction: it is a solid blue triangle centered on a white background.
```

`output` carries the adherence score for this eval (0 to 1, higher is better), `reason` explains it in plain language. `model_name` picks the [evaluator model](/docs/evaluation/concepts/evaluator-models) that scores the image; `turing_flash` is a fast default.

</Step>
<Step title="Check for signs of a synthetic image">

`SyntheticImageEvaluator` looks for signs of synthetic imagery. Here you know the marker was drawn by code. A score reflects the judge’s interpretation of the pixels, not proof of an asset’s origin.

```python
from fi.evals.templates import SyntheticImageEvaluator

provenance_template = SyntheticImageEvaluator()

score, reason = judge(provenance_template, {"image": image_data})
print(score)
print(reason)
```

Example output (illustrative, depends on the actual image):
```
0.0
The image is a basic digital graphic rather than a textured scene.
```

Higher values indicate stronger signs of synthetic imagery. In the example the judge did not find signs of AI generation, although you know the marker is computer-drawn. This score is not a calibrated probability and should not replace a provenance record.

</Step>
<Step title="Batch-evaluate a full dataset">

Loop the alignment check over every datapoint and collect the pass rate. This is where a real dataset load belongs: one small list here, or a `pd.read_csv(...)` / `json.load(...)` over your own generation log in production.

```python
datapoints = [
    datapoint,
    {"prompt": "A red square centered on white", "category": "shape-mismatch"},
    {"prompt": "A blue triangle on a black background", "category": "background-mismatch"},
]
PASS_THRESHOLD = 0.5
results = []
for dp in datapoints:
    score, reason = judge(alignment_template, {"instruction": dp["prompt"], "images": image_data})
    results.append({"category": dp["category"], "score": score,
                    "passed": score >= PASS_THRESHOLD, "reason": reason})

with open("image-scores.csv", "w", newline="") as f:
    writer = csv.writer(f)
    writer.writerow(["eval_id", "template", "score"])
    writer.writerows(eval_log)
pass_rate = sum(1 for r in results if r["passed"]) / len(results)
print(f"Pass rate: {pass_rate:.0%} across {len(results)} prompt/image pairs")
```

You should see a pass rate printed. The three rows here reuse one image against different prompts on purpose, so you can compare how different mismatches affect the score. Group `results` by `category` on your own dataset to spot which prompt categories the generator handles worst.

</Step>
<Step title="Inspect a failed case">

When `passed` is `False`, `reason` tells you why the image didn't match.

```python
failures = [r for r in results if not r["passed"]]

for f in failures:
    print(f["category"], f["score"])
    print(f["reason"])
```

Example output (illustrative, from the batch above):
```
shape-mismatch 0.0
The prompt asks for a red square but the image shows a blue triangle.
```

Inspect the actual image alongside the reason. A missing subject and an incorrect background call for different fixes; a changed score alone does not tell you which one worked.

</Step>
</Steps>

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `ModuleNotFoundError: No module named 'fi.testcases'` | Following an older version of this cookbook that imported `MLLMTestCase` | That module doesn't exist in Agent Learning Kit. Pass a plain `inputs` dict to `evaluate()`, as shown above |
| `ImportError: cannot import name 'ImageInstruction'` | Importing `ImageInstruction` instead of `ImageInstructionAdherence` | Use `ImageInstructionAdherence` from `fi.evals.templates` |
| `AttributeError: 'EvalResult' object has no attribute 'metrics'` | Reading `.metrics[0].value` on the result | The class-based templates on this page return the verdict on `.output`; `.metrics` is not populated on this call path |
| `InvalidAuthError` on the first `evaluate()` call | `FI_API_KEY` or `FI_SECRET_KEY` unset or wrong | Confirm both are exported and match the keys in [app.futureagi.com](https://app.futureagi.com) admin settings |
| Eval call times out or hangs on a large batch | Looping `evaluate()` synchronously over hundreds of images | Lower the batch size, or add a `timeout` argument to `evaluate()` and retry failed rows individually |
| `reason` mentions it could not load the image | The image input is unreadable | Pass a complete PNG data URL as shown above, not a local path |
| Every row in a category scores the same regardless of content | Categories keyed on the wrong dataset field | Print `dp["category"]` for a few rows and confirm it matches the value your generation pipeline actually wrote |
