<TLDR>
Trace four Google ADK agents drafting a Ridgeline Outfitters support reply. Compare what the critic received with what the writer sent. If Error Analysis has scored the trace, use its reasoning to choose a more specific critic instruction, then rerun the same request.
</TLDR>

<Prerequisites>
- Future AGI account with `FI_API_KEY` and `FI_SECRET_KEY` (see [Admin Settings](/docs/admin-settings))
- A workspace with Error Feed enabled to see Error Analysis, and permission to adjust sampling on your demo project
- An OpenAI API key. ADK runs the agents; its LiteLLM adapter calls the model.
- Python 3.12
</Prerequisites>

## Install

Run these commands in an empty directory. Save the Python files below alongside each other.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install 'google-adk==1.39.1' 'litellm==1.83.14' traceai-google-adk==0.1.7 fi-instrumentation-otel==1.5.1
```

```bash

export FI_SECRET_KEY="your-secret-key"
export OPENAI_API_KEY="your-openai-key"
```

For a self-hosted installation only, set `export FI_TRACES_URL=https://your-collector.example.com` to the base URL of your trace collector.

## Tutorial

<Steps>
<Step title="Instrument Google ADK">

Save this as `adk_tracing.py`. The instrumentor adapts ADK's native OpenTelemetry tracer. By default it hides inputs and outputs. Enable content capture here only for the fictional policy and ticket below; do not copy that setting into a service handling sensitive requests without reviewing your capture policy.

```python
from fi_instrumentation import register, TraceConfig
from fi_instrumentation.fi_types import ProjectType
from traceai_google_adk import GoogleADKInstrumentor

provider = register(project_name="google-adk-demo", project_type=ProjectType.OBSERVE, verbose=False)
GoogleADKInstrumentor().instrument(
    tracer_provider=provider, config=TraceConfig(hide_inputs=False, hide_outputs=False)
)
```

</Step>
<Step title="Define the specialists and their handoffs">

Save this as `adk_team.py`. `SequentialAgent` controls the order. Each `output_key` saves an agent's answer in session state; placeholders such as `{notes}` insert it into the next agent's instructions. No model has to guess which agent gets the next turn.

```python
from google.adk.agents import Agent, SequentialAgent
from google.adk.models.lite_llm import LiteLlm

POLICY = "Ridgeline accepts unused boots within 30 days of delivery. Return shipping is not specified."

def build_team(strict_critic=False):
    model = LiteLlm(model="openai/gpt-4o-mini")
    planner = Agent(name="planner_agent", model=model, output_key="plan",
                    instruction="Plan a reply to the ticket in two short steps. Do not invent policy.")
    researcher = Agent(name="researcher_agent", model=model, output_key="notes",
                       instruction="Use the plan: {plan}. Extract only relevant facts from this policy: " + POLICY)
    check = ("Start with PASS or FAIL. Flag any claim that Ridgeline pays for shipping."
             if strict_critic else "Review the notes for clarity and correctness.")
    critic = Agent(name="critic_agent", model=model, output_key="critique",
                   instruction="Notes: {notes}. Policy: " + POLICY + " " + check)
    writer = Agent(name="writer_agent", model=model, output_key="reply",
                   instruction="Write a two-sentence customer reply from these notes: {notes}. "
                               "Address this review: {critique}. Do not promise more than the policy says.")
    return SequentialAgent(name="support_team", sub_agents=[planner, researcher, critic, writer])
```

</Step>
<Step title="Run the agents">

Save this as `google_adk_futureagi.py`. The session is in memory, so no separate database is needed. Consuming the event stream runs all four agents. The last printed line is the trace ID; use it to find the run in Observe.

```python
import argparse
import asyncio
from uuid import UUID
from google.adk.runners import InMemoryRunner
from google.genai import types
from adk_tracing import provider
from adk_team import build_team

async def run(strict):
    app = "ridgeline_support"
    runner = InMemoryRunner(app_name=app, agent=build_team(strict))
    try:
        session = await runner.session_service.create_session(app_name=app, user_id="demo-shopper")
        ticket = "My unused boots arrived 20 days ago. Can I return them? Will you pay for shipping?"
        with provider.get_tracer(__name__).start_as_current_span("review return policy") as span:
            trace_id = UUID(int=span.get_span_context().trace_id)
            async for event in runner.run_async(
                user_id=session.user_id, session_id=session.id,
                new_message=types.Content(role="user", parts=[types.Part(text=ticket)]),
            ):
                if event.is_final_response() and event.content:
                    text = "".join(p.text or "" for p in event.content.parts or [])
                    if text:
                        print(f"[{event.author}] {text}")
    finally:
        await runner.close()
        provider.force_flush()
    print(trace_id)

if __name__ == "__main__":
    parser = argparse.ArgumentParser()
    parser.add_argument("--strict-critic", action="store_true")
    asyncio.run(run(parser.parse_args().strict_critic))
```

Run `python google_adk_futureagi.py`. You should see the planner, researcher, critic, and writer responses in that order.

</Step>
<Step title="Inspect a sampled trace">

Open **Observe** → `google-adk-demo` and select the printed trace ID. Expand the trace tree and follow the four agents. Did the researcher preserve the 30-day limit? Did the writer promise free shipping? The supplied policy does not say who pays.

<img src="/images/docs/agent-compass-quickstart/observe_llm_tracing.png" alt="Example of the project's trace list in Observe" style={{ borderRadius: '5px' }} />

Trace collection and Error Analysis are separate. If the demo project is new, open its settings, set the Error Feed sampling rate above zero, and save. Use 100% only if you intend all demo traces to be eligible for analysis. Run `python google_adk_futureagi.py` again after enabling sampling. See [Turn on Error Feed](/docs/error-feed/guides/turn-on-error-feed).

</Step>
<Step title="Read the scores and change one instruction">

Once a sampled trace has been analyzed, open its **Scores** accordion. The four dimensions answer different questions:

- **Factual Grounding:** Are claims about returns and shipping supported by the supplied policy?
- **Privacy And Safety:** Does the reply handle the customer's information appropriately?
- **Instruction Adherence:** Does the writer follow the requested format and respect the policy boundary?
- **Optimal Plan Execution:** Did the sequence of agents help resolve the ticket?

<img src="/images/docs/agent-compass-quickstart/agent_compass_expanded.png" alt="Example of the four Error Analysis scores on a trace" style={{ borderRadius: '5px' }} />

For example, if the review overlooked an unsupported shipping promise, run `python google_adk_futureagi.py --strict-critic`. It sends the same ticket through a new session and changes only the critic's instruction. Compare the critique and final answer, then compare scores if both traces have analysis. A new instruction does not guarantee a better score. A missing score is not a zero.

</Step>
</Steps>

## Troubleshooting

| Symptom | What to check |
|---|---|
| No trace in Observe | Confirm both Future AGI credentials and the collector endpoint. Instrument ADK before the run and flush the provider at the end. |
| Agents never respond | Check the OpenAI key and chat-model access. This example does not use the Gemini API. |
| The trace appears but has no scores | Confirm the workspace capability and project sampling settings. Exporting a trace does not mean analysis has finished. |

For more on how to interpret scores, see [Trace error analysis](/docs/error-feed/concepts/trace-error-analysis).
