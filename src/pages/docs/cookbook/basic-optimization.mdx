<TLDR>
Score a short summary instruction on two articles, then use [Random Search](/docs/optimization/reference/optimizers/random-search) to compare five rewrites against that baseline.
</TLDR>

## The problem

“Summarize this” doesn't tell the model which details to keep or how long the summary should be. A rewrite may sound clearer, but its score alone won't tell you whether it beats the original instruction. You need to score both on the same articles.

## What you'll build

A Python comparison that prints the original prompt's average score, the best of five variations and the prompt text behind each score.

<Mermaid chart={`flowchart LR
  accTitle: Compare six instructions on the same articles
  accDescr: Run the original instruction and five variations on the same two articles. Score each summary against its source and compare the best variation with the original.
  A["Two articles"] --> B["Original prompt"] --> E["Summary quality scores"]
  A --> V["Five variations"] --> E
  E --> R["Best variation versus baseline"]`} />

You'll:

1. Generate a baseline summary for each article.
2. Score each summary against its source with the [Summary Quality eval](/docs/evaluation/builtin/summary-quality).
3. Compare the best variation's score with the baseline and inspect the other four.

<Prerequisites title="Before you start">
- Python 3.11. This beginner example takes about 15 minutes and uses `agent-opt`.
- A [Future AGI account](https://app.futureagi.com) and a matching [workspace API key and secret key](/docs/admin-settings/api-keys).
- An OpenAI API key for the generator and teacher, which call OpenAI through LiteLLM.
</Prerequisites>

## Define the comparison

Place the Python blocks in order in the same file. None of the first four blocks calls a model.

<Steps>
<Step title="Define the dataset">

Each dictionary holds one article. You don't need a target summary: the judge compares the generated summary with the article itself.

```python
dataset = [
    {
        "article": "The James Webb Space Telescope has captured stunning new images of the Pillars of Creation, revealing intricate details of gas and dust clouds where new stars are forming.",
    },
    {
        "article": "Researchers have discovered a new enzyme that can break down plastics at record speed, offering a potential solution to the global plastic pollution crisis.",
    },
]
```

</Step>
<Step title="Set the starting instruction">

`LiteLLMGenerator` wraps a model and a prompt template. Bind `Summarize this: {article}` to `gpt-4o-mini`. This is the prompt you're about to improve.

```python
from fi.opt.generators import LiteLLMGenerator

initial_prompt = "Summarize this: {article}"
initial_generator = LiteLLMGenerator(
    model="gpt-4o-mini",
    prompt_template=initial_prompt,
)
```

</Step>
<Step title="Choose the evaluator">

The `Evaluator` scores each candidate prompt's output using a Future AGI eval template. Use the same template and [judge model](/docs/evaluation/concepts/evaluator-models) for the baseline and all five variations.

```python
from fi.opt.base.evaluator import Evaluator

evaluator = Evaluator(
    eval_template="summary_quality",  # built-in template for summarization
    eval_model_name="turing_flash",   # judge model
)
```

</Step>
<Step title="Map the article and summary">

`BasicDataMapper` tells the optimizer which dataset column is the input and which generated field is the output to score.

```python
from fi.opt.datamappers import BasicDataMapper

data_mapper = BasicDataMapper(
    key_map={"input": "article", "output": "generated_output"}
)
```

`article` names a dataset field. The literal `generated_output` is different: it tells `BasicDataMapper` to substitute the generated summary rather than look up a column with that name.

</Step>
</Steps>

## Score the original before trying variations

Add the baseline calculation. It generates a summary for each row, maps it with its article, and averages the two eval scores.

```python
baseline_outputs = [initial_generator.generate(example) for example in dataset]
baseline_inputs = [
    data_mapper.map(output, example)
    for output, example in zip(baseline_outputs, dataset)
]
baseline_results = evaluator.evaluate(baseline_inputs)
baseline_score = sum(r.score for r in baseline_results) / len(baseline_results)
print(f"Baseline score: {baseline_score:.4f}")
```

When you run the file, you should see `Baseline score` between 0 and 1. Keep that number: the optimizer reports its best variation, not a comparison with the unmodified prompt.

## Try five rewrites

<Steps>
<Step title="Configure the search">

`RandomSearchOptimizer` uses the `gpt-4o` teacher model to write five prompt variations, then scores each one with the `Evaluator`. Nothing runs until you call `optimize()`.

```python
from fi.opt.optimizers import RandomSearchOptimizer

optimizer = RandomSearchOptimizer(
    generator=initial_generator,
    teacher_model="gpt-4o",  # writes the prompt variations
    num_variations=5,        # how many variations to generate
)
```

</Step>
<Step title="Pass the same dataset to the optimizer">

Hand the evaluator, data mapper, and dataset to the optimizer. This is the step that calls the teacher and generator models.

```python
result = optimizer.optimize(
    evaluator=evaluator,
    data_mapper=data_mapper,
    dataset=dataset,
)
```

The search asks the teacher model for 5 prompt variations, runs each against the same rows, and scores every output. Larger datasets and a higher `num_variations` take longer to run.

</Step>
<Step title="Print the comparison">

Pull the winning prompt and its score out of `result`, and print every variation alongside the baseline you scored earlier.

```python
print(f"Baseline Score: {baseline_score:.4f}")
print(f"Final Score: {result.final_score:.4f}")
print(f"Best Prompt Found:\n{result.best_generator.get_prompt_template()}")

for i, iteration in enumerate(result.history):
    print(f"\n--- Variation {i+1} ---")
    print(f"Score: {iteration.average_score:.4f}")
    print(f"Prompt: {iteration.prompt}")
```

</Step>
</Steps>

Run the assembled file with Python 3.11. You should see `Baseline Score`, `Final Score`, `Best Prompt Found`, and one entry per variation in `result.history` with its prompt and score.

`result.final_score` is the score of the best variation found, so compare it with `baseline_score` to see whether optimization helped. If the final score is no higher than the baseline, none of these five variations demonstrated an improvement on this dataset. The exact numbers depend on your dataset and the models you called, so don't expect to match anyone else's run.

Two rows are enough to try the workflow; use 5 to 10 before relying on the ranking.

## Troubleshooting

<div class="sdk-ref-table max-sm:[&_td]:px-1.5! max-sm:[&_th]:px-1.5!">

| Symptom | Cause | Fix |
|---|---|---|
| `ModuleNotFoundError: No module named 'fi.opt'` | `agent-opt` isn't installed in the active environment | Run `pip install agent-opt` inside the same virtualenv you're running the script in |
| `AuthenticationError` when the Evaluator scores an output | `FI_API_KEY` or `FI_SECRET_KEY` is missing or wrong | Re-export both keys from the keys page in the shell where you run the file |
| `optimize()` raises a LiteLLM provider error | `OPENAI_API_KEY` isn't set, but the generator and teacher model both call OpenAI through LiteLLM | Export `OPENAI_API_KEY` alongside the FI keys |
| Evaluator scores every output as if it were empty | `key_map["output"]` isn't set to the literal string `"generated_output"`, so the mapper looks for a dataset column instead of substituting the generated text | Keep `key_map={"input": "article", "output": "generated_output"}`; that exact string is what tells `BasicDataMapper` to substitute the generated output |
| `optimize()` runs for several minutes with no output | `num_variations` is high and each variation calls the teacher and generator models one at a time | Lower `num_variations` (e.g. 3) or use a faster model in `LiteLLMGenerator` |
| Every entry in `result.history` scores near identically | The dataset is too small for the eval to distinguish variations | Try 5 to 10 rows before relying on the ranking |

</div>
