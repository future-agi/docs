<TLDR>
Create a Knowledge Base from a set of policy files, add a file to it, remove one, then delete it, all through the `KnowledgeBase` client.
</TLDR>

For a reference-style walkthrough of each method with no error handling, see [Manage with the SDK](/docs/knowledge-base/guides/manage-with-the-sdk). Here you'll use three short Ridgeline Outfitters policies and remove only the files and knowledge base you created.

| Time | Difficulty | Package |
|------|-----------|---------|
| 10 min | Beginner | `futureagi` |

<Prerequisites>
- Future AGI account → [app.futureagi.com](https://app.futureagi.com)
- API keys: `FI_API_KEY` and `FI_SECRET_KEY` (see [Get your API keys](/docs/admin-settings/api-keys))
- Python 3.11
- An empty working directory for the sample files
</Prerequisites>

## Tutorial

Run the Python blocks in one session, except for the optional cleanup script at the end.

<Steps>
<Step title="Initialize the client">

```python
from pathlib import Path
from uuid import uuid4

from fi.kb import KnowledgeBase

kb_client = KnowledgeBase()
kb_name = f"ridgeline-policies-{uuid4().hex[:12]}"
```

`KnowledgeBase()` reads `FI_API_KEY` and `FI_SECRET_KEY` from the environment, so no arguments are required. Pass `kb_name` here instead if you want the client to attach to a knowledge base that already exists.

</Step>
<Step title="Create a knowledge base with files">

```python
docs = Path("docs")
docs.mkdir(exist_ok=True)
policies = {
    "refund-policy.txt": "Ridgeline refunds unworn boots within 30 days of purchase.",
    "shipping-policy.txt": "Standard shipping takes three to five business days.",
    "warranty-policy.txt": "Ridgeline repairs torn tent seams within the first year.",
}
for filename, policy in policies.items():
    (docs / filename).write_text(policy, encoding="utf-8")

kb_client.create_kb(
    name=kb_name,
    file_paths=[str(docs / "refund-policy.txt"), str(docs / "shipping-policy.txt")],
)
kb_id = str(kb_client.kb.id)
Path("ridgeline-kb-id.txt").write_text(kb_id, encoding="utf-8")
print(kb_name, kb_id)
```

Open **Knowledge Base** in your workspace and look for the printed name. The ID identifies this particular knowledge base even if you run the example again. The upload response doesn't mean indexing has finished.

</Step>
<Step title="Add a file to the knowledge base">

Wait for the first upload to finish indexing before you add another file. The file-list API returns a status for each file, whereas `kb_client.kb.files` only holds IDs.

```python
import os
import time

import requests


def wait_for_files(kb_id, expected_names, timeout=300):
    base = os.environ.get("FI_BASE_URL", "https://api.futureagi.com").rstrip("/")
    deadline = time.monotonic() + timeout
    while time.monotonic() < deadline:
        response = requests.post(
            f"{base}/model-hub/knowledge-base/files/",
            headers={"X-Api-Key": os.environ["FI_API_KEY"],
                     "X-Secret-Key": os.environ["FI_SECRET_KEY"]},
            json={"kb_id": kb_id},
            timeout=15,
        )
        response.raise_for_status()
        rows = response.json()["result"]["table_data"]
        states = {row["name"]: row["status"] for row in rows}
        if any(states.get(name) == "Failed" for name in expected_names):
            raise RuntimeError(f"File indexing failed: {states}")
        if all(states.get(name) == "Completed" for name in expected_names):
            return
        time.sleep(2)
    raise TimeoutError("Indexing is still in progress. Check Knowledge Base before uploading again.")


wait_for_files(kb_id, ["refund-policy.txt", "shipping-policy.txt"])
```

Pass the same `kb_name` when you add the warranty policy. `update_kb` requires the name even when the client already has the knowledge base cached.

```python
kb_client.update_kb(kb_name=kb_name, file_paths=[str(docs / "warranty-policy.txt")])
wait_for_files(kb_id, ["warranty-policy.txt"])
```

</Step>
<Step title="List the files in a knowledge base">

```python
for file_id in kb_client.kb.files:
    print(file_id)
```

The update response includes the IDs of all three files. These are cached IDs, not a live listing or an indication that indexing has finished.

</Step>
<Step title="Delete specific files">

```python
kb_client.delete_files_from_kb(
    file_names=["shipping-policy.txt"],
)
```

`delete_files_from_kb` doesn't raise if the deletion succeeds. `file_names` takes the file's base name as stored in the knowledge base, not its local path: `docs/shipping-policy.txt` from step 2 is removed here by `shipping-policy.txt`.

</Step>
<Step title="Delete the knowledge base">

When you no longer need these policies, save this as `delete_kb.py` in the same directory. Run `python delete_kb.py` with the same environment and credentials. It deletes the knowledge base identified by the ID you saved at creation, not a matching name.

```python
from pathlib import Path
from uuid import UUID

from fi.kb import KnowledgeBase

kb_id = UUID(Path("ridgeline-kb-id.txt").read_text(encoding="utf-8").strip())
KnowledgeBase().delete_kb(kb_ids=str(kb_id))
print(f"Deleted knowledge base {kb_id}")
```

Refresh **Knowledge Base**: the entry should no longer appear. Your local policy files are unchanged.

</Step>
</Steps>

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `TypeError: update_kb() missing 1 required positional argument: 'kb_name'` | `update_kb` called with only `file_paths` | Pass `kb_name="support-policies"` (or the knowledge base's actual name) alongside `file_paths` |
| `SDKException: Knowledge Base with name '...' not found` on `KnowledgeBase(kb_name=...)` | `kb_name` was passed for a knowledge base that doesn't exist yet | Drop `kb_name` and call `create_kb()` first, or check the name for typos |
| `UnsupportedFileType` on `create_kb` or `update_kb` | A file extension isn't PDF, DOCX, TXT, or RTF | Convert the file or remove it from `file_paths` |
| `FileNotFoundException` on `create_kb`, or `SDKException: Knowledge Base update failed due to a file processing issue.` on `update_kb` | A path in `file_paths` doesn't exist relative to the current working directory | Check the path, or pass an absolute path |
| `InvalidAuthError` (403) on any call | `FI_API_KEY` or `FI_SECRET_KEY` missing or invalid | Re-run the `export` block in the current shell, then verify the keys in [Settings > API Keys](/docs/admin-settings/api-keys) |
| `SDKException: File with same name already exists.` | Two files in the same `create_kb` or `update_kb` call share a base name | Rename or drop the duplicate, then retry |
| `SDKException: Maximum knowledge base size exceeded.` | The upload exceeds the size limit | Drop files until the knowledge base fits the cap, then retry |
