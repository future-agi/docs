<TLDR>
Summarize a short Ridgeline Outfitters meeting with three OpenAI models. Use `summary_quality` to judge each summary against the transcript, then use BERTScore to compare it with a human reference. The two checks answer different questions.
</TLDR>

## Install

Use Python 3.12, an OpenAI API key, and [Future AGI API keys](/docs/admin-settings/api-keys). The example sends the transcript to your model provider and Future AGI. Use only material you have permission to send. The CPU-only PyTorch installation below is for Linux; on other platforms use the [PyTorch installer](https://pytorch.org/get-started/locally/) for your system.

```bash

python -m pip install agent-learning-kit==0.3.7 bert-score==0.3.13 'transformers>=4.48,<5' openai
```

## Generate comparable summaries

Save this as `make_summaries.py` and run `python make_summaries.py`. Each model sees the same transcript and instruction, but never the reference summary. Keep that reference independent: its job is to tell you what a human considered important.

```python
import csv
from openai import OpenAI

client = OpenAI()
transcript = (
    "Store lead: The pack buckle repair queue has reached twelve requests. "
    "Repair lead: I will clear the backlog by Friday. "
    "Store lead: Agreed. Keep the repair fee unchanged. "
    "Shipping lead: I can move two Saturday shifts to repairs. "
    "Store lead: Let's decide on that next week, not today."
)
reference = "The repair lead will clear twelve buckle repairs by Friday. Fees stay the same; no shift change was approved."
models = ["gpt-4o", "gpt-4o-mini", "gpt-4.1-mini"]
with open("meeting-summary.csv", "w", newline="", encoding="utf-8") as f:
    writer = csv.DictWriter(f, fieldnames=["model", "source", "reference", "summary"])
    writer.writeheader()
    for model in models:
        response = client.chat.completions.create(model=model, temperature=0, messages=[
            {"role": "system", "content": "In at most two sentences, summarize decisions, owners, deadlines, and what was not decided."},
            {"role": "user", "content": transcript},
        ])
        summary = response.choices[0].message.content
        if not summary or not summary.strip():
            raise RuntimeError(f"No summary from {model}")
        writer.writerow(dict(model=model, source=transcript, reference=reference, summary=summary))
        print(model, summary)
```

To use your own exported summaries, supply a CSV with those same four columns and one row per candidate. Keep the transcript and reference identical across candidates for a meeting. For a larger benchmark such as [MeetingBank](https://huggingface.co/datasets/lytang/MeetingBank-transcript), start with a small, representative sample before spending credits on the full set.

## Score summaries against the source

Save this as `judge_summaries.py` and run `python judge_summaries.py`. The hosted Summary Quality eval compares the transcript (`input`) with the candidate (`output`); it doesn't use the human-written reference. The script saves the judge's verdict and explanation so you can inspect the cases behind the comparison.

```python
import csv
from fi.evals import Evaluator

evaluator = Evaluator()
with open("meeting-summary.csv", newline="", encoding="utf-8") as f:
    rows = list(csv.DictReader(f))
with open("summary-quality.csv", "w", newline="", encoding="utf-8") as f:
    writer = csv.DictWriter(f, fieldnames=["model", "quality", "reason", "eval_id"])
    writer.writeheader()
    for row in rows:
        result = evaluator.evaluate(
            eval_templates="summary_quality",
            inputs={"input": row["source"], "output": row["summary"]},
            model_name="turing_flash",
        ).eval_results[0]
        if result is None or result.output is None:
            raise RuntimeError(f"No Summary Quality verdict for {row['model']}: {result}")
        writer.writerow(dict(model=row["model"], quality=result.output,
                             reason=result.reason, eval_id=result.eval_id))
        print(f"{row['model']}: {result.output}")
```

## Cross-check with BERTScore

Save this as `compare_summaries.py` and run `python compare_summaries.py`. BERTScore matches contextual token embeddings between each candidate and its reference. **Precision** measures how well the candidate's tokens match the reference, **recall** reverses the comparison, and **F1** combines the two. The first call needs network access to download the public model weights; later calls can reuse the cache.

```python
import csv
from bert_score import score

with open("meeting-summary.csv", newline="", encoding="utf-8") as f:
    candidates = list(csv.DictReader(f))
with open("summary-quality.csv", newline="", encoding="utf-8") as f:
    verdicts = list(csv.DictReader(f))
if [r["model"] for r in candidates] != [r["model"] for r in verdicts]:
    raise ValueError("Run judge_summaries.py on this CSV first")

precision, recall, f1 = score(
    [r["summary"] for r in candidates], [r["reference"] for r in candidates],
    model_type="bert-base-uncased", lang="en", device="cpu", verbose=False,
)
print("Model | Summary Quality | Precision | Recall | F1")
for row, p, r, f in zip(verdicts, precision.tolist(), recall.tolist(), f1.tolist(), strict=True):
    print(f"{row['model']} | {row['quality']} | {p:.3f} | {r:.3f} | {f:.3f}")
```

## Interpret a disagreement

Check whether the summary says the two Saturday shifts **will** move. The team discussed moving them but deferred the decision. A summary can use almost all the same words as the reference and still reverse that decision, so a high BERTScore is not proof of factual accuracy. Read the transcript and judge's reason before picking a winner. One meeting illustrates the check; it does not establish a model ranking.

## Troubleshooting

- **No hosted verdict:** Check both Future AGI credentials and the configured API endpoint. Don't convert a missing result to zero.
- **Missing CSV columns:** The generation script writes `model`, `source`, `reference`, and `summary`. Check these names before scoring your own export.
- **BERTScore can't load the model:** Confirm you can access the public weights and have a writable Hugging Face cache. On a machine without internet access, populate that cache first.

Next, try [prompt optimization](/docs/cookbook/basic-optimization) on a separate set of transcripts.
