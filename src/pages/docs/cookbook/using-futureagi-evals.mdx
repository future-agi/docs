<TLDR>
**What you'll build:** A set of built-in eval checks for support replies, run with the `Evaluator` class from `fi.evals`: a judged context-adherence check, a deterministic JSON check, a PII screen, and a batch conciseness pass. Each call returns an `output` (a score or a pass/fail verdict, depending on the template) and a reason.
</TLDR>

## The problem

A support reply can promise a refund sooner than the policy allows. An order confirmation can say the right thing but contain malformed JSON. A single judge score won't tell you both whether the promise is supported and whether a parser can read the confirmation.

## What you'll build

Checks from [built-in eval templates](/docs/evaluation/concepts/eval-templates) that judge the refund promise and parse the JSON separately, plus a PII screen and a conciseness pass.

<Mermaid chart={`flowchart TD
  accTitle: Two checks for different support failures
  accDescr: A judge compares the support reply with the refund policy and returns an adherence score and reason. A separate deterministic check parses the order confirmation and returns a JSON verdict.
  A["Refund policy and reply"] --> J["Context adherence judge"] --> R["Score and reason"]
  O["Order confirmation"] --> C["JSON parser check"] --> V["Pass or fail"]`} />

You'll:

1. Compare a refund reply with the policy the agent was given.
2. Verify that an order confirmation parses as JSON without a judge model.
3. Screen an inbound message for personal information.
4. Compare concise and wordy replies before rerunning a shorter version.

<Prerequisites title="Before you start">
- Python 3.11 or later.
- A Future AGI account. Sign up at [app.futureagi.com](https://app.futureagi.com).
- A workspace [API key and secret key](/docs/admin-settings/api-keys), set as `FI_API_KEY` and `FI_SECRET_KEY`.
</Prerequisites>

## Set up the evaluator

<div class="sdk-ref-table">

| Variable | What to set | Where to find it |
| --- | --- | --- |
| `FI_API_KEY` | Workspace API key | **Build > Keys** |
| `FI_SECRET_KEY` | Matching secret key | Shown when you create the key pair |

</div>

1. Install the evaluation package:

```bash
pip install ai-evaluation
```

2. Export the credentials in the shell where you'll run Python:

```bash
export FI_API_KEY="your-api-key"
export FI_SECRET_KEY="your-secret-key"
```

3. Initialize the evaluator:

```python
import os
from fi.evals import Evaluator

evaluator = Evaluator(
    fi_api_key=os.environ["FI_API_KEY"],
    fi_secret_key=os.environ["FI_SECRET_KEY"],
)
```

No output to check here. The `Evaluator` instance is what every later step calls `.evaluate()` on, so keep the same Python session for the examples below.

The [decision models guide](/docs/evaluation/guides/decision-models#run-a-saved-eval-from-code) shows the same `evaluate()` call with the Agent Learning Kit `Evaluator`.

## Check the support examples

<Steps>
<Step title="Score a support reply for context adherence">

The [context adherence](/docs/evaluation/builtin/context-adherence) template compares the customer-facing refund promise with the policy. `context_adherence` is a judged template: it needs a `model_name` to act as the grading model (see [evaluator models](/docs/evaluation/concepts/evaluator-models)).

```python
support_context = (
    "Refunds are issued within 5-7 business days to the original payment method. "
    "Store credit is available immediately as an alternative."
)
support_reply = "You'll get your refund back on the original card within 5 to 7 business days."

result = evaluator.evaluate(
    eval_templates="context_adherence",
    inputs={"context": support_context, "output": support_reply},
    model_name="turing_flash",
)

item = result.eval_results[0]
print(item.output)
print(item.reason)
```

Illustrative score and explanation, not a recorded run:
```
0.92
The response accurately reflects the refund timeline stated in the context.
```

`item.output` is the 0-1 adherence score, `item.reason` is the grading model's explanation.

</Step>
<Step title="Run a deterministic check with no judge model">

[Is JSON](/docs/evaluation/builtin/is-json) checks the order confirmation itself, not the refund policy. Deterministic templates don't grade with a model. Pass `eval_templates` and `inputs` only, no `model_name`.

```python
order_confirmation = '{"order_id": "SO-48213", "status": "shipped", "refund_issued": false}'

result = evaluator.evaluate(
    eval_templates="is_json",
    inputs={"text": order_confirmation},
)

print(result.eval_results[0].output)
```

Expected verdict for a valid JSON string:
```
Passed
```

</Step>
<Step title="Screen a customer message for PII">

[PII](/docs/evaluation/builtin/pii) is a judged safety template. Run it on inbound text before it reaches a log or a downstream store.

```python
customer_message = "My order number is SO-48213 and my name is Jordan Reyes."

result = evaluator.evaluate(
    eval_templates="pii",
    inputs={"input": customer_message},
    model_name="turing_flash",
)

item = result.eval_results[0]
print(item.output)
print(item.reason)
```

Illustrative verdict and reason for the sample message:
```
Failed
The message contains a personal name (Jordan Reyes) and an order identifier.
```

</Step>
<Step title="Batch-score replies for conciseness">

Run [Is concise](/docs/evaluation/builtin/is-concise) on each candidate reply and compare verdicts.

```python
support_replies = [
    "Your refund will be back on your card within 5 to 7 business days after we process the return.",
    "Sure, no problem at all, happy to help, let me just check on that for you real quick, one moment please.",
]

for reply in support_replies:
    result = evaluator.evaluate(
        eval_templates="is_concise",
        inputs={"output": reply},
        model_name="turing_flash",
    )
    item = result.eval_results[0]
    print(f"{item.output!s:<8} {reply[:50]}")
```

Illustrative verdicts for the direct reply and the one with filler:
```
Passed   Your refund will be back on your card within 5 
Failed   Sure, no problem at all, happy to help, let me
```

</Step>
<Step title="Recheck a shorter reply">

Remove the filler from the second reply and run the same template again:

```python
tightened_reply = "Your refund will be back on your card within 5 to 7 business days."

result = evaluator.evaluate(
    eval_templates="is_concise",
    inputs={"output": tightened_reply},
    model_name="turing_flash",
)
item = result.eval_results[0]
print(f"before: Failed")
print(f"after:  {item.output!s}")
```

Illustrative comparison. The `before` line in this snippet is a fixed label; only the `after` line reads the new result:
```
before: Failed
after:  Passed
```

</Step>
<Step title="Catch evaluation errors before they reach production">

Wrap `evaluate()` so a bad template name or a transient API error doesn't crash a batch job.

```python
def score_reply(template, output, **extra_inputs):
    try:
        result = evaluator.evaluate(
            eval_templates=template,
            inputs={"output": output, **extra_inputs},
            model_name="turing_flash",
        )
        item = result.eval_results[0]
        return item.output, item.reason
    except Exception as exc:
        print(f"Eval '{template}' failed: {exc}")
        return None, None

status, reason = score_reply("toxicity", "I completely disagree, but I respect your view.")
print(status, reason)
```

Illustrative [toxicity](/docs/evaluation/builtin/toxicity) result when the call succeeds:
```
Passed The response is respectful and contains no toxic language.
```

The `try`/`except` here is what turns a bad template name into a logged failure instead of a stopped script.

</Step>
</Steps>

## Troubleshooting

<div class="sdk-ref-table">

| Symptom | Cause | Fix |
|---|---|---|
| `AuthenticationError` on `evaluator.evaluate()` | `FI_API_KEY` or `FI_SECRET_KEY` missing or unexported | Re-run the `export` block in the current shell, then re-run the script |
| `ModuleNotFoundError: No module named 'fi.evals'` | The evaluation package is not installed, or an unrelated `fi` package shadows it | `pip install ai-evaluation`, and check `pip show fi` doesn't point at a different package |
| `evaluate()` raises an unknown-template error | Typo in the `eval_templates` string | Check the exact name against the [built-in eval catalog](/docs/evaluation/builtin) |
| `IndexError` on `result.eval_results[0]` | The call ran but returned no results, usually a rate limit or timeout | Check `result.eval_results` is non-empty before indexing, retry the call, and lower `max_workers` on the `Evaluator()` constructor if you're hitting rate limits |
| A judged template like `context_adherence`, `pii`, or `is_concise` errors out or scores every row the same | `model_name` was left out, but judged templates require one | Pass `model_name="turing_flash"` for any non-deterministic, non-statistical template |
| A deterministic template like `is_json` raises a model-related error | `model_name` was passed but isn't needed for deterministic or statistical templates | Drop the `model_name` kwarg for those categories |

</div>
