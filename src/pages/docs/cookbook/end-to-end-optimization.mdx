<TLDR>
Build a Python optimization run that grades summaries against their source articles and prints the score difference between the best rewrite and the original prompt.
</TLDR>

## The problem

The instruction `Summarize this: {article}` specifies neither a length nor which facts to keep. You can't judge a replacement from its wording alone. Even a high summary score tells you little if the original instruction scored just as well, or if the judge never received the article.

## What you'll build

A run that pairs each summary with its source, scores the baseline and five rewrites, and prints the best candidate's signed score change.

<Mermaid chart={`flowchart LR
  accTitle: Measure a change in summary quality
  accDescr: A prompt produces a summary for each article. The mapper pairs article and summary for the judge. The same process scores the original and five candidates so their scores can be subtracted.
  A["Article"] --> G["Generate summary"] --> M["Map article and summary"]
  A --> M
  M --> E["Score with the same judge"] --> D["Best candidate minus baseline"]`} />

You'll:

1. Map the source article and generated summary to the judge's expected inputs.
2. Average the original prompt's scores before changing the wording.
3. Rank the variations and use the delta to decide whether to keep a rewrite.

<Prerequisites title="Before you start">
- Python 3.11. This intermediate example takes about 20 minutes and uses `agent-opt`.
- A [Future AGI account](https://app.futureagi.com) and a matching [workspace API key and secret key](/docs/admin-settings/api-keys).
- An OpenAI key for the `gpt-4o-mini` generator and `gpt-4o` teacher, both called through LiteLLM.
</Prerequisites>

## Establish the baseline

Place the Python blocks in order in the same file.

<Steps>
<Step title="Define the comparison inputs">

The dataset is the set of inputs the optimizer scores every prompt variant against. Keep these two articles and the starting instruction fixed while measuring the baseline.

```python
dataset = [
    {
        "article": "The James Webb Space Telescope captured detailed images of the Pillars of Creation.",
    },
    {
        "article": "Researchers discovered an enzyme that rapidly breaks down plastic.",
    },
]

# Deliberately vague: no length constraint, no instruction on what to keep
baseline_prompt = "Summarize this: {article}"
```

</Step>
<Step title="Connect the generator to the judge">

The generator binds the baseline prompt to a model configuration, and the optimizer calls it to produce output for every candidate prompt it tries. The evaluator scores each candidate's output: it is the objective the optimizer works against. The [Summary Quality eval](/docs/evaluation/builtin/summary-quality) reads the article and the generated summary, not the prompt instructions. The data mapper connects dataset fields to what the evaluator expects.

```python
from fi.opt.generators import LiteLLMGenerator
from fi.opt.base.evaluator import Evaluator
from fi.opt.datamappers import BasicDataMapper

generator = LiteLLMGenerator(
    model="gpt-4o-mini",
    prompt_template=baseline_prompt,
)

evaluator = Evaluator(
    eval_template="summary_quality",
    eval_model_name="turing_flash",
)

data_mapper = BasicDataMapper(
    key_map={
        "input": "article",
        "output": "generated_output",
    }
)
```

`BasicDataMapper` reads `article` from the row. `generated_output` is a sentinel value it recognises and replaces with each variant's output, so keep it exactly as shown. For a different task, swap `summary_quality` for a matching [built-in eval](/docs/evaluation/builtin).

</Step>
<Step title="Score the original instruction">

Score the baseline now, before touching the optimizer, so you have a real number to compare against later.

```python
baseline_outputs = [generator.generate(row) for row in dataset]
mapped = [
    data_mapper.map(output, row)
    for output, row in zip(baseline_outputs, dataset)
]
results = evaluator.evaluate(mapped)
baseline_score = sum(r.score for r in results) / len(results)

print(f"Baseline score: {baseline_score:.3f}")
```

When the file runs, you should see `Baseline score` between 0 and 1. This is the mean on these two articles, not a prediction of how much a rewrite will help.

</Step>
</Steps>

## Compare five candidates

<Steps>
<Step title="Configure the search">

Configure [Random Search](/docs/optimization/reference/optimizers/random-search) with a teacher model and five variations. It generates prompt variations with the teacher and scores each with the evaluator.

```python
from fi.opt.optimizers import RandomSearchOptimizer

optimizer = RandomSearchOptimizer(
    generator=generator,
    teacher_model="gpt-4o",
    num_variations=5,
)
```

Creating the optimizer doesn't run the search.

</Step>
<Step title="Add the search and the report">

Add the search and reporting block to the file. `optimize()` handles evaluation, the search loop and ranking.

```python
result = optimizer.optimize(
    evaluator=evaluator,
    data_mapper=data_mapper,
    dataset=dataset,
)

print(f"Baseline score: {baseline_score:.3f}")
print(f"Final score: {result.final_score:.3f}")
print(f"Delta: {result.final_score - baseline_score:+.3f}")
print(f"Best prompt:\n{result.best_generator.get_prompt_template()}")

for i, iteration in enumerate(result.history):
    print(f"Round {i + 1}: score={iteration.average_score:.3f}")
```

</Step>
<Step title="Run the file">

Run the assembled file with Python 3.11.

You should see the baseline score, the final score, the signed delta, the text of the highest-scoring prompt variant, and one score per round as Random Search works through the 5 variations it generated.

</Step>
</Steps>

## Decide what the delta supports

The delta is `result.final_score - baseline_score`. A positive value means the best candidate outscored the original on these rows. Zero is a tie, and a negative value means the original did better. The highest-scoring *candidate* isn't necessarily an improvement.

Future AGI ships 5 other strategies behind the same `optimize()` call. Swapping the optimizer class doesn't change the rest of the workflow: the dataset, evaluator and data mapper stay the same.

- [Bayesian Search](/docs/optimization/reference/optimizers/bayesian-search) for few-shot example selection
- [ProTeGi](/docs/optimization/reference/optimizers/protegi) for targeted edits
- [Meta-Prompt](/docs/optimization/reference/optimizers/meta-prompt) for higher-level rewrites
- [GEPA](/docs/optimization/reference/optimizers/gepa) for evolutionary search
- [PromptWizard](/docs/optimization/reference/optimizers/promptwizard) for multi-stage refinement

## Troubleshooting

<div class="sdk-ref-table max-sm:[&_td]:px-1.5! max-sm:[&_th]:px-1.5!">

| Symptom | Cause | Fix |
|---|---|---|
| `ValueError` naming `fi_api_key` / `fi_secret_key` when constructing `Evaluator(...)` | `FI_API_KEY` / `FI_SECRET_KEY` weren't exported before the script started | Export both keys in the same shell session, then rerun |
| `ValueError: Invalid configuration...` constructing `Evaluator()` | Neither a `metric` nor the `eval_template` + `eval_model_name` pair was passed | Pass `eval_template` and `eval_model_name` together, or a local `metric` instead |
| LiteLLM raises an OpenAI auth error | `OPENAI_API_KEY` missing; the generator's `gpt-4o-mini` and the optimizer's `gpt-4o` teacher model both route through LiteLLM to OpenAI | Export `OPENAI_API_KEY` alongside the FI keys |
| The evaluator scores an empty or missing `output` input and returns a flat/zero score | `BasicDataMapper`'s `key_map` output value isn't the literal `generated_output` sentinel, so the mapper silently drops the field | Keep `"output": "generated_output"` exactly as shown |
| `result.final_score` barely moves after optimization | `num_variations` too low, or `eval_template` doesn't match what the dataset actually tests | Raise `num_variations`, and match `eval_template` to the task |
| `optimizer.optimize()` takes several minutes | Expected for `RandomSearchOptimizer` with `num_variations=5`: each variation calls the `gpt-4o` teacher model plus the evaluator | Lower `num_variations` for a faster first run, or wait it out |

</div>
