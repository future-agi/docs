## About

A prompt can win a search on familiar tickets and still route new ones incorrectly. Run a small release check for Ridgeline Outfitters: optimize on one set of tickets, test on a separate set, and save the candidate only if it beats the original.

| Time | Difficulty | Package |
|---|---|---|
| 20 min | Intermediate | `agent-learning-kit==0.3.7` |

## Set up Python

Use a fresh Python 3.12 environment. In Bash, enter an OpenRouter API key when prompted. The model calls use that key; the exact-match metric runs locally without Future AGI credentials.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install agent-learning-kit==0.3.7
read -rsp 'OpenRouter API key: ' OPENROUTER_API_KEY; printf '\n'
export OPENROUTER_API_KEY
```

## Search, check, and save a prompt

1. Keep the two `holdout` rows out of `optimize()`. They represent new requests with the same two queue labels.
2. Give random search only `train`. Afterward, score a fresh generator with the original template and the returned generator on `holdout`. Pass only `ticket` to each generator, not the answer key.
3. Reject a rewrite before calling the routing model unless it uses `{ticket}` and no other replacement field. Otherwise, save it only if its holdout score is higher. Reload it and check that its next reply is actually a queue name before using it.

Save as `end_to_end.py` and run `python end_to_end.py` in a directory where the script can write `ridgeline-router.txt`. Running it again replaces that file.

<CodeGroup titles={["Python"]}>

```python
from pathlib import Path
from string import Formatter

from fi.evals.metrics import Equals
from fi.opt.base import Evaluator
from fi.opt.datamappers import BasicDataMapper
from fi.opt.generators import LiteLLMGenerator
from fi.opt.optimizers import RandomSearchOptimizer

MODEL = "openrouter/openai/gpt-4o-mini"
seed = "Ticket: {ticket}\nQueue (RETURNS or REPAIRS):"
train = [
    {"ticket": "My new boots don't fit. Can I send them back?", "queue": "RETURNS"},
    {"ticket": "Can you fix a broken buckle on my pack?", "queue": "REPAIRS"},
]
mapper = BasicDataMapper({
    "response": "generated_output",
    "expected_response": "queue",
})
evaluator = Evaluator(metric=Equals(config={"case_sensitive": True}))
holdout = [
    {"ticket": "I ordered the wrong tent. Can I get a refund?", "queue": "RETURNS"},
    {"ticket": "Can you replace my sleeping bag zipper?", "queue": "REPAIRS"},
]


def accuracy(generator, rows):
    inputs = []
    for row in rows:
        reply = generator.generate({"ticket": row["ticket"]})
        if not reply:
            raise RuntimeError("No reply from the generator")
        inputs.append(mapper.map(reply, row))
    scores = evaluator.evaluate(inputs)
    return sum(item.score for item in scores) / len(rows)


def accepts_ticket(template):
    try:
        fields = [(name, spec, conversion) for _, name, spec, conversion
                  in Formatter().parse(template) if name is not None]
    except ValueError:  # Unmatched braces in a rewrite.
        return False
    return bool(fields) and all(field == ("ticket", "", None) for field in fields)


class TicketRouter(LiteLLMGenerator):
    def generate(self, row):
        if not accepts_ticket(self.get_prompt_template()):
            return ""  # An invalid rewrite cannot match either queue.
        return super().generate({"ticket": row["ticket"]})


generator = TicketRouter(MODEL, seed)
optimizer = RandomSearchOptimizer(
    generator=generator, teacher_model=MODEL, num_variations=2
)
result = optimizer.optimize(evaluator=evaluator, data_mapper=mapper, dataset=train)

# Random Search changes its generator in place. Rebuild the original for comparison.
before = accuracy(LiteLLMGenerator(MODEL, seed), holdout)
candidate = result.best_generator.get_prompt_template()
after = accuracy(result.best_generator, holdout) if accepts_ticket(candidate) else None
promote = after is not None and after > before
chosen = candidate if promote else seed
Path("ridgeline-router.txt").write_text(chosen, encoding="utf-8")
candidate_score = f"{after:.0%}" if after is not None else "invalid template fields"
print(f"Holdout: baseline={before:.0%}, candidate={candidate_score}")
print("Saved:", "candidate" if promote else "baseline")

router = LiteLLMGenerator(
    MODEL, Path("ridgeline-router.txt").read_text(encoding="utf-8")
)
prediction = router.generate({"ticket": "Can you mend a torn tent fly?"})
print("New ticket:", prediction if prediction in {"REPAIRS", "RETURNS"} else "manual review")
```

## Read the result

The file contains the chosen template, including its `{ticket}` placeholder, rather than a rendered reply. Here are the decision and routing lines from one run:

```text
Holdout: baseline=50%, candidate=100%
Saved: candidate
New ticket: REPAIRS
```

The original routed one held-out ticket correctly; the candidate routed both. The script saved the candidate and got `REPAIRS` for the new ticket. A tie would have kept the original.

## Limits and troubleshooting

- `RandomSearchOptimizer` changes its generator's template. Reusing that instance as the baseline after the search would compare the candidate against itself.
- Two held-out tickets can only distinguish 0%, 50%, and 100%. Use more unseen examples, especially tickets whose wording spans multiple queues, before promoting a change.
- `manual review` is the script's fallback for a reply outside the two allowed labels, including an empty reply. A score during search is not a guarantee that the next output has the right format.
