<TLDR>
**What you'll build:** Trace a four-agent CrewAI research crew (market researcher, competitive analyst, report writer, quality analyst) and use span-level evals to check whether the report writer's claims have evidence in the research it received.
</TLDR>

## The problem

A market report can have an executive summary, a competitive analysis and recommendations without backing its claims. Reading the finished report doesn't tell you which findings the writer received from the researchers. To check a questionable claim, you need both the writer's output and the research available to that task.

## What you'll build

A sequential research crew with [traceAI](/docs/integrations/traceai) instrumentation and an [Observe](/docs/observe) evaluation task that scores individual [spans](/docs/observe/concepts/spans).

<Mermaid chart={`flowchart TD
  accTitle: Follow a claim back to the writer's evidence
  accDescr: The market researcher and competitive analyst research the topic. The report writer uses their findings, then a quality analyst reviews the report. A trace records task spans so an eval can compare the writer's output with its research context.
  T["Research topic"] --> M["Market researcher"] --> C["Competitive analyst"]
  M --> W["Report writer"]
  C --> W --> Q["Quality analyst"]
  W --> S["Writer's task span"] --> E["Compare output with evidence"]
`} />

You'll:

1. Instrument four CrewAI tasks so you can follow one research topic through a [trace](/docs/observe/concepts/traces).
2. Inspect the writer's input and its report rather than judging only the crew's final output.
3. Attach [completeness](/docs/evaluation/builtin/completeness), [groundedness](/docs/evaluation/builtin/groundedness) and [context relevance](/docs/evaluation/builtin/context-relevance) checks to task spans.
4. Make the upstream task dependencies explicit and compare the writer's evidence on a rerun.

## Instrument the crew

Start a Python file with the block below. It registers `crewai-research-team` as `ProjectType.OBSERVE` and installs `CrewAIInstrumentor` before CrewAI executes. That lets the platform attach evals to captured spans rather than requiring an evaluator call in each task.

```python
from crewai import LLM, Agent, Crew, Process, Task
from crewai_tools import SerperDevTool, FileReadTool
from fi_instrumentation import register, FITracer
from fi_instrumentation.fi_types import ProjectType
from traceai_crewai import CrewAIInstrumentor

trace_provider = register(
    project_type=ProjectType.OBSERVE,
    project_name="crewai-research-team",
    set_global_tracer_provider=True,
)

# Auto-instruments crewai.Task._execute_core and crewai.Crew.kickoff.
# No manual spans needed for the crew's own execution.
CrewAIInstrumentor().instrument(tracer_provider=trace_provider)

tracer = FITracer(trace_provider.get_tracer(__name__))
```

The crew itself hasn't run yet. The instrumentor wraps CrewAI execution in this process so task execution and tool calls can be inspected later.

## Define the four agents

Append the agent definitions to the same file. Each agent has a narrow role. The two researchers use web search; the report writer has a file-reading tool; the quality analyst checks the work. `allow_delegation=False` keeps the sequential process predictable: each agent runs once, in order.

```python
llm = LLM(model="gpt-4o", temperature=0.7, max_tokens=2000)

market_researcher = Agent(
    role="Senior Market Research Analyst",
    goal="Research and analyze emerging technology trends and market dynamics",
    backstory=(
        "You are a market research analyst with 15 years in technology markets. "
        "You favor data-backed claims over speculation."
    ),
    llm=llm,
    tools=[SerperDevTool()],
    allow_delegation=False,
)

competitive_analyst = Agent(
    role="Competitive Intelligence Specialist",
    goal="Analyze competitive landscapes and identify market opportunities",
    backstory=(
        "You analyze competitor strategies and market positioning to find gaps "
        "a new entrant could exploit."
    ),
    llm=llm,
    tools=[SerperDevTool()],
    allow_delegation=False,
)

report_writer = Agent(
    role="Technical Report Writer",
    goal="Create a comprehensive, well-structured research report",
    backstory="You turn raw research into executive summaries and recommendations.",
    llm=llm,
    tools=[FileReadTool()],
    allow_delegation=False,
)

quality_analyst = Agent(
    role="Research Quality Assurance Specialist",
    goal="Verify accuracy and completeness of the research findings",
    backstory="You fact-check claims and flag logical gaps before a report ships.",
    llm=llm,
    allow_delegation=False,
)
```

## Define a task for each agent

Append the task factory. Each task specifies its expected output. Notice that neither `report_generation_task` nor `quality_assurance_task` declares `context=` yet, so CrewAI has no explicit link telling them which upstream task output to build on.

```python
def create_research_tasks(research_topic: str) -> list[Task]:
    market_research_task = Task(
        description=(
            f"Research the market for: {research_topic}. Cover market size, "
            "growth drivers, major players, and regulatory landscape. Cite sources."
        ),
        agent=market_researcher,
        expected_output="A market research summary with cited data points",
    )

    competitive_analysis_task = Task(
        description=(
            f"Analyze the competitive landscape for: {research_topic}. "
            "Cover top competitors, positioning, and market gaps."
        ),
        agent=competitive_analyst,
        expected_output="A competitive analysis with named competitors",
    )

    report_generation_task = Task(
        description=(
            f"Write a research report on: {research_topic} with an executive "
            "summary, market overview, competitive landscape, and recommendations."
        ),
        agent=report_writer,
        expected_output="A structured research report",
    )

    quality_assurance_task = Task(
        description=(
            "Review the report for factual accuracy, logical consistency, and "
            "completeness. List any issues found."
        ),
        agent=quality_analyst,
        expected_output="A quality review with a pass/fail verdict",
    )

    return [
        market_research_task,
        competitive_analysis_task,
        report_generation_task,
        quality_assurance_task,
    ]
```

The factory returns four `Task` objects. `Process.sequential` in the next section runs them in this order.

## Trace the first run

1. Append the entry point for the crew.

```python
def run_research_crew(research_topic: str) -> str:
    tasks = create_research_tasks(research_topic)

    research_crew = Crew(
        agents=[market_researcher, competitive_analyst, report_writer, quality_analyst],
        tasks=tasks,
        process=Process.sequential,
        memory=True,
    )

    result = research_crew.kickoff()
    return str(result)


if __name__ == "__main__":
    topic = "Generative AI in Healthcare: Market Opportunities and Challenges"
    report = run_research_crew(topic)
    print(report[:500])
```

2. Run the Python file with the supplied healthcare research topic.

   The crew runs four tasks in sequence; the script prints up to the first 500 characters of the kickoff result.

## Score the writer's evidence

1. In the project, open **Add Evals** to [configure an evaluation task](/docs/observe/guides/setup-evals).
2. Choose **Spans** as the unit under **Run evaluations on**.
3. Under **Filters**, use **Add filter** to limit the task to the crew's task spans.
4. Add the three checks from the [built-in eval library](/docs/evaluation/builtin).
5. Map each eval's variables to the fields it needs.

   For groundedness, `output` is the writer's text and `context` is the research that could support it, not the topic string.

6. Check the mapped fields in **Live Preview**.
7. Choose the data to score.

   Use **Historical data** with a time window that includes the first trace to score a baseline; **New incoming data** applies only to future arrivals.

8. Select **Create Task** once the preview contains the intended evidence.

You should see the task listed for the selected project. Open a scored task span in the trace to read its eval results alongside its output. The existing **Spans** view below illustrates why the span matters: tool spans with relevance scores of 80% or 100% can still show 0% completeness. It does not show a groundedness result for the report writer.

## Pass the findings explicitly and compare

1. Replace the report-writing and quality-assurance task definitions inside `create_research_tasks` with the following versions.

```python
    report_generation_task = Task(
        description=(
            f"Write a research report on: {research_topic} with an executive "
            "summary, market overview, competitive landscape, and recommendations."
        ),
        agent=report_writer,
        expected_output="A structured research report",
        context=[market_research_task, competitive_analysis_task],
    )

    quality_assurance_task = Task(
        description=(
            "Review the report for factual accuracy, logical consistency, and "
            "completeness. List any issues found."
        ),
        agent=quality_analyst,
        expected_output="A quality review with a pass/fail verdict",
        context=[market_research_task, competitive_analysis_task, report_generation_task],
    )
```

The writer now names both research tasks as context, and the reviewer names those same tasks and the report. CrewAI feeds those upstream outputs into the two tasks instead of leaving them to infer the link.

2. Check that the scoring schedule will cover the rerun.

   Configure an incoming-data task before the run, or use a historical window that includes the new trace afterward.

3. Run the same Python file again without changing the research topic.
4. Open the new trace's report-writing span.
5. Compare its captured research with the writer's input in the first run.
6. Compare the groundedness results for the two writer spans once both are scored.

With the market and competitive findings in the span's input, the groundedness eval has source material to check the report against instead of just the topic string. Read the judged claim against that evidence: a larger context alone does not establish a better result.

## Troubleshooting

<div class="sdk-ref-table max-sm:[&_td]:px-1.5! max-sm:[&_th]:px-1.5!">

| Symptom | What to check |
| --- | --- |
| No spans in Observe | Call `instrument()` immediately after `register()`, before constructing the agents or crew. |
| `TypeError: unexpected keyword argument 'debug'` from `register()` | `register()` has no `debug` parameter; use `verbose=True` (the default) for logs. |
| No eval results | Confirm the project uses `ProjectType.OBSERVE`, the eval task targets the intended span type, and its schedule covers the run. |
| `crewai_tools` cannot import `SerperDevTool` | Check that `crewai` and `crewai_tools` are compatible; pin compatible versions. For tool initialization, set `SERPER_API_KEY` before constructing the tool. |
| Inconsistent or incomplete task output | Make the required sections explicit in `description` and give each agent the tools its role needs. |
| `Crew.kickoff()` hangs or times out | Check the SerperDev dashboard for rate limits and check the network; use a task timeout if your CrewAI version supports it. |
| Low groundedness on a downstream task | Inspect its captured context and its variable mapping. If the upstream findings are missing, add the task dependencies explicitly, rerun and compare. |

</div>
