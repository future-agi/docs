<TLDR>
Build a PDF RAG chatbot that stores chunks and embeddings in [MongoDB Atlas](https://www.mongodb.com/products/platform/atlas-database) vector search and answers with a LangChain `RetrievalQA` chain. Instrument it with [traceAI](/docs/integrations/traceai) so every question produces a trace, attach an Observe Eval Task that scores retrieval and grounding, and compare the answer with the actual chunk the model saw.
</TLDR>

| Time | Difficulty | Package |
|------|-----------|---------|
| 30-40 min | Intermediate | `fi-instrumentation-otel` + `traceAI-langchain` |

<Prerequisites>
- Future AGI account → [app.futureagi.com](https://app.futureagi.com)
- API keys: `FI_API_KEY` and `FI_SECRET_KEY` (see [Get your API keys](/docs/admin-settings))

</Prerequisites>

## Tutorial

<Steps>

<Step title="Instrument the pipeline with traceAI">

Save as `tracing.py`. Register the Observe provider before running the chain. The outer span will record the question, retrieved policy and final answer together so an eval can use all three.

```python
from uuid import UUID
from fi_instrumentation import register
from fi_instrumentation.fi_types import ProjectType
from traceai_langchain import LangChainInstrumentor

trace_provider = register(project_type=ProjectType.OBSERVE,
                          project_name="langchain_mongodb_project",
                          set_global_tracer_provider=True, verbose=False)
LangChainInstrumentor().instrument(tracer_provider=trace_provider)
tracer = trace_provider.get_tracer(__name__)
```

</Step>
<Step title="Store the policy and create the vector index">

Save as `policy_store.py`. The example writes a two-page Ridgeline policy PDF and creates a **new collection** in `rag_demo` for each run. `PyPDFLoader` keeps page metadata, and the splitter adds overlap within each page. The vector index definition uses the dimension reported by the actual embedding model. Insert the chunks before building the index, then wait for it to become queryable.

```python
import os
import time
from uuid import uuid4
from langchain_community.document_loaders import PyPDFLoader
from langchain_mongodb import MongoDBAtlasVectorSearch
from langchain_openai import OpenAIEmbeddings
from langchain_text_splitters import RecursiveCharacterTextSplitter
from pymongo import MongoClient
from pymongo.operations import SearchIndexModel
from reportlab.pdfgen.canvas import Canvas


def build_store():
    pdf = "ridgeline-refund-policy.pdf"
    canvas = Canvas(pdf)
    for text in ("Final-sale items cannot be refunded, even within 30 days.",
                 "Full-price boots can be returned unworn within 30 days of delivery."):
        canvas.drawString(50, 760, text)
        canvas.showPage()
    canvas.save()
    pages = PyPDFLoader(pdf).load()
    chunks = RecursiveCharacterTextSplitter(chunk_size=1000, chunk_overlap=150).split_documents(pages)

    client = MongoClient(os.environ["MONGODB_ATLAS_URI"], serverSelectionTimeoutMS=30000)
    collection = client["rag_demo"].create_collection("policy_" + uuid4().hex[:12])
    embeddings = OpenAIEmbeddings(model="text-embedding-3-small", check_embedding_ctx_length=False)
    dimension = len(embeddings.embed_query("dimension probe"))
    store = MongoDBAtlasVectorSearch(collection, embeddings, index_name="vector_index",
                                     auto_create_index=False)
    ids = store.add_documents(chunks)
    print(f"{collection.full_name}: stored {len(ids)} chunks with {dimension} dimensions")
    collection.create_search_index(SearchIndexModel(name="vector_index", type="vectorSearch",
        definition={"fields": [{"type": "vector", "path": "embedding",
                                "numDimensions": dimension, "similarity": "cosine"}]}))
    for _ in range(120):
        status = list(collection.list_search_indexes("vector_index"))
        if status and status[0].get("queryable"):
            return store
        if status and status[0].get("status") == "FAILED":
            raise RuntimeError("Vector index build failed; check the index definition")
        time.sleep(2)
    raise TimeoutError("Vector index is not yet queryable")
```

</Step>
<Step title="Retrieve a chunk and answer the question">

Save as `ask_policy.py`. Ask for one source so you can check exactly which policy was supplied. The chain returns both the answer and its source documents. Inspect the evidence rather than assuming that retrieval guarantees a correct answer.

```python
from tracing import UUID, trace_provider, tracer
from policy_store import build_store
from langchain.chains import RetrievalQA
from langchain_openai import ChatOpenAI

store = build_store()
qa = RetrievalQA.from_chain_type(
    llm=ChatOpenAI(model="gpt-4o-mini", temperature=0),
    retriever=store.as_retriever(search_kwargs={"k": 1}), return_source_documents=True,
)
question = "Can I get a refund for a final-sale item?"
with tracer.start_as_current_span("answer-policy-question") as span:
    response = qa.invoke({"query": question})
    context = "\n".join(doc.page_content for doc in response["source_documents"])
    if not context:
        raise RuntimeError("No policy was retrieved; check the index before evaluating the answer")
    answer = response["result"]
    span.set_attribute("raw.input", question)
    span.set_attribute("raw.context", context)
    span.set_attribute("raw.output", answer)
    trace_id = UUID(int=span.get_span_context().trace_id)
    print("Retrieved:", context)
    print("Answer:", answer)
trace_provider.force_flush()
print(trace_id)
```

</Step>
<Step title="Run on Atlas or Atlas Local">

**Hosted Atlas:** Set `MONGODB_ATLAS_URI` in your environment using your cluster's connection string, allow your client IP in Atlas, and run `python ask_policy.py`. The collection printed by the script remains in your cluster. Remove only your demo collection when you no longer need it.

**Atlas Local:** If you don't have a hosted cluster, save the following as `run_local.sh` and run `bash run_local.sh`. Docker starts MongoDB with Vector Search, binds it to a temporary loopback port and removes the demo container when the script exits. The Future AGI trace remains available in either case.

```bash
set -eu
container=$(docker run --detach --rm -p 127.0.0.1::27017 mongodb/mongodb-atlas-local:8.0)
trap 'docker stop "$container" >/dev/null' EXIT
for attempt in {1..120}; do
  health=$(docker inspect --format '{{.State.Health.Status}}' "$container")
  if [[ $health == healthy ]]; then break; fi
  if [[ $health == unhealthy ]]; then break; fi
  sleep 2
done
if [[ $health != healthy ]]; then printf 'Atlas Local did not start\n' >&2; exit 1; fi
address=$(docker port "$container" 27017/tcp)
export MONGODB_ATLAS_URI="mongodb://${address}/?directConnection=true"
python ask_policy.py
```

Look for `2 chunks with 1536 dimensions`, the final-sale policy and the answer. Open the last printed ID in **Observe → Traces → `langchain_mongodb_project`** and expand the retriever and model spans.

</Step>

<Step title="Score retrieval and grounding with an Eval Task">

Configure evals in the platform as an **Eval Task**, not from the SDK, if you want matching questions through this chain scored consistently. Filter for the `answer-policy-question` span and map question, retrieved context and answer to its `raw.input`, `raw.context` and `raw.output` fields. Create the task on `langchain_mongodb_project` and pick evals that isolate each layer of the pipeline:

- **Context Relevance**: did retrieval fetch chunks that answer the question?
- **Context Adherence**: did the answer stay inside the retrieved chunks?
- **Detect Hallucination**: did the model introduce anything not in the source PDF?
- **Task Completion**: did the answer fully address the question?

*Attaching evals to the span type they should run against*

For domain-specific fidelity beyond general hallucination detection, add a custom eval of your own naming (for example, one you call `reference_verification`) that fails a response unless every claim traces back to a retrieved chunk. See [Creating your own evals](/docs/evaluation/guides/custom-evals).

**You should see** the Eval Task listed as active on the project, and scores start appearing on new traces within a few minutes.

</Step>

<Step title="Read the trace where the score catches the failure">

Open a trace and compare the retrieved chunk against the answer directly. This is where "the pipeline looked healthy" and "the answer was wrong" split apart.

<img src="/images/docs/cookbook-mongodb/mongodb4.png" alt="Trace detail view showing the embedding, retrieval, and generation span hierarchy on the left, input and output on the right, and eval scores in the bottom panel" style={{ borderRadius: '5px' }} />

*Span hierarchy, input/output, and per-span eval scores on one trace*

For the final-sale question, the retrieved chunk should rule out a refund. If the answer nevertheless promises one, retrieval found the relevant policy but generation contradicted it. A relevance score alone would miss that distinction. Compare the actual scores and reasons on a sampled span; no particular score is guaranteed.

</Step>

<Step title="Alert on the metric that caught the failure">

Turn the check from step 6 into a standing monitor instead of something you eyeball per trace. Set an alert on the eval score, an interval to check it over, and a threshold that represents an acceptable answer.

<img src="/images/docs/cookbook-mongodb/mongodb6.png" alt="Alert rule configuration setting Context Adherence as the metric, a monitoring interval, and a threshold for the langchain_mongodb_project" style={{ borderRadius: '5px' }} />

*Creating an alert on Context Adherence*

Triggered alerts land in a single dashboard across projects, so you can see which ones are healthy and which are firing without opening each trace.

<img src="/images/docs/cookbook-mongodb/mongodb7.png" alt="Alerts dashboard listing triggered and healthy alerts across projects with their last-triggered time" style={{ borderRadius: '5px' }} />

*Alerts dashboard across projects*

**You should see** the alert listed as Healthy until Context Adherence drops below the threshold you set, at which point it moves to Triggered and notifies the channel you configured.

</Step>

</Steps>

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| No trace in Observe after step 4 | `register()` or `.instrument()` ran after building the chain, or the script exited before flush | Instrument before any chain call; call `trace_provider.force_flush()` before exit |
| `LangChainInstrumentor` import error | Ran without `traceAI-langchain` installed, or imported `LangChainInstrumentor` from `fi_instrumentation` instead of `traceai_langchain` | `pip install traceAI-langchain`; import from `traceai_langchain`, not `fi_instrumentation` |
| Atlas rejects the vector index definition | Index `numDimensions` doesn't match the embedding model's output length | Use the printed vector dimension as `numDimensions` |
| `MongoClient` fails to connect | The cluster is unreachable, or the connection credentials are incorrect | Add your IP in Atlas Network Access; check the URI, cluster permissions and credentials |
| Retrieval returns 0 chunks | `index_name` in the retriever doesn't match the Atlas Search index name | Use the exact index name you created in Atlas, not the collection name |
| Eval Task shows no scores after several minutes | It ran before any trace existed, or the span didn't carry `INPUT_VALUE` / `OUTPUT_VALUE` | Send at least one traced query first; confirm the LLM span has input and output set |
| Context Adherence is high but the answer is still wrong | The eval is mapped to the wrong span or the wrong context field | Re-check the Eval Task's field mapping against the retriever span's output |
| Alert never fires even when scores are low | Metric alerts only run on `observe`-type projects, or the threshold direction is inverted | Confirm the project type is Observe; verify the operator is "Less than" for a quality score |

To turn that into an automated fix instead of a manual prompt edit, continue with [Improve a prompt automatically](/docs/cookbook/quickstart/prompt-optimization).
