<TLDR>
Load a RAG dataset, score each row for context relevance, completeness, and factual accuracy with `fi.evals`, then pull out the row with the lowest score to investigate whether retrieval or answer generation failed.
</TLDR>

## Tutorial

<Steps>
<Step title="Import the evaluator">

Run the Python blocks in order in the same Python session. `fi.evals` ships in the `agent-learning-kit` package, not `futureagi`.

```python
import csv
from fi.evals import evaluate
import pandas as pd
```

</Step>
<Step title="Load a RAG dataset sample">

Start with three synthetic Ridgeline Outfitters support cases. Each row records the question, the retrieved policy excerpt and the generated answer. The second answer contradicts the policy; the third row retrieves an unrelated policy.

```python
df = pd.DataFrame([
    ("When can I return a jacket?", "Return jackets within 30 days.", "You can return it within 30 days."),
    ("Do you cover return shipping?", "Customers pay for return shipping.", "We cover all return shipping."),
    ("How long is the tent warranty?", "Boots ship in three days.", "I could not find the tent warranty."),
], columns=["question", "context", "generated_with_rag"])
print(df[["question", "context", "generated_with_rag"]])
```

You should see three rows with `question`, `context`, and `generated_with_rag` columns populated.

Score the first row to see what a real result looks like before running the whole sample.

```python
history = []

def score(metric, **kwargs):
    result = evaluate(metric, **kwargs)
    if result.score is None or not 0 <= result.score <= 1:
        raise RuntimeError(f"No valid {metric} score: {result.error or result.reason}")
    history.append((result.metadata["eval_id"], metric, result.score))
    return result

first = df.iloc[0]
result = score(
    "context_relevance",
    input=first["question"],
    context=first["context"],
    model="turing_small",
)
print(result.score, result.reason)
```

You should see a score between 0 and 1 and a short text explanation.

</Step>
<Step title="Pick the RAG metrics to run">

Each metric needs a different combination of `context`, `input`, and `output`. Passing all three to every call, as Step 4 does, covers every metric here.

```python
metrics = ["context_relevance", "completeness", "factual_accuracy"]
```

- `context_relevance` (needs `context`, `input`): are the retrieved chunks relevant to the question
- `completeness` (needs `input`, `output`): does the answer address every part of the question
- `factual_accuracy` (needs `input`, `output`, `context`): are the claims in the answer correct

</Step>
<Step title="Score every row">

Scale the single `evaluate()` call from Step 2 to every metric and every row.

```python
for metric in metrics:
    df[metric] = None

for index, row in df.iterrows():
    for metric in metrics:
        result = score(
            metric,
            input=row["question"],
            output=row["generated_with_rag"],
            context=row["context"],
            model="turing_small",
        )
        df.at[index, metric] = result.score
```

You should see each metric column filled with a score between 0 and 1 for all three rows.

</Step>
<Step title="Aggregate the scores">

```python
for metric in metrics:
    print(f"Average {metric}: {df[metric].mean():.2f}")
```

Example output for the three support cases (judge scores can vary):

```
Average context_relevance: 0.67
Average completeness: 1.00
Average factual_accuracy: 0.67
```

In this example, factual accuracy ties with context relevance for the lowest mean. Inspect factual accuracy to see which answer contradicts the retrieved policy.

</Step>
<Step title="Find the weakest row">

An average hides which row is actually broken. Sort on the metric you care about and inspect the lowest scorer.

```python
worst = df.sort_values("factual_accuracy").iloc[0]

print(f"Question: {worst['question']}")
print(f"Answer:   {worst['generated_with_rag']}")
print(f"Score:    {worst['factual_accuracy']}")
```

Read the answer against its `context` column. A low `factual_accuracy` score with a context that does contain the fact points at the generation step, not retrieval; a low score with missing context points at the retriever.

</Step>
<Step title="Rerun the weak rows with a larger model">

Change one thing and rerun: re-score the rows below the sample average with `turing_large` instead of `turing_small`, and compare the means.

```python
before = df["factual_accuracy"].mean()

weak = df[df["factual_accuracy"] < before]
for index, row in weak.iterrows():
    result = score(
        "factual_accuracy",
        input=row["question"],
        output=row["generated_with_rag"],
        context=row["context"],
        model="turing_large",
    )
    df.at[index, "factual_accuracy"] = result.score

after = df["factual_accuracy"].mean()
print(f"factual_accuracy: {before:.2f} -> {after:.2f}")

# Keep the evaluation IDs alongside your scores so you can revisit each judgment.
with open("rag-scores.csv", "w", newline="") as f:
    writer = csv.writer(f)
    writer.writerow(["eval_id", "metric", "score"])
    writer.writerows(history)
```

Example output for the three support cases (judge scores can vary):

```
factual_accuracy: 0.67 -> 0.67
```

Only the judge changed. A different mean indicates disagreement about the same answers, not an improvement to your RAG pipeline. If all rows tie, the below-average subset is empty.

</Step>
</Steps>

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `ImportError: cannot import name 'evaluate' from 'fi.evals'` | Agent Learning Kit is not installed; `futureagi` alone does not ship `fi.evals` | `python -m pip install agent-learning-kit==0.3.7` |
| `401 Unauthorized` from `evaluate(..., model="turing_small")` | `FI_API_KEY` / `FI_SECRET_KEY` not exported, or exported with a stray space | Re-copy both keys from [app.futureagi.com](https://app.futureagi.com) settings and re-export |
| `KeyError: 'context'` when reading a row | The loaded dataset uses a different column name for context | Run `df.columns` first and match the exact column name |
| `result.score` is `None` | The call failed or did not return a numeric result | Inspect `result.status`, `result.error` and `result.reason` before adding it to your average |
| Looping over the dataframe takes minutes on larger samples | Each `evaluate()` call is a separate network request to a Turing model | Score a smaller sample while iterating, or parallelize the loop with a thread pool |
| `context_relevance` scores are uniformly low | `context` holds the full source article instead of the retrieved chunk | Pass only the chunk your retriever actually returned, not the whole document |

For a metric-by-metric breakdown of retrieval failures versus generation failures on a single test case, see [RAG Evaluation: Retrieval vs Generation](/docs/cookbook/quickstart/rag-evaluation).
