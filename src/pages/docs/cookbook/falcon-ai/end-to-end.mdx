## Tutorial

<Steps>
<Step title="Trace a support agent">

Run the tracing and replay blocks in one Python session. Falcon AI reads your agent's **traces**: the structured record of one request, broken into **spans** for each LLM call, tool invocation, or sub-step inside it. `OpenAIInstrumentor` patches the OpenAI SDK so every call is captured automatically, and `@tracer.agent` wraps your agent's entry point so each request lands as one parent span with the OpenAI calls nested underneath.

```python
from fi_instrumentation import register, FITracer
from fi_instrumentation.fi_types import ProjectType
from traceai_openai import OpenAIInstrumentor

trace_provider = register(
    verbose=False,
    project_type=ProjectType.OBSERVE,
    project_name="falcon-ai-end-to-end",
)
OpenAIInstrumentor().instrument(tracer_provider=trace_provider)
tracer = FITracer(trace_provider.get_tracer("falcon-ai-end-to-end"))
```

```python
import csv
from uuid import UUID
from openai import OpenAI
from opentelemetry.trace import get_current_span

client = OpenAI()
cases = [
    ("Where is order RO-12345?", "RO-12345 has shipped. Tracking is not yet available."),
    ("Can I return opened trail shoes?", "Trail shoes are returnable within 30 days if unworn."),
]
rows = []

@tracer.agent(name="support_reply")
def my_agent(query, prompt):
    reply = client.chat.completions.create(
        model="gpt-4o-mini", messages=[{"role": "system", "content": prompt},
                                      {"role": "user", "content": query}],
    ).choices[0].message.content
    return str(UUID(int=get_current_span().get_span_context().trace_id)), reply

def run_cases(version, instructions, include_source=False):
    for query, source in cases:
        prompt = instructions + ("\nSource: " + source if include_source else "")
        trace_id, answer = my_agent(query, prompt)
        if not answer:
            raise ValueError("The model returned no answer")
        rows.append(dict(version=version, query=query, context=source,
                         agent_output=answer, trace_id=trace_id))
        print(version, trace_id, answer)
    trace_provider.force_flush()
    with open("support-replays.csv", "w", newline="") as f:
        writer = csv.DictWriter(f, fieldnames=rows[0].keys())
        writer.writeheader()
        writer.writerows(rows)

run_cases("baseline", "You answer product and order questions for Ridgeline Outfitters.")
```

You should see two new traces in **Tracing** → your project within a few seconds. If nothing appears, see Troubleshooting below.

</Step>
<Step title="Find the failing traces">

Falcon AI picks up whatever page you're viewing as context, so opening the sidebar from your project's Tracing page scopes every question and skill to that project automatically.

`/analyze-trace-errors` looks for issues such as unsupported claims. Give it the two baseline trace IDs, not your entire project, and review the evidence before labeling an answer as a failure.

Stay on the Tracing page, open the sidebar, and type:

> /analyze-trace-errors Review these two baseline traces. Which specific claims about the order or the return policy lacked a source?

<Tip>
`Cmd+K` (Mac) or `Ctrl+K` (Windows) opens Falcon AI from anywhere in the dashboard, with the current page auto-attached as a context chip.
</Tip>

You should see a completion card listing per-trace scores and the dominant error category. Switch to the **Feed** tab in Tracing to see the same findings per-trace, with the quote that triggered each one.

</Step>
<Step title="Lock the failures into a regression dataset">

Same conversation. `/build-dataset` reads the findings from the previous turn and writes the matching rows to a new dataset. This locks the bad traces as a **regression dataset**, a fixed snapshot you can re-run anytime: when you try a fix later, you score it against the exact same failing inputs instead of new traffic that may not reproduce the same problem.

> Build me a dataset called `falcon-demo-failures` from my two baseline trace IDs. Include both as regression examples even if neither hallucinated. Columns: `query` (text), `agent_output` (text), `context` (text), `trace_id` (text). I will provide the two reference facts from `cases`; do not infer policy from the generated replies.

You should see a completion card with a link to the new dataset. Use a new dataset name if this one exists. Open **Datasets** to confirm each row has the correct trace ID, answer and reference fact.

</Step>
<Step title="Score the baseline">

Same conversation. `/run-evaluations` runs Future AGI evals (LLM-as-judge metrics like `factual_accuracy` or `completeness`) against every row in the dataset and returns per-row and aggregate scores. This is the baseline the fix needs to beat.

> Run `factual_accuracy` and `completeness` evals on the `falcon-demo-failures` dataset.

Inspect each judgment: map `query` to input, `agent_output` to output and `context` to the reference for factual accuracy. A polite refusal and a fabricated order status may both be incomplete, but they fail for different reasons.

</Step>
<Step title="Generate the prompt fix">

`/fix-with-falcon` reads the system prompt and model output from a specific span and returns a copy-pasteable prompt edit in a *Current* / *Replace with* format. Unlike the previous skills it needs a single failing trace as context, not a whole project, so open it from a trace detail page.

For ungrounded hallucinations like these, the typical fix is a refusal instruction: the agent is told to decline rather than invent specifics when it lacks tool grounding.

Open one of the worst-scoring traces from the Feed. With that trace as context, type:

> /fix-with-falcon

You should see sections for *What happened*, *Root cause in the agent*, *The fix* (current vs replace with), and *Expected score improvement*.

</Step>
<Step title="Apply the fix and verify scores recover">

Use the reviewed edit or try this version. A prompt cannot recover order details it never received, so this replay also supplies the reference fact for each request:

```python
run_cases("revised", "Answer only from the supplied source. If a detail is missing, say so.",
          include_source=True)
```

Add the revised outputs beside the baseline outputs for the same two queries. Ask Falcon to score the **revised output column** with the same templates and references. Re-running evals against the unchanged baseline column does not test a fix. Compare each row's answers, reasons and scores. Improvement is not guaranteed.

</Step>
</Steps>

## Save a scored snapshot from Python

If you want a reproducible alternative to assembling the dataset in chat, use `support-replays.csv` from the replay above. This creates a separate snapshot of all four answers, not a new version of the dataset you created in Falcon. Use separate environments: Agent Learning Kit scores replies, while the `futureagi` platform SDK uploads datasets. Both packages install modules under `fi`.

```bash
python3.12 -m venv .judges
.judges/bin/python -m pip install agent-learning-kit==0.3.7
python3.12 -m venv .datasets
.datasets/bin/python -m pip install futureagi==0.7.0
```

Save as `score_replays.py` and run `.judges/bin/python score_replays.py`.

```python
import csv
from fi.evals import evaluate

with open("support-replays.csv", newline="") as f:
    rows = list(csv.DictReader(f))
for row in rows:
    for metric in ("factual_accuracy", "completeness"):
        inputs = {"input": row["query"], "output": row["agent_output"]}
        if metric == "factual_accuracy":
            inputs["context"] = row["context"]
        judge = evaluate(metric, model="turing_flash", **inputs)
        if judge.score is None:
            raise RuntimeError(judge.error or judge.reason)
        row[metric] = judge.score
        row[metric + "_id"] = judge.metadata["eval_id"]
with open("scored-replays.csv", "w", newline="") as f:
    writer = csv.DictWriter(f, fieldnames=rows[0].keys())
    writer.writeheader()
    writer.writerows(rows)
```

Save as `upload_replays.py` and run `.datasets/bin/python upload_replays.py`. Use the printed ID to find the snapshot in Datasets. The score columns are recorded values, not live evaluation configurations.

```python
from uuid import uuid4
from fi.datasets import Dataset, DatasetConfig
from fi.utils.types import ModelTypes

name = f"falcon-support-replays-{uuid4().hex[:8]}"
dataset = Dataset(dataset_config=DatasetConfig(name=name, model_type=ModelTypes.GENERATIVE_LLM))
dataset.create(source="scored-replays.csv")
print(dataset.dataset_config.id)
```

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| No traces appear in Tracing after running the script | `force_flush()` wasn't called before the process exited, or `OPENAI_API_KEY` is unset | Call `trace_provider.force_flush()` before exit and confirm `OPENAI_API_KEY` is exported |
| `/analyze-trace-errors` returns no traces or the wrong ones | Falcon AI is scoped to a different project than the one you just traced | Open the sidebar from the Tracing page of the exact project you instrumented |
| `/build-dataset` writes 0 rows | The failure category named in the prompt doesn't match the exact label `/analyze-trace-errors` returned | Copy the category name verbatim from the previous turn's completion card |
| Eval scores in `/run-evaluations` look identical across rows | Dataset columns aren't mapped to what the eval reads (`input`, `output`, `context`) | Map `query`, `agent_output`, and `context` to the eval's `input`, `output`, and `context` keys when building the dataset in step 3 |
| `/fix-with-falcon` has no trace context | The skill was run from a project or feed page instead of a trace detail page | Open the specific trace first, then run `/fix-with-falcon` |
| Re-run in step 6 shows the same low score as before | The `Replace with` prompt was copied but never redeployed to the running agent | Confirm the deployed system prompt matches the `Replace with` block exactly, then re-run |
