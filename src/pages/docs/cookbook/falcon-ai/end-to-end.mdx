## The problem

An electronics-store agent can answer “Where is my order?” with a tracking detail even though it has no order lookup tool. Spotting that answer in a [trace](/docs/observe/concepts/traces) doesn't stop it happening again. Save the question and the evidence so the next prompt has to answer the same case.

## What you'll build

A regression dataset that keeps the failing question, reply and context, with baseline eval scores to compare against after a prompt fix.

<Mermaid chart={`flowchart LR
  accTitle: From an unsupported reply to a regression check
  accDescr: Analyze the support trace, save the failure as a dataset row and score the original reply. Propose a prompt edit from the failing trace, rerun the same query and compare the new scores with the baseline.

  T --> F["Propose prompt edit"] --> R["Rerun same query"] --> C["Compare scores with baseline"]

You'll:

1. Find the quote in a support reply that the trace doesn't support.
2. Save the failing query, output and context as a fixed regression dataset.
3. Score the original replies before applying a suggested prompt change.
4. Re-run the same evals after the fix and compare them with the baseline.

## Trace a support agent

If you already have a trace with an unsupported reply, skip to [Find the unsupported claim](#find-the-unsupported-claim). Otherwise, run this example to generate two responses. The agent has no tool for orders or store policy, so it tends to invent specifics such as tracking numbers and return windows. Read what it actually says before you treat either response as a failure.

<Steps>
<Step title="Install the tracing packages">

```bash
pip install fi-instrumentation-otel traceai-openai openai
```

</Step>
<Step title="Set the keys">

Set the keys in the shell where you'll run Python.

<div class="sdk-ref-table max-sm:[&_td]:px-1.5! max-sm:[&_th]:px-1.5!">

| Variable | What it supplies | Where it comes from |
| --- | --- | --- |
| `FI_API_KEY` | Workspace API key for trace export | [app.futureagi.com/dashboard/keys](https://app.futureagi.com/dashboard/keys) |
| `FI_SECRET_KEY` | Secret matching that key | The same page, when you create the key pair |
| `OPENAI_API_KEY` | Credentials for the model call | Your OpenAI account |

</div>

```bash
export FI_API_KEY="your-fi-api-key"
export FI_SECRET_KEY="your-fi-secret-key"
export OPENAI_API_KEY="your-openai-key"
```

</Step>
<Step title="Register the tracer">

Register the tracer before creating the OpenAI client. `OpenAIInstrumentor`, from the [OpenAI instrumentation](/docs/integrations/traceai/openai), patches the OpenAI SDK so every call is captured as a [span](/docs/observe/concepts/spans).

```python
from fi_instrumentation import register, FITracer
from fi_instrumentation.fi_types import ProjectType
from traceai_openai import OpenAIInstrumentor

trace_provider = register(
    project_type=ProjectType.OBSERVE,
    project_name="falcon-ai-end-to-end",
)
OpenAIInstrumentor().instrument(tracer_provider=trace_provider)
tracer = FITracer(trace_provider.get_tracer("falcon-ai-end-to-end"))
```

</Step>
<Step title="Run the agent">

Run the agent example in the same Python process. `@tracer.agent` wraps the agent's entry point, so each request lands as one parent span with the OpenAI calls nested underneath.

```python
from openai import OpenAI

client = OpenAI()


# Replace this with your own agent's entry point.
# @tracer.agent makes each call show up as one parent span in your
# Future AGI Tracing project, with the OpenAI calls nested underneath.
@tracer.agent(name="my_agent")
def my_agent(user_message: str) -> str:
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": "You are a customer support assistant for an electronics store. Answer questions about products and orders."},
            {"role": "user", "content": user_message},
        ],
    )
    return response.choices[0].message.content


# A support agent with no grounding tool tends to fabricate specifics
# (tracking numbers, return windows, warranty lengths) when asked about
# them. That gives Falcon AI a failing trace to analyze next.
print(my_agent("Where is order ORD-12345?"))
print(my_agent("What's your return policy for opened wireless headphones?"))

trace_provider.force_flush()
```

You should see two new traces under **Tracing** in the `falcon-ai-end-to-end` project within a few seconds. If nothing appears, see [Troubleshooting](#troubleshooting).

</Step>
</Steps>

## Find the unsupported claim

Falcon AI picks up whatever page you're viewing as context. Opening the sidebar from your project's Tracing page scopes every question and skill to that project automatically.

1. Open your project's **Tracing** page.
2. Open the Falcon AI sidebar.

   `Cmd+K` (Mac) or `Ctrl+K` (Windows) opens Falcon AI from anywhere in the dashboard, with the current page attached as a context chip.

3. Send this request, which uses the `/analyze-trace-errors` skill:

   > Analyze trace errors in this project

   The skill runs across every trace in the project, classifies each issue against an error taxonomy (Hallucinated Content, Wrong Intent, Tool Misuse, and others), and scores every trace 1 to 5. You should see a completion card listing per-trace scores and the dominant error category.

4. Open the **Feed** tab in Tracing.

   You should see the same findings per trace, with the quote that triggered each one.

5. Read the quote for a finding labeled Hallucinated Content.

   Does the reply assert an order status, return window or warranty that the agent had no evidence for? If the example agent declined to invent an answer, choose an actual failing trace rather than labeling the refusal a failure.

## Save the failing cases

`/build-dataset` reads the findings from the previous turn and writes the matching rows to a new [dataset](/docs/dataset/concepts/understanding-datasets). This locks the failing traces into a regression dataset, a fixed snapshot you can re-run anytime. When you try a fix later, you score it against the exact same failing inputs instead of new traffic that may not reproduce the problem.

1. In the same conversation, send:

   > Build me a dataset called `falcon-demo-failures` with the queries from the traces flagged with Hallucinated Content. Columns: `query` (text), `agent_output` (text), `context` (text), `failure_category` (text).

   You should see a completion card with a link to the new dataset.

2. Open **Datasets**.
3. Select `falcon-demo-failures`.

   You should see the rows, with the question in `query` and the original reply in `agent_output`.

## Score the original replies

`/run-evaluations` runs Future AGI evals against every row in the dataset and returns per-row and aggregate scores. `factual_accuracy` and `completeness` are [LLM-as-judge](/docs/evaluation/concepts/eval-types) metrics. This run is the baseline the fix needs to beat.

1. In the same conversation, send:

   > Run `factual_accuracy` and `completeness` evals on the `falcon-demo-failures` dataset.

2. Read the per-row and aggregate scores.

   Keep them as the baseline. For invented answers, look for low `factual_accuracy` with high `completeness`: the agent fully addresses each question, but the answers are invented. [Completeness](/docs/evaluation/builtin/completeness) checks whether the reply covers the question, so read it alongside the factual check.

<Note>
[`factual_accuracy`](/docs/sdk/evals/cloud-evals) reads `input`, `output` and `context`. `completeness` reads `input` and `output`. The dataset's `query`, `agent_output` and `context` columns map to those keys.
</Note>

## Request a prompt edit for one trace

`/fix-with-falcon` reads the system prompt and model output from a specific span and returns a copy-pasteable prompt edit in a *Current* / *Replace with* format. Unlike the previous skills, it needs a single failing trace as context, not a whole project, so open it from a trace detail page.

1. Open one of the worst-scoring traces from **Feed**.
2. Check that the chat context is that trace, not the whole project.
3. Send the skill command:

   > /fix-with-falcon

   You should see sections for *What happened*, *Root cause in the agent*, *The fix* (current vs replace with), and *Expected score improvement*.

4. Compare *Current* with *Replace with*.

   For ungrounded hallucinations like these, the typical fix is a refusal instruction: the agent is told to decline rather than invent specifics when it lacks tool grounding. The expected improvement is a prediction, not a measured result.

## Re-run the regression case

1. Paste the *Replace with* block as the agent's new system prompt.
2. Re-run the same queries through your traced agent.
3. Back in Falcon AI, send:

   > Re-run the same evals on `falcon-demo-failures` and compare to the previous run.

4. Compare the new scores with the baseline.

   Look for `factual_accuracy` to recover because the agent no longer fabricates, while `completeness` stays high because the refusal still addresses the question. Your numbers will vary.

5. Read the new replies.

   If a reply still makes the unsupported claim, the edit did not fix that case, whatever the aggregate score says.

## Troubleshooting

<div class="sdk-ref-table max-sm:[&_td]:px-1.5! max-sm:[&_th]:px-1.5!">

| Symptom | Cause | Fix |
|---|---|---|
| No traces appear in Tracing after running the script | `force_flush()` wasn't called before the process exited, or `OPENAI_API_KEY` is unset | Call `trace_provider.force_flush()` before exit and confirm `OPENAI_API_KEY` is exported |
| `/analyze-trace-errors` returns no traces or the wrong ones | Falcon AI is scoped to a different project than the one you just traced | Open the sidebar from the Tracing page of the exact project you instrumented |
| `/build-dataset` writes 0 rows | The failure category named in the prompt doesn't match the exact label `/analyze-trace-errors` returned | Copy the category name verbatim from the previous turn's completion card |
| Eval scores in `/run-evaluations` look identical across rows | Dataset columns aren't mapped to what the eval reads (`input`, `output`, `context`) | Map `query`, `agent_output`, and `context` to the eval's `input`, `output`, and `context` keys when you build the dataset |
| `/fix-with-falcon` has no trace context | The skill was run from a project or feed page instead of a trace detail page | Open the specific trace first, then run `/fix-with-falcon` |
| The re-run shows the same low score as before | The `Replace with` prompt was copied but never redeployed to the running agent | Confirm the deployed system prompt matches the `Replace with` block exactly, then re-run |

</div>
