<TLDR>
Use [Falcon AI](/docs/falcon-ai/concepts/understanding-falcon-ai) on a failing [trace](/docs/observe/concepts/traces) to find an invented citation and draft a change to the system message.
</TLDR>

## The problem

A research assistant is told to cite its sources but has no search tool. Its answer can include a plausible paper description that it never checked. A quality score alone doesn't show which instruction the model saw when it wrote the citation.

## What you'll build

A three-turn debugging session that connects an unsupported claim to the exact system message in the model [span](/docs/observe/concepts/spans).

<Mermaid chart={`flowchart TD
  accTitle: Follow an unsupported citation back to its instruction
  accDescr: A research question produces a traced answer. Falcon AI reads the trace, proposes a system message change, and a new trace lets you compare the answer to the same question.
  Q["Research question"] --> T["Trace with citation"] --> D["Falcon diagnosis"] --> P["Proposed instruction"] --> R["Same question, new trace"]`} />

You'll:

1. Capture a research assistant's model calls in [Observe](/docs/observe).
2. Read the diagnosis and classify the failure without copying a trace ID.
3. Compare the proposed prompt edit with the actual system message.
4. Ask the same question again and check the new answer.


2. Set the workspace credentials and your model provider key in the same shell.

```bash

```

## Add tracing to your agent

Falcon AI works by reading your agent's traces, so the agent has to be sending traces to Future AGI before any of the next steps can run.

1. Register `research-assistant-demo` and enable [OpenAI tracing](/docs/integrations/traceai/openai) before you create the client.

   `OpenAIInstrumentor` captures the model calls automatically.

```python
from fi_instrumentation import register, FITracer
from fi_instrumentation.fi_types import ProjectType
from traceai_openai import OpenAIInstrumentor

trace_provider = register(
    project_type=ProjectType.OBSERVE,
    project_name="research-assistant-demo",
)
OpenAIInstrumentor().instrument(tracer_provider=trace_provider)
tracer = FITracer(trace_provider.get_tracer("research-assistant-demo"))
```

2. Run the decorated agent on the two research questions in the same Python process.

   The decorator puts the model calls for each request under one parent span.

```python
from openai import OpenAI

client = OpenAI()


# Replace this with your own agent's entry point.
# The @tracer.agent decorator makes each call show up as one parent span
# in your Future AGI Tracing project, with the OpenAI calls nested underneath.
@tracer.agent(name="my_agent")
def my_agent(user_message: str) -> str:
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": "You are a research assistant. Provide citations to support your claims."},
            {"role": "user", "content": user_message},
        ],
    )
    return response.choices[0].message.content


# Asking for citations on a topic the model has no search tool for is a
# common failure mode (the model fabricates papers from training data).
# This gives Falcon AI a failing trace to analyze in the next step.
print(my_agent("What's the seminal paper on transformers?"))
print(my_agent("What are the key papers on contrastive learning for self-supervised vision?"))

trace_provider.force_flush()
```

You should see two responses printed, and a new trace on your project's **Tracing** page in the dashboard. For broader instrumentation patterns (custom spans, metadata tagging, prompt template tracking), see [Manual Tracing](/docs/cookbook/quickstart/manual-tracing).

## Ask Falcon AI what went wrong

Falcon AI is the assistant built into the Future AGI dashboard. It picks up whatever page you're viewing as **context**: a trace, a project or a dataset. Open it on a trace detail page and the trace ID auto-attaches as a context chip in the chat input, so every question and skill in this conversation answers against that specific trace.

Its [skills](/docs/falcon-ai/concepts/skills) are slash commands that run a structured workflow over the current context and produce a clickable artifact: a dataset, an eval run or a prompt diff.

1. In **Tracing**, open the trace for the answer with the unsupported citation.
2. Open the Falcon AI sidebar.

   You should see the trace context chip in the chat input.

3. Send the question:

> What went wrong with this trace?

<Tip>
`Cmd+K` (Mac) or `Ctrl+K` (Windows) opens Falcon AI from anywhere in the dashboard, with the current page auto-attached as a context chip.
</Tip>

In the example below, the diagnosis says the model invented paper descriptions rather than grounding its answer in sources. Your model may answer the sample questions differently.

## Drill into the failure mode

In the same conversation, send `/analyze-trace-errors`. The skill classifies issues against an error taxonomy (Hallucinated Content, Tool Misuse, Wrong Intent, etc.), assigns a severity to each finding, and produces a quality scorecard for the trace.

The example shows Hallucinated Content as a High impact finding (the model invented papers from training data instead of grounding the answer in retrieved sources), plus a quality scorecard and recommended fixes.

<img src="https://fi-cookbook-assets.s3.ap-south-1.amazonaws.com/falcon-ai/context-aware-debugging/turn-2-analyze-trace-errors.png" alt="Falcon AI showing the structured /analyze-trace-errors output with category findings, severity, and a quality scorecard for the same trace" style={{width: "100%", borderRadius: "0.75rem", border: "1px solid var(--color-border-default)"}} />

*The severity assigned to each finding is what turns a wall of trace text into a triage list*

This is diagnosis with suggestions. The next turn converts that suggestion into a paste-ready diff.

## Generate the prompt fix

Send `/fix-with-falcon` in the same conversation. The skill reads the system prompt and model output from the trace's LLM span and returns a copy-pasteable prompt edit in a *Current* / *Replace with* format. The Current block is pulled directly from the span so the diff is grounded in what the agent actually saw, not guessed from a description.

In this example, the proposed diff keeps the original system prompt and adds an instruction to decline rather than invent a citation when no source is available. Check what your proposed instruction would change before applying it.

<img src="https://fi-cookbook-assets.s3.ap-south-1.amazonaws.com/falcon-ai/context-aware-debugging/turn-3-fix-with-falcon.png" alt="Falcon AI fix-with-falcon output for the same trace showing What happened, Root cause in the agent, and a Current vs Replace with prompt diff" style={{width: "100%", borderRadius: "0.75rem", border: "1px solid var(--color-border-default)"}} />

*The Current block is pulled straight from the trace's LLM span, not retyped from memory*

## Verify the fix

1. Paste the **Replace with** block into `my_agent`'s system message.
2. Re-run the question that produced the original failure. The example below repeats the transformers question:

```python
print(my_agent("What's the seminal paper on transformers?"))
trace_provider.force_flush()
```

3. Open the new trace on the **Tracing** page.
4. Run `/analyze-trace-errors` with the new trace attached.

   Check the reply itself: did the assistant decline to give a citation without a source? Then check whether the new analysis still reports Hallucinated Content. The proposed edit is not proof of a fix.

## Troubleshooting

<div class="sdk-ref-table max-sm:[&_td]:px-1.5! max-sm:[&_th]:px-1.5!">

| Symptom | Cause | Fix |
|---|---|---|
| Falcon AI's context chip doesn't show the trace | Chat was opened before navigating to the trace, or from a project-level view instead of the trace detail page | Open the trace detail page first, then open Falcon AI so it picks up the active page as context |
| `/analyze-trace-errors` returns nothing to analyze | `trace_provider.force_flush()` wasn't called before the script exited, so spans never reached the platform | Call `force_flush()` at the end of the script and confirm the trace appears on the project's Tracing page before asking Falcon AI about it |
| `register()` raises or the tracer never attaches spans | `FI_API_KEY` / `FI_SECRET_KEY` aren't exported in the shell running the script | Export both keys in the same shell, then re-run; check `os.environ` if instrumenting inside a notebook |
| OpenAI calls don't appear as spans under the parent span | `OpenAIInstrumentor().instrument()` was called after the `OpenAI()` client was already created | Call `instrument(tracer_provider=trace_provider)` before instantiating the OpenAI client |
| `/fix-with-falcon` returns a diff for the wrong trace | The context chip still points at a trace from an earlier page, not the one currently open | Check the chip on the chat input, remove it, and re-attach the current trace before running the skill |
| Re-run after applying the fix still hallucinates | The pasted block replaced the wrong message (user message instead of system message) | Confirm the edit landed in the system message content, not the user message, then re-run and inspect the new trace's LLM span |

</div>
