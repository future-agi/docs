## Tutorial

<Steps>
<Step title="Add tracing to your agent">

Run the two Python blocks below in one session. Falcon AI reads your agent's **traces**, so the agent has to be sending traces to Future AGI before any later step can run. `OpenAIInstrumentor` patches the OpenAI SDK so every API call is captured automatically. The `@tracer.agent` decorator on your agent's entry point makes each classification appear as one parent span Falcon AI can filter on.

```python
from fi_instrumentation import register, FITracer
from fi_instrumentation.fi_types import ProjectType
from traceai_openai import OpenAIInstrumentor

trace_provider = register(
    verbose=False,
    project_type=ProjectType.OBSERVE,
    project_name="ridgeline-email-triage-demo",
)
OpenAIInstrumentor().instrument(tracer_provider=trace_provider)
tracer = FITracer(trace_provider.get_tracer("ridgeline-email-triage-demo"))
```

```python
import csv
from uuid import UUID
from openai import OpenAI
from opentelemetry.trace import get_current_span

client = OpenAI()

@tracer.agent(name="triage_email")
def triage_email(email_text):
    reply = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": "Route support email to urgent, billing, technical, general, or spam. Reply with just the label."},
            {"role": "user", "content": email_text},
        ],
    ).choices[0].message.content
    if not reply:
        raise ValueError("Empty classification")
    return str(UUID(int=get_current_span().get_span_context().trace_id)), reply.strip()

# Reviewer's routing labels. Only email_text goes into the classifier.
cases = [
    ("The checkout system is down for every store.", "urgent"),
    ("I see two charges for my sleeping bag. Please refund the duplicate.", "billing"),
    ("The app crashes when I open my saved hiking routes.", "technical"),
    ("What time does your shop open on Sunday?", "general"),
    ("Buy bulk advertising lists now! Limited offer!", "spam"),
    ("My receipt is wrong and my login no longer works.", "NEEDS_REVIEW"),
]
with open("triage-traces.csv", "w", newline="") as f:
    writer = csv.writer(f)
    writer.writerow(["email_text", "predicted_category", "expected_category", "trace_id"])
    for email, expected in cases:
        trace_id, label = triage_email(email)
        writer.writerow([email, label, expected, trace_id])
        print(trace_id, label)
trace_provider.force_flush()
```

You should see six trace IDs and predicted labels. `force_flush()` asks the exporter to send pending spans; storage and indexing can take a little longer. For broader instrumentation patterns see [Manual Tracing](/docs/cookbook/quickstart/manual-tracing).

</Step>
<Step title="Explore failures with Falcon AI">

Falcon AI picks up whatever page you're viewing as context. Open it from your project's Tracing page (the context chip should show the project name), then type:

> What categories did my agent assign across these traces, and which ones look like misclassifications?

<Tip>
`Cmd+K` (Mac) or `Ctrl+K` (Windows) opens Falcon AI from anywhere in the dashboard, with the current page auto-attached as a context chip.
</Tip>

Compare the returned counts and suspected misclassifications with the six IDs in `triage-traces.csv`. These flagged misclassifications are a strong starting point, not ground truth. You'll confirm them in a later step.

</Step>
<Step title="Build the dataset with curation criteria">

`/build-dataset` reads the traces in context and writes matching rows to a new dataset. The skill follows whatever selection criteria you give it, so the prompt below bakes in a coverage rule that mixes easy-pass rows with the misclassifications from the previous turn.

> /build-dataset
>
> Build a new dataset called `email-triage-eval-v1` using only the six trace IDs I provide. Include one row per ID, even if a label repeats. Do not invent emails to fill a category quota. Columns:
> - `email_text` (text): the email body the agent classified
> - `predicted_category` (text): what the agent chose
> - `trace_id` (text): so we can trace any failure back

Choose a fresh name if that dataset already exists and use it throughout the chat. Open the resulting dataset. Compare the six saved IDs, input texts and predictions with your CSV; stop if any are missing or duplicated. With more traffic, sample more than one example per category rather than inventing missing cases.

</Step>
<Step title="Add a ground truth column">

`predicted_category` is what the agent chose. To turn the dataset into an eval, you need `expected_category`, what the agent should have chosen. For genuinely ambiguous rows (hostile tone over a small issue, multi-issue emails) there is no single correct answer, so this step uses a `NEEDS_REVIEW` value plus a `review_note` column to surface them for human judgment instead of poisoning the eval with arbitrary labels.

> Add a column `expected_category` (text) to `email-triage-eval-v1`. For each row, propose the correct category based on the email text. For rows where the correct category is genuinely ambiguous (e.g., hostile tone over a small issue, multi-issue emails), use the value `NEEDS_REVIEW` and add a one-sentence note in a new column `review_note` (text) explaining why.

You should see both columns populated on every row, with a split between confident `expected_category` values and a few rows tagged `NEEDS_REVIEW`. Open the dataset in **Datasets → email-triage-eval-v1**, click each `NEEDS_REVIEW` row, and decide based on your team's routing rules. Edit the rows in the UI or ask Falcon AI to update them.

</Step>
<Step title="Lock in a baseline eval">

`/run-evaluations` runs an eval template from your workspace's catalog against every row in the dataset and returns per-row and aggregate scores. Describe the goal in plain English so Falcon AI picks the right template (here, an exact-match check between two text columns).

> /run-evaluations
>
> Score only the reviewed rows. Use `equals` to compare `predicted_category` (`text`) with `expected_category` (`expected_text`). Leave `NEEDS_REVIEW` out of the denominator. If the run cannot exclude pending rows, make a reviewed-only dataset before running it.

Review each verdict. With the example labels, the denominator is five, not six. Both 0% and 100% are possible. For a later prompt revision, classify the same emails again and compare the new predictions against the frozen human labels.

</Step>
</Steps>

## Save the reviewed example from Python

For these six synthetic emails, the `cases` list already contains the reviewer's labels. If you prefer a scripted snapshot to the chat steps, score the five resolved rows and upload the results with their source trace IDs. Use separate environments for Agent Learning Kit and the `futureagi` platform SDK because both install `fi` modules.

```bash
python3.12 -m venv .judges
.judges/bin/python -m pip install agent-learning-kit==0.3.7
python3.12 -m venv .datasets
.datasets/bin/python -m pip install futureagi==0.7.0
```

Save as `score_triage.py` and run `.judges/bin/python score_triage.py`.

```python
import csv
from fi.evals import Evaluator

evaluator = Evaluator()
with open("triage-traces.csv", newline="") as f:
    rows = list(csv.DictReader(f))
for row in rows:
    row.update(verdict="Pending review", eval_id="")
    if row["expected_category"] == "NEEDS_REVIEW":
        continue
    result = evaluator.evaluate(eval_templates="equals", inputs={
        "text": row["predicted_category"], "expected_text": row["expected_category"],
    }).eval_results[0]
    if result.output not in ("Passed", "Failed"):
        raise RuntimeError(result.reason or "Missing exact-match verdict")
    row.update(verdict=result.output, eval_id=result.eval_id)
scored = [row for row in rows if row["eval_id"]]
print(f"{sum(row['verdict'] == 'Passed' for row in scored)} of {len(scored)} reviewed emails matched")
with open("reviewed-triage.csv", "w", newline="") as f:
    writer = csv.DictWriter(f, fieldnames=rows[0].keys())
    writer.writeheader()
    writer.writerows(rows)
```

Save as `upload_triage.py` and run `.datasets/bin/python upload_triage.py`. This creates a new dataset with the frozen predictions, labels and verdicts. It does not overwrite the one from chat.

```python
from uuid import uuid4
from fi.datasets import Dataset, DatasetConfig
from fi.utils.types import ModelTypes

name = f"reviewed-email-triage-{uuid4().hex[:8]}"
dataset = Dataset(dataset_config=DatasetConfig(name=name, model_type=ModelTypes.GENERATIVE_LLM))
dataset.create(source="reviewed-triage.csv")
print(dataset.dataset_config.id)
```

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Falcon AI's context chip shows no project, or the wrong one | The sidebar was opened from a page outside the traced project | Open Falcon AI from inside the project's Tracing tab, not the global dashboard |
| Falcon AI says it found no traces | Spans haven't reached Future AGI yet | Call `trace_provider.force_flush()` and wait a few seconds before opening the sidebar |
| `/build-dataset` returns fewer than six rows | A trace was not indexed, selected or exported | Locate each ID from the CSV, then ask Falcon to add only the missing rows |
| `expected_category` disagrees with an obviously correct `predicted_category` | The row's email text is genuinely ambiguous, or the selection criteria in the prompt was too vague | Re-run with a more specific rule, or edit the row directly in the dataset UI |
| `/run-evaluations` picks a template that isn't an exact-match check | The workspace has no string-equality template, or the prompt didn't name the columns explicitly | Name `predicted_category` and `expected_category` directly in the prompt, or create a matching template in the Evaluations settings |
| The eval run shows a 0% or 100% pass rate | All reviewed examples may actually agree or disagree | Check the mappings and denominator before adding examples that improve coverage |
| `OpenAIInstrumentor` captures no spans for OpenAI calls | The client was created before `.instrument()` ran | Call `OpenAIInstrumentor().instrument(tracer_provider=trace_provider)` before creating the `OpenAI()` client |
