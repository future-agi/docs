<TLDR>
Add the Future AGI MCP server to your IDE, sign in via OAuth, and ask your AI assistant questions like *"what went wrong with the last failing trace in my support-agent project?"* It pulls span data, retrieves recorded error analysis, and proposes fixes, all in the same chat where you're writing code.
</TLDR>

| Time | Difficulty | Package |
|------|-----------|---------|
| 20-25 min (first success at Step 3, ~10 min in) | Beginner | None (MCP server, no SDK install) |

<Prerequisites>
- Future AGI account → [app.futureagi.com](https://app.futureagi.com)
- A traced project with at least a few traces. If you don't have one, follow [Manual Tracing](/docs/cookbook/quickstart/manual-tracing) to instrument an agent first
- An MCP-capable IDE: Cursor, Claude Code, VS Code with MCP support, Claude Desktop, or Windsurf
- Error Feed turned on for the project, so error clusters and error analysis have something to return: see [Turn on Error Feed](/docs/error-feed/guides/turn-on-error-feed)
</Prerequisites>

## Tutorial

<Steps>
<Step title="Connect the MCP server to your IDE">

The MCP server lives at `https://api.futureagi.com/mcp` and authenticates over OAuth, so there are no API keys to copy around.

<Tabs items={["Claude Code", "Cursor", "VS Code", "Claude Desktop", "Windsurf"]}>

<Tab title="Claude Code">

Merge this entry into `.mcp.json` in your project. Review the project server when Claude Code asks whether to trust it.

```json
{
  "mcpServers": {
    "futureagi": {
      "type": "http",
      "url": "https://api.futureagi.com/mcp"
    }
  }
}
```

</Tab>

<Tab title="Cursor">

Merge into `.cursor/mcp.json` in your project:

```json
{
  "mcpServers": {
    "futureagi": {
      "url": "https://api.futureagi.com/mcp"
    }
  }
}
```

Or use the [one-click install link](/docs/falcon-ai/guides/use-the-mcp-server) on the setup page.

</Tab>

<Tab title="VS Code">

Merge into `.vscode/mcp.json` in your project:

```json
{
  "servers": {
    "futureagi": {
      "type": "http",
      "url": "https://api.futureagi.com/mcp"
    }
  }
}
```

</Tab>

<Tab title="Claude Desktop">

Open **Settings → Connectors**, choose to add a custom connector, and enter `https://api.futureagi.com/mcp` as the remote server URL. This requires custom connectors to be available in your plan or workspace.

</Tab>

<Tab title="Windsurf">

Merge into `~/.codeium/windsurf/mcp_config.json`:

```json
{
  "mcpServers": {
    "futureagi": {
      "serverUrl": "https://api.futureagi.com/mcp"
    }
  }
}
```

</Tab>

</Tabs>

Restart your IDE after editing the config.

Open your client's MCP server list. If `futureagi` needs authentication, select it and start the sign-in flow. In Claude Code, use `/mcp`.

</Step>
<Step title="Authorize via OAuth">

Ask your assistant anything that needs Future AGI data, for example:

> List my Future AGI projects.

If prompted to sign in, open the consent screen. Review the permission groups and click **Authorize**.

You should see: the assistant returns your project list, and the browser tab confirms the connection. Your client may ask you to authorize again when the session expires.

<Tip>
You can revoke access anytime from **Settings → MCP Server** in the dashboard. That nav item is visible to Owners and Admins only.
</Tip>

</Step>
<Step title="Find failing traces from chat">

Open your IDE's chat panel and ask about your traces directly:

> List the most recent traces in my support-agent project that have errors.

Ask the assistant to resolve `support-agent` with `list_projects`, then use its project ID with `search_traces`. Request error filtering using the tool’s `filters` argument, not a top-level `has_error` parameter.

You should see: a list of recent traces flagged as errored, with timestamps and a short description of each. If nothing comes back because the traces don't carry a raw error flag, ask the assistant to try error clusters instead:

> Show me error clusters for my support-agent project.

That routes to `list_error_clusters`, which surfaces AI-detected failure categories across the project, a signal that catches more than HTTP-level errors alone.

</Step>
<Step title="Inspect a trace and diagnose the failure">

Pick a trace from the previous list and ask for detail:

> Show me the span tree for the second trace from that list.

The assistant calls `get_trace` with the trace ID and project ID. It returns the recorded span tree, including captured model and tool calls.

Then ask for a diagnosis:

> Retrieve any existing error analysis for that trace. Separate recorded findings from your interpretation.

`get_trace_error_analysis` retrieves existing findings; it does not start an analysis. If Error Feed has not analyzed this trace, inspect the tool result and final answer directly. A missing finding is not a passing score.

</Step>
<Step title="Check whether the problem recurs">

> Show error clusters for support-agent. For a cluster about unsupported claims, show the associated traces and compare the supporting evidence.

Use `list_error_clusters`, then `list_error_cluster_traces` with a cluster ID. Ask the assistant to identify a specific trace and quote the conflicting span values. A failed refund tool call followed by a promise of a refund is stronger evidence than an unhappy-sounding customer message.

</Step>
<Step title="Patch the code and verify the fix">

The same chat that read the trace can now read your code. Ask:

> Based on the error analysis, draft a system-prompt patch that refuses to answer policy questions when no grounding tool is available. Show it as a diff against agent.py.

Your assistant has both the trace findings from MCP and the file from your editor, so it produces a paste-ready diff. Apply it, re-run a few queries through your agent, then ask:

> Compare the new support-agent traces with the original trace. Did each answer about the policy follow a successful lookup? Cite the tool results and final answers.

Compare like-for-like queries using `search_traces` and `get_trace`. An assistant's assessment in chat is not a saved annotation. If you want a durable score, use a configured [Observe Eval Task](/docs/cookbook/observe-langgraph-agent-and-obtain-insights).

</Step>
</Steps>

<Check>
With the Future AGI MCP server connected to your IDE, you can inspect a trace and its recorded findings from the same editor where you review the patch.
</Check>

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Server shows `Needs authentication` | The OAuth session is missing or expired | Open your client's server list, select `futureagi`, and complete sign-in |
| Assistant says it has no Future AGI tools available | The IDE loaded its MCP config before you added the `futureagi` server | Restart the IDE after editing the config file |
| `search_traces` returns nothing even though the dashboard shows traces | The assistant defaulted to the wrong project or too narrow a time window | Name the project explicitly ("in my support-agent project") and widen the range ("in the last 7 days") |
| Error-filtered search is empty | Not every incorrect answer sets an error flag | Ask for recorded error clusters instead |
| `get_trace` reports a response size limit | The full detail exceeds the MCP transport limit | Inspect individual spans with `list_spans` and `get_span`, or open the trace in Observe |
| OAuth consent screen never opens | The default browser is blocked from launching by the OS or terminal sandbox | Copy the URL the CLI prints and open it manually |

For the full setup reference and one-click install links, see [Use the MCP Server in your IDE](/docs/falcon-ai/guides/use-the-mcp-server).
