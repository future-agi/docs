<TLDR>
**What you'll build:** An IDE chat that can inspect a failing request before it suggests a fix. Add the [Future AGI MCP server](/docs/falcon-ai/guides/use-the-mcp-server) to your editor, sign in via OAuth, and ask your AI assistant questions like *"what went wrong with the last failing trace in my support-bot project?"* It pulls span data, runs error analysis, and proposes fixes, all in the same chat where you're writing code.
</TLDR>

## The problem

When a support bot answers a policy question without consulting a source, the final reply may be all your IDE assistant sees. It needs the failing [trace](/docs/observe/concepts/traces) and its [spans](/docs/observe/concepts/spans) to tell a missing tool call from an unhelpful tool result. A proposed patch isn't evidence that the next request will behave differently.

## What you'll build

An IDE debugging workflow that uses Model Context Protocol (MCP) to look up one failure, inspect the evidence and compare fresh traces after a patch.

<Mermaid chart={`
flowchart LR
    accTitle: Debug one failing request from IDE chat
    accDescr: Find a failing trace, inspect its span tree and analysis, then use that evidence to draft a patch in the editor. Run the agent again and compare the new trace with the original.

You'll:

1. Authorize a single MCP connection from your IDE.
2. Find a failing trace in a named project and inspect its span tree.
3. Tag and score the affected traces on a named metric.
4. Compare the next trace with the original instead of assuming the patch worked.

<Prerequisites title="Before you start">
- A [Future AGI account](https://app.futureagi.com) and a traced project with requests to inspect. Start with [Manual tracing](/docs/cookbook/quickstart/manual-tracing) if you need sample traffic.
- An MCP-capable client: Claude Code, Cursor, VS Code with MCP support, Claude Desktop or Windsurf. The IDE path uses no SDK package.
- [Enable Error Feed](/docs/error-feed/guides/turn-on-error-feed) in the project for error clusters and trace error analysis.
- [Create a groundedness label](/docs/annotations/guides/create-label) on that project if you plan to write scores. Use test traces you intend to annotate.
</Prerequisites>

This beginner walkthrough takes about 20 to 25 minutes, with the first trace lookup about 10 minutes in.

## Connect your editor

1. Add the server using your client's configuration below.

   The five tabs configure the same remote server at `https://api.futureagi.com/mcp`. OAuth handles sign-in; no platform API key goes in the file.

2. Restart the IDE after changing its configuration.

   Claude Code's `claude mcp list` should include `futureagi`; `! Needs authentication` is expected before the first tool call. In the other clients, look for the server in the available tools.

3. Ask the assistant anything that needs Future AGI data, for example “List my Future AGI projects.”

   This first lookup opens the OAuth consent screen in your browser.

4. Review the permission groups for this connection.
5. Click **Authorize** if those permissions match what you intend to do.

   You should see the browser confirm the connection and the project list arrive in chat. The token is cached, so you won't see the consent screen again from this IDE. You can revoke access anytime from **Settings > MCP Server** in the dashboard, a nav item visible to Owners and Admins only.

## Find the failing span

Use the name of your own project in place of `support-bot` in each question.

1. Ask: “List the most recent traces in my support-bot project that have errors.”

   The assistant can use `search_traces` with `has_error=True`. Look for recent errored requests with their timestamps and descriptions.

2. If the error flag returns no rows, ask: “Show me error clusters for my support-bot project.”

   `list_error_clusters` returns [grouped findings](/docs/error-feed/concepts/understanding-error-feed), including failures that don't set a raw error flag.

3. Ask for the span tree of one of the returned traces, for example “Show me the span tree for the second trace from that list.”

   `get_span_tree` returns the parent and nested calls, including timings and inputs. Identify which call failed or which expected tool call is absent.

4. Ask: “Run error analysis on that trace.”

   `get_trace_error_analysis` reads the analysis for that trace. It can include a category such as Unsupported Claim, Language-only, Tool Selection Errors or Goal Deviation; an impact rating (HIGH, MEDIUM or LOW); and a scorecard for factual grounding, privacy and safety, instruction adherence, and optimal plan execution.

5. To check whether this recurs, ask: “Analyze all traces in my project from the last hour and group failures by category.”

   `analyze_project_traces` and `list_error_clusters` can return category counts to put the individual finding in context.

## Record the baseline on test traces

Once you know what's wrong, mark the affected traces so they're easy to find later.

1. Ask: “Add the tag `needs-policy-grounding` to the failing traces, and score them on groundedness.”

   The assistant calls `add_trace_tags` to apply the tag, then `create_score` with the `annotation_label_id` of the groundedness label you created in the prerequisites. Ask it to name the metric explicitly so you can use it again after the change.

2. Inspect the tag and score on the traces in the dashboard.

   They should appear within a few seconds.

`submit_trace_scores` is a different tool: it writes a full 1 to 5 quality scorecard (factual grounding, privacy and safety, instruction adherence, optimal plan execution, each with a reason) on a single trace. It is not a batch form of `create_score`.

## Compare the trace after the patch

1. Ask: “Based on the error analysis, draft a system-prompt patch that refuses to answer policy questions when no grounding tool is available. Show it as a diff against agent.py.”

   The same chat that read the trace can read your code. The assistant has both the trace findings from MCP and the file from your editor, so it produces a paste-ready diff. Review whether the diff addresses the failure you found.

2. Apply the reviewed patch in your test project.
3. Re-run a few queries through your agent, including the same policy question.
4. Ask: “Score the latest traces in my support-bot project on groundedness and tell me if they still show Unsupported Claim findings.”

   The assistant re-runs `search_traces` to pull the new traces, scores them with `create_score` the same way as in the baseline, and reports the new scores next to the ones you recorded earlier. Nothing re-scores traces automatically, and `get_trace_error_analysis` only returns something once Error Feed has sampled and analyzed the new traces, so treat the manual score comparison as your proof. Missing analysis alone is not evidence of a fix.

That's the full loop: detect, diagnose, fix, verify, all from one IDE chat thread, without copying trace IDs or switching to the dashboard.

## Troubleshooting

<div class="sdk-ref-table max-sm:[&_td]:px-1.5! max-sm:[&_th]:px-1.5!">

| Symptom | Cause | Fix |
|---|---|---|
| `claude mcp list` still shows `Needs authentication` after you've been chatting | The OAuth handshake only fires on the first tool call, and a stale session can skip it | Ask a trivial question like "list my Future AGI projects" to force the handshake, then re-check `claude mcp list` |
| Assistant says it has no Future AGI tools available | The IDE loaded its MCP config before you added the `futureagi` server | Restart the IDE after editing the config file |
| `search_traces` returns nothing even though the dashboard shows traces | The assistant defaulted to the wrong project or too narrow a time window | Name the project explicitly ("in my support-bot project") and widen the range ("in the last 7 days") |
| `search_traces` with `has_error` comes back empty on a project with real failures | Not every failure sets a raw error flag on the span | Ask for error clusters instead: "show me error clusters for this project" |
| Tagging or scoring a trace from chat does nothing | `create_score` needs an existing `annotation_label_id`, and the assistant has no label to pass if none exists on the project | Create the annotation label first, then ask again to score with a named metric ("score this trace on groundedness") |
| OAuth consent screen never opens | The default browser is blocked from launching by the OS or terminal sandbox | Copy the URL the CLI prints and open it manually |

</div>
