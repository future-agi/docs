<TLDR>
**What you'll build:** A check that the [Agent Command Center](/docs/command-center) gateway reuses a returns answer when the next customer asks the same question in different words. You enable exact and semantic caching once in the dashboard, and the `x-agentcc-cache: hit_semantic` response header confirms the reuse, with no application-code rewrites.
</TLDR>

## The problem

An exact cache can reuse the answer to “What is your return policy?” when the request is identical. “Can I return a product I bought?” is a different request, so an exact cache alone can send it to the model again. A fast response isn't proof of a hit: check the response headers.

## What you'll build

A Python check that sends identical requests and paraphrases to the same endpoint, then compares cache status, provider cost and latency.

<Mermaid chart={`

    accDescr: The gateway first checks for an exact match. After an exact miss the semantic cache can serve a close match; otherwise the request goes to the provider. The response carries the cache status.

You'll:

1. Record headers for a baseline request.
2. Check an exact repeat against the cache.
3. See which paraphrases clear the similarity threshold.
4. Compare a batch's total cost and refresh a stale answer.

## Send a baseline request

<div class="sdk-ref-table max-sm:[&_td]:px-1.5! max-sm:[&_th]:px-1.5!">

| Variable | What to set | Where to find it |
| --- | --- | --- |
| `AGENTCC_API_KEY` | The Agent Command Center API key starting with `sk-agentcc-`, not a workspace or model provider key | **Settings > API Keys** |

</div>

1. Install the OpenAI SDK.

```bash
pip install openai
```

2. Set `AGENTCC_API_KEY` to your gateway key.

```bash
export AGENTCC_API_KEY="sk-agentcc-your-key"
```

3. Point the OpenAI SDK at the gateway and send the returns question.

   The response headers tell you what the request cost and whether it came from cache.

```python
import os
from openai import OpenAI

API_KEY = os.environ["AGENTCC_API_KEY"]

client = OpenAI(
    api_key=API_KEY,
    base_url="https://gateway.futureagi.com/v1",
)

r = client.chat.completions.with_raw_response.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "What is your return policy?"}],
)
print(f"cache:   {r.headers.get('x-agentcc-cache')}")
print(f"cost:    ${r.headers.get('x-agentcc-cost')}")
print(f"latency: {r.headers.get('x-agentcc-latency-ms')}ms")
```

On a fresh call, look for an empty cache header or `miss`. Keep the printed cost and latency as the baseline: they are what you'd pay every time without caching.

## Check an exact repeat

1. Open **Gateway > Providers > Cache**.
2. Click **Configure Cache**.
3. Turn on **Enable Response Cache**.
4. Set **Default TTL**, the lifetime of an entry, to a value suited to your data (`1h` in this example).
5. Save the configuration.

   Caching is now active for every request through the gateway, with no client change required. The dashboard shows `Enabled: Yes` with `L1 Backend: memory`, and `Semantic Cache: Disabled` confirms only exact matches are served right now. L1 is always exact-match; `memory` means it's stored in-process. Switch to Redis or disk for a multi-instance gateway.

6. Run the identical request twice with the same client.

```python
prompt = [{"role": "user", "content": "What is your return policy?"}]

r1 = client.chat.completions.with_raw_response.create(model="gpt-4o-mini", messages=prompt)
print(f"call 1: {r1.headers.get('x-agentcc-cache')} | ${r1.headers.get('x-agentcc-cost')}")

r2 = client.chat.completions.with_raw_response.create(model="gpt-4o-mini", messages=prompt)
print(f"call 2: {r2.headers.get('x-agentcc-cache')} | ${r2.headers.get('x-agentcc-cost')}")
```

Compare the two header lines. With a fresh cache, call 1 comes back `miss`. Call 2 comes back `hit_exact` with `$0` provider cost: the gateway served the stored answer without calling the provider. Exact caching only helps when requests are identical, and the match covers the whole request, not just the words in the prompt.

<Tip>
Use cache **namespaces** to isolate environments or experiments. Set `x-agentcc-cache-namespace: staging` on a request to keep its cache separate from production. Each namespace is independent. A `prod` hit won't leak into `staging`.
</Tip>

## Check paraphrases against the semantic cache

Real customers don't ask the same question the same way twice. Semantic caching matches prompts by meaning rather than exact text. It runs as an L2 fallback after the L1 exact-match check.

1. Open **Configure Cache** again.
2. Turn on **Enable Semantic Cache**.
3. Set **Similarity Threshold** to `0.92`.

   The scale runs from 0 to 1. Lower values allow looser matches; higher values require more similar questions.

4. Save the configuration.
5. Send the four returns questions through the same client.

```python
prompts = [
    "What is your return policy?",
    "Can I return a product I bought?",
    "How do refunds work at your store?",
    "Tell me about returning items.",
]
for p in prompts:
    r = client.chat.completions.with_raw_response.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": p}],
    )
    print(f"{(r.headers.get('x-agentcc-cache') or 'miss'):14} | ${r.headers.get('x-agentcc-cost')} | {p}")
```

An identical question can still hit the exact cache you just populated. For each *different* question, look for `hit_semantic` in the first column: the L2 cache found a match after L1 missed. A paraphrase that doesn't meet the threshold can still miss. Compare the printed cost rather than assuming semantic lookup is free.

At a low threshold such as `0.7`, unrelated questions can collide. At `0.99`, even useful paraphrases can miss. Start at `0.92` and adjust based on your hit rate and your false-positive rate: check whether the stored answer fits the question before changing the threshold.

## Measure savings on a batch

1. Run the mixed batch of returns and shipping questions.

```python
import time
from collections import Counter

batch = [
    "What is your return policy?",
    "Can I return a product?",
    "How do I get a refund?",
    "What's the shipping cost?",
    "How long does shipping take?",
    "Do you ship internationally?",
] * 5  # 30 calls total

tally = Counter()
total_cost = 0.0
start = time.time()

for p in batch:
    r = client.chat.completions.with_raw_response.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": p}],
    )
    tally[r.headers.get("x-agentcc-cache") or "miss"] += 1
    total_cost += float(r.headers.get("x-agentcc-cost") or 0)

print(f"cache results: {tally}")
print(f"total cost:    ${total_cost:.5f}")
print(f"wall time:     {time.time() - start:.1f}s")
```

2. Compare its total cost with the same batch run with caching disabled.

   The batch contains six distinct questions repeated five times. Expect most calls to land as `hit_exact` or `hit_semantic` after the first pass over each unique question. Read the tally, total cost and wall time from your run; earlier cache entries and similarity matches can change how many provider calls it makes.

   The difference from the uncached total is your savings, and it scales with how repetitive your real traffic is.

## Refresh a stale answer

1. Send a request with `x-agentcc-cache-force-refresh: true` when you change a system prompt or want a fresh response for a specific call.

```python
r = client.chat.completions.with_raw_response.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "What is your return policy?"}],
    extra_headers={"x-agentcc-cache-force-refresh": "true"},
)
print(f"forced refresh: {r.headers.get('x-agentcc-cache')}")
```

   Look for `miss`: the gateway skips the cache read but writes the new response back for subsequent requests.

2. For a global wipe after a prompt-template update, route your traffic to a fresh namespace by setting `x-agentcc-cache-namespace: support-v2` instead of `support`.

   The old cache stays available to anything still pointed at `support`.

## Troubleshooting

<div class="sdk-ref-table max-sm:[&_td]:px-1.5! max-sm:[&_th]:px-1.5!">

| Symptom | Cause | Fix |
|---|---|---|
| `x-agentcc-cache` header is missing on every response | Requests aren't going through the gateway, or `base_url` points somewhere else | Confirm `base_url="https://gateway.futureagi.com/v1"` and that `AGENTCC_API_KEY` is set |
| Call 2 with the identical prompt still shows `miss` | Response Cache isn't enabled, or the TTL already expired | Check **Gateway → Providers → Cache** shows `Enabled: Yes`, and confirm the TTL covers your test window |
| Two calls with the same text return `miss` twice | The request bodies aren't byte-identical: different `temperature`, `max_tokens`, or message order breaks an exact match | Keep every parameter identical across calls, or rely on semantic caching for near-duplicates |
| Paraphrases never come back as `hit_semantic` | L2 Semantic Cache is still toggled off, or the similarity threshold is set too high for the paraphrase | Enable **L2 Semantic Cache** in the Configure Cache dialog and lower the threshold, e.g. from `0.99` to `0.92` |
| Unrelated questions return the same cached answer | Similarity threshold is set too low, so distinct prompts collide | Raise the threshold (e.g. `0.92` to `0.97`) and re-run your batch to confirm hits still land where expected |
| Request fails with a 401 or 403 | `AGENTCC_API_KEY` is unset, expired, or missing the `sk-agentcc-` prefix | Regenerate the key under Settings → API Keys and re-export `AGENTCC_API_KEY` |
| `x-agentcc-cache-force-refresh: true` doesn't return a fresh answer | The header value was sent as a boolean instead of the string `"true"`, or the header name is misspelled | Pass `extra_headers={"x-agentcc-cache-force-refresh": "true"}` exactly, with a string value |

</div>
