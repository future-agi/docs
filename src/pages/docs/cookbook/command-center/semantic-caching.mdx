<TLDR>
Ask a Ridgeline Outfitters FAQ twice, then change its wording. The `x-agentcc-cache` header distinguishes an exact hit, a similarity hit, and a new provider call. Similar wording can qualify for a hit; similar intent alone is not enough.
</TLDR>

## Tutorial

<Steps>
<Step title="Send a baseline request and note the cost">

Run the Python blocks in order in one session. Use a fresh namespace and a public FAQ, not a personalized order lookup. Supply the policy in a system message so the model does not have to invent one. The first request uses `no-store` to get an uncached baseline without warming either cache.

```python
import os
from uuid import uuid4
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["AGENTCC_API_KEY"],
    base_url="https://gateway.futureagi.com/v1",
    default_headers={"x-agentcc-cache-namespace": f"returns-{uuid4().hex}"},
)
policy = (
    "You help Ridgeline Outfitters shoppers. Unused gear can be returned within "
    "30 days. A prepaid label is included. Answer in one sentence; do not invent details."
)
question = "How long do I have to return unused gear to Ridgeline Outfitters?"

def ask(text, headers=None):
    return client.chat.completions.with_raw_response.create(
        model="gpt-4o-mini",
        messages=[{"role": "system", "content": policy}, {"role": "user", "content": text}],
        extra_headers=headers or {},
    )

baseline = ask(question, {"Cache-Control": "no-store"})
print("baseline:", baseline.headers.get("x-agentcc-cache", "not reported"))
print("cost (USD):", baseline.headers.get("x-agentcc-cost", "not reported"))
print("latency (ms):", baseline.headers.get("x-agentcc-latency-ms", "not reported"))
```

With caching active, `no-store` reports `skip`. If your organization has not enabled the cache yet, you may see `skip_org_disabled`; a gateway without the cache plugin may omit the header. A missing cost is not the same as zero cost.

</Step>
<Step title="Turn on exact caching in the dashboard">

In the dashboard, go to **Gateway → Providers → Cache** and click **Configure Cache**. Toggle:

- **Enable Response Cache**: on
- **Default TTL**: `1h` (or whatever fits your data freshness needs)

Save the settings. On a self-hosted gateway, the cache plugin must also be enabled at startup (`cache.enabled`). The in-memory backend keeps entries on one gateway instance, so direct this example to the same instance throughout.

```python
r1 = ask(question)
r2 = ask(question)
print("call 1:", r1.headers.get("x-agentcc-cache", "not reported"))
print("call 2:", r2.headers.get("x-agentcc-cache", "not reported"))
print("same completion:", r1.parse().id == r2.parse().id)
```

Expect `miss`, then `hit_exact` and the same completion ID. The cached response did not need another provider completion.

</Step>
<Step title="Switch to semantic caching for paraphrased prompts">

In **Configure Cache**, turn on **L2 Semantic Cache → Enable Semantic Cache**, set **Similarity Threshold** to `0.92`, and save. On a self-hosted gateway, the L2 store and its threshold come from startup configuration: set `cache.semantic.enabled` to `true` and `cache.semantic.threshold` to `0.92`. Changing the organization settings alone does not create or retune that store.

The gateway checks L1 first. On a miss it compares character sequences in the last user message, with case and punctuation normalized. Keep the system message, model, namespace and request options fixed. Force a fresh answer first so L2 has an entry even if you enabled it after the previous step.

```python
anchor = ask(question, {"x-agentcc-cache-force-refresh": "true"})
near = ask("How long do I have to return unused gear to Ridgeline Outfitters, please?")
other = ask("Is a prepaid shipping label included?")
for label, reply in [("anchor", anchor), ("near match", near), ("shipping label", other)]:
    print(label, reply.headers.get("x-agentcc-cache", "not reported"))
print("near match reused completion:", near.parse().id == anchor.parse().id)
```

At this threshold, look for `hit_semantic` on the near match and `miss` on the shipping-label question. Do not assume every paraphrase qualifies. Check that the reused answer is *right*, not just that the request cost less. Avoid similarity caching for account-specific answers or questions where a small wording change reverses the meaning.

</Step>
<Step title="Measure the savings">

Tally the headers for a mixed batch. Cost is only comparable if the gateway reports it for every request.

```python
from collections import Counter
from decimal import Decimal
from time import perf_counter

batch = [question, "How long do I have to return unused gear to Ridgeline Outfitters, please?",
         "Is a prepaid shipping label included?"] * 5
tally = Counter()
costs = []
start = perf_counter()
for text in batch:
    headers = ask(text).headers
    tally[headers.get("x-agentcc-cache", "not reported")] += 1
    if "x-agentcc-cost" in headers:
        costs.append(Decimal(headers["x-agentcc-cost"]))
print("requests:", sum(tally.values()), "cache results:", dict(tally))
print("total reported cost (USD):", sum(costs) if len(costs) == len(batch) else "incomplete")
print(f"wall time: {perf_counter() - start:.1f}s")
```

The batch has 15 requests. Count `hit_exact` and `hit_semantic` to see how many completions the gateway reused. For a cost comparison, run the same batch with `Cache-Control: no-store` and compare complete cost totals; that second batch incurs provider charges.

</Step>
<Step title="Bypass or invalidate the cache when you need fresh answers">

When you need a fresh completion for the *same* request, bypass the read and refresh its entry:

```python
fresh = ask(question, {"x-agentcc-cache-force-refresh": "true"})
repeat = ask(question)
print("forced refresh:", fresh.headers.get("x-agentcc-cache", "not reported"))
print("after refresh:", repeat.headers.get("x-agentcc-cache", "not reported"))
print("refreshed completion reused:", repeat.parse().id == fresh.parse().id)
```

Expect `miss` on the refresh and `hit_exact` on the next read. For a clean set of entries, start a new namespace. This does not delete existing entries.

</Step>
</Steps>

<Check>
You can now tell whether the gateway called the provider, returned an exact match, or reused a similar FAQ response. Compare completion IDs as well as cache headers when checking a refresh.
</Check>

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `x-agentcc-cache` header is missing on every response | Requests aren't going through the gateway, or `base_url` points somewhere else | Confirm `base_url="https://gateway.futureagi.com/v1"` and that `AGENTCC_API_KEY` is set |
| Call 2 with the identical prompt still shows `miss` | Response Cache isn't enabled, or the TTL already expired, or the requests reached different in-memory gateways | Check **Gateway → Providers → Cache** shows `Enabled: Yes`, and confirm the TTL covers your test window |
| Two calls with the same text return `miss` twice | The request bodies aren't byte-identical: different `temperature`, `max_tokens`, or message order breaks an exact match | Keep every parameter identical across calls, or rely on semantic caching for near-duplicates |
| Paraphrases never come back as `hit_semantic` | L2 Semantic Cache is still toggled off, or the similarity threshold is set too high for the paraphrase | Enable **L2 Semantic Cache** in the Configure Cache dialog and lower the threshold, e.g. from `0.99` to `0.92` |
| Unrelated questions return the same cached answer | Similarity threshold is set too low, so distinct prompts collide | Raise the threshold (e.g. `0.92` to `0.97`) and re-run your batch to confirm hits still land where expected |
| Request fails with a 401 or 403 | `AGENTCC_API_KEY` is unset, expired, or missing the `sk-agentcc-` prefix | Regenerate the key under Settings → API Keys and re-export `AGENTCC_API_KEY` |
| `x-agentcc-cache-force-refresh: true` doesn't return a fresh answer | The header value was sent as a boolean instead of the string `"true"`, or the header name is misspelled | Pass `extra_headers={"x-agentcc-cache-force-refresh": "true"}` exactly, with a string value |
