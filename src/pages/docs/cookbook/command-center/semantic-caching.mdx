<TLDR>
The semantic cache runs on a self-hosted Agent Command Center gateway and is turned on in its config file. It compares the spelling of the last user message, not its meaning, so it serves near-identical prompts rather than paraphrases.
</TLDR>

<Note>
The response cache, semantic cache included, is off on Future AGI's hosted gateway (`gateway.futureagi.com`). Nothing on this page applies to requests sent there.
</Note>

## What it matches

The gateway does not call an embedding model. It turns the last user message into a vector of character 3-gram and 4-gram counts. With the in-memory and Qdrant backends, and with Pinecone on an index that uses the cosine metric, it serves a stored response when the cosine similarity is at or above the threshold (`0.85` by default) for the same model and organization. [How semantic matching works](/docs/command-center/features/caching#how-semantic-matching-works) has the details.

Scores from the gateway's own vectorizer, at the default 256 dimensions:

| Stored prompt | New prompt | Similarity | At the default threshold |
|---|---|---|---|
| What is your return policy? | what is your return policy | 1.000 | Served from cache |
| What is your return policy? | What's your return policy? | 0.883 | Served from cache |
| What is the capital of France? | What is the capital of Spain? | 0.826 | Not served |
| What is your return policy? | Can I return a product I bought? | 0.341 | Not served |

The third row is why the threshold matters: two different questions can score close to it.

## Turn it on

A response is cached only when both of these are on:

1. **The gateway's cache**, in its config file:

   ```yaml
   cache:
     enabled: true
     default_ttl: 1h
     semantic:
       enabled: true
       threshold: 0.85
       backend: memory    # or qdrant, pinecone
   ```

2. **Your organization's cache**: **Enabled** under **Gateway > Providers > Cache > Configure Cache** in the dashboard (on a self-hosted install), or `cache.enabled` in the org config. An organization's config cannot turn on the semantic cache or change its threshold; those come from the gateway's config file.

Send requests with an API key that belongs to that organization. A key with no organization is never served from the cache.

## Read the cache status

```python
from openai import OpenAI

client = OpenAI(
    api_key="sk-agentcc-your-key",
    base_url="http://localhost:8080/v1",  # your self-hosted gateway
)

r = client.chat.completions.with_raw_response.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "What is your return policy?"}],
)
print(r.headers.get("x-agentcc-cache"))
```

The `x-agentcc-cache` header is `miss` when nothing matched, `hit_exact` for an identical request, and `hit_semantic` when the last user message scored at or above the threshold against a stored one. Streamed requests are not cached.

## Refresh or separate entries

- `x-agentcc-cache-force-refresh: true` skips the cache read for one request and stores the new response.
- `x-agentcc-cache-namespace: <name>` keeps exact-match entries apart, for example per environment. Semantic matching is per organization and model.
