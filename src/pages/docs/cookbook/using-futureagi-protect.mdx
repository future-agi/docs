<TLDR>
Return the message from [Protect](/docs/protect) so a blocked model reply does not reach the caller.
</TLDR>

## The problem

A support model can answer a refund request with an insult. Even if a rule catches the reply, the customer still sees it if your application returns the raw model output.

## What you'll build

A response check that sends the caller either the original reply or your fallback message.

<Mermaid chart={`
flowchart TD
    accTitle: Return the Protect fallback instead of a blocked reply
    accDescr: Protect checks a reply from the model. On a pass the caller receives the reply. On a failure the caller receives the fallback instead.
    A["Model reply"] --> B["Protect rules"]
    B -->|Pass| C["Original reply"]
    B -->|Fail| D["Fallback message"]
    C --> E["Caller"]
    D --> E
`} />

You'll:

1. Define rules for [toxicity](/docs/evaluation/builtin/toxicity) and [prompt injection](/docs/evaluation/builtin/prompt-injection).
2. Compare a polite refund reply with an insulting one.
3. Read the failed rule and send the returned message to the caller.

<Prerequisites title="Before you start">
- A Future AGI account: [app.futureagi.com](https://app.futureagi.com)
- A [workspace API key and secret key](/docs/admin-settings/api-keys) (`FI_API_KEY` and `FI_SECRET_KEY`)
- An `ANTHROPIC_API_KEY` (only needed for the Anthropic step)
- Python 3.11+
</Prerequisites>

## Set up the Python example

Install the SDK and the Anthropic client:

```bash
pip install ai-evaluation anthropic
```

Then export the three keys the examples read:

<div class="sdk-ref-table max-sm:[&_td]:px-1.5! max-sm:[&_th]:px-1.5!">

| Variable | What to set | Where to find it |
| --- | --- | --- |
| `FI_API_KEY` | Workspace API key | **Build > Keys** |
| `FI_SECRET_KEY` | Matching secret key | **Build > Keys**, when you create the pair |
| `ANTHROPIC_API_KEY` | Model provider key for the homework example | Your Anthropic account |

</div>

```bash
export FI_API_KEY="your-api-key"
export FI_SECRET_KEY="your-secret-key"
export ANTHROPIC_API_KEY="your-anthropic-key"
```

## Check the reply before you return it

<Steps>
<Step title="Initialize the Protect client">

Create a client authenticated with your Future AGI keys.

```python
import os
from fi.evals import Protect

protector = Protect(
    fi_api_key=os.environ["FI_API_KEY"],
    fi_secret_key=os.environ["FI_SECRET_KEY"],
)
```

You should see no output. `Protect` only raises if the keys are missing, which is covered in the troubleshooting table below.

</Step>
<Step title="Define the ruleset">

Protect rules key off the SDK's `metric_map`, not arbitrary metric names. Its keys include `toxicity`, `bias_detection`, `prompt_injection` and `data_privacy_compliance`. This ruleset blocks toxic content and prompt injection attempts.

```python
rules = [
    {"metric": "toxicity"},
    {"metric": "prompt_injection"},
]

fallback_message = "This message cannot be displayed"
```

Only the SDK's tone-matching branch accepts `contains` and `type` keys. Add either to a `content_moderation` or `security` rule and `protect()` raises `SDKException` before it runs a single check.

</Step>
<Step title="Apply Protect to a text">

Run the ruleset against a single piece of text to see the pass path.

```python
response = protector.protect(
    "Sure, I can process a refund for order #48213 - it'll land back on your card in 5-7 business days.",
    protect_rules=rules,
    action=fallback_message,
    reason=True,
    timeout=25000,  # milliseconds, not seconds
)
print(response)
```

<details>
<summary>Illustrative pass response</summary>

```
{'status': 'passed', 'messages': "Sure, I can process a refund for order #48213 - it'll land back on your card in 5-7 business days.", 'reasons': ['All checks passed'], 'completed_rules': ['toxicity', 'prompt_injection'], 'uncompleted_rules': [], 'failed_rule': None, 'time_taken': 0.42}
```

</details>

A clean support reply passes every rule, so `messages` comes back unchanged and `status` reads `passed`.

</Step>
<Step title="Trip a rule and see the fallback">

Run the same ruleset against a reply written to fail, so you can see the fallback replace it.

```python
unsafe_response = "You're an idiot for even asking that. Figure it out yourself."

blocked = protector.protect(
    unsafe_response,
    protect_rules=rules,
    action=fallback_message,
    reason=True,
    timeout=25000,
)
print(blocked)
```

<details>
<summary>Illustrative fallback response</summary>

```
{'status': 'failed', 'messages': 'This message cannot be displayed', 'reasons': ['toxicity check failed'], 'completed_rules': ['toxicity'], 'uncompleted_rules': ['prompt_injection'], 'failed_rule': 'toxicity', 'time_taken': 0.31}
```

</details>

`status` reads `failed`, and `messages` is no longer the original text: it's `fallback_message`. Return `messages` to the caller, not `unsafe_response`.

</Step>
<Step title="Guard an Anthropic response">

Run the same ruleset against a real model response before it reaches someone.

```python
from anthropic import Anthropic
from fi.evals import Protect

anthropic_client = Anthropic()
protector = Protect()  # reads FI_API_KEY / FI_SECRET_KEY from the environment

response = anthropic_client.messages.create(
    max_tokens=1000,
    model="claude-3-5-sonnet-20240620",
    messages=[
        {"role": "user", "content": "Hi, I am a student, can you help me with my homework?"}
    ],
)
response_text = response.content[0].text

protect_response = protector.protect(
    response_text,
    protect_rules=rules,
    action=fallback_message,
    reason=True,
    timeout=25000,
)

print(protect_response["messages"])
```

You should see the model's homework-help answer printed unchanged: a helpful, on-topic reply doesn't trip `toxicity` or `prompt_injection`. Swap the user message for something that provokes an unsafe response and `protect_response["messages"]` becomes `fallback_message` instead.

</Step>
<Step title="Use the standalone protect() function">

Skip the `Protect` class entirely when you don't need a reusable client.

```python
from fi.evals import protect

protected_response = protect(
    "Your subscription renews on the 14th - you can cancel anytime from account settings.",
    protect_rules=[{"metric": "toxicity"}],
    action=fallback_message,
    reason=True,
    timeout=25000,
)
print(protected_response["messages"])
```

You should see the subscription text printed unchanged. `protect()` takes the same `protect_rules`, `action`, `reason` and `timeout` arguments as `Protect.protect()`, without instantiating a client first.

</Step>
<Step title="Read the reasons">

Log `reasons` alongside `status` so a blocked response is auditable after the fact, not just silently swapped.

```python
print(blocked["reasons"])
print(blocked["completed_rules"])
print(blocked["failed_rule"])
```

<details>
<summary>Illustrative failure details</summary>

```
['toxicity check failed']
['toxicity']
'toxicity'
```

</details>

`reasons` is a short summary, not one entry per rule. On a pass it's just `['All checks passed']`. For which rules ran and which one tripped, use `completed_rules` and `failed_rule`.

</Step>
</Steps>

## Troubleshooting

<div class="sdk-ref-table max-sm:[&_td]:px-1.5! max-sm:[&_th]:px-1.5!">

| Symptom | Cause | Fix |
|---|---|---|
| `InvalidValueType` on `protector.protect(...)` | A rule uses a metric name outside the valid set (`"Tone"`, `"Toxicity"`, or any typo) | Use one of `toxicity`, `bias_detection`, `prompt_injection`, `data_privacy_compliance`, or check the [SDK guide](/docs/protect/guides/run-protect-from-the-sdk) for the other accepted values |
| `SDKException` mentioning `contains` or `type` | A `toxicity` or `prompt_injection` rule carries a `contains` or `type` key | Drop those keys. Only tone-matching rules accept them, and `"Tone"` itself isn't a valid metric here |
| Call times out almost immediately | `timeout` is in milliseconds; a value like `25` aborts after 25ms | Pass a realistic value, e.g. `timeout=25000` for roughly 25 seconds |
| `InvalidAuthError` on `Protect(...)` or `protect(...)` | `FI_API_KEY` or `FI_SECRET_KEY` missing or unexported | Re-run the `export` block in the current shell, then re-run the script |
| `ModuleNotFoundError: No module named 'fi.evals'` | The SDK isn't installed, or an unrelated `fi` package shadows it | Run `pip install ai-evaluation`, and check `pip show fi` doesn't point at a different package |
| `anthropic.AuthenticationError` on `anthropic_client.messages.create(...)` | `ANTHROPIC_API_KEY` not exported | Export `ANTHROPIC_API_KEY`, or swap in a client for a provider key you have |
| `protect_response["messages"]` never changes even for an unsafe response | The ruleset only covers metrics the response doesn't trip | Add the relevant metric (e.g. `bias_detection` for biased output) or test with input written to trip the rule you're checking |

</div>
