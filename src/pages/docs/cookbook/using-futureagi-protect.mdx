<TLDR>
Define a Protect ruleset, run it against a text response, and see Protect swap a rule-violating output for a safe fallback message before it ever reaches someone.
</TLDR>

| Time | Difficulty | Package |
|------|-----------|---------|
| 15 min | Intermediate | `agent-learning-kit` |

<Prerequisites>
- Future AGI account → [app.futureagi.com](https://app.futureagi.com)
- API keys: `FI_API_KEY` and `FI_SECRET_KEY` (see [Get your API keys](/docs/admin-settings))
- Access to the Protect model in your Future AGI deployment. An evaluation judge alone is not sufficient.
- An `OPENAI_API_KEY` (only needed for the OpenAI step)
- Python 3.11+
</Prerequisites>

## Tutorial

Run the Python blocks in order in the same session.

<Steps>
<Step title="Initialize the Protect client">

Create a client authenticated with your Future AGI keys.

```python
import os
from fi.evals import Protect

protector = Protect(
    fi_api_key=os.environ["FI_API_KEY"],
    fi_secret_key=os.environ["FI_SECRET_KEY"],
)
```

Creating the client does not run a check or confirm model access. The first call to `protect()` does that.

</Step>
<Step title="Define the ruleset">

Protect rules key off the SDK's `metric_map`, not arbitrary metric names. The four canonical keys are `toxicity`, `bias_detection`, `prompt_injection`, and `data_privacy_compliance`. This ruleset blocks toxic content and prompt injection attempts.

```python
rules = [
    {"metric": "toxicity"},
    {"metric": "prompt_injection"},
]

fallback_message = "This message cannot be displayed"
```

Use `metric` to select a check. Don't add `contains` or `type`: neither is accepted for these metrics.

</Step>
<Step title="Apply Protect to a text">

Run the ruleset against a single piece of text to see the pass path.

```python
clean_reply = "Ridgeline refunds unworn boots within 30 days of purchase."
response = protector.protect(
    clean_reply,
    protect_rules=rules,
    action=fallback_message,
    reason=True,
    timeout=25000,  # milliseconds
)
print(response["status"], sorted(response["completed_rules"]))
print(response["messages"])
```

When both checks finish and pass, the message stays unchanged:

```text
passed ['prompt_injection', 'toxicity']
Ridgeline refunds unworn boots within 30 days of purchase.
```

Don't use `status` on its own to decide what to display. Check that all required rules completed before releasing a reply.

</Step>
<Step title="Trip a rule and see the fallback">

Check how the same rules handle an insulting reply.

```python
unsafe_response = "You're an idiot for even asking that. Figure it out yourself."

blocked = protector.protect(
    unsafe_response,
    protect_rules=rules,
    action=fallback_message,
    reason=True,
    timeout=25000,
)
print(blocked["status"])
print(blocked["messages"])
```

A toxicity failure returns your fallback rather than the insulting text:

```text
failed
This message cannot be displayed
```

</Step>
<Step title="Guard an OpenAI response">

Generate a Ridgeline support reply, but don't send or stream it to the customer yet. Release it only when every required check has finished and passed.

```python
from openai import OpenAI


def display_message(result, required_rules):
    required = {rule["metric"] for rule in required_rules}
    if (result["status"] == "passed" and not result["uncompleted_rules"]
            and set(result["completed_rules"]) == required):
        return result["messages"]
    return fallback_message


completion = OpenAI().chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Tell a Ridgeline customer in one sentence that tent repairs take five business days."}],
)
reply = completion.choices[0].message.content
if reply and reply.strip():
    result = protector.protect(reply, protect_rules=rules, action=fallback_message, timeout=25000)
    print(display_message(result, rules))
else:
    print(fallback_message)
```

If both checks pass, you see the model's reply. A failed or incomplete check displays the fallback instead. If the provider or Protect raises, the code stops without printing the unreviewed reply.

</Step>
<Step title="Use the standalone protect() function">

Skip the `Protect` class entirely when you don't need a reusable client.

```python
from fi.evals import protect

single_rule = [{"metric": "toxicity"}]
protected_response = protect(
    "Ridgeline can mail you a repair label for your tent.",
    protect_rules=single_rule,
    action=fallback_message,
    reason=True,
    timeout=25000,
)
print(display_message(protected_response, single_rule))
```

When the check passes, you see the repair-label message unchanged. `protect()` takes the same `protect_rules`, `action`, `reason`, and `timeout` arguments as `Protect.protect()`, just without instantiating a client first.

</Step>
<Step title="Read the reasons">

Inspect the diagnostic fields for this synthetic example.

```python
print(blocked["reasons"])
print(blocked["completed_rules"])
print(blocked["failed_rule"])
```

`failed_rule` is a list of triggered metrics (for this reply, look for `toxicity`). Checks can run in parallel, so the order of `completed_rules` can vary. `reasons` can contain the judge's wording, including excerpts of the input. Don't log raw reasons or customer text unless your retention policy permits it.

</Step>
</Steps>

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Both a clean reply and the insult return `failed` with a message that the request could not be processed | The check did not produce a content verdict. A missing Protect model in the deployment can cause this | Keep the fallback in place. Verify model access and credits before treating either reply as a policy violation |
| `InvalidValueType` on `protector.protect(...)` | A rule uses a metric name outside the valid set (`"Tone"`, `"Toxicity"`, or any typo) | Use one of `toxicity`, `bias_detection`, `prompt_injection`, `data_privacy_compliance` |
| `SDKException` mentioning `contains` or `type` | A `toxicity` or `prompt_injection` rule carries a `contains` or `type` key | Drop those keys. These metrics match the `Failed` verdict automatically |
| Call times out almost immediately | `timeout` is in milliseconds; a value like `25` aborts after 25ms | Pass a realistic value, e.g. `timeout=25000` for roughly 25 seconds |
| `InvalidAuthError` on `Protect(...)` or `protect(...)` | `FI_API_KEY` or `FI_SECRET_KEY` missing or unexported | Re-run the `export` block in the current shell, then re-run the script |
| `ModuleNotFoundError: No module named 'fi.evals'` | `agent-learning-kit==0.3.7` isn't installed, or an unrelated `fi` package shadows it | `pip install agent-learning-kit==0.3.7`, and check `pip show fi` doesn't point at a different package |
| `openai.AuthenticationError` in the model step | Your OpenAI key is invalid | Check `OPENAI_API_KEY` in the same shell before starting Python |
| `protect_response["messages"]` never changes even for an unsafe response | The ruleset only covers metrics the response doesn't trip | Add the relevant metric (e.g. `bias_detection` for biased output) or test with input written to trip the rule you're checking |
