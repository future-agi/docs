## About

Should Ridgeline Outfitters rewrite its routing instruction or show the model a labeled ticket? Try both, plus a rewrite guided by evaluation feedback. Compare the three returned prompts on tickets that none of the optimizers saw.

| Time | Difficulty | Package |
|---|---|---|
| 20 min | Intermediate | `agent-learning-kit==0.3.7` |

## Set up Python

Use a fresh Python 3.12 environment. Replace the OpenAI key placeholder with your own key in Bash. The model calls use that key; the exact-match metric runs locally without Future AGI credentials.

## Run the same task three ways

| Optimizer | What changes in this run | Search setting |
|---|---|---|
| Random Search | A teacher proposes new wording for the instruction. | Ask for two variations. |
| Bayesian Search | The instruction stays fixed. Optuna selects a labeled ticket to prepend as an example. | Try two selections with one example each. |
| GEPA | A reflection model uses examples, generated answers, and metric feedback to propose a revised instruction. | Give the search a budget of eight metric calls. |

Use the same seed, model, training rows, and case-sensitive exact-match metric for every search. Score each returned generator on the same two held-out tickets; do not put their labels in the prompt. Save as `compare.py` and run `python compare.py`.

<CodeGroup titles={["Python"]}>

```python
from fi.evals.metrics import Equals
from fi.opt.base import Evaluator
from fi.opt.datamappers import BasicDataMapper
from fi.opt.generators import LiteLLMGenerator
from fi.opt.optimizers import (
    BayesianSearchOptimizer, GEPAOptimizer, RandomSearchOptimizer,
)

MODEL = "gpt-4o-mini"
seed = "Ticket: {ticket}\nQueue (RETURNS or REPAIRS):"
train = [
    {"ticket": "My new boots don't fit. Can I send them back?", "queue": "RETURNS"},
    {"ticket": "Can you fix a broken buckle on my pack?", "queue": "REPAIRS"},
]
mapper = BasicDataMapper({
    "response": "generated_output",
    "expected_response": "queue",
})
evaluator = Evaluator(metric=Equals(config={"case_sensitive": True}))
holdout = [
    {"ticket": "I ordered the wrong tent. Can I get a refund?", "queue": "RETURNS"},
    {"ticket": "Can you replace my sleeping bag zipper?", "queue": "REPAIRS"},
]


def accuracy(generator, rows):
    inputs = []
    for row in rows:
        reply = generator.generate({"ticket": row["ticket"]})
        if not reply:
            raise RuntimeError("No reply from the generator")
        inputs.append(mapper.map(reply, row))
    scores = evaluator.evaluate(inputs)
    return sum(item.score for item in scores) / len(rows)


shared = dict(evaluator=evaluator, data_mapper=mapper, dataset=train)
random_search = RandomSearchOptimizer(
    LiteLLMGenerator(MODEL, seed), MODEL, num_variations=2
)
few_shot = BayesianSearchOptimizer(
    inference_model_name=MODEL, min_examples=1, max_examples=1, n_trials=2,
    example_template="Ticket: {ticket}\nQueue: {queue}", few_shot_position="prepend",
)
reflection = GEPAOptimizer(reflection_model=MODEL, generator_model=MODEL)
results = {
    "Random Search": random_search.optimize(**shared),
    "Bayesian Search": few_shot.optimize(**shared, initial_prompts=[seed]),
    "GEPA": reflection.optimize(**shared, initial_prompts=[seed], max_metric_calls=8),
}
print(f"Baseline holdout: {accuracy(LiteLLMGenerator(MODEL, seed), holdout):.0%}")
for name, result in results.items():
    held_out = accuracy(result.best_generator, holdout)
    print(f"{name}: search={result.final_score:.0%}, holdout={held_out:.0%}")
```

</CodeGroup>

## Read the result

Compare each `holdout` score to `Baseline holdout`. The `search` score is what the optimizer reported while selecting a prompt. One run printed:

```text
Baseline holdout: 100%
Random Search: search=0%, holdout=0%
Bayesian Search: search=50%, holdout=100%
GEPA: search=50%, holdout=50%
```

Bayesian Search matched the original on these two unseen tickets; neither rewrite did. This run gives no reason to replace the original.

## Limits and troubleshooting

- The few-shot search draws examples from its search dataset. A correct reply to a ticket already in the prompt does not establish that a different ticket will be routed correctly.
- Two trials, two variations, and eight metric calls are not equal budgets for model calls or cost. Use the score to compare the outputs, not to infer which method is cheaper.
- If all prompts tie, inspect their raw replies and test on more distinct tickets. Exact match gives no partial credit for a correct label inside a longer reply.
