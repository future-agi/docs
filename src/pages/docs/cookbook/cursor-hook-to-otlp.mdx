<TLDR>
Cursor's command hooks receive structured JSON on stdin. This recipe maps `stop`, `preToolUse`, `postToolUse`, and `postToolUseFailure` events to completed OTLP spans, groups them with `session.id`, and keeps prompt/tool/response bodies off by default.
</TLDR>

<Warning>
This is an application-session recipe, not Cursor SDK tracing and not provider-call instrumentation. It uses Cursor's documented command-hook interface and exports through the Future AGI OTLP/HTTP contract.
</Warning>

## What this covers

The example captures:

- one completed session summary from `stop`;
- tool names, outcome, session identity, model metadata, and timing;
- successful and failed tool events;
- a stable session grouping key without forwarding the complete hook payload.

The repository example is [cursor-hook-to-otlp](https://github.com/future-agi/docs/tree/main/examples/cursor-hook-to-otlp). Run its loopback contract test before installing it in a project:

```bash
cd examples/cursor-hook-to-otlp
./run_contract.sh
```

The test uses fixture payloads and a local receiver. It does not call Cursor, Future AGI, or any vendor service.

## Prerequisites

- Cursor with command hooks enabled.
- A Future AGI project that accepts OTLP/HTTP traces.
- A runtime environment for the hook command (`python3` in this example).
- `FI_API_KEY`, `FI_SECRET_KEY`, and `FI_PROJECT_NAME` available to the Cursor process.

## Configure the project hook

Create `.cursor/hooks.json` in the project root:

```json
{
  "version": 1,
  "hooks": {
    "preToolUse": [
      { "command": "python3 .cursor/hooks/emit.py preToolUse" }
    ],
    "postToolUse": [
      { "command": "python3 .cursor/hooks/emit.py postToolUse" }
    ],
    "postToolUseFailure": [
      { "command": "python3 .cursor/hooks/emit.py postToolUseFailure" }
    ],
    "stop": [
      { "command": "python3 .cursor/hooks/emit.py stop" }
    ]
  }
}
```

Copy `emit.py` from the example into `.cursor/hooks/emit.py` and make it executable if you invoke it directly:

```bash
chmod +x .cursor/hooks/emit.py
```

Project hooks run from the project root. User-level hooks under `~/.cursor/hooks.json` run from `~/.cursor/`; adjust the script path if you install the hook globally.

## Configure the collector

```bash
export FI_OTLP_ENDPOINT=https://api.futureagi.com/tracer/v1/traces
export FI_API_KEY='[REDACTED]'
export FI_SECRET_KEY='[REDACTED]'
export FI_PROJECT_NAME='my-cursor-project'
```

The exporter explicitly sends:

- `X-Api-Key` and `X-Secret-Key` headers;
- `project_name` and `project_type=observe` resource attributes;
- OTLP/HTTP JSON to `/tracer/v1/traces`.

Do not put credentials in `hooks.json`, span attributes, or command output. If the collector endpoint is changed, keep the path explicit; do not append `/v1/traces` twice.

## Privacy defaults

Content is off by default. The default spans contain metadata and hashes/lengths for tool input, but not the input itself. The exporter also omits prompt, response, tool-result, and exception bodies and emits a generic error status message.

To opt into bounded content for a controlled test only:

```bash
export CURSOR_CAPTURE_CONTENT=true
```

Opt-in content is capped at 4 KiB and common API-key/Bearer-token patterns are replaced with `[REDACTED]`. This is not a substitute for a secret-management or DLP control.

## Verify a real Cursor session

1. Start Cursor with the four collector variables set.
2. Open a trusted project containing the hook configuration.
3. Ask Cursor to make a small file edit and run one harmless local command.
4. Ask it to stop or finish the turn.
5. In Future AGI, open the project and find the latest trace by `session.id` and `service.name=cursor-ide`.
6. Confirm there is a session summary and tool metadata, while prompt/tool/result bodies are absent.
7. Repeat once with `CURSOR_CAPTURE_CONTENT` unset after restarting Cursor; the privacy-off run is the acceptance run.

The acceptance evidence should record the Cursor version, hook event names, collector endpoint path, project name, trace count, session ID, tool names, and the absence of payload bodies. Never include API-key values or full prompts in the evidence.

## Unsupported paths and limits

- Cursor's Enterprise metrics/logs export is not the session/tool span tree required here and is out of scope.
- Tab completion hooks are not included; this recipe covers Agent command hooks only.
- Prompt-based hooks are not supported because they do not provide a deterministic command-side payload contract.
- Cursor SDK, extension APIs, and provider calls made outside Cursor hook events are not covered.
- The recipe cannot observe events that Cursor does not emit. Unknown future fields are ignored rather than forwarded wholesale.
- A local hook process failure is reported as a hook-export failure; it must not block the user's Cursor action.
