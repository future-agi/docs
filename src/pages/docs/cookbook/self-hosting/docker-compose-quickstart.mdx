<TLDR>
Start the v1.59.1 Standalone stack on your machine, sign in, and send an instrumented support reply to the local trace collector. The app, Postgres, and ClickHouse run locally. Only the example's chat request goes to OpenAI.
</TLDR>

| Time | Difficulty | Packages |
|------|------------|----------|
| 15 min, plus the first boot | Beginner | `fi-instrumentation-otel` and `traceai-openai` |

<Prerequisites>
- Docker Engine 24.0+ with Docker Compose v2.24+, a working local Docker context, and Git
- At least 2 vCPUs, 4 GB of memory available to Docker, and 10 GB of free disk
- Bash on Linux, macOS, or WSL 2; Python 3.12 on the same host as Docker
- An OpenAI API key for the example, not for running the stack
</Prerequisites>

## Tutorial

Run the commands from a new directory. Stay in that directory throughout; the checkout will be in `future-agi/`. This is a fresh installation, not a procedure for upgrading an existing project.

<Steps>
<Step title="Clone the release">

```bash
git clone --depth 1 --branch v1.59.1 https://github.com/future-agi/future-agi.git future-agi
```

Pin the container image to the same release. The Compose project name keeps this quickstart's containers and volumes separate from the default `futureagi` project. Choose a different unused name if you already have a `ridgeline-quickstart` installation. Run this only in the fresh checkout, before the installer generates secrets.

```bash
(umask 077; set -C; printf '%s\n' 'FUTURE_AGI_VERSION=v1.59.1' 'COMPOSE_PROJECT_NAME=ridgeline-quickstart' > future-agi/.env)
```

If the usual ports are occupied by another install, add six **unused** host ports before starting. Skip this block to use the defaults.

```bash
cat >> future-agi/.env <<'PORTS'
FRONTEND_PORT=13000
BACKEND_PORT=18000
VITE_HOST_API=http://localhost:18000
FI_COLLECTOR_OTLP_PORT=14317
FI_COLLECTOR_OTLP_HTTP_PORT=14318
AGENTCC_GATEWAY_PORT=18090
MINIO_API_PORT=19005
PORTS
```

</Step>
<Step title="Start the installer">

Run the installer before exporting any SDK or provider credentials. The clean environment below keeps unrelated keys from your shell out of the containers. It uses Docker's local default connection; keep your usual Docker settings if your context requires additional variables.

```bash
env -i HOME="$HOME" PATH="$PATH" future-agi/bin/install --skip-user-creation --no-telemetry
```

This pulls the images, generates secrets in `future-agi/.env`, starts the stack, and waits for the API and UI. With `--skip-user-creation` you sign up in the UI after startup. `--no-telemetry` disables usage reports; creating the first account still sends a minimal registration without email addresses. See [deployment telemetry](/docs/self-hosting/configuration/telemetry) for details.

```bash
docker compose --project-directory future-agi ps --services --status running
```

Look for `app`, `postgres`, and `clickhouse`. Use the endpoints printed by the installer, especially if it changed a busy port:

| Service | Default | With the alternate ports above |
|---|---|---|
| UI | http://localhost:3000 | http://localhost:13000 |
| API | http://localhost:8000 | http://localhost:18000 |
| Trace collector (OTLP/HTTP) | http://localhost:4318 | http://localhost:14318 |
| LLM gateway | http://localhost:8090 | http://localhost:18090 |

</Step>
<Step title="Open the dashboard and get your keys">

Open the UI, complete the setup check, and sign up. In **Keys** (`/dashboard/keys`), copy the API key and secret key for this installation. Cloud keys and keys from a different installation are not interchangeable.

Install the Python client in a separate virtual environment on the host:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install fi-instrumentation-otel==1.5.1 traceai-openai==0.1.16 openai
```

Set these values in your client shell. Replace the placeholders with your own keys. If you used alternate ports, replace both URLs with the matching endpoints from the table. Avoid saving real keys in shell history or committing them to source control.

```bash
export FI_API_KEY="your-fi-api-key"
export FI_SECRET_KEY="your-fi-secret-key"
export FI_BASE_URL="http://localhost:8000"
export FI_TRACES_URL="http://localhost:4318"
export OPENAI_API_KEY="your-openai-key"
```

This example calls OpenAI from the client. You do not need to put a provider key in the server's `.env`. For features that call a provider from the app, see [Environment variables](/docs/self-hosting/configuration/environment).

</Step>
<Step title="Send your first trace">

Save this as `first_trace.py` next to `future-agi/` and run `python first_trace.py`. The app supplies a return policy rather than asking the model to invent one.

```python
from uuid import UUID

from fi_instrumentation import register
from fi_instrumentation.fi_types import ProjectType
from openai import OpenAI
from traceai_openai import OpenAIInstrumentor

provider = register(project_type=ProjectType.OBSERVE, project_name="local-stack-smoke-test", verbose=False)
OpenAIInstrumentor().instrument(tracer_provider=provider)
client = OpenAI()
tracer = provider.get_tracer("ridgeline-support")

with tracer.start_as_current_span("answer return question") as span:
    result = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": "Unused boots can be returned within 30 days. Answer using this policy only."},
            {"role": "user", "content": "Can I return unused boots after 12 days?"},
        ],
    )
    print(result.choices[0].message.content)
    trace_id = UUID(int=span.get_span_context().trace_id)

provider.force_flush()
print(trace_id)
```

Open **Observe** and select `local-stack-smoke-test`. Match the printed trace ID to the `answer return question` span and expand it to see the OpenAI call.

</Step>
</Steps>

## Troubleshooting

| Symptom | What to do |
|---|---|
| The installer reports too little Docker memory | Increase the Docker VM's memory, then rerun the installer in the same checkout. |
| The UI says **Future AGI is starting** | Let the first migrations finish. Check `docker compose --project-directory future-agi logs --tail 50 app` locally for the current phase. Do not share unredacted logs. |
| The trace does not appear | Use keys from this install, check both endpoint ports, and run the script on the Docker host. The collector binds to loopback. |
| You cannot sign in | See [Installation](/docs/self-hosting/installation) for account creation and host-side password reset. Do not reset an account you do not own. |

Continue to [Installation](/docs/self-hosting/installation) for Distributed, installer flags, and everyday operations.
