<TLDR>
Trace one OpenAI request, then find the matching [trace](/docs/observe/concepts/traces) in Observe and read its reply, timing and token usage.
</TLDR>

## The problem

A reply is slow or wrong, but the terminal only shows the answer. To see which model ran, how long it took and how many tokens it used, you need the trace of that same request.

An **OK** row in Observe is not enough by itself: unless its input and output match the request you just made, you may be investigating a different call.

## What you'll build

One traced OpenAI request that you can recognize in both your terminal and the Observe project, without changing your app's logic.

<Mermaid chart={`

You'll:

1. Install the traceAI instrumentor and register an Observe project.
2. Run one instrumented chat completion.
3. Match its prompt and reply in the dashboard before reading the trace metrics.
4. Read the [span](/docs/observe/concepts/spans) for model, latency, token counts and cost.

New to tracing? Read the [observability model](/docs/observe/concepts/observability-model) first.

<Prerequisites title="Before you start">
- A Future AGI account and your [API key and secret key](/docs/admin-settings/api-keys) (`FI_API_KEY` and `FI_SECRET_KEY`) from **Build > Keys**.
- Python 3.10+, or Node 18+ for the TypeScript path.
- An OpenAI API key for the model call. The Future AGI keys authorize trace export, not generation.
</Prerequisites>

<Note>
Pin the packages to the version you test against, so a later release cannot change behavior under you. For a standalone script with pinned versions that shuts down the tracer provider on exit, see [Send your first trace](/docs/get-started/send-your-first-trace).
</Note>

## Trace one OpenAI call

<Steps>
  <Step title="Install traceAI">
    Install the core instrumentation package and the OpenAI instrumentor

    <CodeGroup titles={["Python", "JS/TS"]}>
    ```bash Python
    pip install "fi-instrumentation-otel[grpc]" traceAI-openai
    ```
    ```bash JS/TS
    npm install @traceai/fi-core @traceai/openai
    ```
    </CodeGroup>
  </Step>

  <Step title="Set your keys">
    Read keys from the environment, never hardcode them in source

    ```bash
    export FI_API_KEY="your-futureagi-api-key"
    export FI_SECRET_KEY="your-futureagi-secret-key"
    export OPENAI_API_KEY="your-openai-api-key"
    ```
  </Step>

  <Step title="Register a project and trace one call">
    `register` returns a tracer provider. Set `project_type` to `OBSERVE`, attach the OpenAI instrumentor, then call OpenAI exactly as you normally would

    <CodeGroup titles={["Python", "JS/TS"]}>
    ```python Python
    from fi_instrumentation import register, Transport
    from fi_instrumentation.fi_types import ProjectType
    from traceai_openai import OpenAIInstrumentor
    from openai import OpenAI

    # Connect to Future AGI and create (or reuse) an Observe project
    trace_provider = register(
        project_type=ProjectType.OBSERVE,
        project_name="self-improving-agent",
        transport=Transport.GRPC,
    )

    # Auto-instrument OpenAI: every call is now traced
    OpenAIInstrumentor().instrument(tracer_provider=trace_provider)

    # Use OpenAI exactly as you normally would
    client = OpenAI()
    completion = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": "Suggest one habit I could build to keep improving every day."}],
    )
    print(completion.choices[0].message.content)
    ```
    ```typescript JS/TS
    import { register, ProjectType } from "@traceai/fi-core";
    import { OpenAIInstrumentation } from "@traceai/openai";
    import { registerInstrumentations } from "@opentelemetry/instrumentation";
    import OpenAI from "openai";

    // Connect to Future AGI and create (or reuse) an Observe project
    const traceProvider = register({
      projectType: ProjectType.OBSERVE,
      projectName: "self-improving-agent",
    });

    // Auto-instrument OpenAI: every call is now traced
    registerInstrumentations({
      instrumentations: [new OpenAIInstrumentation({})],
      tracerProvider: traceProvider,
    });

    // Use OpenAI exactly as you normally would
    const client = new OpenAI();
    const completion = await client.chat.completions.create({
      model: "gpt-4o",
      messages: [{ role: "user", content: "Suggest one habit I could build to keep improving every day." }],
    });
    console.log(completion.choices[0].message.content);
    ```
    </CodeGroup>

    Expected terminal output (the wording varies):

    ```text
    Spend five minutes each evening noting one thing you learned that day.
    Small daily reflections compound into steady improvement over time.
    ```
  </Step>

  <Step title="Confirm the trace">
    Open the `self-improving-agent` project in **Observe > Tracing**. Within a few seconds you will see one trace row with **status OK**, the **model**, the **latency**, and the **token count**. If no row appears, see [Not seeing your trace?](#not-seeing-your-trace)

    <img src="/images/docs/observe/llm-tracing-overview.webp" alt="Observe trace explorer for another project, listing traces with Input, Output, Timestamp, Status, Latency and Tokens columns" style={{ borderRadius: '5px' }} />
    *The trace explorer, shown here for a busier project. Your project has one row for the request you just sent.*
  </Step>
</Steps>

## Check that the trace is your request

1. Click the trace row to read the prompt, the completion, and the span timing.
2. Compare its input with the prompt in the script: `Suggest one habit I could build to keep improving every day.`
3. Compare its completion with the reply printed in your terminal.
4. Read the model, latency and token counts on the span.

The input identifies the call; the reply and timestamp tell repeated runs of the same prompt apart. **OK** is a status, not a quality score.

## What you just captured

That row is a trace, the full record of one request. Because this example made a single OpenAI call, the trace holds one span: the `llm` operation, carrying the model, the prompt and completion, the token counts, and the cost.

The same four steps instrument 30+ frameworks. Swap the instrumentor for your stack and the flow is the same; see [all framework integrations](/docs/integrations/traceai).

## Not seeing your trace?

- **No trace appears**: a short script can exit before the exporter flushes. Call `trace_provider.force_flush()` before the process ends. A printed reply only shows that the model call worked, not that the trace was exported.
- **Wrong or empty project**: confirm `project_name` matches the project you are viewing, and that `FI_API_KEY` and `FI_SECRET_KEY` belong to this workspace.
- **Still nothing**: widen the date picker (it defaults to the last 7 days) and turn on **Auto refresh**. For deeper help see [No traces appear](/docs/observe/troubleshooting/no-traces-appearing).
