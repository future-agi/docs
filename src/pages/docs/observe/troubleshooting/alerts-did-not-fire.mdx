## Symptom

You expected an alert but got no email, Slack message, or webhook request. Open the monitor, clear any issue filters or search text, and look for an entry at the time of the breach. If there is no entry, check the rule. If there is an entry, the rule fired: check the destination instead.

---

## Quick checks

- The monitor has had time for a check at its configured **Interval** (minimum five minutes).
- The monitor is not muted, and the spans you expect match its project and filters.
- The observed value is strictly above or below the configured threshold. Equality is not a breach.
- **Define Notification** has the intended method and destination. Switching methods in the editor replaces the previous one.

## Causes and fixes

| Cause | What you see | Fix |
|---|---|---|
| Interval | The monitor hasn't checked the window yet | Wait one configured interval, then compare the metric for the same window. |
| Monitor is muted | There are no new scheduled checks | Unmute the monitor to resume checks. |
| Threshold direction or value | A spike didn't fire a **Below** rule | Check the direction and the critical and warning values. |
| Percentage-change baseline | A new project doesn't alert | Check that the historical window contains enough data to calculate a baseline. |
| Email or Slack | History has an alert but your inbox or Slack channel doesn't | Verify the email addresses or the Slack incoming webhook for the intended channel. |
| Webhook URL won't save | The receiver is on localhost or a private network | Enter the final HTTP(S) URL of a receiver you control. Its hostname must resolve only to public addresses. |
| Webhook didn't arrive | History has an alert but your integration didn't process it | Check the receiver's access log at the alert time. Accept a JSON `POST` and return `2xx` promptly; the sender uses a 10-second connect and read timeout. The sender doesn't follow redirects or retry a failed delivery. |

For the request fields and an example body, see [Webhook delivery](/docs/observe/features/alerts#webhook-delivery).

## Minimal smoke test

Use a test monitor and a destination you control. Choose **Count of errors**, **Static Value**, and **Above**. Enter `0` for **Warning** and `1` for **Critical**. Send a test trace with one error span that matches the monitor's filters. If it is the only matching error in the next check's window, expect a warning, not a critical alert. Match the entry in history to the notification at your destination. Mute the test monitor when you're done.

## Escalate

If the monitor still won't fire on a confirmed breach, contact support@futureagi.com with its name, the threshold and interval, the breach time with time zone, and whether an alert appears in history. Do not include credentials or the full webhook URL.

## Prevent recurrence

- Choose a check interval that matches how quickly you need to hear about a breach.
- Test delivery again after changing your destination.
