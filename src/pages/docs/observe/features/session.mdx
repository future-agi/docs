A customer asks about shipping and then about changing a password, but each turn is a separate [trace](/docs/observe/concepts/traces). Open the [session](/docs/observe/concepts/sessions) to read those turns together, then open the [user](/docs/observe/concepts/users) to see their conversations across visits.

<Prerequisites title="Before you start">
- Open a project with traced conversations in [Observe](/docs/observe).
- Attach the [grouping keys `session.id` and `user.id`](/docs/sdk/tracing/set-session-user-id) to the [spans](/docs/observe/concepts/spans) you want to group. Reuse one session ID per conversation and one user ID per customer.
</Prerequisites>

  U --> V["Traces or sessions for one customer"]`} />

## Read one conversation

1. Open the project.
2. Choose **Sessions**.

   You should see one row per conversation. The `support-agent` example shows `chat_1001` and `chat_1002`.

<img src="/images/docs/observe/sessions-list.png" alt="Observe Sessions tab for the support-agent project listing conversations chat_1001 and chat_1002 with first and last message, duration, total cost, and trace count" style={{ borderRadius: '5px' }} />

3. Sort by **Total Cost** to find expensive sessions, or **Total Traces** to find conversations with the most requests.
4. Open `chat_1002`, or the conversation you want to investigate.

   **Session History** shows the traces in order, with their [eval scores](/docs/observe/features/evals) and [annotations](/docs/annotations).

<img src="/images/docs/observe/session-detail.png" alt="Session detail with the Session History conversation and a Trace Details panel showing trace ID, evaluations, and metadata" style={{ borderRadius: '5px' }} />

*In the example, **Total Traces** is `2`, **User ID** is `cust_77`, and the shipping question comes before the password question.*

5. Select **View Trace** on a turn to inspect its full span tree.

For voice and other replayable sessions, configure session replay to step back through a conversation as it happened. For voice calls, see how to [review the transcript or recording](/docs/observe/features/voice).

### Read the session columns

<div class="sdk-ref-table max-sm:[&_td]:px-1.5! max-sm:[&_th]:px-1.5!">

| Column | What it shows |
|---|---|
| **Session Id** | The shared identifier for the conversation |
| **First Message** | The opening message |
| **Last Message** | The most recent message |
| **Duration** | How long the conversation lasted |
| **Total Cost** | Combined cost of all calls in the session |
| **Total Traces** | How many requests were part of it |

</div>

## Follow the customer across conversations

1. Switch to **Users**.

   You should see one row per user, with trace and session counts. Sort either count to find the most active users.

<img src="/images/docs/observe/users-list.png" alt="Observe Users view for the support-agent project listing end users cust_42 and cust_77 with User ID, First Active, Last Active, number of traces, and number of sessions columns" style={{ borderRadius: '5px' }} />

2. Open a user row, such as `cust_77`.
3. Choose **Trace** to see individual requests.

<img src="/images/docs/observe/user-detail-traces.png" alt="User detail Traces tab listing every trace for user cust_77 with input, output, status, and latency" style={{ borderRadius: '5px' }} />

4. Choose **Sessions** to see the same customer's conversations.

<img src="/images/docs/observe/user-detail-sessions.png" alt="User detail Sessions tab listing every conversation for user cust_77 with first and last message, duration, cost, and trace count" style={{ borderRadius: '5px' }} />

*Under `cust_77`, **Sessions** shows one row: `chat_1002`, with two traces. These are the same two turns you saw in session history.*

Cost, evals and guardrail results are available by session and trace in the user detail view.

### Read the user columns

<div class="sdk-ref-table max-sm:[&_td]:px-1.5! max-sm:[&_th]:px-1.5!">

| Column | What it shows |
|---|---|
| **User ID** | The `user.id` value you set in code |
| **First Active** | When the user's first trace arrived |
| **Last Active** | When their most recent trace arrived |
| **No. of Traces** | How many traces are attributed to the user |
| **No. of Sessions** | How many conversations they had |

</div>

## Narrow either list

1. Set the time window with the date-range picker.

   The column metrics reflect activity in that window.

2. Apply a filter for `session.id` in the session list or `user.id` in the user list.

   You can also filter on metadata or span attributes; the [filter syntax reference](/docs/observe/reference/filters) lists the fields and operators.

## Troubleshooting

<div class="sdk-ref-table max-sm:[&_td]:px-1.5! max-sm:[&_th]:px-1.5!">

| Symptom | Cause | Fix |
|---|---|---|
| Traces not grouping | The call ran outside the `using_session` / `using_user` block, so spans never got the ID | Make the call inside the block (or a decorated function) |
| One conversation split across sessions | A different `session.id` was used on some turns | Reuse one stable string for the whole conversation |
| One person split across users | A different `user.id` was used on some requests | Reuse one stable string for that person |
| Row exists but no metrics | Spans carried the ID but no cost or token attributes | Confirm the LLM spans are auto-instrumented |

</div>

After changing the instrumentation, send another turn with the same IDs. Reopen the session and look for that turn; then reopen the user and check that the conversation appears in **Sessions** for the same time window.
