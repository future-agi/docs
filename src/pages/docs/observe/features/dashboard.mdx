How many errors occurred after a release? Build a dashboard widget from your project's [spans](/docs/observe/concepts/spans), then check the count against the matching rows for the same time window.

A dashboard is a collection of widgets. Each widget runs a query against your data and shows the result as a chart or table, so you can track error rates, latency, token usage, eval scores, or any metric from your spans and experiments.

<Prerequisites title="Before you start">
- Access to the project that received the release traffic. Dashboards are scoped to the organization and project; project team members with access can view and edit them.
- [Traced requests](/docs/observe/features/quickstart) from the period you want to inspect.
</Prerequisites>

## Create the dashboard

1. Open **Dashboards**.
2. Select **Create Dashboard**.
3. Name the dashboard for the release you're monitoring.

   You can also add a description. An empty dashboard shows **No widgets yet**.

   ![An empty dashboard with the Add Widget button below No widgets yet.](/screenshot/product/observe/dashboard/1.png)

## Add the error-count widget

1. Select **Add Widget**.

   ![A new widget has no metric yet; the Query tab offers a metric, a filter, and a breakdown.](/screenshot/product/observe/dashboard/2.png)

2. Choose the error count under **Select Metric**.
3. Choose the metric chart type for a single number.
4. Choose the aggregation that answers your question.

   Sum, average, median, count, distinct count, min and max are available, and each answers a different question.

5. Set the time range to the post-release window.
6. Apply any [filters](/docs/observe/reference/filters) you need to isolate the traffic.
7. Inspect the preview.
8. Select **Save**.

   You should see the widget on the dashboard. The dashboard's global time range applies to all its widgets.

## Interpret the widget settings

<div class="sdk-ref-table max-sm:[&_td]:px-1.5! max-sm:[&_th]:px-1.5!">

| Setting | How it changes what you read |
| --- | --- |
| Metric | Error count answers a different question from span count, latency, token usage or an [eval score](/docs/observe/features/evals). |
| Aggregation | Sum, average, median, count, distinct count, min and max answer different questions. Confirm the widget uses the one you mean. |
| Granularity | Minute, hour, day, week and month set the bucket size. The options adjust to the time range, and per-hour and per-day buckets give different numbers for the same traffic. |
| Time range | Use **Custom** for a start and end date. Presets include **30 mins**, **6 hrs**, **Today**, **Yesterday**, **7D**, **30D**, **3M**, **6M** and **12M**. |
| Filters | A model, status or other attribute filter excludes nonmatching rows. Apply the same conditions when checking the count. |
| Group by | A breakdown by a span attribute such as model, user or status separates groups. Check a group's value against rows for that group. |
| Chart type | Metric shows one number; line, stacked line, column, stacked column, bar, stacked bar and pie show patterns or breakdowns. Use a table to inspect raw data or export CSV. |

</div>

![Time range presets from Custom to 12M, with the granularity menu open on Day.](/screenshot/product/observe/dashboard/3.png)

## Check the count against the rows

1. Open the [trace explorer](/docs/observe/guides/explore-dashboard) in the same project.
2. Select the same time range as the widget.
3. Apply the same filters as the widget.
4. Filter status to `ERROR`.
5. Count the matching rows.

   Compare that count with the widget. If the two agree, the widget's settings explain the number. If they differ, see [Dashboard numbers look wrong](/docs/observe/troubleshooting/dashboard-numbers-look-wrong).

## Arrange the team's view

Dashboards work across project types and are shareable across your team. Put related widgets side by side to spot correlations, such as a latency spike beside a rise in error rate, or to keep cost, token usage, experiment metrics and eval scores in one view. Drag a widget to reorder it, or resize it to make a chart or table easier to read.

![Widgets arranged side by side on a dashboard.](/screenshot/product/observe/dashboard/4.png)

The widget menu lets you edit, duplicate, resize or delete a widget.

![The widget menu open on a chart, with Edit, Duplicate, Resize Width and Delete.](/screenshot/product/observe/dashboard/5.png)

## Read a widget from code

The [dashboards SDK reference](/docs/sdk/reference/dashboards) lists `dashboards.widgets.query`, which runs a saved widget's query and returns its chart data, and `dashboards.widgets.get`, which returns the widget with its query and chart configuration, in Python and TypeScript. The corresponding MCP tools are `query_dashboard_widget` and `get_dashboard_widget`.
