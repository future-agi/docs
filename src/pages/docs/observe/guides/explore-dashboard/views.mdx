If you keep rebuilding the same [filters](/docs/observe/guides/explore-dashboard/filters) in the [trace table](/docs/observe/guides/explore-dashboard), save them as a named view. This example reopens a `gpt-4o-mini` view in the [support-agent project](/docs/cookbook/observe-langgraph-agent-and-obtain-insights).

<Prerequisites title="Before you start">
- A project with traces from the model you want to inspect. Use a model recorded in your own project if it isn't `gpt-4o-mini`.
</Prerequisites>

## Save the model filter

1. Apply the condition `Model is one of gpt-4o-mini` in the trace table.
2. Click **+** beside **Trace**, **Sessions** and **Users**.

<img src="/images/docs/observe/views-create.png" alt="Observe trace table filtered to Model is one of gpt-4o-mini, with the + button next to the Trace, Sessions, and Users tabs highlighted" style={{ borderRadius: '5px' }} />

3. In **View Name**, enter `Filter by model`.

<img src="/images/docs/observe/views-save-modal.png" alt="Save view dialog with a View Name field reading Filter by model and a Save view button" style={{ borderRadius: '5px' }} />

4. Click **Save view**.

   You should see **Filter by model** as a tab alongside **Trace**, **Sessions** and **Users**.

## Reopen the view

1. Select **Filter by model**.
2. Check the condition shown above the table.

   You should see `Model is one of gpt-4o-mini` again. The table reloads with every filter the view saved, with no rebuilding.

<img src="/images/docs/observe/views-saved-tab.png" alt="Trace table with the saved Filter by model view now showing as a tab beside Trace, Sessions, and Users, its gpt-4o-mini filter still applied" style={{ borderRadius: '5px' }} />

*In the captured view, the `gpt-4o-mini` condition appears above five `support_turn` rows. It selects the final-sale question as well as the routine questions because the filter is on model, not answer quality.*

A named view lets the team return to the same filtered slice. If no rows appear, check whether the selected time window includes traces for that model. Save a separate view for a different recurring question, such as which requests have high latency.
