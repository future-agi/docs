## About

A trace groups the spans, or individual operations, that belong to one request. In Ridgeline Outfitters' support project, you can sort traces by recorded cost, open an expensive reply, and see which model or tool calls contributed to it.

## Inspect a request in the dashboard

<Steps>
<Step title="Open your project">

Under **Observe**, open **Tracing** and select your support project. If you don't have indexed traces yet, follow the [tracing quickstart](/docs/observe/quickstart).

<img src="/images/docs/observe/dashboard-projects.png" alt="Tracing project list showing a project's last activity and tags" style={{ borderRadius: '5px' }} />

</Step>
<Step title="Compare requests">

On the **Trace** tab, compare **Input** with **Output** to see what the agent answered. **Latency** shows how long the request took. Click the **Total Cost** heading to sort by recorded cost, or **Tokens** to sort by token count. If the heading isn't sortable, clear filters other than date and usage filters.

Click a **Trace Name** to open its span tree. Select a model call to inspect its recorded input, output, model, and usage, or a tool call to see what the tool returned. For traces that include session or user identifiers, use **Sessions** to follow a conversation or **Users** to explore one customer's requests.

## Send spans from the platform SDK

Use `client.spans.ingest` when you already have records of completed operations. It sends a JSON **array** to `POST /tracer/observation-span/create_otel_span/` on the platform API. It does not take an OTLP export request or use the trace collector. To capture spans as your app runs instead, use the [tracing quickstart](/docs/observe/quickstart).

<Note>
On self-hosted installations, the JSON endpoint relies on the legacy span mirror to copy its records into the Observe index. If your installation indexes spans only through the collector, use the tracing quickstart for ingestion. You can still use the SDK below to read and sort indexed traces.
</Note>

Set `FI_API_KEY` and `FI_SECRET_KEY` from your [API key pair](/docs/admin-settings/api-keys). Install the Python client with `python -m pip install futureagi==0.8.0`, or install the TypeScript client with `npm install @future-agi/sdk@0.3.0`. The Node.js examples can run as `.mjs` files.

The example records three synthetic support replies, each as the root span of a separate trace. `start_time` and `end_time` are Unix timestamps in **nanoseconds**; `latency` is the duration in **milliseconds**. `gen_ai.usage.total_tokens` supplies a token count without calling a model. Each run creates a new example project. These replies include token counts, not prices.

Send **one span first** and wait for its response: that call creates the named project if it doesn't exist. Then batch the other two. The SDK returns `ids` in each response. These are **span IDs**, not trace IDs; batch results need not follow input order.

<CodeGroup titles={["Python", "TypeScript"]}>

```python
from time import time_ns
from uuid import uuid4

from fi import Client

client = Client()
project_name = f"ridgeline-support-{uuid4().hex[:8]}"


def reply(topic, question, answer, tokens):
    end = time_ns()
    return {
        "project_name": project_name, "project_type": "observe",
        "trace_id": uuid4().hex, "span_id": uuid4().hex[:16],
        "name": topic, "start_time": end - 1_000_000_000, "end_time": end,
        "latency": 1000, "status": "OK",
        "attributes": {
            "gen_ai.span.kind": "LLM", "gen_ai.usage.total_tokens": tokens,
            "input.value": question, "output.value": answer,
        },
    }


first = client.spans.ingest([
    reply("shipping", "Where is my tent?", "It is out for delivery.", 90)
])
batch = client.spans.ingest([
    reply("returns", "Can I return unused boots?", "Yes, within 30 days.", 30),
    reply("sizing", "Which pack fits a 19-inch torso?", "Try the medium.", 60),
])
projects = client.projects.list(name=project_name, project_type="observe")["projects"]
project = next(p for p in projects if p["name"] == project_name)
print("Project name:", project_name)
print("Project ID:", project["id"])
print("Span IDs:", *first["ids"], *batch["ids"])
```

```javascript
import { randomUUID } from "node:crypto";
import { Client } from "@future-agi/sdk";

const client = new Client();
const hexId = () => randomUUID().replaceAll("-", "");
const projectName = `ridgeline-support-${hexId().slice(0, 8)}`;

function reply(topic, question, answer, tokens) {
  const end = Math.floor(Date.now() / 1000) * 1_000_000_000;
  return {
    project_name: projectName, project_type: "observe",
    trace_id: hexId(), span_id: hexId().slice(0, 16),
    name: topic, start_time: end - 1_000_000_000, end_time: end,
    latency: 1000, status: "OK",
    attributes: {
      "gen_ai.span.kind": "LLM", "gen_ai.usage.total_tokens": tokens,
      "input.value": question, "output.value": answer,
    },
  };
}

const first = await client.spans.ingest([
  reply("shipping", "Where is my tent?", "It is out for delivery.", 90),
]);
const batch = await client.spans.ingest([
  reply("returns", "Can I return unused boots?", "Yes, within 30 days.", 30),
  reply("sizing", "Which pack fits a 19-inch torso?", "Try the medium.", 60),
]);
const { projects } = await client.projects.list({ name: projectName, project_type: "observe" });
const project = projects.find(p => p.name === projectName);
console.log("Project name:", projectName);
console.log("Project ID:", project.id);
console.log("Span IDs:", ...first.ids, ...batch.ids);
```

</CodeGroup>

## Read the spans and sort the traces by cost

Set `PROJECT_ID` to the ID of a project with indexed traces. To read the example spans, use the project ID from ingestion and set `SPAN_IDS` to the three printed IDs, separated by spaces. Omit `SPAN_IDS` if you only want the sorted trace list.

Pass `sort_params` as a **JSON-encoded list**, not a dictionary or a raw array. `page_number=0` requests the first numbered page. The server sorts matching traces across the project **before** returning that page.

<CodeGroup titles={["Python", "TypeScript"]}>

```python
import json
import os

from fi import Client

client = Client()
project_id = os.environ["PROJECT_ID"]
page = client.traces.list(
    project_id=project_id, page_number=0, page_size=10,
    sort_params=json.dumps([{"column_id": "cost", "direction": "asc"}]),
)
for row in page.table:
    print(row["trace_id"], row["trace_name"], row["cost"])

for span_id in os.environ.get("SPAN_IDS", "").split():
    span = client.spans.get(span_id, project_id=project_id).observation_span
    print(span["id"], span["name"])
```

```javascript
import { Client } from "@future-agi/sdk";

const client = new Client();
const project_id = process.env.PROJECT_ID;
if (!project_id) throw new Error("Set PROJECT_ID to your project's ID.");
const page = await client.traces.list({
  project_id, page_number: 0, page_size: 10,
  sort_params: JSON.stringify([{ column_id: "cost", direction: "asc" }]),
});
for (const row of page.table) {
  console.log(row.trace_id, row.trace_name, row.cost);
}

for (const id of (process.env.SPAN_IDS || "").split(/\s+/).filter(Boolean)) {
  const { observation_span: span } = await client.spans.get(id, { project_id });
  console.log(span.id, span.name);
}
```

</CodeGroup>

The first loop prints the trace ID, name, and recorded cost, least expensive first. Use `desc` for the most expensive first. To compare the synthetic replies instead, set `column_id` to `total_tokens` and print `row["total_tokens"]` (Python) or `row.total_tokens` (TypeScript). Once indexed, the ascending token order is `returns` (30), `sizing` (60), then `shipping` (90). The second loop prints the ID and name of each span you requested.

## Limits and troubleshooting

| If you see this | What to do |
| --- | --- |
| Ingestion returned IDs but a trace or span is missing | An ID acknowledges the write, not that the span is searchable. Check the project ID and retry the read with the same span IDs after indexing, rather than sending the spans again. On a self-hosted install, check the span mirror as described above. |
| `Usage sorting requires a project, numbered pages, and only date or usage filters. Clear the sort to use other filters.` | For example, changing the cost-sorted request to `cursor_mode=True` is not supported. Keep `project_id` and numbered pages; omit `cursor`, `cursor_mode`, `session_id`, and `project_version_id`. To switch to cursor pagination, omit both `sort_params` and `page_number`. For a session, project version, or workspace-wide read, omit `sort_params`. |
| A sort column or a filter is rejected | Sort by `cost`, `total_tokens`, `prompt_tokens`, or `completion_tokens`, not by `latency`. Combine a usage sort only with date or usage filters. A span attribute named `cost` is not a usage filter. Clear the sort to filter by other attributes or evals. |
