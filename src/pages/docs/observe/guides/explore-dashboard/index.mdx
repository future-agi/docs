## About

A trace groups the spans, or individual operations, that belong to one request. In Ridgeline Outfitters' support project, you can sort traces by recorded cost, open an expensive reply, and see which model or tool calls contributed to it.

## Inspect a request in the dashboard

<Steps>
<Step title="Open your project">

Under **Observe**, open **Tracing** and select your support project. If you don't have indexed traces yet, follow the [tracing quickstart](/docs/observe/quickstart).

![Tracing project list filtered to support-agent, with its 30-day volume chart and last activity](/images/docs/observe/explore-dashboard/tracing-support-project.png)

</Step>
<Step title="Compare requests">

On the **Trace** tab, compare **Input** with **Output** to see what the agent answered. **Latency** shows how long the request took. Click the **Total Cost** heading to sort by recorded cost, or **Tokens** to sort by token count. If the heading isn't sortable, clear filters other than date and usage filters.

![Support traces sorted by Total Cost, highest first. The top row pairs the export-log question with its reply, 2.3-second latency, and $0.0164 cost.](/images/docs/observe/explore-dashboard/support-traces-by-cost.png)

</Step>
<Step title="Inspect a span">

Click a **Trace Name** to open its span tree. Select a model call to inspect its recorded input, output, model, and usage, or a tool call to see what the tool returned. For traces that include session or user identifiers, use **Sessions** to follow a conversation or **Users** to explore one customer's requests.

![The export-log trace with the gpt-4.1-mini span selected beneath support_agent. The preview shows the model input, reply, 41.0K tokens, and $0.02 rounded cost.](/images/docs/observe/explore-dashboard/selected-support-model-span.png)

</Step>
</Steps>

## Send three example traces

If you already have indexed traces, skip to the read examples below. Otherwise, send three synthetic Ridgeline replies to the trace collector. Each reply has a recorded token count but no model price. Set `FI_API_KEY` and `FI_SECRET_KEY` from your [API key pair](/docs/admin-settings/api-keys). For a self-hosted installation, use your HTTP collector origin for `FI_TRACES_URL` and your platform API origin for `FI_BASE_URL`.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install fi-instrumentation-otel==1.5.1 futureagi==0.8.0
export FI_TRACES_URL="https://api.futureagi.com"
```

Save this as `send.py` and run `python send.py`. It prints a new project name. Once it appears in Observe, set `PROJECT_NAME` to that name, or to the name of an existing Observe project.

```python
from uuid import uuid4
from fi_instrumentation import register
from fi_instrumentation.fi_types import ProjectType

project_name = f"ridgeline-support-{uuid4().hex[:8]}"
provider = register(project_name=project_name, project_type=ProjectType.OBSERVE, verbose=False)
tracer = provider.get_tracer("ridgeline.support")
for topic, question, answer, tokens in [
    ("shipping", "Where is my tent?", "It is out for delivery.", 90),
    ("returns", "Can I return unused boots?", "Yes, within 30 days.", 30),
    ("sizing", "Which pack fits a 19-inch torso?", "Try the medium.", 60),
]:
    with tracer.start_as_current_span(topic) as span:
        span.set_attribute("fi.span.kind", "LLM")
        span.set_attribute("input.value", question)
        span.set_attribute("output.value", answer)
        span.set_attribute("llm.token_count.prompt", tokens - 10)
        span.set_attribute("llm.token_count.completion", 10)
        span.set_attribute("llm.token_count.total", tokens)
provider.shutdown()
print(project_name)
```

## Read the spans and sort the traces by cost

Use `python -m pip install futureagi==0.8.0` if you skipped the Python setup above, or `npm install @future-agi/sdk@0.3.0` for Node.js. Save the example as `read.py` or `read.mjs` and run `python read.py` or `node read.mjs` after exporting `PROJECT_NAME`.

Pass `sort_params` as a **JSON-encoded list**, not a dictionary or a raw array. `page_number=0` requests the first numbered page. The server sorts matching traces across the project **before** returning that page.

<CodeGroup titles={["Python", "TypeScript"]}>

```python
import json
import os

from fi import Client

client = Client()
name = os.environ["PROJECT_NAME"]
projects = client.projects.list(name=name, project_type="observe")["projects"]
project_id = next(p["id"] for p in projects if p["name"] == name)
page = client.traces.list(
    project_id=project_id, page_number=0, page_size=10,
    sort_params=json.dumps([{"column_id": "cost", "direction": "asc"}]),
)
for row in page.table:
    print(row["trace_id"], row["trace_name"], row["cost"])

for span in client.spans.list(project_id=project_id, page_size=10).table:
    print(span["span_id"], span["span_name"])
```

```javascript
import { Client } from "@future-agi/sdk";

const client = new Client();
const name = process.env.PROJECT_NAME;
if (!name) throw new Error("Set PROJECT_NAME to your project's name.");
const { projects } = await client.projects.list({ name, project_type: "observe" });
const project_id = projects.find(p => p.name === name).id;
const page = await client.traces.list({
  project_id, page_number: 0, page_size: 10,
  sort_params: JSON.stringify([{ column_id: "cost", direction: "asc" }]),
});
for (const row of page.table) {
  console.log(row.trace_id, row.trace_name, row.cost);
}

for (const span of (await client.spans.list({ project_id, page_size: 10 })).table) {
  console.log(span.span_id, span.span_name);
}
```

</CodeGroup>

The first loop prints the trace ID, name, and recorded cost, least expensive first. Use `desc` for the most expensive first. To compare the synthetic replies instead, set `column_id` to `total_tokens` and print `row["total_tokens"]` (Python) or `row.total_tokens` (TypeScript). Once indexed, the ascending token order is `returns` (30), `sizing` (60), then `shipping` (90). The second loop prints the ID and name of up to ten spans in the project.

## Limits and troubleshooting

| If you see this | What to do |
| --- | --- |
| Your new project or spans are missing | Wait for indexing and refresh Observe. Check that the tracing exporter uses the collector URL and the platform client uses the API URL for the same workspace. |
| `Usage sorting requires a project, numbered pages, and only date or usage filters. Clear the sort to use other filters.` | For example, changing the cost-sorted request to `cursor_mode=True` is not supported. Keep `project_id` and numbered pages; omit `cursor`, `cursor_mode`, `session_id`, and `project_version_id`. To switch to cursor pagination, omit both `sort_params` and `page_number`. For a session, project version, or workspace-wide read, omit `sort_params`. |
| A sort column or a filter is rejected | Sort by `cost`, `total_tokens`, `prompt_tokens`, or `completion_tokens`, not by `latency`. Combine a usage sort only with date or usage filters. A span attribute named `cost` is not a usage filter. Clear the sort to filter by other attributes or evals. |
