## About

The trace table shows one row per request. Open a row to see the individual steps, called spans, behind the response. For example, you can compare what Ridgeline Outfitters' support agent spent answering shipping, returns, and sizing questions, then inspect the most expensive reply.

## Inspect a request in the dashboard

1. Under **Observe**, open **Tracing** and select your project. If you don't have traces yet, [send the three example requests](#send-spans-from-the-platform-sdk) first.

{/* MEDIA: The Tracing project list with the support-agent project visible. */}

<img src="/images/docs/observe/dashboard-projects.png" alt="Tracing project list showing a project's last activity and tags" style={{ borderRadius: '5px' }} />

2. On the **Trace** tab, compare **Input** with **Output** to see what the agent answered. **Latency** tells you how long the request took; **Tokens** and **Total Cost** describe its usage. Click the **Total Cost** column heading to sort. Use **Sessions** instead to follow a conversation across requests, or **Users** to see requests grouped by customer.

{/* MEDIA: The Ridgeline project's Trace tab with Total Cost sorted and Input, Output, and Latency visible. */}

<img src="/images/docs/observe/dashboard-trace-table.png" alt="Trace table showing the input, output, status, and latency for individual requests" style={{ borderRadius: '5px' }} />

3. Click a **Trace Name** to open its span tree. Select a model call to see its input, output, model, and recorded usage; select a tool call to inspect what the tool returned.

## Send spans from the platform SDK

Use `client.spans.ingest` when you already have records of completed operations. It sends a JSON **array** to `POST /tracer/observation-span/create_otel_span/` on the platform API. It does not take an OTLP export request or use the trace collector. To capture spans as your app runs instead, use the [tracing quickstart](/docs/observe/quickstart).

Set `FI_API_KEY` and `FI_SECRET_KEY` from your [API key pair](/docs/admin-settings/api-keys). Install `futureagi==0.8.0` with `python -m pip install futureagi==0.8.0`, or install the TypeScript client with `npm install @future-agi/sdk@0.3.0`. The Node.js examples can run as `.mjs` files.

The example records three synthetic support replies, each as the root span of a separate trace. `start_time` and `end_time` are Unix timestamps in **nanoseconds**; `latency` is the duration in **milliseconds**. `gen_ai.cost.total` records a cost for the example, without calling a model.

Send **one span first** and wait for its response: that call creates the named project if it doesn't exist. Then batch the other two. The SDK returns `ids` in each response. These are **span IDs**, not trace IDs; batch results need not follow input order.

<CodeGroup titles={["Python", "TypeScript"]}>

```python
from time import time_ns
from uuid import uuid4

from fi import Client

client = Client()
project_name = f"ridgeline-support-{uuid4().hex[:8]}"


def reply(topic, question, answer, cost):
    end = time_ns()
    return {
        "project_name": project_name, "project_type": "observe",
        "trace_id": uuid4().hex, "span_id": uuid4().hex[:16],
        "name": topic, "start_time": end - 1_000_000_000, "end_time": end,
        "latency": 1000, "status": "OK",
        "attributes": {
            "gen_ai.span.kind": "LLM", "gen_ai.cost.total": cost,
            "input.value": question, "output.value": answer,
        },
    }


first = client.spans.ingest([
    reply("shipping", "Where is my tent?", "It is out for delivery.", 0.003)
])
batch = client.spans.ingest([
    reply("returns", "Can I return unused boots?", "Yes, within 30 days.", 0.001),
    reply("sizing", "Which pack fits a 19-inch torso?", "Try the medium.", 0.002),
])
projects = client.projects.list(name=project_name, project_type="observe")["projects"]
project = next(p for p in projects if p["name"] == project_name)
print("Project name:", project_name)
print("Project ID:", project["id"])
print("Span IDs:", *first["ids"], *batch["ids"])
```

```javascript
import { randomUUID } from "node:crypto";
import { Client } from "@future-agi/sdk";

const client = new Client();
const hexId = () => randomUUID().replaceAll("-", "");
const projectName = `ridgeline-support-${hexId().slice(0, 8)}`;

function reply(topic, question, answer, cost) {
  const end = Math.floor(Date.now() / 1000) * 1_000_000_000;
  return {
    project_name: projectName, project_type: "observe",
    trace_id: hexId(), span_id: hexId().slice(0, 16),
    name: topic, start_time: end - 1_000_000_000, end_time: end,
    latency: 1000, status: "OK",
    attributes: {
      "gen_ai.span.kind": "LLM", "gen_ai.cost.total": cost,
      "input.value": question, "output.value": answer,
    },
  };
}

const first = await client.spans.ingest([
  reply("shipping", "Where is my tent?", "It is out for delivery.", 0.003),
]);
const batch = await client.spans.ingest([
  reply("returns", "Can I return unused boots?", "Yes, within 30 days.", 0.001),
  reply("sizing", "Which pack fits a 19-inch torso?", "Try the medium.", 0.002),
]);
const { projects } = await client.projects.list({ name: projectName, project_type: "observe" });
const project = projects.find(p => p.name === projectName);
console.log("Project name:", projectName);
console.log("Project ID:", project.id);
console.log("Span IDs:", ...first.ids, ...batch.ids);
```

</CodeGroup>

## Read the spans and sort the traces by cost

Set the environment variable `PROJECT_ID` to the printed project ID. To read back the individual spans as well, set `SPAN_IDS` to the three printed span IDs, separated by spaces. If you're using an existing project, you can omit `SPAN_IDS` and just list its traces.

Pass `sort_params` as a **JSON-encoded list**, not a dictionary or a raw array. `page_number=0` requests the first numbered page. The server sorts matching traces across the project **before** returning that page.

<CodeGroup titles={["Python", "TypeScript"]}>

```python
import json
import os

from fi import Client

client = Client()
project_id = os.environ["PROJECT_ID"]
page = client.traces.list(
    project_id=project_id, page_number=0, page_size=10,
    sort_params=json.dumps([{"column_id": "cost", "direction": "asc"}]),
)
for row in page.table:
    print(row["trace_id"], row["trace_name"], row["cost"])

for span_id in os.environ.get("SPAN_IDS", "").split():
    span = client.spans.get(span_id, project_id=project_id).observation_span
    print(span["id"], span["name"])
```

```javascript
import { Client } from "@future-agi/sdk";

const client = new Client();
const project_id = process.env.PROJECT_ID;
if (!project_id) throw new Error("Set PROJECT_ID to your project's ID.");
const page = await client.traces.list({
  project_id, page_number: 0, page_size: 10,
  sort_params: JSON.stringify([{ column_id: "cost", direction: "asc" }]),
});
for (const row of page.table) {
  console.log(row.trace_id, row.trace_name, row.cost);
}

for (const id of (process.env.SPAN_IDS || "").split(/\s+/).filter(Boolean)) {
  const { observation_span: span } = await client.spans.get(id, { project_id });
  console.log(span.id, span.name);
}
```

</CodeGroup>

Once all three example traces are indexed, the order is **returns** (`0.001`), **sizing** (`0.002`), then **shipping** (`0.003`), not the order you sent them. Use `desc` for the most expensive request first.

## Limits and troubleshooting

| If you see this | What to do |
| --- | --- |
| Ingestion returned IDs but a trace or span is missing | The read index updates asynchronously. Wait and rerun the **read** example with the same IDs, rather than sending more spans. |
| `Usage sorting requires a project, numbered pages, and only date or usage filters. Clear the sort to use other filters.` | For example, changing the cost-sorted request to `cursor_mode=True` is not supported. Keep `project_id` and numbered pages; omit `cursor`, `cursor_mode`, `session_id`, and `project_version_id`. If you need a cursor, a session, a project version, or a workspace-wide read, omit `sort_params` instead. |
| A sort column or a filter is rejected | Sort by `cost`, `total_tokens`, `prompt_tokens`, or `completion_tokens`, not by `latency`. Combine a usage sort only with date or usage filters. A span attribute named `cost` is not a usage filter. Clear the sort to filter by other attributes or evals. |
