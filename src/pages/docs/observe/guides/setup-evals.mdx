Run a [toxicity eval](/docs/evaluation/builtin/toxicity) on support replies to find harmful language without reading each reply yourself. Use a task in [Observe](/docs/observe) to choose which replies to score and see the verdict beside each scored request.

<Prerequisites title="Before you start">
- A project with recorded replies. This guide uses `support-agent` from [Observing a LangGraph agent](/docs/cookbook/observe-langgraph-agent-and-obtain-insights).
</Prerequisites>

## Choose what counts as one row

<div class="sdk-ref-table max-sm:[&_td]:px-1.5! max-sm:[&_th]:px-1.5!">

| Unit | When to use it | What you can map |
| --- | --- | --- |
| [Span](/docs/observe/concepts/spans) | Score one operation, such as a model call. | Attributes recorded on that span. |
| [Trace](/docs/observe/concepts/traces) | Score the reply for a whole request, as in this example. | Trace fields such as `input`, `output` and `metadata`, or paths into its spans. |
| [Session](/docs/observe/concepts/sessions) | Check a conversation when a tool result and the later reply are in different requests. | Session fields or paths into the session's traces and spans. |

</div>

## Create the task

1. Open the project's trace explorer.
2. Click **Add Evals**.

<img src="/images/docs/observe/evals-add-button.png" alt="Observe trace table for the support-agent project with the Add Evals button highlighted at the top right" style={{ borderRadius: '5px' }} />

3. Enter a task name.
4. Confirm the target project.
5. Under **Run evaluations on**, select **Traces**.

<img src="/images/docs/observe/evals-create-task.png" alt="Create Task page with a task name, the support-agent project, and Spans, Traces, and Sessions level options" style={{ borderRadius: '5px' }} />

## Map the reply to the eval

1. Under **Evaluations**, click **Add Evaluation**.

<img src="/images/docs/observe/evals-add-evaluation.png" alt="Create Task page with the Add Evaluation button highlighted and no evaluations added yet" style={{ borderRadius: '5px' }} />

2. Search the [eval templates](/docs/evaluation/concepts/eval-templates) for `toxicity`.

   You can also filter by category, such as Safety, RAG, Hallucination or Conversation; each row shows its output type (Pass/fail, Percentage or Choices).

3. Click **Add** on the toxicity row.

<img src="/images/docs/observe/evals-select-evaluation.png" alt="Select Evaluation library listing built-in templates like toxicity and conversation_hallucination with category filters and output types" style={{ borderRadius: '5px' }} />

   The name fills in automatically; the built-in instructions and Pass/fail output type are read-only.

4. If you want to locate the text that caused a failure, enable [error localization](/docs/evaluation/concepts/error-localization).
5. In **Variable mapping**, map the eval's `output` to the field containing the reply, such as the trace's `output`.
6. Click **Add Evaluation**.

   You should see the configured eval under **Evaluations**.

<img src="/images/docs/observe/evals-configure.png" alt="Toxicity eval configuration showing the read-only instructions, Pass/fail output, an error-localization checkbox, and a variable-mapping panel" style={{ borderRadius: '5px' }} />

### Map a reply inside a JSON attribute

Use dot notation for nested fields and numeric positions such as `.0` or `.1` for array items; bracket notation such as `[0]` is not supported. If a top-level span attribute contains a JSON object or array encoded as a string, the resolver parses it before following the rest of the path.

```json
{
  "attr_1": "{\"x\": {\"y\": [{\"z\": \"Your refund has been approved and will appear in your account within five business days.\"}]}}"
}
```

Here `attr_1.x.y.0.z` selects just the reply: `Your refund has been approved and will appear in your account within five business days.`

## Preview the rows and set the schedule

1. Under **Filters**, use **Add filter** if you want to narrow the eligible rows.
2. In **Live Preview**, inspect a matching row.

   Check the value beside the mapped field: the judge needs the reply, not a tag or an empty field.

3. Choose **Historical data** for existing rows or **New incoming data** for arrivals after the task starts.
4. For historical data, select a **Time window**.

   The presets are **30 mins**, **6 hrs**, **Today**, **Yesterday**, **7D**, **30D**, **3M**, **6M** and **12M**; choose **Custom** for another range.

5. For a historical run, set **Row limit** to the maximum number of matching rows to process.

   The choices shown are **100**, **1K**, **10K**, **100K** and **Custom**.

6. Set **Sampling rate** to the percentage of matching rows to evaluate.

   A lower rate runs faster and uses less budget; at 50%, about half the matching rows get a score.

<img src="/images/docs/observe/evals-schedule.png" alt="Create Task page with the added toxicity eval, Historical vs New incoming options, time window, row limit, and sampling rate, plus Test and Create Task buttons" style={{ borderRadius: '5px' }} />

*This preview has a 7D window and 50% sampling. Its mapping points to `tags`, not reply text: check the mapping in your own task before starting it.*

7. Click **Test** to dry-run the eval against a sample.
8. Click **Create Task** when the sample uses the intended field.

### What to look for in a sample

These two sample inputs from the [tone, toxicity and bias cookbook](/docs/cookbook/quickstart/tone-toxicity-bias-eval) show how to check a mapping. They are examples to test, not captured outcomes from the task pictured here.

| Mapped `output` text | Expected verdict | Evidence to check |

## Inspect a scored row

1. Return to the project's trace table.
2. Find the eval column for the task.

   In the screenshot the request status is **OK**, but the toxicity column reads **Fail**: execution status and the eval verdict answer different questions.

<img src="/images/docs/observe/evals-results-column.png" alt="Trace table with an added eval column showing Fail in the toxicity column beside OK request statuses" style={{ borderRadius: '5px' }} />

3. Open a trace to inspect its spans and any per-span scores.

Use `scores.<name>` in [dashboard filters](/docs/observe/guides/explore-dashboard/filters) or configure [alerts](/docs/observe/guides/setup-alerts) to track regressions.

## Edit a saved task

The [task SDK reference](/docs/sdk/reference/evals#evalstaskscreate) documents `client.evals.tasks` for Python and TypeScript, and the [MCP](/docs/falcon-ai/guides/use-the-mcp-server) tools `create_eval_task` and `update_eval_task`. The [create endpoint](/docs/api/eval-tasks/create-eval-task) takes a list of eval config UUIDs.

Choose a rerun mode **before** sending an update: `edit_rerun` keeps earlier results and runs missing evals; `fresh_run` clears previous results and starts over.

1. [Look up the task](/docs/api/eval-tasks/get-eval-task) by its UUID to check its project, status and current settings.
2. [Pause the task](/docs/api/eval-tasks/pause-eval-task) if it is running.
3. [Update the task](/docs/api/eval-tasks/update-eval-task) with the changed settings and your choice of rerun mode.

   Only the fields you include change.

## A row has no score

- **Not in the preview?** Check the project, unit, historical date window and row filters. A task set to new incoming data doesn't backfill earlier requests.
- **In scope but not scored?** Check the row limit and sampling rate before interpreting an empty cell as a failure. **Fail** is a verdict; a blank cell is not.
- **No usable reply in the sample?** Inspect the mapped value in **Live Preview**, correct the field or nested path, then test again. The saved task record also lists span IDs that failed during evaluation.
