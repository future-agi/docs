## About

Observe is where you monitor your AI application in production. When an answer is wrong, a request is slow, or cost spikes, it shows you exactly what your app did on that request — so you find the cause instead of guessing, and catch problems before your users report them.

You can replay any request end to end, watch quality, cost, and latency trends, group activity by conversation or by end user, score responses automatically with evals, and get alerted the moment something degrades.

Under the hood, Observe records each request as a [trace](/docs/observe/concepts/traces) — but day to day you work with the views built on top: the trace explorer, sessions, users, evals, dashboards, and alerts. If you're starting fresh, send your [first trace](/docs/observe/quickstart); if traces are already flowing, open the [trace explorer](/docs/observe/features/llm-tracing).

## Why this matters in production

LLM apps fail in ways logs don't capture — the model returns a confident wrong answer, a retrieval pulls stale context, a token bill climbs without warning. Observe gives you three concrete things:

- **Debug one bad request.** When a customer reports a wrong answer, open that exact trace and read the real prompt, retrieval, and tool calls behind it — instead of trying to reproduce it blind.
- **Catch regressions before users do.** Watch quality, latency, and cost across a release window, so a prompt change or model swap that quietly degrades output shows up as a trend, not a support ticket.
- **Control cost.** Token counts and cost ride on every model span, so you can see which steps, sessions, or users are expensive and act before the bill does.

---

## What you can do

- **Replay any request** — open a trace and step through every model call, tool call, and retrieval, with the exact inputs and outputs your app produced.
- **Track quality, cost, and latency** — chart the trends that matter and compare one release window against the next.
- **Group by conversation or user** — roll individual requests up into [sessions](/docs/observe/features/session) and [users](/docs/observe/features/users) to see whole journeys, not isolated calls.
- **Score responses automatically** — run [evals](/docs/observe/features/evals) on live traffic so quality is measured continuously, not sampled by hand.
- **Get alerted** — set thresholds on any metric and have [Alerts](/docs/observe/features/alerts) reach you by email or Slack before users notice.

## What you work with

Everything in Observe is built on the [trace](/docs/observe/concepts/traces), with the rest layered on top. Day to day, these are the objects you'll use:

| Object | What it is | Where you use it |
|---|---|---|
| **Trace** | The full record of one request, made of spans. | [Trace explorer](/docs/observe/features/llm-tracing) |
| **Span** | One step inside a trace (model, tool, retrieval, eval). | [Trace explorer](/docs/observe/features/llm-tracing) |
| **Session** | Traces from one multi-turn conversation. | [Sessions](/docs/observe/features/session) |
| **User** | All traces and sessions from one end user. | [Users](/docs/observe/features/users) |
| **Eval score** | A quality score attached to a trace or span. | [Evals](/docs/observe/features/evals) |
| **Dashboard** | Custom charts over your trace metrics. | [Dashboards](/docs/observe/features/dashboard) |
| **Alert** | A notification when a metric crosses a threshold. | [Alerts](/docs/observe/features/alerts) |

## How Observe connects to the rest of FutureAGI

- **Tracing** — Observe reads the spans your app emits through traceAI. Start with an [integration guide](/docs/traceai/auto) above, or instrument by hand with [manual instrumentation](/docs/traceai/manual-instrumentation/set-up-tracing).
- **Evaluation** — the same eval templates you use elsewhere run against production traces; see [Run evals on traces](/docs/observe/features/evals).
- **Alerts** — Observe metrics feed the [alerting system](/docs/observe/features/alerts) so threshold breaches reach you by email or Slack.
- **Voice** — connect a voice provider and calls arrive as traces; see [Voice observability](/docs/observe/features/voice).
