A [knowledge base](/docs/knowledge-base/concepts/understanding-knowledge-base) rarely stays static: policies get revised, new documents arrive, and old ones get pulled. Update its files before you generate new data from it. This guide covers the four ways to keep one current: add documents, rename it, remove individual files, and delete it altogether.

<Prerequisites title="Before you start">
- An existing knowledge base, such as `FAQ knowledge base` from [Create a knowledge base](/docs/knowledge-base/guides/create-knowledge-base).
- An account with write access. The [Viewer and Workspace Viewer roles](/docs/roles-and-permissions) cannot update or delete a knowledge base.
</Prerequisites>

## Add documents

1. Open `FAQ knowledge base` from the list at `/dashboard/knowledge`.

   The detail page at `/dashboard/knowledge/:knowledgeId` shows which files are already there.

2. Select **Add docs**.

   The **Add files** drawer says “Add more files to update your knowledge base.”

3. Select the documents to add.

   Everything you add still counts against the knowledge base's 1 GB total.

4. Select **Add**.

   A file whose name already exists in `FAQ knowledge base` is refused at submission rather than added as a duplicate.

5. Check the file list for the new names.

   Adding or removing files restarts processing. **Create Synthetic data** on the detail screen, which [grounds a synthetic dataset in this knowledge base](/docs/quickstart/generate-synthetic-data), stays disabled until the knowledge base's status reads **Completed** on that screen.

## Rename the knowledge base

1. Select the pencil on the detail screen.
2. Replace the current name in the **Knowledge base** field of the **Edit Name** dialog.
3. Select **Save** to keep the new name, or **Cancel** to keep the old one.

## Remove selected files

1. Select the file rows on the detail screen.

   The bar shows `{n} Selected`, **Delete**, and **Cancel**. Selecting all rows selects up to 20 at a time.

2. Select **Delete** on the selection bar.

   The `Delete {n} file(s)` confirmation is your last chance to stop. Check the count: there is no undo for a deleted file.

3. Confirm the deletion.

   You should see **Updating Knowledge Base**, followed by a message such as `{n} files have been deleted.` Check that only the intended files are gone.

## Delete the knowledge base

1. Select one or more knowledge bases on the knowledge base list, not on the detail screen.
2. Select **Delete** on the `{n} Selected` bar.

   Stop at **Delete Knowledge Base** or **Delete Knowledge Bases** if you meant to remove only a file. A deleted knowledge base is gone along with its files. You can delete one while its files are still processing; doing so stops that work in progress.

3. Confirm the deletion.

   For a single knowledge base, the dialog asks “Are you sure you want to delete this knowledge base?” and the success toast reads “Knowledge base deleted successfully.”

## Troubleshoot a change

<div class="sdk-ref-table">

| Symptom | What to check and do | Confirmation |
| --- | --- | --- |
| A file is refused at submission | Compare its name with the existing rows. Choose a distinct name before adding it. | The new name appears once in the list. |
| “No files selected” | Select the intended file rows before clicking **Delete**. | The selection bar shows the expected count. |
| **Create Synthetic data** is disabled | Check the status on the detail screen after adding or removing files. If extraction failed, inspect the affected file's row. | Wait for **Completed** before generating data. |

</div>
