The platform's upload dropzone caps a single file at 5 MB, which is small next to a real policy manual or a scanned contract. Reach for the SDK when:

- A file is bigger than 5 MB
- You want to point at a whole directory instead of picking files one by one
- A [knowledge base](/docs/knowledge-base) is something your own pipeline builds and refreshes on a schedule

This guide creates a knowledge base from Python, adds a file, removes one by name and deletes the knowledge base. After each change, check the stored file names and processing status before you rely on the documents.

<Prerequisites title="Before you start">
- A knowledge base name that is unique in your organization. The examples create and delete `FAQ knowledge base`.
- Your [workspace API key and secret](/docs/admin-settings/api-keys), set in the environment where Python runs.
- Practice files at the paths the examples use: `docs/refund-policy.pdf` and `docs/shipping-policy.txt` for the create call, and `docs/warranty-policy.pdf` for the update. Use made-up policies, not customer records.
</Prerequisites>

If you're creating a knowledge base from the UI and want a starting point, its create drawer has an **Import from SDK** tab that hands you a ready-made Python snippet for creating one; see [Create a knowledge base](/docs/knowledge-base/guides/create-knowledge-base) for that flow.

## Choose the helper or the client resource

The examples on this page use the Python `KnowledgeBase` helper from `fi.kb`. The same operations are also on the SDK client, as `file_knowledge_bases` in Python and `fileKnowledgeBases` in TypeScript. The [file knowledge base reference](/docs/sdk/reference/file-knowledge-bases) documents each method.

<div class="sdk-ref-table">

| Operation | Python resource on `client` | TypeScript resource on `client` |
| --- | --- | --- |
| Create a knowledge base, optionally with its first files | `file_knowledge_bases.create` | `fileKnowledgeBases.create` |
| Rename it or upload more files | `file_knowledge_bases.update` | `fileKnowledgeBases.update` |
| List files with their processing status | `file_knowledge_bases.files.list` | `fileKnowledgeBases.files.list` |
| Delete files by ID or name | `file_knowledge_bases.files.delete` | `fileKnowledgeBases.files.delete` |
| Delete knowledge bases by ID | `file_knowledge_bases.delete` | `fileKnowledgeBases.delete` |

</div>

## Install the SDK

The [Knowledge Base SDK cookbook](/docs/cookbook/using-futureagi-kb) runs these operations on Python 3.11.

```bash
pip install futureagi
```

## Set your credentials

The client reads `FI_API_KEY` and `FI_SECRET_KEY` from the environment. Substitute your matching workspace credentials for the placeholders below; do not save them in the Python file.

```bash
export FI_API_KEY="your-api-key"
export FI_SECRET_KEY="your-secret-key"
```

## Initialize the client

```python
from fi.kb import KnowledgeBase

kb = KnowledgeBase()
```

## Create a knowledge base

Call `create_kb` with a name and `file_paths`. Run only one of the two forms below, because the name has to be unique. Pass a list of paths to upload specific files:

```python
kb.create_kb(
    name="FAQ knowledge base",
    file_paths=["docs/refund-policy.pdf", "docs/shipping-policy.txt"],
)
print("Created FAQ knowledge base")
```

Or pass a directory path to upload everything in it:

```python
kb.create_kb(
    name="FAQ knowledge base",
    file_paths="docs/support_policies/",
)
```

`create_kb` returns the client itself (`self`), so calls can be chained. If the call returns without raising an exception, the knowledge base was created. The printed message is not a per-file processing result.

These rules apply whichever path you use above, since they're enforced on the server, not by the dropzone:

- Only PDF, DOCX, TXT, and RTF files are indexed
- A knowledge base holds up to 1 GB total
- The name has to be unique in your organization
- A single call can't upload two files with the same name

`create_kb` fails on any of the above. Fix the file, rename, or split the upload, then re-run.

## Add a file

`update_kb` adds files to an existing knowledge base. Pass the knowledge base's name and the new `file_paths`:

```python
kb.update_kb(
    kb_name="FAQ knowledge base",
    file_paths=["docs/warranty-policy.pdf"],
)
```

## Check the files before removing one

1. List the files with `file_knowledge_bases.files.list` and the knowledge base ID, which `file_knowledge_bases.list_names` returns. Or open the knowledge base in the dashboard.
2. Find `refund-policy.pdf`, `shipping-policy.txt` and the newly added `warranty-policy.pdf`, if you created the knowledge base from the list of paths.
3. Read each file's `status`. Each row also has an `error` field; the [file response model](/docs/sdk/reference/knowledge-bases-models#legacyknowledgebasefilerow) lists every field.

## Remove a file by name

`delete_files_from_kb` removes specific files. It takes the file names as they're stored in the knowledge base, not file IDs: that's the file's base name, not its local path. The `create_kb` call above uploads `docs/shipping-policy.txt`, and it's removed here by its base name, `shipping-policy.txt`:

```python
kb.delete_files_from_kb(
    file_names=["shipping-policy.txt"],
    kb_name="FAQ knowledge base",
)
```

List the files again. You should see the refund and warranty files but not `shipping-policy.txt`.

## Delete the knowledge base

`delete_kb` removes one or more knowledge bases at once, by name or by ID:

```python
kb.delete_kb(kb_names="FAQ knowledge base")
```

To confirm, list the knowledge bases in the workspace with `file_knowledge_bases.list` and check that `FAQ knowledge base` is gone.

For the by-ID form and its full parameters, see the [Knowledge Base SDK reference](/docs/sdk/knowledgebase).

## Troubleshooting

- **A file is not indexed.** Check that the path exists relative to the directory where Python runs and that the file is a PDF, DOCX, TXT or RTF.
- **`create_kb` fails on names or size.** Check for two files with the same name in one call, a knowledge base name already in use, or a knowledge base over the 1 GB total.
