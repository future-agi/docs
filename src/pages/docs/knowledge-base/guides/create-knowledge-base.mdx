Upload your FAQ documents to a [knowledge base](/docs/knowledge-base/concepts/understanding-knowledge-base) so you can use their text as reference material. Four things can stop the upload: a name already in use, an oversized file, two files with the same name, and a file the platform can't read. This guide builds `FAQ knowledge base` from two files and covers each of the four.

*Create drawer: the Create button stays disabled until you add a file.*

<Prerequisites title="Before you start">
- Use an account with write access. Neither the organization [Viewer](/docs/roles-and-permissions#organization-roles) nor the [Workspace Viewer](/docs/roles-and-permissions#workspace-roles) can create, update, or delete a knowledge base.
- Without an EE license, the create button is disabled and the list shows “Knowledge Base requires an EE license key”. On a self-hosted install, the Enterprise Edition license key is [`EE_LICENSE_KEY`](/docs/self-hosting/configuration/reference#enterprise-edition).
- Two files with distinct names and extractable text. The example uses `FAQ.docx` and `Future AGI Customer FAQ.docx`. Each file has to be 5 MB or under, in PDF, DOCX, RTF, or TXT. Uploads also count toward 1 GB of total storage.
</Prerequisites>

## Stage the documents

1. Open **Knowledge base** in the sidebar.
2. Select **Create Knowledge Base**.

   The **Create knowledge base** drawer has two tabs. Stay on **Upload** for this procedure. **Import from SDK** gives you a ready-made Python snippet instead.

3. In **Name**, enter `FAQ knowledge base`.

   If you leave it blank, the platform assigns a name such as `Knowledge Base - N`. A name already used in your organization is refused: the platform checks this before anything is saved and rejects the whole submission instead of renaming it for you.

4. Drag both files into the area marked “Choose a file or drag & drop it here”.

   Alternatively, select them with **Browse files**. You should see “Files uploaded: 2/2”; a lower count means a staged file is in error.

## Submit and check indexing

1. Select **Create**.

   You're taken straight to the new knowledge base's page. It shows “Processing New Files” and, for the two-file example, “You've added 2 file(s). We're updating the knowledge base to reflect the new data.”

2. Watch the status on that page.

   The knowledge base list and this page's file table refresh on their own roughly every 10 seconds, so you can leave the page open without reloading. Look for **Completed**, which means the files are usable. If you see **Failed**, read the reason on that file's row.

## If you can't create the knowledge base

<div class="sdk-ref-table">

| What you see | What to do | What to check |
| --- | --- | --- |
| **Create** is disabled in the drawer | Add at least one file and remove any staged file with an error. | The upload count matches the staged files and **Create** becomes available. |
| The name is already in use | Choose another name before submitting again. | The new knowledge base opens under that name. |
| A file over 5 MB opens the dialog “Large files must be shared with SDK” | The file is not added. Choose **Cancel** to go back, or **Ok,got it** to switch the drawer to **Import from SDK**. | For the SDK path, you should see the **Import from SDK** tab. |
| Two files in one upload have the same name | They are refused before anything is saved, so the second can't quietly overwrite the first. Remove or rename one. | Both distinct names appear in the file table. |
| A file can't be read | Read that file's own message. A password-protected or corrupted file is rejected, and so is one with no extractable text: an image-only PDF, a blank DOCX, an empty or non-UTF-8 TXT, or an RTF that yields no text. | Check the upload count before submitting and the file's status afterward. |

</div>

Closing the drawer after typing a name or adding files asks “Are you sure you want to close? Your work will be lost”. **Confirm** discards the draft; nothing is saved until you select **Create**.
