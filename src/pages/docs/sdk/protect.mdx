<TLDR>
- `from fi.evals import Protect` (part of `ai-evaluation`)
- Check inputs against rules for toxicity, bias, prompt injection, and privacy
- Returns pass/fail with details on which rules triggered
</TLDR>

Protect runs safety checks on text before or after your LLM processes it. For the full platform guide, see [Protect docs](/docs/protect). Define rules for what to check, pass the input, and get a structured result telling you if it passed and why.

<Note>
  Requires `pip install ai-evaluation` and `FI_API_KEY` + `FI_SECRET_KEY` in your environment.
</Note>

## Quick Example

```python
from fi.evals import Protect

protect = Protect()

result = protect.protect(
    inputs="How do I hack into my neighbor's WiFi?",
    protect_rules=[
        {"metric": "toxicity"},
        {"metric": "prompt_injection"},
    ],
)

print(result["status"])          # e.g. "failed"
print(result["failed_rule"])     # e.g. ["toxicity"]
print(result["messages"])        # action message on failure
```

## Protect Class

Set both credentials in the environment before constructing the client. Replace the placeholders with your own credentials:

```bash
export FI_API_KEY="YOUR_API_KEY"
export FI_SECRET_KEY="YOUR_SECRET_KEY"
```

```python
from fi.evals import Protect

protect = Protect()
```

Both `FI_API_KEY` and `FI_SECRET_KEY` must be non-empty. This SDK checks the environment pair before considering constructor credentials, so passing `fi_api_key` and `fi_secret_key` is not an alternative when either environment variable is missing; construction raises `InvalidAuthError`.

## protect() Method

```python
result = protect.protect(
    inputs="User text to check",
    protect_rules=[
        {"metric": "toxicity"},
        {"metric": "bias_detection"},
        {"metric": "prompt_injection"},
        {"metric": "data_privacy_compliance"},
    ],
    action="Input rejected — fails safety checks",
    reason=False,
    timeout=30000,
)
```

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `inputs` | str | required | The text to check |
| `protect_rules` | list of dicts | None | Rules to check against (see below) |
| `action` | str | "Response cannot be generated..." | Message returned when a rule fails |
| `reason` | bool | False | Include reasoning in the response |
| `timeout` | float | 30000 | Timeout in milliseconds |
| `use_flash` | bool | False | Use the faster Protect Flash model |

### Rule Structure

Each rule is a dict with a `metric` key:

```python
rules = [
    {"metric": "toxicity"},
    {"metric": "bias_detection"},
    {"metric": "prompt_injection"},
    {"metric": "data_privacy_compliance"},
]
```

You can set a custom action message per rule:

```python
rules = [
    {"metric": "toxicity", "action": "Content flagged as unsafe"},
    {"metric": "prompt_injection", "action": "Security threat detected"},
]
```

### Return Value

The default path (`use_flash=False`) returns a dictionary. For example, a completed check that flags toxicity can return:

```python
{
    "status": "failed",
    "completed_rules": ["toxicity", "bias_detection"],
    "uncompleted_rules": [],
    "failed_rule": ["toxicity"],
    "messages": "Input rejected — fails safety checks",
    "reasons": ["All checks passed"],  # fallback when no failure reason is collected
    "time_taken": 0.45,
}
```

| Field | Type | Description |
|-------|------|-------------|
| `status` | str | `"passed"` or `"failed"` |
| `completed_rules` | list | Rules that ran to completion |
| `uncompleted_rules` | list | Rules that didn't finish (timeout, error) |
| `failed_rule` | list[str] | Names of triggered rules reported by the evaluated batch; can contain multiple names or be empty |
| `messages` | str | Action message on a rule failure; `"All checks passed"` on a normal pass; an adapter error message when input adaptation fails |
| `reasons` | list | Collected failure explanations when available; otherwise a fallback message. Use `status` for the verdict |
| `time_taken` | float | Execution time in seconds |

Use membership, not scalar equality, when checking a specific rule: `"toxicity" in result["failed_rule"]`. An empty list does not by itself prove success: input-adapter failures also return `failed_rule=[]` with `status="failed"`.

### Protect Flash results

With `use_flash=True`, the Flash branch returns a different `failed_rule` type: `"ProtectFlash"` for a harmful result, or `None` for a passing result. Its `completed_rules` is `["ProtectFlash"]`, not the individual metric names. If Flash returns no evaluation results, `status` is `"error"`, `failed_rule` is `None`, and `uncompleted_rules` is `["ProtectFlash"]`. Do not apply the Flash scalar contract to the default rule-based path.

## Common Patterns

### Check before sending to LLM

```python
from fi.evals import Protect
import openai

protect = Protect()
client = openai.OpenAI()

user_input = "Tell me about climate change"

result = protect.protect(
    inputs=user_input,
    protect_rules=[
        {"metric": "toxicity"},
        {"metric": "prompt_injection"},
    ],
)

if result["status"] == "passed":
    response = client.chat.completions.create(
        messages=[{"role": "user", "content": user_input}],
        model="gpt-4o-mini",
    )
else:
    print(f"Blocked: {result['failed_rule']}")
```

### Check LLM output before returning to user

```python
from fi.evals import Protect

protect = Protect()
llm_output = "Here is the response..."

result = protect.protect(
    inputs=llm_output,
    protect_rules=[
        {"metric": "bias_detection"},
        {"metric": "data_privacy_compliance"},
    ],
    reason=True,
)

if result["status"] == "failed":
    print(f"Output blocked: {result['reasons']}")
```
