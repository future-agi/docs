## Pass inputs to `evaluate()`

The current `futureagi` package does not provide `fi.testcase` or the `TestCase`, `LLMTestCase`, `ConversationalTestCase`, and `MLLMTestCase` classes. Pass the inputs required by your chosen evaluation as keyword arguments to `fi.evals.evaluate()` instead.

For this local metric example, use Python 3.11+ and install the evaluation extra:

```bash
pip install "futureagi[evals]"
```

```python
from fi.evals import evaluate

result = evaluate(
    "contains",
    output="The capital of France is Paris.",
    keyword="Paris",
)
print(result.score)
```

`evaluate()` accepts a metric or template name and evaluation-specific inputs such as `output`, `input`, `context`, and `keyword`. Input names depend on the evaluation; there is no single test-case class that supplies the fields for every metric.

## Metric input models

For APIs that accept metric input models, the current models live in `fi.evals.types`:

| Model | Fields |
|---|---|
| `TextMetricInput` | Required `response: str`; optional `expected_response: str` or list of strings. |
| `JsonMetricInput` | Required `response: str`, dictionary, or list; optional `expected_response` of the same types and optional `schema` as a string or dictionary. |

```python
from fi.evals.types import TextMetricInput

text_input = TextMetricInput(
    response="The capital of France is Paris.",
    expected_response="Paris",
)
```

These models do not replace the keyword arguments to `evaluate()` automatically. Use the input names expected by the metric or template you selected.
