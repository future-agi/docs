You changed who your agent deals with, and want to know whether it still passes. This page does the whole loop from code: add an actor to an [environment](/docs/environments/concepts/understanding-environments), save and prove the change, run a seeded test, and read what happened in each call. Each section adds one step to the same script.

<Note>
You need an environment in **Ready** status, its ID (the last part of its address in the app), and an API key and secret key from your workspace settings. Set `FI_API_KEY`, `FI_SECRET_KEY` and `FI_WORKSPACE_ID` in your shell. The methods on this page need a Future AGI SDK release that includes them; the [Simulation reference](/docs/sdk/reference/simulation) lists the methods of the release you have installed.
</Note>

## Connect the SDK

Install the SDK and create a client. It reads your keys from the shell.

<Tabs>

  </Tab>

The rest of the page is in Python. The TypeScript client has the same methods under `client.simulation`, named in camelCase (`actors.setLimits`, `executions.listCalls`), with the keyword arguments passed as one object: `await client.simulation.environments.run(envId, { trials: 1, seed: "7" })`.

## Add an actor to the draft

An **actor** is someone in a scenario besides your agent and the caller, such as a manager who approves refunds. Changes to actors go into the environment's **draft**, its unsaved changes. Runs keep using the saved version until you save the draft, so trying a change never affects a run in progress.

```python
actors = client.simulation.environments.actors

cast = actors.list(env_id)
new = {"name": "Dana Brooks", "role": "Store manager", "side": "world"}

check = actors.validate(env_id, op="create", changes=new, new_id="dana_brooks")
if check.problems:
    raise SystemExit(check.problems)
actors.create(env_id, changes=new, new_id="dana_brooks", expected_revision=cast.revision)
```

`validate` says what a create, change or removal would do, without writing anything, and it costs nothing. It names the field at fault, such as an ID with a hyphen (actor IDs take lowercase letters, digits and underscores). Pass `expected_revision` from the last `list`, so a draft someone else changed in the meantime is refused instead of overwritten.

The other actor methods follow the same pattern:

- `actors.get(env_id, "dana_brooks")`: what one actor sees and may do, and what it never sees
- `actors.update` and `actors.delete`: change or remove one actor. A scenario that includes an actor blocks its removal
- `actors.set_limits(env_id, limits={"max_active": 3})`: replace the cast's limits. A limit you leave out takes the channel's default
- `actors.accept_unresolved`: accept the cast as written for one point the builder couldn't turn into an actor, named as `list` returns it under `unresolved`

## Save the draft

Where your environment can prove its scenarios, a changed cast is validated before it is saved, the way **Validate** comes before **Save** in the app. Validation builds the new versions in a **build sandbox**, a temporary copy of the environment, and replays scenarios against your agent there. It makes model calls and takes a few minutes.

`drafts.list` reports where validation stands:

| State | What it means | What to do |
|---|---|---|
| `validating` | Still running | Wait and read `drafts.list` again |
| `ready` | The changed cast passed | Save the candidates |
| `check_unavailable` | The check couldn't run, for a reason on our side | Save; it goes ahead unchecked, as a run would |
| `retry`, `outdated`, `superseded` | Nothing proved this draft yet, the draft changed after validating, or the saved versions moved under it | Validate again |
| `failed` | Your agent failed the check | Fix the change before saving |
| `unavailable` | This environment can't validate | Save the draft itself |

```python
import time

drafts = client.simulation.environments.drafts

def start_validation():
    listed = drafts.list(env_id)
    review = drafts.review(env_id)
    drafts.validate(
        env_id,
        expected_revisions={"environment": listed.environment.revision},
        expected_review_digest=review.review_digest,
    )
    return review

review = start_validation()
tries = 1
while True:
    listed = drafts.list(env_id)
    state = listed.validation.state if listed.validation else "unavailable"
    if state == "validating":
        time.sleep(20)
    elif state in ("retry", "outdated", "superseded") and tries < 3:
        review = start_validation()
        tries += 1
    else:
        break

if state in ("ready", "check_unavailable"):
    drafts.save(
        env_id,
        candidates={
            "environment_version_id": listed.candidates.environment_version_id,
            "suite_version_id": listed.candidates.suite_version_id,
        },
        expected_review_digest=review.review_digest,
        name="Add Dana Brooks",
        idempotency_key="add-dana-brooks",
    )
elif state == "unavailable":
    drafts.save(
        env_id,
        drafts=[{"piece": "environment", "expected_parent_id": listed.environment.parent_id}],
        idempotency_key="add-dana-brooks",
    )
else:
    raise SystemExit(f"Not saved: {state}")
```

`review_digest` ties the save to the changes you reviewed, so a change made after you looked is never saved unseen. Each validation makes model calls, so the script validates at most three times. The same `idempotency_key` sent twice saves once.

## Prove and archive scenarios

A scenario is **proved** when its checks pass the expected handling and fail a deliberately wrong answer, so a pass means your agent did the right thing, as [Work with scenarios](/docs/environments/guides/work-with-scenarios#prove-and-archive-scenarios) describes. After a change, prove only the scenarios it touched; each one replays in a build sandbox.

```python
scenarios = client.simulation.environments.scenarios
key = "refund-needs-manager-approval"

started = scenarios.validate(env_id, keys=[key])
while True:
    status = scenarios.validation_status(env_id, job_id=started.job_id)
    if status.state != "validating":
        break
    time.sleep(20)
print(status.proved, "of", status.total, "proved")
```

To take a scenario out of future runs without losing its past runs, archive it; `restore` brings it back:

```python
scenarios.archive(env_id, key, reason="duplicate")
scenarios.restore(env_id, key)
```

`client.simulation.jobs.scenarios.list(env_id, lifecycle="archived")` lists the scenarios in one state. `scenarios.revisions(env_id, key)` shows how a scenario changed across saved versions, and `scenarios.records(env_id, key, table="orders")` returns the seeded rows of one table of the **World**, the test copy of your agent's data, so you can pick a real record for a scenario. Where the world can't list its rows, it answers with `available` false and no rows.

## Check that a run will start

**Run readiness** says whether a **pairing**, one agent version with one environment and suite version, is ready to run. Leave a version out to use the environment's default:

```python
report = client.simulation.environments.readiness.get(env_id, keys=[key], trials=1)
print(report.answer.kind, report.blockers)
```

The answer is `ready`, `blocked`, `stale`, `unchecked` or `validating`. To check a version other than the default, pass it, such as `agent_version_id="..."`. `readiness.cases` lists the scenarios held back by one check, `readiness.history` lists the pairings already certified, and `readiness.recheck` checks the pairing again without a run. A recheck of a pairing that isn't certified yet replays in a build sandbox.

## Run with a seed and read the calls

A **seed** draws the same personas and variations again, so two runs with one seed differ only by what you changed. A run plays your agent and simulated people, so it may incur usage charges.

```python
run = client.simulation.environments.run(
    env_id, scenario_ids=[key], trials=1, seed="7",
    idempotency_key="after-adding-dana",
)

for row in client.simulation.executions.list_calls(run.test_execution_id):
    print(row["scenario"], row["outcome"])
    call = client.simulation.calls.get(row["id"])
```

Each row is one call, one trial of one scenario, with its `outcome`; `row["id"]` is its call ID. A run takes a few minutes to finish, and calls appear as they complete. `calls.get` returns its transcript, tool calls, checks and what it changed in the World, the same as a call's page in [Read run results](/docs/environments/guides/read-run-results). Sending the same `idempotency_key` again, for example after a timeout, returns the same run instead of starting a second one.

## Read a multi-agent call

When your agent is a multi-agent app, a coordinator that hands work to other agents, `calls.workers` returns which participants acted in one call and what each did, read from the traces your app sent:

```python
workers = client.simulation.calls.workers(row["id"])
```

While the traces are still arriving, it returns `pending` and `next_read_at`; read it again after that time. For a call that handed nothing to another agent, it returns `None`.
