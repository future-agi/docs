<TLDR>
Use `fi.simulate.TestRunner` from the Agent Learning Kit to test a Python callback or a voice agent in a LiveKit room. Both modes return a `TestReport` to your process. For hosted runs, use [Environments](/docs/environments).
</TLDR>

## Two local modes

| Mode | Pass to `run_test()` | What you get | Requirements |
|---|---|---|---|
| Text | `agent_callback` and a `scenario` or `topic` | A case per persona, with a transcript, structured messages, and any tool calls your callback exposes | Base kit. A plain Python callback needs no credentials. |
| LiveKit voice | `agent_definition`, `livekit_runtime`, and a `scenario` | A case per caller, with transcript, status, and optional recording paths | The `livekit` extra, LiveKit credentials, a voice agent in the target room or available for dispatch, and the model and speech providers' credentials |

These runs do not create a hosted simulation by default. An `outcome` on a persona describes a goal; it is not an evaluation score. Score a transcript separately if you need a pass/fail decision.

## Quick example: local text

Start in an empty directory with Python 3.12:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install agent-learning-kit==0.3.7
```

Save this as `returns.py` and run `python returns.py`. Both personas ask about the same store policy. The callback stands in for your agent: replace it with your application logic when you are ready.

```python
import asyncio
from fi.simulate import AgentInput, Persona, Scenario, TestRunner

scenario = Scenario(name="ridgeline-returns", dataset=[
    Persona(persona={"name": "Casey"}, situation="I need to return my jacket.",
            outcome="Learn the return window."),
    Persona(persona={"name": "Morgan"}, situation="Can I return unworn hiking boots?",
            outcome="Learn where to start a return."),
])

async def returns_agent(turn: AgentInput) -> str:
    question = (turn.new_message or {}).get("content", "").lower()
    if "boot" in question:
        return "Start a return from your Ridgeline order page."
    return "You have 30 days from delivery to return unworn gear."

async def main():
    report = await TestRunner().run_test(scenario=scenario, agent_callback=returns_agent,
                                         min_turns=1, max_turns=1)
    for case in report.results:
        print(case.persona.persona["name"])
        print(case.transcript)

if __name__ == "__main__":
    asyncio.run(main())
```

You should see a separate transcript for Casey and Morgan. The one-turn limit makes the first reply easy to inspect. Raise `max_turns` to exercise follow-up replies.

## TestRunner.run_test()

Await the method and read `report.results`. For local text, pass a callback; for LiveKit, pass a target definition instead. Use keyword arguments so the target, runtime, caller, and scenario do not get mixed up.

| Parameter | Default | Mode | Meaning |
|---|---|---|---|
| `scenario` | `None` | Both | A named collection of personas to run. |
| `agent_callback` | `None` | Text | Your callable or `AgentWrapper`. |
| `topic`, `num_scenarios` | `None`, `1` | Text | When there is no explicit scenario, generate personas from this topic. |
| `min_turns`, `max_turns` | `2`, `6` | Text | Turn bounds for the local conversation. |
| `environment` | `None` | Text | Optional adapters, such as a `ToolMockEnvironment` for local tool execution. |
| `agent_definition` | `None` | LiveKit | The voice agent under test. In an external room, `target_participant_identity` can identify the target. |
| `livekit_runtime` | `None` | LiveKit | `LiveKitSimulatorRuntime` sets the server URL, room name, and room lifecycle. Use `room_mode="external"` to join the room your agent is already in. |
| `simulator` | `None` | LiveKit | A `SimulatorAgentDefinition` configures the caller's LLM, speech-to-text, and text-to-speech providers separately from the target. |
| `record_audio` | `False` | LiveKit | Capture per-speaker and mixed audio. Inspect the returned paths rather than assuming a recording exists. |
| `min_turn_messages`, `max_seconds` | `8`, `45.0` | LiveKit | Minimum message target and conversation time limit. Connection and cleanup take additional time. |

For the full voice example, including installation, a working target agent, and a recording, see [Test a local voice agent](/docs/cookbook/simulate-sdk).

## Agent callback

Return a string for a text-only reply, or `AgentResponse` when the turn includes structured data such as a tool call. To see the difference, save this as `lookup.py` next to `returns.py` and run `python lookup.py`. The mock returns a fixture, not a live shipping status.

```python
import asyncio
from fi.simulate import AgentInput, AgentResponse, Persona, Scenario, TestRunner, ToolMockEnvironment

async def lookup_agent(turn: AgentInput) -> AgentResponse:
    return AgentResponse(content="I'll look that up for you.", tool_calls=[{
        "id": f"lookup-{turn.turn_index}", "type": "function",
        "function": {"name": "lookup_order", "arguments": {"order_id": "ORD-12345"}},
    }])

async def main():
    scenario = Scenario(name="tracking", dataset=[Persona(
        persona={"name": "Casey"}, situation="Where is order ORD-12345?",
        outcome="Find the shipping status.",
    )])
    report = await TestRunner().run_test(
        agent_callback=lookup_agent, scenario=scenario, min_turns=1, max_turns=1,
        environment=ToolMockEnvironment({"lookup_order": "Shipped"}),
    )
    case = report.results[0]
    print("Requested:", case.tool_calls[0]["function"]["name"])
    for message in case.messages:
        if message["role"] == "tool":
            print("Tool result:", message["content"])

if __name__ == "__main__":
    asyncio.run(main())
```

### AgentInput

| Field | Type | Meaning |
|---|---|---|
| `thread_id` | `str` | Conversation ID |
| `messages` | `list[dict]` | Conversation history, including the latest message |
| `new_message` | `dict` or `None` | Latest message to answer |
| `turn_index` | `int` or `None` | Current turn index, starting at zero in local text mode |
| `execution_id` | `str` or `None` | Execution tracking ID |

### AgentResponse

| Field | Type | Meaning |
|---|---|---|
| `content` | `str` | Agent's text response |
| `tool_calls` | `list[dict]` or `None` | Requested tools and arguments |
| `tool_responses` | `list[dict]` or `None` | Tool result messages if your agent already executed the calls; match each `tool_call_id` to a call ID |
| `metadata` | `dict` or `None` | Additional response metadata |

## Scenarios and personas

A `Scenario` has a `name` and a `dataset` of `Persona` objects. Here `dataset` means the list in your Python program, not a dataset you must upload. Give each persona a `persona` dictionary, a `situation` to react to, and an `outcome` to aim for. For a voice case, also inspect `case.metadata["status"]`: even a failed or timed-out call may have a partial transcript.
