<TLDR>
- Python: `from fi import Client`; TypeScript: `import { Client } from "@future-agi/sdk"`
- `client.experiments.create` starts a run with at least one configuration and one evaluation
- Pass split IDs through Python `extra_body` or TypeScript `extraBody` in the second options argument
</TLDR>

An experiment runs prompt or agent configurations against the same dataset rows and scores their outputs with evaluations. For the platform workflow, see [Run an experiment](/docs/dataset/guides/run-an-experiment).

These examples use the **platform Client**, not the separate `FutureAGIClient` facade or the Python `Dataset` helper.

## Create an Experiment on Selected Splits

Before running the example, replace each `your-...` placeholder with an existing UUID from your workspace:

- A dataset and a split in that dataset with at least one live member row.
- A saved, non-draft prompt version and the prompt it belongs to. For a minimal first run, use a prompt without input variables. For prompts that use dataset inputs, configure their mappings as described in the [experiment guide](/docs/dataset/guides/run-an-experiment).
- An evaluation template whose only required input is `output`. The example maps that input to the experiment's generated output. If your template needs other inputs or settings, supply those in its `config` too.

Choose a model available to your workspace; `gpt-4o-mini` is the example prompt model below. Creating an experiment starts execution; it does not wait for the run to finish.

<Tabs>
  <Tab title="Python">
    ```python
    from fi import Client

    client = Client()
    result = client.experiments.create(
        name="split-output-quality",
        dataset_id="your-dataset-uuid",
        experiment_type="llm",
        prompt_config=[{
            "name": "baseline",
            "prompt_id": "your-prompt-uuid",
            "prompt_version": "your-prompt-version-uuid",
            "model": "gpt-4o-mini",
        }],
        user_eval_metrics=[{
            "template_id": "your-output-eval-template-uuid",
            "name": "output_quality",
            "model": "turing_flash",
            "config": {"mapping": {"output": "output"}},
        }],
        extra_body={"split_ids": ["your-split-uuid"]},
    )
    print(result)
    ```
  </Tab>
  <Tab title="TypeScript">
    ```typescript
    import { Client } from "@future-agi/sdk";

    const client = new Client();
    const result = await client.experiments.create({
      name: "split-output-quality",
      dataset_id: "your-dataset-uuid",
      experiment_type: "llm",
      prompt_config: [{
        name: "baseline",
        prompt_id: "your-prompt-uuid",
        prompt_version: "your-prompt-version-uuid",
        model: "gpt-4o-mini",
      }],
      user_eval_metrics: [{
        template_id: "your-output-eval-template-uuid",
        name: "output_quality",
        model: "turing_flash",
        config: { mapping: { output: "output" } },
      }],
    }, {
      extraBody: { split_ids: ["your-split-uuid"] },
    });
    console.log(result);
    ```
  </Tab>
</Tabs>

The create result is a message string containing `experiment_id=<uuid>`, not an object with an `experiment_id` property. Use that UUID with `client.experiments.get` to follow the run.

### Required configuration

| Field | What to supply |
|-------|----------------|
| `name` | Experiment name |
| `dataset_id` | Dataset UUID |
| `prompt_config` | A nonempty list of prompt or agent configurations |
| `user_eval_metrics` | A nonempty list of evaluations, each with `template_id`, `name`, and `config` |
| `experiment_type` | `"llm"` for the prompt or agent examples on this page; also the default |

For an LLM prompt entry, provide `prompt_id`, `prompt_version`, and `model`. Each entry represents one model; use multiple entries to compare models. An agent entry instead needs both `agent_id` and `agent_version`, with no prompt identifiers, model, or inline messages. Its saved version must belong to that agent and must not be a draft.

Do not send empty `prompt_config` or `user_eval_metrics` arrays: the API rejects both. An evaluation's `config.mapping` must include all inputs required by the selected template. The mapping value `"output"` refers to each configuration's generated output, not a column named `output` in the source dataset.

### Split selection rules

- `split_ids` contains 1–100 distinct UUIDs, all belonging to the selected dataset.
- Selected splits form a union of their live member rows. A row in multiple selected splits is selected once.
- An empty resulting selection is rejected. A split with no live rows does not mean “use the whole dataset.”
- Split selection does not require `row_ids` or `sample`.

<Note>
  `split_ids` is not a first-class parameter of `experiments.create`. Use Python's `extra_body={"split_ids": [...]}` or TypeScript's second argument `{ extraBody: { split_ids: [...] } }`, as shown above. To run across the dataset without selecting splits, omit that extra body from the example.
</Note>

## Get an Experiment

Use the experiment UUID from the create message or a list result. Continue with the `client` initialized above:

<Tabs>
  <Tab title="Python">
    ```python
    experiment = client.experiments.get("your-experiment-uuid")
    print(experiment.id, experiment.name, experiment.status)
    ```
  </Tab>
  <Tab title="TypeScript">
    ```typescript
    const experiment = await client.experiments.get("your-experiment-uuid");
    console.log(experiment.id, experiment.name, experiment.status);
    ```
  </Tab>
</Tabs>

The detail response includes the experiment's status and its prompt, agent, and evaluation configurations.

## List Experiments

Iterate the returned pager to list experiments, optionally filtering by dataset:

<Tabs>
  <Tab title="Python">
    ```python
    for experiment in client.experiments.list(dataset_id="your-dataset-uuid"):
        print(experiment.id, experiment.name, experiment.status)
    ```
  </Tab>
  <Tab title="TypeScript">
    ```typescript
    for await (const experiment of client.experiments.list({
      dataset_id: "your-dataset-uuid",
    })) {
      console.log(experiment.id, experiment.name, experiment.status);
    }
    ```
  </Tab>
</Tabs>

Omit the dataset filter to list experiments in the current workspace. Use `search` to search names or `ordering: "-created_at"` in TypeScript (`ordering="-created_at"` in Python) to request newest first.
