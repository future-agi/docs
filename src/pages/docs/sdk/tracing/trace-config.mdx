## About

Use `TraceConfig` to keep model names and token counts in a trace without recording a customer's message, photo, or tool arguments. Masking changes what the tracer records, not what your application sends to the model.

## Choose what to hide

Suppose the Ridgeline Outfitters support agent accepts a photo of a damaged item and calls an order lookup tool. To keep both the lookup arguments and the result out of supported spans, set these variables **before starting the application**:

```bash
export FI_HIDE_INPUTS=true
export FI_HIDE_OUTPUTS=true
export FI_HIDE_ERROR_DETAILS=true
```

Use the broad input and output switches when content must stay private. Hiding only messages is narrower: a tool's arguments can be recorded as separate attributes, not just inside a message. Hiding just the image does not hide the order number.

| On a supported span | What the broad switches do |
| --- | --- |
| Inputs | `FI_HIDE_INPUTS` hides structured input message content and masks opaque `input.value`, prompt-template variables, tool definitions, `gen_ai.tool.call.arguments`, and retrieval queries. |
| Outputs | `FI_HIDE_OUTPUTS` hides structured output message content and masks opaque `output.value`, `gen_ai.tool.call.result`, and returned retrieval documents. |
| Mixed content | Either switch hides the aggregate `gen_ai.tool.call`, which can contain both arguments and results. Both `raw.input` and `raw.output` payloads are withheld even if only one side is hidden: a raw response can echo the request. |
| Typed values | Tool argument and result keys match by name, not by value type. For example, `gen_ai.tool.call.arguments.quantity` is private input even if the quantity is a number. A masked value can be absent or replaced by `__REDACTED__`, rather than a value of its original type. |
| Operational metadata | Separate model, usage, and timing fields remain available if the instrumentor recorded them. A token count buried inside a raw response does not survive as part of that response. |

## Match the policy to your SDK

The examples below use Python `fi-instrumentation-otel` 1.5.1 and Node.js `@traceai/fi-core` 1.4.1. The Java column describes `traceai-java-core` 1.4.1, not the JVM agent. These versions belong to the application that creates the spans. Upgrading the collector alone does not change what the application records. An explicit wrapper setting overrides its environment variable for that wrapper.

| Control | Python | Node.js | Java core |
| --- | --- | --- | --- |
| Apply settings | Pass `TraceConfig(...)` as `config` to `FITracer` or a supporting instrumentor. | Pass `traceConfig` to `FITracer` or a supporting instrumentor, not to `register()`. | Pass `TraceConfig.builder().build()` to `TraceAI.init()`. Use `FITracer` setters for custom span content. |
| Broad switches (off by default) | `hide_inputs`, `hide_outputs` | `hideInputs`, `hideOutputs` | `hideInputs`, `hideOutputs` |
| Message switches (off by default) | `hide_input_messages`, `hide_output_messages` | `hideInputMessages`, `hideOutputMessages` | `hideInputMessages`, `hideOutputMessages` |
| Finer controls (off by default) | `hide_input_text`, `hide_output_text`, `hide_input_images`, `hide_embedding_vectors`, `hide_llm_invocation_parameters` | `hideInputText`, `hideOutputText`, `hideInputImages`, `hideEmbeddingVectors` | No separate text, image, vector, or invocation-parameter switch on this builder. |
| Raw request and response | Both omitted when any broad, message, or finer control above is on. | Both omitted under any of those content controls. | With any of the four content switches on, `setRawInput` and `setRawOutput` skip both bodies. The masker also recognizes `fi.raw_input` and `fi.raw_output`. |
| Inline images | `base64_image_max_length` defaults to `0`: recognized image payloads are redacted. A positive cap can admit an eligible image at or below the cap. An oversized image is **replaced**, not cut to a prefix. | `base64ImageMaxLength` also defaults to `0`. Even with a positive cap, the FI media policy omits recognized base64 image payloads. Raising the cap does **not** enable image export. | No base64 image cap on the builder. Use `hideInputs(true)` for recognized image fields, including `gen_ai.input.images`. `hideInputMessages(true)` alone hides images inside input messages, not that separate attribute. The JVM agent separately omits recognized inline media from its export. |
| Error details | `hide_error_details` is derived from content settings unless explicitly set. | `hideErrorDetails` on the wrapper follows the same default. The separate FI export filter can also hide error details when request parameters are hidden. | `hideErrorDetails` defaults to `false` independently of the content settings. Set it explicitly if errors could repeat an order number. |

Node can suppress additional tool fields even under a one-direction policy. Do not rely on the other direction staying visible.

The message switches also mask the corresponding opaque `input.value` or `output.value`: the SDK cannot separate text from a serialized body just by its attribute name. A message switch cannot turn off a broad switch that is already on. Error-detail hiding or PII matching alone does not turn off raw body capture.

In Python and Node, set `FI_BASE64_IMAGE_MAX_LENGTH` to a nonnegative integer. An invalid cap falls back to `0`. The cap checks inline image data, not remote image URLs. Neither the cap nor the hide switches erase spans already exported.

## Verify the exported attributes

Run this check in a fresh shell without `FI_HIDE_*`, `FI_BASE64_IMAGE_MAX_LENGTH`, or other tracing overrides. If you just set the three switches above, run `unset FI_HIDE_INPUTS FI_HIDE_OUTPUTS FI_HIDE_ERROR_DETAILS` in that separate shell. The example uses a one-pixel GIF and a made-up order reference. The exporter stores spans **in memory**: you need no credentials, collector, or model call.

For Python, run `python3.12 -m venv .venv && source .venv/bin/activate && python -m pip install fi-instrumentation-otel==1.5.1`, or run `npm install @traceai/fi-core@1.4.1 @opentelemetry/sdk-trace-base@2.0.1` in an empty Node project. Save the matching example as `check_mask.py` or `check_mask.cjs` and run `python check_mask.py > python-spans.jsonl` or `node check_mask.cjs > node-spans.jsonl`. Open the resulting file: each line contains one span name and its recorded attributes.

<CodeGroup titles={["Python", "Node.js"]}>

```python
import json
from fi_instrumentation import FITracer, TraceConfig
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import SimpleSpanProcessor
from opentelemetry.sdk.trace.export.in_memory_span_exporter import InMemorySpanExporter

image = "data:image/gif;base64,R0lGODlhAQABAIAAAAAAAP///yH5BAEAAAAALAAAAAABAAEAAAIBRAA7"
attributes = {
    "input.value": image,
    "gen_ai.input.messages.0.message.content": "Check my order",
    "gen_ai.output.messages.0.message.content": "Your order is ready",
    "gen_ai.tool.call.arguments.order": "RGL-DEMO-82",
    "gen_ai.tool.call.arguments.quantity": 2,
    "gen_ai.tool.call.result": "RGL-RESULT-FOUND",
    "raw.input": "Lookup RGL-DEMO-82",
    "raw.output": "Found RGL-DEMO-82",
    "gen_ai.request.model": "ridgeline-support",
    "gen_ai.usage.input_tokens": 18,
}
exporter = InMemorySpanExporter()
provider = TracerProvider()
provider.add_span_processor(SimpleSpanProcessor(exporter))
for name, config in [
    ("default", TraceConfig()),
    ("fits", TraceConfig(base64_image_max_length=len(image))),
    ("too large", TraceConfig(base64_image_max_length=len(image) - 1)),
    ("inputs only", TraceConfig(hide_inputs=True)),
    ("outputs only", TraceConfig(hide_outputs=True)),
    ("private", TraceConfig(hide_inputs=True, hide_outputs=True)),
]:
    tracer = FITracer(provider.get_tracer("ridgeline"), config=config)
    with tracer.start_as_current_span(name, attributes=attributes):
        pass
for span in exporter.get_finished_spans():
    print(json.dumps({"name": span.name, "attributes": dict(span.attributes)}))
provider.shutdown()
```

```javascript
const { FITracer } = require("@traceai/fi-core");
const {
  BasicTracerProvider, InMemorySpanExporter, SimpleSpanProcessor,
} = require("@opentelemetry/sdk-trace-base");

async function main() {
  const image = "data:image/gif;base64,R0lGODlhAQABAIAAAAAAAP///yH5BAEAAAAALAAAAAABAAEAAAIBRAA7";
  const attributes = {
    "input.value": image,
    "gen_ai.input.messages.0.message.content": "Check my order",
    "gen_ai.output.messages.0.message.content": "Your order is ready",
    "gen_ai.tool.call.arguments.order": "RGL-DEMO-82",
    "gen_ai.tool.call.arguments.quantity": 2,
    "gen_ai.tool.call.result": "RGL-RESULT-FOUND",
    "raw.input": "Lookup RGL-DEMO-82",
    "raw.output": "Found RGL-DEMO-82",
    "gen_ai.request.model": "ridgeline-support",
    "gen_ai.usage.input_tokens": 18,
  };
  const exporter = new InMemorySpanExporter();
  const provider = new BasicTracerProvider({
    spanProcessors: [new SimpleSpanProcessor(exporter)],
  });
  for (const [name, traceConfig] of [
    ["default", {}],
    ["fits", { base64ImageMaxLength: image.length }],
    ["too large", { base64ImageMaxLength: image.length - 1 }],
    ["inputs only", { hideInputs: true }],
    ["outputs only", { hideOutputs: true }],
    ["private", { hideInputs: true, hideOutputs: true }],
  ]) {
    const tracer = new FITracer({ tracer: provider.getTracer("ridgeline"), traceConfig });
    tracer.startSpan(name, { attributes }).end();
  }
  await provider.forceFlush();
  for (const span of exporter.getFinishedSpans()) {
    console.log(JSON.stringify({ name: span.name, attributes: span.attributes }));
  }
  await provider.shutdown();
}
main().catch(error => { console.error(error); process.exitCode = 1; });
```

</CodeGroup>

| Span | What to look for |
| --- | --- |
| `default` | No GIF data. The fake order, quantity, result, and both raw bodies are visible: image redaction does not hide tool content. |
| `fits` | The cap equals the length of this complete data URL. Python retains the GIF; Node replaces it with an omission marker. |
| `too large` | Both SDKs replace the image. Neither returns the first part of the GIF. |
| `inputs only` | Neither raw body is present. Python drops the input message field; Node replaces its text with `__REDACTED__`. The tool arguments no longer carry the order reference or quantity. |
| `outputs only` | Neither raw body is present. Python drops the output message field; Node replaces its text with `__REDACTED__`. The tool result no longer carries `RGL-RESULT-FOUND`. |
| `private` | Neither raw body nor the original tool result is present. Python replaces the order and quantity with `__REDACTED__`; Node omits those two attributes. Both keep `gen_ai.request.model` as `ridgeline-support` and `gen_ai.usage.input_tokens` as the number `18`. |

### Check each destination

The example checks values recorded through an explicit `FITracer`. A native OpenTelemetry integration can have its own content settings. Python and Node zero-code agents can also sanitize a separate copy for the Future AGI exporter; a positive Python cap does not override that export's media policy. Other exporters can still receive the original span. Do not assume that inspecting the Future AGI copy proves your console, another backend, or application logs are masked. Repeat the synthetic check at each destination you use. Keep customer content out of custom keys and span names: the directional switches recognize known semantic keys, not the meaning of arbitrary text.

## Errors and privacy

<Note>
For the Python and TypeScript settings below, use `fi-instrumentation-otel` 1.2.3 or later (Python, `hide_error_details`) or `@traceai/fi-core` 1.1.1 or later (TypeScript, `hideErrorDetails`). Both read `FI_HIDE_ERROR_DETAILS`.

Upgrade the instrumentor as well as the core package. For Python LangChain and AutoGen, use `traceai-langchain` 0.2.1 or later and `traceai-autogen` 0.2.1 or later. For TypeScript, use `@traceai/openai` 0.1.14 or later, `@traceai/anthropic` 0.1.3 or later, `@traceai/bedrock` 0.1.1 or later, or `@traceai/langchain` 0.1.3 or later, as appropriate for your integration.
</Note>

When a call fails, traceAI marks the span `ERROR` and records the exception. Error text can carry the same data you hid with the other `hide_*` fields: a provider error body can quote your prompt back or include provider and gateway request IDs, and a framework error can include a stack trace with local file paths. `hide_error_details` keeps the fact that a span failed and what kind of failure it was, and drops the text.

| Field | Where it lives | `hide_error_details` off | `hide_error_details` on |
|-------|----------------|--------------------------|-------------------------|
| Status code | Span status | `ERROR` | `ERROR` |
| Status description | Span status | The exception message, never a traceback | Empty |
| `error.type` | Span attribute | An instrumentor-supplied type or a provider error code; otherwise the exception class (module-qualified in Python, class name in TypeScript), or `_OTHER` if unknown | Kept |
| `exception.type` | `exception` event | The exception class in Python; a code or error name in TypeScript | Kept |
| `exception.escaped` | `exception` event | Kept when set | Kept when set |
| `exception.message` | Span or event attribute | Kept | Dropped |
| `exception.stacktrace` | Span or event attribute | Kept | Dropped |
| `error.message` | Span or event attribute | Kept | Dropped |
| Other error-text attributes: any key ending in `.exception.message`, `.exception.stacktrace`, `.error.message` or `.error_message` (for example `autogen.error.message`) | Span or event attributes | Kept | Dropped |
| Output of a failed LangChain run (Python) | Span attributes | Kept unless output masking is enabled; it can contain the provider's error response | Dropped |

The status description excludes tracebacks in either mode. When error details are enabled, stack traces belong in `exception.stacktrace` on the exception event.

### Default

In Python and Node, when you don't set it in code or through `FI_HIDE_ERROR_DETAILS`, traceAI derives it from the content fields:

| `hide_error_details` setting | Result |
|------------------------------|--------|
| Not set | On if any of `hide_inputs`, `hide_outputs`, `hide_input_messages`, `hide_output_messages`, `hide_input_text`, or `hide_output_text` is true. Off otherwise. |
| `True` or `FI_HIDE_ERROR_DETAILS=true` | On, whatever the other fields are |
| `False` or `FI_HIDE_ERROR_DETAILS=false` | Off, even when content is hidden |

The content fields count whether you set them in code or through their own environment variables, so `FI_HIDE_INPUTS=true` on its own also hides error details. In the Python wrapper, `hide_input_images`, `hide_embedding_vectors`, `hide_llm_invocation_parameters`, and `pii_redaction` don't affect it. The Node wrapper also excludes image, vector, and PII settings from this default. Separately, the Node FI export filter hides error details when `FI_HIDE_LLM_INVOCATION_PARAMETERS=true` unless error hiding is explicitly overridden. As with the other fields, a value set in code takes precedence over the environment variable.

<Warning>
If you already hide content, upgrading also hides error details by default. To retain error text for debugging, set `hide_error_details=False` in Python, `hideErrorDetails: false` in TypeScript, or `FI_HIDE_ERROR_DETAILS=false`. Error messages can expose prompts and other sensitive data even when inputs and outputs are hidden; only enable them when that data is safe to export.
</Warning>

### Scope

`hide_error_details` applies to spans created through `FITracer` and instrumentors that use the shared traceAI span wrapper. In Python, this includes exceptions recorded automatically when they escape a wrapped span's context manager. Released instrumentors such as `traceai-chromadb` 0.2.0 use this wrapper; they do not need a separate privacy adapter.

<Warning>
The `FITracer` setting is not an exporter-wide filter. A span created with a plain OpenTelemetry tracer is not filtered by that wrapper. Native integrations have their own content controls unless their guide explicitly documents support for `TraceConfig`. Follow the integration's privacy instructions or apply redaction in an OpenTelemetry Collector before export. Avoid sensitive values in custom attribute keys, span names, and event names; `hide_error_details` filters the error fields listed above, not arbitrary text.
</Warning>

### Example

If a provider error might quote the customer's order, keep error masking on even if you later turn off input hiding. Set `hide_error_details=True` in Python, `hideErrorDetails: true` in Node, or use the environment:

```bash
export FI_HIDE_ERROR_DETAILS=true
```

## Cap attribute size

Use an OpenTelemetry limit if you want to shorten **strings**, not remove their contents. For example, set `OTEL_ATTRIBUTE_VALUE_LENGTH_LIMIT=100000` before starting the Python process, or pass `span_limits=SpanLimits(max_attribute_length=100000)` to `register()` (`SpanLimits` is exported by `fi_instrumentation`). This is a size control, not a privacy control: the first part of a string can still contain the entire order number. See [ingestion request limits](/docs/observe/reference/export-formats#ingestion-request-limits) for limits on the whole export.

## PII redaction (Python)

To retain free text but mask common identifiers, set `FI_PII_REDACTION=true` or pass `pii_redaction=True` to `TraceConfig`. The Python matcher replaces recognized emails, SSNs, card numbers, API-key patterns, IPv4 addresses, and phone numbers with markers such as `<EMAIL_ADDRESS>`. It exempts correlation identifiers such as `user.id` and `session.id`. A store order reference is not one of those patterns: use the content switches, not PII matching, to suppress tool arguments. Node also exposes `piiRedaction`; the image cap runs independently of PII matching.
