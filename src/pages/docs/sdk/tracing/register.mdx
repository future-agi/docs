---
title: "register()"
description: "Set up the tracer provider and connect to Future AGI with register()."
---


Initialize tracing once per process. The provider exports **ended spans**; registration on its own doesn't give you a trace to inspect. Each example records a `check-return-window` span for a local Ridgeline Outfitters policy lookup. You don't need a model key.

Choose one tab and start in an empty directory. Load `FI_API_KEY` and `FI_SECRET_KEY` from your [Future AGI key pair](/docs/admin-settings/api-keys). For self-hosted HTTP export, replace `https://api.futureagi.com` below with the collector origin, without `/tracer/v1/traces`.

<Tabs>
  <Tab title="Python">
    ```bash
    python3 -m venv .venv
    source .venv/bin/activate
    python -m pip install fi-instrumentation-otel==1.5.1
    export FI_TRACES_URL=https://api.futureagi.com
    ```

    Save this as `register_trace.py` and run `python register_trace.py`:

    ```python
    from fi_instrumentation import register
    from fi_instrumentation.fi_types import ProjectType
    from fi_instrumentation.otel import Transport

    provider = register(project_name="ridgeline-register-python", project_type=ProjectType.OBSERVE,
                        transport=Transport.HTTP, batch=True, verbose=False)
    try:
        with provider.get_tracer("ridgeline.returns").start_as_current_span("check-return-window") as span:
            days = {"unused pack": 30}["unused pack"]
            span.set_attribute("gen_ai.span.kind", "TOOL")
            span.set_attribute("return.window.days", days)
    finally:
        provider.shutdown()
    ```

    | Parameter | Type | Default | Description |
    |-----------|------|---------|-------------|
    | `project_name` | str / None | `FI_PROJECT_NAME`, otherwise `DEFAULT_PROJECT_NAME` | Project identifier in the dashboard |
    | `project_type` | ProjectType | `EXPERIMENT` | `EXPERIMENT` (dev, supports eval tags) or `OBSERVE` (production) |
    | `project_version_name` | str / None | `FI_PROJECT_VERSION_NAME` | Version label (EXPERIMENT only) |
    | `eval_tags` | list / None | None | Evaluation configs for automated span scoring (EXPERIMENT only) |
    | `metadata` | dict / None | None | Custom metadata on the provider resource |
    | `batch` | bool | True | True = BatchSpanProcessor, False = SimpleSpanProcessor |
    | `set_global_tracer_provider` | bool | False | Register as the global OpenTelemetry default |
    | `headers` | dict / None | None | Custom HTTP headers (auto-populated from API keys if not set) |
    | `verbose` | bool | True | Print configuration details on startup |
    | `transport` | Transport | `HTTP` | `HTTP` or `GRPC` |
    | `semantic_convention` | SemanticConvention | `FI` | Convention label on the provider resource; does not change attribute names |

    **Returns:** `TracerProvider` - pass this to `.instrument(tracer_provider=...)` on any instrumentor.
  </Tab>
  <Tab title="TypeScript">
    Use Node.js 22.18 or later:

    ```bash
    npm install @traceai/fi-core@1.4.1
    export FI_TRACES_URL=https://api.futureagi.com
    ```

    Save this as `register-trace.mts` and run `node register-trace.mts`:

    ```typescript
    import { register, ProjectType, Transport } from "@traceai/fi-core";

    const provider = register({
      projectName: "ridgeline-register-node", projectType: ProjectType.OBSERVE,
      transport: Transport.HTTP, batch: true, verbose: false,
    });
    const span = provider.getTracer("ridgeline.returns").startSpan("check-return-window");
    try {
      const windows = { "unused pack": 30 };
      span.setAttribute("gen_ai.span.kind", "TOOL");
      span.setAttribute("return.window.days", windows["unused pack"]);
    } finally {
      span.end();
      await provider.shutdown();
    }
    ```

    | Parameter | Type | Default | Description |
    |-----------|------|---------|-------------|
    | `projectName` | string | `FI_PROJECT_NAME` env var | Project identifier |
    | `projectType` | ProjectType | `EXPERIMENT` | `EXPERIMENT` or `OBSERVE` |
    | `projectVersionName` | string | `FI_PROJECT_VERSION_NAME` or `DEFAULT` | Version label (EXPERIMENT only) |
    | `evalTags` | EvalTag[] | undefined | Evaluation configs (EXPERIMENT only) |
    | `sessionName` | string | undefined | Session name (OBSERVE only) |
    | `metadata` | Record | undefined | Custom metadata |
    | `batch` | boolean | false | Use batch span processor |
    | `setGlobalTracerProvider` | boolean | true | Register as global provider |
    | `headers` | FIHeaders | undefined | Custom HTTP headers |
    | `verbose` | boolean | false | Verbose logging |
    | `endpoint` | string | From environment or hosted default | Override the HTTP exporter destination |
    | `transport` | Transport | `HTTP` | `HTTP` or `GRPC` |

    **Returns:** `FITracerProvider`
  </Tab>
  <Tab title="Java">
    Use Maven and a Java 17 or 21 JDK. Save this as `pom.xml`. For the plain Java example, you need `traceai-java-core`; the additional starter dependencies are for the Spring Boot variant below.

    ```xml
    <project xmlns="http://maven.apache.org/POM/4.0.0">
      <modelVersion>4.0.0</modelVersion>
      <groupId>example.ridgeline</groupId><artifactId>register-trace</artifactId><version>1.0</version>
      <properties><maven.compiler.source>17</maven.compiler.source><maven.compiler.target>17</maven.compiler.target></properties>
      <dependencies>
        <dependency><groupId>com.futureagi</groupId><artifactId>traceai-java-core</artifactId><version>1.4.1</version></dependency>
        <dependency>
          <groupId>com.futureagi</groupId><artifactId>traceai-spring-boot-starter</artifactId><version>1.4.1</version>
          <exclusions><exclusion><groupId>org.springframework.boot</groupId><artifactId>spring-boot-autoconfigure</artifactId></exclusion></exclusions>
        </dependency>
        <dependency><groupId>org.springframework.boot</groupId><artifactId>spring-boot-starter</artifactId><version>3.5.15</version></dependency>
      </dependencies>
    </project>
    ```

    Save this as `src/main/java/example/Returns.java`. Run `mvn -q compile org.codehaus.mojo:exec-maven-plugin:3.5.0:java -Dexec.mainClass=example.Returns` from the directory containing `pom.xml`.

    ```java
    package example;

    import ai.traceai.FISpanKind;
    import ai.traceai.FITracer;
    import ai.traceai.TraceAI;
    import ai.traceai.TraceConfig;
    import java.util.Map;

    public class Returns {
        public static void main(String[] args) {
            TraceAI.init(TraceConfig.builder()
                .baseUrl("https://api.futureagi.com")
                .projectName("ridgeline-register-java")
                .batchSize(512).exportIntervalMs(5000).build());
            try { checkWindow(TraceAI.getTracer()); }
            finally { TraceAI.shutdown(); }
        }

        static void checkWindow(FITracer tracer) {
            var span = tracer.startSpan("check-return-window", FISpanKind.TOOL);
            try { span.setAttribute("return.window.days", Map.of("unused pack", 30L).get("unused pack").longValue()); }
            finally { span.end(); }
        }
    }
    ```

    The builder reads both keys from the environment. If you configure the collector with `FI_BASE_URL` and the project with `FI_PROJECT_NAME` too, you can use `TraceAI.initFromEnvironment()` **instead of** `TraceAI.init(...)`.

    | Builder method | Default | Description |
    |----------------|---------|-------------|
    | `baseUrl(String)` | `FI_BASE_URL` env var | Backend endpoint |
    | `apiKey(String)` | `FI_API_KEY` env var | API authentication |
    | `secretKey(String)` | `FI_SECRET_KEY` env var | Secondary authentication |
    | `projectName(String)` | `FI_PROJECT_NAME` env var | Project identifier |
    | `serviceName(String)` | project name | OpenTelemetry service name |
    | `hideInputs(boolean)` | false | Suppress input values |
    | `hideOutputs(boolean)` | false | Suppress output values |
    | `hideInputMessages(boolean)` | false | Suppress input messages |
    | `hideOutputMessages(boolean)` | false | Suppress output messages |
    | `enableConsoleExporter(boolean)` | false | Log spans to console |
    | `batchSize(int)` | 512 | Span batch size |
    | `exportIntervalMs(long)` | 5000 | Export interval in ms |

    For [Spring AI](/docs/integrations/traceai/spring-boot), configure Boot's native exporter instead of using `TraceAI.init()` or the starter. If you use the Java wrapper SDK in Spring Boot, configure its starter via `src/main/resources/application.yml`:

    ```yaml
    traceai:
      enabled: true
      base-url: https://api.futureagi.com
      api-key: ${FI_API_KEY}
      secret-key: ${FI_SECRET_KEY}
      project-name: ridgeline-register-spring
      batch-size: 512
      export-interval-ms: 5000
    ```

    The starter supplies an `FITracer` bean. To try the same lookup without calling `TraceAI.init()` yourself, save this as `src/main/java/example/ReturnsApp.java` next to `Returns.java`. Run `mvn -q compile org.codehaus.mojo:exec-maven-plugin:3.5.0:java -Dexec.mainClass=example.ReturnsApp`.

    ```java
    package example;

    import ai.traceai.FITracer;
    import ai.traceai.TraceAI;
    import org.springframework.boot.SpringApplication;
    import org.springframework.boot.autoconfigure.SpringBootApplication;

    @SpringBootApplication
    public class ReturnsApp {
        public static void main(String[] args) {
            try (var app = SpringApplication.run(ReturnsApp.class, args)) {
                Returns.checkWindow(app.getBean(FITracer.class));
            } finally { TraceAI.shutdown(); }
        }
    }
    ```

    Replace `ReturnsApp/Program.cs` with the following and run `dotnet run --project ReturnsApp`:

    ```csharp
    using FIInstrumentation;
    using FIInstrumentation.Types;

    var tracer = TraceAI.Register(opts => {
        opts.ProjectName = "ridgeline-register-dotnet";
        opts.ProjectType = ProjectType.Observe;
        opts.Endpoint = Environment.GetEnvironmentVariable("FI_TRACES_URL");
        opts.Transport = Transport.Http;
        opts.Batch = true;
        opts.Verbose = false;
        opts.TraceConfig = TraceConfig.Builder().HideInputs().HideOutputs().Build();
    });
    try {
        tracer.Tool("check-return-window", span => {
            var days = new Dictionary<string, int> { ["unused pack"] = 30 };
            span.SetAttribute("return.window.days", (long)days["unused pack"]);
        });
    } finally { TraceAI.Shutdown(); }
    ```

    | Property | Type | Default | Description |
    |----------|------|---------|-------------|
    | `ProjectName` | string | `FI_PROJECT_NAME` env var | Project identifier |
    | `ProjectType` | ProjectType | Experiment | `Experiment` or `Observe` |
    | `ProjectVersionName` | string | null | Version label (Experiment only) |
    | `Batch` | bool | true | Use batch span processor |
    | `Endpoint` | string | From settings | HTTP collector origin or gRPC endpoint |
    | `Transport` | Transport | Http | `Http` or `Grpc` |
    | `ApiKey` | string | `FI_API_KEY` env var | API key |
    | `SecretKey` | string | `FI_SECRET_KEY` env var | Secret key |
    | `TraceConfig` | TraceConfig | null | Privacy/masking configuration |
    | `EnableConsoleExporter` | bool | false | Log spans to console |
    | `Verbose` | bool | true | Print config on startup |

    **Returns:** `FITracer` - use for creating custom spans.

## ProjectType

| Value | Use for |
|-------|---------|
| `EXPERIMENT` | Development and testing. Supports eval tags and version names. |
| `OBSERVE` | Production monitoring. No eval tags, no version names. |

## Semantic conventions

In Python, `semantic_convention` labels the provider resource. It does not translate attributes your instrumentation emits: changing the label does not change `fi.*` keys to `gen_ai.*`. TypeScript's `register()` does not take this option.

## Verify delivery

Open **Observe → Tracing**, select the `ridgeline-register-*` project named in your example, and open the latest `check-return-window` span. Its `return.window.days` attribute should be `30`. On a long-running server, shut down the provider when the process stops, not after each request.
