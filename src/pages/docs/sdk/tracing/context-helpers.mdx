Attach metadata, tags, session IDs, and user IDs to spans. These apply to all spans created within the scope.

<Tabs>
  <Tab title="Python">
    ```python
    from fi_instrumentation import (
        using_session, using_user, using_metadata,
        using_tags, using_prompt_template, using_attributes,
        suppress_tracing
    )

    # Individual context managers
    with using_session("session-abc-123"):
        with using_user("user-456"):
            response = client.chat.completions.create(...)

    with using_metadata({"environment": "production", "version": "2.1"}):
        response = client.chat.completions.create(...)

    with using_tags(["rag-pipeline", "v2"]):
        response = client.chat.completions.create(...)

    # Prompt template tracking
    with using_prompt_template(
        template="Answer {question} using {context}",
        label="production",
        version="v1.2",
        variables={"question": "...", "context": "..."}
    ):
        response = client.chat.completions.create(...)

    # Combined - set everything at once
    with using_attributes(
        session_id="session-abc",
        user_id="user-456",
        metadata={"env": "prod"},
        tags=["rag", "v2"],
        prompt_template="Answer {question}",
        prompt_template_version="v1.2",
    ):
        response = client.chat.completions.create(...)

    # Suppress tracing for a block
    with suppress_tracing():
        # These calls won't be traced
        result = client.chat.completions.create(...)
    ```

    import {

## Skill and agent-context scopes

The [skill-trace preview](/docs/skills/trace-skills) supplies Python `agent_scope` and TypeScript `withAgentScope` through the high-level SDK. The interfaces below are the preview contract, pending final package/integration verification. They do not replace provider/exporter setup or imply that a linked skill was loaded.

```python
from fi.telemetry import agent_scope

# ctx_snapshot is an already resolved context; tracer belongs to your provider.
with agent_scope(agent="refund-agent", context=ctx_snapshot):
    with tracer.start_as_current_span("refund-request"):
        instructions = ctx_snapshot.read_file("AGENTS.md")
        policy = ctx_snapshot.read_file("skills/refund-policy/SKILL.md")
        # Create model/tool spans after the read to carry the loaded-skill list.
```

```typescript
import { withAgentScope } from "@futureagi/sdk/telemetry";

await withAgentScope({ agent: "refund-agent", context: ctxSnapshot }, async () => {
  await tracer.startActiveSpan("refund-request", async (span) => {
    try {
      const instructions = await ctxSnapshot.readFile("AGENTS.md");
      const policy = await ctxSnapshot.readFile("skills/refund-policy/SKILL.md");
      // Create model/tool spans here, after the verified read.
    } finally {
      span.end();
    }
  });
});
```

Put the scope outside root-span creation to attach agent/context identity from the start. Skills loaded later do not retroactively stamp every earlier span. A current recording span is enriched after the read, and later spans need the [runtime processor](/docs/sdk/tracing/register#skill-and-context-propagation). Explicit attributes on a span win; names and resources are not overwritten.

A nested **context** scope replaces `fi.context.*` and resets the loaded-skill list; a nested plain scope inherits and appends. Context exits restore the prior state on success, error, and cancellation. Python supports sync/async scopes and decoration of functions, coroutines, and async generators. For a synchronous generator, wrap its body explicitly. Thread pools require captured Python context (`contextvars.copy_context()`); JavaScript callbacks may require OTel `context.bind`. Subprocesses require explicit context propagation, not an assumed shared in-memory registry. Automatic mode shares the trace's list when agents interleave, so prefer explicit scopes for agent frameworks.

### traceAI without the high-level SDK

The preview Python helper `using_runtime_attributes(mapping)` in `fi_instrumentation.instrumentation.runtime_attributes` writes the shared runtime carrier. It accepts only `fi.skills.*`, `fi.context.*`, and `gen_ai.agent.*` keys. It does not verify content, emit a `skill.load`, or turn a declared identity into observed evidence. Without the SDK's Python processor, attaching this carrier alone does not stamp vanilla spans.

The carrier is `futureagi.runtime.span_attributes.v1` (a literal Python context key; `Symbol.for` in TypeScript), holding immutable `v`, `attrs`, and `reset_skills` fields. Consumers preserve explicit span attributes. Python's existing general `CONTEXT_ATTRIBUTES` allowlist is unchanged; runtime propagation is a separate processor path. TypeScript traceAI merges ordinary context attributes for both `startSpan` and `startActiveSpan` in the integration, while its runtime processor handles the skill carrier.

Java, C#, Go, and Ruby require manual span attributes for skill/context attribution in this phase; these Python/TypeScript scopes do not establish cross-language automatic support. See [semantic conventions](/docs/sdk/tracing/semantic-conventions#skills-and-agent-contexts) and the [load/evidence rules](/docs/skills/trace-skills#what-each-fact-proves).

## Suppress Tracing

Temporarily disable tracing for a block of code. Useful for health checks, internal calls, or operations you don't want in your traces. Available in Python and C# only - Java and TypeScript don't have this API.

<Warning>
`suppress_tracing` **drops** spans created in its block, it does not move them anywhere else. If a LangChain call inside the block is one you still want traced, but into a different project (for example a linter or internal tool that shares a process with your main agent), suppressing it makes those calls disappear entirely rather than showing up somewhere else. Use a separate `tracer_provider`/project for that code path instead if you need it observable.

In Python, only use the synchronous form, even inside an `async def`:

```python
with suppress_tracing():
    result = await client.chat.completions.create(...)
```

`suppress_tracing` does not support `async with`. Its `__aenter__`/`__aexit__` methods are plain (non-`async def`), so `async with suppress_tracing():` raises a `TypeError` on entry. Because `__aenter__` already attaches the suppression context before that error, the `TypeError` also skips the matching `__aexit__`/detach, so the suppression can leak into code that runs after the failed block.
</Warning>
