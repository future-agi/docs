## About

traceAI SDKs share the following environment-variable names. Support varies by SDK and integration; native OpenTelemetry integrations use the controls documented in their integration guide.

| Variable | Purpose | Default |
|----------|---------|---------|
| `FI_API_KEY` | Authenticate hosted exports | No key |
| `FI_SECRET_KEY` | Authenticate hosted exports | No key |
| `FI_BASE_URL` | Platform API base URL; also the default HTTP trace destination in Python | `https://api.futureagi.com` in Python; set it explicitly for Java core |
| `FI_TRACES_URL` | Override the HTTP trace destination without moving Python platform API calls | Falls back to `FI_BASE_URL` in Python |
| `FI_GRPC_URL` | gRPC collector endpoint | `https://grpc.futureagi.com` in Python |
| `FI_PROJECT_NAME` | Project name when not supplied in code | `DEFAULT_PROJECT_NAME` in Python |
| `FI_PROJECT_VERSION_NAME` | Project version when not supplied in code | `DEFAULT_PROJECT_VERSION_NAME` in Python |
| `FI_HIDE_INPUTS` | Redact inputs | False |
| `FI_HIDE_OUTPUTS` | Redact outputs | False |
| `FI_HIDE_INPUT_MESSAGES` | Redact input messages | False |
| `FI_HIDE_OUTPUT_MESSAGES` | Redact output messages | False |
| `FI_HIDE_INPUT_IMAGES` | Redact input images | False |
| `FI_HIDE_INPUT_TEXT` | Redact input text | False |
| `FI_HIDE_OUTPUT_TEXT` | Redact output text | False |
| `FI_HIDE_EMBEDDING_VECTORS` | Redact embedding vectors | False |
| `FI_HIDE_LLM_INVOCATION_PARAMETERS` | Hide the aggregate request-parameters attribute in Python. The Node FI export filter also reads this variable and drops recognized request parameter fields, including temperature. | False |
| `FI_BASE64_IMAGE_MAX_LENGTH` | Python: a positive cap can retain eligible small inline images; over-limit images are replaced, never truncated. Node.js: raising the cap does not enable recognized base64 image export. See [TraceConfig by SDK](/docs/sdk/tracing/trace-config#match-the-policy-to-your-sdk). | `0` (Python and Node.js); no Java core builder setting |
| `FI_PII_REDACTION` | Mask recognized PII patterns (Python and Node.js) | False |
| `FI_HIDE_ERROR_DETAILS` | Hide error messages and stack traces on supported traceAI spans. Use Python `fi-instrumentation-otel` 1.2.3 or later or TypeScript `@traceai/fi-core` 1.1.1 or later. See [Errors and privacy](/docs/sdk/tracing/trace-config#errors-and-privacy) | Python and Node.js: derived from the resolved input/output content flags. Java core: false. See below. |

In `fi-instrumentation-otel` 1.5.1, `@traceai/fi-core` 1.4.1, and Java core 1.4.1, either `FI_HIDE_INPUTS` or `FI_HIDE_OUTPUTS` also hides the corresponding structured messages and withholds both raw bodies. Use the literal `true` for a shared deployment. Java enables these switches only for `true` (case-insensitive, without surrounding whitespace); values such as `1`, `yes`, and `on` enable them in Python and Node but **not** in Java. Java core reads `FI_HIDE_ERROR_DETAILS` independently; it defaults to false.

For Python and TypeScript, `FI_HIDE_ERROR_DETAILS` defaults to true when any of `hide_inputs`, `hide_outputs`, `hide_input_messages`, `hide_output_messages`, `hide_input_text`, or `hide_output_text` is true (camelCase in TypeScript). These flags can come from code or their `FI_` environment variables. Otherwise, it defaults to false. Image-only, embedding-vector, and PII masking do not enable it. Invocation-parameter masking does not enable it in Python. At the Node FI export boundary, `FI_HIDE_LLM_INVOCATION_PARAMETERS=true` also hides error details unless explicitly overridden. An explicit error-details setting in code takes precedence over `FI_HIDE_ERROR_DETAILS`; an explicit environment value takes precedence over the derived default.
