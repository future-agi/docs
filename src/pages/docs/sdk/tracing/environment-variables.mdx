---
title: "Environment variables"
description: "Environment variables that configure traceAI tracing."
---

Environment-variable support differs by language. Set variables before initializing tracing; do not assume a variable supported by one SDK is read by another. Native OpenTelemetry integrations use the controls documented in their integration guide.

## Connection variables

| Variable | Purpose |
|----------|---------|
| `FI_API_KEY` | Authentication |
| `FI_SECRET_KEY` | Authentication |
| `FI_BASE_URL` | HTTP collector base URL |
| `FI_GRPC_URL` | gRPC collector endpoint; not read by Java's `TraceConfig` |
| `FI_PROJECT_NAME` | Default project name |
| `FI_PROJECT_VERSION_NAME` | Default version; not read by Java's `TraceConfig` |

Java reads `FI_BASE_URL`, `FI_API_KEY`, `FI_SECRET_KEY`, and `FI_PROJECT_NAME`. Set `FI_BASE_URL` explicitly (for cloud, `https://api.futureagi.com`): Java's `TraceConfig` has no built-in base URL default. See [register()](/docs/sdk/tracing/register) for programmatic connection options.

## Privacy variables by language

“Yes” means the SDK reads the environment variable. It does not mean the setting is enabled by default. Input/output hiding flags default to `false`.

| Variable | Python | TypeScript | Java | C# |
|----------|--------|------------|------|----|
| `FI_HIDE_INPUTS` | Yes | Yes | Yes | Yes |
| `FI_HIDE_OUTPUTS` | Yes | Yes | Yes | Yes |
| `FI_HIDE_INPUT_MESSAGES` | Yes | Yes | No; use builder | Yes |
| `FI_HIDE_OUTPUT_MESSAGES` | Yes | Yes | No; use builder | Yes |
| `FI_HIDE_INPUT_IMAGES` | Yes | Yes | No | Yes |
| `FI_HIDE_INPUT_TEXT` | Yes | Yes | No | Yes |
| `FI_HIDE_OUTPUT_TEXT` | Yes | Yes | No | Yes |
| `FI_HIDE_EMBEDDING_VECTORS` | Yes | Yes | No | Yes |
| `FI_HIDE_LLM_INVOCATION_PARAMETERS` | Yes | Yes | No | Yes |
| `FI_HIDE_ERROR_DETAILS` | Yes | Yes | Yes | Yes |
| `FI_BASE64_IMAGE_MAX_LENGTH` | Yes; default `0` | Yes; default `0` | No | Yes; default `32000` |
| `FI_PII_REDACTION` | Yes; default `false` | Yes; default `false` | No | No |

In Java, `FI_HIDE_ERROR_DETAILS` defaults to `false`. In Python, TypeScript, and C#, an unset error-detail flag is derived from the input/output content-hiding flags. Explicit programmatic values take precedence over environment defaults. For C#, environment defaults are read by `TraceConfig.Builder()`; constructing `new TraceConfig()` does not read them.

`FI_HIDE_ERROR_DETAILS` hides error messages and stack traces on supported traceAI spans. Use Python `fi-instrumentation-otel` 1.2.3 or later or TypeScript `@traceai/fi-core` 1.1.1 or later. See [Errors and privacy](/docs/sdk/tracing/trace-config#errors-and-privacy) for the supported scope.

For Python and TypeScript's `TraceConfig`, error-detail hiding defaults to true when any of `hide_inputs`, `hide_outputs`, `hide_input_messages`, `hide_output_messages`, `hide_input_text`, or `hide_output_text` is true (camelCase in TypeScript). These flags can come from code or their `FI_` environment variables. An explicit error-details setting in code takes precedence over `FI_HIDE_ERROR_DETAILS`; an explicit environment value takes precedence over the derived default. Export-time controls can apply additional hiding.

## Java message hiding

Java does not read `FI_HIDE_INPUT_MESSAGES` or `FI_HIDE_OUTPUT_MESSAGES`. Set the corresponding builder methods instead:

```java
import ai.traceai.TraceAI;
import ai.traceai.TraceConfig;

// Connection values come from FI_BASE_URL, FI_API_KEY,
// FI_SECRET_KEY, and FI_PROJECT_NAME.
TraceAI.init(TraceConfig.builder()
    .hideInputMessages(true)
    .hideOutputMessages(true)
    .build()
);
```

The Java builder also reads `FI_HIDE_INPUTS`, `FI_HIDE_OUTPUTS`, and `FI_HIDE_ERROR_DETAILS` when their corresponding builder methods are not set. It does not read the image, text, embedding, invocation-parameter, image-length, or PII variables in the matrix.
