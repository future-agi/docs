## About

You can trace an order lookup without storing the customer's message, photo, or tool arguments. Start with the broad input and output settings if you need model names, token counts, and timing but not content.

## Set a policy before startup

For the Ridgeline Outfitters support agent, set the following in the environment of the process that creates spans. Use Python `fi-instrumentation-otel` 1.5.1, Node.js `@traceai/fi-core` 1.4.1, or Java core 1.4.1 for the content behavior below.

```bash
export FI_HIDE_INPUTS=true
export FI_HIDE_OUTPUTS=true
export FI_HIDE_ERROR_DETAILS=true
```

Start your instrumented application from that environment. An explicit `TraceConfig` option on a supporting instrumentor overrides its environment setting. These switches cover known content fields, including input and output messages, tool arguments and results. Either broad switch withholds **both** raw bodies because either can repeat the hidden content.

For a narrower policy, replace the broad switches above rather than adding more switches to them:

| Goal | Setting and limit |
| --- | --- |
| Hide messages in one direction | `FI_HIDE_INPUT_MESSAGES` or `FI_HIDE_OUTPUT_MESSAGES`. The matching opaque input or output value is masked too. Separate attributes, such as tool arguments, can remain visible. |
| Hide inline images but keep tool calls | In Python and Node the base64 image cap defaults to `0`. Python can retain eligible images under a positive `FI_BASE64_IMAGE_MAX_LENGTH`; it never keeps a prefix of an oversized image. Raising the Node cap does not enable recognized base64 image export. Keep the default cap if you only need to suppress recognized inline images. `FI_HIDE_INPUT_IMAGES=true` is stronger: it can also hide an opaque input or tool fields inside a chat request. |
| Keep error type but not error text | `FI_HIDE_ERROR_DETAILS=true`. The error-detail switch requires Python `fi-instrumentation-otel` 1.2.3 or later or Node `@traceai/fi-core` 1.1.1 or later. The Java core builder has an independent error-details switch. See [Errors and privacy](/docs/sdk/tracing/trace-config#errors-and-privacy). |

## Check the exported span

In a separate shell, run the [synthetic order lookup example](/docs/sdk/tracing/trace-config#verify-the-exported-attributes). Compare the default and private spans: neither the fake order reference nor the quantity should remain in the private span, even though its model and token count match the default span.

`TraceConfig` on a manual instrumentor is not an exporter-wide filter. Other instrumentors, application logs, and additional exporters can record the original data. Inspect your own destinations with synthetic data before sending customer traffic.
