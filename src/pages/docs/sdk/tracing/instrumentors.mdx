## About

An instrumentor records a library call as a span. If your Python app calls DeepSeek, Fireworks, xAI, MiniMax or vLLM through the OpenAI client, you usually need just `traceai-openai`. The package that records the span and the provider named on that span can be different.

## Choose one tracing route

For a new app, install the shared OpenAI instrumentor alongside the Python core. Run this in your application's virtual environment; these releases support Python 3.10 through 3.13 and the shared instrumentor requires `openai>=1.69.0`.

```bash
python -m pip install 'fi-instrumentation-otel==1.5.1' 'traceai-openai==0.1.16'
```

If you already use a provider-specific package, you do not have to remove it before migrating. With the versions below, `fi-instrument` selects installed integrations at startup. For a supported Chat Completions request, the result is **one model span**, not one per installed package.

| Installed tracing packages (besides the core) | Who records the call by default? |
| --- | --- |
| Shared `traceai-openai` only | The shared instrumentor records the request and labels it from the client's API host. |
| Provider adapter only | The adapter records matching requests itself. You still need the `openai` client library, but not the `traceai-openai` tracing package. |
| Shared instrumentor and updated adapter | The adapter yields to the active shared instrumentor at request time. The shared tracer provider and its privacy settings apply. |

| Provider | Provider adapter version | `FI_INSTRUMENTATIONS` name | `gen_ai.provider.name` on the shared span |
| --- | --- | --- | --- |
| DeepSeek | `traceai-deepseek==0.1.4` | `deepseek` | `deepseek` for `api.deepseek.com` |
| Fireworks AI | `traceai-fireworks==0.1.4` | `fireworks` | `fireworks` for `api.fireworks.ai` |
| xAI | `traceai-xai==0.1.3` | `xai` | `xai` for `api.x.ai` |
| MiniMax | `traceai-minimax==0.1.2` | `minimax` | `minimax` for `api.minimax.io` and `api.minimax.chat` |
| vLLM | `traceai-vllm==0.1.2` | `vllm` | `openai` for an unrecognized self-hosted endpoint; `vllm` with an explicit client override |

The [cross-package tests](https://github.com/future-agi/traceAI/blob/fi-instrumentation-otel-v1.5.1/python/tests_cross_package/openai_compatible/test_defaults.py) check one-span behavior for synchronous and asynchronous Chat Completions with simulated provider responses. That checks how the SDK traces a call, not which APIs a live model supports.

## Verify one request

Suppose the Ridgeline Outfitters support agent uses DeepSeek to draft a question about a broken tent pole. To check its tracing, send one request outside the rest of the agent so there are no tool calls or retries from the agent to count.

1. Set `FI_API_KEY` and `FI_SECRET_KEY` from your [Future AGI keys](https://app.futureagi.com/dashboard/keys) in the process environment. Separately, set `DEEPSEEK_API_KEY` to your model provider's key and `DEEPSEEK_MODEL` to a model your account can call.
2. Save this as `support_reply.py`. This is ordinary application code: the launcher instruments it before the first model call.

```python
import os

from openai import OpenAI

with OpenAI(base_url="https://api.deepseek.com", api_key=os.environ["DEEPSEEK_API_KEY"]) as client:
    reply = client.chat.completions.create(
        model=os.environ["DEEPSEEK_MODEL"],
        messages=[{
            "role": "user",
            "content": "Ask a Ridgeline Outfitters customer which tent pole broke so we can send the right replacement.",
        }],
    )
    print(reply.choices[0].message.content)
```

3. Choose a project, hide the prompt and response from the trace, and run the app. The hide flags affect exported telemetry, not the request to DeepSeek.

```bash
export FI_PROJECT_NAME=ridgeline-support
export FI_HIDE_INPUTS=true FI_HIDE_OUTPUTS=true
fi-instrument python support_reply.py
```

4. After the process exits, open **Observe**, select **ridgeline-support**, and open the trace for that request. Look for one model span with `gen_ai.provider.name` set to `deepseek` and `gen_ai.request.model` set to the model you requested. With the shared package active, the instrumentation scope is `traceai_openai`; this does not mean the request went to OpenAI.

### Compare the two routes during migration

In the same environment, add the adapter. Run the same script once with **only** the adapter selected, then once with the default selection. Each command makes a separate model request.

```bash
python -m pip install 'traceai-deepseek==0.1.4'
FI_INSTRUMENTATIONS=deepseek fi-instrument python support_reply.py
env -u FI_INSTRUMENTATIONS fi-instrument python support_reply.py
```

Both traces should have one `deepseek` model span. The first comes from `traceai_deepseek`, just as it would with only the updated provider package installed. The second comes from `traceai_openai`. If both packages are installed but you want only the shared integration, set `FI_INSTRUMENTATIONS=openai`.

`FI_INSTRUMENTATIONS` is a comma-separated **allowlist**, not an addition to the defaults. For example, `deepseek,langchain` selects those two integrations and leaves `openai` out. `FI_DISABLED_INSTRUMENTATIONS` takes precedence if a name is in both lists. These variables control the zero-code launcher; they do not undo an explicit `.instrument()` call in your application.

## Troubleshoot missing, duplicate or mislabeled spans

| What you see | What to check |
| --- | --- |
| Two model spans for the same call | Upgrade the core, shared package and adapter together, or select just one owner. The launcher leaves an older adapter off by default if it cannot defer, or if the installed shared package lacks a capability the adapter needs. Explicitly enabling both can bypass that protection. Remove any extra manual wrapper for the same client. A parent agent span and a child model span are different operations, not duplicates. |
| No model span | Run `fi-instrument doctor --offline` in the app's environment. Check the integration is installed, the allowlist includes it, and both Future AGI keys are configured. The offline check does not test delivery. |
| The provider is `openai` for a self-hosted vLLM server | Host detection does not guess from a port or model name. With the shared package, import `set_client_provider` from `traceai_openai` and call `set_client_provider(client, provider="vllm")` before the request. Set it again on clients returned by `copy()` or `with_options()`. This changes span metadata, not the request. |
| Chat works but another API has no span | The legacy DeepSeek and vLLM adapters trace Chat Completions, not Responses; the legacy vLLM adapter does not trace embeddings either. Use the shared client instrumentor for those APIs only if the endpoint and deployed model support them. Client tracing does not instrument the vLLM inference engine. |

If you manage Python instrumentation explicitly instead of using the launcher, keep one [registered tracer provider](/docs/sdk/tracing/register). Pass it to the instrumentor's `.instrument(tracer_provider=...)` at startup, call `.uninstrument()` when you need to remove that wrapper, and flush and shut down the provider before exit.

## Find packages for other libraries and languages

Use the package for the client you actually call. The [language-by-integration catalog](https://github.com/future-agi/traceAI/blob/fi-instrumentation-otel-v1.5.1/README.md#integrations) links each dedicated package to its source. An entry is not a claim that every endpoint, transport or client version has been exercised. A missing dedicated package does not rule out a shared OpenAI-compatible client or manual spans.

| What you're tracing | Package or setup guide |
| --- | --- |
| Python model clients | [OpenAI](/docs/integrations/traceai/openai), [SageMaker Runtime](https://github.com/future-agi/traceAI/tree/fi-instrumentation-otel-v1.5.1/python/frameworks/sagemaker) (`traceai-sagemaker`), [Aleph Alpha](https://github.com/future-agi/traceAI/tree/fi-instrumentation-otel-v1.5.1/python/frameworks/alephalpha) (`traceai-alephalpha`). For compatible endpoints, see the [CometAPI](/docs/integrations/providers/cometapi), [Novita AI](/docs/integrations/providers/novita-ai) and [Z.ai](/docs/integrations/providers/z-ai) chat examples. |
| Python retrieval and vector stores | [Elasticsearch](https://github.com/future-agi/traceAI/tree/fi-instrumentation-otel-v1.5.1/python/frameworks/elasticsearch) (`traceai-elasticsearch`) and [Marqo](https://github.com/future-agi/traceAI/tree/fi-instrumentation-otel-v1.5.1/python/frameworks/marqo) (`traceai-marqo`). The [Python registry](https://github.com/future-agi/traceAI/blob/fi-instrumentation-otel-v1.5.1/docs/python/auto-instrumentation.md#what-is-traced) also lists Pinecone, Qdrant, Weaviate, ChromaDB and other clients. |
| Python frameworks and voice | [LangGraph](/docs/integrations/traceai/langgraph) uses `traceai-langchain`; [Prompt flow](/docs/integrations/traceai/promptflow) uses `traceai-promptflow`. Follow the framework setup for [Pipecat](/docs/integrations/traceai/pipecat), [LiveKit](/docs/integrations/traceai/livekit) or [BeeAI with OpenInference](/docs/integrations/frameworks/beeai). |
| Node.js / TypeScript | Start with the [`@traceai/auto` preload](/docs/integrations/traceai/auto) or install a dedicated instrumentor such as `@traceai/openai`. Check the Node guide for its supported SDKs and transports; do not assume Python package parity. |
| Java | Use the [Java client guides](/docs/integrations/traceai/java) or the [JVM startup agent](https://github.com/future-agi/traceAI/tree/fi-instrumentation-otel-v1.5.1/java/traceai-javaagent). For [Spring AI native observations](https://github.com/future-agi/traceAI/tree/fi-instrumentation-otel-v1.5.1/java/traceai-spring-ai), use `SpringAIObservationFilter` with `SpringAITracingObservationHandler` and let Spring Boot own the bridge and exporter. Do not also wrap a natively observed model in `TracedChatModel`. |
| Go | Use [OpenAI client middleware](/docs/integrations/traceai/go/openai), or a library-specific integration such as [Gemini](/docs/integrations/traceai/go/gemini). |
| .NET and Ruby | The [.NET startup hook](https://github.com/future-agi/traceAI/tree/fi-instrumentation-otel-v1.5.1/csharp/src/TraceAI.AutoInstrumentation) and [Ruby preload](https://github.com/future-agi/traceAI/tree/fi-instrumentation-otel-v1.5.1/ruby) have their own transport coverage and source-install instructions. Neither startup package was published to its registry in this release. |
