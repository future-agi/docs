**Agent Learning Kit (ALK)** is an open-source Python package for building test environments and evaluating agents. Try one conversation with a scripted agent first. You’ll see exactly what it said and whether it met the scenario’s goal, without connecting your own agent or providing an API key.

## Set up the example

From a terminal with Python 3.10 or later, install the package in a virtual environment. These commands use a macOS or Linux shell.

```bash
python3 -m venv .alk-venv
source .alk-venv/bin/activate
python -m pip install agent-learning-kit
export AGENT_LEARNING_SYNC=local
export LITELLM_LOCAL_MODEL_COST_MAP=True
agent-learn init alk-demo --preset run
cd alk-demo
```

Installation downloads dependencies. The two settings keep account sync local and tell LiteLLM to use its bundled pricing data. The scripted example can now run offline.

Open `manifests/run.json`. It pairs one scenario with one scripted reply. Kai needs a local check to pass, and the agent’s reply is already filled in. If `init` reports that it would overwrite files, choose a fresh directory name and use that name in the `cd` command too.

## Run the scenario from Python

Save this as `first_run.py` inside `alk-demo`. The SDK returns the run as a Python dictionary. The first result holds the conversation, and the summary tells you whether the evaluation passed.

```python
import asyncio

from fi.alk import simulate

run = asyncio.run(simulate.run_manifest_file("manifests/run.json"))
conversation = run["report"]["results"][0]
print(conversation["messages"][-1]["content"])
print("Evaluation passed:", run["summary"]["evaluation_passed"])
```

Run `python first_run.py`. You should see these two lines:

```text
The local CLI smoke test passes.
Evaluation passed: True
```

The first line is the agent’s reply. The second is ALK’s verdict on that scripted conversation. To inspect both sides of the exchange, print `conversation["transcript"]`.
