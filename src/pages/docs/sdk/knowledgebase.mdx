<TLDR>
- Import `KnowledgeBase` from `fi.kb` in the `futureagi` platform SDK.
- Upload PDF, DOCX, TXT, or RTF documents. Pass a list for individual files or a directory path for a folder.
- Use the knowledge base as a context source for evaluations. Uploading a file does not mean it has finished indexing.
</TLDR>

For concepts and platform usage, see the [Knowledge Base docs](/docs/knowledge-base). This example manages Ridgeline Outfitters' return and warranty policies. It leaves the current policy in your workspace and deletes a separate draft collection.

<Note>
  Set `FI_API_KEY` and `FI_SECRET_KEY` for a workspace that can create knowledge bases. Install the platform SDK in a separate virtual environment from Agent Learning Kit: both packages install files under `fi/`.
</Note>

```bash
python3.12 -m venv .venv-platform
source .venv-platform/bin/activate
python -m pip install futureagi==0.8.0
```

## Quick example

Run the Python snippets in order in one session. This first one writes a policy file and uploads it. The suffix makes both the local directory and the knowledge base unique to this example.

```python
from pathlib import Path
from uuid import uuid4
from fi.kb import KnowledgeBase

suffix = uuid4().hex[:12]
name = f"ridgeline-returns-{suffix}"
docs = Path(name)
docs.mkdir()
returns = docs / "returns.txt"
returns.write_text("Ridgeline accepts unused gear within 30 days of delivery.\n", encoding="utf-8")

kb = KnowledgeBase().create_kb(name=name, file_paths=[str(returns)])
policy_id = str(kb.kb.id)
print(f"Created {kb.kb.name}: {policy_id}")
```

Open **Knowledge base** in your workspace and look for the printed name. Use a list even for one file: in this SDK version a bare string is interpreted as a directory.

## Creating a knowledge base from a directory

For a directory upload, use a folder containing only the supported files you want to add. The SDK takes files directly inside the folder, not files in subdirectories. Here you create a separate draft collection to delete later.

```python
draft_name = f"ridgeline-draft-{suffix}"
draft_docs = docs / "draft"
draft_docs.mkdir()
(draft_docs / "draft.txt").write_text("Draft: review the return window.\n", encoding="utf-8")
draft = KnowledgeBase().create_kb(name=draft_name, file_paths=str(draft_docs))
draft_id = str(draft.kb.id)
```

## Loading an existing knowledge base

`KnowledgeBase(kb_name=...)` searches by name and selects the first result. Before you change anything, check that the name and ID match the intended collection. A loaded client caches the ID and name; it does not download the documents.

```python
kb = KnowledgeBase(kb_name=name)
if kb.kb.name != name or str(kb.kb.id) != policy_id:
    raise ValueError("The lookup did not select the returns knowledge base.")
```

## Updating

Rename the policy collection and upload a new document in the same request. Give each added file a name that is not already present.

```python
warranty = docs / "warranty.txt"
warranty.write_text("Ridgeline covers tent pole defects for one year.\n", encoding="utf-8")
current_name = f"{name}-current"
kb.update_kb(kb_name=name, new_name=current_name, file_paths=[str(warranty)])
print(kb.kb.name)
```

## Deleting files

Delete by the exact file name, including the extension. Omitting `kb_name` targets the loaded collection. This removes `returns.txt` but leaves `warranty.txt` in the renamed knowledge base.

```python
kb.delete_files_from_kb(file_names=[returns.name])
```

## Deleting a knowledge base

Use the ID from creation when you know which collection to delete. The following deletes only the draft, not the policy collection.

```python
draft.delete_kb(kb_ids=draft_id)
```

## Method reference

| Method | What it does | Returns |
|--------|-------------|---------|
| `create_kb(name, file_paths)` | Create a collection. Supply a list of file paths or a directory path to upload documents. | Client |
| `update_kb(kb_name, new_name, file_paths)` | Add files and optionally rename the collection. | Client |
| `delete_files_from_kb(file_names, kb_name)` | Remove named files from the selected collection. | Client |
| `delete_kb(kb_ids, kb_names)` | Delete by ID or name. Both accept one string or a list. Prefer IDs to avoid ambiguous name lookups. | Client |
