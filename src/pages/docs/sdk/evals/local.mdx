<TLDR>
- Use `LocalEvaluator` for checks such as valid JSON or a required phrase without a Future AGI API key.
- Use `HybridEvaluator` to see which metrics need the cloud before you run them.
- After you download an Ollama model, you can judge responses without a hosted LLM.
</TLDR>

If Ridgeline Outfitters' support agent returns JSON, you can check its format before making another model call. For a different question, such as whether the answer is relevant, you can route to a local LLM instead.

Use a fresh Python 3.12 environment. Run the Python examples in order in the same session. You only need an Ollama server for the Ollama section.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install agent-learning-kit==0.3.7
```

## Quick Example

```python
from fi.evals.local import LocalEvaluator

evaluator = LocalEvaluator()

# Check the support agent's structured reply
result = evaluator.evaluate("is_json", [{"response": '{"return_status": "eligible"}'}])
print(result.results.eval_results[0].output)  # 1.0
print(sorted(result.executed_locally))       # ['is_json']
```

## LocalEvaluator

Use `fail_on_unsupported` to choose between a skipped result and an exception when a metric is not supported locally.

```python
from fi.evals.local import LocalEvaluator, LocalEvaluatorConfig

evaluator = LocalEvaluator(
    config=LocalEvaluatorConfig(
        fail_on_unsupported=False,
    )
)
```

### Single metric

```python
result = evaluator.evaluate(
    "bleu_score",
    [{"response": "unused gear ships", "expected_response": "unused gear ships in five days"}],
)

for r in result.results.eval_results:
    print(f"{r.name}: {r.output:.3f}")  # bleu_score: 0.207
print(sorted(result.executed_locally))  # ['bleu_score']
```

### With config

Pass metric-specific options in `config`. Here you check that the reply names the return window:

```python
result = evaluator.evaluate(
    "contains",
    [{"response": "You can return unused gear within 30 days."}],
    config={"keyword": "30 days"},
)
print(result.results.eval_results[0].output)  # 1.0
```

### Batch evaluation

Run multiple metrics in one call:

```python
result = evaluator.evaluate_batch([
    {"metric_name": "is_json", "inputs": [{"response": '{"valid": true}'}]},
    {"metric_name": "one_line", "inputs": [{"response": "single line output"}]},
    {"metric_name": "contains", "inputs": [{"response": "Return approved"}], "config": {"keyword": "approved"}},
    {"metric_name": "bleu_score", "inputs": [{"response": "unused gear", "expected_response": "unused gear ships"}]},
])

for r in result.results.eval_results:
    print(f"{r.name}: {r.output}")
print(sorted(result.executed_locally))  # ['bleu_score', 'contains', 'is_json', 'one_line']
```

### Check what runs locally

```python
from fi.evals.local import can_run_locally, LOCAL_CAPABLE_METRICS

print(can_run_locally("bleu_score"))  # True
print(can_run_locally("toxicity"))    # False
print(sorted(LOCAL_CAPABLE_METRICS))
print(evaluator.can_run_locally("is_json"))  # True
```

`LOCAL_CAPABLE_METRICS` lists heuristic names. `LocalEvaluator.can_run_locally()` also checks whether the name is registered. A registered metric outside the heuristic set won't run through `LocalEvaluator.evaluate()`. Some heuristics need extra resources: for example, BLEU can download NLTK's `punkt` data on first use. Install it before going offline.

## HybridEvaluator

The hybrid evaluator selects a route before scoring. You can inspect a cloud route without credentials. If no cloud evaluator is configured, evaluating a cloud-only metric returns a skipped result; it doesn't submit a hosted evaluation.

```python
from fi.evals.local import HybridEvaluator

evaluator = HybridEvaluator(prefer_local=True, offline_mode=False)
```

### Auto-routing

```python
from fi.evals.local import HybridEvaluator, RoutingMode

evaluator = HybridEvaluator()

# Check where a metric will run
print(evaluator.route_evaluation("is_json"))       # local
print(evaluator.route_evaluation("toxicity"))       # cloud
print(evaluator.route_evaluation("faithfulness"))   # cloud

# Force routing
print(evaluator.route_evaluation("is_json", force_cloud=True))  # cloud
```

### Partition evaluations

Split a batch into local vs cloud groups:

```python
evaluator = HybridEvaluator()

evaluations = [
    {"metric_name": "is_json", "inputs": [{"response": "{}"}]},
    {"metric_name": "toxicity", "inputs": [{"response": "hello"}]},
    {"metric_name": "bleu_score", "inputs": [{"response": "test", "expected_response": "test"}]},
]

partitioned = evaluator.partition_evaluations(evaluations)
for mode, evals in partitioned.items():
    print(f"{mode.value}: {[e['metric_name'] for e in evals]}")
# local: ['is_json', 'bleu_score']
# cloud: ['toxicity']
```

### Evaluate

```python
# The JSON check takes the local route.
result = evaluator.evaluate("is_json", [{"response": '{"key": "value"}'}])
print(result.results.eval_results[0].output)  # 1.0
```

<Note>
  `HybridEvaluator.evaluate()` takes the metric name as its first positional argument (parameter is named `template` internally). You can also pass it as `template="is_json"`.
</Note>

### Offline mode

With `offline_mode=True`, a single evaluation raises `ValueError` if the metric would require the cloud:

```python
evaluator = HybridEvaluator(offline_mode=True)

# Local metrics work fine
result = evaluator.evaluate("is_json", [{"response": "{}"}])  # works

# Cloud metrics raise ValueError
try:
    evaluator.route_evaluation("toxicity")
except ValueError as e:
    print(e)  # "Metric 'toxicity' requires cloud execution but offline_mode is enabled"
```

## Ollama Integration

### Setup

Install [Ollama](https://ollama.com), start its local server (`ollama serve` if it isn't already running), and run `ollama pull llama3.2:1b` while online. After the download, the judge uses the model on your machine. A reachable server alone doesn't guarantee that the requested model is installed.

```python
from fi.evals.local import OllamaLLM, LocalLLMConfig

llm = OllamaLLM(config=LocalLLMConfig(model="llama3.2:1b"))
print(llm.is_available())                     # True when the server is reachable
print(llm.config.model in llm.list_models())  # True after pulling this model
```

### Using with HybridEvaluator

```python
from fi.evals.local import HybridEvaluator

evaluator = HybridEvaluator(local_llm=llm, offline_mode=True)
print(evaluator.can_use_local_llm("relevance"))  # True
print(evaluator.route_evaluation("relevance"))   # local
```

<Tip>
  LLM-based metrics that can run through Ollama: `coherence`, `relevance`, `answer_relevance`, `context_relevance`, `groundedness`, `hallucination`, `safety`, `tone`, `bias`, `pii`, `custom_llm_judge`.
</Tip>

### Direct LLM usage

Give the judge a specific criterion. Check for generation and parsing errors before treating the returned score as a verdict. The score and explanation depend on the model.

```python
verdict = llm.judge(
    query="How long do I have to return my unused jacket?",
    response="You have 30 days to return it.",
    criteria="Does the reply state a 30-day return window?",
)
if verdict.get("error") or verdict.get("parse_error"):
    raise ValueError(verdict["reason"])
print(f"Judge score: {verdict['score']:.2f}")
print(verdict["reason"])

# Score a batch against the same criterion.
checks = [
    {"query": "What is the return window?", "response": answer,
     "criteria": "Does the reply state a 30-day return window?"}
    for answer in ["You have 30 days.", "Ask the store."]
]
for item in llm.batch_judge(checks):
    if item.get("error") or item.get("parse_error"):
        raise ValueError(item["reason"])
    print(f"Batch score: {item['score']:.2f}")

# Generate an unscored reply, with or without chat history.
print("Draft:", llm.generate("Suggest a subject line for a return confirmation.", max_tokens=40))
print("Reply:", llm.chat([
    {"role": "system", "content": "You help Ridgeline Outfitters customers."},
    {"role": "user", "content": "What should I include when I ask about my return?"},
], max_tokens=50))
```

### Factory

Create LLM instances programmatically:

```python
from fi.evals.local import LocalLLMFactory, LocalLLMConfig

# By backend name
llm = LocalLLMFactory.create(backend="ollama", config=LocalLLMConfig(model="llama3.2:1b"))

# From a spec string (format: "backend/model")
llm = LocalLLMFactory.from_string("ollama/llama3.2:1b")
```

## Metric Registry

The registry maps names to metric classes. Use it to discover metrics or register custom ones.

```python
from fi.evals.local import get_registry

registry = get_registry()

# List all registered metrics
metrics = registry.list_metrics()
print("bleu_score" in metrics)  # True

# Check if a metric is registered
print(registry.is_registered("bleu_score"))  # True

# Get a metric class (use registry.create() for an instance)
metric_cls = registry.get("bleu_score")
```

### Registering custom metrics

To run a newly registered name, create its metric instance and call `evaluate()` on that instance. Registration doesn't add the name to the local evaluator's heuristic set.

```python
from fi.evals.local import get_registry
from fi.evals.metrics.base_metric import BaseMetric
from fi.evals.types import TextMetricInput

class ReturnWindowMention(BaseMetric[TextMetricInput]):
    metric_name = "return_window_mention"

    def compute_one(self, inputs):
        found = "30 days" in inputs.response.lower()
        return {"output": float(found), "reason": f"Mentions 30 days: {found}"}

registry = get_registry()
registry.register("return_window_mention", ReturnWindowMention)
metric = registry.create("return_window_mention")
rows = metric.evaluate([{"response": "You can return it within 30 days."}])
print(rows.eval_results[0].output)  # 1.0
```

### Lazy registration

If a metric needs a separate module, put its import in a loader. The registry calls the loader the first time you request the class.

```python
def load_return_check():
    from fi.evals.metrics.heuristics.string_metrics import Contains
    return Contains

registry.register_lazy("return_check", load_return_check)
metric = registry.create("return_check", {"keyword": "30 days"})
print(metric.evaluate([{"response": "Returns close after a week."}]).eval_results[0].output)  # 0.0
```

## Routing Logic

```python
from fi.evals.local import select_routing_mode, RoutingMode

# Auto-select based on capability
mode = select_routing_mode("is_json", RoutingMode.HYBRID)       # LOCAL
mode = select_routing_mode("toxicity", RoutingMode.HYBRID)      # CLOUD
mode = select_routing_mode("is_json", RoutingMode.CLOUD)        # CLOUD - preferred_mode overrides

# Force overrides
mode = select_routing_mode("is_json", RoutingMode.HYBRID, force_local=True)   # LOCAL
mode = select_routing_mode("toxicity", RoutingMode.HYBRID, force_cloud=True)  # CLOUD
```

<Warning>
  `force_local=True` raises `ValueError` if the metric isn't in `LOCAL_CAPABLE_METRICS`. Only use it with metrics you know can run locally.
</Warning>

## Result Types

### LocalEvaluationResult

| Field | Type | Description |
|-------|------|-------------|
| `results` | `BatchRunResult` | Evaluation results (same format as cloud) |
| `executed_locally` | `set[str]` | Metric names that ran locally |
| `skipped` | `set[str]` | Metrics that were skipped |
| `errors` | `dict[str, str]` | Metric name to error message |

```python
evaluator = LocalEvaluator()
result = evaluator.evaluate_batch([
    {"metric_name": "is_json", "inputs": [{"response": "{}"}]},
    {"metric_name": "toxicity", "inputs": [{"response": "Hello!"}]},
    {"metric_name": "contains", "inputs": [{"response": "30 days"}]},  # missing keyword
])
print(sorted(result.executed_locally))  # ['is_json']
print(sorted(result.skipped))           # ['toxicity']
print(result.errors["contains"])        # Contains metric requires a 'keyword' config.

for r in result.results.eval_results:
    print(f"{r.name}: score={r.output}, reason={r.reason}")
```

## When to Use What

| Scenario | Use |
|----------|-----|
| CI pipeline, no API keys | `LocalEvaluator` or `HybridEvaluator(offline_mode=True)` |
| Air-gapped environment | `HybridEvaluator` + `OllamaLLM` |
| Development/testing | `LocalEvaluator` for fast iteration |
| Production with cost control | Inspect `HybridEvaluator` routes before you submit hosted calls |
| Need toxicity/faithfulness | Use [hosted evaluations](/docs/sdk/evals/evaluate) for Turing scores |
| Need LLM scoring offline | `HybridEvaluator` + `OllamaLLM` |
