<TLDR>
- Give the judge a rubric in `prompt` and the material to grade in fields such as `query`, `output`, and `context`.
- Choose a model that can return a numeric score and explanation as JSON.
- Use `generate_prompt=True` if you want a model to expand a short description into a rubric first.
</TLDR>

Use an LLM judge when a string check or a built-in template does not capture what matters to you. For example, a reply can mention a return window without telling the customer how to start the return.

## Quick Example

Install the kit in a fresh Python environment and set `OPENAI_API_KEY` in your shell. The examples use `gpt-4o-mini`; your model provider receives the grading criteria and inputs. Run the Python blocks in order in one session.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install agent-learning-kit==0.3.7
```

```python
import json
from fi.evals import evaluate

model = "gpt-4o-mini"
question = "How do I return my unused backpack?"
reply = "Open your order, choose Return, and download the prepaid label."
result = evaluate(
    prompt="Rate helpfulness from 0 to 1. A helpful reply answers the question with specific next steps.",
    output=reply,
    query=question,
    engine="llm",
    model=model,
)

def show(label, result):
    # A successful custom judge returns the score and explanation together as JSON.
    try:
        judgment = json.loads(result.reason)
    except (TypeError, ValueError) as exc:
        raise RuntimeError("The judge did not return a valid judgment. Check your model and credentials.") from exc
    print(f"{label}: {result.score:.2f} | {judgment['reason']}")

show("Helpfulness", result)
```

## How It Works

1. The SDK uses `prompt` as the grading criteria and includes the input fields separately. It does **not** interpolate `{query}` or `{output}` inside the rubric.
2. The judge receives the criteria, the inputs, and the requested JSON output format.
3. A successful call returns an `EvalResult` with a `score` from 0 to 1 and a JSON-encoded `reason`. The SDK derives `passed` from `score >= 0.5`. Inspect the reason as well: a provider or parsing failure can produce a zero score without a valid judgment.

## Writing Criteria

### Simple criteria

Anchor the scale with an example of what deserves full credit. The exact score can vary across calls.

```python
result = evaluate(
    prompt="Rate the tone of the support reply. Score 1 for courteous and professional, 0 for dismissive or rude.",
    output="Read the returns page yourself.",
    engine="llm", model=model,
)
show("Tone", result)
```

### Criteria with input references

Name the fields the judge should compare, then supply their values. You do not need to repeat the customer's question inside the rubric.

```python
result = evaluate(
    prompt="Does the output answer the query? Score 1 for a direct answer and 0 for an unrelated reply.",
    query="How many days do I have to return an unused pack?",
    output="You have 30 days from delivery.",
    engine="llm", model=model,
)
show("Relevance", result)
```

### Multi-dimensional criteria

Provide the policy when you ask the judge about accuracy. Without it, the judge can assess tone but cannot verify Ridgeline Outfitters' return terms.

```python
result = evaluate(
    prompt="""Give one score from 0 to 1. Weight three criteria equally:
- Empathy: does the output acknowledge the customer's frustration?
- Accuracy: does it follow the policy in context?
- Actionability: does it explain what to do next?""",
    query="My pack doesn't fit and I'm frustrated. Now what?",
    context="Unused packs may be returned within 30 days of delivery. Start the return on the order page.",
    output="I'm sorry the fit didn't work. If the pack is unused and arrived within 30 days, open your order and choose Return.",
    engine="llm", model=model,
)
show("Support quality", result)
```

## Auto-Generated Rubrics

Set `generate_prompt=True` to expand a short description before judging. The first call adds a model request; the SDK caches the generated text in the current process by description and model, not by input fields or values.

```python
criteria = "Check whether the reply acknowledges the customer's frustration."
case = {"output": "I'm sorry the pack didn't fit after you waited for delivery. Let's get the return started."}
for label, expand in [("Original rubric", False), ("Expanded rubric", True)]:
    result = evaluate(prompt=criteria, engine="llm", model=model, generate_prompt=expand, **case)
    show(label, result)
```

To inspect the rubric, call `generate_grading_criteria()` with the same description, model, and an inputs dictionary. When generating new criteria, the helper uses the field names, not the example values. Pass `cache=False` to regenerate instead of reusing previously generated text.

```python
from fi.evals.core.prompt_generator import generate_grading_criteria

rubric = generate_grading_criteria(criteria, model=model, inputs=case)
print("Generated rubric:", rubric)
```

## Supported Models

The judge uses [LiteLLM](https://docs.litellm.ai/docs/providers) to reach the model. Use a model identifier available to your account or local server. The model must reliably produce a JSON score and explanation.

| Provider | Model selection | Credentials |
|----------|-----------------|-------------|
| OpenAI | `gpt-4o-mini` in the examples | `OPENAI_API_KEY` |
| Other hosted providers | Use the provider's LiteLLM model identifier | Provider-specific credentials |
| Ollama | Use `ollama/` followed by an installed model tag | A running local Ollama server |
