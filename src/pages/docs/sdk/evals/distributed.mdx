<TLDR>
- Three modes: blocking (sync), non-blocking (async), distributed (via backends)
- Backends: ThreadPool (default), Celery, Ray, Temporal, Kubernetes
- Built-in resilience: circuit breakers, rate limiting, retries, graceful degradation
</TLDR>

The `FrameworkEvaluator` runs evaluations in three ways: wait for results, collect them later from a future, or submit work to a backend. Local scorers return in-memory results; calling a hosted evaluation from a scorer also creates a hosted evaluation record.

Start in a fresh Python environment. Run the interactive examples in order; the Celery client and hosted example below are separate scripts.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install agent-learning-kit==0.3.7
```

## Quick Example

```python
from fi.evals.framework import blocking_evaluator, custom_eval

@custom_eval(name="length_check", required_fields=["response"])
def check_length(inputs):
    length = len(inputs["response"])
    return {"score": min(length / 100, 1.0), "passed": length > 20}

evaluator = blocking_evaluator(check_length)
reply = {"response": "You can return an unused pack within 30 days of delivery."}
result = evaluator.run(reply)

print(result.batch.success_rate)  # 1.0
for r in result.batch.results:
    print(f"{r.eval_name}: score={r.value.score}, passed={r.value.passed}")
```

## Execution Modes

| Mode | Factory | When to use |
|------|---------|-------------|
| `BLOCKING` | `blocking_evaluator()` | Development, testing, simple scripts |
| `NON_BLOCKING` | `async_evaluator()` | Production APIs where latency matters |
| `DISTRIBUTED` | `distributed_evaluator()` | Large-scale batch runs across workers |

### Blocking (synchronous)

Runs evaluations and waits for results.

```python
from fi.evals.framework import blocking_evaluator

evaluator = blocking_evaluator(check_length, fail_fast=True)
result = evaluator.run(reply)

print(result.batch.success_rate)
for r in result.batch.results:
    print(f"{r.eval_name}: {r.value}")
```

### Non-blocking (async)

Returns immediately with a future. Results compute in background threads.

```python
from fi.evals.framework import async_evaluator

with async_evaluator(check_length, max_workers=8) as evaluator:
    result = evaluator.run(reply)
    # Do other work before collecting the result.
    batch = result.wait(timeout=30)
    print(batch.success_rate)  # 1.0
```

### Distributed

`distributed_evaluator()` submits one task per evaluation and collects the results before `run()` returns. Start with the same contract on a local thread pool:

```python
from fi.evals.framework import distributed_evaluator
from fi.evals.framework.backends import ThreadPoolBackend, ThreadPoolConfig

backend = ThreadPoolBackend(ThreadPoolConfig(max_workers=2, timeout_seconds=30))
with distributed_evaluator(check_length, backend=backend) as evaluator:
    batch = evaluator.run(reply).batch
    print(batch.results[0].value.passed)  # True
```

## Backends

### ThreadPool

The explicit backend above runs in your process. For `async_evaluator()`, set `max_workers` on the factory instead; the result is a future. Neither option requires a queue or another service.

### Celery

To run the scorer in a **separate worker process**, install Celery and its SQLAlchemy transport. This single-machine example uses private SQLite files as a disposable broker and result store. For multiple machines, use a shared, access-controlled broker and result backend. Only trusted clients should have write access: the worker deserializes Python callables.

```bash
python -m pip install 'celery[sqlalchemy]>=5.4,<6' cloudpickle
```

Save this client as `distributed_check.py`. The worker and client must use the same kit version, queue and connection settings.

```python
import os
from fi.evals.framework import distributed_evaluator, simple_eval
from fi.evals.framework.backends import CeleryBackend, CeleryConfig

check_length = simple_eval("min_length", lambda x: float(len(x["response"]) >= 20))
backend = CeleryBackend(CeleryConfig(
    broker_url=os.environ["CELERY_BROKER_URL"],
    result_backend=os.environ["CELERY_RESULT_BACKEND"],
    task_queue="pack_checks",
    timeout_seconds=60,
))
with distributed_evaluator(check_length, backend=backend) as evaluator:
    row = evaluator.run({"response": "Your pack is ready for pickup."}).batch.results[0]
    if row.error:
        raise RuntimeError(row.error)
    print(f"{row.eval_name}: passed={row.value.passed}")  # min_length: passed=True
```

Run this in Bash from the directory containing the client. The subshell stops its worker and removes its temporary queue files when the client exits.

```bash
(
  set -eu
  queue_dir=$(mktemp -d)
  export CELERY_BROKER_URL="sqla+sqlite:///$queue_dir/broker.sqlite"
  export CELERY_RESULT_BACKEND="db+sqlite:///$queue_dir/results.sqlite"
  celery -A fi.evals.framework.backends.celery_worker worker --pool=solo \
    --without-gossip --without-mingle --without-heartbeat -Q pack_checks \
    > "$queue_dir/worker.log" 2>&1 &
  worker_pid=$!
  trap 'kill "$worker_pid" 2>/dev/null || :; wait "$worker_pid" || :; rm -rf "$queue_dir"' EXIT
  python distributed_check.py
)
```

### Ray

`RayConfig` describes how to connect to Ray; it does not start a cluster. For an existing Ray deployment, install the compatible `ray` client before constructing `RayBackend(config)`.

```python
from fi.evals.framework.backends import RayConfig

config = RayConfig(address="auto", num_cpus=1, namespace="pack-checks")
```

### Temporal

`TemporalConfig` names the server, namespace and queue. To submit work, you also need `temporalio`, a reachable Temporal server and a worker polling that queue. Creating the config below makes no network call.

```python
from fi.evals.framework.backends import TemporalConfig

config = TemporalConfig(host="localhost:7233", namespace="default", task_queue="pack-checks")
```

## Resilience

Apply a circuit breaker, rate limit and retries to task submission. These settings do not turn a failing score into a pass. If you add a fallback backend, use a different backend name from the primary: version 0.3.7 uses that name to route result lookups.

```python
from fi.evals.framework import resilient_evaluator
from fi.evals.framework.resilience import (
    ResilienceConfig, CircuitBreakerConfig, RateLimitConfig, RetryConfig,
)

evaluator = resilient_evaluator(
    check_length,
    resilience=ResilienceConfig(
        circuit_breaker=CircuitBreakerConfig(failure_threshold=5, timeout_seconds=30),
        rate_limit=RateLimitConfig(requests_per_second=10, burst_size=20),
        retry=RetryConfig(max_retries=3, exponential_base=2.0, jitter=True),
    ),
)

with evaluator:
    result = evaluator.run(reply)
    print(result.batch.results[0].value.passed)  # True
```

### Presets

```python
config = ResilienceConfig.default()   # balanced defaults
config = ResilienceConfig.minimal()   # retries only
config = ResilienceConfig.strict()    # aggressive circuit breaking
```

## Custom Evaluations

Build your own scoring logic and run it through the framework.

### Decorator

```python
from fi.evals.framework import custom_eval

@custom_eval(name="tone_check", required_fields=["response"], threshold=0.7)
def check_tone(inputs):
    response = inputs["response"]
    is_professional = "dear" in response.lower() or "regards" in response.lower()
    return {"score": 1.0 if is_professional else 0.3, "passed": is_professional}
```

### Simple (one-liner)

```python
from fi.evals.framework import simple_eval

length_check = simple_eval(
    name="min_length",
    scorer=lambda inputs: min(len(inputs["response"]) / 100, 1.0),
    threshold=0.5,
    required_fields=["response"],
)
```

### Builder

```python
from fi.evals.framework import EvalBuilder

my_eval = (
    EvalBuilder("custom_relevance")
    .version("2.0.0")
    .required_fields(["response", "query"])
    .threshold(0.8)
    .evaluator(lambda inputs: {
        "score": float(inputs["query"].lower() in inputs["response"].lower()),
        "passed": inputs["query"].lower() in inputs["response"].lower(),
    })
    .build()
)

with blocking_evaluator(check_tone, length_check, my_eval) as evaluator:
    batch = evaluator.run({**reply, "query": "pack"}).batch
    for row in batch.results:
        print(row.eval_name, row.value.passed)
```

### Mixing custom + built-in

Set `FI_API_KEY` and `FI_SECRET_KEY` for your Future AGI account. Save this as `mixed_checks.py` and run `python mixed_checks.py`. The toxicity check uses the hosted API; the length check stays local. The last line is the hosted evaluation ID.

```python
from fi.evals.framework import blocking_evaluator, custom_eval, simple_eval
from fi.evals import evaluate as run_eval

@custom_eval(name="toxicity_wrapper", required_fields=["response"])
def toxicity_check(inputs):
    result = run_eval("toxicity", output=inputs["response"], model="turing_flash")
    if result.score is None or result.error:
        raise RuntimeError("The hosted toxicity check did not return a score")
    return {"score": result.score, "passed": result.passed, "eval_id": result.metadata["eval_id"]}

length_check = simple_eval("min_length", lambda i: min(len(i["response"]) / 100, 1.0))

evaluator = blocking_evaluator(toxicity_check, length_check)
result = evaluator.run({"response": "You can exchange the hiking pack at any of our stores."})
for row in result.batch.results:
    if row.error:
        raise RuntimeError(row.error)
    print(row.eval_name, row.value.score, row.value.passed)
print(result.batch.get_by_name("toxicity_wrapper")[0].value.details["eval_id"])
```

## Result Types

### EvaluatorResult

Returned by `evaluator.run()`.

| Field/Method | Type | Description |
|-------------|------|-------------|
| `.batch` | BatchEvalResult | Results (blocking and distributed modes) |
| `.future` | BatchEvalFuture | Future (non-blocking mode) |
| `.is_future` | bool | Whether result is a future |
| `.wait(timeout)` | BatchEvalResult | Block until done |

### BatchEvalResult

| Field/Method | Type | Description |
|-------------|------|-------------|
| `.success_rate` | float | Fraction that completed, not fraction with a passing score |
| `.avg_latency_ms` | float | Average per-evaluation time |
| `.total_count` | int | Number of evaluations |
| `.success_count` | int | Evaluations that completed, regardless of verdict |
| `.failure_count` | int | Execution failures |
| `.get_by_name(name)` | list | Results for a specific evaluation |
| `.get_failures()` | list | Only results with a failed execution status |
