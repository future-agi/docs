<TLDR>
- Use `is_json` for a complete JSON response or `contains_json` for an object or array embedded in prose.
- Pass `schema=` to check a contract and `expected=` to compare with an example object.
- These metrics run locally. You don't need a model or an API key.
</TLDR>

Suppose your Ridgeline Outfitters support agent returns an item and the quantity to refund. Start by checking that the response parses, then check what the fields contain. Install the kit in a Python 3.12 virtual environment:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install agent-learning-kit==0.3.7
```

Run the Python examples in order in the same session. They reuse the response below and the schema defined under `json_schema`.

```python
from fi.evals import evaluate

output = '{"sku": "TRAIL-42", "quantity": 2}'
result = evaluate("is_json", output=output)
print(result.score)   # 1.0
print(result.passed)  # True
```

## JSON Metrics

| Metric | What it checks |
|--------|---------------|
| `is_json` | The entire response parses as JSON |
| `contains_json` | An object or array embedded in text parses as JSON |
| `json_schema` | The response satisfies a supplied JSON Schema (binary score) |
| `json_validation` | Syntax, then schema compliance or agreement with an expected value (partial credit possible) |
| `json_syntax` | JSON syntax only |

### is_json

Extra prose makes the response invalid as a whole, even when it contains a valid object.

```python
print(evaluate("is_json", output=output).score)              # 1.0
print(evaluate("is_json", output=f"Refund: {output}").score)  # 0.0
```

### contains_json

Use this when the agent is allowed to include prose around a single JSON object or array.

```python
result = evaluate("contains_json", output=f"Refund: {output}")
print(result.score)  # 1.0
```

### json_schema

Pass the schema as a `schema` input, not inside `config`. The schema below requires a string SKU and an integer quantity.

```python
refund_schema = {
    "type": "object",
    "properties": {"sku": {"type": "string"}, "quantity": {"type": "integer"}},
    "required": ["sku", "quantity"],
}
result = evaluate("json_schema", output=output, schema=refund_schema)
print(result.score)  # 1.0
```

### json_validation

Without a schema or expected value, this checks only syntax. Supply an `expected` object to catch a response that parses but refunds the wrong quantity.

```python
result = evaluate("json_validation", output=output, expected={"sku": "TRAIL-42", "quantity": 1})
print(result.score)  # 0.3: valid JSON, wrong value
```

### json_syntax

JSON booleans are lowercase. Python's `True` is not valid JSON.

```python
print(evaluate("json_syntax", output='{"refundable": true}').score)  # 1.0
print(evaluate("json_syntax", output='{"refundable": True}').score)  # 0.0
```

## Structured Output Metrics

Pass the agent's output as JSON text. For the comparison, supply a JSON Schema or an example Python dictionary, depending on what you want to measure.

| Metric | What it measures |
|--------|-----------------|
| `schema_compliance` | Conformance to a schema, with partial credit |
| `type_compliance` | Whether field types match the schema |
| `field_completeness` | Presence of schema fields, weighting required fields more than optional ones by default |
| `required_fields` | Fraction of top-level required fields present |
| `field_coverage` | Fraction of expected field paths present, regardless of value |
| `hierarchy_score` | Similarity of paths, types, and nesting depth |
| `tree_edit_distance` | Normalized edit distance; lower is better |
| `structured_output_score` | Weighted score for syntax, schema, completeness, types, and values |
| `quick_structured_check` | Lightweight syntax and top-level key check |

### schema_compliance

Use `mode="strict"` when you don't want the validator to coerce values to the schema's types.

```python
result = evaluate("schema_compliance", output=output, schema=refund_schema, mode="strict")
print(result.score)  # 1.0
```

### type_compliance

Check field types rather than exact values. The quantity `2` is an integer, as required by the schema.

```python
result = evaluate("type_compliance", output=output, schema=refund_schema)
print(result.score)  # 1.0
```

### field_completeness

Both fields in `refund_schema` are required. An output with just the SKU gets half credit.

```python
result = evaluate("field_completeness", output='{"sku": "TRAIL-42"}', schema=refund_schema)
print(result.score)  # 0.5
```

### required_fields

Use this when only the presence of top-level required fields matters. It doesn't check their types or values.

```python
result = evaluate("required_fields", output=output, schema=refund_schema)
print(result.score)  # 1.0
```

### field_coverage

A key with a `null` value is still present. This response includes two of the three expected keys; only `reason` is absent.

```python
result = evaluate(
    "field_coverage",
    output='{"sku": "TRAIL-42", "quantity": null}',
    expected={"sku": "TRAIL-42", "quantity": 2, "reason": "wrong size"},
)
print(result.score)  # 0.6667
```

### hierarchy_score

Compare nested structure rather than literal values. Both responses place a string at `refund.item.sku`.

```python
result = evaluate(
    "hierarchy_score",
    output='{"refund": {"item": {"sku": "TRAIL-42"}}}',
    expected={"refund": {"item": {"sku": "PACK-12"}}},
)
print(result.score)  # 1.0
```

### tree_edit_distance

This metric returns a distance, not a similarity. Compare `score` directly: identical trees have distance `0.0`. The generic `passed` flag assumes higher scores are better.

```python
expected_refund = {"sku": "TRAIL-42", "quantity": 2}
result = evaluate("tree_edit_distance", output=output, expected=expected_refund)
print(result.score)  # 0.0
```

### structured_output_score

Supply both the schema and a reference object to evaluate all five components. If you omit either input, its components contribute no points.

```python
result = evaluate(
    "structured_output_score", output=output, schema=refund_schema, expected=expected_refund
)
print(result.score)  # 1.0
```

### quick_structured_check

For an object with required keys, valid syntax earns half the score; the rest depends on the fraction of those keys present. It does not check their values.

```python
result = evaluate("quick_structured_check", output='{"sku": "TRAIL-42"}', schema=refund_schema)
print(result.score)  # 0.75
```
