<TLDR>
- Call `scanner.scan(text)` to check a message locally. The examples below don't need an API key.
- Use `result.passed` for the decision. A match is a signal to review the message, not proof of an attack.
</TLDR>

Ridgeline Outfitters wants to catch customer contact details before a support reply goes into a public ticket. You can scan the reply in memory and record which rule matched without logging the reply itself. Install the kit in a fresh environment, then run the Python examples in order in one session.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install agent-learning-kit==0.3.7
```

```python
from fi.evals.guardrails.scanners import RegexScanner

contact = RegexScanner(patterns=["email", "phone_us"])
result = contact.scan("Please contact shopper@example.com about the return.")
print(result.passed)            # False
print(result.matched_patterns)  # ['email']
```

## Scanners

| What you want to check | Local scanner |
|------------------------|---------------|
| Prompt manipulation | `JailbreakScanner` looks for phrases associated with instruction overrides. |
| Personal data | `RegexScanner` looks for formats you choose, such as emails and US phone numbers. It doesn't identify arbitrary names or street addresses. |
| Secrets | `SecretsScanner` recognizes formats such as private-key headers. |
| SQL-like text | `CodeInjectionScanner` recognizes SQL patterns as well as other kinds of code. It doesn't execute the text. |

### Prompt manipulation

The default `JailbreakScanner` uses patterns, not a model. Even a support article quoting a suspicious phrase can match.

```python
from fi.evals.guardrails.scanners import JailbreakScanner

prompt = JailbreakScanner()
print(prompt.scan("The manual describes developer mode.").passed)  # False
print(prompt.scan("What size jacket should I order?").passed)     # True
```

### Personal data

Use the `contact` scanner from above. It checks only the two formats you selected.

```python
print(contact.scan("Email the label to returns@example.org.").passed)  # False
print(contact.scan("Your return label is ready.").passed)              # True
```

### Secrets

A private-key header alone triggers this rule. You don't need a real key, and you shouldn't log the matched text.

```python
from fi.evals.guardrails.scanners import SecretsScanner

secrets = SecretsScanner()
print(secrets.scan("-----BEGIN PRIVATE KEY-----").passed)       # False
print(secrets.scan("Keep credentials out of tickets.").passed)  # True
```

### SQL-like text

Even the name of a SQL operation can match. Use a scanner as an early warning, not as a substitute for parameterized queries.

```python
from fi.evals.guardrails.scanners import CodeInjectionScanner

code = CodeInjectionScanner()
print(code.scan("The SQL glossary has an entry for DROP TABLE.").passed)  # False
print(code.scan("Search the catalog by item number.").passed)             # True
```

## Using Guardrails in Production

Before publishing a reply, stop on the first failed check. This example treats any scanner match as a reason for review. If a scanner raises an exception, don't publish the unchecked reply. A pass means that none of these scanners flagged the text, not that it contains no sensitive information.

```python
def review_before_publishing(reply: str) -> str:
    for scanner in (prompt, contact, secrets, code):
        result = scanner.scan(reply)
        if not result.passed:
            return f"Review: {result.scanner_name}"
    return "Ready to publish"

print(review_before_publishing("Your jacket is on its way."))  # Ready to publish
print(review_before_publishing("CC shopper@example.com."))     # Review: regex
```
