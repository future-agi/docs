<TLDR>
- Use `faithfulness` or `claim_support` to compare a reply with its context. Use `factual_consistency` when you have a reference answer.
- Higher scores mean better grounding. `contradiction_detection` returns `0.0` if it detects a contradiction and `1.0` otherwise.
- The base install uses word overlap. For judgments that depend on meaning rather than shared words, you can add a local NLI model or ask an LLM to review the result.
</TLDR>

Ridgeline Outfitters' return policy supports one sentence in this reply and says nothing about the other. The reply passes the SDK's default threshold even though the second claim is unsupported. Read the reason alongside the score.

Start with a fresh Python 3.12 environment. Run the Python examples in the same session until you reach the optional NLI installation.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install agent-learning-kit==0.3.7
```

```python
from fi.evals import evaluate

policy = "Unused jackets can be returned within 30 days."
reply = "Unused jackets can be returned within 30 days. Every tent includes a repair kit."
result = evaluate("faithfulness", output=reply, context=policy)
print(result.score, result.passed)  # 0.7 True
print(result.reason)               # 1/2 claims supported. 1 neutral
```

## Metrics

| Metric | How to interpret the local score |
|--------|----------------------------------|
| `faithfulness` | Averages claim-level judgments. Supported claims get full credit; neutral claims get partial credit. |
| `claim_support` | Averages support scores across claims, taking confidence into account. |
| `factual_consistency` | Compares claims to `reference` and penalizes contradictions. |
| `contradiction_detection` | Reports whether any claim contradicts `context`. A pass doesn't mean all claims were supported. |
| `hallucination_score` | Combines claim support, a contradiction penalty and a preliminary risk check. Lower is worse. |

### faithfulness

A reply that repeats the policy gets full credit. The SDK extracts claims from sentences, so a short fragment or question may not be counted as a claim.

```python
result = evaluate("faithfulness", output="Unused jackets can be returned within 30 days.", context=policy)
print(result.score, result.reason)  # 1.0 1/1 claims supported
```

### claim_support

The same two-claim reply scores differently on `claim_support`: the repair-kit sentence shares no meaningful words with the policy, so it contributes no support in the base install.

```python
result = evaluate("claim_support", output=reply, context=policy)
print(result.score)   # 0.5
print(result.reason)  # Average claim support: 50.0% across 2 claims
```

### factual_consistency

Pass the source as `reference`, not `context`. The answer only needs to be consistent with the reference; it doesn't need to repeat every fact.

```python
result = evaluate(
    "factual_consistency",
    output="Unused jackets can be returned within 30 days.",
    reference="Unused jackets can be returned within 30 days. Keep your receipt.",
)
print(result.score, result.reason)  # 1.0 Consistent: 1, Contradicted: 0, Neutral: 0, Total: 1
```

### contradiction_detection

Changing *can* to *cannot* reverses the policy. This metric flags the contradiction rather than measuring how much of the reply is correct.

```python
contradictory_reply = "Unused jackets cannot be returned within 30 days."
result = evaluate("contradiction_detection", output=contradictory_reply, context=policy)
print(result.score, result.passed)  # 0.0 False
```

### hallucination_score

Despite its name, a low `hallucination_score` means the reply is *less* grounded. Inspect the reason for the counts behind the score.

```python
result = evaluate("hallucination_score", output=contradictory_reply, context=policy)
print(result.score)   # 0.0
print(result.reason)  # Hallucination severity: severe. Supported: 0, Neutral: 0, Unsupported: 0, Contradicted: 1
```

## LLM Augmentation

All five metrics support `augment=True` with a judge model. The judge receives the reply, reference information and local analysis. Use text you can send to your provider, and set `OPENAI_API_KEY` in your environment for this OpenAI example. The judge's score and explanation can vary.

```python
import json

result = evaluate(
    "faithfulness",
    output="Items may be returned without their tags.",
    context="Returns require the original tags.",
    augment=True,
    model="openai/gpt-4o-mini",
)
if result.status != "completed" or result.metadata.get("engine") != "local+llm":
    raise RuntimeError("The LLM judgment did not complete.")
# A successful judge returns its score and explanation as JSON in reason.
judgment = json.loads(result.reason)
print(f"Judge score: {judgment['score']}")
print(judgment["reason"])
```

## NLI-Based Detection

Natural language inference (NLI) compares the meaning of two texts. To use it locally, install the NLI extra in the same environment. On Linux without a GPU, install the CPU build of PyTorch first:

```bash
if [ "$(uname -s)" = Linux ]; then
  python -m pip install 'torch>=2.10,<3' --index-url https://download.pytorch.org/whl/cpu
fi
python -m pip install 'agent-learning-kit[nli]==0.3.7'
```

Start a **new Python session** so the kit can detect the new dependencies. On first use it loads `cross-encoder/nli-deberta-v3-base` from Hugging Face. Allow network access for the initial download. If the model can't load, the SDK warns and falls back to word overlap. This pair illustrates the difference: *delivery is free* and *shipping costs nothing* share no content words.

```python
from fi.evals import evaluate

result = evaluate("faithfulness", output="Delivery is free.", context="Shipping costs nothing.")
print(result.score, result.reason)
```
