<TLDR>
- Start with the console exporter to see what your application records.
- `evaluate()` can create a scored child span inside your request trace. Use manual enrichment when you want a score on the request itself.
- Switch to the Future AGI exporter to see traces in your Observe project.
</TLDR>

## Setup

Install Agent Learning Kit in a fresh Python environment. For standalone instrumentation across your stack instead, see the [Tracing SDK](/docs/sdk/tracing).

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install agent-learning-kit==0.3.7
```

Save this helper as `tracing_config.py` alongside your application. Without an explicit exporter it writes to the console. Initialize the provider once per process.

```python
from fi.evals.otel import CostConfig, EvaluationConfig, TraceConfig, setup_tracing


def start_tracing(*, exporters=None, project_name=None):
    config = TraceConfig(
        service_name="ridgeline-support",
        processors=[],
        evaluation=EvaluationConfig(enabled=False),
        cost=CostConfig(enabled=False),
    )
    if exporters is not None:
        config.exporters = exporters
    return setup_tracing(config=config, project_name=project_name)
```

This configuration intentionally leaves the kit's automatic span processors off. In 0.3.7 they do not implement the span-ending hook expected by recent OpenTelemetry SDKs. You can still instrument clients, run explicit evaluations and export finished spans.

## Quick example: trace an OpenAI call

Set `OPENAI_API_KEY` in your environment. Save this as `trace_reply.py` and run `python trace_reply.py`. The console exporter prints a span named `openai.chat.completions.create`, including the requested model and the token counts returned by OpenAI. Instrumentation can capture message content; use non-sensitive inputs here.

```python
from openai import OpenAI
from fi.evals.otel import instrument, shutdown_tracing, uninstrument
from tracing_config import start_tracing

start_tracing()
try:
    if not instrument("openai"):
        raise RuntimeError("OpenAI instrumentation is unavailable")
    reply = OpenAI().chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": "In one sentence, explain a 30-day return window."}],
    )
    print(reply.choices[0].message.content)
finally:
    uninstrument("openai")
    shutdown_tracing()
```

### Auto-instrumentation and tracer utilities

`instrument_all()` tries the supported clients (OpenAI and Anthropic). Its return value depends on what is installed. To inspect the current status or remove the patches, run this in a Python session:

```python
from fi.evals.otel import instrument_all, is_instrumented, uninstrument_all

print(instrument_all())
print(is_instrumented("openai"))
uninstrument_all()
```

### Tracing LLM calls manually

Use `trace_llm_call()` instead of automatic instrumentation when you want to choose the span name and record usage yourself. The following three snippets run in order in one Python session, in the directory containing `tracing_config.py`.

```python
from openai import OpenAI
from fi.evals.otel import trace_llm_call
from tracing_config import start_tracing

provider = start_tracing()
model = "gpt-4o-mini"
with trace_llm_call("draft-return-reply", model=model, system="openai") as span:
    reply = OpenAI().chat.completions.create(
        model=model,
        messages=[{"role": "user", "content": "Write a short reminder to keep a return receipt."}],
    )
    span.set_attribute("gen_ai.usage.input_tokens", reply.usage.prompt_tokens)
    span.set_attribute("gen_ai.usage.output_tokens", reply.usage.completion_tokens)
```

## Evaluation enrichment

`evaluate()` records the metric name and numeric score on an evaluator span. If you call it inside an active request span, the evaluator span is a child of that request. Here `contains` checks a fixed policy reply locally; it doesn't call a judge model.

```python
from fi.evals import evaluate
from fi.evals.otel import enable_auto_enrichment, get_tracer

enable_auto_enrichment()
tracer = get_tracer("ridgeline.returns")
answer = "You can return unused gear within 30 days."
with tracer.start_as_current_span("check-return-window"):
    result = evaluate("contains", output=answer, config={"keyword": "30 days"}, engine="local")
    print(result.score)  # 1.0
```

### Manual enrichment

Use `enrich_span_with_evaluation()` inside a recording span to attach a score to that span. To give a custom check its own named child, use `EvaluationSpanContext`.

```python
from fi.evals.otel import EvaluationSpanContext, enrich_span_with_evaluation, shutdown_tracing

with tracer.start_as_current_span("review-policy-reply"):
    enrich_span_with_evaluation("return_window", result.score, reason=result.reason)
    with EvaluationSpanContext("mentions_condition") as check:
        check.record_result(score="unused" in answer, reason="The reply says unused gear.")

shutdown_tracing()
```

## Cost tracking

`calculate_cost()` estimates input and output costs in USD from token counts. `DEFAULT_PRICING` is a bundled table, not a live price feed. Pass `custom_pricing` with prices **per 1,000 tokens** to use your own rates.

```python
from fi.evals.otel import TokenPricing, calculate_cost

costs = calculate_cost(
    "support-model", input_tokens=1000, output_tokens=500,
    custom_pricing={"support-model": TokenPricing("support-model", 0.001, 0.002)},
)
print(f"${costs['total_cost']:.4f}")  # $0.0020
```

## Exporter backends

Choose `ExporterType.CONSOLE` for local output, `OTLP_HTTP` for an OTLP HTTP traces endpoint, or `OTLP_GRPC` for a gRPC collector. For HTTP, include the traces path, not just the host. You can configure more than one destination. For example, this builds the exporter list for a local HTTP collector plus console output; pass it to `start_tracing(exporters=destinations)` in place of the default at startup.

```python
from fi.evals.otel import ExporterConfig, ExporterType

destinations = [
    ExporterConfig(type=ExporterType.OTLP_HTTP, endpoint="http://localhost:4318/v1/traces"),
    ExporterConfig(type=ExporterType.CONSOLE),
]
```

## Exporting to Future AGI

Set `FI_API_KEY` and `FI_SECRET_KEY` from your workspace. Point the exporter at the hosted ingestion endpoint below, or use your self-hosted collector's `/tracer/v1/traces` endpoint.

```bash
export FI_OTLP_ENDPOINT="https://api.futureagi.com/tracer/v1/traces"
```

Save this as `export_return_trace.py` and run `python export_return_trace.py`. In **Observe**, open the `support-agent` project and look for the printed trace ID. The `ridgeline-return-review` request and its `eval.contains` child belong to the same trace.

```python
import os
from fi.evals import evaluate
from fi.evals.otel import ExporterConfig, ExporterType, get_tracer, shutdown_tracing
from tracing_config import start_tracing

start_tracing(
    project_name="support-agent",
    exporters=[ExporterConfig(type=ExporterType.FUTUREAGI, endpoint=os.environ["FI_OTLP_ENDPOINT"])],
)
try:
    with get_tracer("ridgeline.returns").start_as_current_span("ridgeline-return-review") as span:
        span.set_attribute("gen_ai.span.kind", "CHAIN")
        result = evaluate("contains", engine="local", output="Returns accepted within 30 days.", config={"keyword": "30 days"})
        print(f"Return-window score: {result.score}")
        trace_id = f"{span.get_span_context().trace_id:032x}"
finally:
    shutdown_tracing()
print(trace_id)
```

## Semantic conventions

Use the helper functions to construct attribute dictionaries without spelling out each OpenTelemetry key. These helpers do not create a span.

```python
from fi.evals.otel import create_evaluation_attributes, create_llm_span_attributes

usage = create_llm_span_attributes(system="openai", model="gpt-4o-mini", input_tokens=100, output_tokens=50)
score = create_evaluation_attributes(metric="return_window", score=1.0, reason="Includes the 30-day limit.")
print(usage["gen_ai.usage.total_tokens"], score["gen_ai.evaluation.score.value"])  # 150 1.0
```
