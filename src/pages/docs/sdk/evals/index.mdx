<TLDR>
- Install Agent Learning Kit in a fresh Python environment for evaluation.
- Import `evaluate` from `fi.evals`. Local string checks need no credentials.
- Turing uses `FI_API_KEY` and `FI_SECRET_KEY`. An external LLM judge uses its model provider's credentials instead.
</TLDR>

Set up the environment and try a local check on a support reply:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install agent-learning-kit==0.3.7
```

```python
from fi.evals import evaluate

result = evaluate("contains", output="You can return unused packs within 30 days.", keyword="30 days")
print(result.passed)  # True
```

To run a hosted toxicity check, set `FI_API_KEY` and `FI_SECRET_KEY` for a workspace with available evaluation credits and quota. On a self-hosted deployment, also set `FI_BASE_URL` to the API base URL. Save the example as `hosted_score.py` and run `python hosted_score.py`. It prints the score, explanation, and evaluation ID.

```python
from fi.evals import evaluate

result = evaluate("toxicity", output="You can return unused packs within 30 days.", model="turing_flash")
if result.score is None:
    raise RuntimeError(result.error or result.reason or "The hosted check did not return a score.")
print("Score:", result.score, result.reason)
print(result.metadata["eval_id"])
```

See [Installation and extras](/docs/sdk/list/evaluation) for setup or the [platform guide](/docs/evaluation) to run evals in the UI.

## How Engine Routing Works

The `evaluate()` function picks an engine automatically:

| You pass | Engine used | Credentials |
|----------|-------------|-------------|
| Local metric name without a model | Local metric | None |
| Hosted template + `model="turing_flash"` | Turing | Future AGI API and secret keys |
| `prompt=` + `engine="llm"` + a provider model | LLM judge | Model provider key for hosted models |
| Supported local metric + provider model + `augment=True` | Local metric followed by an LLM judge | Model provider key for hosted models |

You can force an engine with `engine="local"`, `engine="turing"`, or `engine="llm"`.

## Choosing the Right Approach

| You want to... | Use |
|----------------|-----|
| Check if output contains a keyword | [Local metric](/docs/sdk/evals/metrics) (`contains`) |
| Detect hallucinations in RAG output | [Local metric](/docs/sdk/evals/metrics/hallucination) (`faithfulness`) |
| Score tone or toxicity with a pretrained model | [Cloud eval](/docs/sdk/evals/cloud-evals) (`toxicity`) |
| Evaluate with your own criteria | [LLM-as-Judge](/docs/sdk/evals/llm-judge) (custom grading criteria) |
| Evaluate tokens as they stream in | [Streaming eval](/docs/sdk/evals/streaming) |
| Improve accuracy over time with corrections | [Feedback loops](/docs/sdk/evals/feedback) |
| Run evals at scale across workers | [Distributed evaluator](/docs/sdk/evals/distributed) |
| Auto-pick metrics for your app type | [AutoEval](/docs/sdk/evals/autoeval) |
| Block unsafe LLM inputs/outputs | [Guardrails](/docs/sdk/evals/guardrails-module) |
| Run evals offline, no API key | [Local & Hybrid](/docs/sdk/evals/local) |
| Trace evals with OpenTelemetry | [OpenTelemetry](/docs/sdk/evals/otel) |
| Scan AI-generated code for vulnerabilities | [Code Security](/docs/sdk/evals/code-security) |
