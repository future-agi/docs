<TLDR>
- `from fi.evals import evaluate` gives you one function for local, Turing and LLM evaluations
- Returns `EvalResult` with score, passed, reason, and latency
- Pass a list of eval names to batch multiple evals in one call
</TLDR>

The `evaluate()` function is the main entry point for running evaluations. It accepts a metric name (or list), your inputs as keyword arguments, and optionally a model. The engine is selected automatically based on what you pass.

<Note>
  Local string checks need no credentials. Set `FI_API_KEY` and `FI_SECRET_KEY` to run the hosted Turing example. Set `OPENAI_API_KEY` to run the OpenAI judge examples. Your judge receives the criteria and the inputs.
</Note>

Install the kit in a fresh environment. Run the Python snippets in order in one session, except for the standalone hosted script.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install agent-learning-kit==0.3.7
```

## Quick Examples

### Local metric (no API key needed)

```python
from fi.evals import evaluate

result = evaluate("contains", output="Hello world", keyword="Hello")

print(result.eval_name)   # "contains"
print(result.score)       # 1.0
print(result.passed)      # True
print(result.reason)      # "Keyword 'Hello' found"
print(result.latency_ms)  # elapsed milliseconds; varies by run
```

### Cloud eval (needs API key + model)

Save this as `hosted_eval.py` and run `python hosted_eval.py`. The last line identifies the hosted evaluation.

```python
from fi.evals import evaluate

result = evaluate(
    "toxicity",
    output="Thanks for your patience. Your new hiking pack ships tomorrow.",
    model="turing_flash",
)

if result.status != "completed" or result.score is None:
    raise RuntimeError(result.error or "No hosted score returned")
print(result.score, result.passed)
print(result.reason)
print(result.metadata["eval_id"])
```

### LLM-as-Judge (custom criteria)

```python
import json
from fi.evals import evaluate

result = evaluate(
    prompt="Rate how helpful this response is from 0 to 1. A helpful response directly answers the question with actionable steps.",
    output="Open your order history, select the pack, then choose Start a return.",
    query="How do I return an unused pack?",
    engine="llm",
    model="gpt-4o-mini",
)

def show_judgment(result):
    if result.status != "completed" or result.score is None:
        raise RuntimeError(result.error or "No judge score returned")
    # A valid judge response contains JSON. A provider or parsing error
    # can instead produce a zero score and a plain-text diagnostic.
    judgment = json.loads(result.reason)
    print(f"Judge score: {result.score}. {judgment['reason']}")

show_judgment(result)
```

### Batch evaluation

```python
from fi.evals import evaluate

results = evaluate(
    ["contains", "one_line", "is_json"],
    output="Hello world",
    keyword="Hello",
)

for r in results:
    print(f"{r.eval_name}: score={r.score}, passed={r.passed}")
# contains: score=1.0, passed=True
# one_line: score=1.0, passed=True
# is_json: score=0.0, passed=False
```

<Warning>
  Don't mix local and cloud metrics in the same batch call. If you pass `model="turing_flash"`, the kit sends every name to Turing. Run local metrics in a separate call without `model`.
</Warning>

## Parameters

<ParamField body="eval_name" type="str | list[str] | None">
  Metric name or list of metric names. Use a string for local/cloud metrics (e.g. `"toxicity"`, `"contains"`). Pass a list for batch evaluation. Set to `None` when using LLM-as-Judge with a custom `prompt`.
</ParamField>

<ParamField body="prompt" type="str | None">
  Grading criteria for LLM-as-Judge mode. Describe how to assess the input fields by name. The judge receives your criteria and the field values separately.
</ParamField>

<ParamField body="engine" type="str | None">
  Force a specific engine. Options: `"local"`, `"turing"`, `"llm"`. If omitted, the engine is selected automatically from the model.
</ParamField>

<ParamField body="model" type="str | None">
  Model to use for cloud or LLM evals. For Turing: `"turing_flash"`, `"turing_small"`, `"turing_large"`. For LLM-as-Judge: a model supported by your LiteLLM provider, such as `"gpt-4o-mini"`.
</ParamField>

<ParamField body="augment" type="bool | None">
  Run the local heuristic first, then ask an LLM to refine it. Requires a non-Turing `model`. Supported metrics include: `faithfulness`, `hallucination_score`, `task_completion`, `action_safety`, `reasoning_quality`, `claim_support`, `factual_consistency`.
</ParamField>

<ParamField body="config" type="dict | None">
  Metric-specific configuration. For example, set `config={"max_length": 100}` for the local `length_less_than` metric.
</ParamField>

<ParamField body="generate_prompt" type="bool" default="False">
  Auto-generate grading criteria from a plain English description. When `True`, the `prompt` parameter is treated as a description and a detailed rubric is generated from it. Generated criteria are cached per session.
</ParamField>

<ParamField body="feedback_store" type="Any | None">
  A feedback store the augmentation step can consult for similar examples. See [Feedback Loops](/docs/sdk/evals/feedback).
</ParamField>

<ParamField body="fi_api_key" type="str | None">
  Override the `FI_API_KEY` environment variable for this call.
</ParamField>

<ParamField body="fi_secret_key" type="str | None">
  Override the `FI_SECRET_KEY` environment variable for this call.
</ParamField>

<ParamField body="fi_base_url" type="str | None">
  Override `FI_BASE_URL` when using the Turing engine.
</ParamField>

<ParamField body="**inputs" type="keyword arguments">
  The data to evaluate. Common fields:

  | Field | Used by |
  |-------|---------|
  | `output` | The output to be evaluated |
  | `query` / `input` | Metrics that need the original user query |
  | `context` / `contexts` | Retrieved context for RAG metrics (string or list) |
  | `expected_output` / `ground_truth` | Similarity and correctness metrics |
  | `keyword` | String matching metrics (`contains`, `contains_all`, etc.) |
  | `image_url` | Multimodal image evaluation |
  | `audio_url` | Audio evaluation |
  | `messages` | Conversation evaluation |
</ParamField>

## Return Types

### `EvalResult` (single eval)

<ResponseField name="eval_name" type="str" required>
  Name of the metric that was run.
</ResponseField>

<ResponseField name="score" type="float | None">
  Score between 0.0 and 1.0. Some metrics return binary 0 or 1.
</ResponseField>

<ResponseField name="passed" type="bool | None">
  Whether the evaluation passed based on the metric's threshold.
</ResponseField>

<ResponseField name="reason" type="str">
  Human-readable explanation of the score.
</ResponseField>

<ResponseField name="latency_ms" type="float">
  Execution time in milliseconds.
</ResponseField>

<ResponseField name="status" type="str">
  `"completed"` when the engine returns a result; `"failed"` for errors such as an unknown local metric. A failing score is not an execution failure.
</ResponseField>

<ResponseField name="error" type="str | None">
  Diagnostic when the engine reports a failed execution. Invalid arguments can also raise an exception.
</ResponseField>

<ResponseField name="metadata" type="dict">
  Engine-specific fields, such as `eval_id` for a hosted evaluation or `engine` for an augmented one.
</ResponseField>

### `BatchResult` (multiple evals)

Returned when `eval_name` is a list. Iterable collection of `EvalResult` objects.

```python
# Reuse the local batch from Quick Examples.
json_check = results.get("is_json")
print(json_check.passed)      # False: the text was not JSON
print(results.success_rate)  # 1.0: all three metrics completed
print(len(results))          # 3
```

## Engine Routing

If you don't set `engine` explicitly, the function picks one:

1. **No model passed** → local engine (the metric must exist in the local registry)
2. **`model="turing_flash"` / `"turing_small"` / `"turing_large"`** → Turing cloud engine
3. **Any other model string** → LLM-as-Judge engine; supply grading criteria with `prompt`
4. **`augment=True`** → local first, then LLM refinement

For augmented metrics, check `result.metadata.get("engine")` to distinguish `"local+llm"` from a local fallback. That field is not present on every result.

## Common Patterns

### Error handling

```python
result = evaluate("unknown_example_metric", output="A pack is ready.")

if result.status == "failed":
    print(f"Eval failed: {result.error}")
else:
    print(f"Score: {result.score}")
```

### Augmented evaluation (local + LLM)

```python
result = evaluate(
    "faithfulness",
    output="Paris is the capital of France.",
    context="France is a European country with Paris as its capital.",
    model="gpt-4o-mini",
    augment=True,
)

print(result.metadata["engine"])  # "local+llm" when the augmentation step runs
if result.metadata["engine"] == "local+llm":
    show_judgment(result)
```

### Auto-generated grading criteria

```python
result = evaluate(
    prompt="Check if the response is empathetic and acknowledges the customer's frustration",
    output="I understand this is frustrating. Let me help fix that right away.",
    engine="llm",
    model="gpt-4o-mini",
    generate_prompt=True,
)
show_judgment(result)  # The judge uses the expanded criteria
```

| Variable | Required for | Default |
|----------|-------------|---------|
| `FI_API_KEY` | Cloud (Turing) evals | Not set |
| `FI_SECRET_KEY` | Cloud (Turing) evals | Not set |
| `FI_BASE_URL` | Custom API endpoint | `https://api.futureagi.com` |
| `OPENAI_API_KEY` | OpenAI models (LLM judge) | Not set |
| `ANTHROPIC_API_KEY` | Claude models (LLM judge) | Not set |
