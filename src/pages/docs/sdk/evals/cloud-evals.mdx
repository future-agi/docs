Cloud evaluations send the inputs you supply to Future AGI for scoring. For example, a toxicity check asks whether a reply is safe to send; a context-adherence check asks whether the same reply is supported by your policy. Passing one doesn't imply passing the other.

Set `FI_API_KEY` and `FI_SECRET_KEY` from your [workspace API keys](/docs/admin-settings/api-keys). Install Agent Learning Kit in a fresh environment. Run the Python snippets in order in one notebook kernel, or save them in order in `cloud_evals.py` and run `python cloud_evals.py`. The final pipeline example also requires an existing Observe project.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install agent-learning-kit==0.3.7
```

## Discover templates and required inputs

Use `list_evaluations()` to read the catalog available to your account. Match by name instead of taking the first entry. The count and ordering can change without an SDK update.

```python
from fi.evals import Evaluator

evaluator = Evaluator()
templates = evaluator.list_evaluations()
by_name = {t["name"]: t for t in templates if t.get("owner") == "system"}
print("System templates:", len(by_name))
t = by_name["context_adherence"]
print(t["description"])
print("Required inputs:", t["config"]["required_keys"])
print("Parameters:", t["config"].get("config_params_desc", {}))
```

### Filter by tag

Use the tag strings your catalog returns. For example, find other templates that share a tag with `toxicity`. A shared tag is not a shared input schema.

```python
tags = set(by_name["toxicity"]["eval_tags"])
related = sorted(t["name"] for t in by_name.values() if tags.intersection(t.get("eval_tags") or []))
print("Toxicity tags:", sorted(tags))
print("Related templates:", related)
```

If your gateway rejects the discovery GET with HTTP 400, consult the [built-in template reference](/docs/evaluation/builtin). Some gateways reject a GET with an empty JSON body; a discovery error doesn't tell you whether a scoring POST succeeded.

## Score a reply for toxicity

Pass a Turing model name to route `evaluate` to the hosted template. A transport error or a rate-limit refusal isn't a low score: check the result status and the presence of a score before using it.

```python
from fi.evals import evaluate

reply = "You can return unworn boots within 30 days with a receipt."
check = evaluate("toxicity", output=reply, model="turing_flash")
if check.status != "completed" or check.score is None:
    raise RuntimeError(check.error or "No toxicity score returned")
print("Toxicity check:", check.passed, check.score, check.reason)
```

## Score a reply against a policy

The `context_adherence` template takes two inputs: the reply under review (`output`) and the source text (`context`). Use `turing_flash`, `turing_small`, or `turing_large` where supported by your template. Compare models on the same examples rather than assuming a latency or accuracy improvement.

```python
policy = "Unworn boots can be returned within 30 days with a receipt."
grounding = evaluate("context_adherence", output=reply, context=policy, model="turing_small")
if grounding.status != "completed" or grounding.score is None:
    raise RuntimeError(grounding.error or "No context-adherence score returned")
print("Policy adherence:", grounding.score, grounding.reason)
```

### Get a categorical result by ID

Not every template produces a numeric score. `tone` returns a choice. Use `Evaluator.submit` to start it, then retrieve the execution by its actual ID. Save the IDs if you want to look up the same evaluations later without paying to run them again.

```python
import json
from pathlib import Path

from fi.evals import Evaluator

evaluator = Evaluator()
tone = evaluator.submit("tone", {"output": reply}, model_name="turing_flash")
finished = evaluator.get_execution(tone.id).wait(timeout=120)
print("Tone:", finished.result.output, finished.result.reason)
ids = {"toxicity": check.metadata["eval_id"], "context_adherence": grounding.metadata["eval_id"], "tone": tone.id}
Path("evaluation-ids.json").write_text(json.dumps(ids, indent=2))
```

## Run a versioned evaluation pipeline

Use an existing Observe project name in place of `your-project`. Each version must be new within that project. A pipeline item takes an `eval_template` and a dictionary of inputs; each input is a **list**, with one element per example. Here both replies are checked for toxicity, not for policy adherence.

```python
import time
from uuid import uuid4

project = "your-project"
version = f"ridgeline-returns-{uuid4().hex[:12]}"
accepted = evaluator.evaluate_pipeline(
    project_name=project, version=version,
    eval_data=[{"eval_template": "toxicity", "model_name": "turing_flash",
                "inputs": {"output": [reply, "Please bring your receipt to the store."]}}],
)["result"]
run_id = accepted["evaluation_run_id"]
print("Submitted:", version, run_id)

for _ in range(90):
    status = evaluator.get_pipeline_results(project_name=project, versions=[version])["result"]
    if status["status"] == "completed":
        break
    time.sleep(2)
else:
    raise TimeoutError(f"Check version {version} again; don't resubmit it")

run = next(r for r in status["evaluation_runs"] if r["id"] == run_id)
print("Toxicity pass percentage among completed evaluations:", run["results_summary"]["toxicity"])
Path("pipeline-result.json").write_text(json.dumps(run, indent=2))
```

The submission ID acknowledges the run, not a passing score. Read the summary for your version; a missing template in the summary isn't a zero or a pass.

## Template Reference
