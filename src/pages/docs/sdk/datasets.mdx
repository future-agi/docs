<TLDR>
- `pip install futureagi` (or comes with `ai-evaluation`)
- Create datasets from scratch, CSV/JSON files, or HuggingFace
- Chain operations: create → add columns → add rows → run evals → download results
</TLDR>

Datasets hold your test data and evaluation scores. For the full platform guide, see [Dataset docs](/docs/dataset). Create one, fill it with data, run evals across every row, and download the results.

<Note>
  Python requires `pip install futureagi`; TypeScript requires `npm install @future-agi/sdk`. Set `FI_API_KEY` and `FI_SECRET_KEY` in your environment. If you installed `ai-evaluation`, you already have `futureagi`.
</Note>

Unless marked **platform Client**, examples use the Python `Dataset` helper. The platform `Client` is a separate API, not the `FutureAGIClient` facade; use the imports shown in each example.

## Quick Example

```python
from fi.datasets import Dataset, DatasetConfig

# Create a dataset
config = DatasetConfig(name="my-eval-data", model_type="GenerativeLLM")
dataset = Dataset(dataset_config=config)
dataset.create()

# Add columns and rows
dataset.add_columns([
    {"name": "question", "data_type": "text"},
    {"name": "answer", "data_type": "text"},
])

dataset.add_rows([
    {"cells": [{"column_name": "question", "value": "What is Python?"}, {"column_name": "answer", "value": "A programming language."}]},
    {"cells": [{"column_name": "question", "value": "What is 2+2?"}, {"column_name": "answer", "value": "4"}]},
])

# Keep the ID for platform Client reads and cell updates.
print(dataset.dataset_config.id)
```

## DatasetConfig

Every dataset needs a config with a name and model type.

```python
from fi.datasets import DatasetConfig

config = DatasetConfig(
    name="my-dataset",          # required, max 255 chars
    model_type="GenerativeLLM", # "GenerativeLLM" or "GenerativeImage"
)
```

## Creating Datasets

### Empty dataset

```python
from fi.datasets import Dataset, DatasetConfig

config = DatasetConfig(name="my-dataset", model_type="GenerativeLLM")
dataset = Dataset(dataset_config=config).create()
```

### From a CSV or JSON file

```python
dataset = Dataset(dataset_config=DatasetConfig(name="from-file", model_type="GenerativeLLM"))
dataset.create(source="path/to/data.csv")
# Supported: .csv, .json, .jsonl, .xlsx, .xls
```

### Uploading with the platform Client

Use `create_from_file` in Python or `createFromFile` in TypeScript. The Client sends the file as a multipart upload, separately from fields such as `new_dataset_name` and `model_type`. A JSON body containing a filename is not a file upload.

<Tabs>
  <Tab title="Python">
    ```python
    from fi import Client

    client = Client()
    result = client.datasets.create_from_file(
        file="path/to/data.csv",
        new_dataset_name="uploaded-eval-data",
        model_type="GenerativeLLM",
    )
    print(result)
    ```
  </Tab>
  <Tab title="TypeScript">
    ```typescript
    import { Client } from "@future-agi/sdk";

    const client = new Client();
    const result = await client.datasets.createFromFile({
      file: "path/to/data.csv", // Local paths require Node.js.
      new_dataset_name: "uploaded-eval-data",
      model_type: "GenerativeLLM",
    });
    console.log(result);
    ```
  </Tab>
</Tabs>

Both methods also accept an optional `source` field. TypeScript's `file` accepts a local path, `Uint8Array`, `Blob`, or a named object such as `{ name: "data.csv", data: csvText }`. When uploading bytes or a blob, use a named object to preserve the file extension.

Processing is asynchronous: the response contains a `dataset_id` and an initial `processing_status`, not a completed table. Use `client.datasets.get` with that ID to read the dataset as processing completes.

### From HuggingFace

```python
from fi.datasets.types import HuggingfaceDatasetConfig

hf = HuggingfaceDatasetConfig(name="squad", subset="default", split="train", num_rows=100)
dataset = Dataset(dataset_config=DatasetConfig(name="squad-sample", model_type="GenerativeLLM"))
dataset.create(source=hf)
```

## Columns and Rows

### Adding columns

Pass a list of dicts with `name` and `data_type`.

```python
dataset.add_columns([
    {"name": "input", "data_type": "text"},
    {"name": "output", "data_type": "text"},
    {"name": "score", "data_type": "float"},
    {"name": "metadata", "data_type": "json"},
])
```

Column types: `text`, `boolean`, `integer`, `float`, `json`, `array`, `image`, `datetime`, `audio`.

### Adding rows

Each row is a dict with a `cells` list. Each cell maps a column name to a value.

```python
dataset.add_rows([
    {"cells": [
        {"column_name": "input", "value": "Summarize this article"},
        {"column_name": "output", "value": "The article discusses..."},
        {"column_name": "score", "value": 0.85},
    ]},
])
```

<Tip>
  You can also use typed `Column`, `Row`, and `Cell` objects from `fi.datasets.types` instead of dicts. Both work the same way — dicts are simpler for most cases.
</Tip>

### Updating or clearing a cell with the platform Client

Adding rows appends data; it does not change an existing cell. Use `client.datasets.cells.update` with the dataset, row, and column IDs to correct one value. Always pass `new_value` explicitly.

<Tabs>
  <Tab title="Python">
    ```python
    from fi import Client

    client = Client()
    client.datasets.cells.update(
        "your-dataset-id",
        row_id="your-row-id",
        column_id="your-column-id",
        new_value="Corrected answer",
    )

    # To clear a cell deliberately, pass None.
    client.datasets.cells.update(
        "your-dataset-id",
        row_id="your-row-id",
        column_id="your-column-id",
        new_value=None,
    )
    ```
  </Tab>
  <Tab title="TypeScript">
    ```typescript
    import { Client } from "@future-agi/sdk";

    const client = new Client();
    await client.datasets.cells.update("your-dataset-id", {
      row_id: "your-row-id",
      column_id: "your-column-id",
      new_value: "Corrected answer",
    });

    // To clear a cell deliberately, pass null.
    await client.datasets.cells.update("your-dataset-id", {
      row_id: "your-row-id",
      column_id: "your-column-id",
      new_value: null,
    });
    ```
  </Tab>
</Tabs>

An explicit empty string (`""`) also clears a cell. Updates and clearing are subject to the column's edit rules and the dataset's schema validation. For numeric or boolean values, pass strings such as `"0"` or `"false"` that match the column type.

## Running LLM Prompts on a Dataset

Run an LLM on every row to generate outputs. Use `{{column_name}}` in your messages to reference column values.

```python
dataset.add_run_prompt(
    name="gpt4o_response",
    model="gpt-4o-mini",
    messages=[
        {"role": "system", "content": "You are a helpful assistant."},
        {"role": "user", "content": "Answer this question: {{question}}"},
    ],
    max_tokens=500,
    temperature=0.7,
)
```

A new column `gpt4o_response` appears with the LLM output for each row.

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `name` | str | required | Column name for the generated outputs |
| `model` | str | required | LLM model name (e.g. `"gpt-4o-mini"`) |
| `messages` | list | required | Chat messages with `{{column}}` placeholders |
| `max_tokens` | int | 500 | Maximum tokens per response |
| `temperature` | float | 0.5 | Sampling temperature |
| `concurrency` | int | 5 | Parallel requests |
| `top_p` | float | 1 | Top-p sampling |
| `tools` | list or None | None | Tool definitions for function calling |
| `response_format` | dict or None | None | Structured output format |

## Running Evaluations on a Dataset

Score every row using an evaluation template. Map the template's required inputs to your dataset columns.

```python
dataset.add_evaluation(
    name="tone_check",
    eval_template="tone",
    model="turing_flash",
    required_keys_to_column_names={
        "output": "gpt4o_response",
    },
)
```

This adds a `tone_check` column with the evaluation score for each row.

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `name` | str | required | Column name for the scores |
| `eval_template` | str | required | Template name (see [Cloud Evals](/docs/sdk/evals/cloud-evals)) |
| `model` | str | required | Turing model (`turing_flash`, `turing_small`, `turing_large`) |
| `required_keys_to_column_names` | dict | required | Maps template inputs to column names |
| `reason_column` | bool | False | Add a column with the reasoning |
| `config` | dict or None | None | Template-specific config |

## Downloading Results

For exports, use the **platform Client** to read every page, then serialize the collected values once.

<Note>
  The Python `Dataset.download` helper reads 100 rows per page; its CSV output repeats headers across pages and appends when the filename already exists. Its JSON output is an array, but `load_to_pandas` reads JSON as lines, so that combination is not a reliable round trip. The legacy TypeScript helper reads only the first page of up to 1,000 rows; its CSV formatter can lose native `0`/`false` values and does not escape column headers. Use the paged recipe below instead.
</Note>

### Paged reads and a single CSV export

`datasets.get` returns `column_config`, `table`, and pagination `metadata`. Each table row stores cells under their column IDs; `cell_value` is the value to export. Start at page zero and follow `metadata.next_page_index` while `metadata.has_more` is true.

Run the export after processing finishes and while the dataset is not being edited. These page-index reads are not a frozen snapshot. The examples collect rows in memory and replace `results.csv` with one header row.

<Tabs>
  <Tab title="Python">
    ```python
    import csv
    from fi import Client

    client = Client()
    dataset_id = "your-dataset-id"
    page_index = 0
    columns = None
    rows = []

    while True:
        page = client.datasets.get(
            dataset_id, page_size=100, current_page_index=page_index,
        ).model_dump()
        if columns is None:
            columns = page["column_config"]
        for row in page["table"]:
            rows.append([
                (row.get(column["id"]) or {}).get("cell_value")
                for column in columns
            ])
        metadata = page["metadata"]
        if not metadata["has_more"]:
            break
        next_index = metadata["next_page_index"]
        if next_index is None or next_index <= page_index:
            raise RuntimeError("Missing or invalid next page index")
        page_index = next_index

    with open("results.csv", "w", newline="", encoding="utf-8") as output:
        writer = csv.writer(output)
        writer.writerow([column["name"] for column in columns])
        writer.writerows(rows)

    # Optional: build a DataFrame directly from the collected values.
    # import pandas as pd
    # df = pd.DataFrame(rows, columns=[column["name"] for column in columns])
    ```
  </Tab>
  <Tab title="TypeScript (Node.js)">
    ```typescript
    import { writeFile } from "node:fs/promises";
    import { Client } from "@future-agi/sdk";

    // Table cells have dynamic column-ID keys beyond the generated row type.
    type ExportPage = {
      column_config: { id: string; name: string }[];
      table: Record<string, unknown>[];
      metadata: { has_more: boolean; next_page_index: number | null };
    };

    const client = new Client();
    const datasetId = "your-dataset-id";
    let pageIndex = 0;
    let columns: ExportPage["column_config"] | undefined;
    const rows: unknown[][] = [];

    while (true) {
      const page = await client.datasets.get(datasetId, {
        page_size: 100,
        current_page_index: pageIndex,
      }) as ExportPage;
      columns ??= page.column_config;
      for (const row of page.table) {
        rows.push(columns.map((column) => {
          const cell = row[column.id] as { cell_value?: unknown } | null;
          return cell?.cell_value ?? "";
        }));
      }
      if (!page.metadata.has_more) break;
      const nextIndex = page.metadata.next_page_index;
      if (nextIndex === null || nextIndex <= pageIndex) {
        throw new Error("Missing or invalid next page index");
      }
      pageIndex = nextIndex;
    }

    // Quote headers and values alike; nullish values, not 0/false, become blank.
    const csvField = (value: unknown): string => {
      const text = value == null ? "" : typeof value === "object"
        ? JSON.stringify(value) : String(value);
      return `"${text.replace(/"/g, '""')}"`;
    };
    const records = [columns!.map((column) => column.name), ...rows];
    const csv = records.map((row) => row.map(csvField).join(",")).join("\r\n");
    await writeFile("results.csv", csv + "\r\n", "utf8");
    ```
  </Tab>
</Tabs>

## Chaining

Most methods return `self`, so you can chain them:

```python
from fi.datasets import Dataset, DatasetConfig

dataset = (
    Dataset(dataset_config=DatasetConfig(name="pipeline", model_type="GenerativeLLM"))
    .create(source="questions.csv")
    .add_run_prompt(
        name="response",
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": "Answer: {{question}}"}],
    )
    .add_evaluation(
        name="helpfulness",
        eval_template="is_helpful",
        model="turing_flash",
        required_keys_to_column_names={"input": "question", "output": "response"},
    )
)
```

After the evaluations finish, export the values with the [paged-read recipe](#paged-reads-and-a-single-csv-export).

## Reconnecting to an Existing Dataset

In Python, `Dataset.get_dataset_config(name)` returns a cached **Dataset instance**, not a `DatasetConfig`. Read its `.dataset_config` for configuration and call methods such as `.add_rows` or `.add_evaluation` on the instance.

```python
from fi.datasets import Dataset

existing = Dataset.get_dataset_config("my-eval-data")
print(existing.dataset_config.id)
print(existing.dataset_config.name)

existing.add_rows([
    {"cells": [
        {"column_name": "question", "value": "What is 3+3?"},
        {"column_name": "answer", "value": "6"},
    ]},
])
```

Python matches the name exactly and case-sensitively. If only `my-eval-data-copy` exists, looking up `my-eval-data` raises a not-found error rather than connecting to the prefix match.

<Note>
  TypeScript's legacy `Dataset.getDatasetConfig` returns configuration, not a Dataset instance. It does not provide the same exact-name guarantee: it rejects multiple substring matches and accepts a single match without checking name equality. Verify the returned name and ID before using that configuration, or use the platform Client with a known dataset ID.
</Note>

## Class Methods

Python helpers for operations by dataset name, without creating an instance first:

| Method | What it does |
|--------|-------------|
| `Dataset.create_dataset(config, source)` | Create a dataset |
| `Dataset.download_dataset(name, load_to_pandas=True)` | Download by name; the [helper export limits](#downloading-results) also apply |
| `Dataset.delete_dataset(name)` | Delete by name |
| `Dataset.get_dataset_config(name)` | Get a cached Dataset instance by exact name; config is in `.dataset_config` |
| `Dataset.add_dataset_columns(name, columns)` | Add columns by name |
| `Dataset.add_dataset_rows(name, rows)` | Add rows by name |
