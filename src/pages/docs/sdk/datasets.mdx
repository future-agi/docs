Use the `futureagi` platform SDK to manage the same tables you see in [Datasets](/docs/dataset). In this example you generate short replies to Ridgeline Outfitters shoppers and check whether each reply fits a 30-word limit.

Use a fresh directory. Set `FI_API_KEY` and `FI_SECRET_KEY` to your [workspace credentials](/docs/admin-settings/api-keys), then install the platform SDK. Keep this environment separate from Agent Learning Kit: both packages install files under `fi/`.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install futureagi==0.7.0
```

Run `python` and run the Python snippets in order in the same session. The suffix gives each new dataset a distinct name. The prompt step also needs access to the selected model in your workspace.

## Quick example: create an empty dataset and add a row

`DatasetConfig` takes a name and model type. Use `GenerativeLLM` for these text examples. `create()` returns the dataset; `get_config().id` identifies the table for subsequent API calls.

```python
from uuid import uuid4
from fi.datasets import Dataset, DatasetConfig
from fi.platform import Client

suffix = uuid4().hex[:12]
def config(label):
    return DatasetConfig(name=f"ridgeline-{label}-{suffix}", model_type="GenerativeLLM")

dataset = Dataset(dataset_config=config("returns")).create()
dataset_id = str(dataset.get_config().id)
client = Client()
dataset.add_columns([{"name": "question", "data_type": "text"}])
client.datasets.rows.add(dataset_id, rows=[{"cells": [
    {"column_name": "question", "value": "Can I return unworn boots?"},
]}])
print(dataset_id, dataset.download(load_to_pandas=True)["question"].tolist())
```

You should see the new dataset ID and one shopper question. `load_to_pandas=True` returns a DataFrame and also writes a CSV locally. Use a fresh output path for each download so repeated exports don't append to an earlier file.

## Other ways to create datasets

### From a CSV file

Import the one-row CSV you just downloaded into a separate dataset. The return value identifies the new dataset; the upload can still be processing when the call returns.

```python
csv_dataset = Dataset(dataset_config=config("from-file")).create(
    source=f"{dataset.get_config().name}.csv"
)
print("CSV import:", csv_dataset.get_config().id)
```

### From Hugging Face

Import two synthetic support exchanges from the public Bitext training split. The repository name identifies the source; `name` is what you'll see in your workspace. You can keep using the original `dataset_id` while this import finishes.

```python
imported = client.datasets.create_from_huggingface(
    name=f"ridgeline-support-sample-{suffix}", model_type="GenerativeLLM",
    huggingface_dataset_name="bitext/Bitext-customer-support-llm-chatbot-training-dataset",
    huggingface_dataset_config="default", huggingface_dataset_split="train", num_rows=2,
)
print("Hugging Face import:", imported.dataset_id)
```

## Columns and rows

Add a text column to the original returns dataset. Existing rows keep their values; the new field starts empty.

```python
dataset.add_columns([{"name": "channel", "data_type": "text"}])
```

Use the column **names** in `rows.add`. A row is a dictionary with a `cells` list; you don't need to supply row or cell IDs.

```python
client.datasets.rows.add(dataset_id, rows=[{"cells": [
    {"column_name": "question", "value": "Do I need a receipt for a return?"},
    {"column_name": "channel", "value": "chat"},
]}])
```

## Run a prompt on each row

`add_run_prompt` resolves `{{question}}` against your dataset columns and starts generating a `reply` for each row. The shared policy in the system message is the source of truth for both questions. Wait for both cells before scoring them: a successful submission is not a completed generation.

```python
import time

dataset.add_run_prompt(
    name="reply", model="gpt-4o-mini",
    messages=[
        {"role": "system", "content": "Ridgeline accepts unworn boots within 30 days with a receipt. Answer using this policy in at most 30 words."},
        {"role": "user", "content": "{{question}}"},
    ],
)

def wait_for_column(name, timeout=300):
    deadline = time.monotonic() + timeout
    while time.monotonic() < deadline:
        table = client.datasets.get(dataset_id)
        columns = {c.name: c.id for c in table.column_config}
        if name in columns:
            cells = [row.model_dump().get(columns[name]) or {} for row in table.table or []]
            if any(cell.get("status") == "error" for cell in cells):
                raise RuntimeError(f"Inspect the failed {name} cell in dataset {dataset_id}")
            if len(cells) == 2 and all(cell.get("cell_value") for cell in cells):
                return [cell["cell_value"] for cell in cells]
        time.sleep(2)
    raise TimeoutError(f"Still waiting for {name} in dataset {dataset_id}")

print(wait_for_column("reply"))
```

## Run an evaluation on the replies

Choose the system template `word_count_in_range`. For `client.datasets.evals.add`, map its `text` input to the reply column's **ID**, not its name. `min_words` and `max_words` are literal parameters. This check measures length, not whether a reply follows the return policy.

```python
templates = client.evals.templates.list(owner_filter="system", search="word_count_in_range")
template = next(t for t in templates.items if t.name == "word_count_in_range")
reply_id = next(c.id for c in client.datasets.get(dataset_id).column_config if c.name == "reply")
client.datasets.evals.add(
    dataset_id, name="short-reply", template_id=template.id, run=True,
    config={"mapping": {"text": reply_id}, "params": {"min_words": 1, "max_words": 30}},
)
print(wait_for_column("short-reply"))
```

## Download results

For this two-row table, read the selected fields into a DataFrame and write them to a new CSV. The `short-reply` values in the table are `Passed` or `Failed`. For large datasets, request subsequent pages while `table.metadata.has_more` is true.

```python
import pandas as pd

table = client.datasets.get(dataset_id)
columns = {c.name: c.id for c in table.column_config}
fields = ["question", "reply", "short-reply"]
results = pd.DataFrame([
    {name: row.model_dump()[columns[name]]["cell_value"] for name in fields}
    for row in table.table
])
results.to_csv(f"scored-{dataset_id}.csv", index=False)
print(results.to_string(index=False))
```

## Chaining and deleting a dataset

`create()` and `add_columns()` return the same `Dataset` object, so you can chain them. Create a separate scratch table if you want to try deletion without touching your support data.

```python
scratch = (
    Dataset(dataset_config=config("scratch"))
    .create()
    .add_columns([{"name": "note", "data_type": "text"}])
)
print("Scratch dataset:", scratch.get_config().name, scratch.get_config().id)
```

Delete **only** the scratch table you just created. The original dataset and both imports remain available in your workspace.

```python
scratch.delete()
client.close()
```
