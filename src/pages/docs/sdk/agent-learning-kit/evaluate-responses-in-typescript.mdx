---
title: "Evaluate responses in TypeScript"
description: "Run a local keyword check in Node.js and make a failing order-status reply visible to CI"
---

Your order assistant knows that order A-104 ships Friday. Before releasing a change, check whether its saved replies still give customers that day. A local ALK metric returns a score and a reason for each reply, and your script can use the score to fail a build.

<Note>
Use Node.js 18 or later and npm. The example uses the ESM exports of `@future-agi/agent-learning-kit@0.4.0`. Once installed, the check runs offline without credentials.
</Note>

## Install the evaluator in a new project

```bash
mkdir order-check
cd order-check
npm init -y
npm install @future-agi/agent-learning-kit@0.4.0
npm install --save-dev typescript@5
```

## Score two order-status replies

Save this as **check-order.mts**. The `.mts` extension tells TypeScript to emit an ES module. The `contains` metric looks for one keyword in each response.

```typescript
import { LocalEvaluator } from "@future-agi/agent-learning-kit/local";

const replies = [
  { response: "Order A-104 ships Friday." },
  { response: "Order A-104 ships Monday." },
];

const evaluator = new LocalEvaluator();
const check = evaluator.evaluate("contains", replies, { keyword: "Friday" });

if (check.errors.length) {
  throw new Error(check.errors.map((error) => error.error).join("\n"));
}

const rows = check.results.eval_results;
for (const [index, row] of rows.entries()) {
  console.log(`Reply ${index + 1}: ${row.output} ${row.reason}`);
}

if (rows.some((row) => row.output !== 1)) {
  throw new Error("A reply is missing the expected shipping day.");
}
```

Compile and run it from the same directory.

```bash
npx tsc check-order.mts --module nodenext --target es2022 --skipLibCheck
node check-order.mjs
```

The second reply triggers the error and Node exits with a nonzero status.

```text
Reply 1: 1 KEYWORD_FOUND
Reply 2: 0 KEYWORD_MISSING
Error: A reply is missing the expected shipping day.
```

Change `Monday` to `Friday` in **check-order.mts**, then repeat both commands. Both rows now print `1 KEYWORD_FOUND` and Node exits successfully. A reply like “Friday delivery is unavailable” also contains the word. Use a stricter rule when the wording must express a particular decision.

## Add a second check

Use `getAvailableMetrics()` from the same import path to list registered metrics. To score several rules in one call, append this block to the repaired script, then compile and run it again.

```typescript
const batch = evaluator.evaluateBatch([
  { metricName: "contains", inputs: replies, config: { keyword: "A-104" } },
  { metricName: "one_line", inputs: replies },
]);
console.log(batch.executedLocally);
console.log(batch.results.eval_results.map((row) => row.output));
```

The first line lists `contains` and `one_line`. The second gives four scores of `1`, one per reply for each metric. Use `batch.errors` to inspect an unknown metric name or another execution error.

## Choose where the next check runs

| What you need | Import and execution |
| --- | --- |
| Heuristics, automatic metric selection, streamed output or text scanning | Import `LocalEvaluator`, `AutoEvalPipeline`, `StreamingEvaluator` or `Scanner` from `@future-agi/agent-learning-kit/local`. The alias `/evals/local` exposes the same exports |
| A model to judge an answer | `HybridEvaluator` accepts an `OllamaLLM` connected to a running Ollama server. If you supply a cloud evaluator, it can route inputs to Future AGI. Set `offlineMode: true` to keep cloud fallback disabled |
| Hosted evaluations, templates and guardrails | The package root and `/evals` export `Evaluator`, `EvalTemplateManager`, `Templates` and `Protect`. Hosted calls send the supplied data to Future AGI and require your workspace’s [API key pair](/docs/admin-settings/api-keys) |
