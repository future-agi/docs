---
title: "Run evaluation suites"
description: "Run the same response checks across multiple orders, find the failing case, and verify the fix"
---

Your order-status agent should mention the order number and give the shipment day on record. Put both rules in an evaluation suite so you can run them for every order when you change the agent.

<Note>
Activate the Python environment from the [ALK quickstart](/docs/sdk/agent-learning-kit) and keep its local settings. The provider in this guide is a Python function that runs on your machine. If your function calls a model, it sends the prompt to that provider and can incur charges.
</Note>

## Connect the function that returns a reply

Save this as `order_agent.py`. The function looks up the day by order number. One record deliberately has the wrong day so you can see which rule catches it.

```python
SHIP_DAYS = {"A-104": "Friday", "A-105": "Tuesday"}


def reply(*, prompt, vars, test, provider):
    order = vars["order"]
    return f"Order {order} ships on {SHIP_DAYS[order]}."
```

ALK calls the function with the rendered `prompt`, the test variables in `vars`, and the `test` and `provider` records. To exercise your own implementation, return its reply here.

## Define the expected day for each order

Save `orders.json` beside `order_agent.py`. Each test fills in the prompt template and checks the function's output. Keep the expected days in the tests independent of the agent's lookup table.

```json
{
  "version": "agent-learning.eval.v1",
  "name": "order-status",
  "providers": [{"id": "order-agent", "type": "python", "target": "order_agent.py:reply"}],
  "prompts": [{"id": "ship-day", "template": "When does order {{order}} ship?"}],
  "tests": [
    {
      "id": "friday-order",
      "vars": {"order": "A-104"},
      "assert": [
        {"type": "contains", "value": "A-104"},
        {"type": "contains", "value": "Friday"}
      ]
    },
    {
      "id": "monday-order",
      "vars": {"order": "A-105"},
      "assert": [
        {"type": "contains", "value": "A-105"},
        {"type": "contains", "value": "Monday"}
      ]
    }
  ],
  "threshold": 1.0
}
```

## Run the suite and locate the mismatch

Run these commands in the directory that contains both files. The dry run checks the suite definition. The second command calls the function once per test and writes the results, even when a test fails.

```bash
agent-learn eval orders.json --dry-run --output orders-preview.json
agent-learn eval orders.json --output orders-result.json
```

The second command exits with code `1`. Save this as `read_orders.py` and run `python read_orders.py` to see which assertion failed.

```python
import json
from pathlib import Path

result = json.loads(Path("orders-result.json").read_text())
summary = result["summary"]
print(result["status"], summary["case_count"], summary["failed_assertion_count"])
for finding in result["evaluation"]["findings"]:
    print(finding["test_id"], finding["expected"], finding["actual"])
```

```text
failed 2 1
monday-order Monday Order A-105 ships on Tuesday.
```

Change the `A-105` day in `order_agent.py` to `Monday`. Run the second command and the reader again. ALK exits with code `0`, and the reader prints `passed 2 0`. In CI, check the exit code and the expected case count. A dry run can pass with zero executed cases.

## Check a saved result without calling the agent

If another job already produced `orders-result.json`, use an `artifact` provider to check that file. Save this as `check-saved.json` beside the result. ALK reads each field at its path in the saved JSON and exposes it under `fields` for assertions.

```json
{
  "name": "saved-orders",
  "providers": [{
    "id": "orders", "type": "artifact", "path": "orders-result.json",
    "fields": [
      {"name": "cases", "path": "summary.case_count"},
      {"name": "failures", "path": "summary.failed_assertion_count"}
    ]
  }],
  "prompts": [{"id": "inspect", "template": "Check both orders"}],
  "tests": [{
    "id": "all-orders-pass",
    "assert": [
      {"type": "json_path_equals", "path": "fields.cases", "value": 2},
      {"type": "json_path_equals", "path": "fields.failures", "value": 0}
    ]
  }]
}
```

Run `agent-learn eval check-saved.json --output saved-check.json`. After the fix, `saved-check.json` shows one passing case with two assertions. If you save the earlier failing result again, the second assertion fails.
