## About

An Agent Learning Kit manifest describes a test case, the agent that answers it, and how to score the answer. Use `alk` (also installed as `agent-learn`) to test a scripted returns reply for Ridgeline Outfitters, save the full result, and verify the local run history without an account or model key.

## Run a returns case locally

<Steps>
  <Step title="Install the CLI and check the engines">
    Start in an empty directory with Python 3.10 or later. Run the following commands in the same shell.

    ```bash
    python3 -m venv .venv
    . .venv/bin/activate
    python -m pip install agent-learning-kit==0.3.7
    alk doctor --quiet
    ```

    Look for `doctor: passed` and zero missing public and engine modules. This checks the installation, not your agent or your account credentials.
  </Step>
  <Step title="Create a run manifest">
    ```bash
    alk init ridgeline-returns --preset run --name ridgeline-returns
    cd ridgeline-returns
    export AGENT_LEARNING_LEDGER_PATH="$PWD/.ledger"
    ```

    `--preset run` creates `manifests/run.json` with a scripted agent, one local text case, and a one-turn simulation. The last command gives this example its own ledger directory. Without an override, ALK uses `~/.agent-learning/ledger/runs.jsonl` by default. Leave `AGENT_LEARNING_TELEMETRY` unset to record the run.
  </Step>
  <Step title="Set the reply and the expected outcome">
    Replace the scaffold's smoke test with a customer returning an unused jacket. The scripted agent always gives the reply you specify, so this tests the case and scoring setup, not a live support agent.

    ```bash
    python - <<'PY'
    import json
    from pathlib import Path

    path = Path("manifests/run.json")
    manifest = json.loads(path.read_text())
    reply = "Bring the unused rain jacket and your receipt to a Ridgeline store within 30 days."
    manifest["agent"]["content"] = reply
    case = manifest["scenario"]["dataset"][0]
    case["persona"] = {"name": "Kai", "role": "customer"}
    case["situation"] = "Kai wants to return an unused rain jacket to Ridgeline Outfitters."
    case["outcome"] = reply
    path.write_text(json.dumps(manifest, indent=2) + "\n")
    PY
    ```
  </Step>
  <Step title="Run the case and inspect the saved result">
    ```bash
    alk run manifests/run.json --output artifacts/run.json
    python - <<'PY'
    import json
    from pathlib import Path

    path = Path("artifacts/run.json")
    result = json.loads(path.read_text())
    print(path, result["kind"], result["status"], result["summary"]["case_count"])
    PY
    ```

    Expect `artifacts/run.json agent-learning.run.v1 passed 1`. The file contains the evaluation and per-case report, not just the pass/fail verdict. A relative `--output` path starts at your working directory.
  </Step>
</Steps>

## Inspect and verify the run ledger

The **result file** answers “what happened in this case?” The **ledger** records a smaller entry with a run ID, verdict, scores, and references rather than copies of assets. To inspect the most recent entry and check the history:

```bash
alk runs list
run_id=$(alk runs list --limit 1 --json | python -c 'import json, sys; print(json.load(sys.stdin)[0]["run_id"])')
alk runs show "$run_id"
alk runs verify
```

For this case, `list` shows `pass`, `local_gate`, and `local`. `show` also accepts a unique prefix of the ID. `verify` recomputes the content hashes and chain links across the ledger. Look for a row count of `1` and `CHAIN OK` on your first run. This checks the ledger, not the contents of `artifacts/run.json`, and does not rerun the case.

## Preview optional account sync

To see which entries are still local and preview the returns entry without sending anything, stay in the same shell:

```bash
alk runs list --synced local
alk runs sync "$run_id" --dry-run
```

Without a Future AGI API key, the preview reports no destination. If you have configured your account credentials (`FI_API_KEY` and `FI_SECRET_KEY`), the same preview prints the destination, header presence without values, and the metadata payload. Review one run ID at a time. Metadata includes the verdict and scores, not the customer conversation, prompts, or tool inputs and outputs.

Only when you want to send metadata, use `alk runs sync "$run_id"` for that entry or `alk runs sync --queued` for all unsynced entries in the selected ledger. A deferred sync leaves the row local for retry. Setting `AGENT_LEARNING_TELEMETRY=off` goes further than omitting credentials: it prevents new ledger entries **and** disables sync even with credentials. `alk run --output` can still save a result file.

## Troubleshooting

| What you see | What to do |
| --- | --- |
| `agent-learn run: manifest root must be an object` (exit 1) | Pass the manifest, not a list of cases. A JSON file containing only `[]` is invalid. Use `alk run manifests/run.json --dry-run` to check the manifest and its required environment without executing the case. |
| `missing required environment variable(s)` (exit 1) | Set the names declared in the manifest's `required_env` before running it. The `run` preset needs none unless you add them, for example with `init --required-env`. |
| `agent-learn: unknown command` (exit 2) | Use `alk --help` for the kit's commands. `fagi` is the separate platform CLI. |
| `no runs yet` after a run | Check `AGENT_LEARNING_LEDGER_PATH` in this shell and whether telemetry was `off` during the run. A saved result alone does not mean a ledger entry exists. |
