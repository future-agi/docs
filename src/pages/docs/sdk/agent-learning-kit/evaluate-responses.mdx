title: "Evaluate responses"
description: "Check an agent's reply against a rule, inspect a failure, and refine what counts as a match"
---

Suppose a customer asks about order `A-104`. Your support agent should repeat the order number so the customer knows which shipment it found. Use ALK to check two replies against that rule, then tighten the check to catch a reply about the wrong order.

<Note>
Install ALK and set the local execution settings in the [ALK quickstart](/docs/sdk/agent-learning-kit). Keep that Python environment active. Both checks below run on the supplied text without calling a model.
</Note>

## Check the replies for the order number

Save this as `check_replies.py`. Each call to `evals.evaluate` takes the reply you want to score as `output`. The `contains` metric searches it for the `keyword` you supply.

```python
from fi.alk import evals

replies = [
    "We received order A-104.",
    "We received your order.",
]

for reply in replies:
    result = evals.evaluate(
        "contains", engine="local", output=reply, keyword="A-104"
    )
    print(result.status, result.passed, result.score, result.reason)
```

Run `python check_replies.py`. The lines appear in the same order as the replies:

```text
completed True 1.0 Keyword 'A-104' found
completed False 0.0 Keyword 'A-104' not found
```

Both checks completed. The second reply failed because it omitted the order number. Use `result.passed` for the verdict and `result.reason` to explain it. To evaluate your own agent, replace the sample strings with its replies and take the expected ID from the customer request.

## Catch a reply about a different order

The reply `We received order A-1049.` would pass the first check because `A-104` occurs inside the longer ID. To catch this case, use the `regex` metric with a word boundary on each side of the ID. Append this to the same file:

```python
for reply in ("We received order A-104.", "We received order A-1049."):
    result = evals.evaluate(
        "regex",
        engine="local",
        output=reply,
        config={"pattern": r"\bA-104\b"},
    )
    print(result.passed, reply)
```

Run the script again. The two additional lines show which reply meets the stricter rule:

```text
True We received order A-104.
False We received order A-1049.
```

A passing reply includes the expected order number. It can still give the wrong shipping day. In [Simulate an agent](/docs/sdk/agent-learning-kit/simulate-an-agent), the customer expects a Friday shipment. Use the final reply from `report.test_cases[0].result.messages[-1]["content"]` as `output` to evaluate that conversation, and check the day against the order record separately.
