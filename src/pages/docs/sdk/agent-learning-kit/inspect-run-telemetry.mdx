---
title: "Inspect run telemetry"
description: "Find a run in a temporary local ledger, verify its record, preview account sync, and export a span to your terminal"
---

Use the run ledger to look up a verdict after an ALK process exits. The ledger keeps a local record for each run it receives. You can verify those records and preview which metadata would go to your Future AGI account. For timings inside your own application, record an OpenTelemetry span.

<Note>
Install ALK with the [quickstart](/docs/sdk/agent-learning-kit). Run the shell blocks in the same terminal with that virtual environment active. The examples use a fresh ledger and need no credentials.
</Note>

## Record a result locally

Set the ledger directory and keep automatic account export off. Unset the telemetry switch so the recorder can append a row. The directory normally defaults to `~/.agent-learning/ledger`.

```bash
export AGENT_LEARNING_LEDGER_PATH="$(mktemp -d)"
export AGENT_LEARNING_SYNC=local
export LITELLM_LOCAL_MODEL_COST_MAP=True
unset AGENT_LEARNING_TELEMETRY

run_id=$(python - <<'PY'
from fi.alk import telemetry

answer = "Refunds take 3 days."
passed = "3 days" in answer
run = telemetry.emit_run(kind="evals", name="refund-timeline",
                         metrics={"passed": passed},
                         verdict="pass" if passed else "fail")
assert run.status == "local"
print(run.run_id)
PY
)
agent-learn runs list --verdict pass
agent-learn runs show "$run_id" --json
```

The list contains one row. The JSON contains the fields ALK hashes to identify that row, including the verdict and evidence class. The SDK writes status messages to standard error, so `run_id` captures only the printed identifier.

## Verify the record and recover a failed check

```bash
agent-learn runs verify
```

Expect `CHAIN OK` and a count of one row. The verifier recomputes each row's content address and its link to the preceding row.

To see what a changed verdict looks like, tamper with a *copy* of the temporary ledger. This block checks the copy and then verifies the original again.

```bash
copy_dir=$(mktemp -d)
cp "$AGENT_LEARNING_LEDGER_PATH/runs.jsonl" "$copy_dir/runs.jsonl"
python - "$copy_dir/runs.jsonl" <<'PY'
import json
import sys
from pathlib import Path

path = Path(sys.argv[1])
row = json.loads(path.read_text())
row["verdict"] = "fail"
path.write_text(json.dumps(row) + "\n")
PY
AGENT_LEARNING_LEDGER_PATH="$copy_dir" agent-learn runs verify
agent-learn runs verify
```

The first check exits with code 1 and reports `content_address_mismatch` at row 0. The second prints `CHAIN OK`. If this happens to a working ledger, preserve the damaged copy and verify a known-good backup before pointing `AGENT_LEARNING_LEDGER_PATH` at it.

## Preview account sync

```bash
agent-learn runs sync "$run_id" --dry-run
```

Without credentials, the preview says a real sync would send nothing. With configured `FI_API_KEY` and `FI_SECRET_KEY`, it shows the destination, header names, and metadata payload. The preview makes no request. By default a real sync sends metadata. Add `--content` only when you intend to opt in to content sync with a reviewed capture and redaction map.

To send this row to your account, supply your credentials and run `agent-learn runs sync "$run_id"` without the preview flag. An explicit sync can send a row even with `AGENT_LEARNING_SYNC=local`. For automatic dashboard traces from `emit_run`, select `AGENT_LEARNING_SYNC=auto` with credentials. A successful automatic export from `emit_run` returns `status="synced"` and a trace ID. For `deferred` or `export_failed`, check the collector URL and credentials before retrying.

## Disable ALK recording for one run

```bash
AGENT_LEARNING_TELEMETRY=off python - <<'PY'
from fi.alk import telemetry

run = telemetry.emit_run(kind="evals", name="private-check", verdict="pass")
print(run.status, run.run_id)
PY
agent-learn runs verify
```

Expect `off None` and the same one-row count. This setting disables ALK's run recorder and account sync. If a run seems to be missing, check the ledger path and unset `AGENT_LEARNING_TELEMETRY` before repeating the run.

## Export an application span to the console

A [span](/docs/observe/concepts/spans) records one timed operation. The evaluation SDK lets you choose its exporter separately. In a fresh Python process, select the console exporter and turn off the optional model, evaluation, and cost processors for this timing check.

```python
from fi.alk import evals

otel = evals.otel
config = otel.TraceConfig(
    service_name="refund-agent",
    exporters=[otel.ExporterConfig(type=otel.ExporterType.CONSOLE)],
    processors=[], evaluation=otel.EvaluationConfig(enabled=False),
    cost=otel.CostConfig(enabled=False),
)
otel.setup_tracing(config)
with otel.get_tracer("refund-agent").start_as_current_span("check-refund") as span:
    span.set_attribute("refund.days", 3)
otel.shutdown_tracing()
```

Save the block as `trace_refund.py` and run `python trace_refund.py` in a fresh process. Expect a JSON span named `check-refund` with the attribute `refund.days` set to 3. A network exporter sends span attributes to the collector you configure. Use that collector's endpoint and authentication settings when you switch exporters. The ALK ledger switches apply to the run recorder and account sync. An exporter you configure in your application has its own destination and controls.
