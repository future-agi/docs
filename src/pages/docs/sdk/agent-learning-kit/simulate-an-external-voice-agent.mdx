title: "Simulate an external voice agent"
description: "Validate a voice test locally, call a deployed agent through LiveKit, Vapi, Retell or SIP, and inspect the conversation"
---

Can a customer learn when order A-104 ships by calling your deployed agent? Give ALK one customer scenario, a connection to the target agent and a LiveKit room for the simulated caller. Preview the configuration locally before placing a call.

<Note>
Start in the Python environment from the [ALK quickstart](/docs/sdk/agent-learning-kit). For connected runs, install `python -m pip install 'agent-learning-kit[livekit]==0.3.7'`. You need a test agent you can call, a LiveKit project and access to the simulator’s model and speech services. A connected run uses these services and can incur provider and carrier charges.
</Note>

## Describe one call

Create **scenario.json**. Each item in `dataset` runs as a separate call. Start with one row so you can inspect what both parties said.

```json
{
  "name": "order-shipping-day",
  "dataset": [{
    "persona": {"name": "Morgan", "role": "customer"},
    "situation": "Ask when order A-104 ships. Give the order number when asked.",
    "outcome": "Learn the shipping day for order A-104 and confirm it with the agent."
  }]
}
```

Create **runtime.json**. Replace the example URL with the WebSocket URL of the LiveKit project where ALK can create a room. Vapi and Retell web calls also use this room to connect the simulated caller to the provider.

```json
{
  "url": "wss://example.livekit.cloud",
  "room_name": "order-{test_case_id}",
  "room_mode": "managed",
  "api_key_env": "LIVEKIT_API_KEY",
  "api_secret_env": "LIVEKIT_API_SECRET"
}
```

Create **simulator.json**. This customer uses OpenAI for speech recognition, replies and speech synthesis. Set `OPENAI_API_KEY` in the connected run’s environment.

```json
{
  "instructions": "Act as the customer. Ask for the shipping day and wait for the answer.",
  "llm": {"provider": "openai", "model": "gpt-4o-mini"},
  "stt": {"provider": "openai", "model": "gpt-4o-mini-transcribe", "language": "en"},
  "tts": {"provider": "openai", "model": "gpt-4o-mini-tts", "voice": "alloy"}
}
```

## Point ALK at your test agent

Save this Vapi example as **agent.json**. Replace `assistant-id` with the deployed assistant’s ID and copy its current instructions into `system_prompt`. The prompt tells the simulator what the target does. The provider continues to serve its deployed configuration and tools during the call.

```json
{
  "name": "order-support",
  "system_prompt": "You help customers find the shipping day for their orders.",
  "transport": {"kind": "vapi_websocket"},
  "target": {"provider": "vapi", "assistant_id": "assistant-id", "api_key_env": "VAPI_API_KEY"}
}
```

For a different route, keep `name` and `system_prompt`, remove the Vapi `target` and `transport`, and add the fields from the matching row. Replace the example IDs and phone numbers with your test resources. Phone numbers use international E.164 format.

| Route | Fields to add to **agent.json** | Setup for a connected run |
| --- | --- | --- |
| Retell web call | `"target": {"provider": "retell", "agent_id": "agent-id", "api_key_env": "RETELL_API_KEY"}, "transport": {"kind": "retell_webcall"}` | Export the Retell key for the agent |
| LiveKit WebRTC | `"agent_name": "order-support", "transport": {"kind": "webrtc"}` | Register a running target worker under that exact name in the simulator’s LiveKit project |
| Dial the target’s number | `"transport": {"kind": "sip_outbound", "sip_trunk_id": "ST_trunk", "sip_number": "+12025550110", "sip_call_to": "+12025550111"}` | Provision an outbound trunk with an authorized caller ID. The destination can answer through LiveKit, Vapi or Retell |
| Receive a call from your LiveKit target | `"transport": {"kind": "sip_inbound", "readiness_timeout_seconds": 120}` | Export `LIVEKIT_INBOUND_TRUNK_ID`. Have the target dial your LiveKit inbound number after ALK starts listening |
| Receive a call from Vapi | `"transport": {"kind": "sip_inbound", "inbound_call_originator": "vapi", "readiness_timeout_seconds": 120}, "provider_evidence": {"provider": "vapi", "call_id_source": "originator_response"}` | Export `LIVEKIT_INBOUND_TRUNK_ID`, `LIVEKIT_INBOUND_DID`, `VAPI_API_KEY`, `VAPI_ASSISTANT_ID` and `VAPI_PHONE_NUMBER_ID` |
| Receive a call from Retell | `"transport": {"kind": "sip_inbound", "inbound_call_originator": "retell", "readiness_timeout_seconds": 120}, "provider_evidence": {"provider": "retell", "call_id_source": "originator_response"}` | Export `LIVEKIT_INBOUND_TRUNK_ID`, `LIVEKIT_INBOUND_DID`, `RETELL_API_KEY`, `RETELL_AGENT_ID` and `RETELL_FROM_NUMBER` |

For incoming SIP calls, configure the inbound trunk for the simulator’s number and allow the originating caller ID. If your direct dispatch rule already routes calls into the intended room, set `dispatch_rule_name` in `transport`. Set a fixed `room_name` in **runtime.json** and add `"room_name_verbatim": true` so ALK joins the room named by that rule. Otherwise ALK creates a temporary rule on the supplied `LIVEKIT_INBOUND_TRUNK_ID` and removes the rule during cleanup.

## Validate the files without calling the agent

Run the preview below for the Vapi example. The sample values are scoped to this command. For another route, supply the environment names required for that route instead.

```bash
LIVEKIT_API_KEY=preview LIVEKIT_API_SECRET=preview VAPI_API_KEY=preview \
agent-learn simulate voice --agent-definition agent.json --scenario scenario.json \
  --livekit-runtime runtime.json --simulator simulator.json \
  --write-manifest voice.json --dry-run -o preview.json
```

Open **preview.json**. It should contain top-level `dry_run` set to `true`, top-level `status` set to `passed`, and `summary.scenario_cases` set to `1`. **voice.json** contains the target, scenario, runtime and required environment names. Repeat the command after removing `VAPI_API_KEY=preview` from its first line. The CLI exits with code 2 and names the missing variable. Restore the value to repeat the preview. The preview checks the input shapes and the LiveKit and transport variables declared in the manifest. It checks the OpenAI credential only when execution starts. Authentication, audio and the target’s availability require a connected run.

## Place the call and inspect the report

Set `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`, `OPENAI_API_KEY` and the real credentials for your chosen route. Choose `simulator_first` if the customer opens the conversation. Set `agent_first` if the target is configured to greet first, including when it originates the phone call. The flag controls who speaks first. The transport controls who dials.

<Warning>
Record only test calls that every participant has authorized. The command below saves audio and a transcript under the current directory. Protect those files as customer data and delete them when you no longer need the evidence.
</Warning>

```bash
agent-learn simulate voice --agent-definition agent.json --scenario scenario.json \
  --livekit-runtime runtime.json --simulator simulator.json \
  --conversation-direction simulator_first --max-seconds 150 --readiness-timeout 120 \
  --record-audio --recording-root recordings -o call.json
```

The command opts in to recording. Remove `--record-audio` to skip it. After the run writes **call.json**, inspect the first case:

```python
import json
from pathlib import Path

run = json.loads(Path("call.json").read_text())
case = run["report"]["results"][0]
print("Call status:", case["metadata"].get("status"))
print("Failure:", case["metadata"].get("failure"))
print(case["transcript"])
print("Customer audio:", case.get("audio_input_path"))
print("Agent audio:", case.get("audio_output_path"))
print("Evaluation:", run["summary"]["evaluation_passed"])
```

Save the block as `inspect_call.py` beside **call.json** and run `python inspect_call.py`. A case with status `completed` has a conversation to inspect. Read the transcript to see whether Morgan learned the shipping day, and check the evaluation separately. For a readiness timeout, check the registered worker name, the provider’s greeting configuration or the trunk’s routing, depending on the route. A silent or failed call can have empty recording paths. Check the case failure before relying on the audio.

**Execution evidence.** Local previews validated the provider web, LiveKit WebRTC and SIP configurations on this page. The repository acceptance matrix marks LiveKit WebRTC as agent-first, LiveKit and Vapi telephony in both speaking directions, Vapi web in both speaking orders, and Retell web and telephony as simulator-first. Retell agent-first paths have local configuration evidence only in this guide. No new live call was placed for these examples.

To generate the cases during a connected run, replace `--scenario scenario.json` with `--topic "shipping delays" --num-scenarios 1`. This calls the simulator’s configured language model before the test. In ALK 0.3.7, a topic-generated run leaves `summary.evaluation_passed` as `null`; evaluate its saved replies separately. A prewritten scenario is required for `--dry-run` and `--write-manifest`. To reuse a workspace dataset instead, [generate or fetch a platform scenario](/docs/sdk/agent-learning-kit/create-personas-and-scenarios) and pass its saved JSON to `--scenario`.
