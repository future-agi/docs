The `agent-learning-kit` distribution installs the `fi.alk` namespace and the `agent-learn` and `alk` commands. Module names below use the same import form, for example `from fi.alk import simulate, evals`. Calls marked `await` run asynchronously.

## Simulation and authoring

| Entry point | Input and result | Execution |
| --- | --- | --- |
| `await simulate.run_manifest_file(path)` | A run manifest. The dictionary contains `summary` and `report["results"]`. Each result holds a transcript | Scripted agents run locally. HTTP targets, connected tools, and model-backed agents contact their configured services |
| `await simulate.SimulationRunner().run(spec, target=agent)` | A `simulate.SimulationSpec` and an agent. The report exposes `test_cases[0].result.transcript` and execution `status` | The selected environment determines how to invoke the target |
| `simulate.register_environment(name)` | Decorator for a runnable environment. Its async `run(spec, *, target, **kwargs)` returns a `TestReport` | Registration lasts for the current Python process |
| `extensions.register_environment(record)` | A namespaced metadata record for a world. `extensions.register_objective`, `register_optimizer`, `register_generator`, and `register_role` record other extensions. `extensions.registered(point)` lists names | Local registration. A runnable environment also needs a factory registered with `simulate` |
| `harness.load_bundle(root)` | Loads and verifies an authored environment bundle. `harness.load_environment_plan(root)` reads the plan | Loading reads local files. Creating a bundle from source with `agent-learn harness author` runs authoring stages and requires the selected model backend. See [Author an environment](/docs/sdk/agent-learning-kit/author-an-environment) |
| `studio.build_persona`, `validate_persona`, `calibrate_persona` | Create a persona, validate its traits, or run its calibration checks and inspect their results. `save_persona` and `load_persona` handle local persona files | Local operations on supplied data. See [Create personas and scenarios](/docs/sdk/agent-learning-kit/create-personas-and-scenarios) |
| `studio.expand_scenarios`, `coverage_report`, `synthesize_next_scenario` | Expand coverage combinations, inspect missing combinations, or request the specification for the weakest coverage cell. `load_scenario` and `save_scenario` handle local scenario files | Local. Platform calls such as `pull_personas`, `pull_scenarios`, and `generate_scenario` need service access. Generation can create workspace records |

## External voice

| Entry point | Input and result | Execution |
| --- | --- | --- |
| `simulate.build_voice_run_manifest(...)` | A typed agent definition, simulator settings, and scenario become a portable run manifest | Building the manifest is local. [Simulate an external voice agent](/docs/sdk/agent-learning-kit/simulate-an-external-voice-agent) covers the prerequisites for a call |
| `await simulate.run_voice_simulation(...)` | The agent definition and either a scenario or topic. Returns a `TestReport` with per-case results | Running connects to the configured voice services and can incur provider and telephony charges |
| `await simulate.generate_platform_voice_scenario(...)` | Agent definition and generation configuration. Returns a generated scenario with platform references | Requires workspace credentials and can create or update platform records |
| `episode.convert_call(provider, record, context)` | A saved provider call and its context become a common voice episode dictionary. `episode.check_conformance(episode, context)` returns the names of broken rules | Local conversion of existing evidence |
| `voice_loop.compile_voice_objective(payload)` | Validates voice scoring terms and guards. `voice_loop.attribute_voice_sublayer(...)` maps a failure signal to a voice component | Local scoring configuration |

## Evaluation, benchmarks, and campaigns

| Entry point | Input and result | Execution |
| --- | --- | --- |
| `evals.evaluate(metric, engine="local", ...)` | A response and metric parameters. The result exposes `status`, `passed`, `score`, and `reason` | Deterministic checks such as `contains` run locally. A model-backed check needs the configured model or service |
| `evals.run_eval_suite_file(path)`, `evals.evaluate_artifact_file(path)` | A suite file supplies cases and assertions. An artifact file supplies a saved run to score. Both return dictionaries with a `summary` and `exit_code` | Suite execution uses the declared provider and evaluators. See [Run evaluation suites](/docs/sdk/agent-learning-kit/run-evaluation-suites) |
| `await redteam.redteam_manifest_file(path)` | A campaign manifest. The returned dictionary contains `summary` and campaign evidence | The target and providers determine connectivity and cost. See [Red team an agent](/docs/sdk/agent-learning-kit/red-team-an-agent) |
| `tasks.compile_task_dataset(payload)`, `tasks.run_benchmark(dataset, agent)` | Experimental. Compile named tasks, objectives, and optional splits. A run produces `per_task` rows and an `aggregate` | Local for scripted targets. A connected target makes its normal requests |
| `bench.run_bench(suite, agent, ...)`, `bench.run_bench_file(path, ...)` | A benchmark suite plus an agent or submission. Each task row exposes `verdict` and `result["scalar"]` in the JSON result | Supports a driven agent, scoring submitted work, and an agent-driven environment. Code grading can execute submitted code. [Benchmark an agent](/docs/sdk/agent-learning-kit/benchmark-an-agent) covers the three modes |
| `suite.run_suite_file(path)` | A workflow suite combines jobs such as simulation, evaluation, and optimization. Returns the suite result, `summary`, and `exit_code` | Each job retains its own provider and command requirements. `suite.verify_trust_certificate_file` checks a saved certificate |

## Optimization and practice

[Measure an agent improvement](/docs/sdk/agent-learning-kit/measure-an-agent-improvement) includes independent examples for configuration search, loss, practice, and source edits.

| Entry point | Input and result | Execution |
| --- | --- | --- |
| `optimize.optimize_manifest_file(path, dry_run=True)` | Preview the search. With `dry_run=False`, read `summary["best_candidate_id"]`, the selected score, and `optimization["history"]` | Runs the agent and evaluators declared in the manifest |
| `tasks.optimize_against_dataset(dataset, base_agent, search_space)` | Experimental. A base agent, candidate values, and named dataset splits. Compares configurations on the training split and scores the selected candidate on held-out tasks | Invokes the supplied agents and scoring configuration |
| `loss.compile_objective(payload)`, `loss.verdict_row(...)`, `loss.loss_report(objective, verdicts)` | Compile scoring terms and guards, record a scored observation, and aggregate the rows into per-cell losses and a scalar score | Local. Training requires a declared objective with guards |
| `practice.run_practice_loop(manifest, cell_scorer=..., repeat_scorer=..., replay_row=...)` | A simulation with its objective, budget, and seed. Each round reports the loss, drills, and updates | The default callbacks pass. Custom callbacks supply measured scores and may contact services. The practice store holds saved lessons |
| `improve.improve_agent_code(...)` | Source text, function name, dataset, objective, and proposer. Returns `fixed`, held-out scores, and `accepted_source` or `None` | Executes trusted candidate source in a temporary directory. The caller applies an accepted edit. `propose_patch_via_llm` sends source and failure evidence to a model and requires provider access |

## Artifact actions and capabilities

An action describes something you can do with a saved result. A capability describes what the kit declares or what an artifact shows. Both catalogs return data you can inspect before starting another run.

Save this as `inspect_actions.py` and run `python inspect_actions.py`:

```python
import json
from pathlib import Path
from tempfile import TemporaryDirectory

from fi.alk import actions, capabilities

with TemporaryDirectory() as directory:
    path = Path(directory) / "refund-run.json"
    path.write_text(json.dumps({
        "kind": "agent_learning.run.v1",
        "name": "refund-check",
        "status": "passed",
        "summary": {"evaluation_passed": True},
    }))

    artifact = actions.load_artifact_file(path)
    catalog = actions.action_catalog(artifact, source_path=path)
    plan = actions.run_action(
        artifact, "report_artifact", source_path=path, dry_run=True,
    )
    gate = capabilities.capability_catalog(
        [artifact], required_capabilities={"commands": ["report"]},
    )

    print(catalog["summary"]["action_ids"])
    print(plan["dry_run"], plan["command"])
    print(gate["summary"]["capability_gate_passed"])
```

The first line contains `report_artifact`. The second starts with `True` and shows the report command without running it. The last line is `True` because this installation declares the required `report` command. Replace `report` with an unavailable command to see `capability_gate_passed` become `False` and inspect `missing_required_capabilities`.

| Entry point | Input and result |
| --- | --- |
| `actions.load_artifact_file(path)` | Reads a JSON or YAML object from disk |
| `actions.action_catalog(artifact, source_path=path)` | Lists actions in `actions` and IDs in `summary["action_ids"]`. Includes the generic `report_artifact` action |
| `actions.run_action(artifact, action_id, source_path=path, inputs=..., dry_run=True)` | Resolves the selected action and returns the planned operation. Without `dry_run=True`, the action can write files or run a connected workflow |
| `capabilities.capability_catalog(artifacts, required_capabilities=...)` | Returns `static_capabilities`, `observed_capabilities`, and their combined catalog. For example, `{"commands": ["report"]}` requires the reporting command. A missing requirement appears in `summary["missing_required_capabilities"]` with exit code 1 |
| `trinity.trinity_status()` | Inspects local imports and configuration. Its summary lists missing public and engine modules. A passing result verifies the installation's import checks |

## Telemetry and credentials

| Entry point | Input and result | Destination |
| --- | --- | --- |
| `telemetry.emit_run(...)`, `telemetry.run_telemetry(...)` | Record a completed run or wrap code in a recording context. The `RunSummary` includes `status`, `run_id`, and, after successful account export, `trace_id` | `AGENT_LEARNING_SYNC=local` keeps automatic recording local. `AGENT_LEARNING_TELEMETRY=off` suppresses the recorder and account sync |
| `telemetry.RunLedger()` | `rows()` reads the records. `verify()` reports `chain_intact` and the first broken links in `breaks` | Reads the ledger directory. [Inspect run telemetry](/docs/sdk/agent-learning-kit/inspect-run-telemetry) covers verification, account sync, and span export |
| `evals.otel.setup_tracing(config)` | An OpenTelemetry configuration with exporters. Returns a tracer provider when tracing is enabled and its dependencies are available | A console exporter prints to the current process. A network exporter sends spans to the configured collector |
| `from fi.alk import configure, current_config, get_api_key` | `configure(...)` sets the shared SDK configuration. `current_config()` returns it. `get_api_key(required=True)` raises if a key is missing | Future AGI credentials include `FI_API_KEY` and `FI_SECRET_KEY`. `FI_BASE_URL` selects the API destination. External models, target endpoints, and voice services use their own credentials |
