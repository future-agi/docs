Installing `agent-learning-kit` gives you the Python namespace `fi.alk`. The same installation includes the `agent-learn` and `alk` commands. Use [the quickstart](/docs/sdk/agent-learning-kit) to check your installation with one scripted conversation.

## Choose an entry point

| Task | Python entry point | Input and result |
| --- | --- | --- |
| Run a saved scenario | `simulate.run_manifest_file` | Await it with a manifest path. The returned dictionary contains the run status, summary and conversation report |
| Call an agent from Python | `simulate.SimulationRunner().run` | Await it with a `SimulationSpec` and a target. Read individual conversations from the returned report's `test_cases` |
| Check an existing answer | `evals.evaluate` | Select a metric, supply the response and its check parameters, and inspect the result. [Evaluate responses](/docs/sdk/agent-learning-kit/evaluate-responses) shows a local check |
| Run a suite of evaluations | `evals.run_eval_suite_file` | Pass a suite file with its provider, cases and assertions. The result dictionary includes the summary and exit code |
| Compare candidates | `optimize.optimize_manifest_file` | Pass an optimization manifest defining what to try and how to score it. The result records candidate and evaluation evidence |
| Generate an environment from source | `agent-learn harness author` | Supply an agent source directory and a fresh output directory. The [reference harness guide](/docs/sdk/agent-learning-kit/author-an-environment) covers model access, commands and files to inspect |

For the Python calls in this table, import the matching module with `from fi.alk import simulate`, `from fi.alk import evals`, or `from fi.alk import optimize`. When using the simulation runner, pass your agent implementation as the target. [Simulate an agent](/docs/sdk/agent-learning-kit/simulate-an-agent) includes a complete example.

## Read a simulation result

The two simulation entry points expose the conversation differently. Use the accessor that matches the call you made:

| After calling | Read the first transcript | Check the outcome |
| --- | --- | --- |
| `run = await simulate.run_manifest_file(path)` | `run["report"]["results"][0]["transcript"]` | For the quickstart's evaluated run, read `run["summary"]["evaluation_passed"]` |
| `report = await simulate.SimulationRunner().run(spec, target=agent)` | `report.test_cases[0].result.transcript` | `report.status` describes execution. Check the recorded answer against the scenario's expected outcome |

## Choose an extension

| What you want to change | What to implement |
| --- | --- |
| What happens during a scenario | Define an environment with a manifest and an async `run(spec, *, target, **kwargs)` method. Register it with `simulate.register_environment` and return a `TestReport`. [Build an environment plugin](/docs/sdk/agent-learning-kit/build-an-environment-plugin) walks through registration and the return value |
| Which agent replies | Pass the target expected by your environment. The built-in chat environment calls the agent it receives, while a custom environment can call a method you define |
| Which backend drives source authoring | A harness backend creates a session for an authoring stage. It must support the selected model, tool calls and session lifecycle. Register its loader in the process that starts the harness before selecting it with `ALK_HARNESS` |

These extensions have different scopes. Registering an environment changes one simulated world. Selecting an authoring backend changes how the harness performs its stages. ALK does not expose a switch that substitutes an arbitrary executor for the entire harness.

## Know when a workflow connects to a service

The scripted agent, the in-memory order plugin and the local response checks in these guides run after installation without an API key. A target that calls your own HTTP endpoint still makes that request. A model-backed evaluator or authoring stage sends its inputs to the configured provider and can incur charges. `AGENT_LEARNING_SYNC=local` controls account telemetry only.

To submit work to Future AGI and read the results in the dashboard, follow [hosted Environments](/docs/environments).
