When usage jumps, the total alone doesn't tell you which team caused it. The Usage Summary page shows how your organization is using Future AGI, with one card per meter for the billing period. To see which [workspace](/docs/admin-settings/workspace-management) drove a change, compare one meter over the same billing period. Changing the period and the workspace together makes it hard to tell which caused the difference.

<Prerequisites title="Before you start">
- You can view usage for workspaces you have access to. An organization [Owner or Admin](/docs/roles-and-permissions) can also view the organization total.
- For a workspace-to-workspace comparison, choose two workspaces you can see. Billing applies to Cloud and Enterprise deployments.
</Prerequisites>

## Compare one meter across workspaces

1. Open **Settings > Usage Summary**.

   You should see the period dates, [plan](/docs/billing/guides/manage-your-plan), estimated cost and meter cards.

2. Select the billing period to compare.
3. Set the workspace filter to the first workspace.
4. Note the usage and unit on one meter's card, such as gateway requests.
5. Switch only the workspace filter to the second workspace.

   Compare requests with requests for the same dates, not the first workspace's request count with the second workspace's estimated cost. For the organization-wide view, an Owner or Admin can select **All**.

## Choose the right unit

<div class="sdk-ref-table">

| Meter | What the usage counts |
| --- | --- |
| Storage | Stored data in GB |
| Credits | Managed work such as [evaluations](/docs/evaluation); a credit count is not a count of eval runs |
| Gateway requests | Requests through [Agent Command Center](/docs/command-center) |
| Gateway cache hits | Gateway responses served from cache |
| Text simulation tokens | Tokens consumed by text [simulations](/docs/environments) |
| Voice simulation minutes | Call duration for voice simulations |
| Tracing events | [Spans](/docs/observe/concepts/spans) ingested into Observe |

</div>

The page filter scopes all the cards to one workspace. To compare several workspaces for a single meter instead, open its trend and use the workspace breakdown for the same period. The trend shows daily values within a month or monthly values over a range of months.

## Read a zero or an estimate

- **All cards read zero:** check the selected period and workspace. If no meter has moved in that scope, zero is expected.
- **Usage is nonzero but there is no usage charge:** compare usage with the meter's free allowance before treating it as missing data.
- **The projection changes:** it estimates the period-end total from usage so far. Read the actual usage for a comparison, especially early in a period.

## Check the scope from the SDK

The Python and TypeScript [usage overview reference](/docs/sdk/reference/usage) documents `client.usage.overview`, with optional `period`, `period_end` and `workspace_id`. Match the dates and workspace when comparing an SDK result with a dashboard card. Compare `current_usage` and `display_unit` for the same meter in the returned [usage dimensions](/docs/sdk/reference/account-models#usageoverviewdimension). The reference also lists the `get_usage_overview` [MCP](/docs/falcon-ai/guides/use-the-mcp-server) tool.
