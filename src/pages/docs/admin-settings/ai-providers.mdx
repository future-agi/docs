**AI Providers** is where you connect LLM services to Future AGI. The platform uses these providers for [evaluations](/docs/evaluation), prototype runs, [optimization](/docs/optimization) and other features that need to call a language model.

Choose an organization default when teams share a model provider, or a workspace override when one team needs a different connection.

<Prerequisites title="Before you start">
- To configure an organization provider, you need the Owner or Admin [role](/docs/roles-and-permissions). Workspace admins and members can view and use configured providers.
- Have the provider credentials ready. For a [custom model](/docs/evaluation/guides/custom-models), you also need its served model name and full chat-completions URL.
</Prerequisites>

## Choose the scope

| The connection is for | Open | Result |
| --- | --- | --- |
| The organization | **Settings > AI Providers** | The organization supplies the default connection. |
| A single workspace | **Settings > Workspace**, then the workspace’s **AI Providers** | Its configuration overrides the organization provider in that workspace. |

## Connect a built-in provider

Built-in providers are pre-configured. You only need to add your API key.

1. Open the settings page for the scope you chose.
2. Select the provider.

   Built-in choices include OpenAI, Anthropic, Google (Gemini or Vertex AI), AWS Bedrock, Azure OpenAI, Mistral and Cohere.

3. Enter the provider credentials.
4. Fill in the required provider-specific settings, such as a region or endpoint.
5. Select **Save**.

## Connect a custom endpoint

Use this path for a self-hosted model or an HTTP endpoint that is not a built-in provider.

1. Open the **Custom model** tab.
2. Select **Create custom model**.
3. Choose **Configure Custom Model**.
4. Enter the **Model Name** your endpoint serves.
5. Enter the input and output token costs per million tokens.

   Zero is valid, for example for a model you host yourself; a negative cost is not.

6. Set **API Base URL** to the full chat-completions URL, such as `https://your-host/v1/chat/completions`.
7. Add any headers or authentication parameters the endpoint requires under **Custom Configuration**.
8. Select **Add Custom model**.

   Future AGI sends a test request to the endpoint. After it succeeds, you should see the model in the custom model list. It also appears alongside built-in providers when you select a model for evaluations, optimization or other features.

## Find a configured provider

Use the filter buttons to narrow the view:

| Filter | What it shows |
| --- | --- |
| **All Providers** | All configured providers |
| **Default Model Providers** | Standard providers, including OpenAI and Anthropic |
| **Cloud Providers** | Cloud-hosted providers, including AWS Bedrock and Azure OpenAI |
| **Custom Models** | Your custom endpoints |

The platform SDK’s [provider key listing](/docs/sdk/reference/provider-keys) returns the organization’s configured provider keys with their values masked. Use it to inspect the configuration from code.

## Troubleshooting

**The test request returns `404 Not Found`.** Check whether the URL ends at `/v1` instead of the chat-completions path. Check that the endpoint serves the exact **Model Name** you entered. Then select **Add Custom model** again and look for the model in the custom model list.
