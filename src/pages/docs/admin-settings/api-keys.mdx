## About

API keys authenticate your application with Future AGI. Each key pair consists of an API Key (`FI_API_KEY`) and a Secret Key (`FI_SECRET_KEY`). You need these for every way into the platform: the Python and TypeScript SDKs, the Java and C# SDKs, any OpenTelemetry based instrumentation, and the REST API.

Access: **Owner**, **Admin**, and **Workspace Admin**. For everyone else the Keys page is not in the sidebar, and its address returns a 404. See [Roles & Permissions](/docs/roles-and-permissions).

Every organization is created with one key already in the list, named `system_org_key`.

<Warning>
**A key belongs to the workspace you have open when you create it.** Traces sent with it land there, and **Build > Keys** only ever lists the keys of your current workspace. The dialog says none of this and offers no workspace to pick, so switch to the workspace you want the key for before you create it.

If the page says *No keys has been added yet* and you know you made one, you are standing in a different workspace. Switch and look again.
</Warning>

That workspace binding is firm for traces and only for traces. Other API and SDK calls made with the same key can name a different workspace on the request, and it is honoured for any workspace in the same organization the caller has access to. If you are separating teams, the key's workspace is not the thing keeping them apart. See [Roles & Permissions](/docs/roles-and-permissions).

## How to

<Steps>
  <Step title="Open the Keys page">
    In the left sidebar, find the **Build** section and click **Keys**, or go straight to [https://app.futureagi.com/dashboard/keys](https://app.futureagi.com/dashboard/keys).
  </Step>
  <Step title="Check which workspace you are in">
    The switcher at the top of the sidebar shows it. The key you are about to make belongs to whichever workspace that is.
  </Step>
  <Step title="Create a new key">
    Click **Add API Key**. The dialog asks for a name and nothing else.
  </Step>
  <Step title="Copy your keys">
    You are shown an API Key and a Secret Key. Both stay masked on screen, so take each one with its copy button and store it before you close the dialog. This dialog does not come back, and there is no way to reveal a secret later. If you are creating the key for somebody else, send them both values now.
  </Step>
  <Step title="Use in your application">
    Set them as environment variables.

    ```python
    import os
    os.environ["FI_API_KEY"] = "YOUR_API_KEY"
    os.environ["FI_SECRET_KEY"] = "YOUR_SECRET_KEY"
    ```

    ```typescript
    process.env.FI_API_KEY = "YOUR_API_KEY";
    process.env.FI_SECRET_KEY = "YOUR_SECRET_KEY";
    ```
  </Step>
</Steps>

## Managing keys

The table lists each key with its name, a masked API Key and Secret Key, who created it, and when. Every row carries a menu with two actions.

| Action | What it does | Who |
|--------|-----|-----|
| Disable Key | Turns off the API Key and the Secret Key together. The row gains a **Disabled** badge, and the menu changes to **Re-enable key**. This is reversible | Owner, Admin, Workspace Admin |
| Delete Key | Removes the API Key and the Secret Key permanently. It cannot be undone | Owner only |

Both actions ask you to confirm first.

<Warning>
**Delete Key** appears for everyone who can open this page, but only an Owner's goes through. An Admin or a Workspace Admin gets the confirmation and then **You are not authorized to access this resource**, and the key stays in the list.
</Warning>

<Tip>
**To rotate a key:** create the replacement, update your application, then **disable** the old key rather than deleting it. If something you forgot about was still using it, re-enable takes one click. Disabling is also the part you can do yourself without being an Owner.
</Tip>

<Warning>
Disabling or deleting a key immediately revokes access for any application using it. Update your code first.
</Warning>

<Tip>
Never commit API keys to version control. Use environment variables or a secret manager.
</Tip>

## Gateway keys are separate

The keys on this page are platform API keys. The Agent Command Center has its own keys under **Gateway > API Keys**, and those are reachable by anyone in the organization. See [Roles & Permissions](/docs/roles-and-permissions) for the difference.
