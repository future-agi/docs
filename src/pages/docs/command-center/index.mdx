## About

Agent Command Center is Future AGI's AI gateway. It sits between your application and LLM providers, giving you a single API that handles routing across your providers, safety guardrails, cost tracking, and full observability, plus response caching on a self-hosted gateway.

<Note>
**Already using the OpenAI SDK?** Just change `base_url` to `https://gateway.futureagi.com` and swap your API key. No other code changes needed. Switch between the providers you have connected by changing the model name.
</Note>

## Quick look

<CodeGroup>

```python Python
from openai import OpenAI

client = OpenAI(
    base_url="https://gateway.futureagi.com/v1",
    api_key="sk-agentcc-your-api-key-here"
)

response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "What is the capital of France?"}]
)
print(response.choices[0].message.content)
```

```typescript TypeScript
import OpenAI from 'openai';

const client = new OpenAI({
    baseURL: 'https://gateway.futureagi.com/v1',
    apiKey: 'sk-agentcc-your-api-key-here'
});

const response = await client.chat.completions.create({
    model: 'gpt-4o-mini',
    messages: [{ role: 'user', content: 'What is the capital of France?' }]
});
console.log(response.choices[0].message.content);
```

```bash cURL
curl -X POST https://gateway.futureagi.com/v1/chat/completions \
  -H "Authorization: Bearer sk-agentcc-your-api-key-here" \
  -H "Content-Type: application/json" \
  -d '{"model": "gpt-4o-mini", "messages": [{"role": "user", "content": "What is the capital of France?"}]}'
```

## Supported providers

Command Center speaks six provider APIs natively: OpenAI, Anthropic, Google Gemini (including Vertex AI), AWS Bedrock, Azure OpenAI, and Cohere. Requests to providers with a different native API (Anthropic, Gemini, Bedrock, Cohere) are translated from the OpenAI format, so your code stays the same whichever provider handles the request. Any other endpoint that implements the OpenAI API, hosted or self-hosted, connects with its base URL.

In the dashboard, **Add Provider** has presets for OpenAI, Anthropic, Google Gemini, Google Vertex AI, Azure OpenAI, Cohere, AWS Bedrock, Groq, Together AI, Fireworks AI, Mistral AI, and OpenRouter, and **Custom / Self-hosted** for any other OpenAI-compatible endpoint.

| Provider | Type | How it connects |
|----------|------|-----------------|
| OpenAI | Cloud API | Native API |
| Anthropic | Cloud API | Native API |
| Google Gemini | Cloud API | Native API |
| AWS Bedrock | Cloud API | Native API |
| Azure OpenAI | Cloud API | Native API |
| Cohere | Cloud API | Native API |
| Groq, Together AI, Fireworks | Cloud API | OpenAI-compatible base URL |
| Mistral AI, DeepInfra, Perplexity | Cloud API | OpenAI-compatible base URL |
| Cerebras, xAI, OpenRouter | Cloud API | OpenAI-compatible base URL |
| Ollama, vLLM, LM Studio, TGI | Self-hosted | OpenAI-compatible base URL |

See [Manage Providers](/docs/command-center/features/providers) for the full list and configuration details.

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Do I need to change my code?">
    No. If you use the OpenAI SDK, just change `base_url` and `api_key`. All providers work through the same OpenAI-format API.
  </Accordion>
  <Accordion title="Which providers are supported?">
    OpenAI, Anthropic, Google Gemini and Vertex AI, AWS Bedrock, Azure OpenAI, and Cohere through their own APIs, and any endpoint that implements the OpenAI API, such as Groq, Mistral AI, Together AI, Fireworks AI, OpenRouter, or a self-hosted server like Ollama, vLLM, or LM Studio.
  </Accordion>
  <Accordion title="What happens if a provider goes down?">
    With provider failover turned on, a chat completion that fails with one of the failover status codes moves to another of your providers that serves the same model. Retries, circuit breakers, and per-model fallback chains are set in your organization's routing settings. See <a href="/docs/command-center/features/routing">Routing</a>.
  </Accordion>
  <Accordion title="Is my data stored?">
    On Future AGI's hosted gateway, yes. Every request to the [model endpoints](/docs/command-center/concepts/core#about) is logged, and by default the request log keeps the request and response bodies (content mode `full`).

    To keep less, set the content mode to `metadata` (no request or response bodies and no request headers) or `none` (as `metadata`, and also no error text, no guardrail messages, and none of your own metadata keys). Set it per organization (`privacy.content_mode` in the org config), per API key (the key's `log_content` field), or per request (the `x-agentcc-log-content` header). The most restrictive setting applies. These settings are made through the API, not in the dashboard.

    Requests are still logged and billed in every mode. The content mode covers the request log only: it does not change what is sent to the provider, and it is not a zero-data-retention mode.

    A self-hosted gateway keeps bodies in its request log only when `logging.request_logging.include_bodies` is `true` in its config file (it is `false` unless you set it) and the content mode is `full`. The response cache is off on the hosted gateway.
  </Accordion>
  <Accordion title="What's the latency overhead?">
    Overhead depends on the features you turn on: guardrails add more than simple routing.
  </Accordion>
  <Accordion title="Can I self-host Agent Command Center?">
    Yes. Command Center is distributed as a Go binary and Docker image. See the <a href="/docs/command-center/deployment/self-hosted">Self-Hosted Deployment</a> guide.
  </Accordion>
</AccordionGroup>
