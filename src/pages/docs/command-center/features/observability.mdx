## About

Agent Command Center logs every request and response, exports metrics to Prometheus, can export OpenTelemetry traces from self-hosted gateways, and propagates trace IDs for distributed tracing. No additional setup needed for basic logging - it's on by default.

---

## Request logging

Every request through Agent Command Center is logged with:

- Request ID, trace ID, session ID
- Model requested and model actually used
- Provider that handled the request
- Input/output token counts
- Cost
- Latency
- Cache status (hit/miss/skip)
- Guardrail results
- Any errors or fallback events

Logs sync to the Future AGI dashboard automatically. View them in **Agent Command Center > Logs**.

### Log levels

| Level | What's logged |
|---|---|
| `error` | Failed requests, provider errors, guardrail blocks |
| `warn` | Fallbacks, slow requests, budget warnings |
| `info` | Every request (default) |
| `debug` | Full request/response bodies, header details |

For self-hosted deployments, set the log level in `config.yaml`:

```yaml
logging:
  level: info
```

## Distributed tracing

Agent Command Center propagates trace IDs across the request lifecycle. Set `x-agentcc-trace-id` on incoming requests and the same ID appears in all downstream provider calls and logs.

<Tabs items={["Agent Command Center SDK", "OpenAI SDK", "cURL"]}>

<Tab title="Python (Agent Command Center SDK)">

```python
response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Hello"}],
    trace_id="trace-from-my-app-abc123",
    user_id="user-42",
)

print(response.agentcc.trace_id)    # trace-from-my-app-abc123
print(response.agentcc.provider)    # openai
print(response.agentcc.latency_ms)  # 342
print(response.agentcc.cost)        # 0.00015
```

</Tab>

<Tab title="Python (OpenAI SDK)">

```python
raw = client.chat.completions.with_raw_response.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Hello"}],
    extra_headers={
        "x-agentcc-trace-id": "trace-from-my-app-abc123",
        "x-agentcc-user-id": "user-42",
    },
)
print(raw.headers.get("x-agentcc-trace-id"))
print(raw.headers.get("x-agentcc-cost"))
```

</Tab>

<Tab title="cURL">

```bash
curl -i https://gateway.futureagi.com/v1/chat/completions \
  -H "Authorization: Bearer sk-agentcc-your-key" \
  -H "x-agentcc-trace-id: trace-from-my-app-abc123" \
  -H "x-agentcc-user-id: user-42" \
  -H "Content-Type: application/json" \
  -d '{"model": "gpt-4o", "messages": [{"role": "user", "content": "Hello"}]}'
# Look for x-agentcc-trace-id in response headers
```

</Tab>

</Tabs>

If you don't set a trace ID, Agent Command Center generates one automatically. Use it for correlating gateway logs with your application logs.

### OpenTelemetry export

Self-hosted gateways can also emit one OpenTelemetry span per request (model, provider, latency, token counts, cost, cache status and caller metadata, named with the `gen_ai.*` semantic conventions) to any OTLP-compatible backend. This is separate from the request log above: request logs always go to **Agent Command Center > Logs**, while spans are only exported when you turn on the `otel` block in the gateway's `config.yaml`. It is off by default.

```yaml
otel:
  enabled: true
  exporter: otlp                         # default is stdout: spans go to the gateway's own output
  endpoint: "http://otel-collector:4318" # /v1/traces is appended when the URL has no path
  protocol: "http/protobuf"              # the only supported transport
  service_name: "agentcc-gateway"
  headers:                               # sent on every export request
    Authorization: "Bearer ${OTEL_TOKEN}"
```

<Warning>
The gateway speaks OTLP over **HTTP with protobuf** only, so point it at your collector's OTLP/HTTP port (usually **4318**), not the gRPC port 4317. With `exporter: otlp`, `protocol: grpc` and `protocol: http/json` stop the gateway at startup. Setting `enabled: true` without `exporter: otlp` prints spans to stdout instead of exporting them.
</Warning>

When `exporter` is `otlp`, the gateway refuses to start with no `endpoint`, an endpoint that is not an absolute `http(s)` URL, or a header whose value is empty (usually a `${VAR}` that is not set). Spans are queued and sent in the background, so a slow or unreachable collector never adds latency to a request. Each span carries the gateway's trace ID as `agentcc.trace_id`, so you can match it to its row in the request log.

| Key | Default | Description |
|---|---|---|
| `enabled` | `false` | Turns span creation on |
| `exporter` | `stdout` | `stdout` or `otlp` |
| `endpoint` | none | Collector base URL; required for `otlp` |
| `protocol` | `http/protobuf` | The only supported value |
| `headers` | none | Headers sent with every export, for collector authentication. Use `${VAR}` to keep credentials out of the file |
| `service_name` | `agentcc-gateway` | `service.name` resource attribute |
| `sample_rate` | `1.0` | Fraction of requests that get a span. `0` or unset means every request |
| `attributes` | none | Extra OTLP resource attributes |
| `include_bodies` | `false` | Attach the prompt and completion (`input.value` / `output.value`). Redacted with the organization's privacy settings, like the request log |
| `trace_propagation` | `false` | Honor an inbound W3C `traceparent` so the gateway span nests under the caller's span |
| `metadata_attributes` | `true` | Also emit each caller metadata key as `agentcc.metadata.<key>` |
| `body_attributes` | `true` | Emit unknown scalar request-body fields as `agentcc.body.<key>` |
| `capture_headers` | none | Allowlist of request headers to copy onto the span; credential headers are never copied |

### Send gateway spans to self-hosted Observe

When you self-host Future AGI alongside the gateway, point the `otel` block at your install's `fi-collector` to see gateway spans in Observe. In Docker Compose the gateway reads the config file named by `AGENTCC_CONFIG_PATH` in `.env` (default `agentcc-gateway/config.example.yaml`); with Helm, set the block under `agentccGateway.config.otel`.

```yaml
otel:
  enabled: true
  exporter: otlp
  endpoint: "http://127.0.0.1:4318"   # see the table below for your setup
  protocol: "http/protobuf"
  headers:
    X-Api-Key: "${FI_API_KEY}"
    X-Secret-Key: "${FI_SECRET_KEY}"
  attributes:
    project_name: "my-chatbot"        # Observe project the spans land in
    project_type: "observe"
  include_bodies: false               # decide deliberately; see below
  trace_propagation: true             # only if your app sends traceAI spans to the same project
```

1. **Endpoint.** `fi-collector` takes OTLP/HTTP on port 4318. Use the address the gateway can reach it on:

   | Setup | `endpoint` |
   |---|---|
   | Standalone (`docker-compose.yml`), where the gateway runs in the same `app` container as the collector | `http://127.0.0.1:4318` |
   | Distributed (`docker-compose.distributed.yml`) | `http://fi-collector:4318` |
   | Helm | `http://<fullname>-fi-collector:4318`. `<fullname>` is the release name when it contains `futureagi` (for example `futureagi-fi-collector`), otherwise `<release>-futureagi`; `kubectl get svc` shows the name |

2. **Credentials.** The collector rejects spans without an `X-Api-Key` and `X-Secret-Key` pair. Create one in your install under **Build → Keys** and give it to the gateway as `FI_API_KEY` and `FI_SECRET_KEY`: in `.env` for either Compose setup, or in `agentccGateway.extraEnv` with Helm. If a variable is unset, the gateway refuses to start rather than send unauthenticated spans.

3. **Project.** The collector files spans by the `project_name` resource attribute and rejects the whole export request (HTTP 400) if it is missing. If the project doesn't exist yet, it is created as an Observe project on first use. Set `project_type: "observe"` next to it.

4. **Prompt and completion bodies.** `include_bodies` is off by default, so spans carry metrics and metadata but not message content. Turning it on sends prompts and completions to Observe, redacted with the organization's privacy settings. Decide this separately from `logging.request_logging.include_bodies`.

5. **Nesting under traceAI spans.** If your application is instrumented with traceAI, set `trace_propagation: true` and use the same `project_name` as the application. The gateway then adopts the trace ID from the inbound W3C `traceparent` header and becomes a child of the caller's span, instead of starting a second root trace. Only a `traceparent` marked as sampled is honored. Leave it off if the caller's spans go somewhere else: the gateway span would point at a parent that Observe never receives.

## Metrics

Agent Command Center exports Prometheus metrics on the `/-/metrics` endpoint.

### Available metrics

| Metric | Type | Description |
|---|---|---|
| `agentcc_requests_total` | Counter | Total requests by model, provider, status code |
| `agentcc_request_duration_seconds` | Histogram | Request latency distribution |
| `agentcc_tokens_total` | Counter | Total tokens (input + output) by model |
| `agentcc_cost_total` | Counter | Total cost in USD by model and provider |
| `agentcc_cache_hits_total` | Counter | Cache hits by strategy (exact/semantic) |
| `agentcc_cache_misses_total` | Counter | Cache misses |
| `agentcc_provider_errors_total` | Counter | Provider errors by provider and error code |
| `agentcc_circuit_breaker_state` | Gauge | Circuit breaker state (0=closed, 1=open, 2=half-open) |
| `agentcc_rate_limit_exceeded_total` | Counter | Rate limit rejections by key |
| `agentcc_guardrail_triggered_total` | Counter | Guardrail triggers by guardrail name and action |

### Scrape configuration

```yaml
# prometheus.yml
scrape_configs:
  - job_name: "agentcc-gateway"
    scrape_interval: 15s
    metrics_path: "/-/metrics"
    static_configs:
      - targets: ["agentcc-gateway:8080"]
```

### Self-hosted metrics config

```yaml
telemetry:
  metrics:
    enabled: true
    prometheus:
      enabled: true
      path: "/-/metrics"
```

## Session tracking

Group related requests into sessions for conversation-level analytics. Set `x-agentcc-session-id` on each request in a conversation:

```python
session_id = "user-123-conversation-456"
messages = []

# Each turn in the conversation shares the same session_id
messages.append({"role": "user", "content": "What's the capital of France?"})
response = client.chat.completions.create(
    model="gpt-4o",
    messages=messages,
    session_id=session_id,
    user_id="user-123",
)
messages.append({"role": "assistant", "content": response.choices[0].message.content})

messages.append({"role": "user", "content": "What's its population?"})
response = client.chat.completions.create(
    model="gpt-4o",
    messages=messages,
    session_id=session_id,
    user_id="user-123",
)
```

Sessions appear in the dashboard under **Agent Command Center > Sessions** and show:
- Total requests in the session
- Cumulative cost
- Models and providers used
- Timeline of requests

## Alerting

Configure alerts to get notified about issues. See [Cost tracking > Budget alerts](/docs/command-center/features/cost-tracking#budget-alerts) for alert configuration.

| Event | When it fires |
|---|---|
| Budget threshold crossed | Spend exceeds configured percentage |
| Error rate spike | Error rate exceeds threshold over a time window |
| Latency spike | P95 latency exceeds threshold |
| Guardrail triggered | A guardrail blocks or flags a request |
