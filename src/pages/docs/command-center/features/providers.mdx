title: "Connect a provider to Agent Command Center"

When one application has to call models from several vendors, you don't want a separate client and key for each. Agent Command Center supports 20+ cloud and self-hosted LLM providers through a unified OpenAI-compatible API. Add a provider once with its API key, then switch between providers by changing the model name in your request. The provider header on the reply tells you which one handled the call.

<Prerequisites title="Before you start">
- Use an [organization Owner or Admin account](/docs/command-center/admin/organizations) to manage providers.
- Have credentials for the upstream provider and access to the model you want to serve. The provider API key is stored in the organization's configuration.
- Have a gateway [virtual key](/docs/command-center/concepts/virtual-keys) that is allowed to call that provider and model. Your application sends this key, not the upstream credential.
- For a self-hosted server, have an OpenAI-compatible base URL that Agent Command Center can reach.
</Prerequisites>

## Add a cloud provider

1. Open **Gateway > Providers** in the Future AGI dashboard.
2. Select **Add Provider**.
3. Select the provider from the list.
4. Enter your API key and any required settings.

   The [format table](#choose-a-provider-format) lists what each provider needs, such as an AWS region for Bedrock or `api_version` for Azure OpenAI.

5. Select **Save**.

<Warning>
Provider API keys are stored encrypted and never exposed in API responses.
</Warning>

### Add a provider from code

<Tabs items={["Python (Agent Command Center SDK)", "TypeScript (Agent Command Center SDK)"]}>

<Tab title="Python (Agent Command Center SDK)">

```python
from agentcc import AgentCC

client = AgentCC(
    api_key="sk-agentcc-your-key",
    base_url="https://gateway.futureagi.com",
    control_plane_url="https://api.futureagi.com",
)

client.org_configs.create(
    org_id="your-org-id",
    config={
        "providers": {
            "openai": {
                "api_key": "sk-your-openai-key",
                "api_format": "openai",
                "models": ["gpt-4o", "gpt-4o-mini"],
            },
            "anthropic": {
                "api_key": "sk-ant-your-key",
                "api_format": "anthropic",
            },
        }
    }
)
```

</Tab>

## Add a self-hosted provider

Connect models running on your own infrastructure.

1. Open **Gateway > Providers**.
2. Select **Add Provider**.
3. For **Provider**, select **Custom / Self-hosted**.
4. Enter your model server's endpoint URL as the **Base URL**.
5. Enter an API key.

   For a server that checks no key, such as Ollama or a vLLM server started without one, enter any placeholder, such as `ollama`.

6. Select the models from the list the dialog fetches.
7. Select **Add Provider**.

Ollama, vLLM, LM Studio, HuggingFace TGI, LocalAI and any other server that implements the OpenAI API connect the same way: set `api_format: "openai"` and point `base_url` at the server. Agent Command Center has no preset for these servers, so a `type` value such as `ollama` or `vllm` has no effect. In the gateway's `config.yaml`, a provider without a `models` list gets its models from the server's `/v1/models` endpoint when the gateway starts. [Self-hosted models](/docs/command-center/features/self-hosted-models) has configuration examples.

<Note>
Your self-hosted endpoint must be reachable from the Agent Command Center. Use a tunnel (ngrok, Cloudflare Tunnel), a cloud VM with a public IP, or deploy behind a reverse proxy.

On a self-hosted Future AGI install, a provider you add in the dashboard can use a private or LAN address, such as `http://host.docker.internal:11434/v1` for Ollama on the Docker host, only after you set `AGENTCC_ALLOW_PRIVATE_PROVIDER_URLS=true`. Loopback addresses such as `localhost` are never allowed. See [Private and local provider URLs](/docs/command-center/features/self-hosted-models#private-and-local-provider-urls).
</Note>

### Add a self-hosted provider from code

<Tabs items={["Python (Agent Command Center SDK)", "TypeScript (Agent Command Center SDK)"]}>

```python
from agentcc import AgentCC

client = AgentCC(
    api_key="sk-agentcc-your-key",

                "api_key": "your-vllm-api-key",
                "models": ["meta-llama/Llama-3.1-8B-Instruct"],
            },
        }
    }
)
```

## Check which provider answers

Change the model name to route to a different provider. Same code, same API, different LLM.

1. Send a request for a configured model with your gateway key.

   Use one of the clients below. The examples call a model from each of several providers, so run the calls your configured providers can serve.

<Tabs items={["Python (Agent Command Center SDK)", "Python (OpenAI SDK)", "LiteLLM", "cURL"]}>

<Tab title="Python (Agent Command Center SDK)">

```python
from agentcc import AgentCC

client = AgentCC(
    api_key="sk-agentcc-your-key",
    base_url="https://gateway.futureagi.com",
)

# OpenAI
response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Hello"}]
)

# Anthropic - same code, different model
response = client.chat.completions.create(
    model="claude-sonnet-4-6",
    messages=[{"role": "user", "content": "Hello"}]
)

# Google Gemini
response = client.chat.completions.create(
    model="gemini-2.0-flash",
    messages=[{"role": "user", "content": "Hello"}]
)
```

</Tab>

<Tab title="Python (OpenAI SDK)">

```python
from openai import OpenAI

# Works with the OpenAI SDK - just swap base_url and api_key
client = OpenAI(
    base_url="https://gateway.futureagi.com/v1",
    api_key="sk-agentcc-your-key",
)

response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Hello"}]
)
```

</Tab>

<Tab title="LiteLLM">

```python
import litellm

response = litellm.completion(
    model="openai/gpt-4o",
    messages=[{"role": "user", "content": "Hello"}],
    api_key="sk-agentcc-your-key",
    base_url="https://gateway.futureagi.com/v1",
)
```

</Tab>

<Tab title="cURL">

```bash
curl -X POST https://gateway.futureagi.com/v1/chat/completions \
  -H "Authorization: Bearer sk-agentcc-your-key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-4o",
    "messages": [{"role": "user", "content": "Hello"}]
  }'
```

</Tab>

</Tabs>

2. Inspect the [response headers](/docs/command-center/api/headers).

   You should see the serving provider in `x-agentcc-provider` and the model it used in `x-agentcc-model-used`.

3. Request a model from a second configured provider with the same gateway key.

   Compare the provider headers from the two calls, not just the reply text.

## Choose a provider format

<div class="sdk-ref-table">

| Provider | Type | `api_format` | Auth | Notes |
|---|---|---|---|---|
| OpenAI | `openai` | `openai` | API key | Native format |
| Anthropic | `anthropic` | `anthropic` | API key | Auto-translated to OpenAI format |
| Google Gemini | `gemini` | `gemini` | API key | Auto-translated to OpenAI format |
| Google Vertex AI | `vertexai` | `gemini` | Bearer token | Uses GCP project/location headers |
| AWS Bedrock | `bedrock` | `bedrock` | SigV4 | Requires AWS region, cross-region failover supported |
| Azure OpenAI | `azure` | `azure` | API key | Requires `api_version`, supports Azure AD bearer auth |
| Cohere | `cohere` | `cohere` | API key | Auto-translated to OpenAI format |
| Groq | `groq` | `openai` | API key | OpenAI-compatible |
| Mistral AI | `mistral` | `openai` | API key | OpenAI-compatible |
| Together AI | `together` | `openai` | API key | OpenAI-compatible |
| Fireworks AI | `fireworks` | `openai` | API key | OpenAI-compatible |
| DeepInfra | `deepinfra` | `openai` | API key | OpenAI-compatible |
| Perplexity | `perplexity` | `openai` | API key | OpenAI-compatible |
| Cerebras | `cerebras` | `openai` | API key | OpenAI-compatible |
| xAI (Grok) | `xai` | `openai` | API key | OpenAI-compatible |
| OpenRouter | `openrouter` | `openai` | API key | OpenAI-compatible |
| Hugging Face | `huggingface` | `openai` | API key | Inference API |
| Anyscale | `anyscale` | `openai` | API key | OpenAI-compatible |
| Replicate | `replicate` | `openai` | API key | OpenAI-compatible |

</div>

In the gateway's `config.yaml`, a `type` field has no effect: every provider needs its own `base_url` and `api_format`.

Providers marked "OpenAI-compatible" use the same wire format as OpenAI. No translation needed. Providers with native formats (Anthropic, Gemini, Bedrock, Cohere) are automatically translated by Agent Command Center, so your code stays identical regardless of which provider handles the request.

<Tip>
Agent Command Center supports all models from each provider, including new releases. Use any model name your provider supports.
</Tip>

## Provider health

Agent Command Center monitors provider health automatically. It tracks response times, error rates, and availability. When a provider becomes unhealthy:

1. The circuit breaker opens to stop sending requests to the failing provider
2. Traffic fails over to healthy alternatives
3. After a cooldown period, Agent Command Center sends probe requests to check recovery
4. Once the provider responds successfully, it's added back to the rotation

See [Failover and circuit breaking](/docs/command-center/features/routing) for configuration details.

## If a model is missing

- **The model is not listed:** call `GET /v1/models` with the gateway key you plan to use. Available models depend on which providers are configured for your organization.
- **The model is listed but the call returns `model_not_found`:** try the explicit `provider/model` name. If that works, set up a [model map](/docs/command-center/concepts/configuration#model-mapping). [Error handling](/docs/command-center/guides/errors) lists the other causes.
