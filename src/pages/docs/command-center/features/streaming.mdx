Stream a [chat completion](/docs/command-center/api/chat) when your user should see the first words before the model finishes. With Server-Sent Events (SSE), the server pushes data to the client incrementally as it becomes available, rather than waiting for a complete response.

Set `"stream": true` and Agent Command Center returns response chunks in the OpenAI streaming format. It works across all providers: the gateway translates each provider's native streaming format to standard OpenAI SSE.

<Prerequisites title="Before you start">
- A [gateway key](/docs/command-center/concepts/virtual-keys) authorized for the model, and a [configured provider](/docs/command-center/features/providers).
- cURL, or a Python or TypeScript client for the examples. Keep the gateway key in `AGENTCC_API_KEY` rather than saving a real key in source; the literal in each snippet is a placeholder. The [gateway client setup](/docs/get-started/route-your-first-llm-request) shows how to read the variable explicitly.
</Prerequisites>

## When to use

- **Real-time chat interfaces**: Display tokens as they arrive for responsive user experience
- **Long-form generation**: Stream articles, reports, or code without waiting for the full response
- **Voice and TTS pipelines**: Feed tokens to downstream processors incrementally

## Read the response as it arrives

<Steps>
  <Step title="Enable streaming in your request">
    Set `"stream": true` in your request payload to the Agent Command Center.
  </Step>
  <Step title="Handle SSE events">
    Connect to the streaming endpoint and process incoming SSE events as they arrive.
  </Step>
  <Step title="Parse completion chunks">
    Each event carries a delta. Append each nonempty content delta in order to reconstruct the full response. Not every event contains text.
  </Step>
</Steps>

## Try a streaming request

The following diagrams illustrate the difference between blocking (non-streaming) and streaming responses:

**Blocking (non-streaming) request:**

![Blocking request flow: client waits for complete response](/screenshot/product/command-center/blocking-flow.gif)

In a blocking request, the client sends a request and waits for the entire response to be generated before receiving any data.

**Streaming request:**

![Streaming request flow: client receives tokens incrementally](/screenshot/product/command-center/streaming-flow.gif)

In a streaming request, the client receives tokens as they are generated, enabling real-time display of the response.

Each example below sends the same request with `stream` set to true:

<Tabs>
  <Tab title="cURL">
```bash
curl https://gateway.futureagi.com/v1/chat/completions \
  -H "Authorization: Bearer sk-agentcc-your-key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-4o-mini",
    "messages": [
      {"role": "user", "content": "Write a short poem"}
    ],
    "stream": true
  }'
```
  </Tab>
  <Tab title="Python">
```python
from agentcc import AgentCC

client = AgentCC(
    api_key="sk-agentcc-your-key",
    base_url="https://gateway.futureagi.com"
)

stream = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[
        {"role": "user", "content": "Write a short poem"}
    ],
    stream=True
)

for chunk in stream:
    if chunk.choices and chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end="", flush=True)
```
  </Tab>
  <Tab title="TypeScript">
```typescript
import { AgentCC } from '@agentcc/client';

const client = new AgentCC({
  apiKey: 'sk-agentcc-your-key',
  baseUrl: 'https://gateway.futureagi.com'
});

const stream = await client.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [
    { role: 'user', content: 'Write a short poem' }
  ],
  stream: true
});

for await (const chunk of stream) {
  if (chunk.choices[0]?.delta?.content) {
    process.stdout.write(chunk.choices[0].delta.content);
  }
}
```
  </Tab>
</Tabs>

You should see some reply text before the stream ends. If the entire reply appears at once, check whether your client waits until the loop finishes before it prints.

## Get the full completion with the Stream Manager

The Stream Manager provides a managed context for streaming with automatic resource cleanup and access to the full completion after streaming completes. The examples print total tokens only when `completion.usage` is present; a missing total is not a count of zero.

<Tabs>
  <Tab title="Python">
```python
from agentcc import AgentCC

client = AgentCC(
    api_key="sk-agentcc-your-key",
    base_url="https://gateway.futureagi.com"
)

with client.chat.completions.stream(
    model="gpt-4o-mini",
    messages=[
        {"role": "user", "content": "Explain quantum computing"}
    ]
) as stream:
    for text in stream.text_stream:
        print(text, end="", flush=True)
    
    # Access full completion after streaming
    completion = stream.get_final_completion()
    if completion.usage:
        print(f"\nTotal tokens: {completion.usage.total_tokens}")
```
  </Tab>
  <Tab title="TypeScript">
```typescript
import { AgentCC } from '@agentcc/client';

const client = new AgentCC({
  apiKey: 'sk-agentcc-your-key',
  baseUrl: 'https://gateway.futureagi.com'
});

const stream = await client.chat.completions.stream({
  model: 'gpt-4o-mini',
  messages: [
    { role: 'user', content: 'Explain quantum computing' }
  ]
});

for await (const chunk of stream) {
  if (chunk.choices[0]?.delta?.content) {
    process.stdout.write(chunk.choices[0].delta.content);
  }
}

const completion = stream.getFinalCompletion();
if (completion.usage) console.log(`Total tokens: ${completion.usage.total_tokens}`);
```
  </Tab>
</Tabs>

## SSE Format

Streaming responses follow the standard OpenAI SSE format. This illustration shows two content deltas followed by the end marker; it is not a capture of the requests above:

```
data: {"id":"chatcmpl-123","object":"chat.completion.chunk","created":1234567890,"model":"gpt-4o-mini","choices":[{"index":0,"delta":{"role":"assistant","content":"Hello"},"finish_reason":null}]}

data: {"id":"chatcmpl-123","object":"chat.completion.chunk","created":1234567890,"model":"gpt-4o-mini","choices":[{"index":0,"delta":{"content":" world"},"finish_reason":null}]}

data: [DONE]
```

Each event contains a delta with the next token or function call. Append `Hello` and ` world` to get `Hello world`. The stream ends with a `[DONE]` message, which is not part of the reply.

## Streaming with Guardrails

Post-processing guardrails run after the response text has been sent, just before the closing `[DONE]`, so they cannot stop or change the stream, and a slow check delays `[DONE]`. A block or warning is recorded in the request log. A self-hosted gateway can also check the stream while it is generated and stop it. See [Streaming Guardrails](/docs/command-center/features/guardrails#streaming-guardrails).

<Note>Pre-processing guardrails run before streaming begins. If they trigger in Enforce mode, the stream never starts.</Note>

## Streaming with Caching

Streaming requests bypass [response caching](/docs/command-center/features/caching) entirely. Each streaming request goes directly to the provider, ensuring real-time responses.

## Cross-Provider Streaming

Agent Command Center translates streaming from all providers to the standard OpenAI SSE format:

- **Anthropic**: Converts Claude's streaming format to OpenAI chunks
- **Gemini**: Translates Google's streaming protocol to SSE
- **Bedrock**: Adapts AWS Bedrock streaming to OpenAI format

Your application reads the same SSE event format regardless of the underlying provider.
