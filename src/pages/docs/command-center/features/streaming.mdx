## About

Agent Command Center supports full Server-Sent Events (SSE) streaming, a standard protocol where the server pushes data to the client incrementally as it becomes available, rather than waiting for a complete response. This is identical to the OpenAI streaming format. Set `"stream": true` and receive response chunks as the provider sends them. Works across all providers. Agent Command Center translates each provider's native streaming format to standard OpenAI SSE format.

---

## When to use

- **Chat interfaces**: Display tokens as they arrive
- **Long-form generation**: Stream articles, reports, or code without waiting for the full response
- **Voice and TTS pipelines**: Feed tokens to downstream processors incrementally

---

## How to

<Steps>
  <Step title="Enable streaming in your request">
    Set `"stream": true` in your request payload to the Agent Command Center.
  </Step>
  <Step title="Handle SSE events">
    Connect to the streaming endpoint and process incoming SSE events as they arrive.
  </Step>
  <Step title="Parse completion chunks">
    Each event contains a delta with the next token. Accumulate deltas to reconstruct the full response.
  </Step>
</Steps>

## Basic Streaming

The following diagrams illustrate the difference between blocking (non-streaming) and streaming responses:

**Blocking (non-streaming) request:**

![Blocking request flow: client waits for complete response](/screenshot/product/command-center/blocking-flow.gif)

In a blocking request, the client sends a request and waits for the entire response to be generated before receiving any data.

**Streaming request:**

![Streaming request flow: client receives tokens incrementally](/screenshot/product/command-center/streaming-flow.gif)

In a streaming request, the client receives tokens as they are generated, so it can display the response as it arrives.

```python
from agentcc import AgentCC

client = AgentCC(
    api_key="sk-agentcc-your-key",
    base_url="https://gateway.futureagi.com"
)

stream = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[
        {"role": "user", "content": "Write a short poem"}
    ],
    stream=True
)

for chunk in stream:
    if chunk.choices and chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end="", flush=True)
```
  </Tab>
  <Tab title="TypeScript">
```typescript
import { AgentCC } from '@agentcc/client';

const client = new AgentCC({
  apiKey: 'sk-agentcc-your-key',
  baseUrl: 'https://gateway.futureagi.com'
});

const stream = await client.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [
    { role: 'user', content: 'Write a short poem' }
  ],
  stream: true
});

for await (const chunk of stream) {
  const content = chunk.choices[0]?.delta?.content;
  if (content) process.stdout.write(content);
}
```
  </Tab>
</Tabs>

A chunk with an empty `choices` array comes only when you ask for usage or for the gateway's metadata (see [SSE Format](#sse-format)). These loops check `choices` before reading `choices[0]`, so they work either way.

## Stream Manager

The Stream Manager provides a managed context for streaming with automatic resource cleanup and access to the full completion after streaming completes.

<Tabs>
  <Tab title="Python">
```python
from agentcc import AgentCC

client = AgentCC(
    api_key="sk-agentcc-your-key",
    base_url="https://gateway.futureagi.com"
)

with client.chat.completions.stream(
    model="gpt-4o-mini",
    messages=[
        {"role": "user", "content": "Explain quantum computing"}
    ]
) as stream:
    for text in stream.text_stream:
        print(text, end="", flush=True)
    
    # Access full completion after streaming
    completion = stream.get_final_completion()
    if completion.usage:
        print(f"\nTotal tokens: {completion.usage.total_tokens}")
```
  </Tab>
  <Tab title="TypeScript">
```typescript
import { AgentCC } from '@agentcc/client';

const client = new AgentCC({
  apiKey: 'sk-agentcc-your-key',
  baseUrl: 'https://gateway.futureagi.com'
});

const stream = await client.chat.completions.stream({
  model: 'gpt-4o-mini',
  messages: [
    { role: 'user', content: 'Explain quantum computing' }
  ]
});

for await (const text of stream.textStream()) {
  process.stdout.write(text);
}

const completion = stream.getFinalCompletion();
console.log(`Total tokens: ${completion.usage?.total_tokens}`);
```

</Tabs>

## SSE Format

Streaming responses follow the standard OpenAI SSE format:

```
data: {"id":"chatcmpl-123","object":"chat.completion.chunk","created":1234567890,"model":"gpt-4o-mini","choices":[{"index":0,"delta":{"role":"assistant","content":"Hello"},"finish_reason":null}]}

data: {"id":"chatcmpl-123","object":"chat.completion.chunk","created":1234567890,"model":"gpt-4o-mini","choices":[{"index":0,"delta":{"content":" world"},"finish_reason":null}]}

data: {"id":"chatcmpl-123","object":"chat.completion.chunk","created":1234567890,"model":"gpt-4o-mini","choices":[{"index":0,"delta":{},"finish_reason":"stop"}],"usage":{"prompt_tokens":12,"completion_tokens":2,"total_tokens":14}}

data: [DONE]
```

Content events carry text or function-call deltas in `choices`. Usage or metadata events can have an empty `choices` array, so guard access to `choices[0]` as the examples do. A normal stream ends with `[DONE]`; an interrupted stream can end without it.

Request `stream_options.include_usage: true` when you need usage. Read usage only when it is present; do not rely on a fixed finish-chunk or metadata ordering across gateway/provider versions. The published AgentCC stream managers expose accumulated usage through `get_final_completion().usage` in Python and `getFinalCompletion().usage` in TypeScript.

## Streaming with Guardrails

- **Pre-stage checks** run before the stream opens. A block returns HTTP 403 instead of a stream; Warn and Log can add the guardrail-triggered header.
- **Ordinary post-stage checks** run after the response text has been sent. They cannot recall content or change the HTTP status or headers; their outcome is recorded in the request log. Do not rely on a post-stage block as a client-visible stream interruption.
- **Self-hosted in-stream checks** require `guardrails.streaming.enabled: true`. A blocking check during generation sends a `stream_blocked` SSE error and ends without `[DONE]`; a blocking final check sends the error followed by `[DONE]`. Text sent before a check is already visible to the client.

See [Streaming Guardrails](/docs/command-center/features/guardrails#streaming-guardrails) for capture requirements, `check_interval`, asynchronous rules and `failure_action`.

## Streaming with Caching

Streaming requests bypass the cache entirely. Each streaming request goes directly to the provider.

## Cross-Provider Streaming

Agent Command Center translates streaming from all providers to the standard OpenAI SSE format:

- **Anthropic**: Converts Claude's streaming format to OpenAI chunks
- **Gemini**: Translates Google's streaming protocol to SSE
- **Bedrock**: Adapts AWS Bedrock streaming to OpenAI format

Your application receives identical SSE events regardless of the underlying provider.
