Custom Properties let you define a schema of typed metadata fields that are attached to every request log in the Agent Command Center. Once a property is defined, you can tag requests with values for it, then filter, search, and group your [request logs](/docs/command-center/features/observability#request-logging) by those values.

This guide defines a `user_tier` property, sends it with a gateway request, and finds the tagged request in the logs. `user_tier` is an Enum, so clients and log filters use the same set of values.

<Prerequisites title="Before you start">
- Access to **Gateway > Custom Properties**.
- A gateway API key (see [virtual keys](/docs/command-center/concepts/virtual-keys)) that can call the model in the examples.
</Prerequisites>

## Choose what to track

- **Segmentation:** Tag requests with `user_tier`, `feature_name`, or `environment` so you can filter logs by segment.
- **Cost attribution:** Attach a `team` or `cost_center` property to every request for [per-team cost breakdowns](/docs/command-center/features/cost-tracking).
- **Debugging:** Mark requests with a `session_id` or `trace_id` to correlate gateway logs with your own tracing system.

## Create the user-tier property

1. Open **Gateway > Custom Properties**.

   The table shows all defined properties with their name, type, whether they are required, any allowed values (for Enum types), and their default value.

2. Click **+ Create Property**.
3. Enter `user_tier` in **Property Name**.
4. Select `Enum` as the **Type**.
5. Add `enterprise` to the list of allowed values. The requests below send this value.
6. Decide whether to toggle **Required** on.

   For an Enum, requests with values outside the allowed list are rejected if the property is required. Turn it on only if every caller can send an allowed value.

7. Click **Save**.

   You should see `user_tier` in the table with the type and allowed values you chose.

### Property options

| Field | Required | Description |
|-------|----------|-------------|
| **Property Name** | Yes | The key used in request metadata (e.g., `user_tier`) |
| **Description** | Optional | Human-readable label shown in the UI |
| **Type** | Yes | `String`, `Number`, `Boolean`, or `Enum` |
| **Required** | Optional | Toggle on to enforce the property on every request |
| **Default Value** | Optional | Value used when the property is not provided |

For the **Enum** type, you also define the list of allowed values. Requests with values outside this list will be rejected if the property is required.

## Send an allowed value

Pass custom property values as metadata on your request, in the [`x-agentcc-metadata` header](/docs/command-center/api/headers#metadata-and-properties). Both examples set `user_tier` to `enterprise` and add `team` and `environment` values. The key strings are placeholders for your own gateway key.

<Tabs items={["Python (OpenAI SDK)", "cURL"]}>


<Tab title="Python (OpenAI SDK)">

```python
import json
from openai import OpenAI

client = OpenAI(
    base_url="https://gateway.futureagi.com/v1",
    api_key="sk-agentcc-your-key",
)

response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Summarize this document."}],
    extra_headers={
        "x-agentcc-metadata": json.dumps({
            "user_tier": "enterprise",
            "team": "data-science",
            "environment": "production",
        }),
    },
)
```

</Tab>


<Tab title="cURL">

```bash
curl https://gateway.futureagi.com/v1/chat/completions \
  -H "Authorization: Bearer sk-agentcc-your-key" \
  -H "Content-Type: application/json" \
  -H 'x-agentcc-metadata: {"user_tier":"enterprise","team":"data-science","environment":"production"}' \
  -d '{
    "model": "gpt-4o",
    "messages": [{"role": "user", "content": "Summarize this document."}]
  }'
```

</Tab>

</Tabs>

The values appear in the request log and are available for filtering.

## Find the tagged request

1. Open **Agent Command Center > Logs**.
2. Select the request you just sent.

   You should see `user_tier` set to `enterprise` in its metadata.

3. Filter the logs by the `user_tier` key and the value `enterprise`.

   The tagged request should remain in the results.

## Preview the log entry

The **Log Preview** panel on the Custom Properties page shows how property values appear in the raw request log JSON, so you can verify the schema before deploying. The preview is not a live request.

## Troubleshooting

- **A request is rejected.** A required Enum property rejects values outside its allowed list. Compare the value you sent for `user_tier` with the list in **Gateway > Custom Properties**, then resend with an allowed value such as `enterprise`.
- **A successful request is missing the property.** Compare the property name and value in the JSON header with the schema in **Gateway > Custom Properties**. Correct the header, resend, and check the new log row.
