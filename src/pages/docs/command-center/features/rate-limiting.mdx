## About

Rate limiting controls how many requests and tokens each API key can use per minute. Budgets control how much money can be spent per period. Credits give individual keys a prepaid USD balance. All three work together to prevent runaway costs and protect provider quotas.

---

## When to use

- **Prevent abuse**: Cap RPM per key so one user can't monopolize gateway capacity
- **Control spending**: Set monthly budgets per org so teams can't exceed their allocation
- **Reseller billing**: Give each customer key a credit balance that auto-deducts per request
- **Protect provider quotas**: Cap each key's RPM and TPM so no single client drives you into provider rate limits

---

## Rate limiting

Agent Command Center supports rate limits at three levels: gateway, per-org, and per-key.

| Level | Scope | How to set |
|---|---|---|
| **Gateway** | Default for every key on a self-hosted gateway | `rate_limiting.global_rpm` in `config.yaml` |
| **Per-org** | Keys in one organization | Rate Limiting tab of the org config |
| **Per-key** | One API key | `rate_limit_rpm` and `rate_limit_tpm` on the key in `config.yaml` |

Limits don't stack. Each request gets one RPM limit, the first one set in this order: the key's own `rate_limit_rpm`, the org's `per_key_rpm`, the org's `global_rpm`, then the gateway's `global_rpm`. The TPM limit is the key's own `rate_limit_tpm`, then the org's `global_tpm`.

Counters are kept per API key in fixed 60-second windows, so every limit caps each key separately. An org `global_rpm` of 1000 lets each key in the org send 1000 requests a minute; it is not a shared ceiling for the whole org.

### Configuration

<Tabs items={["Dashboard", "Org config JSON"]}>

<Tab title="Dashboard">

1. Go to **Gateway > Settings** and open the **Org Config** tab
2. Click **Edit Config**, or **Create Custom Config** if your organization still uses the defaults
3. Open the **Rate Limiting** tab, turn on **Enable per-org rate limiting**, and set the limits
4. Click **Save & Activate**

The API key dialogs in **Gateway > API Keys** have no RPM or TPM fields. To limit every key in the org, set **RPM per Key**.

</Tab>

<Tab title="Org config JSON">

The Rate Limiting tab saves these keys in the `rate_limiting` section of your org config:

```json
{
  "rate_limiting": {
    "enabled": true,
    "global_rpm": 500,
    "global_tpm": 100000,
    "per_key_rpm": 100
  }
}
```

| Key | Effect |
|---|---|
| `enabled` | Turns the org's limits on. With `false`, only the gateway's own limits apply |
| `global_rpm` | Requests per minute for each key, when `per_key_rpm` is not set |
| `global_tpm` | Tokens per minute for each key |
| `per_key_rpm` | Requests per minute for each key. Takes precedence over `global_rpm` |
| `per_key_tpm`, `per_model_rpm`, `per_user_rpm` | Saved with the config, but the gateway does not enforce them yet |

</Tab>

</Tabs>

**Self-hosted config.yaml:**

```yaml
# Default RPM for each key
rate_limiting:
  enabled: true
  global_rpm: 1000

# Per-key limits are set on the key itself
auth:
  keys:
    - name: "limited-key"
      key: "sk-agentcc-..."
      rate_limit_rpm: 100
      rate_limit_tpm: 50000
```

### Response headers

When an RPM limit applies to the request, the response includes these headers. With no RPM limit set, they are absent:

| Header | Description |
|---|---|
| `X-Ratelimit-Limit-Requests` | Maximum requests allowed per minute |
| `X-Ratelimit-Remaining-Requests` | Requests remaining in the current window |
| `X-Ratelimit-Reset-Requests` | Seconds until the window resets |

### Error response (429)

When the RPM limit is exceeded:

```json
{
  "error": {
    "type": "rate_limit_error",
    "code": "rate_limit_exceeded",
    "message": "Rate limit exceeded. Please retry after 42 seconds.",
    "param": null
  }
}
```

When the TPM limit is used up, the code is `token_rate_limit_exceeded` and the message starts with `Token rate limit exceeded`. Both responses carry a `Retry-After` header with the seconds to wait.

### Retry logic

<Tabs items={["Python (Agent Command Center SDK)", "Python (OpenAI SDK)", "cURL"]}>

<Tab title="Python (Agent Command Center SDK)">

```python
import time
from agentcc import AgentCC, RateLimitError

client = AgentCC(
    api_key="sk-agentcc-your-key",
    base_url="https://gateway.futureagi.com",
)

def call_with_retry(max_retries=3):
    for attempt in range(max_retries):
        try:
            return client.chat.completions.create(
                model="gpt-4o",
                messages=[{"role": "user", "content": "Hello"}],
            )
        except RateLimitError:
            if attempt < max_retries - 1:
                time.sleep(2 ** attempt)  # 1s, 2s, 4s
                continue
            raise

result = call_with_retry()
```

</Tab>

## Budgets

Set spending limits for the whole org, and for teams, users (the key's owner), keys (by key name) and tags. A team, user, key or tag budget can also cap single models with `per_model`. Budgets can be daily, weekly, monthly, or total.

| Setting | Description |
|---|---|
| `period` | `daily`, `weekly`, `monthly`, or `total`. Defaults to `default_period`, which is `monthly` |
| `limit` | USD amount |
| `action` | `block` (reject requests once the limit is reached) or `warn` (let them through) |
| `warn_threshold` | Fraction of the limit at which requests are flagged as near the budget. Default `0.8` |

<Tabs items={["Dashboard", "Org config JSON"]}>

<Tab title="Dashboard">

Go to **Gateway > Budgets** in the Future AGI dashboard and click **Set Budget** to set the org budget. The **Budgets** tab of the org config editor (**Gateway > Settings > Org Config > Edit Config**) edits the same settings.

</Tab>

<Tab title="Org config JSON">

The `budgets` section of the org config:

```json
{
  "budgets": {
    "enabled": true,
    "org": {
      "period": "monthly",
      "limit": 500.00,
      "action": "block"
    },
    "keys": {
      "support-bot": {
        "limit": 50.00,
        "per_model": { "gpt-4o": 20.00 }
      }
    }
  }
}
```

The org budget can also be set with the flat keys `org_limit`, `org_period` and `hard_limit`. An org budget with neither `action: "block"` nor `hard_limit: true` never refuses requests. Team, user, key and tag budgets block by default; set `"hard": false` or `"action": "warn"` to only flag them.

</Tab>

</Tabs>

**Self-hosted config.yaml:**

```yaml
budgets:
  enabled: true
  org:
    period: monthly
    limit: 500.00
    hard: true   # block when the limit is reached (default)
```

When a blocking org budget is used up, new requests return 429:

```json
{
  "error": {
    "type": "rate_limit_error",
    "code": "org_budget_exceeded",
    "message": "org budget exceeded: spent $500.12 of $500.00 monthly limit",
    "param": null
  }
}
```

A budget set in `config.yaml` returns the code `budget_exceeded` instead, with a message that starts with `budget exceeded:`.

## Managed key credits

Managed keys have a USD credit balance that auto-deducts the cost of each request. When credits run out, requests are blocked.

**Create a managed key with credits** in the gateway's `config.yaml`. The `POST /-/keys` admin endpoint creates only regular keys and rejects `key_type` and `credit_balance`:

```yaml
auth:
  keys:
    - name: "customer-key"
      key: "sk-agentcc-..."
      key_type: managed
      credit_balance: 25.00   # starting balance in USD
```

**Add more credits:**

```bash
curl -X POST "https://gateway.futureagi.com/-/keys/key_123/credits" \
  -H "Authorization: Bearer your-admin-token" \
  -H "Content-Type: application/json" \
  -d '{"amount": 50.00}'
```

The remaining balance is returned in the `x-agentcc-credits-remaining` response header on every request made with a managed key.
