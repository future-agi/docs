## About

Rate limiting controls how many requests a key or org can make per minute. Budgets control how much money can be spent per period. Together they prevent runaway costs and protect provider quotas.

---

## When to use

- **Prevent abuse**: Cap RPM per key so one user can't monopolize gateway capacity
- **Control spending**: Set monthly budgets per org so teams can't exceed their allocation
- **Protect provider quotas**: An organization's `global_rpm` and `global_tpm` cap all its keys together, so you can keep them below your provider's own limits

---

## Rate limiting

Agent Command Center supports rate limits at three levels: per-org, per-key, and the gateway's default per key, set in the gateway's own `config.yaml`.

| Level | Scope | How to set |
|---|---|---|
| **Per-org** | Requests from one organization: all its keys together, each key, each model, or each end user | The `rate_limiting` section of the org config |
| **Per-key** | Requests using a specific API key | For an organization's keys, the org config's `per_key_rpm` and `per_key_tpm`, which apply to each of its keys. On a self-hosted gateway, a key in `config.yaml` (`auth.keys`) can also have its own `rate_limit_rpm` and `rate_limit_tpm` |
| **Gateway default** | Each key that has no requests-per-minute limit of its own and none from its organization, counted for each key separately. Requests with no key share one counter | `config.yaml` (`rate_limiting.global_rpm`) |

A key's own `rate_limit_rpm` is used in place of the organization's `per_key_rpm` and the gateway's default per-key limit. The organization's other limits count the key's requests too: a request is refused when any limit that applies to it is reached.

The organization's `rate_limiting` section takes these fields:

| Field | Limit |
|---|---|
| `global_rpm` | The organization's requests per minute, all keys together |
| `global_tpm` | The organization's tokens per minute, all keys together |
| `per_key_rpm` | Each key's requests per minute |
| `per_key_tpm` | Each key's tokens per minute |
| `per_model_rpm` | Each model's requests per minute, all keys together |
| `per_user_rpm` | Each end user's requests per minute, all keys together |

These limits count the organization's chat completions, completions, Responses, Anthropic Messages and Gemini (`/v1beta`) requests.

### Configuration

<Tabs items={["Dashboard", "Organization config", "Self-hosted config.yaml"]}>

<Tab title="Dashboard">

Go to **Gateway > Settings > Org Config** in the Future AGI dashboard and open the **Rate Limiting** tab to set the organization's limits.

The tab's **RPM per Key** and **TPM per Key** (`per_key_rpm` and `per_key_tpm`) apply to each of the organization's keys. The dashboard does not set a limit on one key: the key dialogs under **Gateway > API Keys** have no rate limit fields.

</Tab>

<Tab title="Organization config">

```json
{
  "rate_limiting": {
    "enabled": true,
    "global_rpm": 500,
    "global_tpm": 100000,
    "per_key_rpm": 100
  }
}
```

</Tab>

<Tab title="Self-hosted config.yaml">

```yaml
# enabled turns on every rate limit on this gateway, organizations' included.
# global_rpm is the default for each key that has no limit of its own
# (or from its organization): 1000 requests a minute per key, not in total.
rate_limiting:
  enabled: true
  global_rpm: 1000

# A key's own limits are set on the key itself
auth:
  keys:
    - name: "limited-key"
      key: "sk-agentcc-..."
      rate_limit_rpm: 100
      rate_limit_tpm: 50000
```

</Tab>

</Tabs>

### Response headers

When a request limit applies to a request, the response includes rate limit headers:

| Header | Description |
|---|---|
| `X-Ratelimit-Limit-Requests` | Maximum requests allowed per minute |
| `X-Ratelimit-Remaining-Requests` | Requests remaining in the current window |
| `X-Ratelimit-Reset-Requests` | Seconds until the window resets |

### Error response (429)

When a rate limit is exceeded, the response is a 429 with a `Retry-After` header, and the error names the limit that was reached:

```json
{
  "error": {
    "type": "rate_limit_error",
    "code": "rate_limit_exceeded",
    "message": "Rate limit exceeded: <limit> (<field> = <value>). Please retry after <seconds> seconds.",
    "param": "<field>"
  }
}
```

A key with its own `rate_limit_tpm` that has spent it for the minute gets a 429 with code `token_rate_limit_exceeded` instead, `param` `rate_limit_tpm`, the message `Token rate limit exceeded. Please retry after <seconds> seconds.` and a `Retry-After` header. The organization's `global_tpm` and `per_key_tpm` answer with `rate_limit_exceeded`, as above.

### Retry logic

<Tabs items={["Python (Agent Command Center SDK)", "Python (OpenAI SDK)", "cURL"]}>

<Tab title="Python (Agent Command Center SDK)">

```python
import time
from agentcc import AgentCC, RateLimitError

client = AgentCC(
    api_key="sk-agentcc-your-key",
    base_url="https://gateway.futureagi.com",
)

def call_with_retry(max_retries=3):
    for attempt in range(max_retries):
        try:
            return client.chat.completions.create(
                model="gpt-4o",
                messages=[{"role": "user", "content": "Hello"}],
            )
        except RateLimitError:
            if attempt < max_retries - 1:
                time.sleep(2 ** attempt)  # 1s, 2s, 4s
                continue
            raise

result = call_with_retry()
```

</Tab>

## Budgets

Set spending limits for the organization, and for its teams, users, keys, or tags, with optional per-model limits inside a level. Budgets can be daily, weekly, monthly, or total.

The organization's budget is set in the `budgets` section of the org config:

| Field | Description |
|---|---|
| `enabled` | Turn the organization's budgets on |
| `org_limit` | The organization's limit, in USD |
| `org_period` | `daily`, `weekly`, `monthly`, or `total` (else `default_period`, else `monthly`) |
| `hard_limit` | `true` refuses requests past the limit. Without it, passing the limit is a warning |
| `action`, `throttle_rpm` | `action: "throttle"` holds requests past the limit to `throttle_rpm` a minute |
| `warn_threshold` | The share of the limit (0 to 1) at which to warn (default `0.8`) |
| `teams`, `users`, `keys`, `tags` | Budgets for each team, user, key, or tag: `limit`, `period`, `hard` (default `true`), and `per_model` |

<Tabs items={["Dashboard", "Organization config", "Self-hosted config.yaml"]}>

<Tab title="Dashboard">

Go to **Gateway > Settings > Org Config** in the Future AGI dashboard and open the **Budgets** tab to set the organization's budgets and alerts.

</Tab>

<Tab title="Organization config">

```json
{
  "budgets": {
    "enabled": true,
    "org_limit": 500.00,
    "org_period": "monthly",
    "hard_limit": true
  }
}
```

</Tab>

<Tab title="Self-hosted config.yaml">

In a self-hosted gateway's `config.yaml`, `budgets.org` is the gateway-wide budget: one budget for every request to the [model endpoints](/docs/command-center/concepts/core#about) that the gateway serves, whichever organization sends it. For a gateway that serves one organization, that is the organization's budget. Per-organization budgets are the org config's `budgets` section. When the gateway-wide budget is spent with `hard: true` (the default), requests get 429 with the code `budget_exceeded`.

```yaml
budgets:
  enabled: true
  org:
    limit: 500.00
    period: monthly
    hard: true
```

</Tab>

</Tabs>

When the organization's budget is exceeded with `hard_limit: true`, new requests return a 429:

```json
{
  "error": {
    "type": "rate_limit_error",
    "code": "org_budget_exceeded",
    "message": "org budget exceeded: spent $500.12 of $500.00 monthly limit"
  }
}
```

## Managed key credits

<Note>
Managed keys and credit balances are not enabled on Future AGI's hosted gateway (`gateway.futureagi.com`). This section applies to a self-hosted gateway.
</Note>

Managed keys have a USD credit balance, from which the gateway deducts the cost it records for each request to the [model endpoints](/docs/command-center/concepts/core#about). When credits run out, those requests are blocked.

**Create a managed key with credits** in the gateway's config file:

```yaml
auth:
  keys:
    - name: "customer-key"
      key: "sk-agentcc-..."
      key_type: managed
      credit_balance: 25.00
```

**Add more credits** with the admin API:

```bash
curl -X POST "http://localhost:8080/-/keys/key_123/credits" \
  -H "Authorization: Bearer your-admin-token" \
  -H "Content-Type: application/json" \
  -d '{"amount": 50.00}'
```

The remaining balance is returned in the `x-agentcc-credits-remaining` response header on a request made with a managed key.
