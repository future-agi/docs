## About

For requests billed in tokens, such as chat completions and embeddings, Agent Command Center calculates the cost automatically from the token usage and the model's price. The cost appears in the `x-agentcc-cost` response header and in the `response.agentcc.cost` SDK accessor. No setup required. Audio requests are priced per character of input text or, for a WAV upload, per second of audio instead; see [Media endpoints](/docs/command-center/api/media#about).

Cost is calculated as:

```
cost = (input_tokens * input_price_per_token) + (output_tokens * output_price_per_token)
```

On an exact cache hit (a self-hosted gateway with the response cache on), no cost is calculated and `x-agentcc-cost` is not sent, since no provider call was made.

## Reading cost per request

<Tabs items={["Python (Agent Command Center SDK)", "Python (OpenAI SDK)", "cURL"]}>

<Tab title="Python (Agent Command Center SDK)">

```python
from agentcc import AgentCC

client = AgentCC(
    api_key="sk-agentcc-your-key",
    base_url="https://gateway.futureagi.com",
)

response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Hello"}],
)

print(f"Cost: ${response.agentcc.cost}")
print(f"Provider: {response.agentcc.provider}")
print(f"Model: {response.agentcc.model_used}")
```

The Agent Command Center SDK also tracks cumulative cost across all requests made with a client:

```python
# After several requests...
print(f"Total session cost: ${client.current_cost:.4f}")

# Reset the counter
client.reset_cost()
```

</Tab>

<Tab title="Python (OpenAI SDK)">

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://gateway.futureagi.com/v1",
    api_key="sk-agentcc-your-key",
)

raw = client.chat.completions.with_raw_response.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Hello"}],
)

print(f"Cost: ${raw.headers.get('x-agentcc-cost')}")
print(f"Provider: {raw.headers.get('x-agentcc-provider')}")
```

</Tab>

<Tab title="cURL">

```bash
curl -i https://gateway.futureagi.com/v1/chat/completions \

  -H "Content-Type: application/json" \

  }'
```

## Cost attribution

Tag requests with metadata to break down costs. The analytics dashboard groups cost by the `application` and `service` keys. Every key you send, other than names the gateway reserves for its own use, is kept with the request in the request log, unless the request log's content mode is `none` (see [Is my data stored?](/docs/command-center#frequently-asked-questions)).

<Tabs items={["Python (Agent Command Center SDK)", "Python (OpenAI SDK)", "cURL"]}>

<Tab title="Python (Agent Command Center SDK)">

```python
response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Hello"}],
    request_metadata={"application": "support-bot", "service": "ticket-triage", "team": "data-science"},
)
```

</Tab>

<Tab title="Python (OpenAI SDK)">

```python
import json

response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Hello"}],
    extra_headers={
        "x-agentcc-metadata": json.dumps({"application": "support-bot", "service": "ticket-triage", "team": "data-science"}),
    },
)
```

</Tab>

<Tab title="cURL">

```bash
curl https://gateway.futureagi.com/v1/chat/completions \
  -H "Authorization: Bearer sk-agentcc-your-key" \
  -H "Content-Type: application/json" \
  -H 'x-agentcc-metadata: {"application":"support-bot","service":"ticket-triage","team":"data-science"}' \
  -d '{
    "model": "gpt-4o",
    "messages": [{"role": "user", "content": "Hello"}]
  }'
```

## Analytics dashboard

**Gateway > Analytics** in the Future AGI dashboard shows your organization's traffic for the time range you pick, in five tabs: **Usage**, **Cost**, **Latency**, **Errors**, and **Models**.

The **Cost** tab shows:
- Total cost for the time range
- Cost grouped by model, provider, application, or service (the `application` and `service` metadata keys)
- How the cost is distributed across the groups

The SDK has no analytics API. To total cost in your own code, read each response's cost or the client's running total, as in [Reading cost per request](#reading-cost-per-request).

## Budget alerts

Get notified when spending, errors, or latency cross a threshold. There are two kinds of alerts:

- **Alert rules** run in the gateway. A rule watches one metric over a sliding window and notifies your channels (a webhook, Slack, or the gateway's log) when its condition holds.
- **Email alerts** are sent by the Future AGI platform, from your organization's request logs.

### Alert rules

<Tabs items={["Dashboard", "Organization config", "Self-hosted config.yaml"]}>

<Tab title="Dashboard">

1. Go to **Gateway > Monitoring** in the Future AGI dashboard and click **Add Channel** to add a Webhook, Slack, or Log Only channel
2. Click **Create Rule** and set the **Metric** (for spend, **Total Cost ($)**), the **Condition**, **Threshold**, **Window**, **Cooldown**, and **Severity**, and the **Notify Channels**

Creating a rule turns alerting on for your organization. The rules and channels are also on **Gateway > Settings > Org Config**, **Alerting** tab.

</Tab>

<Tab title="Organization config">

The `alerting` section of the organization's config:

```json
{
  "alerting": {
    "enabled": true,
    "channels": [
      {
        "name": "finance-webhook",
        "type": "webhook",
        "url": "https://hooks.example.com/agentcc-alerts"
      }
    ],
    "rules": [
      {
        "name": "spend-over-50-per-hour",
        "metric": "cost_total",
        "condition": ">=",
        "threshold": 50,
        "window": "1h",
        "cooldown": "1h",
        "channels": ["finance-webhook"],
        "severity": "warning"
      }
    ]
  }
}
```

A rule's `severity` is `info`, `warning` (the default), or `critical`, and is sent with each alert: as `severity` in the webhook's JSON body, and as a "Severity:" line in a Slack message.

</Tab>

<Tab title="Self-hosted config.yaml">

The gateway's own rules, in its config file, count every request to the [model endpoints](/docs/command-center/concepts/core#about) that the gateway serves, whichever organization sends it:

```yaml
alerting:
  enabled: true
  channels:
    - name: ops-slack
      type: slack
      url: "https://hooks.slack.com/services/T000/B000/XXXX"
  rules:
    - name: spend-over-50-per-hour
      metric: cost_total
      condition: ">="
      threshold: 50
      window: 1h
      cooldown: 1h
      channels: [ops-slack]
```

A rule in the config file has no severity.

</Tab>

</Tabs>

| Metric | What the rule compares with its threshold |
|---|---|
| `cost_total` | Total cost, in USD, of the requests in the window |
| `request_count` | Number of requests in the window |
| `error_count` | Number of failed requests in the window |
| `tokens_total` | Total tokens (prompt and completion) of the requests in the window |
| `latency_avg` | Mean latency, in milliseconds, of the requests in the window |

The condition is one of `>=`, `>`, `<=`, `<`, and `==`. A rule saved with no window uses one minute. After a rule fires, it waits its cooldown before it can fire again: 15 minutes when an organization's rule sets none. Set `cooldown` on every rule in a self-hosted gateway's config file: a config-file rule without one fires on every request past its threshold.

Rules are evaluated after each request to the model endpoints, on counts each gateway process keeps in memory: on a gateway that runs several processes, each one counts only the requests it serves.

### Email alerts

In **Gateway > Settings**, the **Email Alerts** card's **Add Alert** sends an email to the recipients you list when one of the events you choose happens. The email goes through the email provider you set on the alert (SendGrid, Resend, or SMTP).

| Event | Sent when |
|---|---|
| Budget Exceeded | A budget refuses a request (once per budget and period) |
| Error Occurred | A request fails |
| Guardrail Triggered | A guardrail check triggers on a request |
| Error Rate Spike | The share of failed requests in the window reaches **Error rate (%)** (default 5), with at least **Minimum requests** (default 5) in the window |
| Latency Spike | The 95th-percentile latency in the window reaches **p95 latency (ms)** (default 5000), with at least the minimum requests |
| Cost Threshold | The spend in the window reaches **Spend (USD)** (default 10) |

The window is **Window (minutes)** (default 5, at most 1440). **Cooldown (minutes)** is the least time between two emails from one alert: events in between are sent together in the next email.

<Tip>
Set a cooldown to prevent alert flooding when thresholds are repeatedly crossed.
</Tip>

## Budget enforcement

Budgets are configured on the [Rate limiting & budgets](/docs/command-center/features/rate-limiting) page. A budget with a hard limit (the organization's `hard_limit: true`, or a team, user, key, or tag budget that does not set `hard: false`) refuses new requests with a 429 error until the next period (a budget whose `action` is `throttle` instead holds requests past its limit to `throttle_rpm` a minute). See that page for configuration details.
