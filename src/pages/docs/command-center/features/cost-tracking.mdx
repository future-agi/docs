## About

Read `x-agentcc-cost` for the cost in USD of a non-streaming request. To see where that number came from, match `x-agentcc-request-id` to the request log and check `cost_source` in its metadata. A provider's bill can include fees that token prices alone do not capture.

## Reading cost per request

Choose the example for a [provider you have configured](/docs/command-center/features/providers). You only need one provider. Route the model through that provider and allow it on your gateway key.

| Example | Dashboard provider name | Model | Base URL | API Path Prefix |
|---|---|---|---|---|
| Python (AgentCC or OpenAI) | `openrouter` | `openai/gpt-4o-mini` | `https://openrouter.ai/api` | `/v1` |
| TypeScript or cURL | `perplexity` | `sonar` | `https://api.perplexity.ai` | Leave empty |

Use the OpenAI API format for both providers. For Sonar, the empty prefix sends chat requests to `/chat/completions`, not `/v1/chat/completions`.

In Bash, set the gateway URL and load your gateway key from a private file containing only the key. Keep provider keys in the gateway, not in the client.

```bash
export AGENTCC_BASE_URL="https://gateway.futureagi.com"
export AGENTCC_API_KEY="$(< /path/to/your/gateway-key)"
```

Each example prints the request ID, provider, and cost in USD.

- **Python:** In a new directory, run `python3 -m venv .venv && source .venv/bin/activate`. Install the SDK for your tab with `python -m pip install agentcc==1.0.0` or `python -m pip install openai`. Save the example as `packing.py` and run `python packing.py`.
- **TypeScript:** Save the example as `packing.mts` and run `node packing.mts` with Node.js 22.18 or later.
- **cURL:** Run the example in Bash with cURL 7.84 or later.

<CodeGroup titles={["Python (AgentCC)", "Python (OpenAI)", "TypeScript", "cURL"]}>

```python
from agentcc import AgentCC

client = AgentCC()
response = client.chat.completions.create(
    model="openai/gpt-4o-mini",
    messages=[{"role": "user", "content": "Name one item to pack for a rainy hike. Answer in five words or fewer."}],
    max_tokens=32,
    request_metadata={"application": "ridgeline-support", "service": "packing-list"},
)
meta = response.agentcc
print(meta.request_id, meta.provider, meta.cost)
```

```python
import json
import os
from openai import OpenAI

client = OpenAI(base_url=os.environ["AGENTCC_BASE_URL"] + "/v1", api_key=os.environ["AGENTCC_API_KEY"])
raw = client.chat.completions.with_raw_response.create(
    model="openai/gpt-4o-mini",
    messages=[{"role": "user", "content": "Name one item to pack for a rainy hike. Answer in five words or fewer."}],
    max_tokens=32,
    extra_headers={"x-agentcc-metadata": json.dumps({"application": "ridgeline-support", "service": "packing-list"})},
)
print(raw.headers["x-agentcc-request-id"], raw.headers["x-agentcc-provider"], raw.headers.get("x-agentcc-cost"))
```

```typescript
const { AGENTCC_BASE_URL, AGENTCC_API_KEY } = process.env;
if (!AGENTCC_BASE_URL || !AGENTCC_API_KEY) throw new Error("Set the gateway URL and key");
const tags = { application: "ridgeline-support", service: "packing-list" };
const response = await fetch(`${AGENTCC_BASE_URL}/v1/chat/completions`, {
  method: "POST",
  headers: {
    Authorization: `Bearer ${AGENTCC_API_KEY}`,
    "Content-Type": "application/json",
    "x-agentcc-metadata": JSON.stringify(tags),
  },
  body: JSON.stringify({
    model: "sonar",
    messages: [{ role: "user", content: "Name one item to pack for a rainy hike. Answer in five words or fewer." }],
    max_tokens: 32,
  }),
});
if (!response.ok) throw new Error(`Gateway returned HTTP ${response.status}`);
console.log(response.headers.get("x-agentcc-request-id"), response.headers.get("x-agentcc-provider"), response.headers.get("x-agentcc-cost"));
```

```bash
curl --fail --silent --show-error "$AGENTCC_BASE_URL/v1/chat/completions" \
  -H "Authorization: Bearer $AGENTCC_API_KEY" \
  -H 'Content-Type: application/json' \
  -H 'x-agentcc-metadata: {"application":"ridgeline-support","service":"packing-list"}' \
  -d '{"model":"sonar","messages":[{"role":"user","content":"Name one item to pack for a rainy hike. Answer in five words or fewer."}],"max_tokens":32}' \
  --output /dev/null \
  --write-out '%header{x-agentcc-request-id} %header{x-agentcc-provider} %header{x-agentcc-cost}\n'
```

With the AgentCC Python client, `client.current_cost` sums the costs seen by that client. `client.reset_cost()` resets the local counter, not your organization's spend.

## Check how a request was priced

In **Agent Command Center > Request Logs**, search for the request ID. Open the row and select **Metadata**. For streaming calls, check the completed log: the final usage may not be available when the gateway sends the response headers.

These two packing-list requests illustrate why the cost source matters. The amounts are examples, not per-request rates. Both rows had `cost_source: provider_reported`.

| Provider and requested model | `x-agentcc-cost` (USD) | `cost_catalogue` (USD) | `cost_reported_unit` |
|---|---:|---:|---|
| OpenRouter, `openai/gpt-4o-mini` | `0.000008` | `0.000008` | `openrouter_credits` |
| Perplexity, `sonar` | `0.002710` | `0.000027` | `usd` |

Perplexity includes any request, search, or tool fees in `usage.cost.total_cost`. Use the total once; do not add those fees or `cost_catalogue` to it.

### Cost sources, in order of precedence

| `cost_source` | What it means for a chat request |
|---|---|
| `org_custom` | The gateway used your organization's custom pricing for the model. Applicable org pricing takes precedence over both the provider and the catalogue. |
| `provider_reported` | The gateway accepted the cost in the provider's usage data. This takes precedence over the model catalogue, including operator price overrides. |
| `catalogue` | The gateway used model pricing and usage because no eligible provider cost was available or the operator disabled it. |
| `unpriced` | The request used billable tokens but the gateway could not price them. Do not interpret a missing cost header as a free request. |

For chat completions, Responses, Messages, and completions, the gateway accepts a reported cost only from an OpenAI-format provider on its official host. The configured type must match the vendor; if no type is set, the provider ID must match. In the dashboard, use the exact name `openrouter`, `perplexity`, or `xai`. A matching model name alone is not enough. A cache hit does not reuse the original provider charge.

If the reported cost is invalid or exceeds $1,000 for one request, the gateway falls back to the catalogue. If you use a model alias with a configured cost multiplier, the gateway applies that multiplier to both the reported cost and the catalogue comparison.

| Provider | Field used | Unit in log metadata |
|---|---|---|
| OpenRouter (`openrouter.ai`) | `usage.cost`. If OpenRouter used your own upstream provider key, the gateway uses `usage.cost_details.upstream_inference_cost` instead of OpenRouter's fee. If that upstream cost is missing or invalid, the gateway falls back to catalogue pricing. | `openrouter_credits` (one OpenRouter credit equals one USD) |
| Perplexity (`api.perplexity.ai`) | `usage.cost.total_cost`, including any search, tool, or request fees. The Agent API must state USD; Sonar's token-cost breakdown can omit the currency. | `usd` |
| xAI (`api.x.ai`) | `usage.cost_in_usd_ticks`, converted at 10 billion ticks per USD. | `usd_ticks` |

The audit fields are optional. A `provider_reported` row includes `cost_catalogue` only if the catalogue could also price the request. `cost_is_byok: "true"` means OpenRouter used your own upstream provider key, not just that you configured an OpenRouter key in the gateway. A reported zero is valid: if the request used tokens the catalogue prices above zero, `cost_reported_zero: "true"` flags the discrepancy without changing the charge. You cannot set these fields with request metadata.

If you operate the gateway and want catalogue pricing instead, set `ignore_provider_cost: true` on the provider entry in `config.yaml`. It applies to organization instances of the same provider ID. It does not override organization custom pricing, and there is no dashboard toggle.

## Cost attribution

The examples tag each request with `application: ridgeline-support` and `service: packing-list` using `x-agentcc-metadata`. Both tags appear in the same request-log metadata as the cost source. Use **Application** to compare products or **Service** to isolate the part of a product driving spend.

## Analytics dashboard

In **Analytics > Cost**, choose a time range and group by model, provider, application, or service. To get the breakdown by provider through the platform API, set `FI_API_KEY` and `FI_SECRET_KEY` to your Future AGI platform credentials (not your gateway key). With `jq` installed, run:

```bash
set -o pipefail
curl -fsS 'https://api.futureagi.com/agentcc/analytics/cost-breakdown/?group_by=provider' \
  -H "X-Api-Key: $FI_API_KEY" -H "X-Secret-Key: $FI_SECRET_KEY" \
  | jq -e '.result | {group_by, total_cost, breakdown: [.breakdown[] | {name, request_count, total_cost}]}'
```

## Budget alerts

In **Settings > Email Alerts**, select **Add Alert**, choose **Budget Exceeded**, and configure your recipients, email provider, and cooldown. This event fires when the gateway rejects a request because its budget is exhausted. It is not an advance warning at a percentage of the budget.

## Budget enforcement

Configure limits in [Rate limiting & budgets](/docs/command-center/features/rate-limiting). With `action: block`, a request rejected for exceeding the budget returns HTTP 429.
