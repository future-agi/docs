## About

Agent Command Center calculates the cost of every request automatically based on token usage and model pricing. The cost appears in the `x-agentcc-cost` response header and in the `response.agentcc.cost` SDK accessor. No setup required.

Cost is calculated as:

```
cost = (input_tokens * input_price_per_token) + (output_tokens * output_price_per_token)
```

The price comes from, in order of precedence:

1. The organization's custom pricing (`cost_tracking.custom_pricing.<model>` in the org config, with `input_per_mtok` and `output_per_mtok` in USD per million tokens), when `cost_tracking.enabled` is `true` and it has an entry for the model.
2. The cost the provider states in its own response, for OpenRouter, Perplexity and xAI, when the request went to the provider's official host (`openrouter.ai`, `api.perplexity.ai`, `api.x.ai`) through a provider of that type, or a dashboard provider named exactly `openrouter`, `perplexity` or `xai`. This includes fees the token price leaves out, such as Perplexity's search fees. A response with no usable stated cost is priced from the catalogue.
3. The model catalogue's list price, using the formula above.

Exact cache hits are not priced: no provider call was made, so the response has no `x-agentcc-cost` header. Semantic cache hits are priced from the catalogue on the cached response's token usage.

## Reading cost per request

<Tabs items={["Agent Command Center SDK", "OpenAI SDK", "cURL"]}>

<Tab title="Python (Agent Command Center SDK)">

```python
from agentcc import AgentCC

client = AgentCC(
    api_key="sk-agentcc-your-key",
    base_url="https://gateway.futureagi.com",
)

response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Hello"}],
)

print(f"Cost: ${response.agentcc.cost}")
print(f"Provider: {response.agentcc.provider}")
print(f"Model: {response.agentcc.model_used}")
```

The Agent Command Center SDK also tracks cumulative cost across all requests made with a client:

```python
# After several requests...
print(f"Total session cost: ${client.current_cost:.4f}")

# Reset the counter
client.reset_cost()
```

</Tab>

<Tab title="Python (OpenAI SDK)">

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://gateway.futureagi.com/v1",
    api_key="sk-agentcc-your-key",
)

raw = client.chat.completions.with_raw_response.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Hello"}],
)

print(f"Cost: ${raw.headers.get('x-agentcc-cost')}")
print(f"Provider: {raw.headers.get('x-agentcc-provider')}")
```

</Tab>

<Tab title="cURL">

```bash
curl -i https://gateway.futureagi.com/v1/chat/completions \
  -H "Authorization: Bearer sk-agentcc-your-key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-4o",
    "messages": [{"role": "user", "content": "Hello"}]
  }'
# Look for: x-agentcc-cost: 0.00015
```

</Tab>

</Tabs>

## Cost attribution

Tag requests with metadata to attribute costs to a team, feature, user, or any custom dimension. Metadata is stored on each request log. **Gateway > Analytics** groups cost only by the `application` and `service` metadata keys. Other keys, such as `team` and `feature` in the examples below, are filters in **Gateway > Request Logs** once you declare them as [custom properties](/docs/command-center/features/custom-properties); Analytics does not group by them.

<Tabs items={["Agent Command Center SDK", "OpenAI SDK", "cURL"]}>

<Tab title="Python (Agent Command Center SDK)">

```python
response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Hello"}],
    request_metadata={"team": "data-science", "feature": "recommendations", "user": "alice"},
)
```

</Tab>

<Tab title="Python (OpenAI SDK)">

```python
import json

response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Hello"}],
    extra_headers={
        "x-agentcc-metadata": json.dumps({"team": "data-science", "feature": "recommendations", "user": "alice"}),
    },
)
```

</Tab>

<Tab title="cURL">

```bash
curl https://gateway.futureagi.com/v1/chat/completions \
  -H "Authorization: Bearer sk-agentcc-your-key" \
  -H "Content-Type: application/json" \
  -H 'x-agentcc-metadata: {"team":"data-science","feature":"recommendations","user":"alice"}' \
  -d '{
    "model": "gpt-4o",
    "messages": [{"role": "user", "content": "Hello"}]
  }'
```

</Tab>

## Analytics dashboard

Go to **Gateway > Analytics** in the Future AGI dashboard. The page opens with overview KPIs for the selected time range, including total cost, and has **Usage**, **Cost**, **Latency**, **Errors**, and **Models** tabs. The **Cost** tab shows total cost and a breakdown you can group by model, provider, application, or service (the `application` and `service` metadata keys).

The Agent Command Center SDK has no analytics methods (there is no `client.analytics` or `control_plane_url` option); use the dashboard.

## Alerts

Alerts are configured per organization, in the dashboard. The SDK has no alert methods (there is no `client.alerts`). There are two kinds.

### Event alerts (email)

Go to **Gateway > Settings**, and under **Email Alerts** click **Add Alert**. Choose the events, the recipients, and the email provider (SendGrid, Resend, or SMTP). An alert emails at most once per its cooldown (5 minutes by default).

| Event | When it fires |
|---|---|
| `budget.exceeded` | A request is refused because a budget is exhausted (`budget_exceeded` or `org_budget_exceeded`). It fires on the refused request, not when spend approaches the limit |
| `error.occurred` | A request fails (status 400 or above) |
| `guardrail.triggered` | A guardrail blocks or flags a request |

The dialog also lists **Error Rate Spike**, **Latency Spike**, and **Cost Threshold**, but these never send: an email alert has no threshold to compare with. Use a threshold alert instead.

### Threshold alerts

Go to **Gateway > Monitoring**, open the **Alert Rules** tab, and create a rule: a metric, a condition (`>`, `>=`, `<`, `<=`, `==`), a threshold, a time window (for example `5m`), and the channels to notify. Add channels on the **Channels** tab: a webhook, a Slack incoming webhook, or log only.

| Metric | What it measures over the window |
|---|---|
| `cost_total` | Total cost in USD |
| `request_count` | Number of requests |
| `error_count` | Number of failed requests |
| `latency_avg` | Average latency in milliseconds |
| `tokens_total` | Total prompt and completion tokens |

`cost_total` compares spend in dollars, not as a percentage of a budget; there is no alert on reaching a share of a budget. The rule dialog's **Severity** is only a label in the dashboard: it does not change how or where the alert is sent.

<Tip>
Set a cooldown on a rule (in **Gateway > Settings > Org Config**, **Alerting** tab; 15 minutes by default there) to prevent alert flooding when a threshold is repeatedly crossed.
</Tip>

## Budget enforcement

Budgets are configured on the [Rate limiting & budgets](/docs/command-center/features/rate-limiting) page. When a budget is exceeded with `action: block`, new requests return a 429 error until the next period. See that page for configuration details.
