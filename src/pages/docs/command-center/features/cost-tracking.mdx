To find out which feature is spending money, start with the [cost response header](/docs/command-center/api/headers#response-headers) on one request. Attach [metadata](/docs/command-center/features/custom-properties) to group requests by team, feature or user in the dashboard.

<Prerequisites title="Before you start">
- A [configured gateway and provider](/docs/command-center/quickstart) and a gateway key for the request examples.
- Access to the organization dashboard to inspect totals or configure alerts.
</Prerequisites>

## Estimate one request’s cost

Agent Command Center calculates the cost of every request automatically, based on token usage and model pricing. No setup required.

When the model has pricing data, the `x-agentcc-cost` response header reports an estimate in US dollars. The Agent Command Center SDK exposes the same value as `response.agentcc.cost`.

Cost is calculated as:

```
cost = (input_tokens * input_price_per_token) + (output_tokens * output_price_per_token)
```

An exact [cache hit](/docs/command-center/features/caching) returns `x-agentcc-cost: 0` because it needs no provider call.

## Read the cost on a response

<Tabs>

<Tab title="Python (Agent Command Center SDK)">

```python
from agentcc import AgentCC

client = AgentCC(
    api_key="sk-agentcc-your-key",
    base_url="https://gateway.futureagi.com",
)

response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Hello"}],
)

print(f"Cost: ${response.agentcc.cost}")
print(f"Provider: {response.agentcc.provider}")
print(f"Model: {response.agentcc.model_used}")
```

The Agent Command Center SDK also tracks cumulative cost across all requests made with a client:

```python
# After several requests...
print(f"Total session cost: ${client.current_cost:.4f}")

# Reset the counter
client.reset_cost()
```

</Tab>

<Tab title="Python (OpenAI SDK)">

```python
from openai import OpenAI

client = OpenAI(

raw = client.chat.completions.with_raw_response.create(
    model="gpt-4o",

print(f"Cost: ${raw.headers.get('x-agentcc-cost')}")
print(f"Provider: {raw.headers.get('x-agentcc-provider')}")
```

## Tag a request for cost attribution

Tag requests with metadata to break down costs by team, feature, user, or any custom dimension. Metadata is indexed and queryable in the analytics dashboard.

<Tabs>

<Tab title="Python (Agent Command Center SDK)">

```python
response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Hello"}],
    request_metadata={"team": "data-science", "feature": "recommendations", "user": "alice"},
)
```

</Tab>

<Tab title="Python (OpenAI SDK)">

```python
import json

response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Hello"}],
    extra_headers={
        "x-agentcc-metadata": json.dumps({"team": "data-science", "feature": "recommendations", "user": "alice"}),
    },
)
```

</Tab>

<Tab title="cURL">

```bash
curl https://gateway.futureagi.com/v1/chat/completions \
  -H "Authorization: Bearer sk-agentcc-your-key" \
  -H "Content-Type: application/json" \
  -H 'x-agentcc-metadata: {"team":"data-science","feature":"recommendations","user":"alice"}' \
  -d '{
    "model": "gpt-4o",
    "messages": [{"role": "user", "content": "Hello"}]
  }'
```

</Tab>

## Inspect the tagged request

1. Read `x-agentcc-request-id` from the response to the tagged request.
2. Open **Agent Command Center > Logs**.
3. Find the matching ID in the [request log](/docs/command-center/features/observability).

   Check the model, provider, cost and metadata on that row rather than comparing two different requests.

4. In the analytics dashboard, open the cost by metadata dimension view.

   Look for `data-science` under `team`. Its spend is the total for that group and period, not necessarily the price of the single request.

The Future AGI dashboard shows cost breakdowns and trends across your organization.

Available views:

- Total spend for the current period
- Cost by model
- Cost by provider
- Cost by API key
- Cost timeseries (daily/weekly/monthly)
- Cost by metadata dimension (team, feature, user)

### Read analytics from code

The Agent Command Center SDK reads the same analytics from code:

```python
from agentcc import AgentCC

client = AgentCC(
    api_key="sk-agentcc-your-key",
    base_url="https://gateway.futureagi.com",
    control_plane_url="https://api.futureagi.com",
)

# Spending overview
overview = client.analytics.overview(
    start_date="2026-01-01",
    end_date="2026-01-31",
)

# Cost breakdown by model
costs = client.analytics.cost_breakdown(group_by="model")

# Compare models
comparison = client.analytics.model_comparison(
    models=["gpt-4o", "claude-sonnet-4-6"],
)
```

On the platform SDK, the [gateway analytics reference](/docs/sdk/reference/gateway#gatewayanalytics) documents `client.gateway.analytics()` in Python and TypeScript. It reads an overview, with optional start, end, granularity and gateway key filters.

## Budget alerts

Get notified when spending crosses a threshold. Alerts are configured per organization. An alert notifies recipients. A blocking budget, covered under [Budget enforcement](#budget-enforcement), controls whether the next request can run.

<Tabs>

<Tab title="Dashboard">

1. Open **Agent Command Center > Settings > Alerts** in the Future AGI dashboard.
2. Create a new alert.
3. Select the event type.
4. Set the recipients.
5. Configure the severity.

</Tab>

<Tab title="Python (Agent Command Center SDK)">

```python
alert = client.alerts.create(
    name="Budget warning at 80%",
    condition="cost > 80",
    recipients=["team@example.com"],
    severity="high",
)
```

</Tab>

<Tab title="TypeScript (Agent Command Center SDK)">

```typescript
const alert = await client.alerts.create({
    name: "Budget warning at 80%",
    condition: "cost > 80",
    recipients: ["team@example.com"],
    severity: "high",
});
```

</Tab>

</Tabs>

### Alert types

| Event | Trigger |
|---|---|
| `budget_exceeded` | Spend crosses the budget limit |
| `budget_threshold` | Spend crosses a percentage threshold (e.g. 80%) |
| `error_spike` | Error rate exceeds configured threshold |
| `latency_spike` | P95 latency exceeds configured threshold |
| `guardrail_triggered` | A guardrail blocks or flags a request |

<Tip>
Configure a cooldown period to prevent alert flooding when thresholds are repeatedly crossed.
</Tip>

## Budget enforcement

Budgets are configured on the [Rate limiting & budgets](/docs/command-center/features/rate-limiting) page. When spending exceeds a budget configured with `action: block`, new requests return a 429 error until the next period. An alert alone does not set this limit.

## Troubleshooting

- **There is no cost header.** Inspect the raw response, not the parsed completion. Confirm that it contains a gateway request ID and check whether the model has pricing data. A missing estimate is not a zero-cost request.
- **The header is zero.** Check the cache status. An exact hit needs no provider call.
- **My team breakdown is empty.** Check the tagged request in the logs. If the `team` value is missing, send the request again with the metadata shown above. Select the time period containing that request and look for the same value in the breakdown.
