Agent Command Center can send real-time HTTP notifications to your endpoints when gateway events occur, such as completed requests, triggered [guardrails](/docs/command-center/features/guardrails), exceeded budgets, and errors. Use webhooks to build integrations, trigger alerts, or log events in your own systems.

This guide subscribes one receiver to `request.completed`, verifies the signature before acting on the event, then compares the delivery log with what the receiver actually accepted.

<Prerequisites title="Before you start">
- An HTTPS endpoint you control that accepts POST requests. The example receivers use Python with either FastAPI or Flask.
- Access to **Gateway > Webhooks**, and a secret that the gateway and your receiver share. Keep the secret out of source control and logs.
</Prerequisites>

## When to use

- **Alerting**: Get notified immediately when error rates spike or budgets are exceeded
- **Audit logging**: Stream every request event to your own data pipeline
- **Guardrail monitoring**: React when a guardrail triggers on a request
- **Cost control**: Trigger actions when a budget threshold is hit

## Subscribe to completed requests

1. Open **Gateway > Webhooks**.
2. Select **+ Create Webhook**.
3. Enter a **Name** for the endpoint.
4. Enter the receiver's HTTPS **URL**.
5. Set **Secret** to the same value your receiver uses. It is optional on the form but required to verify a signed delivery.
6. Add notes in **Description** if needed.
7. Under **Event Subscriptions**, select `request.completed`.
8. Select **Create**.

The form has these fields:

<div class="sdk-ref-table">

| Field | Required | Description |
|-------|----------|-------------|
| **Name** | Yes | A label for this endpoint |
| **URL** | Yes | Your HTTPS endpoint, e.g., `https://example.com/webhook` |
| **Secret** | Optional | HMAC secret for verifying payload signatures |
| **Description** | Optional | Notes about this webhook |
| **Event Subscriptions** | Optional | Select which events to receive (see below) |

</div>

The subscription tells the gateway which events to send. It does not prove that your endpoint can receive them.

## Event types

| Event | Trigger |
|-------|---------|
| `request.completed` | A gateway request finishes (success or error) |
| `guardrail.triggered` | A guardrail rule fires on a request |
| `budget.exceeded` | Spend crosses a configured [budget limit](/docs/command-center/features/cost-tracking) |
| `error.occurred` | A gateway-level error occurs |
| `batch.completed` | A [batch processing job](/docs/command-center/api/async-batch) finishes |

Subscribe to only the events you need to reduce noise.

## Verify the signature before parsing the event

If you set a **Secret**, Agent Command Center signs each request with HMAC-SHA256 and includes the signature in the `X-AgentCC-Signature` header. Verify it on your server to confirm the payload came from Agent Command Center.

The handlers compute the signature from the raw body, compare it with the header, and only then parse the JSON. `WEBHOOK_SECRET` stands for your configured secret in these snippets; do not use the sample string as the secret.

<Tabs items={["Python (FastAPI)", "Python (Flask)"]}>

<Tab title="Python (FastAPI)">

```python
import hmac
import hashlib
from fastapi import FastAPI, Request, HTTPException

app = FastAPI()
WEBHOOK_SECRET = "your-webhook-secret"

@app.post("/webhook")
async def handle_webhook(request: Request):
    payload = await request.body()
    signature = request.headers.get("X-AgentCC-Signature", "")

    expected = hmac.new(
        WEBHOOK_SECRET.encode(),
        payload,
        hashlib.sha256,
    ).hexdigest()

    if not hmac.compare_digest(f"sha256={expected}", signature):
        raise HTTPException(status_code=401, detail="Invalid signature")

    data = await request.json()
    event_type = data.get("event")

    # Handle the event
    print(f"Received event: {event_type}")
    return {"status": "ok"}
```

</Tab>

<Tab title="Python (Flask)">

```python
import hmac
import hashlib
from flask import Flask, request, abort, jsonify

app = Flask(__name__)
WEBHOOK_SECRET = "your-webhook-secret"

@app.route("/webhook", methods=["POST"])
def handle_webhook():
    payload = request.get_data()
    signature = request.headers.get("X-AgentCC-Signature", "")

    expected = hmac.new(
        WEBHOOK_SECRET.encode(),
        payload,
        hashlib.sha256,
    ).hexdigest()

    if not hmac.compare_digest(f"sha256={expected}", signature):
        abort(401)

    data = request.get_json()
    event_type = data.get("event")

    # Handle the event
    print(f"Received event: {event_type}")
    return jsonify(status="ok")
```

## Match the delivery to the receiver

The **Delivery Log** tab on the Webhooks page shows the status of every webhook delivery attempt, including timestamp, HTTP status code, and response body. Use it to debug failed deliveries and retry them manually.

1. Send one [gateway chat request](/docs/command-center/api/chat) while your receiver is running.
2. Open the **Delivery Log** tab.
3. Inspect the attempt's timestamp, HTTP status code and response body.
4. Compare that attempt with the receiver log for the same time. For these handlers, look for `Received event: request.completed` and a successful response.

A completed model request can be a success or an error. The HTTP status in **Delivery Log** belongs to the separate webhook delivery, not the original model call.

## Troubleshoot a failed delivery

- **The receiver returns 401.** The example handlers reject a missing or mismatched signature before printing the event. Check that both ends use the same secret and that verification uses the original body bytes. Do not log the secret.
- **The receiver has no matching event.** Check the configured HTTPS URL and subscription, then read the status and response body for that attempt.
- **You corrected the receiver.** Retry the failed delivery manually from **Delivery Log**. Check the new attempt and the receiver log rather than treating the retry action as confirmation.
