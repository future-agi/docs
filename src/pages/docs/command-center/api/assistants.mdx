## About

Agent Command Center proxies the OpenAI Assistants API. Create assistants with instructions and tools, manage conversation threads, and execute runs through the gateway. Each request runs the gateway's request pipeline and then goes to OpenAI. [What Agent Command Center adds](#what-agent-command-center-adds) lists what applies.

The Assistants API is stateful (OpenAI stores threads and messages server-side), so it only works with OpenAI as the provider. Use the OpenAI SDK pointed at Agent Command Center.

<Warning>
Assistants API requests go to OpenAI. Threads and runs are stored on OpenAI's servers, so the assistant's model must be an OpenAI model.
</Warning>

## Endpoints

### Assistants

| Method | Path | Description |
|---|---|---|
| POST | `/v1/assistants` | Create an assistant |
| GET | `/v1/assistants` | List assistants |
| GET | `/v1/assistants/{id}` | Get an assistant |
| POST | `/v1/assistants/{id}` | Update an assistant |
| DELETE | `/v1/assistants/{id}` | Delete an assistant |

### Threads

| Method | Path | Description |
|---|---|---|
| POST | `/v1/threads` | Create a thread |
| GET | `/v1/threads/{id}` | Get a thread |
| POST | `/v1/threads/{id}` | Update a thread |
| DELETE | `/v1/threads/{id}` | Delete a thread |

### Messages

| Method | Path | Description |
|---|---|---|
| POST | `/v1/threads/{id}/messages` | Add a message to a thread |
| GET | `/v1/threads/{id}/messages` | List messages in a thread |
| GET | `/v1/threads/{id}/messages/{msg_id}` | Get a message |
| POST | `/v1/threads/{id}/messages/{msg_id}` | Update a message |
| DELETE | `/v1/threads/{id}/messages/{msg_id}` | Delete a message |

### Runs

| Method | Path | Description |
|---|---|---|
| POST | `/v1/threads/{id}/runs` | Create a run |
| GET | `/v1/threads/{id}/runs` | List runs |
| GET | `/v1/threads/{id}/runs/{run_id}` | Get a run |
| POST | `/v1/threads/{id}/runs/{run_id}` | Update a run |
| POST | `/v1/threads/{id}/runs/{run_id}/cancel` | Cancel a run |
| POST | `/v1/threads/{id}/runs/{run_id}/submit_tool_outputs` | Submit tool outputs |
| GET | `/v1/threads/{id}/runs/{run_id}/steps` | List run steps |
| POST | `/v1/threads/runs` | Create thread and run in one call |

## Quick example

Create an assistant, start a conversation, and get a response:

<Tabs items={["OpenAI SDK", "cURL"]}>

<Tab title="Python (OpenAI SDK)">

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://gateway.futureagi.com/v1",
    api_key="sk-agentcc-your-key",
)

# 1. Create an assistant
assistant = client.beta.assistants.create(
    name="Math Tutor",
    instructions="You are a math tutor. Explain concepts step by step.",
    model="gpt-4o",
)

# 2. Create a thread
thread = client.beta.threads.create()

# 3. Add a message
client.beta.threads.messages.create(
    thread_id=thread.id,
    role="user",
    content="Explain the Pythagorean theorem",
)

# 4. Run the assistant
run = client.beta.threads.runs.create_and_poll(
    thread_id=thread.id,
    assistant_id=assistant.id,
)

# 5. Get the response
if run.status == "completed":
    messages = client.beta.threads.messages.list(thread_id=thread.id)
    for msg in messages.data:
        if msg.role == "assistant":
            print(msg.content[0].text.value)
            break
```

</Tab>

<Tab title="cURL">

```bash
# 1. Create an assistant
ASSISTANT_ID=$(curl -s -X POST https://gateway.futureagi.com/v1/assistants \
  -H "Authorization: Bearer sk-agentcc-your-key" \
  -H "Content-Type: application/json" \
  -H "OpenAI-Beta: assistants=v2" \
  -d '{
    "name": "Math Tutor",
    "instructions": "You are a math tutor. Explain concepts step by step.",
    "model": "gpt-4o"
  }' | jq -r '.id')

# 2. Create a thread
THREAD_ID=$(curl -s -X POST https://gateway.futureagi.com/v1/threads \
  -H "Authorization: Bearer sk-agentcc-your-key" \
  -H "Content-Type: application/json" \
  -H "OpenAI-Beta: assistants=v2" \
  -d '{}' | jq -r '.id')

# 3. Add a message
curl -s -X POST "https://gateway.futureagi.com/v1/threads/$THREAD_ID/messages" \
  -H "Authorization: Bearer sk-agentcc-your-key" \
  -H "Content-Type: application/json" \
  -H "OpenAI-Beta: assistants=v2" \
  -d '{"role": "user", "content": "Explain the Pythagorean theorem"}'

# 4. Create a run
RUN_ID=$(curl -s -X POST "https://gateway.futureagi.com/v1/threads/$THREAD_ID/runs" \
  -H "Authorization: Bearer sk-agentcc-your-key" \
  -H "Content-Type: application/json" \
  -H "OpenAI-Beta: assistants=v2" \
  -d "{\"assistant_id\": \"$ASSISTANT_ID\"}" | jq -r '.id')

# 5. Poll until complete, then get messages
# (poll GET /v1/threads/$THREAD_ID/runs/$RUN_ID until status is "completed")
curl -s "https://gateway.futureagi.com/v1/threads/$THREAD_ID/messages" \
  -H "Authorization: Bearer sk-agentcc-your-key" \
  -H "OpenAI-Beta: assistants=v2" | jq '.data[0].content[0].text.value'
```

## Tool use

Assistants can call tools (functions you define) during a run. When the run enters `requires_action` status, you submit tool outputs to continue.

```python
import json

# Create assistant with tools
assistant = client.beta.assistants.create(
    name="Weather Bot",
    instructions="You help users check the weather.",
    model="gpt-4o",
    tools=[{
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "Get current weather for a city",
            "parameters": {
                "type": "object",
                "properties": {
                    "city": {"type": "string", "description": "City name"},
                },
                "required": ["city"],
            },
        },
    }],
)

thread = client.beta.threads.create()
client.beta.threads.messages.create(
    thread_id=thread.id,
    role="user",
    content="What's the weather in Tokyo?",
)

run = client.beta.threads.runs.create(
    thread_id=thread.id,
    assistant_id=assistant.id,
)

# Poll until the run needs action or completes
import time
while run.status in ("queued", "in_progress"):
    time.sleep(1)
    run = client.beta.threads.runs.retrieve(
        thread_id=thread.id,
        run_id=run.id,
    )

if run.status == "requires_action":
    tool_calls = run.required_action.submit_tool_outputs.tool_calls

    # Process each tool call
    tool_outputs = []
    for call in tool_calls:
        args = json.loads(call.function.arguments)
        # Your actual function call here
        result = f"22°C and sunny in {args['city']}"
        tool_outputs.append({
            "tool_call_id": call.id,
            "output": result,
        })

    # Submit outputs and wait for completion
    run = client.beta.threads.runs.submit_tool_outputs_and_poll(
        thread_id=thread.id,
        run_id=run.id,
        tool_outputs=tool_outputs,
    )

if run.status == "completed":
    messages = client.beta.threads.messages.list(thread_id=thread.id)
    print(messages.data[0].content[0].text.value)
```

## Streaming runs

Stream run events to update a UI as the run progresses, instead of polling:

```python
from openai import AssistantEventHandler

class MyHandler(AssistantEventHandler):
    def on_text_created(self, text):
        print("\nassistant > ", end="", flush=True)

    def on_text_delta(self, delta, snapshot):
        print(delta.value, end="", flush=True)

    def on_tool_call_created(self, tool_call):
        print(f"\n  Tool call: {tool_call.type}", flush=True)

# Using thread and assistant from earlier examples
with client.beta.threads.runs.stream(
    thread_id=thread.id,    # from the thread you created
    assistant_id=assistant.id,  # from the assistant you created
    event_handler=MyHandler(),
) as stream:
    stream.until_done()
```

## What Agent Command Center adds

Each Assistants API request runs the gateway's request pipeline, as a request to the [model endpoints](/docs/command-center/concepts/core#about) does, and then goes to OpenAI. Requests to the Vector Stores API routes in the [endpoints reference](/docs/command-center/api/endpoints#vector-stores) run it the same way. On these requests, the gateway:

- **Requires your Agent Command Center API key.** The key's allowed models and access groups apply to the four requests that name a model: creating or updating an assistant (its `model`), and creating a run or a thread and run (the run's `model`). A key that may not use the model gets the answer chat completions give the same key and model, before OpenAI is called: 403 `model_not_permitted` for a model outside its allowed models, and 403 `permission_denied` for a model its access groups do not hold. The key's allowed providers apply too.
- **Reads the model as OpenAI reads it** and sends OpenAI that one `model`. An `openai/` prefix is removed (`openai/gpt-4o` is sent as `gpt-4o`); any other name with a `/` is refused with 403 `permission_denied`. A body chat completions would refuse as invalid JSON (not a JSON object, a `model` that is not a string, or a `stream` that is not a boolean) gets 400 `invalid_json` on those four requests and on submitting tool outputs.
- **Applies rate limits:** the key's own `rate_limit_rpm` (for a key without one, the gateway's default, `rate_limiting.global_rpm`) and its own `rate_limit_tpm`. A request over the request limit gets 429 `rate_limit_exceeded`, and one whose key has spent its `rate_limit_tpm` for the minute gets 429 `token_rate_limit_exceeded`. Neither reaches OpenAI. The organization's `rate_limiting` section counts chat completions, completions, Responses, Anthropic Messages and Gemini (`/v1beta`) requests (see [Rate limiting](/docs/command-center/features/rate-limiting#rate-limiting)).
- **Runs your organization's guardrails** on the request body when you create or update an assistant, create a thread, message or run, or submit tool outputs, and on a vector store search's query.
- **Writes a request log entry** for every request the pipeline runs, run polls (`GET /v1/threads/{id}/runs/{run_id}`), lists and retrievals included, and a request a rate limit or a guardrail refuses. The entry has the status you got, the model the request names, and its operation (`assistants_operation`, or `vector_stores_operation`). A streamed run is logged when its stream ends.
- **Meters each request as a gateway request.** Each one counts toward your organization's monthly `gateway_requests` quota, polls and lists included: an SDK helper that polls a run, such as `create_and_poll`, makes one metered request per poll. An organization that is paused or over its quota is refused.
- **Serves them with your organization's own OpenAI provider**, never with managed credentials: when the gateway's own `openai` provider is managed, these APIs answer 501 `not_supported`.

Every response carries `x-agentcc-request-id` and `x-agentcc-latency-ms`. A successful one also carries `x-agentcc-provider`.
