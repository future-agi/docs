## About

Agent Command Center reads `x-agentcc-*` request headers to control per-request behavior (caching, sessions, routing) and writes `x-agentcc-*` response headers to report what happened (which provider, latency, cost, cache status).

The Agent Command Center SDK handles these automatically. If you're using the OpenAI SDK or cURL, set them manually or use `create_headers()` to generate them.

---

## Request headers

### Tracking and correlation

| Header | Value | Description |
|---|---|---|
| `x-agentcc-trace-id` | string | Custom trace ID for distributed tracing. If omitted, the gateway generates one. |
| `x-agentcc-session-id` | string | Group related requests into a logical session for analytics. |

The gateway does not read `x-agentcc-session-name`, `x-agentcc-session-path`, `x-agentcc-user-id` or `x-agentcc-request-id` on requests. To identify the end user, set the `user` field in the request body. The request ID is generated by the gateway and returned in the `x-agentcc-request-id` response header.

### Metadata and properties

| Header | Value | Description |
|---|---|---|
| `x-agentcc-metadata` | JSON object | Arbitrary key-value pairs for cost attribution and filtering. Example: `{"team":"ml","env":"prod"}`. A value that is not a JSON object (such as `team=ml`) is not recorded; the request still goes through and the response carries `x-agentcc-metadata-error`. |

Keys that start with `auth_`, `key_`, `org_`, `budget_`, `ratelimit_`, `cache_`, `guardrail_`, `credit_` or `credits_` are reserved for the gateway and dropped without an error, as are a few exact names such as `cost`, `client_ip` and `timeout_ms`. A key named `org_name`, for example, is not recorded.

The gateway does not read `x-agentcc-property-{key}` headers. Put each property in `x-agentcc-metadata` instead.

### Cache control

| Header | Value | Description |
|---|---|---|
| `x-agentcc-cache-ttl` | duration (`60s`, `5m`, `1h`) | Override the cache TTL for this request. A bare number such as `300` is ignored. |
| `x-agentcc-cache-namespace` | string | Route to a specific cache namespace for isolation (e.g. `prod`, `staging`). |
| `x-agentcc-cache-force-refresh` | `true` | Bypass cache, fetch a fresh response from the provider, and update the cache with the new result. |
| `Cache-Control` | `no-store` | Disable caching entirely for this request. The response is not read from or written to cache. |

### Routing control

| Header | Value | Description |
|---|---|---|
| `x-agentcc-provider-lock` | string | Force this request to a specific provider, bypassing the routing strategy. Example: `openai`. |
| `x-agentcc-complexity-override` | string | Override complexity-based routing tier. Pass the tier name (e.g. `simple`, `moderate`, `complex`). |

### Guardrails

| Header | Value | Description |
|---|---|---|
| `X-Guardrail-Policy` | `log-only`, `disabled`, or `strict` | Self-hosted gateways: override how the rules in the gateway's own `config.yaml` run for this request (the organization's guardrail checks are not affected). `log-only` runs every guardrail without blocking, `disabled` skips them, and `strict` runs every guardrail in block mode. The virtual key must have `allow_policy_override: true` in its metadata, or the request is refused with `403`. Any other value returns `400 invalid_policy`. |

### Timeouts

| Header | Value | Description |
|---|---|---|
| `x-agentcc-request-timeout` | integer (ms) | Total request timeout in milliseconds. Also set automatically when using `TimeoutConfig.total` in the SDK. |
| `x-agentcc-timeout` | duration (`180s`, `3m`) | The same setting as a Go duration. Accepted on every endpoint. When both headers are sent, this one wins. |

Either header is held at `server.max_request_timeout`, and at the serving
provider's own `default_timeout`. Read `x-agentcc-timeout-ms` on the response
for the limit that was actually applied, which may be lower than you asked for.
A value that does not parse is ignored rather than rejected.

<Note>
The gateway does not read `x-agentcc-config`. Retry, fallback, routing and other settings sent in it (for example by the SDK's `GatewayConfig`) have no effect. Configure them on the gateway or in your organization's config instead.
</Note>

## Response headers

### Always present

| Header | Example | Description |
|---|---|---|
| `x-agentcc-request-id` | `01JD7Q8Z6X3M4N5P6R7S8T9V0W` | Unique identifier the gateway generates for this request. Use this when filing support tickets or searching logs. |
| `x-agentcc-trace-id` | `trace-x7y8z9` | Trace ID for distributed tracing. Matches the request header if one was sent. |
| `x-agentcc-provider` | `openai` | Which provider served this request. |
| `x-agentcc-model-used` | `gpt-4o-2024-08-06` | Actual model returned by the provider. May differ from the requested model if routing redirected the request. |
| `x-agentcc-latency-ms` | `342` | Total gateway latency in milliseconds, including the provider call. |
| `x-agentcc-timeout-ms` | `30000` | The limit that bounded this request: whichever is shortest of the timeout you asked for, `server.max_request_timeout`, and the serving provider's `default_timeout`. Gateway error responses can omit this header, so its absence on a 504 does not identify where the timeout occurred. Check the response body and gateway logs to distinguish a gateway timeout from one returned by a proxy or ingress. |

### Conditional

| Header | Present when | Value |
|---|---|---|
| `x-agentcc-cost` | Model has pricing data | Estimated cost in USD (e.g. `0.00234`). Omitted on exact cache hits. |
| `x-agentcc-cache` | The cache stage ran | `hit_exact`, `hit_semantic`, `hit_conditional`, `miss`, `skip`, or `skip_org_disabled`. `skip` means the request was not cacheable: streaming, sent with `Cache-Control: no-store`, or not a chat request (embeddings, audio, images) |
| `x-agentcc-metadata-error` | `x-agentcc-metadata` was not a JSON object | Reason the metadata was not recorded |
| `x-agentcc-guardrail-triggered` | A guardrail fired | `true` |
| `x-agentcc-fallback-used` | A provider fallback occurred | `true` |
| `x-agentcc-routing-strategy` | A routing policy is active | Strategy name: `round-robin`, `weighted`, `least-latency`, `cost-optimized`, `adaptive`, `fastest` |
| `x-agentcc-credits-remaining` | Managed key with credit balance | Remaining USD balance (e.g. `12.50`) |

### Rate limit headers

Present when a requests-per-minute limit applies to the key or org.

| Header | Description |
|---|---|
| `x-ratelimit-limit-requests` | Maximum requests allowed per minute |
| `x-ratelimit-remaining-requests` | Requests remaining in the current window |
| `x-ratelimit-reset-requests` | Seconds until the window resets |

## Reading headers

### Agent Command Center SDK

Every response from the Agent Command Center SDK has a `.agentcc` attribute with typed access to all gateway metadata:

```python
from agentcc import AgentCC

client = AgentCC(
    api_key="sk-agentcc-your-key",
    base_url="https://gateway.futureagi.com",
)

response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Hello"}],
)

print(response.choices[0].message.content)
print(response.agentcc.provider)            # openai
print(response.agentcc.latency_ms)          # 342
print(response.agentcc.cost)                # 0.00015
print(response.agentcc.cache_status)        # miss
print(response.agentcc.model_used)          # gpt-4o-2024-08-06
print(response.agentcc.request_id)          # 01JD7Q8Z6X3M4N5P6R7S8T9V0W
print(response.agentcc.trace_id)            # trace-x7y8z9
print(response.agentcc.guardrail_triggered) # False
print(response.agentcc.fallback_used)       # False
print(response.agentcc.routing_strategy)    # None (or "weighted", etc.)

# Rate limit info (when enabled)
if response.agentcc.ratelimit:
    print(response.agentcc.ratelimit.limit)
    print(response.agentcc.ratelimit.remaining)
    print(response.agentcc.ratelimit.reset)
```

### OpenAI SDK

The OpenAI SDK doesn't have `response.agentcc`. Use `with_raw_response` to read headers:

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://gateway.futureagi.com/v1",
    api_key="sk-agentcc-your-key",
)

raw = client.chat.completions.with_raw_response.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Hello"}],
)

print(raw.headers.get("x-agentcc-provider"))
print(raw.headers.get("x-agentcc-cost"))

response = raw.parse()
```

### cURL

Use the `-i` flag to include response headers in the output:

```bash
curl -i -X POST https://gateway.futureagi.com/v1/chat/completions \
  -H "Authorization: Bearer sk-agentcc-your-key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-4o",
    "messages": [{"role": "user", "content": "Hello"}]
  }'
```

## Setting request headers

### Agent Command Center SDK

The SDK accepts tracking parameters directly on each `create()` call:

```python
from agentcc import AgentCC

client = AgentCC(
    api_key="sk-agentcc-your-key",
    base_url="https://gateway.futureagi.com",
)

response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Hello"}],
    session_id="sess-abc",
    trace_id="trace-123",
    request_metadata={"team": "ml", "feature": "search", "env": "prod"},
    user="user-42",  # end user, read from the request body
)
```

The SDK's `user_id` and `properties` parameters send `x-agentcc-user-id` and `x-agentcc-property-*` headers, which the gateway does not read. Use the body `user` field and `request_metadata` instead.

To set cache headers on every request, pass them as default headers. Cache TTL must be a duration string:

```python
from agentcc import AgentCC

client = AgentCC(
    api_key="sk-agentcc-your-key",
    base_url="https://gateway.futureagi.com",
    default_headers={
        "x-agentcc-cache-ttl": "5m",
        "x-agentcc-cache-namespace": "prod",
    },
)

# Per-request override
response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Hello"}],
    extra_headers={"x-agentcc-cache-force-refresh": "true"},
)
```

<Warning>
`GatewayConfig` sends most of its settings in `x-agentcc-config`, which the gateway ignores, and sends `CacheConfig(ttl=300)` as a bare number, which the gateway also ignores. Its `guardrails` policy names go in `x-agentcc-guardrail-policy`, which the gateway also ignores: it reads only `X-Guardrail-Policy`. Only its cache namespace, force-refresh and total-timeout settings take effect.
</Warning>

### OpenAI SDK with create_headers()

Use `create_headers()` to generate all `x-agentcc-*` headers for the OpenAI SDK:

```python
from openai import OpenAI
from agentcc import create_headers

headers = create_headers(
    trace_id="trace-abc",
    session_id="sess-123",
    metadata={"team": "ml", "env": "production"},
    cache_namespace="prod",
)

client = OpenAI(
    api_key="sk-agentcc-your-key",
    base_url="https://gateway.futureagi.com/v1",
    default_headers=headers,
)

response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Hello"}],
)
```

### cURL

Pass headers with `-H`:

```bash
curl -X POST https://gateway.futureagi.com/v1/chat/completions \
  -H "Authorization: Bearer sk-agentcc-your-key" \
  -H "x-agentcc-session-id: sess-abc" \
  -H "x-agentcc-trace-id: trace-123" \
  -H "x-agentcc-metadata: {\"team\":\"ml\",\"env\":\"prod\"}" \
  -H "x-agentcc-cache-ttl: 5m" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-4o",
    "messages": [{"role": "user", "content": "Hello"}],
    "user": "user-42"
  }'
```
