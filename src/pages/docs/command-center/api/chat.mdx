## About

`POST /v1/chat/completions` is the main endpoint. It works exactly like the OpenAI API — same request body, same response format. Agent Command Center adds routing, guardrails, and cost tracking transparently (and response caching on a self-hosted gateway), and supports streaming via SSE.

## Basic usage

<Tabs items={["Python (Agent Command Center SDK)", "Python (OpenAI SDK)", "LiteLLM", "cURL"]}>

<Tab title="Python (Agent Command Center SDK)">

```python
from agentcc import AgentCC

client = AgentCC(
    api_key="sk-agentcc-your-key",
    base_url="https://gateway.futureagi.com",
)

response = client.chat.completions.create(
    model="gpt-4o",
    messages=[
        {"role": "system", "content": "You are a helpful assistant."},
        {"role": "user", "content": "What is the capital of France?"},
    ],
)

print(response.choices[0].message.content)
```

## Request body

All standard OpenAI chat completion parameters are supported:

| Parameter | Type | Description |
|---|---|---|
| `model` | string | **Required.** The model to use (e.g., `gpt-4o`, `claude-sonnet-4-6`). |
| `messages` | array | **Required.** The conversation messages. See [Message format](#message-format) below. |
| `temperature` | number | Sampling temperature (0-2). |
| `top_p` | number | Nucleus sampling (0-1). |
| `n` | integer | Number of completions to generate. |
| `stream` | boolean | Enable SSE streaming. See [Streaming](#streaming). |
| `stream_options` | object | Set `include_usage: true` to get one more chunk, with an empty `choices` array and the billed `usage`, right before `[DONE]`. Without it and without the `x-agentcc-include-metadata` header, `usage` rides on the last chunk that has choices, the one with `finish_reason`. See [Streaming](#streaming). |
| `stop` | string or array | Stop sequences. |
| `max_tokens` | integer | Maximum tokens to generate. |
| `max_completion_tokens` | integer | Max tokens for o1/o3-style models. |
| `presence_penalty` | number | Penalize repeated topics (-2 to 2). |
| `frequency_penalty` | number | Penalize repeated tokens (-2 to 2). |
| `logit_bias` | object | Token ID to bias value mapping. |
| `logprobs` | boolean | Return log probabilities. |
| `top_logprobs` | integer | Number of top log probs per token (0-20). |
| `user` | string | End-user ID for tracking and rate limiting. |
| `seed` | integer | Seed for reproducible outputs. |
| `tools` | array | Function definitions for tool/function calling. |
| `tool_choice` | string or object | `"auto"`, `"none"`, `"required"`, or a specific tool. |
| `response_format` | object | `{type: "json_object"}` or `{type: "json_schema", json_schema: {...}}`. |
| `modalities` | array | Output modalities, e.g., `["text", "audio"]`. |
| `audio` | object | Audio output config: `{voice: "alloy", format: "wav"}`. |

<Tip>
On providers that use the OpenAI format, fields Agent Command Center does not know, such as a vendor extension, are passed through to the provider.
</Tip>

### Fields a translated request does not carry

A request to Anthropic, AWS Bedrock, or Google Gemini is rebuilt in that provider's own format, and these fields are left out, with no error or header to say so:

| Provider | Fields not sent |
|---|---|
| Anthropic, AWS Bedrock | `n`, `seed`, `presence_penalty`, `frequency_penalty`, `logit_bias`, `logprobs`, `top_logprobs`, `user`, `service_tier`, a `response_format` of type `json_object` (a `json_schema` format is sent), and a request for extended thinking (`thinking`, `thinking_budget`, or `reasoning_effort`) |
| Google Gemini | `n`, `seed`, `presence_penalty`, `frequency_penalty`, `logit_bias`, `logprobs`, `top_logprobs`, `user`, and `service_tier`. A `json_object` or `json_schema` format, `thinking_budget`, and `reasoning_effort` are sent |

Requests to providers that use the OpenAI format carry these fields as sent.

## Response body

```json
{
  "id": "chatcmpl-abc123",
  "object": "chat.completion",
  "created": 1711000000,
  "model": "gpt-4o-2024-08-06",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "The capital of France is Paris."
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 25,
    "completion_tokens": 8,
    "total_tokens": 33
  }
}
```

| Field | Description |
|---|---|
| `choices[].finish_reason` | `"stop"` (natural end), `"length"` (hit max tokens), `"tool_calls"` (model wants to call a function), `"content_filter"` (blocked by provider) |
| `usage` | Token counts. Always present on non-streaming responses. |

## Streaming

Set `stream: true` to receive the response as Server-Sent Events (SSE). Each chunk arrives as a `data:` line:

```
data: {"id":"chatcmpl-abc","object":"chat.completion.chunk","choices":[{"index":0,"delta":{"content":"The"},"finish_reason":null}]}

data: {"id":"chatcmpl-abc","object":"chat.completion.chunk","choices":[{"index":0,"delta":{"content":" capital"},"finish_reason":null}]}

...

data: {"id":"chatcmpl-abc","object":"chat.completion.chunk","choices":[{"index":0,"delta":{},"finish_reason":"stop"}],"usage":{"prompt_tokens":25,"completion_tokens":8,"total_tokens":33}}

data: [DONE]
```

Where the stream's usage goes depends on what you ask for:

- **Without `stream_options.include_usage` or the `x-agentcc-include-metadata` header**, no chunk has an empty `choices` array. The usage the request is billed for rides on the last chunk that has choices, the one with `finish_reason`, as above. The gateway holds the finish chunk (with `n` above 1, each choice's) until the provider's stream has ended and the request is metered, then sends it, the usage on the last one. A provider stream that never sends a `finish_reason` gives no usage this way.
- **With `"stream_options": {"include_usage": true}`**, you get OpenAI's shape: exactly one chunk with an empty `choices` array, right before `[DONE]`, carrying the billed `usage`. No other chunk carries usage.
- **With the header `x-agentcc-include-metadata: 1`** (or `true`), you get that final chunk too, and it also carries `agentcc_metadata` with the request's `cost` and `latency_ms`.

The gateway asks the provider for usage on every chat stream and meters the stream on it, whatever you ask for. The provider's own usage is never forwarded, so the usage arrives once. The examples below check `choices` before reading `choices[0]`, so they work with either shape.

<Tabs items={["Python (Agent Command Center SDK)", "Python (OpenAI SDK)", "LiteLLM", "cURL"]}>

<Tab title="Python (Agent Command Center SDK)">

```python
from agentcc import AgentCC

client = AgentCC(
    api_key="sk-agentcc-your-key",
    base_url="https://gateway.futureagi.com",
)

stream = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Write a haiku about coding"}],
    stream=True,
)

for chunk in stream:
    if chunk.choices and chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end="", flush=True)
```

### Streaming behavior

- **Pre-request plugins** (guardrails, rate limiting, etc.) run before the stream starts. If a guardrail blocks the request, you get a 403 JSON error response with `"code": "content_blocked"`, not a stream.
- **Post-response plugins** (cost, logging, metrics) run when the provider's stream ends, once token usage is known, and before the chunk that carries the usage is sent.
- **Cache**: Streaming requests bypass the cache entirely, both on read and write.
- **Failover**: Not supported mid-stream. If the provider fails after streaming starts, the error appears as an SSE data event.
- **Client disconnect**: Post-plugins still run even if you disconnect early, so cost tracking stays accurate.

## Function calling

Define tools in the request, and the model can choose to call them. The response will have `finish_reason: "tool_calls"` with the function name and arguments.

<Tabs items={["Python (Agent Command Center SDK)", "Python (OpenAI SDK)", "LiteLLM", "cURL"]}>

<Tab title="Python (Agent Command Center SDK)">

```python
import json
from agentcc import AgentCC

client = AgentCC(
    api_key="sk-agentcc-your-key",
    base_url="https://gateway.futureagi.com",
)

tools = [
    {
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "Get current weather for a location",
            "parameters": {
                "type": "object",
                "properties": {
                    "location": {"type": "string", "description": "City name"},
                },
                "required": ["location"],
            },
        },
    }
]

messages = [{"role": "user", "content": "What's the weather in Tokyo?"}]

# First call: model decides to call a tool
response = client.chat.completions.create(
    model="gpt-4o",
    messages=messages,
    tools=tools,
    tool_choice="auto",
)

if response.choices[0].finish_reason == "tool_calls":
    # Add the assistant's tool call to the conversation
    messages.append(response.choices[0].message)

    # Execute each tool call and add the result
    for tool_call in response.choices[0].message.tool_calls:
        args = json.loads(tool_call.function.arguments)
        result = {"temperature": "22°C", "condition": "Sunny"}  # your function here

        messages.append({
            "role": "tool",
            "tool_call_id": tool_call.id,
            "content": json.dumps(result),
        })

    # Second call: model uses the tool result to respond
    final = client.chat.completions.create(
        model="gpt-4o",
        messages=messages,
        tools=tools,
    )
    print(final.choices[0].message.content)
```

On providers that use the OpenAI format, Agent Command Center sends your tool definitions as you wrote them. ## Structured outputs

Force the model to return valid JSON matching a schema:

```python
response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "List 3 European capitals"}],
    response_format={
        "type": "json_schema",
        "json_schema": {
            "name": "capitals",
            "schema": {
                "type": "object",
                "properties": {
                    "capitals": {
                        "type": "array",
                        "items": {"type": "string"},
                    }
                },
                "required": ["capitals"],
            },
        },
    },
)
```

On providers that use the OpenAI format, Agent Command Center forwards `response_format` as sent, and the provider handles constrained decoding. Use `"type": "json_object"` for simpler JSON without a schema. Anthropic and AWS Bedrock are sent a `json_schema` format but not a `json_object` one; Gemini is sent both. See [Fields a translated request does not carry](#fields-a-translated-request-does-not-carry).

## Message format

Each message in the `messages` array has:

| Field | Type | Description |
|---|---|---|
| `role` | string | `"system"`, `"user"`, `"assistant"`, or `"tool"` |
| `content` | string or array | Text string, or array of content parts for multimodal inputs |
| `name` | string | Optional sender name |
| `tool_calls` | array | Tool calls made by the assistant (on assistant messages) |
| `tool_call_id` | string | ID of the tool call this message responds to (on tool messages) |

---

## Response headers

Agent Command Center adds these headers to every response (streaming and non-streaming):

| Header | Description |
|---|---|
| `x-agentcc-request-id` | Unique request ID for log correlation |
| `x-agentcc-provider` | Which provider handled the request (e.g., `openai`) |
| `x-agentcc-latency-ms` | Total latency in milliseconds |
| `x-agentcc-model-used` | Actual model returned by the provider |
| `x-agentcc-cost` | Estimated cost in USD |
| `x-agentcc-cache` | Cache status (`hit_exact`, `hit_semantic`, or `miss`), on a gateway that runs the response cache. The hosted gateway does not |
| `x-agentcc-guardrail-triggered` | `true` if a guardrail fired |
| `x-agentcc-fallback-used` | `true` if a fallback provider or model was used |
| `x-agentcc-routing-strategy` | Which routing strategy was applied |
| `x-agentcc-credits-remaining` | Remaining credit balance (managed keys, which are not enabled on Future AGI's hosted gateway) |
| `x-ratelimit-limit-requests` | Rate limit ceiling |
| `x-ratelimit-remaining-requests` | Remaining requests in current window |

## Switching providers

Change the model name to route to a different provider. The request format stays identical:

```python
# OpenAI
response = client.chat.completions.create(model="gpt-4o", messages=messages)

# Anthropic
response = client.chat.completions.create(model="claude-sonnet-4-6", messages=messages)

# Gemini
response = client.chat.completions.create(model="gemini-2.0-flash", messages=messages)
```

Agent Command Center translates the request to each provider's native format. Your code doesn't change.
