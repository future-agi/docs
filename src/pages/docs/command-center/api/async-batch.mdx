## About

Agent Command Center supports two modes for deferred processing: **async inference** sends a single request and returns a job ID you poll for the result, and **batch processing** submits many requests at once and runs them concurrently through the gateway.

Both modes take the same chat completion request body as synchronous requests. Batch requests are billed at the provider's normal rate: the gateway sends each one as a regular chat completion, not through a provider's discounted batch API.

---

## Endpoints

| Method | Path | Description |
|---|---|---|
| GET | `/v1/async/{job_id}` | Get async job status and result |
| DELETE | `/v1/async/{job_id}` | Cancel an async job |
| POST | `/v1/scheduled` | Schedule a completion for later |
| GET | `/v1/scheduled` | List scheduled jobs |
| GET | `/v1/scheduled/{job_id}` | Get a scheduled job |
| DELETE | `/v1/scheduled/{job_id}` | Cancel a scheduled job |
| POST | `/-/batches` | Submit a batch (admin token) |
| GET | `/-/batches/{batch_id}` | Get batch status and results (admin token) |
| POST | `/-/batches/{batch_id}/cancel` | Cancel a batch (admin token) |

## Async inference

Send a chat completion request with the `x-agentcc-async: true` header. The gateway returns `202 Accepted` immediately with a job body instead of a chat completion:

```json
{
  "job_id": "async-3f9c2a7d1e8b4c6a5d0f2e1b",
  "status": "queued",
  "created_at": "2026-04-05T09:00:00Z",
  "expires_at": "2026-04-06T10:00:00Z"
}
```

Poll the job endpoint to get the result when it's ready. Results are kept for one hour after the job finishes by default; set `x-agentcc-async-job-result-ttl` (seconds) to change this.

### Sending an async request

<Tabs items={["OpenAI SDK", "cURL"]}>

<Tab title="Python (OpenAI SDK)">

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://gateway.futureagi.com/v1",
    api_key="sk-agentcc-your-key",
)

# Send async request with x-agentcc-async header.
# The body is a job, not a chat completion, so read the raw response.
raw = client.chat.completions.with_raw_response.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Write a detailed essay about climate change"}],
    extra_headers={"x-agentcc-async": "true"},
)

job_id = raw.http_response.json()["job_id"]
print(f"Job ID: {job_id}")
```

</Tab>

<Tab title="cURL">

```bash
curl -X POST https://gateway.futureagi.com/v1/chat/completions \
  -H "Authorization: Bearer sk-agentcc-your-key" \
  -H "Content-Type: application/json" \
  -H "x-agentcc-async: true" \
  -d '{
    "model": "gpt-4o",
    "messages": [{"role": "user", "content": "Write a detailed essay about climate change"}]
  }'
```

</Tab>

</Tabs>

### Polling for results

```python
import time
import requests

headers = {"Authorization": "Bearer sk-agentcc-your-key"}

while True:
    resp = requests.get(
        f"https://gateway.futureagi.com/v1/async/{job_id}",
        headers=headers,
    )
    data = resp.json()

    if data["status"] == "completed":
        print(data["response"]["choices"][0]["message"]["content"])
        break
    elif data["status"] == "failed":
        print(f"Job failed: {data.get('error')}")
        break
    elif data["status"] == "cancelled":
        print("Job was cancelled")
        break
    else:
        time.sleep(2)
```

The poll response is the job itself: `id` (the `job_id` from submission), `status`, `endpoint_type`, `created_at`, `started_at`, `completed_at`, `expires_at`, and `response` or `error` once the job finishes.

### Job statuses

| Status | Description |
|---|---|
| `queued` | Job is waiting for a worker |
| `processing` | Job is being processed |
| `completed` | Result is ready |
| `failed` | Job failed (check `error` field) |
| `cancelled` | Job was cancelled |

## Scheduled completions

Schedule a request to run at a specific time. Useful for time-sensitive content generation or deferred workloads.

```bash
curl -X POST https://gateway.futureagi.com/v1/scheduled \
  -H "Authorization: Bearer sk-agentcc-your-key" \
  -H "Content-Type: application/json" \
  -d '{
    "scheduled_at": "2026-04-05T09:00:00Z",
    "request": {
      "model": "gpt-4o",
      "messages": [{"role": "user", "content": "Generate the daily summary report"}]
    }
  }'
```

### Managing scheduled jobs

```bash
# List scheduled jobs
curl https://gateway.futureagi.com/v1/scheduled \
  -H "Authorization: Bearer sk-agentcc-your-key"

# Get a specific job
curl https://gateway.futureagi.com/v1/scheduled/job_123 \
  -H "Authorization: Bearer sk-agentcc-your-key"

# Cancel a scheduled job
curl -X DELETE https://gateway.futureagi.com/v1/scheduled/job_123 \
  -H "Authorization: Bearer sk-agentcc-your-key"
```

## Batch processing

For high-volume workloads, submit a list of chat completion requests to `/-/batches`. The gateway runs them concurrently through the normal request pipeline and returns all results together once the batch finishes.

<Note>
Batch endpoints are admin endpoints on a gateway you run yourself. They require that gateway's admin token (`AGENTCC_ADMIN_TOKEN`) as the Bearer token, not a virtual key. There is no OpenAI-compatible `/v1/batches` endpoint, so `client.batches.create()` from the OpenAI SDK does not work through the gateway.
</Note>

### Creating a batch

Send a `requests` array of chat completion bodies. `max_concurrency` is optional and defaults to 10.

<Tabs items={["Python", "cURL"]}>

<Tab title="Python">

```python
import requests

headers = {"Authorization": "Bearer your-admin-token"}

resp = requests.post(
    "https://<your-gateway>/-/batches",
    headers=headers,
    json={
        "requests": [
            {
                "model": "gpt-4o-mini",
                "messages": [{"role": "user", "content": "Summarize: Machine learning is..."}],
            },
            {
                "model": "gpt-4o-mini",
                "messages": [{"role": "user", "content": "Summarize: Neural networks are..."}],
            },
        ],
        "max_concurrency": 5,
    },
)
batch = resp.json()
print(f"Batch ID: {batch['batch_id']}, Status: {batch['status']}")
```

</Tab>

<Tab title="cURL">

```bash
curl -X POST https://<your-gateway>/-/batches \
  -H "Authorization: Bearer your-admin-token" \
  -H "Content-Type: application/json" \
  -d '{
    "requests": [
      {"model": "gpt-4o-mini", "messages": [{"role": "user", "content": "Summarize: Machine learning is..."}]},
      {"model": "gpt-4o-mini", "messages": [{"role": "user", "content": "Summarize: Neural networks are..."}]}
    ],
    "max_concurrency": 5
  }'
```

</Tab>

</Tabs>

The gateway returns `202 Accepted` with `batch_id`, `status` (`processing`), `total`, `max_concurrency` and `created_at`.

### Checking status and reading results

```python
import time

while True:
    batch = requests.get(
        f"https://<your-gateway>/-/batches/{batch['batch_id']}",
        headers=headers,
    ).json()
    print(f"Status: {batch['status']}")

    if batch["status"] in ("completed", "cancelled"):
        break
    time.sleep(5)

for result in batch["results"]:
    if result["status"] == "success":
        print(f"{result['index']}: {result['response']['choices'][0]['message']['content'][:100]}")
    else:
        print(f"{result['index']}: {result['status']} {result.get('error', '')}")

print(batch["summary"])
```

A batch is `processing` until every request finishes, then `completed`. `results` and `summary` (total cost, input and output tokens, and completed, failed and cancelled counts) appear only once the batch is `completed` or `cancelled`. Each result has an `index` matching its position in `requests` and a `status` of `success`, `error` or `cancelled`.

To stop a running batch, call `POST /-/batches/{batch_id}/cancel`. Batches are held in gateway memory and removed one hour after they finish, so read the results before then.

## When to use each mode

| Mode | Best for | Latency | Cost |
|---|---|---|---|
| Synchronous | Interactive apps, real-time responses | Lowest | Standard |
| Async | Long-running requests, fire-and-forget | Medium (poll) | Standard |
| Scheduled | Time-triggered jobs, deferred work | Scheduled | Standard |
| Batch | High-volume processing, data pipelines | Until the slowest request finishes | Standard |
