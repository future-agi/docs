## The problem

You can point your existing OpenAI SDK at [Agent Command Center](/docs/command-center) by changing two lines: `base_url` and `api_key`. But a model answers the same way whether you call it directly or through the gateway, so the text of the reply doesn't tell you which path it took. To prove a request used the gateway, match the provider and request ID on the response with a gateway log entry.

## What you'll build

A chat request whose path you can verify, then the same client switched to another configured provider. All providers work through the same API. No new SDK required.

You'll:

1. Send a request using a gateway key and a model your organization has configured.
2. Identify the serving provider in the [response headers](/docs/command-center/api/headers).
3. Match that call to its [request log](/docs/command-center/features/observability).
4. Switch to a second provider without replacing the client.

<Prerequisites title="Before you start">
- A Future AGI account. Sign up at [app.futureagi.com](https://app.futureagi.com).
- A Command Center API key, found in your dashboard under **Settings > API Keys**. Keys start with `sk-agentcc-`. This is a gateway [virtual key](/docs/command-center/concepts/virtual-keys), not a provider key.
- At least one [provider configured](/docs/command-center/features/providers), such as OpenAI, Anthropic or Google. The first examples call `gpt-4o-mini`; the provider switch needs a second configured provider.
</Prerequisites>

## Prepare the client settings

<div class="sdk-ref-table">

| Setting | What to set | Where to find it |
| --- | --- | --- |
| `api_key` | Your Command Center API key. It starts with `sk-agentcc-` | **Settings > API Keys** |
| `base_url` | `https://gateway.futureagi.com/v1` | Same for every client on this page |
| `model` | A model from a provider you configured, such as `gpt-4o-mini` | **Gateway > Providers** |

</div>

## Send the first request

If you already use the OpenAI SDK, change two lines and you're done. For a TypeScript client, see the [streaming](/docs/command-center/features/streaming) examples.

<Tabs items={["Python (OpenAI SDK)", "Python (Agent Command Center SDK)", "LiteLLM", "cURL"]}>


<Tab title="Python (OpenAI SDK)">

```python
from openai import OpenAI

# Already using OpenAI? Just swap base_url and api_key
client = OpenAI(
    base_url="https://gateway.futureagi.com/v1",
    api_key="sk-agentcc-your-api-key-here",
)

response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "What is the capital of France?"}],
)

print(response.choices[0].message.content)
# Output: Paris
```

## Check the response headers

Command Center adds metadata to every response so you can see what happened.

1. Send this request with the OpenAI SDK client from your first request. The code comments call that Step 1.

```python
# Using the OpenAI SDK client from Step 1
response = client.chat.completions.with_raw_response.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Hello"}],
)

print(f"Provider:  {response.headers.get('x-agentcc-provider')}")
print(f"Latency:   {response.headers.get('x-agentcc-latency-ms')}ms")
print(f"Cost:      ${response.headers.get('x-agentcc-cost')}")
print(f"Cache:     {response.headers.get('x-agentcc-cache')}")
print(f"Model:     {response.headers.get('x-agentcc-model-used')}")

# Parse the actual response
completion = response.parse()
print(f"Response:  {completion.choices[0].message.content}")
```

Example output:

```
Provider:  openai
Latency:   423ms
Cost:      $0.000045
Cache:     miss
Model:     gpt-4o-mini
Response:  Hello! How can I help you today?
```

2. Read the `x-agentcc-request-id` header from the same `response.headers`.
3. Open **Gateway > Request Logs**.
4. Find the entry with the same request ID.

   The log entry should show the same provider that `x-agentcc-provider` named. The cache header is present only when caching is enabled, and the [cost](/docs/command-center/features/cost-tracking) header only when the model has pricing data.

## Switch providers

Change the model name to route to a different provider. Using the same client as your first request, run the calls your configured providers can serve:

```python
# OpenAI
response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Hello"}]
)

# Anthropic
response = client.chat.completions.create(
    model="claude-sonnet-4-6",
    messages=[{"role": "user", "content": "Hello"}]
)

# Google Gemini
response = client.chat.completions.create(
    model="gemini-2.0-flash",
    messages=[{"role": "user", "content": "Hello"}]
)
```

Command Center translates the request to each provider's native format. Your code doesn't change.

Repeat the header check on the second call. A different value in `x-agentcc-provider`, not a difference in the reply's wording, shows that the switch worked.

## Try streaming

Stream responses to show output as it arrives:

<Tabs items={["Python (OpenAI SDK)", "LiteLLM", "cURL"]}>


<Tab title="Python (OpenAI SDK)">

```python
stream = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Write a short poem about AI"}],
    stream=True,
)

for chunk in stream:
    if chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end="", flush=True)
```

## Using a framework?

Command Center works with any OpenAI-compatible client. If you use LangChain, LlamaIndex, or any other framework that supports custom base URLs, just point it at `https://gateway.futureagi.com/v1` with your Command Center key.

## Troubleshooting

- **401 `unauthorized`:** the API key is missing or invalid. Check that the request carries your `sk-agentcc-` key, not a provider key.
- **404 `model_not_found`:** the model is not configured for any provider. Call `GET /v1/models` with your key to see what is available, or try the `provider/model` format. [Error handling](/docs/command-center/guides/errors) lists every code.
- **No `x-agentcc-` headers:** check that `base_url` points to the gateway, and read the raw response headers, not only the completion body.
