## About

Each Agent Command Center organization is an isolated environment with its own providers, routing rules, rate limits, budgets, and API keys. Organizations are the top-level unit for multi-tenancy in Agent Command Center.

---

## Organization settings

Organization config controls all gateway behavior for that org. Settings are managed via the dashboard or the control-plane API.

<Tabs items={["Dashboard", "cURL"]}>

<Tab title="Dashboard">

In the Future AGI dashboard:

- **Gateway > Settings**, **Org Config** tab: view and edit org-level gateway configuration (providers, routing, caching, rate limits, budgets, and more). Click **Edit Config** to change it.
- **Gateway > Providers**: add provider API keys
- **Gateway > API Keys**: view and manage the org's API keys
- **Settings > Members**: manage members and roles
- **Settings > Org Settings**: organization-wide settings (Owner and Admin only)

</Tab>

<Tab title="cURL">

The org is taken from the Future AGI API key you call with:

```bash
# Get the active org config
curl https://api.futureagi.com/agentcc/org-configs/active/ \
  -H "X-Api-Key: YOUR_API_KEY" \
  -H "X-Secret-Key: YOUR_SECRET_KEY"

# Save a new config version (sections left out are reset to defaults)
curl -X POST https://api.futureagi.com/agentcc/org-configs/ \
  -H "X-Api-Key: YOUR_API_KEY" \
  -H "X-Secret-Key: YOUR_SECRET_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "rate_limiting": {"enabled": true, "per_key_rpm": 1000},
    "budgets": {"enabled": true, "org_limit": 500.0, "org_period": "monthly", "hard_limit": true}
  }'
```

Each `POST` creates a new version from the body and makes it active, so include every section you want to keep. See [Configuration](/docs/command-center/concepts/configuration#example-configuration) for the accepted keys.

</Tab>

</Tabs>

## Members and roles

Organizations can have multiple members with different roles.

| Role | Permissions |
|---|---|
| **Owner** | Full access. Can delete the org, manage billing, and change all settings. |
| **Admin** | Can manage providers, keys, routing, budgets, and members (except owner). |
| **Member** | Can view config and create API keys. Cannot change org settings. |
| **Viewer** | Read-only access to dashboard, logs, and analytics. |

### Managing members

Members are managed through the Future AGI dashboard at **Settings > Members**. Invite new members by email. Each member can belong to multiple organizations.

## API key management

Each organization has its own pool of API keys (virtual keys). Keys inherit org-level settings and can have additional per-key restrictions.

Create and revoke keys under **Gateway > API Keys** in the dashboard, or with the control-plane API:

```bash
# List keys for the org
curl https://api.futureagi.com/agentcc/api-keys/ \
  -H "X-Api-Key: YOUR_API_KEY" \
  -H "X-Secret-Key: YOUR_SECRET_KEY"

# Create a new key (the full key is returned only in this response)
curl -X POST https://api.futureagi.com/agentcc/api-keys/ \
  -H "X-Api-Key: YOUR_API_KEY" \
  -H "X-Secret-Key: YOUR_SECRET_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name": "backend-service", "allowed_models": ["gpt-4o", "gpt-4o-mini"]}'

# Revoke a key
curl -X POST https://api.futureagi.com/agentcc/api-keys/KEY_ID/revoke/ \
  -H "X-Api-Key: YOUR_API_KEY" \
  -H "X-Secret-Key: YOUR_SECRET_KEY"
```

A key takes `name`, `owner`, `allowed_models`, `allowed_providers`, and `metadata`. Rate limits are not set per key here: the org config's `rate_limiting.per_key_rpm` applies to every key.

See [Virtual keys & access control](/docs/command-center/concepts/virtual-keys) for detailed key configuration (RBAC, IP ACL, model restrictions).

## Multi-tenancy patterns

### One org per customer

For SaaS products, create a separate org per customer. Each customer gets isolated providers, budgets, and rate limits:

- Customer A: budget $100/month, access to gpt-4o-mini only
- Customer B: budget $500/month, access to gpt-4o and claude-sonnet-4-6
- Customer C: unlimited budget, all models

### One org with per-key isolation

For internal teams, use a single org with per-key restrictions:

- Marketing team key: gpt-4o-mini only, budget $200/month
- Engineering team key: gpt-4o and claude-sonnet-4-6, budget $1000/month
- Data science key: all models, no budget cap

Model restrictions are set on the key. Per-key budgets go in the org config's `budgets.keys` section, keyed by key name. The org's `per_key_rpm` gives every key the same RPM limit; a different RPM per key is only possible on a self-hosted gateway, with `rate_limit_rpm` on the key in `config.yaml`.
