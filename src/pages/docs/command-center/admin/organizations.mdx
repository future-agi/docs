Each Agent Command Center organization is an isolated environment with its own [providers](/docs/command-center/features/providers), [routing rules](/docs/command-center/features/routing), [rate limits and budgets](/docs/command-center/features/rate-limiting), and [virtual keys](/docs/command-center/concepts/virtual-keys). Organizations are the top-level unit for multi-tenancy in Agent Command Center.

Use one organization per customer to keep each customer's settings apart. If internal teams share those settings, keep one organization and give each team its own key instead.

<Prerequisites title="Before you start">
- An Owner or Admin role to change organization settings. Members can view the config and create API keys.
- A provider configured in the organization, if you want to send the test request at the end.
</Prerequisites>

## Choose org-level or per-key settings

Organization config controls all gateway behavior for that org. Keys inherit org-level settings and can have additional per-key restrictions. Set shared defaults on the organization, and restrict a key when only one caller needs a model allowlist, an IP restriction, a budget or a requests-per-minute (RPM) limit.

### One org per customer

For SaaS products, create a separate org per customer. Each customer gets isolated providers, budgets, and rate limits:

- Customer A: budget $100/month, access to gpt-4o-mini only
- Customer B: budget $500/month, access to gpt-4o and claude-sonnet-4-6
- Customer C: unlimited budget, all models

### One org with per-key isolation

For internal teams, use a single org with per-key restrictions:

- Marketing team key: rate limit 50 RPM, budget $200/month
- Engineering team key: rate limit 500 RPM, budget $1000/month
- Data science key: rate limit 200 RPM, all models, no budget cap

## Check your role

Organizations can have multiple members with different roles.

<div class="sdk-ref-table max-sm:[&_td]:px-1.5! max-sm:[&_th]:px-1.5!">

| Role | Permissions |
|---|---|
| **Owner** | Full access. Can delete the org, manage billing, and change all settings. |
| **Admin** | Can manage providers, keys, routing, budgets, and members (except owner). |
| **Member** | Can view config and create API keys. Cannot change org settings. |
| **Viewer** | Read-only access to dashboard, logs, and analytics. |

</div>

Members are managed through the Future AGI dashboard. Each member can belong to multiple organizations. To add someone:

1. Open **Settings > Members**.
2. Invite the new member by email.

## Change organization settings

Settings are managed via the dashboard or the admin API.

<Tabs items={["Dashboard", "Python (Agent Command Center SDK)", "TypeScript (Agent Command Center SDK)"]}>

<Tab title="Dashboard">

Go to **Settings > Organization** in the Future AGI dashboard. From here you can:

- View and edit org-level configuration (providers, routing, caching, etc.)
- Manage members and roles
- View API key inventory
- Set budgets and rate limits

</Tab>

<Tab title="Python (Agent Command Center SDK)">

```python
from agentcc import AgentCC

# base_url = inference gateway, control_plane_url = admin/config API
client = AgentCC(
    api_key="sk-agentcc-your-key",
    base_url="https://gateway.futureagi.com",
    control_plane_url="https://api.futureagi.com",
)

# Get org config
config = client.org_configs.retrieve(org_id="your-org-id")

# Update org config
client.org_configs.update(
    org_id="your-org-id",
    config={
        "rate_limiting": {
            "enabled": True,
            "rpm": 1000,
        },
        "budgets": {
            "limit": 500.00,
            "period": "monthly",
        },
    },
)
```

</Tab>

<Tab title="TypeScript (Agent Command Center SDK)">

```typescript
import { AgentCC } from "@futureagi/agentcc";

const client = new AgentCC({
    apiKey: "sk-agentcc-your-key",
    baseUrl: "https://gateway.futureagi.com",
    controlPlaneUrl: "https://api.futureagi.com",
});

const config = await client.orgConfigs.retrieve({
    orgId: "your-org-id",
});

await client.orgConfigs.update({
    orgId: "your-org-id",
    config: {
        rate_limiting: {
            enabled: true,
            rpm: 1000,
        },
        budgets: {
            limit: 500.0,
            period: "monthly",
        },
    },
});
```

</Tab>

</Tabs>

A budget or rate limit set here applies to the whole organization. For a restriction that applies to only one service, use its key instead.

## Create a key for one service

Each organization has its own pool of API keys (virtual keys).

1. Open **Settings > API Keys** in the Future AGI dashboard.
2. Create a virtual key for the service.
3. Store the new key securely when it is shown.

   The full key is shown only at creation.

The Python SDK does the same job. This example lists the keys for an org, creates a `backend-service` key limited to 100 RPM and two models, then revokes it:

```python
# List keys for an org
keys = client.keys.list(org_id="your-org-id")
for key in keys:
    print(f"{key.name}: {key.key_prefix}...")

# Create a new key
new_key = client.keys.create(
    org_id="your-org-id",
    name="backend-service",
    rate_limit_rpm=100,
    allowed_models=["gpt-4o", "gpt-4o-mini"],
)
print(f"Key: {new_key.key}")  # full key shown only at creation

# Revoke a key
client.keys.delete(key_id=new_key.id)
```

The virtual keys page linked above covers detailed key configuration (RBAC, IP ACL, model restrictions).

## Check the key with a request

1. Send a [gateway request](/docs/command-center/quickstart) with the new virtual key and a model the key allows.
2. Open **Agent Command Center > Logs**.

   You should see a [request log](/docs/command-center/features/observability) entry for the call. To find it, search for the `x-agentcc-request-id` value from the [response headers](/docs/command-center/api/headers). The entry shows the provider that handled the request.

## Use the right credential

<div class="sdk-ref-table max-sm:[&_td]:px-1.5! max-sm:[&_th]:px-1.5!">

| Job | Credential |
| --- | --- |
| Manage members or settings in the dashboard | A signed-in organization member with the required role |
| Create, list or revoke keys through the gateway admin API | The admin token in the `Authorization` header |
| Make an inference request | The caller's `sk-agentcc-` virtual key |

</div>

## Troubleshooting

- **You can view settings but cannot change them.** Check your role in this organization. Members and Viewers cannot change org settings, and your role can differ in another organization you belong to.
- **A key cannot call the test model.** Compare the requested model with the key's allowed models and the organization's configured providers.
- **You cannot find the test request.** Check which organization's key you sent, then search the logs for the `x-agentcc-request-id` from the response.
