## What a dataset owns

A **dataset** owns two collections: columns and rows. A **column** defines one attribute every row carries. Whether its values are static or dynamic, who or what fills them in, is covered in [Static & Dynamic Columns](/docs/dataset/concepts/static-and-dynamic-columns). A **row** is one example. Where a row crosses a column sits a **cell**: the stored value for that column, on that row.

Row order isn't insertion order. Every row carries its own `order`, an explicit integer the dataset uses to lay rows out top to bottom, so resorting rows in the grid doesn't touch when they were created or any other row's data.

Column layout works the same way one level up. The dataset keeps a `column_order`, an array that fixes the left-to-right order of its columns. It's pruned every time the dataset saves, dropping any column ID that no longer exists, so deleting a column also removes it from the layout without a separate cleanup step.

A cell's value is always stored as text, whatever the column's data type. A JSON column's value is JSON-stringified before it's stored, and a media column, an image or an audio file, holds a URL string rather than the file itself. Underneath a typed column, every cell is a string.

Take a two-column dataset: `input` is static, filled in once when the row is added, and `model_response` is dynamic, filled in by running a prompt against `input`. Both rows get a cell in each column: four cells total, two static and two dynamic, all belonging to the same dataset. Add a third row and both columns grow a new cell; add a third column and both rows do too, which is what keeps the grid rectangular no matter how many of its columns are dynamic.

## Ownership and scoping

A dataset always belongs to one organization; the `organization` foreign key is required, so there's no such thing as a dataset with no owning org. A workspace is optional: a dataset can sit inside one workspace for scoping, or none at all.

`model_type` fixes what kind of data the dataset is built for: generative text by default, or image, audio, video, and structured types such as classification and ranking. See the full list in [Limits & Data Types](/docs/dataset/reference/limits-and-data-types).

## Why it matters

- Row order is explicit, so you can resort rows for review without disturbing anything else in the dataset. The order field is separate from when a row was created or which cells it holds
- Because `column_order` is pruned on save, deleting a column cleans up its position in the layout automatically. Nothing is left pointing at a column that no longer exists
- Every cell value is text underneath, so anything that reads one back, a prompt template, an eval, an export, gets a string and has to parse or fetch it for JSON and media columns
- Organization ownership means access to a dataset follows organization membership first; the optional workspace narrows that further
