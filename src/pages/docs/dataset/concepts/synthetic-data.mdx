## What synthetic data is

**Synthetic data** is a [dataset's](/docs/dataset/concepts/understanding-datasets) rows generated from a schema you define, instead of rows you upload or bring in yourself. You describe the [columns](/docs/dataset/concepts/static-and-dynamic-columns) you want, their names, types, descriptions, and constraints, and Future AGI generates rows that match.

Define this schema for a customer-support dataset:

| Column | Type | Description |
|---|---|---|
| customer_query | text | A realistic customer support question |
| sentiment | text | One of: positive, negative, neutral |
| priority | integer | 1 (low) to 5 (urgent) |

Generation produces rows like:

| customer_query | sentiment | priority |
|---|---|---|
| I haven't received my order and it's been two weeks | negative | 4 |
| Can I change the shipping address on my recent order? | neutral | 2 |
| Your product is fantastic, just wanted to say thanks! | positive | 1 |

The constraints in your schema (the allowed values, or a range like 1-5) guide the generator, so rows stay inside them while still varying in content.

## How synthetic data is generated

Every synthetic dataset saves what you defined, columns, row count, description, objective, and an optional [Knowledge Base](/docs/knowledge-base) link, as the dataset's own generation config. That's what lets you reopen a synthetic dataset later, change a column or the row count, and regenerate without rebuilding the schema from scratch.

Starting generation queues a background job that reads that config, optionally pulls context from the connected Knowledge Base, and writes the resulting rows into the dataset.

Regenerating, editing the config and running it again, replaces the dataset's current rows and columns with a fresh batch generated from the updated config. The saved config is what makes that replay possible: you're never redefining the schema by hand.

## While it's generating

Generation doesn't happen instantly. Because it runs as a background job, a synthetic dataset sits in a **Generating** state (or **Regenerating**, if you kicked off a rerun) with a live progress bar while the job works, and a **Configure Synthetic Data** button that reopens the schema. If the job errors out, the dataset shows a **Failed** state instead, with the same button to fix the configuration and try again.

To generate your first synthetic dataset hands-on, follow the [Generate synthetic data quickstart](/docs/quickstart/generate-synthetic-data).

## When to use synthetic data

Reach for synthetic data whenever real rows are unavailable, risky to use, or lopsided for what you're testing:

- **No real data yet**: you're building a new feature and don't have production rows to test against
- **Privacy limits**: real data carries PII you can't put in a test dataset
- **Edge cases**: you need scenarios that are rare in real traffic, like an angry customer or a multilingual query
- **Scale**: you need thousands of rows to stress-test a prompt or eval
- **Skewed data**: real data leans one way (mostly positive reviews) and you need a more balanced set
