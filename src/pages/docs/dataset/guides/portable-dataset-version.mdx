## About

The existing FutureAGI SDK can export a complete `DatasetVersion` to a versioned JSONL archive and import it through the existing snapshot API. This format preserves typed JSON values and stable IDs without mutating the legacy `Dataset → Row → Cell` tables.

<Note>
  Draft SDK workflow. Use SDK PR #32 and a deployment containing the snapshot API. No package release, hosted availability or browser UI is established by this draft.
</Note>

## Format and limits

The archive has one envelope line followed by one line per case. It records the source dataset/version, parent, metadata, revision, item count, server fingerprints and `records_sha256` over the exact UTF-8 case-line bytes. Cases preserve `example_id`, `external_id`, `input`, nullable `expected`, metadata, source trace/span strings, content hash and nullable legacy-row provenance.

The SDK rejects archives over 10 MiB or 10,000 cases, malformed JSONL, invalid UTF-8, duplicate identities, mismatched counts/checksums, unsupported format versions, unsafe TypeScript integers, and null case input. Imports validate the entire archive before one snapshot POST. Snapshot creation remains non-idempotent: an accepted retry creates a new version.

Cross-dataset imports reject `legacy_row` by default because row IDs are dataset-local. Pass `legacy_rows="drop"` or `legacyRows: "drop"` to remove that relationship explicitly. Preserve it only for a same-dataset import with `legacy_rows="preserve"` / `legacyRows: "preserve"`. Trace and span strings remain caller assertions; the SDK does not verify Observe.

## Python

```python
from pathlib import Path

from fi import FutureAGIClient
from fi.generated.openapi_client.models.dataset_version_create import DatasetVersionCreate

with FutureAGIClient(
    api_key="YOUR_API_KEY",
    secret_key="YOUR_SECRET_KEY",
    base_url="https://your-deployment.example.com",
) as client:
    archive = client.datasets.versions.export_jsonl(
        "DATASET_UUID",
        "VERSION_UUID",
    )
    Path("dataset-version.jsonl").write_text(archive, encoding="utf-8")

    # Validate first, then perform exactly one non-idempotent snapshot POST.
    imported = client.datasets.versions.import_jsonl(
        "TARGET_DATASET_UUID",
        Path("dataset-version.jsonl").read_bytes(),
        legacy_rows="drop",
    )
    print(imported.result.id)
```

The SDK returns generated response models. The version hash can change when importing into another dataset because the server hash includes dataset identity; item hashes and stable example IDs remain available for comparison.

## TypeScript

```typescript
import { FutureAGIClient } from "@future-agi/sdk";
import { readFile, writeFile } from "node:fs/promises";

const client = new FutureAGIClient({
  apiKey: process.env.FI_API_KEY!,
  secretKey: process.env.FI_SECRET_KEY!,
  baseUrl: process.env.FI_BASE_URL!,
});

const archive = await client.datasets.versions.exportJsonl(
  "DATASET_UUID",
  "VERSION_UUID",
);
await writeFile("dataset-version.jsonl", archive, "utf8");

const imported = await client.datasets.versions.importJsonl(
  "TARGET_DATASET_UUID",
  await readFile("dataset-version.jsonl"),
  { legacyRows: "drop" },
);
console.log(imported.result.id);
```

Use Node's file APIs instead of `Bun.write` when Bun is not part of your runtime. TypeScript rejects integers outside JavaScript's safe range; use strings or a Python exporter when exact large integer values are required.

## Failure and retry behavior

- A malformed archive fails before any POST, so no empty or partial version is created.
- A failed POST is returned to the caller. Do not automatically retry it unless your application can determine whether a version was accepted; identical accepted imports create separate versions.
- A same-dataset legacy-row preservation request forwards the source row reference for server validation. A cross-dataset drop removes only that local foreign key; it does not invent a target row.
- Duplicate JSON object keys follow the parser's last-value behavior. Avoid duplicate keys in archives.
