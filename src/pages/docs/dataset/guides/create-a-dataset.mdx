If your test cases are in a spreadsheet, you can bring them into a [dataset](/docs/dataset/concepts/understanding-datasets) without retyping them. If you have no examples yet, start with an empty grid or generate rows from a schema. All six paths lead to a table you can edit.

<Prerequisites title="Before you start">
- You need a [role](/docs/roles-and-permissions) that can create resources in the workspace. A Viewer has read-only access.
- Choose a name that is unique in your organization. A name that's already taken is rejected, and the clash can be with a dataset you don't have access to see.
</Prerequisites>

## Choose a starting point

1. Open **Dataset** in the left navigation.
2. Select **Add Dataset**.

   A panel opens with six tiles. Start with the one that matches where your examples are today:

| Method | Choose it when |
| --- | --- |
| Add data using SDK | You're scripting the setup or pushing rows from your own pipeline. |
| Upload a file (JSON, CSV) | You already have test cases in a CSV, Excel or JSON export. |
| Create Synthetic Data | You don't have real data yet, but know the shape of the examples you need. |
| Add datasets Manually | You're hand-building a small set and want an empty grid to fill in. |
| Import from HuggingFace | The data you need already exists as a Hugging Face dataset. |
| Add from existing model dataset or experiment | You want to branch off a dataset or experiment you already have. |

Whichever method you pick, you land on the same table of rows and columns, and you can keep editing it afterward. The full set of dataset and column limits is in [Limits & Data Types](/docs/dataset/reference/limits-and-data-types).

## Upload a file

1. Select **Upload a file (JSON, CSV)**.
2. Enter a unique dataset name.
3. Drop or browse to your file. Supported formats are `.csv`, `.xls`, `.xlsx`, `.json` and `.jsonl`, up to 25 MB.
4. Check the dataset list for the new name.

   The dataset appears while the file is still processing. Wait for processing to finish, then open the grid to check the imported rows and columns.

## Create synthetic data

1. Select **Create Synthetic Data**.
2. Name the dataset.
3. Describe the schema as Future AGI walks you through it.

   Future AGI generates the rows for you. See [Synthetic Data](/docs/dataset/concepts/synthetic-data) if you want to regenerate later.

## Add a dataset manually

1. Select **Add datasets Manually**.
2. Name the dataset.
3. Choose the starting row count, up to 100.
4. Choose the starting column count, up to 100.

   You should see the requested number of empty rows and columns, ready for entry.

## Import from Hugging Face

1. Select **Import from HuggingFace**.
2. Paste the Hugging Face dataset ID.
3. Select **Load Dataset**.
4. Choose the **Subset**.
5. Choose the **Split**.
6. Name the new dataset to finish.

   Only the first 100 rows of the source are ingested.

## Add from an existing dataset or experiment

1. Select **Add from existing model dataset or experiment**.
2. Choose the source dataset or experiment.
3. Choose **Import Data** for data alone or **Import data and prompt configuration** to keep the prompt configuration too.
4. Select the columns you want to include.
5. Name the new dataset to finish.

   The new dataset holds the columns you selected, not the whole source table.

## Add data using the SDK

1. Select **Add data using SDK**.
2. Name the dataset. The examples below use `support-agent-eval`.

   Future AGI creates an empty dataset and drops you on its **Data** tab. The tab shows the dataset's name, ID, API key and secret key alongside a ready-to-run code snippet.

3. Run the code below against your dataset to add [columns](/docs/dataset/concepts/static-and-dynamic-columns) and rows.

   An empty dataset starts with at most 10 rows. Add the rest with the SDK.

| Setting | What to use | Where to find it |
| --- | --- | --- |
| `FI_API_KEY`, `FI_SECRET_KEY` | Your API key and secret key | The **Data** tab, or the [API keys](/docs/admin-settings/api-keys) page |
| Dataset name | The dataset you just created, for the Python and TypeScript examples | **Data** tab |
| Dataset ID | The same dataset's ID, in place of `<dataset_id>` in the cURL URL | **Data** tab |

The examples define three columns: `user_query` (text), `response_quality` (integer) and `is_helpful` (boolean). `<fi_api_key>` and `<fi_secret_key>` are placeholders. If your environment already sets both keys, leave those two lines out, and don't put live keys in source.

<CodeGroup>

```python Python
# pip install futureagi

import os
from fi.datasets import Dataset
from fi.datasets.types import Cell, Column, DataTypeChoices, Row, SourceChoices

os.environ["FI_API_KEY"] = "<fi_api_key>"
os.environ["FI_SECRET_KEY"] = "<fi_secret_key>"

# Get the dataset you just created
dataset = Dataset.get_dataset_config("support-agent-eval")

# Define columns
columns = [
    Column(name="user_query", data_type=DataTypeChoices.TEXT, source=SourceChoices.OTHERS),
    Column(name="response_quality", data_type=DataTypeChoices.INTEGER, source=SourceChoices.OTHERS),
    Column(name="is_helpful", data_type=DataTypeChoices.BOOLEAN, source=SourceChoices.OTHERS),
]

# Define rows
rows = [
    Row(order=1, cells=[
        Cell(column_name="user_query", value="What is machine learning?"),
        Cell(column_name="response_quality", value=8),
        Cell(column_name="is_helpful", value=True),
    ]),
    Row(order=2, cells=[
        Cell(column_name="user_query", value="Explain quantum computing"),
        Cell(column_name="response_quality", value=9),
        Cell(column_name="is_helpful", value=True),
    ]),
]

dataset = dataset.add_columns(columns=columns)
dataset = dataset.add_rows(rows=rows)
```

```typescript Typescript
import { Dataset, DataTypeChoices, createRow, createCell } from "@future-agi/sdk";

process.env["FI_API_KEY"] = "<fi_api_key>";
process.env["FI_SECRET_KEY"] = "<fi_secret_key>";

async function main() {
  // Get the dataset you just created
  const dataset = await Dataset.open("support-agent-eval");

  // Define columns
  const columns = [
    { name: "user_query", dataType: DataTypeChoices.TEXT },
    { name: "response_quality", dataType: DataTypeChoices.INTEGER },
    { name: "is_helpful", dataType: DataTypeChoices.BOOLEAN },
  ];

  // Define rows
  const rows = [
    createRow({
      cells: [
        createCell({ columnName: "user_query", value: "What is machine learning?" }),
        createCell({ columnName: "response_quality", value: 8 }),
        createCell({ columnName: "is_helpful", value: true }),
      ],
    }),
    createRow({
      cells: [
        createCell({ columnName: "user_query", value: "Explain quantum computing" }),
        createCell({ columnName: "response_quality", value: 9 }),
        createCell({ columnName: "is_helpful", value: true }),
      ],
    }),
  ];

  await dataset.addColumns(columns);
  await dataset.addRows(rows);
}

main();
```

```bash Curl
curl --request POST \
  --url https://api.futureagi.com/model-hub/develops/<dataset_id>/add_columns/ \
  --header 'X-Api-Key: <fi_api_key>' \
  --header 'X-Secret-Key: <fi_secret_key>' \
  --header 'content-type: application/json' \
  --data '{
    "new_columns_data": [
      {"name": "user_query", "data_type": "text"},
      {"name": "response_quality", "data_type": "integer"},
      {"name": "is_helpful", "data_type": "boolean"}
    ]
  }'
```

</CodeGroup>

Open the dataset's grid after the run. The Python and TypeScript examples add the three columns and two rows. The cURL request adds the columns only, so follow [Add rows](/docs/dataset/guides/add-rows#append-examples-from-code) to fill them.

To read the table back from code, [`datasets.get`](/docs/sdk/reference/datasets#datasetsget) returns the rows, columns and metadata for a dataset. See the [Datasets SDK](/docs/sdk/datasets) page for the full `Dataset` API.

## Troubleshooting

- **"A dataset with this name already exists in your organization":** pick a different name. Names must be unique per organization, so the clash can be with a dataset you can't see.
- **The upload finished but the dataset shows no rows yet:** the file is still processing in the background. Wait for it to finish; the rows land once it does.
- **Something else:** see [dataset troubleshooting](/docs/dataset/troubleshooting).
