Make a working copy before editing a dataset you still need. Check the copy alongside the original: duplicating preserves the rows and [static columns](/docs/dataset/concepts/static-and-dynamic-columns), not computed columns or their results.

This guide also covers finding, exporting, editing and deleting a dataset that already has data in it.

<Prerequisites title="Before you start">
- An existing dataset. If you're starting without data, [create a dataset](/docs/dataset/guides/create-a-dataset) first.
- [Dataset permissions](/docs/roles-and-permissions) for the change you're making. Without permission, the bulk actions are disabled; viewers can't edit cells and don't see rename, type or delete actions in the column menu.
</Prerequisites>

## Find and select the dataset

1. Filter the dataset list by name in the search box.

   **No datasets found** means nothing matches. Only **Dataset Name** and **Datapoints** can be sorted: click either header to reorder the list. The list is paginated; see [Limits and data types](/docs/dataset/reference/limits-and-data-types) for the page size.

2. Check the box beside the original dataset.

   The bulk bar shows the number selected, **Delete**, **Cancel**, and, with exactly one row selected, **Duplicate**. **Cancel** clears the selection without changing data.

If you select two or more datasets, **Compare** replaces **Duplicate**. It opens **Select Base Columns**, where you choose the column the selected datasets share.

## Duplicate one dataset

1. Select **Duplicate**.
2. In **Enter Dataset Name**, give the copy an unused name such as `support-agent-eval-copy`.
3. Select **Create**.

   The dialog validates the name; a success message confirms creation. **Cancel** leaves the original alone without creating a copy.

4. Open the copy.
5. Compare its column list with the original's.

   You should see the original rows and static columns, without any dynamic columns or their computed values, so the copy can have fewer columns than the original. The copy is a separate dataset: editing or deleting one doesn't change the other.

## Export the data

1. Open the dataset you want to download.
2. Select the download icon in its toolbar.

   You should see **Download has been started...**, followed by **Dataset downloaded successfully** when the file is ready. Downloading isn't restricted to editors, but the control is disabled for an empty dataset or a synthetic dataset that's still processing.

## Edit data in the grid

<div class="sdk-ref-table max-sm:[&_td]:px-1.5! max-sm:[&_th]:px-1.5!">

| Job | Where to do it | What changes |
| --- | --- | --- |
| Rename a column | **Edit Column Name** in the column header menu | The cell values stay the same, but SDK and cURL calls that reference the old name break. |
| Change its type | **Edit Column Type** in the same menu | The type changes how the stored values are interpreted. |
| Edit a static cell | Edit the cell in **Data** | Only that value changes. Audio and persona cells can't be edited this way. |
| Change a computed cell | Check what produces its dynamic column | Cells in a dynamic column can't be edited at all: the column is managed by whatever produces it. |

</div>

<Warning>
A rename changes what your integrations have to send. `add_rows` and other SDK or cURL calls key each cell by `column_name`. If a call still references `response_quality` after you rename the column to `quality_score`, that call fails until it's updated.
</Warning>

The [column rename endpoint](/docs/api/datasets/columns/update-column-name) itself identifies the column by its UUID, not its name. Renaming the *dataset* is a different operation: the [update dataset endpoint](/docs/api/datasets/update-dataset) takes the dataset UUID and the new name. The [dataset SDK reference](/docs/sdk/reference/datasets) lists `datasets.columns.rename` and `datasets.delete` separately.

## Check what deletion removes

Deletes are final. Choose the smallest scope that covers what you want gone:

<div class="sdk-ref-table max-sm:[&_td]:px-1.5! max-sm:[&_th]:px-1.5!">

| Scope | What disappears |
| --- | --- |
| Selected rows | The selected rows and every cell in them. |
| One column | The column and all its cells. For a dynamic column, its producer (such as a prompt run or eval) and anything derived from it also go. |
| Whole dataset | The dataset and its [experiments](/docs/dataset/guides/run-an-experiment). |

</div>

To delete rows, select their checkboxes and confirm the delete action in the grid toolbar. To delete one column, use **Delete Column** in the column header menu.

## Delete a dataset you no longer need

1. Check the boxes beside the datasets to remove.
2. Select **Delete** in the bulk bar.
3. Check the selection before confirming.

   The dialog title is **Delete Dataset** for one or **Delete Datasets** for several; **Cancel** backs out without deleting anything.

4. Select **Delete** to confirm.

   You should see a success message. Bulk deletion is limited to 50 datasets per request; larger selections need separate batches.
