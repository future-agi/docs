## About

Use the existing comparison endpoint as a read-only CI check. The caller owns the baseline/candidate IDs, selected evaluator metric, and policy file. The server evaluates only recorded case evidence.

<Note>
  Draft tutorial. It does not execute an agent, run a model, verify Observe traces, choose a baseline, or publish a release. The local Python script exits `0` only for `verdict: pass`, `1` for a valid failed gate, and `2` for a request or response error.
</Note>

## Create a policy file

Save this as `release-gate-request.json` and replace the IDs with accessible runs and metric:

```json
{
  "baseline_run_id": "11111111-1111-4111-8111-111111111111",
  "candidate_run_id": "22222222-2222-4222-8222-222222222222",
  "metric_id": "33333333-3333-4333-8333-333333333333",
  "passing_score": 1,
  "higher_is_better": true,
  "include_trial_stability": true,
  "release_gate": {
    "max_regressions": 0,
    "critical_cases": []
  }
}
```

The full plan must be complete and valid on both sides. Set `max_regressions` above zero only when that allowance is an explicit product decision. Add critical cases for cases that must not regress.

This request opts into [trial stability](/docs/api/datasets/compare-experiment-runs#inspect-repeated-trials). Use a deployment containing that option. Remove `include_trial_stability` to keep the ordinary response. The linked reference includes Python and TypeScript SDK snippets and their required draft builds; the script below uses REST.

## Run the check

Download [`check-experiment-run.py`](/cookbook/check-experiment-run.py), then run:

```bash
export BASE_URL="https://your-deployment.example.com"
export FUTURE_AGI_API_KEY="YOUR_API_KEY"
export FUTURE_AGI_SECRET_KEY="YOUR_SECRET_KEY"

python check-experiment-run.py release-gate-request.json --output release-gate.json
status=$?
cat release-gate.json
exit "$status"
```

The script saves the complete comparison and gate report. A valid failed verdict exits `1` with deterministic blockers. A malformed request, hidden run, incompatible version/plan/binding, or unavailable endpoint exits `2`; CI must treat that as failure as well.

## Read the result

Check `release-gate.json` before accepting a build:

| Field | Meaning |
| --- | --- |
| `verdict` | `pass` or `fail` for the supplied policy. |
| `expected_count` | Complete pinned case/trial count required by the gate. |
| `comparable_count` | Cases with valid assessed numeric evidence on both sides. |
| `regression_count` | Comparable candidate regressions using the supplied score direction. |
| `blockers` | Missing, invalid, critical, or allowance failures in deterministic order. |

Do not replace the gate with a mean comparison. Two runs can have equal means while a critical case regresses. Incomplete and not-assessed evidence must remain visible and fail closed.

### Inspect trial stability beside the gate

The saved envelope also contains `result.trial_stability` when requested. Read each example's `expected_trial_count` alongside the baseline and candidate recorded, missing, and assessed counts before interpreting its mean or spread. With fewer than two assessed trials, `score_stddev` is `null`. The [equal-mean example](/docs/api/datasets/compare-experiment-runs#inspect-repeated-trials) shows why a mean of `0.5` can hide a spread of `0.5` versus `0`.

Read the saved report without turning zero spread into missing data:

<CodeGroup titles={["Python", "TypeScript"]}>

```python
import json
from pathlib import Path

report = json.loads(Path("release-gate.json").read_text())
for example in report["result"].get("trial_stability", []):
    spread = example["candidate"]["score_stddev"]
    print(example["example_id"], "unavailable" if spread is None else spread)
```

```typescript
import { readFileSync } from "node:fs";

const report = JSON.parse(readFileSync("release-gate.json", "utf8"));
for (const example of report.result.trial_stability ?? []) {
  console.log(example.example_id, example.candidate.score_stddev ?? "unavailable");
}
```

</CodeGroup>

The script saves this diagnostic data, but its exit status still uses the case-level `release_gate`. Trial summaries do not change the gate, establish statistical significance, or certify future reliability. Keep safety and tool-behavior assertions as independent CI checks.

## Evidence boundary

This policy evaluates caller-recorded outputs and score references. It does not prove that the evaluator ran, that trace IDs resolve in Observe, or that the selected baseline is approved. Add those checks as separate verified stages when the product contract supports them.

Gate-only requests from this script were exercised on 2026-10-13 through local HTTP with real API-key authentication and disposable PostgreSQL. A regression exited 1; an explicit allowance exited 0; a critical regression and an incomplete run exited 1; malformed policy exited 2. Each result replaced the saved artifact, including failure cases. The test used deterministic outputs and no model calls; it did not verify the optional trial-stability response.

Separate Python and TypeScript SDK comparison probes exercised the opt-in option through authenticated local HTTP and disposable PostgreSQL on the same date. They returned identical JSON and preserved omitted/false behavior, missing-trial counts, null statistics, zero spread, paired deltas, and a failed full-plan gate. Their scores were deterministic fixtures, with no model calls or live Observe ingestion.
