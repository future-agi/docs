An **experiment** runs every [prompt or agent](/docs/prompt) and model combination you set up against the same [dataset](/docs/dataset/concepts/understanding-datasets), scored by the [evals](/docs/evaluation) you attach, so you can compare configurations side by side instead of testing them one at a time.

## The experiment grid

One experiment lays your dataset's rows against every configuration you add. A **configuration** pairs one prompt or agent with one model, so attaching three models to the same prompt gives you three configurations, one column each. Every eval you attach scores every configuration against the same rows, which is what makes the columns comparable.

## Build the experiment

Click **New experiment** on the dataset to open the creation flow. The current default wizard has four steps: **Configuration → Data → Evaluations → Review & run**.

<Steps>
  <Step title="Configuration">
    Name the experiment. New experiments in the experiment wizard are **LLM-only**; **TTS**, **STT**, and **Image** are not choices for a fresh experiment.

    Add the prompts or agents you want to compare and select a saved version of each. Attach a model to each prompt. Every prompt-model pair becomes its own configuration column; an agent uses its saved version. LLM experiments can mix prompts and agents in the same run.
  </Step>
  <Step title="Data">
    Check the dataset data the experiment will use. If the **Dataset version** selector is available in your build, choose the version to run against. Map every required prompt or agent input variable to a dataset column and check the sample values. Unmapped inputs block **Continue** and the final run action. Choose a reference column here if your evaluations need one.
  </Step>
  <Step title="Evaluations">
    Add at least one evaluation to score the configurations, then continue to review.
  </Step>
  <Step title="Review & run">
    Check the runs, data, and evaluations in the summary. Resolve any issues reported by the earlier steps, then click **Run experiment** to start the configured prompt and agent runs.
  </Step>
</Steps>

The configurations run against the dataset data, with each output scored by your evals as it comes in.

<Note>
An existing TTS or STT experiment retains its selected type. Builds with experiment enhancements explicitly disabled also expose the classic type choices, including Image. Those are separate paths from the default new-experiment flow above.
</Note>

<Note>
An eval you add after the run sits queued for a few seconds before it starts scoring.
</Note>

## Stop and rerun

Each experiment stops and reruns independently. Stop a running one without touching the others in the dataset, and rerun a completed, failed, or cancelled one later without setting it up again, though rerunning overwrites its existing results. Select more than one experiment at a time to rerun or delete them together.

## Choose a winner

The experiment summary already lists every configuration. Once every configuration has a score, click **Choose winner** to open Winner Settings, where you set the importance of Average Response Time, Completion tokens, Total tokens, and each eval. Click **Save & Run** and the summary marks the winning configuration.

## Tips

- **Failed-only rerun**: when transient failures (rate limits, network blips) leave a few cells errored, use the failed-only rerun on the column to recover them without redoing successful rows
