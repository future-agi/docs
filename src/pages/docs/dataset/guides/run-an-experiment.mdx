To decide between two configurations, run them on the same [dataset](/docs/dataset/concepts/understanding-datasets) and score both with the same [evals](/docs/evaluation). The experiment summary shows the alternatives side by side and lets you choose how much quality, speed and token use matter.

<Prerequisites title="Before you start">
- A dataset with the rows you want to compare.
- A [prompt or agent](/docs/prompt) and a model for each configuration. For a comparison that changes just the model, use the same prompt with two models.
</Prerequisites>

## The experiment grid

Each configuration pairs one prompt or agent with one model. Three models on the same prompt give you three configuration columns. Every attached eval scores each column against the same rows.

## Set up the comparison

1. Select **Experiment** on the dataset.
2. Under **Basic Info**, name the experiment.
3. Choose the experiment type.

   Choose **LLM** for text, **TTS** for speech generation, **STT** for transcription, or **Image** for image output. The type decides the output format and which models you can attach.

4. Under **Configuration**, add the prompt you want to compare.
5. Attach the first model to that prompt.
6. Attach the second model to the same prompt.

   You should see two prompt-model pairs. Each pair becomes its own configuration column. An LLM experiment can also mix prompts and agents in the same run and attach tools to a prompt, which helps you decide whether an agent earns its extra complexity over a plain prompt. TTS, STT and Image experiments take prompts only.

## Score the same rows

1. Under **Evaluations**, choose a baseline column if you have reference outputs to compare against.
2. Add the evals that will score every configuration.
3. Select **Run Experiment**.

   You should see an output for each completed row and configuration, with scores as the evals finish. An eval added after the run can stay queued for a few seconds before scoring starts.

## Choose a winner

1. Check that every configuration has a score in the experiment summary.
2. Select **Choose winner**.
3. In **Winner Settings**, set the importance of **Average Response Time**.
4. Set the importance of **Completion tokens**.
5. Set the importance of **Total tokens**.
6. Set the importance of each eval.
7. Select **Save & Run**.

   The summary should mark the winning configuration for those settings. When reporting a winner, keep the settings with the result so readers know what the comparison rewarded.

## Stop or rerun an experiment

Each experiment stops and reruns independently: stopping a running one does not touch the dataset's other experiments. When only a few cells failed because of a rate limit or network problem, use the failed-only rerun on the column rather than redoing successful rows.

<Note>
A full rerun overwrites the experiment's existing results. Keep any results you need before starting it.
</Note>

You can rerun a completed, failed or cancelled experiment without configuring it again. Selecting multiple experiments lets you rerun or delete them together.

## Create or read an experiment from code

The [experiments SDK reference](/docs/sdk/reference/experiments) lists `experiments.create` to start an experiment and `experiments.get` to read it by ID in Python and TypeScript. The corresponding MCP tools are `create_experiment` and `get_experiment`. The reference also lists experiments in the current workspace; it doesn't document a **Choose winner** operation.
