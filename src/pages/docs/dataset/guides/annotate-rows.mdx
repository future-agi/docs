---
title: "Annotate rows"
description: "Label dataset rows by hand: create a view, define a label, wire fields, and assign annotators."
---

Attach human labels to the rows of a dataset so you can grade model output, build training or evaluation data, and catch what automated checks miss. Annotation happens right inside the dataset itself, next to the rows you're grading.

<Note>
This guide covers labeling rows inside one dataset. For structured campaigns across multiple annotators, with progress tracking and assignment rules, use [annotation queues](/docs/annotations) instead.
</Note>

<Steps>
  <Step title="Create an annotation view">
    Open the dataset you want to annotate, then create a new **annotation view**. A view defines what you're annotating and how: give it a name, then set its label and fields in the steps below.
  </Step>

  <Step title="Define a label and its type">
    Define the **label** you'll apply to each row: give it a name and a type that matches what you're capturing.

    If you also add the label to the table as a column, that column is recorded with the `annotation_label` source, the same way a prompt run or an eval column carries its own [dynamic column](/docs/dataset/concepts/static-and-dynamic-columns) source.
  </Step>

  <Step title="Wire static fields and response fields">
    Point the view at the columns that give context while you annotate (static fields), and the columns that hold what you're actually judging (response fields).
  </Step>

  <Step title="Assign annotators">
    Assign the workspace members who will do the labeling. Each annotator sees the view and applies the label to the rows in it.
  </Step>

  <Step title="Review and edit">
    Move through the rows and apply the label. You can revisit and change an existing annotation at any time.

    Deleting removes the whole annotation view, not just one row's label: it drops the view and the `annotation_label` column it produced across the dataset, while each row's own values stay put.

    The label is stored on the [cell](/docs/dataset/concepts/understanding-datasets) it belongs to, as annotation metadata alongside the cell's own value.
  </Step>
</Steps>
