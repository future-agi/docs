<TLDR>
Test a password-reset reply in the [Prompt Workbench](/docs/prompt), then commit the instructions so your team can reuse that version.
</TLDR>

## The problem

A support teammate asks which instructions produced a password-reset reply. The reply in **Output** tells you what the model said, but not whether anyone saved that draft as a reusable version. A run and a commit are separate actions.

## What you'll build

A [versioned prompt](/docs/prompt/concepts/versions-and-labels) with a support policy in the system message and a password-reset question in the user message.

You'll:

1. Separate the support instructions from the customer's question.
2. Run the prompt on a configured model.
3. Find the tested version in **Commit History**.

<Prerequisites title="Before you start">
- A Future AGI workspace with at least one [model provider](/docs/admin-settings/ai-providers) configured under **Settings > AI Providers**.
</Prerequisites>

## Write the instructions

1. Open **Build > Prompts**.
2. Select **Create prompt**.
3. Choose **Start from scratch**.

   The other options are **Generate with AI** and **Start with a template**.

   ![Create prompt offers a blank prompt, AI generation and a template.](/images/docs/get-started/create-your-first-prompt/create-prompt.png)

4. Click the title, **Untitled-1**, and rename the prompt `Acme Support Assistant`.
5. Paste the support policy into **System**. This field is optional and shapes the model's overall behavior:

```text
You are a customer support assistant for Acme, a company that makes project-management software.
Answer the customer's question clearly and accurately, in a friendly and professional tone.
Keep your reply under 120 words. If you are unsure of the answer, say so honestly and point the
customer to help@acme.com instead of guessing.
```

6. Paste the customer's question into **User**, the message that drives the response:

```text
How do I reset my password?
```

![Acme Support Assistant with separate System and User messages for the support policy and reset question.](/images/docs/get-started/create-your-first-prompt/write-prompt.png)

## Test the reply

1. Choose a model under **Select Model**.

   ![Model picker in the support prompt editor.](/images/docs/get-started/create-your-first-prompt/select-model.png)

2. Optionally, adjust [model parameters](/docs/prompt/reference/model-configuration) in **Params**.

   ![Params panel for settings such as temperature, maximum tokens and top P.](/images/docs/get-started/create-your-first-prompt/parameters.png)

3. Select **Run Prompt** in the top-right corner.

   ![The password-reset prompt while generation is in progress; the right-hand panel is where the reply will appear.](/images/docs/get-started/create-your-first-prompt/run-prompt.png)

4. Read the reply in **Output**. Check it against the policy: it should stay under 120 words and refer the customer to support rather than guess if it lacks the answer.

## Commit the tested version

1. Select **Commit** in the editor header.
2. Enter a description of the tested change in **Commit message**.
3. Select **Commit** in the dialog.

   The dialog should close with a confirmation; this saves the version without changing the default.

4. Open **Commit History**.

   You should see your committed version listed there, not just the reply in the editor. The prompt also appears in the **Prompts** list.

Each commit creates a new version, so you can [compare versions](/docs/prompt/guides/commit-and-compare-versions), roll back, deploy a specific one via labels, and reuse the prompt across datasets, simulations, experiments and the SDK.

## Use the committed version from code

Use the [prompt SDK reference](/docs/prompt/reference/sdk-api#fetch-by-name) to fetch `Acme Support Assistant` by name and the version you just committed. Compiling a template returns messages; it does not call the model. To run that version, use the separate platform client operation below.

<div class="sdk-ref-table max-sm:[&_td]:px-1.5! max-sm:[&_th]:px-1.5!">

| Variable | What to set | Where to find it |
| --- | --- | --- |
| `FI_API_KEY` | Workspace API key | [Workspace API keys](/docs/admin-settings/api-keys) |
| `FI_SECRET_KEY` | Secret paired with that key | Shown once, when you create the pair |

</div>

In Python, `get_template_by_name()` returns a `Prompt` you can compile directly. In TypeScript, `getTemplateByName()` returns a template; wrap it in a `Prompt` before compiling. Compare the compiled system and user messages with the two you entered above, not with the generated reply.

To execute the committed version rather than compile its messages:

1. Submit the template UUID to the [prompt run operation](/docs/sdk/reference/prompts#promptsrun) with the committed `version` and `is_run` set to `"prompt"`.

   In both Python and TypeScript, `client.prompts.run` returns an asynchronous receipt rather than the password-reset reply.

2. Read the [status and output](/docs/sdk/reference/prompts#promptsrun_status) for the same template UUID, passing the returned version as `template_version`.

   Use `client.prompts.run_status` in Python or `client.prompts.runStatus` in TypeScript so you read the version you submitted rather than the default.

3. Compare the finished reply with the saved system instructions, including the word limit and the direction not to guess.

## Troubleshooting

- **API key not configured.** Add a model provider key under **Settings > AI Providers**, then run again.
- **Empty output.** Check that the **User** field isn't blank before running.
- **Commit is disabled.** Run the current draft first. If several versions are open for comparison, return to a single version before committing.
