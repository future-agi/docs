<TLDR>
Use [Observe](/docs/observe) to match a printed reply to the model call that produced it.
</TLDR>

## The problem

The application prints a bedtime story, but the terminal does not show the tokens used or how long the model took. A [trace](/docs/observe/concepts/traces) groups the work for that request; its model [span](/docs/observe/concepts/spans) records the prompt and reply.

## What you'll build

An instrumented [OpenAI client](/docs/integrations/traceai/openai) that sends one request to `my-llm-app` in Observe. Observe supports auto-instrumentation for OpenAI, Anthropic, LangChain, LlamaIndex, CrewAI and 30+ other frameworks. This guide uses OpenAI.

You'll:

1. Connect the trace exporter to your workspace.
2. Instrument the OpenAI client before sending a request.
3. Find the same prompt and reply in the model span.

<Prerequisites title="Before you start">
- A workspace [API key and secret key](/docs/admin-settings/api-keys) for `FI_API_KEY` and `FI_SECRET_KEY`.
- An OpenAI API key and a Python or Node.js environment. The [first-trace guide](/docs/get-started/send-your-first-trace) has complete files with pinned tracing packages and exporter shutdown.
</Prerequisites>

## Set the credentials

Use the same environment for registration and the model call. Step 2 below sets placeholder values in code. In your own application, set the keys in the shell or a secret manager instead.

| Variable | Value | Where to get it |
| --- | --- | --- |
| `FI_API_KEY` | Workspace API key | **Build > Keys** |
| `FI_SECRET_KEY` | Matching workspace secret | **Build > Keys**, when creating the pair |
| `OPENAI_API_KEY` | Model provider key | Your OpenAI account |

## Instrument the client

The snippets below show the registration and the model call separately. Use the complete first-trace files above for a short-lived script: they shut down the provider so pending spans flush before exit.

<Steps>
  <Step title="Install the SDK">
    Install the Future AGI instrumentation package and the OpenAI integration (used in this example).

    <CodeGroup titles={["Python", "JS/TS"]}>
    ```bash Python
    pip install "fi-instrumentation-otel[grpc]" traceAI-openai openai
    ```

    ```bash JS/TS
    npm install @traceai/fi-core @traceai/openai openai
    ```
    </CodeGroup>
  </Step>
  <Step title="Configure Your Environment">
    Set up your environment variables to connect to Future AGI. Get your API keys from the [keys page](https://app.futureagi.com/dashboard/keys).

    <CodeGroup titles={["Python", "JS/TS"]}>
    ```python Python
    import os
    os.environ["FI_API_KEY"] = "YOUR_API_KEY"
    os.environ["FI_SECRET_KEY"] = "YOUR_SECRET_KEY"
    os.environ["OPENAI_API_KEY"] = "YOUR_OPENAI_API_KEY"
    ```

    ```typescript JS/TS
    process.env.FI_API_KEY = "YOUR_API_KEY";
    process.env.FI_SECRET_KEY = "YOUR_SECRET_KEY";
    process.env.OPENAI_API_KEY = "YOUR_OPENAI_API_KEY";
    ```
    </CodeGroup>
  </Step>
  <Step title="Register Your Observe Project">
    Register your project with the necessary configuration.

    <CodeGroup titles={["Python", "JS/TS"]}>
    ```python Python
    from fi_instrumentation import register, Transport
    from fi_instrumentation.fi_types import ProjectType

    trace_provider = register(
        project_type=ProjectType.OBSERVE,
        project_name="my-llm-app",
        transport=Transport.GRPC,
    )
    ```

    ```typescript JS/TS
    import { register, ProjectType } from "@traceai/fi-core";

    const traceProvider = register({
        projectType: ProjectType.OBSERVE,
        projectName: "my-llm-app",
    });
    ```
    </CodeGroup>

    **Configuration parameters:**
    - **project_type**: Set as `ProjectType.OBSERVE` for observe
    - **project_name**: A descriptive name for your project
    - **transport** (optional): Set the transport for your traces. The available options are `GRPC` and `HTTP`.
  </Step>
  <Step title="Send an instrumented request">
    There are two ways to trace your project. An auto-instrumentor captures LLM calls automatically and is recommended for most use cases. [Manual tracing](/docs/sdk/tracing/set-up-tracing) gives you full control over what gets traced using OpenTelemetry.

    For Node.js or TypeScript, [zero-code tracing](/docs/integrations/traceai/auto) installs `@traceai/auto` and preloads it at startup, without tracing imports or per-call wrappers. Use that path instead of the explicit JS/TS instrumentor below. Do not instrument the same client twice.

    After registration, run the request in the same program:

    <CodeGroup titles={["Python", "JS/TS"]}>
    ```python Python
    from traceai_openai import OpenAIInstrumentor
    from openai import OpenAI

    # Enable auto-instrumentation
    OpenAIInstrumentor().instrument(tracer_provider=trace_provider)

    # Use OpenAI as normal
    client = OpenAI()

    completion = client.chat.completions.create(
        model="gpt-4o",
        messages=[
            {
                "role": "user",
                "content": "Write a one-sentence bedtime story about a unicorn."
            }
        ]
    )

    print(completion.choices[0].message.content)
    ```

    ```typescript JS/TS
    import { OpenAIInstrumentation } from "@traceai/openai";
    import { registerInstrumentations } from "@opentelemetry/instrumentation";
    import { OpenAI } from "openai";

    // Enable auto-instrumentation
    registerInstrumentations({
        instrumentations: [new OpenAIInstrumentation({})],
        tracerProvider: traceProvider,
    });

    // Use OpenAI as normal
    const client = new OpenAI();

    const completion = await client.chat.completions.create({
        model: "gpt-4o",
        messages: [{ role: "user", content: "Write a one-sentence bedtime story about a unicorn." }],
    });

    console.log(completion.choices[0].message.content);
    ```
    </CodeGroup>
  </Step>
</Steps>

## Match the reply in Observe

1. Note the story printed in the terminal.
2. Open your [Future AGI dashboard](https://app.futureagi.com) and go to **Observe > Tracing**.
3. Select `my-llm-app`.
4. Open the trace containing the bedtime-story prompt.
5. Compare the model span’s output with the story in your terminal.

   You should see the same prompt and reply, along with latency and token usage. Use the trace to inspect cost or group related requests into [sessions](/docs/observe/concepts/sessions).

## Troubleshooting

**The story printed, but the trace is missing.** Confirm the workspace keys and project name. Let the exporter finish before the process exits, then reopen the project. If the trace still does not appear, follow [No traces appear](/docs/observe/troubleshooting/no-traces-appearing).
