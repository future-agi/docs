<TLDR>
Generate a [prompt](/docs/prompt) for document summaries, then test it with a passage whose key facts you can check.
</TLDR>

## The problem

The workbench can generate instructions for summarizing a document without ever seeing the document itself. A draft that says “capture the essential information” is not evidence that the model kept the cancellation date or refund condition in its summary.

## What you'll build

A summary prompt you can test with a short cancellation policy before adding it to [version history](/docs/prompt/guides/commit-and-compare-versions).

You'll:

1. Generate the first draft with **Generate with AI**.
2. Fill the document and format variables before choosing a model.
3. Check the summary against the policy before changing [model parameters](/docs/prompt/reference/model-configuration) or [evaluating outputs](/docs/prompt/guides/evaluate-prompt-outputs) on more inputs.

<Prerequisites title="Before you start">
- A workspace with a [model provider](/docs/admin-settings/ai-providers) configured under **Settings > AI Providers**.
- A short document to summarize. You can use the policy passage below.
</Prerequisites>

## Generate the draft

1. Open **Build > Prompts**.

   ![The Prompts list with the Create prompt button at the top right.](/screenshot/product/prompt/from-ai/1.png)

2. Select **Create prompt**.
3. Select **Generate with AI**.

   ![The Create a new prompt dialog with three options: Generate with AI, Start from scratch and Start with a template.](/screenshot/product/prompt/from-ai/2.png)

4. Enter “Summarize the following text in bullet points” in **Generate a prompt**.

   Any description of the job works here, such as “Write a professional email using the recipient's name and topic” or “Answer customer support questions in a friendly, concise way”.

   ![The Generate a prompt drawer has a task description field and a Summarize a document suggestion.](/screenshot/product/prompt/from-ai/3.png)

5. Select **Generate**.

   The example draft begins “You are an AI assistant specialized in creating clear, accurate, and concise document summaries.” Its input section asks for `{{DOCUMENT}}` and formatting preferences. Your draft can differ.

   ![Generated document summarization instructions with variables for the document, length, focus, format, audience and document type.](/screenshot/product/prompt/from-ai/4.png)

6. Select **Continue**.

   You should see the instructions in the **User** message; the **System** message is optional.

   ![The generated summarization prompt in the User message, with its document and length variables highlighted.](/screenshot/product/prompt/from-ai/5.png)

7. Give the prompt a name by editing its title.

You can edit the generated content before you test it.

## Test it on a cancellation policy

1. Open **Variables**.
2. Enter this passage as the document:

   > Pro plan subscriptions can be canceled anytime from Account Settings > Billing. Cancellation takes effect at the end of the current billing cycle, and no partial refunds are issued for unused time.

3. Fill the other variables in that row to suit the task. For the pictured draft, specify length, focus, format, audience and document type; for example, request bullet points about cancellation timing and refunds for a subscriber.
4. Choose your model under **Select Model**.
5. Select **Run Prompt**.

   You should see the summary in **Output**. Compare it with the source: does it say **end of the current billing cycle**, rather than immediately? Does it preserve **no partial refunds**?

## Run the prompt from code

The [platform SDKs](/docs/sdk/reference/prompts#promptsrun) let Python and TypeScript clients run a configured version of the prompt by its template ID with `client.prompts.run`. The first response is an asynchronous receipt, not the summary. To read the output for that call, pass its returned version as `template_version` to `client.prompts.run_status` in Python or `client.prompts.runStatus` in TypeScript.

## Troubleshooting

- **Run Prompt opens Variables instead of generating.** A `{{name}}` in a message still needs a value. Fill every declared variable in the test row, including length or format, then run again.
- **The model picker opens instead.** Select a configured model, then retry.
