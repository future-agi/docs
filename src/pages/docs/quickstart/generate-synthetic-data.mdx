<TLDR>
Build a product-review [dataset](/docs/dataset) from [synthetic data](/docs/dataset/concepts/synthetic-data) when you cannot use real reviews.
</TLDR>

## The problem

You need reviews to test an application, but the real reviews are unavailable or restricted. A generated review is only useful for this test if its rating fits your scale and its sentiment is a value your application accepts.

Synthetic data generation creates realistic, structured rows from a schema you define, without collecting or exposing real user data. Use it to build training sets, test edge cases, prototype AI pipelines or create evaluation datasets.

## What you'll build

A table of review text, integer ratings and sentiment labels, with checks for each field.

3. Inspect a generated row against the schema.

<Prerequisites title="Before you start">
- A workspace where you can create a dataset in the dashboard.
- A rating range and a list of permitted sentiments; this example supplies both.
</Prerequisites>

## Describe the dataset

1. Open **Dataset** in the sidebar.
2. Select **Add Dataset**.
3. Choose **Create Synthetic Data**.

   ![The dataset creation menu includes Create Synthetic Data.](/screenshot/product/quickstart/1.png)

4. Enter a name that identifies the product reviews in **Name** (required).
5. Describe the reviews you want in **Description** (required).
6. Describe the intended use in **Objective**.
7. Optionally, describe a **Pattern**, such as "Follow a conversational pattern" or "Keep tone formal".
8. Enter the number of reviews to generate in **Enter No. of rows**.

   ![The Add details form shows Name, Description, Objective, Pattern and the required row count, with a minimum of 10 rows.](/screenshot/product/quickstart/2.png)

## Define the fields

Select **Next** to open **Add column properties**. Use these definitions for the product-review example. Put ranges and allowed values in the column properties, not just the descriptions.

| Column | Type | Property |
| --- | --- | --- |
| `review_text` | Text | Freeform review |
| `rating` | Integer | Minimum `1`, maximum `5` |
| `sentiment` | Text | Categorical values `positive`, `negative`, `neutral` |

1. Enter `review_text` as the first **Column Name**.
2. Select **Text** as its type.

   ![The blank column editor shows the type menu, including Text and Integer.](/screenshot/product/quickstart/3.png)

   Other available types are Boolean, Float, JSON, Array and Datetime. A field can also use a string pattern or leave values to the generator.

3. Add the `rating` column using the type and range in the table.
4. Add the `sentiment` column using the allowed values in the table.
5. Select **Next**.
6. Describe what each field should contain.

   The description gives the generator the context it needs for each field. You should see a description field for each of your three columns.

   ![The Add description step shows a description box for one column, here a placeholder column called test.](/screenshot/product/quickstart/4.png)

## Generate and check a row

1. Compare the preview with the three column definitions above.
2. Correct any mismatched type, range or allowed value in the schema.
3. Select **Create**.
4. Open the saved dataset after generation finishes.

   You should see rows under `review_text`, `rating` and `sentiment`.

5. Inspect a row: does it contain review text, a whole-number rating from 1 through 5 and one of the three sentiment values?

   Properties guide generation; they do not guarantee that every row passes. Edit an individual entry if needed before using the data for training, evaluation or experiments. You can also add columns to the dataset.

## Read the saved rows from code

This quickstart generates the rows in the dashboard. To read them from code, the [dataset SDK reference](/docs/sdk/reference/datasets#datasetsget) documents how to retrieve a dataset's rows, columns and metadata by ID in Python or TypeScript.
