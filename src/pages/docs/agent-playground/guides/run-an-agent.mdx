When a workflow returns the wrong result, you need to see which node went wrong and what it was handed. Running a graph in Agent Playground executes every node your edges connect, and gives you a live account of what happened at each one: which node ran, what it received, and what it returned.

This guide runs the [Invoice Triage graph](/docs/agent-playground/guides/build-workflow), checks that its classifier handed the right value to the router, and finds the run again after you've left the builder. A run uses the [last saved version](/docs/agent-playground/concepts/versions-and-execution) of the graph.

<Prerequisites title="Before you start">
- Save the graph you want to run, with the classifier's output connected to the router's input.
- Configure every node, including the [LLM Prompt node](/docs/agent-playground/guides/build-workflow/configure-an-llm-prompt-node) and the [Agent node](/docs/agent-playground/guides/build-workflow/configure-an-agent-node).
- Supply the [input variables](/docs/agent-playground/guides/build-workflow/set-input-variables) the graph needs.
</Prerequisites>

## Launch the saved graph

1. Open **Agent Builder** for Invoice Triage.
2. Select **Run Agent Workflow**.

   If you've made changes you haven't saved, a dialog titled "Unsaved Changes" stops you before anything runs: "You have unsaved node changes. Running now will use the last saved configuration." Click **Run Anyway** to go ahead with the last saved version, or close the dialog and save first if the run needs to reflect your edits.

   Once the run starts, a run panel opens at the bottom of the builder and lists each node by name. The button's label switches to **Rerun Agent Workflow** the next time you run it, so the button itself tells you whether this is a first run or a repeat.

## Inspect the handoff

<Mermaid chart={`flowchart TD
  accTitle: What to inspect between the classifier and router
  accDescr: A successful classifier produces the value the router receives. If the classifier fails, the dependent router is skipped and has no handoff to inspect.
  C["Classifier node"] -->|Success| O["Classifier output"] --> I["Router input"]
  C -->|Failure| F["Failed classifier"] --> S["Skipped router"]`} />

1. Select the classifier in the run panel.

   Its output is the value to look for in the router.

2. Select the router in the same run.

   Its input should be the same value the classifier handed off.

While it runs, the node currently executing is the one animating on the canvas. **Show Outcome** and **Hide Outcome** fold the panel away or bring it back without stopping anything underneath. Once the agent finishes, the panel selects the last node that ran.

A node marked failed didn't complete, and any node downstream of it is marked skipped rather than running. Click a node inside the panel, including one marked failed, to see what went into it and what came out.

## Exit a running workflow

1. Select **Exit Workflow** while the run is in progress.

   A dialog titled "Leave running workflow?" asks first: "Your workflow will run in the background. You can find it in the Execution tab." Choose **Cancel** to stay and keep watching.

2. Select **Leave**.

   A toast confirms it: "Exited workflow. It will continue running in the background." **Exit Workflow** doesn't stop the run. It keeps executing with the builder closed.

## Reopen the execution

1. Open the same agent.
2. Select **Executions**.
3. Select the run in the list on the left.

   Its per-node detail loads on the right, the same kind of detail the run panel showed while it was in progress. When a step is an [Agent Node](/docs/agent-playground/concepts/understanding-agent-playground#composing-agents-with-an-agent-node), opening it opens the nested run inside it too.

## If the handoff is missing

<div class="sdk-ref-table">

| What you see | What to check |
| --- | --- |
| `Node not configured`, or `3 nodes are not configured` when more than one is missing setup | The run is refused until every node on the canvas is configured. Finish the setup, then run again. |
| `Fill in all variables before running` | The run is held and the **Variables** drawer opens on its own. Fill in every variable the graph needs, then run again. |
| `Workflow execution failed` | The run as a whole couldn't complete for a reason that isn't pinned to one node. Check the panel's per-node statuses for one marked failed, and click it to see what it received and returned. If the run never started, retry it, and if it keeps failing to start, send support the agent ID. |
| A failed node followed by a skipped node | Open the failed node to read its inputs and outputs. The downstream node did not run, so fix the upstream failure first. |
| `No executions yet` | Start a run from **Agent Builder**; the empty state reads “Run your workflow from the Agent Builder to see results here.” |

</div>
