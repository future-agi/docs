Use a [nested agent](/docs/agent-playground/concepts/understanding-agent-playground#composing-agents-with-an-agent-node) when one workflow needs to run another. The Agent Node's form, in the node drawer, sets three things: which agent to run, which [saved version](/docs/agent-playground/reference/limits-and-rules#agent-nodes) of that agent, and which of the parent workflow's values feed its inputs. Beyond those three, the node carries no configuration of its own.

<Prerequisites title="Before you start">
- A [workflow with an Agent Node](/docs/agent-playground/guides/build-workflow) already on the canvas.
- A **different** agent with an active or inactive saved version. An Agent Node never points at a draft.
</Prerequisites>

## Choose the agent and version

1. Click the **Agent Node** on the canvas.

   The drawer opens with fields for the agent, version and input mapping. **Agent** starts at **Select agent**; **Version** reads **Select an agent first**.

2. Under **Agent**, select the agent to nest.

   Its latest non-draft version is preselected under **Version**.

3. Under **Version**, keep that version or change it to any of the agent's other saved versions.

   If another Agent Node in this workflow already references the same agent, select the same version here. Save refuses a second version of an agent you've already referenced.

## Map a parent value to a child input

For example, say the nested agent expects an `invoice_details` input, and a `classify_invoice` node feeds into this Agent Node. You pass that node's `response_1` output down to the nested agent:

<Mermaid chart={`flowchart LR
    accTitle: Pass an upstream value to the child agent
    accDescr: In the parent workflow, classify_invoice produces response_1. The Agent Node maps that value to invoice_details on the selected child version.
    O["classify_invoice.response_1"] --> M["Agent Node input mapping"]
    M --> C["Child input: invoice_details"]
`} />

1. Find `invoice_details` under **Input Mapping**.

   **Input Mapping** lists one row per input the nested agent expects. Row labels are the nested agent's own input names, set when that agent was built rather than here; they double as the mapping keys. If the nested agent has no inputs, the section doesn't appear at all.

2. In that row's **Variable** field, select `classify_invoice.response_1`.

   The options are the output ports of the nodes connected directly into this one, labeled `node_name.output_name`.

   Leave a row unmapped and no edge is created for it. That input becomes one of the parent workflow's own [input variables](/docs/agent-playground/guides/build-workflow/set-input-variables) instead, and the run refuses to start until it has a value.

3. Click **Save**.

   A successful save closes the drawer. When the parent runs, the nested agent's own run appears inside the parent run's results.

## If Save rejects the node

If the save fails, a toast reads "Failed to save agent node" and the node reverts. Check the reference rules:

- **One version per agent.** If another Agent Node in this workflow references the same agent, select the version already in use and save again.
- **No self-reference.** The node cannot point at the agent it belongs to.
- **No cycles.** Agent Nodes cannot form a cycle of agents pointing at each other.
