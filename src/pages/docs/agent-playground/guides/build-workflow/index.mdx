Say you're building Invoice Triage, a workflow that reads each invoice and decides where it goes. It needs two steps: one to classify the invoice and one to route it to the right approver. This guide places an [LLM Prompt node](/docs/agent-playground/guides/build-workflow/configure-an-llm-prompt-node) and an [Agent node](/docs/agent-playground/guides/build-workflow/configure-an-agent-node) on the canvas, connects them so the router receives the classification, and saves the graph as one version.

Use an LLM Prompt node for a single, focused call to an LLM, the way Invoice Triage classifies an invoice. Use an Agent Node when the step needs to run an agent, the way Invoice Triage routes the invoice.

<Prerequisites title="Before you start">
- [Create an agent](/docs/agent-playground/guides/create-agent) for Invoice Triage and open its editable draft. You need permission to edit it.
- Have a text-based classifier prompt and a saved, non-draft version of a **different** agent to route the result. The nested agent's inputs determine what you can map.
</Prerequisites>

## Place the classifier

1. Open the agent. You land on the **Agent Builder** tab.

   The builder has three regions: the node palette on the left, the canvas in the middle, and the node drawer, which opens on the right when you select a node. The other two tabs across the top are **Changelog** and **Executions**.

   <img src="/images/docs/agent-playground/builder-overview.png" alt="The Agent Builder with the Agent Builder, Changelog, and Executions tabs across the top, the node palette on the left, a two-node graph on the canvas, and the node drawer open on the right" style={{ borderRadius: '5px' }} />

2. In the node palette, click the **LLM Prompt** card to drop the classifier onto the canvas. You can also drag the card and release it where you want the node to land.

   <img src="/images/docs/agent-playground/node-selection-panel.png" alt="The node palette listing LLM Prompt, described as Run a prompt against an LLM, and Agent Node, described as Run an agent through LLM" style={{ borderRadius: '5px' }} />

3. Click the new node to open its drawer.
4. In **Prompt Name**, enter a name no other node on the canvas uses, such as `classify_invoice`.
5. Select a prompt version. Only text-based prompts are supported in the builder.
6. Select the model.
7. In the prompt messages, use a `{{variable}}` placeholder for the invoice text.

   Placeholder names become the node's input names. The invoice text comes from outside any node, as an [input variable](/docs/agent-playground/guides/build-workflow/set-input-variables).

8. Click **Save prompt**.

   The drawer closes when the prompt saves. A single configured node already runs on its own. Connecting it is how its output becomes the next node's input.

## Connect the router

1. Click the **Agent Node** card in the palette.
2. Drag from the classifier's output handle to the router's input handle.

   The builder draws the connection between them.

   <img src="/images/docs/agent-playground/node-connection-handles.png" alt="An output handle on the classifier connected by a dashed line to an input handle on the router" style={{ borderRadius: '5px' }} />

   Instead of steps 1 and 2, you can click the **+** button to the right of a node with no outgoing connection. The same node picker opens, and the new node lands already connected.

3. Click the router to open its drawer.
4. Under **Agent**, select the agent to nest.
5. Under **Version**, check the version to run. The agent's latest non-draft version is preselected.
6. Under **Input Mapping**, pick the classifier's output in the **Variable** select for the input it should feed.

   For example, if the nested agent expects an `invoice_details` input, pick `classify_invoice.response_1` on that row. A row you leave unmapped becomes one of the parent workflow's own input variables.

7. Click **Save** in the node drawer.

   A successful save closes the drawer.

Connections follow a few rules:

- One output can feed as many inputs as you connect it to, so one node's result can branch into several downstream nodes.
- One input takes only one source.
- A connection that loops back into a node's own upstream path draws fine but won't save.

## Save the workflow version

1. Click **Save Agent**.

   A dialog opens with a **Version** field you can't edit and a **Commit Message** box. If the graph contains a cycle or a node is left unconfigured, a toast shows the error and the dialog doesn't open.

2. Enter a note about the change in **Commit Message**.
3. Click **Save**.

   The dialog closes and the graph is saved as a new version. If you reached the dialog by clicking **Run Agent Workflow** on an unsaved draft, the button reads **Save & Run** and also runs the agent after saving.

4. Open the **Changelog** tab to find the new version and its commit message.

Invoice Triage now has its shape: an LLM Prompt node feeding an Agent Node, connected and versioned.

## Remove an unwanted node

- **From the canvas:** the delete icon on the node removes it immediately, with no confirmation.
- **From the drawer:** the delete icon opens a dialog titled **Delete Node** that asks “Are you sure you want to delete this node? This action cannot be undone.” Click **Delete** to confirm, or close the dialog to keep the node. If the deletion doesn't go through, a “Failed to delete node” toast tells you.

## Troubleshooting

- **Save Agent is disabled:** it stays disabled until you have permission to edit the agent, the agent is on a draft, you're on the **Agent Builder** tab, no run is in progress, and the canvas has finished loading. Hover the button to see why. Without edit permission, the tooltip reads “You don't have permission to edit this agent.”
- **Save Agent shows an error about an unconfigured node:** open that node's drawer, finish its configuration and save the node, then save the workflow again.
- **A connection draws but the graph won't save:** look for a connection that loops back into a node's own upstream path and remove it. See the [connection rules](/docs/agent-playground/reference/limits-and-rules#connections) and [troubleshooting](/docs/agent-playground/troubleshooting).
