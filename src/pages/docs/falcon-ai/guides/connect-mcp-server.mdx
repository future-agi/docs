Add an external Model Context Protocol (MCP) server as a Falcon AI [connector](/docs/falcon-ai/concepts/mcp-connectors) when you want to use its tools in chat. Discovery enables every tool the server returns, so review the [allowed-tool selection](/docs/falcon-ai/guides/choose-connector-tools) before anyone uses the connector.

<Prerequisites title="Before you start">
- A [role](/docs/roles-and-permissions) with access to [workspace settings](/docs/admin-settings/workspace-management). The connector is shared with everyone in the workspace.
- The server URL, its transport, and the credentials or provider sign-in the server requires.
</Prerequisites>

Here Falcon AI calls **your server**. To have an external client call Future AGI tools instead, see [Use the Future AGI MCP server](/docs/falcon-ai/guides/use-the-mcp-server).

## Add the server

1. Open **Settings**.
2. Under **Workspace Settings**, select **Falcon AI Connectors**.

<img src="/images/docs/falcon-ai/guides/connect-mcp-server.png" alt="The Falcon AI Connectors settings page with no connectors added, showing the Add Connector button top right and the No connectors configured panel with Add your first connector" style={{ borderRadius: '5px' }} />

3. Select **Add Connector**.

   On an empty page, **Add your first connector** opens the same form.

4. Enter a **Name** that is unique in this workspace.
5. Enter the **Server URL**.

   Both fields are required; a duplicate name prevents saving.

6. Choose **Transport**: **Streamable HTTP** for a current server, or **SSE (Legacy)** for an older server that still expects that transport.

You can also reach these settings from **+ > Connectors > Manage connectors** in chat or **Customize > Connectors > Add connector**.

## Set authentication

1. Choose the **Authentication** method your server expects.

<div class="sdk-ref-table max-sm:[&_td]:px-1.5! max-sm:[&_th]:px-1.5!">

| Method | Fields to complete |
| --- | --- |
| **None** | No credentials. |
| **API Key** | Enter the server's **Header Name** and **Header Value**. |
| **Bearer Token** | Enter the **Bearer Token**. |
| **OAuth 2.0** | No extra fields here; sign in after saving. |

</div>

2. Complete the fields for your method.
3. Select **Create**.
4. Select the saved connector in the left-hand list.

   You should see **Edit**, **Discover Tools**, **Test Connection**, and **Delete** in the detail pane. A connector that signs in through OAuth also shows **Re-authenticate**.

## Sign in to an OAuth connector

Saving an **OAuth 2.0** connector doesn't sign you in. Skip this section for the other methods.

<Warning>
OAuth sign-in, including reauthentication, can trigger tool discovery. Successful discovery enables every returned tool and replaces your previous restrictions.
</Warning>

1. Select **Re-authenticate**, even for the first sign-in.
2. Approve access in the provider's sign-in window.

   On success the window closes and the connector details refresh; Settings does not display an **Authentication updated.** message.

If sign-in fails, check the provider's error or the brief message in the callback window. Confirm you approved access before trying **Re-authenticate** again.

Authentication can succeed even if tool discovery fails. A **Connected** chip is not proof that discovery succeeded, and a **Discovered Tools** list can remain from an earlier attempt. Run **Discover Tools** and check its result when you need to confirm that the list was refreshed.

## Test, discover, and narrow the tools

1. Select **Test Connection**.

   While the button reads **Testing...**, wait for the result: success normally reads **Connection test succeeded.**, but the server may supply another message.

A successful test doesn't update the stored verified status or the tool list.

<Warning>
Discovery resets the allowed tools, even on a connector you have restricted before. Review the toggles immediately after discovery and before using the connector in chat.
</Warning>

2. Select **Discover Tools**.

   The button reads **Discovering...** while it runs. A successful pass shows something like **Discovered 4 tools.**

<img src="/images/docs/falcon-ai/guides/connect-mcp-server-discovered.png" alt="A connected connector's detail pane with the Edit, Discover Tools, Test Connection, and Delete buttons above a Discovered Tools list holding three tools, each with its description and an enabled toggle" style={{ borderRadius: '5px' }} />

The DeepWiki example lists `ask_question`, `read_wiki_contents` and `read_wiki_structure`. All three toggles are on, even though you have not selected any tools individually.

3. Under **Discovered Tools**, switch off each tool you don't want Falcon AI to call.

   Leave at least one allowed; each toggle saves immediately, and the count still shows all discovered tools, not just those enabled.

Discovery stores the list against the connector, so it is still there when you come back.

If testing or discovery fails, use the reported error; the fallback messages are **Connection test failed.** and **Tool discovery failed.** Check the URL, transport and authentication, including both header fields for an API key. If they match the server's settings, check server availability, network access or a platform error before retrying the failed action.

## Change or remove the connector

1. Select **Edit** in the connector's detail pane.
2. Change its name, URL, transport or authentication as needed.

   Leave **Header Value** or **Bearer Token** blank to keep the stored secret. A blank field does not mean no secret is stored, and saving it blank does not clear the secret. Enter a new value only to replace it.

3. Select **Save**.
4. Select **Test Connection** after changing connection settings.
5. Select **Discover Tools** again, then review the allowed tools.

To remove a connector instead, check the selected name first: **Delete** removes it immediately without confirmation.
