## About

The platform MCP server lets your IDE call Future AGI tools in your workspace. To look up a tracing project for the Ridgeline Outfitters support agent, for example, you can grant your IDE the observability tools without granting it access to your datasets.

## Connect your IDE

<Steps>
<Step title="Choose the groups available to connected clients">

In the workspace you want to use, open [Settings > MCP Server](https://app.futureagi.com/dashboard/settings/mcp-server). Expand **Tool Groups**, turn on **Observability / Traces** for the project lookup, and select **Save changes** if you changed a switch. These settings apply to clients connecting as you in this workspace, not just the IDE you are about to connect.

{/* MEDIA: Tool Groups expanded in Settings > MCP Server, with Observability / Traces enabled and Save changes visible. */}

</Step>
<Step title="Add the platform server to your IDE">

On Future AGI Cloud, add `https://api.futureagi.com/mcp` using the tab for your client below. Choose Streamable HTTP if your client asks for the transport. For another deployment, use the install instructions under **Connect Your IDE** in its settings so you connect to the right URL.

<MCPIDETabs />

{/* MEDIA: Connect Your IDE showing the MCP URL, client tabs, and install action in the dashboard. */}

</Step>
<Step title="Grant this client the permissions it needs">

Connect from the IDE and sign in when the browser opens. On **Authorize MCP Connection**, check the client name. Under **Permissions**, leave only **Observability / Traces** selected for this example and click **Authorize**. You must select at least one group to authorize. If you do not want to grant access, choose **Deny**. You do not need an API key for this flow.

{/* MEDIA: Authorize MCP Connection showing the client name, Observability / Traces selected, and the Deny and Authorize buttons. */}

</Step>
</Steps>

## Discover and call a tool

Ask your IDE: “Use `list_projects` to find tracing projects with `ridgeline-support` in the name. Request page 0 with a page size of 5. Show the matching names and IDs.” Substitute part of a project name from your workspace to see a match.

The client discovers tools with `tools/list`. Look for `list_projects` and inspect its `inputSchema` before calling it. For this request, `tools/call` takes the name `list_projects` and the arguments `{"name":"ridgeline-support","page_number":0,"page_size":5}`. Its `structuredContent` contains `projects` and `total_count`. An empty `projects` list with `total_count: 0` is a successful search with no matches, not a missing tool.

### Compare with Falcon

In [Falcon chat](/docs/falcon-ai/guides/chat-with-falcon-ai), select the same workspace and ask the same question. Expand the completed `list_projects` card. **Parameters** shows what Falcon sent; **Full output**, when present, shows what came back. Compare the `id` of the same project, not the assistant's wording or the row position. If the results differ, first compare the workspace, name filter and page.

{/* MEDIA: Falcon's expanded list_projects card showing Parameters and a matching project's ID alongside the IDE tool result for the same request. */}

For a platform catalog tool like `list_projects`, both clients use the same name, argument schema and underlying API. Your workspace access still applies, and a grant does not give you a write role. Falcon also has native helpers such as documentation search. Tools you [connect to Falcon](/docs/falcon-ai/guides/connect-mcp-server) come from third-party servers; neither kind is automatically published to your IDE. [Gateway MCP federation](/docs/command-center/features/mcp-a2a) serves a different purpose: it puts upstream servers behind the gateway for your agents to call.

### Run the same read from Python

Install the MCP client with `python -m pip install mcp==1.30.0`. For a script, supply a valid [API key pair](/docs/admin-settings/api-keys) for the workspace through the `FI_API_KEY` and `FI_SECRET_KEY` environment variables. The key pair uses the connection's enabled tools, **not** the IDE's OAuth grant. Use the IDE itself to check what you authorized there.

```python
import asyncio
import os

import httpx
from mcp import ClientSession
from mcp.client.streamable_http import streamable_http_client


async def main():
    url = os.environ.get("MCP_URL", "https://api.futureagi.com/mcp")
    headers = {
        "X-Api-Key": os.environ["FI_API_KEY"],
        "X-Secret-Key": os.environ["FI_SECRET_KEY"],
    }
    async with (
        httpx.AsyncClient(headers=headers, timeout=60) as http,
        streamable_http_client(url, http_client=http) as streams,
        ClientSession(streams[0], streams[1]) as client,
    ):
        await client.initialize()
        tools = {tool.name for tool in (await client.list_tools()).tools}
        if "list_projects" not in tools:
            print("list_projects is not available to this connection.")
            return
        result = await client.call_tool(
            "list_projects", {"name": "ridgeline-support", "page_number": 0, "page_size": 5}
        )
        if result.isError:
            raise RuntimeError(result.structuredContent["error"]["message"])
        data = result.structuredContent
        print(f"Matching projects: {data['total_count']}")
        for project in data["projects"]:
            print(project["name"], project["id"])


asyncio.run(main())
```

## When a tool is missing

For OAuth, a tool's group must be **both** enabled in the connection settings **and** granted to this client. `tools/list` omits tools outside that intersection. Calling an omitted tool by name does not grant access: `tools/call` checks the same permissions before running it.

| What you see | What to do |
| --- | --- |
| One IDE can list `list_projects`; another, authorized only for **Context & Navigation**, cannot. A direct call returns `FORBIDDEN` with `required_scope: observability` in the error details. | Start a new authorization from the second IDE. Select **Observability / Traces**, authorize, then request the tool list again. Changing a dashboard switch does not expand an existing access token. |
| The IDE was granted observability, but a call returns `Tool is disabled: list_projects`. | Check **Tool Groups** for your user and workspace. If the group is off, turn it on, save, and refresh the tool list. You do not need a broader grant if it already includes the group. |
| A new group is absent after an upgrade, or `tools/list` is empty. | Existing connections keep their saved choices, even if all groups were off. Enable the group you need; if your client was never granted it, authorize again. Discovery only includes tools available on your deployment. |

## When authentication fails

| Symptom | Next action |
| --- | --- |
| You can sign in with SAML but cannot approve a connected app. | A SAML-scoped session cannot approve MCP OAuth. Sign in independently with your password or OAuth if your organization's policy permits it; otherwise ask your administrator. Changing tool groups does not fix sign-in. |
| Token exchange returns `invalid_grant` for an expired or already-used authorization code. | Start a fresh authorization in the client. A code can be exchanged only once; do not retry the same callback. |
| `/mcp/oauth/token/` returns HTTP `429` and `slow_down`. | Pause token requests for the number of seconds in `Retry-After`. Repeated invalid exchanges can also cause a temporary lockout; correct the credentials before retrying. |
| The Python example receives HTTP `401` with `api_key_expired` or `Invalid credentials`. | Replace an expired key pair. For `Invalid credentials`, check that both keys belong to the same enabled pair. An ingest-only key can send spans to the collector but cannot authenticate to MCP. |
